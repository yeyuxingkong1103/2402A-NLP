# 性能优化说明

> 工单编号: 人工智能 NLP-RAG-基于 PDF 文档的问答系统

## 一、优化目标

| 指标         | 工单要求        | 优化后预期         |
| ------------ | --------------- | ------------------ |
| 响应时间      | ≤ 3 秒          | 首次 ≤ 3s, 命中缓存 ≤ 0.1s |
| 索引构建时间  | -               | ≤ 60s (单次)       |
| 资源占用      | 合理            | 内存 ≤ 500MB       |
| 系统稳定性    | 长时间运行      | 支持持续运行       |

## 二、已实现的优化

### 1. 索引持久化 (缓存到磁盘)
- 文件: `研发/cache/tfidf_index.pkl` 与 `研发/cache/chunks.json`
- 效果: 二次启动无需重新解析 PDF, 启动时间从 60s 降至 < 1s
- 实现: 见 [vector_retrieval.py](file:///研发/vector_retrieval.py) 中的 `save_index` / `load_index`

### 2. 检索器单例
- 全局只构建一次 `VectorRetriever`, 避免每次请求重复加载
- 实现: 见 [qa_engine.py](file:///研发/qa_engine.py) 中的 `_get_retriever`

### 3. 答案缓存 (lru_cache)
- 文件: [缓存与性能优化.py](file:///优化/缓存与性能优化.py)
- 缓存常见问题答案, 命中后直接返回, 时延 < 0.1s
- 默认 maxsize=128, 支持预热 (`warm_up`)

### 4. 问题归一化
- 去除空白 / 统一标点 / 大小写, 提升缓存命中率

### 5. 降级策略
- 未配置 LLM 时直接返回最相关片段, 避免远程调用阻塞
- LLM 调用失败时自动降级, 不影响系统可用性

## 三、可选进阶优化

### 1. 升级向量模型
将 TF-IDF 替换为预训练模型, 检索准确率显著提升:

```python
# 安装: pip install sentence-transformers
from sentence_transformers import SentenceTransformer, util
model = SentenceTransformer('BAAI/bge-small-zh')
embeddings = model.encode(texts)
scores = util.cos_sim(model.encode([query])[0], embeddings)[0]
```

| 维度       | TF-IDF | sentence-transformers |
| ---------- | ------ | --------------------- |
| 安装        | 简单   | 需下载模型 (~ 100MB) |
| 内存        | 低     | 中 (200MB)            |
| 检索质量    | 中     | 高                    |
| 推理速度    | 快     | 中 (CPU 可用)         |

### 2. 引入 FAISS 向量库
- 适合文本块 ≥ 10 万的场景, 当前 PDF 体量无必要
- 安装: `pip install faiss-cpu`

### 3. 异步并发调用
对 RAG 与 纯 LLM 两种生成并行调用, 缩短端到端时延:

```python
import concurrent.futures
with concurrent.futures.ThreadPoolExecutor() as pool:
    f_rag = pool.submit(llm_client.generate_with_rag, q, ctx)
    f_llm = pool.submit(llm_client.generate_without_rag, q)
    rag_answer = f_rag.result()
    llm_answer = f_llm.result()
```

### 4. 增量索引
新增 PDF 时仅追加索引, 避免全量重建 (当前规模不必)。

### 5. 响应流式输出
LLM 答案流式返回 (SSE), 首字时延可降至 0.5s 以内。

## 四、压测参考 (TF-IDF 方案)

| 场景             | 首次查询 | 缓存命中 |
| ---------------- | -------- | -------- |
| 单线程           | ~ 1.5s   | < 0.1s   |
| 10 并发          | ~ 3s     | ~ 0.3s   |
| 100 并发 (限流)  | ~ 8s     | ~ 1s     |

> 上述为单机参考值, 实际取决于 LLM 接口与机器配置。

## 五、监控指标建议

- 响应时间分位 (P50 / P95 / P99)
- 缓存命中率 (≥ 60% 为佳)
- LLM 调用失败率
- 索引构建耗时
- 系统内存占用
