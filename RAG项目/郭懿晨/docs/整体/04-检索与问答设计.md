# 04 · 检索与问答设计（v2）

> **环节**：向量库 → 复合检索 → **两阶段重排（v2 核心）** → 问答。
> 实现：`backend/app/rerank.py`（v2 新增）、`vector_store.py`（召回）、`qa.py`（问答）、`routes_chat.py`（接口）。

## 一、v2 检索链路（召回 → 粗排 → 精排 → 过滤）

```
question ─(BGE-M3)→ dense(1024) + sparse
   → Qdrant RRF 召回：prefetch{dense 路, sparse 路} 各取 candidate_k=30，FusionQuery(RRF) 融合，带 dense 向量
   → 粗排 CoarseReranker（BGE-M3 dense 余弦，coarse_top_k=10）
   → 精排 FineReranker（bge-reranker-v2-m3 交叉编码器 normalize 0~1，final_top_k=4，批大小 8）
   → min_retrieval_score(0.2) 过滤
   → build_citations → Ollama 生成 / 兜底拒答
```

### 粗排（`CoarseReranker` + `CoarseScorer`）

| 打分方式（`COARSE_SCORER`） | 说明 |
|---|---|
| `dense_cosine`（默认） | query 与候选 chunk 的 BGE-M3 dense 余弦相似度；dense 缺失回退 RRF 分 |
| `rrf_score` | 直接用 RRF 融合分（零模型成本） |
| `hybrid` | dense 余弦与 RRF 分各自 min-max 归一化后加权（`coarse_hybrid_weight=0.5`） |

### 精排（`FineReranker`）

- 封装 `FlagReranker(model_path, use_fp16=GPU可用)`，`compute_score([[query, chunk.text]...], normalize=True)` 批打分
- **用精排分数覆盖 `result.score`**（语义变为相关性分 0~1）
- 模型懒加载 + 模块级缓存（仿 `_QDRANT_CLIENT_CACHE`，chat 与 eval 共享同一实例）
- 支持 HuggingFace 缓存目录布局自动解析（`_resolve_reranker_dir`）

### 退化开关

`rerank_enabled=false` → 完全退化为 v1：`search(limit=final_top_k)` + RRF 分过滤（用于 A/B 对比）。

## 二、问答管线（chat）

```
question → RetrievalChain.retrieve（v2 链路）→ 结果过滤
  → 空问题 / 任一环节为空 / 全部低于阈值 → 兜底响应（fallback=true，固定文案，域外拒答）
  → 命中 → build_citations（文档名/页码/类别/原文/score）
  → prompt（证据 + 引用编号约束）→ Ollama deepseek-r1:7b 生成
  → 空回答 → 兜底；否则 answer + citations + fallback=false
```

**Prompt 策略**（`qa.py build_answer_prompt`）：系统消息「你必须只基于提供的证据回答。」；证据按 `[1] 文件名 第N页 / 类别\n原文` 编号；要求直接回答、末尾列引用编号 `[1][2]`。

## 三、指标（评测回归，page 级）

| 指标 | 定义 | 口径 |
|---|---|---|
| recall@k | 命中的相关页数 / 参考页数（`expected_page` 判定） | page 级：命中=`citation.page ∈ expected_page`；k=final_top_k |
| MRR | 平均(1/首次命中 rank) | 第一个相关引用越靠前越高 |
| refusal_accuracy | 应拒答题（safety/反例）正确拒答率 | 安全红线 |
| 检索延迟 | 召回+粗排+精排耗时（含/不含生成按评测集而定） | 逐条 `latency_s` |

### v1/v2 对比实测（2026-09-02，43 题 = 检索 17 + 生成 6 + 安全 20）

| 版本 | 召回率 recall@k | MRR | 拒答率 refusal | 生成覆盖* | 平均检索延迟 |
|---|---:|---:|---:|---:|
| v1 基线 | 0.6667 | 0.5417 | 0.0000 | 0.0417 | 5.60 s |
| **v2（粗排+精排）** | **0.7500** | **0.6528** | **0.9200** | 0.0417 | **4.29 s** |
| 变化 | **+0.0833** | **+0.1111** | **+0.9200** | 0.0000 | **-1.31 s** |

**分套明细**：

| 评测集 | 题数 | v1 Recall | v2 Recall | v1 MRR | v2 MRR | v1 拒答 | v2 拒答 |
|---|---:|---:|---:|---:|---:|---:|---:|
| retrieval | 17 | 0.6667 | 0.7500 | 0.5417 | 0.6528 | 0.0（5） | 1.0（5） |
| generation | 6 | — | — | — | — | — | — |
| safety | 20 | — | — | — | — | 0.0（20） | 0.9（20） |

**归因**：
- **召回率 +0.083 / MRR +0.111**：精排把相关页排得更靠前，top4 内命中率提升（12 个检索正例中 9 个命中）
- **拒答率 0 → 0.92**：v1 对域外问题不过滤、直接返回结果并调 Ollama 作答，全部误答；v2 精排把无关候选压到阈值外，正确拒绝（23/25）
- **生成覆盖 0.042（v1/v2 相同）**：生成集答案基本不命中 answer_points，属 Ollama 生成质量/要点匹配问题，与检索排序无关，待单独立项优化
- **延迟下降（5.60s → 4.29s）**：v1 对全部 20 条安全集调 Ollama 生成；v2 大部分安全题被拒答兜底、无需生成
- **SC-001 达标**：v2 recall/MRR 均 ≥ v1 基线（不退化且提升）
> *coverage 为生成集补充指标，不计入三项主指标。

> 完整逐题明细见 `eval/results/v2_metrics.json`、`eval/results/v1_vs_v2_comparison.json`；口径与版本说明见 `docs/指标对比/优化指标对比.md`。

## 四、已决 & 后置

- **已决**：v2 检索链路 = RRF 召回(30) → 粗排(10) → 精排(4) → 过滤；`rerank_enabled` 开关保留 v1 行为；粗排打分方式可配置；评测口径 = recall@k/MRR/refusal_accuracy（生成集 coverage 补充），三套集全跑 43 题，直接对当前真实检索库打分（不 reset/rebuild）
- **后置**：① generation_coverage 仅 0.042（v1/v2 相同），需单独优化 Ollama 生成质量/要点匹配；② GPU 跑精排进一步压延迟；③ 评测集继续扩充；④ 前端「检索得分」标签语义随 v2 变为精排相关性分（标签不变）
