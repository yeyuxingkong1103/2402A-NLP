## 3. 准备模型

两个本地模型必须就位：

| 模型 | 路径 | 用途 |
|---|---|---|
| bge-m3 | `D:\模型\bge-m3` | 稠密向量（1024 维） |
| bge-reranker-v2-m3 | `D:\模型\bge-reranker-v2-m3` | 交叉编码器重排 |

在 `.env` 中配置（**必须用正斜杠**）：

```ini
EMBEDDING_MODEL_PATH=D:/模型/bge-m3
RERANKER_MODEL_PATH=D:/模型/bge-reranker-v2-m3
```

> ⚠️ **路径必须用正斜杠**。写成 `D:\模型\bge-m3` 时，`\b` 会被 `.env` 解析为退格符，导致路径错误、模型加载失败。

## 4. MinerU 中文路径补丁（**本机必做**）

### 问题现象

```
DetectError: Failed to load FastText model:
C:\Users\雨子\...\fast_langdetect\ft_detect\resources\lid.176.ftz
cannot be opened for loading!
```

### 原因

fasttext 的 C 扩展在 Windows 上**打不开含非 ASCII 字符的路径**，而本机用户名是「雨子」，Python 的 user-site 包路径因此含中文。这与 MinerU 权重、PDF 路径都无关。MinerU 的 CLI 会用 `multiprocessing spawn` 起子进程，所以**在调用进程里 monkeypatch 无效**，必须通过 `PYTHONPATH` 让子进程也加载补丁。

### 已落地的修复

`C:\mineru_models\langfix\` 下已有：

1. `lid.176.ftz` —— 模型文件的纯 ASCII 路径副本；
2. `sitecustomize.py` —— 用 `sys.meta_path` 导入钩子，在 `fast_langdetect.ft_detect.infer` 加载后把 `LOCAL_SMALL_MODEL_PATH` 改写到 ASCII 路径。

### 使用方式

`start.bat` 已自动注入，等效命令：

```bat
set PYTHONPATH=C:\mineru_models\langfix;%PYTHONPATH%
set MINERU_MODEL_SOURCE=modelscope
```

### 未配置的后果

MinerU 会失败，系统**自动降级**为 pymupdf + pdfplumber。功能不中断，但表格结构精度下降——招股书里"募集资金投资（万元）""军用领域收入"这类关键数字都在表格中，降级会明显影响答题准确率。任务状态中会标注 `parser=fast`。

### 另一个 MinerU 坑（代码已处理）

MinerU 的 `content_list.json` 里**表格内容存在 `table_body`（HTML）字段，`text` 字段为 `None`**。只读 `text` 会丢掉全部 502 张表。本项目在 `app/rag.py::_blocks_from_content_list` 中显式取 `table_body` 并转成 `行 | 行 | 行` 的纯文本。

## 5. 启动依赖服务

### 5.1 Redis

本机为 Windows 原生服务：

```bat
sc query Redis
net start Redis
```

> **Redis 5 不支持 RESP3**，`redis-py` 8.x 默认发送 `HELLO` 命令会报 `unknown command 'HELLO'`。本项目在 `.env` 中通过 `REDIS_PROTOCOL=2` 强制 RESP2，代码已处理。

### 5.2 Milvus

```bat
docker compose -f deploy\docker-compose.yml up -d
docker compose -f deploy\docker-compose.yml ps
```

三个容器：`rag-etcd`（元数据）、`rag-minio`（对象存储）、`rag-milvus`（本体，19530/9091）。

首次冷启动约需 **90 秒**，看到 `rag-milvus` 状态为 `(healthy)` 即可。

**Docker 不可用怎么办？** 不启动即可。`app/store.py::get_milvus()` 会先尝试 `MILVUS_URI`，连不上自动降级到 milvus-lite 本地文件库（`data/milvus/lite.db`），功能完整、性能略低。

## 6. 配置 DeepSeek

**新环境第一步：先有 `.env` 这个文件。**
`.env` 含密钥、已被 `.gitignore` 排除，所以**从版本库克隆出来的机器上是没有它的**，
文档里"编辑 `.env`"在新机器上是悬空的。仓库根目录提供了模板，复制一份即可：

```bat
copy .env.example .env
```

然后编辑 `.env`（模板内每一项都带注释，含模型路径、Milvus/Redis 地址、检索参数）：


```ini
LLM_API_KEY=sk-xxxxxxxxxxxxxxxx        # 你的 DeepSeek Key
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-v4-flash
```

> 代码优先读取系统环境变量 `DEEPSEEK_API_KEY`，未设置时回退到 `.env` 的 `LLM_API_KEY`。
>
> **本项目 `.env` 中的 Key 来源说明**：取自本机 `专高六/liu-专高六/电力维修RAG项目/.env`（用户自己的另一个项目），实测可用。生产部署请替换为自己的 Key。

验证 Key 可用：

```bat
curl -X POST https://api.deepseek.com/v1/chat/completions ^
  -H "Authorization: Bearer sk-xxxx" -H "Content-Type: application/json" ^
  -d "{\"model\":\"deepseek-v4-flash\",\"messages\":[{\"role\":\"user\",\"content\":\"ok\"}]}"
```

## 7. 建立索引

```bat
:: 把 PDF 放到 data/uploads/ 下（仓库已放置 招股说明书1.pdf）
python scripts/build_index.py --pdf "data/uploads/招股说明书1.pdf"
```

预期输出（本机实测）：

```
[1/4] 开始解析：招股说明书1.pdf（MinerU=开启）
      解析器=mineru，块数=4174，耗时=0.1s          ← 首次为 15~25 分钟，之后复用产物
[2/4] 语义分块中（调用 bge-m3 计算句间相似度）…
      分块数=1093（其中表格 542 块），耗时=35.3s
[3/4] 向量化并写入 Milvus…
      写入 1093 条，doc_id=d9189c37185596a2，耗时=36.2s
[4/4] 完成。知识库现有文档：
      招股说明书1.pdf  分块=1093  最大页码=547  表格=542
总耗时 71.2s
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--no-mineru` | 跳过 MinerU，用 pymupdf 快速解析（约 1 分钟） |
| `--drop` | 重建 collection（清空全部向量） |
| `--pdf <路径>` | 指定其它 PDF |

> **解析产物复用**：若 `data/parsed/<文件名>/` 下已有比 PDF 更新的 `*_content_list.json`，脚本会直接复用、跳过 MinerU，二次建索引只需约 1 分钟。

## 9. 生产部署建议

| 项 | 建议 |
|---|---|
| 进程管理 | 用 `nssm` 把 uvicorn 注册为 Windows 服务，或 `waitress`/`gunicorn` 多 worker |
| 并发 | 当前单进程 + 线程池（FastAPI 默认 40 线程）足够本机演示；高并发需给 GPU 加锁或部署多个推理实例 |
| 反代 | Nginx 反代 8000 端口，注意为 `/api/chat/stream` 关闭 `proxy_buffering`（SSE 需要） |
| Milvus | 生产建议改用 Milvus 集群版，并把 `consistency_level` 按需下调以换取吞吐 |
| 密钥 | `.env` 不要提交到版本库；改用系统环境变量注入 |
| 日志 | 当前输出到控制台，生产建议重定向到文件并做轮转 |
