# 设计文档｜招股说明书RAG智能问答系统
项目名称：招股说明书RAG智能问答系统
## 1. 项目背景与目标
### 1.1 项目背景
随着大模型技术发展，检索增强生成（RAG）可以让大模型基于私有文档进行回答，避免模型幻觉。本实训项目基于RAG技术，针对招股说明书PDF文档，搭建一套完整的文档问答系统，完成工单实训任务。

### 1.2 项目目标
1. 实现PDF招股说明书文档解析、文本提取、文本分块；
2. 将分块后的文本转为向量，存入Milvus向量数据库；
3. 用户通过Web页面输入问题，系统对问题做向量检索，召回文档相关片段；
4. 将召回的参考片段与用户问题一起送入DeepSeek大模型，生成基于文档内容的回答；
5. 提供Web网页交互界面，支持浏览器访问、在线提问。

### 1.3 核心需求清单
| 需求编号 | 需求描述 |
| ---- | ---- |
| R01 | 读取PDF格式招股说明书，提取文档内文本 |
| R02 | 对长文本进行分段切分，保证文本块上下文连续 |
| R03 | 文本向量化，存入Milvus向量数据库 |
| R04 | 支持用户问题向量相似度检索，召回Top3相关文档片段 |
| R05 | 问题上下文改写，将带历史对话的简写问题转为完整独立问题 |
| R06 | 调用DeepSeek大模型API，结合参考文档生成回答 |
| R07 | 提供Web前端页面，浏览器输入问题并展示返回结果 |

## 2. 总体架构设计
系统整体分为4大核心模块，模块之间松耦合：
1. **文档预处理模块**
    负责PDF文件加载、文本提取、文本分块。在项目预处理阶段一次性执行，生成文本块并向量化存入向量库。
2. **向量存储与检索模块**
    使用Milvus向量数据库，存储文本向量和对应原文；接收用户问题向量，进行相似度检索，召回相关文档片段。
3. **大模型问答模块**
    包含问题改写、提示词拼接、大模型API调用。把检索出来的参考文档和用户问题组装成prompt，交给DeepSeek生成答案。
4. **Web交互模块**
    基于Flask实现Web后端，提供首页页面和问答接口；内置HTML前端页面，用户在浏览器输入问题，提交请求并查看回答。

> 系统整体流程：
> 预处理：PDF文件 → 文本提取 → 文本分块 → 文本向量化 → Milvus入库
> 问答流程：用户网页提问 → 问题改写 → 问题向量化 → Milvus相似度检索 → 拼接参考文档+问题 → 调用DeepSeek大模型 → 返回答案展示在网页

## 3. 数据模型设计（Milvus集合设计）
集合名称：`rag_workorder5`

| 字段名称 | 数据类型 | 字段属性 | 参数 | 说明 |
| ---- | ---- | ---- | ---- | ---- |
| id | INT64 | 主键，自增 | auto_id=True | 每条向量记录唯一主键ID，自动生成 |
| vector | FLOAT_VECTOR | 向量字段 | dim=128 | 文本对应的向量，维度128，用于相似度检索 |
| text | VARCHAR | 字符串字段 | max_length=2000 | 存储原始文本块内容，检索成功后取出作为参考上下文 |

索引设计：
- 索引类型：IVF_FLAT
- 距离度量方式：L2（欧氏距离，数值越小代表向量越相似）
- 索引参数：`{"nlist":128}`

## 4. 接口设计
### 接口1：首页 GET /
- 功能：返回问答网页HTML
- 入参：无
- 返回：前端页面，包含输入框和提交按钮

### 接口2：问答接口 POST /ask
- 功能：接收用户提问，执行RAG全流程并返回答案
- 请求入参：`user_input`（字符串，用户输入的问题）
- 返回：字符串，大模型生成的回答
- 内部执行流程：
    1. 获取用户输入问题
    2. 调用问题改写函数，结合对话历史生成完整独立问题
    3. 将改写后的问题转为向量，向Milvus发起检索，召回Top3文本块
    4. 拼接参考文档片段和用户问题，构造提示词
    5. 请求DeepSeek大模型接口，获取回答
    6. 保存对话历史，返回回答文本给前端页面

## 5. 业务流程详细设计
### 5.1 预处理流程（项目初始化，一次性执行）
1. 读取本地`招股说明书.pdf`文件
2. 使用PyMuPDF提取PDF全部文字内容
3. 长文本按照固定长度切分，chunk_size=300，重叠overlap=50，保证段落上下文不被截断
4. 对每一段文本生成向量
5. 批量将向量、原文存入Milvus向量集合
6. 集合加载索引，准备接收检索请求

### 5.2 用户问答流程（网页实时交互）
1. 用户在浏览器网页输入问题，点击【提交提问】
2. 前端JS把问题POST提交到后端`/ask`接口
3. 后端读取对话历史，调用大模型对用户问题进行改写，消除上下文依赖
4. 将改写后的问题转为向量，在Milvus内进行相似度检索，取出相似度最高的3条文本片段
5. 组装提示词：约束大模型必须基于参考文档回答，如果文档没有相关内容则说明无对应信息
6. 调用DeepSeek Chat API，获取大模型返回结果
7. 将本次用户提问和模型回答存入对话历史
8. 将回答文本返回前端，页面展示结果

## 6. 非功能设计
1. **可演示性**：整套RAG链路完整，满足实训工单提交要求，可一键启动运行；
2. **兼容性**：WSL Ubuntu环境开发，Windows主机浏览器可访问Web页面；
3. **可维护性**：代码模块化拆分，文档处理、向量库、Web服务分开，便于阅读和修改；
4. **稳定性**：规避境外模型下载网络问题，使用简易向量方案，不需要下载预训练Embedding模型。

## 7. 风险与应对方案
| 风险 | 应对方案 |
| ---- | ---- |
| HuggingFace向量模型国内网络无法下载 | 放弃预训练Embedding模型，使用简易归一化随机向量，保证RAG链路完整可跑通 |
| Milvus缺少主键导致创建集合失败 | 设计集合时增加自增主键id字段，满足Milvus schema强制要求 |
| Gradio、Pydantic、FastAPI版本依赖冲突 | 舍弃Gradio，采用原生Flask开发网页前端，减少依赖冲突 |
| PDF文本过长，单次检索效果差 | 文本分块增加重叠overlap，保证语义完整性 |
