# 基于 RAG 的多角色扮演系统 - 需求规格说明书

## 一、项目背景

本项目基于 RAG（检索增强生成）技术，构建多角色扮演系统。用户可与不同领域角色
（律师、医生、心理咨询师、金融理财师、英语老师、虚拟朋友等）对话，系统从对应知识库
检索资料，结合大模型生成专业回答，并具备多轮记忆、知识库动态更新与运维可视化能力。

## 二、功能需求

### 2.1 核心功能

| 功能 | 说明 |
|---|---|
| 多角色扮演 | 10 个预置角色，支持动态创建，角色绑定知识域 |
| 知识库检索 | 混合检索（向量+BM25）+ 多路召回 + 重排序 |
| 多轮对话 | Redis 短期记忆 + MongoDB 长期记忆 |
| 多用户 | user_id 隔离会话 |
| 文档入库 | 多引擎解析、清洗、分块、向量化、入库 |
| 知识库管理 | 上传、批量入库、文档列表、删除、动态更新 |
| 运维可视化 | Redis 与 Milvus 监控面板 |
| 流式输出 | `/chat_stream` 逐字返回 |

### 2.2 业务流程（在线问答）

1. 用户提问
2. 查询改写 / 扩写（多查询）
3. 多路召回：Milvus 向量 + BM25 + Redis + MongoDB + Neo4j + MySQL
4. RRF 融合 + 去重 + 相似度阈值过滤
5. BGE-reranker 精排
6. 拼角色提示词 + 上下文
7. 大模型生成（可流式）
8. 后处理 + 引用校验
9. 写回短期记忆 / 热问题 / 缓存
10. 返回用户

### 2.3 业务规则

1. 回答应依据知识库资料，不编造事实与法条
2. 律师角色须引用具体法条并提醒咨询当地执业律师
3. 医生/心理/金融等角色须给出免责声明与边界
4. 对话历史保留最近 N 轮（默认 10 轮），1 小时过期
5. 历史过长时压缩为长期记忆摘要

## 四、技术组件

FastAPI、Streamlit、Milvus、Redis、MySQL、MongoDB、BGE-m3、BGE-reranker、
多方大模型（DeepSeek/千问/豆包/本地 vLLM 等）、RAGAS。

## 五、非功能需求

- 响应时间：单次问答目标小于 30 秒（受大模型与重排影响）
- 并发：支持多用户并发，可横向扩展
- 日志：统一 logging 记录请求与错误
- 可扩展：新增角色 / 知识库仅需配置或入库，不改核心代码
- 可配置：多环境（dev/test/prod），密钥外置
- 可观测：Redis 与 Milvus 可视化监控
