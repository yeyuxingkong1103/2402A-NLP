# 容错机制清单与长时间运行方案（工单07 · 硬性要求7）

> **工单编号**：人工智能NLP-RAG-功能测试及评估
> 说明：下表**只列本工程真实存在并已实测的机制**。标注「实测」的条目在本工单执行过程中
> 确实被触发或验证过；未触发的机制标注「未触发（已就位）」，不做无根据的承诺。

## 一、容错机制清单

### 1. 附件解压失败（`ccf_competition.zip`）

| 失效场景 | 机制 | 状态 |
| --- | --- | --- |
| zip 文件缺失 | `setup_project.py` 检查存在性，报"缺少附件 …"并以**退出码 1** 结束，不继续建库 | 已就位 |
| 条目名中文乱码 | 按 ZIP 规范 `cp437→gbk` 还原；解码失败（`UnicodeEncodeError`/`UnicodeDecodeError`）则**原样保留**该条目名并计入"跳过"，不中断 | 实测（20 条目全部还原成功） |
| 文件名不符合预期格式 | `_ORIG_RE` 不匹配 → 计入 `skip` 计数，**不静默丢弃**（打印跳过数） | 已就位 |
| 解压中断/磁盘满 | 逐文件 `copyfileobj`，单文件异常向上抛出；脚本幂等，**重跑即续**（同名覆盖） | 已就位 |
| 目录项（结尾 `/`） | 显式跳过，不当文件处理 | 实测（20 条目 = 18 文件 + 2 目录） |

### 2. `sample_questions.pdf` 解析失败

| 失效场景 | 机制 | 状态 |
| --- | --- | --- |
| 文件缺失 | `setup_project.py` 报"缺少 data/corpus/sample_questions.pdf"并计入失败清单 | 已就位 |
| 解析异常 | 10 个问题已**落盘为 `data/test_questions.json`**，测试流程**不依赖运行时解析 PDF**；即附件损坏也不阻塞评估 | 设计上解耦 |
| 问题提取口径追溯 | 问题清单与金标准分离：`test_questions.json`（题面）+ `data/eval/ground_truth.json`（金标），后者由 `scripts/grep_corpus.py` 逐条回原文核对 | 实测 |

### 3. 问题提取失败

| 失效场景 | 机制 | 状态 |
| --- | --- | --- |
| 金标缺失 | `evaluate_retrieval.py::evaluate` 检测到缺金标 → 打印 `id=N 缺金标，跳过` 并继续其余题，**不编造金标** | 已就位 |
| **金标写错（转述/过泛）** | `scripts/validate_ground_truth.py` 逐条 `evidence_fact` 统计全语料命中：0 命中 → 报错退出；>200 命中 → 报"过泛" | **实测（首轮发现 6 条 0 命中 + 2 条过泛并修正）** |
| 页号口径不符 | 自检脚本逐题核对 `page_hints`，未命中即打印告警 | 实测（id3 第13页因表格单元格写作"0.86"无百分号，已在 `page_note` 注明） |

### 4. RAG 系统调用失败

| 失效场景 | 机制 | 状态 |
| --- | --- | --- |
| **文档路由误判** | `rag.retrieve`：路由后候选 < `RERANK_INPUT_TOP_K` 时**自动放开过滤全库重检**（`DOC_ROUTER_FALLBACK_OPEN=True`），并在 `analysis.doc_route.fallback_opened` 留痕 | 已就位（本工单 10 题未触发开通） |
| 路由构造失败 | `doc_router.build_filter` 抛异常 → 退化为**不过滤**（全库检索），不中断 | 已就位 |
| **Reranker 加载/推理失败** | 进入**冷却期**并在界面/报告中**如实标注降级**（`rerank_info.degraded`），**绝不假装精排过** | 已就位（本工单全程未降级） |
| 精排超时 | `RERANK_TIMEOUT_S=8.0` 单次超时 → 降级返回召回序 | 已就位 |
| **LLM 幻觉数字** | `rag.py` 内置**数字校验**：答案中的数字必须能在上下文中找到（或由两个上下文数字一步运算得出，且两数取自同一片段），否则触发重生成/兜底 | 已就位 |
| LLM 服务不可用 | Ollama 超时（`LLM_TIMEOUT_S=120`）→ 回退 `qwen2.5:0.5b`；仍失败则返回 `mode="error"`，**不返回编造答案** | 已就位 |
| Query 改写失败 | 分级降级：L2 实体判定 → L3 生成 → **L4 规则兜底**；改写超时 8s | 已就位 |
| 回答无法从上下文得出 | 提示词强制"根据已有资料无法确定"，而非编造 | 实测（id10 即返回"未提及…"，未编造板块名） |

### 5. 评估框架调用失败

| 失效场景 | 机制 | 状态 |
| --- | --- | --- |
| RAGAS 卸载/导入失败 | `evaluate_ragas.py` 捕获导入异常并给出明确报错与非 0 退出码 | 已就位 |
| **裁判 LLM 缺失** | `_check_judge()` 预检；缺失 → 明确报错并**退出码 1**（不产出"全 0 分"的假报告） | 已就位 |
| 裁判 embedding 缺失 | `answer_relevancy` 无法算 → **跳过该指标并在结果中标注原因**，其余指标照常 | 已就位 |
| 单题评判异常 | 逐题 try/except，失败题记入 `errors[]` 与 `_failed_questions`，**不影响其余题** | 已就位 |
| 重复评判耗时 | 两阶段落盘：先 `ragas_answers.json` 存（问题/答案/上下文），`--reuse-answers` 可**只重跑评判不重新问答** | 实测（本工单复用该机制） |
| 指标口径不透明 | 指标实现复用上游 `evaluate_retrieval.py` 的函数，**不另写一套** | 实测 |

### 6. 模型加载失败

| 失效场景 | 机制 | 状态 |
| --- | --- | --- |
| **静默下载** | `src/bootstrap.py` 在进程最早期置 `HF_HUB_OFFLINE=1` / `TRANSFORMERS_OFFLINE=1` / `HF_DATASETS_OFFLINE=1` / `MODELSCOPE_OFFLINE=1`；所有 `from_pretrained` 显式 `local_files_only=True` → **漏写离线参数的调用会直接失败，而不是偷偷联网** | 实测（全程零下载） |
| 模型缺失 | `scan_local_models.py` 先扫描并输出缺口清单（硬性要求0）；**本机四类角色零缺口**，未触发下载询问 | 实测 |
| GPU 不可用 | `EMBEDDING_DEVICE="cuda"` 不可用时自动回退 CPU | 已就位 |
| **Windows 导入期栈溢出** | `bootstrap.py`：①预热 `pandas/sklearn/scipy` 断开循环导入链；②`run_with_large_stack()` 把各入口放到 **16 MB 大栈线程**执行（主线程仅 ~1 MB，实测会段错误） | 已就位（所有入口均走该包装） |
| BLAS 线程吃内存 | `OMP_NUM_THREADS` 等 5 个变量统一限为 4，避免 OpenBLAS 分配失败 | 已就位 |
| 模型加载显存不足 | Reranker 支持 fp16 + 3 个模型副本可按名切换（`bge-reranker-v2-m3` / `-ms` / `base`），大模型失败可切 base | 已就位 |

### 7. 本工单实测遇到并已解决的问题（真实记录）

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| **控制台 GBK 编码** | 中文输出抛 `UnicodeEncodeError: 'gbk' codec can't encode character '\xa0'` | 全程 `PYTHONIOENCODING=utf-8` + 写入 UTF-8 文件后再读；`evaluate_ragas.py` 自带 `stdout.reconfigure(errors="replace")` |
| **表格结构错乱** | PyMuPDF 默认策略把年报表格压成 2~3 列，行值错位（表格题必错） | 改用 `strategy="text"` + 网格清洗 + 单位抽取（详见 `docs/03`） |
| **Qdrant 关闭告警** | 进程退出时 `QdrantClient.__del__` 报 `ImportError: sys.meta_path is None` | **无害**：解释器关闭阶段的析构告警，退出码为 0、数据已落盘（`points: 7225` 已确认）。不影响结果 |
| **金标准口径错误** | 首轮 6 条 0 命中 + 2 条过泛，会使指标假性偏低 | 新增 `validate_ground_truth.py` 作为评估前闸门并修正金标 |
| **表格数字被切散 / 双栏正文被误判为表格** | `strategy="text"` 的副作用（42/2101 表块数字切碎；双栏正文成假表） | 见 `docs/03` 末节，已修 |
| **Windows 段错误（stack overflow）偶发** | 实测一次**连续 3 个进程全部 exit 139**（崩溃点在 reranker 加载后）；紧接的 5 次重跑**全部成功** | 属 `src/bootstrap.py` 已记录的**间歇性**栈溢出（文档原文："实测同一条命令多次运行，仍会偶发"）。诱因为连续启停进程时的显存/内存压力。**处置：重试即可，非代码缺陷**；批处理建议每次运行间留间隔（实测 `sleep 5` 后 5/5 通过） |
| **数值校验拒绝后退化为"摘录原文"** | 端到端问答偶见答案形如 `【片段1】来源：…第20页（2019年，集团实现…`，即**不是回答问题，而是贴出上下文片段**。`timings` 显示 `retry_rejected: True` + `numeric_patch: True` | 这是**防幻觉机制按设计生效**：LLM 首答的数字未在上下文中找到 → 拒绝 → 重试仍不合规 → 用原文片段兜底。**宁可不可读，也不编造数字**。副作用是答案可读性下降、可能不正面回答问题，属当前提示词与校验强度的权衡，已记入 `docs/06` 改进项 |

## 二、长时间运行方案

本工单在**本机规模**（2812 页 / 7225 块 / 10 题）下全流程约 **10 分钟**（解析 4.8 分 + 建索引
2.7 分 + 三策略问答 ~2 分 + RAGAS ~4 分），不属于长任务。但工单要求给出长跑方案，
以下为**面向更大语料/持续服务**的已就位能力与建议：

### 1. 日志与留痕

| 机制 | 落地 |
| --- | --- |
| 分阶段日志落盘 | 所有耗时步骤写 `logs/*.log`（`build_parse.log` / `build_embed.log` / `run_*.log` / `ragas_*.log`），tee 到控制台 |
| 逐题留痕 | `data/eval/rag_results_<strategy>.json` 保存每题完整片段原文、名次、分数、耗时——**任何指标都能事后复算**，不必重跑 |
| 中间产物落盘 | 解析→`data/chunks/chunks.json`；表格→`data/tables/`；RAGAS 两阶段→`data/eval/ragas_answers.json`（可 `--reuse-answers` 复用） |
| 进度可观测 | 解析逐 50 页打印；建库按文档分节打印块数；RAGAS 用 tqdm 显示 `n/40` |

**建议（生产环境）**：日志按天/按大小轮转（`logging.handlers.TimedRotatingFileHandler`），
本工程当前为一次性批处理，未引入轮转。

### 2. 内存与显存监控

| 机制 | 落地 |
| --- | --- |
| BLAS 线程限制 | `OMP_NUM_THREADS` 等 5 个变量 = 4，避免每核一线程造成内存放大 |
| 大栈但不过大 | 线程栈固定 **16 MB**（实测 64 MB 会抬高提交内存并引发 OpenBLAS 分配失败） |
| 分批向量化 | `EMBEDDING_BATCH_SIZE=32`，7225 块分 226 批，峰值显存可控 |
| 解析器内存 | PyMuPDF 逐页处理，单文档 235—421 页峰值稳定 |

**建议（生产环境）**：接入 `psutil` 定时采样 RSS/显存并落指标；对超长 PDF 按页区间分片解析。

### 3. 异常重启与断点续跑

| 机制 | 落地 |
| --- | --- |
| **幂等入口** | `setup_project.py` 可重复运行（同名覆盖）；`build_index.py --rebuild` 才重解析，否则**复用 `data/chunks/chunks.json`** |
| **阶段解耦** | 解析 / 建索引 / 问答 / 评估四阶段各自独立命令，任一段失败**只需重跑该段** |
| 单题隔离 | 评估逐题 try/except，单题失败不拖垮整轮；失败题记入 `errors[]` |
| 缓存复用 | 答案缓存（`ANSWER_CACHE_SIZE=128`）+ 改写缓存 + VLM 描述缓存，重启后仍有效 |

**建议（生产环境）**：用 `supervisord`/`nssm` 守护 Streamlit 与 Qdrant server；
`QDRANT_MODE` 由 `local` 切 `server`（**注意**：local 嵌入式模式**同一存储目录只能被
一个进程占用**，多进程并发必须切 server 模式——这是本工程已实测的硬约束）。

### 4. 数据安全

| 机制 | 落地 |
| --- | --- |
| 不覆盖原始附件 | `ccf_competition.zip` 与解压目录只读使用；规范化副本写 `data/corpus/` |
| 旧文件不删除 | 版本更迭产生的过期同名副本由 `setup_project.py --stale-to` **挪到 `_stale/`**，而非 `rm`，保留人工回溯能力 |
| 金标准闸门 | 评估前强制跑 `validate_ground_truth.py`，避免"用错金标得出错误结论"这类不可逆的分析污染 |
