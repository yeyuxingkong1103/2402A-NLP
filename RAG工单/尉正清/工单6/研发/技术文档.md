## 三、核心实现要点

### 1. 去除页眉页脚（影响检索准确率）

招股书每页页眉都是「公司名 + 招股意向书」。实测 1396 个文字块中有 **548 个（39%）以公司名开头**，而工单的 10 个问题全都含公司名——等于近四成的块都吃到同等匹配加分，排序被拉平。实测表现为：问"注册资本"，Top1 命中的是**子公司**的 100 万元，正确答案 5,520 万元掉到第 3~4 位。

`document._strip_repeats()` 统计出现在 30% 以上页面里的行并删除，同时过滤纯页码行。

### 2. Query 理解用规则而非大模型

原实现调用大模型做意图识别与重写，单这一项就要 **3~10 秒**，直接超过工单 3 秒的响应要求。改为规则实现后耗时接近于 0：

- **意图识别**：按关键词表匹配（数据查询 / 事实查询 / 关系查询 / 比较查询）
- **消歧**：内置本领域歧义词词典（报告期、注册资本、公司、收入、上游、下游），把澄清说明追加到检索查询上
- **分解与抽象**：出现「分别 / 各自」等并列标志时按连词拆分，并给子问题补全主语

### 3. RRF 混合检索

BGE-M3 的稠密分（余弦，约 0.3~0.8）与稀疏分（词权重，约 0~0.2）量纲不同。若直接把稀疏分按最大值归一化后加权，一个只有 0.141 的弱匹配会被抬成满分 1.0，贡献 `0.3×1.0=0.3` 分，超过稠密向量整段的区分度（约 0.19），无关块会被顶进 Top-K。

改用 RRF：`分数 = 0.7/(60+稠密名次) + 0.3/(60+稀疏名次)`，只与名次有关，与分数量纲无关。

### 4. 大模型调用失败必须抛异常

原实现把超时、HTTP 错误转成 `"[LLM 调用超时...]"` 字符串正常返回，上层无法区分"回答"和"错误"，报错文案会被当成答案一路传到界面，甚至进入评估模块参与打分。现改为抛出 `LLMError`，由界面捕获后单独提示。

### 5. `max_tokens` 必须给足

`deepseek-flash` 是**推理模型**，reasoning token 先消耗额度。上下文较长时 reasoning 能吃掉上千 token，若 `max_tokens` 给小了，正文会返回**空字符串**。实测 1024 在真实上下文下会返回空，故设为 4096。

### 6. 两阶段检索（工单2 新增）

召回与精排分离，由 `RECALL_K` / `TOP_K` 独立控制：

```
问题 ──> 粗排召回 RECALL_K=20 个候选（BGE-M3 稠密+稀疏 RRF 融合）
          └─> 精排（可选，默认关闭）──> 取 TOP_K=8 个送入大模型
```

重排序用 `bge-reranker-v2-m3` 交叉编码器，并对送检正文做截断
（`RERANK_MAX_CHARS=400`），把 20 个候选的打分耗时从 0.96 秒降到 0.51 秒。

**⚠️ 该功能默认关闭**：实测在本任务的财务表格上，交叉编码器会系统性地把
「语义相近的散文」排在「真正含答案的表格」之前，导致准确率 100%→90%、
精确率 22%→19%、最慢响应 2.2 秒→11.5 秒。完整实验数据见
`优化/优化方案与对比.md`。换用叙述型文档时可打开开关重新评估。

### 7. 并发与资源保护（工单2 新增，对应「高并发稳定运行」验收项）

- **GPU 前向串行化**：BGE-M3 与重排序模型同时常驻显存（约 3.2GB / 6GB），
  用 `threading.Lock` 把 GPU 前向串行化。接口层仍可并发，只有真正落到 GPU
  的那一步排队。
- **请求队列**：Gradio `queue(max_size=32, default_concurrency_limit=4)`。

### 8. 表格解析（工单3 核心）

招股书的关键数据几乎都在表格里（发行情况、募集资金用途、关联方持股）。
但**纯文字提取会把表格打散成互不相干的单元格**，而表格块本身又只有
「赵马克 | 42.35% | 公司控股股东」这样的内容 —— **关键词「关联方」在标题里**。

三项处理（详见 `优化/表格解析优化说明.md`）：

1. **清理空行空列**：pdfplumber 会因版面空白切出大量空列，p157 关联方表被切成
   9 列、其中 6 列全空。清理后表格块体积平均减少 16%。
2. **表格块补标题**：用表格边框定位，裁出上方最近 2 行文字作为标题拼在表格前。
   实测 p157 关联方表的检索名次从第 10 名提升到第 2 名。
   两个坑：一页多表时要以上一张表的底边为下界；裁出的标题要滤掉页眉，
   且比对前必须做空白归一化（pymupdf 与 pdfplumber 的空格数不同）。
3. **多文档支持**：每份 PDF 单独建索引，公司名从开头三页自动提取；
   提问时按公司名路由到对应知识库（`MultiDocEngine`）。

### 9. 图像内容解析（工单4 核心）

招股书里的组织结构图、市场结构图，**数据不在文本层**：组织结构图的文字虽在文本层，
但被平铺成一串，看不出层级；市场结构图是位图，数值压根没有。这类问题靠文本检索
永远答不出来。

`image_parser.py` 把图表页渲染成 PNG，走 OpenAI 兼容接口的 `image_url`
（base64 data URL）交给多模态模型转写。三个要点：

1. **页面选择要收三类**：有较大位图的页；出现「结构图/示意图/如下图」字样的页；
   **以及后者的下一页** —— 招股书常把「如下图所示：」写在页尾、图放在下一页，
   漏掉这条会整整丢掉组织结构图。
2. **提示词明确要求层级与极值**：组织结构图要写「谁下面包含谁」，统计图要写
   最大值/最小值/增长最快项/负增长项，并要求看不清就写「不可辨认」、不许推测。
3. **增量缓存**：约 18 秒/页，结果按页落盘，重跑只补缺失页。

图像描述以 `{"type": "image", "page": N, "text": "【第N页 图表】..."}` 进入
**同一个向量索引**，与文字块、表格块同等参与检索，无需额外路由。

### 10. 多轮对话（工单5 核心）

连续追问里大量出现指代和省略，单轮系统直接拿去检索必然失败：

| 轮次 | 问句 | 问题 |
|---|---|---|
| 2 | **他**参与的哪个工程荣获了国家科技进步一等奖？ | 「他」是谁 |
| 3 | **这个公司**的法定代表人是谁？ | 「这个公司」是哪家 |
| 4 | **那武汉力源信息技术股份有限公司呢？** | 压根没说问什么 |

`dialogue.py` 用规则把这类问句改写成自足的独立问题，再用改写结果走正常检索。
四类策略按优先级：省略补全 → 原样 → 指代消解 → 话题延续。

**两个实测踩出来的细节**：

1. **省略补全必须排在「已点明主体」之前**。「武汉力源信息技术股份有限公司呢？」
   既出现公司名、又是省略追问；若先按「已点明主体」原样返回，就把「问什么」丢了。
2. **「呢」前面要判断是不是真问题**。「…的注册资本是多少呢？」含疑问词「多少」，
   是完整问题，不做省略补全。

改写用规则而非大模型：多一次大模型调用要 1.5~2 秒，叠加生成会突破 3 秒要求。

界面新增对话历史区（Gradio Chatbot）与清空对话按钮，元信息栏会写明每轮的改写过程。

### 11. 三种检索策略（工单6 核心）

把检索做成可配置、可切换的三种，界面可选：

| 策略 | 实现 |
|---|---|
| 向量检索 | BGE-M3 稠密+稀疏 RRF 召回，可选重排 |
| 全文检索 | 倒排索引（`fulltext.py`），支持布尔/短语/模糊、标题与正文双字段 |
| 混合检索 | 两路都跑，按 alpha（向量权重）融合，三种融合算法 |

**中文分词用字符二元组**而不是分词库：「军用领域」切成 军用/用领/领域，
检索时同样切即可对上，省掉一个依赖。

**重排算法 4 种**（`rerank.py`）：TF-IDF（本地毫秒级）、用户反馈自适应
（按历史 👍/👎 调权）、LLM 重排（最准但慢）、交叉编码器（工单2 引入）。

**融合三种**（`retrieval.py`）：加权平均（默认）、RRF 名次融合、投票制。

**实测结论**（16 题）：向量 100%/100%、全文 **81%/90%**、混合 **100%/100%**。
全文单用两项都不达标，混合后双双拉满 —— 两路互补，向量补语义、全文补词面。

## 四、开发流程

```
1. 环境准备      部署/install.sh        创建 conda 环境 + 装依赖 + CUDA 版 torch
2. 配置环境变量   DEEPSEEK_BASE_URL / DEEPSEEK_API_KEY / BGE_M3_PATH
3. 启动服务      部署/start.sh          浏览器打开 http://<ip>:7860
4. 初始化知识库  界面上传 PDF 并点击初始化（首次约 80 秒，之后走缓存约 10 秒）
5. 提问验证      界面提问，或用 `测试/eval_dialogue.py` 跑多轮对话验收
6. 跑评估        研发/evaluator.py      输出 RAG 与纯 LLM 的对比评估报告
7. 停止服务      部署/stop.sh
```

## 七、已知限制

1. 语音识别模型（whisper small）首次使用时会自动下载，需联网
2. 知识库缓存以 PDF 文件名称为键，换用同名但内容不同的 PDF 需要先删除旧缓存
3. Query 理解为规则实现，超出招股说明书领域的问法可能识别不准
