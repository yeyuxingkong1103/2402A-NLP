## 4. 环境变量（不改代码切换行为）

| 变量 | 作用 | 本机建议值 |
| --- | --- | --- |
| `RAG_LLM__BASE_URL` | LLM 服务地址 | `http://127.0.0.1:8000/v1` |
| `RAG_LLM__MODEL` | 模型名 | `Qwen3-0.6B`（联调） / `Qwen2.5-7B-Instruct-AWQ`（云端） |
| `RAG_LLM__MAX_CONTEXT_CHUNKS` | 送入 LLM 的片段数 | `3`（CPU）；云端 `0` 用默认 |
| `RAG_ASR__BACKEND` | 语音后端 | `api` / `local` / `auto` |
| `RAG_ASR__BASE_URL` | 语音服务地址 | `http://127.0.0.1:8001/v1` |
| `RAG_LANGUAGE__DEFAULT_ANSWER_LANGUAGE` | 回答语言 | `auto`（跟随提问）/ `zh` / `en` |
| `RAG_LANGUAGE__QUERY_BRIDGE` | 英文→中文检索方式 | `glossary`（默认，毫秒级）/ `model` |
| `RAG_RETRIEVAL__MIN_CONFIDENCE_COSINE` | 拒答阈值 | `0.55` |

示例：

```powershell
$env:RAG_LANGUAGE__DEFAULT_ANSWER_LANGUAGE = "en"   # 中文提问也回英文
pwsh -File 部署\run.ps1 ask "注册资本是多少？"
```

## 5. 本机性能实测（如实记录）

> 本机为 **RTX 2060（6GB 显存，算力 7.5）**，已安装 CUDA 版 torch
> （`2.6.0+cu124`，从 pip 缓存离线安装，见 `设计/规格说明/install_cuda_torch.py`）。
> 因此 LLM 推理走 **GPU**，不再受 CPU prefill 拖累。

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| **抽取式首字** | **0.8~2.5 ms** | 确定性路径，达标（< 3 秒） |
| **LLM 流式首字** | **1.27~1.72 秒** | GPU（RTX 2060 + Qwen3-0.6B），**达标** |
| LLM 流式端到端 | 3.9~4.2 秒 | 生成 17~18 个 delta |
| 中文 10 题准确率 | **100%** | 抽取式路径 |
| 英文 5 题准确率 | **100%** | 跨语言桥接 |
| 引用正确率 | **100%** | 逐条校验 |
| 语音转写 | 1.0~1.6 秒 | whisper-tiny |
| GPU prefill（8 片段/3818 字符） | **1.94 秒** | 同条件下 CPU 需 **18.2 秒**，相差 9.4 倍 |

**设备与显存**：`Qwen3-0.6B` 以 float16 加载，占用显存约 1.2GB / 6GB，
剩余空间足够跑更大模型。若换用 7B 量化模型（约 4.5GB 权重），
6GB 显存会比较紧张，建议在 4090 上跑 7B、本机跑 0.6B~3B 做联调。

**查看 GPU 是否真的在用**：

```powershell
nvidia-smi --query-gpu=name,memory.used,memory.total,utilization.gpu --format=csv
```

**切换回 CPU**（对比测试用）：

```powershell
pwsh -File 部署\run.ps1 llm --device cpu
# 注意：CPU 上首字会退化到 5~18 秒，属预期
```

### 5.1 如果 GPU 不可用

```powershell
# 1) 确认驱动与设备
nvidia-smi

# 2) 确认 torch 是 CUDA 版（应为 True）
python -c "import torch;print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
```

若 `available` 为 `False`，说明装的是 CPU 版 torch。
本机 PyPI 镜像不可达，无法在线安装；可从 pip 缓存离线安装：

```powershell
python 设计\规格说明\install_cuda_torch.py --dry-run   # 先看会做什么
python 设计\规格说明\install_cuda_torch.py             # 实际安装（约 2.4GB 解包）
```

该脚本会自动备份原 torch 到 `site-packages/torch_cpu_backup`（可回滚），
并禁用与 CUDA torch ABI 不兼容的 `torchvision` / `torchaudio`
（改名为 `*.disabled`，文本生成不需要它们）。

## 6. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| **`OSError: [Errno 10048] ... bind on address ('127.0.0.1', 8000)`** | 端口已被占用（通常是上一次的服务没关）。**现已前置检查**，不会再白等模型加载：<br>• 已在运行 → 直接提示并正常退出，无需重复启动；<br>• 想换配置重启 → 加 `--force` 自动结束旧进程；<br>• 或换端口 `--port 8010` |
| `check` 显示「LLM 服务探测 → 未启动」 | 另开终端跑 `pwsh -File 部署\run.ps1 llm`；未启动时会自动降级为抽取式回答，功能不受影响 |
| 语音上传后提示「只支持 WAV」 | 本机没有 ffmpeg，mp3/m4a 无法解码。请用 WAV，或在算力云上用 `run_whisper.sh` |
| 界面首字几百毫秒但 LLM 模式要数秒 | 正常：抽取式毫秒级，LLM 依赖 GPU。启动日志会打印推理设备，`cuda:0` 才是用上了 GPU |
| 报告写不进 `优化/评估结果/` | 该目录由 `settings.paths.eval_results` 决定，可用 `RAG_PATHS__EVAL_RESULTS` 覆盖 |
| 端口被占用（手动排查） | `netstat -ano \| findstr :8501` 找到 PID 后 `Stop-Process -Id <PID> -Force` |

### 6.1 服务已在运行时如何重启

```powershell
# 方式一：自动结束旧进程并用新配置启动（推荐）
pwsh -File 部署\run.ps1 llm --force
pwsh -File 部署\run.ps1 asr --force

# 方式二：先全部停掉，再按需启动
Get-Process python -ErrorAction SilentlyContinue |
  Where-Object { $_.Path -like "E:\gao6gongdan\工单1*" } |
  Stop-Process -Force
pwsh -File 部署\run.ps1 llm
pwsh -File 部署\run.ps1 asr
```

> 端口预检逻辑见 `研发/scripts/port_utils.py`：它在**加载模型之前**检查端口，
> 并区分「本项目服务已在运行」（提示后正常退出，退出码 0）与
> 「被其它程序占用」（报错并给出占用 PID 与三种解决办法）。
| 报告写不进 `优化/评估结果/` | 该目录由 `settings.paths.eval_results` 决定，可用 `RAG_PATHS__EVAL_RESULTS` 覆盖 |
| 端口被占用 | `netstat -ano \| findstr :8501` 找到 PID 后 `Stop-Process -Id <PID> -Force` |
