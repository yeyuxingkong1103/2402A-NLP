## 2. 迭代一：为什么把学习率从 3e-5 降到 1e-5

**观察**（轮次1）：相似度指标全面变好，但检索指标变差——
- 正例对平均相似度 0.6205 → **0.3512**（−43.4%），负例对 0.5372 → 0.1860（−65.4%）；
- 相似度间隔 0.0832 → 0.1651（**+98.4%**），正负例判别准确率 0.7002 → 0.7559（+8.0%）；
- 但 Recall@1 0.1467 → **0.1000**，MRR 0.1850 → 0.1549，真题命中@1 0.294 → 0.118。

**根因分析**：正例的**绝对相似度被整体拉低**（0.62→0.35），说明模型把嵌入空间「撑开」了——
三元组损失（margin 0.3，余弦距离域）在 3e-5 学习率下把 anchor 推向正例、推离负例的同时，
也把所有文本的余弦相似度整体压缩。对**训练分布内**的短模板化查询，相对判别力确实变强（间隔翻倍）；
但工单7 的真题是**长句、多条款、跨指标**的复杂查询，属于训练分布的域外输入，
其向量被这种「撑开」效应带偏，导致 Top-1 命中从 5/17 掉到 2/17。

**结论**：这是典型的**小数据 + 小模型 + 高学习率**导致的表征漂移（representation drift），
而非数据或代码错误（防泄漏测试 0 命中，见 `测试/测试报告.md`）。

**对策**：降低学习率至 1e-5，缩短步数，让微调只做「轻微偏置」而非「重塑空间」。

## 3. 迭代二：学习率 1e-5（70 步）

结果（`研发/评估/评估结果_迭代2.json`）：
- Recall@5 0.2133 → **0.2267（+6.25%）**，Recall@10 0.2333 → **0.2467（+5.71%）**；
- 平均命中排名 386.5 → **305.4（改善 21.0%）**；相似度间隔 0.0832 → **0.1090（+31.0%）**，判别准确率 0.7002 → 0.7286；
- Recall@1 0.1467 → 0.1333（−9.1%），MRR 0.1850 → 0.1777（−3.9%），真题 MRR 0.420 → 0.305（−27.4%）。

对比轮次1：**所有指标都向基线回靠且部分反超**，验证了「漂移」假设。

**遗留问题**：70 步 × 批大小 12 ÷ 1400 三元组 = **0.60 个 epoch**，不满足工单「至少 1 个 epoch」要求。

## 4. 迭代三：学习率 1e-5，跑满 1 个 epoch（最终采用）

保持 1e-5，步数补到 117（× 批大小 12 = 1404 样本 ≈ 1.003 个 epoch），训练 221.8 s。
损失正常下降（0.401 → 0.267，−20.7%），末段相似度间隔 0.0997（日志 step 102）~0.15 区间波动。
最终模型的完整指标见 `优化/评估结果/对比表.csv` 与 `测试/测试报告.md`。

## 7. 未达成项与下一步方案（如实记录）

**未达成**：工单验收标准「微调后检索效果比微调前好」**只在部分指标上达成**
（Recall@5 / Recall@10 / 平均命中排名 / 相似度间隔 / 判别准确率提升；
Recall@1 / MRR / 真题命中率下降）。**不许编造提升**，此处明确记录。

**根因（按可能性排序）**：
1. **训练查询与真实查询的分布差**：训练查询是 28 字左右的模板化短问句，真题是 100+ 字的多条款复杂问句；
   微调只适配了前者，后者属于域外输入。
2. **数据规模过小**：1400 个三元组、9 份文档，不足以让 512 维空间学到稳健的领域几何。
3. **底座偏好**：bge-small-zh-v1.5 本身已在中文通用语料上对齐良好，其「实体+指标」区分力本就不差
   （真题命中@1 基线 0.294），微调的收益空间被压缩，而扰动风险更大。
4. **只有 1 个 epoch 且步数受限**：CPU 预算下无法做学习率扫描与早停选择。

**下一步方案（按性价比排序）**：
1. **用真题风格的长查询增强训练集**：把「指标+数值」模板扩展为多条款、跨指标的复杂问句（可用 qwen2.5:3b 生成，
   再用规则校验数值正确性），直接消除分布差。
2. **加入 in-batch 难负例**：配置已内置 `TripletLoss.hard_mining` 开关，打开后每步取 batch 内最难的负例，样本效率更高。
3. **早停 + 学习率扫描**：以留出集 MRR 为早停指标，在 {5e-6, 1e-5, 2e-5} × {40, 80, 120} 网格上选点（每点约 2 分钟，CPU 可承受）。
4. **换底座或加 LoRA**：`bge-base-zh-v1.5`（1024 维级）在 CPU 上训练成本约 ×3，若允许联网下载权重可尝试。
5. **重排兜底**：在检索后接一个 cross-encoder 重排，用少量标注数据微调重排器而非嵌入模型。
