# 用户手册

> 工单编号：**人工智能NLP-RAG-PDF文档的表格解析及检索优化**
> 适用对象：需要运行、演示或二次开发本工单功能的同学。

---

## 一、环境准备

### 1.1 依赖

在项目根目录（`工单作业/`）执行：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

本工单直接依赖：

| 依赖 | 用途 | 缺失后果 |
| --- | --- | --- |
| `pdfplumber>=0.11` | 表格抽取（核心） | 无法抽取表格 |
| `PyMuPDF` | 文本层解析 | 无法解析 PDF |
| `sentence-transformers` | BGE 向量嵌入 | 无法建向量索引 |
| `chromadb` | 向量库（缺失时自动降级为 NumPy 本地库） | 降级但不影响功能 |
| `jieba` | 中文分词（缺失时降级为单字+二元组） | 降级但不影响功能 |
| `fastapi` / `uvicorn` | Web 服务 | 无法启动 `serve.py` |
| `openai` | 调用 DeepSeek 生成答案 | 自动降级为抽取式作答 |

### 1.2 生成模型（可选）

```bash
# Windows (cmd)
set DEEPSEEK_API_KEY=sk-xxxxxxxx
# Windows (PowerShell)
$env:DEEPSEEK_API_KEY="sk-xxxxxxxx"
# Linux / macOS
export DEEPSEEK_API_KEY=sk-xxxxxxxx
```

**未配置也可以跑完整流程**：所有脚本会自动降级为「抽取式作答」
（把命中的表格/正文原文回填成答案），检索精确度与准确率指标照常计算。

### 1.3 PDF 素材

默认读取 `rag_core.config` 中登记的路径：

```
D:\工单\RAG 工单\RAG 工单\附件\招股说明书1.pdf     武汉兴图新科电子股份有限公司
D:\工单\RAG 工单\RAG 工单\附件\招股说明书2.pdf     武汉力源信息技术股份有限公司
```

路径不同时，用各脚本的 `--pdf` 参数覆盖。

## 二、快速开始（四步跑通）

```bash
cd "工单作业/工单03-表格解析及检索优化/src"

# ① 抽取表格（输出 results/tables/*.md 与 results/table_inventory.json）
python table_extractor.py --pdf "D:/工单/RAG 工单/RAG 工单/附件/招股说明书2.pdf" --name 招股说明书2

# ② 建立「含表格」索引（文本块 + 表格块）
python build_index_with_tables.py

# ③ 表格类问题问答（id 1~4，含检索精确度）
python table_qa.py

# ④ 消融实验：不含表格 vs 含表格（核心证据）
python compare_with_without_tables.py
```

`compare_with_without_tables.py` 会自动构建两套索引（`wo03_no_table`
与 `wo03_with_table`），第一次运行耗时较长（需要解析 PDF 与编码向量），
之后复用缓存。

## 三、脚本逐个说明

### 3.1 `table_extractor.py` —— 表格抽取

```bash
python table_extractor.py                      # 默认抽《招股说明书2.pdf》
python table_extractor.py --all                # 两份招股书都抽
python table_extractor.py --max-pages 60       # 只抽前 60 页（调试）
```

**产出**：

| 文件 | 内容 |
| --- | --- |
| `results/tables/<文档>_p<页码>_t<序号>[_merged].md` | 每张表一个 Markdown 文件，文件头含页码、规格、质量标记 |
| `results/table_inventory_<文档>.json` | 表清单：页码 / 行列数 / 表头 / 字符数 / 质量标记 / 跨页合并事件 |

**看什么**：打开任意 `.md`，确认表头与数据行是否一一对应；
打开清单 JSON，看 `merge_events` 里每次合并/拒绝合并的理由。

### 3.2 `build_index_with_tables.py` —— 建索引

```bash
python build_index_with_tables.py                                    # 含表格（工单03 主方案）
python build_index_with_tables.py --no-tables --collection wo03_no_table   # 对照组的空索引
python build_index_with_tables.py --raw-tables                       # 不做质量校验/跨页合并（对比用）
```

**产出**：`results/index_stats.json`（chunk 总数、文本/表格块数量、
向量条数、BM25 文档数、构建耗时、表格 chunk 明细）。

索引文件位置：`data/index/<collection>.pkl`（或 Chroma 目录）、
`data/index/<collection>.bm25.pkl`。

### 3.3 `table_qa.py` —— 表格类问题问答

```bash
python table_qa.py                     # 默认调用 LLM
python table_qa.py --no-llm            # 抽取式作答
python table_qa.py --no-boost          # 关闭表格块加权（对比用）
python table_qa.py --top-k 8
```

**产出**：`results/table_qa.json` + `results/table_qa.md`。
Markdown 报告里每题都有：答案定位、参考答案、检索精确度、
**检索到的表格原文**（Markdown 代码块）、生成的答案、缺失要点。

### 3.4 `compare_with_without_tables.py` —— 消融实验

```bash
python compare_with_without_tables.py                # 14 问 × 2 组索引
python compare_with_without_tables.py --no-llm       # 不调用生成模型（快）
python compare_with_without_tables.py --rebuild      # 强制重建两套索引
python compare_with_without_tables.py --top-k 8
```

**产出**：`results/table_ablation.json` + `results/table_ablation.md`
（两组准确率对比表、索引规模、逐题明细、失败样例的缺失要点、结论）。

### 3.5 `run_evaluation.py` —— 14 问 RAG 评估

```bash
python run_evaluation.py               # 检索层 + RAGAS 生成层
python run_evaluation.py --no-llm      # 只跑检索层（秒级完成）
python run_evaluation.py --fast        # 只算 answer_correctness + context_recall
```

**产出**：`results/evaluation.json` + `results/evaluation.md`
（准确率、要点覆盖率、命中页率、Hit Rate / MRR、RAGAS 五大指标、逐题明细）。

### 3.6 `serve.py` —— Web 服务

```bash
python serve.py                                  # http://127.0.0.1:8013
python serve.py --port 8000
python serve.py --build-if-missing               # 索引不存在时自动建
python serve.py --no-llm                         # 强制抽取式作答
```

浏览器打开后：

- 左侧是问答区，输入问题回车；
- 右侧列出 14 个演示问题（点击即问）与索引概况；
- 回答区同时显示：**答案**、**检索精确度**（片段精度 / 要点召回 /
  表格命中 / 答案要点全中）、**检索到的片段**（表格会渲染成真正的 HTML 表格，
  正文按原文展示）、来源页码、各阶段耗时。

**接口**（供二次开发）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查（集合、向量数、模型） |
| GET | `/api/documents` | 已入库文档与索引统计 |
| GET | `/api/table_inventory?limit=50` | 表格清单（页码/行列数/表头） |
| GET | `/api/demo_questions` | 14 个演示问题 |
| POST | `/api/ask` | `{question, top_k, use_llm, use_table_boost}` |

## 四、常见问题

**Q1：`[error] 找不到 PDF`**
PDF 不在默认路径。用 `--pdf "你的路径/招股说明书2.pdf"` 指定。

**Q2：建索引很慢**
首次运行需下载 BGE 模型（约 1.3 GB）并逐页解析 PDF（pdfplumber 较慢，
350 页约数分钟）。表格记录会缓存到 `results/tables/<文档>_records.json`，
第二次运行直接命中缓存。

**Q3：没有 API Key 会怎样？**
所有脚本自动切换为**抽取式作答**：直接把命中的表格/正文原文回填成答案，
并在答案开头标注「（离线抽取式作答，未调用生成模型）」。
检索精确度、要点覆盖率等指标不受影响；`run_evaluation.py`
会跳过 RAGAS 生成层指标并在报告中明确标注。

**Q4：检索结果里表格没排在最前面**
确认没有加 `--no-boost`；再确认问题里包含「多少 / 比例 / 哪些 / 分别」
等数值类特征词（这类问题加权 1.35，其它 1.15）。

**Q5：端口被占用**
`python serve.py --port 8014`。

**Q6：想只看某几页的表格**
`python table_extractor.py --max-pages 25`（只解析前 25 页）。

**Q7：表格被拆成两次输出 / 两张表被错误合并**
检查 `results/table_inventory.json` 的 `merge_events` 字段，
每条记录都会写明 `merged` 或 `rejected` 及其理由；
如判定有误，可调整 `table_extractor.py` 顶部的
`TOP_RATIO` / `BOTTOM_RATIO` / `STRICT_*` 门限。
