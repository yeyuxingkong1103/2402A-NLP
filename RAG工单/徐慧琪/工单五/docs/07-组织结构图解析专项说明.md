## 一、图在哪、怎么定位

| 步骤 | 做法 |
| --- | --- |
| 1 | 以文本锚点「（二）发行人内部组织结构图」定位到**其后的整页图** |
| 2 | 取 `page_idx = 38`（0 基索引）= **PDF 阅读器第 39 页** |
| 3 | 只在这**一页**内解析；图区＝全部节点框与线段的并集再外扩一个小 padding |

**实测图区**（A4 竖向页 595×842 pt）：

```
_chart_region = (129.8, 70.2, 490.8, 649.6)      # 约 361 × 579 pt，居中的一块
```

> **〔实施期修正〕** 设计文档 §2.3 当时记的是「占满整页 `bbox=[119,67,818,767]`」，
> 其中 x=818 **超过了页宽 595**，是把尺寸记串了。以本节实测值为准。
> 图区之所以要精确算出来，是为了**把页眉页脚挡在外面**——见 3.1 的踩坑说明。

**页码口径**（沿用工单3，避免溯源错位）：`page_idx` 是 0 基索引，
`page_display = page_idx + 1` 是 PDF 阅读器页码。本图 `page_idx=38` / 显示第 39 页；
招股2 的**文档自印页码**也恰好是 38。引用中一律给 **page_display**。

## 二、为什么不用 CLIP / VLM（三条依据，缺一不可）

1. **本机没有视觉大模型**：`docs/01-本机模型扫描结果.md` 的扫描结论是可用资源为
   Qwen2.5 系列 + bge-m3 + bge-reranker + PaddleOCR-VL，**无 CLIP 类中文对齐模型**。
2. **硬约束禁止下载**：所有模型必须从本机路径加载并 `local_files_only=True`，
   引入 CLIP/VLM 必然触发下载，违反工单硬约束。
3. **工单4 的实测反例**：工单4 用 `openai/clip-vit-base-patch32` 做图像检索，
   金标图在 162 张图中排 **136 名**（CLIP 中文文图对齐失效），
   且其平均时延已超 3 秒硬指标。该链路被本工单**明确弃用**。

**并且——本机唯一的多模态资产也验证不了这张图**：本项目实测让 PaddleOCR-VL
去读这一页，它把整页判成**一个图片块**，没有吐出任何文字（详见第五节）。
也就是说，即便想走多模态路线，本机也拿不到可用的转录结果。

**结论**：这张图是**矢量绘制**（不是位图），所以正确答案不是「让模型看图」，
而是**直接读图的几何结构**——零模型、确定性、毫秒级。

## 三、矢量提取与建树算法

### 3.1 提取（PyMuPDF，零模型）

| 元素 | 取法 | 实测数量 |
| --- | --- | --- |
| 节点框 | `page.get_drawings()` 的矩形，剔除页眉横线（实测 `rect=(88.4, 55.3, 507.0, 56.0)`，高 0.7pt、宽 418.6pt） | **29 个** |
| 连接线 | `get_drawings()` 中 `kinds={'l'}` 的线段 | **36 条** |
| 框内文字 | `get_text("words")`，先按图区过滤页眉/页脚/页码/对角水印，再逐字逐行合并成标签 | 29 个标签，**无一个未绑定** |

文字归属规则：**标签中心落在哪个框内，就属于哪个框**（含竖排逐字，如「财务部」「市场开发部」）。

> **〔踩坑〕页眉页脚会"贴"到节点上**：文字按「最近框」兜底绑定时，
> 页眉「武汉力源信息技术股份有限公司 / 招股意向书」（y≈44–53）与页脚页码「38」（y≈780）
> 会被吸进相邻节点，实测把节点名污染成
> 「武汉力源信息技术股份有限公司薪酬与考核委员会」「招股意向书监事会」「38深圳销售处」。
> 因此必须先算出**图区**（本页 129.8–490.8 × 70.2–649.6）把区域外的文字全部滤掉，
> 再绑定。残留的**对角水印**（八维教育/人工智能刘敏）同法过滤。

### 3.2 建树（核心是「谁是谁的父」）

1. **连线聚簇**：端点重合的线段并成一簇；**T 型接头**（端点落在另一段内部）也算同簇。
   36 条线聚成 **10 簇**，每簇对应图上的一个分叉。
2. **框边归类**：每个框按「哪条边被线段端点贴到」记为 `top / bottom / left / right`。
3. **方向判定**（核心规则）：
   - 一簇里**有且仅有 1 个框从 `bottom` 接入**、其余从 `top` 接入 → 该框为父（**水平总线**）；
   - 一簇里**有且仅有 1 个框从 `left` 接入**、且 ≥2 个框从 `right` 接入 → 该框为父（**竖直总线**）；
   - **只剩两个框直连**时按几何定向：`bottom/top` 者取上框为父；`right/left` 者取左框为父。
4. **BFS 定向**：从根出发逐层展开，消解剩余歧义。

> **〔实测修正〕** 原设计把「单侧 `left` 接入者即父」当作竖直总线的**通用**规则，
> 结果在 `seg11`（董事会右边缘 323.8 → 董事会秘书左边缘 377.8）这条**水平直连**上
> 把父子接反——实测产出 **27 条边、2 个根**，校验当场失败。
> 故对「二框直连」单独按几何定向。这条修正记录在此，是因为它说明**校验是有效的**：
> 错误的结果没能溜过去，而是被 29/28/单根三条断言挡下来了。

### 3.3 校验（宁可失败，也不产出错误的树）

`assert_expected()` 要求：**29 节点 / 28 边 / 单根**，任一不符即抛错。

实际落盘值（`data/tables/招股说明书2_orgchart.json` 的 `verify` 字段）：

```json
{"n_nodes": 29, "n_edges": 28, "roots": ["股东大会"], "single_root": true,
 "n_boxes_detected": 29, "n_segments": 36, "n_clusters": 10,
 "unbound_labels": [], "page_idx": 38}
```

`unbound_labels: []` 表示**没有任何一个文字标签找不到归属框**。

### 3.4 解析出的树（与图上绘制逐层一致）

```
股东大会
├── 董事会
│   ├── 总经理
│   │   ├── 上海分公司   ├── 财务部   ├── 市场开发部 → 研发中心
│   │   ├── 信息系统部   ├── 行政人事部   ├── 物流部
│   │   └── 销售部
│   │       ├── 电话及网络销售部   ├── 渠道销售部   ├── 国际贸易部
│   │       └── 大客户销售部
│   │           ├── 珠海销售处  ├── 深圳销售处  ├── 北京销售处
│   │           └── 武汉销售处  ├── 广州销售处  └── 成都销售处
│   ├── 董事会秘书 → 证券部
│   ├── 薪酬与考核委员会   ├── 提名委员会
│   └── 战略委员会        └── 审计委员会 → 内部审计部
└── 监事会
```

**Q5 的答案直接来自这棵树**：`大客户销售部` 有 **6 个**销售处（其余二级部门为 0 个），
即珠海、深圳、北京、武汉、广州、成都销售处——由 `descendants()` 确定性聚合得出，
**不是**让 LLM 数出来的。

## 四、入库与检索侧注入

- **入库**：`build_orgchart.py` 增量写入工单5 自己的 collection（**不重建**全量索引）：
  一条「整树块」+ 29 条「节点块」（含节点路径、直接下级、聚合结论），
  节点块的 `parent_id` 指向整树块——沿用**子块检索 + 父块上下文**机制，
  命中任一节点即可还原全树。
- **检索侧**：`src/context.py` 命中 `block_type=orgchart` 时走专门分支，
  把子树与聚合结论一并注入提示词。
- **引用**：节点块带 `org_path` 字段，故引用能精确到**节点路径**：

  > 📄 组织结构图｜招股说明书2.pdf 第 39 页｜发行人基本情况 / 发行人内部组织结构图 /
  > 股东大会/董事会/总经理/销售部/大客户销售部

  （这条引用是系统在 `docs/06-验收序列逐轮报告.md` 的 Q5 中**实际返回**的。）

## 五、PaddleOCR-VL 交叉验证：**实际执行了，结果是 `ok: false`**（如实披露）

设计里 PaddleOCR-VL 承担的是**文字集合的独立复核**（层级以矢量连线为准，OCR 给不出树结构）。
本工单在 Task11 阶段**真跑了一次**（本机 venv 可用，`D:\model\Paddle-OCR\venv`），耗时 **34.9 秒**，
实际结果：

```json
{"ok": false,
 "reason": "RuntimeError: PaddleOCR-VL 未返回可用文字（整页被识别为图片块/无文字层）：
            '<div style=\"text-align: center;\"><img src=\"imgs/img_in_image_box_187_73_1481_1919.jpg\"
            alt=\"Image\" width=\"74%\" /></div>'" }
```

**原因**：PaddleOCR-VL 把 210 DPI 渲染的整页**整体判定为一个图像块**，
只回吐了一段 markdown 图片占位符，**没有输出任何文字层**。
`ocr_image_text()` 用 `_is_page_text()` 过滤掉该占位符后判定「未拿到可用文字」并抛错，
`verify_with_ocr()` 捕获后记 `ok: false`。

**这意味着什么（不粉饰）**：

1. **交叉验证没有通过**——本机现有的多模态资产**无法**转录这张图，
   因此「矢量解析的文字集合」**没有得到 OCR 的独立复核**。
2. 这不影响 Q5 的答案正确性，因为层级与计数**只依赖矢量几何**，
   且该几何结果已由下一节的两处原文证据独立佐证。
3. 它反而**加强了第二节的选型结论**：在这台机器上，「让模型看图」这条路
   连转录这一步都走不通，矢量解析是**唯一**可行且可验证的路线。

> 落盘位置：`data/tables/招股说明书2_orgchart.json` 的 `ocr` 字段。
> 该字段此前是 `{"ok": false, "reason": "skipped"}`（构建脚本的默认跳过占位），
> **本次已用上面的真实结果替换**——占位符不能冒充「已验证」。

## 六、三方一致性（图的层级 + 正文的两处独立佐证）

| # | 证据 | 位置 | 内容 | 与图的关系 |
| --- | --- | --- | --- | --- |
| 1 | 图 | 招股2 **第 39 页**（阅读器页码） | 29 框 / 28 线重建的层级树 | 主体 |
| 2 | 正文 | 招股2 **第 40 页** | 「②销售部：销售部下设渠道销售部、电话及网络销售部、**大客户销售部**和国际贸易部。」 | 与图中 `销售部` 的 4 个下级**逐个吻合** |

## 七、结论

1. Q5 的答案来自**图结构本身**（`descendants()` 聚合），是确定性结果，不是模型"看图说话"。
2. 解析质量由三条断言（29 节点 / 28 边 / 单根）与两处正文证据共同保证。
3. **PaddleOCR-VL 交叉验证未通过**（整页被判为图像块），已如实记录并落盘，
   未以「skipped」占位符冒充。
4. 「不用 CLIP/VLM」不是偏好，而是**本机资源 + 硬约束 + 实测反例 + 本次 OCR 失败**
   共同得出的结论。
