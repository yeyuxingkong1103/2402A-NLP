## 2. 图像资产提取与去重（`image_parser.py`）

### 2.1 提取

```python
# 工单：人工智能NLP-RAG-图像内容解析及检索优化
# 逐页提取，禁止抽样；每张图记录 xref/尺寸/bbox/色彩空间/滤镜/字节哈希
for i in range(doc.page_count):
    page = doc[i]
    for it in page.get_image_info(xrefs=True):      # 含 bbox（占位与旋转信息）
        xref = it["xref"]
        raw = doc.extract_image(xref)               # {"image": bytes, "ext": "jpeg", ...}
```

### 2.2 去重与过滤规则（**顺序固定，先杀水印**）

| 顺序 | 规则 | 处置 | 依据 |
| --- | --- | --- | --- |
| R1 | `xref` 出现次数 ≥ 页数 × 0.5 | **丢弃**（记入 `watermark_blacklist.json`，**同时登记其 smask**） | 实测 97.9% / 92.1% |
| R1b | 命中 R1 的 xref，其 `smask` 也登记 | Java 生成的软遮罩不作为独立图出现，但换页复用同一 smask，需一并屏蔽 | 实测 PDF2 2338↔2339 |
| R2 | 原始像素 `min(w,h) ≤ 4` 或 `max(w,h)/min(w,h) ≥ 20` | **丢弃**（字符条/分隔线） | 页 39 的 1×394 长条 |
| R3 | 原始像素 `w×h ≤ 4096` 且非图表页 | **丢弃**（可疑小图标） | PDF2 单页重复 15 张 143×127 |
| R4 | 页面 bbox 面积 < 页面面积 × 0.5% | **丢弃**（页眉页脚装饰） | 页 72 的页眉线 |
| R5 | 字节 SHA1 相同（不同 xref） | **合并**：保留首个 xref，记录**全部出现页码**（引用时可列多页） | 同一图多次复用 |
| R6 | 与前一张图的 bbox 完全包含且面积比 > 0.95 | 保留大的（避免同一图两种分辨率重复入库） | — |

> ⚠️ **不要把「纯色/近空白」当作水印判据**：实测水印底图是**纯黑 143×127 PNG（154 B）**，
> 文字在**同 xref 的 smask** 里（PDF1 112173↔112174、PDF2 2338↔2339）。
> 用「纯色」启发式会误伤其它纯色装饰图；**唯一可靠判据是 xref 重复度 R1**。

**必须落盘**：`研发/data/processed/images.jsonl`（全部资产）、`watermark_blacklist.json`（R1 结果）、`image_candidates.jsonl`（过滤后候选）。

### 2.3 与文本层的关联

- **标题/资料来源归属**：若候选图的 bbox 上方 40 pt 内的文本含「图」「表」「资料来源」「单位：」等，作为该图的 `caption` 与 `source`。
- **页码**：一律写 **1-based 物理页码**（`doc[i]` → `i+1`）。

## 3. 矢量框图结构解析（`diagram_parser.py`）— 第 5 题

### 3.1 结构判定（避免把每页的线条都当框图）

```
是框图 ⟺
  矩形数 ≥ 6（get_drawings() 中 type=='re' 且 宽>20pt 且 高>15pt）
  且 矩形存在至少 2 层「上下相邻 + 水平投影重叠」关系
  且 矩形内文本单元 ≥ 3
```

实测：页 39 满足（31 个 drawings，含 6+4+6 个方框）；普通页不满足。

### 3.2 文本单元构造（**本方案的核心，已实测验证**）

页 39 的文本层有两种形态，必须分别处理：

| 形态 | 特征 | 构造方法 |
| --- | --- | --- |
| **横向** | 一个 span 内含多个汉字（如 `董事会秘书`） | 直接取 span 文本与 `bbox` |
| **竖排** | **每字一个 span、x 相同、y 递增**（如 `财`/`务`/`部`） | **按 x 列聚类（容差 ±6 pt）+ 列内按 y 升序拼接** |

```
列聚类伪代码（实测可用）：
  按 (x, y) 升序遍历 span：
    若已存在列 c 满足 |c.x − span.x| ≤ 6 且 0 < span.y − c.y末 < 14：
        并入 c；c.y末 = span.y
    否则：新建列 {x: span.x, y起: span.y, y末: span.y}
  每列文本 = 列内按 y 升序拼接
```

**⚠️ 反面算法（实测会错，禁止使用）**：按 y 把同一水平线的字符聚成一行 ——
会把 6 个方框的首字串成 `财场息销政物` 之类的乱码（见 `设计/复现脚本/环境事实复现结果.json`
→ `§7_语料 → 第5题_物理页39 → 行聚类复原结果_反面示例`）。

**实测验证结果**：列聚类复原 **28/29** 个节点名；
唯一未复原的是 `薪酬与考核委员会`——该框内**两行且第二行缩进**（x 144.6 → 155.1）。
→ **补充规则 R7**：若两个列单元的 bbox 被**同一个矩形框**包含，且两列 y 相邻，则**合并为一个节点名**。

### 3.3 层级重建（几何 + 连线双判据）

> ⚠️ **T2 实测更正（2026-10）**：本节的「几何规则」作为**唯一判据会在页 39 失效**。
> 实测：大客户销售部 box x∈[341.82, 368.82]，而 6 个销售处 box 的中心 x
> 为 247.3/292.3/337.3/382.3/427.3/472.3 —— **没有一个落在父框 x 区间内**，
> 几何规则会把 6 个销售处拆给「电话及网络销售部 / 渠道销售部 / 国际贸易部」。
> **实际实现改为「折点图 + 遇框即停 BFS」**（连线证据为主、几何为兜底），
> 详见 **§11.2**。下面的几何规则保留为**无连线页面的兜底**。

```
1) 文字单元 → 所属矩形：取「包含该单元 bbox（外扩 2pt）」的最小矩形框
2) 分层：按矩形中心 y 聚类（容差 = 框中位高 × 0.6）→ 第 1..N 层
3) 同层排序：按框中心 x 升序
4) 父子判定（几何）：
     父候选 = 上一层中「水平区间覆盖子框中心 x」的框
     若有多个：取「与子框中心 x 距离最小」者
     若无：向上再找一层（允许跨层，因 4 层以上框图常见跳线）
5) 父子判定（连线，增强）：
     get_drawings() 的 type=='l'/'c' 中，若存在线段一端落在父框下边、
     另一端落在子框上边且 x 偏差 ≤ 6pt → 该父子关系**置信度拉满**
6) 冲突处理：几何与连线结论不一致时，**以连线为准**，并把该处记入解析报告（不得静默）
```

### 4.2 条形图抽取算法（无 cv2 / 无 OCR 条件下的实现路径）

**依赖**：`numpy`（已装）+ `PIL`（已装）+ `scipy.ndimage`（scipy 1.17.1 已装，用于连通域标记）。
**像素流程**：

```
1) Pixmap(doc, xref) → PNG bytes → PIL.Image → numpy(H,W,3) → 灰度 → 二值化
     阈值：Otsu（自行实现，numpy 直方图 + 类间方差最大化）
2) 定位纵轴：逐列统计深色像素数，取最大值列 → x_axis（条形图的基线）
3) 切柱条：在 x_axis 右侧（正向）与左侧（负向）分别统计
     对每一行 y：深色像素在 x_axis 右侧的连续长度 run(y)
     行区间满足 run(y) > 阈值 的连续 y 段 = 一根柱（用连通域标记更稳）
4) 量取：len_i = 该柱的像素长度；方向 = 右（正）/ 左（负）
5) 判负：存在长度显著但方向为左的柱 → 该行业为负增长
6) 数值标定（关键）：
     a. 正文锚点：物理页 72 正文含「工业控制领域所占的比例虽然仅为7%，
        但其增长率达10.5%，在所有应用行业中位列第二，仅次于汽车电子。」
        → 可**自动抽取**出「工控 = 10.5%」这一锚点（正则：行业名 + 百分比）
     b. 比例标定：value_i = len_i / len(工控) × 10.5%
     c. 取整到 1 位小数（该图刻度即为 1 位小数）
     d. 一致性校验：max(value) 对应行业，应与正文「仅次于汽车电子」互证
     e. 若 a 失败（正文锚点缺失）：退回「只报相对关系（最长/负向）+ CLIP 标签匹配值」，
        并在报告中**显式标注绝对刻度未标定**（不得猜数）
7) 行业名与标签值识别（见 §4.3）
```

**几何校验（必须做）**：所有正向柱共享同一线性刻度 → `len_i / len_j` 应等于 `value_i / value_j`（容差 ±5%）。
不满足即说明柱子切分有误，**必须报错并留痕，不得输出可疑数值**。

### 4.3 行业名与数值标签的识别策略（诚实分级）

图表内的行业名与百分比**画在位图里**，文本层取不到；本机**无 OCR**（pytesseract/paddleocr/easyocr 全缺）。
因此按下列**分级策略**执行，并**如实报告实际走到哪一级**：

| 级别 | 手段 | 说明 |
| --- | --- | --- |
| **A（首选）** | **中文 CLIP 零样本匹配** | 用 `ChineseCLIPModel` 同时对「裁剪出的标签小图」与「候选文本」编码，取余弦最大者。候选集：行业名 {IC卡, 工控, 计算机, 其他, 汽车, 网络通信, 消费}；数值 {−2.0%, 2.6%, 5.1%, 6.1%, 7.9%, 10.5%, 14.0%}。**数值候选由几何比例反推生成候选区间**（如比例≈1.0 → 候选 {13.5%~14.5%}），把零样本难度降到「有限候选分类」 |
| **B（可选增强）** | 本地模板/几何数字识别 | 仅当 A 不可用时尝试；不做承诺 |
| **C（兜底）** | 纯几何 + 正文锚点 | 能给出「最长柱 = 增长最快」「存在负向柱 = 负增长」，行业名用**行位置**与 CLIP 整图-文本相似度（对整图问「增长率最快的是汽车」vs「…是IC卡」取最大）确定 |

**强制留痕**：`chart_extractor` 必须输出 `extraction_method` 字段（`clip_zero_shot` / `geometry_only` / `geometry+anchor`），
测试报告中必须写明第 6 题实际走的是哪一级。**严禁把 CLIP 结果伪装成 OCR 结果。**

### 4.4 3D 饼图（xref 1693）的处置

3D 饼图在透视下扇区角度**不可靠**，故：

- **不做角度定量反算**（避免给出错误百分比）；
- 只做「标签—数值对」的 CLIP 匹配与落库（计算机 2515/42%、消费 1541/26%、网络通信 1189/20%、工控 448/7%、其他 137/2%、汽车 102/2%、IC卡 48/1%）；
- 报告中明确标注：**3D 饼图未做几何反算，仅标签识别**。

## 5. 多模态语义编码（`multimodal_encoder.py`）

### 5.1 模型与权重（**提示词硬性要求：必须用多模态模型**）

| 项 | 值 |
| --- | --- |
| 模型 | `OFA-Sys/chinese-clip-vit-base-patch16`（中文 CLIP，`ChineseCLIPModel`） |
| 加载方式 | `transformers.ChineseCLIPModel` / `ChineseCLIPProcessor`（**不用** `clip`/`open_clip` 包，二者缺失） |
| 权重可达性 | **实测 HTTP 200**；⚠️ 镜像上报 `753,177,983 B`，**实际落盘 `pytorch_model.bin` = `771,304,190 B`**（仓库无 safetensors）—— **判等以 sha256 为准**，见 `设计/环境事实.md` §4.2 |
| 下载镜像 | `HF_ENDPOINT=https://hf-mirror.com`（环境已预设）；仓库脚本 `研发/scripts/download_clip.py` 走**纯 HTTP**，同时支持 ModelScope 备用端点 |
| 实测速率 | **1.21 MB/s（32 MB 片段计时）**；`download_clip.py` 末段实测可达 15.84 MB/s，全程数分钟 |
| **落地目录** | **`研发/data/models/chinese-clip-vit-base-patch16/`**（`download_clip.py` 的 `DEFAULT_DEST`；校验位见 `部署/脚本/verify_config_env.py`：`CLIP_SHA256` + `CLIP_WEIGHT_BYTES_MEASURED = 771_304_190`） |

### 5.4 检索融合（CLIP 通道怎么用）

```
查询文本 → CLIP 文本编码器 → 与 images_clip.npy 内积 → 取 Top-M（M 小，如 10）
     ↓
与 FAISS 文本向量召回、BM25 召回 一起做 RRF 融合
     ↓
重排后交给生成器
```

**注意**：中文 CLIP 的文本塔与 bge-m3 语义空间**不同**，**禁止把两种相似度直接相加**；
必须用**排名融合（RRF）**或分别设阈值后并集召回。此点必须在实现中注释说明。

### 11.2 框图解析：为什么必须走「连线证据」

实测（`page.get_drawings()`）发现页 39 的**全部 36 条连线都在某个 drawing 的 `l`（线段）item 里**，
因此实现改为三步：

1. **折点图**：线段端点 + 线段与矩形边界的交点 → 按 1.2pt 容差**聚类合并**成折点；
   线段在框边处切断；**并处理 T 形接头**（某线段端点落在另一线段内部时把后者切断）。
2. **遇框即停 BFS**：从某框**下边**上的折点出发，走到另一个框的边界就记为该框的下级并**停止**。
   （若允许穿过，大客户销售部会顺着母线把兄弟节点也当成长辈。）
3. **父节点**：从该框**全部** attach 折点出发做同样的 BFS，候选按
   「① 路径无 ≥3 度分叉点 → ② 不与自身同列 → ③ BFS 跳数 → ④ 垂直间距」排序取第一。

页 39 实测输出（`evidence=connector_lines`，29 个方框 / 36 条连线）：

```
股东大会 ─ 董事会 ─ 总经理 ─┬ 财务部 / 市场开发部(→研发中心) / 信息系统部
                            ├ 销售部 ─┬ 电话及网络销售部
                            │         ├ 渠道销售部
                            │         ├ 大客户销售部 ─ 珠海/深圳/北京/武汉/广州/成都 销售处
                            │         └ 国际贸易部
                            ├ 行政人事部
                            ├ 上海分公司        ← 挂总经理侧，**不是**销售处
                            └ 物流部
股东大会 ─ 监事会；董事会 ─ 董事会秘书(→证券部)；董事会 ─ 薪酬与考核/提名/战略/审计 委员会(→内部审计部)
```

**同时修正的两处方案偏差**：
* §3.3 的「几何覆盖子框中心 x」在页 39 失效（见该节 T2 更正框）；
* §9 遗留的「研发中心归属未确认」→ 实测**连线确认**挂在市场开发部（`(188.82,395.04)->(188.82,434.04)` 一条线段直达）。

**表格网格误检防护（新增）**：两份 PDF 表格极多，单元格边框也是矩形，仅「矩形 ≥ 6」会把表格页判成框图
（实测 PDF2 有 36 页通过该阈值）。新增 `_looks_like_table_grid()`：
表格单元格彼此紧贴（间距 ≈ 0）而框图方框之间留白 ≥ 7pt，
「相邻贴边矩形对 / 总矩形对 > 0.25」即判为表格排除；
`extract_images.py` 再加一道「父子边 ≥ 2 且有名节点 ≥ 4」的质量门。

### 11.3 图表数值：三层证据链 + 独立复核

| 层 | 做法 | 实测结果（页 72 xref=1692） |
| --- | --- | --- |
| 几何 | 彩色掩膜（通道极差 > 40，**天然滤掉灰水印**）→ 行连续段切柱 → 与基线列比较得**带符号柱长** | 7 根柱：49(-)/254/191/147/339/62/123 px |
| 定标 | 从**正文**抽 `增长率…10.5%…位列第二`→ (锚点值 10.5, 排名 2)，取**排名第 2 长**的柱 → `scale=10.5/254` | 反算 7 个值：**-2.0 / 10.5 / 7.9 / 6.1 / 14.0 / 2.6 / 5.1** |
| 识别 | 字形模板匹配（系统 CJK 字体 × 4 字号，Dice + 列投影相关，±2px 微移） | 7/7 行业名全对（IoU 0.68~0.80）：IC卡/工控/计算机/其他/汽车/网络通信/消费 |
| 复核 | 柱末端**印刷数值**再单独识别一次（候选 = 几何算出的 7 值 × ±号，即 1/14 分类），与几何值比对 | **6/7 一致**；IC卡 的 `-2.0%` 被读成 `-2.6%`（0/6 形近），**如实记为 warning，不用它覆盖几何值** |

结论：**汽车 14.0% 最快**、**IC卡 −2.0% 唯一负增长**，且与正文「仅次于汽车电子」互证
（`top_hint_matches_max=True`）。

**两处实现上的关键修正**（都是实测踩出来的）：
1. **必须剔除位图边框**：xref1692 左右各有一列近乎全黑（dark≈467/473），
   不剔除会把整页文字粘成一条巨型「文本行」，行业名被裁成 `(1,352,88,392)` 这种跨行巨框。
2. **数值标签位置不固定**：IC卡 的 `-2.0%` 画在柱**上方**而不是柱端外侧；
   按「排除行业名区域后，离柱端最近」自适应选行即可，不要写死方向。

**3D 饼图（xref 1693）**：按 §4.4 只做标签识别、**不做角度反算**，
实测识别出 {其他, 计算机, 消费, 工控} 4/7（小扇区标签密集，字行会被并成一条），已在产物中标注 `quantitative=false`。

### 11.5 中文 CLIP：**权重已成功下载并可正常编码**（重点）

* 端点：`hf-mirror.com` **实测 200 且可用**（`pytorch_model.bin` 镜像上报 753,177,983 B，
  **实际落盘 771,304,190 B**；末段实测 **15.84 MB/s**，全程数分钟内完成）。`huggingface.co` 的 `huggingface_hub` 路径不可用
  （软链落点 `PermissionError`），故**改纯 HTTP**，见 `研发/scripts/download_clip.py`（同时支持 ModelScope 备用端点）。
* 落地：`研发/data/models/chinese-clip-vit-base-patch16/`，
  `sha256(pytorch_model.bin)=3b8ca5a9ba36830e008bef8f980184cf29eeff986f1f3c1be9e5153f8712e7cc`。
* 🔴 **两个实测坑（都会静默毁掉结果，必须在实现里挡住）**：
  1. 仓库里的 `clip_cn_vit-b-16.pt`（753,196,934 B）是 **cn_clip 训练检查点**
     （顶层 `{epoch,name,step,state_dict}`，内层是 timm 命名 `module.visual.transformer…`）。
     把它当 `pytorch_model.bin` 加载 → **全部权重随机初始化**且**只打 warning 不报错**。
     → `multimodal_encoder.inspect_weight_file()` + `download_clip.verify_weights()` 双重体检。
  2. transformers 4.57.6 的 `ChineseCLIPModel.get_text_features()` **在本 checkpoint 上必崩**：
     它取 `text_outputs.pooler_output`，而 `ChineseCLIPModel.__init__` 用
     `ChineseCLIPTextModel(cfg, add_pooling_layer=False)` 构造、且 checkpoint 里**没有 pooler 权重**
     （实测 `[k for k in sd if 'pooler' in k] == []`）→ `TypeError: linear(): argument 'input' must be Tensor, not NoneType`。
     → 按其 docstring「final **[CLS] hidden state**」显式取 `last_hidden_state[:, 0]` 再过 `text_projection`，
     并在 manifest 写 `text_encoder_workaround=true`。
* 编码实测（CPU）：模型加载 0.55~0.71 s，4 张图 **0.74~1.09 s**；嵌入 512 维、L2 范数 = 1.000。
* **语义有效性抽检**（不是只看形状）：条形图 vs「这是一张横向条形图，比较各行业的增长率」= **0.428**（该图最高），
  饼图 vs「这是一张三维饼图，按行业划分市场份额」= **0.426**（该图最高），「公司公章照片」两者均最低（0.285/0.337）。
* CLIP 与文本向量**不同空间**，只提供**排名**（`rank()` 返回 `clip_rank`/`clip_similarity`），**不与其他通道分数相加**。
