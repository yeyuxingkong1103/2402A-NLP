# 工单11 Embeddings模型微调｜部署文档
工单编号：人工智能NLP‑RAG 项目‑Embedding 模型微调任务

## 1.环境信息
- WSL Ubuntu24.04；虚拟环境 venv_gongdan5
- 微调产出模型目录：`工单11/研发/output_model`

## 2.微调后模型如何接入前面RAG项目（工单7‑9‑10）
> 原来RAG系统使用线上/原始BAAI/bge‑base‑zh‑v1.5，现在替换为本工单微调后的本地模型。

### 2.1 在本地WSL的RAG系统使用
修改RAG代码中embedding加载路径，把原来的模型名字替换为本微调模型本地路径：
```python
from sentence_transformers import SentenceTransformer
# 替换为微调后的模型
model = SentenceTransformer("./output_model")
向量库 (Milvus) 注意：**必须重新全部向量化文档，重新入库**。

> 
> ⚠️重要提醒：向量库里面旧向量是原始模型生成，不能和微调模型混用，文档必须重新生成向量。

### 2.2 如果要放到工单 10 的 Docker 容器部署

1. 将`output_model`模型目录拷贝进项目；
2. 修改 Dockerfile，把微调模型打包进镜像；
3. RAG 代码内修改 embedding 加载路径指向容器内微调模型；
4. 容器启动后，重新执行文档向量化，写入 Milvus 向量数据库。

## 3. 模型验证方式

1. 加载微调模型，运行 eval_embedding.py 脚本，复现 Recall 指标；
2. 接入 RAG，实际提问业务问题，观察检索召回结果变化。

## 4. 注意事项

1. embedding 微调模型产出之后，**旧向量库必须全部重建**，新旧模型向量空间不一致，不可混用。
2. CPU 环境推理速度慢，生产环境建议 GPU 部署。
3. 本实训模型受训练数据限制，效果提升有限；真实业务需要扩充训练数据集。

## 5. 运维命令
# 评估微调模型
python3 eval_embedding.py
