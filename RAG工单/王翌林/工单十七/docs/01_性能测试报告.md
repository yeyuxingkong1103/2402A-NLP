# 工单十七 · 性能测试报告（优化前后对比）

## 测试环境
- 机器：WSL2 Ubuntu-22.04（内存约束 ~7.6GB），单进程 uvicorn。
- 场景A：20 并发、45 秒、高频问答（唯一问题，覆盖检索+生成全链路，排除缓存命中干扰）。
- 工具：自包含 Python 线程压测 `scripts/load_test.py` + Locust `loadtest/locustfile.py`。

## 核心结果对比

| 指标 | 基线（优化前） | 优化后 | 结论 |
|------|:----:|:----:|------|
| 平均延迟 | 1104 ms | **876 ms** | ↓ 21% |
| P95 延迟 | 1107 ms | **957 ms** | 达标（≤3s） |
| P99 延迟 | 1108 ms | **1000 ms** | 达标（≤3s） |
| 吞吐量 | 18.1 req/s | **22.8 req/s** | ↑ 26% |
| 请求失败数 | 0 | **0** | 稳定 |
| 内存增长 | **+915.7%**（48→491MB） | **+7.8%**（50→54MB） | 泄漏修复，波动<10% |

## 达标判定（对照验收标准）
- ✅ 场景A 20 并发无失败，P95 远 ≤ 3s。
- ✅ 压测期间内存波动 < 10%，无持续上涨趋势（基线对比可见泄漏已消除）。
- ✅ 文档解析走异步入队（`/api/v1/documents/parse` 返回 task_id，消费者异步处理），不阻塞问答。
- ✅ Prometheus `/metrics` 暴露请求量/延迟分位/在途/缓存/RSS，可接入 Grafana 长稳监控。

## 结论
通过“单例 + 连接池 + 有界 LRU 缓存 + 异步队列 + LLM 并发限流 + 显式资源释放”，在保持/提升吞吐与延迟的同时，彻底消除内存泄漏，满足验收标准。
