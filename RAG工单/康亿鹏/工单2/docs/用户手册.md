# 用户手册 —— 基于 PDF 文档的问答系统

> 工单编号：**人工智能NLP-RAG-基于PDF文档的问答系统**
> 适用文档：《招股说明书1.pdf》（武汉兴图新科电子股份有限公司）

本手册面向系统使用者与部署人员，介绍环境准备、PDF 入库、提问与查看结果、命令行用法、
效果评估以及常见问题处理。

---

## 1. 环境准备

### 1.1 安装依赖

建议使用独立的 conda 环境（示例环境名 `langchain_ragas`），**一次性安装全部依赖**，避免版本冲突：

```powershell
conda activate langchain_ragas
pip install -r requirements.txt
```

> 若只需运行核心问答功能，可至少安装：
> ```powershell
> pip install langchain langchain-openai langchain-community langchain-text-splitters pymilvus FlagEmbedding sentence-transformers pymupdf streamlit python-dotenv pandas ragas datasets
> ```

### 1.2 启动 Milvus 向量库

使用 Docker 启动 Milvus 单机版（示例）：

```powershell
# 首次拉取并启动
docker run -d --name milvus -p 19530:19530 -p 9091:9091 milvusdb/milvus:latest

# 后续启动
docker start milvus
```

启动后可访问 Attu（Milvus 可视化管理工具）查看集合与数据。

### 1.3 配置环境变量

复制配置模板并填写真实值：

```powershell
copy .env.example .env
```

编辑 `.env`：

```ini
DEEPSEEK_API_KEY1=你的DeepSeek密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_MODEL=deepseek-chat
MILVUS_URI=http://localhost:19530
MILVUS_TOKEN=
```

> 变量名 `DEEPSEEK_API_KEY1` 需与 `config.py` 中的 `LLM_API_KEY` 读取的变量名一致。
> 也可以不创建 `.env`，直接在系统环境变量中设置同名的 `DEEPSEEK_API_KEY1`、`DEEPSEEK_BASE_URL`，同样生效。

> 说明：`.env` 仅存放 **API Key 与服务地址**；其余参数统一在 `config.py` 中修改。

### 1.4 准备 PDF 文档

把待问答的 PDF 放到 `data/raw/` 目录下：

```
data/raw/招股说明书1.pdf
```

如需更换文档，可在入库时用 `--pdf` 指定路径，或在 `config.py` 中修改 `DEFAULT_PDF_PATH`。

## 2. 快速开始（三步）

```powershell
# 第 1 步：解析 PDF 并写入向量库（首次约需数分钟，取决于模型下载与设备）
python main.py ingest

# 第 2 步：命令行验证一个问题
python main.py ask "武汉兴图新科电子股份有限公司法定代表人是谁？"

# 第 3 步：启动图形界面
streamlit run app.py
```

浏览器会自动打开 `http://localhost:8501`。

## 3. 图形界面使用说明

### 3.1 界面布局

| 区域 | 内容 |
| --- | --- |
| 左侧栏 | 知识库管理、检索参数设置、语音输入 |
| 主区域 | 对话区（问题、答案、引用来源、反馈按钮） |

### 3.2 上传并解析 PDF

1. 在左侧栏「① 知识库管理」点击 **上传 PDF 文档**，选择本地 PDF；
2. 点击 **解析并入库**；
3. 等待提示“入库完成：N 条片段”；
4. 在「刷新统计」下方可查看当前集合名、Milvus 地址与片段总数。

> 再次入库同一文档会**清空并重建**集合，避免重复数据。

### 3.3 提问

1. 在底部输入框输入问题，例如：
   `报告期内，武汉兴图新科电子股份有限公司来自军用领域的收入分别是多少？`
2. 按回车发送；
3. 界面会**流式**展示答案，并在答案下方给出：
   - **检索来源**（可展开）：片段内容、页码、类型、重排得分；
   - **耗时信息**：总耗时与召回 / 重排 / 生成各阶段耗时；
   - **Query 理解结果**：意图、规范问题、子问题。

### 3.4 查看结果与反馈

- 点击「查看检索来源与耗时」可核对答案依据，实现**答案可溯源**；
- 点击 **👍 有帮助** / **👎 需改进** 提交使用反馈。

### 3.5 语音输入

1. 在左侧栏「③ 语音输入」点击录音按钮并说出问题；
2. 点击 **识别语音**，识别文本会自动填入提问框并触发问答。

> 语音识别依赖 `SpeechRecognition` 与网络（Google Web Speech API）；
> 未安装或识别失败时，系统会给出提示，不影响文字提问。

### 3.6 检索参数调节

| 参数 | 说明 | 调节建议 |
| --- | --- | --- |
| 向量召回数量 k | 粗排返回的候选片段数 | 答案漏检时增大（如 15~20） |
| 重排后保留数量 top_n | 送入大模型的片段数 | 上下文过长或干扰多时减小（如 2~3） |
| 启用 Query 理解 | 是否进行意图识别 / 消歧 / 分解 | 复杂多跳问题建议开启 |

### 3.7 多语言支持

系统支持中文与英文提问，会**自动使用与问题相同的语言作答**。
例如输入 `Who is the legal representative of the company?`，将返回英文答案。

## 4. 命令行使用说明

| 命令 | 作用 | 示例 |
| --- | --- | --- |
| `ingest` | 解析 PDF 并入库 | `python main.py ingest` |
| `ask` | 单轮问答 | `python main.py ask "注册资本是多少？"` |
| `chat` | 交互式多轮问答 | `python main.py chat` |
| `search` | 仅检索，查看召回片段 | `python main.py search "军用领域收入"` |
| `stats` | 查看知识库统计 | `python main.py stats` |
| `reset` | 清空知识库 | `python main.py reset` |

常用参数：

```powershell
python main.py ingest --pdf "D:\docs\某公司招股书.pdf"   # 指定 PDF
python main.py ingest --no-tables                         # 不解析表格，加快入库
python main.py ingest --append                            # 追加写入而非重建
python main.py ask "法定代表人是谁？" --no-understanding    # 关闭 Query 理解
python main.py ask "法定代表人是谁？" --pure                # 仅大模型回答（不检索）
```

## 5. 效果评估

运行评估脚本，对工单给定的 10 条问题逐条对比 RAG 与纯 LLM 的表现：

```powershell
python evaluate.py
```

可选参数：

```powershell
python evaluate.py --limit 3                 # 仅评估前 3 条，快速试跑
python evaluate.py --no-ragas                # 只使用内置 LLM 评审（RAGAS 不可用时）
python evaluate.py --ground-truth data/ground_truth.json   # 提供参考答案，启用上下文召回率
```

评估完成后：

- 控制台打印汇总报告（检索命中率、平均 / P95 / 最大响应时间、≤3s 比例、四项指标、逐条 RAG 与纯 LLM 答案对照）；
- 结果导出到：

```
output/eval_result_<时间戳>.json    # 完整明细（含检索上下文）
output/eval_result_<时间戳>.csv     # 便于用 Excel 打开对比
```

> 参考答案（可选）格式：`{"260": "参考答案文本", "95": "参考答案文本"}`，键为问题 id。

## 6. 常见问题（FAQ）

**Q1：提示“连接 Milvus 失败”？**
确认 Docker 中 `milvus` 容器已启动（`docker start milvus`），且 `config.py` 中 `MILVUS_URI`
或 `.env` 中的 `MILVUS_URI` 地址正确（默认 `http://localhost:19530`）。

**Q2：提示“未配置 DeepSeek API Key”？**
未创建或未填写 `.env`。复制 `.env.example` 为 `.env` 并填写 `DEEPSEEK_API_KEY1`（或在系统环境变量中设置同名变量）。

**Q3：首次入库很慢 / 卡在下载模型？**
本项目已改为使用 **D 盘本地模型目录**，不会联网下载。路径在 `config.py` 中配置：

```python
EMBEDDING_MODEL_PATH = r"D:\models\bge-m3"
RERANKER_MODEL_PATH  = r"D:\models\bge-reranker-large"
```

若更换模型目录，直接修改上述两行即可。需要联网下载其它模型时，可设置镜像：

```powershell
$env:HF_ENDPOINT="https://hf-mirror.com"
```

**Q4：答案总是“根据提供的文档内容，无法回答该问题”？**
可能是知识库为空（先执行 `ingest`），或问题与文档无关。可先用
`python main.py search "关键词"` 确认是否能召回相关内容，并适当增大召回数量 `k`。

**Q5：响应时间超过 3 秒？**
影响耗时的环节依次为：大模型生成 > 重排 > 向量检索。可采取：
- 使用 GPU 运行嵌入与重排模型；
- 降低 `top_n` 与 `LLM_MAX_TOKENS`；
- 关闭 Query 理解（`--no-understanding`）减少一次 LLM 调用；
- 若输出无需逐字展示，可关闭流式。

**Q6：表格内容没有检索到？**
确认入库时未使用 `--no-tables`，且 `config.py` 中 `ENABLE_TABLE_PARSING = True`。
若 PDF 为扫描件（无文字层），需先做 OCR（属工单 04 范围）。

**Q7：如何更换问答文档？**
将新 PDF 放入 `data/raw/`，用 `python main.py ingest --pdf "新文档路径"` 入库即可；
或在界面左侧上传 PDF 后点击「解析并入库」。

**Q8：评估脚本报 RAGAS 相关错误？**
当前环境若存在 RAGAS 依赖冲突，脚本会**自动降级**为内置 LLM 评审并在报告中标注
`eval_backend`。也可显式使用 `python evaluate.py --no-ragas`。
