# 检索质量优化与对策

> **工单编号**：人工智能 NLP-RAG-基于 PDF 文档的问答系统优化
> 本文以"问题 → 对策 → 验证"的方式，梳理检索质量优化的完整闭环。

---

## 一、问题清单与对策映射

| 编号 | 问题现象 | 根因 | 对策 | 代码位置 | 验证题 |
|---|---|---|---|---|---|
| P1 | 页眉页脚在几乎每页重复 | 未做版式清洗，噪声稀释语义 | 跨页重复行统计 + 剔除 | `pdf_parser.detect_boilerplate` | 全部 |
| P2 | 财务表格数值被截断、表头与数据分离 | 固定长度切片不识别表格 | 表格渲染为 Markdown 原子块 | `pdf_parser._render_table` / `chunking.build_chunks` | Q260、Q33、Q207 |
| P3 | 跨小节"串味" | 切片跨越标题边界 | 结构感知分块（按标题切小节） | `chunking._split_sections` | Q34、Q793 |
| P4 | 上下文不足，答案句被切散 | 子块过短 | 父子块（父块补全上下文） | `chunking.build_chunks` | Q260、Q543 |
| P5 | 公司名等套话占据语义权重 | 整句问题直接检索 | 噪声剥离 + 关键词抽取 + 多路查询 | `query_understanding` | Q34、Q207、Q531 |
| P6 | "能召回但不准"，正确片段排位靠后 | 仅靠 RRF 排名，无内容级信号 | 加权线性重排（5 维信号） | `reranker.Reranker.rerank` | Q33、Q34、Q531 |
| P7 | 答非所问（问下游却召回上游） | 上游/下游语义相近 | 对比词惩罚 | `answer_builder._contrast_penalty` | Q34、Q793 |
| P8 | 签署页人名被误当答案 | 保荐代表人等密集出现 | 套话惩罚 | `answer_builder._boilerplate_penalty` | Q531 |
| P9 | 数值张冠李戴的幻觉 | LLM 生成不可控 | 抽取式合成（零幻觉、可溯源） | `answer_builder.build_answer` | Q260、Q33、Q957 |
| P10 | 回答慢（平均 3.5 s，个别 >10 s） | 推理型模型输出长思维链 | 抽取式合成替代生成 | `qa_engine.answer_optimized` | 全部 |

## 二、分层面优化对策

### 2.1 PDF 解析层

| 对策 | 说明 |
|---|---|
| 版式清洗 | 只统计每页首尾各 3 行，出现次数 ≥ max(3, 页数×25%) 判为模板文字并剔除 |
| 页码剔除 | 正则匹配纯数字/罗马数字短行 |
| 行合并 | 行尾非句末标点且下一行非标题时合并，修复 PDF 断句 |
| 表格结构化 | PyMuPDF `find_tables()` → Markdown，保留行列 |
| 标题识别 | 抽取"第X节/一、/（一）/1.1"作为分块锚点 |

### 2.2 分块层

| 对策 | 说明 |
|---|---|
| 结构感知分块 | 先按标题切语义小节，再在小节内递归切片（700/120） |
| 表格原子块 | 表格整体不可切分（`ctype=table`） |
| 父子块 | 子块检索、父块补上下文；检索按父块去重 |
| 过短合并 | < 60 字符的小节不单独成块 |
| 元数据齐全 | 每块带 `page / section / ctype / parent`，便于溯源与先验打分 |

### 2.3 检索层

| 对策 | 说明 |
|---|---|
| 噪声剥离 | 剔除公司全称、"根据…招股意向书"、"是多少/有哪些"等 |
| 关键词抽取 | jieba 实词 + 去停用词 + 保留数字/年份/单位 |
| 答案类型识别 | ratio/amount/number/list/entity/boolean/fact |
| 多路查询 | 核心问句 + 关键词组合 + 实体增强 |
| 双路召回 | 向量 Top-15 + BM25 Top-15 |
| RRF 融合 | k=60，规避分数量纲不可比 |
| 加权重排 | 向量 0.30 + BM25 0.20 + 关键词覆盖 0.25 + 数值 0.15 + 实体 0.10 |
| 父块去重 | 同小节只保留最高分块 |

### 2.4 答案合成层

| 对策 | 说明 |
|---|---|
| 抽取式 | 从候选句/表格行中抽取，零幻觉、可溯源 |
| 类型感知打分 | 按答案类型选择信号（比例看 %、金额看万元/亿元、列举看顿号密度…） |
| 章节先验 | 基本信息类问题优先"概览/发行人基本情况"章节（权重 0.18） |
| 对比词惩罚 | 问一侧却出现另一侧时降权 0.20 |
| 套话惩罚 | 签署页/中介机构人名密集区降权 0.15 |
| 标题行剔除 | 避免标题关键词误命中 |
| 单页限流 | 同页最多 2 句，保证多样性 |
| 页码引用 | 输出"根据招股说明书第 X 页、第 Y 页：…" |

## 三、关键权衡

| 权衡点 | 选择 | 理由 |
|---|---|---|
| 生成 vs 抽取 | **抽取式** | 需求要求"准确率 ≥ 90% + 响应 ≤ 3 s"，推理型本地模型无法同时满足；抽取式零幻觉、毫秒级 |
| 召回广度 vs 精度 | **扩大候选池 + 重排** | 召回 25 条再重排，兼顾召回与精度 |
| 块粒度 | **700/120 + 父子块** | 兼顾切片语义完整性与上下文补全 |
| 是否用大模型做 Query 理解 | **不用（规则）** | 毫秒级、确定性、无网络依赖；`USE_LLM_QUERY_UNDERSTANDING` 保留开关 |

| 指标 | 优化前 | 优化后 |
|---|---|---|

## 五、后续可优化方向

1. **重排模型升级**：用 `bge-reranker` 交叉编码器替代线性重排，进一步提升 Top-1 精度（当前 70%）；
2. **Query 理解增强**：引入轻量 NER 替代硬编码噪声词表，提升跨文档泛化；
3. **答案可读性**：对抽取式答案做摘要压缩，减少父块上下文带来的冗余；
4. **多文档支持**：扩展为多 PDF 知识库，验证跨文档检索的鲁棒性。
