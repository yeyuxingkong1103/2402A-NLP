## 1. 文档概述

### 1.1 编写目的

本文档面向农户使用场景，定义农业 RAG 知识库的建设目标、知识范围、功能需求、非功能需求、数据需求及评估标准，作为后续知识体系设计、数据采集、文档解析、检索生成与验收的依据。

### 1.2 项目背景

农户在种植过程中遇到病虫草害、施肥浇水、品种选择、灾害应对、政策补贴等问题时，主要依赖农资店推荐、邻里经验或网络搜索，存在信息不权威、不适用本地、农药用量不清等风险。本项目拟构建一个面向农户的农业 RAG 知识库，让农户用口语提问即可获得**可执行、可溯源、带安全提示**的答案。

### 1.3 术语定义

- **RAG**：检索增强生成，先检索知识库再生成答案。
- **Chunk**：知识切分后的最小检索单元。
- **召回**：检索阶段找回相关内容的能力。
- **高危知识**：涉及农药剂量、安全间隔期、禁限用农药、人身安全等，错误后果严重。
- **农户口语**：方言、俗称、症状描述等非标准表达。

### 1.4 参考依据

- 国家及行业标准（GB、NY/T 等）
- 农业农村部公告与地方标准
- 省级农技推广手册
- 相关科研文献

## 3. 用户分析

### 3.1 目标用户画像

- **小农户**：种植面积小，依赖经验，手机使用能力一般。
- **种植大户/合作社**：面积大，关注成本与效率，会用手机查信息。
- **年龄**：以 40–65 岁为主。
- **阅读习惯**：偏好短句、分步骤、结论前置，不喜长篇科普。

### 3.2 使用场景

- 田间地头手机文字或语音提问
- 农闲时提前查询
- 突发病虫害或灾害时紧急查询

### 3.3 用户表达特征

- 口语化、方言、错别字多
- 描述症状而非病名（如“叶子有黄斑”）
- 问题短、信息不全（常缺作物、生育期、地区）

### 3.4 用户核心诉求（按优先级）

1. 打什么药 / 施什么肥
2. 用多少量
3. 什么时候用
4. 多久后能采收/能吃
5. 去哪买 / 有没有补贴

### 4.5 地域与时效标注规则

- 适用地区粒度：**☑ 全国**（本批语料为全国性国标）、☐ 省 ☐ 市 ☐ 县；原文明确写地方范围时才填地方
- 每条知识标注适用年份，取值为**标准发布年**（本批为 2009–2022，多数为 2011），不得用采集年冒充
- 农药登记、政策类知识每季度复核
- 过期知识自动标记"待更新"，不参与检索
- **重点时效风险**：2011 年标准中的药剂方案可能已被后续农药登记公告限用或禁用，高危答案必须带核实提示并引导咨询当地农技站

## 5. 功能需求

### 5.1 查询输入

- 支持文字与语音输入
- 支持口语、错别字、方言容错
- 信息不全时主动追问：作物？生育期？地区？

### 5.2 检索

- 混合检索：向量 + 关键词（BM25）+ 元数据过滤
- 按作物、地域、年份过滤
- 查询改写：补全作物与生育期

### 5.3 答案生成

### 7.3 数据质量要求

- 去重、纠错、术语归一
- OCR 错误修正（**只记录不确定项，不得改数**；数值/单位一律以原文为准）
- 上标还原（`667m` + `2` → `667m²`、`hm` + `2` → `hm²`）并记入 `ocr_uncertain`
- 页眉页脚（如 `GB/Z26583—2011`、页码）不得进入引用原文
- 表格列错位时填 `null` 并记入 `missing_fields`，**禁止跨行猜配药剂与剂量**
- 交叉验证三级来源

### 7.4 元数据字段（与 `configs/prompts/parse_pdf_to_knowledge.md` 的 schema 一致）

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `card_id` | 是 | 唯一 ID，形如 GBZ26583-2011-p20-c03 |
| 标准号/名称 `std_no` / `std_name` | 是 | GB/Z 26583-2011 / 辣椒生产技术规范 |
| 作物 `crop` | 是 | 原文没写填 `null`，不得按常识推断 |
| 俗称 `crop_alias` | 否 | 只在原文出现俗称时填，不得自造 |
| 地域 `region` | 是 | 本批=全国；原文写地方才填地方 |
| 生育期 `growth_stage` | 否 | 原文表述，找不到填 `null` |
| 知识类型 `knowledge_type` / `type_group` | 是 | 细类 + 对齐 4.1 的 6 大类。**`knowledge_type` 只取枚举值**（病虫害防治/杂草防治/鼠害防治/土肥水管理/品种选择/农事操作/灾害应对/政策补贴/基地与投入品管理/劳动保护/档案记录/加工贮运/其他），**没有「病害防治」「虫害防治」**——病/虫细分见 `pest_kind` |
| 病/虫/草细分 `pest_kind` | 否 | 病害 / 虫害 / 杂草 / `null`。`knowledge_type` 的细分维度；「防治原则」这类病、虫兼有的通用条款填 `null`，不硬分 |
| 细类 `subtype` / 标题 `title` | 是 | 如 蚜虫 / "辣椒生长期蚜虫化学防治方案" |
| 症状 `symptoms` / 触发条件 `trigger` | 否 | 原文照抄；`trigger` 可承载防治指标（如 8头/株~10头/株）。⚠️ **卡片本体的 `symptoms` 全为 null**——三份国标正文无症状描述，没有可照抄的原文就不得编；症状知识改由**挂卡覆盖层** `data/processed/symptoms.jsonl` 提供（外部二级来源、逐条带字段级来源、按 `card_id` 挂到 203 张进索引的卡上），切分时并入 `sym_text` 喂编码，卡片本体一个字不动；症状**绝不进** 4.6 的口语映射表（那张表只做词形替换，写症状＝造诊断） |
| 措施 `measures`（数组） | 否 | 农业/生物/物理/化学防治等，逐条含原文 |
| 药剂 `chemicals`（数组） | 高危必填 | 产品/有效成分/剂量/兑水/施用方法/施药间隔/安全间隔期/每茬最多使用次数/原文 |
| 肥料 `fertilizer` | 否 | 类型/用量/方法/生育期 |
| 注意事项 `precautions` | 否 | 原文照抄（含禁用/限用表述） |
| 兼治对象 `chemicals[].companion_control` | 否 | 原文照抄，无则 `null`。**粒度是方案级**：同一防治对象的不同方案兼治对象可能不同，须挂在各自 `chemicals[]` 下 |
| 记录表单 `record_form` | 否 | 仅附录A 记录表类卡片填，其他卡 `null`；含 `table_no` / `table_name` / `header_items` / `columns` / `footnote` / `is_blank_form`。**表号须取该标准自己的原文**——三份标准的表号→表名映射并不一致 |
| 来源 `source` | 是 | `std_no` + `section`（条款号或"附录B 表B.1"）+ `page`（PDF 物理页）+ `channel`（text/vision/mixed）+ `quote`（≤200 字原文） |
| 年份 `year` | 是 | **标准发布年** |
| 权威等级 `authority_level` | 是 | 1=国标/行标/部委文件，2=手册/文献，3=网络；团体标准按 1 级但需注明 |
| 是否高危 `is_high_risk` | 是 | 是 / 否 |
| 高危原因 `high_risk_reasons` | 高危必填 | 枚举：农药剂量、安全间隔期、每茬最多使用次数、防治指标、禁用限用、混用、施药安全 |

| `missing_fields` / `ocr_uncertain` | 否 | 缺失字段路径、预处理不确定项 |

### 7.6 解析要求（本期新增，依据第一批语料的实测问题）

1. **双通道分流**：逐页判断，文本层可读（CJK 字数足够）走通道 A（文本抽取/MinerU），文本层为字形码或该页含表格则走通道 B（页面渲染 150–200dpi → 视觉模型逐页转录）。本批 175 页属于通道 B。
2. **表格一律以视觉转录为准**：即使文本层"能抽出字"，附录 B 表格也会被压成一列导致药剂与剂量错配——这是最不可接受的错误类型。
3. **只抽取不改写**：解析阶段不做"农户友好"改写（那是生成阶段的职责）。数值、单位、药剂名逐字保留，禁止换算。
4. **可溯源定位**：每张卡必须给出条款号/表号 + PDF 物理页码 + ≤200 字原文引用，供人工复核。
5. **乱码不猜字**：字形码页返回 `abort` 并转视觉通道，绝不用字形码拼字。
6. 提示词与设计说明见 `configs/prompts/` 与 `docs/05-解析提示词设计.md`。
7. **视觉转录后回填缺口结论**：字形码页转录完成后，必须重跑关键词复核（`农药混用` / `限用` / `禁` / `安全间隔期` / `每茬最多使用次数` / `防治指标`），把结果回写 2.2 的缺口表并记录前后差异——「本批语料没有 X」这类结论只能由这个复核给出，不能用文本层统计一锤定音（大蒜的附录 B 就是反例）。
   - **执行情况（2026-09-27）**：本期 3 份已复核完毕（视觉转录 16 页），结论与前后差异见 2.2；**非本期 23 份的 151 页字形码页仍未转录**，对那 23 份的「没有 X」维持「未复核」，只能按「暂无」作答。
