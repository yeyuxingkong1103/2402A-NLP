## 1. 启动系统

双击项目根目录下的 **`start.bat`**。

脚本会自动完成：

1. 检查 Python 环境；
2. 注入 MinerU 中文路径补丁（本项目路径含中文，必须）；
3. 启动 Redis（已装则跳过）；
4. 用 Docker 启动 Milvus（未装 Docker 会自动跳过并降级）；
5. 启动后端服务并在浏览器打开 <http://127.0.0.1:8000>。

> 首次启动需要 3–5 分钟预热模型（bge-m3、bge-reranker）。看到控制台输出 `[预热] 模型与服务依赖已就绪` 即可开始使用。

**若不想用命令行**，也可以手动启动：

```bat
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 2. 如何上传 PDF

1. 点击顶部 **「知识库」** 标签页。
2. 点击 **「选择文件」**，选中要问的 PDF。
3. 选择解析引擎：
   - **MinerU（表格精度高）** —— 推荐。能还原表格的行列结构。548 页的招股书约需 **15–25 分钟**。
   - **快速解析（pymupdf，无 MinerU）** —— 约 1 分钟，速度快，但表格是规则抽取、结构较差。
4. 点击 **「开始解析入库」**。
5. 观察进度条与状态文字，依次经过：
   ```
   parsing  → 正在解析 PDF…
   parsing  → 解析完成（mineru），共 4061 个块，正在语义分块…
   indexing → 分块完成，共 872 块，正在向量化入库…
   done     → 入库完成：872 条，解析器 mineru
   ```
6. 完成后，下方「已入库文档」表格会出现该文档，显示分块数、表格块数、最大页码与文档 ID。

> **同一个 PDF 重复上传不会产生重复数据**：系统按文件内容指纹（md5）识别，重复上传会先清除旧索引再写入。

> **扫描件不支持**：如果 PDF 是拍照/扫描生成的（无法选中文字），上传后会提示「未提取到任何文本」。请先用带 OCR 的工具另存为带文本层的 PDF 再上传。

### 查看已解析的内容

在「已入库文档」表格中点击 **「查看分块」**，可以：

- 逐条查看解析出的文字块与表格块（带页码、类型标记）；
- 用上方的下拉框只看 `text` 或只看 `table`；
- 用「上一页 / 下一页」翻页。

这一步可以直观验证「PDF 解析是否准确」。

### 删除文档

点击 **「删除」** 并确认，该文档的全部向量与关键词索引会被一并清除。

## 3. 如何提问

1. 点击 **「问答」** 标签页。
2. 在输入框中输入问题，例如：

   > 武汉兴图新科电子股份有限公司法定代表人是谁？

3. 按 **Ctrl+Enter** 或点击 **「提 问」**。

也可以直接点击下方的**示例问题**按钮快速体验。

### 提问技巧

| 建议 | 说明 |
|---|---|
| 一次问一件事 | 系统能处理多跳问题，但单点问题更准更快 |
| 带上主体 | 如"武汉兴图新科电子股份有限公司的注册资本"，便于关键词召回 |
| 数字类问题说清口径 | 如"报告期内""2018 年度"，便于定位到对应表格 |
| 不需要加"请根据 PDF 回答" | 系统已强制只用检索到的资料作答 |

### 高级选项（可选）

| 选项 | 说明 |
|---|---|
| 启用重排 | 默认开启。用 bge-reranker-v2-m3 对候选片段精排。实测：开启时关键事实命中率 100%、完整答案约 3.1s；关闭后命中率降到 80%、但完整答案降到 2.0s。对准确性要求高就保持开启 |
| Query理解 | `自动`（默认）：简单问题走本地规则，零延迟；复杂问题才调大模型<br>`强制LLM`：总是调用 DeepSeek 做消歧与子问题分解（会明显变慢）<br>`仅本地`：完全不调大模型做查询理解 |

## 4. 如何查看结果

提问后，页面分两块展示：

### 4.1 回答区

- **答案正文**：以打字机效果流式显示，首字通常 1–2 秒内出现。
- **耗时标签**：
  - `检索 x.xx s` —— 从提问到拿到引用片段的时间；
  - `首字 x.xx s` —— 你看到第一个字的时间；
  - `总耗时 x.xx s` —— 完整答案生成完毕的时间（**绿色**=3 秒内，**红色**=超过 3 秒）；
  - `缓存命中` —— 该问题此前问过，直接返回缓存结果（通常 <0.1 秒）；
  - `已降级` —— 大模型服务暂时不可用，系统返回了检索到的原文摘录。
- **Query理解**：显示本次意图识别结果与理解来源（`local` 本地规则 / `llm` 大模型改写）。

### 4.2 引用片段区

每个片段显示：

| 标记 | 含义 |
|---|---|
| `#1` | 片段序号，按相关度排序 |
| `第 N 页` | 该片段在 PDF 中的页码，可据此翻原文核对 |
| `text` / `table` | 片段来自正文还是表格 |
| `score x.xx` | 重排后的相关度分数（0–1，越高越相关） |

> **核对答案**：把「页码」对照 PDF 原文即可验证答案真伪。这是本系统与纯大模型最大的区别——每个答案都可溯源。

## 5. 如何反馈

在回答下方点击：

- **👍 有帮助** —— 点赞
- **👎 没帮助** —— 点踩

点击后按钮置灰，右侧会显示累计的点赞/点踩数。反馈会被记录，供后续优化检索与提示词使用。

## 6. RAG 与纯 LLM 对比

点击顶部 **「RAG对比」** 标签页：

1. 输入问题，点击 **「开始对比」**；
2. 左右分栏同时展示：
   - **左：RAG（检索增强）** —— 基于 PDF 内容回答，附引用片段数与耗时；
   - **右：纯 LLM（不传上下文）** —— 只用大模型自身知识回答，不传任何资料。

**典型差异**：对于招股书里的具体数字（如注册资本 5,520 万元、军用领域收入 6,464.51 万元），纯 LLM 通常答不出或编造，而 RAG 能给出正确数字并标注来源页码。

## 7. 如何查看评估结果

点击顶部 **「评估」** 标签页：

1. 点击 **「开始评估」**；
2. 系统会依次执行工单列出的 10 个问题，每个问题分别走 RAG 链路与纯 LLM 链路；
3. 随后调用 RAGAS 计算四项指标，约需数分钟；
4. 完成后页面展示：
   - **四个指标卡片**：`faithfulness`（忠实度）、`answer_relevancy`（答案相关性）、`context_precision`（上下文精确率）、`context_recall`（上下文召回率）；
   - **耗时摘要**：平均耗时、3 秒内达标率；
   - **逐题对比表**：每题的问题、RAG 回答、纯 LLM 回答、耗时。

## 8. 界面语言切换与语音输入

### 语言切换

点击右上角的 **中文** / **EN**，整个界面文案会切换为英文。同时语音识别语言也会跟着切换（中文 → `zh-CN`，英文 → `en-US`）。

### 语音输入

在问答页输入框左侧有一个 **🎤** 按钮：

1. 点击后浏览器会请求麦克风权限，请选择「允许」；
2. 按钮变红表示正在聆听，说出问题；
3. 识别完成后文字自动填入输入框，再点「提问」即可。

> **浏览器要求**：语音识别使用浏览器原生的 Web Speech API，**Chrome / Edge 支持**。若使用不支持的浏览器，🎤 按钮会自动隐藏。
> 需要联网，语音由浏览器厂商的识别服务处理。

## 9. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 右上角状态显示 `degraded` | 知识库为空（还没上传 PDF），或 Milvus 未启动。先上传 PDF，或运行 `start.bat` 启动 Milvus |
| 提问后回答"资料中未找到" | 该问题所需内容不在已入库的 PDF 里，或分块未覆盖。可换一种问法（更贴近原文用词） |
| 回答出现「生成服务暂不可用」 | DeepSeek 接口超时或 Key 失效。请检查 `.env` 中的 `LLM_API_KEY` 与网络 |
| 回答带「（已降级）」标记 | 同上，系统此时返回的是检索到的原文摘录，仍然可溯源 |
| 上传后立刻提问答不出来 | 请确认任务状态已变为 `done`；Milvus 采用强一致性，入库完成后立即可检索 |
| 上传后提示「未提取到任何文本，可能是扫描件」 | 该 PDF 没有文本层（扫描件）。系统会明确报错而不是静默入库空内容。请改用带文本层的 PDF |
| 首次提问特别慢（十几秒） | 模型预热未完成。等控制台出现 `[预热] 模型与服务依赖已就绪` 后再提问 |
| 语音按钮点了没反应 | 浏览器不支持或未授权麦克风。请用 Chrome/Edge 并允许麦克风权限 |
| 想清空知识库重来 | 在「知识库」页逐个删除文档，或执行 `python -c "from app import store; store.ensure_collection(drop=True)"` |
