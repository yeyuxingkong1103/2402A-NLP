# 金融问答系统 · 系统设计文档

> **工单编号：人工智能 NLP-RAG-金融问答系统部署**
> 任务：将已开发的金融问答系统以 Docker 容器的形式部署在服务器中，并运行成功，以便于金融场景下的对话功能。
> 工时预估：1 人日 ｜ 方向：人工智能 NLP

---

## 一、项目背景与目标

前序工单（01 基于 PDF 的问答系统 → 02 优化 → 03 表格解析 → 04 图像解析 → 05 Query 理解 → 06 混合检索 → 07 功能测试及评估）已完成一套可用的
**RAG 金融问答系统**：以 9 份 A 股上市公司年度报告（银行 / 保险 / 证券，共 2812 页）为知识源，
支持多嵌入模型向量召回、倒排索引全文检索、混合融合与多级重排，以及多轮对话理解。

本工单的目标是**把该系统交付为可部署的容器化服务**：

| 目标 | 说明 |
|---|---|
| 容器化 | 以 Docker 镜像封装应用 + 依赖 + 知识库，一条命令拉起服务 |
| 可服务 | 容器启动后在 **8501** 端口提供 Streamlit 金融问答界面 |
| 可持久 | 关键数据（知识库 / 年报 / 运行产物）通过 **Docker 命名卷** 持久化，容器重建不丢数据 |
| 可共享 | 多容器挂载同一命名卷，实现容器间数据共享，便于横向扩展 |
| 可互通 | 自定义 bridge 网络，容器可与对端服务（RTMP 流媒体服务器）正常通信 |

## 二、总体架构

系统采用「**应用分层 + 容器化承载**」的两维架构。

### 2.1 应用分层（纵向）

```
┌───────────────────────────────────────────────────────────────┐
│  展示层    Streamlit 界面 (app.py)  ·  端口 8501               │
│            多轮对话 / 检索策略配置面板 / 证据溯源 / 反馈        │
├───────────────────────────────────────────────────────────────┤
│  理解层    Query 理解 · 同义词扩展 · 多轮改写（指代消解/省略补全）│
├───────────────────────────────────────────────────────────────┤
│  检索层    混合检索 HybridRetriever                             │
│            ├── 向量召回 VectorRetriever  (Ollama 嵌入)          │
│            └── 全文召回 FulltextRetriever (倒排索引 / BM25)     │
│            融合：加权平均 / RRF / 投票                          │
├───────────────────────────────────────────────────────────────┤
│  重排层    linear / tfidf / llm / adaptive / none               │
├───────────────────────────────────────────────────────────────┤
│  索引层    向量库 emb_*.npy  ·  倒排索引 inverted_index.pkl     │
│            ·  切片 chunks.jsonl  ·  元信息 meta.json            │
├───────────────────────────────────────────────────────────────┤
│  数据层    9 份上市公司年报 PDF  ·  评测题集                    │
└───────────────────────────────────────────────────────────────┘
```

### 2.2 容器化承载（横向）

| 容器 | 镜像 | 职责 | 端口 |
|---|---|---|---|
| `finqa-app` | `finqa:1.0` | 金融问答服务（Streamlit） | 8501 |
| `finqa-rtmp` | `finqa-rtmp:1.0` | 对端流媒体服务（RTMP 握手，验证网络互通） | 1935 |
| `finqa-kb-tool` | `finqa:1.0` | 一次性数据共享演示容器（复用主镜像） | — |

外部依赖：**宿主 Ollama**（`http://host.docker.internal:11434`）提供嵌入模型与 LLM，
容器内不落 GPU / torch 重依赖，镜像轻量、构建稳定。

> 架构图见 `设计/流程图/01_系统总体架构.png`。

## 三、关键技术选型

| 维度 | 选型 | 理由 |
|---|---|---|
| 基础镜像 | `python:3.10-slim` | 与应用宿主 CPython 3.10 对齐；slim 体积小；glibc 兼容主流 wheel |
| Web 框架 | Streamlit 1.65.0 | 前序工单已用；内置 `/_stcore/health` 健康检查端点 |
| 向量编码 | Ollama HTTP（bge-m3 / bge-large / nomic-embed） | 免去容器内 torch/GPU，宿主统一托管模型 |
| 全文检索 | 自研倒排索引 + BM25 | 无第三方检索服务依赖，纯 Python 可移植 |
| 数据持久化 | Docker 命名卷（named volume） | 生命周期独立于容器；首次启动自动播种镜像内置知识库 |
| 容器编排 | Docker Compose v2 | 一条命令管理服务 / 网络 / 卷 / 对端服务 |
| 对端服务 | 自研最小 RTMP 服务器（标准库） | 公共 RTMP 镜像在镜像站白名单中不可用，自建可控 |

## 四、核心流程与决策

### 4.1 一次问答的核心流程

```
用户提问
  → Query 理解（实体识别 / 噪声剥离 / 同义词扩展）
  → 多轮改写（指代消解、省略补全；跨轮话题实体继承）
  → 混合检索：向量召回 Top-K ∥ 全文召回 Top-K
  → 融合（RRF / 加权 / 投票）
  → 重排（linear 多信号融合）
  → 答案合成（抽取式 + 模板，含数值/比例/列举型）
  → 输出答案 + 证据（来源文档 / 页码 / 分块类型 / 分数）
```

### 4.2 检索策略决策

| 问法特征 | 建议策略 | 说明 |
|---|---|---|
| 表述与原文不同、需语义理解 | 向量检索 | 例：「招商银行全年赚了多少钱」 |
| 精确术语 / 引号短语 / 布尔式 | 全文检索 | 例：`不良贷款率 AND 拨备覆盖率` |
| 混合、复杂分析型 | **混合检索（默认）** | RRF 融合，兼顾语义与词法 |
| 结构化数值 / 比例 | 混合 + linear 重排 | 数值信号加权，表格块加成 |

> 核心流程与决策图见 `设计/流程图/04_问答核心流程与决策.png`。

## 五、容器化设计要点

### 5.1 镜像分层

```
python:3.10-slim                     ← 基础层（本地已有，无需联网拉取）
  └─ pip install requirements.docker ← 依赖层（国内源，独立成层便于缓存）
      └─ COPY src/ app.py ...        ← 代码层
          └─ COPY data/ vector_db/   ← 数据层（命名卷初始种子）
              └─ USER appuser        ← 非 root 运行
```

### 5.2 数据持久化设计

| 命名卷 | 容器内路径 | 承载数据 |
|---|---|---|
| `finqa_kb_vol` | `/app/vector_db` | 向量库 `emb_*.npy`、倒排索引 `inverted_index.pkl`、切片 `chunks.jsonl`、`meta.json` |
| `finqa_data_vol` | `/app/data` | 9 份年报 PDF、评测题集 |
| `finqa_out_vol` | `/app/output` | 运行产物、共享数据 `shared/writers.json` |

**播种机制**：镜像内 `/app/vector_db`、`/app/data` 预置了完整知识库与数据集。
首次创建命名卷时，Docker 会把镜像目录内容**自动播种**进空卷，因此容器首次启动即可直接问答，
无需在容器内重建索引；此后对卷的写入与容器生命周期解耦，实现「数据不丢失」。

### 5.3 网络设计

```
宿主
 ├─ Ollama :11434  ◄── host.docker.internal（--add-host host-gateway）
 └─ Docker 自定义 bridge 网络 finqa-net
       ├─ finqa-app  172.18.0.2:8501
       └─ finqa-rtmp 172.18.0.x:1935
```

- 宿主侧经 `-p 8501:8501` 访问问答服务；
- 容器间经 `finqa-net` 内建 DNS 按**容器名**互相解析（无需 IP）；
- 容器访问宿主 Ollama 经 `host.docker.internal`，在 Linux 宿主上通过 `--add-host host.docker.internal:host-gateway` 注入。

> 容器网络与存储拓扑图见 `设计/流程图/03_容器网络与存储拓扑.png`。

### 5.4 健康检查与运行安全

- **HEALTHCHECK**：每 30s 请求 `http://127.0.0.1:8501/_stcore/health`，期望返回 `ok`；
  因容器内不装 `curl`，改用 Python 标准库 `urllib` 实现，零额外依赖。
- **非 root**：容器以 `appuser(uid=1000)` 运行，降低越权风险。
- **时区**：`TZ=Asia/Shanghai`，并通过 `tzdata` 包保证时区数据可用。

## 六、配置项

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://host.docker.internal:11434` | 宿主 Ollama 地址 |
| `EMBEDDING_MODEL_SLUG` | `bge-m3` | 嵌入模型（bge-m3 / bge-large / nomic-embed） |
| `RETRIEVAL_STRATEGY` | `hybrid` | 检索策略（vector / fulltext / hybrid） |
| `RERANKER` | `linear` | 重排算法 |
| `TZ` | `Asia/Shanghai` | 时区 |
| `TOP_K` / `RECALL_K` | `8` / `150` | 展示条数 / 召回候选数 |

> `.env` 由 `python-dotenv` 加载，**默认不覆盖**已存在的环境变量，
> 因此 `docker run -e` 与 `compose environment` 的配置优先于镜像内 `.env` 生效。
