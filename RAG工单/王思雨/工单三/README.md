### ⚠️ 一个必须说明的教训：首轮 14/14 是假满分

首轮自动判分给出 accuracy = 1.0，但**逐条人工核对答案原文发现 id 4 是错的**——它多答了 `佰力电子`、`盈硅电子` 两家「曾为关联方但目前已不存在关联关系」的企业。

原因是判分口径只查"关键字段是否都在"，**看得见漏答、看不见多答**；而 RAG 最典型的错误恰恰是"把范围相近的不同表的条目合并作答"。工单要求"检索结果准确无误"，多答同样是错。

**处置**：① 判分口径补负样本清单，改为"关键字段全在 **且** 非目标实体不在"；② 先用首轮那条错误答案回判，确认新口径会判它 False（**判分器本身也要验证，否则只是换个方式假通过**）；③ 重跑 14 题，加严后仍是 100%。

### 📋 降级路径验证规范（本项目适用，后续工单建议沿用）

**规则：文档里每写一条容错/降级，就必须有一条"真把依赖停掉"的实测记录，并逐项标注「已实测 / 未实测」。**

这条规范的由来：本项目一度在文档里写着"Milvus 不可用时降级到 BM25"，**停掉容器后证明是假的**——
而它返回的是一句体面的中文提示，看不出任何异常，所以被当成"已验证"写了很久。

四条具体做法：

1. **不许读代码下结论**。"这里有个 except 分支"不等于"这条路径真的会按预期走"。
   本项目这轮查出的 4 个缺陷，**全部是读代码看不出来、只有停掉依赖才会现的**。
2. **注意构造阶段的异常**。客户端对象（Milvus / Redis / DB driver）常常在**实例化**时就连接，
   里层函数的 try 拦不到。兜底必须放在实例化的那一层，否则就是死代码。
3. **查出第一个坏分支后，把同一类分支全部过一遍**。踩一次是运气，踩两次是模式。
   本项目修完 Milvus 后按这个思路逐个停依赖复测，同批又查出故障源误报、索引损坏无提示、OCR 兜底不可用 3 个。
4. **误报的故障源和"没有提示"一样有害**。本项目出现过"向量模型路径错、日志却报 Milvus 不可用"，
   这种日志会把排障直接带偏。

**当前状态**：容错表 **15 项，全部停机实测，未实测项为零**（明细见 `docs/03_test.md` §5）。

### ⚠️ 停机实测推翻了自己文档里的说法

文档里一直写着"Milvus 不可用时降级到 BM25"。**真把 Milvus 停掉后，这条是假的**——`MilvusClient()` 在构造阶段就抛异常，异常绕过了里层兜底分支，问答直接整体失败；返回的却是一句"系统繁忙"，看着像友好降级，所以此前一直被当成"已验证"。

这一轮把 15 条容错路径**逐条停机实测**，共查出 **4 个真实缺陷**：

| 缺陷 | 性质 |
|---|---|
| Milvus 降级是假的 | 兜底层级与异常抛出层级不匹配 |
| 故障源误报 | 向量模型路径错，日志却报成"Milvus 不可用"，会把排障带偏 |
| 索引损坏无有效提示 | 只回"系统繁忙"，用户不知道要重建索引 |
| 扫描件 OCR 兜底不可用 | PaddleOCR 模型打不开中文路径（与 MinerU 的 fasttext 同类问题） |

**降级不再静默**：现在返回 `retrieval_mode` / `degraded` / `degraded_reason`，前端显示橙色横幅。
原因是 BM25 单通道下质量**确实**下降——实测问"兴图新科法定代表人"会混入真实存在的关联实体「武汉兴图投资有限公司」（纯关键词分不清"兴图新科"与"兴图投资"）。
**降级档的准确率与响应时间不能按正常档的验收标准衡量**，这一点写在 `docs/03_test.md` §5.2。

全部修复见 `docs/04_optimize.md` 优化点 8~14，完整过程见 `docs/03_test.md` §5、§7。

## 2. 检索链路

```
PDF 解析(MinerU) → 表格结构化+定位 ★ → 语义分块 → bge-m3 向量化 → Milvus 存储
   → BM25 关键词检索 ┐
   → Milvus 向量检索 ┘→ 并行召回 → 加权融合 → bge-reranker-v2-m3 重排
   → DeepSeek 生成 → Redis 缓存 → FastAPI 返回 → Vue 展示
```

**表格怎么定位答案**（工单 P8 备注 1 的正面回答）：

1. MinerU 的表格只在 `table_body`（HTML）字段里，只读 `text` 会丢掉全部 590 张表；
2. 展开 `rowspan`/`colspan` 还原成规整单元格矩阵——不展开时"关联方名称/持股比例/与本公司关系"会与数据行错列；
3. 首行各格都短且不含数字才算表头，识别不出就整表当数据，避免丢内容；
4. 每个数据行生成一个块，文本是 `表头:值` 逐对拼接，并写入 `page_no` / `table_id` / `row_index` / `locator`：

```
[table_row] 招股说明书2 P157 表1 第1行
关联方名称:赵马克 | 持股比例:42.35% | 与本公司关系:公司控股股东
```

每张表**另产出一个整表块**，承载"不存在控制关系的关联方企业有哪些"这类需跨 7 行汇总的问题，避免被 Top-N 截断。
