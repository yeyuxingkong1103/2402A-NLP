## 1. 镜像 `rag-finance:1.0`

| 项 | 值 |
|---|---|
| 基础镜像 | `python:3.11-slim` |
| 体积 | 3.40 GB |
| 工作目录 | `/app` |
| 入口 | `/entrypoint.sh`（前置自检 → 启动 Gradio） |
| 默认命令 | `python -u app.py` |
| 暴露端口 | `7860` |

### 1.1 环境变量

| 变量 | 默认值 | 必填 | 说明 |
|---|---|---|---|
| `DEEPSEEK_BASE_URL` | — | ✅ | 大模型接口地址 |
| `DEEPSEEK_API_KEY` | — | ✅ | 大模型密钥 |
| `BGE_M3_PATH` | `/models/bge-m3` | | 向量模型目录（镜像内路径） |
| `KB_CACHE_DIR` | `/kb` | | 知识库根目录（卷挂载点） |
| `PORT` | `7860` | | 容器内监听端口 |
| `HOST` | `0.0.0.0` | | 监听地址 |
| `GRADIO_ANALYTICS_ENABLED` | `False` | | 关掉 Gradio 匿名统计上报 |
| `TRANSFORMERS_VERBOSITY` | `error` | | 压掉 transformers 告警（验收要求日志无异常） |
| `TOKENIZERS_PARALLELISM` | `false` | | 同上 |
| `HF_HUB_OFFLINE` | `1` | | 禁止联网拉模型，模型只从本地卷读 |

### 1.2 卷挂载点

| 路径 | 建议挂载 | 读写 | 不挂会怎样 |
|---|---|---|---|
| `/models` | `model-data` 卷 | 只读 | **启动失败**，入口脚本报「模型目录不存在」 |
| `/kb` | `kb-data` 卷 | 读写 | 用容器内临时目录，容器一删知识库和反馈日志全丢 |

### 1.3 健康检查

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --start-period=180s --retries=3 \
    CMD curl -fsS "http://127.0.0.1:${PORT:-7860}/" >/dev/null || exit 1
```

`start-period` 180 秒是给模型加载留的余量（BGE-M3 约 3.2GB 显存 + 7009 块知识库）。
期间状态是 `starting` 属正常，不是故障。

### 1.4 最小启动命令

```bash
docker run -d --name rag-app --gpus all -p 7860:7860 \
  -v rag-finance_model-data:/models:ro \
  -v rag-finance_kb-data:/kb \
  -e DEEPSEEK_BASE_URL=https://api.deepseek.com \
  -e DEEPSEEK_API_KEY=sk-你的密钥 \
  rag-finance:1.0
```

知识库由入口脚本从镜像内的种子自动初始化，**不需要额外挂载**。

## 2. 镜像 `rag-rtmp:1.0`

网络连通性验证的对端，基于 `alpine:3.20` + `nginx-mod-rtmp`，体积 4.2MB。

| 端口 | 用途 |
|---|---|
| `1935` | RTMP 推流（验收测试在这个端口做 TCP 连通性探测） |
| `80` | 健康检查 `/health`、RTMP 状态页 `/stat` |

健康检查：`wget -qO- http://127.0.0.1/health`。

## 3. Compose 服务

| 服务 | 镜像 | Profiles | 端口 | 卷 |
|---|---|---|---|---|
| `rag-app` | `rag-finance:1.0` | 默认启动 | `${APP_PORT:-7860}:7860` | `model-data:ro`、`kb-data` |
| `rtmp-server` | `rag-rtmp:1.0` | 默认启动 | `1935:1935`、`8080:80` | — |
| `kb-builder` | `rag-finance:1.0` | `tools` | — | `model-data:ro`、`kb-data`、语料`:ro` |
| `model-init` | `alpine:3.20` | `init` | — | 宿主机模型`:ro`、`model-data` |

网络：`rag-net`（bridge，提供容器名 DNS 解析）。
卷：`model-data`、`kb-data`。

`kb-builder` 与 `rag-app` **挂同一个 `kb-data` 卷** ——
这是「容器间数据共享」的实际用法：换语料时重建知识库不必动主服务。

| `DEEPSEEK_BASE_URL` | — | **必填** |

模板见 `部署/.env.example`。`.env` 里有密钥，已在 `.gitignore` 里排除。

## 5. 脚本接口

### 5.1 `部署/entrypoint.sh`

容器入口。环境变量：`BGE_M3_PATH`、`KB_CACHE_DIR`、`KB_NAME`（默认
`ccf_competition`）、`PORT`、`SEED_KB`（默认 `/app/seed_kb`）。

自检失败时以非 0 退出，错误信息里写明缺什么、该怎么挂载。

### 5.2 `测试/验收测试.sh`

把工单三条验收标准跑成 15 项检查。

```bash
bash 测试/验收测试.sh          # 输出到 测试/验收结果.log，全过则退出码 0
```

只创建并清理临时容器 `rag-verify`（宿主机端口 `APP_PORT+1`），
**不动 `rag-app` 与数据卷**。

### 5.3 `测试/部署截图.py`

```bash
python 测试/部署截图.py [--url http://127.0.0.1:7860]
```

连接**已部署的容器服务**截图（不是本地起进程），输出到 `测试/截图/`。

### 5.4 `研发/build_kb.py`

由 `kb-builder` 服务调用，也可直接执行。

```bash
python 研发/build_kb.py [--limit N] [--no-cache]
```

读环境变量 `CORPUS_DIR`（语料目录，需含 `pdf/` 与 `txt/`）、
`KB_CACHE_DIR`（知识库输出目录）、`BGE_M3_PATH`（向量模型）。
