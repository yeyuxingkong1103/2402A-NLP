# 优化方案文档

> 工单编号：人工智能NLP-RAG项目-Embedding模型微调任务

---

## 一、问题背景：语义鸿沟

通用 Embedding 模型（bge-base）在大规模通用语料上预训练，但面对金融年报中的专业术语（如"净息差""拨备覆盖率""偿付能力充足率""保险资金投资组合"）和特定实体，存在语义鸿沟：

- **误解查询**：将金融术语按通用语义理解
- **遗漏相关文档**：专业同义词、别称无法关联
- **检索不相关文档**：过度强调通用表面相似度

**解决思路**：在金融问答数据上微调 Embedding 模型，重塑嵌入空间。

## 二、数据侧优化

### 2.1 高质量段落采样

| 优化点 | 规则 |
|--------|------|
| 长度过滤 | 80~500 字（过短无信息，过长 QA 质量差） |
| 中文比例 | ≥30%，剔除乱码/数字噪声段 |
| 均匀采样 | 每份年报按页间隔抽 40 段，保证全文覆盖 |
| 总量控制 | 9 份 × 40 = 360 段 |

### 2.2 LLM 问答对生成

- 使用 DeepSeek（temperature=0.3）生成事实型/数字型/定义型问题
- 要求答案直接摘自段落，防止训练数据引入幻觉
- **20 线程并发**，360 条约 2~5 分钟完成
- 问题表述模拟真实用户（可省略实体、使用代词），增强泛化

### 2.3 困难负例挖掘

仅靠随机负例会让训练任务过简单。采用 **BM25 困难负例**：

```
对每条 query → BM25 检索 top20 → 取排名最高的非正例段落为 hard_negative
```

困难负例与问题词面相似但语义不同，迫使模型学习细粒度语义区分。

## 三、损失函数优化

工单列出 4 类损失，本方案组合使用其中两种以获得最佳效果：

| 损失函数 | 适用格式 | 本项目用途 |
|----------|----------|-----------|
| 三元组损失 TripletLoss | (锚点,正例,负例) | 思想被 MNRL 吸收 |
| 对比损失 ContrastiveLoss | 正负例对 | — |
| 余弦相似度损失 CosineSimilarityLoss | 带分数句子对 | — |
| **多重负例排序损失 MNRL** | (query,正例[,困难负例]) | ✅ 核心损失 |
| **套娃损失 MatryoshkaLoss** | 包裹任意损失 | ✅ 外层损失 |

### 3.1 MNRL（内层）

一个 batch 内，每个 query 只有 1 个正例，其余样本的正例 + 各样本的困难负例均为负例，利用大规模 in-batch negatives 高效对比学习。

### 3.2 Matryoshka（外层）

在 `[768, 512, 256, 128, 64]` 五个截断维度上分别计算损失，使同一模型输出支持可变维度：

- 高精度场景：768 维
- 低延迟/省存储场景：截断为 256/128 维，无需重新训练

## 四、训练参数优化

| 参数 | 取值 | 理由 |
|------|------|------|
| max_seq_length | 256 | 问答对均较短，缩短序列降低 CPU 开销 |
| epochs | 2 | 小数据防过拟合，2 轮足够 |
| batch_size | 16 | in-batch negatives 数量与显存/内存的平衡 |
| learning_rate | 2e-5 | BERT 类模型微调标准区间 |
| warmup_ratio | 0.1 | 学习率预热，训练初期稳定 |
| 优化器 | AdamW | 默认权重衰减 |

## 五、评估优化

### 5.1 评估协议

- **60 条独立评估查询**（训练时不可见）
- **360 段候选语料**（正例 1 个 + 其余干扰段）
- 指标：Recall@1/3/5/10、MRR@10、Top1 准确率
- **每 epoch 回调**实时监控，早停依据

### 5.2 微调前后对比

同一评估器、同一语料，确保对比公平；指标提升量化写入 `finetune_report.json`。

## 六、工程与部署优化

1. **CPU 可跑通**：全流程在无 GPU 环境完成（缩短序列 + 小 batch + 小模型）
2. **断点续跑友好**：数据生成与训练解耦，中间产物落盘
3. **一键脚本**：`install.sh` 装环境、`start.sh` 跑全流程、`stop.sh` 停进程
4. **GPU 自动加速**：检测到 CUDA 后无需改代码即可提速
