## 5. 部署步骤

### 5.1 安装与初始化

```bash
cd /home/dabaie/code/工单/工单二
bash scripts/install_optimized.sh
```

执行内容：

1. **准备 Python 3.10 环境**（按优先级自动选择）：
   - `PYTHON_BIN=/path/python`：显式指定解释器；
   - 已装 conda：创建/复用 conda 环境 **`rag_pdf_qa_opt`**（已存在则复用，不做破坏性删除）；
   - 无 conda 但存在自备 venv（默认 `/home/dabaie/code/my_project/.venv`，可用 `VENV_DIR=` 改）：直接复用；
   - 全新机器：自动下载安装 Miniconda 到 `~/miniconda3` 后创建 conda 环境。
2. **安装依赖**：`pip install -r requirements.txt`，自动追加 PyTorch cu128 索引；
   若全量 freeze 因历史并存包触发 `ResolutionImpossible`（如 `hf-xet 1.6.0` 与 `langchain-redis 0.2.5` 旧元数据冲突），自动回退 `pip install --no-deps`（freeze 已含全部传递依赖，安全）。
3. **依赖冒烟检查**：fastapi / uvicorn / streamlit / pymilvus / sqlalchemy / pymysql / PyMuPDF / sentence-transformers 逐一导入验证。
4. **初始化 MySQL**：自动 `CREATE DATABASE IF NOT EXISTS rag_pdf_qa` + 建全部业务表（幂等）。
5. **初始化 Milvus**：连接远程 Milvus，`ensure_collection()` 创建 `rag_chunks`（HNSW M=16 / efConstruction=200 / COSINE，幂等）；远程不可用自动降级 Milvus Lite。

可选开关：

| 变量 | 作用 |
| --- | --- |
| `PYTHON_BIN=/path/python` | 跳过环境探测，直接用指定解释器 |
| `VENV_DIR=/path/venv` | 指定自备 venv 目录 |
| `SKIP_PIP=1` | 跳过依赖安装（离线 / 依赖已就绪） |
| `SKIP_INIT=1` | 只准备环境，不初始化 MySQL/Milvus |

### 5.2 启动

```bash
bash scripts/start_optimized.sh
```

- 自动加载 `.env`、探测解释器（conda `rag_pdf_qa_opt` → venv → 系统 python3）；
- 启动前探活 MySQL/Milvus（仅提示不阻断，应用内有降级兜底）；
- **幂等**：若 8000/8502 已被占用，会先 TERM→KILL 旧进程再启动；
- 后台运行，日志与 PID 落盘：

| 文件 | 路径 |
| --- | --- |
| API 日志 | `data/logs/api_optimized.log` |
| Streamlit 日志 | `data/logs/streamlit_optimized.log` |
| PID 文件 | `data/pids/api_optimized.pid`、`data/pids/streamlit_optimized.pid` |

- API 首次启动需加载 bge-m3 / reranker，脚本以最多约 180 秒轮询 `/api/health` 直到就绪。
- 启动后自动注入 `API_BASE=http://127.0.0.1:8000`，8502 前端默认即连本机 8000。

需要临时改端口：

```bash
APP_PORT=18000 STREAMLIT_PORT=18502 bash scripts/start_optimized.sh
```

### 5.3 停止

```bash
bash scripts/stop_optimized.sh
```

三层清理，保证停干净且**不误伤**基线（8001）与 Step 8（8002）实例：

1. 读取 `data/pids/*_optimized.pid`，TERM 等 2 秒后 KILL；
2. 扫描 8000 / 8502 端口监听进程兜底；
3. 进程特征兜底：仅匹配 `streamlit run app/streamlit_app_optimized.py` 与命令行含 `--port 8000` 的 uvicorn。

脚本幂等：服务已停止时重复执行退出码仍为 0。

## 8. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `ResolutionImpossible: hf-xet ... langchain-redis ...` | 全量 freeze 的历史并存约束冲突；脚本已自动 `--no-deps` 回退，无需人工处理 |
| 健康检查 `mysql=failed` | 确认 MySQL 已启动且 `.env` 端口/账号正确；服务不退出，修好后重启即可 |
| 健康检查 `milvus` 非 remote | 远程 Milvus 未启动，已自动降级 Milvus Lite（`data/milvus_local.db`）；如需远程请先启动 Milvus standalone |
| API 启动等待较久 | 首次加载 bge-m3 / reranker（实测约 12~130 秒，视磁盘缓存而定），脚本会自动轮询 |
| 8502 打开后提示无法连 API | 确认 8000 API 已启动；侧栏 API Base 可手工改，默认值由 `API_BASE` / `APP_PORT` 环境变量控制 |
| 全新机器无 conda | 直接运行安装脚本即可自动安装 Miniconda；无外网时请改用 `PYTHON_BIN=` 指向预装解释器 |
| 只想初始化数据库 | `SKIP_PIP=1 bash scripts/install_optimized.sh`；建库/建表/建 collection 全部幂等，可安全重复执行 |
