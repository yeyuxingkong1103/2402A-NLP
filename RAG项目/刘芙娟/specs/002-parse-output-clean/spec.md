# Feature Specification: 解析产物清洗（S3 清洗步骤）

**Feature Branch**: `002-parse-output-clean`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "生成解析产物清洗脚本，存放到 `d:\zg6_Project\9\med_rag\backend`。清洗类别：剔除类、保护类、转换类、修复类。不确定的情况需汇报并提供 2–3 个方案；需要下载的依赖需汇报并给出最简下载指令；最后说明运行方法。"

## 背景与定位

本特性实现 `docs/04_数据管线设计.md` §1 中的 **S3 清洗**步骤，也是 `specs/001-mineru-pdf-parse` 的直接下游：把 `data/parsed/{doc_id}/` 下 MinerU 的 `content_list.json` 变成 `data/clean/{doc_id}.blocks.jsonl` + `{doc_id}.dropped.jsonl`，供 S4 分块消费。

`docs/04 §6` 已经为这一步确立了铁律：**清洗只做"去装饰"，绝不改写正文**。本特性在此基础上引入用户显式要求的四类操作，其中**转换类与修复类会触碰正文字符**，与 §6 的既有铁律存在张力。该张力已由人工裁决（见文末 **D1/D2/D3**）：转换限定为三类无损转换 + 白名单空格合并，修复类的范围见 **D2 的二次裁决**：跨页断句合并 + 粘连标题切出还原 + 标题层级重算与补标。

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 剔除版式噪声，且每一次剔除都留痕 (Priority: P1)

运维人员对一份已解析的文档运行清洗命令，得到一份**只含正文块**的 `blocks.jsonl`，以及一份**逐块记录了"丢了什么、为什么丢"**的 `dropped.jsonl`。

**Why this priority**: 没有这一步，下游分块拿到的是一份混着页眉、印刷页码、DOI 页脚的文本流。`docs/04 §6` 原则 P2 指出：医疗语料里"噪声"和"正文"的边界模糊，**静默丢弃等于静默篡改知识库**。因此"剔除"与"留痕"是同一件事的两半，不可拆开交付。

**Independent Test**: 对 `data/parsed/d6da41b5d356/` 下的指南运行一次清洗，检查 `dropped.jsonl` 中每一行都有非空的 `drop_rule` 且规则名到具体规则类别（如 `type:page_number`），抽查任意 5 条可人工判断该剔除是否合理。

**Acceptance Scenarios**:

1. **Given** 一份已解析的 `content_list.json`，**When** 运维运行清洗命令，**Then** 生成 `blocks.jsonl` 与 `dropped.jsonl`，命令以退出码 0 结束
2. **Given** 清洗已完成，**When** 检查 `dropped.jsonl` 的任意一行，**Then** 该行携带 `drop_rule`、`block_type`、`page`、`text`、`char_len` 五个字段，且 `drop_rule` 标识的是**具体命中的规则**而非笼统的 `"dropped"`
3. **Given** 清洗已完成，**When** 统计被丢弃块的 `type` 分布，**Then** 页眉（`header`）、页脚（`footer`）、印刷页码（`page_number`）三类**全部**被剔除，无一残留进 `blocks.jsonl`
4. **Given** 清洗已完成，**When** 计算丢弃比例，**Then** 输出该比例；若超过 40% 则给出显式告警（`docs/04 §14` P5）

---

### User Story 2 - 保护不可丢失的医疗内容 (Priority: P1)

清洗规则绝不会误杀四类内容：**引文标注**、**表格与表注**、**紧急症状/转诊表述**、**剂量与数值**。

**Why this priority**: 与 U1 同为 P1。剔除规则一旦误杀，知识库会**照常给出看起来正常、但依据缺失的回答**——`docs/04 §6` 明确指出这是"最危险的一类缺陷"。宪法原则 II（强制溯源引用）与原则 IV（紧急症状前置响应）把这件事从"质量要求"提到了"不可协商"。

**Independent Test**: 对样例文档跑清洗后，逐条核对：`blocks.jsonl` 中引文标注 `<sup>[N]</sup>` 的计数与原始 `content_list.json` 一致（样例文档实测为 23 处）；含"转诊""急救车""意识丧失"的块计数不为 0；表格块计数与原始一致。

**Acceptance Scenarios**:

1. **Given** 原始块含引文标注，**When** 清洗完成，**Then** 该标注在 `blocks.jsonl` 中**逐字符原样保留**，计数与清洗前一致
2. **Given** 原始块是 `page_footnote` 类型，**When** 清洗完成（默认配置），**Then** 该块**被保留**（`docs/04 §6`：医疗指南页脚常是剂量或注意事项注解，误杀代价高于噪声代价）
3. **Given** 原始块是 `table` 类型，**When** 清洗完成，**Then** 该表整表保留，且 `table_caption` / `table_footnote` 与表体**重新拼合**为一个块（`docs/04 §5`：三者是分离字段）
4. **Given** 清洗规则集合被修改，**When** 运行一次自检命令，**Then** 系统能报出"哪些保护类内容在新的规则下会消失"，并在清零时以非 0 退出码告警

---

### User Story 3 - 按类别审阅与调参清洗规则 (Priority: P2)

运维人员能从产物中看出**每一条块是被哪一类规则处置的**：剔除类、保护类、转换类、修复类。

**Why this priority**: 这四类是用户显式提出的组织方式，也是清洗环节"调参最频繁"（`docs/04 §4`）所依赖的可观测性。没有分类计分，调规则只能靠盲猜。

**Independent Test**: 清洗命令输出一份**按四类分组的处置报告**：每类命中了多少块、涉及哪些具体规则名、各多少条。

**Acceptance Scenarios**:

1. **Given** 清洗完成，**When** 查看命令输出，**Then** 可见四类各自的命中块数与规则明细
2. **Given** 某类规则命中数为 0，**When** 查看报告，**Then** 该类被显式标为 0（区别于"该类未实现"）
3. **Given** 运维只想重跑某一类规则，**When** 通过命令行开关关闭其余类别，**Then** 产物中对应类的处置不发生，且报告如实反映

---

### User Story 4 - 无解析产物时明确失败而非静默成功 (Priority: P3)

输入路径不存在、产物缺失、JSON 损坏、出现未知块类型时，命令以非 0 退出码结束并说明原因。

**Why this priority**: `docs/04 §5` 把"出现未列出的类型"定为必须**停止并人工决策**的事件——未知类型意味着可能有内容被无声跳过。`specs/001` 已建立"不静默失败"的基线（其 FR-008/FR-010），本特性必须延续。

**Independent Test**: 依次构造 4 种坏输入（不存在的 doc_id、缺 `content_list.json`、JSON 语法损坏、人工注入一个未知 `type`），每种都以非 0 退出且**不写出** `blocks.jsonl`。

**Acceptance Scenarios**:

1. **Given** `data/parsed/` 下无任何文档，**When** 运行清洗命令，**Then** 明确提示无待处理文档，非 0 退出
2. **Given** `content_list.json` 不存在或 JSON 损坏，**When** 运行清洗命令，**Then** 报错并指出具体文件路径，非 0 退出，**不产生半份产物**
3. **Given** 输入中存在 `docs/04 §5` 未列出的块类型，**When** 运行清洗命令，**Then** 该类型被显式标出并要求人工决策，命令非 0 退出，**不得静默忽略或当作正文保留**
4. **Given** 清洗中途失败，**When** 检查输出目录，**Then** 不存在可被误认为完整的 `blocks.jsonl`

---

### Edge Cases

- **输入文档的块全部被剔除**（清洗后块数为 0）→ 报错并非 0 退出，**不得**写出空 `blocks.jsonl` 冒充成功
- **`table_body` 缺失**（`docs/04 §5` 明确此情形存在）→ 不得静默丢弃该表；应保留可得的 `img_path`/`table_caption` 并显式标记该表降级
- **表格含 `rowspan`/`colspan` 合并单元格**（样例文档表 4 实测存在）→ 处置方式见 **D3**（按行展开填充，文字零丢失）；**不得静默丢失单元格内容**
- **文本块为空或纯空白**（样例文档实测 14 处）→ 剔除并留痕，`drop_rule` 为 `empty:text`
- **`page_idx` 缺失**（`specs/001` FR-005 要求上游不得产生，但本步骤仍须防御）→ 报错非 0 退出，**不得**以 0 填充
- **同一 `doc_id` 重复清洗** → 覆盖旧产物；产物内记录规则版本，规则版本变化时给出"需重建下游"的提示
- **`list` 类型的 `sub_type` 为未见过的新值** → 按用户故事 4 的未知类型处理，停止并人工决策
- **块内容含未转义的反斜杠**（样例文档实测 74 处，如 `75%\~100%`）→ 处置属转换类，见 **D1** 与 FR-026
- **跨页被截断的句子**（实测：`page_idx 8` 的块以「…心血管高风险患者，应」结尾，`page_idx 9` 的块以「给予降压药物治疗。」开头，中间夹着页眉与页码）→ 按 FR-030 合并，见 **D2**

## Requirements *(mandatory)*

### Functional Requirements

**通用**

- **FR-001**: 脚本 MUST 接受一个**文档标识**或一个已解析产物目录作为输入；未指定时 MUST 处理 `data/parsed/` 下的全部文档
- **FR-002**: 脚本 MUST 以 `data/parsed/{doc_id}/` 为输入根、以 `data/clean/{doc_id}.blocks.jsonl` 与 `{doc_id}.dropped.jsonl` 为输出（`docs/04 §4` 产物契约）
- **FR-003**: 脚本 MUST 只读 `content_list.json`；MUST NOT 读 `{doc_id}.md` 或 `middle.json` 作为正文来源（`docs/04 §5`：Markdown 不携带页码）
- **FR-004**: 脚本 MUST NOT 依赖解析工具（MinerU）运行时或模型权重，MUST 可离线独立运行（宪法原则 I）
- **FR-005**: 脚本 MUST 在源码中硬编码的依赖之外，**只**使用运行环境已具备的库；任何新增依赖 MUST 先报告给人并附最简安装指令（宪法原则 I）
- **FR-006**: 脚本 MUST NOT 硬编码密钥或凭据（宪法原则 III）
- **FR-007**: 脚本 MUST 以退出码区分成功与各类失败（缺输入 / 坏 JSON / 未知类型 / 空产出）（`specs/001` FR-011）
- **FR-008**: 脚本 MUST NOT 用宽泛的异常捕获吞掉失败；所有失败条件 MUST 以非 0 退出码显式暴露

**剔除类**

- **FR-009**: 脚本 MUST 剔除以下块类型：`page_number`、`header`、`footer`、`aside_text`（`docs/04 §6` 处置表）
- **FR-010**: 脚本 MUST 默认**保留** `page_footnote`，并 MUST 提供显式开关才能丢弃它（`docs/04 §6`；理由：医疗页脚常是剂量注解）
- **FR-011**: 脚本 MUST 剔除 `list` 类型中 `sub_type == "ref_text"` 的块（参考文献条目），并 MUST 保留 `sub_type == "text"` 的块（`docs/04 §6`）
- **FR-012**: 脚本 MUST 剔除文本为空或纯空白的块
- **FR-013**: 每一个被剔除的块 MUST 以一条独立记录写入 `dropped.jsonl`，记录 `drop_rule`（具体规则名）、`block_type`、`page`、`text`、`char_len`（`docs/04 §6`）
- **FR-014**: 脚本 MUST 在清洗结束后输出丢弃块数与丢弃比例；比例超过 40% MUST 告警（`docs/04 §14` P5）

**保护类**

- **FR-015**: 清洗 MUST NOT 删除或改写正文块中的**引文标注**（`<sup>[N]</sup>` 形式）；清洗前后的标注计数 MUST 一致（宪法原则 II）
- **FR-016**: 脚本 MUST 保留全部 `table` 块，且 MUST 把 `table_caption`、`table_footnote` 与表体拼合为同一个块（`docs/04 §5`）
- **FR-017**: 清洗 MUST NOT 删除含**紧急症状或转诊表述**的块，即使在剔除规则命中时（宪法原则 IV）
- **FR-018**: 脚本 MUST 提供一份**保护类清单**：一组绝不可被任何剔除规则命中的内容判据；任一保护判据在新的规则下失效时，脚本 MUST 以非 0 退出码告警
- **FR-019**: 清洗 MUST NOT 改动数值与剂量表达（`mmHg`、`mg`、`g`、`℃`、区间符号等）的语义（`docs/04 §6` 核心原则）

**转换类**

- **FR-020**: 脚本 MUST 把 `bbox`（0–1000 归一化整数）与 `page_idx` 转成**1-based 物理页码 `page`**（`docs/04 §6`：`page = page_idx + 1`）
- **FR-021**: 脚本 MUST 依据 `type == "text"` **且 `text_level` 键存在**识别标题；MUST NOT 依据 `type == "title"` 或 `text_level` 的默认值判断（`docs/04 §5` 明列的三个易错点）
- **FR-022**: 脚本 MUST 为每个正文块维护 `heading_path`（从文档根到当前块的标题链）。标题块**同时产出块**（`is_heading=true`）并参与 `heading_path` 构建；「标题块不单独成 chunk」是下游 S4 的职责，不在本步骤。
- **FR-023**: 脚本 MUST 按 `docs/04 §6` 的字段契约输出 `blocks.jsonl`：`doc_id`、`block_id`、`file_name`、`page_idx`、`page`、`block_type`、`is_heading`、`heading_path`、`text`、`char_len`、`clean_rule_version`
- **FR-024**: `block_id` MUST 形如 `{doc_id}:{全局序号6位}`，在清洗后的块序列中唯一且稳定（`docs/04 §6`）
- **FR-025**: 脚本 MUST 把 `clean_rule_version` 写入每一条输出记录（`docs/04 §6`）
- **FR-026**: 转换类 MUST 执行以下三类**无损转换**，且 MUST 只做这三类：① 反转义 Markdown 残留反斜杠（`\~` → `~`、`\*` → `*`、`\△` → `△`）；② 解码 HTML 实体（`&lt;` → `<`、`&gt;` → `>`、`&amp;` → `&`）；③ 表格 HTML → Markdown（见 FR-016 与 D3）

**修复类**

- **FR-027**: 修复类规则 MUST 各自独立开关、独立计数、独立留痕；任一条规则 MUST 可被单独关闭
- **FR-028**: 任何被修复规则改动过的块 MUST 在输出中携带**原始文本副本 `raw_text`**，使改动可被逐字回溯（`docs/04 §6`：引用必须逐字可核对）
- **FR-029**: 修复类 MUST 执行以下四条（裁决 2-B + 3-D）：① 跨页断句合并；② 粘连标题切出还原为独立标题块；③ 补标 MinerU 漏标的标题；④ 按章节编号重算标题层级；⑤ 图/表题注误标为标题时降级为正文块
- **FR-030**: 跨页断句合并 MUST 同时满足：① 两块在**剔除后的保留序列中相邻**；② `page_idx` 差为 0 或 1（实测断句既有跨页的，也有同页被列切分切断的）；③ `page_idx` 差为 0 时，二者之间的原始块 MUST 全为 `empty:text`；④ 前块结尾**无终止标点**；⑤ 后块开头**非章节编号、非列表项**；⑥ 二者 MUST NOT 是标题块
- **FR-031**: 合并后的块 MUST 保留**前块的 `page`**（引用页码取起始页），MUST 在 `merged_from` 记录两个来源，MUST 在 `raw_text` 保留合并前的原文
- **FR-032**: 标题层级 MUST 按章节编号重算：编号可解析时用编号深度（`5.4.6.1` → 4 级），编号不可解析时回退 `text_level`。实测 74 个标题块的 `text_level` 最大只有 2，而编号最深到 4 级
- **FR-033**: 脚本 MUST 只把**有章节编号**的块视为章节标题；无编号且符合题注判据（`图/表/续表/Figure/Table + 数字` 开头，或紧邻其后的原始块是表格/图片且文本 ≤40 字）的块 MUST 降级为正文块。实测 3 个题注被 MinerU 误标为标题，不降级会在 `heading_path` 里冒充一章、打断 4 级章节树

**可观测性**

- **FR-034**: 脚本 MUST 输出一份**按四类分组的处置报告**（剔除类 / 保护类 / 转换类 / 修复类），每类给出命中块数与规则明细（用户故事 3）
- **FR-035**: 报告 MUST 显式区分"该类命中 0 条"与"该类未实现"
- **FR-036**: 脚本 MUST 在启动时输出所读取的输入路径与所写出的产物路径，便于人工核对
- **FR-037**: 脚本 MUST 在 `content_list.json` 中出现 `docs/04 §5` 未列出的块类型时非 0 退出并列出该类型（`docs/04 §5` 核对方法）
- **FR-038**: 脚本 MUST 把 `page_footnote` 的保留数、表格块数与引文标注数写入报告，作为保护类的**回归基线**（对应 SC-003）

### Key Entities

- **解析产物 (Parsed Artifact)**: `data/parsed/{doc_id}/content_list.json`，扁平、按阅读顺序、每项带 `page_idx` 的块序列。本步骤的**唯一输入**。
- **清洗后块 (Clean Block)**: 输出 `blocks.jsonl` 的一行。携带 `block_id`、`page`、`heading_path`、`text`、`char_len` 等，是 S4 分块的直接输入，也是引用卡片回溯原文的中间节点。
- **丢弃记录 (Dropped Record)**: 输出 `dropped.jsonl` 的一行。**它存在的唯一目的是让"知识库缺了一块"这件事可被人发现**，因此 `drop_rule` 必须是具体规则名。
- **规则集合版本 (clean_rule_version)**: 一组清洗规则的标识。规则变更即版本变更，需全量重建下游（`docs/04 §6` 原则 P3）。
- **四类处置 (Drop / Protect / Convert / Repair)**: 本特性对清洗规则的**组织方式**。剔除类与保护类是互斥的安全对；转换类与修复类会触碰字符，是本规格中最需要人工裁决的部分。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对 15 页样例文档（实测 304 个块），一次清洗在 **5 秒内**完成
- **SC-002**: 清洗后 `blocks.jsonl` 中 `page_number`、`header`、`footer`、`aside_text` 四类块的残留数为 **0**
- **SC-003**: 清洗前后**引文标注计数完全一致**（样例文档基线 23 处）；表格块计数完全一致（基线 8 个）；含转诊/紧急症状表述的块计数完全一致
- **SC-004**: `dropped.jsonl` 中 **100%** 的记录携带具体 `drop_rule`，且任意 10 条抽样可由人工在 2 分钟内判定剔除是否合理
- **SC-005**: 四类处置报告**每次运行必然输出**，人工可在 1 分钟内据此判断是否需要调整规则
- **SC-006**: 全部 9 项边界情况均以非 0 退出码结束，且**没有任何一种**产生可被误认为成功的产物
