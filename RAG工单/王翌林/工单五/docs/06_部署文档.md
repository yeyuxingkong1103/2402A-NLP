# 06_部署文档

> 工单编号：人工智能NLP-RAG-Query 理解优化任务（工单五）
> 增量说明：工单五 = 工单四（图文表融合 RAG）+ 多轮对话能力（会话管理 + 指代消解）

## 1. 系统架构

```
用户提问 ──> ConversationEngine（会话管理 + 指代消解 + 问句改写）
              │
              ├── 策略1: 那X呢 → 切换实体 + 复用问法
              ├── 策略2: 他/这个公司 → 当前实体
              ├── 策略3: 无代词 → 继承当前实体
              └── 策略4: 含公司名 → 直连
                    │
                    ▼
          RAGEngineV4.ask（图文表三路检索 + LLM 生成）
                    │
                    ▼
          更新会话状态（历史 + 当前实体 + 最后问法）
```

| 服务 | 端口 | 入口 |
|------|------|------|
| FastAPI v5 | 8005 | `src.api_v5:app` |
| Streamlit v5 | 8505 | `app/streamlit_app_v5.py` |
| Milvus | 19530 | rag_chunks / rag_tables / rag_images |
| MySQL | 3307 | 库 rag_pdf_qa |

## 2. 环境要求

沿用工单四环境（Python 3.10 + venv、Milvus 2.6、MySQL 8、DeepSeek API Key）。
无需额外依赖（多轮对话为纯 Python 规则实现，不引入新模型）。

## 3. 启动 / 停止

```bash
bash scripts/start_v5.sh   # 启动 FastAPI(8005) + Streamlit(8505)，含健康检查
bash scripts/stop_v5.sh    # 按端口停止两个服务
```

- 日志：`data/logs/api_v5.log`、`data/logs/streamlit_v5.log`
- 健康检查：`curl http://127.0.0.1:8005/api/v5/health`

## 4. API v5 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v5/health` | 健康检查（会话数 + 图像库行数） |
| POST | `/api/v5/chat` | 多轮对话（body: question/session_id/use_image） |
| GET | `/api/v5/history/{session_id}` | 获取会话历史 |
| POST | `/api/v5/feedback` | 用户反馈（点赞/点踩/评论） |
| POST | `/api/v5/reset/{session_id}` | 重置会话 |

### 多轮对话示例

```bash
# 第一轮（自动创建 session）
curl -s -X POST http://localhost:8005/api/v5/chat \
  -H 'Content-Type: application/json' \
  -d '{"question":"报告期内，武汉兴图新科电子股份有限公司来自军用领域的收入分别是多少？"}'

# 第二轮（传入 session_id，"他"自动消解为兴图新科）
curl -s -X POST http://localhost:8005/api/v5/chat \
  -H 'Content-Type: application/json' \
  -d '{"question":"他参与的哪个工程荣获了国家科技进步一等奖？","session_id":"<上一轮返回的session_id>"}'
```

## 6. 常见问题

| 现象 | 原因 | 处置 |
|------|------|------|
| 首轮响应 >3s | 模型冷启动 | 已通过预热（warmup + 真实 RAG 查询）消除；生产环境启动后先调用一次 health/chat 预热 |
| 代词消解失败 | 会话无历史实体 | 首轮须明确公司名；后续轮次自动继承 |
| Milvus 连接失败 | 服务未启动/重启 | `scripts/load_milvus_collections_step5.py` 巡检 |
