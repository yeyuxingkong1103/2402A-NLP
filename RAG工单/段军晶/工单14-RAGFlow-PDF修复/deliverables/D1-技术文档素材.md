| 项 | 值 | 位置 |

| **读取方式** | `xreadgroup(count=1, block=5)` | `rag/utils/redis_conn.py:381-388` |

```python
# common/settings.py:128-134
def get_svr_queue_name(priority: int) -> str:
    if priority == 0:
        return SVR_QUEUE_NAME
    return f"{SVR_QUEUE_NAME}_{priority}"

def get_svr_queue_names():
    return [get_svr_queue_name(priority) for priority in [1, 0]]   # priority=1 优先消费
```

```python
# rag/utils/redis_conn.py:350-361
def queue_product(self, queue, message) -> bool:
    for _ in range(3):
        try:
            payload = {"message": json.dumps(message)}
            self.REDIS.xadd(queue, payload)
            return True
        except Exception as e:
            logging.exception("RedisDB.queue_product " + str(queue) + " got exception: " + str(e))
            self.__open__()
    return False
```

**优先级队列机制的现状**（重要）：

- 生产者侧由 `priority` 决定写入哪个 Stream
- 消费者侧 `get_svr_queue_names()` 返回 `[priority=1, priority=0]`，`collect()` 按此顺序依次尝试拉取（`rag/svr/task_executor.py:177, 185-188`），即**优先消费 `_1` 队列**
- **但代码内所有生产调用点传入的 priority 均为 `0`**（`document_service.py:1107`、`api/apps/sdk/doc.py:847`、`api/apps/kb_app.py:632/701/770`、`api/apps/sdk/dataset.py:590/667`、`api/apps/canvas_app.py:211`、`api/db/joint_services/memory_message_service.py:372`），且 API 层未暴露 priority 参数

→ **结论：优先级队列机制已实现但当前未被任何调用方使用，`rag_flow_svr_queue_1` 实际为空。**

**parse 任务的消息体字段**（来自 `task_service.py:381-389, 410-413, 419-421, 438-440`）：

`id`、`doc_id`、`progress`、`from_page`、`to_page`、`begin_at`、`digest`、`priority`；命中复用时额外带 `chunk_ids`、`progress_msg`。

### 1.4 消费机制与可靠性

**消费者命名**（`rag/svr/task_executor.py:112-113`）：

**拉取与 ack**：

| 项 | 位置 | 说明 |
|----|------|------|
| 消费组自动创建 | `redis_conn.py:369-379` | group 不存在时 `xgroup_create(..., id="0", mkstream=True)` |

| ack 实现 | `redis_conn.py:45-51` | `xack(queue_name, group_name, msg_id)` |

**未确认消息（unacked）处理**（`rag/svr/task_executor.py:173-188`）：

```python
async def collect():
    svr_queue_names = settings.get_svr_queue_names()
    ...
    if not UNACKED_ITERATOR:
        UNACKED_ITERATOR = REDIS_CONN.get_unacked_iterator(svr_queue_names, SVR_CONSUMER_GROUP_NAME, CONSUMER_NAME)
    try:
        redis_msg = next(UNACKED_ITERATOR)
    except StopIteration:
        for svr_queue_name in svr_queue_names:
            redis_msg = REDIS_CONN.queue_consumer(svr_queue_name, SVR_CONSUMER_GROUP_NAME, CONSUMER_NAME)
            if redis_msg:
                break
```

`get_unacked_iterator`（`redis_conn.py:410-434`）遍历两个队列，从 `current_min = 0` 开始反复以递增 msg_id 调 `queue_consumer`，即**按 ID 顺序重读本消费者自己未 ack 的消息**。迭代器耗尽（StopIteration）后才去读新消息。

**重试机制**（`api/db/services/task_service.py:127-142`）：

```python
msg = f"\n{datetime.now().strftime('%H:%M:%S')} Task has been received."
prog = random.random() / 10.0
if docs[0]["retry_count"] >= 3:
    msg = "\nERROR: Task is abandoned after 3 times attempts."
    prog = -1
cls.model.update(progress_msg=..., progress=prog, retry_count=docs[0]["retry_count"] + 1).where(...).execute()
if docs[0]["retry_count"] >= 3:
    return None
```

> ⚠️ **重试机制的真实触发条件**：`retry_count + 1` 发生在 `TaskService.get_task()` 每次被调用时，而 `handle_task` 在**所有路径下都无条件 ack**（`rag/svr/task_executor.py:1231`）。因此**正常情况下消息只被消费一次，`retry_count` 不会增长**。
>
> 真实触发条件是：**task_executor 进程在 ack 之前被杀/崩溃** → 消息留在 pending → 重启后 `get_unacked_iterator` 重新读回 → `retry_count` 递增。连续 3 轮这样的崩溃 → 任务被放弃（`progress = -1`，msg 为 `ERROR: Task is abandoned after 3 times attempts.`）。
>
> **这个机制防的是"执行器反复崩溃导致任务无限重投"，不是"用户反复点解析"。** 重新点解析会重建 Task（`retry_count` 归零）。

#### 1.6.1 `paper` 详述

签名（`paper.py:144-145`）：

```python

          lang="Chinese", callback=None, **kwargs):
```

docstring（`paper.py:146-149`）："Only pdf is supported. The abstract of the paper will be sliced as an entire chunk, and will not be sliced partly."

**⚠️ `chunk_token_num` 声明但从不读取**：默认配置字典在 `paper.py:150-152` 声明了 `chunk_token_num: 512`，但全文件**没有任何读取处**（真正被读取的只有 `table_context_size` / `image_context_size`，`paper.py:251-252`）。因此 **paper 的分块不受 token 数控制**。

实际切分逻辑（`paper.py:230-249`）：

```python
bull = bullets_category([txt for txt, _ in sorted_sections])
most_level, levels = title_frequency(bull, sorted_sections)
assert len(sorted_sections) == len(levels)
sec_ids = []
sid = 0
for i, lvl in enumerate(levels):
    if lvl <= most_level and i > 0 and lvl != levels[i - 1]:
        sid += 1
    sec_ids.append(sid)

chunks = []
last_sid = -2
for (txt, _), sec_id in zip(sorted_sections, sec_ids):
    if sec_id == last_sid:
        if chunks:
            chunks[-1] += "\n" + txt
            continue
    chunks.append(txt)
    last_sid = sec_id
```

即：**只有 `lvl <= most_level` 且标题层级发生变化时才开新块**；同 `sec_id` 的相邻段落拼进同一 chunk。摘要单独成块，并加 `important_kwd = ["abstract","总结","概括","summary","summarize"]`（`paper.py:216-225`）。

**`is_english` 判定**（`pdf_parser.py:1098-1105`）：

```python
self.is_english = [
    re.search(r"[ a-zA-Z0-9,/¸;:'\[\]\(\)!@#$%^&*\"?<>._-]{30,}", "".join(random.choices([c["text"] for c in self.page_chars[i]], k=min(100, len(self.page_chars[i])))))
```

逐句解释：

1. 对**每一页**：从该页文本层字符里**随机抽最多 100 个**（`k=min(100, len)`）拼成字符串，用正则要求**连续出现 ≥30 个**属于 `[ a-zA-Z0-9,/¸;:'\[\]\(\)!@#$%^&*"?<>._-]` 的字符。
2. 得到逐页结果列表（每项 Match 对象或 None）。
3. **塌缩成一个全局布尔值**：判定为英文的页数 > 总页数/2 则 `True`，否则 `False`。

特征点：判定用**逐页随机采样**（有随机性），阈值含义是"该页存在一段 30+ 字符的纯 ASCII 串"，即**该页看起来主要是拉丁文本**。

**`is_english` 对 OCR 的影响（关键）**（`pdf_parser.py:1128-1134`）：

### 3.5 OCR

**`__ocr` 签名与步骤**（`pdf_parser.py:285-348`）：

```python

```

1. `bxs = self.ocr.detect(np.array(img), device_id)`（`:287`）—— 对**整页图**做文本检测
2. 无框则 `self.boxes.append([])` 后返回（`:291-293`）
3. 检测框转统一字典并按 Y 序排序（阈值 `self.mean_height[pagenum-1]/3`）（`:294-302`），初始字段 `x0/x1/top/text/bottom/chars/page_number`（`:297`）
4. **`# merge chars in the same rect`**（`:304-328`）—— 把文本层字符塞进框（见下）
5. 对**没有文字的框**逐个裁剪送识别（`:334-343`）
6. `bxs = [b for b in bxs if b["text"]]`（`:345`）—— 识别后仍无文字的框被丢弃
7. `self.boxes.append(bxs)`（`:348`）

**OCR 触发条件**：

- **检测（detect）无条件、每页都跑**（`:1136-1168` → `asyncio.run(__img_ocr_launcher())` `:1172`）。没有"仅扫描页才 OCR"的判断。
- **识别（recognize_batch）只对合并文本层字符后仍为空的框执行**（`:334-343`）。
- **⚠️ 该版本没有"强制 OCR"开关**：全仓 grep `force_ocr`、`ocr_enabled`、`enable_ocr` **均无命中**。是否识别某区域只取决于上述两条。
- **粒度**：以**页**为调度单位（每页一次 detect），**识别以检测框为粒度批量进行**（`recognize_batch`，`:696-706`）。
- 并行：`settings.PARALLEL_DEVICES > 1` 时按设备分信号量并发（`:71-72`、`:1136-1155`）。

**文本层字符与 OCR 框的合并**（`pdf_parser.py:304-328`）：

```python

for c in chars:
    ii = Recognizer.find_overlapped(c, bxs)
    if ii is None:
        self.lefted_chars.append(c)
        continue
    ch = c["bottom"] - c["top"]
    bh = bxs[ii]["bottom"] - bxs[ii]["top"]
    if abs(ch - bh) / max(ch, bh) >= 0.7 and c["text"] != " ":
        self.lefted_chars.append(c)

    bxs[ii]["chars"].append(c)

        continue
```

**第 1 步：`is_english` 判定**

- `page_chars` 全为空（无文本层，`pdf_parser.py:1064`）
- `random.choices([], k=0)` → 空字符串 → 正则不匹配 → 逐页结果全为 `None`
- `sum(...) > len(page_images)/2` 为假 → **`is_english = False`**
- 后续 `chars = self.page_chars[i] if not self.is_english else []` → `chars = []`（空列表）

**第 2 步：OCR**

- 检测（detect）**无条件对每页执行**
- 因 `chars` 为空，所有检测框都无文字 → **每个框都走识别**（`pdf_parser.py:334-343`）
- 即：**OCR 一定会跑，且是全量识别**

> 由此得出一个重要排查结论：**该文档不存在"OCR 没被触发"的问题。** 出问题时方向应从"OCR 已跑但结果不理想"入手。

**第 3 步：二次 `is_english` 回填**（`pdf_parser.py:1176-1178`）

- 条件"非英文 + 全部页无文本层 + 有 OCR 结果"**满足** → 用 OCR 结果重新判定
- 文档为中文专利 → 仍判为 `False`

**第 4 步：放大重试**（`pdf_parser.py:1184-1185`）

- 若 `len(self.boxes) == 0` 且 `zoomin < 9`，会把 zoom 从 3 放大到 9 重跑一次（兜底机制）

### 4.3 "信息丢失"的具体发生位置（按流水线顺序）

### 4.4 VLM（image2text）的真实作用

| 结论 | 依据 |
|------|------|
| 未配置 VLM **不会**导致图纸被丢弃 | `figure_parser.py:91-96, 123` 原样返回 |
| 未配置时图纸仍入库，内容 = 图注 + 图内 OCR 文字 | `rag/nlp/__init__.py:375-406` |
| VLM 描述是**追加**在原图注之前 | `figure_parser.py:248-251` |
| VLM 补的是 OCR **拿不到**的信息 | 尤其是图纸内的空间关系 |

**对 6 个测试问题的影响推断**：

| 题 | 所需信息 | VLM 是否必要 |
|----|----------|--------------|
| Q1、Q2 | 第 1 页扉页文本 | 否 |
| Q3 | **第 7 页图中部件 4 与 5 的左右关系** | **是**（OCR 文字不含空间关系） |
| Q4 | 第 7 页 X1/X2/X3 标注 + 第 6 页正文 | 否（增强） |
| Q5 | 第 7 页箭头 7 与 6/6'/6'' 排布 + 第 6 页正文 | 否（增强） |
| Q6 | 第 7 页 D/h1/h2 标注 + 第 6 页量化关系 | 否（增强） |

**OCR 字形风险（需在调优中处理）**：

- 撇号家族：`6`、`6′`、`6′′`（原文用全角撇号排版），OCR 可能输出 `6'`、`6"`、`6”`、`6″`、直角引号等多种形态
- 下标：`x₁`~`x₃`、`h₁`、`h₂`，OCR 可能识别为 `x1`、`xl`、`x1`（下标丢失）
- 全角/半角标点混用（`，` vs `,`、`（` vs `(`）
- 题面用大写 `X1/X2/X3`，原文用小写斜体带下标 `x₁~x₃`
