# 平台使用说明

本平台是面向多用户、多角色的本地化检索增强问答系统（Role RAG）。所有模型都在本机运行，
知识库、聊天记录与短期记忆分别存放在 Milvus 与 Redis 中。

## 一、角色（Role）

每个角色拥有独立的系统人设、回答红线与知识库范围：

| 组成部分 | 说明 |
|---|---|
| 人设（persona） | 决定语气、专业深度与输出结构 |
| 红线（guardrails） | 硬性禁止项，命中风险词时系统会强制追加免责声明 |
| 知识库范围 | 角色目录 + 公共目录（shared），不同角色互不检索对方的知识 |

同一个用户在同一个会话内固定使用一个角色；切换到其他角色会创建新的检索上下文，
但**用户的长期记忆（姓名、目标、偏好）在所有角色之间共享**。

## 二、引用编号

回答中的 `[1]`、`[2]` 是知识片段的编号，对应本次检索到的第 1、2 段资料。
系统会对编号做二次校验：

* 编号超出范围或不存在 → 视为模型自造引用，直接从结果中剔除；
* 一条回答里没有任何有效引用 → `cited=false`，表示答案没有明确依据，需要谨慎采信。

## 三、记忆机制

| 层级 | 存放位置 | 内容 | 生命周期 |
|---|---|---|---|
| 聊天记录 | Redis List | 每轮问答原文、引用、耗时 | 7 天 |
| 短期记忆 | Redis List + String | 最近 5 轮原文 + 会话摘要 | 7 天 |
| 长期记忆 | Milvus 向量库 | 规则抽取的事实（姓名、目标、偏好等） | 长期保留 |

用户可以说「请记住：我偏好稳健型产品」来显式写入长期记忆，也可以在记忆面板中一键清空。

## 四、混合检索

系统同时使用三路召回，再用加权 RRF 融合：

1. **稠密路**：BGE-M3 CLS 向量（1024 维，COSINE）语义匹配，解决同义改写问题；
2. **稀疏路**：BGE-M3 lexical 权重（词级权重，内积）精确匹配专业术语；
3. **关键词路**：jieba 分词 + BM25Okapi，对编号、缩写、专有名词最敏感。

RRF 只看排名不看分数，因此三路的量纲差异不会互相干扰。检索调试面板可以并列查看
四种模式（dense / sparse / bm25 / hybrid）的命中差异。
