# 需求规格说明书 —— 基于 RAG 的角色扮演系统

## 1. 项目背景与目标

大模型本身没有记忆、知识滞后、易幻觉。RAG（Retrieval-Augmented Generation，检索增强生成）通过把
「领域知识库」检索到的内容注入提示词，让大模型基于真实资料作答，从而具备专业知识、可追溯来源、
并能动态更新知识。本项目将 RAG 与「角色扮演」结合，让大模型扮演具备领域知识的角色
（心理咨询师、律师），提供专业、可控、多轮对话的聊天机器人。

**目标**：交付一个可运行、可部署的「基于 RAG 的角色扮演系统」——第一版（MVP）跑通
「文档解析 → 入库 → 混合检索 → 重排 → LLM 角色对话」主链路。

## 2. 范围

### 2.1 MVP（第一版）范围

- 单角色（医生/高血压健康助手）、单用户（默认会话）。
  > ⚠️ 这是 MVP 第一版的范围。**当前实现已扩展为 2 个内置角色（心理咨询师、律师）+ 用户表**
  > （多角色共享向量库、按 `role_id` 隔离召回），且两个角色的知识库都改为公开数据集语料
  > （见 [数据来源](数据来源.md)），与本节描述不再一致，以 `README.md` 与代码为准。
- 离线链路：上传/扫描文档 → 解析 → 清洗 → 分块 → 向量化 → 写入 Milvus。
- 在线链路：问题向量化 → 混合检索（向量 + BM25）→ RRF 融合 → 重排 → 提示词 → 大模型 → 后处理 → 返回。
- 短期记忆（多轮对话上下文，进程内内存，已支持 Redis）。
- 用户/角色信息持久化（SQLite，已支持 MySQL）。
- REST 接口 + 流式（SSE）输出。

### 2.2 非目标（后续版本）

- 多用户登录/鉴权、知识库自动增量更新、BM25 迁入 Milvus 稀疏向量。
- **多数据源（Neo4J / MongoDB / ClickHouse 多路召回）**：经确认**不属于本项目需求**，不做。
  仓库里保留的 `deploy/docker-compose.multi-source.yml` 与 `rrf_fusion` 的 N 路扩展能力
  只是「架构上留了口子」的演示，**没有接入任何一路**，验收时不作为交付项。

> 原列于此的 OCR 扫描件解析、Redis/MySQL、负载均衡与压测、完整 RAGAS 指标**均已落地**，
> 属 MVP 之外已补全的部分，见 `README.md` 与 `deploy/README.md`，故从非目标中移除。

## 3. 功能需求

| 编号 | 功能 | 说明 |
|---|---|---|
| FR-1 | 文档入库 | 支持 PDF/txt/md/图片（png·jpg·...）上传或本地目录导入，扫描件与图片走 OCR；解析→清洗→分块→向量化→写入向量库 |
| FR-2 | 文档列表 | 查询已入库文档（来源、分块数、角色） |
| FR-3 | 角色对话 | 按角色人设，基于检索到的知识库内容回答用户问题 |
| FR-4 | 流式输出 | 对话支持 SSE 流式返回 |
| FR-5 | 混合检索 | 稠密向量召回 + BM25 关键词召回，RRF 融合 |
| FR-6 | 重排序 | 对召回的候选 chunk 精排（默认融合分数，可切 BGE-rerank 交叉编码） |
| FR-7 | 短期记忆 | 保存最近多轮对话，注入提示词实现上下文连续 |
| FR-8 | 角色管理 | 查询/创建角色（人设提示词） |
| FR-9 | 健康检查 | 探测 LLM / Embedding / Milvus / SQL / 短期记忆 五路连通状态；非 `ok` 时给出**降级原因** |
| FR-10 | 后处理 | 对生成结果做正则清洗、敏感词替换、去幻觉式引用 |

## 4. 业务规则

- BR-1：角色回答**只依据检索到的知识库资料**，资料中没有的内容需明确告知用户，不得编造。
- BR-2：涉医疗/法律等专业领域，涉及用药、剂量、方案时必须提示用户遵医嘱/咨询专业人士。
- BR-3：多角色共享向量库，但按 `role_id` 隔离召回，互不串库。
- BR-4：短期记忆按 `session_id` 隔离。存储层保留最近 10 轮（`MEMORY_MAX_TURNS`），但**真正决定
  送进提示词多少的是字符预算**（`HISTORY_MAX_CHARS` 默认 12000 字符、`PROMPT_MAX_CHARS` 默认
  14000 字符）——单条回答上千字时实际只装得下约 3 轮，所以调大 `MEMORY_MAX_TURNS` 常常看不到效果。
- BR-5：重复入库同一 `source` 时，先删除旧向量再写入（幂等）。

## 5. 业务流程

### 5.1 离线入库流程（文字流程图）

```
开始
  │
  ├─ 读取文档（PDF/txt/md/图片）
  ├─ 解析文本（PDF: PyMuPDF → 文本过少则 pdfplumber；无文本层/图片走 RapidOCR）
  ├─ 数据清洗（去空白/水印/页眉页脚）
  ├─ 分块（段落/固定/句子，默认段落 + 重叠）
  ├─ 向量化（Ollama bge-m3，L2 归一化）
  ├─ 写入 Milvus（text + vector + role_id + source + 摘要等元数据）
  ├─ 失效该角色 BM25 缓存
  └─ 登记 SQL（documents 表）
结束
```

### 5.2 在线对话流程（文字流程图）

```
用户提问
  │
  ├─ Query 改写/扩写（可选，QUERY_REWRITE_ENABLED，默认关）
  ├─ 问题向量化
  ├─ 混合检索
  │    ├─ 稠密召回：Milvus ANN（按 role_id 过滤 + 余弦阈值）
  │    └─ BM25 召回：关键词索引
  ├─ RRF 融合去重
  ├─ 重排序（ScoreFusion / BGE-rerank）
  ├─ 组装提示词 = 角色人设 + 知识库上下文 + 短期记忆 + 用户问题
  ├─ 调用大模型（流式/非流式）
  ├─ 后处理（正则清洗）
  ├─ 写回短期记忆（一问一答）
  └─ 返回答案 + 引用来源（sources）
结束
```

## 7. 非功能需求

- **可移植**：所有外部服务可配置，MVP 轻量本地（Milvus Lite + SQLite + 内存），生产平滑切换服务化。
- **可观测**：统一 python logging（控制台 + 按天滚动文件）。
- **可测试**：单元测试 + 接口测试 + 冒烟测试；预留 Jmeter 压测、Postman/ApiPost 联调。
- **可部署**：提供 install.sh / run.sh / shutdown.sh + README 部署文档，目标 Ubuntu/算力云/腾讯云/阿里云。
