## 二、多语言（英文）检索 · 10 题（`python evaluation/run_eval_en.py`）

英文问句（同 id、同金标准）考察**跨语检索**：术语级映射（registered capital→注册资本、military revenue→军用领域收入…）+ 口径词补齐 + 条件补公司全名。

| 指标 | 数值 |
|---|---|
| Hit@1 | 80.0%（8/10） |
| Hit@3 | **100.0%（10/10）** |
| Hit@5 | **100.0%（10/10）** |
| MRR | 0.883 |

> 修复过程：英文“军用领域收入金额”一开始会召回“占比”段落 → 加了**中英统一口径消歧**；
> 无条件补公司全名会把“公司名称表格页”抬到首位 → 改为**只对工商登记类问题补全名**，英文命中率从 8/10 提到 10/10。

## 三、拒答阈值标定（`python evaluation/calibrate.py`）

| 分组 | 置信度范围 |
|---|---|
| 库内 10 题（应作答） | 最低 **0.644** |
| 库外 8 题（应拒答） | 最高 **0.509** |

两组**完全可分**（0.509 < 0.644），取中点 → **`REFUSE_SCORE = 0.58`**：库内不误拒、库外（天气/菜谱/世界杯等）100% 拒答。

## 五、RAGAS 标准指标体系（`evaluation/run_ragas.py`）

裁判 LLM / 嵌入走本机 Ollama 的 OpenAI 兼容端点（qwen2:7b + bge-m3），不调用外部 API、零费用。
环境与用法见 `README_ragas.md`；结果存 `ragas_result_zh.json` / `ragas_result_en.json`。

| 指标 | 中文（n=10） | 英文（n=10） |
|---|---|---|
| faithfulness（忠实度） | 0.7333 | 0.8083 |
| answer_relevancy（答案相关性） | 0.6659 | 0.7946 |
| llm_context_precision_without_reference | 0.9722 | 0.9542 |
| context_recall（上下文召回） | 0.8800 | 0.8125 |
| answer_correctness（答案正确性） | 0.7546 | 0.7664 |

说明：
- **上下文精度/召回高**（0.88–0.97）→ 检索质量是达标的；
- **忠实度/答案相关性中等**（0.67–0.81）→ 扣分点主要在裁判（qwen2:7b）对“多期数值罗列型”答案的归因判定偏严，以及答案里带页码标注时措辞差异；用更强裁判（如 GPT/DeepSeek）会更高，本项目刻意用**与系统同源的开源小模型**以保证可复现、零成本。

## 六、RAG vs 纯 LLM 对比（`python evaluation/run_qa_report.py`）

详见 `report_rag_vs_llm.md`（含每题两路完整答案）。

| 维度 | RAG（检索增强） | 纯 LLM（不检索） |
|---|---|---|
| 平均耗时 | 约 1.8 s（1.0–3.4 s，流式首字更快） | 约 2.9 s（0.4–6.9 s，波动大） |
| 引用页码 | 有，可核对 | 无 |
| 事实题（id95/957/795） | 正确 | 部分答不出或含糊 |
| 数值题（id260/33/207） | 正确（逐字照抄原文） | **id260 直接答“无法提供数据”** |
| 涉密脱敏名称（“某视频技术规范”） | 忠于原文 | 易编造具体名称 |

**结论**：RAG 在事实型/数值型问题上显著优于纯 LLM，且每条结论可溯源；纯 LLM 遇到具体数字普遍拒答或含糊，在涉密脱敏处有编造风险。

## 七、并发 / 高可用压测（`python evaluation/load_test.py`）

|---|---|---|---|---|

### 7.2 问答接口 `/api/ask`

| 并发 | QPS | 平均延迟 | p95 | 错误 |
|---|---|---|---|---|
| 1 | 0.63 | 1590 ms | 3379 ms | 0 |

（原始数据：`load_test_search.json`、`load_test_ask.json`）

## 八、已知限制（如实记录）

1. **id260 的年代标注**：金额正确（6,464.51/14,414.16/18,780.67/4,627.14 万元），但年份偶有错配（原文对应 2016/2017/2018/2019 年 1-6 月）——该句原文未直接标年份，年份在表头。
2. **表格跨页**：个别跨页表格可能在分块边界处拆开。
3. **解析通道**：当前索引由 PyMuPDF（含内置表格识别）产出；MinerU 因本机无 GPU（torch 为 CPU 版）全量需数小时，输出到位后 `python app/build_kb.py` 可秒级重建升级。
4. **RAGAS 裁判**：用本机 qwen2:7b，指标绝对值偏保守；追求更高考分可换更强裁判模型（脚本已支持 `--gen`）。
