# 工单十二 实现步骤：LightRAG 知识图谱构建与检索优化

工单编号：人工智能NLP-RAG 项目-LightRAG 优化
语料：《招股说明书1.pdf》（武汉兴图新科电子股份有限公司）、《招股说明书2.pdf》（武汉力源信息技术股份有限公司）

> 两份说明书的归属经正文词频核验：招股说明书1 全文出现「兴图新科」571 次、「力源」0 次；招股说明书2 反之（368 次 / 0 次）。

---

## 一、总体流程

```
PDF 抽页 → 语料分块 → 领域 schema 约束下的实体关系抽取 → 图谱合并去重 → 实体向量索引
                                                                    ↓
测试问题 → 双层关键词抽取 → 局部路（实体→块）/ 全局路（沿关系扩散）/ BM25 路 → RRF 融合 → MMR 去冗余 → 上下文
                                                                    ↓
                                        RAG（向量+BM25）与 LightRAG 双系统 → LLM 生成答案 → RAGAS 四指标评估 → 对比报告
```

一段式入口：`python run_all.py`（`--force` 可强制重建全部缓存）。

---

## 二、分步实现

### 步骤 1：PDF 抽页与语料分块（`corpus.py`）

- 用 PyMuPDF 逐页抽取文本，共 **894 页**，缓存到 `data/pages.json`。
- 按句末标点做贪心切分，目标块长 500 字、重叠 50 字，过滤长度不足 30 字的噪音块，得到 **1950 块 / 796506 字**，缓存到 `data/chunks.json`。
- 两份说明书**全量使用，不做抽样**，保证语料完整性。

### 步骤 2：面向招股说明书的图谱 schema（`kg_schema.py`）

工单要求「根据 pdf 中的内容，优化图谱构建中的实体、关系，抽取出准确的实体类型和关系类型」。招股说明书章节结构固定（发行人基本情况、业务与技术、同业竞争与关联交易、募集资金运用、董监高、财务信息），据此收敛出封闭 schema：

**实体类型 12 类**：公司、人员、机构、产品、技术、业务领域、财务指标、金额、时间、项目、地点、资质荣誉。

**关系类型 22 类**，并约束头尾实体类型，例如：

| 关系 | 头类型 | 尾类型 | 含义 |
| --- | --- | --- | --- |
| 控股 / 参股 / 是子公司 / 是股东 | 公司 | 公司 | 股权关系（须带持股比例） |
| 是关联方 / 是实际控制人 | 公司 / 人员 | 公司 | 关联方关系 |
| 任职于 | 人员 | 公司 | 任职关系（含职务） |
| 销售给 / 采购自 / 竞争关系 | 公司 | 公司 | 上下游与竞争 |
| 拥有技术 / 参与制定 | 公司 | 技术 | 技术标准与专利 |
| 指标取值 | 财务指标 | 金额 | 财务指标数值 |

配套措施：
1. **代词消解**：`PRONOUN_ALIASES = ["本公司", "发行人", "公司", "本企业", "股份公司"]`，抽取时替换为实际发行人名。发行人按 `ISSUER_BY_SOURCE` 按来源说明书区分，避免两份说明书的「本公司」互相污染。
2. **名称归一化**：`normalize_name()` 统一全角/半角括号、去书名号与空白；`short_name()` 剥离「股份有限公司/有限公司」等企业后缀，用于全称与简称归并。

### 步骤 3：实体关系抽取与图谱合并（`kg_build.py`）

- **建图范围**：从 1950 块中选取 **900 块**——每个测试问题先取 BM25 top-8 强相关块（去重后 98 块，保证每个验收问题在图谱中有覆盖），其余按两份说明书均匀抽样补足。
- **并发抽取**：每 4 块组成一批，共 225 批，8 线程并发调用 DeepSeek，结果按批序落盘 `data/extract_raw.json`（重复运行命中缓存，不重复计费）。
- **合并去重**：实体按「主名 + 短名」归并为别名表；关系按 `(头, 关系, 尾)` 三元组聚合，累计支撑块编号、取值（持股比例、金额等）、报告期与支撑次数。
- **产出**：`data/graph.json`，共 **3355 个实体、2333 条关系**。

实体类型分布与关系类型分布见 `evaluation/知识图谱统计.md`，图谱可视化见 `evaluation/knowledge_graph.png`。

### 步骤 4：实体向量索引（`lightrag_index.py`）

- 每个实体把「实体名 + 类型 + 描述 + 最多 6 条关系短句」拼成语义文本，用 m3e-base 编码为 768 维向量，缓存 `data/entity_vecs.npy`。
- **实体链接**：关键词编码后在实体向量中检索，得分 = 余弦相似度 + 字面命中加权（完全同名 +0.25、互相包含 +0.15），且完全同名实体无条件进入候选。加权用于纠正「武汉兴图新科电子股份有限公司**章程**」这类共享前缀的实体把真正发行人挤到后面的问题。
- **图谱扩散**：沿无向邻接表做 1 跳扩散，单次上限 20 个邻居。

### 步骤 5：LightRAG 双层检索（`lightrag_retriever.py`）

按工单流程图实现查询响应流程：

1. **双层关键词抽取**：调用 LLM 把问题拆成
   - 低层关键词（`low_level_keywords`）：具体实体，如「武汉力源信息技术股份有限公司」「注册资本」；
   - 高层关键词（`high_level_keywords`）：概念主题，如「公司注册信息」「企业基本信息」。
2. **局部检索**：低层关键词 → 实体链接 → 取实体关联的语料块。
3. **全局检索**：高层关键词 → 实体链接 → 沿关系扩散 1 跳 → 取邻域实体关联的语料块。
4. **BM25 检索**：问题原文走全文检索，保证覆盖全量语料。
5. **三路 RRF 融合**（k=60，等权）→ **MMR 去冗余**（λ=0.90）→ 取 top-6 作为上下文。

### 步骤 6：RAG 与 LightRAG 双系统对比（`run_eval.py`）

- **扁平 RAG**：向量 top-30 + BM25 top-30 → RRF → MMR → top-6（`rag_retriever.py`）。
- **LightRAG**：上述双层检索流程。
- 两系统使用**同一套** 16 个工单测试问题、**同一套**参考上下文口径、**同一个**生成模型与提示词。

### 步骤 7：RAGAS 评估（`evaluator.py`、`references.py`）

工单允许「RAGAS 或其他评估框架」，这里用 LLM 判定实现 RAGAS 等价的四个指标，不引入额外依赖：

| 指标 | 定义 |
| --- | --- |
| context_precision | 有用上下文是否排在前面：对每个有用块计算「命中数 / 当前排名」后取平均 |
| context_recall | 参考答案的要点句能被检索上下文支持的比例 |
| faithfulness | 答案论断句能被检索上下文支持的比例（衡量幻觉） |
| answer_relevancy | 答案要点句直接回应问题的比例 |

**参考答案（银标）构造**：工单未提供标准答案。用**纯 BM25 宽窗口**（top-40 块）+ LLM 生成参考答案——刻意不含向量、不含图谱，使参考答案的构造过程独立于两个被评估系统，避免评估自我循环（见 `references.py` 模块注释）。

### 步骤 8：交付物生成（`report.py`）

生成 `evaluation/` 下四份交付物：知识图谱统计、知识图谱可视化 PNG、检索结果对比、RAGAS 指标对比。

### 步骤 9：交互界面（`app.py`、`start_app.py`）

Streamlit 界面，侧边栏可在 **RAG 知识库** 与 **LightRAG 知识库** 之间切换（工单要求「检索时，可以选择使用 RAG 还是 LightRAG 的知识库进行检索」），展示检索结果表（名次/来源/页码/召回路径/得分）、各块正文、LightRAG 的关键词与实体链接追溯，以及生成的答案。`start_app.py` 用 socket 探测空闲端口，自动切换端口启动。
