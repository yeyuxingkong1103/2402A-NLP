## 二、安装 Ollama 与模型

```powershell
# 1) 安装 Ollama 后启动服务（默认监听 11434）
ollama serve

# 2) 拉取嵌入模型（本工单使用三种，满足「支持多种嵌入模型」）
ollama pull bge-m3:567m              # 多语言，默认
ollama pull bge-large:latest         # 中文语义
ollama pull nomic-embed-text:latest  # 英文语义

# 3) 可选：LLM 重排 / 英文翻译
ollama pull deepseek-r1:1.5b

# 4) 校验
ollama list
```

> 若 Ollama 不在默认地址，可设置环境变量 `OLLAMA_BASE_URL`。

## 四、准备数据

```powershell
# 解压 ccf_competition.zip，把 9 份 PDF 放入：

```

文件名保持原样（形如 `日期__公司全称__股票代码__简称__年份__年度报告.pdf`）。
若解压后中文名出现 `╞╜░▓╥°╨╨` 类乱码，先执行一次修复（幂等，可反复运行）：

```powershell
python tools/fix_source_names.py            # 预览
python tools/fix_source_names.py --apply    # 修正 PDF 文件名 + chunks.jsonl/meta.json 来源名
```

系统同时以文件名中的 **6 位股票代码**识别文档，因此即便名称异常也不影响检索与路由。

同时确认评测集与多轮脚本就位：

```
研发/data/eval_questions.json      # 10 道测试题（本工单核心）
研发/data/multiturn_dialogue.json  # 5 轮多轮对话验收脚本
```

## 八、配置项

`研发/.env`（可选，均有默认值）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Ollama 服务地址 |
| `EMBEDDING_MODEL_SLUG` | `bge-m3` | 默认嵌入模型 |

| `FUSION` | `rrf` | 默认融合算法 |
| `TOP_K` | `8` | 返回/展示片段数（召回率按此 K 计） |
| `RECALL_K` | `60` | 单通道召回候选数（`.env` 覆盖 config 默认 30） |
| `ANSWER_TOP_K` | `40` | 参与答案合成的重排池深度（`.env` 覆盖 config 默认 30） |
| `DOC_FILTER_ENABLE` | `1` | 文档级路由（公司名消歧）开关 |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `600` / `100` | 切片参数 |

## 九、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `知识库未构建，请先运行 build_kb.py` | `vector_db/` 缺失或不完整 | 执行 `python build_kb.py --rebuild` |
| 嵌入报连接错误 | Ollama 未启动或模型未拉取 | `ollama serve` + `ollama list` 核对 |
| 首次提问较慢 | 冷启动（分词 / 索引 / 模型加载） | 已内置 `warmup()`；`bench_latency.py` 区分冷/热口径 |
| 跨公司召回串味 | 文档路由被关闭 | 确认 `DOC_FILTER_ENABLE=1` |
| 界面无知识库信息 | `meta.json` 缺失 | 重新构建知识库 |
| 中文乱码文件名 | 原始压缩包为 GBK 编码被误按 CP437 解码 | `python tools/fix_source_names.py --apply` 一键修复；不改也不影响检索（以股票代码识别） |
