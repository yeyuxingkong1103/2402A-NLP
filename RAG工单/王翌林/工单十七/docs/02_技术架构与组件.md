# 工单十七 · 技术组件与架构设计

## 1. 技术组件清单

| 组件 | 作用 | 选型 |
|------|------|------|
| API 网关层 | 接收问答/解析请求、限流、鉴权 | FastAPI + Uvicorn |
| RAG 编排引擎 | 检索 + 生成串联、缓存、单例管理 | 自研 `RAGEngine`（本仓库） |
| 向量检索 | 工业文档语义检索 | 内存向量库（生产可替换 Milvus） |
| 文档解析 | PDF/图片 OCR、版面分析 | DeepDoc / VLM（工单十六微调模型） |
| 大模型推理 | 问答生成 | VLM-LLM，经并发限流调用 |
| 语义缓存 | 重复问题短路返回 | 有界 LRU + TTL |
| 任务队列 | 文档解析异步消费 | asyncio.Queue / Redis Stream |
| 连接管理 | 向量库/DB 连接复用 | 连接池（borrow/return） |
| 监控 | 指标采集与可视化 | Prometheus + Grafana |
| 缓存/消息 | 队列、限流计数 | Redis |
| 压测 | 并发复现与对比 | Locust / JMeter / 自研线程压测 |

## 2. 技术架构

```
                    ┌───────────────┐
   客户端 ─────────▶│  FastAPI 8017 │
                    └───────┬───────┘
                            │（中间件：指标/在途计数）
              ┌─────────────┴──────────────┐
              ▼                            ▼
     ┌────────────────┐          ┌────────────────────┐
     │ 问答请求        │          │ 文档解析请求        │
     │ 语义缓存命中? ──是─返回   │ 入 asyncio.Queue    │
     └────────┬───────┘          └─────────┬──────────┘
              否                           │（消费者异步处理）
              ▼                            ▼
     ┌────────────────┐          ┌────────────────────┐
     │ 连接池借连接    │          │ DeepDoc/VLM 解析    │
     │ 向量检索 TopK  │          │ 入向量库 + 更新状态  │
     └────────┬───────┘          └────────────────────┘
              │归还连接（finally）
              ▼
     ┌────────────────┐
     │ LLM 并发限流    │  Semaphore(40) + run_in_executor
     │ 生成答案        │  推理后 del/gc 释放中间张量
     └────────┬───────┘
              ▼
        写缓存 → 返回
              │
              ▼
        Prometheus /metrics ← 采集（请求量/延迟分位/在途/缓存/RSS）
```

## 3. 关键设计决策
- **单例化重组件**：Embedder / VectorStore / LLM / 连接池在进程启动时初始化一次，避免每请求重复加载。
- **有界资源**：缓存 LRU(512)+TTL、连接池 size=8、LLM 并发 40，全部有上限，杜绝无限增长。
- **异步不阻塞**：问答经 `run_in_executor`；解析走队列，API 立即返回 task_id。
- **显式释放**：推理结束 `del` 中间对象 + `gc.collect()`；GPU 场景追加 `torch.cuda.empty_cache()`。
- **可观测**：全链路埋点 Prometheus，支撑长稳与告警。
