3.3 评估脚本
关键设计：工业准确性评估，针对多选题设计选项抽取式判分。

在调试过程中发现原判分逻辑存在 bug：

python
# 原逻辑（错误）：只看预测前 20 字符里有没有 expected 首字母
def is_correct(pred, expected):
    exp_letter = expected.strip()[0].upper()
    return exp_letter in pred.upper()[:20]
该逻辑导致所有输出较长推理过程的预测都被误判为错，因为答案通常在末尾，前 20 字符内不含选项字母。

修复后判分逻辑：

python
def is_correct(pred, expected):
    import re as _re

    def _extract(text):
        if not text:
            return ""
        text = str(text)
        # 优先匹配 A. / A、 / A． / A) / A） / A， / A：
        matches = _re.findall(r'([ABCD])[\s.、．,，)）:：]', text)
        if matches:
            return matches[-1].upper()
        # 退化：单词边界匹配
        matches = _re.findall(r'\b([ABCD])\b', text)
        if matches:
            return matches[-1].upper()
        return text.strip()[:1].upper()

    pred_letter = _extract(pred)
    exp_letter = _extract(expected)
    if not pred_letter or not exp_letter:
        return False
    return pred_letter == exp_letter
调试中发现的另一个严重问题：原代码中正则表达式的 \b（单词边界）在文件写入时被误转为退格符 \x08，导致该分支永远无法匹配。已通过字符级替换修复。

4.2 失败案例分析
以下为在评测过程中观察到的典型失败模式：

案例 1：位置推理错误（旧数据集，题 6）

问题：部件 9 相对于部件 10 的位置

标准答案：C. 在其左侧

微调前：根据参考文件中的第8页的图片，部件9（进水口）相对于部件10（清水口）的位置是：\n\nC. 在其左侧 ✅

微调后：B. 在其下方 ❌

分析：微调后模型丢失了推理过程，直接猜测答案并选错。这是典型的过拟合到短答案格式——训练数据的 assistant 回答都是裸选项（如 "C. 液压泵"），模型学会"只输出答案、不做推理"，在需要空间推理的题目上表现下降。

案例 2：推理方向偏移（旧数据集，题 3）

问题：哪个部件温度会升高

标准答案：C. 冷却水出口管13

微调前：完整推理后得出选项 C ✅

微调后：推理方向变为"隔板 21 温度降低"，最终选 A. 隔板21 ❌

分析：模型对"隔板"类概念的偏置增强，可能与训练数据中该类题目占比有关。

案例 3：正收益（旧数据集，题 8）

问题：气固分离部件

标准答案：C. 过滤室

微调前：选了 B. 沉降室 ❌

微调后：直接给出 C. 过滤室 ✅

分析：该题可能是训练数据中覆盖充分的题型，微调带来正向收益。

案例 4：干净测试集上的典型错误

在 50 题测试集中，微调后仍有 25 题答错。抽样分析显示，错误集中在：

多步空间关系推理题：需要综合图中多个部件的相对位置

长文本专利描述理解题：需要跨段落定位答案

图像细节识别题：小尺寸部件编号识别

4.3 关键发现
微调带来显著正向收益：在干净测试集上准确率从 36% 提升到 50%，+14 个百分点，证明领域适应微调有效。

训练数据格式决定模型行为：assistant 回答为"裸答案"时，模型倾向于牺牲推理能力换取输出简洁性，在复杂推理题上表现下降。

训练/测试集隔离是评估的前提：数据重叠会导致评估结果完全失效。

判分脚本的正确性直接影响结论：一个字符级 bug（\b → \x08）就能让准确率从 50% 变成 0%。

建议：

安装 GPU 版 PyTorch（CUDA 12.8+，适配 RTX 5060 的 Blackwell 架构需 PyTorch 2.7+）

或申请 GPU 服务器资源

预期加速比：20~30 倍（单步 550 秒 → 20~30 秒）

6.2 训练数据改进
当前训练数据的 assistant 回答为裸选项（如 "C. 液压泵"），导致模型丢失推理链。

建议改为"推理 + 答案"格式：

json
"assistant": "分析：蜗杆(17)旋转带动螺纹杆(6)，螺纹杆与扇叶(20)相连，因此扇叶会随之运动。\n答案：B. 扇叶（20）"
预期效果：

保留 base 模型的多步推理能力

提高空间关系题、运动原理题的正确率

减少"直接猜测"导致的错误
