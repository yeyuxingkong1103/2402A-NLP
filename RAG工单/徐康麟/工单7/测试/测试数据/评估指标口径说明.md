## 1. 一句话口径总表

| 指标（汇总键） | 怎么算 | 达标线 | **最容易读错的地方** |
| --- | --- | --- | --- |
| **严格准确率** `准确率.严格准确率` | `严格判对题数 ÷ 有效题数`；判对 = `is_correct(覆盖率, refused, 0.6)` | **≥ 90%**（17 题 ⇒ **≥ 16/17**） | 拒答**算判错**；分母是**有效题数**（异常题不计入） |
| **宽松准确率** `准确率.宽松准确率(严格+部分)` | `(严格判对 + 部分正确) ÷ 有效题数` | 参考值（**不得**用它替代严格准确率） | 「部分正确」= 覆盖率 ∈ [0.3, 0.6) **或** 数值原子覆盖 ≥ 0.6（英文/单位换算兜底）；**不算严格判对** |
| **关键词覆盖率** `judge.keyword_coverage` | `keyword_coverage()`：命中关键词数 ÷ 关键词总数 | 单题 **≥ 0.6** 才可能严格判对 | 同义改写会**漏判**（虚低）；**数字边界**已防 `11.65` 误命中 `1.65` |
| **recall@5 / recall@10** `检索召回.平均recall@5` / `平均recall@10` | `retrieval_recall_at_k(hits_text, keywords, k)`：前 K 条片段**合并正文**是否含该关键词；题级宏平均 | **≥ 95%**（沿用召回口径） | 是 **union 口径**；K=5/10 取自**同一次 top-10 检索**，不是两次检索 |
| **页命中率** `页命中.命中率` | `page_hit(hits, expected_pages_hint, expected_files)` 的 `hit` | **辅助指标**（不单独判达标） | `expected_pages_hint` 是「最小~最大」，**区间内非证据页也算命中** ⇒ 系统性偏高 |
| **跨语料泄漏** `跨语料泄漏.*` | `cross_corpus_leak()`：top-**3**（另有 top-10 复核）是否出现非期望文件名；`citation_leak()` 另看引用 | 单语料题 **目标 0** | 跨文档题（Q04/Q09）与**不提公司名**的题天然不可控；引用级泄漏单列 |
| **响应时间** `响应时间ms.*` + `SLA.*` | 逐题 `total_ms`（= `Answer.latency_ms.total`，**服务端端到端口径**）；报 平均/中位/P50/P90/P95/最大/最小 + 检索/生成/首字分段 | 端到端 **≤ 3000 ms**；报 `SLA.达标率` 与 `SLA.超时题号` | **无独立客户端 wall 计时**；冷启动不预热必超线；缓存命中会虚高（本框架 `USE_CACHE=False`） |
| **拒答率** `拒答.拒答率` | `拒答题数 ÷ 有效题数`；附 `拒答题号` / `按原因` | 17 道功能题 **目标 0**（任何拒答都要归因）；异常输入题 **期望 100%** | 两类分母**不得混算**；拒答 ≠ 答错 |
| **无引用率** | **汇总 JSON 未直接给该字段** ⇒ 需从 `评估结果.jsonl` 的 `cited_pages` 重算：非拒答且 `cited_pages=[]` | **目标 0** | 「有引用页」≠「该页确实是答案证据」；拒答题不计入分母 |
| **索引可达性** `索引可达性.索引内可达率` | 对每个关键词做全库检索：索引里是否存在 | 用于**归因**（非达标项） | 它把「索引里根本没有」与「索引有但没召回」分开——**这是解释 recall 低的第一入口** |

## 3. 归一化与匹配口径（读 `关键词覆盖率` 前必须知道）

| 步骤 | 规则（`判分.py::normalize`） | 示例 |
| --- | --- | --- |
| ① 全角→半角 | 含全角空格、全角数字/字母/标点 | `１３７９．５８` → `1379.58` |
| ② 去所有空白 | 空格 / 制表 / 换行 / `\u3000` / `\u00a0` | `1,379.58 亿元` → `1379.58亿元` |
| ③ 去标点/符号/控制符 | Unicode 类别 `P`/`S`/`Z`/`C` 全部剔除，**唯独保留小数点 `.`** | `1,379.58` → `1379.58`；`1.65％` → `1.65` |
| ④ 小写化 | 英文大小写不敏感 | `ROE 11.05%` → `roe11.05` |

**数字边界（关键防假阳性）**：以数字开头/结尾的关键词，匹配位置的相邻字符**不能**是数字或小数点 ⇒
`11.65` **不**命中 `1.65`；`18.25` **不**命中 `18.2`；`1165` **不**命中 `165`。

**数值原子（`atomic_coverage`）**：抽出关键词里的数字，允许单位换算引起的 10ⁿ 倍差（相对误差 0.5%），
例如 `610.36亿元` ≈ `RMB 61.036 billion`。**仅作补充判据**（部分正确档），不单独定对错。

## 6. 三条「读错就白读」的红线

1. **`answer_keywords` 是代理标注，不是真值**（语料无人工相关度标注）。
   命中关键词 **≠** 语义正确；未命中 **≠** 语义错误（同义改写会漏判）。
   它**不衡量**论述完整性、逻辑与可读性 ⇒ 分析论述题（Q03/Q04/Q17）的分数只能当「要点覆盖」看。
   本工单指标**不得**与工单4/5/6（招股说明书语料、题数与判据来源均不同）直接横向比较。
2. **延迟必须写口径**：预热 + 独占 Ollama + `use_cache=False`；本框架的端到端是**服务端 `total_ms`**（无独立客户端 wall 计时），
   冷启动口径（首字 3.4 s）与缓存口径（毫秒级）**都不可用于验收**。
3. **必须看 `异常题数`**：`运行评估.py` 即使在索引缺失/后端不可用/连续 3 题异常中止时，**退出码仍可能是 0**。
   → 判读顺序永远是：`评估运行日志.txt` → `异常题数/异常题号` → 指标。

## 7. 判读时的常见误读（速查）

| 你看到的 | 别急着下结论 | 先看什么 |
| --- | --- | --- |
| `关键词覆盖率 = 1.0` 但答案像表格片段 | 不是「答得完美」 | `generation_method` / `judge` 之外的 `composer_method`、`生成回退` 标签 |
| `是否拒答 = True` | 不一定是缺陷 | 功能题（压准确率，要归因）还是异常输入题（**期望**拒答）；再看 `拒答.按原因` |
| `总ms` 很小（个位数） | 极可能命中缓存 | `配置.use_cache` 是否为 `false`（本框架恒为 false） |
| 首题延迟特别大 | 冷启动未预热 | `运行元信息.warmup_ms` 是否存在 |
| `recall@10` 高、`关键词覆盖率` 低 | 检索到了但**生成没说出来** | 是否触发原子护栏回退（`llm_rejected_reason` / `missing_atoms`） |
| `页命中 = True` | 不代表命中证据页 | 区间是「最小~最大」；非证据页也算命中 |
| 英文题（Q13）判错 | 英文是**降级路径**（问句英文 / 语料中文） | `language_degraded` 与 `atomic_coverage`；**不得**删题或改判据 |
| 图像相关问题无结果 | 图像块 = **0**（缺 `cv2`/`onnxruntime` + 无中文 CLIP 权重） | 属**已知缺口**；报告须登记，不得声称图像解析有产出 |
| `异常题数 > 0` 但退出码 0 | 流程「跑完」≠ 全部成功 | `异常题号` + `评估运行日志.txt` |
