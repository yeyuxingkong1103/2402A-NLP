# 优化方案文档

**工单编号**：人工智能NLP-RAG-图像内容解析及检索优化

## 一、优化目标

在工单三「文本 + 表格」解析的基础上，让 RAG 系统能够"看懂"PDF 中的**结构图、统计图、流程图**等图像内容（包括没有文本层的纯矢量图），把图像信息转化为可检索、可问答的语义块，解决"图里有答案却检索不到"的问题。

## 二、核心优化点

### 1. 图像内容解析流水线（核心新增）

| 环节 | 做法 | 作用 |
|---|---|---|
| 定位含图页 | 内嵌大图 / 图引用词 + 矢量笔画数达标 / 承接上页引用 | 只处理真正含图的页 |
| 图像获取 | 内嵌位图逐张提取；纯矢量图整页 2x 高分辨率渲染 | 一页多图数字互不混淆；矢量图清晰可辨 |
| OCR 识别 | RapidOCR（ONNX Runtime），保留每个文字框坐标 | CPU 即可运行，无需 GPU/外网 |
| 密度门槛 | 有效文字框 / 总字数低于阈值判为非图表 | 过滤照片、印章、Logo、凭证扫描噪声 |
| 空间配对 | 标签与百分比按 y 坐标就近贪心配对（容差 8% 图高） | 保证"行业名↔增长率"正确归位 |
| LLM 语义 | DeepSeek 结合正文事实约束生成语义块 | 输出可检索的中文语义，`block_type=image` |

### 2. 关键难点：行业名 ↔ 百分比的空间配对

柱状图中条形末端的数字与左侧行业名存在十几像素的 y 偏差，先后尝试：

1. **整页 OCR**：同页两张图的数字混在一起 → 改为逐图分别 OCR；
2. **逐图但乱序**：按 OCR 输出顺序让 LLM 猜配对 → 必然错配；
3. **严格同行（y 相等才聚行）**：偏差导致"汽车"误配 5.1%；
4. **y 就近贪心配对（最终方案）**：标签与数值分组后按 y 就近匹配，容差放宽到图高 8%，并排除"增长率"等标题词 → 全部正确。

### 3. 检索与生成衔接

- 图像语义块 `block_type="image"`，与表格块一样**不再切分**，保持语义完整；
- Prompt 中以 `[图像语义 i]` 单独标记，并强化"据图像语义还原部门构成、增长率等"的指令；
- 入库元数据额外保留 `image_caption`、`ocr_box_count`，便于溯源。

### 4. 依赖与环境兼容

| 项 | 说明 |
|---|---|
| OCR 引擎 | rapidocr-onnxruntime 1.4.4（onnxruntime + opencv） |
| numpy | 固定 1.26.4，避免与 numba/gensim/scipy 冲突 |
| 硬件 | 无 GPU 可运行（CPU 推理） |

## 五、后续优化方向

1. **CLIP 跨模态检索**：直接用"图向量"匹配问题，覆盖 OCR 难以还原的图表；
2. **版面分析**：用布局检测模型区分标题/图例/坐标轴，进一步提升配对准确率；
3. **图像块加权**：检索时对高质量图像语义块给予适当权重；
4. **图—表互证**：图像语义与正文/表格数据交叉校验，自动纠错。
