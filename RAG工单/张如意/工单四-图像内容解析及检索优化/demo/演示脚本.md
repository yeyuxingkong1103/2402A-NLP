## 分镜 1（0:00–0:40）开场与问题抛出

**画面**：项目根目录 `工单作业/`，随后打开 `工单04-图像内容解析及检索优化/` 目录树。

**解说词**：
> 大家好，这是人工智能 NLP-RAG 项目的第四个工单：PDF 文档的图像内容解析及检索优化。
> 本次要解决两个"答案根本不在文字里"的问题：
> 第一，力源信息组织结构图中，销售部有几个部门构成，其中大客户销售部有几个销售处构成？
> 第二，2008 年中国 IC 市场应用结构与增长图中，增长率最快的是哪个行业？负增长的是哪个行业？
> 这两个问题的答案都画在图里。接下来我们演示：不做图像解析会怎样，做了之后又会怎样。

**字幕**：本工单核心 —— 让"图里的信息"变成"可检索的答案"

## 分镜 2（0:40–2:00）数据定位：答案到底藏在哪儿

**画面**：终端执行定位命令（见 `docs/图像问题定位分析.md` 文末），高亮输出：

```
p38 绘图=33 内嵌图=19 文本=328字
p39 绘图=31 内嵌图=23 文本=323字     ← 组织结构图（矢量绘制）
p72 绘图=1  内嵌图=17 文本=787字     ← IC 市场图（2 张真图 + 15 个水印）
```

**解说词**：
> 先用 PyMuPDF 做一次定位。第 39 页就是公司组织结构图：它有 31 个矢量绘图对象，
> 却没有任何一张真实的嵌入图片——23 张全是每页重复的 143×127 水印切片。
> 换句话说，用 get_images 抽图，这一页只能抽到一堆水印，图本身是"画"出来的路径，抽不到。
> 第 72 页的 IC 市场图不一样，它是两张真实的位图：一张饼图、一张条形图，
> 但同样混着 15 个水印，需要过滤。
> 还要注意，第 39 页的文本层其实有 323 个字，是"销、售、部"这样逐字竖排的节点名——
> 字都在，但谁是谁的下级，文字流里完全没有。

**字幕**：矢量图 → get_images 取不到；文本层 → 只有节点名，没有层级

## 分镜 3（2:00–4:00）第一步：抽图（含矢量图整页渲染回退）

**画面**：终端执行并逐行高亮输出：

```bash
python src/image_extractor.py --docs 2
```

```
[抽取] 《招股说明书2》 ...
   p39  page_render  → 组织结构图 (0.93)
   p72  embedded     → 饼图 (0.91)
   p72  embedded     → 柱状图 (0.88)
[完成] 共 N 张图（内嵌 x / 整页渲染 y）
```

**画面切换**：右键打开 `results/images/招股说明书2/p39_fullpage.png`，
用看图工具放大到"销售部 → 大客户销售部 → 六个销售处"区域；
再打开 `p72_img*.png`，放大条形图上的 `-2.0%` 与 `14.0%`。

**解说词**：
> 抽图模块做了三件事：第一，按"截断尺寸加全文档重复度"识别水印，
> 那 5250 个水印切片全部被过滤；第二，对第 39 页这类矢量图，
> 因为没有可用的内嵌图，自动回退为整页渲染，用 200 dpi 生成这张清晰的整页图；
> 第三，用 CLIP 给每张图做零样本分类，判定它属于组织结构图、柱状图还是产品照片，
> 用来决定后面用哪种 prompt 去读它。
> 大家可以看清楚，组织结构图的层级、条形图的百分比，现在都以像素形式拿到了。

**字幕**：水印过滤 + 矢量图整页渲染回退 + CLIP 分类

## 分镜 4（4:00–5:40）第二步：多模态语义解析

**画面**：终端执行：

```bash
python src/image_semantic_parse.py --pages 39,72,310
```

随后打开 `results/image_descriptions.md`，滚动展示"层级结构"与"图表结构化数据"：

```
销售部 的直接下级（4 个）：电话及网络销售部、渠道销售部、大客户销售部、国际贸易部
大客户销售部 的直接下级（6 个）：珠海销售处、深圳销售处、北京销售处、武汉销售处、广州销售处、成都销售处
...
增长率 —— IC卡：-2.0，工控：10.5，计算机：7.9，其他：6.1，汽车：14.0，网络通信：2.6，消费：5.1
增长率 中的最大值：汽车（14.0）；最小值：IC卡（-2.0）
增长率 中为负值的类别：IC卡
```

**解说词**：
> 这是本工单的技术核心：CLIP 负责"这是什么图"，多模态大模型负责"图里写了什么"。
> 对组织结构图，用专用 prompt 输出缩进层级树；对图表，用结构化抽取 prompt 输出 JSON 数据。
> 更关键的是后处理：层级树里的父子关系由程序解析，子节点数量由程序统计，不靠模型"数数"，
> 这样"4 个部门""6 个销售处"是确定性结论；增长率的最大值和负值也是程序算出来的，
> 模型只负责把数字读准。
> 这些内容会拼成一段可检索文本，作为图像块写进知识库。

**字幕**：CLIP 路由 → VLM 精读 → 程序化计数/最值（消除幻觉）

## 分镜 5（5:40–7:20）核心对比实验：解析前 vs 解析后

**画面**：终端先跑"不含图像"的问答（用对照索引），再跑"含图像"：

```bash
python src/image_qa.py --collection wo04_text --qids 5,6      # 对照组
python src/image_qa.py --collection wo04_multimodal --qids 5,6 # 实验组
```

**对照组画面**（口播重点）：

```
▌1. 命中的图像（0 个图像块）
▌3. 生成的答案
   根据提供的文档内容，未能找到该问题的答案。
▌4. 检索精确度：要点命中率 0%
```

**实验组画面**：

```
▌1. 命中的图像（2 个图像块）
   · 《招股说明书2》第39页  相关度=0.87  来源=['page_render']
     图像文件：results/images/招股说明书2/p39_fullpage.png
     层级事实：
       - 销售部 的直接下级（4 个）：电话及网络销售部、渠道销售部、大客户销售部、国际贸易部
       - 大客户销售部 的直接下级（6 个）：珠海销售处、深圳销售处、…
▌2. 图像的语义描述 …
▌3. 生成的答案：销售部由 4 个部门构成……大客户销售部由 6 个销售处构成……
▌4. 检索精确度：Context Precision = 0.9x；要点命中率 100%；图像页命中 True
```

**解说词**：
> 同一个问题、同一套检索与生成配置，唯一的区别是图像语义块有没有入库。
> 左侧对照组的检索结果里没有任何图像块，模型只能如实回答"未能找到"。
> 右侧实验组命中了第 39 页的图像块，答案下方直接给出了抽出的图和层级事实，
> 销售部 4 个部门、大客户销售部 6 个销售处，回答完整。
> 这就是本工单要证明的事情：这两问的差距，完全来自图像解析。

**字幕**：唯一变量 = 图像语义块是否入库

## 分镜 6（7:20–8:40）消融报告与 16 问评估

**画面**：终端执行：

```bash
python src/compare_with_without_images.py

```

打开 `results/image_ablation.md` 与 `results/evaluation_multimodal.md`，
高亮"准确率对比表""id5/id6 行""响应时间"。

**解说词**：
> 消融实验把 16 个问题在两个索引上各跑一遍：不含图像解析的准确率与含图像解析的准确率，

> 完整评估报告同时给出准确率、检索耗时与端到端耗时；
> 检索链路稳定在一秒以内，端到端时长受生成模型的网络往返影响，报告里两个口径都如实列出。

## 分镜 7（8:40–10:00）Web 交互演示

**画面**：`python src/serve.py` → 浏览器打开 `http://127.0.0.1:8000`。

1. 点击「图像问题5」按钮 → 展示答案 + 图像卡片（左侧整页组织结构图，右侧语义描述）；
2. 点击「图像问题6」按钮 → 展示 IC 市场图与增长率结论；
3. 输入一个文本问题（例："武汉兴图新科电子股份有限公司法定代表人是谁？"）→ 展示跨文档问答；
4. 输入英文问题："How many sales offices are under the Key Account Sales Department?"；
5. 指出答案下方的耗时标注与来源页码。

**解说词**：
> 最后是交互界面。点击图像问题按钮，答案会连同命中的图像一起展示：
> 左边是系统实际抽取的图，右边是多模态模型读出的语义描述，方便人工核验。
> 文本问题、跨文档问题同样支持，中英文提问都能作答，
> 每条答案都标注来源页码，并显示检索与端到端耗时。

**字幕**：图像卡片 · 中英文支持 · 来源溯源 · 耗时可见
