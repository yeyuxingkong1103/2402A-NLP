# scripts/eval/ —— 评测与链路观测脚本

与 `evaluation/` 的分工：

| | `evaluation/` | `scripts/eval/` |
| --- | --- | --- |
| 面向 | **跑评测集出指标**（Recall / MRR / 引用正确率 / 拒答准确率），产物是 `reports/eval_*.{json,md}` | **观测单条链路是否真的生效**（多轮、摘要、改写），产物是控制台证据 + 退出码 |
| 会话形态 | 每题一个独立 session（`eval_<题号>`），窗口永远不满 | 同一 session 连跑多轮，窗口会满、摘要会触发 |
| 能否证明摘要/改写生效 | ❌ 不能（不走 `persist_turn`，Redis 里没有 key） | ✅ 能（按真实链路顺序回写短期记忆） |

## 共同前置

| 项 | 要求 |
| --- | --- |
| 依赖服务 | MySQL / Redis / Milvus 在线；先跑 `python scripts/check_services.py`（全绿再跑） |
| 模型 API | LLM / Embedding / Reranker 线上可用（脚本会真实调用，**消耗额度**） |
| 配置 | 项目根 `.env`（经 `scripts/_env.py` 读取，源码内零口令） |

## 脚本清单

| 脚本 | 作用 | 额外前置 | 可重复运行 | 运行后清理 |
| --- | --- | --- | --- | --- |
| `multi_turn_summary_check.py` | 连跑 N 轮真实问答（真实检索 + 真实 LLM），观测：① 摘要何时产出 ② 提示词何时注入「# 本次会话前情」段 ③ 每轮查询改写记录（原问 → 改写后） | LLM 可用；摘要开关会被脚本强制设为 `true` | ✅ 是（探针 key 跑完自动删；`--keep` 可保留观察） | 默认自动删 Redis 探针 key（`probe_b22_user` / `probe_b22_multiturn`）；**不写 MySQL**（`chat_store=None`） |

### 退出码（措辞上区分"没验到"与"验了没通过"）

| 码 | 含义 |
| --- | --- |
| `0` | 摘要生成 + 前情注入都在真实多轮链路里观测到 |
| `1` | 跑了足够轮数仍没触发（真失败） |
| `2` | 前置/参数不满足：开关关闭、轮数不足、摘要产出后没有可观测的后续轮次（末轮被检索侧拒答，没调用 LLM） |
| `3` | 前置服务不可用（检索链路装配失败） |

## 常用命令

```bash
python scripts/eval/multi_turn_summary_check.py                # 默认 14 轮
python scripts/eval/multi_turn_summary_check.py --rounds 2     # 只看前 2 轮的改写记录
python scripts/eval/multi_turn_summary_check.py --keep         # 保留 Redis 探针 key
```

## 观测口径（改窗口/节流策略后需同步复核）

- 短期记忆窗口 = 20 条消息 = 10 轮 → **第 10 轮**结束时窗口满，当轮即可产出摘要
  （若该轮摘要因 LLM 返回空回答失败，按设计保留旧摘要并顺延）
- 摘要写入发生在本轮回答**之后** → 前情段最早在**下一轮**（第 11 轮）进入提示词
- 改写只在问题带**指代/省略信号**时触发（"那这个要赔多少？"会触发，"经济补偿怎么算"不会）；
  默认题目集末两条特意写成省略式追问，用于覆盖这条路径
- 检索侧拒答（无候选 / 相关性过低）的轮次**不调用 LLM**，提示词无从观测，日志里记为 `前情=n/a` ——
  这是"没测到"，不是"没注入"
