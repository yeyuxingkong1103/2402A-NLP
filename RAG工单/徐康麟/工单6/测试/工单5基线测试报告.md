## 5. 响应时间（验收线：逐轮 ≤3000 ms）

| 指标 | 多轮序列（wall） | 改写阶段 | 单轮回归 16 题（wall） |

| max | **872.3 ms** | 0.2 ms | 2042.2 ms |

| **超 3000 ms 的轮数** | **0** | — | **0** |
| 冷启动（预热 1 次，**不计入**） | 2168.3 ms | — | — |

**结论：达标。** 关键观察：

* **改写层的开销可以忽略**：P95 仅 **0.2 ms**，占 3 秒预算的 **0.007%**。
  这是「**规则 + 状态**改写、不调用任何生成模型」技术选型的直接收益 ——
  多轮能力几乎是「免费」加上去的。
* **延迟主体是生成**（qwen2.5:3b 单次 ≈0.3~1.7 s），与工单4 同源；
  多轮并没有把链路拖慢 —— MT3/MT4 只有 ≈205~288 ms，因为它们的证据是**表格/结构化字段**，
  走确定性合成器，不需要 LLM 润色。
* 冷启动 2168.3 ms 已接近 3 s 线，故验收**必须**用预热口径（与工单4 同一纪律）。

### 8.1 如实登记的一个质量缺陷（不算失败，但不算好）

乱码输入（如 `asdkjfh#$%^&*`）虽然**不崩溃**、也返回了合法字符串，但会命中检索并给出
**一段无关但语法正确的答案**。根因是工单4 的可答性闸门对「无实词问句」不生效。
这是**工单4 的基线行为，不是工单5 引入的**（改写策略为 `none` 时链路与工单4 逐字一致，
且工单4 自己的测试报告已登记同类限制）。
按本工单「异常输入不得崩溃」的判据**通过**，但**答案质量不过关**，故如实登记。
（注：在评测台的另一些乱码样式上确实返回了「不清楚」，说明闸门对部分样式有效，
覆盖面不完整。）

## 12. 已知限制与环境事实（如实登记）

| # | 项 | 说明 |
| --- | --- | --- |
| ① | **乱码输入会给出「自信的错答」** | 见 §8.1。工单4 基线行为；按「不崩溃」判据通过，但答案质量不过关。 |
| ② | **本机无 `gradio`** | Gradio 界面文件齐备但**未真机运行**；多轮界面以纯标准库实现交付并已实测。 |
| ③ | **对话历史只保留最近 3 轮** | 工单「速度优先」的明确要求；更早上下文被裁剪（另存 `entity_stack` 缓解实体丢失）。 |
| ④ | **MT2 答案主语与参考答案措辞不同** | 参考答案写「武汉兴图新科…参与的…工程」，系统返回证据原文「某大型研究所牵头承担的…工程」。**工程名与奖项逐字一致**（判分通过），主语取自证据原文。 |
| ⑤ | **引用页码存在生成随机性** | 同一问句两次独立生成，答案正文一致但**引用页码可能不同**（如第 68 页 vs 第 52 页）。故校验分「硬口径（答案 / 改写问句 / 拒答标志 / 策略）」与「软口径（引用页码）」两档；本报告的主判据只用硬口径。 |
| ⑥ | **两个空的游离目录删不掉** | 仓库根残留 `.pytest_tmp/` 与 `.tmp_pytest/`（**均为空目录**）。根因：本机沙箱下 pytest 的 `tmp_path` 与系统 `%TEMP%` 不可写，测试已改用仓内 `研发/data/runtime/_pytest_tmp/`；这两个空目录是早期尝试的残留，`rmdir` / `.NET Directory.Delete` 均返回 `WinError 5`（沙箱拒绝），**非交付物缺陷**。 |
| ⑦ | **答案级缓存曾带有工单4 的陈旧条目** | 复制过来的 `研发/data/index/qa_runtime.sqlite3` 内含 25 条工单4 时期写入的答案。**已在最终评测前清空**（`answer_cache` / `qa_history` / `sessions`），确保所有数字来自当前代码。之所以必须清：工单5 修改了答案合成器（主体绑定），陈旧缓存会掩盖改动效果。 |
| ⑧ | **工单4 的既有已知限制仍适用** | 向量通道弱于 BM25、本机无 OCR、3D 饼图不做角度反算、Docker 未构建等，逐条见 `设计/工单4基线交付说明.md`。 |
| ⑨ | **长对话端到端延迟下降未实测** | 缓存接线后的「100 轮长会话延迟对比」**未运行**，不估算。 |
| ⑩ | **英文省略式的改写是「骨架复用」而非地道英文** | E3 改写为 `Who is Wuhan P&S Information Technology Co., Ltd legal representative?`（英文语序不完美）。它**能正确检索**（bge-m3 多语言 + 英文翻译路径），但不是润色后的自然英文。本工单「速度优先、不引入第二个模型」的取舍结果。 |
