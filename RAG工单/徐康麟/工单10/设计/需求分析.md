### 验收三：容器管理 —— ② 容器数据管理

| 子项 | 判定口径 | 落地实现 | 证据 |
| --- | --- | --- | --- |
| Docker 卷持久化关键数据 | 索引/模型/日志/会话/上传 | **6 个具名卷** + **2 处绑定挂载**（详见 `设计/数据持久化设计.md`） | `测试/测试数据/卷内容列表.txt` |

## 3. 隐含需求（原文没写但部署必须做）

| # | 隐含需求 | 为什么必须做 | 落地 |
| --- | --- | --- | --- |
| R1 | **非 root 运行** | root 容器逃逸风险高；reviewer 会查 | Dockerfile `useradd -u 10001 rag` + `USER rag` |
| R2 | **镜像别太大** | 服务器拉镜像时间 = 停机时间 | 多阶段构建 + 不装 torch/transformers（走宿主 Ollama），真实数字见 `优化/部署优化说明.md` |
| R3 | **冷启动可控** | 基座实测加载 27.3 秒，容器会被误判不健康 | `HEALTHCHECK --start-period=90s~150s` + `DEPLOY_WARMUP` 开关 |
| R4 | **中文字体/时区** | 中文日志与年报文本不能乱码；时间戳要对得上 | `fonts-wqy-zenhei` + `TZ=Asia/Shanghai` + `LANG/LC_ALL=C.UTF-8` |
| R5 | **日志不吞** | 管道缓冲会让 `docker logs` 看不到输出 | `PYTHONUNBUFFERED=1` + `PYTHONIOENCODING=utf-8` |
| R6 | **配置不硬编码** | 换端口/换 Ollama 地址不该改代码 | `RAG_*`（业务）+ `DEPLOY_*`（部署）双前缀环境变量，见 `部署/配置/.env.example` |
| R7 | **优雅降级** | Redis 挂、索引缺、Ollama 掉线都不能裸崩 | `session_store` 熔断降级；`/health` 如实报告；异常兜底 handler |
| R8 | **可回滚** | 上线出问题要能快速回退 | `部署/脚本/down.ps1` 默认**保留卷**；回滚步骤见 `部署/部署文档.md` §7 |

## 4. 边界与非目标（明确不做，避免过度设计）

| 项 | 说明 |
| --- | --- |
| K8s/Helm 编排 | 工单只要求 Docker；compose 足够，K8s 留给后续工单 |
| CI/CD 流水线 | 不在验收范围；脚本已可被流水线直接调用（退出码规范） |
| 容器内跑大模型 | 明确**不装** torch/transformers/open_clip；嵌入与生成走宿主机 Ollama |
| 多副本水平扩展 | 会话共享已铺好路（Redis + 卷），但副本调度不在本工单 |
| 镜像安全扫描 | 说明性提及（`docker scout` 插件在本机存在），未作为交付项 |

## 5. 关键风险与对策（开工前就识别到的）

| 风险 | 实测算不算发生 | 对策 |
| --- | --- | --- |
| Docker 命名管道权限 | **发生了** | 提权一次即被禁用 → 如实记录 + 等价本机验证（见 `部署/过程问题记录.md` 问题1） |
| 索引卷只读导致 sqlite 写失败 | **发生了**（设计期识别） | 运行期数据独立到 `DEPLOY_RUNTIME_DIR` 可写卷 |
| compose 相对路径基准搞错 | **发生了** | 用 `docker compose config --format json` 反查解析结果后修正（问题6） |
| 中文路径 + faiss 序列化 | 基座已解决 | 继承工单7 结论，本工单索引复用不重建（问题2） |
| 镜像拉取超时 | 预防 | 全程走清华镜像源（问题3） |
| 容器内 127.0.0.1 ≠ 宿主机 | 预防 | 统一 `host.docker.internal` + `extra_hosts`（问题4） |
| Windows 卷权限 | 预防 | 固定 uid/gid 10001 + entrypoint 写探针（问题5） |
