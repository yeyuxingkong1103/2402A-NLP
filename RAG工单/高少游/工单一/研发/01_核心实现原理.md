## 1. pdf_parser.py — 文档解析

**目标**：把 PDF 变成"一页一页、带页码、含表格"的结构化文档。

实现要点：
- 用 `PyMuPDF (fitz)` 逐页 `get_text()` 抽正文；
- 用 `page.find_tables()` 抽表格，`_render_table()` 转成 **Markdown 风格表格文本**（`| 列 | 列 |`），保证财务数字不丢；
- 每页 try/except 兜底，**单页失败不影响整体**；
- 返回 `PageDoc(page_no, text, tables)`，`content` 属性拼接正文+表格。

关键代码：
```python
class PageDoc:
    def __init__(self, page_no, text, tables):
        self.page_no, self.text, self.tables = page_no, text, tables
    @property
    def content(self) -> str:
        return self.text + ("\n\n" + "\n".join(...) if self.tables else "")
```

**为什么重要**：招股说明书核心数据都在表格里，只抽文字会丢关键数字。

## 2. knowledge_base.py — 切片 + 向量化 + 入库

**目标**：把长文本切成可检索的小块，向量化后存 FAISS。

实现要点：
- `RecursiveCharacterTextSplitter`：chunk=500、overlap=80、中英文分隔符；
- 每块 `metadata` 记录 `page`（页码）与 `chunk`（序号），检索后能溯源页码；
- **`_BatchedEmbeddings`**（核心）：继承 `OllamaEmbeddings`，把嵌入拆成**每批 50 条**。原因是本地 `bge-m3` 一次性塞超长请求会触发 Ollama tokenizer 服务连接被拒（`127.0.0.1:1510`）。
- `build_kb()`：切片→分批嵌入→`FAISS.from_documents`；
- `save_local/load_kb`：FAISS 索引落盘 `vector_db/`；
- `kb_stats()`：返回切片总数。

关键代码：
```python
class _BatchedEmbeddings(OllamaEmbeddings):
    def embed_documents(self, texts):
        out = []
        for i in range(0, len(texts), 50):      # 分批，每批50
            out.extend(super().embed_documents(texts[i:i+50]))
        return out
```

**实测**：2670 个切片全部嵌入成功，但落盘 `save_local` 在 TRAE 沙箱被拦截（`Permission denied`），改用内存模式。

## 3. query_understanding.py — 查询理解

**目标**：检索前先让 LLM"读懂"问题，提升召回。

实现要点：
- 结构化提示词，让 `deepseek-r1` 输出 JSON，包含 `intent / entities / disambiguated_query / sub_questions`；
- `_parse_json()` **健壮解析**：剥掉 ```json``` 包裹、截取第一个 `{...}`——因为推理模型常输出多余文字；
- 解析失败整体降级为"直接用原问题"，**不影响主流程**；
- `retrieval_queries`：把"消歧主问题 + 子问题"整理成候选检索查询，优先主问题保主线语义。

关键代码：
```python
@property
def retrieval_queries(self):
    primary = self.disambiguated_query or self.question
    subs = [s for s in self.sub_questions if s and s != primary]
    return [primary, *subs]
```

## 4. retriever.py — 混合检索（核心）

**目标**：兼顾"语义相似"与"精确匹配"。

实现要点：
- **向量检索**：`store.similarity_search`（FAISS，bge-m3 语义），对同义改写友好；
- **词法检索**：`jieba` 分词 + `BM25Okapi`，对数字/专有名词精确命中友好；
- **RRF 融合**（倒数排名融合）：`score = Σ 1/(k + rank)`，按排名加和再排序；
- `format_contexts()`：把片段拼成"第x页：..."上下文供生成。

关键代码：
```python
def _rrf(self, ranked):
    scores = {}
    for lst, weight in ranked:
        for rank, doc in enumerate(lst):
            key = doc.metadata["page"]
            scores.setdefault(key, 0.0)
            scores[key] += weight / (RANK_FUSION_K + rank + 1)
    return sorted(scores.items(), key=lambda x: -x[1])
```

## 5. qa_engine.py — 问答引擎

**目标**：串起全链路，产出受控的答案。

实现要点：
- `answer_rag()`：query_understanding → retriever → 组装上下文 → LLM 生成；
- `answer_llm_only()`：不注入文档上下文，纯模型记忆（作对照基线）；
- **防幻觉提示词**三铁律：仅依据文档、关键数值原样输出、无法回答时明示；
- `_retrieve_unique()`：多路查询同时召回、按内容去重；
- `_invoke()`：统一调用 LLM，失败返回可读错误不崩溃；
- 两链路都记录 `elapsed`，服务"≤3s"验收。

## 7. 关键经验（研发心得）

1. **本地模型带来工程约束**：推理模型(deepseek-r1)输出非严格 JSON → 解析须健壮；长文档嵌入有上限 → 须分批。
2. **混合检索显著优于单一检索**：招股说明书场景数字多，BM25 补足了纯向量的精确匹配短板。
3. **防幻觉靠"提示词铁律 + 页码溯源"双保险**。
4. **评估要"两链路对照"**：RAG vs 纯 LLM，才能证明"检索增强"的价值。
