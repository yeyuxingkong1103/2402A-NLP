# Feature Specification: MinerU PDF 解析（S2 解析步骤）

**Feature Branch**: `001-mineru-pdf-parse`

**Created**: 2026-09-22

**Status**: Draft

**Input**: User description: "使用 MinerU 解析 PDF，生成 backend 下的单文件脚本；依赖写成清单文件由人工安装；后端可切换（c）"

## 背景与定位

本特性实现 `docs/04_数据管线设计.md` §1 中的 **S2 解析**步骤：把 `data/source_data/` 中的权威 PDF 变成带页码的结构化内容产物，供后续 S3 清洗、S4 分块消费。

它是**离线链路**（不在问答请求路径上），因此允许慢、允许人工介入、允许重跑——但**不允许出错而不被发现**（`docs/04 §0`）。

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 解析一份 PDF 并落盘带页码的结构化产物 (Priority: P1)

运维人员把一份权威 PDF 放入 `data/source_data/`，运行一次命令，得到一份**每个内容块都带页级索引**的结构化产物，以及该文档的 `doc_id`。

**Why this priority**: 这是整个知识库的唯一入口。没有这一步，后续清洗/分块/向量化/入库全部无输入。页码是引用功能的物理前提——`docs/04 §5` 论证过：一旦产物丢失页码，后续任何环节都无法补救。

**Independent Test**: 对 `data/source_data/国家基层高血压防治管理指南2025版.pdf`（15 页、无内嵌位图的原生数字版）跑一次解析，检查产物中存在 `page_idx` 字段，且其值域覆盖 0–14。

**Acceptance Scenarios**:

1. **Given** `data/source_data/` 中存在一份可读 PDF，**When** 运维执行解析命令，**Then** 在该文档对应的产物目录下生成结构化内容文件，且命令以退出码 0 结束
2. **Given** 解析已完成，**When** 检查产物中的任一内容块，**Then** 该块携带 `page_idx` 字段，可换算出 1-based 物理页码
3. **Given** 解析已完成，**When** 统计产物中的内容块类型分布，**Then** 输出一份人类可读的类型计数报告

---

### User Story 2 - 新增 PDF 后重复运行，已有产物不被重算 (Priority: P2)

运维后续继续往 `data/source_data/` 投放新 PDF，再次运行解析命令时，**内容未变的文档被跳过**，只有新文档（或内容已变的文档）触发解析。

**Why this priority**: 用户明确说明"PDF 后续还会继续上传"。解析是管线中最贵的一步（`docs/04 §1` 原则 P1），重复解析同一份文件是纯粹的成本浪费。

**Independent Test**: 连续运行两次解析且中途不修改任何 PDF，第二次运行不产生新的解析耗时，且产物内容逐字节不变。

**Acceptance Scenarios**:

1. **Given** 某文档已成功解析且源文件未变，**When** 再次运行解析命令，**Then** 该文档被跳过并在输出中明确说明跳过原因
2. **Given** 源 PDF 内容发生变化，**When** 再次运行解析命令，**Then** 该文档被重新解析，且新产物的标识与旧产物不同
3. **Given** 命令行显式要求强制重解析，**When** 运行解析命令，**Then** 即使产物已存在也重新解析

---

### User Story 3 - 在两种解析后端之间切换，并核对输出契约 (Priority: P3)

运维可在"小模型流水线"与"视觉大模型"两种解析后端之间切换，并在解析后得到一份**实际输出类型分布**，用于回填 `docs/04 §5` 的类型对照表。

**Why this priority**: `docs/04 §5` 明确指出 MinerU 的输出契约在版本间发生过破坏性变更，且 §15 把"实测类型取值集合"列为 M3 第一项待验证任务。当前本机只有视觉大模型权重，但 `docs/04 §5/§12` 锁的是流水线后端——两套产物契约不同，必须实测后才能定论。

**Independent Test**: 分别用两种后端解析同一份 PDF，各自得到一份类型分布报告；报告中的类型若未被 `docs/04 §5` 的表格覆盖，命令以非 0 退出码结束并提示人工决策。

**Acceptance Scenarios**:

1. **Given** 运维未指定后端，**When** 运行解析命令，**Then** 使用视觉大模型后端（本机唯一具备权重的后端）
2. **Given** 运维指定了流水线后端但本机缺少对应权重，**When** 运行解析命令，**Then** 命令以非 0 退出码结束并明确指出缺失的权重路径，**不得**回退到另一后端或联网下载
3. **Given** 解析产物的类型分布中出现 `docs/04 §5` 未列出的类型，**When** 运行解析命令，**Then** 该类型被单独标出并要求人工决策，**不得**静默忽略

---

### Edge Cases

- **PDF 路径不存在或不可读** → 报错并以非 0 退出，不创建任何产物目录
- **PDF 加密/受密码保护** → 报错并以非 0 退出，不产生半份产物
- **PDF 损坏或非 PDF 格式** → 报错并以非 0 退出
- **PDF 为零页或解析结果为空** → 报错并以非 0 退出；**不得**写出空的产物文件冒充成功
- **目标产物目录已存在但内容不完整**（上次解析中途失败） → 不得视为"已完成"而跳过
- **`data/source_data/` 为空** → 明确提示无待处理文档，非 0 退出（区别于"静默成功"）
- **模型权重目录不存在** → 报错并以非 0 退出，**不得**回退到联网下载（`docs/04 §11`）
- **磁盘空间不足导致写出中断** → 报错并以非 0 退出，不留下可被误认为完整的产物
- **同一份 PDF 传入两次**（路径或目录扫描重叠） → 按内容标识去重，只解析一次

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 脚本 MUST 接受两种输入形式：单个 PDF 文件路径、或一个目录（批量处理其中的 PDF）
- **FR-002**: 脚本 MUST 在未显式指定输入时，默认处理一个**在脚本中写明的固定存储目录**（对应用户要求的"后续继续上传"）
- **FR-003**: 脚本 MUST 以源 PDF 的**内容哈希**（而非文件名或修改时间）作为文档标识，标识取哈希前 12 位
- **FR-004**: 脚本 MUST 把每份文档的解析产物写入以其文档标识命名的独立子目录，多份文档互不覆盖
- **FR-005**: 解析产物 MUST 保留**块级页码信息**；页码缺失时 MUST 报错退出，MUST NOT 以 0/null 填充后继续（`docs/04 §11`）
- **FR-006**: 脚本 MUST 支持在两种解析后端间切换，并 MUST 在未指定时默认使用**本机具备权重的那一种**
- **FR-007**: 脚本 MUST 在指定后端所需的权重不存在时报错退出，MUST NOT 静默回退到其他后端或联网下载
- **FR-008**: 脚本 MUST 在解析完成后输出**实际观测到的内容块类型分布**，并把 `docs/04 §5` 未覆盖的类型单独标出
- **FR-009**: 脚本 MUST 在已存在可用产物且源文件内容未变时跳过解析，除非显式要求强制重解析
- **FR-010**: 脚本 MUST NOT 用异常捕获吞掉失败条件；所有权重缺失、格式错误、页码缺失 MUST 以非 0 退出码显式暴露（constitution 代码规范）
- **FR-011**: 脚本 MUST 以退出码区分成功与各类失败，供上层人工/脚本判断
- **FR-012**: 脚本 MUST 只依赖**独立声明的依赖清单文件**，且该清单 MUST 位于仓库根目录（constitution 原则 I）
- **FR-013**: 解析产物 MUST 为**人类可读的辅助形式**（便于人工抽查）与**机器可消费的结构化形式**各留一份，且明确标注哪一份进入下游管线
- **FR-014**: 脚本 MUST 在启动时输出所用解析工具的实际版本号，供版本锁定与产物溯源
- **FR-015**: 脚本 MUST NOT 在源码中硬编码密钥或凭据（constitution 原则 III）

### Key Entities

- **源文档 (Source Document)**: `data/source_data/` 中的一份 PDF。关键属性：文件路径、内容哈希、页数。它是唯一的知识依据，不可重建。
- **文档标识 (doc_id)**: 由内容哈希前 12 位派生。**内容一变，标识即变**——这是"同名不同内容不得混入"的机制（`docs/04 §10.1`）。
- **解析产物 (Parsed Artifact)**: 一份文档解析后的全部输出，按文档标识隔离存放。核心是**扁平、按阅读顺序排列、每项带页级索引**的内容块序列。
- **内容块 (Content Block)**: 产物中的最小单元。关键属性：类型（正文/标题/表格/公式/图片/噪声）、文本或结构化表示、页级索引、版面框。**标题通过"层级字段是否存在"识别，而非独立的类型**（`docs/04 §5`）。
- **类型分布报告 (Type Distribution Report)**: 一次解析后对内容块类型的计数统计，用于核对解析工具的输出契约是否与设计假设一致。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对语料中的 15 页原生数字版 PDF，一次解析在 CPU 环境下 10 分钟内完成，在 GPU 环境下 1 分钟内完成
- **SC-002**: 解析产物中 **100%** 的内容块携带有效页级索引，且页码值域与源 PDF 实际页数一致
- **SC-003**: 重复解析同一份未变更的 PDF，第二次运行的解析耗时相对第一次下降 **90% 以上**（命中跳过）
- **SC-004**: 每次解析后**必然**输出一份类型分布报告，人工可在 1 分钟内据此判断输出契约是否与 `docs/04 §5` 一致
- **SC-005**: 全部 9 类边界情况（见 Edge Cases）均以非 0 退出码结束，且**没有任何一种**产生可被误认为成功的不完整产物
- **SC-006**: 从零开始的使用者，仅依据脚本文件头部的说明与依赖清单，可独立完成"安装依赖 → 解析 → 检查产物"全流程，无需阅读其他文档

## Assumptions

- **对 `docs/04 §4` 的有意偏离**：用户明确要求"PDF 后续还会继续上传，直接在脚本里写明存储文件在哪"，因此本特性**不实现 manifest 准入闸门**（`docs/04 §4` 与 `§11` 要求的 sha256 校验、`authority_level` 限制、`confirmed_by` 非空校验均不在本次范围内）。文档标识改为直接由文件内容计算。**这是一处已知偏离，须由人工记入 `docs/04` 并评估其对人工资格审查的影响。**
- 语料以**原生数字版 PDF** 为主（`docs/04 §3` 实测：无内嵌位图、文本可无损提取），扫描件路径本特性不专门优化，但代码不做假设性排除。
- 运行环境为 `D:/zg6_Project/9/med_rag/rag/python.exe`（Python 3.12.14），不新建虚拟环境、不使用系统 Python（constitution 原则 I）。
- 本机已存在一份视觉大模型权重（约 2.2 GB），但**尚未安装**解析工具的程序包本身；程序包由人工按依赖清单手动安装。
- 解析工具的程序包采用 AGPL-3.0 许可（`docs/03 §1` 已记录该风险）；模型权重采用 Apache-2.0 许可。
- 依赖清单中的程序包版本号在安装实测前保持待定，安装后须回填并锁定（`docs/04 §5` 要求锁定版本）。
- 本特性**只做 S2 解析**，不做清洗、分块、向量化、入库（`docs/05 §5` 关键设计 2：每个子命令只做一步）。
- 产物可随时从源 PDF 重建，不属于需独立备份的资产（`docs/04 §2`）。
