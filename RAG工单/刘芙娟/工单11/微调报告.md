## 五、模型体积对比（你实测的真实数据）

| 项目                   | 实测大小 | 说明                                                         |
| ---------------------- | -------- | ------------------------------------------------------------ |
| **微调前（原始基座）** | **1.5G** | `/root/autodl-tmp/models/qwen3-0.6B/`                        |
| **微调后（合并模型）** | **1.2G** | `/root/autodl-tmp/merged_qwen3_06b/`                         |
| **LoRA adapter**       | **59M**  | `/root/autodl-tmp/output/v3-20260923-180419/checkpoint-750/` |

### 🔍 为什么合并后反而更小？

- 原始基座目录里可能有**冗余文件**（比如多个格式的权重、旧版本残留、`.bin` 和 `.safetensors` 重复等），所以显示 1.5G。
- 合并模型目录是 `swift export` 重新生成的，**只保留必要文件**：`model.safetensors`（1.19 GB）+ 配置 + tokenizer，所以显示 1.2G。
- 两者**权重实际参数量一致**（都是 5.96 亿参数，bf16 精度），只是文件组织方式不同。

> 用 `du -sh` 是含文件系统块大小的粗略统计，用 `ls -la` 看单个文件才准确：合并模型的 `model.safetensors` 是 **1,192,135,096 字节 ≈ 1.19 GB**。

## 七、部署与推理

### 方式一：终端交互（你现在用的）

```bash
cd /root/autodl-tmp
conda activate finetune
python chat.py
```

- **模型路径**：`/root/autodl-tmp/merged_qwen3_06b`
- **显存占用**：约 2–3 GiB
- **无端口**，纯终端对话
- 支持多轮上下文，输出带 `<think>` 标签

### 方式二：vLLM 部署 API（默认端口 8000）

```bash
pip install vllm -q

vllm serve /root/autodl-tmp/merged_qwen3_06b \
    --served-model-name qwen3-06b-merged \
    --port 8000
```

- **默认端口：8000**
- 支持 OpenAI 兼容接口
- 适合被其他程序调用
