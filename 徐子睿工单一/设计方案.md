## 1. 需求解读

### 1.1 任务描述（工单原文拆解）

> 作为 **用户**，我想要 **开发一个基于大语言模型（LLM）的问答系统，能够针对《招股说明书 1.pdf》中的内容进行高效的问答检索**。

三大能力块：

1. **Query 理解** —— 意图识别 / 消歧 / 分解与抽象
2. **检索与生成** —— 文档解析 / 向量检索 / 答案生成
3. **用户体验** —— 交互界面（问题输入、答案展示、反馈机制；工单产出物还要求**支持文字和语音输入**）

### 1.2 验收标准（逐条对应到设计）

| 验收项 | 设计要求 | 本方案落点 |
|---|---|---|
| PDF 解析：准确解析文字、**表格数据** | 文本层直抽 + 表格结构化 | §4.1（PyMuPDF 正文 + pdfplumber 表格，双通道；本项目 PDF 为文字版，无需 OCR） |
| 问答准确性：基于 pdf 内容作答 + **与纯 LLM 对比** | 必须有 baseline | §6.4（同一 10 题，两路作答 + 人工/自动评分对照表） |
| 交互友好性 | 简洁界面 | §4.7 |
| 多语言支持（中/英） | 中英问答 | §4.5（BGE-M3 多语向量 + 问题语言识别/翻译） |
| 响应时间 ≤ 3 s | 流式 + 缓存 + 轻量模型 | §4.8 |
| 资源消耗、高并发稳定 | 单机可控资源 | §4.8（并发限流 + 索引常驻内存） |
| 容错 | 异常兜底 | §4.8（三类失败路径） |
| 代码注释含工单编号 | 统一文件头注释 | §10（模板） |

### 1.3 语料特征与难点（决定分块/检索策略）

- **长文档**：548 页，单篇 51.9 万字符 → 必须分块，且块要带**页码 + 章节**元数据（答案溯源靠它）。
- **章节结构清晰**：有完整“第X节”层级 + 目录页 → 天然适合**标题感知分块**。
- **大量表格/数字**：财务数据以表格呈现（如军用收入 6,464.51 万元、募集资金 15,000.00 万元）。文本层抽取会把表格拍平成“值+单位”序列，**数字精度是评估重点**。
- **同句多页重复**：如“重要供应商”“国家科技进步一等奖”在第 26/27/94/95/96/154/155/160/181/182/193/241 页反复出现 → 需要**去重 + 稳定取源**，否则引用页码会飘。
- **“上游 vs 下游”“金额 vs 占比”** 成对出现在同一段 → 需要**消歧**（id34/id793、id260/id33 就是专门考这个）。
- **涉密脱敏**：文中多处“某视频技术规范”“某大型研究所”“单位 A/单位 D”→ LLM 裸答极易编造具体名称，RAG 必须**忠于原文**。

### 2.2 数据流（一句话）

> 上传 PDF → 后台构建（解析→清洗→分块→向量化→入库）→ 用户提问 → Query理解(改写/消歧) → 混合检索(向量+BM25→RRF→重排) → 组装带引用上下文 → LLM 生成 → 前端流式展示，附页码溯源与反馈。

### 2.3 两条作答链路（对照实验用，工单强制要求）

- **链路 A（RAG）**：检索原文片段 → 注入 Prompt → LLM 生成（答案须可溯源）。
- **链路 B（纯 LLM）**：不检索，直接把问题给 LLM（同模型、同温度）。
- 两路结果并排展示 + 打分对照（§6.4）。

## 3. 技术选型

| 层 | 选型 | 理由 / 可行性 |
|---|---|---|
| PDF 解析 | **PyMuPDF**（正文）+ **pdfplumber**（表格） | 本机已验证 PyMuPDF 1.28.2 可用，548 页秒级抽取 51.9 万字符；文字版 PDF 无需 OCR |
| 分块 | 自研**标题感知滑窗**：chunk≈600 字符、overlap≈120 | 招股书章节规整，按“第X节/一、二、/（一）（二）”切分，块带页码+章节 |
| 嵌入模型 | **BGE-M3**（本机已有 `D:\桌面\bge-m3`）或 m3e-base | 中文长文本检索强；BGE-M3 多语→天然支持英文问句 |
| 向量库 | **ChromaDB**（本机已装 0.5.23）/ Qdrant（embedded） | 单文档万级块，本地单进程足够；Chroma 零部署 |
| 稀疏检索 | **jieba 分词 + BM25**（自实现，避开 rank_bm25 未装） | 财务数字/专有名词精确匹配，补向量漏召回 |
| 融合 | **加权 RRF**（λ≈2.5，网格搜索） | 已在同类项目验证可将 recall@5 提到 1.0 |
| 重排（可选） | LLM 打分重排（0–5），失败回退 RRF | 提升排序稳定性，单点失败不中断 |
| 生成 LLM | **Ollama qwen2:7b**（本机）/ 实例侧 vLLM 同款 | 工单“仅用 LLM 对比”需同一模型；本地 Ollama OpenAI 兼容端点 `http://localhost:11434/v1` |
| 后端 | **FastAPI + uvicorn**（本机已装） | SSE 流式天然支持 |
| 前端 | 单文件 **HTML+原生JS**（`static/index.html`） | 零构建、易交付、易录屏 |
| 语音输入 | 浏览器 **Web Speech API**（降级为文字输入） | 无需额外服务；不支持时自动回退 |
| 评估 | 自建脚本（检索命中/EM/数字一致）+ RAGAS（faithfulness / answer_relevancy / context_precision） | RAGAS 未装则先本地实现核心三项 |

> 依赖红线：**transformers 必须 4.44.x/4.46.x 系**（若走 HF 且 torch<2.4）；本方案主链路用本地 BGE-M3 + Ollama，避开该坑。

## 4. 模块详细设计

### 4.1 PDF 解析与清洗（对应验收“准确解析文字、表格”）

- **双通道解析**
  - 正文：PyMuPDF `get_text("text")`，逐页抽取，落 `page_text[p]`。
  - 表格：pdfplumber `extract_tables()`，识别财务表，转 Markdown/键值对，**与所在页绑定**。
- **清洗规则**
  - 去页眉页脚（“武汉兴图新科电子股份有限公司 招股意向书”“1-1-XX”页码行）。
  - 合并被换行切断的词（中文字符间无意义换行、金额“6,464.51 万元”跨行）。
  - 数字规范化：全角→半角、千分位保留、单位统一（万元）。
  - 标注章节：正则识别 `第[一二三四五六七八九十]+节`、`[一二三四五六七八九十]+、`、`（[一二三四五六七八九十]+）`，作为 chunk 的 `section` 元数据。
- **容错**：解析失败 → 回退逐页循环 + 记录失败页码，不阻断构建。

### 4.2 分块策略

| 参数 | 取值 | 说明 |
|---|---|---|
| 切分锚点 | 章节标题优先，段落次级 | 保证一个 chunk 语义完整 |
| chunk 长度 | ~600 字符 | 兼顾上下文与检索精度 |
| overlap | ~120 字符 | 防跨块答案被切断（如“6,464.51…”与“…82.10%”同段） |
| 元数据 | `page`、`section`、`type`(正文/表格)、`chunk_id` | **页码是引用溯源的根** |
| 表格块 | 保持整表为一个 chunk（超长则按行组切） | 数字题命中率关键 |

> 关键：**数值密集段落不做激进切分**，否则 id260/id33/id207 这类题会被拆散。

### 4.3 向量化与知识库

- BGE-M3 编码 chunk → 归一化 → 写入 Chroma collection（cosine）。
- 同步构建 **BM25 倒排索引**（jieba 分词，自定义词典加入“兴图新科”“程家明”“C4ISR”“JAVS”等专名）。
- 知识库管理接口：文档列表、chunk 浏览、按文档删除、重建、统计（块数/页数/向量维度）。

### 4.4 检索层

1. **向量召回** top-20（BGE-M3 cosine）。
2. **BM25 召回** top-20（jieba）。
3. **加权 RRF 融合**：`score = Σ w_i / (k + rank_i)`，k=60，λ 由小验证集网格搜索确定（起点 2.5）。
4. **去重**：相同文本（同句多页）只保留**页码最小**的一条 + 记录全部来源页码。
5. **（可选）LLM 重排**：对 RRF top-8 按 0–5 打分重排；异常→回退 RRF 原序。
6. 取 top-k（k=5）作为上下文。

### 4.5 Query 理解（意图识别 / 消歧 / 分解）

- **意图识别**：规则+LLM 分类 → {事实查询, 数值查询, 列举查询, 对比查询, 闲聊/域外}。域外问题走拒答或直答并声明“非文档内容”。
- **消歧**（本项目高频）：
  - 金额 vs 占比（id260 vs id33）→ 依据问句关键词“收入/金额” vs “比重/占比”绑定抽取口径。
  - 上游 vs 下游（id34 vs id793）→ 保留方位词，不做同义替换。
- **改写/术语扩展**：如“军用领域的收入” → 补“国防客户/军方销售/军品销售收入”；**规则化 REWRITE_RULES，不依赖 LLM**（可离线、可复现）。
- **分解/抽象**：复合问题（“收入是多少、占比多少”）拆成子问题分别检索后合并。
- **多语言**：英文问题 → 语言识别 → 用 BGE-M3 跨语检索（或先译中再检索），答案按提问语言输出。

### 4.6 答案生成

- Prompt 结构（五要素）：**角色 + 任务 + 上下文(带 [页码] 标注) + 输出格式(结论+依据+引用) + 约束(无依据不许编)**。
- 引用格式：`……（依据：第 129 页 / 第六节 业务与技术）`。
- **拒答机制**：检索最高分低于阈值 或 上下文与问题无关 → 固定话术“本问题在招股说明书中未找到依据”，不调用 LLM 编造。
- 忠实性约束：数值必须**逐字照抄**原文，不得四舍五入或改写单位。
- 流式：SSE 逐字返回，边生成边展示。

### 4.7 交互界面

- 左侧对话区（问 + 答 + 引用卡片，可点开看命中原文）。
- 顶部：上传 PDF / 重建知识库 / 知识库状态（块数、页码范围）。
- 语音输入按钮（Web Speech API，中文/英文）。
- “对比模式”开关：同屏展示 **RAG 答案** vs **纯 LLM 答案**。
- 每条答案 👍/👎 反馈，落盘 `feedback.jsonl` 供后续分析。
- （加分）检索链路可视化：Query→召回→RRF→重排→生成，各步耗时与命中明细。

### 4.8 稳定性 / 性能 / 容错

| 目标 | 措施 |
|---|---|
| 端到端 ≤ 3 s | 向量索引与 BM25 常驻内存；LLM 流式（首字 < 1 s，达标按“首字/完整均可 <3 s”口径）；答案缓存（相同问题直接命中） |
| 高并发 | uvicorn workers + 检索无状态；限流队列，超载返回 429 |
| 容错三类 | ①用户输入异常（空/超长/乱码）→ 校验拦截 + 友好提示；②PDF 解析失败 → 回退解析 + 记录；③模型/向量库不可用 → 降级（纯 BM25 检索 或 明确报错） |
| 构建原子性 | 构建步骤状态机，失败不留半成品库 |

## 6. 评估方案

### 6.1 检索指标

- **Hit@k**（top-k 是否含金标准所在页/chunk）、**MRR**、**Recall@5**。
- 判定依据：命中页 ∈ 金标准 `page` 集合（见 `evaluation/eval_questions.json`）。

### 6.2 生成指标（RAG 评估体系）

- **Faithfulness（忠实度）**：答案是否仅依据检索上下文。
- **Answer Relevancy（答案相关性）**：是否直接回答所问。
- **Context Precision / Recall**：检索上下文对答案的贡献。
- **数值一致性（本项目自加）**：金额/百分比是否与原文**逐字一致**（如“6,464.51 万元”“82.10%”）。
- 工具：优先 RAGAS；不可用则本地实现上述四项的规则+LLM 评判版。

> 详细金标准（含 `gold_facts` 与原文依据）见 `evaluation/eval_questions.json`。
> 这 10 题**全部需要文档依据**（纯 LLM 无法可靠作答），正好用于 RAG vs 裸答对比。

### 6.4 RAG vs 纯 LLM 对比实验设计

- 固定 LLM、温度、Prompt 长度上限。
- 两路分别作答 10 题，记录：答案文本、耗时、引用页码、是否正确。
- 评分：① 正确性（人工 3 档：完全正确/部分/错误）；② 忠实度（有无编造）；③ 数值一致性。
- 产出对照表（示例结构）：

| id | RAG 答案 | RAG 正确? | 纯 LLM 答案 | LLM 正确? | 说明 |
|---|---|---|---|---|---|
| 260 | ……（第129页） | ✅ | （易编造/拒答） | ❌ | 数值来自原文 |
| … | | | | | |

**预期结论**：RAG 在事实/数值题上显著优于裸答，且引用可溯源；裸答在涉密脱敏名称处易编造（如编出具体机构名）。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 表格数字被抽取拍平、串行 | 数值题答错 | pdfplumber 表格通道 + 数字规范化 + 数值一致性校验 |
| 同句多页重复 | 引用页码飘 | 文本去重 + 保留最小页码 + 记录全部来源 |
| 3 s 响应（本地 LLM 慢） | 不达标 | 流式首字 + 答案缓存 + 小参数模型 + 检索常驻 |
| LLM 编造涉密名称 | 忠实性差 | 严格 Prompt + 拒答阈值 + 引用强制 |
| 上游/下游、金额/占比混淆 | 消歧错 | 问句口径绑定 + 方位词保留 |
| 中英文混合 | 多语言不达标 | BGE-M3 跨语向量 + 语言识别 |
| 依赖版本坑（transformers/torch） | 环境报错 | 主链路用本地模型+Ollama，避开 HF 版本冲突 |
