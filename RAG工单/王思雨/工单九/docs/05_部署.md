## 2. 环境变量

复制 `.env.example` 为 `.env` 并填写。**工单要求的 5 个键全部包含**：

```ini
DEEPSEEK_API_KEY=
MILVUS_HOST=localhost:19530
REDIS_URL=redis://localhost:6379/0
BGE_M3_PATH=D:/模型/bge-m3
BGE_RERANKER_PATH=D:/模型/bge-reranker-v2-m3
```

**两点必读**：

1. **路径必须写正斜杠**。写成工单原文的 `D:\模型\bge-m3` 时，`\b` 会被 dotenv 解析成退格符，
   加载即报"路径不存在"（既有记忆 [[dotenv-backslash-path-trap]]）。
2. `MILVUS_HOST` 是工单要求的键名；本实现底层沿用 08 工单的 **`MILVUS_URI=http://localhost:19530`**。
   两个键都在 `.env.example` 里给出，**实际生效的是 `MILVUS_URI`**。

**工单九专属优化旋钮**（`after` 链路用；`before` 链路始终走 08 原参数，不受影响）：

| 键 | 默认 | 含义 |
|---|---|---|
| `HOPS` | 2 | 图扩展跳数（08 为 1） |
| `EXPAND_TERMS` | 8 | 注入 BM25 的邻居词条数（08 为 6） |
| `VEC_W` / `BM25_W` | 0.6 / 0.4 | 融合权重（08 为 0.7 / 0.3） |
| `FUSION_K` | 40 | 融合候选数（08 为 30） |
| `RERANK_N` | 6 | 送进大模型的片段数（08 为 8） |
| `USE_COMM` | 1 | 社区摘要 global 通道开关（消融用） |
| `API_PORT` | 8012 | 服务端口（8000/8010/8011 已被其它工单占用） |
| `SAMPLE_Q_PDF` | 空 | 题集 PDF 的替代路径（默认找 `data/sample_questions.pdf`） |

## 3. 启动命令

### 3.1 Milvus（向量库）——**复用本机已运行容器，不要重建**

```bash
# 查看状态（本工单的容器名为 rag-milvus / rag-etcd / rag-minio）
docker ps --format "{{.Names}}\t{{.Status}}" | grep rag-

# 若 Docker Desktop 重启后容器集体 Exited，用 start 复活（数据不丢）——不要用 docker compose up
docker start rag-etcd rag-minio rag-milvus

# 连通性自检
python -c "from pymilvus import MilvusClient; m=MilvusClient(uri='http://localhost:19530'); \
print(m.query('gd8_chunks', filter='', output_fields=['count(*)'], consistency_level='Strong')[0]['count(*)'])"
# 预期：4879（复用 08 工单已建索引；本单不重建、不写其它工单集合）
```

> ⚠ 本机 19530/6379 已被占用，**不要再跑 `docker compose up`**。

### 3.2 Redis（缓存）

```bash
# 本机已有 Redis 在 6379 监听；若没有，在 Windows 下用官方 Windows 版 redis-server 启动
redis-cli -h 127.0.0.1 -p 6379 ping        # 预期：PONG

# 自检（本机 Redis 5.0.14 不支持 RESP3，必须 protocol=2，否则连接直接失败）
python -c "import redis; print(redis.Redis.from_url('redis://localhost:6379/0', protocol=2, decode_responses=True).ping())"
# 预期：True
```

### 3.3 FastAPI 后端（Windows 下不要用 `--reload`，会与 MinerU 子进程抢句柄）

```bash
cd "D:/Users/雨子/Desktop/专高六/liu-专高六/RAG/工单九"
D:/myconda1/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8012

# 预期输出
# INFO:     Uvicorn running on http://127.0.0.1:8012 (Press CTRL+C to quit)
```

**首个请求前务必先打 `/health`**——它在返回状态的同时**预热 bge-m3 与 bge-reranker-v2-m3**（冷加载 15~18 秒）。
不预热的话，首个业务请求的 3 秒预算会被模型加载吃光并触发降级（本机实测：45~95 秒并走降级）。

```bash
curl -s http://127.0.0.1:8012/health
# 预期：{"milvus":"up","redis":"up","chunks":4879,"llm":"configured","models":"warm", ...}
```

## 5. 排障

| 现象 | 原因 | 处置 |
|---|---|---|
| `/health` 显示 `"graph":"missing: ..."` | 未建图 | 跑 `python -m app.graph_rag build`（或忽略，问答仍可用） |
| `/health` 显示 `"milvus":"down: ..."` | 容器 Exited | `docker start rag-etcd rag-minio rag-milvus`（**不要 compose up**） |
| `/health` 显示 `"redis":"down"` | Redis 未启动 | 启动 redis-server，确认 `protocol=2` |
| `redis` 连接直接被拒 | 用了 RESP3 | 必须是 `REDIS_PROTOCOL=2`（本机 Redis 5.0.14） |
| 首次请求极慢（数十秒） | 模型未预热 | 先打一次 `/health` |
| 检索突然变慢十几倍（如 rerank 40 s） | **显存被残留进程占满** | `nvidia-smi` 看 Memory-Usage；`tasklist \| grep python` 找残留 PID，`taskkill //F //PID <pid>`。Git Bash 的 `pkill` **杀不掉** Windows 原生进程 |
| 答案是 `【降级】…` | 检索超 3 秒预算，或大模型异常 | 看 `answer` 里的原因；若因冷却慢，先预热；若是 Key 问题，查 `DEEPSEEK_API_KEY` 与余额（402） |
| 路径报"不存在" | `.env` 里用了反斜杠 | 全部改成正斜杠 |
| 上传返回 400「三级解析器均失败」 | 文件无文本层（扫描件）或损坏 | 换带文本层的 PDF；扫描件需启用 MinerU/OCR |
| 截图/演示时中文乱码 | Git Bash 的 curl 传中文乱码 | 换 UTF-8 客户端（Python `urllib` 或 Postman），别去查服务端 |
