## 一、环境要求

| 项 | 要求 | 实测环境 |
|---|---|---|
| 操作系统 | Windows 10/11 / Linux / macOS | Windows 11 |
| Python | 3.10+ | 3.10.11 |
| Ollama | 本地推理服务（提供嵌入与 LLM） | 已安装，`http://localhost:11434` |
| 内存 | ≥ 8 GB（嵌入模型 + 切片） | 满足 |
| 磁盘 | ≥ 3 GB（模型 + 索引） | 满足 |

### 1.1 需要拉取的 Ollama 模型

| 用途 | 模型 | 维度/规模 | 命令 |
|---|---|---|---|
| 嵌入（默认） | `bge-m3:567m` | 1024 | `ollama pull bge-m3:567m` |
| 嵌入（备选） | `bge-large:latest` | 1024 | `ollama pull bge-large:latest` |
| 嵌入（备选） | `nomic-embed-text:latest` | 768 | `ollama pull nomic-embed-text:latest` |
| LLM（重排/翻译，可选） | `deepseek-r1:1.5b` | 1.8B | `ollama pull deepseek-r1:1.5b` |

> 说明：本系统**不依赖 faiss / torch**，向量检索走 Ollama HTTP + numpy，依赖轻、易复现。
> `m3e-base` 已在 `config.EMBEDDING_MODELS` 登记为可选模型，安装后填入 Ollama 模型名即可切换。

## 二、部署步骤

### 2.1 安装依赖

```powershell
cd 研发
pip install -r requirements.txt
```

### 2.2 启动 Ollama 服务

```powershell
ollama serve          # 默认监听 127.0.0.1:11434
# 另开窗口确认模型就绪：
ollama list
```

### 2.3 配置 `.env`

```ini
# 工单编号: 人工智能 NLP-RAG-混合检索任务
OLLAMA_BASE_URL=http://localhost:11434
EMBEDDING_MODEL=bge-m3:567m
LLM_MODEL=deepseek-r1:1.5b

# 检索与多轮参数（可按需覆盖 src/config.py 默认值）
TOP_K=8              # 界面展示/返回条数（召回率按此 K 计）
RECALL_K=60          # 单通道召回候选数
ANSWER_TOP_K=40      # 参与答案合成的候选池深度
USE_LLM_REWRITE=0    # 是否启用 LLM 改写（默认关闭，确定性改写更快）
DOC_FILTER_ENABLE=1  # 文档级路由（公司名消歧）
```

### 2.4 构建知识库

```powershell
# 复用已有切片，重建多模型向量 + 倒排索引
python build_kb.py --models bge-m3,bge-large,nomic-embed

# 或：强制重新解析 PDF（含图形语义）——本次实测耗时 570.6s
python build_kb.py --rebuild --models bge-m3,bge-large,nomic-embed
```

构建产物落盘 `vector_db/`：

| 文件 | 说明 |
|---|---|
| `chunks.jsonl` | 2357 个知识块（文本 1737 / 表格 615 / 图形 5） |
| `emb_bge-m3.npy` / `emb_bge-large.npy` / `emb_nomic-embed.npy` | 各模型向量矩阵（9.21 / 9.21 / 6.91 MB） |
| `inverted_index.pkl` | 多字段倒排索引（词表 20629，4.35MB） |
| `meta.json` | 索引元信息 |

### 2.5 启动服务 / 演示

```powershell
# ① 命令行多轮演示（5 轮验收对话）
python run_demo.py

# ② 检索策略评测（准确率 / 召回率 / 响应时间）
python evaluate_retrieval.py                              # 三策略对比
python evaluate_retrieval.py --full                       # 全量消融
python evaluate_retrieval.py --strategies hybrid --rerankers linear --fusions rrf

# ③ 检索策略对比演示（向量 / 全文 / 混合）
python tools/run_strategy_demo.py

# ④ 功能测试
python tools/run_functional_tests.py

# ⑤ 响应时间基准（冷启动 / 热缓存）
python tools/bench_latency.py --strategies vector,fulltext,hybrid

# ⑥ 生成流程图 / 架构图（输出到 设计/assets/）
python tools/gen_flowcharts.py

# ⑦ 生成界面截图 + 演示视频（输出到交付物「实训一工单/工单六/演示/」）
python tools/render_ui_shots.py
python tools/make_demo_video.py --shots <交付>/实训一工单/工单六/演示/shots      --out <交付>/实训一工单/工单六/演示/演示视频_功能演示.mp4
python tools/make_demo_video.py --shots <交付>/实训一工单/工单六/演示/shots_tech --out <交付>/实训一工单/工单六/演示/演示视频_技术讲解.mp4

# ⑧ 启动 Streamlit 界面（浏览器访问 http://localhost:8501）
streamlit run app.py
```

> 路径说明：若 `工单代码\工单六\研发` 与 `实训一工单\工单六\演示` 同处 `交付\` 下，
> 可用相对路径 `../../../实训一工单/工单六/演示/shots`；否则直接用绝对路径。

## 四、常见问题（FAQ）

| 现象 | 原因 | 处理 |
|---|---|---|
| `Connection refused` 连接 Ollama 失败 | 服务未启动 | `ollama serve` 后重试 |
| `向量库缺少模型「xxx」的向量` | 该 slug 未向量化 | `python build_kb.py --models xxx` |
| 首问耗时偏大 | 冷启动（加载分词/索引/编码器） | `QAEngine.warmup()` 已预热；首次运行可先跑 `run_demo.py` |
| 界面提示「知识库未构建」 | `vector_db/meta.json` 缺失 | 执行 `build_kb.py` |
| **LLM 重排很慢（实测均值 4.23s，离群 67s，超 3s）** | 本地小模型逐题推理，长表格候选上易退化 | **默认使用 `linear`**；必须用 LLM 时限制候选数 + 推理超时（2s）+ 回退 linear |
| 切换重排为 `none` 后回答变「未检索到相关内容」 | 融合分（RRF）量纲小，低于相关性门限 | 已修复：`none`/`tfidf` 分数单调校准到 [0.5,1.0] |
