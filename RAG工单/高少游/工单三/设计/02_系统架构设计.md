## 1. 总体架构

系统为**离线建库 + 在线问答**的两段式 RAG 架构，全部组件本地化运行（Ollama + FAISS）。

```

│                                                                                          │

│                  ├─► pdf_parser（版式清洗：页眉页脚剔除 + 断句合并 + 标题识别）              │
│  招股说明书2.pdf ┘        │                                                              │
│                          ├─► table_parser（★本工单核心：版面级表格检测 → 结构还原）          │

│                          │        · 合并单元格还原（左邻优先/上邻兜底）                     │

│                          │        · 表题识别（bbox 上方文本块）                            │
│                          │        · 双表示：Markdown 表 + 键值对行                        │
```

## 3. 双链路设计（优化前 / 优化后）

为量化本工单优化贡献，系统同时保留**基线链路**，二者共享同一份 PDF 数据，仅"表格处理方式"不同：

| 环节 | 优化前（复刻 01/02 工单） | 优化后（本工单） |
|---|---|---|
| 表格处理 | 拍平为普通文本行 | 结构化：Markdown 块 + 键值对块 |
| 分块 | 固定 500/80 递归切片 | 结构感知 700/120 + 父子块 |
| 检索 | 向量 + BM25 + RRF（无重排） | 多路召回 + RRF + **表格感知重排** |
| 文档消歧 | 无 | **公司名 → 文档级路由** |
| 答案 | 本地 LLM 生成 | **抽取式（表格专用路径）** |
| 可溯源 | 弱 | 强（文档 + 页码 + 片段） |

引擎共提供 **4 条链路**用于对比与消融：

| 链路 | 检索 | 答案合成 | 用途 |
|---|---|---|---|
| `baseline` | 基线 | LLM 生成 | 优化前基准 |
| `baseline_extractive` | 基线 | 抽取式 | 消融：隔离"答案合成"贡献 |
| `optimized` | 优化 | 抽取式 | **最终方案** |
| `optimized_llm` | 优化 | LLM 生成 | 消融：隔离"检索"贡献 |

## 4. 关键设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| 答案合成 | **抽取式**（非 LLM 生成） | 需求要求 ≤3s 且 ≥90%；本地 deepseek-r1:1.5b 为推理型，慢且易幻觉。抽取式零幻觉、可溯源、毫秒级 |
| 向量模型 | 本地 `bge-m3`（Ollama） | 中英文混合、无需外网、隐私安全 |
| 向量库 | FAISS（本地单文件） | 轻量、无服务依赖、加载快 |
| 重排 | 加权线性融合（非 Cross-Encoder） | 毫秒级、可解释、可调权重；满足 3s 约束 |
| 多文档消歧 | 显式公司名路由（非仅靠语义） | 同构表格语义极近，语义无法区分，必须用实体硬路由 |
| 中文路径 | 临时 ASCII 目录桥接 | Windows 版 FAISS 窄字符 API 不支持中文路径 |
| Query 理解 | 确定性规则（非 LLM） | 毫秒级、稳定可复现 |
