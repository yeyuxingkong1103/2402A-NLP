# RAG 角色扮演系统 · 部署文档

目标环境：**WSL Ubuntu-24.04**（本机已验证 Docker/Milvus 方案；腾讯云/阿里云 Ubuntu 同理）。

## 部署架构

```
Windows 11（开发机）                 WSL Ubuntu-24.04（部署目标）
┌─────────────────────┐            ┌──────────────────────────────┐
│ MySQL(3306) Redis(6379)│◄─────────│ FastAPI (0.0.0.0:8000)          │
│ Milvus Docker(19530)  │  网络可达  │  ├─ venv（Python 依赖）         │
└─────────────────────┘            │  ├─ models/（BGE 模型）         │
                                    │  └─ docker compose（Milvus，可选）│
                                    └──────────────────────────────┘
```

两种数据库布局任选：
- **布局 A（推荐给课程演示）**：WSL 镜像网络模式下（`%UserProfile%\.wslconfig` 里 `networkingMode=mirrored`，Win11 新装 WSL 常见默认），WSL 与 Windows 共享 localhost——`.env` 全部填 `127.0.0.1` 即可直连 Windows 的 MySQL（注意：若 WSL 内也装了 MySQL 会占用 3306 端口，需先 `sudo service mysql stop` 让流量落到 Windows）
- **布局 B（生产形态）**：WSL 内 `bash deploy/install.sh --with-db --with-milvus` 全量自包含
- 若为非镜像网络（NAT 模式）：MySQL host 填 Windows 宿主 IP（WSL2 内 `ip route | grep default | awk '{print $3}'`），且需放行 Windows 防火墙 3306

## 一、打包上传（Windows → WSL）

```powershell
# Windows PowerShell，在项目根目录
Compress-Archive -Path app,scripts,deploy,docs,jmeter,data,eval_report,docker-compose.yml,requirements.txt,.env.example,README.md -DestinationPath rag-roleplay.zip -Force

# WSL 内
wsl -d Ubuntu-24.04
mkdir -p ~/rag-roleplay && cd ~/rag-roleplay
cp /mnt/c/Users/孟笑含/rag-roleplay/rag-roleplay.zip . && unzip -o rag-roleplay.zip
```

> 也可以 git 拉取：`git clone <仓库地址> ~/rag-roleplay`（venv/models/tools 已在 .gitignore）

## 二、安装

```bash
cd ~/rag-roleplay
bash deploy/install.sh --with-milvus     # 布局B再加 --with-db；不下载模型加 --skip-models
```

脚本做 6 件事（幂等，可重复跑）：检查系统/内存/磁盘 → apt 装 python3-venv 等 → 建 venv + pip 装依赖（阿里镜像，torch 约 2GB 需耐心）→ 生成 .env → （可选）docker compose 起 Milvus → 下载 BGE 模型（约 4.5GB，hf-mirror）。

## 三、配置

编辑 `.env`（关键项）：

```ini
LLM_API_KEY=sk-你的key                    # DeepSeek 等 OpenAI 兼容 API
MYSQL_HOST=<宿主IP或127.0.0.1>            # 布局A填 Windows 宿主 IP
MYSQL_PASSWORD=你的MySQL密码
REDIS_HOST=<宿主IP或127.0.0.1>
MILVUS_HOST=<宿主IP或127.0.0.1>
```

## 四、启动 / 停止

```bash
bash deploy/run.sh           # 启动（自动建库、健康检查，日志 server.log，PID .server.pid）
bash deploy/run.sh --mock    # 压测模式：LLM_MOCK=true，不调外部 API
bash deploy/shutdown.sh      # 停止
```

## 六、故障排查

| 现象 | 排查 |
|---|---|
| run.sh 报"MySQL 不可达" | 镜像模式：确认 WSL 内没有自带 MySQL 占用 3306（`ss -tlnp | grep 3306`，停掉 `sudo service mysql stop`）；NAT 模式：确认 .env 里 MYSQL_HOST 是宿主 IP 且 Windows 防火墙放行 3306 |
| 依赖安装慢/失败 | 换镜像：`PIP_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/pypi/simple bash deploy/install.sh` |
| Milvus 起不来 | `docker compose ps` 看健康状态；首次拉镜像需要时间 |
| 模型加载 404 | `models/bge-m3/config.json` 是否存在；重跑 `python scripts/download_models.py` |
| 端口占用 | `lsof -i:8000` 查占用；`bash deploy/run.sh --port=8001` 换端口 |
| ragas 依赖（如需评测） | 见 README：ragas 0.4.3 需对 venv 里 ragas/llms/base.py 打 vertexai 导入补丁 |

## 七、生产建议

- uvicorn 单 worker 有 anyio 线程池（40）上限；生产用 `--workers 4`（或 nginx 反代多实例，实测 100 并发吞吐 +111%）
- MySQL 连接池已按压测调优（pool 20+40）；更高并发建议独立数据库实例
- 大模型用在线 API 时，系统吞吐上限 = 并发数 / LLM 延迟（实测端到端约 1.3s/请求）
