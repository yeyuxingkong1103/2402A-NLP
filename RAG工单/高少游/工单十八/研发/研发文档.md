## 4. 主流程实现

`run()` 是唯一的对外入口，内部按以下顺序执行。

**第一步：扫描。** `scan_files()` 按 `scan.include_ext` 白名单收集文件，支持是否跟随符号链接、是否跳过隐藏文件、是否限制文件数、按名或按大小排序。返回相对路径列表。

**第二步：确定并行度。** `workers = max(1, min(配置值, CPU 核数))`，避免过度订阅。本机实测 4 进程最优，详见 `优化\优化报告.md` 的 O5。

**第三步：并行抽取。** 每份文件封装成 job 元组 `(abs_path, root, cfg_dict, rel_path)`，交给 `mp.Pool.imap_unordered(_analyze_one, jobs, chunksize=4)`。`_analyze_one()` 在子进程内完成：stat → MD5 → 按格式族抽取文本 → PDF 逐页统计 → SimHash → 敏感信息，返回一条结构化记录。**异常被整体捕获**并写入记录的 `error` 字段，因此单份损坏文件不会中断整批处理。

**第四步：断点写入。** 每拿到一条结果立即 `ckpt.add(rec)`，每 50 条落盘一次，同时回调 `progress` 更新进度条。重跑时 `done` 中已存在的 `rel_path` 直接跳过，无需重新入队。

**第五步：报告组装。** `_build_report()` 先跑重复检测并回填 `dup_exact` / `dup_near` 标记（分类需要用到），再依次聚合五大功能，最后按配置截断长列表。

## 5. 关键实现细节

### 5.1 单文件记录（内部数据契约）

五个分析模块都只读这一份记录，字段见 `设计\系统设计文档.md` 第 6 节。字段在 `_analyze_one()` 顶部初始化为默认值，保证即使解析失败记录结构也完整，下游聚合无需做存在性判断。

### 5.2 PDF 分流的实现

`extract_text_pdf()` 返回逐页统计列表，每页含可提取字符数与图片覆盖面积占比；`classify_pdf()` 据此定级：字符数低于 `text_char_threshold`（默认 30）的页记为扫描页，扫描页占比高于 `scanned_page_ratio`（默认 0.70）判扫描型，低于 `text_page_ratio`（默认 0.10）判文字型，之间判混合型。同时用图片覆盖面积做交叉信号，当交叉信号与文本信号不一致、或占比落在 `confirm_band`、或页数少于 `min_pages_for_strict` 时，进入 `to_confirm` 列表。

### 5.3 分类路由的顺序（关键）

`classify_record()` 中的路由判定顺序是本工单踩过坑后定下的，务必保持：

```
损坏 → manual_review
PDF 扫描型 → ocr_parser        ← 必须在「空文本」规则之前
PDF 混合型 → hybrid_parser
PDF 文字型 → text_parser
PDF 空文本 → manual_review
非 PDF 空文本 → manual_review
非 PDF 有文本 → 按格式族路由
最后：完全重复 → dedup_review   ← 覆盖以上所有
```

扫描型 PDF 天然无可抽取文本，若先判空文档会被误路由到人工复核，OCR 链路失效。这段顺序在 `src/classifier.py` 第 89–109 行有显式注释。

### 5.4 SimHash 阈值

`simhash64()` 对规范化文本按 shingle 切分、取 64 位哈希加权累加。阈值 `simhash_hamming_threshold` 经真实数据校准为 **8**（实测无关文档最小距离 17），校准依据写在 `assessment_config.yaml` 注释里。短于 `min_chars_for_simhash`（默认 200 字符）的文档不参与近似去重，避免短文本指纹不稳定。

### 5.5 敏感信息检测

`detect_sensitive()` 用带上下文的正则匹配手机号、邮箱、身份证三类，银行卡默认关闭。每条命中保留命中位置与前后 `context_chars`（默认 40）个字符，命中值默认脱敏后写入报告，避免报告本身成为二次泄露源。单文件命中数由 `max_hits_per_doc` 封顶。

### 5.6 断点续跑

`Checkpoint` 把每条记录以一行 JSON 追加写入 `<out>/.qcheck/records.jsonl`，`flush_every` 条强制落盘一次。加载时按 `rel_path` 建索引。这一机制把「调参后重跑」的成本从全量降到增量。

## 6. 集成实现

**Skill 三层结构。** `document_quality_assessment/SKILL.md` 的 YAML frontmatter 声明 `name`、`triggers`、`inputs`、`outputs`、`entrypoint`，让智能体在不加载正文的情况下判断是否调用；正文描述 SOP；`references/` 与 `scripts/` 作为按需加载的资源层。

**技能注册表。** `src/skill_registry.py` 维护注册表，`GET /v1/skills` 可列出已注册技能用于集成自检。

**工作流。** `document_ingestion_workflow` 用「节点 + 边」描述「触发质检 → Skill → Switch 路由」链路，节点字段与 RAGFlow Agent DSL 对齐，Switch 节点以 `classification.route` 为分派字段。既能被本地 `WorkflowExecutor` 跑通，也能序列化后导入 RAGFlow。

**API。** `src/api_router.py` 暴露 `POST /v1/document/quality-inspection`（接受文件夹或文件列表，同步返回报告，`?format=html` 返回简报）与 `GET /v1/document/quality-inspection/{run_id}`。`app.py` 中 `include_router` 即可挂载，无需改动宿主应用。

## 7. 配置体系

所有阈值集中在 `assessment_config.yaml`，分七段：`scan`、`pdf`、`length`、`dedup`、`sensitive`、`classification`、`report`、`checkpoint`。代码中不出现魔法数字。运行期可用 `overrides` 深度合并覆盖：

```python
DocumentQualityAssessmentSkill(overrides={"pdf": {"scanned_page_ratio": 0.8}})
```

命令行 `--workers`、`--sample` 也会转成覆盖项。每次运行的配置以 `meta.config_snapshot` 完整快照落盘，保证报告可复现。

## 11. 复用与扩展说明

本工单骨架复用并改造自前序工单的 RAG 项目（`交付\实训一工单\工单七\研发\src\`）。沿用其并行抽取、断点续跑、配置化与 Skill 注册的工程结构，新增了 PDF 分流、两层去重、敏感信息、分类路由四个模块，并把它们编排成一个可被工作流调用的 Skill。

扩展点：新增文档类型只需在 `assessment_config.yaml` 的 `scan.include_ext` 加扩展名、在 `classification.routing` 加路由映射；新增检查项只需在 `src/` 加一个只读记录的分析模块并在 `_build_report()` 中聚合；换数据集只需调配置，无需改代码。
