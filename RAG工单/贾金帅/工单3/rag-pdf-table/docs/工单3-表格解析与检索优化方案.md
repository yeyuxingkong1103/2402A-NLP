> 页码口径：统一使用 **PDF 物理页序（1-based）**。力源 PDF 的书眉上印的是「3-21」这类原书章节页码，与物理页序不同，引用时以物理页序为准。

| id | 问题 | 答案所在位置 | 表格形态 | 关键事实 |

| 2 | 本次募集资金拟投资哪些项目？ | **力源 p22**「本次募集资金拟投资以下项目」；**力源 p306** 募投项目主表 | p22：3 列 5 行；p306：**5 列、表头跨 2 行** | 仓储及物流中心 3,393.40 / 研发中心 1,526.38 / 电子商务平台 2,492.78 / 扩充产品种类和数量 9,000.00 / 其他与主营业务相关的营运资金 |

### 为什么必须用表格解析才能定位（这是工单3 的直接动因）

1. **id=3 的那张表全表只有一个百分数**（`42.35%`）。工单2 判断「要不要抽表」的启发式是「一行出现 ≥3 个数字的行数 ≥3」，在这张表上判定为 `looks_tabular=False` —— **整张表被跳过，而 id3/id4 的答案全在里面**。
   → 结论：用「数字密度」猜表格，在「名称 + 关系描述」这类表上会漏干净。工单3 改为**对每一页全量跑 `find_tables()`**，实测代价可接受（力源 350 页 24.5s、兴图 548 页 66.3s，含文字解析）。

2. **id=1 的答案在键值表里**，而键值表存在一个隐蔽的版式陷阱（详见 3.3）：单元格内的**标签垂直居中**、值从单元格顶部开始排，导致「按行 top 聚词」时键与值错配成
   `每股发行价格 | 通过向询价对象询价…确定2.18元(按…除以发行前总` / `发行前每股净资产 | 股本计算)`。
   按单元格 bbox 分派词之后才得到正确结果。

3. 表格区域必须**从正文里摘掉**：id=2 实测发现，表格虽然被正确解析，但正文里残留了表格的**引导句**
   （「四、本次发行情况 / 五、募集资金用途 / 本次募集资金拟投资以下项目：」）形成一个**有标题无数据的碎片块**，
   它和问题的字面重合度极高，排到了第 1 名 —— 而真正装了数据的表格块连 top-8 都没进。
   → 表名既然是表的一部分，正文里就不再保留（见 3.6）。

## 三、表格解析技术方案（`src/table_parser.py`）

### 3.1 工单2 的做法为什么在这份 PDF 上失效

工单2 是「把 pdfplumber 的 `extract_tables()` 结果直接转 Markdown」。在力源这份 PDF 上实测两个硬伤：

**硬伤一：抽不到（见第二节第 1 点）。**

**硬伤二：抽到了也是烂的。** 该 PDF 的表格用**双线边框**，pdfplumber 会把两条线之间的**缝隙**也当成一列：

```
x 边界: 84.5 | 89.9 | 155.9 | 161.3 | 166.7 | 362.6 | 368.0 | 373.5 | 505.4 | 511.7
间距:     5.4    66.0     5.4     5.4   195.9     5.4     5.5   131.9     6.3
```

三列的表被切成九列，中间夹着 5~6pt 的「缝隙列」。更糟的是**窄数字会掉进缝隙列**：``序号`` 表头落在第 2 列，而数据 ``1`` 落在第 1 列 —— 表头与数据错位，行列对应关系实际已经断了。

### 3.2 列重建：先合并缝隙边界

```
① 取表格 bbox 内的所有词（含精确 x0/x1/top）
② 取该表格所有单元格的 x 边界，按 8pt 阈值合并「缝隙边界」→ 真实列边界
③ 每个词按 x 中心落到某一列
```

为什么 8pt 是安全的：实测缝隙 **5.4~6.3pt**，而最小真实列宽 **66pt**，两者差一个数量级。阈值可在 `config.TABLE_GAP_MERGE_PT` 调整。

### 3.3 按单元格分派词（修「标签垂直居中」导致的键值错配）

最初实现是「词按全局 `top` 聚行 + 续行合并」。第 24 页实测坐标暴露了这个做法的致命缺陷：

```
top=216.99  每股发行价格        ← 标签（单元格内垂直居中）
top=216.99  通过向询价对象询价或中国证监会认可的其他定价方式确定
top=243.09  2.18元(按截至2010年6月30日经审计净资产除以发行前总
top=249.87  发行前每股净资产    ← 下一个标签（比值的首行低 33pt）
top=256.71  股本计算)
```

按 `top` 聚行的结果：`每股发行价格 | 通过向询价对象询价…确定2.18元(按…除以发行前总`、`发行前每股净资产 | 股本计算)` —— **键与值完全错位**。

改为**按 pdfplumber 的单元格 bbox 分派词**（单元格内的多行文本自然落到同一格并按 top 排序拼接）后得到正确答案，且主路径上再也不需要「续行合并」这个补丁。修复后实测：

```
p24 表0  表头 ['字段','内容']  15 行
  ['每股发行价格', '通过向询价对象询价或中国证监会认可的其他定价方式确定']
  ['发行前每股净资产', '2.18元(按截至2010年6月30日经审计净资产除以发行前总 股本计算)']
  ['发行后每股净资产', '6.19元(按截至2010年6月30日经审计的净资产加上本次募 集资金净额除以发行后总股本计算)']
```

### 3.4 表头识别：三判据 + 一个特例

「第几行是表头」不能靠行号，因为**表头行与数据行的非空单元格个数往往完全一样**（id=2 的募投表就是 3 对 3）。最终采用三条判据，顺序执行：

| 判据 | 作用 | 实测修对了什么 |
|---|---|---|
| ① 表头行**不能含纯数字**单元格（`1` / `3,393.40` / `(1,234)` 算；`2010年1-6月` / `(万元)` / `持有公司股份5%以上的股东` 不算） | 把「序号 1 / 项目名称 仓储及物流中心」这种首行数据挡在外面 | p22/p306 募投表 |
| ② 下一行的非空列集合与本行**完全相同**即停止 | 截断「全行只有 2 个非空单元格」的表 | p157 两张关联方表 |
| ③ 最多收 3 行 | 支持列名跨行 | p306 的「项目总投资(万元)」被排成两行 |

**特例**：`ncol == 2` 且首行第二格字数 > 8 → 判定为**键值表**（无列名行），表头固定输出 `['字段','内容']`。
不加这条会退化成「表头 = 股票种类 | 人民币普通股(A股)」，于是数据行被输出成「股票种类：发行股数」—— 键与值张冠李戴（p22「四、本次发行情况」实测）。

### 3.5 输出形态：行级语义文本

每张表不是输出 Markdown，而是输出「**列名与值绑定**」的行级文本：

```
【表】1、存在控制关系的关联方[关联方表]（第157页）
来源文档：武汉力源信息技术股份有限公司招股说明书
列名：关联方名称 | 持股比例 | 与本公司关系
关联方名称：赵马克；持股比例：42.35%；与本公司关系：公司控股股东
```

三个理由：
- BM25 能命中「持股比例」这类**列名**（问题问法与列名往往不逐字相同）；
- 生成模型不必自己去数列 —— **数错列是表格问答最常见的错法**；
- 超长表按行切块时**每块重复表头**，从中间断开也不会丢失列名。

### 3.6 正文剔除：表格区域 **和表名**

```
正文 = 整页词 - 落在表格 bbox 内的词 - 表格的引导句
```

第一步的理由：不剔除的话，同一批事实会以「高质量结构化块」和「低质量稀释段落」两种形态同时存在，检索时稀释段落可能先被召回，表格解析的收益就体现不出来，消融实验也就比不出东西。

第二步（表名）是实测补的一刀，理由见第二节第 3 点。对照版（`with_tables=False`）两步都不做 —— 表格内容全部作为普通文本行参与分块。

## 四、语料从 1 份变 2 份带来的三个新问题

### 4.1 页眉 / 页码规则必须按文档配置

两份说明书的页眉分别是「公司名 + 招股意向书 / 招股说明书」，页码格式也不同（兴图 `1-1-30` 三段式，力源 `3-21` 两段式）。写死一家公司的正则会漏掉另一家的页眉，而页眉被 BM25 当高频词命中的后果很严重。→ `config.DOCS` 每份文档各挂一条 `header_re`。

### 4.2 分块 ID 必须全局唯一

`rag.retrieve_for` 用 `chunk_id` 去重，而**两份文档里都存在「第 22 页」**。若两篇文档各自从 `c00001` 开始编号，去重时会互相顶掉。→ `chunk_document(..., seq_start=...)` 由调用方累加，块 ID 全程串行编号；同时给每个块加 `doc_key` 字段，引用与评测都靠它区分「答的是哪一家」。

### 4.3 DF 过滤会把「公司名」删掉 —— 而公司名恰恰是两文档语料里最强的消歧信号

工单2 的 DF 过滤会自动剔除语料级无区分度成分，其中就包括公司全称（单文档里它出现在几乎所有块中）。语料变成两份之后，这一招反过来咬人，实测：

```
问：武汉兴图新科电子股份有限公司注册资本是多少？
检索式（DF 过滤后）：注册资本是多少
→ 召回 top1~top6 全是【力源】的「历次验资情况及设立时投入资产的计量属性」段落
→ 兴图的正确答案（p22/p52/58-60）全部被挤出候选；「5,520」在 top-8 里一次都没出现
```

**修法不是「别删公司名」**（删它仍然是对的：它在 BM25 里是纯噪音），而是给公司名换一种用法：

```
① 在**原问题**（未过滤）里识别公司名 → 映射到目标文档（config.DOC_ALIASES 支持全称/简称）
② 把候选池做一次「文档内 top-k」追加召回，保证那份文档的最优块一定在池子里
③ 排序时给该文档的块一个加法加成（RETRIEVAL_DOC_HINT_DELTA = 0.25）
```

**加成只作用于 `score`（排序），闸门仍只看 `evidence`（绝对量纲）** —— 「问的是哪一家」是主题先验，不该让离题问题借此过闸门。这与工单2「双分设计」的取舍是同一套逻辑。

修复效果（同一组问题、只切这一个变量）：

| | id=543 注册资本 | id=531 法定代表人 | 10 道旧题 MRR |
|---|---|---|---|
| 修前 | 正确页未命中 | 正确页未命中 | 0.414 |
| 修后 | 正确页 rank 1 | 正确页 rank 1 | 0.720 |

## 六、遗留问题与已知代价（如实记录）

### 6.1 表格块的向量相似度天然偏低，在 top-8 预算下会吃亏

实测（问「…募集资金的多少用于补充流动资金？」）：

| 块 | 类型 | 余弦 | BM25 |
|---|---|---|---|
| 正确答案所在块（p30 / p479 表格，含「补充流动资金 15,000.00」） | table | 0.586 / 0.525 | 28.43 / 24.59 |
| 召回 top1（p483 的叙述段落） | text | — | — |

表格块的**余弦相似度中位数 0.415**，正文块 **0.439**；具体到这道题，正确表块的余弦 0.586，而排在它前面的叙述段落明显更高。

**原因**：表格块的文本是「列名：值；列名：值」的密集枚举，语义分布与自然语言问句不同 —— 它的强项是关键词（BM25 = 28.43，很高），弱项是向量语义。

**已确认这不是解析错误**：`c00745` / `c01153` 两个块的内容分别是

```
字段：项目名称；内容：项目总投资（万元）
字段：补充流动资金；内容：15,000.00
...
项目名称：补充流动资金；总投资：15,000.00；拟投入募集资金：15,000.00
```

列名与值绑定完全正确；把 `top_k` 从 8 提到 12，该题的关键事实即全部命中（5.5 节）。

**可选的后续改法**（本次未做，避免在收尾阶段引入未充分验证的启发式）：
- 为表格块单独建一个「表名 + 列名」的短文本检索单元（small-to-big / parent-document retrieval），用短单元召回、再把整表带入上下文；
- 或给表格块的 `evidence` 一个类型补偿项（需重新校准闸门，见 6.2）。

### 6.2 闸门阈值在双文档语料上无法完全分离真题与离题问题

工单2 校准的 0.80 是在「单文档 + 表格展平」状态下测的。语料变成两份 + 表格结构化后重新测量：

| | top1 依据分区间 |
|---|---|
| 14 道验收题 | **0.7756 ~ 1.0996**（最低是「兴图法定代表人」0.7756） |
| 7 个离题问题 | **0.4131 ~ 0.8090**（最高是「力源董事长今年多大年纪」0.8090） |

两段区间**有重叠**，单一标量阈值做不到既不漏真题、又不放离题。取舍：

- 取 **0.82** → 离题 0 漏，但会把「兴图法定代表人」拦空 → 演示时用户会看到「资料中没有相关内容」，属于硬伤；
- 取 **0.75**（当前采用）→ 14 道真题全部通过闸门，代价是 2 个离题问题（0.795 / 0.809）过闸门，由生成层兜底（资料里没有答案时，模型被要求如实回答「资料中没有相关内容」）。

工单验收明确要求「问答准确性 ≥ 90%」，拦掉真题直接不达标，因此选 0.75。

另有 2 道题在闸门口径下关键事实命中从 1.00 降到 0.50（id=531 / id=207）：闸门会把 `evidence < 0.75` 的块整体丢掉，而这两题的部分关键事实恰好落在阈值下方的辅助块里。**正确页命中率不受影响（仍为 1.000）**。

### 6.3 表格解析的误检与漏检

- 力源 350 页共抽出 **221 张**「有意义的表」（`is_meaningful` 已过滤掉纯边框/目录点线框等假表）；兴图 548 页抽出 **412 张**。
- 仍然存在假表：少数页眉框、章节分隔线会被识别成 2 列表。它们的内容多为「标题 + 占位符」，对检索影响有限，但会占用少量块。
- 也存在漏检：跨页续表目前按两页各出一张表处理，**表头不继承**；若第二页没有重复表头，那段数据的列名会退化成 `列1/列2`。
