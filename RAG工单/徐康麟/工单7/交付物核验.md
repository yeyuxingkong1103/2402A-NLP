## 6.2 原计划设计的恢复（依赖补装 + 图像链路 + Gradio）

### 起因：一处判断失误的更正

本仓库最初写「沙箱封禁外网出口、pip 会挂死」，据此把 Gradio / pandas / pdfplumber / 中文 CLIP
全部列为「技术栈偏离 / 已知缺口」。**用户指出该判断有误**，逐层复测后确认：

| 探测项 | 实测 |
| --- | --- |
| DNS / TCP 443 | ✅ 正常 |
| **Python TLS 握手**（OpenSSL 3.5.6 + certifi） | ✅ baidu / pypi.org / 清华源 / 阿里源 / hf-mirror / github **全部成功** |
| **Python HTTP GET** | ✅ 全部 **200**（0.33~1.23 s） |
| `pip index versions gradio` | ✅ 秒回 |
| HF 镜像下载 718 MB 权重 | ✅ **1.22 MB/s** 完成 |
| `curl.exe` / `Invoke-WebRequest` | ❌ `schannel: SEC_E_NO_CREDENTIALS`（**Windows 系统 TLS 凭证不可用**，与封网无关） |

**真正受限的只有 `pip install` 的落点**：`pip install --target` 抛 `PermissionError`
（pip 自己的临时解包目录被拒，改 TMP/TEMP 亦无法绕过）。

### 解决方案：`工具/不依赖pip装包.py`

直接下 wheel → `zipfile` 解包到 `研发/第三方库`，具备：
- **依赖约束求解**：解析 `Requires-Dist` + 环境标记 + 规格符（`==` / `>=` / `,`），
  实测修掉了 `pydantic 2.13.5` 与 `pydantic-core 2.49.0` 的冲突（正确装 2.46.5）；
- **排除预发布版**（实测若不排除会装 `pandas-3.1.0rc0`）；
- **Requires-Python 与 wheel tag 兼容筛选**（cp311 / abi3 / win_amd64）；
- **镜像优先**：清华直链 4.95 MB/s vs PyPI CDN 2.06 MB/s（快 2.4 倍）；
- **完整性判定**：认 `*.dist-info`（第一版按目录名判断，把半成品 opencv 误判为已装）；
- **`_lock.json` 版本凭证**。

### 补装结果（`研发/第三方库`，269.3 MB / 60 个分发包）

| 包 | 版本 | 用途 |
| --- | --- | --- |
| **gradio** | **6.29.1** | 任务书原计划设计的界面 |
| **pandas** | **3.0.6** | 任务书技术栈建议（CSV/表格处理） |
| **pdfplumber** | **0.11.10** | 任务书技术栈建议（PDF 解析备用路径） |
| 中文 CLIP 权重 | 718.3 MB | 图像语义编码（`研发/data/models/chinese-clip-vit-base-patch16`） |

### 图像链路真实打通

旧结论「缺 cv2/onnxruntime → CLIP 不可用」**同样有误**：实测 `extract_images.py` 只依赖
`PIL + pymupdf + numpy`，本机早已具备。

```
图像抽取（extract_images.py --all，9 份年报全量）
  → image_blocks.jsonl 175 条 / charts.jsonl 102 / diagrams.jsonl 19 / image_candidates.jsonl 177
  → images_clip.npy 196 条 × 512 维（ChineseCLIPModel，device=cpu）
重建索引（build_index.py --include-images）
  → 8847 块 = 文本 7325 + 表格 1417 + 图像 105（覆盖全部 9 份年报）
```

### 两处必须记住的踩坑（已写进代码注释）

1. **`研发/第三方库` 必须放在 `PYTHONPATH` 最后**：它含 numpy 2.x，而 venv 的 faiss 1.7.4 是针对旧 numpy
   编译的 C 扩展；放前面会让 `import faiss` 抛 `AttributeError: _ARRAY_API not found`，向量检索整条链路失败。
2. **已把第三方库里的 numpy 2.4.6 移除**，统一使用 venv 的 numpy 1.26.4（pandas 3.0.6 与之兼容）。
