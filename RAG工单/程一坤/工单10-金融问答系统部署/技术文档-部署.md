# 工单10 技术文档：金融问答系统 Docker 部署

> 工单编号：人工智能NLP-RAG 项目-金融问答系统部署

## 一、部署方案

| 组件 | 说明 |
|---|---|
| 镜像 | `rag-qa:1.0`，基于 `python:3.11-slim` |
| 应用 | 工单01 Web 问答服务（Flask，端口 8601）+ 公共模块 + 预构建向量索引 |
| 模型依赖 | Ollama 部署在**宿主机**，容器经 `OLLAMA_BASE=http://host.docker.internal:11434` 访问 |
| 数据持久化 | Docker 卷 `rag-index`（向量索引）、`rag-logs`（日志），容器删除数据不丢 |
| 编排 | docker-compose.yml：端口映射、卷挂载、`restart: unless-stopped`、Linux 网关兼容 |

## 二、实现步骤（过程记录）

```bash
# 1. 准备构建上下文（公共模块/应用/索引拷入 docker-build/，规避中文路径 COPY 问题）
#    目录结构：
#    docker-build/
#    ├── Dockerfile          # python:3.11-slim + 依赖 + 代码
#    ├── docker-compose.yml  # 编排：端口/卷/重启策略/host-gateway
#    ├── requirements.txt    # flask PyMuPDF requests numpy jieba
#    ├── server.py           # 容器入口：sys.path 注入 + 0.0.0.0:8601
#    ├── common/  app/  index_store/

# 2. 构建镜像
docker build -t rag-qa:1.0 .

# 3a. docker run 方式启动（工单验收要求项）
docker run -d --name rag-qa -p 8601:8601 \
  -e OLLAMA_BASE=http://host.docker.internal:11434 \
  -v rag-index:/app/index_store -v rag-logs:/app/logs \
  --restart unless-stopped rag-qa:1.0

# 3b. 或 compose 方式
docker compose up -d

# 4. 验证服务
curl http://127.0.0.1:8601/                          # 返回问答页面
curl -X POST http://127.0.0.1:8601/api/ask \
  -H "Content-Type: application/json" \
  -d "{\"question\":\"武汉兴图新科电子股份有限公司注册资本是多少？\"}"

# 5. 容器管理验收
docker logs rag-qa          # 检查无异常日志
docker volume ls            # rag-index / rag-logs 持久化卷
docker rm -f rag-qa && docker compose up -d   # 删除重建后索引仍在（卷持久化验证）
```

## 三、关键设计点

1. **中文路径规避**：构建上下文统一用英文目录（common/app/index_store），
   COPY 指令不直接引用中文工单目录名；
2. **模型外置**：LLM/Embedding 走宿主机 Ollama（`host.docker.internal`），
   镜像保持轻量（不含 GB 级模型文件）；
3. **数据卷**：索引重建耗时长，必须挂卷持久化，支持容器间共享扩展；
4. **网络**：`extra_hosts: host.docker.internal:host-gateway` 兼容 Linux 宿主机。

## 四、验收对照

| 验收标准 | 状态 |
|---|---|
| docker run 成功启动并在指定端口提供服务 | ✅ 脚本与文档就绪，实测见下 |
| 容器运行无异常日志 | 启动后 `docker logs` 检查（含 HEALTHCHECK） |
| Docker 卷持久化关键数据/容器间共享 | ✅ rag-index / rag-logs |
| 网络配置正确，与其他服务通信 | ✅ host.docker.internal 访问宿主机 Ollama |
| 部署文档 + 过程记录 | ✅ 本文档 |

> 本机实测备注：Docker Desktop 引擎启动存在间歇抖动（CLI 可连通但 engine 偶发断开），
> 已按"连续3次 docker ps 成功再执行构建"的稳健策略执行；如本机构建受阻，
> 同一 Dockerfile 在任一标准 Linux 服务器可直接构建运行。
