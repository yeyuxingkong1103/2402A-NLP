## 一、任务与目标

| 项 | 内容 |
|---|---|
| 任务 | 基于 01–06 工单实现的 RAG 系统，对 `ccf_competition.zip` 中的 PDF 执行 **RAG 测试及检索评估** |
| 目标 | 以《sample_questions.pdf》题型口径整理 10 道问题，经评估框架产出 **检索结果 + 评估结果** |
| 输出 | 10 个问题及对应的 RAG 检索结果、RAG 评估结果；检索问题分析 |
| 验收 | ① 10 题体现 CCF 年报内容相关性；② 使用 01–06 工单的 RAG 系统测试；③ 有 10 题检索结果与评估结果，并体现检索问题分析 |

**核心设计取舍**：本工单**不新建 RAG 能力**，而是复用 01–06 工单的系统作为被测对象（SUT），
新增「测试题集 + ground-truth 标注 + 评估框架 + 问题诊断」四件套，使评测**可复现、可归因、可对比**。

## 二、总体架构

系统采用分层架构，被测 RAG 系统与评估框架相互独立：评估框架只通过 `QAEngine.ask()` 这一
公开接口驱动被测系统，保证「黑盒评测」。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 应用层   Streamlit 检索配置界面 │ run_demo 多轮演示 │ evaluate_ccf 评测 │
├──────────────────────────────────────────────────────────────────────┤
│ 多轮理解层  会话记忆 Conversation │ Query 改写(指代/省略) │ Query 理解   │
├──────────────────────────────────────────────────────────────────────┤
│ 重排层   多信号线性融合 │ TF-IDF │ LLM 重排 │ 反馈自适应重排            │
├──────────────────────────────────────────────────────────────────────┤
│ 检索层   向量检索(召回+重排) │ 全文检索(倒排索引) │ 混合检索(权重+融合) │
├──────────────────────────────────────────────────────────────────────┤
│ 索引层   多嵌入模型向量库 │ 多字段倒排索引 BM25 │ 结构感知切片          │
├──────────────────────────────────────────────────────────────────────┤
│ 数据层   ccf_competition 9 份年报（银行 4 / 保险 3 / 证券 2，2812 页）  │
└──────────────────────────────────────────────────────────────────────┘
```

架构图与流程图见 `设计/assets/`：`01_系统总体架构.png`、`02_混合检索核心流程.png`、
`03_检索策略决策流程.png`、`04_测试与评估流程.png`。

## 四、数据设计

### 4.1 数据集

`ccf_competition.zip` 解压后共 9 份年度报告，文件名形如
`日期__公司全称__股票代码__简称__年份__年度报告.pdf`。原始压缩包内文件名为 GBK 编码，
若解压工具按 CP437/Latin-1 解码会产生「╞╜░▓╥°╨╨」类乱码，污染界面与报告。
系统采用**双重保障**：

1. **乱码修复**：`config.normalize_source()` 把 `name.encode("cp437").decode("gbk")`
   还原为正常中文名（幂等：已是正常中文时 encode 抛异常，原样返回），并在
   `pdf_parser` 解析、`knowledge_base` 加载、`config.DOC_COMPANY` 建表三处统一调用；
   一次性维护脚本 `tools/fix_source_names.py` 可将存量 PDF 文件名与
   `vector_db/chunks.jsonl`、`meta.json` 的来源字段批量修正（纯元数据操作，无需重嵌入）。
2. **稳定标识**：即便名称仍异常，也**统一以 ASCII 股票代码作为稳定标识**，
   中文名仅用于展示：

| 股票代码 | 公司 | 年份 | 类别 |
|---|---|---|---|
| 000001 | 平安银行 | 2019 | 银行 |
| 600036 | 招商银行 | 2019 | 银行 |
| 601658 | 邮储银行 | 2019 | 银行 |
| 601318 | 中国平安 | 2019 | 保险 |
| 601628 | 中国人寿 | 2020 | 保险 |
| 601601 | 中国太保 | 2021 | 保险 |
| 600030 | 中信证券 | 2020 | 证券 |
| 600999 | 招商证券 | 2021 | 证券 |
| 601211 | 国泰君安 | 2021 | 证券 |

`src/config.py` 中 `CCF_DOCS` 建立「股票代码 → 公司简称/年份/检索别名」映射，
`_stock_code_of()` 从文件名提取代码，`PDF_PATHS` 按代码排序得到稳定的文档顺序。

### 4.2 多文档实体消歧（本工单关键）

9 份年报存在大量**同构字段**（营业收入 / 归母净利润 / 不良贷款率 / 拨备覆盖率 …），
若不做文档级路由，会出现「问邮储却召回招商」的跨文档串味。设计：

- `DOC_COMPANY`：源文件名 → 公司别名列表；
- 检索前由 Query 理解得到 `doc_hint`，命中则把候选**限定在该文档的块集合内**（白名单）；
- 路由优先级：本轮显式公司名 > 主查询别名 > 扩展查询别名；历史话题实体仅作兜底。

### 4.3 切片与索引

| 项 | 取值 |
|---|---|
| 切片大小 / 重叠 | 600 字 / 100 字 |
| 块类型 | `text`（正文）/ `table`（表格键值对）/ `figure`（图形语义） |
| 向量库 | `vector_db/emb_<slug>.npy`（bge-m3 1024 维、bge-large 1024 维、nomic-embed 768 维） |
| 倒排索引 | `vector_db/inverted_index.pkl`（含位置信息的倒排链 + 多字段 BM25） |
| 元信息 | `vector_db/meta.json`（块数 / 维度 / 词表 / 来源 / 类型分布） |

## 五、评估框架设计

### 5.1 评测口径

| 指标 | 定义 | 目标 |
|---|---|---|
| 准确率 accuracy | 答案文本命中该题**全部** `key_tokens` 的题目占比 | ≥ 90% |
| 召回率 recall（问题级） | Top-K 命中 ≥1 个 ground-truth 相关块的题目占比 | ≥ 95% |
| 块级召回 chunk_recall | avg(\|相关块 ∩ Top-K\| / \|相关块\|)，衡量召回完备度 | 参考值 |
| 响应时间 latency | 单问端到端耗时（改写 + 检索 + 重排 + 合成），含 avg / P95 / max | ≤ 3 s |

数值型 key_token 匹配时**忽略千分位逗号与空白**（`2,697.03` ≡ `2697.03`）。

### 5.2 ground-truth 标注（避免自证）

相关块**不取检索器产出**，而是独立地在语料侧标注：块文本归一化后包含该题**全部**
`key_tokens` 者视为相关块；若不存在这样的块，则退化为「包含最长 key_token」的块，
保证每题都有可核验的相关块。这样「召回率」衡量的是检索器与语料事实的一致性。

### 5.3 问题诊断（对应产出物「分析检索结果存在的问题」）

逐题输出四类诊断信号，并归类失败模式：

1. **文档路由**是否正确（Top-1 来源 vs 预期年报）；
2. 相关块**首次命中排名**（>3 视为偏后）；
3. 关键信息是否进入 **Top-K 片段文本**；
4. 答案是否覆盖全部关键信息，**缺失项**是什么。

### 5.4 消融维度

`evaluate_ccf.py` 支持在四维上做对比：策略（vector/fulltext/hybrid）× 重排
（none/tfidf/llm/adaptive/linear）× 融合（weighted/rrf/voting）× 嵌入模型
（bge-m3/bge-large/nomic-embed），支撑「优化报告」的策略调优结论。

## 六、界面设计

`app.py`（Streamlit）：

- 左侧**检索策略配置面板**：策略 / 嵌入模型 / 全文模式 / 重排算法 / 融合算法 / 向量权重 / 全文权重；
- 左侧知识库信息：块数、维度、倒排词表、文档列表；
- 右侧多轮对话区：答案 + 可展开的「多轮改写 / 检索证据 / 检索策略详情」；
- 每条回答支持 👍/👎 反馈，驱动自适应重排器在线学习；
- `?demo=1` 自动回放 5 轮验收对话，便于截图与录屏。

## 七、非功能设计

| 维度 | 设计 |
|---|---|
| 性能 | 查询编码批量合并 + 内存缓存；向量离线预计算（numpy 内积）；确定性改写，无额外 LLM 调用 |
| 可复现 | 检索参数全部经 `RetrievalConfig` 显式传递；评测结果与中间产物全部落盘 JSON |
| 可解释 | 抽取式答案零幻觉，逐条给出源文件 / 页码 / 块类型 / 分数 |
| 可扩展 | 嵌入模型注册表新增条目即可支持新模型；融合算法/重排器为可插拔函数 |
| 可移植 | 不依赖 faiss / torch，向量服务走 Ollama HTTP，`requirements.txt` 轻量可复现 |
