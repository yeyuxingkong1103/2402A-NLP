---

## 1. 项目概述

一个多用户、多角色的 RAG 智能聊天助手平台。用户登录后，可通过「设定角色提示词 + 上传知识库文件」创建自定义角色，让大语言模型扮演该角色进行多轮对话。

系统定位为中小规模（几十~几百用户）的本地可部署服务，以 Docker Compose 一键启动，通过 FastAPI 提供后端接口，前端为纯 HTML + JS 的单页应用。

核心特色：
- 角色种类覆盖「虚拟朋友 / NPC 人物」「领域专家（中医、心理医生、律师、金融理财师等）」。
- 每个角色拥有独立的系统提示词、知识库、模型配置和对话上下文，彼此完全隔离。
- 双层记忆：Redis 短期记忆（会话上下文）+ Milvus 长期记忆（知识库 + 对话事实沉淀）。
- 大模型同时支持本地部署（Ollama / vLLM）与云端 API，统一走 OpenAI 兼容协议。

## 2. 用户与场景

### 2.1 用户形态
- **多用户 + 登录**：用户需注册/登录。
- 角色、知识库、会话、记忆等所有数据均按用户隔离，用户之间不可见。

### 2.2 典型场景
1. 用户创建一个「中医」角色，上传若干中医典籍 PDF，之后以患者身份向该角色咨询。
2. 用户创建一个「虚拟朋友」角色（自定性格提示词），进行闲聊，系统从对话中逐步沉淀该用户的偏好为长期记忆。
3. 用户上传含文字的图片，希望角色既能按图中文字回答，也能「看图说话」。

## 3. 功能需求

### 3.1 账号与认证
- 注册 / 登录（用户名 + 密码）。
- 会话级认证（JWT），所有接口需鉴权。
- 密码需加密存储（不可明文）。

### 3.2 角色管理
- **创建角色**：必填「角色名」+「系统提示词」；可选「模型配置」「知识库文件」。
- **角色模板**：系统内置若干预设模板（NPC 朋友、虚拟朋友、中医、心理医生、律师、金融理财师等），每个模板自带系统提示词；用户可一键选用，也可完全自定义。
- **角色列表 / 编辑 / 删除**：用户只能管理自己创建的角色。
- 角色信息持久化于 MySQL。

### 3.3 模型配置（每角色独立）
- 每个角色可独立选择：
  - **LLM 来源**：本地（Ollama / vLLM，走 OpenAI 兼容 base_url）或云端 API。
  - **模型名**、**温度 / top_p / max_tokens** 等生成参数。
- 全局可提供默认模型配置，角色可覆盖。

### 3.4 知识库管理
- **支持格式**：纯文本（txt/markdown）、PDF、纯图片。
- **上传**：文件按角色归属，仅角色所有者可见。
- **解析与入库流程**：
  - 文本 / PDF → 提取文本 → 分块（chunk）→ 文本嵌入向量 → 写入 Milvus。
  - 图片 → 两条路径（见下）→ 写入 Milvus。
- **图片处理（双通道）**：
  1. **OCR 提取文字**：识别图中文字，按文本切片入 Milvus（文字向量检索）。
  2. **视觉向量**：整图生成视觉嵌入向量入 Milvus（支持「以图搜图 / 自然语言找图」）。
  - 视觉向量由**多模态 API**生成。
- **文件删除 / 重新索引**：删除角色知识库中的文件时，需同步清除 Milvus 中对应向量。
- 知识库索引与检索需带角色归属，保证角色间隔离。

### 3.5 对话（多轮 + 流式）
- **会话模型**：一个角色下可创建多个会话；每个会话有独立上下文窗口；会话之间、角色之间互不干扰。
- **多轮对话**：上下文由 Redis 短期记忆承载。
- **流式输出**：回答通过 SSE（Server-Sent Events）逐块返回，前端实时渲染。
- **每轮对话流程**：
  1. 读取该会话的短期记忆（Redis）。
  2. 对用户消息做知识库 + 长期记忆的向量检索（Milvus）。
  3. 组装系统提示词 + 检索上下文 + 短期记忆摘要 + 用户消息。
  4. 调用该角色绑定的 LLM，流式返回。
  5. 更新短期记忆；按需触发长期记忆沉淀（异步）。

### 3.6 记忆系统（双层）

#### 短期记忆（Redis）
- 每个会话保留固定条数（默认 20 轮）的对话记录。
- 策略：**固定条数 + 摘要压缩**——窗口满时，将最早内容压缩成摘要保留在窗口内，保证上下文长度可控且不丢要点。
- 摘要**只服务于当前会话窗口**（存 Redis，随会话生命周期管理）。

#### 长期记忆（Milvus）
- 组成：
  1. **知识库**：上传文件的向量切片。
  2. **对话记忆沉淀**：从对话中自动提炼的重要事实（如用户偏好、身份信息、关键结论）。
- **触发方式**：异步 + 阈值触发——后台检测，累积到一定量或识别到重要事实时提炼写入。
- 长期记忆与窗口摘要**职责分离**：摘要是会话内的上下文压缩，长期记忆是跨会话持久化的事实沉淀。
- 长期记忆同样带角色归属，隔离。

### 3.7 检索策略
- 每轮对话对「知识库」和「长期记忆」分别做相似度检索，结果**合并去重**后一起拼入提示词。
- 检索结果需包含来源信息，便于追溯与调试。

## 4. 技术栈与架构约束

| 组件 | 选型 |
|------|------|
| 后端框架 | FastAPI（Python） |
| 前端 | 纯 HTML + CSS + JS（由 FastAPI 静态托管） |
| 短期记忆 | Redis |
| 向量库 / 长期记忆 | Milvus（standalone） |
| 关系存储 | MySQL（用户、角色、会话元数据） |
| 文本 LLM | OpenAI 兼容协议（Ollama / vLLM / 云端 API 统一） |
| 文本嵌入 | OpenAI 兼容 embedding 接口 |
| 视觉嵌入 | 多模态 API（图片视觉向量） |
| 异步任务 | 后台任务队列（文档解析、记忆提炼） |
| 部署 | Docker Compose 一键启动 |

### 4.1 模型接入总览
三类模型，统一抽象层：
1. **文本 LLM**：OpenAI 兼容（本地 Ollama/vLLM 与云端 API 同协议，靠 base_url + api_key + model 区分）。
2. **文本 Embedding**：OpenAI 兼容接口。
3. **视觉 Embedding**：多模态 API（独立依赖，用于图片向量）。

### 4.2 数据隔离
- 所有数据以 `user_id` + `character_id`（角色）为隔离边界。
- Redis key、Milvus 集合/分区、MySQL 行记录均需体现归属。

## 5. 非功能需求

### 5.1 性能
- 支持几十~几百用户、千级文档规模。
- 文档解析、OCR、记忆提炼等重任务走异步队列，不阻塞对话接口。
- 对话首 token 延迟控制在可接受范围（具体指标待实现阶段定）。

### 5.2 安全
- 密码加密存储；JWT 鉴权。
- 接口需校验资源归属，防止越权访问他人角色/文件/会话。
- 上传文件需做类型与大小校验。
- API Key 等敏感配置需通过环境变量注入，不入库、不入前端。

### 5.3 可用性
- Docker Compose 一键启动，提供 `.env` 配置模板。
- 组件故障（如 Milvus 暂不可用）需有明确错误提示，不影响系统其余部分（降级策略后续迭代考虑）。

## 6. 关键决策记录（ADR 摘要）

| 决策点 | 结论 |
|--------|------|
| 用户形态 | 多用户 + 登录 |
| 长期记忆含义 | 知识库 + 对话记忆沉淀 |
| 本地模型接入 | Ollama 与 vLLM 都支持，走 OpenAI 兼容接口 |
| API 协议 | 仅 OpenAI 兼容 |
| 视觉嵌入 | 多模态 API |
| 知识库格式 | 纯文本、PDF、纯图片 |
| 图片处理 | OCR 文字 + 视觉向量（两者都要） |
| 前端 | 纯 HTML + JS（无框架） |
| 部署 | Docker Compose |
| 角色创建 | 预设模板 + 可自定义 |
| 模型配置 | 每角色独立 |
| 短期记忆策略 | 固定条数 + 摘要压缩 |
| 摘要 vs 长期记忆 | 摘要只留窗口内，记忆沉淀另提取 |

## 8. 验收标准（初版）

1. 用户可注册登录，创建/编辑/删除自己的角色。
2. 角色可从内置模板一键创建，也可完全自定义提示词。
3. 可上传 txt / pdf / 图片到指定角色，文件经解析后可在对话中被检索引用。
4. 同一角色下可开多个会话，会话间上下文互不干扰。
5. 对话支持多轮、流式输出。
6. 对话能被短期记忆（Redis）承载；窗口满时触发摘要压缩。
7. 对话中的关键事实可被异步提炼为长期记忆（Milvus），跨会话可检索。
8. 不同角色、不同用户之间的知识库、记忆、上下文完全隔离。
9. 模型可配置为本地（Ollama/vLLM）或云端 API，角色级独立设置。
10. 全系统可 Docker Compose 一键启动。
