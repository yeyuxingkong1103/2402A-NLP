# 优化报告

**工单编号：人工智能NLP-RAG-修复低质量工业PDF的解析与信息丢失工单**
**项目：工业专利（图片型 PDF）多模态检索问答系统**

---

## 1. 优化背景

工单任务二要求：针对 6 道测试题，在 RAGFlow 中测试运行结果，通过调整解析方法、分块策略、向量相似度权重、ReRank 模型等技术策略，把测试精度提升到 100%。

本系统在自研流水线上复现了同样的排错过程。初始版本在解析层修复后仍有多题作答错误，经过多轮定位与优化，最终 6 题全部正确。本报告记录每一处问题的现象、根因与修复措施。

---

## 2. 多轮测试与问题定位

### 2.1 初始状态

解析层修复（OCR + 附图语义）完成后，知识库已包含正文与附图语义块，但作答准确率仅约 50%（3/6）。错误集中在纯文本题与配气带孔盘相关题。

### 2.2 问题一：Q1 发明人题误判

**现象**：Q1「该静电除尘器的发明人是」预测为 C（静电除尘器研究小组），标准答案 A（P·吉特勒）。

**根因分析**：

- 评分使用字符 bigram **F1**，短选项「P·吉特勒」在长证据句中占比低，F1 被稀释；
- 干扰项 C 因包含「静电除尘器」这一高频词而获得更高的词面分，形成误判。

**修复措施**：

- 用 **`_coverage`（选项 bigram 在证据中的覆盖率 / precision）替代 F1**：短选项只要完整出现在证据中即得高分，不受证据句长度影响；
- 增强 `strip_noise`，剥离首尾虚词，保留「发明人」等核心检索词。

**效果**：Q1 得分 A=0.600 > C=0.459，作答正确。

### 2.3 问题二：Q2 特征描述题误判

**现象**：Q2「符合该静电除尘器特征的描述」预测为 B，标准答案 C。

**根因分析**：

- 选项 B 描述的是现有技术，选项 C 才是本发明特征，但两者字面相似度接近；
- 原评分只看字面与语义相似，无法区分「现有技术」与「本发明特征」的语境差异。

**修复措施**：引入**专利领域语境校正权重**：

- 证据中含「其特征在于 / 本发明 / 技术方案」等线索时，对该选项**加分**（`W_INVENTION = 0.30`）；
- 证据中含「现有技术 / 背景技术 / 已知 / 通常」等线索时**降权**（`W_PRIORART = 0.25`）。

**效果**：Q2 得分 C=0.799 > B=0.702，作答正确。

### 2.4 问题三：Q4 尺寸含义题误判

**现象**：Q4「X1/X2/X3 代表什么部件的间隔距离」预测错误。

**根因分析**：

- 配气带孔盘编号「6″、6′、6」中的撇号/引号在 OCR 后形态不一（`''`、`"`、`″`、`'`、`′`）；
- 题干中的 `6"` 与正文中的 `6''` 被判定为不同部件，导致匹配失败。

**修复措施**：

- 实现 `_canon_quotes` 统一撇号/引号：先合并两连撇号（`6'' → 6″`），再统一双撇号与单撇号；
- 在附图语义块中增强配气带孔盘的次序描述，使「6″、6′、6」作为整体出现。

**效果**：Q4 得分 A=0.556，作答正确。

### 2.5 问题四：Query 核心提取不完整

**现象**：检索精度不稳定，部分题目召回了弱相关块。

**根因分析**：噪声剥离后残留「的 / 是」等虚词，污染检索查询。

**修复措施**：增强 `strip_noise`，移除首尾虚词，保留「发明人」「部件 4 位置」等核心检索词。

**效果**：检索命中更集中，附图题稳定命中附图语义块。

### 2.6 问题五：证据溯源页码错位

**现象**：证据片段引用的页码/文本与实际知识块不一致。

**根因分析**：`_evidence` 函数误传 `ctx` 而非 `ctx.kb`，使用了上下文缓存的 chunk 而非原始知识库。

**修复措施**：修正调用为 `_evidence(ctx.kb, [best_detail.get("chunk_id", -1)] + ctx.chunk_ids[:4])`。

**效果**：证据溯源页码与文本对齐，溯源完整率 100%。

### 2.7 问题六：响应时间超过 3s

**现象**：单问响应时间约 4.46s，超过工单 3s 要求。

**根因分析**：

- 查询编码与选项编码各自发起一次 Ollama 嵌入调用；
- Ollama 每次嵌入调用有约 2.1s 固定开销，两次即约 4.2s。

**修复措施**：

1. **共享编码器**：检索与答案合成复用同一 `Embedder` 实例；
2. **合并批量编码**：把「主查询 + 扩展查询 + 6 个选项」合并为**单次** `encode_many_cached` 调用；
3. **编码缓存**：相同文本命中缓存后零开销；
4. **预热**：`warmup()` 提前加载分词 / 索引 / 编码器，避免首问冷启动超标。

**效果**：单问冷启动延迟从 4.46s 降至 2.34s（下降 47.5%），热缓存 0.02s，满足 ≤ 3s。

### 2.8 问题七：界面证据面板无法展开

**现象**：截图时点击证据面板展开后被 Streamlit 重渲染收起。

**根因分析**：React 渲染机制覆盖了 JS 操作。

**修复措施**：新增 `?expand=1` URL 参数，在 `app.py` 中通过 `expanded=expand` 默认展开全部证据面板。

**效果**：证据溯源面板可稳定展开，截图清晰呈现。

## 3. 优化措施汇总

| 类别 | 措施 | 关键参数 / 代码 |
|---|---|---|
| 解析 | OCR + 版面分析 + 附图语义解析 | `src/ocr_engine.py`、`src/figure_semantics.py` |
| 解析 | 部件名受控词表 + 最长优先匹配 | `figure_semantics._HEADS_SORTED` |
| 解析 | 附图方位水平优先判定 | `X_THRESH = 60`，`Y_THRESH = 90` |
| 解析 | 配气带孔盘按 x 坐标还原撇号 | `figure_semantics._disc_family` |
| 分块 | 结构感知切片 + 章节前缀 | `src/chunking.py`，`CHUNK_SIZE = 500` |
| 检索 | 三策略可切换 + RRF 融合 | `src/hybrid_retriever.py` |
| 检索 | 同义词扩展 | `config.SYNONYMS` |
| 重排 | 多信号线性融合，附图/页码加成 | `src/rerankers.py`，`W_FIGURE = 0.10`，`W_PAGE = 0.08` |
| 作答 | 覆盖率替代 F1 | `answer_builder._coverage` |
| 作答 | 发明语境加成 / 现有技术降权 | `W_INVENTION = 0.30`，`W_PRIORART = 0.25` |
| 作答 | 撇号/引号归一化 | `answer_builder._canon_quotes` |
| 性能 | 共享编码器 + 合并批量编码 + 缓存 | `qa_engine.ask()`、`embedding.encode_many_cached` |
| 界面 | 证据面板默认展开 | `app.py` 的 `?expand=1` |

## 5. 优化结论

通过解析层（OCR + 附图语义）、检索层（混合检索 + 多信号重排）、作答层（覆盖率 + 语境校正 + 符号归一化）、性能层（共享编码器 + 批量合并）四个维度的多轮优化，系统在 6 道测试题上达到 100% 准确率，单问响应时间降至 3s 以内，并保持完整证据溯源能力。工单任务二要求的多轮测试、原因分析与优化目标全部达成。

## 6. 调整后的实现代码

优化涉及的代码均在本交付的代码目录 `交付/工单代码/工单十四/研发/src/` 中，核心文件：

- `src/answer_builder.py`：`_coverage`、`_canon_quotes`、`_mcq_answer`、专利语境校正；
- `src/figure_semantics.py`：受控部件词表、水平优先方位判定、配气带孔盘次序还原；

- `src/embedding.py`：`encode_many_cached` 批量缓存；
- `src/config.py`：`W_INVENTION`、`W_PRIORART`、`W_FIGURE`、`W_PAGE` 等权重；
- `app.py`：证据面板默认展开。
