## 一、优化前基线的问题诊断

01 工单实现的基础 RAG 链路为：**PDF 直接抽文本 → 固定 500/80 字符递归切片 → 向量检索 + BM25 词法检索 → RRF 融合 → 本地大模型生成答案**。在 10 道验证题上实测存在四类问题：

| 编号 | 问题现象 | 根因分析 | 典型题 |
|---|---|---|---|
| P1 | 页眉页脚（"武汉兴图新科电子股份有限公司 招股意向书"）在几乎每页重复 | 未做版式清洗，噪声高频词稀释语义权重 | 全部题目 |
| P2 | 财务表格数值被切片截断，表头与数据分离 | 固定长度切片不识别表格边界 | Q260、Q33、Q207 |
| P3 | 检索结果"能召回但不准"，正确片段排位靠后 | 单路查询 + 仅靠 RRF 排名，未利用内容级匹配信号 | Q34、Q207 |
| P4 | 回答慢（平均 3.5 s，个别 >10 s）且存在数值张冠李戴的幻觉 | 本地 `deepseek-r1:1.5b` 属推理型模型，先输出长思维链再给结论 | Q260、Q33、Q957、Q531 |

**基线实测**：答案命中率 **60%（6/10）**，平均响应 **3.53 s**，最大 5.34 s。

---

## 二、优化总体思路

围绕"**让正确的片段排到前面、让答案直接从原文抽出来**"这一主线，在四个层面协同优化：

```
① PDF 解析处理  →  ② 分块  →  ③ 检索  →  ④ 答案合成
   去噪、结构化     结构感知    多路召回+重排   抽取式、可溯源
```

四个层面分别解决 P1、P2、P3、P4 四类问题，形成端到端的准确率与响应时间提升。

## 三、优化点 1：PDF 解析处理优化

**代码位置**：`src/pdf_parser.py`

| 措施 | 说明 | 解决的问题 |
|---|---|---|
| 版式清洗 | 统计跨页重复行，识别并剔除页眉/页脚（公司名+招股意向书、页码、罗马数字页码） | P1：噪声稀释语义 |
| 表格结构化 | 用 PyMuPDF 的表格识别能力把页内表格渲染为 Markdown，保留行列关系 | P2：数值与表头分离 |

| 章节标题识别 | 抽取"第X节 / 一、/（一）/ 1.1"等层级标题，作为结构化分块的锚点 | 为优化点 2 提供支撑 |
| 容错 | 单页文字/表格解析异常时降级跳过，不中断整体流程 | 稳定性 |

## 四、优化点 2：分块优化

**代码位置**：`src/chunking.py`

### 4.1 结构感知分块

先按标题把每页正文切分为**语义小节**，再在小节内做递归切片（700/120），避免跨小节"串味"。

### 4.2 表格原子块

表格整体作为一个不可切分的块（`ctype=table`），保证财务数据的行列完整。

### 4.3 父子块（Parent-Child）

| 角色 | 内容 | 用途 |
|---|---|---|
| 子块 | 小节内的小片段 | 参与向量/BM25 检索，**提升检索精度** |
| 父块 | 小节全文（截断 2000 字符） | 随子块一并返回，**补全上下文供答案抽取** |

检索时按父块去重，同一小节只保留得分最高的块，既保证多样性又避免重复。

### 4.4 过短合并 / 超长切分

小于 60 字符的片段合并，超长小节按递归分隔符切分，保证块粒度均匀。

## 五、优化点 3：检索优化

**代码位置**：`src/query_understanding.py`、`src/retriever.py`、`src/reranker.py`

### 5.1 查询侧：确定性 Query 理解（毫秒级，不依赖大模型）

- **噪声剥离**：剔除公司全称"武汉兴图新科电子股份有限公司""根据……招股意向书""报告期内"等套话，得到"核心问句"；
- **关键词抽取**：jieba 抽取实词并去停用词，保留年份/数字/单位；
- **答案类型识别**：数值型 / 比例型 / 金额型 / 实体型 / 列举型 / 是非型；
- **多路查询**：生成「核心问句 + 关键词组合 + 实体增强」三路查询并行召回。

> 关键作用：基线把整句问题丢给检索，公司名等高频词占据语义权重；剥离后"军用领域收入""注册资本"等真正关键的实词权重上升。

### 5.2 召回侧：双路召回 + RRF 融合

- 向量召回：`bge-m3:567m` + FAISS，取 Top-15；
- 词法召回：BM25Okapi（jieba 搜索引擎模式分词），取 Top-15；
- RRF（k=60）融合两路排名，得到候选集合。

### 5.3 重排侧：加权线性重排

对每个候选计算综合分：

```
score = 0.30·向量语义相似度(归一化)
      + 0.20·BM25 词法分(归一化)
      + 0.25·查询关键词覆盖率
      + 0.15·数值/年份匹配度
      + 0.10·实体匹配度
      (+ 0.03 表格块加成，当问题为金额/比例/数量型时)
```

其中"关键词覆盖率"有效抑制语义漂移，"数值匹配度"让含数字、单位、年份的片段上浮——金融问答的关键数据多藏于此类片段。

### 5.4 去重与上下文扩展

按父块去重后返回，最终保留 `TOP_K=6`；答案合成阶段再扩大候选池至 `ANSWER_POOL=25`。

## 六、优化点 4：答案合成优化

**代码位置**：`src/answer_builder.py`

### 6.1 为什么用抽取式

需求要求"准确率 ≥ 90% 且响应 ≤ 3 s"。本地可用的 `deepseek-r1:1.5b` 属推理型模型，回答前输出长思维链（基线平均 3.53 s、个别 >10 s），既慢又不稳定，且存在数值张冠李戴的幻觉。金融招股说明书问答的答案多为"原文中的事实句 / 表格行"，**抽取式合成可做到零幻觉、可溯源（附页码）、毫秒级返回**。

### 6.2 打分公式

从候选池（重排 Top-N 片段及其父块）中收集候选句 / 表格行，逐句打分：

```
s = 0.34·关键词覆盖率
  + 0.16·答案线索得分（按答案类型选择信号）
  + 0.09·实体匹配度
  + 0.09·定义式句式得分（关键词后紧跟"为/是/：/，/|"）
  + 0.05·表格行加成
  + 0.04·长度得分
  + 0.05·片段检索得分
  + 0.18·章节先验（公司基本信息类问题优先"概览/发行人基本情况"章节）
  - 0.20·对比词惩罚（问下游却召回上游、问军用却召回民用等）
  - 0.15·套话惩罚（保荐代表人/项目协办人/签署页等人名密集区）
```

### 6.3 关键设计

- **类型感知信号**：比例型看百分号、金额型看"万元/亿元"、列举型看"包括/涉及"与顿号密度、实体型看"为/是/："取值标记；
- **标题行剔除**：避免标题中的关键词造成误命中；
- **单页限流**：同一页最多取 2 句，保证答案多样性；
- **页码引用**：答案统一输出"根据招股说明书第 X 页、第 Y 页：……"，便于人工核对。

### 7.3 结论

1. 优化前的主要瓶颈不在"召回得到"（Top-K 召回率两者均 100%），而在"**排序不准 + 生成幻觉**"；本方案的重排与抽取式合成正是针对这两点。
2. 优化后答案命中率 100%，满足"≥ 90%"验收要求；平均响应 1.12 s、最大 2.18 s，满足"≤ 3 s"验收要求。
3. 优化后答案全部附带页码引用，可溯源、零幻觉。
