# 人工智能 NLP-RAG-RAG 性能瓶颈识别与优化

工单编号：人工智能 NLP-RAG-RAG 性能瓶颈识别与优化

## 一、任务描述

分析 Graph RAG 系统的性能瓶颈，优化到用户提问后 **3 秒内返回答案**，并给出优化前后对比。

## 二、性能剖析方法

对每个阶段独立计时：

| 阶段 | 说明 |
|---|---|
| embed | bge_m3 编码 query |
| vector | Chroma 向量召回 |
| bm25 | BM25 关键词召回 |
| graph | NetworkX 图扩展 |
| rerank | bge-reranker 重排 |
| llm | DeepSeek 生成答案 |

## 三、瓶颈识别

### 3.1 优化前耗时（6 题平均）

| 阶段 | 平均耗时 | 占比 |
|---|---|---|
| embed | 0.134 s | 5% |
| vector | 0.436 s | 17% |
| bm25 | 0.040 s | 2% |
| graph | 0.001 s | 0% |
| **rerank** | **0.867 s** | **34%** |
| **llm** | **1.065 s** | **42%** |
| **TOTAL** | **2.543 s** | 100% |

### 3.2 瓶颈定位

- **LLM 生成（42%）**：DeepSeek API 往返 + 长上下文
- **重排（34%）**：bge-reranker 交叉编码器 + 30 条候选
- 其余阶段（24%）：可忽略

## 四、优化方案

### 优化 1：LLM 生成

- 限制 `max_tokens=200`
- 上下文从 Top-5 降到 Top-3
- **答案缓存**：重复问题 0 秒返回

### 优化 2：重排

- 候选从 30 降到 15
- FP16 半精度推理
- **嵌入缓存**

### 优化 3：向量召回

- 减少 Top-K
- 嵌入缓存

## 五、优化前后对比

| 阶段 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| embed | 0.134 s | 0.157 s | -17.2% |
| retrieve | 0.476 s | 0.529 s | -11.1% |
| **rerank** | **0.867 s** | **0.751 s** | **+13.4%** |
| **llm** | **1.065 s** | **0.818 s** | **+23.2%** |
| **TOTAL** | **2.543 s** | **2.255 s** | **+11.3%** |

## 六、问题分析

### 6.1 首题冷启动

第 1 题 total 5.968 s，其中 retrieve 2.924 s，原因是 **Chroma 向量库首次加载到内存**。2~6 题 retrieve 均在 0.05 s。

### 6.2 稳定耗时

排除首题冷启动，优化后稳定 **1.4~1.8 秒**。

## 七、结论

1. 优化前平均 **2.543 s**，已达标 < 3 s。
2. 优化后平均 **2.255 s**，进一步降低 11.3%。
3. 主要瓶颈为 **LLM 生成（42%）+ 重排（34%）**，合计 76%。
4. 缓存机制让重复问题 0 秒返回。
5. 冷启动有 2~3 s 开销，可通过预热解决。

## 八、进一步优化方向

| 方向 | 预期效果 |
|---|---|
| LLM 流式输出 | 首 token 0.3 s（用户感知） |
| 本地小模型替代 DeepSeek | 省 API 往返 |
| 向量库常驻内存 | 消除冷启动 |
| Redis 缓存 | 分布式共享 |
