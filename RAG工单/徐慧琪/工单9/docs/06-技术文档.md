## 二、复用边界（关键设计取舍）

### 为什么「只读引用 08」而不是「复制 08 再改」

| 方案 | 08 目录 | A/B 可比性 | 是否满足「不另起炉灶」 |
| --- | --- | --- | --- |
| 复制改造 | 被复制一份，改的是副本 | ✅ | ⚠️ 易滑向重写 |
| **只读引用（本方案）** | **物理零改动** | ✅ 同一份语料 + 同一份向量索引 | ✅ 直接调用 08 的代码路径 |

实现：`w9/compat.py` 把 `../工单8` 挂到 `sys.path`，`import src` 精确解析到 08；
09 自己的代码放在独立包 `w9` 里，避免包名冲突。

**只读性由 `scripts/wo8_guard.py` 取证**：对 08 工程全树做
`(相对路径, 大小, mtime_ns)` 签名，跑完 09 后再比对，任何写入都会被指出。

> 实测踩坑（已修）：跑一次 08 基线会把 `工单8/data/index/fulltext.pkl`（31.7 MB）
> 重新持久化；Qdrant local 也会往存储目录写 `.lock` 与段文件。
> 09 通过在 config 层把这两个路径改写到 09 自己的 data 目录来解决 ——
> **改的是存储位置，不是算法**。

### Qdrant 索引为什么复制一份

Qdrant local 模式对存储目录加**排他锁**，两个进程共享会互斥。复制后：

- 08 目录真正只读；
- 09 可独立运行、独立压测；
- 副本与原件**逐字节相同**（`baseline08.qdrant_copy_hash()` 实测 sha256 一致，
  101,495,305 字节），不改变检索语义。

## 四、配置项（`w9/config9.py`）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `QUERY_DECOMPOSE_MAX` | 6 | 全局型问题的子查询上限（≤4 会漏掉参考答案的后几个侧面） |
| `GRAPH_FACTS_TOP_K` | 8 | 进入上下文的图谱事实条数（08 最多灌 60 条） |
| `FINAL9_TOP_K` | 8 | 进入上下文的文本块数 |
| `CONTEXT9_MAX_CHARS` | 5200 | 上下文总长预算 |
| `ENTITY_MIN_SCORE` | 0.85 | 低于此分的兜底实体不作检索种子 |
| `RERANK9_POOL` | 40 | 统一精排的候选池大小 |
| `GEN9_NUM_PREDICT` | 640 | 生成 token 上限 |
| `RESPONSE_BUDGET_S` | 3.0 | 响应时间预算（硬性要求） |
| `FUSION_WEIGHTS_BY_QTYPE` | 见文件 | 按问题类型的自适应融合权重 |

## 五、开发流程

```bash
# 0) 模型扫描（硬性要求0，必须先做）
python scripts/scan_local_models9.py --json --report

# 1) 08 只读性基线快照
python scripts/wo8_guard.py snapshot

# 2) 构建 09 图谱（08 第1层 + 第2层合并，六道闸门）
python -m w9.kg_merge

# 3)（可选）Prompt v2 定向补抽
python -m w9.kg_extract_v2 --limit 200

# 4) 评估（08 基线 vs 09 优化）
python -m w9.run_eval --set main --systems wo08,wo09 --ragas core

# 5) 生成对比报告
python -m w9.compare

# 6) 只读性复核（应输出「逐字节未变」）
python scripts/wo8_guard.py verify

# 7) 健康检查
python -c "from w9.runtime9 import health_check; import json; print(json.dumps(health_check(), ensure_ascii=False, indent=2))"
```

## 七、二次开发提示

1. **改 Prompt**：编辑 `w9/prompts/*.yaml`（带 mtime 缓存，改完自动重载）。
   08 的 Prompt 仍可从 `工单8/prompts/` 读到（未优化的沿用），
   查找顺序见 `w9/prompts_loader.py`。
2. **改检索参数**：`w9/config9.py` 的 `FUSION_WEIGHTS_BY_QTYPE`、
   `GRAPH_FACTS_TOP_K`、`FINAL9_TOP_K` 等。
3. **换裁判模型**：`w9.ragas_eval.evaluate(judge_model=...)`；
   若换更强的模型，可关掉 `adapt_prompts_for_small_judge` 用官方提示。
4. **加评测题**：改 `data/sample_questions.json` 或 `data/test_questions.json`。
