# 性能测试报告

- 工单编号：人工智能NLP-RAG项目-LightRAG优化
- 测试对象：招股说明书多轮检索问答系统（传统 RAG / LightRAG）
- 测试时间：2026-10-09
- 数据来源：`output/latency_bench.json`（真实运行结果）
- 验收指标：**从用户提问到返回答案 ≤ 3s**

---

## 1. 测试方法

对 16 道验收问题，分别测量两套系统的**端到端耗时**（提问 → 检索 → 答案生成），并区分两种口径：

- **冷启动（cold）**：每题前**对称清空**查询编码缓存（最坏情况，等价于首次遇到该问法）；
- **热缓存（warm）**：连续重复同一问法（缓存命中，耗时下界）。

> 冷/热口径必须对两套系统**对称清理**：RAG 侧清 `HybridRetriever._vec_cache → VectorRetriever.Embedder._cache`；LightRAG 侧清 `LightRAGRetriever._qcache + Embedder._cache`，否则冷/热不可比。

```bash
python tools/bench_latency.py            # RAG + LightRAG
python tools/bench_latency.py --systems rag
python tools/bench_latency.py --systems lightrag
```

---

## 2. 测试结果

### 2.1 冷启动（最坏情况）

| 系统 | 平均 | P50 | P95 | 最大 |
|---|---|---|---|---|
| 传统 RAG | 2.33s | 2.34s | 2.57s | 2.57s |
| **LightRAG** | **2.21s** | 2.20s | 2.26s | 2.26s |

### 2.2 热缓存（下界）

| 系统 | 平均 | P95 |
|---|---|---|
| 传统 RAG | 0.059s | 0.144s |
| **LightRAG** | **0.042s** | 0.063s |

### 2.3 结论

- 两系统冷启动平均耗时**均 < 3s**（RAG 2.33s / LightRAG 2.21s），满足验收要求；
- LightRAG 冷启动平均比 RAG **快约 0.12s（≈5%）**，P95 更稳定（2.26s vs 2.57s）；
- 热缓存下 LightRAG 平均 0.042s，优于 RAG 的 0.059s。

---

## 3. 耗时构成与优化点

| 环节 | 说明 | 优化 |
|---|---|---|
| 查询向量化 | 调用 Ollama 嵌入（固定 HTTP 开销） | **多路查询一次性批量编码**（`_batch_qvecs` → `encode_many_cached`），降单次调用开销 |
| 图召回 | 实体/关系/主题向量点积 + 一跳扩展 | 限制邻接宽度（`LR_NEIGHBOR_LIMIT=12`），避免巨节点稀释 |
| 全文召回 | BM25 | 倒排索引内存检索，毫秒级 |
| 重排 | 线性多信号融合 | 与 RAG 同款重排器，口径一致 |

> 嵌入向量化是端到端耗时的主要来源（约占冷启动 2.2s 中的绝大部分）；批量编码后，多路查询（原查询 + 改写 + 同义词扩展）只需一次 Ollama 调用。

---

## 4. 稳定性

- 连续 50 轮问答无异常（TC-09）：平均 0.15s，最大约 2.2s（含一次冷启动）；
- 会话重置后状态正确清理（TC-10）；
- 无内存泄漏迹象（进程工作集稳定）。
