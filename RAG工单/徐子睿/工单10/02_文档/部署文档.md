# 工单 10 · 金融问答系统部署（Docker）

> **工单编号**：人工智能NLP-RAG-金融问答系统部署任务
> **目标**：把「Graph RAG 金融问答系统」容器化部署，提供可复现的启动方式与验证手段。

---

## 一、部署架构

```
┌──────────────────────── 宿主机 / 服务器 ────────────────────────┐
│  ┌────────────────── Docker ──────────────────┐                 │
│  │  finqa-api  (python:3.11-slim + uvicorn)   │                 │
│  │   ├─ app/*.py   (FastAPI + RAG/Graph RAG)  │                 │
│  │   ├─ /data  ← 挂载宿主机 ./data            │                 │
│  │   │    data/index（向量+BM25 索引）        │                 │
│  │   │    data/graph（知识图谱）              │                 │
│  │   └─ 端口 8100                             │                 │
│  └──────────────────────┬─────────────────────┘                 │
│                         │ OLLAMA_BASE=http://host.docker.internal:11434
│  ┌──────────────────────▼─────────────────────┐                 │
│  │  Ollama（bge-m3 嵌入 / qwen2:7b 生成）      │                 │
│  └────────────────────────────────────────────┘                 │
└─────────────────────────────────────────────────────────────────┘
```

- **镜像只装服务端运行期依赖**（fastapi/uvicorn/pymupdf/jieba/numpy）；`mineru`（解析）与建库/建图是**离线步骤**，不打进镜像。
- 索引与图谱作为**数据卷**挂载（`/data`），换语料只需重建，不用重打镜像。
- 嵌入/生成走外部 **Ollama**，可用 `OLLAMA_BASE` 指向宿主或独立 GPU 机器。

## 二、文件清单
| 文件 | 作用 |
|---|---|
| `Dockerfile` | 构建 API 镜像（python:3.11-slim） |
| `requirements-docker.txt` | 运行期依赖（不含 mineru） |
| `docker-compose.yml` | 一键起服务（端口映射、数据卷、extra_hosts） |
| `.dockerignore` | 排除索引/语料/venv，减小构建上下文 |

## 三、启动步骤
```bash
cd /d D:\桌面\徐子睿工单二

# 1) 首次：离线建索引 + 建图谱（宿主机，需本机 Ollama）
python app/build_kb_txt.py
python app/graph_build.py

# 2) 构建镜像
docker build -t finqa-graphrag:1.0 .

# 3) 启动（挂载数据卷 + 指向宿主 Ollama）
docker run -d --name finqa-api -p 8100:8100 \
  -e OLLAMA_BASE=http://host.docker.internal:11434 \
  --add-host host.docker.internal:host-gateway \
  -v "%cd%/data:/data" \
  finqa-graphrag:1.0
#   或：docker compose up -d
```

## 四、部署验证
```bash
curl http://localhost:8100/api/health
curl -X POST http://localhost:8100/api/ask -H "Content-Type: application/json" \
     -d "{\"query\":\"平安银行2019年实现营业收入和净利润分别是多少？\"}"
```
- 健康检查：镜像内置 `HEALTHCHECK`（访问 `/api/health`）；
- 浏览器访问 `http://localhost:8100/` 打开问答界面。

## 五、常见问题
| 现象 | 原因 | 处理 |
|---|---|---|
| `/api/health` 显示 `llm.ok=false` | 容器访问不到 Ollama | 用 `--add-host host.docker.internal:host-gateway`；Linux 下改用宿主真实 IP |
| 返回“知识库未就绪”/ 0 块 | `/data` 未挂载或索引缺失 | 确认挂载 `-v .../data:/data`，先跑 `build_kb_txt.py` |
| 首问慢（10–30s） | 模型冷启动 | 预热一次；或给 Ollama 常驻 |
| 端口占用 | 8100 被占 | 改 `-p 8101:8100` |

## 六、生产化建议
- 反向代理（Nginx/Caddy）+ HTTPS；限制请求体与并发；
- GPU 机器上把 Ollama 与 API 分容器部署，`OLLAMA_BASE` 指向 GPU 容器；
- 用 `docker compose` 的 `deploy.resources` 限制 CPU/内存；给 `/data` 做定期备份；
- 日志集中（`docker logs` → ELK/Loki），并保留 `/api/feedback` 的用户反馈用于重排自适应。
