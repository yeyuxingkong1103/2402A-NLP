## 1. Python API

### 1.1 构造引擎

```python
from app.graphrag.config import get_config
from app.graphrag.engine import GraphRAGEngine

cfg = get_config()                       # 读环境变量 GRAPHRAG_* / RAG_*（阈值全部可覆盖）
engine = GraphRAGEngine(cfg=cfg, warmup=True)   # 加载 工单7 索引 + 图谱（进程内缓存）
```

`GraphRAGEngine` 的关键属性：

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `engine.cfg` | `GraphRAGConfig` | 配置树（含全部阈值） |
| `engine.graph` | `GraphStore` | 内存图谱（节点 / 边 / 邻接表 / 名字索引 / 块元信息） |
| `engine.llm` | `GraphLLM` | Ollama 客户端（生成 + 关系补抽） |

### 1.2 问答（主接口）

```python
answer = engine.answer(
    "平安银行2019年年度报告中，该行2019年实现营业收入和净利润分别是多少？",
    top_k=10,          # 返回的命中条数（判定口径，默认取配置 10）
    use_graph=True,    # False = 纯向量+BM25（消融口径）
    language="auto",   # auto | zh | en
    use_llm=True,      # False = 抽取式兜底
)
answer.to_dict()
```

**返回结构（`GraphAnswer`）**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `question` | str | 原问题 |
| `answer` | str | 生成的答案（失败时为抽取式原文） |
| `refused` | bool | 是否拒答（本工单不启用拒答闸门，恒为 `False`；字段保留以对齐 工单7 契约） |
| `language` | str | `zh` / `en` |
| `generation_method` | str | `graph_llm`（Ollama 生成）/ `extractive_fallback`（兜底）/ `error` |
| `backend` / `model` | str | `ollama` / `qwen2.5:3b` |
| **`evidence_chunks`** | list[dict] | **答案所在文本块**（进生成阶段的证据，≤`prompt_top_k + page_context_extra`） |
| `all_chunks` | list[dict] | 全部召回命中（Top-K，含图谱独有块） |
| `graph` | dict | **图谱结构缩略**（见 §1.4） |
| `graph_used` | bool | 本次是否命中图谱实体（`False` = 图谱通道未参与） |
| `latency_ms` | dict | `{retrieve, graph, generate, total}`（毫秒，实测） |
| `diagnostics` | dict | 诊断明细（见 §1.5） |
| `trace_id` | str | 追踪号 |

**`evidence_chunks` / `all_chunks` 的单条结构**：

```json
{
  "chunk_id": "20200214-p5-x1",
  "page": 5,
  "page_basis": "1-based-physical",
  "file_name": "2020-02-14__平安银行股份有限公司__000001__平安银行__2019年__年度报告.pdf",
  "type": "text",
  "text": "业务结构不断优化…（原文）",
  "score": 4.469539,
  "base_score": 4.469539,
  "graph_bonus": 0.055,
  "graph_distance": 0,
  "graph_entities": ["平安银行", "营业收入"],
  "retrieval_channel": "base+graph"
}
```

`retrieval_channel` 取值：`base`（纯基础召回）/ `base+graph`（基础召回且被图谱加分）/ `graph_only`（**图谱独有**，基础通道未召回）。

### 1.3 只检索（不生成）

```python
result = engine.retrieve(question, top_k=10, use_graph=True)
# → {"question", "hits", "hits_raw", "graph", "graph_used", "analysis",
```

### 1.4 图谱结构缩略（`graph` 字段）

```json
{
  "seed_names": ["平安银行", "营业收入", "净利润"],
  "distances": {"company:平安银行": 0, "metric:营业收入": 0, "company:中国平安": 1},
  "distances_named": {"平安银行": 0, "营业收入": 0, "中国平安": 1},
  "nodes": [{"id": "company:平安银行", "name": "平安银行", "type": "company",
             "type_zh": "公司", "distance": 0, "degree": 37}],
  "edges": [{"head": "中国平安", "relation": "持股", "tail": "平安银行", "confidence": 0.71}],
  "edge_total_used": 18
}
```

整体图谱概览用 `engine.graph.to_public_dict()`（默认 120 节点 / 240 边 + 类型与关系统计）。

### 1.5 诊断字段（`diagnostics`）

| 键 | 说明 |
| --- | --- |
| `base_hits` | 基础通道召回条数 |
| `graph_hits` | 图谱通道候选块数 |
| `graph_only_in_topk` / `graph_only_ids` | 进入 Top-K 的**图谱独有块**（图谱扩展增量的直接证据） |
| `graph_slots` | 本次使用的交错名额（默认 `[2,5,9]`） |
| `graph_displaced` | 被图谱独有块替换下去的基础命中（`position` / `chunk_id` / `page` / `score`） |
| `graph_rejected_irrelevant` | 被相关性闸门挡住的图谱候选 |
| `graph_seed_names` | 问句命中的图谱实体名 |
| `graph_nodes` / `hop` / `graph_truncated` | 命中节点数 / 跳数 / 是否被 `max_expand_nodes` 截断 |
| `distances` | 前 30 个命中实体的跳数 |
| `graph_ms` / `total_ms` | 图谱扩展耗时 / 检索总耗时 |

### 1.6 健康检查

```python
engine.health()
# → {"status": "ok"|"degraded",
#    "checks": {"interpreter", "index", "graph", "llm"},
#    "config": {"hop", "top_k", "prompt_top_k", "graph_dir", "index_dir"}}
```

### 1.7 图谱存储 API（`GraphStore`）

| 方法 | 说明 |
| --- | --- |
| `resolve(name)` | 实体名/别名 → `node_id`（先精确、再大小写无关） |
| `match_names(text, min_len=2, limit=40)` | 从问句匹配实体（长名优先） |
| `neighbors(node_id)` | 邻居列表 `[(邻居 id, 关系名, 边下标)]` |
| `expand(seeds, hop=2, max_nodes=40, min_confidence=0.55)` | BFS 一跳/两跳扩展 |
| `chunks_of(node_id, limit=12)` | 实体的提及块（含页码/文件名） |
| `to_graph_json()` | 完整图谱 JSON（节点 + 边 + schema + 统计） |
| `to_public_dict(max_nodes=120, max_edges=240)` | 图谱缩略（UI/截图用） |

## 2. 命令行接口

### 2.1 图谱构建

```powershell
pwsh -NoProfile -File run_py.ps1 研发/scripts/build_graph.py `
     [--limit-chunks 0] [--include-tables] [--llm-sample 400] [--llm-model qwen2.5:3b] [--out-dir <dir>]
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--limit-chunks` | 0（全量 7430） | 只处理前 N 块（调试/抽样） |
| `--include-tables` | 关 | 是否把表格块纳入抽取 |
| `--llm-sample` | 配置值（400） | Ollama 抽样补抽块数，`0` = 关闭 |
| `--llm-model` | `qwen2.5:3b` | 补抽模型 |
| `--out-dir` | `研发/data/graph` | 产物目录 |

退出码：`0` 成功 / `2` 抽取阶段异常 / `3` 判分或索引不可用。

## 3. HTTP 接口（纯标准库，端口 8124）

### 3.1 `GET /`

返回单页界面（HTML），一屏展示：问题输入框 → 图谱结构（节点 + 关系 JSON 缩略）→ 检索结果（Top-K 命中块）→ 答案。

### 3.2 `POST /api/ask`

请求：

```json
{"question": "招商银行2019年营业收入是多少？", "lang": "auto", "top_k": 10, "use_graph": true}
```

响应（`GraphAnswer.to_dict()` + `cited_pages` 兼容字段）：

```json
{
  "question": "...",
  "answer": "…(带 [块1] 标注)",
  "language": "zh",
  "generation_method": "graph_llm",
  "backend": "ollama",
  "model": "qwen2.5:3b",
  "evidence_chunks": [{"chunk_id": "...", "page": 7, "file_name": "...", "text": "..."}],
  "chunks": [...],
  "graph": {"seed_names": [...], "nodes": [...], "edges": [...]},
  "graph_used": true,
  "latency_ms": {"retrieve": 148.2, "graph": 6.4, "generate": 1203.1, "total": 1361.7},
  "diagnostics": {"graph_only_in_topk": 3, "graph_displaced": [...]}
}
```

错误响应（HTTP 400/500）：`{"error": {"code": "E_...", "message": "..."}}`

| 错误码 | 触发条件 |
| --- | --- |
| `E_PARAM_QUESTION_EMPTY` | `question` 为空或长度 > 500 |
| `E_PARAM_TOP_K_RANGE` | `top_k` 非整数或越界 |
| `E_INTERNAL` | 引擎未预期异常（带 `trace_id`） |

### 3.3 `POST /api/retrieve`

只检索不生成：请求同 `§3.2`，响应为 `engine.retrieve()` 的结果（不含 `answer`）。

### 3.4 `GET /api/graph`

返回图谱概览（`graph_digest`：节点/边总数、类型分布、关系分组分布、Top-120 子图）。
查询参数 `?top=120&edges=240` 可调规模。

### 3.5 `GET /api/questions`

返回内置示例问题（含 1 道英文题），供界面一键填充。

### 3.6 `GET /health`

返回 `engine.health()`（索引 / 图谱 / Ollama 三项状态 + 配置摘要）。
