# 优化方案设计

> 工单编号: 人工智能 NLP-RAG-基于 PDF 文档的问答系统优化
> 对比基线: 工单1 (人工智能 NLP-RAG-基于 PDF 文档的问答系统)

## 一、优化目标

| 指标     | 工单1基线 | 工单2优化目标 | 提升幅度 |
| -------- | --------- | ------------- | -------- |
| 问答准确率 | ~60-70%   | ≥ 90%         | +20-30%  |
| 响应时间   | ≤ 3s      | ≤ 3s          | 持平     |
| 检索方式   | 单路 TF-IDF | 混合检索       | 质的飞跃 |
| 分块策略   | 固定字符数 | 语义感知分块     | 质变     |

## 二、工单1问题诊断

### 2.1 分块策略问题
工单1采用固定 500 字符切块,导致:
- 表格被切割成碎片,数据丢失
- 段落在语义中间被切断,上下文不完整
- 标题与内容分离,检索匹配困难

### 2.2 检索策略问题
工单1仅使用 TF-IDF + 余弦相似度:
- TF-IDF 是词袋模型,不理解语义 ("收入" 和 "营收" 无法关联)
- 单一检索方式容易漏召回
- 无重排序,Top-K 结果质量参差不齐

### 2.3 Query 理解问题
工单1仅做关键词匹配与消歧:
- 无查询扩展 (同义词补充)
- 无英文支持
- 无意图驱动的检索策略调整

## 三、优化方案

### 3.1 分块优化 (pdf_parser_v2.py)

**核心改进: 语义感知分块**

1. **按段落切分**: 先按换行符/句号切为段落,而非固定字符数
2. **动态块大小**: 短段落合并 (< 200 字符),长段落拆分 (> 800 字符)
3. **表格独立处理**: 提取 PDF 表格后转为结构化文本块 (行/列独立)
4. **标题识别**: 识别 "第X章"、"一、二、三、" 等标题模式,标题独立为块
5. **保留页号**: 每个块记录原页码,便于溯源

```
原流程: PDF → 整页文本 → 固定500字符切块 (碎片化严重)
新流程: PDF → 段落切分 → 表格独立提取 → 标题识别 → 动态合并/拆分 → 语义块
```

### 3.2 检索优化 (vector_retrieval_v2.py)

**核心改进: BM25 + TF-IDF 混合检索 + Rerank**

1. **BM25 关键词检索**: 引入 BM25 (Okapi Best Matching), 对精确关键词匹配效果好
2. **TF-IDF 向量检索**: 保留工单1的 TF-IDF 作为语义补充
3. **混合融合**: `final_score = 0.5 * bm25_score_norm + 0.5 * tfidf_score_norm`
4. **可选升级**: sentence-transformers (bge-small-zh) 作为第三路, 替换 TF-IDF
5. **Rerank**: 用简单的交叉特征 (如 query 关键词覆盖率) 重排序 Top-20 → Top-5

```
原流程: query → TF-IDF → 余弦相似度 → Top-5
新流程: query → BM25 (Top-20) + TF-IDF (Top-20) → 融合去重 → Rerank → Top-5
```

### 3.3 Query 增强 (query_enhancement.py)

**核心改进: 查询扩展 + 多语言支持**

1. **同义词扩展**: 金融/招股说明书领域同义词字典
   - "收入" → "收入 营收 营业额", "占比" → "占比 比重 比例"
2. **关键词加权**: 识别问题核心实体, 在检索时提升其权重
3. **多语言支持**: 英文问题 → 关键词映射 → 中文检索
4. **检索策略选择**: 根据意图类型选择检索参数
   - 财务数据类: 降低阈值, 扩大 Top-K
   - 公司信息类: 提高阈值, 精准匹配

### 3.4 Prompt 优化 (llm_client_v2.py)

**核心改进: 检索结果格式化 + 答案约束**

1. **表格数据格式化**: 检索到表格块时以 Markdown 表格形式展示
2. **多片段融合**: 将 5 个检索片段按相关性排序后拼接
3. **答案格式约束**: 要求 LLM 先给出明确答案, 再引用数据来源
4. **无答案时返回 "文档中未找到相关信息"** (而非编造)
