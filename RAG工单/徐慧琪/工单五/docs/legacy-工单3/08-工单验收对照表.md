### 唯一确为不完整的题目：id 95

- **问题**：参与制定了哪个技术标准？
- **参考答案**：全军第一个视频指挥系统技术标准，即《某视频指挥系统技术规范（1.0版）》，
  由军事科学院牵头，联合数据通信科学技术研究所、北京大学共同制定
- **系统答案**：视频指挥系统技术标准（即《某视频技术规范 1.0》）

  后文写《某视频指挥系统技术规范（1.0版）》并由军事科学院牵头。
  模型检索到概览页并**逐字引用**，答案本身不是编造，但不如后文完整。

## 七、性能验收

### 7.1 响应时间（单用户，14 题实测）

| 指标 | 数值 |
| --- | --- |
| 平均 / 中位 | 1.35s / 1.13s |
| P95 / 最大 | 1.75s / 1.88s |
| **≤3 秒占比** | **100%**（14/14） |
| 对比上游基线 | 工单01/02 基线 4.54s（≤3s 占比 0.71） |

### 7.2 响应时间（并发，禁用缓存实测）

| 并发数 | 墙钟 | 单请求平均 | 最大 | 失败 |
| --- | --- | --- | --- | --- |
| 2 | 2.3s | 2.02s | 2.31s | 0 |
| 4 | 5.6s | 4.32s | 5.58s | 0 |
| 8 | 9.0s | 7.35s | 8.95s | 0 |

**结论**：并发 ≥4 时单请求超过 3 秒——GPU 推理天然串行，请求在显存上排队。
**系统不崩溃、无错误、无丢失**（"高并发下稳定运行"达标），但"≤3 秒"仅在并发 ≤2 时成立。
若要支撑更高并发，需增加算力（更大显存/多卡）或引入请求队列 + 明确的排队提示。

### 7.3 资源消耗

| 资源 | 实测 |
| --- | --- |
| 显存 | 6.9 GB / 8.2 GB（bge-m3 + reranker + qwen2.5:3b 三者常驻） |

| 已知约束 | 8G 显存接近上限，故 `rag.warmup` 分阶段加载并在加载前主动让 Ollama 释放显存 |
