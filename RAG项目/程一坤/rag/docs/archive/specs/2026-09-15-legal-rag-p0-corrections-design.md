# 法律 RAG 第一阶段 P0 修复设计

## 1. 目标与范围

本阶段只修复会导致测试套件无法完整运行、采集首次请求必然失败、法律条文错切以及跨文档块 ID 冲突的问题。目标是在不引入 MySQL、Redis、Milvus 新依赖的前提下，恢复当前本地代码链路的基本正确性，并为后续持久化和分布式限速保留清晰接口。

本阶段包含：

- 测试运行配置与共享测试替身整理；
- 采集器首次请求的限速行为修复；
- HTML 块级换行保留；
- 法律条文边界限制为真实条文起点；
- 跨文档稳定且不冲突的 `chunk_id`；
- 针对上述缺陷的回归测试。

本阶段不包含：

- Redis 分布式限速；
- MySQL 采集记录和文档版本落库；
- 子块 token 长度与 overlap 重构；
- PDF 解析架构调整；
- Embedding 分批、重试和适配器目录迁移；
- Docker、Redis、Milvus 安装。

## 2. 当前问题

### 2.1 测试收集失败

`tests/unit/test_runner.py` 从 `test_requester.py` 导入 `FakeResponse`，使测试文件之间形成运行时依赖。当前 `backend` 缺少 pytest 配置，完整收集可能出现 `tests.unit` 导入失败。

### 2.2 首次页面请求被限速拦截

`requester.fetch()` 首先读取 `robots.txt`，而 `_get_robots_policy()` 使用同一个来源限速器记录请求时间。页面请求紧随其后检查限速，因此在正间隔配置下必然失败。

本阶段采用“robots 读取不占页面访问限速窗口”的方案：robots 缓存只负责规则读取，页面请求仍由来源级限速器控制。这样既修复首次采集，也避免引入同步等待导致的测试和调用方行为变化。后续 Redis 分布式限速阶段再统一设计等待和跨进程协调。

### 2.3 条文引用被误识别为新条文

当前条文正则使用零宽匹配且不限制位置，正文中的“依照第五十条规定”会被当成新条文起点。修复后只接受行首的条文号，并要求条文号后存在空白分隔符。

### 2.4 HTML 解析丢失块级换行

当前 HTML 提取器以空格拼接文本片段，导致段落和条文边界消失。修复后，块级标签开始或结束时写入换行，最终使用连续换行压缩保留可用于条文切分的边界。

### 2.5 块 ID 跨文档冲突

当前父块 ID 从 `parent-1` 开始，子块 ID 依赖父块 ID，多个文档会生成相同 ID。修复后由文档来源生成稳定前缀，再拼接条文和段落序号。来源路径在当前阶段作为临时文档标识；接入 MySQL 后由持久化 `document_id` 替换，但 `chunk_document()` 的调用接口保持可扩展。

## 3. 设计方案

### 3.1 测试基础设施

新增 `backend/pytest.ini`：

- `pythonpath = .`，保证从 `backend` 目录执行时可以导入 `app`；
- `testpaths = tests`，限定测试发现范围。

新增 `backend/tests/unit/conftest.py`，放置跨测试复用的 `FakeResponse` 和白名单构造辅助。测试文件通过 fixture 或从 conftest 自动发现使用，不再互相导入。

保留测试数据在内存和 pytest 临时目录中，不写入正式 `data` 目录。

### 3.2 页面限速与 robots

`OfficialPageRequester` 继续在页面请求前校验白名单和 robots 规则。读取 robots 时不调用页面访问限速器的 `record_request()`；页面真正发出前检查并记录一次来源页面请求。

这样在 `minimum_interval_seconds > 0` 时：

1. 首次读取 robots；
2. 首次页面请求立即允许并记录；
3. 同一来源下一次页面请求仍遵守最小间隔；
4. robots 已缓存时不再发起 robots 请求。

本阶段不改变 `SourceRateLimiter` 的同步 API，不引入 `sleep`。当页面请求未达到间隔时，仍返回明确失败记录；主动等待和最大等待时间属于后续限速设计。

### 3.3 条文切分

使用多行模式，仅在行首识别条文号，条文号支持中文数字、阿拉伯数字以及 `之一`、`之二` 等扩展形式。条文号后必须为普通空白或全角空格，避免把正文中紧邻其他文字的引用误识别为边界。

由于该策略依赖换行，HTML、TXT、Markdown 和 PDF 的清洗/解析出口必须保留有效换行。条文引用回归测试至少包含：

- 三个真实条文；
- 第一条正文引用另一个条号；
- 另一条正文引用第三个条号；
- 断言最终仅生成三个父块，且条号顺序正确。

### 3.4 HTML 换行

在 `_HtmlTextExtractor` 中定义块级标签集合，覆盖段落、标题、列表、表格、`div`、`section`、`article` 和换行标签。块级标签产生换行，行内标签不额外制造段落边界。

`get_text()` 使用空字符串拼接片段，然后将连续换行压缩为单个换行并去除首尾空白。HTML 回归测试验证两个 `p` 标签能生成两个行首条文，且解析结果可以直接交给条文切分器。

### 3.5 块 ID

为 `chunk_document()` 增加可选的文档标识参数；未传入时根据规范化 `source_path` 生成稳定前缀。ID 规则为：

- 父块：`{document_key}-a{article_index}`；
- 子块：`{document_key}-a{article_index}-c{paragraph_index}`。

`document_key` 只允许稳定、可序列化的安全字符；不同来源路径必须产生不同前缀，同一来源重复分块必须产生相同 ID。现有调用方不需要立即改动，后续 MySQL 文档实体可显式传入数据库 `document_id`。

回归测试使用两个不同来源文档，断言 ID 集合无交集；再对同一文档重复分块，断言 ID 集合一致。

## 4. 错误处理

- 测试配置错误应在测试收集阶段直接暴露，不通过运行时兜底隐藏；
- robots 请求异常仍按当前采集失败路径记录，不在本阶段改变 robots `404/410` 语义；
- 页面限速未满足时继续返回失败记录，错误消息保持明确；
- 条文无法识别时保留当前文档级父块回退行为；
- HTML 空内容仍返回空文本，不生成虚假条文；
- 文档标识为空或无法生成安全前缀时使用确定性的哈希前缀，不使用随机值。

## 5. 测试策略

按 TDD 顺序实施，每个问题先补回归测试并确认旧实现失败，再修改最小实现使其通过。

测试分组：

1. 测试收集：从 `backend` 运行完整 `tests/unit`，不再出现 collection error；
2. 采集限速：正间隔下首次 robots + 页面请求成功，后续页面请求仍受限；
3. 条文切分：正文条号引用不产生额外父块；
4. HTML 解析：块级标签保留换行，条文可被正确切分；
5. 块 ID：跨文档无冲突，同文档重复执行稳定；
6. 回归验证：现有单元测试全部通过。

## 6. 后续衔接

本阶段完成后，下一阶段优先处理主动等待/Redis 分布式限速、robots `404/410` 语义、请求重试、下载大小上限和版本状态持久化。所有后续改动必须继续保持：官方来源约束、真实数据与测试数据隔离、API Key 不进入代码和测试输出。
