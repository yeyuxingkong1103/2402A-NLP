## 1. 第一层：Prompt 构建实体 / 关系层面（图谱质量）

### 1.1 现状

工单8 用「正则 + 词典 + 少量 Ollama 补抽」从 7430 个文本块抽出 9817 实体 / 4861 关系，
落盘为 `entities.jsonl` / `relations.jsonl`（schema 版本 `graphrag-fin-1.0`）。

### 1.2 问题（**逐条都是实测现象**）

| # | 现象 | 实测证据 | 危害 |
| --- | --- | --- | --- |
| P1 | **同一实体分裂**：`何肖`(count=1) 与 `何肖锋` 同时存在 | `entities.jsonl` 第 1 例反查 | 实体链接时两条都是弱节点，谁都锁不住语料 |
| P2 | **公司全称/简称并存**：`平安银行` 与 `平安银行股份有限公司` 各自成节点 | 归并组样例（`优化/评估结果`） | 图谱被同一主体稀释 |
| P3 | **通用刻度噪声占枢纽位**：`2020年度` count=**593**、`2021年12月31日` count=**528** | 工单8 `entities.jsonl` 前 2 行 | 这类日期/比例几乎每页都有、度极大但零信息量，两跳扩展会把整张图拉进来 |
| P4 | **抽取碎片成实体**：`是指本集团` / `当本集团` / `如果本集团` / `之后深发展吸收合并原平安银行` | 剪除样例 | 噪声实体污染实体链接与可视化 |
| P5 | **关系方向/类型未校验**：`head_type`/`tail_type` 与 schema 约束不一致时无人纠正 | 工单8 `relations.jsonl` 字段 | 图遍历方向错，邻居不是真邻居 |
| P6 | **自环与重复边**：head == tail 的边、同 (head,relation,tail) 多条 | 优化统计 | 度数虚高、扩展浪费预算 |

### 1.3 方案（`研发/app/graphrag_opt/抽取层.py`）

四个阶段，全部**配置化**（`配置.py::DEFAULTS["extract"]`）：

1. **别名归并**（`merge_aliases` + `merged_entities`，并查集）
   - **R1 公司/机构后缀剥离**：`平安银行股份有限公司` ≡ `平安银行`；
   - **R2 人名前缀补全**：`何肖` → `何肖锋`（长度差 ≤ `person_prefix_len_diff`、被并入者提及更少）；
   - **R3 数值写法归一**：`2020 年度` ≡ `2020年` ≡ `2020年度`；
   - 规范名取「提及数最多、平手时更长」的写法；被并入的写法进 `aliases` 供实体链接回溯。
2. **关系方向与类型规范化**（`normalize_relations`）
   - 关系名归并到 schema 规范名（复用 `schema.RELATION_ALIASES`）；
   - **方向校验与自动反转**：`head_type/tail_type` 与 `schema.RELATION_TYPES` 的 head/tail 集合比对，
     反了就反转并计数；两者都不合法则保留但记录进 `方向无法判定样例`；
   - 自环剪除、非法关系剪除、同三元组去重（保留最大置信度 + 累计 `support`）。
3. **噪声剪枝**（`prune_noise`）
   - **通用刻度**：`ratio` 类型里数值 ≤ `uninformative_ratio_max` 的**整数**百分比直接剪
     （0% / 1% / 5% / 10% 是财务表格通用刻度）；`date/ratio/amount` 类型 count >
     `max_doc_ratio × 扫描块数` 且 ≥ `min_absolute_count` 时剪（命中 `2020年度` 593 次、`2021年12月31日` 528 次）；
   - **抽取碎片**：公司/机构名长度 > `fragment_max_len`(16)，或含**句级连词/指示词**
     （之后/同受/其中/上述/本集团/如果…），或含并列连词（和/与/及）且长度 ≥ 12 或出现 ≥2 次；
   - **孤立节点**：度 0 且仅出现 1 次；
   - **度数上限**：`max_degree`。
4. **置信度过滤**：实体 `min_confidence` 0.55 → **0.60**；每实体提及块 6 → **4**（扩展更省时）。

> ⚠️ **两条实测踩坑（都已写进代码注释，避免后人重犯）**：
> 1. **边置信度下限不能提**。把 `min_edge_confidence` 从 0.55 提到 0.60 会剪掉
>    2628/4861 = **54%** 的边（工单8 的 `rule_cooccur` 同句共现边正好是 0.55），
>    平均度数反而从 0.9903 掉到 **0.6514** —— 图更碎了。正确做法：保留边，把剪枝压力放节点侧。
> 2. **并列连词不能一律当碎片标记**。第一版把「和/与/及」一律判碎片，误剪 774 个实体，
>    其中包括「审计与风险管理委员会」「薪酬与考核委员会」这类**真实机构**。
>    改成「长度 ≥12 或同连词出现 ≥2 次」后才正确。

### 1.4 效果（`研发/data/图谱优化后/图谱优化统计.json`）

| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 节点数 | 9817 | **6717** | −31.6% |
| 边数 | 4861 | **3807** | −21.7% |
| **平均度数** | 0.9903 | **1.1335** | **+14.5%**（连通性提升） |
| 别名归并组数 | 0 | **104** | 208 个实体被并入规范名 |
| 规范关系覆盖率 | — | **100%** | 全部关系都在 schema 内 |
| 自环剪除 | — | 12 | |
| 重复边合并 | — | 24 | |
| 抽取碎片剪除 | — | **1249** | |
| 孤立节点剪除 | — | **1745** | |

## 2. 第二层：检索层

### 2.1 现状

工单8 的检索链路：`问句 → 基础召回(向量+BM25→RRF→轻量重排) → 图谱一跳/两跳扩展 → score = base_score + graph_bonus → Top-K`。

### 2.2 问题

| # | 现象 | 实测证据 | 危害 |
| --- | --- | --- | --- |
| P7 | **图谱通道形同虚设** | `base_score`（重排 final_score）≈ 4.x，`graph_bonus` ∈ [0.022, 0.06]，**量纲差两个数量级**；17 题里「图谱独有块进 Top5」= **0** | 图谱白建 |
| P8 | **固定 2 跳 + 先到先得截断** | `hop=2`、`max_expand_nodes=40` 是 BFS 顺序截断 | 已点名公司时两跳带进**别家公司**年报（Q07 实测：中国平安 p7 / 招商银行 p7 / 国泰君安 p4 挤掉 p19/p44 表格） |
| P9 | **无查询改写 / 实体链接** | 仅用 `name_index` 子串匹配 | 简称、别名、字段词都没用上 |
| P10 | **无候选裁剪与两段式重排** | 基础召回多少就融合多少 | 噪声候选直接进上下文 |
| P11 | **不做上下文扩展** | `page_context_extra=0` | 答案所在页的**同类兄弟块**进不了上下文，召回上不去 |

### 2.3 方案（`研发/app/graphrag_opt/检索层.py`）

链路升级为：

```
问句
 → ① 查询改写（实体别名 + 字段锚点 + 英中术语；确定性，零额外耗时）
 → ② 实体链接（图谱词典最长匹配，长名优先 + 热度次优）
 → ③ 基础召回（复用 工单7：bge-m3 向量 + BM25 → RRF → 轻量重排），base_k=20
 → ④ 图谱扩展（**自适应跳数** + 邻居按「置信度 × 度数倒数」剪枝 + 跨语料闸门）
 → ⑤ 融合（**min-max 归一化后加权**：base 0.62 / graph 0.23 / feature 0.15）
 → ⑥ 重排裁剪（裁到 14 条 → 按问句实词命中率重排 → top_k=10）
 → ⑦ 同页上下文扩展（焦点页簇）
 → ⑦' 字段锚点召回（按问句里的每个财务字段词/章节词定点捞块）
 → ⑧ 证据选取（14 条；去重 → 焦点页配额 → 锚点配额 → 补足）
```

**关键设计逐条**：

- **⑤ 归一化加权融合**（取代量纲不可比的直接相加）
  ```
  nb = minmax(base)；ng = graph / max(graph)；nf = feature（已归一）
  final = 0.62·nb + 0.23·ng + 0.15·nf
  ```
  `feature` = 0.5·实体命中率 + 0.3·跳数衰减 + 0.2·节点度数倒数（信息密度）。
  权重全部在 `部署/配置/优化配置.json` 的 `retrieval.fusion_weights`，**可调、可审计**。

- **④ 自适应跳数 + 邻居剪枝**：问句已锁定语料 ⇒ 降到 **1 跳**（防跨公司污染）；
  邻居按 `confidence × 1/log(2+degree)` 排序截断（取代 BFS 先到先得）——度数极高的
  `本集团`/`2020年度` 类节点邻居信息量低，而度数 2 的 `逾越者联盟` 邻居信息量高。

- **⑦ 焦点页簇补全**（**本工单提升上下文召回的关键一步**）
  实测诊断（`_页内块`）：国泰君安 p4 的答案要点「连续14年获得A类AA级监管评级」在 **p4-x1**，
  招商银行 p5 的 4 个要点在 **p5-x1**，它们都因「问句实词命中少、加权分低」被挤出上下文 ——
  **同页兄弟块互相挤掉**。修正：锁定「融合后 Top-N 命中所在页」，
  把这些页上的块优先放进上下文（年报同一页讲的通常就是同一件事）。

- **⑦' 字段锚点召回**（**上下文召回的主要来源**）
  按问句里出现的**每个财务字段词/年报章节词**（`FIELD_TERMS` + `DOMAIN_TERMS`）
  定点捞「含该词且附近有数字」的块。依据：问「营业收入/净利润/不良贷款率/拨备覆盖率」时，
  Top-K 只能带回营业收入所在的 p19，p44 的拨备覆盖率永远进不来 —— 召回卡在 0.77。

- **通道配额**：焦点页与字段锚点各有名额（7 / 5）。
  ⚠️ 实测踩坑：不加配额时焦点页会**吃光全部 14 个名额**（4 页 × 6 块 = 24 > 14），
  锚点块一块也进不来，跨文档题召回只有 0.143。

- **证据去重**：候选池由四个通道合并，同一 `chunk_id` 会重复出现；
  不去重时 14 个名额被重复块吃掉（实测 Q03 的 `-p43-x1`/`-p5-x1` 各占 2 席）。

- **英文提问的中文术语并入实词表**
  ⚠️ 实测踩坑（Q13 的根因）：英文问句的实词表是 `According/Postal/net/profit…`，
  在中文年报块上一个都匹配不到 ⇒ `lexical_score` 全 0 ⇒ 所有候选同分 ⇒ 排序退化为
  **按 chunk_id 字典序**，锚点捞回的 p18（含 `610.36亿元`/`16.52%`）被字典序更小的 p104/p105 顶掉。

**被实测否决的方案（如实记录，配置里保留了开关可复现）**：

| 方案 | 实测结果 | 结论 |
| --- | --- | --- |
| 对比题放开字段锚点的语料闸门（`probe_hint=None`） | 全局精度 0.8025 → **0.7395** | 否决，保留闸门 |
| 锚点页兄弟块扩展（`probe_expand`） | 精度 0.8025 → 0.7437，召回 0.8739 → 0.8655 | 否决，默认关闭 |
| `min_edge_confidence` 0.60 | 平均度数 0.99 → 0.65 | 否决，回到 0.55 |

## 3. 第三层：生成层

### 3.1 现状

工单8 的生成：`证据块 → 确定性草稿 → LLM 润色 → 数值原子保全护栏`，**每题都调 qwen2.5:3b**。

### 3.2 问题

| # | 现象 | 实测证据 | 危害 |
| --- | --- | --- | --- |
| P12 | **生成层占 96.7% 的时间** | 3946.94 / 4080.41 ms | SLA ≤3 s 达标率仅 **29.41%** |
| P13 | **图谱三元组没进 prompt** | 工单8 `ANSWER_PROMPT` 只有「证据块」 | 图谱价值无法直达生成层 |
| P14 | **无引用约束** | 答案里没有块号 | 用户无法核对 |
| P15 | **无拒答护栏** | 证据不足也硬答 | 编造风险 |

### 3.3 方案（`研发/app/graphrag_opt/生成层.py`）

1. **图谱三元组结构化注入**（`build_triples_block`）
   把局部子图渲染成 `head --关系--> tail（置信度；来源块）` 的结构化区块，
   与证据块并列进 prompt。三元组给出的是**结构化的字段↔数值绑定**，
   比让 3B 模型自己在 420 字长文里找对应关系更稳（也降低它改写数字的概率）。

2. **引用约束**（`compose_answer`）：每条结论后带 `[块N]`，并在答案末尾给 `【引用】公司 第N页`。

3. **拒答护栏**（`refusal_guard`）：证据块数 < 阈值，或证据与问句实词的**总重叠数** < 阈值
   ⇒ 返回标准拒答文案（中/英），不硬答。

4. **模板化落地生成（快路径，SLA 的关键）**（`template_confidence` + `compose_answer`）
   当确定性草稿满足「长度 ≥ 阈值 ∧ 含 ≥1 个数值原子 ∧ 覆盖 ≥1 个问句实词」时，
   **直接用「草稿 + 关键数据 + 图谱依据 + 引用」组装答案，跳过 LLM** ⇒ 生成耗时 ≈ **0 ms**。

   > **诚实性声明**：快路径不是「不生成」，而是**抽取式 / 模板式生成**
   > （extractive + template grounded generation）：答案的每一句都**逐字来自证据原文**，
   > 且带块号引用，不编造任何内容。唯一省略的是「把已有句子改写得更自然」，
   > 而工单8 的实测恰好表明这一步正是**数字被改写的来源**（原子保全护栏拦下的就是它）。

5. **LLM 慢路径预算压缩**（`llm_polish`）：仅当快路径置信度不足时启用，
   `num_ctx` 2048→**1536**、`num_predict` 380→**200**、每条证据进 prompt 的字符数 420→**220**。

### 3.4 效果

见 `优化/评估结果/优化前后对比.md` §二（响应时间对比）与 §三（答案质量）。
生成方式分布（`生成方式分布` 字段）会如实列出快/慢路径各命中多少题。
