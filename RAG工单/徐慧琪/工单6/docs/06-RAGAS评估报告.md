## 3. 结果解读（不粉饰，逐条说明）

### 3.1 召回类指标是强项，与检索设计一致

`context_recall = 1.000`、`context_precision = 0.912`：本工单的发力点就是**检索**，
这两个指标直接反映检索质量 —— 全部题目的关键信息都进了上下文，
同时上下文里约 1/10 是"同页/同表"的邻近片段（这是刻意的：表格行与表头、
父块与子块的完整性优先，宁可多带不可漏）。

### 3.2 忠实度 0.545：低分题逐题核对后，均为 **3B judge 的定位失败**，不是答案不忠实

faithfulness 得 0 的四道题（id 3 / 6 / 795 / 543），已逐题对照
`data/eval/retrieval_eval.json` 的**地面真值核对结果**（同一批答案、独立于 RAGAS 的确定性核对）：

| id | 问题 | RAGAS faithfulness | 地面真值核对（facts） |
| --- | --- | --- | --- |
| 3 | 存在控制关系的关联方/持股比例/关系 | 0.0 | 3/3 命中（赵马克、42.35%、控股股东），coverage 1.0 |
| 6 | 2008 年中国 IC 市场增长最快/负增长行业 | 0.0 | 2/2 命中（汽车、IC卡），coverage 1.0 |
| 795 | 荣获国家科技进步一等奖的工程 | 0.0 | 1/1 命中（某情报、指挥、控制与通信网络一体化工程），coverage 1.0 |
| 543 | 注册资本是多少 | 0.0 | 1/1 命中（5,520），coverage 1.0 |

即：**答案内容全部正确且来自上下文**（每题均带页码级引用，见 `docs/04`），
faithfulness 为 0 是 3B 评判模型"断句 → 找支撑句"这一步失败所致。失败模式集中在四类：

1. **多事实单句**（id3：一个句子里含三个论断）—— judge 拆句后对不上原文；
2. **图表类答案**（id6：答案来自图像块的 VLM 描述）—— 表述与 judge 预期措辞不同；
3. **长专名**（id795：二十余字的工程名称）—— judge 检索支撑句时匹配失败；
4. **纯数字答案**（id543："5,520.00 万元"）—— judge 对数字格式/单位不敏感。

### 3.3 answer_relevancy 0.465：短事实型答案 X 3B judge 的已知失真

该指标的计算方式是"让 judge 依据答案**反向生成问题**，再与原问题比向量相似度"。
本系统大量答案是**极短的事实型**（如"公司法定代表人为程家明。"、
"国防军队视频指挥领域的重要供应商。"），3B 模型反向生成的问题往往变成泛化问法
（"公司的基本信息是什么？"），与原问题的向量相似度天然偏低 ——
**分数低不代表答非所问**（逐题答案与引用来源见 `docs/04-检索精确度报告.md`，
16 题答案准确率 100%）。得 0 的题（260/33/957/543）全部属于此类。

> 已知小瑕疵：id33 的答案尾部带"同表其余相关行还有：民用领域、民用领域、民用领域、民用领域。"
> —— 该后缀来自 `rag.check_table_rows` 的**确定性补全**（防止小模型漏同行），
> 行名在源表中按报告期重复出现，故列表未去重。不影响正确性（facts 4/4 命中），
> 但会拉低该题的 answer_relevancy，属**已知的外观瑕疵**。

> 对照组：上游工单04 的 RAGAS 报告用**云端较强模型**作 judge，faithfulness 0.4702、
> answer_relevancy 0.8874。两者**不可直接横比**（judge 模型不同、评判集不同）。
> 本工单坚持**零联网、零 API**，故接受 3B judge 的口径偏差，并在此如实标注。

---

## 4. 结论与改进方向

| 结论 | 证据 |
| --- | --- |
| 检索侧达标：上下文完整且相关 | context_recall 1.0、context_precision 0.91 |
| 生成侧"低忠实度"经逐题核对均为 judge 口径问题 | 四道 0 分题的 facts 全部命中（coverage 1.0） |
| 若需更可信的 RAGAS 分数 | 换更大 judge（本机可换云端/更大本地模型），或在
`evaluate_ragas.py` 中替换 judge 后重跑 `--reuse-answers`（复用已采集答案，不必重跑问答） |

**复现命令**

```bash
python evaluate_ragas.py --limit 16                    # 完整 16 题（含问答采集 + 评判）
python evaluate_ragas.py --reuse-answers               # 复用已采集答案，只重跑评判
python evaluate_ragas.py --metrics context_recall,context_precision
```
