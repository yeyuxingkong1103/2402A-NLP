# 工单16 微调方案设计说明

**工单编号**：人工智能NLP-RAG-微调专用视觉语言模型
**目标**：让视觉语言模型适应工业专利文档，提升**工业术语准确性**与**图纸推理能力**

---

## 一、目标与约束

工单要求用 IMDR 数据做领域适应，验收看「工业术语准确性提升 ≥5%」。

**硬约束是显存**：本机 GPU 为 RTX 3060 Laptop，**6GB**。这决定了后面几乎所有取舍
—— 基座模型选多大、要不要量化、图像放多大、batch 能开多少。

---

## 二、基座模型选型

| 候选 | 权重体积 | 6GB 可行性 |
|---|---|---|
| Qwen2.5-VL-3B | 7.5GB | 4-bit 后约 2GB，训练时激活吃紧，风险高 |
| **Qwen2-VL-2B** | **4.4GB** | 4-bit 后约 1.2GB，**可行** |
| SmolVLM-500M | 1GB | 能跑，但 2B 都未必够用，更小的学不动 |

选 **Qwen2-VL-2B-Instruct**：工单点名的就是 Qwen-VL 系列，2B 是这块卡上能真正
训完的最大规格。

---

## 三、数据构造

### 3.1 图像取什么

IMDR 的题面常写「在文件中**第7页**的图片中，部件4相对于部件5…」，所以
**图像就是那一页渲染出来的 PNG**（140 DPI）。这一条直接由题面里的页码决定，
不需要额外标注。

另一路数据来自 RAGFlow 解析出的图纸块（工单14/15 的知识库），配成
「请描述这张技术图纸 → 那段 VLM 描述」的样本。

### 3.2 训练/评估必须**按文档**切分

同一份专利出 6 道题。若按题随机切，同一页图会同时出现在训练集和评估集里，
模型「见过」那张图，评估是虚高的。所以：**60 份文档进评估集，另外 152 份进训练集**。

### 3.3 训练集的选项顺序必须打乱

**这是本方案里最关键的一条设计，代价也最大（一开始没做）。**

IMDR 的选项位置是固定的，正确答案落在 B 的占 43%。不打乱的话，模型会去学
「答案多半在 B」这个**位置先验**而不是读图 —— 实测训出来的模型 B 的准确率
从 69% 涨到 85%，而 **D 的准确率从 28% 掉到 0%**。把训练集选项打乱后，
这份「提升」立刻归零。

所以：**训练集打乱选项并改写答案字母；评估集保持原顺序不动**（评估要忠于数据集）。

### 3.4 术语指标的抽取

「专业术语准确性」要求把标准答案里的**工业术语**抽出来比对。IMDR 有一半的题
在问「谁在谁的哪边」，答案本身就是 `位于编号12的部件之内` 这类方位描述，
不是术语 —— 拿它当术语评等于在测另一个能力。

处理：加方位词表过滤，命中的归到「图纸推理正确性」，剩下的 151 条才是术语型题。

## 四、LoRA 结构设计

### 4.1 4-bit QLoRA

Qwen2-VL-2B 的 bf16 权重就要 4.4GB，加上激活和优化器状态在 6GB 上放不下。
用 nf4 4-bit 量化后权重约 1.2GB，配合 `prepare_model_for_kbit_training` 即可训练。

### 4.2 视觉塔必须一起训

**沿用「训文本模型时冻结底层」的习惯会直接失败。** 只给语言侧挂 LoRA 时，
模型能改善的只有「用什么词回答」，改善不了「看得准不准」，于是就走位置先验
这条捷径（见 3.3）。

所以视觉塔的注意力投影（`qkv` / `proj`）也挂 LoRA：

| | 语言侧 | 视觉侧 |
|---|---|---|
| target_modules | `q_proj/k_proj/v_proj/o_proj/gate_proj/up_proj/down_proj` | `qkv` `proj` |
| 模块数 | 196 | 65 |
| 说明 | peft 传列表时按**叶子名**匹配；`qkv`/`proj` 只有视觉塔在用（语言侧叫 `q_proj`/`o_proj`），不会误伤 | 视觉塔的 `blocks.N.attn.*`；`patch_embed.proj` 会被顺带带上，参数量可忽略 |

可训练参数 22.4M，占全模型 1.0%。

### 4.3 显存预算

三项措施叠起来才装得下：

| 措施 | 省下 |
|---|---|
| 权重 4-bit 量化 | 4.4GB → 约 1.2GB |
| 梯度检查点 | 激活重算换显存 |
| `max_pixels` 压到 451584（约 672×672） | Qwen2-VL 默认把图放到 `1280×28×28`，一张 A4 图纸能吃 2GB |

实测峰值 **5.9GB / 6.1GB**。另外必须设
`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` —— 默认分配器在这个水位会碎片化，
实测第 40 步左右 OOM，之后每步从 96 秒退化到 336 秒。

## 五、超参

| 参数 | 值 | 理由 |
|---|---|---|
| LoRA r / alpha | 16 / 32 | 600 条样本的规模，再大容易过拟合 |
| lr | 1e-4 | QLoRA 的常规起点 |
| 调度 | 线性衰减到 0，warmup 3% | 小数据量下比余弦更稳 |
| batch × 累积 | 1 × 8 | 单步能塞下的最大有效批量 |
| epochs | **2** | 1 轮时 loss 到收尾仍在降（6.80→6.67），2 轮是实测最好的 |
| max_length | 1536 | 题面 + 选项 + 答案通常不到 800 token |

损失只算在**答案**上（题面部分 mask 成 -100），否则模型会去学复述题面。

## 六、评估设计

三层指标，对应工单的三条要求：

| 指标 | 怎么算 | 对应 |
|---|---|---|
| `term_acc` | 标准答案里的工业术语是否出现在输出里 | a) 专业术语准确性（验收看这个） |
| `drawing_acc` | 图文题（group 2/3）的选项是否答对 | b) 图纸推理正确性 |
| `bleu` / `rouge_l` | 字符级 4-gram BLEU（带简短惩罚）、ROUGE-L F1 | 文本重合度 |

BLEU/ROUGE 都自己实现（中文按字算 n-gram）—— 不引第三方包，
免得再碰这个项目里深度学习库互相锁版本的老问题。

**基线与微调模型必须在同一图像分辨率下评测**。中途因为开了视觉塔 LoRA 把
`max_pixels` 从 602112 收到 451584，基线也重新测了一遍，保证可比。

## 七、预期与实测

| | 设计预期 | 实测 |
|---|---|---|
| 术语准确性 | ≥5% | **+5.96%** ✅ |
| 图纸推理 | 有提升 | **−1.28%** ✗ |

图纸推理这一项没涨，原因是**分辨率**：要在整页图纸里找到某个编号、再判断它挨着谁，
而图像压到约 672×672 后小号数字标注已经糊了。这是 6GB 显存下的取舍代价，
改进方向写在 `测试/评估报告.md` 第五节（换更大的卡提分辨率，或按题面里的编号
做局部高分辨率裁剪）。
