### 0.2 2026-10-10 重测（有效）

对 `results/raw_20261009_204719.json` **原样重打分一遍**（问题/答案/contexts/reference 逐字未改，只重跑判官），`scripts/measure_noise.py` → `results/noise_reread.json`：

## 1. 已实施优化①：页眉页脚模板过滤（建库期）

### 1.1 做法

`app/ingest.py::parse_pdf()` 在分块前对每一页正文做一次模板清洗：

- **只看每页头尾各 4 行**（页眉页脚必在页边，而"合计""不适用"等高频词出现在表格中部，不能被误判）；
- 去掉空白后长度 8–40 字（页眉常被拆成多条短行，不能用"整行匹配"——首版要求"行首恰好 24 字"对邮储银行**剔了 0 条**，是自检抓出来的）；
- 某行在语料中出现次数 ≥ `max(8, 页数 × 25%)` 即判为模板，逐行剔除。

### 1.2 实测效果（确定性指标，`scripts/analyze_retrieval.py`）

| 项 | 基线 `eval_20261009_194604.json`（未过滤，5747 块） | 优化 `eval_20261009_204719.json`（过滤后，5660 块） |
|---|---|---|
| 建库分块数 | 5747 | 5660 |
| **模板噪声片段** | **23/80 = 28.7%** | **5/80 = 6.2%** |
| 目标文档命中 | 9/9 | 9/9 |
| 目标页命中 | 7/9 | 7/9 |

### 1.3 RAGAS 对照（判据：是否超过 §0.2 的噪声底 0.027）

| 指标 | 基线 194604 | 优化 204719 | Δ | 是否超噪声底 |
|---|---|---|---|---|
| Faithfulness | 0.9167 | 0.9150 | −0.0017 | 否 |
| Answer Relevancy | 0.7812 | 0.7910 | +0.0098 | 否 |
| Context Recall | 0.7467 | 0.7475 | +0.0008 | 否 |
| Context Precision | 0.7848 | 0.7580 | −0.0268 | 否（≈噪声底 0.0272） |

### 1.4 诚实结论（本节最重要）

1. **确定性层面：过滤把模板噪声从 28.7% 砍到 6.2%——幅度大且可复现。**
2. **指标层面：四项 RAGAS 全部落在噪声底内，测不出改善。** 原因：模板片段不与问题语义竞争（用户问题里不会出现"财务报表附注"这句话），大模型本来就会忽略它们；**其价值在健壮性**（少浪费 token、少被模板词误导的风险），不在分数。
3. **⚠ 一个自我服务偏差的自觉**：模板噪声率与过滤器共用"行首/行边"这一判据，**该指标的下降有一部分是"按定义"必然发生的**，不能单独当作优化成效的证据。真正独立的交叉验证是 §1.3——而它显示指标没动。**两句话一起读才成立：过滤让噪声少了，但没让答案变好。**
4. Context Precision 的 −0.0268 **是噪声**，不是"过滤让精确度变差"：同一份输入重打分时，CP 自己就从 0.758 漂到 0.7852（§0.2）。**不得**把这 0.027 解读为退化。

**保留与否**：**保留**。理由：零额外成本、无副作用（目标文档/页命中不降）、降低 token 浪费与误命中风险；但**不声称它有指标收益**。

## 2. 已实施优化②：参数实测台（零 API 成本）

### 2.1 为什么要另造这把尺子

第三步的 RAGAS 受生成措辞与判官同源偏差影响、且有噪声底。判断"调参到底有没有用"，需要一个**确定性、可复现、不花钱**的检索质量尺子。

`scripts/sweep_retrieval.py`：只跑检索（本地模型 + GPU，**不调用任何大模型**），口径与 `analyze_retrieval.py` 完全一致，并**在跑配置前先用已知正例/反例自检尺子**（自检未通过则直接中止、不产出结论）。

自检输出（实测）：
```
尺子自检: 通过 {'正例_Q05_招商银行': True, '反例_假公司假页': (False, False)}
```
——正例（Q05 招商银行）判为命中、反例（伪造公司+伪造页）判为不命中，**全过/全拦**，尺子可用。

### 2.2 配置扫描结果（`results/sweep_retrieval.json`）

| 配置 | 目标文档 | 目标页 | 模板噪声 | 目标公司占比 | 均首条重排分 |
|---|---|---|---|---|---|
| **当前 0.7/0.3 top8** | 9/9 | 7/9 | 5/80 | 0.653 | **0.868** |
| 向量加权 0.85/0.15 top8 | 9/9 | 7/9 | 5/80 | 0.667 | **0.868** |
| 均衡 0.5/0.5 top8 | 9/9 | 7/9 | 7/80 | 0.667 | **0.868** |
| 关键词加权 0.3/0.7 top8 | 9/9 | 7/9 | 7/80 | 0.681 | **0.868** |
| **top6** 0.7/0.3 | 9/9 | 7/9 | **4/60** | **0.685** | **0.868** |
| **top10** 0.7/0.3 | 9/9 | **8/9** | 7/100 | 0.667 | **0.868** |

「目标公司占比」= 单文档题里 8 条片段中来自**目标公司**的比例（衡量"多答了别的公司"的杂音；Q04 跨文档不计）。

### 2.3 两个发现

**发现 A｜融合权重在本语料上不是有效杠杆。**
`VEC_WEIGHT/BM25_WEIGHT` 从 0.7/0.3 调到 0.85/0.15、0.5/0.5、0.3/0.7，**首条重排分恒为 0.868、目标文档命中恒为 9/9**，目标公司占比只在 0.653–0.681 间摆动。
**根因**：重排模型在融合后的 top-30 上**重新排序**，把融合阶段的次序差异抹平了——融合只决定"进不进候选池"，最终次序由重排决定。
**结论：本语料上不必继续调融合权重**（此前"调权重"是常见直觉，此处用实测否掉）。

**发现 B｜`RERANK_TOP_N` 是有效杠杆。**
- `top6`：文档/页命中不变，目标公司占比升到 **0.685（全表最高）**，上下文条数 −25%（token 更省、噪声更少）；
- `top10`：目标页命中 **7/9 → 8/9**（找回了 Q10 期望的国泰君安 p.16/17），但占比降到 0.667、模板噪声最多（7/100）。
**结论**：**默认建议 `RERANK_TOP_N=6`（更省更净、指标不降）**；仅在需要覆盖边角页时用 10。该结论**已由本表实测支持**。

## 3. 剩余问题归因（哪些是系统的账，哪些不是）

### 3.1 同名校实体混淆（**系统的账**，本轮新发现的主要短板）

**证据**：单文档题的平均「目标公司占比」只有 **0.65**；最差两题——Q03（平安银行）**0.12**、Q01（平安银行）**0.25**——8 条片段里只有 1–2 条真的来自平安银行。

**根因**：语料里**同时存在中国平安(601318) 与平安银行(000001)**，且中国平安的年报里大量披露其子公司平安银行的经营数据。因此问"平安银行"时，中国平安的年报片段在语义和关键词上**都与问题高度相关**，重排也无法把它们压下去。

**这直接解释了 Q01/Q02 为什么"多答了几家公司"**——不是模型乱答，是**检索阶段就把母公司的片段一起召回了**，且有原文支撑。

#### 3.1.1 方案③「实体约束检索」实测（`scripts/entity_filter_probe.py`，2026-10-10）

做法：题面识别出主体公司 → 在 Milvus 加 `code == X` 过滤 + BM25 只在该公司分块上打分 → 再融合重排。
探针先自检（实体识别器 **正例必识别、反例不误识别**；`focus_of` 也有正例自检——**这个自检当场抓到一个真 bug**，见下方 ⚠）。

| 题 | 主体识别 | 目标公司占比 前→后 | 来源变化 |
|---|---|---|---|
| Q03 | 000001 | **0.12 → 1.00** | 中国平安+平安银行 → 平安银行 |
| Q05 | 600036 | 0.62 → 1.00 | +平安/邮储 → 仅招商银行 |
| Q06 | 601658 | 0.62 → 1.00 | +平安/招商 → 仅邮储银行 |
| Q10 | 601211 | 0.88 → 1.00 | +招商证券 → 仅国泰君安 |
| Q08 / Q09 | 600030 / 601628 | 1.00 → 1.00 | 不变（本就纯） |
| **Q01/Q02/Q04** | **未识别** | — | **过滤不触发**：题面是 `xx银行` / 泛称，**没有公司名可识别** |
| **Q07** | **歧义** | — | 题面同时含「中国平安」与「平安银行」→ 识别器拒绝（保守，**宁可不过滤**） |

**触发的 6 题：占比均值 0.708 → 1.000。**
**但 4/10 题根本不触发——而 Q01/Q02 恰恰是最需要它的两题。** 这是方案③ 的硬边界：
**元数据过滤只能救"题面点得出公司名"的题**；题面含糊的题救不了，那属于**查询澄清（query clarification）**的范畴，不在本工单边界内。

> ⚠ **自检抓到的 bug（值得记录）**：`focus_of` 首版按 `h["code"]` 统计占比，但生产 `vector_search` 的 `output_fields`
> **不含 `code`**（只有 `company`），于是向量通道的片段被全部漏计，Q03 的占比被算成 **0.00**（真值 0.12）——
> 一个"看起来过滤效果更惊艳"的假数字。给 `focus_of` 补了正例自检（手造 3 条片段期望 2/3）后才暴露。
> **同一个坑的教训**：探针自检不能只覆盖"识别器"，**被测量的那个函数本身也要有正例**。

#### 3.1.2 指代澄清的收益上限：oracle 实验（`scripts/oracle_q1q2.py`）

既然方案③ 对 Q01/Q02 不触发，那"若把指代问题解决掉能好多少"只能测**上限**：
用 ground_truth 反推主体公司（平安银行 / 招商银行）做 **oracle 过滤**，重跑这两题。

- **答案文本层面（可核验，最有说服力）**：Q01 来源 `平安银行+招商银行+邮储银行` → **仅平安银行**；
  Q02 来源 `平安银行+招商银行` → **仅招商银行**。生成的答案不再并列别家公司，**"多答"问题消除**。
- **指标层面（n=2，无噪声底，仅供指示）**：Q02 的 Faithfulness **0.5 → 0.6667**（方向与机制一致）；
  其余变化（Q01/Q02 的 CP 一升一降）在 2 个样本上**不可解读**。
- **诚实结论**：澄清指代能**确定性地**修好"多答"（答案文本证据），但**RAGAS 分数在 n=2 下测不出**。
  这与 §1.4 是同一个道理——**定性证据比小样本指标更可信**。

> ⚠ 本实验用了标准答案反推的公司，是**收益上限**，**不是可上线配置**（推理时拿不到 ground_truth）。

### 3.2 题面 `xx银行` 指代不明（**题面的账**，非系统缺陷）

`sample_questions.pdf` 原题用 `xx银行` 占位，系统无法判断指代谁。工单要求保留原题问法，故此处如实记录、**不改题面**。正确处理应是让系统反问澄清，或明确按"相关公司并列"输出。

### 3.3 Q03/Q04 的 reference 写成综述体 → 召回系统性偏低（**造题的账**）

**证据**：Q05–Q10（reference 逐字取自 PDF、事实型）Context Recall 为 **0.67–1.0**；Q03/Q04（reference 抄自 sample 参考答案、**分析综述体**）Context Recall 为 **0.0**。
**判断**：同一检索器在事实型题上召回良好，说明**不是检索没找到，是标准答案的措辞体系与语料原文不同**，RAGAS 按 reference 的要点去比对就判为未命中。

### 3.4 Q04 长枚举答案 → Answer Relevancy=0（**指标口径的账**）

`AnswerRelevancy` 由答案反推问题再与原始问题比余弦相似度；答案越长、枚举越多，反推问题越泛化，得分越低。Q04 答案 1605 字、逐条引用四家公司原文、**无幻觉**，却拿 0 分。该题指标不可用，**以人工复核为准**。

### 3.5 目标页漏召（Q10）——只作诊断，不作失败判据

同一事实（如国泰君安营业收入）在年报的"董事会报告""财务报表附注"等处会重复出现，检索命中另一处是**合理的**，答案数字也完全正确。故「目标页命中率」只用于诊断，**不能单独当召回失败**。

### 3.6 方案C「重排阈值截断」——实测结论：**不要用绝对阈值**

先量 80 条召回片段的真实重排分分布（`scripts/entity_filter_probe.py`）：
`min 0.067｜p10 0.225｜中位 0.936｜max 1.000`——**分数高度压缩在两极，不是均匀分布**。

| 题 | 该题 8 条分数 | 绝对 0.85 存活 | 相对 0.5×max 存活 |
|---|---|---|---|
| Q01 | 0.776…0.230 | **0/8** ⚠ | 6/8 |
| Q02 | 0.754…0.385 | **0/8** ⚠ | 8/8 |
| Q04 | 0.182…0.067 | **0/8** ⚠ | 5/8 |
| Q03/Q05/Q06 | 0.83~1.00 | 4~7/8 | 8/8 |
| Q07~Q10 | 0.92~1.00 | 8/8 | 8/8 |

**两条实测结论**：
1. **绝对阈值 0.85 会清空 Q01、Q02、Q04 的全部上下文**（0/8）——这三题的分数**结构性地低**
   （Q04 是跨文档综述题，8 条全 ≤0.182），但它们的内容**是相关的**。这正是"便宜预筛误杀金标"的同型陷阱：
   阈值裁掉的是**分数低但相关**的片段，不是**分数低且无关**的片段。→ 若一定要裁，用**相对阈值**（如 `0.5×该题最高分`）。
2. **更重要：阈值根本分不开跨公司噪声。** Q05 里目标（招商银行）与噪声（平安银行/邮储银行）的片段分数
   都在 **0.83~0.99**、彼此重叠——因为"别家公司大段披露同一指标"**确实语义相关**，重排器看不出主体错位。
   → **实体混淆只能靠元数据/实体约束解决，任何分数阈值都解决不了。**

## 5. 本轮未做（如实标注边界）

1. **未扫描分块参数**（`CHUNK_SIZE` / `SEM_THRESHOLD`）：改动分块需重建索引（9 份年报、约 20 分钟 GPU），超出本轮预算。本轮只扫描了**检索端**参数。
2. **未重跑一遍完整的"优化后 RAGAS"**：需要约 15 分钟 API 调用。本轮"优化后"对照用的是 10-09 已落盘的 `eval_20261009_204719.json`。判定它跑在过滤后索引上的**证据**：该轮 80 条召回片段中邮储页眉特征片段 **0/80**，而基线 194604 是 **7/80**（`scripts/analyze_retrieval.py` 实测）——这正是过滤器的签名。
3. **方案④ 仍为预期、无实测数字**（方案③⑤已实测，见 §3.1.1 / §3.6）——按项目纪律，**未跑过的数字不得当既成事实交付**。
4. **未做全量回归**：本轮所有确定性结论（§1.2 / §2.2 / §3.1.1 / §3.6）都是**检索端**的，未改变线上配置，
