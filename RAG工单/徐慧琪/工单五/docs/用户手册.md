# 用户手册（工单 05）

**工单编号：人工智能NLP-RAG-Query理解优化**

本系统面向《招股说明书1.pdf》（武汉兴图新科电子股份有限公司）与
《招股说明书2.pdf》（武汉力源信息技术股份有限公司）两份文档，提供中文/英文问答，
**支持多轮连续追问**。回答会标注**来源文档 + 页码**；
若答案出自表格，还会给出**表名与命中的行号**；若出自组织结构图，会给出**节点路径**。

---

## 1. 启动系统

### 1.1 前置检查

| 项目 | 要求 | 检查命令 |
| --- | --- | --- |
| Ollama 服务 | 已启动，且有 `qwen2.5:3b` 与 `qwen2.5:0.5b` | `ollama list` |
| 向量库 | 已建库（`data/qdrant` 存在，含表格与组织结构图块） | 若首次使用见 1.2 |

### 1.2 首次使用：建库

```bash
python build_index.py       # 双文档 + 表格结构化（约 6 分钟，详见下文）
python build_orgchart.py    # 组织结构图增量入库（约 1 分钟；含一次 OCR 交叉验证 35s）
```

> `build_index.py` 建完主索引后会**自动补回**组织结构图块；单独跑 `build_orgchart.py`
> 是幂等的（已入库则跳过）。想跳过 OCR 交叉验证：`python build_orgchart.py --skip-ocr`。

### 1.3 启动界面

```bash
streamlit run app.py
```

浏览器自动打开 `http://localhost:8501`。

> **强烈建议先点侧栏「预热模型」**——不预热的话第一题要多等约 25 秒（模型冷启动）。
> 预热后逐轮都在 1.8 秒内。

## 2. 界面功能

左侧边栏可切换 **中文 / English**（界面文案随之切换，回答语言由问题语言决定）。
共 5 个页签：

### 2.1 🧠 多轮对话（本工单核心）

连续追问的页面。**用法**：

1. 先用一个**完整问题**起手（点名一家公司），例如
   「武汉兴图新科电子股份有限公司的法定代表人是谁？」；
   空会话时会给出三个「示例起手」，点一下即可；
2. 接着用**代词或省略**追问，例如
   「**他**参与的哪个工程荣获了国家科技进步一等奖？」
   「**这个公司**的注册资本是多少？」
   「**那武汉力源信息技术股份有限公司呢？**」；
3. 每轮回答下方如果出现「**Query 理解（改写过程）**」折叠项，
   展开就能看到系统**把你的问题改写成了什么**：

   ```
   原问题：这个公司的法定代表人是谁？
   独立问题：武汉兴图新科电子股份有限公司的法定代表人是谁？
   改写方式：coref_llm   指代实体：武汉兴图新科电子股份有限公司
   ```

   ——这一步透明化是本系统的重点：**你能看到它凭什么认为「这个公司」是这家公司**。
   完整问题（点名了公司）那一轮不会出现该折叠项，因为它**不需要改写**（直通）。

**按钮**：

| 按钮 | 作用 |
| --- | --- |
| 👍 / 👎 | 对某轮回答反馈（界面会记账，用于人工评估） |
| 重新生成 | 丢弃最后一轮重问（会同时回退对话焦点，不会串味） |
| 清空会话 | 结束当前对话，重新开始 |
| ▶ 一键跑完工单验收的 5 轮序列 | 清空当前会话后，自动按序问完工单 PDF 指定的 5 个问题（约 7 秒），用于**一键复现验收序列** |

> 「一键跑」会**先清空会话**：验收序列的第 2 轮「他」要靠第 1 轮建立的焦点，
> 混在旧对话里指代可能指错，所以它总是从零开始。

**如果它说「指代无法解析」**：说明当前会话里还没出现过任何公司名，
系统**不会猜**，而是请你先补充公司名称——这是有意设计。

### 2.2 💬 问答（单轮）

1. 在输入框提问（或点「示例问题」）；
2. 点「提问」，查看：
   - **回答**；
   - **📄 引用来源**：形如 `招股说明书2 第15页`、表格题带 `｜表格：本次发行概况（第 2、8 行）`、
     组织结构图题带节点路径 `｜股东大会/董事会/总经理/销售部/大客户销售部`；
   - **🧭 文档路由**：系统识别出问的是哪家公司，只在对应文档内检索；
   - **⏱ 耗时明细**：查询理解 / 混合检索 / 重排 / 上下文 / 生成 / 总计；
   - **检索到的片段**（折叠）：送进模型的原文。

侧栏可调参数：

| 参数 | 说明 | 建议 |
| --- | --- | --- |
| 启用重排 | 用 bge-reranker-v2-m3 精排候选 | 保持开启 |
| 返回片段数 | 送进 LLM 的片段数 | 默认 4；表格题多时可加到 5~6 |
| 预热模型 | 提前加载 embedding/reranker/LLM | 首次提问前点一次 |

### 2.3 ⚖️ 优化前后对比

选一道必测问题，点「开始对比」，三列并排：本系统 / 上游系统（无表格优化）/ 纯 LLM。

> 涉及武汉力源的题目，中间一列会答不出——它没有招股2 的索引。

### 2.4 📊 表格检索

浏览已结构化入库的表格：文档数 / 表格总数 / 低质量表数；
按文档与页选择表格后，可看它的来源、页码、**表型**（`header` 列式表 / `kv` 字段-值表）、
行数、质量分、`table_id`、表头、内容（前 60 行）。

### 2.5 📚 知识库

查看系统状态（向量库模式与集合名、模型信息），并可「重建知识库」（后台运行）。

## 3. 提问技巧

| 场景 | 建议问法 |
| --- | --- |
| **多轮追问** | 首轮**点名公司**，之后用「他 / 这个公司 / 那 XX 呢」；换公司时直接说新公司名即可 |
| 表格类 | 直接问表里的字段名，如「本次发行股数是多少」 |
| 需要计算 | 可直接问比例，如「发行股数占发行后总股本的比例是多少」（系统允许用表中数字做一步除法） |
| 多文档 | **带上公司名**（「武汉力源……」「兴图新科……」），系统自动路由到对应文档 |
| 组织结构图 | 问「XX 公司组织结构图中，哪个部门的 XX 最多？」这类**结构性**问题 |
| 报告期数据 | 说清指标名，如「报告期内来自军用领域的收入分别是多少」 |

**关于「无法确定」**：当检索片段确实不含相关信息时，系统回答
「根据已有资料无法确定。」，而不是编造。这是有意设计。

## 4. 常见问题

**Q1：多轮追问时它指错了公司？**
先看该轮展开的「改写过程」——`指代实体` 写的就是它认定的公司。
若指错了，通常是因为你说的代词在**上一轮**才引入过公司，而更早的轮次里出现过另一家
（焦点以**最近一次点名的公司**为准）。换公司时直接点名即可。

**Q2：为什么「这轮没有改写过程」？**
因为该轮是**完整问题**（点名了公司或没有代词），走直通（`passthrough`），**不付改写开销**。
这是设计上的快路径，不是功能缺失。

**Q3：回答里的数字和我翻书看到的不一致？**
系统有数字校验：答案中的数字必须能在检索上下文中逐字找到（或由其中两个数一步算出），
否则重试一次；仍不一致则改为抽取式回答。
若确认有误，多半是原表识别问题——可在「📊 表格检索」看该表的质量分。

**Q4：系统答不出招股2 的问题？**
检查建库是否包含招股2：`python build_index.py --source 招股说明书2.pdf`，
或在「📊 表格检索」的文档下拉框里确认。

**Q5：响应超过 3 秒？**
首次提问包含模型冷启动。点侧栏「预热模型」后通常 1~2 秒。
多轮页的代词轮会比完整问题多花约 0.2 秒（改写耗时），属正常。

**Q6：重建索引后界面报「向量库为空」？**
Qdrant 本地模式同一时刻只允许一个进程占用。
先关闭其他正在运行的 `build_index.py` / `app.py`，再重建。

**Q7：表格 OCR 兜底很慢？**
首次建库会对低质量表格所在页调用 PaddleOCR-VL（实测 9 页约 236 秒），
结果有缓存，之后重建不再重复识别。不需要时加 `--no-ocr` 跳过。

**Q8：组织结构图那题答错了/答不出？**
先确认 `python build_orgchart.py` 跑过且校验通过（输出会打印 29 节点 / 28 边 / 单根）。
该题答案来自图结构聚合，**不经过 LLM 数数**；若结构校验失败脚本会直接报错而不是写入错误的树。
