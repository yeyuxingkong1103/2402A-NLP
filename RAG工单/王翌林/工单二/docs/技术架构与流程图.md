## 一、系统总体技术架构（分层）

```mermaid
flowchart TB
    subgraph CLIENT["① 用户接入层"]
        U["👤 用户浏览器"]
        ST["Streamlit 优化版前端<br/>:8502<br/>中英双语 / 优化前后对比 / 点赞点踩 / 语音输入"]
    end

    subgraph API["② 接口服务层 FastAPI :8000"]
        H["GET /api/health 健康检查"]
        A["POST /api/ask 同步问答"]
        S["POST /api/ask_stream SSE 流式"]
        F["POST /api/feedback 反馈"]
        Q["GET /api/questions 示例问题"]
        STATS["GET /api/stats 统计"]
    end

    subgraph ENGINE["③ RAG 引擎层 src/rag_engine.py"]
        MU["多语言路由<br/>语言检测 + 翻译"]

        CACHE["语义缓存<br/>DiskCache 余弦≥0.92<br/>命中即直接返回（约2ms）"]

        RR["bge-reranker-v2-m3 重排序"]
        PC["父子块映射<br/>小查大返"]
        LLM["DeepSeek-v4-flash 生成"]
    end

    subgraph RET["④ 检索层"]
        VEC["向量召回<br/>bge-m3 (1024维)"]
        BM25["关键词召回<br/>jieba + BM25"]
        TBL["表格专项召回"]
    end

    subgraph DATA["⑤ 数据与模型层"]
        MILVUS[("Milvus 2.6.9 :19530<br/>rag_chunks / HNSW+COSINE<br/>不可用→Lite 降级")]
        MYSQL[("MySQL 8.0 :3307<br/>rag_pdf_qa<br/>文档/分块/QA日志/反馈")]
        EMB["本地模型<br/>bge-m3 / bge-reranker-v2-m3<br/>PyTorch cu128"]
        DS["☁️ DeepSeek API<br/>deepseek-v4-flash"]
    end

    subgraph INGEST["⑥ 离线入库层（一次性）"]
        PDF["PDF 招股书"]
        PARSER["优化解析<br/>版面分析 + OCR 兜底"]
        CHUNK["语义分块 + 父子块"]
        EMB2["bge-m3 批量向量化"]
    end

    U --> ST
    ST -->|"HTTP/JSON :8502 → :8000"| A
    A --> MU
    S -.->|"SSE 同一引擎链路"| MU

    MU --> QU --> CACHE --> FUSE --> RR --> PC --> LLM

    FUSE --> VEC
    FUSE --> BM25
    FUSE --> TBL
    VEC --> MILVUS
    TBL --> MILVUS
    BM25 --> MYSQL
    RR -.->|"调用 reranker 模型"| EMB
    LLM -->|"HTTPS 调用"| DS

    A -.->|"QA 日志 / 反馈写库"| MYSQL
    F -.-> MYSQL
    H -.->|"健康检查"| MILVUS
    H -.-> MYSQL

    PDF --> PARSER --> CHUNK --> EMB2 --> MILVUS
    CHUNK -.->|"分块元数据"| MYSQL

    TBL ~~~ PDF
```

## 三、RAG 全流程时序图

```mermaid
sequenceDiagram
    autonumber
    participant U as 用户/前端
    participant API as FastAPI :8000
    participant ML as 多语言模块
    participant C as 语义缓存
    participant QU as 查询理解
    participant R as 混合检索
    participant RR as 重排序
    participant PC as 父子块
    participant LLM as DeepSeek
    participant DB as MySQL/Milvus

    U->>API: POST /api/ask {question, top_k, lang, chain}
    API->>ML: 语言检测 / 翻译路由
    alt 英文提问
        ML-->>API: 中文检索 query + 标记回答语言 en
    else 中文提问
        ML-->>API: 原文直走
    end

    API->>C: 生成 query 向量，查缓存（余弦≥0.92）
    alt 缓存命中
        C-->>API: 历史答案（~2ms）
        API-->>U: answer + cache_hit=true（极快返回）
    else 未命中
        C-->>API: miss
        API->>QU: LLM 改写 + Multi-Query / HyDE
        QU-->>API: 改写 query + 意图

        par 并发召回
            API->>R: 向量召回 bge-m3 + Milvus HNSW
            R->>DB: ANN top-50
        and
            API->>R: BM25 召回（jieba）
            R->>DB: 倒排 top-50
        and
            API->>R: 表格专项召回（statistics 意图）
        end
        R-->>API: 多路候选
        API->>R: RRF 融合去重

        API->>RR: Top50 → 重排序
        RR-->>API: TopK 高相关片段
        API->>PC: 子块命中 → 父块合并
        PC-->>API: 完整上下文 + 页码引用

        API->>LLM: 上下文 + 问题（按提问语言）
        LLM-->>API: 生成答案
        API->>C: 异步写缓存
        API->>DB: 写 qa_logs
        API-->>U: answer + references + breakdown + cache_hit=false
    end
```

## 四、RAG 全流程流程图（含优化点 O1~O12 与降级分支）

```mermaid
flowchart TD
    Q[用户提问 question] --> LANG{语言检测 O8}
    LANG -->|英文| TRANS[LLM 翻译为中文]
    LANG -->|中文| RW
    TRANS --> RW[LLM 查询改写<br/>多查询变体 O5]
    RW --> INTENT{意图识别}
    INTENT -->|summary/definition| HYDE[HyDE 假设答案生成 O6]
    INTENT -->|statistics| TBL[表格专项召回路 O7]
    INTENT -->|qa| MAIN[主召回路]
    HYDE --> MAIN

    Q --> SEMCACHE{语义缓存命中?<br/>O9 余弦≥0.92}
    SEMCACHE -->|命中 ~2ms| FAST[直接返回缓存答案]

    MAIN --> V1[向量检索<br/>bge-m3 + Milvus HNSW ef=64 O11]
    MAIN --> B1[BM25 检索<br/>jieba 分词]
    TBL --> V2[表格子集向量检索]
    TBL --> B2[表格 BM25 检索]
    V1 --> RRF[RRF 融合多路结果]
    B1 --> RRF
    V2 --> RRF
    B2 --> RRF

    RRF --> RERANK[bge-reranker-v2-m3<br/>Top50 → TopK 重排]
    RERANK --> PARENT[父子块映射<br/>子块命中→父块返回 O4]
    PARENT --> CTX[构建上下文<br/>section_path + 引用页码]

    CTX --> LLM[DeepSeek-v4-flash<br/>按提问语言生成回答]
    LLM --> ANS[答案 + references + breakdown]
    ANS --> WRITE[异步写语义缓存]
    ANS --> SSE[SSE 流式输出]

    LLM -.超时25s.-> FB[降级: 返回参考片段 O12]
    V1 -.异常.-> FB2[降级: 仅BM25 O12]
    RERANK -.模型异常.-> FB3[降级: 保序透传 O12]
```

## 六、缓存与降级机制

```mermaid
flowchart TD
    REQ[请求进入] --> CK{语义缓存<br/>余弦相似度}
    CK -->|≥0.92 命中| HIT[跳过检索与生成<br/>直接返回 ~2ms]
    CK -->|<0.92 未命中| NORMAL[正常 RAG 链路]

    NORMAL --> E1{Milvus 可用?}
    E1 -->|是| USE_R[使用远程 Milvus]
    E1 -->|否| E2{Milvus Lite 可用?}
    E2 -->|是| USE_L[降级 Lite 本地文件]
    E2 -->|否| BM[降级仅 BM25 检索]

    NORMAL --> E3{Reranker 可用?}
    E3 -->|是| USE_RR[模型重排序]
    E3 -->|否| KEEP[降级: 原序透传]

    NORMAL --> E4{LLM 25s 内响应?}
    E4 -->|是| USE_LLM[返回 LLM 答案]
    E4 -->|否| SNIPPET[降级: 返回参考片段<br/>不返回失败响应]
```

## 八、技术架构分层说明

| 层 | 组件 | 关键职责 | 优化点 |
|----|------|----------|--------|
| ① 用户接入层 | Streamlit :8502 | 中英双语界面、优化前后对比、点赞点踩反馈、语音输入 | 前端对比体验 |
| ② 接口服务层 | FastAPI :8000 | 6 个 REST/SSE 端点、参数校验（422/503/500） | — |
| ③ RAG 引擎层 | rag_engine.py | 多语言、查询理解、缓存、融合、重排、父子块、生成 | O4~O9, O12 |
| ④ 检索层 | retriever / hybrid_retriever | 向量 + BM25 + 表格专项，RRF 融合 | O5~O7, O11 |
| ⑤ 数据与模型层 | Milvus / MySQL / 本地模型 / DeepSeek | 向量存储、关系存储、嵌入重排、答案生成 | O11, O12 |
| ⑥ 离线入库层 | pdf_parser / chunker / ingest | PDF 解析、语义分块、向量化入库 | O1~O4, O10 |
