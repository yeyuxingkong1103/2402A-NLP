### 1.4 文本与图像模态是怎么"融合"的 —— 关键结论

**RAGFlow 不是在检索时做跨模态融合，而是在「解析入库时把图/表文本化」**，让它们统一进同一个文本索引：

1. **图片 → VLM 描述**：`deepdoc/parser/figure_parser.py:85 vision_figure_parser_pdf_wrapper()`
   ```python
   vision_model = LLMBundle(kwargs["tenant_id"], LLMType.IMAGE2TEXT)
   figures_data = [item for item in tbls if is_figure_item(item)]
   if sections and figures_data and context_size > 0:
       figure_contexts = append_context2table_image4pdf(sections, figures_data, context_size, return_context=True)
   parser = VisionFigureParser(vision_model=vision_model, figures_data=figures_data,
                               figure_contexts=figure_contexts, context_size=context_size, **kwargs)
   boosted_figures = parser(callback=callback)
   ```
   `VisionFigureParser.__call__` 用 `ThreadPoolExecutor(max_workers=10)`（模块级 `shared_executor`）并发调
   `picture_vision_llm_chunk(...)` → `vision_model.describe_with_prompt(img_binary.read(), prompt)`，
   最终把 `(图片块, 描述文本)` 一起入库。

2. **表格 → Markdown**：`tokenize_table`，表格整体作为一个块入库。

3. **解析期附加跨模态上下文**：`rag/nlp/__init__.py`
   - `attach_media_context(chunks, table_context_size, image_context_size)`（409 行）给 table/image chunk 附加邻近文本
   - `append_context2table_image4pdf(sections, figures_data, context_size, return_context=True)`（707 行）
     按 `@@` 位置标签为图/表找上下文

4. **检索返回体带 `image_id`**（`search.py:471`），前端据此展示图片。

## 二、瓶颈诊断（为什么"图3部件关系"类问题会失败）

| 故障 | 代码层原因 |
|---|---|
| **故障1：检索无关** | 问题文本 "编号13的部件相对于编号12..." 的向量/BM25 命中的是**大量提及"部件""编号"的纯文本块**。因为第 1.4 节的跨模态融合发生在**入库期**，检索期没有任何"视觉引用"识别逻辑，`Dealer.search` 只用原始 query 文本。 |
| **故障2：图文割裂** | 即便召回到含图 3 的页，`image_context_size` 默认为 `0` → `append_context2table_image4pdf` 不产出上下文 → 图片块进入索引时只有 VLM 描述文本，缺少"这是第11页图3"的位置锚点，靠语义相似度很难与"第11页图3"这类**页码/图号引用**匹配。 |
| **故障3：`page_size` 与图片切分** | `queue_tasks` 对 PDF 默认每任务 12 页；一张跨页大图可能被 task 边界切开，导致图与其说明文字分属不同 chunk。 |
| **故障4：rerank 权重偏语义** | `vector_similarity_weight` 默认 `0.3`，则 `tkweight=0.7`、`vtweight=0.3`，关键词相似度占大头；而"图3"这类短数字引用对关键词相似度是噪声。 |
| **故障5：没有"页码/图号"结构化字段** | 检索表达式里没有按 `page_num`、`image_id` 过滤的能力，坐标类问题无法走精确路径。 |

## 三、优化方案设计（任务二）

### 3.1 优化查询理解：识别"视觉引用"

新增一个查询预处理层，专门抽取 **页码引用**、**图号引用**、**部件编号**：

```python
VISUAL_REF_PATTERNS = {
    "page":  r"第\s*(\d+)\s*页",
    "figure": r"图\s*(\d+)",
    "part":  r"(?:部件|编号|零件)\s*(\d+)",
}
```
命中即产出「结构化过滤条件 + 强化查询文本」：
- 结构化过滤：`page_num in {11}`、`image_id` 命中该页 → 走**精确召回通道**
- 强化查询文本：把命中的图像描述（VLM 生成）拼进查询：

```python
enhanced_query = f"{question}\n[视觉线索] 第11页 图3 的图纸描述：{figure_desc}"
```

### 3.2 优化混合检索：三路召回 + 加权融合

| 通道 | 说明 |
|---|---|
| A. 原始文本查询 | 走 RAGFlow 原生 `Dealer.search`（`weighted_sum`） |
| B. 图像增强查询 | 用「问题 + 图描述」重新编码，只检索 `image`/`table` 类型块 |
| C. 结构化过滤 | 由 3.1 抽出的 `page_num` / `image_id` 直接过滤 |

融合策略（RAGFlow 没有 RRF，这里自己实现并作为补丁落地）：
```python
def rrf_fuse(lists, k=60):
    score = {}
    for lst in lists:
        for rank, doc_id in enumerate(lst, 1):
            score[doc_id] = score.get(doc_id, 0.0) + 1.0 / (k + rank)
    return sorted(score, key=score.get, reverse=True)
```
或加权分数：`final = 0.6 * norm(text_score) + 0.4 * norm(image_score)`。

### 3.3 引入跨模态 Re-Ranker

在 `Dealer.rerank_by_model` 之后追加一次"图文重排"：把候选块的 `image_description` 一并送 rerank 模型，
pair 从 `(query, chunk_text)` 变成 `(query, chunk_text + "\n[图纸]" + image_description)`。

### 3.4 优化提示工程

在生成阶段的 system/user prompt 里，当上下文含图像块时追加指令：

```
【重要】下面的资料中包含技术图纸的解析描述（以 [图纸] 开头）。
请结合图纸描述中的部件编号与位置关系进行分析回答，不要忽略图纸信息。
```
