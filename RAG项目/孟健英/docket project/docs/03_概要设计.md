## 3.2 关键流程设计

### 3.2.1 RAG 应答主流程（rag_chain.prepare）

```
急症拦截 safety.emergency_hits
  → 取角色 role；取历史（Redis）
  → needs_clarify 断句？→ CLARIFY（带选项）
  → rewrite_query 多轮改写（LLM，结合历史）
  → detect_intent 意图 + is_multi_route 决定 top_k（清单题 8 / 普通 5）
  → multi_search（基准+角色偏向+多路口径，去重，禁用术语过滤）
  → reranker.rerank（先按向量分截 12 条再精排，控 CrossEncoder 开销）
  → top 分 < 阈值？
      已澄清 → NO_CONTENT；未澄清 → LLM 生成澄清选项 CLARIFY
  → 否则：长期记忆 recall → 拼 answer_prompt → ANSWER（prompt 交 stream_answer 流式生成）
```

异常策略：prepare 全包 try/except，`logger.exception` 记录完整堆栈，返回 NO_CONTENT
友好文案；stream_answer 异常 yield 错误文本。**任何异常不抛到 UI**。

### 3.2.2 混合检索算法（retrieval.hybrid_search）

- 向量路：Milvus IP 检索 top 12；关键词路：BM25 top 12。
- RRF 融合：`score = Σ 1/(60 + rank + 1)`，**向量路命中额外 ×2 权重**。
- multi_search 对同一问题的多个检索口径（如五类降压药）分别融合后按 text 去重，
  保留每路最大向量分，最后做角色禁用术语过滤。

### 3.2.3 相关性阈值（已用真实问题校准）

| 口径 | 阈值 | 依据 |
|------|------|------|
| reranker 分 | 0.30 | 相关医疗问 0.35~0.95，无关"股市"≤0.011 |
| 症状类问句 | 0.21 | 知识库缺鉴别诊断内容，降阈避免误杀 |
| 回退向量分（reranker 不可用） | 0.45 | 量纲不同单独设置 |
| 入 prompt 片段 | score ≥ 当前阈值 | 低分片段不进 prompt，防乱引用 |

### 3.2.4 图片识别链路（可选能力，未装依赖自动降级）

- **运行时识图（PaddleOCR）**：侧栏上传化验单/药盒/说明书 → `image_ocr.ocr_image`
  识别（模型单例懒加载；按"文件名:大小"指纹缓存，页面 rerun 不重复识别）→
  过滤 <2 字噪声行 → 以 `[图片识别内容：...]` 前缀拼入检索 query 走正常 RAG。
  用户气泡仅展示图片缩略图，OCR 原文收入折叠框备查。
- **离线解析（MinerU，scripts/06）**：针对无文本层的扫描版/影印版 PDF，MinerU
  解析出带页号的 markdown → 重建 `[第N页]` 页标记 → 复用 split_pages/chunk_pages
  切块入库，与文本层 PDF 共用同一套检索/引用链路。
- **降级策略**：未安装 paddleocr 时侧栏隐藏上传框，其余功能零影响；
  OCR 失败返回空串，提问按普通文本处理。

## 3.3 存储结构设计

### Milvus（两个 collection，索引 FLAT + IP）

**medical_knowledge（知识库）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT64 PK auto_id | 自增主键 |
| vector | FLOAT_VECTOR(1024) | BGE-m3 归一化向量 |
| text | VARCHAR(4000) | 文本块 |
| source | VARCHAR(200) | 来源文件名 |
| page | INT64 | 页码（引用展示） |
| chunk_index | INT64 | 来源内块序号（同批次按 source 递增） |

**user_memory（长期记忆）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT64 PK auto_id | 自增主键 |
| vector | FLOAT_VECTOR(1024) | 摘要向量 |
| user_id | VARCHAR(100) | 用户标识（检索 filter） |
| summary | VARCHAR(2000) | 会话摘要 |

> 说明：当前以"自增 id + source/page"满足溯源；创建/修改时间在离线入库批次由
> Milvus 内部时间戳与 source 版本管理，后续如需审计可加 created_at/updated_at 字段重建。

### Redis（短期记忆）

- key：`chat:{session_id}`（List），value 为 {role, content} JSON。
- 滑动窗口裁剪最旧消息；TTL 1800 秒（.env SESSION_TTL）自动过期。

### 长期记忆（Milvus user_memory）

- 会话摘要向量化后存入，字段：vector / user_id / summary。
- 下次对话按当前 query 语义召回 top-3 相关历史摘要拼入 prompt。

## 3.4 角色与提示词设计

角色配置在 `data/roles.json`，每个角色含：id / name / avatar / color / description /
system_prompt / banned_terms（禁用术语，检索后置过滤用）/ boost（检索偏向词，心理医生
配情绪焦虑类词）。system prompt 由 RoleManager 拼接：人设 + 意图约束 + 角色禁令 +
全局安全护栏 + 输出前逐句自检要求。

## 3.5 日志与降级设计

- `config.setup_logging()`：控制台 + `logs/app.log` TimedRotatingFileHandler（按天滚动）。
- 启动分阶段打点（import/embedder/load_records/bm25/角色/链/记忆耗时）。
- 降级链：reranker 失败→向量分；Redis 失败→无短期记忆；Milvus 长期记忆失败→无长期记忆；
  Milvus 连接超时 10s 快速失败；后台线程预热 reranker/Milvus 不阻塞首屏。
