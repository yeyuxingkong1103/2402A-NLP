## 1. 本目录定位（务必先读）

- 本目录是 **原始运行输出的留痕归档**，用途只有一个：**供复核者回查"报告里的数字当初是怎么跑出来的"**；
- 本目录 **不是工单交付物**，**不是任何一条验收的判定依据**，**不得直接引用其中的数值作为结论**；
- 验收与关单的判定依据一律以**正式产物**为准：
  `优化/评估结果/{optimization_compare.md,.csv, accuracy_report.json, ragas_report.md, 验收4_稳定性_三连跑.md, 验收4_同类扩展样本_三连跑.md, 验收证据矩阵.md}`、
  `测试/用户/user_acceptance_checklist_v2.md`；
- 引用本目录的报告：`研发/报告/可答性闸门修复报告.md`（闸门/日志修复的逐题与并发证据）。

## 3. 事故留痕在哪（重要）

`--limit 1` 覆盖事故（F1）的**逐字节副本**放在**兄弟目录** `../验证留痕_原始报告备份/`，
里面仍写着「答案准确率（10 题）… 1.0000」「单题 1/1 判对」这类**被污染口径**。
→ **引用前必读该目录的 `README.md`**；本目录与那份备份**都不得引用其数值**。

## 4. 维护纪律

- 本目录属**留痕**，**只增不改**：不得在其中改写数值、不得覆盖原文件；
- 新增文件**不得以下划线 `_` 开头**（`测试/离线/test_deliverable_integrity.py::test_no_temporary_run_artifacts_in_eval_results`
  对 `优化/评估结果/` 与 `优化/脚本/` 做**递归**规则式检查：任何 `_` 前缀文件/目录都会被判红）；
- 正式产物（`优化/评估结果/*.md|*.json|*.csv` 顶层）与本目录**互不替代**：前者是结论，后者是回查材料。
