# 演示视频录制脚本 —— 基于PDF文档的问答系统

> 工单编号：人工智能NLP-RAG-基于PDF文档的问答系统
> 用途：屏幕录制分镜脚本，照着本文件操作即可完整录出验收演示视频
> 目标成片时长：约 11 分钟（含片头片尾）
> 覆盖流程：启动服务 → 上传PDF → 提问 → 查看答案与引用 → 对比纯LLM → 运行评估 → 查看结果

| 检查项 | 命令 / 操作 | 期望结果 |

| 生成模型密钥 | `echo %DEEPSEEK_API_KEY%` | 输出 `sk-` 开头的完整密钥（录制时**不要**拍到密钥） |

| 服务可用 | 跑一次 `serve.py` 并打开首页 | 页面顶部显示「向量库 xxxx 条」 |
| 语音可用 | `python src/speech_input.py` 说一句话 | 终端打印识别文本 |

### 1.2 为了拍出「3 秒内响应」，务必做两件事

```bash
# ① 预热：先跑一轮问答与评估，让模型加载完成、LLM 响应进入缓存
python "工单01-基于PDF文档的问答系统/src/qa_cli.py" -i        # 问 3 个问题后 exit
python "工单01-基于PDF文档的问答系统/src/compare_rag_vs_llm.py" --ids 531,543

# ② 若要展示「纯 LLM 的真实延迟差异」，录制前删除 LLM 缓存目录
#    （可选，演示 RAG 与纯 LLM 的耗时对比时更真实）
rmdir /s /q data\cache\llm
```

> 说明：`rag_core.llm` 带磁盘缓存，重复提问会秒回。缓存预热后录屏最流畅；
> 若解说里强调「响应时间」，请用评估结果中的 `latency_avg` 数据说话。

## 六、常见录制意外与备用方案

| 意外 | 备用方案 |
| --- | --- |
| 大模型 API 超时/限流 | 提前预热使 LLM 缓存命中（相同问题会秒回）；或暂停录制，恢复后从该镜头重录 |
| 语音识别失败 | 改用 `--file demo录音.wav` 预置音频文件演示；并在解说中说明支持麦克风与文件两种方式 |
| 网络下载模型很慢 | 该镜头只拍「已完成」状态，解说说明首次需下载模型 |
| 浏览器页面卡顿 | 关闭多余标签页，只保留问答界面与 Swagger 两个标签 |
| 麦克风噪声大 | 用手机录音后与画面在剪辑时对齐；或改为纯字幕旁白 |
| 时间不够 | 优先保证镜头 05→09→10→12→17→19（建索引、提问与引用、对比、评估） |
