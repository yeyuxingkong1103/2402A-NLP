# RAG 问答系统优化说明报告

## 1. 优化目标

工单 02 要求在基础 PDF-RAG 问答系统上继续优化，使系统在给定问题上的答案质量更高，尽量提高到约 90% 的准确水平。本项目在工单 01 的基础上，重点优化 PDF 解析质量、文档切分方式、检索策略和批量评测输出。

## 2. 技术栈

- 页面框架：Streamlit
- RAG 框架：LangChain
- PDF 解析：MinerU
- 向量数据库：FAISS
- 检索策略：MMR 多样性检索
- Embedding：通义 DashScope `text-embedding-v4`
- 生成模型：通义千问 `qwen-plus`

## 3. 主要优化

### 3.1 PDF 解析优化

原始招股说明书直接用普通 PDF 文本提取会出现中文乱码，因此改用 MinerU 解析 PDF，并输出结构化 Markdown，提高后续切分和检索质量。

### 3.2 长文档分批解析

MinerU 接口单次最多解析 20 页。本项目支持输入 `1-333`，系统自动拆分为 `1-20`、`21-40` 等批次，逐批解析后合并为完整 Markdown。

### 3.3 解析缓存

完整 PDF 解析耗时较长，因此项目增加 `cache/` 缓存。相同 PDF 和页码范围再次构建知识库时，直接读取本地 Markdown，减少重复请求和等待时间。

### 3.4 文档切分优化

系统先使用 Markdown 标题切分保留章节结构，再使用递归字符切分控制片段长度。相比纯字符切分，章节语义更完整，有利于检索准确内容。

### 3.5 检索优化

基础版本使用普通相似度检索，容易召回重复片段。优化版使用 FAISS 的 MMR 检索，从更多候选片段中选出语义相关且内容多样的片段，提高答案覆盖度。

### 3.6 批量评测输出

批量问答结果会保存问题、答案和检索依据，便于人工检查答案来源，也方便和标准答案进行对比。

## 4. 运行方式

```bash
D:/AN3/python -m streamlit run app.py
```

页面启动后，构建优化知识库，再上传 `questions.json`，点击“批量生成优化答案”，下载 `optimized_answers.json`。

## 5. 完成情况

项目已完成 PDF 解析、自动分批、缓存、Markdown 切分、MMR 检索、单问题问答、批量问答和答案导出功能，满足工单 02 的优化方向。
