# 测试报告

> 基于 RAG 的角色扮演系统 · 自动化测试报告
> 报告日期：2026-09-20 · 测试框架：pytest（pytest-asyncio）

## 一、测试概述

### 1.1 测试目的
验证系统各模块功能正确性、接口契约、RAG 链路质量与回归稳定性，支撑持续开发与交付验收。

### 1.2 测试体系

| 层级 | 手段 | 说明 |
|---|---|---|
| 单元测试 | pytest 纯函数/类测试 | 分块、BM25、提示词、清洗、校验、解析等纯逻辑 |
| 集成测试 | pytest + TestClient | API 全接口（SQLite 内存库 + 真实 Redis + 假 LLM/Milvus） |
| 质量评测 | RAGAS | 三轮提示词优化 + 双 judge 锚点（见 `eval_report/`） |
| 性能测试 | JMeter | 四场景压测（见 `压力测试报告.md`） |

### 1.3 测试环境与隔离策略
- 测试数据库：SQLite 内存库（不污染生产 MySQL）
- Redis：本机 6379 的 **15 号库**（测试专用，跑完自动清空）
- 大模型/Milvus/BGE：**全部假实现注入**（无需外部 API key、无需真实向量库，CI 可跑）
- 运行：`pytest -q`，全量约 7 秒

## 四、测试过程中发现并修复的缺陷（回归保护）

| # | 缺陷 | 发现方式 | 修复 |
|---|---|---|---|
| 1 | MySQL 连接池默认 5+10 在 50 并发耗尽（30s 排队超时） | Jmeter 压测 | pool 20+40（test_store/压测回归） |
| 2 | BGE 模型首次对话即加载（23s/2.5GB）且并发竞态重复加载 | 压测 + 代码审查 | LazyModelProxy 线程安全懒加载（test_rag 回归） |
| 3 | 文件合并后同名 router 变量互相覆盖（API 整个消失） | 全量测试失败 | 分设 user/role/chat/kb 四 router（test_api 回归） |
| 4 | PDF 提取句间空格丢失导致分块粘连 | 测试夹具暴露 | 断句规则加换行/标点边界（test_rag 回归） |
| 5 | 同源同内容重传时"先删后判重"导致数据丢失 | TDD 红灯 | 先判重后删除，全重复即无操作（test_services 回归） |
| 6 | Milvus v3 集合无索引不可 load | 真机验证 | 父集合 dummy 向量+FLAT 索引（真机冒烟回归） |
| 7 | rapidocr 3.x 结果对象接口与 2.x 元组不同 | 真机验证 | 适配 txts 接口（test_rag 回归） |
| 8 | 流式失败写入半截回复 | TDD 红灯 | 完整回复才持久化（test_services 回归） |
| 9 | 回答中无依据数值无提示 | 需求补齐 | 后处理校验 warnings（test_rag/test_api 回归） |

## 五、测试可维护性

- 测试文件按子系统合并为 7 个（原 18 个），每个测试文件与生产模块一一对应
- 假实现（FakeLLM/FakeEmbedder/FakeMilvus）按需注入，测试独立于外部服务
- 评测数据可复跑：`scripts/run_eval.py`；对比：`scripts/compare_eval.py`
- 压测数据可复跑：`jmeter/*.jmx` + `scripts/gen_tokens.py` + `scripts/make_stress_report.py`
