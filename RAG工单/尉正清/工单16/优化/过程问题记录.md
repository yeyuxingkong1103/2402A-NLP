## 一、环境与下载

### 1. HuggingFace 下不动：直连超时，镜像的大文件被 401 挡掉

**现象**：
- `huggingface.co` 直连超时（16s）；
- `hf-mirror.com` 可达，小文件能下，但**权重文件只下到 8.5MB 就断**：
  `CAS Client Error: HTTP status client error (401 Unauthorized), domain: https://cas-server.xethub.hf.co/v2/reconstructions/...`

**真因**：hf-mirror 对 LFS 大文件会 302 到 `cas-server.xethub.hf.co`，
那个域名在本机网络下拿不到授权。

**处置**：改用 **ModelScope**。它的 REST 接口不用装额外包，按文件列表逐个拉即可：

```
列表：https://www.modelscope.cn/api/v1/models/{repo}/repo/files?Revision=master&Recursive=true
下载：https://www.modelscope.cn/api/v1/models/{repo}/repo?Revision=master&FilePath={path}
```

实测 4.43GB 用 32 分钟下完，支持断点续传（已存在且大小一致就跳过）。

### 2. 现有两个环境都不能直接用

| 环境 | 情况 |
|---|---|
| `rag_gd` | **被上游锁死不能动**（见工单01-10）；且 `transformers 4.44.2` 太老，带不动 Qwen2-VL（要 4.45+） |
| `rag_gd1` | `transformers 5.19.0` 够新，但**没有 peft / bitsandbytes / accelerate**，而且它是工单12 的交付环境，不该往里塞包 |

**处置**：按项目规矩另建 `rag_gd2`。用 `conda create --clone rag_gd1` 克隆
（本地操作，不用重下 torch 的 2.5GB），再 `pip install peft accelerate bitsandbytes`。

### 3. 少一个 torchvision，processor 直接起不来

**现象**：
```
ImportError: Qwen2VLVideoProcessor requires the Torchvision library but it was not found
```

**真因**：`AutoProcessor.from_pretrained` 会把 Qwen2-VL 的**视频**处理器一起构建，
它依赖 torchvision。我们只喂图片，但绕不开这一步。

**处置**：`pip install torchvision`，先 `--dry-run` 确认它不会顶掉 torch
（torch 2.14.1 满足 `torch>=2.14.0`，pip 只装 torchvision 0.29.1）。

## 二、transformers 5.x 的 API 变化（这块全是坑）

本机 `transformers 5.19.0` 与网上多数 Qwen2-VL 示例（基于 4.x）差别不小，
照抄示例会连踩三处：

### 4. 视觉塔的路径变了：`model.visual` → `model.model.visual`

**现象**：`AttributeError: 'Qwen2VLForConditionalGeneration' object has no attribute 'visual'`

**真因**：5.x 里顶层只有 `model` 和 `lm_head` 两个子模块，视觉塔和语言模型挪到了
`model.model.visual` / `model.model.language_model`。

**处置**：写成两者都兜底的取法（`getattr(model, "visual", None) or getattr(model.model, "visual", None)`）。

### 5. `pixel_values` **没有** batch 维，别习惯性地压

**现象**：
```
RuntimeError: split_with_sizes expects split_sizes to sum exactly to 1
(input tensor's size at dimension 2), but got split_sizes=[2944]
```

**真因**：processor 返回的 `pixel_values` 形状是 **`[2944, 1176]`** ——
2944 是**这一批所有图展平后的 patch 总数**，本身就没有 batch 维。
我按常规习惯写了 `v[0]` 去「去掉 batch 维」，把 2944 个 patch 砍成了 1 个，
视觉塔的窗口注意力就报了这个错。

**处置**：只有 `input_ids` / `attention_mask` / `labels` / `mm_token_type_ids`
这四个字段带 batch 维需要压；`pixel_values` 和 `image_grid_thw` **原样保留**。
拼接时也用 `torch.cat(dim=0)` 而不是 `torch.stack`。

### 6. `image_grid_thw` 被压成一维会让视觉塔解包失败

**现象**：`TypeError: cannot unpack non-iterable int object`，
位置在 `get_vision_position_ids` 的 `for (t, h, w), merge_size in zip(...)`。

**真因**：`image_grid_thw` 是 `[图数, 3]`（t/h/w）。压成 `[3]` 之后
`.tolist()` 出来的是三个 int，解不出 `(t, h, w)`。

### 7. 5.x 多了一个 `mm_token_type_ids` 字段

processor 会返回它，混在 `BatchEncoding` 里。自写 collator 时要一起 padding 和
stack，否则 `model(**batch)` 少参数。

## 三、数据与评估

### 8. 术语抽取一开始抽出一堆「方位短语」

**现象**：给「专业术语准确性」抽标准答案里的术语，第一版抽出来的是
`位于右侧`、`在 的上方`、`位于 的下方` —— 这些是**位置关系**，不是工业术语。

**真因**：IMDR 的题一半在问「谁在谁的哪边」，答案本身就是方位描述。
拿它们当「术语」评，等于在测另一个能力，而且会把验收指标带偏。

**处置**：加一张方位词表（位于/上方/下方/左侧/右侧/之间/平行/垂直/…），
命中就返回空串、不计入术语指标；这类题归到「图纸推理正确性」那一项。
另外剥掉「部件N」后剩下残句的（`需要 X和 的配合`）也过滤掉。

改完：评估集 236 条里 **151 条术语型 + 85 条关系型**。

### 9. 训练/评估必须**按文档**切分，不能按题随机切

同一份专利会出 6 道题。按题随机切的话，同一页图会同时出现在训练集和评估集里，
模型「见过」那张图，评估分数是虚高的。所以按文档切：60 份文档进评估集，
其余进训练集。

### 10. 选项不打乱，模型会去学「答案多半在 B」

**这是本工单最值得记的一条。**

第一版微调（选项保持 IMDR 原始顺序）训完之后，分选项看准确率：

| 标准答案 | A（57题） | B（101题） | C（60题） | D（18题） |
|---|---|---|---|---|
| 微调前 | 25% | 69% | 68% | 28% |
| 微调后 | 25% | **85%** | 62% | **0%** |

B 的准确率涨了，**D 直接掉到 0%** —— 模型学到的是「答案大概率在 B」这个
**位置先验**，而不是在读图。IMDR 的选项位置固定，B 占 43%，这个先验在训练集里
是可直接利用的。

**处置**：训练集**打乱选项顺序并改写答案字母**（评估集保持原顺序不动）。
打乱后训练集的字母分布变成 26/24/25/26%，位置不再有预测力。

**教训**：做选择题类的微调，**先看答案字母的分布**。分布不均时，
一定要在训练集上打乱，否则指标涨的那部分可能全是先验。

## 四、硬件

### 11. 6GB 显存要同时管住三件事

- **4-bit 量化**：Qwen2-VL-2B 的 bf16 权重 4.4GB，加上激活/优化器放不下；
  nf4 量化后权重约 1.2GB。
- **冻结视觉塔**：只给语言侧的 q/k/v/o/gate/up/down 投影挂 LoRA，
  视觉塔 665M 参数全部冻结。
- **限制图像分辨率**：Qwen2-VL 默认把图放到 `1280×28×28`，一张 A4 图纸能吃掉
  2GB 显存。配置里把 `max_pixels` 压到 602112（约 784×768），识别图上标注够用。

三项都做了之后，训练峰值显存 **5.9GB / 6.1GB**，刚好跑得动。
实测单步约 105 秒（batch 1 × 梯度累积 8），600 样本一轮约 2.2 小时。

### 12. 别一上来就把 600 张图全解码进内存

`DataLoader` 如果先用列表推导把样本全部构建好，600 张图会同时驻留内存（几个 G），
在 6GB 显存的机器上会跟 GPU 抢内存。改成惰性 `Dataset`，图像在 `__getitem__` 里才读。
