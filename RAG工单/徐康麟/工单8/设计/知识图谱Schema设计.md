# 工单8 知识图谱 Schema 设计

> 工单编号：**人工智能NLP-RAG-基于Graph RAG 实现金融问答**
> 代码真源：`研发/app/graphrag/schema.py`（本文件与代码必须一致，pytest 用例 `测试/test_图谱schema.py` 校验）
> Schema 版本：`graphrag-fin-1.0`

---

## 1. 设计原则

1. **语料驱动**：所有实体/关系类型都能在 9 份 A 股年报里找到稳定书写形态（正则或词典可覆盖），
   不引入语料里不存在的类型（例如「事件」「因果」这类需要篇章级推理的类型）。
2. **可审计**：每个实体带 `confidence`（正则置信度）、`count`（出现次数）、`chunks`（提及块 + 原文片段）；
   每条关系带 `evidence`（原文句）、`chunk_id` / `page` / `file_name`、`extractor`（哪个抽取器产出）。
3. **可归并**：抽取器内部可能产出同义关系名（如「持有 / 控股 / 参股 / 认购」），
   统一经 `RELATION_ALIASES` 归并到**规范关系名**，保证图谱里不出现同义重复边。
4. **类型约束**：每条关系声明 `head` / `tail` 允许的实体类型；
   头尾类型不符的关系**直接丢弃并计数**（`dropped_type_mismatch_*`），保证图结构自洽。
5. **不写死答案**：词典只放**金融通用词**（指标名、业务名、城市名、姓氏），
   绝不写死任何一家公司的数据值。

## 2. 实体类型表（9 类）

| 类型键 | 中文名 | 说明 | 抽取来源（正则/词典） | 置信度 |
| --- | --- | --- | --- | --- |
| `company` | 公司 | 发行主体 / 子公司 / 参股公司 | 正则 `(?<![\u4e00-\u9fffA-Za-z])[\u4e00-\u9fffA-Za-z]{2,20}(?:股份有限公司\|有限责任公司\|有限公司\|集团)` + 文件名派生简称 + 黑名单（`股份有限公司`/`本公司`/`母公司`…） | 0.95 |
| `institution` | 机构 | 监管机构 / 交易所 / 会计师事务所 / 银行保险等非发行主体 | 正则 `…(?:交易所\|监督管理委员会\|管理委员会\|委员会\|会计师事务所\|律师事务所\|研究院\|大学\|银行\|证券公司\|保险公司)` + 黑名单（`交易银行`/`商业银行`…） | 0.90 |
| `city` | 地区 | 城市 / 地区（总部、网点、养老社区所在地） | 城市词典（`CITY_TERMS`，50 个），**只在「位于/设在/地处/总部」句式里落库** | 0.78 |
| `metric` | 指标 | 财务与经营指标项 | 指标词典（`METRIC_TERMS`，110 个，长词优先）+ 正则 `…(?:率\|额\|收入\|利润\|资产\|负债\|权益\|收益\|资本\|保费\|股息\|分红\|占比\|增速\|成本\|支出\|准备\|覆盖\|价值\|缺口)`，且必须含 `_METRIC_CORE` 中心词 | 0.92 / 0.85 |
| `amount` | 金额 | 带单位或千分位的货币金额 | 正则 `(?<![\u4e00-\u9fffA-Za-z])(?:人民币)?\d[\d,]*(?:\.\d+)?\s*(?:亿元\|万元\|千元\|百万元\|元\|亿美元\|亿港元)` | 0.90 |
| `ratio` | 比例 | 百分比 / 增减百分点 / 倍数 | 正则 `\d+(?:\.\d+)?\s*(?:%\|个百分点\|倍)` | 0.90 |
| `date` | 日期 | 报告期 / 完整日期 | 正则 `(?:19\|20)\d{2}\s*[-/年]\s*\d{1,2}\s*[-/月]\s*\d{1,2}\s*日?` 与 `(?:19\|20)\d{2}\s*年(?:度\|末\|上半年\|1-12月)`。**不收裸年份**（`2019年` 每页出现，零信息量） | 0.85 / 0.90 |
| `product` | 产品/业务 | 业务条线、产品、服务、平台、计划 | 词典（`PRODUCT_TERMS`，50 个，长度 ≥3）+ 正则 `[“《]([^”》]{2,20})[”》]` 与 `…(?:计划\|平台\|家园\|管家\|蓝本\|联盟\|模式\|体系\|机制\|工程\|指引\|产品线)` | 0.85 / 0.70 |
| `person` | 人物 | 董事、监事、高级管理人员 | **强约束**：职务正则 `(?:董事长\|行长\|总经理\|总裁\|首席执行官\|监事长\|财务负责人\|董事会秘书\|法定代表人)[:：]?\s*([\u4e00-\u9fff]{2,4})`，且姓名须「百家姓开头 + 长度 2~3 + 不含职务字」 | 0.88 |

> **人名为什么这么严**（实测踩坑）：年报「董事、监事和高级管理人员」章节是「职务 + 履历」罗列，
> 宽松正则会抽出 `任平安银行` / `兼深圳分` / `党委书记` 这类**非人名**，进而污染 `任职` 关系
> （第一轮 800 块实测：关系表里全是错的人事边）。加严后 7430 块产出 46 个可靠人名。

## 3. 关系类型表（10 类）

| 关系（规范名） | 头类型 | 尾类型 | 说明 | 抽取器 | 示例 |
| --- | --- | --- | --- | --- | --- |
| `发行` | company / institution | product / amount / date / ratio | 发行、上市、派发股息、回购 | 正则触发词 | 中信证券 —发行→ A股 |
| `披露` | company / institution | metric / amount / ratio / product | 年报披露某指标/事项 | 正则触发词 | 平安银行 —披露→ 拨备覆盖率 |
| `持股` | company / institution | company / institution / ratio / amount | 持股 / 控股 / 参股 / 认购 | 正则触发词 | 中国平安 —持股→ 平安银行 |
| `任职` | person | company / institution / product | 人物任某职务 | 正则（职务+姓名） | 谢永林 —任职→ 平安银行 |
| `归属于` | metric / amount / ratio / company | company / metric | 归属于某主体 | 正则 `归属于` + 同句主体 | 归属于母公司股东的净利润 —归属于→ 中国平安 |
| `同比变动` | metric / amount | ratio / amount / date | 同比增减 | 正则 + 同句共现 | 营业收入 —同比变动→ 18.2% |
| `位于` | company / institution / product | city | 位于/设在某地 | 正则 + 城市词典 | 太保家园 —位于→ 成都 |
| `母子公司` | company / institution | company / institution | 母子 / 总分 / 控股子公司 | 同句双公司共现 | 中国平安 —母子公司→ 平安银行 |
| `拥有` | company / institution | product / metric / amount | 拥有 / 设立 / 开展 / 打造 | 正则触发词 + 同句共现 | 中国太保 —拥有→ 太医管家 |

| `提及` | 任意实体 | chunk | 实体出现在某文本块（实体→证据块反向索引） | 抽取器直接产出 | 1,379.58亿元 —提及→ `20200214-p5-x1` |

## 4. 实体/关系的落盘结构

### 4.1 `entities.jsonl`（每行一个实体）

```json
{
  "id": "metric:营业收入",
  "name": "营业收入",
  "type": "metric",
  "type_zh": "指标",
  "confidence": 0.92,
  "count": 412,
  "aliases": [],
  "chunks": [
    {"chunk_id": "20200214-p5-x1", "page": 5,
     "file_name": "2020-02-14__平安银行股份有限公司__000001__平安银行__2019年__年度报告.pdf",
     "type": "text", "confidence": 0.92, "snippet": "…实现营业收入1,379.58亿元、同比增长18.2%…"}
  ]
}
```

* `chunks` 是**提及块**（每实体最多 `mentions_per_entity=6` 条，按置信度降序 + 页码升序保留）；
* 该字段同时承担 `提及` 关系的职责（见 §5.1）。

### 4.2 `relations.jsonl`（每行一条关系）

```json
{
  "head": "营业收入", "relation": "指标取值", "tail": "1,379.58亿元",
  "head_type": "metric", "tail_type": "amount",
  "confidence": 0.80, "extractor": "rule_clause",
  "evidence": "全行实现营业收入1,379.58亿元、同比增长18.2%",
  "chunk_id": "20200214-p5-x1", "page": 5,
  "file_name": "2020-02-14__平安银行股份有限公司__000001__平安银行__2019年__年度报告.pdf"
}
```

### 4.3 抽取器标记（`extractor` 字段取值）

| 取值 | 含义 | 置信度 |
| --- | --- | --- |
| `rule_trigger` | 关系触发词命中（发行/披露/持股/任职…）+ 同句实体组合 | 0.86 |
| `rule_clause` | 同子句「指标 ↔ 数值」绑定 | 0.80 |
| `rule_cooccur` | 同句共现（公司 ↔ 指标/产品/日期；母子双公司） | 0.55~0.75 |
| `rule_change` | 同比变动（指标 ↔ 比例 + 变动词） | 0.75 |
| `rule_belong` | 归属于（`归属于…的X` + 同句主体） | 0.80 |
| `rule_title` | 任职（职务 + 姓名） | 0.92 |
| `rule_city` | 位于（+ 城市词典） | 0.76 |
| `llm_qwen2.5-3b` | Ollama 抽样补抽（**单独记账**，便于对比增量） | 0.75 |

| 规则 | 判据 | 阈值 | 剪除数 |
| --- | --- | --- | --- |
| 高频剪枝 | 实体出现块数 > `max_doc_ratio` × 扫描块数（公司/机构/地区/人物豁免） | 0.08 → 594 块 | 4（`2019年度` 1203 块、`2019年12月31日` 1569 块、`2020年12月31日` 757 块、`2018年12月31日` 848 块） |

| 无信息量比例剪枝 | 比例数值为整数且 ≤10（0%/5%/10%）或 ≥100（100%/200%） | `uninformative_ratio_max=10.0` | 单位数比例与整倍比例（`100%` 曾与几十家子公司相连，形成星形噪声网） |

剪枝前 23279 实体 / 7322 关系 → 剪枝后 **9817 / 4861**。

### 5.3 节点 id 口径（踩坑修正）

节点 id = **规范化实体名**（如 `平安银行`），**不带类型前缀**。
早期实现用 `f"{type}:{name}"`，导致「私人银行」这类**同名不同型**的实体分裂成两个节点，
关系表里出现 `head == tail` 的**假自环**（被 `测试/test_图谱schema.py::test_无自环边` 抓到）；
改为「一名一节点」后，同名只保留首次判定的类型，自环检查才真正等价于「名字相同」。

## 6. Schema 校验（自动化）

`测试/test_图谱schema.py` 校验以下不变量（任一失败即测试失败）：

1. 所有实体 `type` ∈ `ENTITY_TYPES`（9 类）；
2. 所有关系 `relation` ∈ `RELATION_TYPES`（10 类）；
3. 每条关系满足 `head_type` / `tail_type` 约束；
4. 无自环边（`head == tail`）；
5. 所有关系引用的实体名都能在图谱节点里找到（无悬空边）；
6. 每个实体的 `confidence` ∈ (0, 1]，`count ≥ 1`；
7. `graph.json` 的 `schema.schema_version` 与 `schema.py` 一致。

## 7. 已知局限（如实登记）

1. **表格块默认不抽取**（`include_table_chunks=false`）：表格正文以数字为主，
   正则抽取噪声大；如需可 `--include-tables` 打开。
2. **`person` 召回偏低**（46 人）：为提高精确率采用了强约束（百家姓 + 职务 + 长度），
   代价是「姓名单独出现」的场景（如表格里的董事名单）抽不到。
3. **`amount` / `ratio` 是字面值实体**，不做单位归一（`1,379.58亿元` 与 `1379.58亿元` 是同一实体，
   但 `13.79亿元` 是不同实体）—— 数值归一属 工单9 优化范围。
4. **关系方向**在「同句共现」类（`rule_cooccur`）里取「首家公司 → 首个指标/产品」，
   多主体同句时可能把主体绑错（置信度已按 0.55 标注，供下游按需过滤）。
