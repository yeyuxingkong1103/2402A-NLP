## 二、过程问题记录

### 问题 1：deepseek-flash 的推理开销让建图根本跑不完（影响最大）

**现象**：第一次做单块抽取的耗时实测，一次调用 **33 秒**，而返回的正文是**空的**：

```
max_tokens=4096   finish=length  reasoning=4096   content=0 字符     ← 额度被思维链吃光
max_tokens=8192   finish=length  reasoning=8192   content=0 字符     ← 还是空的
max_tokens=16384  finish=stop    reasoning=10783  content=10104 字符
```

**根因**：`deepseek-flash` 是**推理模型**。它先产出 `reasoning_content` 再产出
`content`，两者共用 `max_tokens` 额度。给 4096/8192 时思维链就把额度耗尽了，
正文一个字都没有 —— 而且 **HTTP 状态码是 200，不报错**，只返回空串。

**为什么这是致命的**：招股书两份共 89.8 万字符，LightRAG 切成约 490 块，
每块至少一次抽取调用。按 33 秒/次算：

```
490 次 × 33 秒 ≈ 4.5 小时（还不含实体合并的调用）
```

一个 2 人日的工单，光建图就要跑半天，不现实。

**排查过程**：试了两种模型、五种关闭推理的参数写法：

| 模型 | 参数 | 耗时 | reasoning token |
|---|---|---|---|
| deepseek-flash | 默认 | 33.0s | 8,076 |
| **deepseek-flash** | **`reasoning_effort=none`** | **1.9s** | **0** |
| deepseek-flash | `thinking={type:disabled}` | 2.3s | 0 |
| deepseek-flash | `enable_thinking=False` | 50.5s | 14,226（无效） |
| deepseek-flash | `chat_template_kwargs` | 50.4s | 13,024（无效） |
| deepseek-v4-pro | 默认 | 85.5s | 6,756（更慢） |

**解决**：`reasoning_effort=none`，**33 秒 → 1.9 秒，17 倍**，思维链归零，
正文照常产出。建图从「4.5 小时」降到「十几分钟」。

**这不只是性能优化，更是对比公平性的要求**：本工单要比 RAG 与 LightRAG，
两边必须跑**完全相同**的大模型配置，否则指标差异里混着「谁的模型配置更强」。
所以 `config.LLM_REASONING_EFFORT` 对两条路同时生效（`rag_engine._request`
也读同一个开关）。

**踩到的细节**：`reasoning_effort` 走 `extra_body` / 原始 JSON 字段，
不能走 OpenAI SDK 的具名参数 —— 那个参数被 SDK 按 OpenAI 的类型校验拦下
（官方取值只认 low/medium/high，不含 none）。

### 问题 2：往共享环境里装包，把工单 01-10 砸了（教训最贵）

**现象**：为了少建一个环境，直接把 `lightrag-hku` + `ragas` 装进了工单 01-10
在用的 `rag_gd`。装完立刻报一堆依赖冲突：

```
ERROR: flagembedding 1.3.3 requires datasets==2.19.0, but you have datasets 5.1.0
ERROR: gradio-client 1.3.0 requires websockets<13.0,>=10.0, but you have websockets 16.1.1
ERROR: tokenizers 0.19.1 requires huggingface-hub<1.0,>=0.16.4, but you have huggingface-hub 2.1.1
ERROR: transformers 4.44.2 requires huggingface-hub<1.0,>=0.23.2, but you have huggingface-hub 2.1.1
```

实测导入结果 —— **RAG 系统的整条链路全废**：

| 模块 | 状态 |
|---|---|
| FlagEmbedding / transformers / sentence-transformers | ✗ `huggingface-hub>=0.23.2,<1.0 required` |
| gradio | ✗ `cannot import name 'HfFolder'` |
| ragas（新装的） | ✗ 自己也起不来 |

**根因**：`rag_gd` 里有一组**被上游硬锁、不能动**的版本 ——
`FlagEmbedding 1.3.3` 在元数据里写死 `transformers==4.44.2` + `datasets==2.19.0`，
而 `gradio 4.44.1` 要求 `huggingface-hub<1.0`（0.26 起删了 `HfFolder`）。
`ragas` 会把 `huggingface-hub` 一路升到 2.1.1，直接把这一组全部顶翻。

**为什么必须回滚而不是凑合**：工单 01-10 是**已交付**的系统，为了做一个新工单
把它们弄坏，是不划算的 —— 这条在工单 11 的记录里已经写过一次，这次又踩了一遍。

**解决**（分三步，全部完成）：

1. **完整还原 `rag_gd`**：装之前先 `pip freeze` 快照，出事后按快照逐项还原 ——
   卸载 57 个新增包、还原 4 个被改版本的包（pydantic / pydantic-core /
   requests / rich）。还原后再次 diff：**113 个包与快照逐项一致，零差异**，
   关键模块全部可导入。
2. **新建独立环境 `rag_gd1`**：python 3.11 + torch(cu126) +
   sentence-transformers + lightrag-hku + neo4j + ragas + pymupdf + pdfplumber。
3. 删掉中间试错的 `rag12` 环境，保持环境目录干净。

**最终环境分工**：

| 环境 | 用途 | 关键约束 |
|---|---|---|
| `rag_gd` | RAG 基座（FlagEmbedding + BGE-M3 + 重排序） | 版本被上游硬锁，**不能装任何新依赖** |
| `rag_gd1` | LightRAG + neo4j + RAGAS | 独立，随便装 |

**教训**：**装包前先 `pip freeze` 快照**，并且**永远不要把新工单的依赖装进已交付
工单的环境**。这次的还原之所以干净，全靠那一步快照。

### 问题 3：ragas 0.4.3 与 langchain-community 0.4 不兼容

**现象**：在新环境里 `import ragas` 就炸：

```
File "ragas/llms/base.py", line 12, in <module>
    from langchain_community.chat_models.vertexai import ChatVertexAI
ModuleNotFoundError: No module named 'langchain_community.chat_models.vertexai'
```

**根因**：`langchain-community` 0.4 把 `chat_models/vertexai.py` **删掉了**
（VertexAI 迁到独立的 `langchain-google-vertexai` 包），而 `ragas 0.4.3`
的依赖声明没跟上，仍然硬导入这个路径。**跟 DeepSeek、跟本工单都无关**，
纯粹是 ragas 的打包问题。

**解决**：把 `langchain-community` 降到 `0.3.31`（还带这个模块的最后一版）：

```bash
pip install "langchain-community<0.4"
```

降级后 `Faithfulness / AnswerRelevancy / ContextPrecision / ContextRecall`
四个指标全部可导入。

### 问题 5：通用实体类型在招股书上没有区分度（验收点 1）

**现象**：LightRAG 默认的实体类型是通用的一套 ——
`Person / Creature / Organization / Location / Event / Concept / Method /
Content / Data / Artifact`。用在招股说明书上，「军工资质」「募投项目」
「技术标准」「IC 市场」这些**本工单最该被抽出来的东西**全被塞进 `Other`，
图谱失去区分度。而验收点 1 要的正是「抽取出准确的实体类型和关系类型」。

**解决**：换掉类型表（`lightrag_engine.ENTITY_TYPES_GUIDANCE`），
按招股书实际会出现的东西定义 12 类：

```
Company / Person / Institution / Product / Technology / Qualification /
Industry / Project / FinancialMetric / Period / Location / Chart
```

并**写明每类的判据**（不写判据模型就会乱归类），同时追加四条招股书专用规则：

- **自称消解**：招股书通篇用「本公司」「发行人」，必须还原成全称，
  否则图谱里会出现一个叫「本公司」的实体，和真实公司名分裂成两个节点。
- **中文专名逐字保留**：不翻译、不缩写，`name` 字段必须是完整法定名称。
- **图表来源合法**：标了「图表解析」的文本块同样是有效来源。
- **数字必须写进描述**：金额、比例、日期要带单位逐字写进 `description`，
  否则下游问答读不到数。

**效果**（小样本实测，3,000 字）：抽出的类型已经是
`company / person / product / industry / institution / location`，
关系类型是 `Controlling Shareholder`、`Shareholding`、`Family`、
`Commitment Letter`、`License Revocation` 这类**有语义的**，
而不是清一色的泛化标签；描述里带住了数值
（`赵马克 holds 42.35% of 武汉力源信息技术股份有限公司`）。

### 问题 7：RAGAS 首轮跑出两个失败，指标缺了一半

**现象**：第一次跑完 RAGAS，八个格子里有四个是空的：

| 指标 | RAG | LightRAG |
|---|---|---|
| faithfulness | 0.6229 | **失败** |
| answer_relevancy | **失败** | **失败** |
| context_precision | 0.5881 | 0.3413 |
| context_recall | 0.7917 | 0.5769 |

日志里两种异常交替出现：

```
AttributeError('HuggingFaceEmbeddings' object has no attribute 'embed_query')
IncompleteOutputException()
```

**根因一：ragas 自带的 `HuggingFaceEmbeddings` 在 0.4.3 里是残的。**
`BaseRagasEmbeddings` 把 `embed_query` / `embed_documents` /
`aembed_query` / `aembed_documents` 四个方法都标成了抽象方法，
而 `HuggingFaceEmbeddings` 没实现 `embed_query`。
`AnswerRelevancy` 需要算「生成的问题」与「原问题」的向量相似度，一调就炸。

**解决**：写一个 `BGEM3Embeddings` 适配器（`测试/ragas_eval.py`），
四个方法都实现，内部用 sentence-transformers 跑本机的 bge-m3。

**根因二：判分模型的输出被截断。**
`faithfulness` 要把回答拆成若干「断言」再逐条核验，输出很长；
LightRAG 的回答普遍更长（实测 180~616 字，RAG 是 18~114 字），
断言条数一多，`max_tokens` 就不够，抛 `IncompleteOutputException`。

**解决**：给判分模型把 `max_tokens` 提到 8192
（`llm_factory(..., max_tokens=8192)`）。

**顺带修掉一个口径问题**：两边喂给 RAGAS 的上下文体量差太多 ——
RAG 的块由 `CHUNK_SIZE=800` 切出来，而 LightRAG 的段是**整页**
（两千字以上）。不拉齐的话 `context_precision` 面对的信息量差一倍多。
现在两边每段都截到 900 字符，与 RAG 的分块尺寸对齐。

**验证**：先用 2 题小样本试跑，四个指标全部出值
（faithfulness 0.90 / answer_relevancy 0.81 / context_precision 0.67 /
context_recall 1.00），再跑全量。
—— 上一轮就是因为**没先小样本验证**，白跑了 45 分钟。

## 三、最终配置

| 项 | 值 |
|---|---|
| 语料 | 招股说明书1（兴图新科，548 页）+ 招股说明书2（力源信息，350 页） |
| RAG 分块 | 2,232 块（正文/表格 2,195 + 图表 37） |

| 查询模式 | `mix`（局部实体 + 全局主题两条路都走，对应工单的「双层检索」） |
