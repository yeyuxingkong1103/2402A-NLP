## 2. 优化方案

### 2.1 检索层优化：加入 Reranker 精排

**优化前**：向量检索 + BM25 混合召回后，直接取前 8 块送 LLM，其中不可避免混入噪声。

**优化后**：召回阶段放宽到 20 个候选块，再用 bge-reranker-base 交叉编码器精排，取最相关的 5 块。

**原理**：Reranker 使用交叉编码（query 与 document 拼接后一起编码），比双塔向量检索更能精确判断相关性。这是工业界 RAG 系统提升准确率最有效的手段。

**效果**：answer_relevancy 从 0.8411 → 0.9392（提升 11.7%）。

### 2.2 Prompt 规则强化

在原有 3 条规则基础上，新增 4 条针对性规则，解决特定问题：

| 规则 | 解决的问题 |
| --- | --- |
| 规则 3：军用收入占比用"直接+间接"合计值 | 避免答成"直接军方占比" |
| 规则 4：军用收入四年度值按原文顺序对应 | 避免数字错位 |
| 规则 5：行业上游/下游以"行业上下游情况"章节为准 | 避免误用竞争格局章节的分类 |
| 规则 6：注册资本取最新值 5,520 万元 | 避免答成历史中间值（5,016 万元） |

### 2.3 多语言支持

**方案**：翻译层（不换嵌入模型）

```text
英文问题 → LLM 翻译成中文 → 中文检索 + 生成 → LLM 翻译回英文
中文问题 → 原路径直接处理（性能不受影响）
```

**理由：**

- 不增加磁盘占用（数据盘紧张）
- 不重建向量库（保持 1214 块不变）
- 中文路径性能完全不变
- Qwen2.5-7B 中英翻译质量满足问答需求

### 2.4 稳定性加固

| 能力 | 实现方式 |
| --- | --- |
| 空输入校验 | 拒绝 None / 空字符串 / 无有效字符 |
| 超长输入处理 | 超过 500 字符自动截断 |
| LLM 生成重试 | 失败重试 2 次，间隔 1 秒 |
| OOM 自动恢复 | 捕获显存溢出，清理缓存后重试 |
| Query 改写失败降级 | 回退用原问题检索 |
| Reranker 失败降级 | 直接返回候选前 5 |
| 单路检索失败隔离 | 向量或 BM25 任一路失败，另一路仍工作 |
| 初始化异常捕获 | 模型加载失败时给出明确错误信息 |
