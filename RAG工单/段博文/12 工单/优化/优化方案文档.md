# 优化方案文档 — LightRAG 优化任务

> 工单编号：人工智能NLP-RAG项目-LightRAG优化

## 一、优化背景与目标

传统 RAG 采用**扁平向量表示**：文档切块后统一映射为向量，检索时按余弦相似度召回。
其固有缺陷：

| 缺陷 | 表现 |
| --- | --- |
| 无法建模实体间复杂语义关系 | "谁控股谁""谁参与制定哪个标准"等关系性问题检索断层 |
| 多实体关联推理逻辑断裂 | 上下文只包含相似文本片段，缺少跨片段关联 |
| 全量更新成本高 | 新增文档需重建/重灌整个向量库 |
| 主题归纳类问题弱 | "上游涉及哪些企业"这类概念性问题召回碎片化 |

本工单引入**香港大学 LightRAG**：以图结构组织知识（实体→关系），配合双层检索
（低层实体检索 + 高层主题检索）与**增量更新算法**，弥补语义鸿沟。

## 二、优化方案总体设计

```
传统 RAG（基线）                    LightRAG（优化后）
─────────────────                  ─────────────────────────────
PDF → chunk → 向量库               PDF → chunk → LLM 抽取实体/关系
        │                                   │
        ▼                                   ▼
  扁平向量检索 Top-K              知识图谱 + 实体/关系/chunk 向量库
        │                                   │
        ▼                                   ▼
   上下文拼接 → LLM            双层检索（Local 实体 / Global 主题）
                                            │
                                            ▼
                                   图邻域扩展 + chunk 回溯 → LLM
```

**公平对比原则**：两条链路使用①完全相同的文本块（LightRAG 切块结果）、
②同一 embedding 模型（本地 bge-m3，1024 维）、③同一答案生成器
（DeepSeek，temperature=0）、④同一 16 题测试集与同一评分规则（RAGAS 简化版）。

## 三、关键优化点

### 1. 图谱构建的领域定制（验收标准 1）

LightRAG 默认抽取的是通用实体类型（person / organization / location 等），
对招股书领域区分度不足。本工单通过 `addon_params["entity_types_guidance"]`
注入**招股书专属的类型体系**：

- **13 类实体**：公司、人员、股东、产品与服务、行业、财务指标、募投项目、
  技术标准、工程奖项、技术与资质、机构、地点、事件；
- **13 类关系**：控股/持股、任职、供应关系、客户关系、子公司关系、所属行业、
  募投投资、参与制定、荣获奖项、拥有资质、位于、竞争关系、中介服务；
- **抽取约束**：实体用全称、比例/金额/报告期必须入描述、关系描述体现业务实质。

该定制通过 `研发/src/lightrag_build.py` 中的 `ENTITY_TYPES_GUIDANCE` 常量实现，
使图谱可直接支撑"参与制定了哪个技术标准""哪个工程荣获国家科技进步一等奖"
等招股书特征问题的图检索。

### 2. 检索层可切换设计（验收标准 2）

`compare_eval.py` 提供双链路检索：`rag_baseline.search()`（传统扁平向量）与
`lightrag_retrieve()`（LightRAG hybrid 双层检索），按同一接口返回上下文列表，
供上层统一评估与切换。

### 3. 性能与成本控制

| 措施 | 参数 | 效果 |
| --- | --- | --- |
| LLM 异步并发 | `llm_model_max_async=16` | 335+ chunks 抽取由串行数小时缩短至十分钟左右 |
| 关闭二次补捞 | `entity_extract_max_gleaning=0` | 每 chunk 仅 1 次 LLM 调用，成本减半 |
| 本地 embedding | bge-m3 CPU 批量编码 | 无需 embedding API，零调用成本 |
| LLM 结果缓存 | LightRAG 内置 response cache | 重跑/断点续跑时命中缓存不再计费 |
| 向量缓存 | baseline 向量落盘 `.npy` | 重复评估免重复编码 |

## 四、RAGAS 评估指标设计

采用 RAGAS 四指标语义的简化实现（以参考答案关键词为基准，两链路同规则）：

- **context_precision**：检索上下文中相关内容的排名加权占比（相关块越靠前越高）；
- **context_recall**：参考答案关键词被上下文覆盖的比例；
- **faithfulness**：答案中出现的关键词可归因（同词存在于上下文）的比例；
- **answer_relevancy**：答案对参考答案关键词的覆盖比例。

## 五、优化效果结论

（详见《测试\检索结果对比.md》《测试\RAGAS指标对比.png》《测试\逐题检索质量对比.png》，
以 16 题实测数据为准。）

| 指标 | 传统 RAG | LightRAG | 差值 |
| --- | --- | --- | --- |
| Context Precision | 0.5300 | 0.3521 | -0.1779 |
| Context Recall | 0.9688 | 0.8214 | -0.1474 |
| Faithfulness | 0.8125 | **0.8750** | +0.0625 |
| Answer Relevancy | 0.7857 | 0.7656 | -0.0201 |
| Overall | 0.7742 | 0.7035 | -0.0707 |
| 平均检索耗时(s) | 0.07 | 1.43 | — |

**结论（如实呈现，未做倾向性修饰）**：

1. 本测试集 16 题以单点事实/数值查找与穷举列表为主。传统 RAG 向量直接召回
   完整原文块，Context Recall（0.97）与性价比占优；LightRAG 经图路由后关联的
   源块在枚举类问题（Q2/Q4/Q34）上较碎片化，召回略低。
2. LightRAG **答案忠实度更高**（0.875 vs 0.8125），图增强上下文使答案更可归因；
   在跨期数据汇总题（Q260 军用领域四期收入）上答案完整，传统 RAG 有遗漏。
3. LightRAG 额外产出 **3677 节点 / 5862 边的可交互领域知识图谱**，其价值不止于
   问答分数：关系网络可视化探索、跨文档主题归纳、文档级增量更新是传统扁平 RAG
   不具备的能力。
4. 代价：检索多一次关键词提取的 LLM 调用，耗时 1.43s vs 0.07s。

**选型建议**：事实/枚举密集型问答优先传统 RAG（或为 LightRAG 增加 chunk 重排）；
关系网络探索、跨文档主题归纳、频繁增量更新场景优先 LightRAG。

## 六、后续优化建议

1. 引入重排模型（bge-reranker）对 chunk 回溯结果重排，进一步提纯上下文；
2. 对图谱做社区检测（Leiden）+ 社区摘要，增强全局主题问答；
3. 表格类页面走专用表格解析（结构化行/列），减少数值抽取误差；
4. 增量更新监控：对已存在实体做 embedding 相似度去重，避免同义实体节点分裂。
