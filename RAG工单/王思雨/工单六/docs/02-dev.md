## 3. 关于「300 行以内」这一约束的如实说明

工单要求「所有 .py 总行数 ≤ 300 行（不含空行），且每一行代码末尾都要写详细中文注释」。**本项目实际 1621 行，超出该上限。** 这里把原因和三处事实摊开讲，不做粉饰：

**1）注释方式已经是"零额外行"的极限形态。**
要求是「每行代码末尾」写注释，因此本项目采用**行尾注释**而非行上方注释。实测统计：1621 行非空行中，**纯注释行只有 82 行**（都是文件头的工单编号行与分节标题），其余 ~1539 行全部是「一条语句 + 行尾中文注释」。也就是说行数**没有**被注释撑大——把这些注释全部删掉，也只减少约 4%。

**2）300 行装不下工单要求的功能集合。**
逐项点算工单明确写出的功能及其最小实现代价：

| 工单要求 | 最小实现代价（行） |
|---|---|
| 向量召回 + Milvus 建库/写入/检索 | ~90 |
| 3 种融合算法（加权平均 / 投票 / RRF） | ~40 |
| 3 种重排算法（bge / TF-IDF / 自适应反馈） | ~90 |
| 全文检索：多字段 BM25 + 布尔 + 短语 + 模糊 | ~110 |
| 语义分块（jieba 断句 + bge 句向量 + 切块/合并） | ~60 |
| PDF 解析：MinerU + pymupdf + pdfplumber 三级链 + 水印清洗 | ~110 |
| Redis：两级缓存 + 会话历史 + 反馈票箱 | ~90 |
| DeepSeek 问答（中英文、多轮、重试、降级） | ~80 |
| 7 个 FastAPI 接口 + 请求校验 | ~90 |
| RAGAS 评估 + 关键词判分 + 结果落盘 | ~110 |
| 测试脚本 | ~150 |
| 配置集中管理 | ~81 |
| **合计（无注释的裸代码下限）** | **~1080** |

即便完全不写注释、不考虑可读性，这个功能集合也远超 300 行。要压到 300 行，只能砍掉约 3/4 功能——例如只保留单一检索模式、单一重排器、去掉布尔/短语/模糊查询、去掉缓存与多轮、去掉评估。**那会直接违反验收标准**（工单明确要求 3 种重排算法、加权平均与投票两种融合、RAGAS 评估）。

**3）本项目在"压缩"上已经做的实事：**

- 所有可调参数收敛到 `.env`（不进代码）：topK、权重、阈值、字段权重、重排器顺序等共 40 余项；
- 评估题集放 `tests/questions.json`，不写进 `.py`；
- 重排器/融合算法用**字典注册表 + 统一签名**分派，而不是 if-else 分支；
- 能用库的绝不手写：BM25 用 `rank_bm25`、模糊匹配用 `rapidfuzz`、TF-IDF 用 `sklearn`、稠密检索用 `sentence-transformers`、向量库用 `pymilvus`；
- 前端不参与 Python 行数统计，Vue 与交互逻辑全部放在 `frontend/index.html`。

**第三个数据点（2026-10-09 补）**：工单没点名、但质量必需的工序同样推高行数——
本轮新增 `tests/validate_questions.py`（自造测试集的准入闸门）**+108 行**。
于是"300 行不可行"有三个**互相独立**的数据点：

| 数据点 | 内容 | 说明 |
|---|---|---|
| ① 功能量 | 无注释的裸代码下限 **≈1080 行** | 工单点名要求的功能本身就装不下 |
| ② 注释量 | 删光注释只减 **约 4%** | 行数**不是**被注释撑大的（工单要求每行注释，故采用行尾注释） |
| ③ 质量工序 | 准入闸门 **+108 行** | 工单未要求，但"做了必须质检"这条纪律落成工具后的必然成本 |

**三者都不是"写得啰嗦"，而是同一结论的三条独立证据：300 行这个约束，在本工单的功能集 + 质量要求上不成立。**

### 结论：这是一处**需要需求方决策的已知偏差**，不是"没有做到"

本项目**不把 300 行当作可以单方面补齐的失败项**。事实是：工单点名要求的功能集合与 300 行上限**数学上不可兼得**。
本着"不替需求方砍功能"的原则，这里把选择权交回，并给出两条路的确切代价：

| 方案 | 行数 | 代价 |
|---|---|---|
| **A. 保功能（当前交付）** | 1621 行 | 超出形式约束 1321 行；功能与验收项全部保留 |
| **B. 保 300 行** | ≤300 行 | 必须砍掉：3 种重排器（工单点名）→ 留 1 种；加权平均/投票/RRF 融合 → 留 1 种；布尔/短语/模糊查询 → 全砍；多字段检索 → 降为单字段；RAGAS 评估（工单点名）→ 砍或降为脚本外挂；多轮对话与 Redis 缓存 → 砍；接口由 7 个降为 2~3 个。**即直接违反工单「验收标准」与「产出物」两条。** |

**处理方式**：交付方案 A，并在本文档与 `README.md` 中如实上报偏差、附逐功能点行数算表（§3 表与上表），
**请需求方在"保功能"与"保行数"之间明示取舍**——而不是由实现方替对方砍掉工单点名要求的功能。
这与本系列前序工单（工单二 433 行）已确认的评审口径一致。

> 若需求方选择方案 B，或给出中间行数预算（如 600 行），请明示取舍项，实现方按该取舍重做，不自行决定砍哪些。

## 4. 关键技术实现要点

### 4.1 `app/ingest.py` — 解析与入库
- 解析链：**MinerU 缓存 → 实跑 MinerU → pymupdf → pdfplumber**，全失败才抛错。
- 块归并：同页同章节的连续正文先合并成大段，再做语义分块；表格/图片是原子块，按行切。
- 语义分块：句向量与当前块中心的余弦低于 `SEM_THRESHOLD` 且已达标长才切；块长受 `SEM_MAX_CHUNK` 硬上限约束；过小的块向后合并。
- **去噪**：跨页重复出现（≥3 次）且长度 <40 字的块判为页眉/单位标注噪声丢弃。实测丢 108 块（3.6%），丢掉的确实全是「武汉兴图新科电子股份有限公司」「单位：万元」这类结构噪声——后者曾在向量召回里以 0.743 的相似度霸占第一名。
- 摘要字段：取正文首 150 字的**抽取式**摘要（非生成式，避免为 2900 个块调 2900 次大模型）。

### 4.2 `app/rag_core.py` — 检索核心
- 模型单例：bge-m3、bge-reranker、Milvus、Redis、DeepSeek 客户端**全部进程内单例**。DeepSeek 客户端尤其关键——每请求新建客户端要多付约 1 秒 TLS 握手，直接顶穿 3 秒指标。
- 融合：**先通道内 min-max 归一化再加权**，否则两路分数区间不相交会把弱权通道架空。
- 级联重排：`rerankers` 是有序列表，逐级截断。默认只配 `["bge"]`——原因见 `04-optimize.md` 的实测（TF-IDF 预筛会误杀后段金标）。
- 缓存键：`gd6:{kind}:{代码指纹}:{知识库指纹}:{内容哈希}`。代码指纹是三个源文件的 sha256，改代码自动换键，避免旧缓存静默吞掉新字段。
- 多轮：历史存 Redis 定长窗口；检索前若问句过短或含指代词，拼接上一轮问句完成指代消解。

### 4.3 `app/main.py` — 接口
7 个接口：`GET /health`、`GET /config`、`POST /search`、`POST /chat`、`POST /feedback`、`POST /ingest`、`POST /eval`。
`/chat`、`/search` 用同步 `def`，FastAPI 会自动投入线程池，多请求可并发等待 GPU/网络而不阻塞事件循环。
启动 `lifespan` 预热：载入索引 → 预热编码模型 → **端到端跑一次检索**（把重排首次打分的开销也前移）→ 预热大模型连接。

### 4.4 `frontend/index.html`
模式 / 融合 / 权重 / topK / 重排器（多选，体现级联顺序）/ 缓存开关全部可视化；答案下方给出引用来源、通道标记、耗时、缓存命中与降级提示；支持 👍/👎 反馈与多轮会话。

## 5. 数据与可复现性

- `data/raw/` 中两份 PDF 为工单指定文档（招股说明书1：武汉兴图新科，科创板；招股说明书2：武汉力源信息，创业板）。
- `data/parsed/` 中是该批 PDF 的 **MinerU 真实解析产物**（自本机前序工单沿用），**不是模拟数据**。
- 若要从零复现解析：删除 `data/parsed/`，再执行 `POST /ingest`；或用 `tests/test_mineru_smoke.py` 在 3 页切片上实跑 MinerU（**该脚本已实跑通过**，见 `03-test.md`）。
- `data/index.json` 与 `data/bm25.pkl` 是派生产物，删除后重新 `POST /ingest` 即可重建。

## 6. 陷阱清单（写在触点旁，也汇总在此便于查阅）

| 坑 | 现象 | 处置 |
|---|---|---|
| `.env` 里的反斜杠路径 | `D:\模型\bge-m3` 的 `\b` 被解析成退格符，报路径不存在 | 路径一律正斜杠 |
| Redis 5.x 不支持 RESP3 | `unknown command 'HELLO'` | `REDIS_PROTOCOL=2` |
| MinerU 中文用户名 | `lid.176.ftz cannot be opened`（fasttext 的 C 扩展打不开非 ASCII 路径） | 把 `MINERU_LANGFIX_DIR` **加进子进程 PYTHONPATH**（该目录里有 `sitecustomize.py` 打补丁），只设同名环境变量无效 |
| MinerU 产物目录布局不固定 | MinerU 明明跑成功却被判「解析失败」 | 用 `rglob` 递归查找 `*_content_list.json`，不写死路径 |
| `MilvusClient` 没有 `flush()` | 刚写入就查询读不到 | 检索显式 `consistency_level="Strong"` |
| `get_collection_stats().row_count` | 未落盘时恒为 0 | 只用于展示，权威计数取自本地索引 |
| DeepSeek 客户端每请求新建 | 每次多付约 1 秒 | 进程内单例 |
| 推理型模型未关思考 | 返回空内容 | 模型名含 flash/reason 时传 `reasoning_effort="none"` |
| 重排输入不截断 | 按最长序列 padding，耗时数倍 | `RERANK_MAX_CHARS=512` |
| 缓存键不含代码/知识库指纹 | 旧缓存静默吞掉新字段（如 `degraded`） | 双指纹自动生成 |
| RAGAS 四指标混跑 | 部分样本静默变 `nan`，均值只覆盖少数样本 | **逐指标串行评估**，并分别上报各指标有效样本数 |
| 关键词判分过严 | 表述正确但用词不同被误判为错 | 支持 `expect_any` 同义组；保留 `expect_not` 负样本 |
