## 二、一句话说清「工单6 做了什么」

**把工单4/5 里写死的那一条「向量 + BM25 → RRF → 重排」链路，抽成一层可配置、可切换、可解释的「检索策略层」**，
并把工单只要求「最低需求」的几个点补齐成真实可用的完整实现。
最关键的一条纪律是：**不传策略时，底层行为与工单4/5 基线保持一致**（工单4 的 16 题、工单5 的五轮序列都不退化）。

### 三种检索模式

| 模式 | 链路 | 什么时候用 |
| --- | --- | --- |
| `vector` 向量检索 | 嵌入模型（bge-m3 / m3e-base 可切）→ FAISS 余弦召回 Top-K → **重排** | 问句与语料措辞差异大、语义相近时 |
| `fulltext` 全文检索 | 倒排索引（布尔 / 短语 / 模糊 / 多字段）→ BM25 打分 → **重排** | 有明确关键词、专名、数字、条款名时 |
| `hybrid` 混合检索 | 两路并行 → **融合算法**（加权平均 / RRF / 投票）→ **重排** | 默认；两路互补，抗单路失效 |

### 实测：混合检索确实比单路强

| 对比 | 准确率变化 | 召回率变化 | 混合修正的题号 | 混合退化的题号 |
| --- | --- | --- | --- | --- |
| **混合 vs 向量** | **+30.00 个百分点** | **+30.00 个百分点** | **[33, 34, 260]** | 无 |
| 混合 vs 全文 | +0.00 个百分点 | +0.00 个百分点 | 无 | 无 |

* 题 260「报告期内军用领域收入分别是多少？」：**纯向量检索答错**（3,507.52 万元…），
  全文与混合**答对**（6,464.51 / 14,414.16 / 18,780.67 / 4,627.14 万元）。
  原因：问句口语化（「来自军用领域的收入」），语料措辞围绕字段名，向量路召回到同页但不同字段的段落 ——
  这正是混合检索要解决的问题，也是本工单「提升检索精度」的直接证据。
* **混合 vs 全文持平**：这 10 题上二者并列 100%。**如实记录，不粉饰** ——
  本工单的价值在于「混合至少不弱于任一单路，且在向量失效时兜底」，而不是宣称它永远更强。

## 七、已知限制与如实声明（**请务必读这一节**）

1. **召回率 90% 的那 1 题是「结构不可达」，不是检索缺陷。**
   题 4「不存在控制关系的关联方企业有哪些？」的 golden 证据原文是「表格标题 + 表格正文」连读，
   而索引里标题落在表格块 `pdf2-p157-t1-0` 的 `[表标题]` 行、正文落在文本块 `pdf2-p157-x1`，
   **任何单块都不含整段**。本仓库用 `check_evidence_reachability.py` 穷举扫描全部 2676 块证明：
   题级可达 9/10，不可达的正是题 4。因此无论用哪种检索策略、Top-K 取多大，`hit_complete` 都不可能命中。
   → 检索系统该背的指标是「**可达题上的召回率 = 100%**」。

2. **`gradio` / `rank_bm25` / `whoosh` 在本机均未安装，且装不上。**
   实测 `importlib.util.find_spec` 三者皆未命中；`pip install --target` 在沙箱内**实测挂死**
   （180 秒无输出、无退出码）。因此：
   * Web 界面用**纯 Python 标准库**（`http.server`）实现，**功能完整**（策略面板 + 权重滑块 + 反馈 + 对比）；
     `部署/界面/gradio_app.py` 保留，装得上 gradio 时即是首选界面；
   * 全文检索是**自实现倒排索引 + BM25**（工单4 已有），能力对照见 `设计/全文检索设计.md` §七。

3. **BM25 词表刻意停用了表格高频词。** `研发/app/core/text_utils.py::STOPWORDS` 含「项目/公司/本次/比例」等
   （词表共 23607 词）。这些词是**词表外词项（OOV）**：若参与 `AND` 约束会导致 0 命中。
   全文检索会把这类词通过 `oov_terms` **显式报告**给用户（不静默返回「查不到」）。

4. **纯否定查询返回空。** `NOT 军用` / `-军用` / `非 军用` 在倒排语义下会命中几乎全库，无检索意义 ⇒
   返回空结果并在 `notes` 里说明。双重否定 `NOT NOT 军用` 与非纯负查询 `军用 AND NOT 领域` 正常返回。

5. **中文 `非` 必须与词隔开空格。** `非甲` 连写会被 jieba 切成普通词项（不解析为布尔非）；
   `NOT 甲`、`-甲` 无此限制。

6. **`标题:发行股数` 会分词成 `(标题:发行 OR 标题:股数)`。** 要短语语义请写 `标题:"发行股数"` 或 `"标题:发行股数"`。

7. **不同嵌入模型的向量不可混用。** 切换模型 = 切换到该模型的索引目录；索引不存在会**显式报错并给出建库命令**，
   绝不拿 bge-m3 的索引去算 m3e 的查询向量。

8. **`m3e-base` 上下文为 512。** 块长约 500 字，中文按字≈词元计属临界，超长块会被 Ollama 截断 ——
   这意味着 m3e 索引的长块召回可能弱于 bge-m3（8k 上下文）。本次评测主用 bge-m3，**m3e 只验证了「可切换、可检索」**。

9. **策略层与工单4 基线不等价（已在 §三 明确列出）。** 需要基线一致时请**不要**传 `strategy`。

10. **工单6 修正了工单4 遗留的两处缓存缺陷**（测试报告与设计文档均有记录）：
    ① 内层检索/生成缓存原本不受调用方 `use_cache` 开关管辖，导致「响应时间测试」量到缓存命中的约 1 ms；
    ② 检索缓存命中时策略诊断字段为空，会让「三模式对比」出现整行为空的假象。
    修正后 `use_cache=False` 真正强制真实执行，策略诊断在任何路径下都完整。
