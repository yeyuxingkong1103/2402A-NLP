## 一、设计纪律（**先读这一节**）

### 1.1 禁止把两路原始分直接相加

| 通道 | 分数 | 实测值域 |
| --- | --- | --- |
| 向量（bge-m3） | L2 归一化后的内积 = 余弦相似度 | 常用区间 0.4~0.8（本例 top1 = 0.7309） |
| 全文（自实现 BM25） | 无上界，随查询词项数与词频变化 | 实测单块 6~20（本例 top1 = 17.19） |

两者属**不同语义空间**，量纲相差一个数量级以上。直接相加时 BM25 会把余弦分完全淹没。
这条纪律沿用 工单4 `研发/README.md` §2「融合纪律」（原文：*向量、BM25、CLIP 图像通道属**不同语义空间** → 用 **RRF 排名融合**，**禁止把相似度直接相加***）。

### 1.2 必须相加时：先各自归一化，且**缺项补 0**

* `weighted_average` 是唯一会「相加原始分」的算法，因此它**强制**先做 min-max 归一化（在**本路 Top-K 内部**）；
* 「仅被一路召回的块」另一路记 **0.0** —— 是**补零**，不是「忽略该项后按剩余权重重新归一」。
  代码里权重不做重归一，`vw·0 + fw·norm_f` 就是这个块的最终分；
* 归一化基准是**该路返回的 Top-K**，不是全库、不是两路公共基准。这是已知口径，已写进 `notes`：
  `两路分数各自在**本路 Top-K 内部**做 min-max 归一化，缺项补 0`（实测出现在每次 `weighted_average` 融合的返回值里）。

### 1.3 权重清洗（`_weight_pair`）

`_weight_pair()` 返回 `(生效向量权重, 生效全文权重, 说明或 None)`，**三个算法共用**它，
因此清洗动作在 `weighted_average` / `rrf` / `voting` 下**都会写进 `notes`**
（评审修正前只有 `weighted_average` 留痕，`rrf` / `voting` 静默清洗 —— 与工单4「回退动作必须写日志」相悖）。

| 输入 | 生效值 | 留痕（实测原文） |
| --- | --- | --- |
| 负数 | 截断为 `0.0` | `负权重已截断为 0：传入 (-1.0, 0.5) → (0.0, 0.5)` |
| 两者同时 `0.0` | 回退 `(1.0, 1.0)` | `两路权重同时为 0，已兜底为 (1.0, 1.0) 以保证结果非空` |
| 正常值 | 原样使用（**不做归一**） | 无 |

`FusionResult.vector_weight` / `fulltext_weight` 存的是**清洗后的生效值**，不是传入值。

> 两层防线的分工：`StrategyConfig.validate()` 是**面向用户输入的第一道闸**（同时为 0 直接拒配）；
> `_weight_pair()` 是**面向内部调用的兜底**（即便绕过校验也不产出空结果/NaN）。两层都保留，且都留痕。

## 二、算法 ①：加权平均 `weighted_average`

**代码**：`weighted_average_fusion()`（`fusion.py:137-173`）
**标签**：`加权平均（归一化后线性加权）`；`describe_algorithms()` 给出的公式串：`w_v·minmax(v) + w_f·minmax(f)`

### 2.1 公式

```
norm_v(c) = minmax( vector_hits 的分数 )      按分数做 min-max
norm_f(c) = minmax( fulltext_hits 的分数 )
score(c)  = w_v · norm_v(c) + w_f · norm_f(c)      c ∈ 两路候选的并集
           其中缺项那一路取 0.0
```

min-max 边界（`minmax_normalize()`，`fusion.py:92-109`）：

| 输入 | 输出 |
| --- | --- |
| 空列表 | `{}` |
| 只有一个候选 | 该候选 = `1.0`（**不是 0.5**：唯一证据不应被腰斩） |
| 所有候选同分（`span ≤ 1e-12`） | 全部 = `1.0` |
| 正常 | `(score - lo) / (hi - lo)` |

### 2.2 实现要点

* 遍历 `set(v_norm) | set(f_norm)`，即**两路并集**，每一条都有分（不会漏掉单路候选）；
* 结果 `round(..., 8)`；排序交给调用方（`FusionResult.ranked()` 按分降序、同分按 `chunk_id` 升序，保证稳定）；
* 权重不重归一 ⇒ `0.7/0.7` 会把所有分数放大 1.4 倍（排序不变，但与阈值口径交互时需注意）。

### 2.3 优点 / 缺点

| 优点 | 缺点 |
| --- | --- |
| 直观：权重直接读作「话语权」；一份分数表、一个公式，好解释 | 受单路分数分布影响：长尾被 min-max 压扁 |
| 缺项补 0 的口径可预测、可复现 | **单路召回的块容易被压到 0 分**：若某块只在向量路出现且分数恰是该路最低，则 `norm_v = 0` ⇒ 总分 `0.0`（实测两路并集 4 条时，两条单路末位块得分均为 `0.0`） |
| 分数落在 `[0, w_v + w_f]`，便于与阈值配合 | 两路分数量纲差异大时，即使归一化，分布形状差异仍会传导到排序 |

### 2.4 适用场景

* 两路分数分布**形状相近**（都是「头部密集、尾部稀疏」）时；
* 需要**明确的业务权重**（例如「语义 7 : 关键词 3」）并向评审解释时；
* 需要与 `vector_min_similarity` / `score_threshold` 这类阈值配合做可控裁剪时。

### 2.5 实测样例

输入：向量 `[("a",0.9),("b",0.8),("c",0.7)]`、全文 `[("b",30.0),("d",12.0)]`，权重 0.5/0.5

```
weighted:  [('b', 0.75), ('a', 0.5), ('c', 0.0), ('d', 0.0)]
```

读法：`b` 两路都在（`norm_v=1.0, norm_f=1.0` ⇒ 0.5+0.5=0.75）；
`a` 是向量路第一（`norm_v=1.0, norm_f=0` ⇒ 0.5）；
`c` 是向量路末位（`norm_v=0`）、`d` 是全文路末位（`norm_f=0`）⇒ **都是 0.0，并列**。

### 2.6 归一化系数项

| 系数 | 默认 | 作用 |
| --- | --- | --- |
| `vector_weight` | 0.5 | 向量路归一化分的线性系数 |
| `fulltext_weight` | 0.5 | 全文路归一化分的线性系数 |
| `rrf_k` | 60 | **本算法不使用**（签名保留以统一 `fuse()` 调用） |
| `both_channel_bonus` | 1.5 | **本算法不使用** |

### 2.7 `detail` 回写字段

`weighted_average_fusion` 为每个候选写入：

`vector_norm`、`fulltext_norm`（保留 6 位）、
`vector_score`、`fulltext_score`（原始分；未出现时为 `None`）、
`vector_rank`、`fulltext_rank`（1-based；未出现时为 `None`）、
`in_vector`、`in_fulltext`（布尔）。

## 三、算法 ②：RRF 倒数排名融合 `rrf`

**代码**：`rrf_fusion()`（`fusion.py:179-212`）
**标签**：`RRF 倒数排名融合`；公式串：`Σ w/(k+rank)`

### 3.1 公式

```
            ⎧ w_v / (rrf_k + rank_v(c))    若 c 出现在向量路
score(c) =  ⎨ + w_f / (rrf_k + rank_f(c))  若 c 出现在全文路
            ⎩   （两路都有则两项相加；都没有则 c 不存在）
```

`rank` 从 **1** 开始；`rrf_k = max(1, int(rrf_k))`（`< 1` 时被夹到 1，不报错）。

### 3.2 实现要点

* **只用名次、不用原始分** ⇒ 天然免疫两路分数的量纲差异，这是它相对加权平均的核心优势；
* 结果 `round(..., 10)`；因为分母是 `rrf_k + rank`，分值很小（实测 `0.0079~0.0163`）；
* 单路末位块**不会**像加权平均那样被压到 0（名次是 1-based，分母有限）；
* `rrf_k` 越大，名次差异越被压平（更强调「两路都出现」而非「某路第一名」）：
  `k=60` 时 `1/(61)` 与 `1/(62)` 的差距只有约 1.6%。

### 3.3 优点 / 缺点

| 优点 | 缺点 |
| --- | --- |
| 免疫量纲差异，**不会**被 BM25 的大数值淹没 | 丢弃了「分差信息」：某路 top1 领先第二名很多时，RRF 看不到 |
| 两路都命中的块自然获得两份贡献 ⇒ 天然奖励一致性 | 分值绝对值小、范围窄，不适合直接当「置信度」展示 |
| 无需归一化，永不产生 0 分候选（单路候选也保有贡献） | 与 `score_threshold` 配合时需要靠相对口径（阈值是相对最高分的比例） |
| 工单4 `hybrid_search` 的既有默认口径，行为已被验证 | 需要额外调 `rrf_k`；调不好会把「双路命中」与「单路第一」的相对关系搞反 |

### 3.4 适用场景

* 两路分数**量纲/分布完全不可比**时的默认选择（例如余弦 vs BM25）；
* 候选集来自 3 路以上（未来加入 CLIP 图像通道）时，RRF 是最省心的合并方式；
* 想复刻工单4 基线排序时（配合 `PRESETS["hybrid_rrf"]`）。

### 3.5 实测样例

同一组输入（`a/b/c` 向量，`b/d` 全文），权重 0.5/0.5，`rrf_k=60`：

```
rrf:  [('b', 0.0162612374), ('a', 0.0081967213), ('d', 0.0080645161), ('c', 0.0079365079)]
```

读法：`b` = 0.5/61 + 0.5/61；`a` = 0.5/61；`d` = 0.5/62；`c` = 0.5/62。
`a` 与 `d` 的差距只来自各自通道的名次位置 —— 这正是「只用名次」的直接后果。

### 3.6 归一化系数项

| 系数 | 默认 | 作用 |
| --- | --- | --- |
| `rrf_k` | 60（`DEFAULT_RRF_K`，与工单4 `RetrievalSettings.rrf_k` 一致） | 平滑常数 |
| `vector_weight` | 0.5 | 向量路贡献的系数 |
| `fulltext_weight` | 0.5 | 全文路贡献的系数 |
| `both_channel_bonus` | 1.5 | **本算法不使用** |

### 3.7 `detail` 回写字段

`vector_rank`、`fulltext_rank`、`vector_score`、`fulltext_score`、
`rrf_vector`、`rrf_fulltext`（两路各自的 RRF 贡献，未出现时为 `0.0`，保留 10 位）、
`in_vector`、`in_fulltext`。

> 额外 `notes`：`rrf_k=60；不使用原始分，仅用名次`（实测）。

## 四、算法 ③：投票机制 `voting`

**代码**：`voting_fusion()`（`fusion.py:218-260`）
**标签**：`投票机制（Borda 计票 + 双路命中加成）`；公式串：`(w_v·Borda_v + w_f·Borda_f)·bonus / Σ`

### 4.1 公式

把每一路看成一位「投票人」，每路对自己的 `N` 个候选给出 Borda 分：

```
Borda_ch(c) = N_ch - rank_ch(c) + 1          （第一名得 N，末名得 1）
raw_votes(c) = w_v · Borda_v(c) + w_f · Borda_f(c)      缺项那一路取 0
bonus(c) = both_channel_bonus (=1.5)  若 c 两路都被提名；否则 1.0
score(c) = raw_votes(c) · bonus(c) / (w_v · N_v + w_f · N_f)
```

分母 `total_votes = w_v·N_v + w_f·N_f` 是「全部选票」；`≤ 0` 时用 `1.0` 兜底。
最大可得分为 `both_channel_bonus`（两路都排第一时：`(w_v·N_v + w_f·N_f) × 1.5 / 分母 = 1.5`），
故值域为 `(0, 1.5]`。

### 4.2 实现要点

* **Borda 分只与名次和该路候选数有关**，因此候选数不同的两路也能公平计票；
* 权重在这里的语义是「投票人话语权」：`w=0` 的那一路等于弃权；
* 「两路同时提名」的块额外 ×1.5 —— 这是投票相对加权平均的核心差异：
  **一致同意的证据被显式奖励**，而单路高频噪声拿不到这个加成；
* 结果 `round(..., 8)`。

### 4.3 优点 / 缺点

| 优点 | 缺点 |
| --- | --- |
| 显式建模「一致性」：双路命中直接乘加成，压制单路噪声 | 引入一个额外超参 `both_channel_bonus`，需要理由来支撑取值 |
| 兼顾名次与「覆盖度」（Borda 分随 N 变化，隐含「该路有多少候选」的信息） | 与 RRF 一样丢弃原始分差信息 |
| 分数上界明确（1.5），便于跨查询做粗略比较 | 当两路命中率差异悬殊（例如一路只召回 3 条、另一路 20 条）时，Borda 分会偏向候选多的那一路 |
| 单路候选仍保有非零分，不会像加权平均那样被压成 0 | 归一化分母含 N，解释成本略高于前两者 |

### 4.4 适用场景

* 单路噪声明显（例如全文路被一个生僻词带出一堆无关块）时，想**奖励双路共识**；
* 候选集来自多路、且各路「候选数量」本身有信息量时；
* 评审需要「为什么这个块排第一」的一句话解释时（`both_channels: true` + `bonus: 1.5` 很直观）。

### 4.5 实测样例

同一组输入（向量 3 条：`a/b/c`；全文 2 条：`b/d`），权重 0.5/0.5：

```
voting:  [('b', 1.2), ('a', 0.6), ('c', 0.2), ('d', 0.2)]
```

读法：分母 = `0.5×3 + 0.5×2 = 2.5`。
`b` = `(0.5×2 + 0.5×2) × 1.5 / 2.5 = 2.0×1.5/2.5 = 1.2`（两路都提名，拿满加成）；
`a` = `(0.5×3) × 1.0 / 2.5 = 0.6`；`c` = `(0.5×1)/2.5 = 0.2`；`d` = `(0.5×1)/2.5 = 0.2`。

### 4.6 归一化系数项

| 系数 | 默认 | 作用 |
| --- | --- | --- |
| `both_channel_bonus` | `VOTING_BOTH_CHANNEL_BONUS = 1.5`（`fusion.py:56`） | 双路命中块的乘数；**不是** `StrategyConfig` 字段，策略层暂不暴露 |
| `vector_weight` / `fulltext_weight` | 0.5 / 0.5 | 两位「投票人」的话语权 |
| `rrf_k` | 60 | **本算法不使用**（签名保留） |

### 4.7 `detail` 回写字段

`borda_vector`、`borda_fulltext`、`votes`（加权计票，保留 6 位）、
`both_channels`（布尔）、`bonus`（1.5 或 1.0）、
`vector_rank`、`fulltext_rank`、`vector_score`、`fulltext_score`、
`in_vector`、`in_fulltext`。

> 额外 `notes`：`Borda 计票 + 双路命中加成 ×1.5`（实测）。

## 五、三算法对比表

| 维度 | `weighted_average` | `rrf` | `voting` |
| --- | --- | --- | --- |
| 是否使用原始分 | **是**（先 min-max 归一化） | 否（只用名次） | 否（只用名次 + 候选数） |
| 是否免疫量纲差异 | 归一化后免疫 | **天然免疫** | **天然免疫** |
| 缺项（单路候选）处理 | 另一路补 `0.0` | 只累加存在的一路 | 只累加存在的一路 |
| 单路末位块得分 | 可能是 `0.0`（实测） | 非零（`w/(k+rank)`） | 非零（`w·1/分母`） |
| 双路命中是否有额外奖励 | 隐式（两份加权分相加） | 隐式（两项相加） | **显式 ×1.5 加成** |
| 分值范围 | `[0, w_v + w_f]`（默认 `[0,1]`） | 约 `[0, (w_v+w_f)/(k+1)]` | `(0, 1.5]` |
| 输出精度 | 8 位小数 | 10 位小数 | 8 位小数 |
| 主要超参 | `vector_weight` / `fulltext_weight` | `rrf_k` + 权重 | `both_channel_bonus` + 权重 |
| 是否为工单4 基线口径 | 否 | **是**（`hybrid_search` 用 RRF） | 否 |
| 是否工单6 默认 | **策略层 `StrategyConfig` 默认** | 由预设 `hybrid_rrf` 使用 | 由预设 `hybrid_voting` 使用 |
| 解释成本 | 低（权重即话语权） | 中（要说明 k 的作用） | 中（要说明 Borda 与加成） |
| 可解释 detail 字段数 | 8 | 8 | 10 |

## 六、统一入口与错误处理

```python
# fusion.py:266
def fuse(algorithm, vector_hits, fulltext_hits, *,
         vector_weight=0.5, fulltext_weight=0.5, rrf_k=DEFAULT_RRF_K) -> FusionResult
```

* `algorithm` 先做 `str(algorithm or "").strip().lower()`，因此大小写与空白不敏感；
* **未知算法抛 `ValueError`，不静默回退**（实测原文：
  `未知融合算法：'bogus'（可选：weighted_average, rrf, voting）`）。

为什么不能静默回退到默认算法？—— 因为「用户选了 RRF 却悄悄跑了加权平均」
会产出一份**看起来正常、实际口径不同**的排序，且没有任何痕迹。
调用方 `retrieval_strategy.search_by_strategy()` 拿到异常后不再包一层，
由 `StrategyConfig.validate()` 在检索前先把 `fusion` 合法性拦掉；
即便绕过校验直接调 `fuse()`，也会立刻失败。这与工单4「回退动作必须写日志、绝不静默」的纪律同源。

**唯一允许的「回退」是权重清洗**（`_weight_pair`），且必须写 `notes` —— 见 §1.3。

### 返回值结构

```python
@dataclass(slots=True)
class FusionResult:
    algorithm: str                       # weighted_average / rrf / voting / single_channel
    scores: dict[str, float]             # chunk_id -> 融合分
    detail: dict[str, dict[str, Any]]    # chunk_id -> 可解释字段（见各算法 §x.7）
    vector_weight: float = 1.0           # 清洗后的生效权重
    fulltext_weight: float = 1.0
    notes: list[str] = field(default_factory=list)

    def ranked(self) -> list[tuple[str, float]]    # 降序；同分按 chunk_id 升序（稳定）
    def to_dict(self) -> dict[str, Any]            # algorithm / algorithm_label / 权重 / candidates / notes
```

`single_channel` 不是融合算法，而是 `mode ∈ {vector, fulltext}` 时的占位标识：
此时 `scores[cid] = 本路原始分 / 本路最高分`，`detail` 只含 `vector_score`+`vector_rank`
（或 `fulltext_score`+`fulltext_rank`）。阈值与 Top-K 仍在策略层统一处理。

## 七、算法选择速查

| 你的情形 | 建议 |
| --- | --- |
| 无特殊理由 / 需要向评审解释权重含义 | `weighted_average`（策略层默认） |
| 两路分数分布差异大、担心归一化失真 | `rrf` |
| 单路噪声多、想奖励「两路都同意」的块 | `voting` |
| 需要与工单4 基线排序对齐 | `rrf`（并注意 `混合检索架构.md` §5.3 的 4 条差异） |
| 只跑单通道 | 把 `mode` 设为 `vector` / `fulltext`，融合环节自动跳过（`algorithm="single_channel"`） |
