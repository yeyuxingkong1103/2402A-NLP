## 一、启动

```bash
cd D:\xinzg6\zy-gq\工单9

# ① 确认本地大模型在运行（界面与问答都依赖它）
ollama serve

# ② 启动界面
streamlit run app.py        # → http://localhost:8501
```

**首次启动会预热约 70 秒**（加载 bge-m3 嵌入模型、Reranker 精排模型、
BM25 倒排索引、并把 qwen2.5:3b 载入显存）。这是**一次性**开销；
不预热的话，第一个问题会被冷启动拖到 50 秒以上。

界面右上角可在**中文 / English** 之间切换。

## 二、提问

「**问答**」页签：

1. 在输入框中输入问题（中文或英文均可，答案语言跟随提问语言）；
2. 点击「提问」；
3. 结果分四块展示：
   - **答案** —— 结构化要点，每条结论后带 `[n]` 引用标记；
   - **引用来源** —— 答案下方自动附上 `[n]` 对应的文档、页码、
     `block_type` 与块 ID（**由系统生成，不是模型写的**，所以不会出错）；
   - **图谱事实** —— 本次检索到的知识图谱结构化事实（已按相关性筛选）；
   - **检索到的原文块** —— 每条给出文档名、页码、`block_type`、块 ID 与得分，
     可展开查看原文。

**中英文示例**

| 语言 | 示例问题 |
| --- | --- |
| 中文 | 平安银行2019年年度报告的董事长致辞中，提到其盈利增长的关键因素有哪些？ |
| 中文 | 对比平安银行2019年末与招商银行2019年末的不良贷款率，哪一家更低？ |
| English | What were Postal Savings Bank of China (601658) NPL ratio and provision coverage ratio at the end of 2019? |

## 三、查看优化前后对比

「**优化对比**」页签：输入一个问题，点「同时运行 08 基线与 09 优化」，
左右两栏分别显示：

- **左：08 基线（优化前）** —— 调用工单08 的原始链路；
- **右：09 优化后** —— 调用本工单的三层优化链路。

每栏下方显示本次耗时、图谱事实条数与文本块数，可直接对比。

## 四、查看指标看板

「**指标看板**」页签展示：

- **RAGAS 核心指标**：context precision（要求 ≥ 0.8）、context recall（要求 ≥ 0.9），
  并与 08 基线并列显示变化量；
- **辅助检索指标**：Precision@k / Recall@k / Hit Rate / MRR / NDCG@k；
- **响应时间**：均值、最大值、超 3 秒题数。

> 看板读取 `data/eval/compare_summary.json`。若为空，先执行：
> ```bash
> python -m w9.run_eval --set main --systems wo08,wo09 --ragas core
> python -m w9.compare
> ```

## 五、查看知识图谱

「**系统状态**」页签展示 09 图谱的规模统计（节点数、边数、实体类型分布、
关系类型分布）。图谱产物位于：

| 文件 | 用途 |
| --- | --- |
| `data/kg09/kg.pkl` | 运行时加载（最快） |
| `data/kg09/kg.graphml` | 可读文本，供 Gephi / yEd 打开 |
| `data/kg09/kg_entities.jsonl` | 实体明细（审计） |
| `data/kg09/kg_relations.jsonl` | 关系明细（含证据与来源页） |
| `data/kg09/merge_log.jsonl` | 合并过程留痕（每条闸门拒绝了多少） |

查看图谱统计：

```bash
python -c "from w9.qa_v2 import get_kg9; import json; print(json.dumps(get_kg9().stats(), ensure_ascii=False, indent=2))"
```

## 六、常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 首问 50 秒以上 | 未预热 | 正常；预热是一次性的。可在启动后先随便问一题「热身」 |
| 界面提示「09 图谱不可用」 | 未构建 09 图谱 | 运行 `python -m w9.kg_merge` |
| 界面提示「LLM 生成失败」 | Ollama 未启动 | 运行 `ollama serve`；答案会降级为抽取式（图谱事实 + 原文片段），仍可交付 |
| Qdrant 报「already accessed」 | 同目录被别的进程占用 | 09 已使用独立副本 `data/qdrant`；若副本缺失，先复制一份 |
| 答案很短或空 | 问题过长 / 上下文不足 | 缩短问题；检查「检索到的原文块」是否为空 |
| 引用编号没有对应来源 | 模型写了不存在的编号 | 系统会忽略无法解析的编号（只列出真实存在的） |

一键体检：

```bash
python -c "from w9.runtime9 import health_check; import json; print(json.dumps(health_check(), ensure_ascii=False, indent=2))"
```

## 七、命令行用法（无界面）

```bash
# 单题问答（09 优化链路）
python -c "
from w9 import config9; from w9.qa_v2 import ask_v2; from src.kg_store import KnowledgeGraph; from src import rag
rag.warmup()
kg = KnowledgeGraph.load(config9.KG9_PICKLE)
r = ask_v2('平安银行2019年年度报告的董事长致辞中，提到其盈利增长的关键因素有哪些？', kg)
print(r.answer)
"

# 批量评测
python -m w9.run_eval --set main --systems wo08,wo09 --ragas core

# 生成对比报告
python -m w9.compare
```
