## 2. 冒烟测试（关键问题与修复）

冒烟测试阶段暴露并修复了以下工程问题：

1. **进程被 OOM 杀死（exit 137）**：上一会话残留的 streamlit/uvicorn 服务占用 ~3GB 内存，WSL 总内存仅 7.6GB。清理残留进程后解决。
2. **`Qwen2VLProcessor` 无 `pad` 方法**：`DataCollatorForSeq2Seq` 依赖 tokenizer.pad。改为自定义 collator，用 `processor.tokenizer.pad` 补齐文本、cat 视觉张量。
3. **`pixel_values` / `image_grid_thw` 被 `[0]` 索引破坏维度**：视觉字段必须保留完整张量，否则 `get_vision_position_ids` 报 `cannot unpack non-iterable int`。
4. **缺 `mm_token_type_ids`**：Qwen2-VL 的 M-RoPE 需要 processor 返回的 `mm_token_type_ids`，随文本字段一并补齐传入。
5. **图像过大导致显存/内存峰值高**：在 dataset 与 evaluate 中统一将图像最长边限制为 384px。

修复后冒烟测试通过：4 样本完成 1 epoch，loss 4.23→1.94，适配器成功保存。

## 3. 完整微调结果

- 训练样本：102（含图 85 + 纯文本 17 大致比例），评估 18
- 配置：LoRA r=16/alpha=32，lr=1e-4，fp16 + gradient checkpointing，batch=1，grad_accum=4
- 可训练参数：18,464,768（0.8290%）
- 1 epoch 耗时 ~67s，3 epoch ~209s；loss 从 4.23 降至 1.0~2.0 区间，整体下降
- 显存峰值 < 5GB（8GB 显卡可稳定运行）

训练曲线见 `docs/screenshots/04_train_loss.png`。
