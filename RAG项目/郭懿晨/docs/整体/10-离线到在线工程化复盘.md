# 10 · 离线到在线工程化 · 复盘与避坑（v1 → v2）

> **主题**：把「离线脚本管道」升级成「在线 Web 服务」（上传→异步构建→状态机→检索/问答），并叠加 v2 检索重排迭代的工程要点与坑。
> **价值**：下次做任何「脚本转服务」或「检索链路迭代」任务，直接对照本节 checklist，避开同类暗坑。
> **来源**：本项目 v1/v2 实现（`backend/app/`）+ 两轮评测跑通过程中的真实经验。

## 1. 背景：为什么「串起来」≠「调用函数」

离线脚本（解析→清洗→分块→向量化→入库）一次跑完即可；转在线服务后，多出的是离线阶段**完全不存在**、也最容易出 bug 的东西：**上传后不能阻塞 HTTP 响应、任务要可查询、进度要可展示、资源要受控、失败要可诊断**。而 v2 迭代再次证明：**「召回变好」≠「引用变好」**——召回之后还要粗排、精排、阈值过滤一整条链路把关。

## 2. 核心差异表（难点全在这 6 列）

| 维度 | 离线脚本 | 在线服务（本项目） |
|---|---|---|
| 执行 | 同步一次跑完 | 上传后**不能阻塞 HTTP 响应** → FastAPI `BackgroundTasks` 异步 |
| 状态 | 无「状态」概念 | 任务状态机：pending→parsing→cleaning→chunking→embedding→upserting→completed/failed |
| 进度 | 看 stdout / 结果文件 | `progress` 逐步回写（20→45→60→75→90→100）+ 前端轮询 |
| 进程 | 独占，随便跑 | **Qdrant embedded 单进程锁**：uvicorn 与独立脚本/评测不能同时开 `data/qdrant` |
| 资源 | 一次性 | 慢模型（BGE-M3 加载、MinerU 解析分钟级、重排推理）不能卡请求 → 进后台任务 |
| 数据假设 | 自己攒类型，跑通即可 | 跨路径/跨阶段类型要一致，失败要落 `error_message` |

## 3. 工程要点与坑（现象 / 根因 / 规避）

### 坑 1 · MinerU 环境集成（HGNetV2/transformers5 兼容补丁）
- **现象**：MinerU 3.4.x 在 transformers 4.x 下 PP-DocLayoutV2 layout 检测全空，静默回退 pypdf；升级 transformers 5.x 后又可能报 backbone/属性缺失。
- **规避**：`mineru.py` 顶部兼容补丁（注册 backbone、补 RTDetrModelOutput 属性、包装 safetensors）+ `scripts/patch_mineru_tf5.py` 幂等补丁（config 校验顺序、decoder head 位置、buffer 重置）；requirements 锁定 `transformers==5.7.0` + `mineru==3.4.5`。
- **教训**：强依赖库的版本兼容补丁集中到适配层/独立脚本，别散落业务代码；**环境变化后先跑 verify_pipeline 自检**。

### 坑 2 · 解析必须兜底（pypdf 降级）
- **规避**：`MinerUParser.parse_pdf` 捕获异常/空结果 → 自动回退 `pypdf` 段落提取，保证链路不中断。
- **教训**：核心环节要有**降级路径**，失败可见可诊断，而不是整体崩溃。

### 坑 3 · 页码有效性红线（page < 1 禁止入库）
- **规避**：`build_chunks` 遇到 `page < 1` 直接 `raise` → 任务 failed + error_message。
- **教训**：**数据入口做契约校验**，宁可失败也不要脏数据进库。

### 坑 4 · 嵌入模型双模式（FlagEmbedding / sentence-transformers）
- **规避**：`BgeM3Embedder` 自动探测——FlagEmbedding 1.4.2 可用优先（真实 lexical_weights）；否则 sentence-transformers + 字符计数哈希稀疏兜底。
- **教训**：**同一能力多种实现路径**，探测优先、降级兜底，接口（dense+sparse）保持一致。

### 坑 5 · Qdrant 检索的 MemoryError 兜底
- **规避**：`search()` 捕获 `MemoryError` → 回退轻量 `scroll`（dense=None → 粗排回退 rrf_score）。
- **教训**：资源受限环境要有**轻量降级**，检索不可用时不能白屏。

### 坑 6 · `Prefetch` 需对象而非 dict
- **规避**：`prefetch=[models.Prefetch(query=…, using="dense", limit=…), …]`，`query=FusionQuery(fusion=RRF)`。
- **教训**：查询结构必须传**类型对象**（Qdrant 模型类），别传裸 dict。

### 坑 7 · v2 重排：召回空间要大，截断要留余量
- **现象**：首轮 v2 用 `candidate=30 → coarse=10 → final=6`，recall 反而比 v1 退化（-0.10）——相关页被截掉。
- **规避**：`final_top_k` 调到 4 配合新口径后 recall 转正（+0.083）；**评测口径变了（k 变小）结论会翻转**，迭代要同时看 recall/MRR/拒答三个数。
- **教训**：重排参数不是越大越好也不是越小越好，**用评测数据说话**，改一个数跑一轮对比。

### 坑 8 · v2 精排模型：懒加载 + 缓存 + 不静默降级
- **规避**：`FineReranker` 模块级缓存（`_FLAGRANKER_CACHE`，chat 与 eval 共享）；模型缺失/加载失败/打分异常 → **抛可诊断错误**，不允许静默降级成错误排序的引用。
- **教训**：精排是「质量守门员」，出错要大声，不能悄悄放水。

### 坑 9 · v2 域外拒答是精排的隐藏价值
- **现象**：v1 对域外问题（天气/无关标准）不过滤直接调 Ollama 作答，20 条安全集**全误答**（拒答率 0）。
- **规避**：v2 精排把无关候选压到阈值外 → 兜底拒答（拒答率 0→0.92）；**延迟反而下降**（少调 20 次 Ollama）。
- **教训**：重排不只提升「答对」，还提升了「该拒则拒」——评测必须包含拒答指标，否则会高估 v1。

### 坑 10 · 评测脚本的破坏性 vs 真实性
- **现象**：早期 `run_sf6_eval.py` 每次 `reset/rebuild`（删 `data/qdrant` + `state.json` 重建），既慢又可能误删用户已入库数据。
- **规避**：v2 迭代后**直接对当前真实检索库打分**（保留 pdf_path 参数仅为兼容），库为空时打印提示。
- **教训**：评测要「真实、可复现、不破坏」——**评估对象就是线上那个库**，结果才有说服力。

### 坑 11 · 配置漂移（.env.example 与代码默认不一致）
- **现象**：`config.py` 的 `final_top_k` 已调为 4，但 `.env.example` 仍是 6（无 `.env` 时用代码默认，行为正确；一旦有人复制 .env 就漂移）。
- **规避**：改配置默认值时**同步更新 `.env.example`**；文档中显式标注当前生效值。
- **教训**：配置的「代码默认值 / 示例文件 / 实际 .env」三处要保持一致，否则排查半天。

## 4. 通用教训（五条）

1. **降级路径**：核心环节（解析/嵌入/检索）都要有兜底实现，失败可诊断。
2. **契约校验**：数据入口做校验（页码/文件名/类型），脏数据不进库。
3. **重排迭代靠评测**：参数改动必须跑 v1/v2 对比（recall/MRR/拒答/延迟），不拍脑袋。
4. **资源锁/单进程**：Qdrant embedded 单进程锁，测试与正式物理隔离。
5. **评测不破坏数据**：对真实库打分，reset/rebuild 类操作先备份或独立目录。

## 5. 下次做服务/迭代的 checklist

- [ ] 上传接口不阻塞：后台任务（BackgroundTasks/线程池）+ 可查询状态
- [ ] 解析/嵌入/检索都有降级路径，失败落 `error_message`
- [ ] 数据入口契约校验（页码 ≥1、非 PDF 拒绝、文件名清洗）
- [ ] 任务状态机：步骤显式回写，终态由主管线 return 后设置
- [ ] 进度诚实：步骤级即可，不虚构页级
- [ ] Qdrant embedded：单进程锁、进程内缓存客户端、测试/正式物理隔离
- [ ] FusionQuery 用 `Prefetch` 对象，不传 dict
- [ ] 重排：候选扩大 + 分层截断留余量；改参数必跑对比评测
- [ ] 精排模型：懒加载缓存、错误大声（不静默降级）
- [ ] 评测包含拒答指标（域外拒答是安全红线）
- [ ] 评测对真实库打分，不破坏用户数据
- [ ] 改配置默认值同步 `.env.example`（三处一致）
- [ ] 环境大变更后跑 `scripts/verify_pipeline.py` 自检
