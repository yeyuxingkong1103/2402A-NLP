# 测试方案与执行流程

> **工单编号**：人工智能 NLP-RAG-基于 PDF 文档的问答系统优化

---

## 一、测试目标

验证优化后 RAG 问答系统是否满足工单验收标准：

1. **功能**：10 道题答案准确率 ≥ 90%；
2. **性能**：端到端响应时间 ≤ 3 s；
3. **稳定性**：支持长时运行，能处理常见异常；
4. **对比性**：可量化给出优化前后检索精确度变化。

---

## 二、测试策略

采用「**基线对照 + 消融分析**」策略：

- **基线对照**：同一数据、同一题目，分别跑"优化前（01 工单复刻）"与"优化后"两条链路，保证 before/after 可比；
- **消融分析**：通过 `answer_baseline_extractive`（仅换答案合成）与 `answer_optimized_llm`（仅换检索）两条消融链路，隔离"检索优化"与"答案合成优化"各自的贡献；
- **自动化**：评估脚本自动统计准确率、Top-1 命中率、MRR、耗时，并生成报告与图表，可一键复现。

## 四、测试指标定义

| 指标 | 定义 |
|---|---|
| 答案命中率（Accuracy） | 最终答案包含参考答案关键线索的题目占比 |
| 检索 Top-K 命中率（Recall@K） | 返回的前 K 个片段中至少一个含关键线索的题目占比 |
| 检索 Top-1 命中率（Precision@1） | 排位第一的片段即含关键线索的题目占比 |
| MRR | 首个命中片段排名倒数的平均值（越接近 1 越好） |
| 端到端耗时 | 从调用 `answer_*` 到返回答案的墙钟时间 |

## 五、执行流程

```
① 环境准备
   conda activate langchain2
   ollama serve（并确保已 pull bge-m3:567m、deepseek-r1:1.5b）

② 构建向量库（优化前 + 优化后）
   python scripts/build_kb.py --all

③ 运行对比评估（自动预热，避免冷启动计入耗时）
   python scripts/evaluate.py
   → output/evaluation_report.json
   → output/evaluation_report_markdown.txt

④ 生成对比图表
   python scripts/make_figures.py

⑤ 界面功能验证
   streamlit run app.py
   → 单题问答 / 前后对比 / 批量评估 逐项验证

⑥ 稳定性测试
   连续提问、异常输入、关闭 Ollama、删除向量库等场景验证
```

## 八、风险与限制

| 风险 | 说明 | 缓解 |
|---|---|---|
| 评测口径依赖关键线索 | 命中判定基于关键线索子串匹配，非人工语义评判 | 线索取自人工核对的参考答案，覆盖核心数值/专名 |
| 本地模型资源占用 | 生成模型推理慢（仅基线链路使用） | 最终方案采用抽取式合成，不依赖生成模型 |
| 单文档单领域 | 仅在招股说明书语料上验证 | 算法与参数通用，可迁移至同类 PDF 文档 |
| 硬编码噪声词 | `_NOISE_PATTERNS` 针对本公司名定制 | 可通过配置扩展，不影响通用检索能力 |
