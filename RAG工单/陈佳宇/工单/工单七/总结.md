# 工单7 RAG功能测试及评估｜项目总结
工单编号：人工智能NLP‑RAG‑功能测试及评估

## 1.任务完成情况
本工单基于工单6混合检索RAG系统副本，完成RAG功能测试与检索评估任务。
1. 保留向量检索、BM25全文检索、RRF混合检索三种检索模式，网页端可以手动提问测试。
2. **新增批量评估模块**，实现召回率、精确率指标计算，程序启动自动输出10条测试问题的检索结果与评估指标。
3. 完成10条业务问题测试，对比三种检索模式的表现，分析检索存在的问题，如语义漂移、漏召回。
4. 完成全套文档编写：设计、研发、测试、优化、部署、总结。

## 2.学到知识点
1. 掌握RAG检索阶段评估指标：召回率、精确率的含义与计算方式。
2. 加深理解向量检索、BM25、RRF混合检索各自优势与短板。
3. 理解RAG系统常见缺陷：语义漂移、漏召回，知道对应的优化思路。
4. 学会对RAG系统做完整的功能测试、量化评估、问题分析。

## 3.项目遇到的难点与解决
1. 前端JS全角符号，导致网页点击提交无响应，修改为半角符号解决。
2. 向量检索语义漂移问题，通过RRF融合BM25关键词能力进行缓解。
3. 评估模块如何比对检索结果和真值，实现批量自动化输出评估报告。

## 4.系统不足
1. 文本切分策略简单，仅使用换行分割，文本块大小不均匀，影响检索效果。
2. 评估方式是简单字符串匹配，不是语义匹配。
3. 存在部分测试用例召回率低，出现漏召回。
4. 使用pymilvus旧ORM接口，存在弃用警告。

## 5.后续拓展方向
1. 使用递归字符分割优化文本分块，设置重叠窗口。
2. 接入Reranker重排序模型，过滤无关召回片段，提升精确率。
3. 将pymilvus旧ORM接口升级为MilvusClient新版接口。
4. 优化评估逻辑，使用向量相似度做评估，替代简单字符串匹配。

## 6.实训整体收获
工单7完整走完RAG系统的**测试‑评估‑问题分析‑优化方案设计**完整流程。
明白了RAG不能只看能否返回结果，需要使用召回率、精确率做量化评估；单一检索策略都存在短板，多路融合可以显著提升RAG检索稳定性。
