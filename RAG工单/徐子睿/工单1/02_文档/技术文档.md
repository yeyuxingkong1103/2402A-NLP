# 招股说明书智能问答系统 —— 技术文档

> 工单编号：人工智能 NLP-RAG-基于 PDF 文档的问答系统优化
> 版本：v1.0 ｜ 语料：《招股说明书1.pdf》（武汉兴图新科电子股份有限公司科创板招股意向书，548 页）

---

## 一、项目概述

### 1.1 目标
把一本 548 页的招股意向书做成本地可运行的智能问答系统：用户用自然语言提问，系统从原文中检索依据并生成**带页码引用**的答案；无依据时明确拒答，不编造。

### 1.2 核心能力
1. **Query 理解**：意图识别（事实/数值/列举）、术语改写扩展、**口径消歧（金额 vs 占比）**、中英语言识别。
2. **检索与生成**：稠密 + 稀疏双路召回、加权 RRF 融合、**跨语（英→中）术语映射检索**、LLM 生成与引用溯源、拒答。
3. **交互**：对话界面、语音输入、中英双语问答、RAG/纯 LLM 对比、反馈收集。

### 1.3 技术栈
| 环节 | 选型 | 说明 |
|---|---|---|
| PDF 解析 | MinerU 3.4（pipeline）+ PyMuPDF 兜底 | 输出结构化 markdown + `content_list.json`（带 `page_idx`） |
| 分块 | 标题感知滑窗 600/120 | 块携带 `page / page_end / section / type` |
| 嵌入 | bge-m3（Ollama） | 1024 维，多语，支持中英 |
| 向量检索 | numpy 余弦（常驻内存） | 单文档万级块毫秒级 |
| 稀疏检索 | jieba + BM25（自实现） | 补数字/专名漏召回 |
| 融合 | 加权 RRF（λ=2.5, k=60） | 向量路权重更高 |
| 生成 | qwen2:7b（Ollama） | RAG 与纯 LLM 同模型，保证对比公平 |
| 服务/前端 | FastAPI + 原生 HTML | SSE 流式，零构建 |

## 二、系统架构与数据流

```
用户提问
  │
  ▼
[Query 理解]  意图识别 · 术语改写扩展 · 语言识别
  │
  ▼
[混合检索]  ┌─ bge-m3 向量召回 top20 ─┐
            └─ jieba BM25 召回 top20 ─┘ → 加权 RRF 融合 → 去重 → top5
  │
  ▼
[置信度判断] 最高余弦 < REFUSE_SCORE → 拒答（固定话术）
  │ 否
  ▼
[生成] 组装带 [第X页] 标注的上下文 → qwen2:7b（温度 0.1）→ 带引用答案
  │
  ▼
[前端] 流式展示 + 引用溯源 + 反馈
```

**离线构建链路**：`PDF → MinerU 解析 → 清洗 → 分块 → bge-m3 向量化 → 索引落盘`。

## 四、关键设计说明

### 4.1 为什么用 MinerU
招股书含大量**表格**（财务报表、募集资金表）。纯文本层抽取会把表格拍平成“值+单位”序列，丢失行列对应关系，导致数值题答错。MinerU 输出：
- `*_content_list.json`：每块带 `type`（text/table/image）、`text_level`（标题级）、`bbox`、**`page_idx`**；
- 表格以 HTML `<table>` 保留结构，可还原“行=项目、列=年度”。

`page_idx` 是**页码溯源的基石**——引用页码直接取自它，不靠猜。

### 4.2 分块策略
1. **标题感知**：MinerU 已标注标题级，结合正则（`第X节`、`一、`、`（一）`）把小节作为上下文边界；
2. **小节内滑窗** 600/120，避免跨节污染；
3. **表格独立成块**，防止被切散；
4. 每块记录 `page / page_end / section / type`。

### 4.3 混合检索与 RRF
- 稠密（语义）+ 稀疏（关键词）互补：向量擅长“意思相近”，BM25 擅长“数字/专名精确命中”。
- 加权 RRF：`score = λ/(k+rank_dense) + 1/(k+rank_sparse)`，λ=2.5 偏向向量路，k=60 抑制顶端权重过激。
- **去重**：多页重复句（如“重要供应商”“国家科技进步一等奖”在多页出现）按“文本前 40 字 + 章节”去重，只保留一条，避免引用页码飘移。

### 4.4 拒答
- `confidence = 命中片段中的最高余弦相似度`；低于 `REFUSE_SCORE` 时返回固定话术，不调用 LLM。
- 阈值需按实际分布校准（见 §六 评估）。

### 4.5 生成约束（忠实性）
Prompt 五要素强制：只用片段信息、数值逐字照抄、每条结论标【第X页】、无依据直言“未找到依据”。

### 4.6 口径消歧（金额 / 占比）
招股书里“军用领域收入 6,464.51 万元”与“军用领域收入占比 82.10%”常在同一页相邻出现。
若只按语义相似度，问“金额”会召回“占比”段落 → 答非所问。做法：
- 用规则判定问题口径（`_hit_caliber`）：金额词（多少/金额/万元/收入/资本/revenue/capital/how much…）vs 占比词（占比/比重/percentage/proportion…），**中英双语同一套规则**；
- 问金额时：把“只含百分比、无万元数值”的块降权（×0.45），把含`万元`数值的块升权（×1.25）；
- 问占比时：把完全不含 `%` 的块降权。

### 4.7 跨语（中英）检索
英文提问时不是把英文直接丢给检索，而是做**术语级映射**后拼中文检索词（`cross_lingual_expand`）：
- `registered capital→注册资本`、`legal representative→法定代表人`、`military revenue→军用领域收入`、`upstream→上游 电子元器件制造企业` 等；
- 按口径补“收入金额 万元 / 占主营业务收入比重 占比”；
- **仅当问题问“发行人工商登记类信息”**（registered capital / legal representative / registered address…）时才补公司全名——实测无条件补全名会把“公司名称表格页”抬到首位，反而拉低命中（改为条件补全名后英文 10 题 Hit@5 = 100%）。

### 4.8 生成结果清洗
小模型偶发“把 prompt 模板当题干续写”或回显模板。`clean_answer()` 在 `【用户问题】/【Question】/【作答要求】` 等模板标记处截断；
英文 System Prompt 另加两条硬约束：① `万元` = 10,000 CNY，写 `X 万元` / `X ten-thousand CNY`，**禁止换算成 million**；② 多期数据要逐期列出，禁止压成区间。

## 五、接口文档

统一响应结构：`{"code":0,"data":...,"message":""}`

| 方法 | 路径 | 请求 | 响应要点 |
|---|---|---|---|
| GET | `/api/health` | - | 模型可用性、索引是否就绪 |
| GET | `/api/kb/overview` | - | 块数、维度、页码范围 |
| GET | `/api/kb/chunks?offset=&limit=` | - | 分块分页浏览 |
| POST | `/api/search` | `{query, top_k}` | 命中的 page/section/score/text |
| POST | `/api/ask` | `{query}` | answer/refused/confidence/cost_ms/hits |
| POST | `/api/ask/stream` | `{query}` | SSE：先 `meta`（命中+置信度）后 `delta`（文本） |
| POST | `/api/ask/llm` | `{query}` | 纯 LLM 答案（对照） |
| POST | `/api/feedback` | `{query, vote}` | 落盘 feedback.jsonl |
| POST | `/api/upload` | multipart file | 保存 PDF，提示重建 |

**SSE 示例**
```
data: {"type":"meta","hits":[...],"confidence":0.71,"refused":false}
data: {"type":"delta","text":"报告期内"}
data: {"type":"delta","text":"公司来自军用领域的收入……"}
data: {"type":"done"}
```

## 六、评估方法

### 6.1 检索指标
- **Hit@1 / Hit@3 / Hit@5**：top-k 中是否命中金标准页码；
- **MRR**：命中排名的倒数均值。
- 运行：`python evaluation/run_eval.py` → 输出 `retrieval_result.json`。

### 6.2 生成指标
- **忠实度 Faithfulness**：答案是否全部可在检索片段中找到依据（人工/LLM 双评）；
- **答案相关性 Answer Relevancy**：是否直接回应所问；
- **数值一致性**：金额/百分比与原文逐字一致（如“6,464.51 万元”“82.10%”）；
- **引用正确率**：标注页码是否确为答案出处。

### 6.3 10 题评测集（金标准已逐题定位）
见 `evaluation/eval_questions.json`。10 题覆盖：数值多值（260/33）、事实单点（95/531/543/957）、列举（34/793）、表内数值（207）、含易错点（795）。

### 6.4 多语言（中英）评估
- `evaluation/run_eval_en.py`：与中文同 10 题（同 id、同金标准）的英文问法，考察跨语检索；
- `evaluation/build_bilingual_qa.py`：跑中英各 10 题并落盘 `report_bilingual.md`（含答案与引用命中）；
- 实测：中文 Hit@5 100% / MRR 0.750；英文 Hit@5 100% / MRR 0.883；引用命中金标准页均 10/10。

### 6.5 RAGAS 标准指标体系
- `evaluation/run_ragas.py`（独立 venv，见 `evaluation/README_ragas.md`）：计算 faithfulness、answer_relevancy、
  context_precision、context_recall、answer_correctness；裁判 LLM/嵌入走本机 Ollama（qwen2:7b + bge-m3），不产生外部费用。
- 结果落盘 `ragas_result_zh.json` / `ragas_result_en.json`。

### 6.6 并发 / 高可用压测
- `evaluation/load_test.py`（标准库，无额外依赖）：对运行中的服务分级并发压测，统计 QPS、平均/尾延迟、错误率。
- 结论：检索接口并发无错误；生成接口受单卡 7B 算力限制（Ollama 串行），QPS 约 1.3，延迟随并发上升但错误率 0。

### 6.7 RAG vs 纯 LLM 对比方案
同模型、同温度；RAG 注入检索片段，纯 LLM 不注入。逐题记录答案、耗时、引用、正确性（完全正确/部分/错误）与是否编造。预期：RAG 在事实/数值题显著领先，且引用可溯源；纯 LLM 在涉密脱敏名称（“某大型研究所”“某视频技术规范”）处易编造或答不出。

## 七、性能与容错

| 目标 | 措施 |
|---|---|
| 端到端 ≤ 3 s | 索引常驻内存；LLM 流式（首字 <1 s）；相同问题答案缓存 |
| 高并发 | 检索无状态、可多 worker；生成受单卡限制（实测 QPS ≈1.3，0 错误，见 §6.6）；超载限流 |
| 容错 | ①输入空/超长 → 校验拦截；②MinerU 失败 → PyMuPDF 兜底；③模型不可用 → 明确报错/降级 |
| 构建原子性 | 构建失败不覆盖旧索引 |

## 八、已知限制与后续优化

1. **表格数值**：极端跨页表格仍需人工校验；后续可加“数值一致性”自动断言。
2. **拒答阈值**：需按实际相似度分布校准（见评估结果）。
3. **重排**：当前 RRF 后直接取 top5；后续可加 LLM 重排（0-5 分）提升排序稳定性。
4. **多语言**：已用“术语映射 + 条件补公司名”的跨语检索（英文 Hit@5 100%）；如换域可继续补术语表，或加“先译中再检索”。
5. **解析耗时**：MinerU 548 页约 40-60 分钟（GPU），已缓存，二次构建秒级复用。
