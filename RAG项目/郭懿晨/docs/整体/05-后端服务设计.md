# 05 · 后端服务设计（v2）

> **环节**：把数据管线 + 检索问答**服务化**（上传/任务/文档/向量库/问答）。实现见 `backend/app/`。
> 详案：`docs/需求说明.md`（FR1-18）、`docs/v2/spec.md`（v2 重排规格）。

## 一、服务定位（四大能力）

| 能力 | 说明 |
|---|---|
| ① 上传 + 文档管理 | 上传 PDF（校验/清洗文件名）、创建文档与任务记录、文档列表 |
| ② 构建任务 | 启动任务（BackgroundTasks 后台执行）、任务状态查询（步骤/进度/错误） |
| ③ 向量库内容 | 向量库记录列表、类别列表（MinerU 标签） |
| ④ 问答（v2） | `POST /api/chat`：RRF 召回 → 粗排 → 精排 → Ollama 生成 → 引用返回/拒答 |

## 二、核心模块（backend/app/）

| 模块 | 职责 |
|---|---|
| `main.py` | FastAPI 入口：注册 4 组路由、挂载 `frontend/` 静态资源、`/` 返回 SPA、`/health` |
| `routes_files.py` | 上传：校验 PDF → 保存 → 创建 Document + BuildTask → 返回 `{document_id, task_id}` |
| `routes_tasks.py` | 启动任务（`background_tasks.add_task`）、查询任务；构造 BuildPipeline（含 VLM 后处理） |
| `routes_documents.py` | 文档列表 / 向量库记录 / 类别列表 |
| `routes_chat.py` | v2：`build_retrieval_chain(...)` 构造 RetrievalChain，chat 走 `chain.retrieve(question)` |
| `rerank.py`（v2 新增） | 粗排/精排/RetrievalChain（见 04） |
| `pipeline.py` | `BuildPipeline.run`：PARSING(20%) → CLEANING(45%) → CHUNKING(60%) → EMBEDDING(75%) → UPSERTING(90%) → COMPLETED(100%)；异常 → FAILED + error_message |
| `storage.py` | `JsonStateStore`：`data/state.json`（documents/tasks/chunks 三段） |
| `config.py` | `AppSettings`：读 `.env`（路径/模型/端口/**重排参数：final_top_k=4 等**/阈值） |

## 三、任务状态机（v1 不变）

```
Document:  uploaded → indexing → indexed / failed
BuildTask: pending → parsing → cleaning → chunking → embedding → upserting → completed / failed
```

- **触发**：`POST /api/tasks/{task_id}/start` → FastAPI `BackgroundTasks` 异步执行（不阻塞 HTTP 响应）
- **查询**：`GET /api/tasks/{task_id}` → `{task_id, document_id, step, progress, status, error_message, created_at, updated_at}`
- **展示**：前端**轮询**任务状态（不用 SSE）；进度为步骤级（诚实进度 NFR4）
- **原子性**：任何一步异常 → 任务 `failed` + `error_message`、文档 `failed`（NFR5）
- **持久化**：`data/state.json` 重启可查（FR13）

## 四、前端（SPA，原生 HTML/CSS/JS）

`frontend/index.html` + `app.js` + `app.css`，无框架、无构建。5 个视图：**上传 / 任务 / 文档 / 向量库 / 问答**。

| 视图 | 数据来源 |
|---|---|
| 上传 | `POST /api/files/upload` |
| 任务 | `POST /api/tasks/{id}/start` + `GET /api/tasks/{id}`（轮询） |
| 文档 | `GET /api/documents` |
| 向量库 | `GET /api/vector-store` + `GET /api/categories` |
| 问答 | `POST /api/chat`（答案 + 引用卡片 + fallback 提示；v2 下 citation.score 语义为精排相关性分 0~1，前端标签不变） |

## 五、辅助脚本（scripts/）

| 脚本 | 用途 |
|---|---|
| `run_sf6_eval.py` | 评测：`--variant v1\|v2\|both`，**直接对当前真实检索库打分（不 reset/rebuild）** |

## 六、环境依赖（详见 08）

- 需 **Ollama**（`deepseek-r1:7b`）问答才可用
- 需 **BGE-M3 本地模型**（`D:\八维学习\bge-m3`）构建与检索才可用
- **v2 需 bge-reranker-v2-m3**（`D:\八维学习\bge-reranker-v2-m3`）精排才可用；路径缺失 → 可诊断错误（不静默降级）
- 需 **MinerU 3.4.5**（transformers 5.x + `patch_mineru_tf5.py`）高质量解析；无则回退 pypdf
- **Qdrant embedded 单进程锁**：`data/qdrant/` 同时只能被一个进程打开
- **GPU 建议**：精排 v2-m3 在 CPU 上仍达标（本轮实测 avg 2.68s 含生成），有 CUDA 时自动 fp16 更快
