## 2. 判分口径（先定义，后判定）

### 2.1 「≥90%」在多轮序列上的等价

| 口径 | 分母 | 判据 | 读数位置 |
| --- | --- | --- | --- |
| **主口径：逐轮准确率** | 5 轮 | 5×90% = 4.5 → **必须 5/5**（4/5 = 80% **不达标**） | `summary.json` → `n_turns` / `n_passed` / `accuracy`（定义字段 `accuracy_definition` = `passed_turns / total_turns`） |
| **并列口径：会话整体准确率** | 2 个 session（seq1 三轮 + seq2 两轮） | **2/2**：该 session 全部轮次 passed 才算通过 | `summary.json` → `n_sessions_all_passed` / `session_accuracy` |
| 扩展口径：多轮 5 轮 + 单轮回归 16 题 | 21 | 21×90% = 18.9 → **≥19/21** | 上表两个文件相加 |
| 指代消解专项（逐维度） | 5 轮 × 4 个改写维度 | **每个维度 5/5（`rate == 1.0`）** | `summary.json` → `dimension_pass.{strategy_match, focus_match, rewrite_contains, focus_in_rewrite}` |

> 主口径与并列口径**必须同时报告**（跑分器已同时输出）；不得只报有利的那个。
> **独立会话对照**（`isolated.jsonl`）的降级轮次**不计入**多轮准确率分母（其角色是「证明这些轮次确实依赖上下文」，见 §3.5）。

### 2.2 判分器（**唯一**，禁止自评）

| 用途 | 判分实现 | 判定字段 |
| --- | --- | --- |
| **多轮 5 轮（主）** | `测试/测试数据/多轮判分.py::judge_case(case, result)` → `{"passed", "checks":[...], "reasons":[...]}` | `results.jsonl` 的 `passed` / `checks` / `check_details` / `reasons` / `judged_by` |
| 单轮 16 题回归 | `测试/common/golden.py::judge_answer(record, answer)` | `regression16.json` 的逐题 `correct` / `reason` |

* 数值归一化**单一实现来源**：`测试/common/golden.py::normalize`（多轮判分在其之上追加 CJK 逗号/全角空格规整）。
  → 千分位逗号、全角半角、`%`↔「百分之」、`万元`↔`亿元` 等价，`6,464.51 ≡ 6464.51`。
* **十个判分维度**（`check` 名 → 含义）：
  `answer_present`（答案非空）/ `answer_must_contain`（必含项）/ `answer_must_contain_any`（任含项）/
  `answer_must_not_contain`（禁含项）/ `refused_match`（拒答一致）/ `strategy_match`（**改写策略一致**）/
  `focus_match`（**焦点实体一致**）/ `rewrite_contains`（**改写结果含期望问句**）/ `focus_in_rewrite`（**改写结果含焦点实体**）/
  `no_leak`（无跨会话实体泄漏）。
* **禁止**用 LLM 自评冒充准确率；判分结果里 `judged_by` 必须写明「确定性判分（`测试/测试数据/多轮判分.py::judge_case`），非 LLM 自评」。

### 3.1 MT1/MT2/MT3/MT5 与工单4 16 题的关系

* MT1 ≡ 工单4 `id=260`（证据页 `招股说明书1.pdf` 页 129）；MT2 ≡ `id=795`（页 27，同句异页 155/157/181/182/241）；
  MT3 ≡ `id=531`（`招股说明书1.pdf` 页 22）；MT5 与 `id=5`（`招股说明书2.pdf` 页 39 组织结构图）**同源但问法不同**：
  MT5 只问「哪个销售部的销售处最多 / 有哪些销售处」，**不问销售部由几个部门构成**。
* MT5 的禁含项因此与 `id=5` 不同：**不得**把其余三个部门（`国际贸易部`/`渠道销售部`/`电话及网络销售部`）当答案列出。
  **禁止**直接照搬工单4 `id=5` 的关键字清单来判 MT5。

### 3.3 改写正确性（多轮专属，逐轮逐字断言）

| 轮 | 期望 `strategy` | 期望 `rewritten_query`（归一化空白后**逐字**比对） | 判分维度 |
| --- | --- | --- | --- |
| MT1 | `none` | 与原句相同（用例 `expected_rewrite` 为空 = 不改写） | `strategy_match` + `focus_match` |
| MT2 | `pronoun` | 武汉兴图新科电子股份有限公司参与的哪个工程荣获了国家科技进步一等奖？ | 上述 + `rewrite_contains` + `focus_in_rewrite` |
| MT3 | `pronoun` | 武汉兴图新科电子股份有限公司的法定代表人是谁？ | 同上 |
| MT4 | `ellipsis_entity_switch` | 武汉力源信息技术股份有限公司的法定代表人是谁？ | 同上（**实体切换 + 槽位继承的合体判据**） |
| MT5 | `none` | 与原句相同 | `strategy_match` + `focus_match` |

> 依据：`设计/Query改写流程.md` §6.6。若某轮 `strategy` 或 `rewritten_query` 不符，**即使答案碰巧判对，该轮仍判不达标**
> （否则无法区分「多轮生效」与「单轮碰巧」）。
> **`strategy_distribution` 的期望直方图**：`{"none": 2, "pronoun": 2, "ellipsis_entity_switch": 1}`
> —— 这是一个**可机械断言**的分布判据（多一个 `topic_carry` 或 `multi_turn_enrich` 都说明规则跑偏）。

| 轮次 | `focus_entity` | `last_slot` | `entity_stack` |
| --- | --- | --- | --- |
| MT1 后 | 武汉兴图新科电子股份有限公司 | 军用领域收入（或等价骨架，见下注） | `[兴图新科]` |
| MT2 后 | 武汉兴图新科电子股份有限公司 | 国家科技进步一等奖工程 | `[兴图新科]` |

| MT4 后 | 武汉力源信息技术股份有限公司 | **必须含「法定代表人」** | `[兴图新科, 力源]` |
| MT5 后 | 武汉力源信息技术股份有限公司 | 组织结构图-销售部-销售处 | `[兴图新科, 力源]` |

* 读取方式：`MultiTurnEngine.state(session_id)`（或 HTTP 侧等价接口）→ `focus_entity` / `last_slot` / `entity_stack`；`turns` 长度 `≤3`。
* **`last_slot` 表示差异（已登记）**：`设计/接口契约_冻结.md` §1.1 的注释把 `last_slot` 示例写作 `"法定代表人"`（**字段名表示**），
  而落地实现采用**槽位骨架表示**（把实体与指代词挖掉后的问句骨架，如 `"法定代表人是谁？"`，见 `研发/app/core/dialogue_state.py` 模块说明）。
  两种表示都满足契约的「上一轮问的字段槽位」语义，且都能唯一还原补全模板。
  → **本文件的判据取两者之交**：`last_slot` 与 `MultiTurnAnswer.rewrite.inherited_slot` **非空且包含「法定代表人」**；
  同时要求该表示差异登记进 `设计/接口契约_冻结.md` 或 `测试/测试报告.md`（不得留暗坑）。
* 表内「兴图新科/力源」为简称，实际断言必须是**全称**。

### 3.5 独立会话对照（**证明多轮改写确实生效**）

| 项 | 内容 |
| --- | --- |
| 用例 | `测试/测试数据/工单5多轮用例_独立会话.jsonl`（每轮换新 session） |
| 产物 | `测试/测试数据/多轮评测结果/<run-tag>/isolated.jsonl` |
| 关键字段 | `degraded_expected`（该轮是否**依赖上下文**）/ `counts_toward_multiturn_accuracy` |
| **判据** | ① MT2/MT3/MT4（`expect_degraded=true`）在独立会话下**消解不生效**（`strategy="none"` 或答案缺 `must_contain`）；② MT1/MT5（`expect_degraded=false`）不受影响，仍可作答；③ 降级轮次**不计入**多轮准确率分母 |
| 作用 | 排除「单轮本来就能答对」的假阳性，使多轮增益可归因；**不得**把对照轮的失败当成缺陷 |

## 5. 延迟口径（与工单4 保持一致，最容易被测歪）

| 项 | 定义 |
| --- | --- |
| **主口径** | **客户端 wall**：请求发出 → 完整答案返回（`latency_wall_ms`） |
| **辅助口径** | 服务端 `latency_ms.total`；**改写段** = `latency_ms.rewrite`（多轮增量开销，必须单独报） |

### 3.4 判分口径（**必须写进测试报告**）

1. **判对 = 确定性关键字判定**：答案（数值归一化后）含该题**全部** `answer_keywords`，且**不含**任何 `forbidden` 关键字。
   - 数值归一化：去千分位逗号、全角转半角、`%` 与「百分之」等价、`万元/亿元` 按原值比对
     （例：`15,000 万元` 与 `15,000.00万元` **等价**，见 id 207 页 490）。
   - `answer_keywords_any_of`：**任一命中即算该组通过**，用于兜住同义/简称正答
     （例：id 95 的正名《某视频指挥系统技术规范（1.0版）》与简称**《某视频技术规范1.0》**）。
   - **禁止**用 LLM 自评冒充准确率；若另做 LLM 辅助判定，必须**并列**给出确定性判定结果并说明差异。
2. **「检索命中」≠「回答判对」**，两者**分别报告**：
   - 检索命中 = 证据原文（`evidence` 逐字或归一化后）**落在返回的 chunk 中**；
   - 命中判定只用 **`evidence_pages_complete` + `supporting_pages`**（合称 `evidence_pages`）；
     **`related_pages` 不参与命中判定**（无证据原句，参与会虚高命中率）；
   - **不得**以「引用页 == `evidence_pages`」判定命中（会把无关页误计为命中、虚高）。
3. 逐题记录：问题、系统答案、golden 答案、是否判对、证据页、检索命中与否、`latency_ms`、引用是否可回溯。
4. 第 5、6 题须额外记录：`extraction_method`（`clip_zero_shot` / `geometry+anchor` / 纯几何）、框图/图表解析产物路径。
