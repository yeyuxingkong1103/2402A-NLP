# 工单13 RAG性能瓶颈识别与优化｜总结文档
## 1.任务完成情况
✅ 理解RAG五大链路阶段：查询处理增强、检索、prompt组装、LLM生成、后处理。
✅ 实现全链路埋点计时，结构化日志记录每个子阶段耗时，request_id追踪单条请求。
✅ 使用cProfile工具做应用级性能分析，定位慢函数。
✅ Locust实现负载测试，模拟并发压力，观察延迟、吞吐量。
✅ 分析常见RAG性能瓶颈：LLM推理、rerank、embedding、向量检索、prompt上下文过大。
✅ 实现多组优化开关，采集优化前后性能对比数据。

## 2.学习收获
1. RAG性能问题不能只看总耗时，需要分阶段埋点，定位到底哪个环节慢；
2. 生产环境RAG最大性能瓶颈通常是LLM生成阶段；rerank、embedding、向量检索也会成为瓶颈；
3. 掌握性能排查工具：cProfile、snakeviz做应用分析；locust负载测试；结构化日志埋点；
4. 理解各类优化手段：缓存、关闭/降级rerank、控制上下文长度、限制输出token、使用轻量模型。
5. 压力下才容易暴露真实瓶颈，单条请求看不出并发场景性能问题。

## 3.现存不足
1. 实训没有接入OpenTelemetry分布式追踪、Prometheus监控；
2. 没有Linux系统级perf工具分析；
3. 压测只是简单locust模拟，没有复杂真实业务流量。

## 4.后续拓展方向
1. 接入OpenTelemetry实现分布式追踪；
2. 部署Prometheus+Grafana做指标可视化和告警；
3. 使用perf做系统级性能分析；
4. k6做更加专业的负载测试。
