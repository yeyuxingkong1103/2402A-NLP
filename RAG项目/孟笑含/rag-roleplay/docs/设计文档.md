# RAG 角色扮演系统 · 设计文档

## 1. 系统概述

基于大模型的角色扮演聊天系统（character.ai 类）：支持多用户 × 多角色（虚拟朋友、医生、律师、教师等），角色人设与提示词模板可配置；每个角色拥有独立知识库（RAG），对话时混合检索知识并注入大模型；多轮对话有短期记忆（Redis）与全量持久化（MySQL）。

## 2. 技术架构

```
┌─────────────┐  HTTP/JSON + SSE    ┌──────────────────────────────────────────┐
│  客户端/压测 │ ──────────────────► │ FastAPI (uvicorn, 可多实例+nginx 反代)      │
└─────────────┘                     │  ├─ api/     路由层（users/roles/chat/knowledge）│
                                    │  ├─ services/ 对话编排、知识库服务             │
                                    │  ├─ core/    LLM兼容层、提示词模板            │
                                    │  ├─ store/   Redis短期记忆                  │
                                    │  ├─ rag/     分块/BM25/PDF/Milvus/本地模型    │
                                    │  └─ eval/    RAGAS评测工具                  │
                                    └──────┬───────────────┬──────────────┬──────┘
                                           │               │              │
                              ┌────────────▼──┐  ┌─────────▼──────┐  ┌────▼──────────────┐
                              │ MySQL         │  │ Redis          │  │ 在线 LLM API      │
                              │ 用户/角色/消息 │  │ 短期记忆/token │  │ DeepSeek(OpenAI协议)│
                              └───────────────┘  └────────────────┘  └───────────────────┘
                              ┌────────────────┐  ┌─────────────────────┐
                              │ Milvus (Docker)│  │ 本地模型 (CPU)        │
                              │ 每角色Collection│  │ BGE-m3 / BGE-reranker│

```

### 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| LLM 接入 | OpenAI 兼容协议统一封装（`core/llm.py`） | 本地 vLLM/SGLang 与在线 API（DeepSeek/豆包/千问）只改配置切换 |
| 检索方式 | 稠密向量 + BM25 稀疏向量混合检索，RRF 融合，再重排 | 兼顾语义与关键词（如"140/90"精确匹配），RAGAS 实测 recall 1.0 / precision 0.97 |
| 父子块 | 子块(~700)检索 + 父块(~2400)做上下文，命中子块映射回完整父块 | parent_child 模式 precision 达 1.000；长文档上下文更完整 |
| BM25 | 客户端 jieba 分词生成稀疏向量入库 | 稳定可单测，兼容 Milvus 2.4+（当前 v3.0.0） |
| 短期记忆 | Redis List（`chat:history:{uid}:{rid}`，最近 10 轮，TTL 7 天） | O(1) 裁剪；多用户×多角色天然隔离；MySQL 另存全量 |
| 知识库 | 每角色一个 Milvus Collection（`role_kb_{id}`） | 角色领域知识隔离（律师查法条、医生查指南） |
| 提示词 | 模板存库（含 `{knowledge}` 占位符），知识块指令在运行时注入 | 三轮 RAGAS 验证：faithfulness 0.718→0.951；旧模板启动自动升级 |
| 模型加载 | LazyModelProxy 线程安全懒加载 | 压测发现：use_rag=false 也会触发 23s/2.5GB 加载且并发竞态 |
| 数据库连接池 | pool 20 + overflow 40 | 压测发现默认 5+10 在 50 并发耗尽排队 30s |

## 3. 功能设计

### 3.1 模块划分

| 模块 | 职责 | 关键文件 |
|---|---|---|
| 路由层 | 参数校验、鉴权、响应组装 | `app/api/{users_roles,chat_knowledge,deps}.py` |
| 依赖注入 | DB 会话、Redis、记忆、LLM、知识库服务、当前用户 | `app/api/deps.py` |
| 对话编排 | 取历史 → 拼提示词 → 调 LLM → 写记忆 | `app/services/chat_service.py` |
| 知识库服务 | PDF 入库（解析→分块→向量化→写入）、检索（混合→重排） | `app/services/knowledge_service.py` |
| 长期记忆 | 每轮对话沉淀到 Milvus 记忆库（user×role 隔离），相似度阈值检索注入 | `app/services/memory_service.py` |
| 提示词模板 | 人设+历史+知识块+few-shot 组装（运行时函数，不存库） | `app/core/prompts.py` |
| LLM 兼容层 | OpenAI 协议 chat / 流式；MOCK 开关 | `app/core/llm.py` |
| RAG 组件 | 分块、清洗、去重、校验、BM25、PDF(解析/去水印)、Milvus、本地模型 | `app/rag/*` |
| 评测工具 | 题库、管线、RAGAS、对比、报告 | `app/eval/*` |

### 3.2 对话主流程

```
请求 → 校验 token(Redis) → 查角色(MySQL) → [use_rag 时] 知识检索
     → 长期记忆检索(Milvus, 相似度过滤) → 取最近10轮历史(Redis)
     → 拼提示词(人设+历史+知识块+长期记忆)
     → 调大模型(流式/非流式) → 写短期记忆(Redis) + 全量消息(MySQL) → 返回(reply+sources)
```

### 3.3 知识入库流程

```
PDF上传 → 去水印 → 清洗 → 分块（CHUNKING_MODE：sentence 句子聚合 / heading 标题前置 / semantic 相似度切分）→ 去重
       → BGE-m3向量化(1024维) → BM25稀疏向量(jieba词表fit现有语料)
       → 写入 Milvus Collection(每角色) → 立即可检索（Strong一致性）
```

### 3.4 检索流程

```
用户问题 → 稠密向量检索 + BM25稀疏检索 → RRF融合召回30 → BGE-rerank重排 → Top4注入提示词
```

## 4. 数据模型（MySQL）

- `users(id, username唯一, password_hash, created_at)` —— 密码 sha256+盐
- `roles(id, name唯一, category, persona, prompt_template, created_at, updated_at)`
- `messages(id, user_id, role_id, sender, content, created_at)` —— 索引 (user_id, role_id, created_at)

Milvus Collection（每角色 v3）：`id自增 / text / summary / parent_id / dense(1024) / sparse / source / created_at / updated_at`；父块集合 `role_parents_{id}`（文本+占位向量）；长期记忆库 `user_memory_{uid}_{rid}` 同构

## 5. 质量保障

| 层面 | 手段 | 结果 |
|---|---|---|
| 单元/集成测试 | pytest 156 用例（SQLite+真Redis+假LLM，无需外部服务） | 全绿 |
| RAG 评测 | RAGAS 三轮 + 双 judge 锚点 | faithfulness 0.718→0.951/0.961；recall 1.0 |
| 性能压测 | JMeter 四场景（10/50/100 并发 + nginx 双实例） | 见 `stress_report/压测报告.md` |
| 可观测 | Python logging（各模块 logger），Swagger 文档 | — |

## 6. 已知限制与后续演进

- 已做：PDF 去水印、数据清洗、块级/文档级去重、抽取式摘要字段、Query 改写扩写、后处理数值校验、长期记忆、父子块；未做：OCR、LLM 摘要、多路召回（MySQL/互联网等）、Embedding 微调（需 GPU）

- 本地 LLM（Qwen 27B vLLM/SGLang）需 GPU，当前环境用在线 API
