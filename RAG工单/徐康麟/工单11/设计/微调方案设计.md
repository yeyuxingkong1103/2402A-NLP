# 工单11 微调方案设计

> 覆盖原文《三、微调介绍》与《四、微调实战》全部要素：数据格式、损失函数选型、超参表、训练与评估口径。

## 1. 数据格式设计（原文点名的三种格式）

统一记录 schema（`研发/data/dataset/{train,dev,test}.jsonl`，每行一条 JSON）：

| 字段 | 含义 |
| --- | --- |
| `id` | 记录唯一 id（`{split}-{tri,pair,sim,simpos}-{锚点序号}-{负例序号}`） |
| `格式` | `正例对` / `三元组` / `相似度分数对` |
| `来源` | 锚点构造方式：`指标数值` / `章节标题` / `表格标题` |
| `anchor` / `positive` / `negative` | 锚点（问题）/ 正例段 / 负例段 |
| `score` | 相似度分数对专用：正例 1.0，负例取 `jaccard(anchor, negative)`（字符 2-gram Jaccard，弱监督标注） |
| `负例分数` | 三元组记录上同口径的负例相似度分数（供 CosineSimilarityLoss 复用同一次前向） |
| `正向分块` / `负向分块` | 分块 id（可追溯到工单7 索引，便于人工复核） |
| `文档` / `页码` / `指标` / `数值` / `负例类型` / `锚点序号` | 溯源与分片元信息 |

| 格式 | 对应原文 | 生成规则 | train 条数 |
| --- | --- | --- | --- |
| **正例对** | 「一对相关的句子（例如，问题、答案）」 | 锚点 ↔ 其所在分块 | 1200 |
| **三元组** | 「（锚点、正例、负例）」 | 锚点 ↔ 正例段 ↔ 2 个负例段 | 2400 |
| **带相似度分数的句子对** | 「一对带有相似度分数的句子」 | 锚点 ↔ 正例(1.0) / 锚点 ↔ 负例(Jaccard) | 2400 |

### 1.1 锚点（问题）生成 —— 即原文「运行问答对生成」

1. **指标数值（1325 条）**：从分块正文抽取「财务指标 + 数值」事实。指标词表 70+ 条（含长名优先匹配，避免「净利润」抢走「归母净利润」），另加 `XX率 = 数字%` 兜底正则；共覆盖 **178 个不同指标**。模板化为自然语言问题，**数值不出现在问题中**，例如：
   - `平安银行2019年末不良贷款率为多少？`（正例 = 含该数值的分块）
2. **章节标题（684 条）**：分块 `section` 标题 → `{文档}中「{章节}」章节的主要内容是什么？`
3. **表格标题（289 条）**：表格块 Markdown 表头 → `{文档}第{页}页表格中，{表头}的数据是多少？`

### 1.2 负例挖掘（三层难度）

| 类型 | 规则 | 条数 | 作用 |
| --- | --- | --- | --- |
| 难负例同指标异公司 | 含**同一指标**的其他公司分块 | 803 | 逼模型学到「实体」这一区分性信息（原文的语义鸿沟核心） |
| 中负例同公司异页 | 同文档、不同页、不含该指标 | 2197 | 逼模型区分页级证据，而非「同公司就算对」 |
| 随机负例异公司 | 其他公司任意分块 | 兜底 | 保证嵌入空间有全局间隔 |

每个锚点默认 2 个负例（配置 `每个锚点负例数`），第 1 个优先难负例、第 2 个优先中负例。

### 1.3 防泄漏口径（硬性）

- **页级留出**：每份文档随机留出 12% 的页面（合计 332 / 2769 页），留出页的分块**既不做正例也不做负例**（负例候选池显式过滤）；
- 工单7 的 **17 道真实测试问题从不进入训练**，只在最终评估阶段使用；
- 相似度分数由 `jaccard(anchor, negative)` 机械计算，不含人工标注或模型打分。

## 2. 损失函数选型

原文点名 4 类损失，本工单**全部实现**（`研发/src/losses.py`），训练默认使用「三元组 + 余弦」组合：

| 损失 | 公式（实现口径） | 适用数据 | 是否启用 |
| --- | --- | --- | --- |
| `TripletLoss` | `relu(d(a,p) − d(a,n) + margin)`，`d`=余弦距离 `1−cos`，margin=0.3 | 三元组 | ✅ 主损失，权重 1.0 |
| `CosineSimilarityLoss` | `MSE((cos(a,b)+1)/2, score) × 缩放(=1.0)` | 相似度分数对 | ✅ 辅助损失，权重 0.5 |
| `ContrastiveLoss` | `y·d² + (1−y)·relu(margin−d)²`，欧氏距离，margin=0.5 | 正负句对 | 已实现，可切换（`--损失类型 contrastive`） |
| `MatryoshkaLoss` | 在 512/256/128/64 维截断上分别算基础损失取平均 | 可截断嵌入 | 已实现，可切换（`--损失类型 matryoshka-triplet`） |

**选型理由**：本任务的评测口径是 **Top-K 检索排序**，而不是相似度回归。TripletLoss 直接优化「正例比负例更近」的排序目标，与 Recall/MRR 同向；CosineSimilarityLoss 用弱监督分数提供额外的绝对尺度约束，防止嵌入空间整体塌缩。二者**复用同一次前向**（anchor/positive/negative 三个向量），不额外增加 CPU 开销，故组合权重取 `1.0 : 0.5`（主损失优先）。

## 4. 训练规模与时间预算（实测推导，非估算）

依据 `研发/data/性能标定.json`（本机实测）：

| 项 | 实测值 |
| --- | --- |
| 模型 | 23.95 M 参数 / 512 维 / 4 层 |
| seq=128, batch=24, 含反向 | 2.7363 s/步 → **8.77 序列/秒** |
| seq=64, batch=24, 含反向 | 1.1594 s/步 → 20.7 序列/秒 |
| 纯推理 seq=128 batch=64 | **39.88 序列/秒** |

据此下采样：`1400 三元组 × 3 = 4200 序列 ÷ 8.77 ≈ 479 s ≈ 8 min`，加验证评估与落盘 ≈ 10~12 min，满足 10~25 min 要求且留有余量（配置硬预算 1080 s）。

## 5. 评估口径

1. **留出测试集（150 条查询）**：查询与唯一金标准分块，检索池为 2500 块抽样池（含全部金标准）。
   指标：`Recall@1/@5/@10`、`MRR`、`nDCG@10`、平均命中排名、自助法 95% 置信区间。
2. **相似度指标**：测试集三元组的正例对平均余弦相似度 vs 负例对平均余弦相似度，以及「正负例判别准确率」（成对比较采样 2000×2000）。
3. **端到端真实检索（17 道工单7 测试问题）**：金标准分块由「判分关键词命中数 ≥ max(2, ⌈0.34×关键词数⌉) 且限定在题目来源文档内」反推（阈值降级规则见 `evaluate.py`），指标为 `命中@1/@3/@5/@10`、`MRR`、`关键词覆盖@10`。

> 三套口径互为印证：第 1 套说明「同分布下是否真的学会了」，第 2 套说明「嵌入空间是否被拉开」，第 3 套说明「在工单7 的真实语料与真实问题上是否管用」。
