## 3. Docker（**实测被沙箱拒绝，这是本工单最重要的一条环境事实**）

| 命令 | 实测结果 | 退出码 |
| --- | --- | --- |
| `docker version` | Client 29.7.2 / API 1.55 打印正常；Server 段报 **`permission denied while trying to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`** | **1** |
| `docker ps` | 同上 permission denied | **1** |
| `docker images` | 同上 | **1** |
| `docker volume ls` | 同上 | **1** |
| `docker network ls` | 同上 | **1** |
| `docker info` | Client 段（含 buildx v0.36.1-desktop.1 / compose v5.5.1 等插件）打印正常；Server 段 permission denied | **1** |
| `docker compose version` | **`Docker Compose version v5.5.1`** | **0** ✅ |
| `docker compose config` | **成功**（客户端侧解析，不连 daemon） | **0** ✅ |

**关键结论（决定了本工单的交付形态）：**

1. `docker` CLI **客户端**是好的（29.7.2，插件齐全），但**任何需要 daemon 的操作**都被拒；
   原因是 DSH 沙箱（file policy = `workspace-write`）+ 命名管道 `npipe:////./pipe/dockerDesktopLinuxEngine` 不在允许范围。
2. 本会话 **approval prompts 被禁用**，`sandbox_permissions='danger-full-access'` 提权**
   会被自动拒绝**，因此**不能**通过提权绕过 —— 按约定"提权被拒就不要反复重试"。
3. **意外之喜**：`docker compose config` 属**纯客户端**子命令，**不需要 daemon**，实测可跑通。
   于是「compose 文件是否合法、卷/端口/网络/资源限制是否如设计」这一块**拿到了真实证据**
   （`测试/测试数据/compose配置-解析结果.json` + 截图 `compose配置解析.png`），
   而不是"我看着像对的"。

真实输出原文见 **`部署/日志/docker提权失败证据.log`**（逐条命令 + 完整 stderr + 退出码）。

## 5. 基座（工单7）复用事实

| 项 | 值 | 来源 |
| --- | --- | --- |
| 索引块总数 | **8847** = 文本 7325 + 表格 1417 + 图像 105 | `研发/data/index/bge-m3_1024/index_manifest.json` |
| 嵌入模型 / 维度 | `bge-m3:latest` / **1024** | 同上 |
| 向量后端 | `faiss:IndexFlatIP` | 同上 |
| 语料 | 9 份 A 股年报（平安银行/中国平安/招商银行/邮储银行/中信证券/中国人寿/中国太保/招商证券/国泰君安） | 同上 `chunk_by_corpus` |
| 索引目录体积 | 约 **91 MB**（faiss.index 36.2MB + vectors.npy 36.2MB + chunks_indexed.jsonl 21.1MB + bm25.pkl 11.8MB + ids.json 0.24MB） | `Get-ChildItem` 实测字节数 |
| 复用方式 | `研发/data/index` = **目录联接（Junction）** → `工单7/研发/data/index`；**未复制 1GB 数据** | `设计/环境事实.md` §5 |

**实测的加载耗时（冷启动，本机）**：`QAEngine.warmup(with_generate=False)` 实测
`elapsed_ms = 27286.43`（≈ **27.3 秒**），其中全文索引构建 `20078.44 ms`、实体标注 `2125.23 ms`、
嵌入探活 `331.39 ms`。→ 这直接决定了容器 `HEALTHCHECK --start-period` 必须给到 90~120 秒，
否则容器会被误判不健康（见 `优化/部署优化说明.md` 冷启动章节）。

> ⚠️ 注意：预热日志里 `generate` 项为 `{'ok': False, 'reason': '无可用生成后端（extractive 路径无需预热）'}`——
> 这是**正常的**：`DEPLOY_WARMUP_WITH_GENERATE=0` 时不预热生成模型，生成链路在首个真实问答时按需建立，
> 且 extractive 抽取合成路径本身无需预热。
