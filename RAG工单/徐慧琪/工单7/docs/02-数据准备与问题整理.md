### 文件名还原（一处重要的更正）

`ccf_competition.zip` 由中文 Windows 打包工具生成，条目名以 **GBK 字节**存储且
未置 ZIP 的 UTF-8 标志位（flag bit 11）。Python `zipfile` 按规范默认用 **CP437** 解码，
于是中文变成乱码：

```
默认解码: 2020-02-14__╞╜░▓╥°╨╨╣╔╖▌╙╨╧▐╣½╦╛__000001__…
还原:     2020-02-14__平安银行股份有限公司__000001__平安银行__2019年__年度报告.pdf
```

`name.encode('cp437').decode('gbk')` 即可**无损还原**。
> 注：本工程早期版本曾据一份**已被二次破坏**的解压副本（UTF-8 + replace 解码过一次，
> U+FFFD 替换符已落盘，信息真正丢失）误判为"不可逆"。改为直接处理 zip 条目后，
> 20 个条目逐一验证均可还原。详见 `scripts/setup_project.py` 文档字符串。

规范化后的短名（本工程内部统一口径）：

```
{披露日期}__{公司简称}__{股票代码}__{报告年度}年度报告.{pdf,txt}
```

## 三、10 个测试问题

问题来源：附件 `sample_questions.pdf`。该 PDF 给出 **7 个示例问题**（含参考答案），
为"平安银行董事长致辞盈利增长因素""招商银行创新商业模式""平安银行风险管理体系"
"跨机构经济周期策略对比"等。本工单在其基础上**整理为 10 个可量化评估的测试问题**：
保留 2 道原示例（id1、id2 以可检索化的措辞改写），其余 8 道按**可核验的原文事实**
扩展，确保每题都有**逐字可查的金标准**（原值 / 原句 / 页码）。

### 相关性说明（硬性要求1：必须针对该 PDF 内容，不能是通用问题）

10 道题**全部**指向 ccf_competition 语料中的具体事实，且**逐题用原文核验**：

- 数值全部取自语料原文，且**保留原始单位口径**——这正是本语料的核心难点：
  | 题 | 单位口径 |
  | --- | --- |
  | 中国平安 | 人民币**百万元** |
  | 中国人寿 | 人民币**百万元** |
  | 中信证券 | **元**（币种：人民币） |
  | 招商证券 | **元** |
  | 中国太保 | **亿元** |
  | 邮储银行 | 百分数（0.86% / 389.45%） |

  同一批题目里混用 5 种量纲，能有效检验系统是否"照抄单位"而非臆造换算。
- 问题 9 需要**跨两份文档**取数并比较，问题 10 的证据**只存在于图像中**，
  二者分别针对多跳推理与图像解析能力。

### 金标准自检（评估前质量闸门）

`scripts/validate_ground_truth.py` 对每题逐条 `evidence_fact` 统计全语料命中块数，
防止"金标准写错导致指标假性偏低"。首轮自检发现并修正了两类问题：

| 问题 | 表现 | 处理 |
| --- | --- | --- |
| 事实写成**转述**而非原文 | id10 的 6 条板块名全语料 0 命中（证据在图像中） | 拆分为 `evidence_facts`（判检索，用文本层真实存在的"组织结构图"）与 `key_facts`（判答案，保留板块名，预期得 0 分以暴露缺陷） |
| 事实**过泛**无区分度 | "人民币百万元" 命中 646 块、"招商银行" 命中面过宽 | 移出 `evidence_facts`，单位改由报告人工核对 |

修正后自检结果：**0 条 0 命中、0 条过泛**，各题相关块数收敛到 1—16（合理区间），
page_hint 全部命中（仅 id3 第 13 页因表格单元格写作"0.86"无百分号而未命中，
已在金标准 `page_note` 中注明）。

> 这一步是**必要的**：若不先做，id10 这类题的 Recall 分母会被兜成 1、
> 全部块判为不相关，指标看起来像"系统全面失败"，而实际是金标准口径问题。
