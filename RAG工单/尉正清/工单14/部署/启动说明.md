# 工单14 启动说明

## 目录说明

```
研发/
├── docker/     ← RAGFlow 的部署配置（compose / .env / nginx / service_conf 模板）
└── patches/    ← 本次改动的两个文件，通过挂载覆盖进容器
```

`研发/ragflow/` 下**只保留了 `docker/`**。RAGFlow 的 Python 源码在容器镜像里，
运行时完全用不到本地的源码副本；那 61MB 的 `web/` 加上其余源码目录已删除，
原始副本在附件 `D:\BW\RAG 工单\14-17附件\ragflow-main\`（逐字节相同）。
任务一文档里的 `file:行号` 引用以**附件那份**为准。

## 依赖镜像

先跑 `pull_images.sh` 把镜像拉下来（脚本里带了重试，本机 Docker Hub 直连不通，
走的是 daemon.json 里配的国内加速器）。

## 起 RAGFlow

> `.env` 里有本机密钥，**不在版本库里**，所以克隆下来是没有的。
> 先补一份，否则 compose 读不到 `env_file` 会直接报错。

```bash
cd 研发/ragflow/docker
cp .env.example .env        # 密钥是空的；要调大模型就填 DEEPSEEK_API_KEY
docker compose up -d ragflow-cpu
```

`docker-compose.yml` 里 `ragflow-cpu.volumes` 有**两行工单14 专有挂载**
（搜索「工单14」注释即可定位）：

| 挂载 | 作用 |
|---|---|
| `../../patches/rag/llm/chat_model.py` → `/ragflow/rag/llm/chat_model.py` | 关闭 deepseek 系列推理模型的思维链 |
| `../../patches/rag/prompts/vision_llm_figure_describe_prompt.md` → `/ragflow/rag/prompts/…` | 图纸描述提示词（补上空间次序与气流穿过顺序） |

> **为什么用挂载而不是改镜像**：附件源码比镜像 `v0.23.1` 里的代码新，
> 直接挂附件源码会让容器起不来（`ImportError: thread_pool_exec`）。
> 所以 `patches/` 下的文件是从**镜像里 `docker cp` 出来**再改的。

容器起来后：

```bash
curl -o /dev/null -w "%{http_code}\n" http://localhost/v1/system/version   # 期望 200
```

## 起本机模型服务（嵌入 + 重排）

```bash
D:/Anaconda/envs/rag_gd/python.exe 测试/embedding_server.py --port 9997
```

- 嵌入 bge-m3 → **CPU**（每次只编一条查询，0.25s）
- 重排 bge-reranker-v2-m3 → **GPU fp16**（每次要打 66 条候选分，
  CPU 上要 80s，GPU 上 1.0s）

两个模型都塞 GPU 会占满 6GB 显存（实测只剩 236MB），重排会偶发卡到 70s。

## 存储说明

这份部署用的 MinIO 是宿主上 Milvus 自带的那个（监听 `127.0.0.1:9000`），
RAGFlow 通过 Docker Desktop 的 `host.docker.internal` 访问。
`.env` 里的 `MINIO_PORT=9010` 是**无效的** —— `service_conf.yaml.template`
里端口写死 9000。
