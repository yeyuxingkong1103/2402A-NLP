## 一、任务目标与验收指标

| 指标项 | 工单要求 | 本方案目标值 |
| --- | --- | --- |
| 回答准确率 | ≥ 90% | 10 个指定问题命中 10/10（100%） |
| 端到端响应时间 | ≤ 3 秒 | 单次问答 P95 ≤ 3 s |
| 交互友好性 | 清晰简洁的用户界面 | Streamlit Web UI |
| 多语言支持 | 支持中英文问答 | 中英文分词/双语 Embedding，UI 双语切换 |
| 稳定性 | 长时运行、异常容错 | 文件解析失败降级、输入校验、全局异常处理 |

优化对象为工单一已实现的基线问答系统（朴素 PDF 文本抽取 + 定长分块 + 纯向量 Top-K 检索）。

## 二、基线系统问题分析

通过对工单一系统在 10 个指定问题上的回归测试，定位到三层瓶颈：

1. **PDF 解析层**：仅按字符流抽取文本，存在①页眉页脚（如"招股意向书 1-1-52"）污染正文；②表格被打散成行，数字与项目名称脱离（如募集资金表）；③断行硬回车把完整句子切断，导致"15,000.00 万元"等数字与上下文割裂。
2. **分块层**：固定 800 字无重叠切分，①跨块语义被截断（如"来自军用领域的收入分别为……"与年份分列两块）；②标题与归属正文分离，检索块缺少公司名、章节名等实体上下文。
3. **检索层**：仅用单路向量召回，①数字/专有名词（"5,520 万元""程家明"）在语义空间中区分度低；②无重排，Top-1 经常命中"提及但非答案所在"的块；③无关键词兜底，语义改写后召回漂移。

## 三、总体架构

```
PDF 文档
  │  ① 解析优化层：PyMuPDF 主解析 + pdfplumber 表格兜底
  ▼
结构化 Document（标题/正文/表格/页码，已清洗页眉页脚）
  │  ② 分块优化层：标题感知 + 滑动窗口重叠 + 父块附加上下文
  ▼
Chunk（携带 标题路径/公司名/页码 元数据）
  │  ③ 索引层：BGE 双语 Embedding + 向量库 + BM25 稀疏索引
  ▼
用户 Query（中英文）
  │  ④ 检索优化层：向量召回 ∪ 关键词召回 → RRF 融合 → Cross-Encoder 重排 → Top-K
  ▼
答案抽取/LLM 生成（≤3s 预算控制，含超时降级）
  │
  ▼
Streamlit 交互界面（中/英文）
```

## 四、分层优化方案

### 4.1 PDF 解析处理优化（pdf_parser.py）

- **双引擎解析**：PyMuPDF（fitz）按页提取文本块（block/line 级坐标信息），速度快（百页 < 1s）；对文本稀疏页回退 pdfplumber 提取表格（`extract_table`），表格按 Markdown 表格序列化，保证"项目名—金额"不脱离。
- **噪声清洗**：用正则去除页眉页脚（`招股意向书\s*1-\d+-\d+`、纯页码行）、合并硬断行（中文行尾非终止符则拼接）、全角空格归一化。
- **结构保留**：识别"第X节/X、/（一）"等标题模式，输出带 `heading_path` 的结构化 Document；记录页码 `page_no` 用于答案溯源。
- **容错**：加密/损坏 PDF 抛出自定义 `PDFParseError`，流水线跳过并记录日志，不影响其他文档。

### 4.2 分块优化（chunker.py）

- **标题感知切分**：先按章节标题切段，段内再按句号/分号切句，用贪心算法打包到目标长度（默认 450 字）。
- **滑动重叠**：相邻块保留 80 字重叠，保证跨句事实完整。
- **父块上下文增强（Small-to-Big）**：子块用于向量检索，返回时扩展为所在父段落，并把"标题路径 + 公司全称"前缀拼进块文本，解决指代和实体缺失。
- **表格独立成块**：Markdown 表格不切断，整块入库，块文本前注入表题。

### 4.3 检索优化（retriever.py）

- **双语 Embedding**：默认 `BAAI/bge-base-zh-v1.5`（中英文同模型空间），支持配置切换 m3e；查询侧按 bge 官方建议加指令前缀。
- **双路召回 + RRF 融合**：稠密向量（Cosine Top-20）∪ BM25 稀疏召回（Top-20），用 Reciprocal Rank Fusion（k=60）融合，数字/专名类问题由 BM25 兜底。
- **Cross-Encoder 重排**：`BAAI/bge-reranker-base` 对融合结果精排取 Top-3；无 GPU/无模型时自动降级为"向量分 + BM25 分"加权精排，保证可离线运行。
- **元数据过滤与加权**：标题命中 Query 实体的块加 0.05 权重提升。
- **答案抽取兜底**：无 LLM 环境时，从 Top-1 块抽取含问题焦点实体（数字/人名/枚举项）的句子作为抽取式答案。

### 4.4 性能预算（端到端 ≤ 3 s）

| 环节 | 预算 | 手段 |
| --- | --- | --- |
| 索引加载 | 不计入单次 | 启动时单例加载，向量/索引常驻内存 |
| Query 向量化 | ≤ 120 ms | ONNX/本地小模型，批大小 1 |
| 双路召回 | ≤ 100 ms | numpy 矩阵化余弦 + 纯 Python BM25 |
| 重排 Top-20 | ≤ 1.8 s | Cross-Encoder 截断 256 token；超时降级 |
| 答案生成 | ≤ 0.8 s | 上下文窗口限制 + 流式输出 |

### 4.5 多语言与交互

- Streamlit 页面提供 中文/English 切换；Embedding 与 BM25 分词（jieba + 英文按词）均覆盖中英文。
- 展示答案、来源页码、Top-3 证据块与相关性分数；侧边栏显示各阶段耗时，便于验收演示。

## 五、异常与稳定性设计

- 用户输入为空/超长：前端校验并提示；
- 文档解析失败：`PDFParseError` 捕获、日志记录、跳过坏文件继续建库；
- 模型加载失败：Embedding 降级为 TF-IDF 向量，重排降级为加权分数，保证服务可用；
- 全链路 `try/except` 包装并在 UI 呈现友好错误信息。

## 六、验证方案

使用工单指定 10 个问题（id 260/95/33/34/957/793/795/543/531/207）在《招股说明书1.pdf》上做优化前后 A/B 评测：统计 Top-1 命中率、答案正确率、平均响应时间，并逐题给出优化前/后证据块对比，形成《优化前后检索精确度对比报告》。
