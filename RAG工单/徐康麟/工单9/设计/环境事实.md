## 4. 评测口径的关键环境事实

| 事实 | 影响与处置 |

| **本机没有 ragas** | 自研近似器，并在所有产物标注「关键词/页码近似口径，非 LLM 裁判」 |

## 6. 已知踩坑清单（后续工单可直接借鉴）

1. **`app/core` 是从 工单7 复制的**，其 `config.py::REPO_ROOT` 按**文件位置**计算
   ⇒ 不显式设 `RAG_LOG__DIR` 就会把日志写进**只读的 工单7 目录**（越界写入）。
   本工单在 `OptimizedEngine.__init__` 与 `run_eval_opt._logger` 两处强制覆盖。
2. **`StructuredLogger.log_event()` 已有绑定字段**，传 `profile=` 会
   `TypeError: got multiple values for keyword argument 'profile'`；改用 `engine_profile=`。
3. **`RA.aggregate()` 需要扁平指标键**，把「逐题行」直接丢进去会得到全 0 的假汇总。
4. **`bundle.chunks` 是 `dict[str, dict]`**（不是 list），且 `IndexBundle` 提供
   `page_chunks(file, page)` 的 O(1) 页索引；直接按 list 遍历会 `AttributeError`。
5. **`判分口径.py` 只导出 `judge`**，`normalize` / `contains_keyword` 在 `judge` 上，
   不在模块顶层。
