**录制方式**：`puppeteer-core` 驱动无头 Chromium 打开真实页面 → 按时间轴逐步操作 → 定时截 JPEG 帧 →

字幕用页面内叠加的 `div` 实现，**帧与字幕天然同步**，不需要后期对齐。

## 三、录制方法（可复现）

```bash
# 1) 启动服务（需先完成入库：python scripts/ingest.py）
cd 工单四
D:/myconda1/python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000

# 2) 另开终端，安装录制依赖（首次）
cd frontend
npm init -y && npm i puppeteer-core@21      # 必须锁 21.x：22+ 移除了 recordVideo 接口

# 3) 录制
node ../docs/record_demo.mjs

# 4) 产物
#    docs/video/工单四演示视频.webm
```

**关键实现说明（踩过的坑）**：

- **浏览器**：用 `puppeteer-core` 的 `executablePath` 指向本机已安装的 Chromium/Edge，不下载浏览器。
- **ffmpeg**：只能用 Playwright 自带的精简版 `ms-playwright/ffmpeg-1011/ffmpeg-win64.exe`，
  它**只接受 `image2pipe` 输入**；本机没有独立的 ffmpeg，直接调 `ffmpeg` 会报找不到。
- **截帧而非录屏**：`page.screenshot()` 按固定间隔截 JPEG，帧率靠等待时间控制；
  比录屏更可控，也避免 puppeteer 版本对录屏 API 的依赖。
- **字幕同步**：字幕是页面里注入的固定 `div`，随每步操作切换文案，因此天然与画面帧同步。
- **稳定性**：每步操作后 `waitForFunction` 等到答案区渲染完成再截图，避免截到 loading 中间态；
  单步最长等待 90 秒（DeepSeek 生成较慢时）。

## 四、人工配音版脚本（如需提交讲解版）

> 自动录制版是压缩静默版，内容一致。若需配音版，按上面的分镜表逐镜讲解即可，要点：

1. **开场**（0:00-0:20）：说明工单编号与目标——在工单 01/02 的问答系统上，新增《招股说明书2.pdf》解析，
   并用多模态模型实现**图像内容解析**以提升检索精度。
2. **图像解析讲透**（0:20-1:20）：重点讲 id=6。现场展示：正文里搜不到"IC卡"、搜不到"-2.0"，
   答案只能从图里读出来；再展示 id=5 的组织结构图层级还原。
   强调两个实测细节：**OCR 必须放大 3 倍才读得出负号**、**子节点判定要用"与总线交叠"而不是"中心落在总线内"**。
3. **检索链路**（1:20-2:20）：向量 + BM25 双通道 → RRF 融合 → 重排 → 生成；
   指着指标卡说明"检索/生成耗时分解"的意义。
4. **指标与验收**（2:20-3:30）：逐条对照工单验收项读实测数字——准确率、响应时间、
   检索精确度及其**口径**（在线代理口径 vs 离线带标注口径，两者不同，不能混说）。
5. **容错与部署**（3:30-4:30）：跑 `tests/test_faults.py` 现场打断依赖；演示 docker-compose 与 README 启动步骤。
6. **收尾**（4:30-5:00）：说明哪些是工单四要求、哪些明确没做（见 `docs/design.md` §1.2）。
