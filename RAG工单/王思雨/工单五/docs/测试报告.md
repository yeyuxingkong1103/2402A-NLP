## 二、测试方法

### 2.1 题组设计（`eval/questions.json`）

| 组 | 会话方式 | 题数 | 目的 |
| --- | --- | --- | --- |
| `multi_turn` | **同一会话按顺序** | 5 | 工单五原文 5 问，验证多轮指代消解与实体切换 |
| `english` | 同一会话 | 3 | 验证中英双语与英文多轮 |
| `standalone` | 每题独立会话 | 2 | 验证无历史时也能正确作答 |
| `multi_turn_warm` | 与首轮同会话同问题 | 5 | 单独量测**缓存命中**时的响应时间 |

### 2.2 判分口径

```
正确 = 关键字段全含(expect) 且 负样本全无(expect_not)
```

负样本的作用：**关键词判分抓不到"多答无关内容"**。工单三曾出现自动判分 14/14 满分、人工复核却发现混入 2 家无关企业的情况。
本工单的负样本专门针对"实体张冠李戴"：Q3 的负样本是 Q4 的答案（赵马克），Q4 的负样本是 Q3 的答案（程家明）。

### 2.3 判分器自检（先验证量具，再采信数字）

```
$ python scripts/evaluate.py --selftest
  [OK ] 期望=True  实得=True   武汉兴图新科电子股份有限公司 法定代表人是程家明。
  [OK ] 期望=False 实得=False  该公司法定代表人是赵马克（Mark Zhao）。
  [OK ] 期望=False 实得=False  该公司法定代表人是程家明，力源信息的赵马克也是。   ← 混入无关内容，应判错
  [OK ] 期望=True  实得=True   军用领域收入 6464.51 万元、14414.16 万元。        ← 千分位差异应容忍
  [OK ] 期望=False 实得=False  军用领域收入 6,464.51 万元。                     ← 漏答一半，应判错
判分器自检：5/5 通过
```

**判分器 5/5 通过后才采信下面的准确率数字。**

### 2.4 响应时间口径

- 计时区间：`POST /chat` 的端到端耗时（不含网络往返，服务端 `latency_ms`）。
- **评测默认关闭缓存读取**（`use_cache=False`）。否则重复评测会全部命中缓存，把响应时间测成几十毫秒的假数据。
- 缓存命中耗时单独用 `multi_turn_warm` 组报告。
- 启动预热（约 30.9 秒）**不计入**单次请求耗时；预热在服务启动时完成。

## 五、ragas 四项指标

判官：DeepSeek（`deepseek-chat`）；嵌入：本地 bge-m3；样本数：**10**（`results/eval_20261009_121151.json`）。

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| faithfulness（忠实度） | **0.9708** | 见下方"引用标记的影响" |
| answer_relevancy（答案相关性） | **0.7499** | |
| llm_context_precision_with_reference（上下文精确率） | **0.7752** | |
| context_recall（上下文召回率） | **0.8000** | |

### 5.1 引用标记对忠实度指标的影响（重要口径说明）

faithfulness 的判官会把答案拆成一条条独立陈述逐条核对。工单**要求**回答附带引用（如【招股说明书1 P129】），
但引用标记不是内容主张，会被拆成"无法被上下文支撑"的陈述，**于是这条验收要求反而拉低了忠实度指标**。

同一批 10 条答案，两种**指标计算口径**（是否保留引用标记）的实测对比：

| 评测口径 | faithfulness |
| --- | --- |
| 带引用标记（原样） | 0.5237 |
| 剥离引用标记 | **0.9708** |

差距几乎全部来自标记本身。因此评测统一按**剥离引用标记**计算，并在此同时给出两个数字，避免用口径制造好看的结果。
实现见 `backend/ragas_eval.py::strip_citations()`。

> 逐题抽查（剥离前）：Q1 = 0.80、Q2 = 0.83、Q3 = 0.33。
> Q3 的答案只有"…法定代表人是程家明"加两个引用标记，三个"陈述"里两个是标记，故得分被压到 0.33 —— 正是上述机制的直接证据。

### 5.2 ragas 相关工程约束（均为实测踩坑后固化）

| 约束 | 原因 |
| --- | --- |
| `EVAL_MAX_WORKERS=2` | 默认 16 并发会打满 DeepSeek 限流，把指标打成 `nan` |
| 不向 `llm_factory` 传 `bypass_n` | 该参数会被透传给 `Completions.create()` 直接报错，导致 **10 条样本全部失败、四项指标静默变 `null`**（看起来像"模型不行"，其实是参数用错层） |
| 结果**先落盘再算指标** | 余额 402 会让整轮静默作废，先落盘才能保住问答结果 |
| 只匹配 `eval_<时间戳>.json` | 用 `eval_*.json` 会把 `eval_warm_*.json`（仅 5 条）当成最新结果，`n_samples` 静默变成 5 |
| 指标有噪声底 | 本报告不做"±0.0x 即改进"的结论，所有优化结论都对应可复现的定性变化 |

> 工单参考口径：渠道销售部，下辖珠海销售处、深圳销售处、北京销售处、武汉销售处、广州销售处（5个）。注意：该口径与招股说明书2 原件不一致，仅用于工单对照，不作为事实依据。

### 7.2 Redis 不可用 → 无历史/无缓存，仍可作答

```

多轮历史(应为空): []
```

✅ 结论：单轮问答不受影响，且 `degraded=["redis"]` 如实上报。

> 说明：初版实现只把 Redis 故障写进日志、**没有**进入响应的 `degraded` 字段 —— 属于"静默降级"，已修复。
> 这类"少报降级"的问题不会导致答错，因此很难在功能测试中发现，必须专门核对 `degraded` 字段。

### 7.3 重排不可用 → 回退混合检索原始排序

代码路径：`reranker.rerank()` 在模型加载失败或打分异常时，返回 `candidates[:top_n]` 并置 `degraded=["rerank"]`。
（重排模型加载失败会记住错误原因，**不重复重试加载**，避免每次请求都卡在加载上。）

### 7.4 大模型不可用 → 只回检索片段，不编造

代码路径：`pipeline._fallback_answer()` 在生成失败时，把检索到的原文片段原样列出，并说明大模型暂时不可用，
同时置 `degraded=["llm"]`。

## 八、数据质量测试

### 8.1 水印污染

两份招股说明书都带**斜向水印**（"八维教育 / 人工智能刘敏 / rengongzhineng liumin"）。
水印不在文本层，MinerU 读页面图像时必然把它读进表格单元格。

处理：`backend/text_clean.py` 用**实测比对**得出的词表清洗。
判定依据：`刘敏`、`八维` 在 PDF 干净文本层出现 **0 次**，可安全剔除；`育` 在干净层出现 29 次（教育、培育），故**不**剔除。

另外，被水印污染的表格块在融合阶段**降权 ×0.5**（不删除）：其数字与表头的对应关系不可信。

### 8.2 图像内容提取

| 项 | 数值 |
| --- | --- |
| 处理图像数 | 77 张（其中 65 张产出有效文本） |
| 耗时 | 152 s |
| 缓存 | `data/image_texts.json`，重建索引时全部复用 |

其中**组织结构图/股权结构图**走层级还原（`backend/image_struct.py`）：几何检出方框与连线 → 还原父子关系 → 逐框 OCR 取标签。
实测 29 个方框全部正确检出，还原出的层级与人工读图一致（见 §六）。

**OCR 参数实测**：框内内缩 3~4 像素会把窄框（75px 宽）的笔画切掉，OCR 退化成单字（"财务部"→"部"）；
内缩 **2 像素**并尝试 0°/90°/270° 三种方向、取"字符数最多、置信度最高"的结果才稳定。
