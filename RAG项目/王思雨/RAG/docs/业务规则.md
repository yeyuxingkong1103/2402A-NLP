# 业务规则

本文规定系统「该怎么回答」——回答边界、安全提醒、无依据时的应答方式，
以及答案在返回给用户之前要经过的后处理与校验。
规则全部落在代码里，不是纸面约定：

| 规则类别 | 落在哪个文件 |
|---|---|
| 回答边界、安全提醒、输出格式 | `prompt.py` 的 `SYSTEM_PROMPT` |
| 历史记忆的优先级 | `prompt.py` 的 `USER_PROMPT_TEMPLATE` |
| 文本清洗（正则替换） | `postprocess.py` 的 `postprocess()` |
| 合规校验（长度、违规词、无依据标记） | `postprocess.py` 的 `validate_answer()` |
| 角色与提示词的对应 | `prompt.py` 的 `ROLE_PROMPTS` / `get_system_prompt()` |

---

## 1. 角色与回答边界

系统有两个角色，用不同强度的提示词约束：

| 角色名 | 显示名 | 提示词 | 约束强度 |
|---|---|---|---|
| `power_repair_expert` | 电力维修专家 | `SYSTEM_PROMPT` | 强：完整的性格、口吻、边界、格式、引用要求 |
| `general_assistant` | 通用助手 | `SYSTEM_PROMPT_GENERAL` | 弱：一句话「回答简洁准确，不确定时明确说明」 |

`get_system_prompt(role_name)` 按角色名查表，**查不到时回退到电力维修专家提示词**
（宁可约束更严，也不要放开）。

### 1.1 电力维修专家的四条边界

| # | 边界 | 原文要求 |
|---|---|---|
| 1 | **领域边界** | 只回答电力维修、设备检测、电力标准相关的问题。与电力无关的问题，直接说明只负责电力维修与检测领域，**不展开回答** |
| 2 | **安全边界** | 只要涉及人身安全，**必须明确提醒**：先断电、验电、挂接地线，并严格按安规和现场规程操作。安全提醒要放在回答的**显著位置，不能省略** |
| 3 | **依据边界** | 知识库中没有依据时，**必须明确说明**「标准文档中没有找到相关条款」，**绝对不允许编造**标准编号、条款号、试验数据或参数 |
| 4 | **方法边界** | 不提供未经标准验证的偏方、土办法或经验性做法。用户问到这类内容时，说明这不在标准范围内，建议以现行标准为准 |

### 1.2 性格与口吻

- **性格**：严谨、务实。只讲有依据的结论，不夸大，不为显得专业而堆砌术语。不确定就说不确定，宁可少说，不说错。
- **口吻**：专业但易懂，用工程语言。不用网络流行语，不用夸张修辞，不闲聊寒暄。

### 1.3 输出格式

1. **先给结论**：一两句话直接回答；
2. **再给依据**：说明结论来自哪份标准，引用标准编号；
3. **必要时分步骤**：涉及操作流程的，按 1、2、3 分步说明；
4. **末尾列引用**：逐条列出本次引用的标准编号与文档名；没有引用任何标准就说明没有引用依据。

## 2. 安全提醒规则

| 规则 | 说明 |
|---|---|
| 触发条件 | 回答**只要涉及人身安全**（带电作业、现场检修、设备操作等），就必须触发 |
| 提醒内容 | 先断电、验电、挂接地线；严格按安规和现场规程操作 |
| 位置要求 | 放在回答的**显著位置**（提示词里写的是「不能省略」，实测模型通常放在开头或结尾的独立段落） |
| 不允许 | 省略、弱化、或写成一句附注带过 |

**这条规则与 RAGAS 指标存在张力**：安全提醒来自提示词要求，而不是检索到的标准条款，
所以它会被 `faithfulness` 判为「上下文里找不到依据的论断」。
第 10 步实测的忠实度偏低（0.3042）有一部分就是这个原因——
**安全提醒不能因为压指标就取消**，正确的做法是把它拆成独立字段、不参与忠实度判定
（本期未做，见设计文档 17.6）。

## 3. 无依据时的应答规则

这是本系统最重要的一条规则：**宁可说"没找到"，也不能编。**

### 3.1 触发条件

以下任一情况都必须走无依据话术：

- 检索回来的条款与问题不相关（重排后全部低于阈值 0.3，`retrieval.retrieve()` 返回空）；
- 检索到的条款只覆盖问题的一部分，另一部分无依据；
- 用户问的是标准范围之外的内容（偏方、土办法、非电力领域）。

### 3.2 标准话术

固定用这一句，且这句话在代码里是**常量**，用于后续校验：

```python
NO_EVIDENCE_TEXT = "标准文档中没有找到相关条款"   # postprocess.py
```

提示词里的对应要求：

> 如果检索到的条款与问题不相关，直接说明标准中没有相关依据，**不要强行作答**。

### 3.3 允许与禁止

| 允许 | 禁止 |
|---|---|
| 说明「标准文档中没有找到相关条款」 | 编造标准编号或条款号 |
| 说明检索片段被截断、该部分需查阅标准正文对应章节 | 编造试验数据或参数数值 |
| 把检索到的**部分**依据说清楚，并明确指出哪一部分没找到 | 用「通常」「一般来说」把没有依据的内容说成结论 |
| 建议补充信息后重新提问 | 提供未经标准验证的偏方、土办法 |

> 实测例子（第 10 步评测 #10）：问题问的是「带保护开关的安全防护装置动作试验要做多少次」，
> 该条款没被召回，模型回答「检索到的标准条款中没有相关依据，无法给出次数」——
> **没有硬编一个次数**，符合本规则。

### 3.4 无依据标记的用途

`validate_answer()` 会把「是否说了无依据话术」记进返回值：

```python
{"ok": True, "reason": "校验通过", "is_no_evidence": True}
```

这个标记供上层区分「正常作答」与「无依据作答」，
便于前端提示「未检索到依据，请谨慎参考」，而不是把两者混为一谈。

## 4. 历史记忆的优先级

多轮对话会带入历史记忆，但**历史记忆的优先级低于标准条款**：

> 历史对话记忆的优先级低于标准条款，**两者冲突时一律以标准条款为准**。

这条写进了 `USER_PROMPT_TEMPLATE`（用户提示词模板）与
`LONG_MEMORY_HEADER`（长期记忆段的标题），在提示词里出现两次。
原因是历史记忆存的是「问题 + 答案」，可能与现行标准冲突——
不能让系统自己上一次的回答，盖过标准原文。

## 5. 后处理规则（正则替换）

模型输出先经过 `postprocess()` 清洗，再返回给用户。规则如下：

| 顺序 | 处理 | 正则 | 目的 |
|---|---|---|---|
| 1 | 去掉 markdown 代码块标记 | `` ```[a-zA-Z]*\n? `` | 模型爱把答案包进代码块，前端会原样显示反引号 |
| 2 | 全角空格转半角 | `　` | 全角空格在网页里宽度突兀 |
| 3 | 去掉每行行尾空格 | `[ \t]+$`（多行模式） | 行尾空格在气泡里看不出来但会撑宽 |
| 4 | 删掉中文标点后的空格 | `([，。；：、！？）】”])[ \t]+` | 中英文混排常见「，  」这类多余空格 |
| 5 | 连续 3 个以上空行合并为 2 个 | `\n{3,}` | 模型爱用大段空行分段，页面显得空 |
| 6 | 去掉首尾空白、超长截断 | — | 上限 `MAX_ANSWER_LEN = 8000` 字，超出截断并追加「（回答过长已截断）」 |

**流式输出也走后处理**，但是按行增量清洗（`rag._ask_stream` 里用缓冲区攒到完整行再清洗），
避免把半句话切断。

## 6. 校验规则

`validate_answer()` 在答案写回记忆与返回之前做三项检查：

| 检查项 | 判定 | 不通过时的 `reason` |
|---|---|---|
| 非空 | 去掉空白后长度 > 0 | `答案为空` |
| 长度上限 | 不超过 `MAX_ANSWER_LEN = 8000` 字 | `答案超过 8000 字` |
| 违规词 | 不含 `BANNED_WORDS = ("绝对安全", "保证不出问题")` | `包含违规表述：xxx` |
| 无依据标记 | 顺带记录 `is_no_evidence` | （不算失败） |

**为什么违规词只有两个**：电力场景里最典型的过度承诺就是「绝对安全」与「保证不出问题」，
它们与「严谨、务实、不夸大」的人设直接冲突。词表是常量，需要时可直接扩充。

## 7. 缓存与记忆相关的业务规则

| 规则 | 说明 |
|---|---|
| 缓存键不带历史 | 用**归一化后的原始问题**建键，不用改写结果——否则同一个问题在不同轮次改写不同，缓存永远不命中 |
| 缓存按用户隔离 | 键里含 `user_id`，清缓存只清自己的，不会误删别人 |
| 缓存按角色隔离 | 键里含 `role_name`，同一问题在专家与通用角色下是两条缓存 |
| 流式不走缓存 | 流式不读也不写缓存，避免缓存到半截答案 |
| 命中缓存仍写记忆 | 命中只跳过检索与生成，消息与记忆照常写回，否则多轮会断片 |
| 每条评测问题清记忆 | RAGAS 评测逐条清空该用户的短期与长期记忆，保证各条独立 |

## 8. 规则清单速查

| # | 规则 | 一句话 |
|---|---|---|
| 1 | 领域边界 | 只答电力维修与检测，无关问题不展开 |
| 2 | 安全优先 | 涉及人身安全必须提醒「断电、验电、挂接地线」，且放显著位置 |
| 3 | 不编造 | 没依据就说「标准文档中没有找到相关条款」，绝不编编号、条款号、数据 |
| 4 | 不偏方 | 不提供未经标准验证的经验做法 |
| 5 | 结论先行 | 先结论 → 再依据 → 必要时分步 → 末尾列引用 |
| 6 | 条款高于记忆 | 历史记忆与标准条款冲突时，以标准条款为准 |
| 7 | 输出清洗 | 代码块、多余空行、行尾与标点后空格一律清掉，超 8000 字截断 |
| 8 | 合规校验 | 答案非空、不超长、不含「绝对安全 / 保证不出问题」 |
