## 1. Windows 本地部署（已验证）

### 1.1 环境要求

| 组件 | 版本/路径 | 校验命令 |
|---|---|---|
| Python 环境 | `D:\anaconda3\envs\rag_env`（3.10.14） | `D:\anaconda3\envs\rag_env\python.exe -V` |
| MySQL | 8.0.42 @ 127.0.0.1:3306 | `netstat -ano \| grep :3306` |
| Ollama | qwen2.5:7b | `curl http://localhost:11434/api/tags` |
| Redis | 免安装版（随项目提供） | `bash tools/redis/start_redis.sh` |
| 嵌入模型 | `D:\桌面\模型\嵌入模型\bge-m3` | 目录含 `sparse_linear.pt` |
| 精排模型 | `D:\桌面\模型\精排模型\bge-reranker-v2-m3` | 目录含 `model.safetensors` |
| Node.js | v24+（前端） | `node -v` |

**磁盘占用参考**：嵌入模型 2.3G + 精排 2.3G + Redis 0.05G + 前端 node_modules 88M + Qdrant 数据。

### 1.2 部署步骤

```bash
# ① 建数据库（首次）
D:/anaconda3/envs/rag_env/python.exe -c "
import pymysql
c = pymysql.connect(host='127.0.0.1', port=3306, user='root', password='123456', charset='utf8mb4')
c.cursor().execute('CREATE DATABASE IF NOT EXISTS raglora CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci')
c.close(); print('raglora 库就绪')
"

# ② 导入知识库（必须：否则检索为空）
#    ⚠️ 必须在后端停止状态下执行（Qdrant 嵌入式模式持有独占文件锁）
cd backend
D:/anaconda3/envs/rag_env/python.exe scripts/ingest_all.py
#    预期：medical 636 向量 / legal 14319 向量，耗时约 4 分钟（GPU 编码）

# ③ 一键启动后端（自动拉起 Redis + 探活依赖 + 后台预热模型）
bash run.sh --bg

# ④ 启动前端
cd ../frontend && npx vite
```

访问 **http://127.0.0.1:5173**，注册账号即可开始对话。


## 2. Linux 服务器迁移指引（待验证）

> ⚠️ 本项目**仅在 Windows 上实际部署验证过**。以下为迁移步骤，迁移后需重新跑一遍 §1.3 的验证清单。

### 2.1 需要改动的部分

| 项 | Windows 现值 | Linux 建议 |
|---|---|---|
| 模型路径 | `D:\桌面\模型\...` | 改为 `/data/models/...`，用环境变量覆盖 |
| 项目路径 | `D:\桌面\RAGLoRA` | `/opt/raglora` |
| Redis | 免安装 zip | 用系统包：`apt install redis-server` |
| GPU | RTX 4060 Laptop 8G | 若服务器无 GPU：见 §2.3 降级方案 |

**环境变量覆盖**（无需改代码）：

```bash
export MYSQL_HOST=127.0.0.1 MYSQL_PASSWORD='强密码'
export EMBED_MODEL_PATH=/data/models/bge-m3
export RERANK_MODEL_PATH=/data/models/bge-reranker-v2-m3
export OLLAMA_BASE_URL=http://127.0.0.1:11434/v1
export JWT_SECRET='生产环境务必换掉默认值'
export REDIS_HOST=127.0.0.1
```

### 2.2 首次安装脚本（示意）

```bash
# 系统依赖
apt update && apt install -y python3.10 python3-pip mysql-server redis-server git

# Python 依赖（严格按 requirements.txt，不要自由升级）
cd /opt/raglora/backend
pip install -r requirements.txt

# 上传代码：建议 git clone 或 tar 包
# tar -czf raglora.tar.gz --exclude=node_modules --exclude=qdrant_storage RAGLoRA/

# 前端依赖
cd /opt/raglora/frontend && npm ci     # 有 node_modules 时可直接复用

# 建库 + 导入知识库
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS raglora CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
cd /opt/raglora/backend && python3 scripts/ingest_all.py
```

> ⚠️ `requirements.txt` 中 `torch==2.5.1+cu121` 是 CUDA 12.1 版本。若服务器 CUDA 版本不同，
> 需从 PyTorch 官方源重装对应版本。**无 GPU 时**改装 CPU 版即可（功能完整，精排与编码变慢）。

### 2.3 无 GPU 服务器降级方案

| 环节 | GPU 方案 | 无 GPU 降级 | 影响 |
|---|---|---|---|
| 嵌入编码 | GPU fp16，234 chunks/s | CPU，8 chunks/s | 入库 1 分钟 → 30 分钟；**在线查询仅慢几十毫秒，可接受** |
| 精排 | GPU 分时复用，413ms | 自动落 CPU（`rerank.py` 里 `use_cuda` 判断） | 每轮多约 2 秒 |
| 生成 | Ollama qwen2.5:7b | 同左（Ollama 自动用 CPU） | 吞吐从 ~48 tok/s 降到 ~5-8 tok/s |

代码已内置判断（`torch.cuda.is_available()`），无需改代码，但需在评测中重新测量延迟。

### 2.4 生产加固建议

| 项 | 建议 |
|---|---|
| `JWT_SECRET` | **必须**通过环境变量换成随机值 |
| CORS | `main.py` 中 `allow_origins=["*"]` 改为前端实际域名 |
| HTTPS | 前置 Nginx 反代 + 证书 |
| SSE | Nginx 需关缓冲：`proxy_buffering off;`（后端已发 `X-Accel-Buffering: no`） |
| 进程守护 | systemd 单元，或 `nohup` + 健康检查脚本 |
| 数据库账号 | 不要用 root，建专用账号并只授权 `raglora` 库 |
| Qdrant | 单 worker 限制在数据量大时是瓶颈，可迁移到 Qdrant 服务端模式（改 `qdrant_store.py` 的 `QdrantClient(path=)` 为 `QdrantClient(host=, port=)`） |

### 2.5 systemd 单元示例（未验证）

```ini
[Unit]
Description=RAGLoRA Backend
After=network.target mysql.service redis-server.service

[Service]
Type=simple
User=raglora
WorkingDirectory=/opt/raglora/backend
EnvironmentFile=/opt/raglora/.env
ExecStart=/usr/bin/python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

> ⚠️ **不要加 `--workers`**：Qdrant 嵌入式模式对存储目录持有独占文件锁，多 worker 会启动失败。

## 3. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报「MySQL 未监听」 | MySQL 服务未启动 | `net start mysql` / `systemctl start mysql` |
| 检索无结果 | 知识库为空 | 跑 `scripts/ingest_all.py` |
| 入库报文件锁错误 | 后端正在运行 | 先 `shutdown.sh`，或改用 `POST /api/kb/ingest` |
| 生成极慢（< 10 tok/s） | 显存不足，Ollama 回退 CPU | 关掉占显存的程序；确认精排未常驻 GPU；`nvidia-smi` 看空闲 |
| 前端 502 | 后端未启动 / 端口不符 | 检查 `vite.config.ts` 的 proxy target 与后端端口一致 |
| Redis 连不上 | 未启动（免安装版无开机自启） | `bash tools/redis/start_redis.sh`；短期记忆会自动降级为 MySQL 回源，不影响对话 |
| 回答无 `[n]` 引用 | 模型未遵循指令 | 检查 `characters.prompt_template`（内置角色模板随代码自动同步） |
