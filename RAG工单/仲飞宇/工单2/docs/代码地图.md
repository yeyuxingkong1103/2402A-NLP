## 1. 全仓树状图（含职责）

```

├── app/                        ★ 应用主体（服务化的部分全在这里）
```

## 2. 分层文件清单（一张表看全）

### 2.1 接入层 `app/api/`

| 文件 | 职责 | 关键实现点 |
|---|---|---|
| `chat.py` | 对话的两个入口 | 未知角色 404 必须**在流开始前**判断；`/chat/stream` 依次发 `sources → delta…→ done`，中途失败发 `error` 事件（此时 HTTP 已是 200） |
| `health.py` | 五组件连通性 | 组件值只有 `ok/unavailable/degraded` 三档；降级原因放 `details` 而不是塞进 `components`，方便调用方做等值判断 |
| `knowledge.py` | 上传入库 / 文档列表 | 刻意用同步 `def`（阻塞 IO 交给线程池）；入库完成后要 `retriever.invalidate(role_id)` 失效 BM25 缓存 |
| `role.py` | 角色 CRUD | 未知角色 404 而非 500 |

### 2.2 编排与生成 `app/core/`

| 文件 | 职责 | 关键实现点 |
|---|---|---|
| `pipeline.py` | **主链路** | 按「会话+角色」加锁串行化同一会话的请求；开精排时先按 `RERANK_POOL` 宽召回再截断精排 |
| `llm.py` | 大模型客户端 | `max_retries=0`（重试对「慢」无益，只会加倍占用线程池）；空 `choices` 抛 `EmptyAnswerError` 而非 IndexError |
| `embedding.py` | 向量化客户端 | 统一 L2 归一化，配合 Milvus 的 IP 度量等价余弦；返回条数不符直接抛错（否则下游 `zip` 会静默丢尾块） |
| `reranker.py` | 重排 | `ScoreFusion`（默认，零成本）/ `BGE`（交叉编码）；BGE 不可用或返回残缺时降级，但**必须留日志** |
| `postprocess.py` | 输出清洗 | 只清理「闭合完整」的思维链块——不做「见到开始标签就删到结尾」的兜底，免得吃掉正文 |
| `config.py` | 配置 | `.env` ← `.env.${APP_ENV}` 分层覆盖；**环境变量优先于文件** |

### 2.3 提示词 `app/core/prompt/`

| 文件 | 职责 | 关键实现点 |
|---|---|---|
| `role_presets.py` | 内置角色的**数据表** | 每个角色 = 名字 + 头像 emoji + 简介 + 人设提示词；新增角色只改这里 + 建语料目录 |
| `templates.py` | 组装最终 messages | 三重字符预算（知识上下文 / 历史 / 整个 prompt）；零召回时不会退化成「只剩人设」 |

### 2.4 检索 `app/core/retrieve/`

| 文件 | 职责 | 关键实现点 |
|---|---|---|
| `hybrid_retriever.py` | 稠密 + BM25 + RRF | BM25 索引**按角色缓存在进程内**，入库后必须 `invalidate`；`rank_bm25` 的负 IDF 陷阱（见文件内注释） |
| `query_rewrite.py` | 问题改写/扩写 | 默认**关**（每次多一趟 LLM 往返）；开启后召回条数会翻数倍，故 pipeline 里有池宽截断 |

### 2.5 文档处理 `app/core/document/`

| 文件 | 职责 | 关键实现点 |
|---|---|---|
| `parser.py` | 文件 → 纯文本 | PDF 三级兜底：PyMuPDF → 文本过少转 pdfplumber → 无文本层走 OCR；单页 OCR 失败不连累整篇 |
| `ocr.py` | RapidOCR | 惰性单例，普通文档零开销；`OCR_ENABLED=false` 时完全退回旧行为 |
| `cleaner.py` | 文本清洗 | 去空白 / 水印 / 页眉页脚 |
| `chunker.py` | 5 种分块 | `semantic` 策略需要 embedding；分块上界受上下文预算约束（常量在文件顶部，接口与脚本共用） |
| `enhance.py` | 数据增强 | 可选 LLM 摘要、按内容哈希去重、按最小长度过滤低质量块 |
| `ingest.py` | 入库流水线 | `build_chunks`（向量化）与 `store_chunks`（写 Milvus + 登记 SQL）被脚本与上传接口**共用**，避免两份实现漂移 |

### 2.6 存储 `app/core/store/`

| 文件 | 职责 | 关键实现点 |
|---|---|---|
| `milvus_store.py` | 向量库 | 一个 `role_knowledge` 集合，按 `role_id` 过滤隔离；`.db` 路径 = Lite，`http://…` = 服务器 |
| `sql_store.py` | 关系库 | users / roles / documents 三表；启动时自动补新列（`avatar`）；并发初始化要防竞态 |
| `memory.py` | 短期记忆 | 内存 = `deque(maxlen)`；Redis = `List` + `LTRIM` + 24h TTL；Redis 不可达**自动降级但不静默** |

## 3. 两条调用链（文件级）

### 3.1 一次提问（`POST /chat`）

```
app/main.py           启动时 RAGPipeline.build(settings) 组装全部依赖
      ↓
app/schemas/          校验请求（question 长度、role_id 白名单）→ 不合法就 422
      ↓
app/api/chat.py       _ensure_role()：未知角色 404（必须在进生成器之前）
      ↓
app/core/pipeline.py  answer()
      ├─ ensure_role ─────────→ core/store/sql_store.py
      │                          （内置角色首次出现时由 core/prompt/role_presets.py 自动登记）
      ├─ retrieve()
      │    ├─ core/retrieve/query_rewrite.py   可选：把问题扩成多条
      │    ├─ core/embedding.py                问题向量化
      │    ├─ core/store/milvus_store.py       稠密召回（按 role_id 过滤）
      │    ├─ core/retrieve/hybrid_retriever.py BM25 召回 + RRF 融合
      │    └─ core/reranker.py                 精排 → 截断到 TOP_K
      ├─ core/store/memory.py  get_history()   取该会话历史
      ├─ core/prompt/templates.py build_messages()  人设 + 知识 + 历史 + 问题（按预算裁剪）
      ├─ core/llm.py           chat()          生成
      ├─ core/postprocess.py   postprocess()   清洗（去思维链/幻觉引用）
      └─ core/store/memory.py  add()           写回一问一答
      ↓
返回 ChatResponse{answer, sources, session_id}
```

流式（`POST /chat/stream`）走同一条链，差别只有两处：
`llm.stream()` 逐段产出增量；`chat.py` 把它们包成 SSE 事件，并在 `done` 里回传**服务端清洗过**的完整答案。

### 3.2 一次入库（`/knowledge/upload` 或 `scripts/ingest.py`）

```
core/document/parser.py     文件 → 纯文本（必要时 core/document/ocr.py）
      ↓
core/document/cleaner.py    清洗
      ↓
core/document/chunker.py    分块（semantic 策略会回调 core/embedding.py）
      ↓
core/document/enhance.py    低质量过滤 / 去重 / 可选 LLM 摘要（core/llm.py）
      ↓
core/document/ingest.py
      ├─ build_chunks()     批量向量化（core/embedding.py）
      └─ store_chunks()     ├→ core/store/milvus_store.py  写向量 + 正文
                            └→ core/store/sql_store.py     登记文档
      ↓
core/retrieve/hybrid_retriever.py  invalidate(role_id)  让本进程的 BM25 索引看见新文档
```

> 重复入库同一个 `source` 时按「先删后插」保证幂等（BR-5）。

## 4. 「我要改 X，动哪个文件」

| 我想… | 改哪里 |
|---|---|
| 换大模型 / 换在线 API | `.env`：`LLM_PROVIDER` / `LLM_MODEL` / `LLM_BASE_URL` / `LLM_API_KEY`（代码在 `core/llm.py`） |
| 换向量模型 | `.env`：`EMBED_MODEL`（**注意** `EMBED_DIM` 必须与已入库向量维度一致，换模型要重灌知识库） |
| 加一个新角色 | ① `core/prompt/role_presets.py` 加一条 ② 建 `data/corpus/<role_id>/` 放语料 ③ 在 `scripts/seed.py` 的 `SEED_KNOWLEDGE` 里挂上 ④ 跑 `python scripts/seed.py` |
| 改某角色的说话风格/规则 | `core/prompt/role_presets.py` 里该角色的 `system_prompt` |
| 改「知识怎么拼进提示词」 | `core/prompt/templates.py` |
| 检索召回不准 | `core/retrieve/hybrid_retriever.py`；先调 `.env` 的 `TOP_K` / `SCORE_THRESHOLD` |
| 开启/关闭精排 | `.env`：`RERANKER=score_fusion|bge`；开启前先 `bash scripts/run_rerank.sh` |
| 开启/关闭 Query 改写 | `.env`：`QUERY_REWRITE_ENABLED` |
| 改分块策略 / 块大小 | `core/document/chunker.py`；运行时可用接口参数或 `ingest.py --strategy/--chunk-size` |
| 改文档清洗规则 | `core/document/cleaner.py` |
| 改回答的清洗规则（去思维链等） | `core/postprocess.py` |
| 加一个 HTTP 接口 | 新建 `app/api/xxx.py` + 在 `app/main.py` `include_router` + 模型放 `app/schemas/__init__.py` |
| 换存储后端（Lite→服务器、SQLite→MySQL、内存→Redis） | 只改 `.env`：`MILVUS_DB_URI` / `SQL_URL` / `MEMORY_BACKEND`（代码在 `core/store/`） |
| 改前端界面 | `app/static/index.html`（单文件，HTML+CSS+JS 都在一起） |
| 加评测指标 | `eval/ragas_eval.py` |
| 加回归测试 | `tests/test_bugfixes.py`（或对应模块的 `test_*.py`） |
| 改部署/压测 | `deploy/` + `scripts/start_all.sh` |

## 5. 配置分层

| 文件 | 用途 |
|---|---|
| `.env.example` | 全量配置模板（**新增配置项先改这里**） |
| `.env` | 本机基础配置，永远先加载 |
| `.env.dev` / `.env.test` / `.env.prod` | 按 `APP_ENV` 覆盖 `.env`（后加载者胜） |
| 真实环境变量 | **优先级最高**，会压过上述所有文件 |

> `APP_ENV` 必须 `export` 出来才生效；不设时按 `.env` 走。
> 逐项说明以 [README.md 的「配置说明」](../README.md) 为准（本文不重复维护一份，避免两处漂移）。

| **一键启动**（含依赖自检与自动拉起） | `bash scripts/start_all.sh` / Windows 双击 `start.bat` |
| 只自检不起服务 | `bash scripts/start_all.sh --no-start` |
| 交付演示（有降级就失败） | `bash scripts/start_all.sh --strict` |
| 停止 | `bash scripts/shutdown.sh` 或 `start.bat stop` |
| 拉取语料（公开数据集，跑 seed 前必须先跑） | `python scripts/fetch_datasets.py` |
| 入库单个目录 | `python scripts/ingest.py --dir data/corpus/lawyer --role lawyer` |
| 灌全部演示数据（2 角色） | `python scripts/seed.py` |
| 起精排服务 | `bash scripts/run_rerank.sh`（首次要先 `download_rerank_model.sh`） |
| 验证精排真的生效 | `bash scripts/verify_rerank.sh` / `python scripts/verify_rerank_e2e.py` |
| 多 worker + nginx | `bash scripts/run_workers.sh` + `sudo bash scripts/setup_nginx.sh` + `bash scripts/verify_lb.sh` |
| 评测 | `python eval/ragas_eval.py --role lawyer`（题组与角色绑定，可选 lawyer / psychologist） |
