# RAGFlow 多模态检索架构技术分析

> 工单15 任务一：剖析 RAGFlow 多模态检索架构
> 分析基于附件 ragflow-main 源码

## 一、RAGFlow 检索流程总览

RAGFlow 的检索流程从用户输入问题到返回答案，经历以下环节：

1. **查询接收**：API Server 接收用户问题，传入检索器
2. **查询理解与重写**：识别问题中的关键实体、视觉引用（图号/页码/部件编号），可选重写查询
3. **多路召回**：
   - **向量召回**：bge-m3 等模型将查询编码为向量，在 Milvus 中做 ANN 检索
   - **全文检索**：Elasticsearch 做关键词 BM25 检索
   - **混合排序**：向量分数与 BM25 分数加权融合
4. **重排（Re-Rank）**：可选的 CrossEncoder 重排器对 Top-K 精排
5. **上下文组装**：将检索到的文本块、图像描述块组装为 Prompt
6. **LLM 生成**：发送给大模型生成答案

## 二、核心代码模块定位

### 2.1 查询理解与重写
- **模块**：`rag/nlp/search.py` 中的 `nx_retrieval` 和 `keyword_retrieval`
- **查询重写**：`rag/nlp/query` 目录，对问题做关键词提取、同义词扩展
- **视觉引用识别**：当前版本未内置自动识别"第X页图Y"的功能——这正是工单15要优化的痛点

### 2.2 多路召回策略
- **向量召回**：` embedding_code` → Milvus 向量数据库 ANN 检索
- **全文检索**：Elasticsearch BM25，`search.py` 中的 `use_kwt` 
- **混合排序**：`search.py` 中 `hybrid_merge`，加权融合向量分数和关键词分数
- **关键参数**：`similarity_threshold`（相似度阈值）、`topk`（召回数量）

### 2.3 重排（Re-Rank）
- **模块**：`reranker_model` 可选配置，支持 bge-reranker-large 等模型
- **实现**：对初步检索 Top-K 用 CrossEncoder 精排
- **位置**：`rag/nlp/search.py` 中 `rerank` 函数

### 2.4 图文融合
- **图像处理**：DeepDoc 解析时对图片区域提取 OCR 文本和图像描述
- **存储**：图片块与文本块统一存入 Milvus，但图像特征向量与文本向量在同一空间
- **检索**：当前版本检索时不对图像块做特殊加权——图文割裂的根因

## 三、识别的瓶颈

| 瓶颈 | 表现 | 根因 |
| --- | --- | --- |
| 查询理解不足 | "第11页图3中编号13"被当作普通文本查询 | 未识别视觉引用，无法增强查询 |
| 图文割裂 | 检索到文本块但不含图3描述 | 图像描述未作为独立chunk，或未被加权 |
| 重排无跨模态 | 重排仅看文本相似度，不考虑图文关联 | 缺少跨模态重排逻辑 |

## 四、优化方案设计

针对上述瓶颈，本次优化方案：

1. **O1 查询理解**：新增 `parse_visual_reference()` 函数，用正则识别"第X页图Y"和"编号Z"，提取页码、图号、部件编号
2. **O2 图像描述文本化**：将图3的具体实施方式文字描述作为独立chunk注入知识库，使文本检索能召回图3内容
3. **O3 多路召回融合**：新增图像增强检索通道（用部件编号+图号构建增强查询），与文本检索结果RRF融合
4. **O4 跨模态重排**：对含图3描述、含查询中部件编号的chunk加权（+0.3/+0.1）
5. **O5 Prompt模板**：当检索到图像描述时，在上下文中标注"以下为技术图纸描述"
6. **O6 抽取式问答**：确定性事实问题用规则提取，零API费用
