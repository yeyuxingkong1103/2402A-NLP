# 数据来源与语料说明

两个角色（心理咨询师、律师）的知识库都不是手写示例，而是**公开数据集**的真实语料。本文记录
它们从哪来、什么许可、怎么变成可入库的 Markdown，以及已知的缺口——「知识库里到底有什么」是
演示和答辩时最容易被追问的一点，所以连不足也一并写在这里。

> 语料由 `scripts/fetch_datasets.py` 拉取与转换，产物在 `data/corpus/`（不入 git，体积大且可重下）。
> `data/corpus/manifest.json` 记录每个文件的来源、字节数与 sha256，该文件**进仓库**，作为语料可
> 追溯的凭据。

## 1. 数据集清单

| 角色 | 数据集 | 内容 | 规模 | 许可 |
|---|---|---|---|---|
| 律师 | [`Duyu/Chinese_Law`](https://hf-mirror.com/datasets/Duyu/Chinese_Law) 《中国法律语料》 | 宪法、法律、法规、司法解释**全文**，规范 Markdown（章/节/法条结构清晰） | 20.8 MB；1296 个一级标题，切成 981 部 | 上游未声明；法律、法规原文依《著作权法》第五条不受著作权保护 |
| 心理咨询师 | [`CAS-SIAT-XinHai/CPsyCoun`](https://hf-mirror.com/datasets/CAS-SIAT-XinHai/CPsyCoun) （CPsyCounD） | 中文**多轮心理咨询对话** 3134 段，覆盖 9 类主题（自我成长/情绪压力/教育/婚恋/家庭/社交/两性/职业/心理疾病）× 7 种流派（精神分析、CBT、人本、家庭、后现代、整合等） | 8.4 MB | CC-BY-SA-4.0；论文 [arXiv:2405.16433](https://arxiv.org/abs/2405.16433)（中科院 CAS-SIAT） |
| 心理咨询师 | 同上法律语料中的《精神卫生法》 | 法律条文全文（保密例外、非自愿住院、咨询人员执业边界） | 10.9 KB | 同上 |

## 2. 为什么是这两个数据集

- **律师**选法条全文而不是法律问答对：本项目是 RAG（检索原文再作答），法条本身就是最权威、
  最结构化的知识，检索到哪一条可以直接标注条文名；问答语料则带别人的答案口径，反而不好溯源。
- **心理咨询师**选 CPsyCoun：中文、有论文与明确许可、体量与许可都干净的咨询语料里它最合适。
  缺点是**对话语料不是知识教材**（见 §6.2），所以我们另外补了《精神卫生法》这篇条文，
  让「知识型问题」也有可引用的依据。

## 3. 怎么下：本机网络实测

本机外网可达性与常识相反，实测结论（2026-09-23）：

| 目标 | 结果 |
|---|---|
| `github.com`、`gitee.com` | ❌ 8 秒超时，不通 |
| `huggingface.co` | ❌ 不通 |
| `hf-mirror.com` | ✅ 通，但慢（约 10~60 KB/s）**且大文件会中途断流** |
| `www.modelscope.cn`、`flk.npc.gov.cn`（国家法律法规数据库） | ✅ 通 |

因此取数脚本做了两件必须的事：

1. **走 hf-mirror 镜像**（`HF_ENDPOINT` 那一类地址直接写进脚本常量）；
2. **断点续传**——这不是保险而是主路径：先 HEAD 拿 `content-length`，本地已下够就跳过；没下够的
   按 256 KB 分段 Range 续传，每段带 4 次重试。实测 20.8 MB 那份语料中途断过，重跑脚本能接着下。

整批约 29 MB，冷启动几分钟到十几分钟，取决于当时的镜像速度。

```bash
python scripts/fetch_datasets.py            # 下载 + 转换（已就绪的跳过）
python scripts/fetch_datasets.py --list     # 只看清单与状态，不联网
python scripts/fetch_datasets.py --only psychologist
```

> `flk.npc.gov.cn`（官方库）虽然可达，但它的 `/api/*` 全是 SPA 兜底（返回 index.html），
> 真接口要逆 JS bundle，性价比低，最终没用它。

## 4. 语料转换规则

| 输入 | 转换 | 产物 |
|---|---|---|
| `Chinese_law.md`（单文件 20.8 MB） | 按**一级标题**（`# 法律名`）切成单部法律；`##`/`###` 是章/节不动 | `data/raw/laws_split/*.md`（981 部，中间产物） |
| 民法典的 8 个一级标题 | **合并成一篇** `civil_code.md`：编提升为 `##`，原章标题整体下沉一档 | `data/corpus/lawyer/civil_code.md` |
| CPsyCounD.json（3134 条） | 每条按 `history` + 末轮渲染成「**来访者**/**咨询师**」的 Markdown 段落；按序号等分为 8 辑 | `data/corpus/psychologist/cpsyccoun_dialogues_01~08.md` |

两条质量闸门：

- **单部法律不足 2000 字符视为残缺，不入库。** 残文件比缺文件更糟——它会以「有资料」的姿态让
  模型给出片面结论。切分阶段不过滤（否则会误伤《民法典-附则》这种天生就短、但属于完整法典
  一部分的篇目），过滤只发生在「挑哪几部进语料库」时。
- **法条的关键词在评测集里核实过**：`eval/ragas_eval.py` 每个角色的陷阱题，其关键词都确认过在
  语料里 0 命中（如「永久居留」），否则那道题就不算陷阱，faithfulness 也失去区分度。

## 6. 已知边界与缺口（如实记录）

### 6.1 律师侧没有覆盖的法

语料里**没有**《公司法》《证券法》《专利法》《商标法》《仲裁法》《破产法》《保险法》等，问到
这些领域的问题会走「知识库没有相关资料，建议咨询执业律师」那条分支——这是设计内的行为（BR-1），
不是故障。补法只需在 `scripts/fetch_datasets.py` 的 `LAWYER_LAWS` 里加一条法律全名 + 文件名。

### 6.2 心理咨询师侧的主体是对话语料，不是知识教材

CPsyCounD 的召回结果是**咨询对话片段**，所以这个角色在回答「我最近压力大」这类问题时表现像
「在示范一段咨询对话」，而不是「引用心理学教科书」。知识型问题（如精神障碍的诊断主体、保密
边界）主要靠《精神卫生法》那一篇支撑。中文、许可干净的**心理学教材**类开源语料很少：

- `Mxode/Chinese-Psychology-Books`（心理学教材 zip）考虑过但没用：CC-BY-NC-4.0（禁商用）、
  教材本身版权存疑、且是 zip + PDF 需要额外解压与抽取。
- 原版 `CAS-SIAT-XinHai/CPsyCounR`（咨询案例报告，知识型更强）在 HF 上是 **gated**，
  没有授权下不了。

### 6.3 数据集本身踩过的坑

- `Dusker/chinese-laws-pretrain`（另一个法律数据集）**弃用**：它的《民法典-婚姻家庭编》只有
  16 条、从「第五章 收养」开始，前四章整段缺失。换用 `Duyu/Chinese_Law` 后该编从「第一章
  一般规定 · 第一千零四十条」起，完整。
- CPsyCoun 的**gated 范围只到 CPsyCounR**：一度以为原仓整个下不了、绕道了社区转载
  `baicuya/CPsyCoun`；后来核实原仓的 `CPsyCounD.json` 其实可下，且与转载版**逐字节一致**
  （都是 8,364,968 字节）。脚本现在以原仓为首选、转载版作兜底（`CPsyCoun["repos"]`）。
  gated 的是 `CPsyCounR`（咨询案例报告，知识型更强），也就是 §6.2 里补不了教材的那个缺口。
- CPsyCounD 只有 `instruction` / `input` / `output` / `history` 四个字段，**没有主题标签**，
  所以对话是按序号分辑，不是按主题分类——不要在演示里把它们说成「按主题整理过」。

## 7. 复现步骤

```bash
python scripts/fetch_datasets.py     # ① 拉语料（约 29MB，支持断点续传）
python scripts/seed.py --reset       # ② 灌角色 + 语料 + 示例用户（跑前先停 web 服务）
```

判据：`data/corpus/manifest.json` 里两份角色的文件数与 sha256 与本文 §5 一致；`seed` 结束会打印
各角色的 chunk 数。
