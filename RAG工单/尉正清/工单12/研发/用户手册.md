# 用户手册

**工单编号**：人工智能NLP-RAG项目-LightRAG优化

本手册面向要**跑这套对比**或**使用知识图谱**的人。

---

## 一、这套东西是什么

同一批语料（两份招股说明书，898 页）建了**两个**知识库：

| | RAG 向量库 | LightRAG 知识图谱 |
|---|---|---|
| 表征 | 2,232 个文本块的向量 | 5,300 个实体 / 8,301 条关系 + 494 个块 |
| 存储 | 本地文件（`kb_cache/`） | neo4j（Docker） |
| 检索 | BGE-M3 稠密+稀疏，RRF 融合，取 Top-8 | mix 模式：局部实体 + 全局主题 |
| 环境 | `rag_gd` | `rag_gd1` |

16 个测试问题在两边各跑一遍，比对检索结果和 RAGAS 指标。

## 三、单题查询（选择用哪套知识库）

工单验收点之一是「可以选择使用 RAG 还是 LightRAG 的知识库进行检索」，
`query.py` 就是那个选择器：

```bash
# 问 RAG 向量库
D:/Anaconda/envs/rag_gd/python.exe 研发/query.py --kb rag \
    "武汉兴图新科电子股份有限公司注册资本是多少？"

# 问 LightRAG 知识图谱
D:/Anaconda/envs/rag_gd1/python.exe 研发/query.py --kb lightrag \
    "武汉兴图新科电子股份有限公司注册资本是多少？"

# 两个都问，并排打印（注意：这需要两个环境，见下）
```

> ⚠️ **一定要注意用对 python**。两条路的依赖装在不同环境里，
> 用错了脚本会直接告诉你该换哪个（而不是抛一堆 ImportError）：
> ```
> [环境不对] 这条路需要 `FlagEmbedding`，但它不在当前 Python 里。
>            请改用 rag_gd 环境运行：...
> ```

LightRAG 还可以选检索模式（默认 `mix`）：

```bash
研发/query.py --kb lightrag --mode local  "问题"   # 只走实体/局部
研发/query.py --kb lightrag --mode global "问题"   # 只走主题/全局
研发/query.py --kb lightrag --mode hybrid "问题"   # 局部+全局
```

## 四、看知识图谱

浏览器打开 **http://localhost:7474**，账号 `neo4j` / 密码 `neo4j123`。

```cypher
-- 实体类型分布（验收点 1 的直接证据）
MATCH (n) WHERE n.entity_type IS NOT NULL
RETURN n.entity_type AS 类型, count(*) AS 数量 ORDER BY 数量 DESC

-- 查一家公司及其全部关联
MATCH (a {entity_id:'武汉兴图新科电子股份有限公司'})-[r]-(b)
RETURN a, r, b LIMIT 50

-- 找带某个关键词的实体
MATCH (n) WHERE n.entity_id CONTAINS '军用'
RETURN n.entity_id, n.entity_type, n.description LIMIT 20
```

> 关系边的语义类型存在 `keywords` 属性里（neo4j 里所有边的基础类型都是
> `DIRECTED`，这是 LightRAG 的存储约定，不是抽取失败）：
> ```cypher
> MATCH (a)-[r]->(b) RETURN a.entity_id, r.keywords, b.entity_id LIMIT 20
> ```

## 五、常见问题

### 「knowledge graph 是空的 / 查不到东西」

按顺序查三处：
1. `docker ps` —— neo4j 容器在跑吗
2. `kv_store_doc_status.json` 里文档状态是不是 `processed`
3. 上面那条 Cypher 的 `entity_type IS NOT NULL` 条件有没有漏 ——
   LightRAG 还会写一些不带 `entity_id` 的节点，不加条件会把它们也数进来

### 「建图特别慢 / 一直不结束」

看 `config.LLM_REASONING_EFFORT` 是不是被改回默认了。`deepseek-flash` 是推理模型，
不关掉思维链单次调用要 33 秒（关掉后 1.9 秒），建图会从 15 分钟变成 4 个多小时。

### 「重跑建图，图谱没变化」

LightRAG 认**文档 id** 做增量：文档内容变了但 id 没变时，它会认为「已处理过」
直接跳过。重建要带 `--reset`：

```bash
研发/build_graph.py --reset
```

### 「大模型返回空字符串」

`deepseek-flash` 的思维链和正文共用 `max_tokens` 额度，额度被吃光时正文是空串
**且 HTTP 仍是 200**。本项目的调用点统一关了 reasoning；自己写调用时
注意 `max_tokens` 要给足（≥4096）。

### 「想省内存，跑完怎么关」

```bash
bash 部署/stop.sh            # 停流水线 + 停 neo4j 容器（数据保留）
bash 部署/stop.sh --purge    # 连容器一起删（图谱会丢，需重建）
```

neo4j 是唯一用到 Docker 的组件。关掉 Docker Desktop 能收回几个 GB，
但 WSL 虚拟机的内存不会立刻释放，要再执行 `wsl --shutdown` 才彻底归还。

### 「改问题 / 换语料」

- 改测试问题：`研发/testset.py` 的 `TEST_SET`（`gold_answer` / `gold_pages`
  是评估用的标准答案，改问题时一并更新）
- 换语料：`研发/prospectus_docs.py` 的 `DOCS`，然后重建两个知识库

## 六、截图怎么来的

`测试/截图/` 里的图不是手工截的，两个脚本可以随时重生成：

```bash
# 1) 知识图谱的 9 张（需要 Docker 里的 neo4j 已启动）
D:/Anaconda/envs/rag_gd/python.exe 测试/图谱截图.py

# 2) 检索对比的 2 张（从 results/*.json 渲染后截）
D:/Anaconda/envs/rag_gd/python.exe 测试/对比截图.py
```

前 9 张是**驱动 neo4j Browser** 截的真界面（自己用绘图库画一张证明不了图谱真建出来了）；
后 2 张是把真实结果渲染成报告页再截，页面上标了「不是实时系统」，免得误认。
