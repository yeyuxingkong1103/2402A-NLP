## 1. 双层检索口径

工单原文的两层：**局部 = 具体关键词 → 向量库找小段落**；**全局 = 概念性关键词 → 图谱沿关系扩展**。

### 1.1 问题分流

| 分流结果 | 触发条件 | 通道 |
| --- | --- | --- |
| 局部 | 问题命中了图谱实体词典中的具体实体（`entity_dict_from_graph=true`；实体长度 2~40 字符） | 仅向量通道 |
| 全局 | 命中 `abstract_suffixes`（37 条，如「募集资金」「上下游」「技术标准」「组织结构」）或 `abstract_char_hints`（17 条，如「哪些」「构成」「趋势」） | 仅图谱通道 |
| 两路都走 | 都命中，或都判不出（`route_fallback="both"`） | 向量 + 图谱 |
| 强制局部白名单 | `whitelist_local`：发行股数、注册资本、法定代表人、持股比例、销售处、销售部 | 强制并入局部 |

### 1.2 两通道检索

| 项 | 局部通道（向量） | 全局通道（图谱） | RAG 基线（对照） |
| --- | --- | --- | --- |
| 输入 | 局部关键词 | 全局关键词 → 图谱实体 | 原始问题 |
| 检索方式 | 余弦相似度（bge-m3，1024 维） | 命中实体 → 沿关系扩展 → 收集关联块 | 向量 + BM25 双路 |
| 候选数 | `local_top_k = 12` | `global_top_k = 12` | `bm25_top_k = 12` + 向量 12 |
| 扩展深度 | — | `graph_hops = 1`（上限 `graph_max_hops = 3`） | — |
| 实体命中数 | — | `graph_expand_top_entities = 8` | — |
| 关系上限 | — | `graph_max_relations = 60` | — |
| 分数构成 | 余弦相似度（< `min_vector_similarity=0.15` 丢弃） | 图分（归一化）+ `0.35 × 关系置信度` | 相似度 / BM25 分 |

### 1.3 融合与截断

| 项 | LightRAG | RAG 基线 |
| --- | --- | --- |
| 融合算法 | RRF（`rrf_k = 60`） | RRF（`rrf_k = 60`） |
| 通道权重 | `local_weight = 0.55`，`global_weight = 0.45` | `rag_vector_weight = 0.5`，`rag_bm25_weight = 0.5` |
| 最终返回 | `top_k = 8` 块 | `top_k = 8` 块 |
| 入提示词 | `top_k_in_prompt = 6` 块，合计 ≤ `max_context_chars = 5200` 字符 | 同左 |

**公平性约定**：两后端共用 `top_k=8`、同一生成模型（`qwen2.5:3b`）、同一生成参数（`temperature=0.1`、`max_tokens=700`）、同一回答模板与引用规则；**唯一变量是检索通道**。

## 2. 16 题对比流程

```
① 载入  研发\评估\测试问题集.jsonl（16 行，字段：id / question / reference_answer /
        reference_keywords / expected_pages / company / doc）
      │
② 逐题 × 逐后端（串行，禁并发调 LLM，全程只有 1 个模型驻留）
      ├─ backend = rag      → 向量 + BM25 → RRF → top8 → 生成
      └─ backend = lightrag → 分流 → 局部/全局 → RRF → top8 → 生成
      │
③ 逐题落盘（不要攒到最后）  优化\评估结果\逐题结果_<后端>.jsonl
      每行含：id / backend / question / answer / retrieved_chunk_ids /
              retrieved_pages / scores / latency_s / 命中关键词 / 命中页
      │
④ 自动判分（无 LLM，见 §3.4）
      · 关键词命中率（对 reference_keywords，空白归一化后匹配）
      · 数字命中率（正则抽出参考答案中的数字/百分比，比对）
      · 页命中（对 expected_pages，**±1 页容差**）
      │
⑤ 汇总  优化\评估结果\对比汇总.json + 对比汇总.csv
      按后端聚合：答对数 / 总题数、关键词命中率、页命中率、平均延迟
      │
⑥ 出图  测试\测试截图\<中文按测试内容命名>.png（真实数字，禁止手绘）
      │
⑦ 报告 优化\评估结果\对比报告.md —— 逐题列 RAG 与 LightRAG 的答案、命中块、命中页，
      并对未达标题写「未达标 + 根因」
```

**耗时预期**：16 题 × 2 后端 × (检索 ~1 s + 生成 3~10 s) ≈ 2~6 分钟；这是本工单唯一跑 LLM 的评估环节。

### 2.1 页号容差（实测依据）

问题集 `expected_pages` 与分块 `page` 存在 **±1 页**偏差：
例：id 5 问题集记 p39，实际命中块为 `招股说明书2pd-p40-text-81`（含「销售部下设渠道销售部、电话及网络销售部、大客户销售部和国际贸易部」）。
→ 判定页命中时允许 `|命中页 - 期望页| ≤ 1`，并在报告中注明使用了容差。

## 3. RAGAS 四项指标口径

### 3.1 官方口径（若 RAGAS 包可用）

| 指标 | 官方定义 | 取值范围 |
| --- | --- | --- |
| faithfulness（忠实度） | 把答案拆成断言，逐条判断能否由检索上下文支持；得分 = 被支持断言数 / 断言总数 | 0~1，越高越好 |
| answer_relevancy（答案相关性） | 由答案反向生成若干问题，与原问题算嵌入余弦相似度取均值 | 0~1，越高越好 |
| context_precision（上下文精度） | 检索到的相关块在排序中的位置质量（平均精度 AP 类） | 0~1，越高越好 |
| context_recall（上下文召回） | 参考断言的覆盖率：能被检索上下文覆盖的断言数 / 参考断言总数 | 0~1，越高越好 |

### 3.2 依赖现状与降级策略

| 项 | 实测 | 处置 |
| --- | --- | --- |
| `ragas` 包 | 未安装（共享约定 §2 缺失清单：pandas / datasets 等均缺失） | 优先尝试 `python -m pip install --target 研发\第三方库 --no-deps ragas`，**自加硬超时**（pip 网络路径实测会挂死 180~300 s） |
| 装不上时 | — | **自实现等价指标**（§3.4），口径与差异**必须写进本文件与结果文件** |

> 严禁编造 RAGAS 数字。若官方包不可用，结果文件里只出现自实现指标，字段名明确带 `_kw` 后缀以示区分，并在报告中写明「RAGAS 官方四项：未达标 —— 根因：依赖包缺失」。

### 3.3 文本归一化口径（所有指标共用）

**去空白归一化**：匹配前对文本执行 `re.sub(r"\s+", "", text)`。
实测依据：PDF 抽取会在数字与术语中间插空格，归一化后命中块数上升——
`军用领域` 20 → **24** 块、`销售处` 26 → **29** 块、`国家科技进步一等` 13 → **14** 块；反之 `IC 卡` 在语料中带空格，归一名后才能匹配。
→ 不归一化会系统性低估命中率。

### 3.4 自实现等价指标（无 LLM 判官版）

| 自实现指标 | 计算方式 | 近似 RAGAS 的哪一项 | 与官方的差异（必须写进报告） |
| --- | --- | --- | --- |
| `faithfulness_kw` | 答案中出现的「参考关键词 + 数字」有多少比例能在**检索上下文**中找到 | faithfulness | 官方是 LLM 逐断言判断；本口径只看词/数字是否被上下文覆盖，**无法识别同义改写与语义蕴含**，对「上下文有词但答案结论相反」不敏感（偏乐观） |
| `answer_relevancy_kw` | 答案与问题做字符 bigram Dice 相似度（并设最短长度 `answer_relevancy_min_len=4` 兜底） | answer_relevancy | 官方用「答案反向生成问题 + 嵌入余弦」；本口径是**词元重叠代理**，对措辞差异敏感、对语义等价不敏感（偏严格） |
| `context_precision_kw` | 命中的相关块中，排在前面的越多分越高：相关块判据 = 含 `reference_keywords` 或与问题相似度 ≥ `context_precision_threshold=0.5`；得分 = 前 k 位相关块的精度均值 | context_precision | 官方用 LLM 判相关；本口径用关键词/相似度阈值，**相关块集合可能与官方不同** |
| `context_recall_kw` | `reference_keywords` 在检索上下文中被覆盖的比例 | context_recall | 官方对参考断言的覆盖；本口径把「断言」降级为「参考关键词」，颗粒度更粗（偏乐观） |

**共同差异（一句话）**：自实现四项全部以「关键词/数字覆盖率 + 词元重叠」代理官方的「LLM 断言判定 + 嵌入语义」，**方向性可用（能区分 RAG 与 LightRAG 谁更好），绝对值不可与公开榜单的 RAGAS 分数直接比较**。

## 4. 小样本建图抽样口径

### 4.1 为什么抽样

| 项 | 数字 | 来源 |
| --- | --- | --- |
| 全量块数 | **3013 块** | `研发\data\processed\corpus_stats.json` |
| 若全量抽取 | 需要 **3013 次** LLM 调用（`batch_chunks = 1`） | `研发\lightrag\config.py` |
| 抽样量 | 计划 **200 块**（6.6%）；**实跑收束于 88 块**（2.9%，1200s 时间预算触发） | `graph.sample_size = 200`、`研发\data\graph\graph_meta.json` |
| 用户约束 | 「约 10 分钟量级出一个工单」「绝不跑全量 3013 块」 | 本次会话明确要求 |

### 4.2 抽样规则

| 规则 | 参数/口径 |
| --- | --- |
| 随机种子 | `sample_seed = 20250826`（可复现，同一语料同一结果） |
| 信息密度下限 | `min_chunk_chars = 150`：`content` 不足 150 字符的块**先剔除** |
| 类型加权 | `density_bonus_types = ["table", "image"]`：表格/图块信息密度更高，加权入选 |
| 每块调用块数 | `batch_chunks = 1`（串行，避免多模型驻留与超长提示词） |
| 分层配额 | 按 `doc_key` 分层，保证两份招股书都覆盖（口径 = 各层块数占比 × 抽样量） |
| 语料分层实况 | `招股说明书1无水` **813** / `招股说明书1pd` **1371** / `招股说明书2pd` **829**（合计 3013） |
| 分层配额（200 块计划） | **实测** `招股说明书1无水=59`、`招股说明书2pd=61`（其余 80 块为题页优先命中）。注：t1 初稿的「108 / 182 / 110」是按**含带水印重复件**（含 `招股说明书1pd` 1371 块）估的投影，t2 按任务书剔除该重复件后已作废，以本节实测值为准 |
| 断点续跑 | 逐块 append 到 `raw_extractions.jsonl`；`extract_cache = true` 复用已抽结果，重跑不重复调 LLM |
| 原始结果留存 | `save_raw_extractions = true`（保留 LLM 原始返回，便于复核与算类型合法率） |

### 4.3 抽样口径必须声明的位置

抽样口径（本次抽了多少块、占全量比例、种子、分层配额）**必须同时出现在**：
① `研发\data\graph\graph_meta.json`；② `优化\评估结果\对比报告.md`；③ `部署\README.md`。
→ 否则「知识图谱」这一产出物不可追溯。
