# 工单十：部署实现步骤与过程问题记录

> 工单编号：人工智能NLP-RAG-金融问答系统部署

## 一、实现步骤

1. **基线复制**：以工单七为基线 `rsync` 复制到 `工单十/`，排除 `__pycache__`/日志/截图/大数据（`data/ccf_reports/*.pdf` 等），被部署系统为工单六 v6 服务（FastAPI 8006 + Streamlit 8506），不改动任何 RAG 代码。
2. **依赖裁剪**：原 `requirements.txt` 含 CUDA 版 `torch==2.11.0+cu128`（数 GB）与 paddleocr/camelot/MySQL/langchain 全家桶等入库期依赖；整理 `requirements-docker.txt` 仅保留运行期服务依赖，torch 走 `download.pytorch.org/whl/cpu` CPU 索引。
3. **编写 Dockerfile**：python:3.10-slim 基础镜像，分层安装依赖后再 COPY 代码以利用构建缓存；模型不打入镜像。
4. **编写 docker-compose.yml**：rag-api/rag-ui 两服务，named volume 持久化 + 容器间共享，bridge 网络 + host-gateway 访问宿主机 Milvus，`env_file` 注入密钥。
5. **编写启停脚本与验收脚本**：`start_docker_v10.sh`（build+up+健康等待）、`stop_docker_v10.sh`（默认保卷）、`test_deployed_v10.py`（验收三项自动化）。
6. **静态单测**：`tests/test_docker_deploy_v10.py` 12 用例全过；全量 pytest 回归无回退。
7. **构建并启动**：`docker compose build` → `up -d` → 健康检查通过。
8. **部署验收**：运行 `test_deployed_v10.py`，结果落 `docs/deploy_v10_test_results.json`。

## 二、过程问题与解决

### 问题 1：宿主机 8006/8506 被原生 v6 服务占用
- **现象**：工单七遗留的 uvicorn/streamlit 原生进程占用 8006/8506，直接 `compose up` 端口映射会冲突，且占用约 1.8GB 内存。
- **解决**：部署前 `bash 工单七/scripts/stop_v6.sh` 停止原生服务释放端口与内存；容器独占 8006/8506。

### 问题 2：CUDA 版 torch 无法用于镜像
- **现象**：原 requirements 中 `torch==2.11.0+cu128` 单个 wheel 数 GB， slim 镜像无 NVIDIA 运行时且构建极易 OOM。
- **解决**：`requirements-docker.txt` 使用 `torch==2.11.0`（PEP 440 下 `==2.11.0` 匹配 `2.11.0+cpu`），pip 增加 `--extra-index-url https://download.pytorch.org/whl/cpu`；同时 `RAG_EMBED_DEVICE=cpu` 强制 CPU 推理。

### 问题 3：paddleocr/camelot 不能进镜像
- **现象**：二者为 PDF 解析期可选依赖（paddle 整套 >1GB）。
- **解决**：核查代码确认均为 `try/except ImportError` 保护（`src/image_parser/image_ocr.py`、`src/pdf_parser_optimized.py`、`src/table_parser/table_extractor.py`），运行期服务（检索+问答）不会触发，故从 docker 依赖中剔除。

### 问题 4：容器如何访问宿主机 Milvus
- **现象**：Milvus 为宿主机原生 systemd 服务，容器内 `localhost` 指向容器自身。
- **解决**：compose `extra_hosts: host.docker.internal:host-gateway` 将宿主机网关注入容器 hosts，环境变量 `MILVUS_HOST=host.docker.internal`；验收脚本实证容器内 TCP 连通 19530。前置要求 Milvus 监听 `*:19530`（已确认）。

### 问题 5：密钥与模型不入镜像
- **现象**：`.env` 含 `DEEPSEEK_API_KEY`，若被 COPY 进镜像层会泄露；模型 7GB+ 不应随镜像分发。
- **解决**：`.dockerignore` 排除 `.env`（运行时 compose `env_file` 注入）；模型以 `/home/dabaie/models:ro` 只读 bind mount 复用，`HF_HUB_OFFLINE=1` 杜绝容器内联网下载。

### 问题 6：named volume 首启内容
- **现象**：`/app/data` 内含图像/表格资源（镜像 COPY 进去），担心 named volume 挂载后遮蔽导致资源缺失。
- **解决**：Docker 行为——空 named volume 首次挂载时自动以镜像目录内容初始化，既有资源完整保留，之后运行期写入（反馈/日志）全部持久化在卷中；验收脚本 down→up 实证数据不丢。

### 问题 7：Streamlit 与 API 的部署形态
- **分析**：`app/streamlit_app_v6.py` 为进程内引擎（`RAGEngineV6` 单例 + `ConversationEngine`），非 HTTP 客户端。
- **决策**：不做多余改造——rag-ui 容器同样挂模型与 Milvus 独立运行；容器间网络连通由验收脚本以 `rag-ui → http://rag-api:8006` HTTP 调用实证（compose 预留 `API_BASE_URL` 环境变量供需要 HTTP 模式的场景使用）。
