# RAG 角色扮演系统完整运行说明

本文档说明如何在 Windows、Conda 环境 zhuangao6 和 D 盘项目目录中完整运行项目。

## 1. 项目位置

项目目录：D:\rag-roleplay-system
Python 环境：D:\develop_tool1\anaconda3\envs\zhuangao6\python.exe

## 2. 启动后端

打开第一个 PowerShell 窗口，执行：

    Set-Location D:\rag-roleplay-system
    .\run_zhuangao6.ps1

后端地址：
- 服务首页：http://127.0.0.1:8000
- Swagger 接口文档：http://127.0.0.1:8000/docs
- 健康检查：http://127.0.0.1:8000/api/v1/health

后端窗口需要保持运行，按 Ctrl+C 会停止后端。

## 3. 启动前端

打开第二个 PowerShell 窗口，执行：

    Set-Location D:\rag-roleplay-system
    .\run_frontend_zhuangao6.ps1

浏览器打开：http://127.0.0.1:3100

进入页面后选择角色，输入问题并发送即可聊天。

## 4. 当前默认运行模式

当前使用开发演示配置：

    LLM_PROVIDER=mock
    EMBEDDING_PROVIDER=hash
    MILVUS_ENABLED=true
    REDIS_ENABLED=true

含义：mock 使用本地演示模型；hash 使用本地 Hash Embedding；Milvus 不可用时回退到本地索引；Redis 不可用时回退到进程内存。

SQLite 数据库：D:\rag-roleplay-system\data\rag_roleplay.db
本地向量索引：D:\rag-roleplay-system\data\indexes\chunks.json

## 5. 使用 Docker 完整组件

如果需要 MySQL、Redis、Milvus 和 Attu，先启动 Docker Desktop，然后执行：

    Set-Location D:\rag-roleplay-system
    docker compose up -d
    docker compose ps

服务地址：
- MySQL：127.0.0.1:3306
- Redis：127.0.0.1:6379
- Milvus：127.0.0.1:19530
- Attu：http://127.0.0.1:3000

如果 Docker 报告外部网络不存在，执行 docker network create rag-milvus-net，然后重新执行 docker compose up -d。
查看日志：docker compose logs -f app 或 docker compose logs -f milvus。

## 6. 使用接口文档测试

打开 http://127.0.0.1:8000/docs。先调用 GET /api/v1/roles，复制一个角色的 id。然后调用 POST /api/v1/chat。

聊天请求字段：
- user_id：用户 ID，例如 demo-user
- role_id：角色 ID
- conversation_id：会话 ID
- message：用户问题，长度为 1 到 10000 个字符
- stream：是否使用 SSE 流式输出
- top_k：最终使用的知识块数量，范围为 1 到 20

## 7. 上传知识库

接口：POST /api/v1/documents/upload
支持格式：PDF、TXT、MD、CSV、JSON。

上传后流程：文件保存 -> 文档解析 -> 表格或 OCR 处理 -> 文档分块 -> 向量化 -> 写入向量库 -> 建立检索索引。
查看文档状态：GET /api/v1/documents。

## 8. 角色知识隔离

当前配置：RAG_GLOBAL_KNOWLEDGE_CATEGORIES=doctor。
全局演示知识默认只允许健康助手使用。律师、投资、朋友和英语角色不会自动检索全局高血压资料。上传专业文档时，建议传入对应角色的 role_id。

## 9. 停止服务

停止本地后端或前端：在对应窗口按 Ctrl+C。
停止 Docker：进入 D:\rag-roleplay-system 后执行 docker compose down。

## 10. 常见问题

### PowerShell 禁止执行脚本
执行 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned，然后重新运行启动脚本。

### 8000 端口被占用
执行 Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue 查看占用情况，也可以修改 .env 中的 PORT，并同步修改前端 API 地址。

### Milvus 无法连接
执行 docker ps -a 和 docker compose ps 检查 Docker。Milvus 未启动时，项目会使用 data/indexes/chunks.json，仍可进行基础测试。

### 页面没有角色
确认后端运行，然后访问 http://127.0.0.1:8000/api/v1/roles。如果返回角色 JSON，再检查前端 API 地址。

## 11. 接入真实大模型

编辑 D:\rag-roleplay-system\.env，设置：

    LLM_PROVIDER=openai_compatible
    LLM_BASE_URL=https://api.deepseek.com/v1
    LLM_API_KEY=你的API密钥
    LLM_MODEL=deepseek-chat

修改后必须重启后端。不要把真实 API Key 提交到 Git 或公开文档。

## 12. 推荐启动顺序

1. 启动 run_zhuangao6.ps1。
2. 启动 run_frontend_zhuangao6.ps1。
3. 浏览器访问 http://127.0.0.1:3100。
4. 选择角色并开始聊天。

当前项目是开发演示配置，使用 Mock LLM、Hash Embedding 和少量演示知识。医疗、法律和金融场景上线前，需要导入经过审核、注明来源和更新时间的专业知识库，并接入可靠的大模型和评测流程。
