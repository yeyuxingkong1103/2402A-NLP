## 二、关键技术点 → 代码落点

工单要求的技术链路：
**pdfplumber 抽表格 → 转 Markdown → 整表作为 1 个 chunk 入库 → 检索时表格块优先级提升**

| 技术点 | 代码位置 | 说明 |
| --- | --- | --- |
| pdfplumber 抽表格 | `table_extractor.extract_page_tables()` | `find_tables(lines)`，必要时回退 `lines+text` / `text+text` |
| 转 Markdown（保留表头与行列对应） | `table_extractor.table_to_markdown()` | 复用 `rag_core.pdf_parse._table_to_markdown`，口径与工单01/02 一致 |
| 整表作为 1 个 chunk | `rag_core.chunk._block_to_single_chunk()` | 表格块走该分支，**不参与字符切分**；本工单不修改 rag_core |
| 检索时表格块优先级提升 | `build_index_with_tables.boost_table_docs()` | 数值/清单类问题 ×1.35，其它 ×1.15 |
| 表格质量校验 | `table_extractor.is_valid_table()` + `normalize_grid()` | 过滤空表/单行单列/列数异常；修复表头列错位 |
| 跨页表合并 | `table_extractor.merge_cross_page_tables()` | 四条件判定，拒绝「同表头不同小节」的错误合并 |
| 表格标题抽取 | `table_extractor.extract_caption()` | 标题前置入库，补回表格块缺失的章节路径 |

## 四、稳定性措施

| 措施 | 实现位置 | 作用 |
| --- | --- | --- |
| 单页解析容错 | `extract_page_tables()` try/except | 某页失败不影响整本 |
| 多策略兜底 | `FALLBACK_SETTINGS` | 主策略抽不到时自动换策略 |
| 表格质量校验 | `is_valid_table()` | 拦截空表、噪声表、列数异常表 |
| 保守合并策略 | `merge_cross_page_tables()` | 宁可漏合并也不错合并，拒绝记录可审计 |
| 离线抽取式兜底 | `build_index_with_tables.extractive_answer()` | 无 API Key / 网络异常时流程不中断 |
| PDF 解析缓存 | `rag_core.pdf_parse` 自带的 JSON 缓存 | 重复运行不重复解析 |
| 表格记录缓存 | `results/tables/<文档>_records.json` | 消融实验两套索引共享一次抽取结果 |
| 独立 BM25 文件 | `bm25_path_of(collection)` | 每个集合一份 `.bm25.pkl`，避免与其它工单互相覆盖 |
| 重排器拟合容错 | `load_retriever(fit_reranker=True)` try/except | 重排器不可用时退化为普通排序 |
| 服务惰性装载 | `serve.get_retriever()` | 首次请求才加载模型，加快启动 |

## 六、验收自检清单（逐条打勾）

运行完四步后，按此清单核对：

- [ ] `results/table_inventory.json` 中能看到 id 1~4 对应的 4 张表，
      且 `header` 为 3 列（`序号/项目名称/计划总投资(万元)`、
      `关联方名称/持股比例/与本公司关系`、`企业名称/与本公司关系`），
      没有出现 9 列 / 15 列的错列表。
- [ ] `results/table_inventory.json` 的 `merge_events` 中，
      p157→p158 的那条是 `rejected`（理由：新小节），
      财务报表类的续页是 `merged`。
- [ ] `results/index_stats.json` 的 `chunk_types` 中 `table` 数量 > 0，
      且 `n_table_records` 与清单条数一致。
- [ ] `results/table_qa.md` 中 id 1~4 的「答案要点命中率」为 100%，
      「表格命中」为「是」。
- [ ] `results/table_ablation.md` 中：
      表格类 4 问的 B 组准确率 > A 组；
      文本类 10 问的 B 组准确率不低于 A 组；
      **14 问总体准确率 ≥ 90%**。
- [ ] `results/evaluation.md` 中 `latency_under_3s_ratio` 接近 100%
      （检索侧为毫秒级；若使用 LLM，端到端耗时取决于生成模型）。
- [ ] `python serve.py` 启动后，页面上提问 id 1~4 能同时看到
      答案、检索精确度、以及渲染成表格的表格原文。
- [ ] 用英文提问（如 *What is the number of shares issued?*）
      能得到英文回答，验证多语言支持。
