## 1. 评测口径（先明确「准确率 / 召回率」怎么算）

工单任务目标：**准确率 ≥90%、召回率 ≥95%**。检索层用以下可自动计算的
代理指标（问题集 14 问，关键信息点均对照《招股说明书1/2》原文核实）：

```
  关键信息点（anchors）：正确答案必须包含的锚点词/数值
  例：问题「注册资本是多少」→ anchors = ["注册资本", "5,520"]

  准确率@5 = Top-5 片段覆盖该问题【全部】关键信息点的问题占比
             （等价于"生成阶段能否答对"，即问答准确率）
  召回率@5 = 被 Top-5 片段覆盖的【关键信息点】平均比例
             （衡量重要信息有没有找全）
  HitRate@5 = Top-5 中至少命中一个相关片段的问题占比
  MRR       = 第一个相关片段排名倒数的均值
  Precision@5 = Top-5 中相关片段的平均占比
```

> 口径说明：问卷式「准确率」需要人工判卷，无法自动复跑；本工程用
> 「关键信息点覆盖」作为可自动化的严格代理——只要有一个关键数字没进
> 上下文，生成阶段就可能答错，因此该口径不虚高。所有 anchors
> 可在 `results/strategy_comparison.md` 第五节「检索答案」中逐条核对。

## 4. 对比三：融合算法（同一问题）

> 实测见 `results/hybrid_demo.md`：三种融合的 Top-5 排序差异、
> 「关键信息点最全的片段」在融合前后的名次变化、α 从 0 到 1 的排序迁移。

结论要点：

- `α = 0` 时排序与纯 BM25 一致，`α = 1` 时与纯向量一致（脚本可验证）；
- `weighted` 的 Top-N 会随 α 平滑变化，适合按问题类型调参；
- `rrf`/`vote` 不提供权重旋钮，但跨量纲更稳，默认选 `rrf`。

## 5. 对比四：多嵌入模型（bge-large-zh-v1.5 vs m3e-base）

> 实测见 `results/vector_demo.md`：同 query 的两模型 Top-5、
> 重合度（Jaccard）与检索耗时。

结论要点：

- 两模型 Top-5 重合度可作为「模型差异」的量化参考，重合度低说明召回互补；
- 中文金融语料上 bge-large-zh-v1.5 通常更准，m3e-base 更轻量；
- 多语言场景可切换 bge-m3 并重建集合。

## 6. 达标判定与结论模板

`retrieval_strategy_comparison.py` 会自动选出「准确率优先、召回率次之」
的最优配置，并在 `results/strategy_comparison.md` 第三节输出：

```
  - 结论配置：<脚本自动判定>
  - 准确率：xx.xx%（目标 ≥90%，达标/未达标）
  - 召回率：xx.xx%（目标 ≥95%，达标/未达标）
  - 平均响应：x.xxx s（目标 <3s，达标/未达标）
```

结论撰写模板（把脚本输出抄入即可）：

1. **策略层增益**：hybrid 相对单路 vector/fulltext 的准确率与召回率提升幅度；
2. **重排层增益**：tfidf/cascade 相对 none 的 MRR 与准确率提升；
3. **代价**：各配置平均耗时，指出满足 3 秒约束的档位；
4. **最终推荐**：默认 `hybrid + rrf + tfidf`；精度优先 `hybrid + rrf + cascade`。
