# 业务与数据流程图

## 1. 用户问答业务流程

```mermaid
flowchart TD
    A[用户输入问题] --> B[API Key 鉴权与限流]
    B --> C{请求是否合法?}
    C -- 否 --> C1[返回 401 / 429 / 413]
    C -- 是 --> D[解析 ChatRequest]
    D --> E[校验用户、租户、知识库范围]
    E --> F{是否带 session_id?}
    F -- 是 --> G[Redis 读取短期历史\nMilvus 读取长期记忆]
    F -- 否 --> H[无状态单轮上下文]
    G --> I[Query 改写与意图处理]
    H --> I
    I --> J[并行召回]
    J --> J1[Milvus Dense 检索]
    J --> J2[BM25 稀疏检索]
    J --> J3[可选多路来源]
    J1 --> K[候选合并去重 / 融合]
    J2 --> K
    J3 --> K
    K --> L[重排序与相似度阈值]
    L --> M{是否找到足够上下文?}
    M -- 否 --> N[返回兜底话术与人工渠道]
    M -- 是 --> O[Prompt 组装\n角色·历史·来源·业务规则]
    O --> P[LLM 生成答案]
    P --> Q[后处理\n格式·引用·长度·安全]
    Q --> R{stream?}
    R -- 是 --> S[SSE 分块返回]
    R -- 否 --> T[JSON 返回答案与来源]
    S --> U[保存会话轮次]
    T --> U
```

## 2. 离线知识库构建流程

```mermaid
flowchart LR
    A[PDF / Word / TXT / Markdown / JSONL] --> B[格式识别与解析]
    B --> C[文本清洗\n页眉页脚·水印·空白]
    C --> D[质量检查\n字段·长度·乱码]
    D --> E[文件 SHA256 去重]
    E --> F[内容去重与分类]
    F --> G[文本分块\nfixed / sentence / paragraph / heading / semantic]
    G --> H[Embedding 批量向量化]
    H --> I[Milvus 写入向量]
    G --> J[MySQL 写入文档和块元数据]
    I --> K[索引完成]
    J --> K
```

## 3. 文档上传数据流

```mermaid
sequenceDiagram
    participant Client as 客户端
    participant API as Upload API
    participant Parser as Parser
    participant Chunker as Chunker
    participant Indexer as Indexer
    participant Milvus as Milvus
    participant MySQL as MySQL

    Client->>API: multipart 上传文件 + KB 参数
    API->>API: 文件名安全校验与大小限制
    API->>Parser: parse_document()
    Parser-->>API: Document + metadata + SHA256
    API->>Chunker: chunk_document()
    Chunker-->>API: Chunk 列表
    API->>Indexer: index(document, chunks)
    Indexer->>MySQL: 检查文档哈希 / 保存元数据
    Indexer->>Milvus: 批量写入向量
    Milvus-->>Indexer: 插入结果
    Indexer-->>API: document_id + chunks_inserted
    API-->>Client: 201 UploadDocumentResponse
```

## 4. 会话生命周期

```mermaid
stateDiagram-v2
    [*] --> Active: POST /sessions
    Active --> Active: POST /chat
    Active --> Active: PUT /sessions/{id}/role
    Active --> Active: POST /sessions/{id}/clear
    Active --> Archived: POST /sessions/{id}/end
    Archived --> [*]
    Active --> Expired: Redis TTL / 生命周期策略
    Expired --> [*]
```

## 5. 数据存储边界

| 数据 | 存储 | 生命周期 |
|---|---|---|
| 原始上传文件 | `DOCUMENT_STORAGE_PATH` | 文档处理期间或按部署策略保留 |
| 文档、块和知识库元数据 | MySQL | 持久化 |
| 文档向量 | Milvus | 持久化，可按文档删除 |
| 当前会话消息 | Redis | 滑动窗口 / TTL |
| 用户偏好和长期摘要 | Milvus 记忆集合 | 跨会话持久化 |
| API 指标 | Prometheus 采集端 | 由监控系统保留 |
