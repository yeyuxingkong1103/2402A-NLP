# 接口文档

> 工单编号：人工智能NLP-RAG-基于PDF文档的问答系统
> 文档版本：V1.0
> 编写日期：2026-09-28
> 基础地址：`http://<host>:8000`  （默认 `http://127.0.0.1:8000`）
> 数据规范：JSON / UTF-8

## 一、接口总览

| 序号 | 接口 | 方法 | 描述 | 鉴权 |
| :--: | :--- | :--: | :--- | :--: |
| 1 | `/api/health` | GET | 健康检查 / 心跳 | 否 |
| 2 | `/api/ask` | POST | 单轮问答（RAG） | 否 |
| 3 | `/api/ask/baseline` | POST | 仅 LLM 基线问答（用于对比） | 否 |
| 4 | `/api/evaluate` | POST | RAGAS 评估（自定义样本） | 否 |
| 5 | `/api/evaluate/workorder` | POST | 工单 10 题一站式评估 | 否 |
| 6 | `/api/feedback` | POST/GET | 提交 / 查询答案反馈 | 否 |
| 7 | `/api/documents` | GET | 列出已入库文档 | 否 |
| 8 | `/api/upload` | POST | 上传 PDF 入库 | 否 |
| 9 | `/api/documents/{doc_id}` | DELETE | 删除文档 | 否 |

> 说明：本工单为内网演示场景，未启用鉴权；生产环境需加 API-Key/OAuth2。

## 二、通用响应包装

所有业务接口响应统一为：

```json
{
  "code": 0,           // 0=成功，非 0=失败
  "message": "ok",     // 描述
  "data": {},           // 业务数据
  "trace_id": "abc123" // 链路追踪 ID
}
```

## 三、接口详细

### 1. GET /api/health
健康检查。

**响应示例**
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "status": "healthy",
    "chunks": 1612,
    "vector_backend": "faiss",
    "cache": "local"
  }
}
```

### 2. POST /api/ask
单轮问答，基于已入库的招股说明书。

**请求体**
| 字段 | 类型 | 必填 | 说明 |
| :--: | :--: | :--: | :-- |
| question | string | 是 | 用户问题 |
| top_k | int | 否 | 检索 Top-K，默认 5 |
| use_cache | bool | 否 | 是否启用答案缓存（本地文件/Redis），默认 true |
| lang | string | 否 | 语言 `zh`/`en`，默认 `zh` |

**请求示例**
```json
{
  "question": "武汉兴图新科电子股份有限公司的法定代表人是谁？",
  "top_k": 5,
  "use_cache": true,
  "lang": "zh"
}
```

**响应示例**
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "answer": "根据招股说明书，武汉兴图新科电子股份有限公司的法定代表人是 ...",
    "refs": [
      {"doc_id": "prospectus1", "page": 1, "score": 0.87, "text": "武汉兴图新科电子股份有限公司..."}
    ],
    "latency_ms": 1830,
    "cache_hit": false
  }
}
```

**错误码**
| code | 含义 |
| :--: | :--- |
| 40001 | 缺少 question 字段 |
| 50001 | LLM 调用失败 |
| 50002 | Milvus 检索失败 |

### 3. POST /api/ask/baseline
不使用 RAG，直接调用 LLM 进行基线回答，用于对比。

**请求体**：同 `/api/ask`

**响应示例**
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "answer": "我无法访问该招股说明书的内容...",
    "latency_ms": 920,
    "refs": []
  }
}
```

### 3.1 POST /api/feedback
提交答案反馈，用于知识库持续优化。

**请求体**
| 字段 | 类型 | 必填 | 说明 |
| :--: | :--: | :--: | :-- |
| question | string | 是 | 原问题 |
| answer | string | 是 | 原答案 |
| rating | string | 是 | `up` / `down` |
| comment | string | 否 | 文字意见 |

**响应示例**
```json
{"code": 0, "message": "ok", "data": {"saved": true}}
```

`rating` 非法时返回 `40002`。`GET /api/feedback` 返回全部反馈列表。

### 4. POST /api/evaluate
对一组问答进行 RAGAS 评估。

**请求体**
| 字段 | 类型 | 必填 | 说明 |
| :--: | :--: | :--: | :-- |
| items | array | 是 | 问答数组 |
| items[].question | string | 是 | 问题 |
| items[].answer | string | 是 | RAG 给出的答案 |
| items[].ground_truth | string | 是 | 标准答案 |
| items[].contexts | array | 否 | 检索上下文 |

**请求示例**
```json
{
  "items": [
    {
      "question": "武汉兴图新科电子股份有限公司的法定代表人是谁？",
      "answer": "王某某",
      "ground_truth": "王某某",
      "contexts": ["..."]
    }
  ]
}
```

**响应示例**
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "summary": {
      "faithfulness": 0.92,
      "answer_relevancy": 0.88,
      "context_precision": 0.85,
      "context_recall": 0.81
    },
    "items": [
      {
        "question_id": 531,
        "faithfulness": 1.0,
        "answer_relevancy": 1.0
      }
    ]
  }
}
```

### 5. GET /api/documents
列出已入库文档。

**响应示例**
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "documents": [
      {"doc_id": "prospectus1", "name": "招股说明书1.pdf", "chunks": 1234, "pages": 548, "ingest_at": "2026-09-28T10:00:00"}
    ]
  }
}
```

### 6. POST /api/upload
上传 PDF 文档并入库（multipart/form-data）。

**请求参数**
| 字段 | 类型 | 必填 | 说明 |
| :--: | :--: | :--: | :-- |
| file | file | 是 | PDF 文件 |
| doc_id | string | 否 | 自定义文档 ID，默认取文件名 |

**响应示例**
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "doc_id": "招股说明书2.pdf",
    "chunks": 980,
    "pages": 412,
    "latency_ms": 24500
  }
}
```

### 7. DELETE /api/documents/{doc_id}
删除指定文档及其向量。

**响应示例**
```json
{
  "code": 0,
  "message": "ok",
  "data": {"deleted": "招股说明书2.pdf"}
}
```

## 四、错误码总表

| code | HTTP 状态 | 含义 | 处理建议 |
| :--: | :--: | :--- | :--- |
| 0 | 200 | 成功 | - |
| 40001 | 400 | 参数错误 | 检查请求体 |
| 40002 | 400 | 反馈参数错误 | rating 仅支持 up/down |
| 40401 | 404 | 资源不存在 | 检查 doc_id |
| 42201 | 422 | PDF 解析失败 | 检查文件有效性 |
| 42901 | 429 | 请求过频 | 限流 |
| 50001 | 500 | LLM 调用失败 | 重试或检查 LLM 服务 |
| 50002 | 500 | 向量库失败 | 检查 FAISS/Chroma/Milvus 状态 |
| 50003 | 500 | 向量化失败 | 检查 Embedding 模型 |

## 五、SDK 调用示例

```python
import httpx

# 问答
resp = httpx.post(
    "http://127.0.0.1:8000/api/ask",
    json={"question": "公司注册资本是多少？", "top_k": 5},
    timeout=10
)
print(resp.json())

# 上传 PDF
with open("招股说明书1.pdf", "rb") as f:
    httpx.post(
        "http://127.0.0.1:8000/api/upload",
        files={"file": f},
        timeout=120
    )
```

## 六、工单 10 题验收映射

| question_id | 接口 | 用途 |
| :--: | :-- | :--- |
| 260 / 95 / 33 / 34 / 957 / 793 / 795 / 543 / 531 / 207 | `POST /api/ask` + `POST /api/ask/baseline` | 对比 RAG vs LLM |

调用示例：
```python
questions = [
    {"id":260,"question":"报告期内，武汉兴图新科电子股份有限公司来自军用领域的收入分别是多少？"},
    {"id":95, "question":"武汉兴图新科电子股份有限公司参与制定了哪个技术标准？"},
    # ... 其余 8 题
]
for q in questions:
    rag = httpx.post("/api/ask", json={"question": q["question"]}).json()["data"]
    base = httpx.post("/api/ask/baseline", json={"question": q["question"]}).json()["data"]
    print(q["id"], rag["answer"], base["answer"])
```

---

> 技术备注：
> - **RESTful 设计**：本接口遵循 REST 风格，资源化路径 + HTTP 动词语义化，便于前端联调与扩展。
> - **RAG（Retrieval-Augmented Generation）**：`/api/ask` 走 RAG 流程，`/api/ask/baseline` 跳过检索直接调用 LLM，二者对比构成工单要求的"对比分析"。
