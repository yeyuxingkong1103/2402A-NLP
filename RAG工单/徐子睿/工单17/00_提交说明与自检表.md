## 一、任务描述（摘自工单）

系统试运行阶段，**>10 用户并发**时出现：响应从 ~2s 飙升到 >10s；**内存缓慢增长直至 OOM**；纯文本问答也占用大量 GPU 显存且释放不及时。要求：

- **任务一**：`docker-compose` 部署完整 RAGFlow（API Server + Task Executor + 向量库 + Redis）；用 **JMeter** 压测两类场景并记录基准：
  - 场景 A：**20 并发**高频问答（已入库文档的简单问题）；
  - 场景 B：**10 并发混合负载**（5 问答 + 5 上传解析 PDF）。
- **任务二**：定位瓶颈与泄漏点——`py-spy` 采 CPU 热点、`memory-profiler`/`objgraph` 跟踪内存对象、`nvidia-smi`/`docker stats` 监控 GPU 与容器内存、`redis-cli INFO stats` 看队列堆积、静态审查 `api/service.py`、模型单例、DeepDoc 调用上下文。
- **任务三**：优化修复——资源池化 + **单例模式**（解析器/重排模型）、连接池；解析任务走 Redis 队列异步化、检索+生成链路 asyncio/线程池限流。
- **任务四**：同脚本复测，对比优化前后指标，出报告。

**验收**：场景 A 跑 10 分钟 P95 ≤3s、无失败、容器内存波动 <10%；场景 B 跑 10 分钟不崩溃、解析入队被消费、问答 P95 ≤5s；连续 12h 内存增长 ≤20%；运维文档清晰。
