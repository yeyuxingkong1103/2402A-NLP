## 一、链路总览

```
【离线】数据 → 知识 → 索引
  ① 采集        data/raw/ 26 份 PDF / 433 页
      ↓
  ② 解析成卡    247 张知识卡（附录B 25 / 正文 186 / 附录A 36）
      ↓
  ③ 切分        203 个 chunk（其中 5 个带症状覆盖层 sym_text）
      ↓
  ④ 向量化      BGE-M3 稠密(1024) + 稀疏(lexical weights)
      ↓
  ⑤ 建索引      Milvus Lite：HNSW/COSINE + SPARSE_INVERTED + 11 标量倒排

【在线】问题 → 答案
  ⑥ 检索       归一 → 意图识别 → 意图路由 → 实体覆盖检查 → RRF 混合检索
               → reranker 闸门 → 三层兜底
      ↓
  ⑦ 生成       高危走模板（不过模型）/ 普通走 DeepSeek + 强制核实提示
      ↓
  ⑧ 服务       FastAPI + 单文件 HTML（:8000）

横向支撑：配置（configs/）· 评估（eval/）· 自检（tests/）· 交叉验证（scripts/diff_mineru.py）
```

## 四、阶段 ③ 切分 + ④ 向量化 + ⑤ 建索引（离线）

| 步骤 | 代码 | 行数 | 输入 → 输出 |
| --- | --- | ---: | --- |
| 切分 / 造检索字段 | `src/index/build_chunks.py` | 281 | 卡 JSONL + `symptoms.jsonl` → `data/chunks/chunks.jsonl`（203 行，5 行带症状） |
| 向量化 | `src/index/embed_chunks.py` | 170 | `chunks.jsonl` → `chunks_embedded.jsonl`（203 行） |
| 建库建索引 | `src/index/build_milvus_index.py` | 230 | → `data/index/milvus_rag.db`，collection `agri_knowledge` |
| 向量质量检查 | `scripts/check_embedding_quality.py` | 161 | 术语对余弦 + 归一化前后对比（入库前先看方向对不对） |

切分层的两个关键设计（都在 `build_chunks.py`）：

- `embed_text(c)` —— **刻意不含剂量/安全间隔期**，数值交给 BM25
- `bm25_text(c)` —— 全卡文本、**含高危数值**，供精确匹配
- `sym_text` —— 症状覆盖层文本（**外部二级来源**），单开一个键，**不写进前两个字段**；
  ✅ **设计口径已实施（2026-09-29 Task 5）**：编码时把 `sym_text` 并入两路——
  `embed_chunks.py` 已改为稠密喂 `embed_text + sym_text`、稀疏喂 `bm25_text + sym_text`，索引已重建
- 一卡一 chunk；附录A 36 张 `in_scope=false` 不进检索；另过滤 8 张光杆章节标题卡（`is_heading_only()`）

**症状挂卡覆盖层（2026-09-28 试点，与切分同层）**

- 数据：`data/processed/symptoms.jsonl` **6 条**（覆盖 5 张卡；字段口径见 `docs/superpowers/specs/2026-09-28-symptoms-field-design.md`），来源快照 `data/external/symptoms_raw/`
- 校验：`scripts/validate_symptoms.py`（退出码 0=通过，2=缺文件；查挂空 / 挂不进索引的卡 / 挂错卡 / 枚举 / 重复 id），亦可被 pytest 导入
- 复核清单：`scripts/make_symptoms_checklist.py` 现算 `data/processed/症状挂卡清单.md`
- 切分产物多三个键：`sym_text` / `symptoms`（结构化条目，供答案层引用）/ `meta.has_symptoms`；`embed_text` / `bm25_text` 口径不变
- **检索层已改（2026-09-29，spec §4.3.2 / §4.3.3）**：原先「检索层一行不改」的口径**已被推翻**——
  Task 7 实测证明纯语义抬不动闸门/排序（`hybrid()` 不取 `sym_text`，重排器看不到症状）。
  现行做法分两步：① 把 `sym_text` 纳入**重排 passage**（`hybrid()` 取回 `sym_text`；
  `rerank_gate` / `rerank_sort` 的 pair 走**唯一**构造点 `_rerank_passage`）
  ② **但只在症状问法时**才拼——判据＝`is_symptom_query(q)`（无语料实体**且**无意图），
  否则问施药规矩的技术问句会被方案卡的症状文本顶过附录B 闸门（实测那条 auto 回退）
- ✅ **索引已重建（2026-09-29 Task 5）**：`chunks_embedded.jsonl` 与 Milvus 均已重跑，
  `embedding_meta` 记 `dense_source_field=embed_text + sym_text` / `sparse_source_field=bm25_text + sym_text`
- ⚠️ **重排器现已能看到症状**（原「看不到」的记录作废）：`output_fields` 取回了 `sym_text`；
  但 `bm25_text` **仍是卡本体口径**（实体表从它现算，污染它会让兜底档位漂移）——
  症状只进重排 passage，不进基底。评估口径见第六节末「现状口径」

```bash
python scripts/validate_symptoms.py                  # 症状覆盖层校验，非 0 别往下走
python scripts/make_symptoms_checklist.py            # 生成人工复核清单
python src/index/build_chunks.py
python src/index/embed_chunks.py                     # BGE-M3，GPU 编码
python src/index/build_milvus_index.py --recreate     # 重建 collection
python scripts/check_embedding_quality.py
```

索引结构：稠密向量 HNSW/COSINE + 稀疏 SPARSE_INVERTED + **11 个标量倒排索引**
（`crop` / `knowledge_type` / `pest_kind` / `region` / `std_no` / `source_section` / `subtype` / `type_group` / `year` / `is_high_risk` / `needs_verification_hint`）。

## 五、阶段 ⑥ 检索（在线，主链路）

**代码：`src/retrieve/search.py`（926 行）—— 全项目最核心的文件。**

| 层 | 函数 | 位置 | 职责 |
| --- | --- | --- | --- |
| L1 口语归一 | `normalize()` | L93 | 口语 → 标准术语，单遍定位 + 链式，每条约映射最多用一次；`_protected_spans()` 防长实体被短词切碎 |
| L2 意图识别 | `detect_intent()` | L271 | 问法 → 14 个意图之一（`intent_map.json`） |
| L3 意图路由 | `route_sections()` / `build_route_expr()` | L243 / L253 | 意图 → 章节号 → Milvus 过滤表达式；`_load_section_titles()` 从正文标题现算 |
| L4 覆盖检查 | `coverage_check()` / `check_pending()` / `extract_entities()` / `_clean()` | L388 / L281 / L359 / L319 | 有卡 / 正文提过 / 完全没提 三档判定；pending 词确定性兜底 |
| 症状问法判据 | `is_symptom_query()` | L433 | **无语料实体「且」无意图**——检索层（症状是否进重排 passage）与生成层（【症状对照】段）**共用这一个函数** |
| L5 混合检索 | `Searcher` 类 | L501 | `dense()`（粗筛）+ `sparse()`（喂原始 query）+ RRF 融合 |
| L6 闸门排序 | `Searcher.rerank_gate()` / `rerank_sort()` | L603 / L637 | BGE-reranker-v2-m3 交叉编码器既当**闸门**又当**排序**（修 RRF 常数噪声）；passage 由唯一构造点 `_rerank_passage()`（L471）产出 |
| 主流程 | `search()` | L699 | 串起以上，返回 `(状态, 归一化query, 意图, 结果, 说明)` |

状态机（`search()` 的返回值，决定下游走模板还是兜底）：

- `ok` / `ok_relaxed` —— 正常命中
- `ok_noplan` —— 有正文知识但**无用药方案**（不硬兜底，走正文清单 + 提示）
- `fallback_nocoverage` / `fallback_empty` / `fallback_lowscore` —— 三层兜底，统一回 `FALLBACK_MSG = "暂无防治方案，请咨询当地农技站"`（L55）

「冠军营救」：全库池 rerank 冠军若是**正文卡**且高出路由池冠军 0.05 以上，判为路由劫持、插到队首；**永不把附录B 方案卡带回**。

**检索行为由配置决定，改这三个文件等于改检索：**

| 配置文件 | 内容 | 条数 |
| --- | --- | --- |
| `configs/colloquial_map.json` | 术语归一化（口语 → 标准术语） | 75 |
| `configs/intent_map.json` | 意图识别（问法 → 14 个意图） | 76 |
| `configs/retrieval_params.json` | 阈值、topk、rerank 参数 | — |
| `scripts/build_colloquial_map.py` (372) | 生成上述两张表 + `口语映射表.md` | — |
| `scripts/make_review_list.py` (121) | 导出 unverified 映射待筛清单 | — |

```bash
# 单条直查（L1–L6 全链路，含分数）
python src/retrieve/search.py --query "黄瓜起腻虫了打什么药" --crop 黄瓜 --show-score

# 无索引阶段的规则层冒烟（关键词版，验识别层）
```

## 六、阶段 ⑦ 生成（在线）

**代码：`src/generate/answer.py`（477 行）。** 分叉逻辑：卡是高危 → 模板，绝不经过模型。

| 函数 | 位置 | 职责 |
| --- | --- | --- |
| `_is_symptom_query()` | L76 | **只做延迟导入 + 保守兜底**：判据本体在检索层 `search.is_symptom_query()`（无语料实体**且**无意图），两层共用同一个函数；⚠️ 输入须是**归一化问句**（`compose` 的 `nq`，spec §5.1） |
| `render_symptoms()` | L105 | 症状条目 → 【症状对照】段：逐字不过模型、外部来源分标，每条冠以自己的 `pest` |
| `_sym_block()` | L125 | 【症状对照】整块（对照结论句 + 症状段）——三条渲染路径共用，结论句主语取自症状条目的 `pest` |
| `_top_symptoms()` | L142 | 取 top-1 卡的症状条目（非症状问法 / 无症状 → 空；喂归一化问句） |
| `render_high_risk()` | L154 | 高危**有药剂**卡：按防治适期分组，数值逐字来自卡片，模型不参与 |
| `render_high_text()` | L219 | 高危**无药剂**卡（28 张）：不渲染【用药方案】，标题用卡自带 `knowledge_type`，正文从 `measures[]`/`precautions` 逐字照抄 |
| `_render_clauses()` | L257 | `measures[]`/`precautions` → 编号原文行 |
| `_render_chem()` | L277 | 一条药剂 dict → 两行文本（剂量/兑水/方法） |
| `call_model()` | L309 | 普通（非高危）卡交 DeepSeek 组织成农户能看懂的话 |
| `compose()` | L345 | 模板 + 模型 + 来源 + **核实提示强制注入**，拼最终答案 |
| `main()` | L437 | CLI：检索 + 生成一条龙 |

【症状对照】段的排序规则（2026-09-28 用户裁决）：**只渲染一次**，且**永远排在所有【用药方案】之前**——
挂在 top-1 所属那一组；top-1 不在任何高危组时整块提前。症状来源与卡片来源**各标各的**；
核实提示里那句「症状描述来自外部文献…」**只在症状段真的渲染了才加**（措辞跟着内容走，
与「没有药剂时不许再说剂量照抄」同一条原则）。

```bash
python src/generate/answer.py --query "黄瓜霜霉病打什么药" --crop 黄瓜 --dry-run   # 不调模型，只看骨架
python src/generate/answer.py --query "黄瓜霜霉病打什么药" --crop 黄瓜
```
