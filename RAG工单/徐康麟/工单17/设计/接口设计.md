# 工单17 接口设计

工单编号：`人工智能NLP-RAG-解决API 服务并发瓶颈与资源泄漏工单`

基座契约来自工单10（`研发/service/api.py`），本工单**新增 4 个端点**并**不破坏既有契约**。

## 2. 核心接口契约

### 2.1 `POST /api/v1/ask`（改造）

**请求**（不变）：

```json
{
  "question": "平安银行的拨备覆盖率是多少？",
  "session_id": "loadgen-1",
  "lang": "auto",
  "top_k": 5,
  "with_evidence": false
}
```

**成功响应** `200`（不变，字段与工单10 逐位一致）：见 `AskResponse`。

**新增：过载响应 `429`**（限流生效时）

```json
{
  "detail": "服务繁忙：在途 8 / 上限 8，排队 32 / 上限 32；请稍后重试",
  "inflight": 8,
  "queued": 32,
  "max_inflight": 8,
  "queue_max": 32,
  "retry_after_s": 2
}
```
响应头：`Retry-After: 2`

**行为变化**：

| 项 | 优化前 | 优化后 |
| --- | --- | --- |
| 路由类型 | `def`（同步，占线程池） | `async def` + `run_in_threadpool` |
| 入口限流 | **无** | `BoundedGate`：在途 ≤ `PERF_MAX_INFLIGHT`，排队 ≤ `PERF_QUEUE_MAX` |
| 过载行为 | 全部堆积 → 全部变慢 | 超出立即 `429` |

### 2.2 `POST /api/v1/uploads`（新增）

**请求**：`multipart/form-data`，字段 `file`（`.pdf`）。

**校验**（全部失败 → `400` + 明确原因，**任务不入队、服务不崩**）：

| 检查 | 条件 | 失败响应 |
| --- | --- | --- |
| 扩展名 | 必须以 `.pdf` 结尾 | `400 {"detail":"只接受 .pdf 文件"}` |
| 大小 | ≤ `PERF_UPLOAD_MAX_MB`（默认 32） | `400 {"detail":"文件超过 32 MB"}` |
| PDF 魔数 | 前 5 字节为 `%PDF-` | `400 {"detail":"不是有效的 PDF（缺少 %PDF- 魔数）"}` |
| 可解析性 | `fitz.open()` 成功 | `400 {"detail":"PDF 已损坏：..."}` |

**成功响应** `202`：

```json
{"task_id": "t-8f3a1c2d", "status": "pending", "queue_depth": 3,
  "filename": "平安银行2022年报.pdf", "size_bytes": 4213877, "submitted_at": 1791888000.12}
```

**队列满响应** `429`：`{"detail":"解析队列已满（32/32）", "queue_depth":32}` + `Retry-After: 5`

### 2.3 `GET /api/v1/tasks/{task_id}`（新增）

```json
{
  "task_id": "t-8f3a1c2d",
  "status": "done",                       // pending | running | done | failed
  "filename": "平安银行2022年报.pdf",
  "size_bytes": 4213877,
  "submitted_at": 1791888000.12,
  "started_at": 1791888001.03,
  "finished_at": 1791888004.51,
  "elapsed_ms": 3480.2,
  "pages": 312,
  "chars": 481233,
  "chunks_est": 942,
  "error": null
}
```
不存在 → `404`。失败任务 `status="failed"` 且 `error` 非空（例如「PDF 加密，无法解析」）。

### 2.4 `GET /api/v1/tasks`（新增）

```json
{"queue_depth": 0, "queue_max": 32, "workers": 2,
 "counts": {"pending":0,"running":0,"done":12,"failed":1},
 "tasks": [ ... 最近 20 条 ... ]}
```

### 2.5 `POST /api/v1/admin/unload`（新增）

仅允许 `127.0.0.1` / `::1` 调用（其他来源 `403`）。

```json
{"ok": true, "unloaded": ["qwen2.5:3b"], "keep_alive": "0s",
 "note": "已请求 Ollama 立即卸载；/api/ps 应随即为空"}
```

## 3. `/metrics` 新增指标（Prometheus 文本格式）

```
# 限流
rag_api_inflight                     gauge    当前在途请求数
rag_api_queued                       gauge    当前排队数
rag_api_rejected_total               counter  因过载被拒（429）总数
rag_api_inflight_peak                gauge    在途峰值

# 连接池
rag_http_pool_created_total          counter  新建连接数
rag_http_pool_reused_total           counter  复用连接数
rag_http_pool_idle                   gauge    空闲连接数

# 缓存
rag_answer_cache_entries             gauge    答案缓存条目数
rag_answer_cache_hits_total          counter  命中数
rag_answer_cache_evictions_total     counter  淘汰数

# 任务队列
rag_parse_queue_depth                gauge
rag_parse_tasks_total{status="done"} counter

# 单例
rag_singleton_probe_hits_total       counter
```

## 4. 向后兼容性

| 项 | 保证 |
| --- | --- |
| `POST /api/v1/ask` 请求/响应字段 | **逐位不变**（`AskResponse` 未改） |
| 既有端点 | 全部保留，路径与语义不变 |
| 默认行为 | `PERF_ENABLED=0` 时与工单10 完全一致（仅多出新增端点） |
| `service/config.py` 的 `DEPLOY_*` | 全部保留，新增 `PERF_*` 独立命名空间，不冲突 |
| 错误码 | 4xx/5xx 语义不变；**新增 429**（过载），仅当 `PERF_ENABLED=1` 时可能出现 |
