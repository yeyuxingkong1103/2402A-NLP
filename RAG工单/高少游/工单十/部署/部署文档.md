# 金融问答系统 · 部署文档

> **工单编号：人工智能 NLP-RAG-金融问答系统部署**
> 目标：将金融问答系统以 Docker 容器形式部署在服务器中并运行成功，提供金融场景对话服务。

本文档所有命令与输出均来自**真实运行**（构建日志、容器日志、验收脚本输出）。

---

## 一、环境要求

| 项 | 要求 | 本次实际环境 |
|---|---|---|
| Docker | 20.10+（含 Compose v2） | Docker Desktop（`desktop-linux` 引擎） |
| 内存 | ≥ 4 GB | 满足 |
| 磁盘 | ≥ 3 GB（镜像 + 卷） | 镜像 1.64 GB |
| 宿主 Ollama | 提供嵌入/LLM 模型 | `bge-m3:567m`、`bge-large:latest`、`nomic-embed-text:latest`、`deepseek-r1:1.5b` |
| 网络 | 容器经 `host.docker.internal` 访问宿主 Ollama | `--add-host host.docker.internal:host-gateway` |

> **镜像源说明**：本次构建环境可访问国内 PyPI 镜像（清华 TUNA），但**无法访问 Docker Hub 与 Debian apt 源**。
> 因此镜像设计上做了两点适配：
> ① 基础镜像 `python:3.10-slim` 已存在于本地，构建时直接复用，无需联网拉取；
> ② **容器内不执行 `apt-get`**，运行期依赖全部由 pip 从国内源安装，健康检查用标准库 `urllib` 实现，无需 `curl`。

## 二、交付文件

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 镜像定义（基础镜像 + 依赖 + 代码 + 知识库 + 健康检查 + 非 root） |
| `requirements.docker.txt` | 容器内运行依赖（精简版，不含 opencv / matplotlib） |
| `docker-compose.yml` | 编排：`finqa-app` / `finqa-kb-tool` / `finqa-rtmp` + 网络 + 卷 |
| `.dockerignore` | 构建上下文裁剪（排除缓存 / 产物 / 版本控制） |
| `deploy/build.sh` | 镜像构建脚本 |
| `deploy/run_container.sh` | `docker run` 启动脚本（网络 + 卷 + 环境变量） |
| `deploy/verify.sh` / `deploy/verify.ps1` | 容器管理验收脚本（Linux / Windows） |
| `deploy/smoke_test.py` | 容器内端到端问答冒烟测试 |
| `deploy/kb_tool.py` | 卷持久化 / 容器间共享 演示工具 |
| `deploy/rtmp_client.py` + `deploy/rtmp_server/` | RTMP 连通性验证客户端 + 自建对端服务镜像 |
| `deploy/healthcheck.sh` | 容器内健康检查脚本 |

## 四、启动服务

### 4.1 方式一：`docker run`（验收标准指定）

```bash
# 1) 自定义 bridge 网络
docker network create finqa-net

# 2) 命名卷（首次创建时自动播种镜像内置知识库）
docker volume create finqa_kb_vol
docker volume create finqa_data_vol
docker volume create finqa_out_vol

# 3) 启动容器
docker run -d --name finqa-app \
  --network finqa-net \
  -p 8501:8501 \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  -e EMBEDDING_MODEL_SLUG=bge-m3 \
  -e RETRIEVAL_STRATEGY=hybrid \
  -e TZ=Asia/Shanghai \
  --add-host host.docker.internal:host-gateway \
  -v finqa_kb_vol:/app/vector_db \
  -v finqa_data_vol:/app/data \
  -v finqa_out_vol:/app/output \
  --restart unless-stopped \
  finqa:1.0
```

### 4.2 方式二：`docker compose`

```bash
docker compose up -d                                    # 仅问答服务
docker compose --profile rtmp up -d                     # 追加 RTMP 对端服务
docker compose --profile tools run --rm finqa-kb-tool   # 容器间数据共享演示
docker compose down                                     # 停止（保留数据卷）
docker compose down -v                                  # 停止并删除数据卷
```

### 4.3 启动结果（真实）

```

## 六、容器管理验收逐项说明

### 6.1 容器启动与运行

- `docker run` 启动容器，`-p 8501:8501` 对外提供服务；
- `HEALTHCHECK` 探活 `/_stcore/health` 返回 `ok`，容器状态 `healthy`；
- `docker logs finqa-app` 无 `Traceback / Error / Exception`：

```
  You can now view your Streamlit app in your browser.
  Local URL: http://localhost:8501
  Network URL: http://172.18.0.2:8501
2026-10-08 15:03:32.183 Uvicorn server started on 0.0.0.0:8501
```

### 6.2 容器数据管理

**卷持久化**（写入 → 销毁容器 → 重建 → 读取）：

```
$ docker run --rm -v finqa_out_vol:/app/output finqa:1.0 python deploy/kb_tool.py write
[WRITE] 容器 ... 已向共享卷写入凭据 → /app/output/shared/writers.json
        卷上知识库: 8086 块 / 9 份文档 / chunks.jsonl=10914154B

$ docker rm -f finqa-app && docker run -d ... finqa:1.0      # 重建容器

$ docker run --rm -v finqa_out_vol:/app/output finqa:1.0 python deploy/kb_tool.py read
[READ] ... 发现 N 份写入凭据（来自其他容器）      ← 重建后数据仍在，未丢失
```

**容器间数据共享**（容器 A 写 → 容器 B 读同一命名卷）：

```
$ docker run --rm --hostname finqa-share-a -v finqa_kb_vol:/app/vector_db -v finqa_out_vol:/app/output \
    finqa:1.0 python deploy/kb_tool.py write
[WRITE] 容器 finqa-share-a 已向共享卷写入凭据
$ docker run --rm --hostname finqa-share-b ... finqa:1.0 python deploy/kb_tool.py read
[READ] 容器 finqa-share-b ... 发现写入凭据: finqa-share-a  ← B 读到了 A 写入的数据
```

```

## 八、常见问题（详见《实现步骤与问题记录》）

| 现象 | 原因 | 处置 |
|---|---|---|
| 容器内无 `curl`，健康检查失败 | 镜像不装 apt 包 | 健康检查改用 `python -c "urllib.request..."` |
| 容器无法访问 Ollama | 未注入宿主映射 | 启动加 `--add-host host.docker.internal:host-gateway` |
| 容器间共享测试读不到写入者 | `gethostname()` 返回容器 ID 而非名称 | 演示容器显式加 `--hostname` |
| 卷上知识库为空 | 卷在镜像目录为空时创建 | 镜像内置 `vector_db/`，首次创建卷时自动播种 |
