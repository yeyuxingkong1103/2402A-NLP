# 文档质量评估 Skill 优化方案文档

## 一、优化背景
知识库入库前，若不做质检直接解析，会遇到：扫描件当文字件解析得到空内容、重复文件污染索引、
不同版本文档冲突、敏感信息违规入库。本 Skill 用一次扫描输出全部风险清单与路由决策，
把"解析失败后补救"前置为"入库前分流"。

## 二、五大功能的关键优化

### 1. 格式分布统计
- 按可配置后缀白名单收集，不支持的文件单独入 `unsupported_files`，不静默丢弃。

### 2. PDF 页面类型识别（启发式分流）
- **逐页判断**（非整文件一次定性）：单页非空白字符数 < 阈值（默认100）为扫描页；
  扫描页占比 >70% 标 Scan_PDF，10%~70% 标 Hybrid_PDF，否则 Text_PDF。
- **置信依据透明**：输出扫描页占比，临界样本（60%~80%）自动进"待确认列表"。
- 明确标注为启发式，用于分流与 OCR 成本估算，不承诺严格正确。

### 3. 文档长度分布
- 线性插值分位数 P25/P50/P75/P90/P99；长度区间边界与标签全部配置化。

### 4. 重复检测（两层机制）
- **MD5**：分块流式计算，精确重复（确定结论，自动去重保留一份）。
- **SimHash（重点优化项）**：
  - 64 位指纹，numpy 向量化，处理 1700 份仅约 45 秒；
  - 特征采用 **4-gram**（解决 2-gram 下专利套话主导导致的 2 万+ 误报）；
  - 确定性多项式 hash（base=1009 > 255，跨进程可复现）；
  - 两两比较先做长度粗筛（长度差 >20% 跳过）；
  - 输出"待确认版本冲突列表"，含汉明距离与相似片段，**不自动删除**。

### 5. 敏感信息检测
- 手机号（含分隔符二次匹配）、邮箱、身份证（校验位验证降误报）默认开启；
  银行卡默认关闭（Luhn 校验，误报率高）。
- 从"只报统计数字"升级为"待审核列表"：每条含命中值（HTML 打码）、偏移量、上下文。

## 三、分类标签与路由
三维标签（格式 / 长度 / 风险）→ 唯一路由，优先级：
损坏审核 > 安全审核 > 版本审核 > 去重 > OCR > 混合解析 > 直接解析。
风险节点一律挂起，不自动放行。

## 四、工程优化
- **阈值全部配置化**（assessment_config.yaml），核心判断零硬编码；
- **损坏/权限异常隔离**：单文件失败只记录，不中断整体流程；
- **checkpoint 中断恢复**：每 50 个文件落盘，1700 份扫描中途可续跑；
- 进度反馈每 50 文件打印一次。

## 五、优化效果
| 指标 | 效果 |
| --- | --- |
| SimHash 误报 | 2-gram 21369 对 → 4-gram 20 对（约75%真实同族） |
| 手机号漏检 | 严格模式 0 条 → 分隔符兼容后 6 条全部检出 |
| 扫描件识别 | 622 份扫描件 100% 进入 OCR 路由，无误路由 |
| 全量耗时 | 1700 份 / 692 MB ≈ 45 秒 |

## 六、后续改进建议
1. SimHash 引入语料级 IDF 加权，进一步抑制跨文档高频通用片段；
2. 增加 PDF 图片占比、嵌入字体检测作为分流辅助证据；
3. 身份证/手机号对接企业 DLP 规则库；
4. 大规模场景下 simhash 改用 Milvus 向量索引做近邻搜索，避免 O(n²) 比较；
5. 质检报告支持增量模式（只评估新增/变更文件）。
