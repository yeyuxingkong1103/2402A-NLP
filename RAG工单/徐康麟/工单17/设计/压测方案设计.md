# 工单17 压测方案设计

工单编号：`人工智能NLP-RAG-解决API 服务并发瓶颈与资源泄漏工单`

---

## 1. 压测工具：为什么自研 `load_runner.py`

工单原文要求用 **jmeter**。本机 **未安装 jmeter**（`Get-Command jmeter` 无结果），
且 `_共享约定.md` 明令「不用 `pip install` 大包 / 不引入装不上的依赖」。

因此本工单自研 `研发/压测/load_runner.py`，**功能逐项对齐 jmeter 的 HTTP 压测能力**：

| jmeter 能力 | 本工具的对应实现 |
| --- | --- |
| Thread Group（并发用户数） | `--concurrency N` → `ThreadPoolExecutor(max_workers=N)` |
| Duration / Loop Count | `--duration S`（秒） |
| Timer（思考时间） | `--think-ms M`（每请求后随机 `[0.5M, 1.5M]` 停顿） |
| CSV Data Set Config | 场景内置问题池（工单2 的 6 个测试问题）+ `--questions` 指定 jsonl |
| HTTP Request Sampler | `urllib.request` POST `/api/v1/ask` |
| Aggregate Report（P50/P90/P95/P99/吞吐/失败率） | 跑完写 `summary.json` |
| Per-request results (JTL) | 每请求一行 JSON → `*.jsonl`（时间戳/延迟/状态码/是否失败） |
| Response Assertion | 非 200 或 `refused=true` 之外的结构异常分别记为 `failed` |
| **（新增）熔断** | 提交内存 >80% 或错误率 >50% → 立即停止并落盘 |

**并发上限硬约束**：`max_workers ≤ 20`（`--concurrency` 解析时钳制，超出直接报错退出），
遵守 `_共享约定.md §5.5` 与工单纪律。**禁止** `multiprocessing` / `ProcessPoolExecutor` /
`joblib` / `Pool(` —— 脚本内自检零命中。

## 2. 场景定义

配置集中在 `研发/压测/场景配置.json`（**阈值配置化**，不硬编码在代码里）。

### 场景 A：高频问答

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `concurrency` | 20 | 原文要求，**不缩减** |
| `duration_s` | 180（原文 600） | **缩减**，原因见 `需求分析.md §3` |
| `think_ms` | 200 | 模拟真实用户停顿时长 |
| 目标接口 | `POST /api/v1/ask` | 问答核心接口 |
| 载荷 | 工单2 的 6 个测试问题轮询 + `session_id` | 与原文「已入库文档的简单问题（如工单2 中问题1、2）」一致 |
| 验收 | **P95 ≤ 3000 ms，失败率 0** | 原文口径 |
| 内存 | 增长 ≤10%，无持续上涨趋势 | 每 5 s 采样 RSS/私有内存 |

### 场景 B：混合负载（5 问答 + 5 上传解析）

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `concurrency` | 10 | 原文要求 |
| 问答线程 | 5 | `POST /api/v1/ask` |
| 上传线程 | 5 | `POST /api/v1/uploads`（multipart PDF）+ 轮询 `GET /api/v1/tasks/{id}` |
| `duration_s` | 180（原文 600） | **缩减** |
| 上传语料 | `工单7/研发/data/raw/` 下的真实年报 PDF（只读引用，不复制） | |
| 验收 | 服务无崩溃；解析任务 `pending→running→done`；问答 **P95 ≤ 5000 ms** | 原文口径 |

### 缩减口径（**必须如实标注**）

| 项 | 原文 | 实测 | 原因 |
| --- | --- | --- | --- |
| 场景A/B 时长 | 600 s | **180 s** | 本机可用内存 4574 MB；API 进程实测 2.41~2.44 GB；`_共享约定.md §5.5` 事故红线 |
| soak | 12 h | **15 min** | 同上；12 h 增长指标改为**斜率外推 `[外推]`**，不标为实测 |

**并发数一律不缩减**（20 / 10 照原文），因为并发才是瓶颈的触发器；时长只影响统计样本量与长稳观察窗口，
缩减后仍在报告中明确写出。

## 3. 压测器命令行接口

```
python 研发/压测/load_runner.py \
    --scenario A|B \
    --concurrency N            # 1..20，超过报错
    --duration S               # 持续秒数
    --think-ms M               # 思考时间基准（毫秒）
    --base-url http://127.0.0.1:8200
    --questions 研发/压测/问题集.jsonl
    --outdir 测试/测试数据
    --tag 基准_优化前 | 优化后
    [--commit-limit-pct 80]    # 熔断：宿主提交内存占用百分比
    [--error-limit-pct 50]     # 熔断：错误率百分比
    [--no-circuit-breaker]     # 关闭熔断（仅用于调试）
```

## 4. 熔断与安全（**本工单风险最高的一环**）

`load_runner.py` 内置三重护栏：

1. **提交内存熔断**：每 2 s 用 `Get-Counter '\Memory\Committed Bytes','\Memory\Commit Limit'`
   之外，**优先用纯 Python 读 `psutil` 不可用时的替代** —— 实际实现为调用
   `powershell -NoProfile -Command "(Get-Counter ...)"`（子进程，超时 5 s，失败则跳过该轮而非崩）。
   占用 > `--commit-limit-pct`（默认 **80%**）→ 立即停止发射、等待在途请求结束、落盘 `summary.json`
   并标注 `circuit_breaker: "commit_memory"`。
2. **错误率熔断**：滚动窗口错误率 > `--error-limit-pct`（默认 **50%**）→ 同上。
3. **启动前置检查**：脚本启动时先探一次可用内存，`Available MBytes < 2500` 时直接拒绝启动并退出码 3。

外部再包一层 `_共享工具\安全跑.ps1`（`-PrivateLimitMB 3400`），由它兜底杀越线进程。

**绝不允许**：同时驻留 2 个 Ollama 模型；同时跑 1 个以上服务实例或压测器。

## 5. 指标定义与统计口径

| 指标 | 口径 |
| --- | --- |
| 延迟 | 客户端侧 `perf_counter` 墙钟，含建连 + 服务端处理 + 响应体读取 |
| P50/P90/P95/P99 | 线性插值分位（`statistics.quantiles` 不可用于任意分位，故自实现 `percentile(sorted, q)`） |
| 吞吐 RPS | `成功请求数 / 实际持续秒数`（实际持续秒数 = 首发时间 → 末收时间） |
| 失败率 | `(HTTP 非 200 数 + 超时数 + 连接错误数) / 总请求数` |
| 429（限流） | **计入失败**（原文「无请求失败」口径），同时在汇总里单列 `rate_limited` 计数 |
| 内存曲线 | 每 5 s 采样一次：`WorkingSet64`（≈RSS）、`PrivateMemorySize64`（私有内存，对应工单10 的 2.41 GB 口径） |
| 内存增长% | `(末 20% 窗口均值 - 首 20% 窗口均值) / 首 20% 窗口均值 × 100` |

## 7. 容错验证清单（对应任务书「容错」要求）

| 故障注入 | 期望行为 | 留痕 |
| --- | --- | --- |
| 服务未启动 | 压测器连接错误计数，前 5 次打印并**不刷屏**；汇总标 `服务不可达` | `*.jsonl` 中 `error=ConnectionRefused` |
| 端口被占用 | 起服务时 `uvicorn` 报 `WinError 10048`，脚本退出码非 0 并写日志 | `部署/日志/` |
| 请求超时 | 客户端 `--timeout` 到期记 `failed=true`，`error=Timeout` | jsonl |
| Ollama 不可达 | API 返回 502（`LLMProbeError`）或降级 extractive；`/health` 中 `llm.ok=false` + 原因 | `/health` JSON |
| 上传损坏 PDF | `POST /api/v1/uploads` 返回 400 + 明确原因；**任务不进队列、服务不崩** | 任务表记 `failed` + `reason` |
| 队列满 | 返回 **429** + `Retry-After`；不堆积 | 指标 `rag_api_rejected_total` |
