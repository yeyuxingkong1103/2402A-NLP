# 基于 RAG 的多角色扮演系统 - 设计文档

## 一、技术架构

### 1.1 整体架构

```
用户 → Streamlit 前端 → FastAPI 后端 → 统一 LLM 客户端（多方 Provider / 本地 vLLM、SGLang）
                             │
        ┌──────────┬─────────┼───────────┬──────────┐
        ↓          ↓         ↓           ↓          ↓
     Milvus      Redis     MySQL      MongoDB     Neo4j
   (向量+BM25) (短记忆/缓存) (角色/元数据) (长记忆/归档) (图谱,可选)
        ↑
  BGE-m3 + BGE-reranker
        ↑
  多引擎文档解析（PyMuPDF / pdfplumber / PaddleOCR / MinerU / 多模态）
```

### 1.2 技术选型

| 组件 | 技术 | 作用 |
|---|---|---|
| 前端 | Streamlit + Plotly | 对话、知识库管理、运维监控可视化 |
| 后端 | FastAPI | REST 接口、生命周期管理 |
| 大模型 | OpenAI 兼容客户端 | 多 Provider 切换、本地部署 |
| 向量化 | BGE-m3 | 文本向量化（1024 维） |
| 重排序 | BGE-reranker | 检索结果精排 |
| 向量库 | Milvus 2.5+ | 向量 + 原生 BM25 混合检索 |
| 缓存/短记忆 | Redis | List/Hash/Set/ZSet/String |
| 角色/元数据 | MySQL | 角色、用户、文档、会话 |
| 长记忆/归档 | MongoDB | 摘要、原文归档 |
| RAG 框架 | LangChain / LlamaIndex | 可切换引擎 |

## 二、模块设计

### 2.1 配置与日志（app/config.py, app/logging_conf.py）

- 使用 pydantic-settings 读取 `.env`，支持 `APP_ENV=dev|test|prod`
- 所有密钥、连接串集中管理，代码零硬编码
- 统一 logging：控制台 + 滚动文件，按环境分级

### 2.2 数据层（app/db/）

| 模块 | 职责 |
|---|---|
| `milvus_store.py` | collection schema：id/vector/sparse(BM25)/text/parent/summary/source/domain/doc_id/chunk_type/parser/create_time/update_time |
| `redis_store.py` | 短期记忆（List）、会话元数据（Hash）、会话集合（Set）、热问题（ZSet）、缓存（String） |
| `mysql_store.py` | roles / users / kb_docs / sessions 建表与种子 |
| `mongo_store.py` | documents（原文归档）、memory（长期记忆摘要） |
| `neo4j_store.py` | 图谱检索（可选，默认关闭） |

### 2.3 离线入库（app/ingest/）

1. 解析：`parsers.py` 提供 PyMuPDF / pdfplumber / PaddleOCR / MinerU / 多模态解析器，
   `detect_parser` 按文本层密度自动选择
2. 清洗：`clean.py` 去水印、归一化、低质量过滤、去重
3. 分块：`chunker.py` 五种策略 + 父子块
4. 增强：`pipeline.py` LLM 摘要、假设问题生成（可开关）
5. 向量化：BGE-m3
6. 入库：Milvus + MongoDB 归档 + MySQL 元数据

### 2.4 在线问答（app/rag/）

1. `query_rewrite.py`：查询改写 / 扩写，生成多查询
2. `retriever.py`：混合检索 + 多路召回 + RRF 融合 + 阈值过滤 + 去重
3. `rerank.py`：BGE-reranker 精排
4. `prompt.py`：角色系统提示词 + 上下文拼装（优先父块）
5. `generator.py`：LLM 生成（同步 / 流式）
6. `postprocess.py`：正则清洗 + 法条引用校验
7. `pipeline.py`：编排 `answer` / `answer_stream`

### 2.5 多角色（app/roles/presets.py）

- 10 个代表性角色，字段：id、role_name、domain、description、opening、system_prompt
- domain 与知识库域绑定，检索时做标量过滤

### 2.6 框架集成（app/frameworks/）

- `langchain_chain.py`：六要素落地（Models/Prompts/Chains/Memory/Indexes/Agents）
- `llamaindex_pipeline.py`：SentenceSplitter 分块 + 自定义检索器
- 通过 `RAG_ENGINE` 切换，失败自动回退 native

## 三、数据模型

### 3.1 Milvus collection（rag_knowledge）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INT64 | 主键，自增 |
| vector | FLOAT_VECTOR(1024) | BGE-m3 向量 |
| sparse | SPARSE_FLOAT_VECTOR | BM25 稀疏向量（由 text 生成） |
| text | VARCHAR | 原文 |
| parent | VARCHAR | 父块原文（父子块） |
| summary | VARCHAR | 摘要 |
| source | VARCHAR | 文档来源 |
| domain | VARCHAR | 知识域 |
| doc_id | VARCHAR | 文档 ID |
| chunk_type | VARCHAR | 分块类型 |
| parser | VARCHAR | 解析引擎 |
| create_time / update_time | VARCHAR | 时间戳 |

### 3.2 MySQL

- `roles(id, role_name, domain, description, opening, system_prompt, created_at)`
- `users(user_id, nickname, created_at)`
- `kb_docs(doc_id, filename, domain, parser, chunks, created_at, updated_at)`
- `sessions(user_id, role_id, turns, updated_at)`

### 3.3 Redis 键设计

| 键 | 类型 | 用途 |
|---|---|---|
| `chat:{uid}:{rid}` | List | 短期记忆 |
| `session:{uid}:{rid}` | Hash | 会话元数据 |
| `sessions:{uid}` | Set | 用户会话索引 |
| `hot:queries` | ZSet | 热问题排行 |
| `cache:query:{q}` | String | 检索缓存 |

## 五、RAG 优化

- 混合检索（向量 + BM25）、多路召回、RRF 融合
- 重排序（BGE-reranker）+ 相似度阈值过滤
- 查询改写 / 扩写
- 分块优化（五种策略 + 父子块）
- 数据优化（清洗、去水印、去重、低质量过滤）
- 知识库数据增强（摘要、假设问题）
- 后处理与引用校验
- 短期记忆 + 长期记忆摘要
- 流式输出

## 六、可视化（运维监控）

- Redis：键总数、内存、命中率、键类型分布、键浏览器、热问题 TopN
- Milvus：实体总数、域分布、实体分页浏览、检索预览
- 前端通过 `/ops/*` 接口取数，Plotly 绘图

## 七、部署方案

- 环境：WSL2 + Ubuntu（亦支持算力云 / 腾讯云 / 阿里云）
- 安装脚本 `scripts/install.sh`：系统检查 → 基础服务 → Python 环境 → 依赖 → 配置
- 启动脚本 `scripts/run.sh`、停止脚本 `scripts/shutdown.sh`
- 多环境：`APP_ENV` 与 `.env` 区分开发 / 测试 / 生产
