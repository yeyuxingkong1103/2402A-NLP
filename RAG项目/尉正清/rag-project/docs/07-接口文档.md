# 接口文档

## 1. 通用约定

| 项 | 值 |
|---|---|
| Base URL | `http://<host>:8000` |
| 编码 | UTF-8，请求与响应均为 `application/json` |
| 交互式文档 | `GET /docs`（Swagger UI）、`GET /openapi.json` |
| 文件上传 | `POST` 使用 `multipart/form-data` |

### 1.1 统一响应格式

除流式接口与 `/docs` 外，所有接口返回同一结构：

```json
{ "code": 200, "msg": "ok", "data": { } }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 200 成功；其余为失败 |
| `msg` | string | 提示信息，成功时为 `ok` |
| `data` | object / array / null | 业务数据，失败时可能为 `null` |

### 1.2 错误码

| HTTP | 场景 | 示例 detail |
|---|---|---|
| 400 | 参数非法或角色不存在 | `角色不存在: xxx` |
| 401 | 用户名或密码错误 | `用户名或密码错误` |
| 403 | 会话不属于当前用户 / 账号停用 | `会话不属于当前用户` |
| 404 | 资源不存在 | `会话不存在` |
| 422 | 请求体未通过 Pydantic 校验 | FastAPI 自动生成 |
| 500 | 服务内部错误 | `服务内部错误: ...` |

## 2. 问答

### 2.1 POST /api/chat/ask

角色扮演问答。完整链路：双层记忆 → 追问改写 → 查询扩写 → 多路召回 → RRF 融合 → 精排 → 生成。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question` | string | 是 | 用户问题，最短 1 字符 |
| `role_key` | string | 是 | `lawyer` / `psychologist` / `financial_advisor` |
| `user_id` | int | 否 | 用户 ID，默认 1 |
| `session_id` | string | 否 | 不传则新建会话；传入则延续该会话 |

```bash
curl -X POST http://127.0.0.1:8000/api/chat/ask \
  -H 'Content-Type: application/json' \
  -d '{"question":"酒驾撞人要判多久？","role_key":"lawyer","user_id":1}'
```

**响应**

```json
{
  "code": 200,
  "msg": "ok",
  "data": {
    "answer": "……（含角色免责声明）",
    "session_id": "efbfef7801304bc08c71ac1165e3d50a",
    "role": { "role_key": "lawyer", "name": "李律师", "category": "法律" },
    "search_query": "酒驾撞人要判多久？",
    "sources": [
      { "title": "《中华人民共和国刑法》第一百三十三条", "source": "legal_statutes.jsonl",
        "doc_type": "statute", "score": 3.79 }
    ]
  }
}
```

| 字段 | 说明 |
|---|---|
| `answer` | 回答正文，末尾自动追加该角色的免责声明 |
| `session_id` | 会话 ID，后续请求带上即可延续多轮 |
| `search_query` | 实际用于检索的问题（追问被改写后的结果） |
| `sources` | 命中的知识来源，含标题、来源文件与精排分数 |

### 2.2 POST /api/chat/stream

同上，但以 SSE 流式返回。事件类型：

| type | 内容 |
|---|---|
| `meta` | 会话 ID、角色、检索用的 query、命中的来源 |
| `delta` | 回答正文增量片段 |
| `done` | 结束，带 `session_id` |
| `error` | 异常信息 |

```bash
curl -N -X POST http://127.0.0.1:8000/api/chat/stream \
  -H 'Content-Type: application/json' \
  -d '{"question":"盗窃罪怎么判？","role_key":"lawyer","user_id":1}'
```

```
data: {"type":"meta","session_id":"...","sources":[...]}
data: {"type":"delta","content":"盗窃公私财物"}
data: {"type":"delta","content":"，数额较大的……"}
data: {"type":"done","session_id":"..."}
```

## 3. 角色

### 3.1 GET /api/roles

返回启用状态的角色列表。

```json
{ "code": 200, "msg": "ok", "data": [
  { "role_key": "lawyer", "name": "李律师", "category": "法律",
    "description": "严谨的中国执业律师……", "greeting": "您好，我是李律师……",
    "avatar": "", "sort_order": 1, "status": true } ] }
```

### 3.2 GET /api/roles/{role_key}

角色详情，额外返回**人设提示词**等配置字段：`persona`、`rules`、`fallback`、`disclaimer`、`collection`。角色不存在返回 404。

### 3.3 GET /api/roles/hot?k=10

角色热度排行（Redis zSet 按提问次数计分）。

```json
{ "code": 200, "msg": "ok", "data": [ { "role_key": "lawyer", "score": 12.0 } ] }
```

## 4. 会话

### 4.1 GET /api/sessions?user_id=1&role_key=lawyer&limit=50

会话列表，按更新时间倒序。

```json
{ "code": 200, "msg": "ok", "data": [
  { "session_id": "43ea62fe...", "role_key": "lawyer", "title": "酒驾撞人要判多久？",
    "turn_count": 2, "created_at": "2026-09-16 08:53:25",
    "updated_at": "2026-09-16 08:53:47" } ] }
```

### 4.2 GET /api/sessions/{session_id}/messages?limit=100

会话历史消息，按时间正序。`sources` 为该轮命中的知识来源（JSON 字符串）。

```json
{ "code": 200, "msg": "ok", "data": {
  "session": { "session_id": "...", "turn_count": 2 },
  "messages": [
    { "role": "user", "content": "酒驾撞人要判多久？", "sources": null, "created_at": "..." },
    { "role": "assistant", "content": "……", "sources": "[{\"title\":\"《中华人民共和国刑法》第一百三十三条\"}]", "created_at": "..." } ] } }
```

### 4.3 GET /api/sessions/{session_id}/memory?user_id=1&role_key=lawyer

查看该会话的双层记忆，用于调试。

```json
{ "code": 200, "msg": "ok", "data": {
  "short_term": ["用户：酒驾撞人要判多久？", "助手：## 一、先厘清一个前提……"],
  "long_term": { "long_term_count": 2 } } }
```

### 4.4 DELETE /api/sessions/{session_id}

删除会话及其全部消息。不存在返回 404。

## 5. 用户

### 5.1 POST /api/users/register

| 字段 | 类型 | 约束 |
|---|---|---|
| `username` | string | 2–64 字符，唯一 |
| `password` | string | 6–64 字符，PBKDF2-HMAC-SHA256 加盐存储 |
| `nickname` | string | 可选，默认取用户名 |

用户名重复返回 400。

### 5.2 POST /api/users/login

```json
// 请求
{ "username": "demo", "password": "demo123" }
// 响应
{ "code": 200, "msg": "登录成功", "data": { "id": 1, "username": "demo",
  "nickname": "演示用户", "status": true } }
```

密码错误返回 401，账号停用返回 403。当前返回用户信息而不签发 token，
若要对公网暴露需在此接入 JWT。

### 5.3 GET /api/users/{user_id}

查询用户，不存在返回 404。

## 6. 知识入库

### 6.1 POST /api/ingest/dataset

把 `data/{role_key}/` 下的全部 JSONL 灌入 Milvus。

```json
{ "role_key": "lawyer", "force": false }
```

`force=true` 会先清空该角色的旧知识再重建。响应含各文件的 `records` 与 `chunks` 明细。

### 6.2 POST /api/ingest/upload

上传文档入库。PDF 先去水印（PyMuPDF redaction），再交给 MinerU 解析为 Markdown；
MinerU 不可用或解析失败时自动退回三件套兜底（PyMuPDF 文本层 + PaddleOCR 图表文字
+ pdfplumber 表格），接口不报错。

| 参数 | 位置 | 说明 |
|---|---|---|
| `file` | form-data | 文件，仅支持 `.pdf` / `.txt` / `.md` |
| `role_key` | form-data | 目标角色 |
| `remove_watermark` | form-data | 是否去水印，默认 `true` |
| `use_ocr` | form-data | 默认 `true`。**只作用于兜底路径**：走 MinerU 时它自带 OCR 且无法单独关闭，该参数被忽略并记一条 note |
| `use_tables` | form-data | 默认 `true`。同上，只在兜底路径下生效 |

```json
{ "code": 200, "msg": "入库完成", "data": {
  "filename": "wm_sample.pdf", "pages": 1, "chunks": 6,
  "watermark": { "text_removed": 6, "image_removed": 6,
                 "text_samples": ["内部资料 严禁外传"],
                 "path": "mineru",
                 "mineru": { "tier": "basic", "raw_chars": 7100000,
                             "text_chars": 15174, "images_dropped": 25 },
                 "ocr_scanned": 0, "ocr_pages": 0, "ocr_lines": 0,
                 "table_pages": 0, "table_count": 0,
                 "notes": [] } } }
```

| 字段 | 说明 |
|---|---|
| `pages` | 记录条数。MinerU 产出**整篇 Markdown**，因此走主路径时恒为 `1`；走兜底路径时等于 PDF 页数 |
| `watermark.path` | 实际走的解析路径：`mineru`（主）或 `pymupdf`（兜底） |
| `watermark.mineru` | MinerU 统计：档位、剥图前字符数、剥图后字符数、剥掉的内嵌图张数；走兜底路径时为空对象 |
| `watermark.ocr_scanned` / `ocr_pages` / `ocr_lines` | 兜底路径下 OCR 的产出：实际跑过 OCR 的页数 / 其中贡献了内容的页数 / 补充的文本行数。**走 MinerU 时恒为 0**——OCR 由 MinerU 内部完成，这一层统计不到 |
| `watermark.table_pages` / `table_count` | 兜底路径下 pdfplumber 提取到的表格页数与表格个数，同样**只在兜底路径下有值** |
| `watermark.notes` | 备注，如「MinerU 未安装，走兜底三件套」「MinerU 解析失败，已转兜底路径：…」「OCR 不可用，仅提取文本层」「MinerU 自带 OCR 与表格识别，use_ocr/use_tables 在主路径下不生效」 |

## 7. 知识更新

### 7.1 POST /api/update/document

按文件内容哈希判断是否需要重建，内容未变则跳过。变更时执行「先删后增」。

```json
{ "file_path": "/root/rag-project/data/lawyer/legal_qa.jsonl",
  "role_key": "lawyer", "force": false }
```

```json
{ "code": 200, "msg": "文件未变更，无需更新",
  "data": { "source": "legal_qa.jsonl", "changed": false } }
```

### 7.2 POST /api/update/dataset/{role_key}?force=false

批量更新某角色目录下的全部数据集，返回变更文件数与明细。

### 7.3 DELETE /api/update/document

按文件名删除某角色下的全部知识。删不存在的来源不报错（磁盘与向量库状态可能不同步）。

```json
{ "source": "legal_qa.jsonl", "role_key": "lawyer" }
```

## 8. 系统

### 8.1 GET /api/health

各依赖健康状态，任一不可用时 `msg` 变为「存在不可用依赖」。

```json
{ "code": 200, "msg": "ok", "data": {
  "mysql": true, "redis": true, "milvus": true,
  "llm": true, "llm_model": "deepseek-flash" } }
```

### 8.2 GET /api/stats?refresh=false

知识库与业务统计。结果用 Redis String 缓存 30 秒，刚入库完想看最新数字加 `refresh=true`。

```json
{ "code": 200, "msg": "ok (cached)", "data": {
  "collections": { "rag_knowledge": 13364, "long_term_memory": 0 },
  "knowledge_per_role": { "lawyer": 4555, "psychologist": 4675, "financial_advisor": 4134 },
  "ingested_sources": { "lawyer": ["legal_articles.jsonl", "legal_statutes.jsonl", "..."] },
  "users": 1, "roles": 3, "sessions": 12, "messages": 30 } }
```

### 8.3 GET /

服务概览，返回名称、版本、模型与主要接口清单。
