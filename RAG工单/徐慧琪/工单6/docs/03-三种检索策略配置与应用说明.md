# 三种检索策略的配置与应用说明（工单06 核心）

**工单编号**：人工智能NLP-RAG-混合检索任务

---

## 0. 一句话总览

| 策略 | 一句话 | 什么时候用 | 精排 |
| --- | --- | --- | --- |
| `vector` 向量检索 | 语义相似召回，问法不同也能命中 | 问题与原文措辞差异大（"钱花在哪了" vs "募集资金投资项目"） | 召回后 **Reranker 精排** |
| `fulltext` 全文检索 | 关键词精确命中，支持布尔/短语/模糊 | 查专名、编号、标准名、精确数字组合 | 默认也过精排（可关） |
| `hybrid` 混合检索（推荐） | 两路召回融合后再精排 | 默认；兼顾语义与精确匹配 | **必经 Reranker 精排** |

## 1. 向量检索（召回 + Reranker 重排）

**链路**：Query → bge-m3 向量 → Qdrant 余弦召回 `top_k_recall` 条 → **Reranker 模型**逐对打分 → `top_k_rerank` 条

**配置项**（界面「🔀 检索策略」页 / `src/config.py` / `RetrievalConfig`）：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `embedding_model` | `bge-m3` | 可切 `bge-m3-ft-v1`、`miniLM-L6`（**先建对应库**：`python build_index.py --embedding-model <名>`） |
| `top_k_recall` | 20 | 召回候选数（宽召回 2× 后截断到该值进精排） |
| `top_k_rerank` | 5 | 精排后返回数 |
| `score_threshold` | 0.0 | 精排分数阈值，低于该值不返回（0=不启用） |
| `reranker_model` | `bge-reranker-v2-m3` | 三选一：v2-m3 / v2-m3-ms / **bge-reranker-base** |
| `rerank_enabled` | True | 关闭=纯召回序截断（**仅用于消融对比**，生产不建议） |

```python
from src import strategies
cfg = strategies.RetrievalConfig(strategy="vector", top_k_recall=20, top_k_rerank=5,
                                 reranker_model="bge-reranker-base", score_threshold=0.3)
res = strategies.retrieve("武汉兴图新科电子股份有限公司注册资本是多少？", cfg)
res["hits"]     # 精排后的 5 条（含 rerank_score / 页码 / block_type / 引用 ID）
res["info"]     # 召回候选数、召回/精排耗时、精排前后名次变化
```

## 2. 全文检索（自研倒排索引）

**链路**：Query → 语法解析 → 倒排表求交/并/差 → 短语位置校验 → BM25 多字段打分 → 精排（默认开）

### 2.1 查询语法（界面「检索策略」页有语法演示区）

| 能力 | 写法 | 例子 |
| --- | --- | --- |
| 普通词 | 空格分隔（默认 OR，命中词多者分高） | `注册资本 法定代表人` |
| **布尔 AND** | `A AND B`（也接受中文「与」、`+A`） | `注册资本 AND 5,520` |
| **布尔 OR** | `A OR B`（中文「或」） | `注册资本 OR 赵马克` |
| **布尔 NOT** | `NOT A`（中文「非」、`-A`） | `发行 NOT 注册资本` |
| 括号分组 | `(A OR B) AND C` | `(武汉博润 OR 上海博润) AND 关联方` |
| **短语匹配** | `"完整短语"`（词序相邻才算命中） | `"存在控制关系的关联方"` |
| **模糊匹配** | `词~` 或 `词~1`（编辑距离 ≤1） | `注册资木~` → 命中 `注册资本` |
| **多字段** | `title:` / `body:` / `summary:` | `title:组织结构图`、`summary:持股比例` |

### 2.2 多字段定义

| 字段 | 内容 | 权重 |
| --- | --- | --- |
| `title` 标题 | 章节标题路径 + 表格标题 + 组织图节点名 | 2.5 |
| `body` 正文 | 块正文 | 1.0 |
| `summary` 摘要 | 表格列表头 / 父块前 160 字 | 1.2 |

### 2.3 应用建议

* **精确事实题**（"参与制定了哪个技术标准"）：`"视频指挥系统技术规范"` 这类短语查询最稳；
* **专名/数字组合**（"注册资本是多少"）：`注册资本 AND 5,520` 一次锁定；
* 全文检索**不需要向量模型**，冷启动只需构建倒排索引（约 8s，已持久化为 23MB pkl），
  在无 GPU 环境下是**唯一可用**的检索策略。

## 3. 混合检索（推荐）

**链路**：向量 recall ∥ 全文 recall → **融合**（RRF / 加权平均 / 投票）→ 截断到 `top_k_recall` → **Reranker 精排** → `top_k_rerank`

### 3.1 融合算法（三种都可选，实测对比见 `docs/04`）

| 算法 | 公式 | 特点 | 适用 |
| --- | --- | --- | --- |
| **RRF**（默认） | `score(d)=Σ w_r/(k+rank_r(d))`，k=60 | 只用名次，规避余弦分/BM25 分量纲不可比 | 通用默认；上游 01~05 的验证口径 |
| 加权平均 | `Σ w_r·norm(score_r)` | 保留"遥遥领先"与"险胜"的差别 | 确信某一路分数质量更高时 |
| 投票(Borda) | 第 i 名得 `N-i+1` 票，按权重加总 | 抗单路异常分，可解释性强 | 一路存在离群高分噪声时 |

### 3.2 权重调整（重要，含实测教训）

权重默认 **0.5 / 0.5**（等权）。调整方式与语义：

* `rrf`/`vote`：按**最大值归一**。设 0.7/0.35 → 向量臂满权重、全文臂半权重；
  某路设 0 → 该路**整体不参与**（不贡献分，也不把只在它里面的文档带进结果）。
* `weighted`：按**和为 1** 归一（凸组合语义）。

> **实测教训**：若 rrf 也按"和为 1"归一，会系统性压制少数臂 ——
> id1「发行股数」的正确答案是全文臂第 1 名（0.4/61=0.0066），
> 却输给向量臂第 15 名（0.6/75=0.0080），**正确答案进不了候选**。
> 修正为 max 归一后，默认等权即退化为上游验证过的无权重 RRF。

### 3.3 配置示例

```python
from src import runtime, strategies

# 方式一：运行时设置（界面用这套，改完下一次提问立即生效）
runtime.update(strategy="hybrid", fusion="rrf",
               vector_weight=0.5, fulltext_weight=0.5,
               top_k_recall=20, top_k_rerank=5,
               reranker_model="bge-reranker-v2-m3",
               rerank_algorithm="model")

# 方式二：显式传参（评估脚本/测试用，优先级更高）
cfg = strategies.RetrievalConfig(strategy="hybrid", fusion="weighted",
                                 vector_weight=0.7, fulltext_weight=0.3)
```

### 3.4 精排算法 4 选 1（工单要求 ≥3 种重排算法）

| 算法 | 是否生产 | 说明 |
| --- | --- | --- |
| `model` | ✅ 默认 | 真实 Cross-Encoder Reranker 模型推理（3 个模型可切） |
| `llm` | 对比基线 | Ollama qwen2.5:3b 逐条 0~10 相关性打分（4 路并发，8s 预算，超时保序） |
| `tfidf` | 对比基线 | TF-IDF 余弦（无模型依赖，最快） |
| `adaptive` | 对比基线 | 用户反馈自适应：直接票数 + 相似问题反馈迁移（界面 👍/👎 即写入反馈库） |

## 4. 界面操作路径（中英双语）

1. 侧栏切换 `中文 / English`；
2. 打开 **🔀 检索策略 / Retrieval Strategy** 页；
3. 「当前生效配置」区：选策略 → 拖 Top-K/阈值 → 拖两路权重 → 选融合算法 →
   选精排算法与 Reranker 模型 → 选嵌入模型 → 点**应用配置**；
4. 下方输入问题，点 **执行检索**（单策略细看）或 **三种策略并排对比**（一键对比）；
5. 结果区逐条显示：来源 PDF/页码、block_type、**表格ID/图像ID/组织图路径**、
   各阶段分数（rerank/fused/vec/fulltext），图像命中会直接**渲染原图**；
6. 观测条显示：召回通路、候选数、召回/融合/精排耗时、精排前后名次变化数、降级状态。

## 5. 常见问题

| 问题 | 处置 |
| --- | --- |
| 切了嵌入模型后检索为空 | 该模型还没建库。跑 `python build_index.py --embedding-model <名>`（不同模型=不同 collection） |
| 全文检索查不到某个数字 | 确认写法：`5,520` 与 `5,520.00` 已做口径归一可互查；若仍不通，加模糊 `5,520~` |
| 精排显示"已降级" | 见 `docs/07` 运维速查（显存不足会自动转 CPU，权重缺失换模型） |
| 想复现论文口径的三方对比 | `python evaluate_retrieval.py --strategies hybrid,vector,fulltext`（报告落 `docs/04`） |
