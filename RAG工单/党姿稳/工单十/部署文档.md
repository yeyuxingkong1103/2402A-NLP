## 四、部署步骤

### 方式一：docker compose 一键部署（推荐）

```bash
cd "C:\Users\dang5\Desktop\工单十"

# 1. 构建镜像并启动全部服务（问答服务 + RTMP 服务）
docker compose up -d

# 2. 查看服务状态（等待健康检查变为 healthy）
docker compose ps

# 3. 跟踪问答服务日志（首次启动需构建索引，CPU 上约 7 分钟）
docker compose logs -f rag-api
```

说明：`docker-compose.yml` 已通过顶层 `name: rag-finance` 显式声明项目名。
本目录名为中文，compose 从目录名推导项目名时会得到空串并报
`project name must not be empty`，显式声明可避免该问题。

### 方式二：docker run 手动部署

```bash
# 1. 构建镜像
cd "C:\Users\dang5\Desktop\工单十"
docker build -t rag-finance-qa:1.0.0 .

# 2. 创建数据卷
docker volume create rag-data
docker volume create rag-logs

# 3. 启动容器（指定端口 8000 对外提供服务）
docker run -d \
  --name rag-finance-api \
  -p 8000:8000 \
  -e DEEPSEEK_API_KEY=sk-REDACTED \
  -e EMBED_ENABLED=true \
  -e EMBED_MODEL_PATH=/models/m3e-base \
  -v rag-data:/app/data \
  -v rag-logs:/app/logs \
  -v "C:/Users/dang5/Desktop/zongwenjianjia/zhuangao4/m3e-base:/models/m3e-base:ro" \
  rag-finance-qa:1.0.0

# 4. 等待就绪并验证
curl http://127.0.0.1:8000/health
```

> 若在 WSL 中调用 Linux 版 `docker` CLI，挂载模型时需把 Windows 路径改写为
> `/mnt/c/Users/dang5/Desktop/zongwenjianjia/zhuangao4/m3e-base`
> （Linux 版 CLI 无法识别 `C:/...` 形式的路径）。使用 `docker.exe` 则直接用 Windows 路径。

### 关键环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 内置默认值 | 大模型密钥，生产环境务必用环境变量注入 |
| `EMBED_ENABLED` | `true` | 是否启用向量检索；模型未挂载时置 `false` 自动降级为纯 BM25 |

| `RAG_LOG_DIR` | `/app/logs` | 日志目录（挂载卷） |
| `RAG_CORPUS_DIR` | `/app/corpus` | 语料目录 |
| `SERVICE_PORT` | `8000` | 服务监听端口 |
| `FINAL_TOP_K` | `5` | 送入大模型的上下文条数 |

## 五、接口说明

服务地址：`http://127.0.0.1:8000`（容器内 `http://0.0.0.0:8000`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查，返回 `{"status":"ok","ready":true,"version":"1.0.0"}` |
| GET | `/stats` | 运行统计：块数、来源数、向量开关、检索词数、历史问答数、索引构建耗时 |
| POST | `/ask` | 检索增强问答，返回答案、上下文来源与分阶段耗时 |
| POST | `/retrieve` | 仅检索不调用大模型，便于压测检索性能 |

请求示例：

```bash
# 问答
curl -X POST http://127.0.0.1:8000/ask \
  -H 'Content-Type: application/json' \
  -d '{"question":"平安银行2019年的不良贷款率是多少？","mode":"hybrid"}'

# 检索（mode 可为 hybrid / bm25 / vector）
curl -X POST http://127.0.0.1:8000/retrieve \
  -H 'Content-Type: application/json' \
  -d '{"question":"逾期60天以上贷款偏离度","mode":"hybrid","top_k":5}'
```

实际返回示例（2026-10-12 实测）：

```json
{
  "question": "平安银行2019年的不良贷款率是多少？",
  "answer": "平安银行2019年的不良贷款率为1.65%【资料1】【资料4】。",
  "mode": "hybrid",
  "retrieve_seconds": 0.1711,
  "generate_seconds": 1.8596
}
```

交互式接口文档：服务启动后访问 `http://127.0.0.1:8000/docs`（Swagger UI）。

## 七、运维操作

```bash
# 查看服务状态
docker compose ps

# 实时查看日志
docker compose logs -f rag-api

# 查看镜像体积
docker images rag-finance-qa:1.0.0

# 停止服务（保留数据卷）
docker compose stop

# 停止并删除容器与网络（保留数据卷，数据不丢）
docker compose down

# 停止并删除容器、网络与数据卷（会清空索引缓存）
docker compose down -v

# 仅重建问答服务
docker compose up -d --force-recreate rag-api
```

数据卷说明：

| 卷名 | 挂载点 | 用途 |
| --- | --- | --- |
| `rag-finance_rag-data` | `/app/data` | 索引缓存（`chunks.json`、`bm25.pkl`、`vectors.npz`）与问答历史 |
| `rag-finance_rag-logs` | `/app/logs` | 服务日志文件 |
| `rag-finance_rag-shared` | `/app/shared`、`/shared` | 问答服务与 RTMP 服务之间的共享数据目录 |

索引为一次性构建、长期复用：首次启动约 7 分钟（CPU 编码 1533 个块），
之后每次启动直接从卷内缓存加载，实测 `build_seconds` 为 0.11 秒。
更新语料后需执行 `docker compose down -v` 清空缓存再启动。

## 八、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `project name must not be empty` | 目录名为中文，compose 推导项目名得到空串 | 已通过 compose 文件顶层 `name: rag-finance` 解决；也可加 `-p rag-finance` |
| `invalid volume specification: 'C:/Users/...'` | 在 WSL 中用 Linux 版 `docker` CLI，无法识别 Windows 路径 | 改用 `docker.exe`，或把 `MODEL_DIR` 设为 `/mnt/c/...` |
| 构建时下载 797 MB 的 torch | `requirements.txt` 中 torch 未锁定 `+cpu` 本地版本，`sentence-transformers` 的 `torch>=1.11.0` 失去约束 | 已锁定 `torch==2.4.1+cpu`，并用 `--find-links /wheels` 指向预下载的 CPU wheel |
| 启动后 `/health` 长时间 `ready:false` | 首次启动正在构建索引（CPU 约 7 分钟） | 等待即可；`/stats` 的 `build_seconds` 可查看进度。健康检查已设置 `start-period=600s` |
| 容器 `unhealthy` | 索引构建耗时超过健康检查宽限期 | 已把 `start-period` 设为 600 秒（须大于冷启动建索引耗时，实测约 440 秒）；语料更大时按比例调大 |
| `/ask` 返回"生成服务暂时不可用" | 容器内无法访问 DeepSeek 或密钥无效 | 检查容器网络出网情况与 `DEEPSEEK_API_KEY` |
| 端口 8000 被占用 | 宿主机已有服务占用 | 修改 compose 中 `ports` 的宿主机侧端口，如 `"8001:8000"` |
| 8080 端口冲突 | RTMP 服务的 HTTP 状态页端口被占用 | 修改 compose 中 rtmp-server 的 `"8080:80"` 宿主机侧端口 |
