## 一、响应时间优化（**收益最大的一项**）

### 现象
工单8 冻结结果（`工单8/测试/测试数据/GraphRAG评估汇总.json`）：

| 分段 | 平均耗时 | 占比 |
| --- | ---: | ---: |
| 检索 | 128.21 ms | 3.1% |
| 图谱扩展 | 4.68 ms | 0.1% |
| **生成** | **3946.94 ms** | **96.7%** |
| 端到端 | 4080.41 ms | 100% |
| SLA ≤3000 ms 达标率 | **29.41%** | — |

### 根因
**每一题都要调用一次 3B 模型（qwen2.5:3b）做「润色」**。
即使工单8 已经有「确定性草稿」这一层，它仍然把草稿 + 证据交给模型改写，
而 3B 模型在 CPU 上的推理时间就是 3~5 s —— SLA 预算被一次性吃光。

### 方案（`研发/app/graphrag_opt/生成层.py`）
1. **模板化落地生成（快路径）**：当确定性草稿满足
   「长度 ≥ `template_min_chars` ∧ 含 ≥ `template_min_numeric` 个数值原子 ∧ 覆盖 ≥1 个问句实词」
   时，**直接用「结论 + 关键数据 + 图谱依据 + 引用」组装答案，跳过 LLM** —— 生成耗时 ≈ **0 ms**。
2. **LLM 慢路径预算压缩**（仅在快路径不置信时启用）：
   `num_ctx` 2048→1536、`num_predict` 380→200、每条证据进 prompt 的字符数 420→220。

> **诚实性声明**：快路径是**抽取式 / 模板式生成**（extractive + template grounded generation），
> 不是「不生成」：答案的每一句都**逐字来自证据原文**，且带 `[块N]` 引用。
> 唯一省略的是「把已有句子改写得更自然」，而工单8 的实测恰好表明这一步正是
> **数字被改写的来源**（其原子保全护栏拦下的就是它）。

## 二、实体/关系构建层优化

### 现象（工单8 图谱产物上的实测）
| 编号 | 现象 | 证据 |
| --- | --- | --- |
| P1 | 同一实体分裂：`何肖`(1 次) 与 `何肖锋` 并存 | `工单8/研发/data/graph/entities.jsonl` |
| P2 | 公司全称/简称各自成节点：`平安银行` vs `平安银行股份有限公司` | 归并组样例 |
| P3 | 通用刻度噪声占枢纽：`2020年度` 出现 **593** 次、`2021年12月31日` **528** 次 | 实体表前 2 行 |
| P4 | 抽取碎片成实体：`是指本集团` / `当本集团` / `之后深发展吸收合并原平安银行` | 剪除样例 |
| P5 | 关系方向/类型未按 schema 校验 | `relations.jsonl` |
| P6 | 自环与重复边 | 优化统计 |

### 根因
正则 + 词典的抽取器**按字面产实体**，没有任何「同一主体不同写法」的归并环节，
也没有按 schema 做方向校验与噪声剪枝；工单8 的 `min_confidence=0.55` 还会放行弱抽取。

### 方案（`研发/app/graphrag_opt/抽取层.py`，四个阶段）
1. **别名归并**（并查集）：R1 公司后缀剥离、R2 人名前缀补全、R3 数值写法归一；
   规范名取「提及最多、平手取更长」，被并入的写法进 `aliases` 供实体链接回溯。
2. **关系规范化**：关系名归并到 schema 规范名 → head/tail 类型校验（反了就**自动反转**并计数）
   → 自环/非法关系剪除 → 同三元组去重（保留最大置信度 + 累计 `support`）。
3. **噪声剪枝**：通用刻度（低值整数比例 / 超高度数日期）、抽取碎片（过长 / 含句级连词 /
   含并列连词且过长）、孤立节点、度数上限。
4. **置信度过滤**：实体 0.55 → **0.60**；每实体提及块 6 → **4**。

### 前后数字
| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 节点数 | 9817 | **6717** | −31.6% |
| 边数 | 4861 | **3807** | −21.7% |
| **平均度数** | 0.9903 | **1.1335** | **+14.5%** |
| 别名归并组数 / 被并入实体数 | 0 / 0 | **104 / 208** | — |
| 规范关系覆盖率 | — | **1.0000** | — |
| 自环剪除 / 重复边合并 | — | 12 / 24 | — |
| 抽取碎片剪除 | — | **1249** | — |
| 孤立节点剪除 | — | **1745** | — |
| 通用刻度剪除 | — | 2 | — |

**为什么「节点 −31.6% 而平均度数 +14.5%」是好事**：节点减少来自**合并重复主体**与
**剪掉噪声/碎片**；边减少主要来自被剪节点携带的边。净效果是同一个图**主体更集中、
连通性更好、噪声更少**。

### 两次被实测否决的做法（配置里保留了开关，可复现）
| 做法 | 实测结果 | 结论 |
| --- | --- | --- |
| `min_edge_confidence` 0.55 → 0.60 | 剪掉 **2628/4861 = 54%** 的边（工单8 的 `rule_cooccur` 正好 0.55），平均度数反降到 **0.6514** | 否决，回到 0.55 |
| 把「和/与/及」一律当碎片标记 | 误剪 **774** 个实体，含「审计与风险管理委员会」「薪酬与考核委员会」等**真实机构** | 否决，改为「长度 ≥12 或同连词 ≥2 次」 |

## 三、检索层优化

### 现象
| 编号 | 现象 | 证据 |
| --- | --- | --- |
| P7 | **图谱通道形同虚设** | `base_score` ≈ 4.x，`graph_bonus` ∈ [0.022, 0.06]，**量纲差两个数量级**；17 题「图谱独有块进 Top5」= **0** |
| P8 | 固定 2 跳 + BFS 先到先得截断 | Q07 两跳带进别家公司年报块 |
| P9 | 无查询改写 / 实体链接 | 仅子串匹配 |
| P10 | 无候选裁剪与两段式重排 | 噪声候选直接进上下文 |
| P11 | 不做上下文扩展 | `page_context_extra=0` |

### 根因
图谱结构分与向量/BM25 分**不在同一量纲**，直接相加等于把图谱通道乘 0；
且扩展策略与证据组装都只有「一遍」，没有「裁剪 + 重排 + 补全」。

### 方案（`研发/app/graphrag_opt/检索层.py`）
| 优化点 | 做法 | 依据 |
| --- | --- | --- |
| **归一化加权融合** | `final = 0.62·minmax(base) + 0.23·norm(graph) + 0.15·feature`；feature = 0.5·实体命中 + 0.3·跳数衰减 + 0.2·度数倒数 | 让图谱分与基础分可比；权重全在配置里 |
| **自适应跳数** | 问句已锁定语料 ⇒ **1 跳**；否则 2 跳 | 防止两跳走到别家公司年报 |
| **邻居剪枝** | 按 `confidence × 1/log(2+degree)` 排序截断，取代 BFS 先到先得 | 高度数节点（`本集团`）邻居信息量低 |
| **焦点页簇补全** | 把「融合后 Top-N 命中所在页」的**全部块**优先放进上下文 | 实测：国泰君安 p4 的要点在 p4-x1、招商银行 p5 的 4 个要点在 p5-x1，被同页兄弟块挤掉 |
| **字段锚点召回** | 按问句里的每个财务字段词/年报章节词定点捞「含该词且附近有数字」的块 | 问「营业收入/净利润/不良贷款率/拨备覆盖率」时，Top-K 只带回营业收入那页 |
| **通道配额** | 焦点页 7 条、字段锚点 5 条的固定名额 | 不加配额时焦点页会吃光全部 14 条（4 页 × 6 块 = 24 > 14） |
| **证据去重** | 按 chunk_id 去重（保留通道优先级最高的一份） | 四路合并会让同一块重复占名额 |
| **英中术语映射** | `net profit → 净利润`、`Ping An Bank → 平安银行`；映射后的中文术语并入实词表并用于**重新做语料路由** | 英文问句在中文语料上实词命中恒为 0 ⇒ 排序退化为 chunk_id 字典序 |
| **对比题处理** | 对比题放宽**焦点页轮转**（不放弃语料闸门） | 直接放开闸门会让精度从 0.8025 掉到 0.7395 |

### 前后数字
| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| **context_precision（主口径）** | 0.7765 | **0.8025** | **+0.0260** |
| context_precision（rank 加权） | 0.8846 | 0.9491 | +0.0645 |
| context_precision（Top-K 附口径） | 0.7588 | 0.7765 | +0.0177 |
| **context_recall（主口径）** | 0.7563 | **0.8739** | **+0.1176** |
| 证据块数（主口径上下文） | 5 | **14** | +180% |
| 跨语料闸门拦下的跨公司块（样例 Q07） | 无闸门 | **54 块** | — |

### 三次被实测否决的做法（配置里保留开关）
| 做法 | 实测结果 | 结论 |
| --- | --- | --- |
| 对比题放开字段锚点的语料闸门 | 全局精度 0.8025 → **0.7395** | 否决，保留闸门 |
| 锚点页兄弟块扩展（`probe_expand`） | 精度 0.8025 → 0.7437，召回 0.8739 → 0.8655 | 否决，默认关闭 |
| 对**全部**提问都按「锚点优先」重排证据 | 中文指标回退（邮储 zh 丢了 610.36亿元） | 否决，**只对非中文提问**启用 |

## 四、生成层优化

### 现象
| 编号 | 现象 | 证据 |
| --- | --- | --- |
| P12 | 生成层占 96.7% 时间 | 3946.94 / 4080.41 ms |
| P13 | **图谱三元组没进 prompt** | 工单8 `ANSWER_PROMPT` 只有证据块 |
| P14 | 无引用约束 | 答案里没有块号 |
| P15 | 无拒答护栏 | 证据不足也硬答 |

### 方案
1. **图谱三元组结构化注入**：`head --关系--> tail（置信度；来源块）` 单独成段进 prompt 与答案，
   给出**结构化的字段↔数值绑定**（比让 3B 在 420 字长文里自己找更稳）。
2. **引用约束**：每条结论带 `[块N]`，答案末尾给 `【引用】公司 第N页`。
3. **拒答护栏**：证据块数 < 阈值，或证据与问句实词总重叠 < 阈值 ⇒ 标准拒答文案（中/英）。
4. **模板快路径 / LLM 慢路径**（见 §一）。
5. **表格行不再被切成碎片**：工单7 的表格块是 Markdown 行结构
   （`营业收入 | 137,958 | 116,716 | 18.2%`），早先按 `\s\|\s` 切句会把整行切成
   不足 8 字的碎片全部滤掉 ⇒ 数值题的「关键数据」段为空。
   改为**表格块按换行切整行**后，数值题的数值才进得了答案。

### 前后数字
| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 生成段平均耗时 | 3421.82 ms | **0.00 ms** | −100% |
| answer_relevancy（近似） | 0.5767 | **0.5802** | +0.0035 |
| 严格准确率 | 0.2941 | **0.4118** | **+0.1177** |
| 平均关键词覆盖率 | 0.3997 | **0.4392** | +0.0395 |
| 拒答护栏触发（容错场景） | 无护栏 | T1/T2/T4/T6 正确拒答、T8 结构化报错 | — |
| 答案引用 | 无 | 每题均有 `[块N]` + `【引用】公司 第N页` | — |

> faithfulness 从 0.9632 降到 0.9440，原因是**上下文从 5 块扩到 14 块后，
> 答案里的数值原子更多、分母变大**，属于口径变化而非质量下降；
> 该指标的绝对值不参与工单达标判定。
> 宽松准确率（严格+部分）保持 0.7647 不变 —— 严格与部分之间发生了**档位迁移**
> （原来判「部分正确」的题现在判「严格正确」），是模板快路径把关键数字稳定带进答案的结果。

## 五、未达标项与根因（**如实报告**）

### context_recall = 0.8739 < 0.90

| 题号 | 题型 | 优化后召回 | 缺口根因 |
| --- | --- | ---: | --- |
| Q01 Q05 Q06 Q07 Q08 Q10 Q11 Q12 Q14 Q15 Q16 Q17（**12 题**） | 数值/定性 | **1.000** | 无缺口 |
| Q02 | 定性 | 0.833 | **已达理论上限**：6 个要点里 `联合合作伙伴共同为用户提供优质服务` 在**全语料 0 命中**（参考答案的意译） |
| Q03 | 定性 | 0.571 | 缺失的 `绿色信贷` / `赤道原则` **在问句里没有出现**，属参考答案对原文的跨章节归纳 |
| Q04 | 跨文档对比 | 0.286 | 7 个要点跨 **6 份年报**，其中 5 个**在问句里完全没有线索** |
| Q09 | 跨文档对比 | 0.500 | 需同时取到平安银行 p19 与招商银行 p7/p20；语料闸门只能锁一家（放开闸门实测精度 −0.063，净收益为负） |
| Q13 | 英文 | 0.667 | 缺失的 `81.80亿元` / `2.96%` 都在邮储 p18-x1；p18 仅 2 块，名额被其它页占满（锚点兄弟块扩展实测净收益为负） |

**结构性原因**：本评估严格遵守「**检索只使用查询侧信息**」（问句、检索到的块、图谱、
从问句识别出的公司线索），**绝不使用**评估集的 `expected_pages_hint` / `answer_keywords`。
上述缺口里，缺失要点在问句里**没有任何线索**，任何合规的检索都无法定位它们所在的页。

**若强行冲 0.90**：把金标准页码喂给检索（直接把 `expected_pages_hint` 对应页的块塞进上下文）
可轻松把 Q03/Q04/Q09/Q13 顶到 1.0、宏平均 ≥0.95。**本工单拒绝这么做**——
那会让「优化前 vs 优化后」的对比失去意义，而工单要的正是「优化手段**自己**带来的提升」。
