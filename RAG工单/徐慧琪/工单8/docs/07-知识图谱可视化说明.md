# 知识图谱可视化说明

本说明对应硬性要求 1「知识图谱需可视化展示」的前端呈现部分。
实现集中在 `src/graph_viz.py`，配色本体在 `src/kg_schema.py`，
界面入口在 `app.py` 的「🕸 图谱可视化」与「🔗 实体关系」两个页签。

---

## 一、两种渲染方式：交互式（vis.js）与静态（matplotlib）

`src/graph_viz.py` 提供两条互补的渲染路径，保证**任何环境下都能看到图**：

| | 交互式（主） | 静态（兜底） |
| --- | --- | --- |
| 生成函数 | `to_vis_html(nodes, edges, height=620, title="")` | `to_matplotlib_png(nodes, edges, path, dpi=140)` |
| 技术栈 | vis.js 力导向布局（`vis-network` 走 CDN 加载） | networkx + matplotlib（`Agg` 后端，直接落 PNG） |
| 产出 | 自包含 HTML 字符串 | 磁盘上的 PNG 文件路径 |
| 嵌入方式 | Streamlit `components.html(...)` | `st.image(path)` |
| 适用场景 | 需要缩放/拖拽/悬停查看属性；有外网 | 无网络、CDN 不可达、或只需一张可贴进文档的静态图 |

### 1.1 交互式：`to_vis_html`

- vis.js 从 `VIS_CDN`（`https://unpkg.com/vis-network/standalone/umd/vis-network.min.js`）加载，**因此需要外网**；
- 生成的是自包含 HTML：页面顶部有标题栏（显示「N 个实体 / M 条关系」）和**全部 10 类实体的颜色图例**（图例由 `ENTITY_TYPES` 逐项生成），下方是图谱画布；
- 在 `app.py` 的「图谱可视化」页签中，`height=600` 传入 `to_vis_html`，外层 iframe 高度 700；
- 在「问答」页签的「🕸 知识图谱结构」子页签中，用的是同一函数、`height=460`、外层 iframe 高度 520，标题为 `子图（模式：{mode}）`；
- **Streamlit 版本提示**：本机安装的是 Streamlit 1.61.1，`st.components.v1.html` 已标记为 deprecated（官方建议将来改用 `st.iframe`）。当前 `app.py` 采用 `import streamlit.components.v1 as components` 后调用 `components.html(...)` 的写法，属于官方仍推荐的调用形式，功能完全可用，但升级 Streamlit 后建议迁移到 `st.iframe`。

### 1.2 静态兜底：`to_matplotlib_png`

- 用 networkx 建 `DiGraph`，`nx.spring_layout(k=0.9, iterations=120, seed=42)` 布局，节点按类型上色、边带关系标签，`plt.axis("off")` 后存 PNG；
- 中文字体按 `"Microsoft YaHei"` → `"SimHei"` → `"DejaVu Sans"` 顺序探测，命中即用；三者都缺失时仍能出图，只是中文可能显示为方框；
- 在 `app.py` 中，选择「静态（matplotlib）」时写入 `config.KG_DIR` 下的 `view.png`（`dpi=120`），再用 `st.image` 展示；
- 静态图**没有交互、没有图例**，也不携带 tooltip —— 要看属性与来源请用交互式或下方「节点详情」。

### 1.3 如何选择 / 触发

「图谱可视化」页签里通过单选控件切换：

```python
view = st.radio("渲染方式", ["交互式（vis.js）", "静态（matplotlib）"], horizontal=True, key="kg_view")
```

- 选「交互式（vis.js）」→ 走 `to_vis_html` + `components.html`；
- 选「静态（matplotlib）」→ 走 `to_matplotlib_png` + `st.image`。

取舍原则：**演示与探索用交互式**（信息量大、可悬停看来源），**离线交付/截图/无网环境用静态**。
模块另提供 `network_available(timeout=2.0)` 用于探测 CDN 可达性（仅作判断/提示用，返回 `bool`，不抛异常）。

## 二、实体类型配色表

配色定义在 `src/kg_schema.py` 的 `ENTITY_COLORS`，共 **10 类**实体；
含义取自同文件的 `ENTITY_TYPES`。节点颜色由 `node_color(etype)` 查表得到：

| 类型 | 颜色值 | 含义 |
| --- | --- | --- |
| `Company` | `#2E6FD9` | 公司（上市公司、控股股东、子公司、同业机构） |
| `Department` | `#37A96B` | 部门/板块/分支机构（个人金融部、信用卡中心、个人金融板块） |
| `Person` | `#D98324` | 人物（董监高、股东） |
| `Institution` | `#8250C4` | 机构（监管机构、交易所、政府部门） |
| `Industry` | `#0E9AA7` | 行业（银行、保险、证券） |
| `Business` | `#C94F7C` | 业务/产品（零售金融、投资银行、财富管理） |
| `Metric` | `#D64545` | 指标（不良贷款率、拨备覆盖率、营业收入、内含价值） |
| `Event` | `#8B6F47` | 事件（发行、分红、回购、并购） |
| `Time` | `#6B7280` | 时间（2019年度、报告期末、本期/上期） |
| `Location` | `#4B8C3F` | 地区（境内、境外、某省） |

**兜底色**：`node_color` 对 `ENTITY_COLORS` 中未收录的类型返回模块级常量
`_DEFAULT_COLOR = "#9AA0A6"`（中性灰），保证未知类型也能正常出图而不报错。

关系（边）不使用彩色区分：边的颜色统一为 `#b9bec7`，关系类型以边上的文字标签表示。

## 三、交互操作说明

以下均以 `to_vis_html` 实际生成的 JS 配置为准（`options` 对象）：

- **缩放与平移**：页面底部提示语写明「滚轮缩放、拖拽平移」；
- **导航按钮**：`interaction.navigationButtons: true`，画布左上角会出现 vis.js 的缩放/方向导航按钮；
- **悬停提示**：`interaction.hover: true`、`tooltipDelay: 120`（悬停 120 毫秒后弹出原生 tooltip）；
  - 悬停**节点** → 显示节点属性与来源（见第五节）；
  - 悬停**边** → 显示该关系的 `evidence` 原文片段（缺失时退化为关系类型标签）；
- **点击节点**：页面提示语为「点击节点查看属性与来源」；更完整的结构化属性可在 App 内的「节点详情」区查看（下拉选择一个节点，右侧以 JSON 展示其完整字典）；
- **箭头方向**：边统一 `arrows: "to"`（有向）；
- **布局参数**（仅列出代码显式设定的值）：`physics.stabilization.iterations: 220`，`physics.barnesHut.gravitationalConstant: -9000`、`springLength: 130`、`springConstant: 0.04`；节点 `borderWidth: 1.5`、字体 `size: 13`、`shape: "dot"`、`size: 14`；边为连续曲线（`smooth.type: "continuous"`），标签字体 `size: 10`、`align: "middle"`。

## 四、子图筛选（公司 / 类型 / 跳数）

「图谱可视化」页签（`app.py` 的 `_tab_graph()`）提供三个筛选控件，全部作用于
`filter_subgraph(kg, companies=..., types=..., hops=..., max_nodes=...)`：

| 控件 | 类型 | 默认值 | 对应参数 |
| --- | --- | --- | --- |
| 公司筛选 | 多选 `st.multiselect`（候选为图谱中全部 `Company` 节点名） | 前 3 家公司 | `companies` |
| 实体类型筛选 | 多选 `st.multiselect`（选项为 `ENTITY_TYPES` 的 10 类） | 空（=不限类型） | `types` |
| 邻居跳数 | 滑块 `st.slider`，范围 1–3 | 1 | `hops` |

页面先显示「子图：N 节点 / M 边」，再渲染图形；节点数上限由
`max_nodes=config.KG_SUBGRAPH_MAX_NODES * 2`（即 120）控制，防止子图过大。

行为细节（均可在 `filter_subgraph` 中核实）：

- **种子节点**：勾选的公司名命中 `Company` 节点即作为种子；**一家都不勾**时自动取图谱中前 3 个 `Company` 节点（若图谱中没有任何 `Company`，则退回前 3 个实体）。
- **邻居扩展**：对每个种子做 `hops` 跳的**无向**邻居遍历（关系有方向，但查询是双向的），节点超过上限时按「距中心最短距离升序 + 度数降序」截断，优先保留中心附近的高价值节点。
- **类型筛选**：`types` 非空时，对扩展后的节点集合按 `type` 过滤——注意它**同样作用于种子公司节点**，即若「实体类型筛选」中没有勾 `Company`，公司节点也会被剔除，图上只剩所选类型。
- 无论选哪种渲染方式，只要子图 `nodes` 非空，页面下方都会出现「节点详情」区（下拉选择节点 + JSON 展示）。
- **Metric 节点标签**：若节点类型为 `Metric` 且属性中有 `value`，标签会渲染为
  `{metric} {value}{unit}`（例如「不良贷款率 1.65%」），让指标图一眼可读。

「问答」页签里的图谱是**另一条路径**：它直接消费问答结果返回的 `subgraph`（`nodes`/`edges` 字典），
不经过上述筛选控件。

## 五、provenance 三元组：evidence / source_doc / page

`src/kg_schema.py` 的 `Relation` 文档字符串明确定义：
**`evidence` / `source_doc` / `page` 构成 provenance 三元组，是工单「返回答案所在的文本块」的实现基础**——
LLM 生成的每条结论都能回溯到具体文本块与页码。三类取值含义：

| 字段 | 含义 | 出现位置 |
| --- | --- | --- |
| `evidence` | 支撑该关系的**原文片段**（LLM 抽取的边必填，规则抽取可为空），可视化时截断到 200 字符 | **边的悬停提示**（边的 `title`） |
| `source_doc` | 该事实出自的**文档名** | **节点的悬停提示**（节点 `attrs` 中） |
| `page` | 该事实在文档中的**页码**（缺省为 `-1`） | **节点的悬停提示**（节点 `attrs` 中） |

字段落到可视化字典里的实际形态（`filter_subgraph` 的返回值）：

- **节点字典**键为 `id`、`label`、`type`、`color`、`attrs`；`attrs` 是白名单投影，只保留
  `metric`、`value`、`unit`、`period`、`yoy`、`source_doc`、`page`、`code`、`industry`、`full` 这些键；
- **边字典**键为 `from`、`to`、`label`（**关系类型**，如 `HAS_METRIC`）、`evidence`（截断 200 字符）、`source_doc`、`page`；
- 节点 tooltip 由 `_node_tooltip` 生成：首行固定为「类型：{type}」，随后按上述顺序逐项列出非空属性，
  因此 tooltip 里能看到 `source_doc` 与 `page`；
- 边 tooltip 取 `evidence`，若为空则退化为关系类型标签；`to_vis_html` 只把
  `from`/`to`/`label`/`title` 写进 vis.js 的边数据集，边的 `source_doc`/`page` 字段仍保留在
  `filter_subgraph` 返回的边字典里（供程序化使用），但不进入前端边对象；
  界面上的 JSON 只展示节点（「节点详情」区展示的是节点字典，其 `attrs` 内含 `source_doc` 与 `page`）。

换言之：**悬停一条边能看到「依据的原文长什么样」（evidence），悬停/点选其端点能看到「出自哪份年报的第几页」（source_doc + page）**，
这正是问答与研报中每个数字可回溯的数据基础（图谱统计显示 873 条边全部带 provenance）。
