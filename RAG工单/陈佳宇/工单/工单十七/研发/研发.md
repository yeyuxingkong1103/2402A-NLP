## 工具说明

1. **singleton_model.py**：单例装饰器；DeepDoc 解析器、重排模型、VLM 模型全局只实例化一次，避免每请求重复初始化。
2. **db_pool_fix.py**：数据库、向量库连接池封装；确保请求完成归还连接；设置空闲连接自动回收。
3. **prometheus_metrics.py**：Prometheus 监控埋点；接口耗时、请求数、队列长度、连接数指标。
4. **perf_analysis.py**：本地辅助脚本；用于 memory‑profiler 内存采样，打印对象留存情况。
5. jmeter 脚本：`scenarioA_20jmx`20 并发问答；`scenarioB_mix.jmx`混合负载（问答 + PDF 上传解析）。

## 3.RAGFlow 关键静态审查点

1. api/service.py/web_server：http 请求入口，确认大模型对象是否每次请求实例化。
2. model/pipeline：VLM、Reranker 模型加载代码，改成单例。
3. deepdoc 调用逻辑：确认解析器是否全局单例；解析任务投递 Redis 队列，API 不阻塞。
4. db / 向量库客户端：确认连接获取‑归还逻辑，防止连接泄漏。

## 运行流程

1. docker‑compose 拉起完整 RAGFlow 集群；
2. 基线压测：JMeter 执行场景 A、场景 B，记录基线指标；
3. py‑spy、memory‑profiler 定位 CPU 热点与内存泄漏位置；
4. 应用补丁：单例模型、连接池修复、prometheus 埋点；
5. 优化后再次执行两套压测；
6. 12 小时长时间稳定性测试，观察 RSS 内存增长。

## 6. 关键业务规则

1. PDF 文档解析任务必须交给 Task‑Executor 消费 Redis 队列；API Server 仅提交任务，**不能同步阻塞做解析**。
2. 所有重量级 AI 模型、DeepDoc 解析器全局单例，禁止在请求函数内部实例化。
3. 数据库、向量库连接，无论正常 / 异常分支，必须归还连接池，使用 try‑finally。
4. 大对象、张量，请求处理结束主动释放，帮助 GC 回收。
