## 1. 通用约定

### 1.1 命名与分层

| 层 | 模块前缀 | 说明 |
| --- | --- | --- |
| 接口层 | `app/ui/*`、`app/main.py` | 只做交互与展示，不含业务算法 |
| 编排层 | `app/core/qa_engine.py` | 唯一把各能力串起来的入口 |
| 能力层 | `app/core/{pdf_parser,chunker,embedder,vector_store,bm25_index,retriever,reranker,query_understanding,llm_client,generator,citation,conversation,evaluator}.py` | 单一职责，互不跨层调用 |
| 数据契约 | `app/models/schemas.py` | 全部 pydantic 模型 |
| 存储层 | `app/storage/sqlite_manager.py` | 只有它碰 SQL |
| 基础设施 | `app/core/{config,logging_conf}.py` | 配置与日志 |

### 1.2 返回值与异常

- **正常**：返回 pydantic 模型或明确类型的值（`int`/`str`/`list[...]`/`dict[str, Any]`）；**不使用"魔法 None"表达失败**（可空语义用模型字段表达，如 `Answer.is_unknown`）。
- **异常**：统一继承 `RAGError`；业务失败抛具体子类，禁止裸 `Exception`。

```python
class RAGError(Exception):
    """工单2 全部业务异常的基类：人工智能NLP-RAG-基于PDF文档的问答系统优化"""
    code: str = "RAG_ERROR"          # 机器可读错误码，见 §9
    def __init__(self, message: str, *, detail: dict | None = None) -> None: ...

class PDFParseError(RAGError):        code = "PDF_PARSE_ERROR"
class IndexNotReadyError(RAGError):   code = "INDEX_NOT_READY"
class RetrievalError(RAGError):       code = "RETRIEVAL_ERROR"
class LLMUnavailableError(RAGError):  code = "LLM_UNAVAILABLE"
class StorageError(RAGError):         code = "STORAGE_ERROR"
class ConfigError(RAGError):          code = "CONFIG_ERROR"
```

### 1.3 强制纪律（对应工单 6.7 / 6.8）

1. 每个**对外函数**必须有 `try/except`，异常路径写 `logger.exception(...)`（含堆栈）或返回结构化错误字段；**禁止 `except: pass`**。
2. 关键函数使用 `@trace` 装饰器，入参/出参/耗时自动写入 `rag_trace.jsonl`。
3. 一次用户提问分配一个 `trace_id`（`uuid4().hex[:16]`），贯穿 `retrieval` / `generation` / `llm_io` 三类事件与 SQLite `retrieval_traces`。
4. 文件读写一律 `encoding="utf-8"`；中文路径统一 `pathlib.Path`。
5. 每个文件 docstring 含工单编号「人工智能NLP-RAG-基于PDF文档的问答系统优化」，注释用中文。

### 1.4 文档范围说明

本文件描述的是**工单2 的目标契约**（T2 必须按此实现）；工单1 已有但未在本文列出的参数/辅助函数可按需保留，但不得改变本文件已固化的**方法名、字段名、异常类型、日志事件名**。

**入参**：`pdf_path` 存在的 PDF；`max_pages=0` 表示全部；`extract_tables=None` 取配置。

**打分契约（规则模式）**：`0.35×关键词覆盖 + 0.25×目标数值覆盖 + 0.15×类型先验 + 0.15×位置先验 + 0.10×融合分归一`，全部归一化到 [0,1] 后加权；结果写回 `RetrievedChunk.rerank_score`，并把 `score` 置为重排后分数。

**性能**：`rule` 模式单次 ≤500 ms（`reranker.budget_ms`），超预算只记 WARNING 不中断。

### 2.11 `app/core/llm_client.py`（新增）

```python
@dataclass
class BackendInfo:
    name: str            # "ollama" | "openai" | "extractive"
    model: str
    base_url: str
    available: bool
    probe_ms: float
    error: str = ""

class LLMClient:
    def __init__(self, settings: Settings | None = None) -> None: ...
    def probe(self, force: bool = False) -> BackendInfo: ...     # 超时 ≤0.5s、不重试、结果缓存
    def chat_stream(self, messages: list[dict[str, str]], *,
                    temperature: float | None = None,
                    max_tokens: int | None = None) -> Iterator[tuple[str, Any]]: ...
    def chat(self, messages: list[dict[str, str]], **kw) -> str: ...   # 非流式（改写等短任务）
    @property
    def backend(self) -> BackendInfo: ...
def get_llm_client() -> LLMClient: ...
```

**事件契约**（流式）：依次产出 `("first_token", {"first_token_ms": float})`（**仅首个非空增量**）、若干 `("delta", {"text": str})`、最后 `("done", {"text": str, "total_ms": float})`；任何失败产出 `("error", {"code": str, "message": str})` 后结束。
**后端映射**：`ollama` → `POST {ollama_base_url}/api/generate`（`stream=true`，逐行 JSON）；`openai` → `POST {base_url}/chat/completions`（`stream=true`，SSE `data: ` 行）；`extractive` → 立即产出 `("error", {"code": "LLM_UNAVAILABLE", ...})`，由 `generator` 走抽取式。
**异常**：不抛出网络异常给上层（转为 `error` 事件）；`probe()` 不抛异常，失败填 `available=False` + `error`。

### 5.1 `/api/health` 与 `/api/stats` 的响应字段（**以实现为准**）

> **同步记录（t4 评审 F5）**：本节此前写成扁平结构
> `{"ok": true, "embedder": {...}, "llm": {...}, "reranker": {...}, "index": {...}}`，
> 与实现不符——实现把 `QAEngine.health()` 的返回值放在 **`health`** 键下，并额外带 `app` 等 7 个字段。
> **决定：以实现为准，文档同步到实现**（前端 `serve_fallback.py` 与在线用例均按嵌套结构读取），
> 不改为扁平结构（那会同时改动实现与前端，且与已通过的在线用例相冲突）。

`GET /api/health` → `200`（结构示意：`<...>` 为占位符，真实值来自 `QAEngine.health()`）

```text
{
  "ok": true,
  "health": {
    "app": {"name": "<app_name>", "version": "<version>"},
    "embedder": {"backend": "ollama|sentence_transformers", "model": "...", "dimension": 1024,
                 "degraded": false, "degrade_reason": "", "index_dir": "bge-m3-1024",
                 "probe": {"available": true, "probe_ms": 12.3, "detail": ""}},
    "index": {"backend": "...", "dimension": 1024, "count": 1669, "model": "...",
              "index_dir": "<绝对路径>", "ready": true},
    "bm25_docs": 1669,
    "llm": {"backend": {...}, "force_extractive": false, "max_context_chunks": 5, "model": "qwen2.5:3b"},
    "reranker": {"mode": "rule", "model": "...", "budget_ms": 80, "available": false},
    "ready": true,
    "doc_id": "招股说明书1",
    "first_token_budget_seconds": 3.0
  }
}
```

| 键（`health` 内） | 类型 | 含义 / 消费方 |
| --- | --- | --- |
| `app.name` / `app.version` | str | 应用名与版本（部署自检、`serve_fallback.py` 页脚） |
| `embedder.backend` / `embedder.model` / `embedder.dimension` | str/int | 嵌入后端、模型名、维度；**降级到 512 维时 `degraded=true` 且 `degrade_reason` 给出原因**（界面据此提示重建索引） |
| `embedder.index_dir` | str | 索引目录名（`bge-m3-1024` / `bge-small-zh-512`），与 §2.4 "索引按模型分目录"一致 |
| `index.backend` / `index.count` / `index.ready` | str/int/bool | 向量库后端、向量条数、索引是否就绪（`ready` 是"能否回答"的唯一判据） |
| `bm25_docs` | int | 自实现 BM25 的文档数（应与 `index.count` 相等；不等说明索引/分块表不一致） |
| `llm.backend` / `llm.model` / `llm.force_extractive` | obj/str/bool | 生成后端探测结果、模型名、是否强制抽取式（评估用 `force_extractive=true`） |
| `reranker.mode` | `"model"｜"rule"｜"off"` | 重排模式；**本机无 `bge-reranker-base` 权重时为 `rule`，不得声称跑了模型重排** |
| `ready` / `doc_id` / `first_token_budget_seconds` | bool/str/float | 引擎就绪、当前文档、首字预算（=3.0，供界面与用例对齐验收 2） |

`GET /api/stats` → `200 {"ok": true, "tables": {...}}`；`tables` 键即 `QAEngine.stats()` 的返回值（各库表行数 + `chunks_loaded` + `doc_id`），与 `health` 一样是**嵌套**结构，不是扁平。

### 6.2 新增 `retrieval_traces`（检索追踪，对应工单"检索片段全记录"）

```sql
CREATE TABLE IF NOT EXISTS retrieval_traces (
    trace_id        TEXT PRIMARY KEY,          -- 一次提问的贯穿 ID（与日志 trace_id 相同）
    conversation_id TEXT,                      -- 可空（离线评估无会话）
    message_id      INTEGER,                   -- 关联 messages.message_id（生成后可回填）
    question        TEXT NOT NULL,             -- 用户原始问题
    rewritten_query TEXT NOT NULL DEFAULT '',  -- 多轮改写后的独立问题
    variants        TEXT NOT NULL DEFAULT '[]',-- 查询变体（JSON 数组）
    candidates      TEXT NOT NULL DEFAULT '[]',-- 候选块（JSON：chunk_id/page/type/score/vector_score/bm25_score/rerank_score）
    boosts          TEXT NOT NULL DEFAULT '{}',-- 各加权/降权系数汇总（JSON）
    final_pages     TEXT NOT NULL DEFAULT '[]',-- 送入生成的页码（JSON）
    rerank_mode     TEXT NOT NULL DEFAULT 'off', -- model | rule | off
    top_cosine      REAL NOT NULL DEFAULT 0,   -- 最高原始余弦（拒答判据）
    first_token_ms  REAL NOT NULL DEFAULT 0,
    total_ms        REAL NOT NULL DEFAULT 0,
    mode            TEXT NOT NULL DEFAULT 'llm', -- llm | extractive | fallback
    created_at      TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_traces_conv ON retrieval_traces(conversation_id, created_at);
CREATE INDEX IF NOT EXISTS idx_traces_q    ON retrieval_traces(question);
```

**写入时机**：`QAEngine.stream()/ask()` 在生成结束后一条 `INSERT`；若生成失败仍写入（`mode="fallback"`）。**查询契约**：`get_retrieval_traces(conversation_id=None, trace_id=None, limit=100)` 返回按 `created_at` 倒序的 `RetrievalTrace` 列表。

### 6.3 迁移与兼容

- 建表语句全部 `CREATE TABLE IF NOT EXISTS`（幂等）；新增表不破坏基线数据。
- 若检测到基线库缺 `chunks.is_boilerplate` 列（本工单新增），执行 `ALTER TABLE chunks ADD COLUMN is_boilerplate INTEGER NOT NULL DEFAULT 0`（幂等：先查 `PRAGMA table_info(chunks)`）。
- 索引目录与 DB 分开管理；`index/<embedder>-<dim>/` 与 DB 中的 `vectors_meta` 校验一致。

## 7. 日志 schema

### 7.1 `app.log`（全量结构化，JSON Lines，每行一个 JSON 对象）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `text` | str | 人类可读消息（loguru `serialize` 结构） |

| `record.level.name` | str | `DEBUG`/`INFO`/`WARNING`/`ERROR` |

| `record.extra.module` | str | 业务模块名（如 `app.core.retriever`） |
| `record.extra.*` | any | 业务字段（`query`/`pages`/`elapsed_ms`/`trace_id`/`degraded`…） |
| `record.exception` | object/null | 异常类型/值/堆栈（`error.log` 必含） |

### 7.2 `error.log`

与 `app.log` 同结构，仅 `ERROR` 及以上；必须满足：①`record.exception.traceback` 非空；②含业务定位字段（`module`、`function`、`trace_id`）。**任何 `except` 分支若无日志即为静默失败（验收会抽查）**。

### 7.3 `rag_trace.jsonl`（事件流水，一行一事件）

**通用字段**（所有事件都有）：`ts`（ISO 8601 带毫秒与时区）、`event`、`module`、`function`（非函数事件可为空）、`trace_id`（函数级事件可为空）。

| 事件 | 触发 | 专属字段 |
| --- | --- | --- |
| `enter` | `@trace` 包裹的函数进入 | `args: list`、`kwargs: dict`（截断 800 字符，去除 `self`） |
| `exit` | 正常返回 | `elapsed_ms: float`、`result`（截断） |
| `error` | 函数抛异常 | `elapsed_ms`、`error_type`、`error`、`traceback`（完整堆栈） |
| `retrieval`【新增】 | `Retriever.retrieve*` 结束 | `trace_id, query, rewritten, variants, vector_hits, bm25_hits, merged, boosts, pages, top_cosine, top_score, rerank_mode, elapsed_ms` |
| `generation`【新增】 | 生成结束 | `trace_id, backend, model, mode, prompt_chars, prompt_sha1, context_pages, context_chunk_ids, first_token_ms, total_ms, answer_chars, citations` |
| `llm_io`【新增】 | LLM 调用前后 | `trace_id, backend, model, prompt`（截断 2000 字符）、`output`（截断 2000 字符）、`stream_chunks: int` |
