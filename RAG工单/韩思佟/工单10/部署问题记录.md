# 工单10 · 部署过程问题记录

> 记录真实遇到过的问题、原因与解决办法。按"现象 → 排查 → 原因 → 解决"四段式写。
> 本机环境：Docker 29.3.1 / Docker Compose v5.1.1 / Windows 11 / RTX 3060 Laptop 6GB。

---

## 问题 1：pip 安装超时，镜像构建卡在 `pip install`

**现象**：`docker build` 在 `pip install -r requirements.txt` 阶段卡住，最终 `ReadTimeoutError`。

**排查**：`files.pythonhosted.org` 连接超时；`pypi.org` 可达但下载域被墙。

**原因**：默认 PyPI 在境外；且 torch 默认 wheel 是 CUDA 版（Windows 上约 2.4GB）。

**解决**：
1. 换国内镜像：`-i https://pypi.tuna.tsinghua.edu.cn/simple`（或华为云 `repo.huaweicloud.com`）
2. torch 用 CPU 版源：`--extra-index-url https://download.pytorch.org/whl/cpu`（约 124MB）
3. `requirements.txt` 单独 COPY 先安装，代码变更时不重复下载依赖（Dockerfile 已实现）

---

## 问题 2：容器启动后立即退出，日志 `RuntimeError: 未配置 LLM_API_KEY`

**现象**：`docker compose up -d` 后容器反复重启。

**排查**：`docker compose logs rag-api` → `RuntimeError: 未配置 LLM_API_KEY`。

**原因**：`src/config.py` 的 `_load_env()` 读取项目根 `.env`，容器里没有；compose 的 `${LLM_API_KEY}` 取的是宿主环境变量，未设置时为空。

**解决**：
- 在项目根目录建 `.env` 填入 Key（已在 `.dockerignore` 排除，不会进镜像）
- 或在 compose 的 `environment` 里直接写，启动时 `LLM_API_KEY=sk-xxx docker compose up -d`

---

## 问题 3：首次问答耗时长（>10s）

**现象**：容器起来后第一个请求很慢，之后正常。

**原因**：embedding 模型（bge-small-zh-v1.5）与 CrossEncoder 是懒加载，第一次请求才载入；
另外 Docker 里 `HF_HOME` 默认指向容器内目录，模型文件不在镜像里会触发下载。

**解决**：
- 启动时预加载：`CMD ["python","-m","src.web_api","--kb","ccf"]`（不加 `--lazy`）
- 把本地模型挂进容器或用卷持久化 `HF_HOME=/app/.cache/huggingface`（compose 已挂 `rag-models` 卷）

---

## 问题 4：容器内存被打到 OOM

**现象**：运行一段时间后容器被 KILL，`docker inspect` 显示 `OOMKilled: true`。

**原因**：torch 默认会占较多内存；并发请求时每请求都新建线程池/模型实例（详见工单17 的分析）。

**解决**：
- compose 里加资源限制（已加 `cpus: 2.0 / memory: 4g`）
- 限制并发：见工单17 的 P4 请求限流补丁
- 调小 `RAG_TOP_K_RECALL`（默认 20 → 12）

---

## 问题 5：端口 8000 已被占用

**现象**：`Error starting userland proxy: listen tcp4 0.0.0.0:8000: bind: address already in use`

**解决**：改 `ports: - "8001:8000"`，或 `netstat -ano | findstr :8000` 找到占用进程停掉。

---

## 问题 6：Windows 上挂载路径导致容器内读不到数据

**现象**：`docker compose up` 后容器内 `/app/data` 为空。

**原因**：Windows 路径分隔符与 Docker Desktop 的文件共享设置。

**解决**：
- 确认 Docker Desktop → Settings → Resources → File Sharing 已包含 D 盘
- compose 里用相对路径 `${HOST_DATA_DIR:-./data}:/app/data:ro`，并在 `.env` 里设 `HOST_DATA_DIR=./data`
