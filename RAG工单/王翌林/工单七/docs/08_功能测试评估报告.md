## 4. 评估框架

[src/evaluation_v7.py](../src/evaluation_v7.py)，纯函数实现（不依赖 Milvus/模型，9 个单元测试覆盖）：

| 指标 | 计算口径 |
| --- | --- |
| doc_recall@5 | top5 中出现的 gold_docs 数 / gold_docs 总数（跨文档题为比例口径） |
| MRR | 第一个金标文档排名的倒数 |
| context_recall | 金标关键词组在 top5 拼接上下文中的覆盖率（组内同义词任一命中即通过） |
| answer_acc | 金标关键词组在 RAG 答案中**全部**命中则为 1（严格全命中口径） |
| noise_docs / issues | top5 非金标文档；自动归类漏检、排序靠后、串档、上下文缺口、答案漏点、超时(>3s) |

## 6. 检索结果存在的问题分析（10 题实测）

### 问题 1：跨文档综合分析题 top-k 槽位不足，多文档覆盖率低（Q10，核心问题）

Q10 要求覆盖银行/保险/券商多家机构，但 top5 仅 5 个槽位：命中 3 家金标（国君还重复占 2 槽 #2/#5），**招商银行（"逾越者联盟"/两大 App 月活破亿）、邮储银行（12 处绿色金融表述）完全未进 top5**，doc_recall 仅 0.6。原因：单路语义召回按 query 整体向量相似度排序，"金融科技 OR 绿色金融"两条主线 + 多公司实体无法在一条向量中同时表达，排序被单一最相似文档主导。
**改进方向**（不在本工单实施，仅记录）：跨文档题自适应扩大 top_k；按 doc_id 做 MMR 多样性去重（每文档限 1~2 条）；对问题做主体/主题分解后多路召回。

### 问题 2：跨文档题响应超时 3.875s（Q10）

Q10 检索仅 597.9ms（达标），耗时主要在长上下文 + 700 tokens 长答案的外部 LLM 生成；9 道单文档题 1000~2412ms 均达标。问题本质是**综合性问题的答案生成长度**而非检索性能。改进方向：跨文档题流式输出、或限定每家机构答案篇幅。

### 问题 3：数字型查询全文通道贡献稀疏，表格数字与文本表达存在鸿沟

10 题全文通道仅 Q3/Q6/Q8 各有 1 条命中（且恰好是这三题的 top1，vec+ft 共现被 RRF 强化到 0.999+）；其余 7 题全文 0 命中，完全依赖向量通道。原因：年报核心数字多位于 excel/表格型 chunk（如邮储"营业收入 276,809"在表格块），且表述方式为"百万元"单位、千分位、跨列拼接，与自然语言问题词面重合少。当前靠语义召回 + 双路共现兜底保证正确，但**纯全文策略对此类问题风险高**（工单六 16 题实测 fulltext 准确率 0.812 亦印证）。

### 问题 4：集团合并口径与子公司数字的语义区分不足，存在干扰上下文（Q9）

Q9 top2/top4 召回国泰君安资管（25.79 亿）、国泰君安创投（112.98 亿）等**子公司口径**数字，与问题所指集团合并口径（428.17/150.13 亿）极易混淆。本次 LLM 正确区分未答错，但检索层面无法识别"合并口径 vs 子公司"约束——这是数字类事实题潜在的错答风险点。改进方向：chunk 元数据补充合并/母公司/子公司口径标签，或在重排 prompt 中强化口径匹配。

### 问题 5：长文档中部分 chunk 有效文本稀疏，页眉噪声明显（Q7 尤甚）

Q7 top5 chunk 文本前 70 字全部只有页眉"招商证券股份有限公司2021年年度报告"，正文被大量空白/表格前导符稀释（278 页年报中表格密集页文本抽取质量差）。本次依靠表格型 chunk 与 reranker 仍拿到正确答案，但 chunk 可读性与引用展示质量差。改进方向：入库前清洗重复页眉页脚、合并被切碎的表格行。

### 问题 6：自动评估指标对开放题的判定边界（框架层面的问题）

Q10 首位的招商证券实际与问题**高度相关**（数字化规划/金融科技中心），但因不在预设 gold_docs 中被自动标记为"跨公司串档"；反之若金标列得更宽，doc_recall 又会虚高。说明**金标关键词/文档法适合事实题（Q1~Q9 判定稳定可信），对开放式分析题只能做粗筛，需结合人工研判**。本报告对 Q10 即采用"自动指标 + 人工核对答案内容"双重结论。

### 问题分布与结论

| 自动归类问题 | 题数 | 涉及题 |
| --- | --- | --- |
| 金标文档漏检（top5 未覆盖全部金标） | 1 | Q10 |
| 跨公司串档（开放题口径，含误判） | 1 | Q10 |
| 响应超时 >3s | 1 | Q10 |
| 上下文关键词缺口 / 答案要点遗漏 | 0 | — |

**结论**：01-06 工单 RAG 系统在 9 份年报新语料、单文档事实/分析题上表现优秀（9/9 全指标满分，平均 1.4s，数字答案零事实错误）；主要短板集中在**不限定文档的跨机构综合分析题**——多文档覆盖（0.6）与响应时延（3.9s），另有表格数字词面鸿沟、子公司口径干扰、chunk 页眉噪声三个数据/检索层面的风险点，均给出改进方向。
