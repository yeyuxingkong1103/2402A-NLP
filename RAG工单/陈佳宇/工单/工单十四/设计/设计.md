# 工单14 修复低质量工业PDF的解析与信息丢失｜设计文档
## 1.项目概述
工业场景存在大量图片型扫描PDF，包含技术图纸、机械示意图，文档分辨率低、图文交错排布。普通PDF直接文本提取会发生图片内信息丢失、图文对应关系错乱，导致RAG检索问答错误。
本工单基于开源RAGFlow项目，研究DeepDoc深度解析模块，针对IMDR数据集工业专利PDF`CN100342976C.pdf`开展调试优化；
测试三类问题：
1. Only‑Text‑Question：纯文本问题
2. Text‑Image‑Question：文本‑图片混合推理问题
3. Only‑Image‑Question：完全依赖图纸图片信息的问题

目标：经过解析参数、分块策略、检索rerank调优，6道测试问题全部回答正确。

## 2.RAGFlow架构梳理
RAGFlow两大核心组件
1. API Server：对外提供Web接口、文件上传、知识库管理、问答交互；接收前端操作请求。
2. Task Executor任务执行器：消费Redis Stream消息队列，执行文件解析、DeepDoc处理、分块切片、向量化入库任务。

### DeepDoc模块解析流水线
文件上传后，选择解析方案（paper / table / one / knowledge_graph等），前端触发解析，任务参数投递到Redis Stream消息队列；
Task Executor中`do_handle_task()`作为主任务处理函数，消费队列消息，完整流程：
> 文件读取 → 分发对应parser解析器 → 布局分析LayoutRecognizer → OCR识别扫描PDF图片文字 → 图表抽取figure_parser → 后处理postprocess → 文本分块 → 向量化 → 写入向量库。

### DeepDoc解析器清单（deepdoc/parser）
|解析器|用途|
|---|---|
|pdf_parser.py|原生可复制文本PDF解析|
|paddleocr_parser.py|OCR扫描图片PDF解析，图片转文字|
|figure_parser.py|图表、图纸提取模块|
|docx/excel/ppt_parser|Office文档解析|
|mineru_parser|第三方文档解析适配器|

> 图片型工业PDF必须启用OCR流水线；否则直接提取文本会丢失图纸内部标注、部件编号信息。

## 3.问题根因分析（工业扫描PDF常见故障）
1. PDF为图片扫描件，没有可复制文本，普通pdf_parser直接解析得到空文本，图纸部件标号全部丢失。
2. 图文混排：图纸图片与说明文本被切分到不同切片，图文上下文割裂，提问图纸部件位置关系检索不到对应说明文字。
3. 分块策略不合理：块过大混入大量无关内容；块过小把单条图文信息切分成多个碎片。
4. OCR识别质量差：低分辨率图纸数字、标号识别乱码。
5. 检索策略缺陷：向量相似度只匹配文本，图纸部件关键词召回不足，rerank未生效。

## 4.优化方案设计
1. 解析层：图片PDF切换paddleocr_parser OCR解析流水线；开启layout布局识别；启用figure_parser抽取图纸信息。
2. 分块层：针对工业专利文档，调优chunk_size、chunk_overlap；开启图文绑定策略，图纸与紧邻说明文本合并到同一个切片。
3. 检索层：调整embedding相似度权重；开启rerank重排序；调高top‑k召回数量。
4. 后处理层：OCR后处理，清洗图纸识别乱码字符；修复部件编号格式。
