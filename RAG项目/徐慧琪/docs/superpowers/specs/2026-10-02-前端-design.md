## 一、范围

**做**：

- 新建 `frontend/`：Vue 3 + Vite + TypeScript + Element Plus，**一工程两入口**（`index.html` 公众侧 / `lawyer.html` 律师侧），共享 `src/core`（类型化 API 客户端）与 `src/components`（法条原文卡、引用列表、导航树、律师卡、费用卡、错误面板、提问框）。
- 公众侧三页：提问页（单轮卡片式）、法条浏览（编章节树）、法条详情。
- 律师侧：登录页、工作台（问答/检索两模式）、法条浏览与详情（含一键复制带条款号）、历史案件（501 联调展示）、审计导出（仅 partner 角色显示）。
- 契约类型：`tools/export_openapi.py` 离线导出 + `openapi-typescript` 生成（`npm run gen:api`）。
- 闸门与验收：Vitest 判据、`vue-tsc` 类型检查、生产构建（两入口产物）、真后端人工验收。

**不做**（本设计不含）：

- **Nginx 托管、Docker Compose 全栈部署** —— 部署子项目；本轮只产出可托管的构建产物。
- **多轮会话** —— 后端 `/qa` 与 `/public/qa` 只收单条 `question`、无会话字段；前端**如实**以单轮卡片呈现（`need_more_info` 时展示反问与「补充后可再问」提示，**不假装记得上文**）。多轮需后端会话支持（进程内 TTL 或 Redis），另期立项。
- **浏览器 e2e（Playwright）** —— 链路已被后端 818 条测试与 ④a 人工验收覆盖；客户端判据用 Vitest 承重。
- **用户管理界面**（账号仍由 `tools/manage_users.py` 创建）、**案件功能实做**（后端 501，前端只做联调展示）、markdown 渲染、i18n、主题定制、SSR/PWA。
- **后端任何运行时改动**（含 CORS —— 不需要引入：dev 走 Vite proxy、生产同源）。

## 三、架构

```
frontend/
  index.html            公众侧入口（公网门面）
  lawyer.html           律师侧入口（内网）
  vite.config.ts        多入口 + dev proxy + Vitest 配置
  package.json / package-lock.json / tsconfig.json / tsconfig.node.json
  scripts/check-size.mjs  文件 ≤300 非空行的检查（npm run check:size）
  src/
    core/
      config.ts         API 前缀、超时、常量
      api-types.gen.ts  openapi-typescript 产物（生成物，禁止手改）
      api/
        request.ts      fetch 封装 / 错误归型 / 超时 / 取消 / token 注入
        public.ts       公众可读端点（publicQa / article / nav）
        lawyer.ts       律师入口专用端点（login / qa / search / casesSearch / exportAudit）
      useAuth.ts        token 生命周期（模块级 reactive；仅律师侧入口使用）
    components/         两入口共享
      QuestionBox.vue   提问框（长度上限、提交、取消）
      AnswerCard.vue    结果卡：解读分区 + 法条原文分区 + 引用跳转
      CitationList.vue  引用列表（article/paragraph/item/quote → 跳转链接）
      ArticleText.vue   法条原文卡（文书风排版；可选复制）
      NavTree.vue       编—章—节—条树（el-tree + 过滤）
      LawyerCards.vue   推荐律师卡（name/org/field/contact_hint/demo 示例角标）
      FeeCard.vue       费用区间卡（必带「参考区间，不构成报价或委托」）
      ErrorPanel.vue    错误面板（code/message/request_id 可复制/重试）
    public/
      main.ts / App.vue / router.ts
      pages/{AskPage,ArticlePage,NavPage}.vue
    lawyer/
      main.ts / App.vue / router.ts
      pages/{LoginPage,WorkbenchPage,ArticlePage,NavPage,CasesPage,AuditPage}.vue
```

**三条定调**：

1. **两个入口是结构性的隔离**：公众入口的构建产物**不含**律师侧模块（路由名、接口路径、页面逻辑不进公网 JS）——与 ④a「未认证访问律师侧路径返回 404、不暴露路径存在性」的设计意图一致；公众侧多为手机访问，包也更小。与部署口径（Nginx 内网 + 公网两个 server 块）一致。
2. **契约只有一份真相源**：前端类型由后端 OpenAPI 离线生成（`tools/export_openapi.py` 用 `create_app().openapi()`，不启服务、零暴露面）；设计不重抄字段清单，需要字段示例时以 `backend/app/api/schemas.py` 与 `2026-09-29-HTTP接口-design.md` §四 为准。
3. **路由只做页面关注点**：网络与错误语义全部收在 `core/api/request.ts`；页面不直接 `fetch`。端点模块按入口拆分（`public.ts` / `lawyer.ts`）——公众入口的模块图里**不存在** `lawyer.ts`，这是「公众包不含律师侧接口名」的结构保证（构建产物扫描测试钉住）。

**数据流**（一次提问）：`QuestionBox 提交 → api.qa() / api.publicQa()（超时 120s、可取消）→ 类型化结果 → AnswerCard 按 status 渲染（ok / need_more_info / 其它终态如实显示）`；失败 → `ErrorPanel`（429 显示 `Retry-After` 倒计时；500/503 通用文案 + `request_id`）。

## 四、页面与交互

### 公众侧（`index.html`）

| 路由 | 页面 | 要点 |
|---|---|---|
| `/` | AskPage | 标题区 + 提问框；结果卡**独立堆叠**（最新在上；仅存内存，刷新即清）；每卡：解读（标「AI 解读，仅供参考」）→ 法条原文分区（引用可跳转详情）→ 推荐律师卡 → 费用区间卡（必带参考区间提示）→ 免责声明（取 API `disclaimer` 字段，逐条必现）；`status=need_more_info` 展示反问 +「补充后可再问（每次提问独立）」 |
| `/nav` | NavPage | 编—章—节—条树（el-tree + 过滤），点「条」→ 详情 |
| `/law/:lawId/articles/:no` | ArticlePage | 法条原文 + 面包屑（`path`）；公开只读 |

- 页面**零本地存储**（不写 cookie / localStorage / sessionStorage）；**无任何上传/编辑/删除/导出入口**（公众入口路由表字面量快照测试钉住）。

### 律师侧（`lawyer.html`）

| 路由 | 页面 | 要点 |
|---|---|---|
| `/login` | LoginPage | 用户名/密码 → `access_token / role / team_id`；错误文案用后端 message |
| `/` | WorkbenchPage | 顶部含当前角色/团队与**退出**（清 token）；提问框 + 模式切换「问答 / 检索」（`/qa` 与 `/search`）；结果卡：解读 + 法条原文分区 + 引用跳转 + **一键复制**（见下）；结果卡同公众侧独立堆叠、仅存内存 |
| `/nav`、`/law/:lawId/articles/:no` | NavPage / ArticlePage | 同公众侧，另含复制 |
| `/cases` | CasesPage | 调 `/cases/search`，优雅展示 **501** 的 reason（接口位联调证明） |
| `/audit` | AuditPage | 仅 `partner` 角色（取登录响应的 `role`）显示入口；下载导出结果（后端返回数组） |

- 路由守卫：无 token → `/login`；**律师侧专用路由上的 404 ⇒ 清 token → `/login`**（共享路由 404 正常显示「未找到」）。

**复制格式（FR-7.4；输出为「解读正文 + 空行 + 依据列表」，格式由字面量锚测试钉住）**：

```
《中华人民共和国民法典》第{article}条{（第{paragraph}款）}{（第{item}项）}：“{quote}”
```

（款/项存在时才附；条号用引用里的 `article` 值，不做额外出网请求。）

**「法条原文」与「AI 解读」分区（FR-4.4）**：两块卡片式分区；原文卡文书风排版，解读卡带「AI 解读，仅供参考」标签；测试断言两区与标签同时存在。

## 五、鉴权与错误处理

| 情形 | 前端行为 |
|---|---|
| 律师侧无 token / token 过期（专用路由 404） | 清 token → `/login`（带 returnTo 回跳） |
| 共享路由 404 | 「未找到」（文章不存在等） |
| 429 | 显示 `Retry-After` 秒数倒计时；倒计时内禁用提交 |
| 400 | 显示后端 message（如问句超长） |
| 413 | 「内容过长」+ 后端 message |
| 500 / 503 | 通用文案 + `request_id` 可复制（便于按 id 回查运维日志） |
| 501 | 展示后端 reason（CasesPage） |
| 网络失败 / 超时 / 用户取消 | 分别如实提示；取消不报错（静默回填输入框） |

token 生命周期：登录写入 → 随请求 `Authorization: Bearer` → 退出清；不做静默续期（TTL 8h，过期即重新登录）。

## 六、安全与合规落点（前端侧）

| 项 | 做法 |
|---|---|
| XSS | 一律纯文本渲染（pre-wrap）；源码扫描测试钉「无 `v-html`」；Element Plus 打包内置、无第三方脚本 |
| AC-19（公众侧不采集身份） | 公众入口零本地存储；不设 cookie；不采集输入之外的任何字段 |
| FR-8.7（公众侧只读） | 结构保证（两入口分包）+ 公众入口路由表字面量快照测试（无写入口） |
| FR-8.4 / FR-9.4（免责与参考区间提示） | 免责声明逐答必现（API `disclaimer` 字段）+ 页脚常驻；费用卡固定提示「参考区间，不构成报价或委托」 |
| 密钥不出前端 | 前端不存在任何密钥/模型配置；LLM 调用全在后端 |
| 文案不编造 | 错误信息一律透传后端 message；`request_id` 始终可见于错误面板 |

## 十、自检结论

**需求覆盖**：

| 需求 | 落点 |
|---|---|
| FR-7.1 / 7.2 / 7.3 / 7.4 | 工作台提问与结果卡、引用跳转、导航树、一键复制（带条款号格式） |
| FR-8.1~8.7 | 公众侧提问（口语直入）、引用与原文、免责与分区、need_more_info 如实呈现、只读与零存储 |
| FR-9.3 / 9.4 / 9.5 | 推荐律师卡、费用区间卡（参考区间提示）、无付费插位（展示顺序来自后端字段，前端不改序） |
| FR-4.4 | 「法条原文」与「AI 解读」分区 + 标签断言 |
| AC-19（前端侧） | 公众入口零本地存储、无身份采集 |
| AC-20（前端侧） | 429 倒计时；错误不外泄细节（透传后端通用文案） |

**两处刻意缺口**（不是遗漏）：

1. **多轮会话不在本轮** —— 后端无会话支持，前端如实单轮呈现；多轮需后端会话（进程内 TTL 或 Redis）另期立项。
2. **部署不在本轮** —— 只产出构建产物；Nginx 内/公网两个 server 块与静态托管属部署子项目。

**命名一致性**：`core/api/lawyer.ts` 的 `login / qa / search / casesSearch / exportAudit` 与 `core/api/public.ts` 的 `publicQa / article / nav`、`useAuth`、组件名如上——跨模块无重名。`lawyersRecommend` **不实现**（v1 无页面使用：公众侧推荐卡来自问答响应的 `lawyers` 字段；服务端端点仍在，将来需要时按同一模式补）。

**占位符扫描**：无 TBD / TODO；`/cases` 的 501 展示是**明确的交付形态**（接口位联调），不是含糊的待实现占位。
