# 工单06 检索策略配置指南

**工单编号：人工智能NLP-RAG-混合检索任务**

本指南回答一个问题：**什么场景用什么检索策略、什么重排器、什么参数。**
所有配置都可通过 `Retriever.retrieve()` 或 Web 接口 `POST /api/ask` 在线切换，
无需重启服务。

---

## 1. 一分钟速查表

| 问题类型 | 推荐策略 | 推荐重排器 | 推荐参数 |
| --- | --- | --- | --- |
| 金额/比例/年份等精确数字 | `hybrid` + `rrf` | `tfidf`（数字加权） | `top_k=5, recall_k=20, alpha=0.6` |
| 专有名词、标准名、人名 | `hybrid` + `rrf` | `tfidf` 或 `none` | 同上；必要时 `fulltext` + `phrase_search` |
| 口语化/同义改写问题 | `vector` 或 `hybrid` + `weighted` | `llm` 或 `cascade` | `alpha=0.7`（向量权重调高） |
| 多期数据对比、跨章节归纳 | `hybrid` + `rrf` | `cascade` | `recall_k=20~30`，多子问题检索（工单05） |
| 表格类问题（财务数据） | `hybrid` + `vote` | `tfidf` | 表格块整块保留，`top_k=5` |
| 关键词筛选/排除（含 A 不含 B） | `fulltext` + 布尔查询 | `none` | `boolean="AND"/"OR"/"NOT"` |
| 错别字/形近字输入 | `fulltext` + `fuzzy_search` | `none` | `max_dist=1`；配合 `hybrid` 兜底 |
| 高风险、必须给依据的问题 | `hybrid` + `vote` | `cascade` | 双通道共识片段优先，答案附页码 |
| 低延迟（<1s）要求 | `vector` 或 `fulltext` | `tfidf` 或 `none` | 避免 `llm`/`cascade` |
| 英文提问（多语言） | `vector`（bge-m3）或 `hybrid` | `tfidf` | 生成侧自动切换英文 Prompt |

> 默认推荐（覆盖大多数场景）：**`hybrid` + `rrf` + `tfidf`**，即
> `{strategy:"hybrid", fusion:"rrf", reranker:"tfidf", top_k:5, recall_k:20}`。
> 若配置了 LLM API 且可接受 1~3s 延迟，升级为 `reranker:"cascade"` 精度更佳。

## 2. 三种策略怎么选

### 2.1 向量检索 `strategy="vector"`

```
  适用：语义相似、同义表达、口语化提问、跨表述检索
  优势：不怕换词（「军品收入」≈「军用领域的收入」）
  弱点：精确数字/编号可能被语义近邻"稀释"；需要嵌入模型在线
  典型：进入系统先做一轮语义召回，或对长问题做主题定位
```

### 2.2 全文检索 `strategy="fulltext"`

```
  适用：精确关键词、金额、比例、年份、专有名词、布尔筛选
  优势：倒排索引毫秒级、结果可解释、金额数字命中准
  弱点：不能理解同义改写；分词错误会漏召回
  典型：数字核对、按标准名/人名定位、限定范围的筛选
```

### 2.3 混合检索 `strategy="hybrid"`

```
  适用：绝大多数真实问答（默认）
  优势：语义 + 关键词双信号互补，召回与精度同时提升
  弱点：计算量约为单通道的 1.6~2 倍（实测仍在百毫秒级）
```

## 3. 融合算法怎么选（仅 hybrid 有效）

| 融合算法 | 参数 | 什么时候用 |
| --- | --- | --- |
| `weighted` | `alpha` | 需要连续调节两路权重；已知某一路更强时 |
| `rrf` | `RRF_K=60` | **默认**；两路分数量纲差异大、追求稳健 |
| `vote` | 无 | 强调「双通道共识」，排序头部要最可靠 |

`alpha` 调节经验（weighted）：

- `alpha = 0.0`：等价纯全文，适合精确数字/关键词；
- `alpha = 0.4~0.5`：关键词与语义均衡，适合术语密集的招股书；
- `alpha = 0.6`：**默认**，向量略占优，适合自然语言提问；
- `alpha = 0.8~1.0`：接近纯向量，适合口语化/同义改写。

## 4. 重排器怎么选

| 重排器 | 延迟 | 成本 | 精度 | 建议 |
| --- | --- | --- | --- | --- |
| `none` | 0 | 0 | 基线 | 压测/纯召回对比 |
| `tfidf` | ~1ms | 0 | 中高 | **默认档**；数字/实体加权对招股书友好 |
| `llm` | 0.5~3s | API 费用 | 最高 | 少量候选精排、离线评测 |
| `adaptive` | ~1ms | 0 | 随反馈增长 | 线上长期运行，配合点赞/点踩 |
| `cascade` | 0.5~3s | 较低 | 接近 llm | **精度优先的推荐档**（TF-IDF 粗排→LLM 精排 Top-10） |

响应时间 ≤3 秒的约束下：

```
  budget:  向量召回 ~30ms + BM25 ~5ms + 融合 ~1ms + 重排 + 生成
  安全组合：tfidf/adaptive 重排            → 检索总耗时 <100ms
  精度组合：cascade（LLM 只看 10 条）      → 检索总耗时 0.5~2s
  不建议 ：llm 直接重排 Top-20             → 有超 3s 风险
```

## 5. 参数清单

| 参数 | 默认 | 调大 | 调小 |
| --- | --- | --- | --- |
| `top_k` | 5 | 上下文更全，但可能引入噪声、增加生成成本 | 上下文更聚焦，可能漏信息 |
| `recall_k` | 20 | 召回更全，重排压力增大 | 更快，可能漏召回 |
| `alpha` | 0.6 | 更偏语义 | 更偏关键词 |
| `RRF_K` | 60 | 排名差异被平滑，头部更稳 | 头部名次影响更强 |
| `k1`（BM25） | 1.5 | 词频影响更大 | 词频饱和更快 |
| `b`（BM25） | 0.75 | 长度归一化更强 | 长文档不吃亏 |

## 6. 场景配方（可直接复制）

```python
from rag_core.retriever import Retriever

r = Retriever("prospectus")

# 配方 A：默认混合检索（推荐起点）
r.retrieve("兴图新科军用领域收入是多少", strategy="hybrid",
           fusion="rrf", reranker="tfidf", top_k=5, recall_k=20)

# 配方 B：精确数字核对（关键词权重提高）
r.retrieve("注册资本 5,520 万元 是哪家公司", strategy="hybrid",
           fusion="weighted", alpha=0.3, reranker="tfidf", top_k=5)

# 配方 C：口语化问题（语义为主 + LLM 精排）
r.retrieve("这家公司靠什么业务赚钱", strategy="hybrid",
           fusion="weighted", alpha=0.8, reranker="cascade", top_k=5)

# 配方 D：布尔筛选（全文通道专有能力）
r.retrieve("军用 民用", strategy="fulltext", boolean="NOT",
           reranker="none", top_k=10)

# 配方 E：高风险场景（双通道共识 + 级联精排）
r.retrieve("本次募集资金拟投资哪些项目", strategy="hybrid",
           fusion="vote", reranker="cascade", top_k=5)
```

Web 接口等价写法：

```bash
curl -X POST http://localhost:8000/api/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"军用领域收入是多少","strategy":"hybrid","reranker":"cascade","return_trace":true}'
```

## 7. 多语言支持

- 生成侧：`rag_core/generator.py` 按提问语言自动切换中/英文 Prompt 与拒答文案；
- 检索侧：默认 `bge-large-zh-v1.5` 覆盖中文；英文为主时把
  `RAG_EMBED_MODEL` 换为 `BAAI/bge-m3`（多语言）并用 `embed.set_model("bge-m3")`，
  重建向量集合后即可跨语言检索；
- 全文通道对英文按词切分，天然支持英文关键词与布尔查询。

## 8. 选型决策树

```
问题里有没有明确的数字/人名/标准名？
├─ 有 ──> hybrid(rrf) + tfidf     ← 关键词信号关键
│         再问：要不要排除某些词？
│         └─ 要 ──> fulltext + boolean NOT（或先 hybrid 再过滤）
└─ 没有（口语化/同义改写）
   ├─ 有没有 LLM API 且允许 1~3s？ ──> hybrid(weighted, alpha=0.7) + cascade
   └─ 没有 ──> hybrid(rrf) + adaptive（并持续收集点赞/点踩）
```
