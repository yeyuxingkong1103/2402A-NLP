## 1 任务描述

RAG 系统搭建后，**检索结果返回时间要优化到 3S 以内**；针对检索结果返回时间过长的问题，需要分析性能瓶颈的原因。

RAG 系统的延迟是其组成部分的延迟之和，再加上各阶段之间数据传输或排队产生的任何开销。另一方面，吞吐量通常由处理能力最低的阶段决定。

## 2 分析范围：五个阶段

通过分析以下流程的运行时间，定位影响性能的原因：

| # | 阶段 | 说明 |
| --- | --- | --- |
| 1 | 查询处理与增强 | query 改写 / 实体标注 / 关键词抽取 |
| 2 | 检索 | 查询嵌入 / 向量检索 / BM25 / RRF 融合 + 重排 / 证据页补全 |
| 3 | 上下文组装与提示工程 | 上下文拼接 / 提示词构造 / 长度预算 |
| 4 | LLM 生成 | 生成后端调用（本机 Ollama qwen2.5:3b） |
| 5 | 后处理与响应格式化 | 引用标注 / 护栏复核 / 答案组装 |

参考：https://apxml.com/zh/courses/optimizing-rag-for-production/chapter-1-production-rag-foundations/rag-performance-bottlenecks
