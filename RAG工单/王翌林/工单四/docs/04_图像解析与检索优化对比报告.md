## 4. 延迟优化（平均 3282ms → 约 2.6s）

工单四首轮评估准确率达标后，平均响应 3282ms 为唯一未达项。经分段探针（bge-m3 encode / Milvus 向量检索 / LIKE 关键词 / bge-reranker 分别计时）定位：**Milvus 检索仅 6–176ms，bge 热 encode 16–143ms，瓶颈在 bge-reranker-v2-m3 交叉编码（约 43ms/候选，24–48 候选 1.0–2.0s）且跨源存在二次精排**。优化措施（全部含工单编号注释）：

1. **智能精排池**（[text_retriever_v3.py](file:///home/dabaie/code/工单/工单四/src/text_retriever_v3.py)）：rerank 前不再对"向量分 + 关键词保底分（0.6+）"混合排序粗截断（实测粗截断会让目录/释义页把语义金标 chunk 挤出，id3/id5/id10 立即答错），改为向量候选全保留、纯关键词新增候选按命中数取 top4，精排池 ≤28 且语义零损失。
2. **跨源分数复用**（[table_retriever.py](file:///home/dabaie/code/工单/工单四/src/table_parser/table_retriever.py)）：bge-reranker `normalize=True` 的分数对同一 query 跨候选可比，表格/文本各自精排后直接按归一化分合并，消除 RRF 融合后的整池二次精排（hybrid 省 ~0.4–0.9s）；并补齐 `use_rerank=False` / 模型加载失败时的 RRF 降级路径。
3. **hybrid 两路并行**：表格召回（bge encode + Milvus）与文本召回线程并行；主检索与图像检索并行（前轮已实现），GPU 前向由 CUDA stream 自然序列化。
4. **reranker 进程级单例**（[reranker.py](file:///home/dabaie/code/工单/工单四/src/reranker.py) `get_reranker()`）：TextRetrieverV3 与 TableRetriever 共享同一 FlagReranker，消除重复加载与双份显存。
5. **生成侧数据完整性**（[llm_client_v4.py](file:///home/dabaie/code/工单/工单四/src/llm_client_v4.py)）：文本块 600→1000 字符（招股书 chunk 前部为页眉页脚，截断会丢报告期首年金额）；system prompt 增加"分别/各年度/报告期内"类问题逐年金额与占比并列的强制规范，消除 id5 只答占比漏金额的不稳定。
6. 全链路计时统一 `time.perf_counter()`，规避 WSL2 墙钟跳变（曾观测到 ±9s/33s 漂移）。

> 单题尾延迟（约 3.1–4.3s，集中在关联方/股东等长枚举题）主要来自公网 LLM 生成耗时波动（检索段稳定 ≤1.3s），不影响平均指标；演示脚本通过启动预热消除冷启动。

## 5. 关键结论

1. **总准确率 100%**：v4 连续三轮 16/16 全对（v3 同期仅 0.562–0.812），上下文召回 1.0、上下文精度 0.927、表格准确率 1.0。
2. **图像类问题从 0 到 100%**：多模态 VLM（Qwen2-VL）+ OCR + Chinese-CLIP 图文向量使 IMG-05/06 关键词与数值全对；id106 纠正了 v3 从正文误答的 10.5%/-3.2%。
3. **图像感知路由有效**：id105/id106 正确路由 image_first（置信度 0.94/0.86，召回 3 张图像），未误伤文本题。
4. **响应时间达标**：平均约 2.6s（v3 约 2.9s），优化后比首轮 v4（3.28s）下降约 20%。
5. **中英文均支持**：T11–T14 英文题全部答对，金额按双单位规范输出。
