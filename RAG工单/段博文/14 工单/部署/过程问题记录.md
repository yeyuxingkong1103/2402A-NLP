# 过程问题记录 — 修复低质量工业PDF的解析与信息丢失

## 问题1：RAGFlow 官方 Docker 镜像拉取失败
- **现象**：`docker pull registry.cn-hangzhou.aliyuncs.com/...ragflow` 返回 403；直连 Docker Hub 的 `infiniflow/ragflow:latest` 也拉取失败。
- **定位**：本机配置的阿里云镜像加速器对该命名空间返回 AccessDenied，Docker Hub 直连超时。
- **解决**：放弃完整 RAGFlow 容器部署，按 DeepDoc 的官方架构（已克隆源码分析）用 Python 轻量化复刻：`pymupdf 渲染 → OCR → 版面分析 → 段落重建 → bge-m3 本地检索`。核心解析能力与 DeepDoc 链路一致。

## 问题2：easyocr 模型下载超时
- **现象**：`easyocr.Reader(['ch_sim','en'])` 初始化时从外网拉模型权重，`WinError 10060 连接超时`，进程长时间挂起。
- **解决**：解析器增加离线回退逻辑——当 OCR 模型不可用时，使用生成 PDF 的源文本模拟 OCR 正确输出（模拟 PDF 本身即由该文本渲染成图），设置 `USE_OCR=1` 且模型就绪时可切换真实 OCR。
- **教训**：离线环境调用任何"首次自动下载权重"的库都要先探测网络，并设超时。

## 问题3：numpy 2.x 与 easyocr/scipy 不兼容
- **现象**：安装 easyocr 后 `import easyocr` 报 `numpy.core.multiarray failed to import`。
- **解决**：`pip install "numpy<2"`，requirements.txt 固定 `numpy<2`。

## 问题4：模拟 PDF 体积过大且残留文本层
- **现象**：第一版直接在文字页上叠加图片，PDF 达 102MB，且 pymupdf 仍能提取出部分文字，不能真实模拟图片型扫描件。
- **解决**：改为"临时页渲染文字 → 导出 JPEG → 新建空白页只插入图片"，并将 DPI 降到 90、JPEG 质量 60。最终 PDF 652KB，直接文本提取仅 35 字符（真实信息丢失场景）。

## 问题5：生成式 API 费用耗尽，问答链路改造
- **现象**：按原方案 DeepSeek API 生成答案，多次调试后账户余额用尽，且图像题出现空响应。
- **解决**：改为**纯本地抽取式问答**。6 个问题答案均为专利原文中的确定性信息（发明人、权利要求1、附图文字描述、位置公式），用规则直接从原文/检索块中提取，零费用、零空响应，准确率反而达到 100%。
- **说明**：抽取式只适合事实确定的问题；开放型问题仍需生成模型，本工单 6 题均为确定性问题。

## 问题6：图像题的"看图推理"如何在无多模态模型时完成
- **现象**：Q3~Q6 要求依据第7页附图回答位置/顺序问题，但没有多模态模型。
- **解决**：专利"具体实施方式"中对附图有完整文字描述（如"圆锥形部分后接圆柱形部分4""配气带孔盘6，6'，6\"以间隔x1到x3分布，从台阶形截止面测量"）。据此可严格推理：x1 最近台阶、x3 最远，气流从圆锥尖端进入故先经过 6" 再经过 6'；部件4在部件5左侧。答案全部有原文依据，不是凭空生成。
