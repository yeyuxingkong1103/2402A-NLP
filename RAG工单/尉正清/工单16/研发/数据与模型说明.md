# 数据与模型：哪些没随仓库交付、怎么补回来

上传到仓库时**手动去掉**了体积大的两处产物（渲染图与 LoRA 权重），
这篇说明它们是什么、怎么重建。**代码、配置、文档、评估结果都是全的。**

## 一、`data/images/` —— 216 张渲染图（约 42MB）

**是什么**：把 IMDR 题目里提到的 PDF 页渲染成 PNG。题面写「在文件中第7页的图片中…」，
所以**图像就是那一页**（140 DPI，约 1150×1620）。

**怎么重建**：

```bash
conda activate rag_gd2
cd 研发
python prepare_data.py --out data --eval-docs 60 --max-train 600 --ragflow --shuffle-options
```

约 5 分钟（渲染 214 份 PDF 的相关页）。**前提是要有 IMDR 附件**
（`14-17附件/original_problems/`），那份附件本身就很大、也不在仓库里 ——
路径在 `prepare_data.py` 顶部的 `SRC` 常量，换机器时改这里。

> `data/train.jsonl` 和 `data/eval.jsonl` **在仓库里**（各几百 KB）。
> 它们记录每条样本的 `image / question / answer` 格式，可以直接看格式；
> 只是里面的 `image` 路径要重跑上面的脚本才会真的有文件。

## 二、`output/qwen2vl-2b-lora-imdr/*.safetensors` —— LoRA 权重（86MB）

**是什么**：微调出来的 LoRA adapter，只有 22.4M 可训练参数，但存成 fp32 后 86MB。

**为什么不传**：GitHub 单文件上限 100MB、**超过 50MB 会告警**，而且一旦进了
git 历史就很难删（要 `git filter-repo` 重写整个历史）。为了一个能重训出来的
文件不值得。

**保留了什么**：

| 文件 | 作用 |
|---|---|
| `adapter_config.json` | **关键** —— 记录 LoRA 的 `r` / `alpha` / `target_modules` / `vision_modules`，评审据此就知道微调挂在哪 |
| `tokenizer.json` / `tokenizer_config.json` / `processor_config.json` | 分词器与图像预处理器配置 |
| `chat_template.jinja` | 对话模板 |

**怎么重建**：

```bash
conda activate rag_gd2
cd 研发
python finetune.py --config finetune_config.json
```

6GB 卡上约 70 分钟（600 样本 × 2 轮 = 150 步）。

**必须连权重一起交付的话**，用 Git LFS：

```bash
git lfs install
git lfs track "研发/output/**/*.safetensors"
git add .gitattributes 研发/output/qwen2vl-2b-lora-imdr/adapter_model.safetensors
```

（Git LFS 免费额度 1GB 存储 / 1GB 月流量，这个 86MB 的文件够用。）

## 三、评估结果**在**仓库里

`测试/results/` 下的 JSON（约 750KB）是评估报告里**所有对比数字的原始依据**，
每条都带完整的模型输出，**务必保留**：

| 文件 | 对应 |
|---|---|
| `base.json` | 基线（451584 像素，与最终模型同分辨率） |
| `base_mp602112.json` | 基线（602112 像素，第 1、2 版的对照基线） |
| `finetuned.json` | **最终交付的模型** |
| `finetuned_run1_noshuffle.json` | 第 1 版：不打乱选项、视觉塔冻结（+3.31%，假象） |
| `finetuned_run2_shuffled_frozen.json` | 第 2 版：打乱选项、视觉塔冻结（+0.00%） |
| `finetuned_run3_1epoch.json` | 第 3 版：视觉塔可训、1 轮（+3.98%） |

`研发/results_train_log*.json` 是三版的 loss 曲线，同样保留。
