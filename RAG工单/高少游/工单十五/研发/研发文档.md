## 3. 核心算法实现

### 3.1 图形语义解析（`src/figure_semantics.py`）

**目标**：把技术图纸位图转为**可检索的图像描述文本**。

流程：

```
页面位图 → 版面分析（OpenCV 连通域找候选标注框）
        → 标注识别（编号 + 部件名）
        → 部件词表构建
        → 空间/流向关系抽取
        → 生成图像描述文本 → 图形语义块
```

关键实现要点（**OCR 噪声处理**是本工单踩坑最多的地方）：

```python
# 1) OCR 在「中文部件名」与「编号」之间会残留空格（如「落 料 架 10」），
#    必须先 despace（剔除所有空白）再解析，否则会漏掉全部「部件—编号」对。
# 2) 名词前常粘连虚词/量词（如「在一个落料架10」），解析后从名称左端剥离：
_LEAD_NOISE = set("在的了个根条种一二年三多和与及或且以由从对向为是这那其又再很最均皆合适设通过把将到")
# 3) 部件名不能以纯虚词/动词收尾（过滤「设置了1」「有2」等误匹配）；
#    注意不含「个/根/条/种」——「链条」等真实部件名正以「条」收尾。
_BAD_TAIL = set("了有是为和与及或且将把通过设")
# 4) 真实部件名至少含一个「物性/机构」字，进一步过滤噪声：
_NOUN_CHARS = set("架管链机构件装置器槽槽口板杆轴轮环栓钉点座体头面")
```

产出（真实结果，图 3）：

```
【图3·技术图纸】文档第11页
图像描述（解析模块生成）：该图为一种分散装置的技术图纸，主体呈倾斜细长的杆状/臂状结构…
部件标注：8-落料架、10-落料架、11-紧固机构、12-保护管、13-链条、14-输入管 …
空间关系：紧固机构11位于落料架10之内；链条13位于保护管12之内；输入管14位于装置顶部；
          调整链条13的位置需操作紧固机构11；散料从输入管14进入后经过链条13
```

### 3.2 视觉引用识别（`src/query_understanding.py`）

识别问题中的三类视觉信号（正则见 `config.py`）：

| 信号 | 正则（节选） | 示例 → 结果 |
| --- | --- | --- |
| 图号 | `第\s*(\d+)\s*页\s*(?:的)?\s*(?:图\|附图)\s*(\d+)` / `(?:图\|附图)\s*(\d+)` | 「图 3」→ `figure_nos=[3]` |
| 页码 | `第\s*(\d+)\s*页` | 「第 11 页」→ `page_refs=[11]` |
| 部件编号 | `编号\s*(\d+)` / `部件\s*(\d+)` / `标号\s*(\d+)` | 「编号 13」→ `part_refs=[13]` |

同时做**领域同义词扩展**（散料↔块状散料/DRI、组件↔部件/机构…）并生成
**图像增强查询**（如「图3 第11页 编号13」），供多路召回使用。

### 3.3 多路召回与融合（`src/hybrid_retriever.py`）

- **多路** = [原始问题] + [查询理解产出的扩展查询（含图像增强查询）]；
- **向量通道**：对每一路分别召回后取并集（同块取最大相似度）；
- **全文通道**：多路查询一并送入倒排检索（取并集）；
- **融合**：支持 `weighted`（加权平均）、`rrf`（倒数排名融合，默认）、`voting`（投票）。

### 3.4 跨模态重排（`src/rerankers.py::CrossModalReranker`）

对「文本块 + 图形块」联合打分，信号与权重（`config.WCM_*`）：

| 信号 | 权重 | 含义 |
| --- | --- | --- |
| 视觉引用命中 | 0.30 | 用户所指图号是否出现在该块（强信号） |
| 图形块身份 | 0.18 | 候选本身是否为该图号的图形语义块（强信号） |
| 部件编号覆盖 | 0.22 | 查询中的「编号 13」等在该块中的覆盖率 |
| 页码命中 | 0.12 | 用户所指页码与该块页码是否一致 |
| 语义相似度 | 0.18 | 向量召回分（兜底） |

对**目标图形块**额外 `+0.5` 强加成，确保「第 N 页图 M」所指图纸块稳定进入 Top-K。

> **退化设计**：当查询**不含**视觉引用（纯文本问题）时，跨模态重排器自动**退化为
> `LinearFusionReranker`**，既保证纯文本问题稳健，又使分数尺度与 `MIN_ANSWER_SCORE` 阈值一致。

### 3.5 答案抽取（`src/answer_builder.py`）

按题型**分流**，取首个命中的专用抽取器（**先图文强关联、后纯文本**，避免泛化抽取器抢占图文问题）：

```
位置关系 → 部件位置 → 物料流向 → 操作对象 → 物料 → 组件 → 通用兜底
```

每个抽取器只从检索到的图文块中抽取**原文依据**，实现**零幻觉、可溯源**。

### 3.6 视觉提示工程（`src/config.py`）

```python
VISUAL_PROMPT_PREFIX = (
    "【重要】以下参考资料包含与问题相关的技术图纸描述（图纸的图像语义），"
    "请结合以下技术图纸的描述进行分析，重点核对图中部件的编号、位置关系与物料流向。\n"
)
```

当检索上下文含图形块时，`config.build_prompt(..., has_visual=True)` 注入该前缀。

## 4. 关键接口

| 接口 | 签名 | 说明 |
| --- | --- | --- |
| `QAEngine.ask` | `ask(question, conv, with_llm=False) -> QAResult` | 单轮问答主接口（含检索策略、跨模态信息、Prompt） |
| `HybridRetriever.search` | `search(query, extra_queries, analysis, top_k) -> List[Retrieved]` | 召回 + 重排 |
| `CrossModalReranker.rerank` | `rerank(query, candidates, kb, analysis, feedback, top_k)` | 跨模态重排 |
| `build_from_scratch` | `build_from_scratch(max_pages, slugs, verbose) -> dict` | 全量构建知识库 |
| `rebuild_from_chunks` | `rebuild_from_chunks(slugs, verbose) -> dict` | 复用 chunks 重建索引（跳过 OCR） |
| `to_text_only` | `to_text_only(kb) -> KnowledgeBase` | 构造「仅文本块」基线知识库 |

## 5. 代码规范

1. **工单编号注释**：每个源码文件与入口脚本的模块 docstring **必须包含**
   `工单编号: 人工智能NLP-RAG-优化技术图纸与文本的跨模态检索流程工单`。
2. **中文注释**：解释「为什么」而非「做什么」，尤其对 OCR 噪声处理、正则设计等易踩坑处。
3. **配置外置**：所有可调参数集中在 `src/config.py` 与 `src/retrieval_config.py`，
   支持环境变量覆盖（见 `config.py` 中 `os.getenv`）。
4. **零幻觉**：答案抽取只使用检索到的原文，不做自由生成。

## 6. 二次开发指南

### 6.1 更换嵌入模型

1. 在 `config.EMBEDDING_MODELS` 注册新模型（slug / 模型名 / 维度 / 说明）；
2. 用 `python build_kb.py --rebuild --models <新slug>` 生成对应向量文件 `emb_<slug>.npy`；
3. 在界面或 `RetrievalConfig(embedding_model="<新slug>")` 中选择。

### 6.2 增加新的技术图纸 / 文档

1. 把 PDF 放入 `data/`，在 `config.PDF_PATHS` 中登记；
2. 若为图纸页，更新 `config.FIGURE_PAGE_HINTS`（页码 → 图号兜底映射）；
3. 重新执行 `python build_kb.py`（首次含 OCR，较慢）。

### 6.3 调整检索策略 / 权重

- 界面：`app.py` 左侧策略面板实时切换（策略 / 融合 / 重排 / 权重 / 四项跨模态开关）；
- 代码：`RetrievalConfig(strategy=..., reranker=..., fusion=..., vector_weight=...)`；
- 跨模态重排权重：`config.WCM_VISUAL_REF` / `WCM_PART_HIT` / `WCM_PAGE_HIT` 等。

### 6.4 新增重排器

在 `src/rerankers.py` 实现 `BaseReranker.rerank`，在 `RERANKERS` 与 `RERANKER_LABEL`
（`src/retrieval_config.py`）中登记，并在 `get_reranker` 工厂中注册即可。

### 6.5 复现评测 / 消融 / 性能

```bash
python build_kb.py --rebuild   # 重建索引（如已构建可跳过）
python evaluate.py             # 优化前后对比评测
python ablation.py             # 逐项消融实验
python perf_bench.py           # 性能基准
python run_demo.py             # 演示轨迹（--baseline 基线）
streamlit run app.py           # 可视化界面
```

## 7. 已知限制与后续方向

| 限制 | 说明 | 后续方向 |
| --- | --- | --- |
| 图形语义依赖 OCR 质量 | 扫描件 OCR 噪声会影响部件名抽取 | 引入版面检测模型（如 PP-Structure）提升标注框定位 |
| 关系抽取为规则式 | 空间关系基于坐标启发式，复杂图纸可能不足 | 引入视觉语言模型（VLM）做图纸理解 |
| 嵌入走 HTTP | Ollama 单次调用 ≈2.15 s 为性能瓶颈 | 改用本地 `sentence-transformers` / ONNX |
| 单文档 | 当前仅一份专利文档 | 扩展 `DOC_COMPANY` 文档级路由支持多文档 |
