# PersonaRAG · 多角色智能顾问系统 · 学习计划

> 面向"想从这个项目学 RAG"的人：从哪读起、每个文件在讲什么、知识点对应哪些资料、动手改什么。
> 代码总量：17 个 Python 文件、约 1810 行纯代码（注释与文档字符串占非空行的 51%），前端 3 个文件共 1221 行。

---

## 一、这个项目是什么

一个**多角色 RAG 问答系统**：用户选一个角色（法律顾问 / 心理专家 / 虚拟朋友），提问后系统先去该角色对应的知识库里检索资料，再让大模型带着资料回答，同时记住对话历史和用户长期偏好。

它在架构上刻意做全了 RAG 的每个环节，适合当作学习样本：

- **入库链路**：文档解析（pdf/docx/wps/扫描件）→ 五种切分策略 → 向量化 → 写入 Milvus → 重建 BM25
- **检索链路**：向量召回 + BM25 召回 → RRF 融合 → CrossEncoder 重排 → 相似度阈值过滤
- **记忆链路**：Redis 短期记忆（20 条滑动窗口）+ Milvus 长期记忆（按 user_id 过滤）
- **生成链路**：角色化 system prompt → DeepSeek 流式生成 → 后处理
- **工程链路**：FastAPI 服务化、知识库增删改、端到端测试、RAGAS 评测

## 二、架构总览

### 分层

```
接入层    main.py（FastAPI，12 个接口，lifespan 里预加载所有重资源）
            │
编排层    retriever.py（检索编排）        llm_client.py（生成 + 提示词 + 后处理）
            │                                    │
存储层    db_milvus.py（向量库 + 长期记忆）  db_redis.py（短期记忆）  db_mysql.py（角色/日志）
            │
外部模型  bge-m3（向量，1024 维，本地）  bge-reranker-large（重排，本地）  DeepSeek API（生成，云端）
```

### 一次提问的完整数据流

```
用户提问
  ├─ 1. Redis 取最近 20 条对话（短期记忆）
  ├─ 2. 向量召回：问题向量化 → Milvus 取 top 10
  ├─ 3. BM25 召回：jieba 分词 → rank_bm25 取 top 10
  ├─ 4. RRF 融合两路排名（等权 0.5/0.5，c=60）
  ├─ 5. CrossEncoder 重排 → 保留 top 5
  ├─ 6. 阈值过滤：score < 0.3 的丢掉
  ├─ 7. 拼上下文：角色提示词 + 资料 + 历史 + 问题
  ├─ 8. DeepSeek 流式生成 → 后处理
  └─ 9. 写回 Redis（短期记忆）+ MySQL（对话日志）
```

### 三个设计要点（面试常问）

1. **每个角色一个集合**：`rag_legal / rag_psychology / rag_companion`，靠 `config.get_collection_for_role()` 路由，知识互不污染；长期记忆单独一个集合，靠 `user_id` 字段过滤。
2. **双路召回 + 重排**：向量擅长语义（"半夜装修很吵" ≈ 噪声扰民），BM25 擅长关键词（法条号、"第二百八十八条"），RRF 只用排名融合，避免两种分数不可比。
3. **短期 / 长期记忆分离**：短期是"这轮对话的上下文"，放 Redis 且会过期；长期是"值得记住的用户画像"，放 Milvus 且永久。

## 六、六个动手实验（都有可观察指标）

| # | 改什么 | 观察什么 |
|---|--------|----------|
| 1 | `CHUNK_SIZE` 300 → 800 | 检索台命中条数与内容完整度 |
| 2 | `EnsembleRetriever(weights=[1.0, 0.0])` 与 `[0.0, 1.0]` | 法条号查询 vs 口语化查询的命中差异 |
| 3 | `SCORE_THRESHOLD` 0.3 → 0.6 | 引用资料条数何时变 0、回答何时开始"编" |
| 4 | 去掉 `CrossEncoderReranker`，直接 `ensemble.invoke()` | 前 3 条排序变化，理解重排价值 |
| 5 | `/memory/clear` 前后问同一句话 | "对方 / 他"这类指代能否对上 |
| 6 | 改一次切分参数后跑 `tests/test_ragas.py` | 四个指标涨跌，体会"调参要有度量" |

**调试技巧**：用 `/cases` 当探针——它只跑检索不调 LLM，改检索参数时用它验证最快、不花钱；Swagger（`/docs`）可以零代码调所有接口。

## 八、进阶方向

- 查询改写：一个问题扩成多个 query 分别召回再合并
- Parent-Child 分块：小块检索、大块喂给模型
- 加权 RRF：向量与 BM25 不再等权，按查询类型动态调
- 标量过滤：按来源 / 章节 / 时间过滤后再做向量检索
- 语义缓存：Redis + 向量相似度命中相似问题直接返回
- 把 RAGAS 接进 CI，改检索参数就能看到指标回归
- 并发压测：项目自带 `persona_rag_test.jmx`，可直接用 JMeter 跑
