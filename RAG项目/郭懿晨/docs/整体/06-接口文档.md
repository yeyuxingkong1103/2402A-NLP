# 06 · 接口文档（API 全清单）

> **Base**：`http://127.0.0.1:8000`（FastAPI）。Swagger：`/docs`。返回格式：JSON；上传格式：`multipart/form-data`。

## 调用总览

**整体流程：上传 → 启动 → 轮询 → 问答（一条线）**

```text
POST /api/files/upload            ──▶  得 {document_id, task_id}
POST /api/tasks/{id}/start        ──▶  后台异步构建
GET  /api/tasks/{id}（轮询）        ──▶  status=completed 就绪
POST /api/chat                    ──▶  检索问答
```

**任务状态流转：`pending → running → completed / failed`**

```text
        POST /start
pending ──────────▶ running ──▶ completed
                          └────▶ failed（看 error_message）
```

> `pending`＝上传时创建的任务；`running`＝`/start` 后后台构建中；`completed/failed`＝终态。`/start` 响应里的 `status:"scheduled"` 仅是调度确认，实际状态以 `GET /api/tasks/{id}` 为准。

## 一、系统

| 方法 | 路径 | 说明 | 响应 |
|---|---|---|---|
| GET | `/` | 前端首页 | `frontend/index.html`（SPA） |
| GET | `/health` | 健康检查 | `{"status":"ok"}` |
| GET | `/docs` | Swagger UI | HTML |

## 二、文件上传

| 方法 | 路径 | 说明 | 请求 | 响应 |
|---|---|---|---|---|
| POST | `/api/files/upload` | 上传 PDF → 保存文件 + 创建 Document + BuildTask | `file`(PDF) | `{document_id, task_id}` |

**失败**：非 PDF → 400 `{"detail":"只允许上传 PDF 文件"}`；与库内 PDF 内容相同（sha256 判重）→ 409 `{"detail":"档案库已存在相同内容的 PDF（…），未重复入库"}`。

## 三、任务

| 方法 | 路径 | 说明 | 响应 |
|---|---|---|---|
| POST | `/api/tasks/{task_id}/start` | 启动构建（BackgroundTasks 后台执行） | `{task_id, status:"scheduled"}` |
| GET | `/api/tasks/{task_id}` | 查询任务状态 | 任务 JSON |

**任务 JSON**：
```json
{
  "task_id": "…", "document_id": "…",
  "step": "chunking", "progress": 45, "status": "running",
  "error_message": null, "created_at": "…", "updated_at": "…"
}
```
**失败**：任务不存在 → 404 `{"detail":"任务不存在"}`。

**轮询约定**：
- 调用 `/start` 后开始轮询 `GET /api/tasks/{task_id}`，间隔 **1~2 秒**。
- `status` 为 `completed` 或 `failed`（终态）时**停止轮询**；`failed` 时读取 `error_message` 定位原因。
- **`completed` 之前禁止调用 `/api/chat`**——问答只查已入库向量，索引未就绪会答非所问或直接兜底。
- ⚠️ `/start` 不校验任务当前状态：对 `running`/`completed` 的任务重复调用会再次触发一次后台构建（返回 200 `scheduled`）。**只在首次启动时调用一次**。

## 四、文档 & 向量库

| 方法 | 路径 | 说明 | 响应 |
|---|---|---|---|
| GET | `/api/documents` | 文档列表 | `[{document_id, file_name, file_path, status, created_at}]` |
| GET | `/api/vector-store` | 向量库记录列表（前端「数据矩阵」页展示，单次上限 1000 条） | `[{id, chunk_id, document_id, page, category, text, …payload}]` |
| GET | `/api/categories` | MinerU 标签类别列表（前端「数据矩阵」做类别筛选） | `["正文","表格","标题", …]` |

## 五、问答（v2）

| 方法 | 路径 | 说明 | 请求 | 响应 |
|---|---|---|---|---|
| POST | `/api/chat` | 检索问答（**v2：RRF 召回 → 粗排 → 精排 → Ollama 生成**） | `{"question": "…"}` | `{answer, citations[], fallback}` |

**响应字段**：
- `answer`：生成答案；无依据/域外时固定兜底 `知识库中未找到相关依据。`
- `citations[]`：每项 `{document_id, file_name, page, category, text, score}`（v2 下 score 为精排相关性分 0~1）
- `fallback`：`true`（兜底/拒答）或 `false`（有依据）

**使用约定**：
- 先看 `fallback`：`true` → 直接展示兜底话术（`citations` 为空，无需渲染）；`false` → 展示 `answer` 并按 `citations` 逐条给出来源。
- `score` 为 0~1 相关性分，可用于引用排序或强弱样式区分。

**失败**：参数格式不正确 → 422；精排模型缺失/加载失败、Ollama 调用失败等 → 500 可诊断错误（不静默降级）。

**精排依赖**：`rerank_enabled=true`（默认）时走精排，需本地 `bge-reranker-v2-m3` 模型路径可用（FlagEmbedding，见 `config.py`）；模型路径不存在 → 500。设 `rerank_enabled=false` 时退化为 v1：直接召回 + 阈值过滤，不加载精排。

## 六、错误码汇总

| 码 | 场景 |
|---|---|
| 400 | 上传非 PDF / 读取上传文件失败 |
| 404 | 任务不存在 |
| 409 | 上传与库内 PDF 内容相同（判重拒绝） |
| 422 | 请求参数格式不正确（如空/缺 question） |
| 500 | 内部错误：精排模型缺失/加载失败、Ollama 调用失败等（v2） |

## 七、调用示例

```bash
# 健康检查
curl http://127.0.0.1:8000/health

# 上传 PDF
curl -F "file=@GB_T_44653-2024_六氟化硫气体现场循环再利用导则.pdf" \
     http://127.0.0.1:8000/api/files/upload
# → {"document_id":"…","task_id":"…"}

# 启动构建
curl -X POST http://127.0.0.1:8000/api/tasks/<task_id>/start
# → {"task_id":"…","status":"scheduled"}

# 查询任务（轮询直到 status=completed/failed，间隔 1~2s）
curl http://127.0.0.1:8000/api/tasks/<task_id>

# 问答（v2 走重排链路；completed 之后才能调用）
curl -X POST http://127.0.0.1:8000/api/chat \
     -H "Content-Type: application/json" \
     -d '{"question":"本标准适用于哪些对象？"}'
```

## 八、总结

**四个接口一条线：上传 → 启动 → 轮询 → 问答。**

1. **上传** `/api/files/upload` → 得 `task_id`；
2. **启动** `/api/tasks/{id}/start` → 调度后台构建（只调一次）；
3. **轮询** `/api/tasks/{id}` → 1~2s/次，到 `completed/failed` 终态即停；
4. **问答** `/api/chat` → 索引就绪（`completed`）后才能调用。

**跳步后果**：任务未建/不存在 → 404；索引未就绪就问答 → 兜底或答非所问。
