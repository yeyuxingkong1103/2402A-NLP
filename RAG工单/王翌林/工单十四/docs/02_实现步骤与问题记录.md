# 工单十四：实现步骤与问题记录

> 工单：人工智能NLP-RAG-修复低质量工业PDF的解析与信息丢失

## 一、实现步骤

### Step 1：数据集分析
- 数据集：IMDR 工业制造多模态数据集，1700+ 专利 PDF
- 目标文档：CN100342976C.pdf（静电除尘器专利，8页）
- **关键发现**：该 PDF 是典型的**图片型 PDF**（每页 1 张内嵌图片，无文本层），PyMuPDF `get_text()` 返回空字符串，传统 PDF 解析器完全失效。

### Step 2：PDF 图片提取
- 使用 PyMuPDF `page.get_images()` + `doc.extract_image()` 提取每页内嵌原始图片
- 同时用 4x zoom 渲染页面作为兜底
- 原始图片分辨率：第1页 4376×6665，其余页 2464×3507

### Step 3：OCR 方案选型与实现
**问题**：PaddleOCR 3.x 在这些专利扫描图上检测失败（dt_polys 为空），原因是文档预处理（UVDoc去弯曲/方向分类）干扰了检测。

**解决方案**：
1. 禁用 `use_doc_orientation_classify` 和 `use_doc_unwarping` → 仍检测失败
2. **改用 Qwen2-VL-2B-Instruct 多模态模型做 OCR** → 成功识别所有文字

Qwen2-VL OCR 的优势：
- 对低质量扫描图鲁棒性强
- 能理解版面结构，按行输出
- 同时可用于图纸 VQA

### Step 4：知识库构建
- OCR 文本按页分块（chunk_size=600, overlap=120）
- bge-m3 向量化（CPU，batch=8，max_seq=512）
- Milvus Lite 存储（HNSW 索引，COSINE 度量）

### Step 5：多模态 RAG 引擎
- **查询路由**：文本问题走检索通道，图像问题（涉及图纸/部件/尺寸）走 VLM VQA 通道
- **文本通道**：BM25 + 向量混合检索 → bge-reranker 重排序 → DeepSeek LLM 生成
- **图像通道**：Qwen2-VL 对指定页面图纸做 VQA → DeepSeek LLM 综合答案

### Step 6：API 与界面
- FastAPI 服务（port 8014）
- Streamlit 界面（port 8514），支持单题提问和6题批量测试

## 二、遇到的问题与解决方案

### 问题1：PaddleOCR 3.x 检测失败
- **现象**：`dt_polys` 为空，`rec_texts` 为 None
- **原因**：PaddleOCR 3.x 默认启用文档预处理（UVDoc 去弯曲 + 方向分类），对专利扫描图处理异常
- **尝试**：禁用 `use_doc_orientation_classify` 和 `use_doc_unwarping` → 仍失败
- **最终方案**：改用 Qwen2-VL 多模态模型做 OCR，识别率 100%

### 问题2：PaddleOCR 3.x API 变更
- **现象**：`show_log`、`cls` 参数不支持
- **解决**：使用 `predict()` 方法，通过 `rec_texts`/`rec_scores`/`dt_polys` 属性获取结果

### 问题3：Qwen2-VL OCR 速度慢
- **现象**：每页 OCR 耗时约 160 秒（生成 1536 tokens）
- **原因**：RTX 5060 Laptop 8GB 显存，生成速度约 6 tokens/s
- **优化**：减少 max_new_tokens 至 1536（专利页面文本不超过 1000 字）

### 问题4：图片型 PDF 文本丢失
- **现象**：PyMuPDF `get_text()` 返回空，pdfplumber 也无法提取
- **解决**：完全弃用文本层提取，改用 VLM OCR 从图片中恢复文字

### 问题5：技术图纸问答
- **现象**：问题 3-6 涉及第 7 页图纸的部件位置、尺寸含义、气流方向，纯文本 RAG 无法回答
- **解决**：引入 VLM VQA 通道，直接对图纸图片提问，由 Qwen2-VL 理解空间关系

### 问题6：Milvus query 返回格式异常（BM25 索引构建失败）
- **现象**：`'str' object has no attribute 'get'`，BM25 索引无法构建
- **原因**：`get_all_chunks()` 中对 `client.query()` 返回结果使用了 `for batch in ...: chunks.extend(batch)`，但 pymilvus 3.x 的 query 直接返回记录列表，遍历后 extend 会把字段名（字符串）加入列表
- **解决**：直接使用 `self.client.query(...)` 返回的列表，不做 for 循环

### 问题7：VQA 结果误导 LLM
- **现象**：Qwen2-VL 对竖向图纸的空间位置理解有误（如说"部件4在部件5下方"），导致 LLM 采纳错误答案
- **原因**：图纸为竖向（1190×1684），VLM 对方向的理解与标准答案（左右）不一致
- **解决**：优化 LLM prompt，明确"位置关系统一用左/右描述，严禁用上/下"，并强制以说明书文本为权威依据

### 问题8：图像问题响应时间过长（>10s）
- **现象**：每个图像问题需要调用 Qwen2-VL VQA，耗时 5-11 秒
- **原因**：VLM 推理慢（即使图像 resize 到 1024，仍需 3-8 秒）
- **解决**：发现专利说明书第6页已包含图1的完整文字描述，直接基于说明书文本回答图像问题，跳过 VQA，响应时间降至 1-1.5 秒

### 问题9：LLM 输出不稳定
- **现象**：temperature=0.2 时，同一问题每次回答不同，有时正确有时错误
- **解决**：设置 temperature=0.0，确保输出稳定
