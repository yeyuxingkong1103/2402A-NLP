# RAG-PDF 问答系统优化方案文档

> 工单编号：人工智能NLP-RAG-基于PDF文档的问答系统优化
> 版本：V2.0 | 日期：2026-09-29

## 一、优化目标

| 指标 | 工单一（优化前） | 工单二目标 | 实际达成 |
|------|----------------|-----------|---------|
| 问答准确率 | 关键词命中 22/28 (78.6%) | ≥90% | 见测试报告 |
| 平均响应时间 | ~16.7秒 | ≤3秒 | 见测试报告 |
| 检索精确度 | 5条/题，含噪声 | 更精准，噪声更少 | 见对比分析 |
| 系统稳定性 | 正常 | 高可用 | 进程级单例+缓存 |

## 二、优化前问题分析

### 2.1 响应时间瓶颈定位（优化前 ~16.7秒/题）

通过在检索链路各阶段插入计时日志，定位到以下瓶颈：

| 阶段 | 耗时（约） | 占比 | 原因分析 |
|------|-----------|------|---------|
| 向量检索（Milvus） | 0.5-1.0s | 6% | 正常 |
| BM25 检索（内存） | 0.1s | 1% | 正常 |
| RRF 融合 | 0.1s | 1% | 正常 |
| **CrossEncoder 重排** | **8-12s** | **60%** | bge-reranker-large 在 CPU 上对 ~20 条候选逐条推理 |
| **DeepSeek LLM 生成** | **5-8s** | **35%** | max_tokens=2048，生成长文本耗时 |
| 总计 | ~16.7s | 100% | — |

### 2.2 检索精度问题

- 分块过大（500字）：向量语义被稀释，召回噪声多
- 重排保留5条：上下文过多，LLM 容易被无关内容干扰
- 无结果缓存：相同问题每次都走完整链路

## 三、优化措施

### 3.1 PDF 解析优化

| 项目 | 优化前 | 优化后 | 说明 |
|------|--------|--------|------|
| 文本清洗 | 无 | 新增断行合并+空白压缩 | 招股书中文字被换行切断很常见，合并后语义更完整 |
| 页眉页脚 | 无 | 连续重复极短行过滤 | 减少噪声块入库 |

### 3.2 分块策略优化（核心）

| 参数 | 优化前 | 优化后 | 理由 |
|------|--------|--------|------|
| CHUNK_SIZE | 500 | 400 | 语义更聚焦，向量召回精度提升 |
| CHUNK_OVERLAP | 80 | 50 | 减少冗余，仍兜住切口 |
| 分隔符优先级 | 英文句号靠前 | 中文句号/分号优先 | 更贴合中文文档句法边界 |
| 块总数 | 1405 | 1621 | 块更小→数量更多→检索更精准 |

### 3.3 检索参数优化（核心）

| 参数 | 优化前 | 优化后 | 理由 |
|------|--------|--------|------|
| TOP_K_RECALL | 10 | 6 | 重排候选从 ~20 降到 ~12，CPU 重排耗时近半 |
| TOP_K_RERANK | 5 | 3 | 喂给 LLM 的上下文更少更精，生成更快 |
| SCORE_THRESHOLD | 0.3 | 0.25 | 候选少了适当放低门槛保召回 |
| RRF 权重 | [0.5, 0.5] | [0.5, 0.5] | 保持不变，两路平权 |

### 3.4 结果缓存优化（新增）

| 机制 | 说明 |
|------|------|
| 检索结果 LRU 缓存 | 相同 query+top_k+阈值第二次直接命中缓存，跳过重排全部耗时 |
| LLM 答案 LRU 缓存 | 相同 query+上下文指纹第二次直接返回缓存答案 |
| 缓存容量 | 256 条（maxsize=256） |
| 缓存清除 | 入库后自动清空，确保新文档可检索 |

### 3.5 LLM 参数优化

| 参数 | 优化前 | 优化后 | 理由 |
|------|--------|--------|------|
| MAX_TOKENS | 2048 | 768 | 事实型问答不需要长篇大论，生成更快 |
| TEMPERATURE | 0.3 | 0.1 | 回答更稳定，减少随机性 |
| 系统提示词 | 较长 | 精简 | 减少输入 token |

### 3.6 入库优化

| 项目 | 优化前 | 优化后 |
|------|--------|--------|
| batch_size | 10 | 25 |
| 去重查询 | 全量拉取 | 空集合跳过，非空才查 |
| 集合加载 | 无 | 查询前显式 load_collection |

## 五、技术架构

### 5.1 系统架构（优化后）

```
用户提问
  │
  ├─ 检索结果缓存（LRU 256）── 命中 ── 直接返回
  │         │
  │       未命中
  │         │
  ├── 向量检索（Milvus, bge-m3, k=6）
  ├── BM25 检索（jieba 分词, k=6）
  │         │
  │    RRF 融合（weights=[0.5,0.5], c=60）
  │         │
  ├── CrossEncoder 重排（bge-reranker-large, top_n=3）
  │         │
  ├── 分数过滤（threshold=0.25）
  │         │
  ├── LLM 答案缓存（LRU 256）── 命中 ── 直接返回
  │         │
  │       未命中
  │         │
  └── DeepSeek LLM 生成（max_tokens=768, temp=0.1）
            │
          返回答案+引用
```

### 5.2 模块清单

| 模块 | 文件 | 优化要点 |
|------|------|---------|
| 配置中心 | config.py | 全部优化参数集中管理 |
| 日志 | logger.py | 双输出+轮转 |
| PDF 解析 | pdf_parser.py | 文本清洗+断行合并 |
| 文本切分 | text_splitter.py | 400/50+中文分隔符优化 |
| Milvus 数据层 | db_milvus.py | 独立集合+批次25+空集合跳过去重 |
| 检索 | retriever.py | LRU缓存+候选收敛+计时日志 |
| LLM 客户端 | llm_client.py | 答案缓存+精简提示词+768token |
| 主应用 | main.py | 计时指标+缓存统计+清缓存 |
| 入库脚本 | ingest_pdf.py | 独立入库+清缓存 |

## 六、部署与运行

### 6.1 环境依赖

- Python 3.12+
- Milvus 3.0（WSL2 Docker）
- DeepSeek API
- 本地模型：bge-m3、bge-reranker-large

### 6.2 启动流程

```bash
# 1. 安装依赖
pip install -r deploy/requirements.txt

# 2. 启动 Milvus（WSL2 Docker）
docker start milvus-standalone milvus-etcd milvus-minio

# 3. 入库
cd src && python ingest_pdf.py

# 4. 启动服务
python main.py
# 或 deploy/start.sh

# 5. 访问
# http://localhost:8000/web/index.html
```

### 6.3 测试

```bash
cd tests
python test_questions.py
```
