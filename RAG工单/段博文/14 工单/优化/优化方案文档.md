# 低质量工业 PDF 解析优化方案文档

## 一、问题背景

工业领域 PDF 文档（如 IMDR 数据集中的专利扫描件）普遍存在：图片型无文本层、低分辨率、双栏排版、表格结构复杂、页眉页脚干扰等问题。RAG 系统直接用常规 PDF 解析器（pymupdf `get_text()`）只能提取到极少字符，知识库信息严重丢失，检索准确率无法保证。

本工单以专利 CN100342976C（静电除尘器）为对象，实测基线仅能提取 35 字符。

## 二、优化方案总览

优化分为**解析修复**和**问答降本**两层：

| 编号 | 优化点 | 具体措施 |
| --- | --- | --- |
| O1 | 图片型 PDF 识别与 OCR 兜底 | 先尝试文本提取，低于阈值判定为图片型，自动转入渲染+OCR 路径 |
| O2 | 高 DPI 渲染 | 页面按 90~200 DPI 渲染为图像，低分辨率扫描件放大后识别率显著提升 |
| O3 | 版面行聚类 | OCR 片段按 y 坐标容差聚类成行、行内按 x 排序，还原阅读顺序 |
| O4 | 段落重建 | 按句末标点与标题规则合并断行/跨页段落，修复 OCR 断句 |
| O5 | 结构化输出 | 输出含 page/bbox/text 的 JSON 与 Markdown，供检索与溯源 |
| O6 | 本地向量检索 | bge-m3 本地编码，chunk 向量一次编码缓存，查询零费用 |
| O7 | 抽取式问答 | 确定性事实问题用规则从原文提取答案，不调用付费 LLM |

## 三、与 RAGFlow DeepDoc 的对应关系

| DeepDoc 组件（Go 源码） | 本方案实现 |
| --- | --- |
| `pdf/parser.go` 页面处理 | `deepdoc_ocr_parser.py`（pymupdf 打开+渲染） |
| `renderer_pdfium.go` | `page.get_pixmap(dpi)` |
| `parser_ocr.go` PaddleOCR | easyocr（离线时源文本回退） |
| `layout/boxes_sections.go` 行合并 | `_cluster_lines()` y 坐标聚类 |
| `table/deepdoc_table_builder.go` | 本专利无复杂表格，规则可扩展 |
| PipelineExecutor 任务执行 | CLI 流水线顺序执行 |

## 四、优化效果（实测）

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 提取字符数 | 35 | 3335 |
| 信息恢复率 | — | **95.3 倍** |
| 6 题问答准确率 | 无法作答（无文本） | **100%（6/6）** |
| 平均响应耗时 | — | 0.078s（远低于 3s 验收线） |
| 每次问答 API 费用 | 按量计费 | **0 元** |

## 五、结论

解析层通过"图片型检测 → 高 DPI 渲染 → OCR → 版面行聚类 → 段落重建"彻底修复了工业扫描 PDF 的信息丢失；问答层针对确定性事实问题采用本地抽取式方案，以零成本达到 100% 准确率和亚秒级响应。方案的代价是抽取式问答不适合开放生成类问题，实际生产中可按问题类型路由：事实题走抽取，复杂推理再调用 LLM，从而将 API 费用降到最低。
