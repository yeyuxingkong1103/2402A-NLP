# 容错机制清单与长时间运行方案

> **工单编号**：人工智能NLP-RAG-Graph RAG优化任务
> 实现位置：`w9/runtime9.py`（`FAULT_MATRIX` 常量，界面「系统状态」页同步展示）

---

## 一、容错机制清单（8 类）

| # | 故障 | 症状 | 处理方式 | 实现位置 |
| --- | --- | --- | --- | --- |
| 1 | 空输入 / 超长输入 | 用户直接回车或粘贴整篇文档 | `validate_question` 入口校验，返回可读提示（上限 2000 字） | `w9/runtime9.py` |
| 2 | Ollama 不可用 / 模型缺失 | 连接被拒、模型未 pull | 降级为**抽取式答案**（图谱事实 + 原文片段拼装），标记 `degraded` 并写明原因 | `w9/qa_v2.py:_extractive_answer` |
| 3 | 09 图谱加载失败 | `kg.pkl` 缺失或损坏 | 退化为纯文本 RAG，`degraded=True` 并给出「请先运行 `python -m w9.kg_merge`」 | `w9/qa_v2.py:get_kg9` |
| 4 | 子图检索失败 | 图谱结构异常导致遍历报错 | 跳过图谱通道，仅用文本通道，**不中断问答** | `w9/retrieve_v2.py` |
| 5 | Qdrant 排他锁冲突 | `Storage folder is already accessed by another instance` | 09 使用独立副本 `data/qdrant`，与 08 互不干扰；健康检查给出明确指引 | `w9/config9.py` |
| 6 | Reranker 显存不足 / 加载失败 | CUDA OOM 或权重缺失 | `rerank_final` 捕获异常后按原召回分排序 | `w9/retrieve_v2.py:rerank_final` |
| 7 | 上传文档解析失败 | 加密 PDF / 扫描件无文字层 | 返回可读错误并保留会话，不写入任何索引 | `app.py` 上传处理 |
| 8 | 磁盘写满 / 日志写失败 | 日志或产物写不进去 | 日志初始化失败降级为 `NullHandler`，不影响主链路；健康检查暴露磁盘余量 | `w9/runtime9.py:get_logger / disk_status` |

### 设计原则

1. **降级必留痕**：任何降级都写进 `degraded` / `degraded_reason`，
   界面与评估结果都能看到，**不静默失败**。
2. **单点失败不扩散**：一个通道（图谱 / 向量 / 全文）失败，其余通道继续工作。
3. **面向用户的错误是可读的**：异常被转成「怎么办」的指引，而不是英文堆栈。

### 硬性要求0 相关：禁止静默下载

`w9/compat.py` 在**任何** transformers / sentence_transformers 导入之前置
`HF_HUB_OFFLINE=1` / `TRANSFORMERS_OFFLINE=1` / `MODELSCOPE_OFFLINE=1`；
Ollama 侧只调用 `/api/chat`、`/api/generate`、`/api/tags`，**不存在 `/api/pull` 调用路径**。

## 二、长时间运行方案

| 机制 | 参数 | 实现 |
| --- | --- | --- |
| **日志轮转** | 8 MB × 5 份 | `RotatingFileHandler`，`data/logs/w9.log` |
| **内存监控** | 阈值 6000 MB | `memory_status()` 返回 `rss_mb / over` |
| **磁盘监控** | — | `disk_status()` 返回剩余空间 |
| **健康检查** | — | `health_check()` 覆盖 graph / qdrant / llm / reuse / memory / disk |
| **模型常驻** | `keep_alive=30m` | 复用 08 的预热策略，避免每题冷启动 |
| **断点续抽** | 单行 append | 抽取每块完成即落 JSONL，进程中断后可 `--resume` |

### 冷启动的实测数据（重要）

| 场景 | 首题耗时 | 说明 |
| --- | --- | --- |
| **未预热** | **51.3s（08）/ 52.9s（09）** | 加载 bge-m3 + Reranker + BM25 倒排索引 + Ollama 入显存 |
| **已预热** | 2.97s（08） | 预热耗时 70.5s，一次性 |

→ **服务启动时必须先预热**，否则第一题会被冷启动拖到 50 秒以上。
`w9/run_eval.py` 与 `app.py` 均在计时/交互前调用 `rag.warmup()`。

### 健康检查用法

```bash
python -c "from w9.runtime9 import health_check; import json; print(json.dumps(health_check(), ensure_ascii=False, indent=2))"
```

## 三、已知限制（如实标注）

| 限制 | 说明 | 影响 |
| --- | --- | --- |
| 未做并发压测 | 交付形态为单机单用户（Streamlit + 本地嵌入式 Qdrant，同目录单实例） | 工单「高并发环境下稳定运行」**未验证** |
| Qdrant local 排他锁 | 同一存储目录只能被一个进程打开 | 09 已用独立副本规避；若要多实例需切 server 模式 |
| 冷启动 70s | 本机模型较多，首次预热慢 | 长时运行场景下只发生一次 |
| 3B 模型能力上限 | 结构化抽取退化率实测 40% | 图谱 LLM 层覆盖度受限，见 `docs/10` |
