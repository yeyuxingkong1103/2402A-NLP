# 工单9 Graph-RAG优化与评估｜项目总结
工单编号：人工智能NLP‑RAG‑Graph RAG 优化任务

## 1.任务完成情况
✅ 基于工单8代码副本搭建独立工单9项目，基线工单8代码完整保留，用于优化前后对比。
✅ 从Prompt构建、实体关系抽取、检索策略、生成输出四个层面完成Graph-RAG系统优化。
✅ 新增eval_ragas.py评估脚本，实现context_precision、context_recall两个RAG核心指标计算。
✅ 完成10条测试问题批量自动评测，对比优化前后指标变化。
✅ Web问答页面正常交互，可在线提问，返回图谱三元组与原文片段。
✅ 知识图谱可视化graph_visual.html可正常打开，查看实体关系。
✅ 全套交付文档：设计.md、研发.md、测试.md、优化.md、部署.md、总结.md。

## 2.学习收获
1. 掌握RAG系统优化的四个核心维度：提示词、实体抽取、检索策略、生成输出。
2. 理解RAG评估指标context_recall（召回）、context_precision（精度）含义，学会量化评估RAG效果。
3. 学会基线对照实验：保留原始版本，对比优化前后指标，验证优化策略是否有效。
4. 掌握检索结果排序、Top-K截断优化手段，了解该方法对精度、召回带来的影响。
5. 熟悉Graph-RAG知识图谱增强检索的调优思路，理解图谱噪声对问答效果的影响。

## 3.项目难点
1. 平衡召回率和精度：Top3截断可以提升精度，但会少量损失召回，需要权衡取舍。
2. 实体标准化：同一实体多种写法会造成图谱检索漏召回，需要做实体清洗。
3. 评估指标设计：实训简易版指标基于文本匹配，和完整RAGAS库大模型评测存在差异。

## 4.系统不足
1. 三元组仍为手工预置，没有实现从PDF文档自动抽取实体关系。
2. 检索使用简单关键词匹配，没有向量语义检索。
3. 没有接入大模型，不能把检索结果整理成自然语言答案。
4. 简易评估脚本基于文本字符串匹配，不是RAGAS原生大模型评估。

## 5.后续拓展方向
1. 接入大模型，基于Prompt自动从文档抽取三元组，实现端到端Graph-RAG。
2. 接入完整RAGAS库，使用大模型做更准确的指标评估。
3. 增加Reranker重排序模型，进一步优化检索结果排序。
4. 接入LLM，将三元组+上下文组装成Prompt，生成通顺的自然语言回答。
5. 图谱持久化，接入Neo4j图数据库，程序重启图谱数据不丢失。

## 6.实训整体总结
工单5→6→7→8→9完整走完RAG全流程：普通向量RAG→混合检索RAG→RAG评测→基础Graph-RAG→Graph-RAG优化与量化评估。
Graph-RAG通过知识图谱引入实体关系信息，解决普通向量RAG实体关系问答容易漂移的问题；同时Graph-RAG也存在依赖实体关系抽取质量的短板。
通过工单9的优化实验验证：检索结果排序、Top-K截断可以有效提升上下文精度，是RAG系统调优常用手段。
