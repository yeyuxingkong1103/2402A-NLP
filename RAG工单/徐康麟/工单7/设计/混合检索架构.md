## 一、目标与范围

### 1.1 目标

把 工单4/5 里**写死的一条**检索链路（向量通道 + BM25 通道 → RRF 融合 → 八维特征重排），
重构为**可配置、可切换、可解释**的检索策略层，使系统支持工单要求的三种模式：

| 模式 id | 中文名 | 一句话链路 |
| --- | --- | --- |
| `vector` | 向量检索 | 嵌入模型 → 余弦召回 Top-K → 重排 |
| `fulltext` | 全文检索 | 倒排索引（布尔/短语/模糊/多字段）→ BM25 打分 → 重排 |
| `hybrid` | 混合检索 | 两路**并行**召回 → 融合算法（加权平均 / RRF / 投票）→ 重排 |

## 三、三种检索模式的链路与差异

### 3.1 模式对照表

| 维度 | `vector`（向量检索） | `fulltext`（全文检索） | `hybrid`（混合检索） |
| --- | --- | --- | --- |
| **输入** | 自然语言问句（整串嵌入，**不做 DSL 解析**） | 问句或查询 DSL（支持布尔/短语/模糊/字段限定） | 同一个问句**同时**喂给两路：向量路按自然语言整串，全文路按 DSL 解析 |
| **召回方式** | `search_vectors`：L2 归一化后的内积（= 余弦），FAISS `IndexFlatIP` 或 numpy 精确检索 | `evaluate_query` 在倒排索引上做集合运算（AND/OR/NOT + 短语位置匹配 + 模糊词表扩展），再在命中行上算 BM25 | 两路并行召回，候选集 = 两路 Top-K 的**并集**（实测一例：20+20 → 37 条候选） |
| **打分** | 余弦相似度，值域约 `[-1, 1]`，实测常用区间 0.4~0.8 | 自实现 BM25，无上界（实测单块 6~20 量级） | 融合分（见下），detail 里同时保留两路原始分 |
| **融合** | **无**（单通道）。`scores[cid] = 余弦分 / 本路最高分`，`algorithm="single_channel"` | **无**（单通道）。`scores[cid] = BM25分 / 本路最高分`，`algorithm="single_channel"` | `weighted_average` / `rrf` / `voting` 三选一 |
| **默认参数** | `embedding_model="bge-m3"`、`vector_k=20`、`vector_min_similarity=0.0`、`rerank_model="rule"` | `fulltext_k=20`、`fulltext_fields=("content",)`、`fulltext_op="OR"`、`enable_fuzzy=True` | `fusion="weighted_average"`、`vector_weight=0.5`、`fulltext_weight=0.5`、`rrf_k=60` |
| **相同点** | 三者共用：`top_k=5`、`score_threshold=0.0`、`use_image_channel=True`、同一套 `apply_rerank` | 同左 | 同左 |
| **典型耗时（实测，已预热）** | 110.9 ms（含 1 次 Ollama 嵌入） | 1.6 ms | 24~91 ms（取决于嵌入是否已热） |

> 实测环境：`run_py.ps1` + 本机 Ollama，问句「军用领域的收入占主营业务收入的比例是多少」，
> `top_k=5`。**单次实测值，不是统计口径**；正式延迟验收必须预热 + 独占 Ollama。

### 3.2 关键差异（工程含义）

1. **向量路不知道 DSL**。问句写 `军用 AND 发行`，在向量路里就是一段普通文本；只有全文路会把它当查询语法。
2. **全文路可以 0 命中，向量路几乎不会 0 命中**（只要有索引就必有近邻）。
   因此 `hybrid` 的鲁棒性下限由向量路兜底，上限由全文路的精确性决定。
3. **两路分数不可比**（余弦 0.4~0.8 vs BM25 无上界）⇒ 这是 `fusion.py` 设计纪律的来源，见 `融合算法说明.md`。
4. **归一化口径不同**：单通道模式按「本路最高分」归一化（top1 恒为 1.0）；
   融合模式按各算法口径归一化，且**重排后 `final_score` 可能 > 1**（融合分 + 特征分加权），
   实测 `final_score=1.07` —— 因此 `score_threshold` 是**相对**口径，不是概率，详见 `检索策略配置.md` §4。

### 3.3 重排的四个档位（三模式共用）

| `rerank_model` | 实现 | 降级行为 |
| --- | --- | --- |
| `none` | 按融合分原序，`final_score = 融合分 / 本批最高融合分` | 无 |
| `rule`（默认） | 复用工单4 `reranker.rerank` 八维特征：词法覆盖 / 字段 / 答案形态 / 模态 / 主体路由 / 极性 / 数值邻近 / 身份簇 | 无 |
| `tfidf` | `_tfidf_cosine`：查询与候选正文的 TF-IDF 加权余弦，`final_score = 0.5·融合分归一 + 0.5·tfidf` | 无 |
| `cross_encoder` | `sentence_transformers.CrossEncoder`，候选正文截断 1500 字，分差 min-max 归一 | **缺模型时显式降级为 `rule`**：`note.degraded=True` + `reason` + WARNING 日志；绝不静默 |

### 5.3 默认行为与基线的关系（**如实说明，含差异**）

**设计意图**（`retrieval_strategy.py` 模块 docstring 第 34-35 行）：
「默认策略（`hybrid` + RRF + 规则重排）与 工单4 `hybrid_search` 同源；
工单6 的改动只体现在「可以选别的」。」

**实读 + 实跑结论**：
`StrategyConfig` 的字段默认 `fusion = fusion_mod.ALGORITHM_WEIGHTED_AVERAGE`（**加权平均**，不是 RRF）。
因此「不传 `strategy`」→ 走工单4 `hybrid_search`（RRF），
「传默认 `StrategyConfig()`」→ 走策略层（加权平均）。**两条路径的默认算法不同。**

实跑对照（3 个问句，`top_k=5`，本机实测）：

| 问句 | 基线 `hybrid_search` Top-5 | 策略默认（weighted_average） | 是否一致 |
| --- | --- | --- | --- |
| 军用领域的收入占主营业务收入的比例是多少 | p129-x2 / p343-x1 / p329-x1 / p185-t0-0 / p339-t1-0 | 同左 | **一致** |
| 武汉兴图新科电子股份有限公司的法定代表人是谁？ | p52-x0 / p68-x0 / p534-x0 / p63-x0 / p64-x0 | 同左 | **一致** |
| 报告期内研发费用分别是多少？ | p389-x1 / p382-x2 / p382-x1 / p394-x1 / p390-x0 | p389-x1 / p382-x2 / **p394-x1 / p390-x0** / p329-x2 | **不一致（第 3 名起顺序与成员均变化）** |

即使把策略换成 `hybrid_rrf` 预设，第 2 个问句的第 3~5 名仍与基线不同
（基线 `p534-x0` 排第 3，策略 RRF 把它排到第 5）。差异来源是**确定的、可解释的**，共 4 条：

| # | 差异点 | 基线 `hybrid_search` | 策略层 |
| --- | --- | --- | --- |
| ① | 查询富化 | 把 `analysis.field_terms` 拼进向量查询与 BM25 查询（`retriever.py:326-334`） | **不做富化**，原句直查 |
| ② | 融合算法 | RRF（`rrf_k=60`）+「单路 rank1 救援分」`rank_rescue_weight` | `weighted_average`（默认）或 RRF，但**没有救援分**逻辑 |
| ③ | 重排预算 | 只对 RRF 分前 `RERANK_BUDGET=60` 条做重排，并按 `RERANK_MIN_RELATIVE=0.02` 截断尾部 | **无预算上限**，融合后的全部候选都进重排 |
| ④ | 候选池 | 两路 Top-K 的 RRF 贡献并集（含救援分引入的项） | 两路 Top-K 的并集（`vector_k` / `fulltext_k` 各自 Top-K） |

> **撰写纪律**：以上是**实测事实**。因此本文档**不声称**「策略层默认 = 基线逐位一致」。
> 需要与工单4 基线逐位一致时，**不要传 `strategy`**（`retriever.retrieve` 的 `strategy=None` 分支）。
> `retriever.py:466-469` 关于「不传时保持既有链路」的描述是准确的；
> `retrieval_strategy.py` docstring 里「默认策略 = RRF」的表述与代码默认值不符，以代码为准。

## 六、扩展点

| 想扩展什么 | 改哪里 | 注意 |
| --- | --- | --- |
| 加一种新融合算法 | `fusion.py`：写 `xxx_fusion()` + 在 `fuse()` 分派 + 加进 `ALGORITHMS` / `ALGORITHM_LABELS` | `fuse()` 对未知算法抛 `ValueError`；新增算法要同步 `describe_algorithms()` |
| 加一种新重排算法 | `retrieval_strategy.py`：加 `RERANK_*` 常量 + `RERANK_MODELS` + `apply_rerank` 分支 | 必须在 `final_score` 上统一到 `[0,1]` 归一量纲，否则阈值不可比 |
| 加一个嵌入模型 | `embedding_models.py` 的 `KNOWN_MODELS` 加一条（含 `ollama_model` / `dim` / `label`），再用 `build_index_multi.py --model <id>` 建索引 | 索引目录必须是 `{id}_{dim}`；维度不符时 `load_vector_index` 抛 `IndexDimensionError` |
| 加一个全文检索字段 | `fulltext_query.py`：`FIELD_LABELS` / `FIELD_ALIASES` / `DEFAULT_FIELD_BOOSTS` / `field_text_of()` 四处同步 | `get_fulltext_index` 的缓存键只看 `index_dir`，加字段需 `clear_fulltext_cache()` 或重启进程 |
| 加一条查询 DSL 语法 | `fulltext_query.py`：`_tokenize_query`（词法）+ AST 节点 + `_Parser`（文法）+ `evaluate_query` 的 `walk` | 新语法必须先于「字段限定」判断，处理顺序不可颠倒（见 `全文检索设计.md` §3） |
| 让策略层接入 HTTP/界面 | `retrieval_strategy.describe_modes()` / `describe_rerank_models()` / `fusion.describe_algorithms()` / `fulltext_query.describe_fields()` 已备好清单 | `StrategyConfig.to_dict()` 可直接 JSON 往返；`from_dict()` 忽略未知键，界面可整包回传 |
