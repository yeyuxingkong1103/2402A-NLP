# 工单10 部署过程与问题记录

## 已处理问题

### 1. Docker客户端存在但引擎未启动

- 现象：`docker version`能显示Client，但Server为空；连接`dockerDesktopLinuxEngine`失败。
- 原因：Docker Desktop未启动或Linux容器引擎尚未就绪。
- 处理：启动Docker Desktop，等待左下角状态显示Engine running，再执行`docker info`。

本机实际复验结果：Docker Desktop 4.72.0后端在启动阶段崩溃，日志显示Inference管理器无法创建`dockerInference`监听文件，并提示`Docker Desktop encountered an unexpected error and needs to close`。使用桌面程序和`docker desktop start`两种安全启动方式均未使引擎上线。由于界面只给出“Quit”和“Reset to factory defaults”，而恢复出厂设置会清除或重置用户Docker数据，本项目未执行该破坏性操作。因此本机完成了Compose静态验证和应用层验收，但不能虚报已经完成本机容器运行验收。

建议处理顺序：

1. 用户正常重启Windows后重新打开Docker Desktop；
2. 如仍失败，使用Docker Desktop Troubleshoot收集诊断；
3. 备份现有镜像与卷后再由用户决定是否恢复出厂设置；
4. 或直接在目标Linux服务器执行`deploy.sh`完成最终容器验收。

### 2. Windows版Compose JSON输出无法被标准JSON解析

- 现象：`docker compose config --format json`中的Windows构建路径含未转义反斜杠。
- 影响：Python标准JSON解析器报`Invalid escape`，但Compose配置本身有效。
- 处理：自动化测试改用`docker compose config`规范化YAML输出，继续由Docker CLI验证配置语义。

### 3. API Key不能写入镜像

- 风险：把`.env`复制进镜像会造成密钥泄漏，镜像上传后无法撤回。
- 处理：`.dockerignore`排除`.env`，Compose通过运行时环境变量注入。

### 4. Windows本地地址在容器中不可用

- 现象：原项目右击运行时绑定`127.0.0.1`，直接放进容器后宿主机无法访问。
- 处理：Docker启动命令使用`uvicorn --host 0.0.0.0 --port 8020`，再映射宿主机8021端口。

### 5. 索引较大且启动需要加载时间

- 现象：GraphRAG索引约57MB，第一次请求前需要加载模型索引。
- 处理：镜像直接包含已经生成的索引；健康检查提供25秒启动宽限并重试5次。

## 服务器常见排查

### 页面无法打开

1. `docker compose ps`确认状态是否healthy；
2. `docker compose logs --tail=200 rag`检查错误；
3. `curl http://127.0.0.1:8021/api/health`检查服务器本机访问；
4. 检查云安全组和系统防火墙是否放行8021/TCP。

### DeepSeek不可用

1. 检查`.env`中Key前后没有引号和空格；
2. `docker compose up -d --force-recreate`重新注入配置；
3. 检查服务器是否能访问`https://api.deepseek.com`；
4. 即使DeepSeek失败，系统仍会回退到证据摘要模式。

### 内存不足

- 默认限制2GB；如果日志显示进程被杀，可把`docker-compose.yml`中的`mem_limit`调为`3g`或`4g`后重建。
