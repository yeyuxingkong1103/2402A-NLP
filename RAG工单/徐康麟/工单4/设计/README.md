## 五条最容易被踩的红线（详见 `环境事实.md`）

1. **`pip install` 的落点是 `工单1\.venv\Lib\site-packages`** → 禁止直接 pip 装包，用 `--target 研发/第三方库`。
2. **一律经 `run_py.ps1` 调解释器**（它强制 `PYTHONDONTWRITEBYTECODE=1`，防止 `.pyc` 写进只读的工单1）。
3. **引用只认 1-based 物理页码**；两份 PDF 的印刷页码都等于「物理页码 − 1」，极易混用。
4. **延迟验收必须预热 + 独占 Ollama**；冷启动首字实测 3430.8 ms，冷口径必违约。
5. **水印占图片总量 92%~98%**（PDF1 xref=112173、PDF2 xref=2338），图像链路第一步必须按 xref 去重。

## 两条护栏（改动设计文档或 golden 后必跑）

```powershell
cd E:\gao6gongdan\工单4

# 护栏 A：§3 与 golden 逐字段对拍（golden 变更后必跑）
pwsh -NoProfile -File run_py.ps1 设计/复现脚本/验收标准_vs_golden_对拍.py
#   已知问题白名单：--known-issue union:id957（当前已无需使用）

# 护栏 B：文档引用的仓库路径存在性（改文档后必跑）
pwsh -NoProfile -File run_py.ps1 设计/复现脚本/设计文档路径核对.py
pwsh -NoProfile -File run_py.ps1 设计/复现脚本/设计文档路径核对.py --all-docs   # 连其它四个目录的 md 一起扫
```

- **护栏 A 对拍范围**：16 题的 `evidence_pages_complete` / `supporting_pages` / `related_pages` 三级页集合、
  扁平行与 `evidence_pages` 的一致性、主证页归属，以及 golden 自身的两条页集合等式。
  **golden 一旦被修订，先跑本脚本，再改设计文档——不要靠人眼发现漂移。**
- **护栏 B 对拍范围**：设计文档（含顶层 `README.md`）里出现的仓库内路径是否真实存在，
  以及 `run_py.ps1 <脚本>` 式复现命令引用的脚本是否存在。
  **文档里禁止出现指向不存在文件的路径**（T8 曾发现一例：文档把评测驱动指向 `研发/scripts/` 目录下的 `evaluate.py`，
  而该文件从未存在；真实驱动是 `测试/在线/run_16q_eval.py`）。
