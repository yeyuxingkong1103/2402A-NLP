## 核心认知：三种手段，不是三选一

**RAG、微调、提示词工程是三种手段，解决不同问题，可以组合。**

| 手段 | 解决什么 | 成本 | 一句话 |
|---|---|---|---|
| 提示词工程 | 让模型"这一次"答好 | 最低 | 不改模型，只改输入 |
| **RAG** | 给模型"补知识"（外部资料） | 低 | 知识可更新、可溯源、防幻觉 |
| **微调** | 改模型"本身"（风格/格式/能力） | 高 | 持久改变模型行为 |

> 记忆口诀：**知识靠 RAG，能力/风格靠微调，两者常一起用**（微调后的模型 + RAG 知识库）。

## 一、RAG 学习路径

### 阶段 1：跑通核心链路 ✅
标准链路：
```
文档 → 解析 → 分块 → 向量化 → 检索 → 生成
```
目标：能准确说出每个词 —— embedding、向量相似度、chunk、top-k、BM25。

### 阶段 2：理解每个环节的「可优化点」⭐（重点）

| 环节 | 可优化点 |
|---|---|
| 分块 | chunk 大小、overlap、语义分块、父子块 |
| 检索 | 混合检索、多路召回、Query 改写/扩写、Rerank |
| 向量化 | 换更强的 embedding（bge-m3 已是主流） |
| 生成 | 提示词模板、引用溯源、后处理 |

### 阶段 3：评测（RAG 的「考试」）

- 检索质量：召回率、命中率、Context Precision / Recall
- 生成质量：Faithfulness（忠实度）、Answer Relevancy
- 工具：**RAGAS**（业界主流开源评测框架）

### 阶段 4：框架（用别人的轮子，反推为什么）

- LangChain / LlamaIndex（灵活、适合教学）
- RAGFlow / Dify / LightRAG（开箱即用的产品）

> 建议顺序：**先把手写的 RAG 吃透，再去看框架**——框架的每个模块都能对应上自己写过的代码。

## 二、微调学习路径

### 三层，由浅入深

| 层级 | 做什么 |
|---|---|
| 1. SFT 指令微调 | 用 (指令, 回答) 对，让模型学会格式 / 领域 |
| 2. LoRA / QLoRA | 只训练少量参数，省钱省显存 |
| 3. 偏好对齐 DPO / RLHF | 让模型更符合人类偏好 |

### 要理解透的 4 个概念

1. **预训练 vs SFT**：预训练 = 海量无监督"学语言"；SFT = 少量有监督"学任务"
2. **LoRA 原理**：冻结原模型，只训练低秩矩阵（`r` 越小越省，合并后是完整模型）
3. **数据质量 > 数据量**：微调数据贵在"精"，几百条高质量往往胜过几万条垃圾
4. **灾难性遗忘**：微调后可能忘掉通用能力（常配合 LoRA 小秩 + 低学习率缓解）

### 什么时候选微调、什么时候选 RAG？

| 场景 | 选 |
|---|---|
| 知识要实时更新、要可溯源 | RAG |
| 想让模型学会"某种语气/格式/专业术语" | 微调 |
| 两者都要 | **微调 + RAG 组合** |
