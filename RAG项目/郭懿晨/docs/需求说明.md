## 一、业务目标

1. **标准条文问答知识库：** 面向电力/工业领域工程师，围绕国家标准、行业标准、技术规程等技术 PDF 文档，构建可检索、可问答、可追溯来源的本地 RAG 知识库；以 GB/T 44653-2024《六氟化硫气体现场循环再利用导则》等标准为典型语料。
2. **构建服务：** 将「解析 → 清洗 → 分块 → 向量化 → 入库」的线下构建流程封装为本地后端服务，支持上传标准 PDF、启动构建任务、查看任务状态与浏览向量库内容，保证标准文档的解析质量与入库可控。
3. **条文级问答与溯源：** 面向工程师「查标、用标」场景，支持对标准具体条款的问答；答案必须附带来源文档、条款页码、类别与原文片段，做到答有所据、可核可溯。
4. **工程落点：** 以单机 MVP 为目标，优先保证链路真实可运行、结果可验证、回答有引用、无依据不编造；为后续扩展为团队级标准知识库打基础。

## 二、功能需求（FR）

| # | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| FR1 | 文档上传 | 高 | 用户可以上传 PDF 文件；后端保存文件并创建文档记录与构建任务。 |
| FR2 | 文档解析 | 高 | 使用 MinerU 解析 PDF，输出带页码和类别信息的内容块。 |
| FR3 | 复杂元素后处理 | 中 | 支持通过可选 VLM 配置对解析结果做视觉后处理；v1 不强制启用。 |
| FR4 | 数据清洗 | 高 | 将解析结果整理为可分块文本，保留必要元数据，过滤无效内容。 |
| FR5 | 分块 | 高 | 将文档拆分为 chunk，保留 `document_id`、页码、类别、文本和来源范围。 |
| FR6 | 向量化 | 高 | 使用 BGE-M3 生成 dense 和 sparse 表示，其中 dense 向量维度为 1024。 |
| FR7 | 向量库存储 | 高 | 使用 Qdrant embedded 存储 chunk 向量和 payload 元数据，包含 `dense` 和 `sparse` named vectors。 |
| FR8 | 复合检索 | 高 | 问答时默认执行全库检索，使用 dense + sparse 检索并通过 RRF 融合排序。 |
| FR9 | 问答生成 | 高 | 使用本地 Ollama 模型基于检索证据生成答案。 |
| FR10 | 引用校验 | 高 | 问答结果必须返回答案、引用来源和 `fallback` 标记；引用包含文档名、页码、类别和原文片段。 |
| FR11 | 构建过程展示 | 高 | 前端展示任务状态、当前步骤、进度和错误信息；v1 使用轮询，不使用 SSE。 |
| FR12 | 向量库内容展示 | 高 | 前端展示文档列表、向量库记录、类别筛选和关键词过滤。 |
| FR13 | 任务状态持久化 | 中 | v1 使用 `data/state.json` 保存文档、任务和 chunk 状态。 |
| FR14 | 前端操作台 | 中 | 提供上传、任务、文档、向量库和问答 5 个视图，便于工程师查标、用标操作。 |
| FR15 | 粗排 | 高 | RRF 召回后先用 BGE-M3 dense 余弦信号粗排，从候选集中保留 `coarse_top_k`。 |
| FR16 | 精排 | 高 | 用本地 bge-reranker-v2-m3 交叉编码器对粗排结果精排，取 `final_top_k` 作为引用。 |
| FR17 | 重排可配置 | 高 | 候选规模、各层 top_k、阈值、粗排打分方式、模型路径、批大小均可通过配置调整。 |
| FR18 | 检索重排评测 | 中 | 评测脚本支持 v1/v2 两档对比，产出 recall/MRR/延迟。 |

## 三、非功能需求（NFR）

| # | 需求 | 说明 |
| --- | --- | --- |
| NFR1 | 可复现 | 系统应能在本地单机运行，依赖本地 PDF、本地模型路径、Qdrant embedded 和 Ollama，便于工程师本地部署复现。 |
| NFR2 | 可追溯 | 每个 chunk 和每条问答引用都必须保留来源文档、页码、类别和原文片段。 |
| NFR3 | 无依据不编造 | 当问题为空、检索为空或引用不可用时，返回固定兜底响应，不生成无依据答案。 |
| NFR4 | 诚实进度 | 构建过程只展示步骤级进度，不虚构 PDF 页级解析进度。 |
| NFR5 | 原子性 | 构建失败时任务和文档必须标记为失败，并保存错误信息；不得将失败任务展示为成功入库。 |
| NFR6 | 轻量化 | v1 不引入账号体系、复杂队列、分布式部署、关系型数据库和额外运维组件。 |
| NFR7 | 可迁移 | Qdrant embedded 的 collection、named vectors 和 payload 设计应贴近 Qdrant 服务端用法，便于后续迁移。 |
| NFR8 | 可测试 | 配置、模型、存储、文件上传、分块、问答、路由和前端入口应有 pytest 覆盖。 |

## 四、范围边界

- **范围内：** 单机本地 RAG PDF 问答 MVP；PDF 上传；MinerU 解析；可选 VLM 后处理；清洗；分块；BGE-M3 向量化；Qdrant embedded 入库；dense + sparse 复合检索；Ollama 问答生成；引用返回；无依据兜底；任务状态轮询；文档与向量库浏览；静态前端操作台。
- **范围外（后置）：** 多用户权限；云端部署；SSE 实时推送；SQLite 任务历史；多文档批量并发；任务队列治理；完整评测平台和指标看板；模型微调；父子/递归分块；Qdrant 到 Milvus 迁移；MinerU 空结果兜底修复（另开一轮）。
