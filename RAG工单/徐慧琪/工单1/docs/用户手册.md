# 用户手册：招股说明书智能问答系统

**工单编号：人工智能NLP-RAG-基于PDF文档的问答系统**

本手册面向使用者，介绍如何启动系统、如何提问、如何查看结果，以及如何上传 PDF 文档。

---

## 1. 启动系统

### 1.1 前置条件

| 项目 | 要求 | 检查命令 |
| --- | --- | --- |
| Python 环境 | 已安装本项目所需依赖（streamlit / torch / sentence-transformers / qdrant-client / langchain 等） | `python -c "import streamlit"` |
| Ollama 服务 | 必须处于运行状态，且本地已有 `qwen2.5:3b` | `ollama list` |
| 向量库 | 已执行过建库（`data/qdrant` 非空） | 见 1.3 |

> ⚠️ **不要同时运行多个程序访问知识库。** 本地 Qdrant 采用文件锁，同一时刻只允许一个进程访问。运行 `build_index.py` 或 `evaluate.py` 之前，请先关闭正在运行的问答界面。

### 1.2 启动问答界面

```bash
cd 工单1
streamlit run app.py
```

浏览器会自动打开 `http://localhost:8501`。首次启动需加载本地模型（bge-m3、reranker、qwen2.5:3b），约 20~40 秒，界面会显示"正在加载本地模型"。

启动后若出现红色错误提示：

- **"LLM 不可用"** → Ollama 没启动，在命令行执行 `ollama serve`；
- **"检索不可用"** → 向量库为空，执行 `python build_index.py` 建库。

### 1.3 首次使用：构建知识库

若是全新环境（或想重建），在命令行执行：

```bash
python build_index.py
```

该命令依次完成：解析 PDF → 分块 → 向量化 → 写入向量库，548 页的招股书约需 3 分钟。

## 2. 提问与查看结果

界面共 4 个页签：**💬 智能问答**、**⚖️ RAG vs 纯 LLM**、**📚 知识库管理**、**ℹ️ 系统信息**。

### 2.1 智能问答

在底部的输入框输入问题后回车，例如：

> 武汉兴图新科电子股份有限公司注册资本是多少？

系统会**流式**输出答案（逐字显示，无需等待），随后展示三部分内容：

**① 答案正文**

答案中的 `[1]`、`[2]` 是引用标号，对应下方的出处。

> 武汉兴图新科电子股份有限公司注册资本是 5,520.00 万元。[1]

**② 引用出处**（可展开）

每条引用显示：

- **页码**：在 PDF 中的第几页；
- **章节路径**：如"第五节 发行人基本情况 > 一、发行人的基本情况"；
- **类型**：正文 / 表格；
- **核验结论**：
  - ✅ **内容核验通过** —— 系统把答案与片段做了数字/词块比对，确认该编号确实支撑该句；
  - ⚠️ **疑似引用错位（更可能出自 [n]）** —— 模型标的编号与核验结果不一致，括号内是系统判断的更可能出处。

> 💡 **为什么要看核验？** 小模型偶尔会把数字抄对、却把引用标到相邻的块上。核验帮你快速判断这个引用能不能直接拿去用。

**③ 耗时面板**

显示各阶段耗时，并对照工单"≤3 秒"指标给出 🟢/🟡 标记：

> ⏱ Query理解 0.88s ｜ 检索 0.03s ｜ 精排 0.28s ｜ 生成 1.18s ｜ **首字 1.2s** ｜ **总计 2.37s** ｜ 工单指标：🟢 达标（≤3s）

**④ 反馈**

每条回答下方有 👍 / 👎 按钮，点击后记录到 `data/eval/feedback.jsonl`，用于后续优化。

**⑤ 语音提问（🎤）**

展开问答页的 **🎤 语音提问（中文）**：

1. 点击麦克风图标开始录音，说完再点一次停止；
2. 系统用 **Windows 自带的离线语音引擎**识别（全程不联网、不下载模型），约 1 秒出结果；
3. **务必核对识别出的文字**，可直接在文本框里修改；
4. 点 **✅ 用这句话提问** 才会真正提问。

> ⚠️ **语音仅支持中文。** 本机只安装了中文（zh-CN）识别器。
> 不要用语音说英文问题 —— 请改用文字输入，文字问答中英文都支持。
>
> 💡 通用听写对专有名词可能出现同音错字（例如把"兴图"听成"信徒"）。
> 系统会按领域词表自动纠正，并**始终把识别结果回显出来**供你确认，
> 不会不打招呼就替你提交。

### 2.2 侧边栏功能

- **⚙️ 检索参数**：可调整送入模型的知识片段数（top-k）、开关精排 / BM25 混合召回 / Query 理解。
  - **Query 理解**是三态下拉：
    | 选项 | 说明 |
    | --- | --- |
    | **自动（推荐）** | 问题里已经写了公司全称时用规则分析（省约 1.4 秒）；问题里有"该公司""发行人"这类指代，或英文提问时，才调用大模型分析 |
    | 始终用 LLM | 每题都调用大模型做分析，最慢但改写质量最高，适合做效果对照 |
    | 关闭 | 全部走规则，最快；含指代的问题召回会变差 |
  - 想跑得最快就保持"自动"；想对比效果可切到"始终用 LLM"。
  - 耗时面板会显示这一步走的是「规则」还是「LLM」，方便核对。
- **📋 必测问题**：工单给定的 10 道验收题，点击任一按钮即可直接提问。
- **🗑️ 清空对话**：开始新一轮对话。

### 2.3 RAG vs 纯 LLM 对比页

用于直观展示"有检索"和"没有检索"的差别：

1. 从下拉框选择一道必测题（或选"自定义问题"自行输入）；
2. 点击 **开始对比**；
3. 左右两栏并排显示：
   - 左：**RAG（检索增强）** —— 答案 + 引用出处 + 耗时；
   - 右：**纯 LLM（无检索）** —— 模型仅凭自身记忆作答，**不带任何出处**，并标注"无法核对出处"。

> 典型对比：问"公司参与制定了哪个技术标准"时，RAG 能从文档中给出准确答案并标出页码；纯 LLM 往往给出一个看似合理但**与实际文档不符**的标准编号。这正是检索增强的价值。

### 2.4 知识库管理页

**① 查看状态**：向量条数、向量维度、Embedding 设备、精排是否启用，以及完整配置。

**② 上传 PDF 并重建知识库**：

1. 点击"选择一个 PDF 文件"上传；
2. 点击 **🚀 开始重建**；
3. 系统依次执行：解析 PDF → 分块 → 向量化 → 重建向量库，页面显示进度条；
4. 完成后提示"知识库已重建：N 个片段（来源 xxx.pdf）"。

> ⚠️ **重建会覆盖当前知识库**。548 页的招股书约需 3~5 分钟，期间请勿关闭页面。

**③ 全量重建**：对当前招股书重新执行"解析 → 分块 → 向量化 → 入库"，等价于命令行 `python build_index.py --rebuild`。

**④ 删除知识库**：危险操作，删除后需重新构建才能问答。

### 2.5 系统信息页

展示各环节的选型与本地路径、离线约束说明，以及本机 Ollama 可用的模型清单。

## 3. 命令行使用（可选）

除界面外，各模块都可单独运行：

```bash
# 扫描本机可用模型（第一步）
python scan_local_models.py

# 构建/重建知识库
python build_index.py
python build_index.py --rebuild        # 全量重建
python build_index.py --skip-parse     # 复用已有解析结果
python build_index.py --limit 50       # 只处理前 50 页（调试）

# 检索冒烟测试
python -m src.retriever "注册资本是多少？"

# 单题问答（含纯 LLM 对照）
python -m src.rag "武汉兴图新科电子股份有限公司法定代表人是谁？"

# 运行评估（10 题，RAG vs 纯 LLM）
python evaluate.py
```

## 4. 常见问题

**Q1：回答里出现"根据提供的文档片段无法确定"，是什么原因？**
说明检索到的片段确实不含答案。可尝试：① 换一种问法（用文档里的书面用词）；② 调大侧边栏的 top-k；③ 确认问题确实在文档范围内。

**Q2：为什么有的引用标着 ⚠️？**
模型把引用编号标错了位置（内容是对的，编号标到了别的块上）。括号里给出了系统判断的更可能出处，可点击展开核对该片段。

**Q3：响应时间超过 3 秒怎么办？**
先看耗时面板定位瓶颈：如果是"生成"慢，通常是显存被其他程序占用导致模型回退到 CPU；关闭一些占用显卡的程序后重试。如果是首次提问，属于冷启动，预热完成后即恢复正常。

**Q3b：启动时程序卡住/闪退，或报 `OSError 1455 页面文件太小` 怎么办？**
说明本机可用内存不足（模型加载需要约 3~4 G 空闲内存）。关闭浏览器、微信、WPS、ToDesk 等占内存的程序后重试。程序已内置大栈线程与失败降级机制来抵御这类环境问题，但物理内存不够时仍需先释放。

**Q3c：回答里没标 ⚠️ 但也和原文页码对不上？**
先核对"引用出处"里展开的原文片段。若系统认为模型标错了编号，会自动修正并在答案上方给出提示（"系统按内容核验修正了 N 处引用"）；若只是模型标注可疑而没有足够证据修正，则会保留原编号并标 ⚠️。

**Q4：可以同时开两个浏览器窗口提问吗？**
可以，但不要同时运行命令行建库/评估脚本，本地向量库有文件锁。

**Q5：支持英文提问吗？**
支持，英文提问会用英文作答。系统会先把英文问句译成中文再检索
（知识库本身是中文的，直接用英文检索容易命中错误的页码），因此英文提问
会比中文提问多花约 1.4 秒用于翻译改写。
注意：**英文只支持文字输入，不支持语音**（本机只装了中文识别器）。

**Q5b：为什么语音说英文没反应 / 识别出一堆中文字？**
因为本机只安装了 Windows 的中文（zh-CN）语音识别器，它会把英文发音硬按中文去猜。
英文请改用文字输入。

**Q6：为什么关掉"Query 理解"后有的问题答不准了？**
Query 理解负责补全指代（"该公司"→ 公司全称）和拆解多跳问题。关掉后，含指代或需要多步推理的问题召回率会下降。
