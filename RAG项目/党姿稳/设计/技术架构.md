# 多角色 RAG 智能问答系统

基于 **Qwen / DeepSeek + 混合检索 + 双层记忆** 的多角色问答系统。用户提问后自动识别意图，
路由到 **法律顾问 / 医疗咨询 / 英语学习助手** 三个角色之一，检索对应知识库后生成回答。

完整链路：

```
用户输入
  → 意图识别（LLM 判断 legal / medical / english / chat）
  → Query 改写
  → 短期记忆（Redis 取最近 5 轮）
  → 混合检索（向量召回 + BM25 关键词召回）
  → BGE-rerank 重排序
  → 余弦相似度过滤（低于阈值丢弃）
  → 组装提示词（角色人设 + 检索结果 + 短期记忆 + 长期记忆）
  → 大模型流式生成
  → 存入 Redis（短期记忆）+ Milvus（长期记忆）
```

---

## 1. 环境要求

| 组件 | 本地测试 | 算力云部署 | 说明 |
|---|---|---|---|
| Python | 3.10+ | 3.10+ | 必需 |
| DeepSeek API | 必需 | — | 测试阶段使用 |
| SGLang / vLLM | — | 必需 | 部署 Qwen 模型 |
| Redis | 不需要 | 需要 | 短期记忆 |
| Milvus | 不需要 | 需要 | 向量库 |
| MySQL | 不需要 | 需要 | 对话记录与文档元数据 |
| Docker | 不需要 | 需要 | 运行 Milvus |

**两种运行模式**：

- `LOCAL_MODE=true`（默认）：内存向量库 + JSON 会话文件，零外部依赖，装完依赖就能跑
- `LOCAL_MODE=false`：Milvus + Redis + MySQL 生产实现

两套实现共用同一份业务代码，切换只需要改一个配置项。

## 2. 安装步骤

### 2.1 本地测试（推荐先跑通这个）

```bash
# 1. 安装轻量依赖（不含 torch / paddle，几分钟装完）
pip install -r requirements-local.txt

# 2. 生成配置文件
cp .env.example .env

# 3. 填写 DeepSeek 密钥（见第 3 节）

# 4. 生成测试 PDF（三个领域各 35 页，含表格和矢量图形）
python scripts/generate_test_pdfs.py

# 5. 建库
python -c "
from knowledge_base import KnowledgeBase
from pathlib import Path
import config
kb = KnowledgeBase()
for domain in config.KB_COLLECTIONS:
    kb.import_directory(config.DATA_DIR / domain, domain)
"

# 6. 启动页面
streamlit run streamlit_app.py
```

浏览器打开 `http://localhost:8501`，输入问题即可。

> 第 4 步生成的 PDF 在 `data/generated_pdfs/`，把它复制到 `data/legal/`、`data/medical/`、
> `data/english/` 下再执行第 5 步；也可以直接在 Streamlit 页面左侧上传 PDF 建库。

### 2.2 算力云部署

```bash
# 上传代码到服务器后
bash scripts/deploy.sh

# 只装依赖不下载模型（改用 hash 向量化）
bash scripts/deploy.sh --skip-models
```

脚本会依次完成：环境检查 → Conda 环境 → Python 依赖 → Redis → MySQL →
Milvus(Docker) → 模型下载 → 配置检查 → 数据库初始化 → 知识库导入。

部署完成后按第 3 节修改配置，再执行：

```bash
bash scripts/start.sh          # 同时启动 API(8080) 与页面(8501)
```

## 3. 配置说明

所有配置集中在 `config.py`，可通过 `.env` 覆盖。**只需要改两处**：

### 3.1 测试阶段：填 DeepSeek 密钥

打开 `config.py`，找到这一段：

```python
# ===================== DeepSeek —— 测试阶段使用 =====================
# ↓↓↓ 请在这里填入你的 DeepSeek API Key ↓↓↓
DEEPSEEK_API_KEY = _env("DEEPSEEK_API_KEY", "")
# ↑↑↑ 留空即可，填写后即可调用 ↑↑↑
```

把密钥填进引号即可。也可以写在 `.env` 里（推荐，不会被误提交）：

```ini
DEEPSEEK_API_KEY=sk-你的密钥
LLM_PROVIDER=deepseek
DEEPSEEK_MODEL=deepseek-v4-flash
```

### 3.2 算力云阶段：切到 Qwen（SGLang）

SGLang 把模型部署好之后，把地址填进 `.env`：

```ini
LLM_PROVIDER=qwen
QWEN_BASE_URL=http://你的算力云公网IP:8000/v1
QWEN_MODEL=qwen27b
QWEN_API_KEY=EMPTY
LOCAL_MODE=false
EMBEDDING_BACKEND=bge-m3
```

`QWEN_MODEL` 要填 SGLang 启动时的 `--served-model-name`，不确定时访问
`http://你的IP:8000/v1/models` 查看。

### 3.3 关键配置项

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `LOCAL_MODE` | `true` | 是否使用本地轻量实现 |
| `EMBEDDING_BACKEND` | `hash` | `hash` 离线降级 / `bge-m3` 生产 |
| `LLM_PROVIDER` | `deepseek` | `deepseek` / `qwen` |
| `SIMILARITY_THRESHOLD` | `0.3` | 余弦相似度过滤阈值 |
| `DUPLICATE_THRESHOLD` | `0.95` | 入库去重阈值 |
| `VECTOR_TOP_K` / `BM25_TOP_K` | `10` / `10` | 两路召回条数 |
| `RERANK_TOP_K` | `5` | 重排后交给模型的条数 |
| `SHORT_TERM_ROUNDS` | `5` | 短期记忆保留轮数 |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `500` / `50` | 分块长度与重叠 |

配置改完可以用内置自检确认：

```bash
python config.py
```

## 6. 测试方法

### 6.1 单元测试（离线，不调用模型）

```bash
python -m unittest discover -s tests -v
```

也可以单独跑某一个：

```bash
python -m unittest tests.test_unit -v       # 意图识别、分块、向量化、过滤去重
python -m unittest tests.test_storage -v    # 向量库读写、知识库、PDF 解析
```

测试数据落在临时目录，不会污染 `storage/` 与 `logs/`。

### 6.2 集成测试（需要 API Key，未配置时自动跳过）

```bash
python -m unittest tests.test_integration -v
```

覆盖：完整链路、SSE 事件序列、多用户记忆隔离、多角色切换。

### 6.3 RAGAS 评测

```bash
python evaluate.py                    # 全量 15 题
python evaluate.py --limit 3          # 只跑 3 题，省时间省费用
python evaluate.py --domain legal     # 只评测法律领域
```

输出四项指标到 `logs/eval_report.json` 与 `logs/eval_report.png`：
忠实度 `faithfulness`、相关性 `answer_relevancy`、
上下文精确率 `context_precision`、上下文召回率 `context_recall`。

未安装 ragas 时自动降级为 LLM 打分，仍使用 `config.py` 中配置的模型。

### 6.4 压力测试

```bash
python scripts/load_test.py --concurrency 50
python scripts/load_test.py --concurrency 100 --requests 500
```

统计 QPS、平均响应时间、P95 延迟与错误率。
也可以使用 `scripts/load_test.jmx` 在 JMeter 中打开运行。

### 6.5 各模块自检

每个模块都带 `__main__` 自检，可以单独运行验证：

```bash
python embeddings.py      # 向量维度、归一化、相似度
python vector_store.py    # 向量库读写
python rerank_filter.py   # 去重与阈值过滤
python retrieval.py       # 混合检索（需先建库）
python knowledge_base.py  # 导入与检索
python llm_client.py      # 模型连通性
```

## 8. 常见问题

**Q：提示 `DEEPSEEK_API_KEY 为空`**
A：按 3.1 节在 `config.py` 或 `.env` 中填入密钥。填完 `python config.py` 可验证。

**Q：模型地址连不上 / 超时**
A：执行 `python llm_client.py` 单独探活。若是算力云部署的 Qwen，
确认安全组已放行 8000 端口，且 `QWEN_BASE_URL` 用的是公网 IP 而非 `127.0.0.1`。

**Q：检索结果总是为空**
A：先确认知识库有数据（`GET /kb/stats` 或 `python -c "from knowledge_base import KnowledgeBase; print(KnowledgeBase().stats())"`）。
若条数正常但仍检索不到，多半是 `SIMILARITY_THRESHOLD` 设高了——
`hash` 向量后端的余弦值普遍低于 `bge-m3`，本地测试可以把它调到 `0.1`。

**Q：为什么不装 torch 也能跑**
A：`EMBEDDING_BACKEND=hash` 时用字符 n-gram 哈希向量，不加载任何模型。
它只做字面匹配，没有语义泛化能力，**仅用于打通链路**，正式评测和上线必须换成 `bge-m3`。

**Q：只装了 PyMuPDF，PDF 里的表格和图片解析不出来**
A：表格需要 `pdfplumber`，图片 OCR 需要 `paddleocr` + `paddlepaddle`，
版面分析需要 `minerU`。缺哪个会自动降级跳过，不影响其余链路。
见 `requirements.txt`。

**Q：切换到生产模式后启动报错**
A：按顺序检查三项——Milvus 是否启动（`docker ps | grep milvus`）、
Redis 是否启动（`redis-cli ping`）、`scripts/init_db.py` 是否执行成功。
服务对 Milvus 连接失败有降级保护（会打告警并回落到本地向量库），
但 Redis 和 MySQL 不可用时对应功能会静默降级。

**Q：日志在哪**
A：`logs/app_YYYYMMDD.log` 按天切分，保留 30 天。
记录用户请求、检索结果与分数、模型调用耗时与 token 数、错误堆栈。

**Q：怎么换成别的模型**
A：任何 OpenAI 兼容接口都可以。在 `config.py` 的 `get_llm_config()` 中加一个分支，
或者在 `.env` 里直接把 `LLM_PROVIDER` 指向的服务地址和模型名改掉即可。
