## 2. 基线版实现要点（缺陷复现）

基线版**刻意保留**工单描述的缺陷，以便基准压测与根因定位：

1. **瓶颈一**：`_reload_index_per_request()` 每请求重读 `chunks.jsonl` 与 `emb_*.npy`
   并 `QAEngine(kb=kb)` 重建引擎，产生 ≈2.5s 固定初始化开销；
   - 校准说明：倒排索引较重（~250MB），为避免瞬时打爆内存，改为**进程内共享**，
     仅重复加载「切片 + 向量」，等价复现「重复初始化重量级组件」的固定开销。
2. **瓶颈二**：`chat_completions` / `upload_document` 均为**同步 `def`**，
   PDF 解析在请求线程内同步执行（数十秒），无队列、无并发限制。
3. **泄漏点一**：`_SESSIONS`（无界会话字典）、`_LEAKED_TENSORS`（每请求留存召回向量快照，
   等效「推理中间张量未 GC」）、`_PARSE_ARTIFACTS`（解析产物累积）。
   - 校准说明：以「每请求留存 N×D 向量快照」等效复现张量泄漏，泄漏速率真实可测、曲线清晰。
4. **泄漏点二**：每请求 `requests.Session()` 新建、从不 `close()`，且被 `_LEAKED_SESSIONS`
   持有引用 → 套接字/文件描述符泄漏。
5. **OOM 模拟**：进程内看门狗，RSS 超限（默认 3072MB）即 `os._exit(137)`，
   等效被 OOM Killer 杀死。

## 3. 优化版实现要点（修复）

| 缺陷 | 修复实现 | 关键代码 |
|------|----------|----------|
| 瓶颈一 | 单例 + 预热 | `ResourceManager.engine()`（`service/resources.py`） |
| 瓶颈一 | 查询编码有界 LRU | `EMBED_CACHE_MAX=2048`（`run_server.py` 注入） |
| 瓶颈二 | 异步端点 + 线程池卸载 | `async def` + `run_in_threadpool`（`api/app_optimized.py`） |
| 瓶颈二 | 并发限流 | `Semaphore(QUERY_CONCURRENCY=8)` |
| 瓶颈二 | 解析异步化 | 入队 + `TaskExecutor`（`service/executor.py`） |
| 泄漏点一 | 有界会话缓存 | `BoundedSessionStore`（LRU+TTL+后台清理） |
| 泄漏点二 | 连接池复用 | `ResourceManager.http()`（`HTTPAdapter`） |
| 观测 | Prometheus | `service/metrics.py` + `/metrics` |

## 4. 复现步骤（端到端）

```bash
# 0) 依赖
pip install -r requirements.txt

# 1) 启动优化版
python run_server.py --variant optimized --port 8001

# 2) 冒烟
curl -s http://127.0.0.1:8001/health | python -m json.tool

# 3) 场景 A 压测（20 并发 × 600s）
python tools/loadtest.py --scenario A --concurrency 20 --duration 600 \
       --base-url http://127.0.0.1:8001 --fail-limit 200 \
       --out output/loadtest/optimized_scenarioA.json

# 4) 场景 B 压测（10 并发 = 5 问答 + 5 上传 × 600s）
python tools/loadtest.py --scenario B --concurrency 10 --duration 600 \
       --base-url http://127.0.0.1:8001 --fail-limit 200 \
       --out output/loadtest/optimized_scenarioB.json

# 5) 队列消费验证
python tools/verify_queue.py --base-url http://127.0.0.1:8001 --count 12

# 6) 一键编排（基线+优化，四组）
python tools/run_benchmarks.py
```

## 6. 与 RAGFlow 生产实现的对应关系

| 本工程 | RAGFlow 对应 | 说明 |

| `api/app_optimized.py` | API Server | 请求入口、限流、指标 |

## 7. 已知限制

1. 沙箱无 Docker/Redis：队列默认回退内存队列（生产配置 `REDIS_URL` 即启用 Redis）；
2. 嵌入/LLM 依赖本地 Ollama：无 Ollama 时问答无法完成（压测需其在线）；
3. 12 小时泄漏验收受环境时长限制，以 10 分钟稳态曲线 + 趋势外推佐证（见性能测试报告）。
