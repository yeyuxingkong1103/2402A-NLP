# RAG 功能测试及评估 · 性能测试报告

> **工单编号：人工智能 NLP-RAG-功能测试及评估**
> 被测系统：01–06 工单实现的 RAG 混合检索问答系统
> 验收要求：从用户提问到返回答案 **≤ 3 s**
> 数据来源：`tools/bench_latency.py`、`evaluate_ccf.py`（真实运行）

---

## 一、测试目的

量化 RAG 系统在 CCF 年报语料（8086 块 / 2812 页）上的**端到端响应时间**，
验证是否满足"提问→答案 ≤ 3s"的验收要求，并定位耗时瓶颈。

---

## 二、测试方法

### 2.1 两种测量口径

查询编码（调用 Ollama 嵌入模型）是整条链路中最重的一步，若只用"连续重复同一问法"测量，
会被**查询缓存**掩盖真实耗时。因此 `bench_latency.py` 区分两种口径：

| 口径 | 做法 | 含义 |
|---|---|---|
| **cold（冷启动）** | 每题前清空查询编码缓存 | 最坏情况，等价于首次遇到该问法 |
| **warm（热缓存）** | 连续重复同一问法 | 缓存命中，理论下界 |

评测题集为 10 道验收题，每题重建 `Conversation`，测量 `QAEngine.ask()` 端到端耗时。

### 2.2 对比维度

- **检索策略**：`vector`（向量）/ `fulltext`（全文，无需嵌入）/ `hybrid`（混合）
- **重排算法**：`none` / `tfidf` / `linear`
- **验收题逐题耗时**：`evaluate_ccf.py` 逐题记录

---

## 三、响应时间基准测试结果

### 3.1 冷启动 / 热缓存（`latency_bench.py`，单位：秒）

| 检索策略 | 冷启动 avg | 冷启动 p50 | 冷启动 p95 | 冷启动 max | 热缓存 avg | 热缓存 p95 |
|---|---|---|---|---|---|---|
| vector | 2.283 | 2.303 | 2.406 | 2.406 | 2.044 | 2.381 |
| fulltext | **0.067** | 0.070 | 0.079 | 0.079 | 0.072 | 0.090 |
| hybrid | 2.334 | 2.311 | 2.451 | 2.451 | 2.069 | 2.367 |

**关键观察**：

- **全文检索仅 0.067s**，向量/混合检索约 2.3s —— 二者唯一差异是**是否需要调用嵌入模型**。
  → 结论：**端到端耗时几乎全部来自"查询向量编码"这一次 Ollama 往返**，检索、重排、答案合成本身仅数十毫秒。
- 全部策略冷启动最大耗时 **2.451s < 3s**，**满足验收要求**（且为最坏情况）。

### 3.2 缓存命中后的纯检索耗时（`evaluate_ccf.py` 策略扫描）

策略扫描按 `vector→fulltext→hybrid` 顺序执行，查询编码缓存跨配置复用，
因此**第 2 个及以后的配置**反映"纯检索 + 重排 + 答案合成"耗时：

| 检索策略 | 重排 | 平均耗时 | P95 | 最大 |
|---|---|---|---|---|
| vector | none | 2.201（缓存冷） | 2.385 | 2.385 |
| vector | tfidf | 0.235 | 0.283 | 0.283 |
| vector | linear | **0.040** | 0.051 | 0.051 |
| fulltext | none | 0.061 | 0.070 | 0.070 |
| fulltext | linear | 0.073 | 0.084 | 0.084 |
| hybrid | linear | **0.094** | 0.111 | 0.111 |
| hybrid | tfidf | 0.290 | 0.311 | 0.311 |

> 最优配置 `hybrid / linear / rrf`：平均 **0.094s**、P95 **0.111s**（缓存命中）。

### 3.3 重排算法对耗时的影响

| 重排算法 | 平均耗时（hybrid） | 说明 |
|---|---|---|
| none | 0.090 | 不重排，最快 |
| linear | 0.094 | 多信号线性融合，开销极小 |
| tfidf | 0.290 | 需在线计算 TF-IDF，最慢 |

**结论**：`linear` 重排器在**几乎不增加耗时**（+0.004s）的前提下显著提升精度
（准确率 70%→90%），性价比最高。

## 六、性能结论

| 指标 | 实测 | 要求 | 结论 |
|---|---|---|---|
| 冷启动最大响应 | 2.451 s | ≤ 3 s | ✅ 达标 |
| 最优配置平均响应 | 0.094 s | ≤ 3 s | ✅ 达标 |
| 最优配置 P95 | 0.111 s | ≤ 3 s | ✅ 达标 |
| 连续 50 轮稳定性 | 无异常，均值 2.224 s | 无异常 | ✅ 达标 |

**瓶颈定位**：响应时间几乎全部由**查询向量编码（Ollama 嵌入往返）**贡献（约 2.0–2.3s），
检索、重排、答案合成合计仅数十毫秒。

**优化建议**（详见《优化报告》）：

1. **查询编码缓存**：同一问法/改写结果复用向量，可将重复问法降至 ~0.1s（已内置）。
2. **全文检索兜底**：对实时性要求极高且允许降级的场景，可先返回全文检索结果（0.067s），
   向量结果异步补全。
3. **嵌入模型量化/常驻**：将 `bge-m3` 常驻显存并量化，可压缩首次往返延迟。
4. **批量编码**：多轮对话中把改写后的多个候选 query 合并为一次嵌入请求。
