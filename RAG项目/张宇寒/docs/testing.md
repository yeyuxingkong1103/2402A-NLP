# 测试文档

## 自动化测试

在项目根目录执行：

```powershell
& "D:\Program File\conda\envs\legal_rag\python.exe" -m pytest tests -q
node --test tests/frontend_identity.test.cjs
```

只指定`tests`目录，避免把`data/runtime`中的第三方依赖测试误当成本项目测试。

| 文件 | 检查内容 |
|---|---|
| test_bootstrap.py、test_runtime_config.py | 配置转换、服务地址和健康响应契约 |
| test_public_database.py | 八集合结构、主键和1024维向量校验 |
| test_pipeline.py | 法律解析、清洗、引用、分块及历史报告输出 |
| test_load.py | 文件读取、表格、分页、OCR及失败处理 |
| test_simple_pipeline.py | 默认不入库、单份预览隔离、OCR后多模态补读及权限、截断保护、向量与入库校验、原编号和正文兼容 |
| test_rag_search.py | 正式知识来源、条文向量检索、精确查询、查询数量、重排分数、降级提示、条文完整性及来源字段 |
| test_rag_workflow.py、test_models.py | 在线问答调用次数、嵌入错误重试、多轮指代、会话删除和默认联网策略 |
| test_frontend.py | 页面入口、登录、设置、问答优先及资源契约 |
| frontend_identity.test.cjs | 账号和访客隔离、历史会话、异步响应、设置与主题切换 |

`tests/__init__.py`是测试包标识，部分测试通过它导入共用样例，保留。
删除的test_memory.py、test_rag.py、test_workspace.py仅是空白占位，没有提供测试覆盖。
目前不能因此宣称记忆、完整RAG流程和上传模块已有完善的专项测试。

## 手工验收

1. 打开主页，确认登录入口、提问入口和法律风险提示可见。
2. 访客提问后登录，检查访客记录不成为其他账号的历史咨询。
3. 登录后打开当前或最近咨询，继续提问，确认会话没有重置或串用。
4. 切换界面外观，检查正文、左侧栏、顶部和设置对话框同时变化。
5. 对借款、租赁等问题检查依据和处理建议；不得把建议展示成确定裁判。
6. 默认运行公共处理命令只产生处理文件；单份预览不覆盖完整库输出，也不能直接入库。

测试失败时先定位问题，不以删掉有效测试作为修复方式。
