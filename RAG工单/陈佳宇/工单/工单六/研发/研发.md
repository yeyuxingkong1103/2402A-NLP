# 工单6 - RAG混合检索系统｜研发文档
## 1.开发环境搭建
1. 复用工单5虚拟环境 venv_gongdan5，激活环境
2. 安装新增依赖：
```bash
pip install rank-bm25 sentence-transformers
3. Docker 启动 Milvus 容器，开放 19530 端口。

## 2. 开发流程

### 2.1 文档解析开发

使用 pymupdf 读取 PDF 文件，逐页提取文本，按换行符切分段落，过滤长度小于 20 字符的无效短文本，生成文本块列表。

### 2.2 向量模型与 Milvus 开发

1. 加载轻量向量模型 all-MiniLM-L6-v2，将文本块编码为 384 维向量。
2. 连接 Milvus，判断集合是否存在，存在则删除重建。
3. 定义 CollectionSchema，创建集合，构建 IVF_FLAT 向量索引。
4. 将向量与原文文本批量插入 Milvus，加载集合到内存。

### 2.3 BM25 检索开发

对全部文本块进行空格分词，构建 BM25Okapi 词表。用户提问时对问题分词，计算所有文本块 BM25 相关性分数，按分数降序召回 top-k 结果。

### 2.4 RRF 混合融合算法开发

实现 RRF 倒数排名融合：分别获取向量检索、BM25 检索的排序结果，使用公式 `score = 1/(k+rank+1)` 对两条结果打分，合并相同文本分数，重新排序，取前 k 个结果。

### 2.5 Flask 网页开发

1. 编写内嵌 HTML 页面，下拉选择三种检索模式，文本框输入问题，提交按钮触发请求。
2. 编写后端接口 `/api/query`，接收前端请求，调用检索函数，返回检索上下文。
3. 配置 Flask 监听 0.0.0.0:7860，允许 WSL 外部浏览器访问。

## 3. 核心代码实现要点

1. Milvus 新版兼容：必须使用 CollectionSchema 包装字段列表，解决 SchemaNotReadyException 报错。
2. 数组越界 bug 修复：Milvus 返回主键 ID 不等于文本块数组下标，改为直接提取文本内容进行 RRF 融合，避免索引越界。
3. 异常兜底：无检索结果时返回提示文本，防止页面崩溃。

## 4. 研发遇到的问题

1. 报错：SchemaNotReadyException，原因新版 pymilvus 要求使用 CollectionSchema，修复：封装 schema 对象。
2. 报错：IndexError 数组越界，原因 Milvus 自增主键不能作为 chunks 数组下标，修改 RRF 融合逻辑，直接操作文本。
3. PyMilvus 版本警告：ORM 接口即将废弃，属于版本提示，不影响程序运行。
