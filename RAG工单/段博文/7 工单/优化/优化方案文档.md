# 优化方案文档

> 工单编号：人工智能NLP-RAG-功能测试及评估

---

## 一、优化背景

基于 ccf_competition 数据集的 9 份金融年报（平安银行、招商银行、邮储银行、中信证券、中国人寿、国泰君安、中国太保、招商证券、中国平安），对 RAG 系统进行功能测试及评估。

**评估目标**：
- 检索准确率 ≥90%
- 检索召回率 ≥95%
- 平均响应时间 ≤5 秒
- RAGAS 指标（faithfulness / context_precision / context_recall / answer_relevancy）

---

## 二、系统架构优化

### 2.1 混合检索策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| **向量检索** | bge-m3 语义向量，余弦相似度 | 语义理解类问题 |
| **BM25 全文** | jieba 分词 + BM25 算法 | 关键词精确匹配 |
| **混合检索** | 向量 + BM25 + RRF 融合 | 通用场景（默认） |

### 2.2 重排算法

| 算法 | 说明 | 速度 | 精度 |
|------|------|------|------|
| **CrossEncoder** | bge-reranker-large 交叉编码 | 慢（2-5s） | 高 |
| **TF-IDF** | 词频-逆文档频率 | 快（<0.1s） | 中 |
| **LLM 重排** | DeepSeek 语义排序 | 最慢（5-10s） | 最高 |

### 2.3 融合算法

| 算法 | 公式 | 特点 |
|------|------|------|
| **RRF** | `score = Σ 1/(rank + k)` | 鲁棒性好，无需调参 |
| **加权融合** | `score = α·vec + (1-α)·bm25` | 可调权重，灵活 |
| **投票融合** | 多数表决 | 简单，抗噪 |

## 三、查询语法优化

支持以下查询语法：

| 语法 | 示例 | 说明 |
|------|------|------|
| **布尔 AND** | `平安 AND 银行` | 同时包含 |
| **布尔 OR** | `平安 OR 招商` | 任一包含 |
| **布尔 NOT** | `银行 NOT 保险` | 排除 |
| **短语匹配** | `"董事长致辞"` | 精确短语 |
| **模糊查询** | `董事~` | 前缀/后缀模糊 |
| **多字段查询** | `source:平安银行` | 指定字段 |

## 四、性能优化

### 4.1 缓存策略

- **LRU 检索缓存**：256 条，重复查询毫秒级返回
- **LLM 答案缓存**：相同问题直接返回缓存答案
- **Query 改写缓存**：改写结果缓存，避免重复调用 LLM

### 4.2 模型加载优化

- **启动时一次性加载**：bge-m3、bge-reranker、BM25 索引
- **单例模式**：全局唯一模型实例，避免重复加载
- **CPU 推理**：无 GPU 环境下使用 CPU，牺牲速度换兼容性

### 4.3 响应时间优化

| 环节 | 优化前 | 优化后 | 措施 |
|------|--------|--------|------|
| 向量检索 | 0.5s | 0.3s | Milvus AUTOINDEX |
| BM25 检索 | 0.3s | 0.1s | 内存索引 + jieba |
| RRF 融合 | 0.1s | 0.05s | 纯内存计算 |
| CrossEncoder | 3-5s | 2-4s | 限制 top_k=6 |
| LLM 生成 | 3-8s | 2-5s | max_tokens=768 |

## 五、评估方案

### 5.1 测试用例设计

基于 9 份年报设计 10 道测试题，覆盖：

| 类型 | 数量 | 示例 |
|------|------|------|
| 文本事实 | 4 | 董事长姓名、风险管理体系 |
| 表格数据 | 3 | 净利润、保费收入、总资产 |
| 多文档对比 | 2 | 银行净利润对比、策略差异 |
| 推理计算 | 1 | 增长率计算 |

### 5.2 RAGAS 评估指标

| 指标 | 定义 | 计算方式 |
|------|------|----------|
| **Context Precision** | 检索结果中相关文档的比例 | 命中关键词的文档数 / 返回文档数 |
| **Context Recall** | 相关文档被检索到的比例 | 命中关键词的文档数 / 总相关文档数 |
| **Faithfulness** | 答案与检索内容的一致性 | 答案关键词在上下文中出现 |
| **Answer Relevancy** | 答案与问题的相关性 | 答案包含问题关键词 |

### 5.3 问题分析

对检索失败的用例进行归因分析：

1. **语义漂移**：向量检索返回语义相近但内容不相关的结果
2. **关键词遗漏**：BM25 未命中关键实体（如人名、数字）
3. **融合偏差**：RRF 融合后正确结果被挤出 top-k
4. **重排误杀**：CrossEncoder 阈值过滤掉正确结果
5. **LLM 幻觉**：答案与检索内容不一致

## 六、部署优化

### 6.1 Linux 部署脚本

```bash
# 一键安装
bash install.sh

# 启动服务（自定义模型路径）
EMBED_MODEL_PATH=/data/models/bge-m3 \
RERANK_MODEL=/data/models/bge-reranker-large \
bash start.sh

# 停止服务
bash stop.sh
```

### 6.2 环境要求

| 组件 | 要求 |
|------|------|
| Python | 3.10+ |
| Milvus | 2.4+ (Docker) |
| 内存 | ≥8GB |
| 磁盘 | ≥10GB（模型+数据） |
| GPU | 可选（CPU 可运行） |

## 七、未来优化方向

1. **GPU 加速**：CUDA 推理可将响应时间降至 1-2 秒
2. **向量量化**：PQ/SQ 压缩减少 Milvus 内存占用
3. **分布式部署**：多实例负载均衡，支持并发查询
4. **增量索引**：新文档实时入库，无需全量重建 BM25
5. **多模态检索**：支持图像、表格的跨模态语义检索
