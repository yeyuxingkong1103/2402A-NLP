# 基于 PDF 文档的问答系统 用户手册

- **项目名称**：基于 PDF 文档的问答系统
- **文档类型**：用户操作指南
- **日期**：2025 年

---

## 1. 系统简介

本系统是一个针对《招股说明书1.pdf》的智能问答工具。您可以用自然语言提问，系统会从招股说明书中检索相关内容并生成准确回答。

---

## 2. 启动系统

### 2.1 启动问答服务

在 AutoDL 容器的终端中执行：

```bash
conda activate rag
cd /root/autodl-tmp/projects/RAG
python app.py
```

启动成功后，终端会显示：

```text
* Running on local URL:  http://0.0.0.0:6006
```

### 2.2 访问界面

1. 打开 AutoDL 控制台网页，找到您的实例
2. 点击"自定义服务"按钮
3. 将端口映射为 6006
4. 点击 AutoDL 给出的公网地址，在浏览器中打开问答界面

---

## 3. 界面说明

界面包含以下区域：

| 区域 | 功能 |
| --- | --- |
| 请输入问题 | 输入问题的文本框 |
| 提交 | 提交问题，开始生成回答 |
| 回答 | 显示系统生成的答案 |
| 查看检索到的原文片段 | 展开后显示回答所依据的原文片段，用于溯源验证回答 |
| 反馈 | 👍 准确 / 👎 不准确按钮，用于提交反馈 |
| 反馈状态 | 显示反馈是否已提交 |

---

## 4. 如何使用

### 4.1 提问

1. 在"请输入问题"文本框中输入您的问题
2. 点击"提交"按钮（或按回车键）
3. 等待约 2-3 秒，答案会显示在"回答"区域

### 4.2 查看来源

如果需要验证答案的依据：

1. 点击"查看检索到的原文片段"展开
2. 可以看到回答所依据的招股说明书原文
3. 对照原文确认答案的准确性

### 4.3 提交反馈

- 如果回答准确，点击 👍 准确
- 如果回答有误，点击 👎 不准确
- 反馈状态会显示在下方"反馈状态"框中

## 6. 如何更换 PDF 文档

如果想用其他 PDF 替换当前的招股说明书：

**第 1 步：上传新 PDF**

将新的 PDF 文件上传到 `/root/autodl-tmp/projects/RAG/0_raw_data/` 目录，并修改 `parse_pdf.py` 中的文件路径。

**第 2 步：重新解析 PDF**

```bash
python parse_pdf.py
```

**第 3 步：删除旧向量库并重建**

```bash
rm -rf /root/autodl-tmp/projects/RAG/2_vector_db
python build_db.py
```

**第 4 步：重启问答服务**

```bash
python app.py
```

## 7. 常见问题

### 7.1 启动时报"Address already in use"

说明 6006 端口被占用。修改 `app.py` 最后一行的 `server_port=6006` 为其他端口（如 6007），重新启动。

### 7.2 访问时打不开页面

- 确认 AutoDL 的"自定义服务"已映射正确的端口
- 确认终端中的 `python app.py` 进程仍在运行（关闭终端会导致服务停止）
- 映射后等待约 10 秒再访问

### 7.3 回答显示"上下文未提供相关信息"

说明该问题的答案不在当前 PDF 中，或检索未命中相关内容。可以：

- 换一种问法重试
- 展开"查看检索到的原文片段"确认检索情况
- 检查 PDF 是否包含该信息

### 7.4 首次提问响应缓慢

首次提问需要加载 LLM 模型，约需 1-2 分钟。之后每个问题约 2-3 秒。

### 7.5 显示"CUDA out of memory"

说明显存不足。解决办法：

```bash
# 杀掉其他占用显存的进程
pkill -9 -f app.py
pkill -9 -f test_rag.py

# 重新启动服务
python app.py
```

确保同一时间只运行一个加载大模型的进程。

---

## 8. 停止服务

在运行 `app.py` 的终端中按 `Ctrl + C` 即可停止服务。

---

## 9. 注意事项

- 不要同时运行多个加载大模型的进程，否则会显存不足
- 关闭终端会导致服务停止，如需后台运行请使用 `nohup`
- 每次重启服务需重新加载模型，约需 1 分钟
- 系统仅供内部使用，请勿将 AutoDL 公网地址对外公开
