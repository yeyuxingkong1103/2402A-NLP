### 4.3 pip 网络路径会挂死（实测）

```powershell
# 实测 1：300 秒硬超时被强杀
pwsh -NoProfile -File run_py.ps1 -m pip download --no-deps -d $env:TEMP\g4pip six
# → [timed out after 300000ms]

# 实测 2：即使 --timeout 8 --retries 1 也挂死 180 秒无任何输出
pwsh -NoProfile -File run_py.ps1 -m pip download --no-deps --timeout 8 --retries 1 -d $env:TEMP\g4pip2 six
# → [timed out after 180000ms]

# 对照：pip 自身正常（无网络模式立刻返回）
pwsh -NoProfile -File run_py.ps1 -m pip download --no-deps --no-index -d $env:TEMP\g4pip3 six
# → 退出码 1（"no matching distribution"，属预期）
```

**结论**：涉及 pip 联网时，**先给硬超时**（`Start-Process` + `WaitForExit(ms)` 或后台作业），
不要让它无限期占住一个前台步骤；拿权重用仓库自带的 **`研发/scripts/download_clip.py`**（自带重试与 sha256 校验，见 §4.2）。

### 4.4 ⚠️ hf-mirror 的 **User-Agent 门禁**（captain 与 T2 各测一次、结论相反，已定位根因）

**背景**：captain 实测 `https://hf-mirror.com` → **HTTP 403**；T2 实测同一镜像下载权重（771,304,190 B）→ **HTTP 200**。
两人记录相反。T2 做对照实验，captain 独立复现，**根因是请求头 `User-Agent`**（不是裸域名/时点差异）：

| 请求 | 默认 UA（`Python-urllib/3.11`） | `User-Agent: Mozilla/5.0` |
| --- | --- | --- |
| **裸域名** `https://hf-mirror.com` | **HTTP 200**（`Server: Caddy`） | HTTP 200 |
| **仓库文件路径** `.../resolve/main/config.json` | **HTTP 403**（`Server: cloudflare`） | **HTTP 200** |

复现命令（captain 实测，两行结果相反即为复现成功）：

```powershell
pwsh -NoProfile -File run_py.ps1 -c "import urllib.request as u; print(u.urlopen('https://hf-mirror.com/OFA-Sys/chinese-clip-vit-base-patch16/resolve/main/config.json').status)"
#  → HTTP 403（Server: cloudflare）
pwsh -NoProfile -File run_py.ps1 -c "import urllib.request as u; r=u.Request('https://hf-mirror.com/OFA-Sys/chinese-clip-vit-base-patch16/resolve/main/config.json', headers={'User-Agent':'Mozilla/5.0'}); print(u.urlopen(r).status)"
#  → HTTP 200
```

**结论（写进代码纪律）**：
1. **Cloudflare 对「默认 python-urllib UA + 仓库文件路径」返回 403**；带浏览器 UA 即 200。
   裸域名是个静态页（`Server: Caddy`），不带 UA 也 200 —— **只打裸域名看不出差别，这正是两人结论相反的原因**。
   两条记录**都正确，不互相覆盖**：captain 打的是裸域名/默认 UA 的文件请求；T2 打的是带 UA 的文件请求。

2. **拿 CLIP 权重的正确姿势 = `研发/scripts/download_clip.py`**（T2 实现，**每个请求自带 `User-Agent: Mozilla/5.0`**，幂等，且自动跑 `verify_weights()` 打印「经复核: 通过 —— HF state dict（N 个张量）」与四文件 sha256）：
   ```powershell

   ```
   权重基准：`sha256(pytorch_model.bin) = 3b8ca5a9ba36830e008bef8f980184cf29eeff986f1f3c1be9e5153f8712e7cc`

3. **⚠️ 更正 §4.2 的落地命令**：该节推荐 `huggingface_hub.snapshot_download`，但 T2 实测**这条路径在本机会失败** —

## 7. 页码口径（**全仓库强制，先读这一节再写任何引用**）

### 7.1 实测关系

| PDF | 页脚形态 | 实测样本 | 关系 |
| --- | --- | --- | --- |
| 招股说明书1 | `1-1-N` | 物理 1/2/51/129/130/131/401/548 → `1-1-0/1/50/128/129/130/400/547` | 印刷 N = **物理 − 1**（8/8 成立） |
| 招股说明书2 | 纯数字 N | 物理 1/22/39/40/72/113/157/340/350 → `0/21/38/39/71/112/156/339/349` | 印刷 N = **物理 − 1**（9/9 成立） |

即：**两份 PDF 的印刷页码都等于「物理页码 − 1」，也等于 pymupdf 的 0-based 索引。**
这正是全项目页码混用的根源，也是最容易被误判的一处。

> 正确取法：**页脚 = 该页 y 坐标最大的文本 span**（不是 `get_text()` 的最后一行！表格页/跨页页的最后一行是正文）。

### 7.2 铁律（写进代码与报告）

1. 引用一律用 **1-based 物理页码**：`doc[i]` → 物理 `i+1`。**唯一可靠来源是 pymupdf 页序**。
2. **禁止**用页脚印刷页码、0-based 索引、目录页码作为引用。
3. 页码断言必须能在 PDF 上复核：`引用页码 == 证据原文所在页`。
