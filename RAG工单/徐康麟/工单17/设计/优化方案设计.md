# 工单17 优化方案设计

工单编号：`人工智能NLP-RAG-解决API 服务并发瓶颈与资源泄漏工单`

---

## 0. 总设计原则

1. **每项修复都有开关**：环境变量前缀 `PERF_*`，`PERF_ENABLED=0` 时行为与工单10 基座**逐位一致**
   —— 这样「优化前 / 优化后」可以用同一份代码、同一条命令复现，对比才可信。
2. **每个阈值都配置化**：不硬编码并发数、队列长度、缓存条数、TTL、`keep_alive`。
3. **降级不裸崩**：连接池、队列、缓存任何一环失败都写 WARNING 后走原路径。
4. **零新依赖**：只用标准库（本机 pip 通道不通）。HTTP 连接池用 `http.client` 自实现。

## 3. 关键机制细节

### 3.1 HTTP 连接池（F1）

- `http.client.HTTPConnection` 天然支持 HTTP/1.1 keep-alive；池按 `(host, port)` 分桶。
- `checkout()`：从空闲栈弹一个，若 `sock is None` 或已关闭则重建；`checkin()` 放回，超过
  `PERF_HTTP_POOL_MAX_IDLE` 则关闭丢弃。
- **流式响应特例**：`_stream_ollama` 是逐行读的长连接，池化后必须**读完整个响应体才归还**；
  实现上用 `contextlib.contextmanager` 的 `lease()` 保证 `finally` 归还。
- 失败重试：连接被对端关闭（`RemoteDisconnected`/`BrokenPipe`）时**重建一次重试**，
  与 `MiniRedis.do()` 同款策略。

### 3.2 有界并发闸门（F3）

```python
class BoundedGate:
    def __init__(self, max_inflight: int, queue_max: int): ...
    def acquire(self, timeout_s: float) -> bool:
        # 在途 < max_inflight → 立即拿票
        # 否则：等待位 < queue_max → 排队等待；否则 False → 调用方返回 429
```
- 用 `threading.BoundedSemaphore(max_inflight)` + 计数器实现，**不用无界队列**。
- `429` 响应体给出 `{"detail": "...", "inflight": N, "queued": M, "retry_after_s": X}`，
  并累加指标 `rag_api_rejected_total`（Prometheus）。

### 3.3 答案缓存瘦身（F5）

`Answer` 的 `chunks` / `evidence` 里带**整块全文**（每块可达 1200+ 字符 × 10 块）。
缓存 `Answer` 对象时，只保留命中需要的字段，`chunks`/`evidence` 截断到
`PERF_CACHE_CHUNK_CHARS`（默认 400）—— 语义不变（缓存命中只用于返回答案与引用），
内存占用下降一个数量级。

### 3.4 Ollama 驻留控制（F7）

- 所有 Ollama 请求统一从 `perf_config.ollama_keep_alive` 取值，默认 `"5m"`。
- 提供 `POST /api/v1/admin/unload`（本地回环限定）主动卸载，与 `soak` 结束时调用。
- **一次只驻留一个模型**：生成与嵌入交替时，`keep_alive` 短可让前一个自然过期。

### 3.5 解析任务队列（F9）

- `POST /api/v1/uploads`（multipart）→ 校验（大小/扩展名/PDF 魔数）→ 入队 → `202 {task_id}`。
- 队列满 → **429**（不堆积）。
- worker 线程做真实解析：用 `fitz`(PyMuPDF) 打开 + 页数/文本抽样，产出 chunk 统计，
  写 `部署/日志/parse_tasks.jsonl`。**不做全量入库**（索引只读，且耗时不可控）。
- `GET /api/v1/tasks/{task_id}` 返回 `pending|running|done|failed` 与耗时。

## 4. 不可开关的硬约束

- 并发上限 20（压测器侧钳制）。
- 熔断：提交内存 > 80% 或错误率 > 50%。
- `keep_alive` 请求头级统一（不允许任何路径漏传）。

## 5. 回滚方案

`PERF_ENABLED=0` 一键回到基座行为；`研发/基座快照/` 保留优化前的 `app/` 与 `service/` 全量副本，
可直接 `robocopy` 覆盖回滚。见 `部署/OPERATION.md` §回滚。
