# 优化报告（LightRAG 图谱构建与检索优化）

- 工单编号：人工智能NLP-RAG项目-LightRAG优化
- 优化对象：传统 RAG 系统的**图谱构建**与**检索**环节
- 数据来源：`graph_db/graph_meta.json`、`output/eval_results.json`、`output/latency_bench.json`（真实运行）

---

## 1. 优化总览

传统 RAG 采用扁平化向量表示，难以建模实体间复杂语义关系，多实体关联推理易出现逻辑断层，且全量更新成本高。本工单按 LightRAG 思路做了 **5 项核心优化**：

| # | 优化项 | 目标 | 落地位置 |
|---|---|---|---|
| 1 | 领域化 Schema（实体/关系类型） | 提升抽取准确度、降低类型漂移 | `src/config.py`、`src/lightrag/schema.py` |
| 2 | 规则 + LLM 混合抽取 | 全量覆盖 + 语义补充，控制成本 | `src/lightrag/extractor.py` |
| 3 | 双层检索（局部 + 全局） | 兼顾实体级与概念级查询 | `src/lightrag/retriever.py` |
| 4 | 三通道 RRF 融合 | 图结构 + 语义 + 字面互补 | `src/lightrag/retriever.py` |
| 5 | 增量更新（图差异） | 新数据局部更新，免重建 | `src/lightrag/graph_store.py`、`src/lightrag/index.py` |

---

## 2. 优化一：领域化 Schema（实体/关系类型）

**问题**：官方默认通用类型（organization / person / concept / event…）粒度粗，会把“募投项目”当“产品”、“关联方”当“公司”，产生抽取歧义。

**优化**：面向招股说明书定义 **16 类实体 + 18 类关系**（受控类型），抽取后做类型校验收敛：

- 实体：公司、人物、产品、技术、行业、**募投项目**、**标准**、**资质**、**奖项**、地点、**财务指标**、**股东**、**关联方**、**客户**、**供应商**、政府机构；
- 关系：控股、参股、持股、任职、生产、研发、采购、销售、竞争、位于、属于、获得、参与制定、投资、上游、下游、关联交易、担保。

**效果**：图谱实体 2167 / 关系 1327，类型分布清晰（行业 1013、公司 653、财务指标 210、人物 185、募投项目 2、关联方 8、股东 5、标准 16、奖项 2、供应商 1、客户 2、资质 1…），领域类型可被下游问答精确使用。

---

## 3. 优化二：规则 + LLM 混合抽取

**问题**：纯 LLM 抽取成本高（CPU 推理慢）且 JSON 不稳定；纯规则召回不了语义关系。

**优化**：
- **规则抽取覆盖全量 2357 块**（1.3s，零 LLM 成本）：公司全称、董监高/法定代表人、标准号、奖项、财务指标、组织结构图枚举、持股比例、地点、行业/上下游 → 6553 条，构成图谱“骨架”；
- **LLM 抽取精选 150 块**（559s）：补充研发/生产/竞争/关联交易等语义关系 → 351 条，构成图谱“血肉”；
- 块选择按“章节关键词 / 公司名 / 董监高 / 标准 / 奖项 / 表格”打分取 Top-N，保证两公司均被覆盖；
- LLM 输出三级容错解析（代码块剥离 → 平衡括号截取 → 正则兜底），适配本地 1.5B 模型的不稳定 JSON。

**效果**：在可控成本（约 9 分钟）下同时获得高准确率的确定性事实与语义关系。

---

## 4. 优化三：双层检索（局部 + 全局）

**问题**：扁平向量检索对“多实体关联/概念级”查询召回不足。

**优化**（对齐 LightRAG 双层机制）：
- **局部检索（low-level）**：查询 → 实体/关系向量召回 + 字面命中 + **一跳图扩展** → 关联来源块；
- **全局检索（high-level）**：查询 → **主题（社区）向量**召回 → 主题覆盖块，贡献按 `相似度 / log(1+规模)` 衰减。

**主题（社区）优化**：招股说明书实体图高度连通，用“连通分量”会并成 1~2 个巨簇；改用 **Louvain 社区发现**（回退贪心模块度 → 连通分量），得到 **20 个粒度适中的主题**，使全局检索具备区分度。

---

## 5. 优化四：三通道 RRF 融合

**问题**：仅靠图遍历会漏召“未与实体强绑定的数值表格块”（如军用领域收入序列表）。

**优化**：候选池 = 图召回块 ∪ BM25 Top-60 ∪ 稠密 Top-60；再以 **三通道 RRF** 融合：

```
稠密（局部语义）  权重 0.5
关键词（局部字面）权重 0.5
图结构（实体/关系/主题）权重 0.25
→ 同一线性融合重排器（与 RAG 同口径）→ 0~1 最终分
```

**效果**：图结构决定“召回哪些块”（与 RAG 的本质区别），打分沿用与 RAG 同口径信号，从而得到**可比的 RAGAS 指标**。Q260（军用领域收入序列）上下文精确率由 RAG 0.25 提升至 LightRAG 0.33；Q793（下游行业）由 0.78 提升至 0.84。

---

## 6. 优化五：增量更新（图差异分析）

**问题**：全量更新使知识库维护成本随规模增长。

**优化**：`incremental_update(new_chunks)` 只对新切片抽取，`GraphStore.diff` 计算新增/受影响节点与边，`apply_diff` 仅更新差异部分并重建主题与受影响向量（`_rebuild_vectors_incremental`），**无需重跑全量抽取**。新增数据到来时可秒级整合。

---

## 7. 性能优化

| 优化点 | 措施 | 效果 |
|---|---|---|
| 查询编码 | 多路查询一次性批量编码（`encode_many_cached`） | 减少 Ollama 固定调用开销，冷启动 LightRAG 2.21s < RAG 2.33s |
| 邻接扩展 | `LR_NEIGHBOR_LIMIT=12` 限制巨节点 | 避免候选被稀释 |
| 主题衰减 | `1/(1+log(1+size))` | 避免巨簇把整库拉进候选 |
| 增量向量化 | 只补新实体向量 | 免全量重算 |

## 8. 优化效果对比

### 8.1 RAGAS 指标（16 题均值）

| 指标 | 传统 RAG | LightRAG | 变化 |
|---|---|---|---|
| 忠实度 | 1.0000 | 1.0000 | — |
| 答案相关性 | 0.8182 | 0.8183 | +0.0001 |
| 上下文精确率 | 0.8550 | **0.8646** | **+0.0096** |
| 上下文召回率 | 0.9531 | 0.9531 | — |
| 答案正确性 | 0.8857 | 0.8857 | — |
| **综合** | 0.9024 | **0.9043** | **+0.0019** |

### 8.2 响应时间（16 题）

| 口径 | 传统 RAG | LightRAG |
|---|---|---|
| 冷启动 平均 | 2.33s | **2.21s** |
| 冷启动 P95 | 2.57s | **2.26s** |
| 热缓存 平均 | 0.059s | **0.042s** |

### 8.3 功能/鲁棒性

| 项 | 传统 RAG | LightRAG |
|---|---|---|
| 功能测试通过率 | 9/10 | **10/10** |
| 域外拒答（TC-08） | 失败（返回无关片段） | **通过（正确拒答）** |

### 8.4 逐题增益（综合分差值，节选）

| 题 | 场景 | Δ(LightRAG−RAG) |
|---|---|---|
| Q260 | 军用领域收入序列（表格） | **+0.0167** |
| Q793 | 电子信息行业下游行业 | **+0.0114** |
| Q6 | IC 市场增长率（图形） | +0.0083 |
| Q4 | 非控制关系关联方清单 | +0.0065 |
| Q2 | 募投项目清单 | −0.0076 |

> 结论：LightRAG 在**多实体/表格/概念级**问题上更优（图结构扩展召回更完整），在**单一清单型**问题上与 RAG 相当或略低；整体综合分与响应时间均不劣于 RAG，且域外鲁棒性显著增强。

## 9. 后续可优化方向

1. **LLM 抽取扩容**：将精选块从 150 扩至 260（`LR_MAX_LLM_CHUNKS`），进一步丰富语义关系；
2. **关系类型均衡**：当前“属于”关系占比较高（行业实体自动生成），可按需降权或拆分；
3. **检索权重调优**：对 `LR_GRAPH_CHANNEL_W` 与局部/全局配比做网格搜索；
4. **重排器升级**：引入 LLM 重排（`RERANKER=llm`）提升答案相关性；
5. **增量更新实测**：补充“新增文档 → 增量更新 → 指标不降”的实验。
