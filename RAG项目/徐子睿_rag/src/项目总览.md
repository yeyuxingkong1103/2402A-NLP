# 跑通验证_新版本｜项目总览

## 一句话概括
这是一个本地可跑通的多文档 RAG 知识库系统：
**PDF 文档 → 解析 / 清洗 / 分块 → 向量化入库 → 混合检索 / 问答 → 前端可视化展示**。

## 这三份文档分别讲什么
### 1）01 · 需求分析
- 说明项目要解决什么问题
- 核心目标是做一个**多文档 RAG 知识库**
- 支持上传、构建、浏览、检索、问答、删除文档
- 强调：**无依据不编造、答案带引用、构建过程可视化**

### 2）02 · 总体架构
- 说明系统怎么分层
- 前端：`static/`（index.html + styles.css + js/）
- 后端：`backend/server/`（包）
- 管线：`backend/pipeline/`（包）
- 检索：`backend/retrieval/`（包）
- 数据：`data/pdfs/`、`documents.json`、Milvus 集合 `rag_docs_v6`
- 模型：`bge-m3`、`qwen2:7b`

### 3）06 · 接口文档
- 说明 API 怎么调用
- 上传：`POST /api/upload`
- 构建状态：`GET /api/build/status`
- 文档列表：`GET /api/documents`
- 检索：`POST /api/search`
- 问答：`POST /api/ask` / `POST /api/ask/stream`
- 知识库：`GET /api/kb/overview`、`GET /api/kb/chunks`、`DELETE /api/kb/document`

## 项目主线
1. 上传 PDF
2. 后台构建：解析 → 清洗 → 分块 → 向量化 → 入库
3. 前端轮询构建状态
4. 混合检索：向量召回 + BM25 关键词召回 + 加权 RRF
5. LLM 生成答案并返回引用
6. 知识库页查看 chunk 和文档信息

## V1 → V3 迭代了什么（每轮新添的功能，不只指标）

**迭代方针**：V1 → V2 → V3 **逐轮增强，不推倒重来**；每轮在上一版可运行能力之上只加一个可验证的新能力，同一套评测集回归，改动可归因。

### V1 · 最小可用（先把 RAG 闭环跑通）
**新增功能**：
- 上传 PDF → 后台自动构建：解析 → 清洗 → 分块 → BGE-M3 向量化 → Milvus 入库
- 纯向量检索（语义相似 top5）
- qwen2:7b 问答生成 + 答案带 **页码溯源**
- 先建**评测集 + 基线报告**（立尺子，之后每轮都能分数说话）

**这轮回答不了的**：功能清单类精确问题（“回收装置应具备哪些功能”）纯靠语义相似会漏召回（miss 1 题）；链路黑盒，看不到中间发生了什么。

### V2 · 可观测 + 复合检索（新增 3 个能力）
**新增功能**：
1. **检索链路可视化（trace）**：查询路由 → 语义召回 → 关键词召回 → RRF → 精排 → 生成，每一步状态/耗时/命中明细都展示在前端（能看到“为什么是它命中”）
2. **复合检索**：在向量路之上新增 **jieba BM25 关键词路**，双路 top20 → **加权 RRF 融合（λ=2.5，网格搜索确定）**
3. **复杂元素补齐**：p10 流程图、表 1 数值等此前文本层提不到的内容也能检索到

**效果**：漏召回的“功能清单”题全部救回（miss 0），recall@5 0.9167→**1.0**，MRR 0.6042→**0.8917**；前端多了检索链路可视化页签。

### V3 · 进阶增强（新增 4 个能力）
**新增功能**：
1. **查询改写**：规则化术语展开（`normalize_query_text` + `REWRITE_RULES`，不依赖 LLM）——问“净化装置有哪些功能”自动补全“过滤/干燥/吸附/低温冷却/精馏”等术语，提高精确匹配命中率
2. **LLM 候选精排**：qwen2:7b 对 RRF 候选按 0-5 分重排（提升排序稳定性），**失败自动回退 RRF 顺序**，链路不因单点失败中断
3. **SSE 流式问答**：答案逐字输出（打字机效果），不用等全部生成完
4. **稳定性**：向量召回门限 cosine 0.5（候选被过滤光即固定拒答文案）、上下文预算、构建步骤状态机（构建失败不产生半成品库）

**效果**：检索指标与 V2 持平（1.0 / 0.8917，精排不破坏召回），但**排序更稳、体验更顺、更诚实**（安全集 20 条无依据问题 refusal 三轮都 1.0）。

### 一句话总结
| 版本 | 一句话 |
|---|---|
| V1 | 先立尺子再实现：最小闭环“能不能用” |
| V2 | 链路看得见 + 双路召回：解决“漏召回、没法归因” |
| V3 | 改写 + 精排 + 流式 + 稳：更稳更好用 |
