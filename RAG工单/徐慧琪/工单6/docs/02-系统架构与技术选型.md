### 2.1 为什么全文检索要自研（而不是只调 BM25）

工单对全文检索提了三条硬技术要求：**倒排索引**、**布尔查询/短语匹配/模糊匹配**、
**多字段检索**。`rank_bm25` 只提供"词袋打分"，不提供位置信息（无法短语匹配）、
不支持布尔语法、没有字段概念。自研位置倒排索引把三者一次做齐：

```
postings[field][term] = { doc_idx: (pos1, pos2, …) }     ← 位置信息 → 短语匹配
doc_len[field][doc_idx] / avgdl[field]                   ← BM25 的文档长度归一
df[field][term] = len(postings[field][term])             ← 文档频率 → idf
```

字段划分（多字段检索）：

| 字段 | 内容 | 权重 |
| --- | --- | --- |
| `title` | heading_path 各级标题 + 表格标题 + 组织图节点名 | 2.5 |
| `body` | 块正文（text） | 1.0 |
| `summary` | 表格列表头 / 父块前 160 字 | 1.2 |

打分：各字段 BM25（k1=1.5, b=0.75）加权求和；短语命中整体 ×1.6。

### 2.2 数字口径归一（实测踩坑）

招股书问题的主干是数字，但同一数字有多种写法。首版按字面切词时，
查询 `5,520` 与正文 `5,520.00` 是两个不同 term，**全文检索直接漏检**。
`src/tokenizer.py` 因此对数字产出等价形态（小数部分全 0 时去小数、千分位去逗号），
两种形态都进倒排表：

```
"5,520.00万元"  →  token:  5,520.00  |  5,520  |  5520
"25.04%"        →  token:  25.04%              （非零小数不裁剪，避免 25%≠25.04% 的事实混淆）
"BGE-M3"        →  token:  bge-m3              （英文词允许内嵌数字，否则被切成 bge-m + 3）
```

## 4. 关键设计决策（含权衡）

### 4.1 混合检索的权重归一化口径（实测修正）

RRF 是"名次类"融合。若把两路权重按**和为 1** 归一化，会**系统性压制少数臂**：

> 实测 id1「本次发行股数是多少，占发行后总股本的比例是多少」：
> 正确答案是全文臂第 1 名（权重 0.4 → 0.4/61 = 0.0066），
> 却被向量臂第 15 名（0.6/75 = 0.0080）压过 —— **正确答案进不了候选**。

修正为**按最大值归一**（`RetrievalConfig.normalized_weights`）：

* `rrf` / `vote`：`w_r / max(w)` —— 被信任的那一路保持满权重，另一路按比例缩放；
  默认等权（0.5/0.5）时恰好退化为上游验证过的**无权重 RRF（k=60）**，与 01~05 可比；
* `weighted`：`w_r / Σw` —— 加权平均是凸组合，和归一才语义正确。

### 4.2 精排的显存闸门与降级策略

8G 显存是硬约束（桌面应用常年占用 3~4G）。`src/rerankers.py`：

* fp16 + `device_map` 直载（fp32 先落内存再搬运会触发 `OSError 1455` 甚至段错误）；
* 加载前查剩余显存，**<2.5G 改用 CPU 推理**（20 候选约 1~2s，稳定性优先）；
* 加载失败进入 **120s 冷却期**而非永久熔断（瞬时内存不足不该让进程此后都不精排）；
* 任何精排异常都不打断问答：降级为"按召回顺序截断"，并在
  `analysis.rerank_info.degraded` / 界面 / 报告中**如实标注**（不假装精排过）。

### 4.3 精排分打平时的名次裁决

Cross-Encoder 分数差在噪声量级时（实测 0.9956 vs 0.9972，差 0.0016）排序无统计意义，
此时回退用 RRF 名次裁决（`RERANKER_TIE_EPSILON=0.01` 分桶）：RRF 聚合了稠密+稀疏
两路独立信号，比噪声级的分数差更可信。

### 4.4 全文检索的三个实现细节（均为实测踩坑）

| 现象 | 根因 | 修正 |
| --- | --- | --- |
| 短语 `"存在控制关系的关联方"` 永不命中 | 查询侧用了带停用词过滤的分词，"的"被丢掉，位置不再相邻 | 短语一律用**完整分词**（`tokenize`）构建位置序列 |
| 模糊 `注册资木~` 命不中 `注册资本` | 模糊词被 jieba 切碎成 `注册/资/木`，扩展作用在碎片上 | 模糊词按**整体词面**处理（无空格即单 term） |
| 短语分数反而低于同词不带引号 | 多字段打分口径不一致（普通词累计各字段，短语取 max） | 短语同样**累计各字段** BM25 后再乘加成 |

### 4.5 表格行列举补全（生成侧兜底）

id4「不存在控制关系的关联方企业有哪些」：表格 7 家企业，前 5 家关系列相同，
3B 模型合并成一句只报 5 家；**即使重试提示里点名漏了哪两家，模型仍照旧**。
故与 `complete_numeric_list`（数字抽取式校正）同构，新增
`complete_row_list`：列举型问题上，若答案已覆盖该表 ≥50% 行且漏行 ≤5，
则把漏行**确定性补入**（行名全部取自上下文表格，属抽取而非编造）。
