# 系统架构流程图（RAG 知识库问答系统）

系统基于本地 langchain2 环境 + Ollama 本地模型，实现"离线建库 + 在线问答"两条管道。
本文件为 Mermaid 源码，可直接在支持 Mermaid 的编辑器（Typora / VS Code / mermaid.live）渲染成图。

工单编号：人工智能 NLP-RAG-基于 PDF 文档的问答系统

---

## 一、整体架构（总览）

```mermaid
flowchart TB
    subgraph Offline["① 离线·构建知识库"]
        A[招股说明书1.pdf] --> B[pdf_parser 解析<br/>文字+表格+页码]
        B --> C[knowledge_base 切片<br/>RecursiveCharacterSplitter]
        C --> D[bge-m3 分批嵌入<br/>每批50条]
        D --> E[(FAISS 向量库<br/>vector_db)]
    end

    subgraph Online["② 在线·检索问答"]
        U[用户提问] --> Q[query_understanding<br/>意图识别·消歧·子问题]
        Q --> R[retriever 混合检索]
        R --> E
        R --> F[BM25 词法检索<br/>jieba分词]
        E --> F1[Top-K 语义召回]
        F --> F2[Top-K 词法召回]
        F1 & F2 --> G[RRF 倒数排名融合]
        G --> H[qa_engine 生成]
        H --> I[答案 + 依据页码]
    end

    E -.读索引.-> R
```

## 二、混合检索流程（retriever.py）

```mermaid
flowchart LR
    A[user_query] --> B{query_understanding}
    B -->|消歧后的主问题| C1[向量检索<br/>FAISS similarity_search]
    B -->|子问题补充| C1
    B -->|问题分词| C2[BM25 词法检索<br/>jieba + BM25Okapi]
    C1 --> D1[Top-K=6 篇]
    C2 --> D2[Top-K=6 篇]
    D1 --> E[RRF 融合<br/>1/(k+rank) 求和排序]
    D2 --> E
    E --> F[Top N 检索上下文<br/>含页码 metadata]
```

## 三、知识库构建流程（knowledge_base.py）

```mermaid
sequenceDiagram
    participant Script as scripts/build_kb.py
    participant KB as knowledge_base.py
    participant PDF as pdf_parser.py
    participant EMB as Ollama bge-m3
    participant S as FAISS vector_db

    Script->>KB: build_kb(force_rebuild)
    KB->>PDF: parse_pdf()
    PDF-->>KB: PageDoc 列表(页码+文本+表格)
    KB->>KB: RecursiveCharacterTextSplitter 切片
    KB->>EMB: _BatchedEmbeddings(每批50) 嵌入
    EMB-->>KB: 向量
    KB->>S: FAISS.from_documents save_local
    Script->>S: kb_stats 统计切片数
```

## 四、在线问答流程（query_understanding → qa_engine）

```mermaid
sequenceDiagram
    participant U as 用户/Streamlit
    participant QU as query_understanding
    participant R as retriever(向量+BM25+RRF)
    participant QE as qa_engine
    participant LLM as Ollama deepseek-r1

    U->>QU: 原始问题
    QU->>LLM: 结构化提示词(意图/实体/消歧/子问题)
    LLM-->>QU: JSON
    QU->>R: retrieval_queries(主问题+子问题)
    R->>R: 语义+词法召回 + RRF 融合 + 去重
    R-->>QE: contexts(含页码) + top_k
    QE->>LLM: 注入依据的生成提示词
    LLM-->>QE: 答案
    QE-->>U: AnswerResult(answer, elapsed, sources)
```

## 五、评估流程（scripts/evaluate.py + build_report.py）

```mermaid
flowchart TB
    A[data/questions.json<br/>10 道题 + 参考答案] --> B[QAEngine 逐题回答]
    B --> C[RAG 回答<br/>带上下文+耗时]
    B --> D[纯 LLM 回答<br/>无上下文+耗时]
    C & D --> E[output/evaluation_report.json]
    E --> F[build_report.py]
    F --> G[output/evaluation_report.md<br/>对比表格+命中统计+结论]
    F --> H[人工命中检查<br/>关键数值/专有名词]
```

---

## 说明

- **设计决策**：采用 向量(FAISS) + 词法(BM25) 混合检索，用 RRF 倒数排名融合平衡"语义相似"与"精确匹配"，适配招股说明书中大量数字、公司名、专有名词的检索。
- **防幻觉**：qa_engine 提示词强制"仅依据参考文档回答、注明来源页码、不编造"。
- **可观测性**：每条回答记录 elapsed 耗时与 sources（页码+得分），支撑"响应 ≤ 3s"验收。
