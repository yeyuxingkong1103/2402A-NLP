>
> | 级别 | 字段 | 含义 | 是否进检索命中判定 |
> | --- | --- | --- | --- |
> | **完整** | `evidence_pages_complete` | 承载**完整答案**原句的页 | ✅ 进 |
> | **支撑** | `supporting_pages` | 承载**部分证据**（部分数字/节点/互证句）的页 | ✅ 进（`evidence_pages` = 完整 + 支撑） |
> | **相关** | `related_pages` | 相关但**不含证据原句**的页 | ❌ **不进**，仅登记 |

> 已标注「完整/支撑/相关」的行按标注执行。
>
> **誊写规则（避免手工分级出错）**：本表逐题的页级别**直接誊写 `研发/data/eval/golden_qa.jsonl` 的三个字段**，
> **不得按语义自行重新分级**。golden 每题带六个页字段，实测满足：
>
> ```
> evidence_pages         = evidence_pages_complete + supporting_pages
> evidence_pages_union   = evidence_pages_complete + supporting_pages + related_pages
> evidence_pages_primary = 主证页（仅决定引用优先级，不影响命中判定）
> ```
>
> 以上等式在 16 题**全域成立**（由 `设计/复现脚本/验收标准_vs_golden_对拍.py` 每次运行时校验）。

> **本表页级别字段与 `研发/data/eval/golden_qa.jsonl` 一一对应；如有出入，一律以 golden 为准。**

### 3.4 判分口径（**必须写进测试报告**）

1. **判对 = 确定性关键字判定**：答案（数值归一化后）含该题**全部** `answer_keywords`，且**不含**任何 `forbidden` 关键字。
   - 数值归一化：去千分位逗号、全角转半角、`%` 与「百分之」等价、`万元/亿元` 按原值比对
     （例：`15,000 万元` 与 `15,000.00万元` **等价**，见 id 207 页 490）。
   - `answer_keywords_any_of`：**任一命中即算该组通过**，用于兜住同义/简称正答
     （例：id 95 的正名《某视频指挥系统技术规范（1.0版）》与简称**《某视频技术规范1.0》**）。
   - **禁止**用 LLM 自评冒充准确率；若另做 LLM 辅助判定，必须**并列**给出确定性判定结果并说明差异。
2. **「检索命中」≠「回答判对」**，两者**分别报告**：
   - 检索命中 = 证据原文（`evidence` 逐字或归一化后）**落在返回的 chunk 中**；
   - 命中判定只用 **`evidence_pages_complete` + `supporting_pages`**（合称 `evidence_pages`）；
     **`related_pages` 不参与命中判定**（无证据原句，参与会虚高命中率）；
   - **不得**以「引用页 == `evidence_pages`」判定命中（会把无关页误计为命中、虚高）。
3. 逐题记录：问题、系统答案、golden 答案、是否判对、证据页、检索命中与否、`latency_ms`、引用是否可回溯。
4. 第 5、6 题须额外记录：`extraction_method`（`clip_zero_shot` / `geometry+anchor` / 纯几何）、框图/图表解析产物路径。
   - **图像题严禁声称使用了 OCR**（本机 OCR 依赖全缺，见 `设计/环境事实.md` §2.4）：
     页 72 数值来自**像素级抽取 + `read_image` 视觉复核**，页 39 结构来自**文本层按 x 列聚类复原**，
     二者的原图/中间产物均已留 sha256（见 `设计/复现脚本/证据图/`）。

## 4. 延迟口径（**最容易被测歪，先定义后测量**）

| 项 | 定义 |
| --- | --- |
| **主口径** | 请求发出 → 完整答案返回（`latency_ms.total`） |
| **辅助口径** | 首字延迟（第一个流式 `delta` 到达），用于「首字 ≤3 s」的旁证 |
| **测量前提** | ① 服务**已完成预热**（`--no-warmup` 一律标注为调试口径）；② **独占 Ollama**（`ollama ps` 无其它模型加载；到 11434 的 ESTABLISHED 连接数 = 0）；③ 同一窗口不并发跑其它评测 |
| **达标线** | **16 题逐题 ≤ 3000 ms**；若某题超线，**必须如实报告题号与原因**，不得删除该样本 |
| **必报统计量** | **P50 / P95 / 最大**（禁止只报平均值） |
| **缓存口径** | 缓存命中与未命中**分别统计**；不得用命中缓存的结果冒充全量性能 |

**实测基线（供对照）**：`qwen2.5:3b` 冷启动首字 **3430.8 ms**（必违约）、预热后首字 **23.5~25.2 ms**、预热后总耗时 **216~217 ms**。
→ 若实测延迟超标，**先查是否冷启动/并发**，再查实现。

## 9. 未达标时的处理规则（**禁止造假的替代行为**）

| 情形 | 允许的处置 | **禁止** |
| --- | --- | --- |
| 准确率 < 90% | 如实报告失败题号 + 归因；**在 golden 正确性经复核的前提下**做检索/提示词优化并复测 | 放宽判分关键字、删样本、改 golden 迁就系统 |
| 延迟超标 | 先复测冷/热与独占状态；附独占证据；做缓存/批处理优化并给出前后对比 | 用缓存命中样本充当全量、只报平均值 |
| CLIP 权重下载失败 | 如实记录失败原因 + 实际替代实现（结构树/数值表通道） | 伪造 CLIP 相似度或声称已启用 |
| Docker 构建失败 | 如实记录未完成原因 + 静态校验（compose config） | 声称已构建成功 |
| 某能力确实不可用 | 在报告、README、`交付物核验.md` 中登记为**已知限制** | 静默省略、含糊表述 |
