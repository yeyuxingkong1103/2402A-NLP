# 代码结构

## 1. 根目录结构

```text
RAG项目/
├── 01-设计/                    # 架构、流程图、思维导图和接口文档
├── 02-研发/
│   ├── 01-研发说明.md
│   ├── 02-代码结构.md
│   └── 核心代码/               # 可独立运行的研发源码
│       ├── app/
│       │   ├── api/v1/         # REST API、Schema、访问控制与依赖装配
│       │   ├── core/           # 配置、安全、指标、请求限制
│       │   ├── ingestion/      # 解析、清洗、分块、向量化、索引
│       │   ├── llm/            # LLM 客户端
│       │   ├── memory/         # 会话、角色、短期和长期记忆
│       │   ├── rag/            # 检索、重排、Prompt、生成与流式输出
│       │   └── main.py         # FastAPI 入口
│       ├── sql/                # MySQL Schema
│       ├── static/             # Web 页面
│       ├── build_knowledge_base.py
│       ├── requirements.txt
│       └── .env.example
├── 03-测试/                    # 用户自行补充测试截图
├── 04-优化/                    # 优化说明
└── 05-部署/                    # 检查、安装、启动、结束脚本
```

部署脚本直接进入 `02-研发/核心代码/` 安装依赖并启动应用，因此 `RAG项目/` 可作为完整交付目录单独提交。

## 2. API 层

| 文件 | 职责 |
|---|---|
| `app/api/v1/routes.py` | 文档上传、兼容 Query、索引统计 |
| `app/api/v1/chat_routes.py` | 标准问答、SSE 问答、问答健康状态 |
| `app/api/v1/kb_routes.py` | 知识库和文档 CRUD |
| `app/api/v1/session_routes.py` | 会话创建、历史、清空、结束、角色切换 |
| `app/api/v1/access.py` | 用户、租户、知识库和会话范围控制 |
| `app/api/v1/deps.py` | Redis、MySQL、记忆和角色等依赖装配 |
| `*_schemas.py` | Pydantic 请求与响应模型 |

## 3. 数据摄取层

| 文件 | 职责 |
|---|---|
| `parser_models.py` | 统一文档/页模型 |
| `parser_adapters.py` | 不同文件格式的解析适配器 |
| `parser.py` | 解析入口和策略选择 |
| `chunk_models.py` | 文本块模型和配置 |
| `chunk_strategies.py` | 分块算法实现 |
| `chunker.py` | 分块统一入口 |
| `dataset_cleaner.py` | 字段规范化、异常隔离和分类 |
| `dataset_dedup.py` | 精确/近似重复检测 |
| `embedding.py` | Embedding 客户端构建 |
| `vector_stores.py` | 向量存储抽象和实现 |
| `metadata_store.py` | MySQL 元数据存储 |
| `indexer.py` | 去重、向量写入和一致性处理 |
| `offline_builder.py` | 离线构建流程编排 |

## 4. RAG 层

| 文件 | 职责 |
|---|---|
| `chat_service.py` | 问答主流程编排 |
| `retriever.py` | Milvus 向量召回 |
| `bm25.py` | 稀疏关键词召回 |
| `hybrid_retriever.py` | 多路结果融合 |
| `multi_path_recall.py` | 可扩展多源召回 |
| `query_rewriter.py` | 问题改写与标准化 |
| `reranker.py` | 精排装配和筛选 |
| `reranker_providers.py` | Lexical、本地、HTTP、Mock 实现 |
| `prompt.py` | 上下文和系统提示词组装 |
| `prompt_templates.py` | 角色和业务模板 |
| `postprocess.py` | 回答清洗、引用和格式处理 |
| `refusal.py` | 无证据时的兜底话术 |
| `streaming.py` | SSE 事件输出 |

## 5. 记忆层

| 文件 | 职责 |
|---|---|
| `session_manager.py` | 会话元数据和生命周期 |
| `redis_memory.py` | 会话消息滑动窗口 |
| `milvus_memory.py` | 长期记忆门面 |
| `milvus_store.py` | 长期记忆的 Milvus 数据访问 |
| `memory_manager.py` | 短期/长期记忆协调 |
| `role_manager.py` | 角色配置和切换 |
| `extractors.py` | 订单号、时间、产品等信息提取 |

## 6. 应用入口与运行

```bash
cd RAG项目/02-研发/核心代码

# 启动 API
python -m app.main

# 离线构建知识库
python build_knowledge_base.py --file /path/to/knowledge.txt --kb-id 1
```

`核心代码/` 是当前工程运行代码的交付副本；后续如果继续修改根目录源码，应重新同步交付副本，避免版本漂移。
