# 接口文档 —— RAG 角色扮演系统

- Base URL：`http://localhost:8000`
- 协议：HTTP + JSON；流式接口使用 SSE（text/event-stream）
- 交互式文档：启动后访问 `http://localhost:8000/docs`（Swagger UI）
- 聊天界面：`http://localhost:8000/`（内置的单文件前端）

## 0. 根路径

**GET /**

按 `Accept` 头做内容协商：

- 浏览器（`Accept` 含 `text/html`）→ 返回聊天界面 `app/static/index.html`；
- 脚本 / curl → 返回 JSON：

```json
{ "service": "rag-roleplay", "version": "0.1.0", "docs": "/docs", "web": "/" }
```

静态资源挂在 `/static/*`（前端页面、图标）。

## 1. 健康检查

**GET /health**

请求：无参数

响应 `200 OK`：
```json
{
  "status": "ok",
  "components": {
    "llm": "ok",
    "embedding": "ok",
    "milvus": "ok",
    "sql": "ok",
    "memory": "ok"
  }
}
```
组件值：`ok` = 正常；`unavailable` = 不可达；`degraded` = 已降级但仍可用（目前只有 `memory`：Redis
不可达时自动降级为进程内内存，服务照常对话，代价是重启丢上下文）。任一组件非 `ok` 时 `status` 为 `degraded`。

降级时额外返回 `details` 说明**原因**（正常时不含该字段）：

```json
{
  "status": "degraded",
  "components": {"llm": "ok", "embedding": "ok", "milvus": "ok", "sql": "ok", "memory": "degraded"},
  "details": {"memory": "Redis 不可达: redis://127.0.0.1:6379/0"}
}
```

## 2. 对话（非流式）

**POST /chat**

请求：
```json
{
  "question": "试用期最长可以约定多久？",
  "role_id": "lawyer",
  "session_id": "user-123"
}
```

响应 `200 OK`（下面这段是 2026-09-23 本机实测的输出，`score` 是 BGE 精排后的语义分）：
```json
{
  "answer": "根据【资料2】第十九条的规定：1. 劳动合同期限三个月以上不满一年的，试用期不得超过一个月；2. 劳动合同期限一年以上不满三年的，试用期不得超过二个月；3. 三年以上固定期限劳动合同或无固定期限劳动合同的，试用期不得超过六个月。……",
  "sources": [
    {
      "text": "第二十一条 劳动合同可以约定试用期。试用期最长不得超过六个月。……",
      "title": "labor_law.md",
      "source": "data/corpus/lawyer/labor_law.md",
      "score": 0.719
    }
  ],
  "session_id": "user-123"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| question | string | 必填，用户问题 |
| role_id | string | 角色 id，默认 `psychologist` |
| session_id | string | 会话 id（短期记忆隔离），默认 `default` |
| answer | string | 角色化回答 |
| sources | array | 引用的知识库 chunk 及来源 |

## 3. 对话（流式 SSE）

**POST /chat/stream**

请求体同 `/chat`。响应 `200 OK`，`Content-Type: text/event-stream`，依次发送四类事件：

```
event: sources
data: {"sources": [{"text": "...", "title": "...", "source": "...", "score": 0.03}]}

event: delta
data: {"delta": "根据资料，"}

event: delta
data: {"delta": "精神障碍的诊断应当由精神科执业医师作出。"}

event: done
data: {"answer": "根据资料，精神障碍的诊断应当由精神科执业医师作出。"}

# 生成中途失败时（HTTP 仍是 200，错误只能从事件里读）
event: error
data: {"message": "APIConnectionError: ..."}
```

| 事件 | 载荷 | 说明 |
|---|---|---|
| `sources` | `{"sources": [...]}` | 首个事件，检索结果（同 `/chat` 的 `sources`） |
| `delta` | `{"delta": "..."}` | 增量文本，逐段到达 |
| `done` | `{"answer": "..."}` | 结束。`answer` 是**服务端后处理过的完整回答**，与 `/chat` 的 `answer` 一致；客户端的增量拼接可能与之有差异（清洗发生在收流之后），**前端应以 `done.answer` 为准** |
| `error` | `{"message": "..."}` | 生成中途失败。流已经以 200 开始，故错误码用不了，只能在事件里给 |

> 依赖掉线也不是都能靠 HTTP 状态码分辨：`/chat/stream` 只有在**开始吐流之前**（检索、取记忆、
> 组装提示词）失败才会返回 503；一旦流出去了就只能是 200 + `error` 事件。

## 4. 知识库

### 4.1 上传入库

**POST /knowledge/upload**（multipart/form-data）

请求参数：
- `file`：文件（PDF / txt / md / 图片 png·jpg·jpeg·bmp·webp·tiff）
  - 扫描件 PDF 与纯图片自动走 OCR（RapidOCR，本地免服务），`OCR_ENABLED=false` 时退回报错
- `role_id`：角色 id（query 参数，默认 `psychologist`，与 `/chat` 的默认角色一致）
- `chunk_size`：分块大小（query，默认 500）
- `chunk_overlap`：重叠长度（query，默认 50）
- `strategy`：分块策略（query，默认 `paragraph`；可选 `fixed/sentence/paragraph/title/semantic`）
- `summary`：是否用 LLM 给每个 chunk 生成摘要（query，默认 `false`）

响应 `200 OK`：
```json
{
  "message": "ok",
  "chunk_count": 6,
  "source": "upload://labor_law.md",
  "role_id": "lawyer"
}
```

### 4.2 文档列表

**GET /knowledge/list?role_id=lawyer**

响应 `200 OK`：
```json
{
  "documents": [
    {
      "id": 1,
      "role_id": "lawyer",
      "source": "data/corpus/lawyer/labor_law.md",
      "title": "labor_law.md",
      "chunk_count": 21
    }
  ],
  "total": 14
}
```

## 5. 角色

### 5.1 角色列表

**GET /role/list**

响应 `200 OK`（内置 2 个角色：心理咨询师、律师；`avatar` 是单个 emoji，前端直接渲染在头像位置）：
```json
[
  { "role_id": "lawyer", "name": "律师", "avatar": "⚖️", "description": "基于法律条文与判例的普法咨询与法律常识助手" },
  { "role_id": "psychologist", "name": "心理咨询师", "avatar": "🧠", "description": "提供情绪疏导、压力管理与心理健康科普的心理咨询师" }
]
```

### 5.2 角色详情

**GET /role/{role_id}**

响应 `200 OK`：
```json
{ "role_id": "lawyer", "name": "律师", "description": "基于法律条文与判例的普法咨询与法律常识助手" }
```

### 5.3 创建/更新角色

**POST /role**

请求：
```json
{
  "role_id": "lawyer",
  "name": "法律助手",
  "description": "基于法律条文与判例的法律咨询助手",
  "system_prompt": "你是一名资深律师……只依据知识库作答……"
}
```

响应 `200 OK`：同角色详情。

## 6. 错误码

| HTTP 状态 | 场景 |
|---|---|
| 400 | 文档解析后无有效文本（扫描件需 OCR 未识别成功，或 `OCR_ENABLED=false`）、不支持的文件类型、未知分块策略 |
| 404 | 未知角色（`role_id` 不在角色表里）：`/chat`、`/chat/stream`、`/knowledge/upload`、`/role/{role_id}` 在进入业务前先校验角色，故都是 404 而不是 500 |
| 422 | 请求参数校验失败（如 question 为空、`role_id` 含非法字符） |
| 502 | 模型一个字都没答（空答案 `EmptyAnswerError`）：模型被截断或上游返回空 `choices`，与"依赖掉线"是两种语义，故不并入 503 |
| 503 | **依赖运行中掉线**（LLM / 向量库 / 关系库 / 记忆），`detail` 里带异常类型便于排查。**`/chat/stream` 只覆盖"开始吐流之前"**（检索、取记忆、组装提示词），吐流之后 HTTP 已是 200，只能改用 `error` 事件（见第 3 节） |

> 定位实现时按**函数名**搜，不要按行号——本仓注释密度高，行号很容易变。
> 例如 404 的判定在 `app/api/chat.py` 的 `_ensure_role()`，空答案在 `app/core/errors.py` 的 `EmptyAnswerError`。
