```
┌─────────────────────────────────────────────┐

├─────────────────────────────────────────────┤
│ 查询理解层：query_router                      │
│   · 视觉引用识别（图3 / 第11页 / 部件编号）     │

│   · BM25 关键词召回 + bge-m3 向量召回          │

│ 知识存储层：Milvus + 分块JSON + 图描述JSON      │
├─────────────────────────────────────────────┤

└─────────────────────────────────────────────┘
```

## 三、RAGFlow 原有检索流程剖析（任务一）

工单要求剖析 RAGFlow 多模态检索架构。RAGFlow 的检索流程为：
**Query 生成 → 多路召回（全文/向量）→ 混合排序（RRF/加权）→ 重排 → 返回**。

其瓶颈在工业图文场景表现为：
1. **检索无关（故障1）**：仅靠“部件”“编号”等泛文本关键词召回，返回大量提及部件但不含目标图纸的文本块。
2. **图文割裂（故障2）**：即使召回图纸页面，也无法将查询词与图纸视觉特征关联，LLM 缺视觉信息。

本项目的优化正是针对这两个故障：
- 故障1 → **视觉引用识别 + 图描述增强召回**：定位到图3 后强制注入图描述，保证 Top-K 含图3 有效描述。
- 故障2 → **跨模态 Prompt + 结构化图描述**：将部件位置关系、物料流向显式喂给 LLM。

## 四、关键检索策略（任务二）

| 策略 | 实现 | 效果 |
|------|------|------|
| 多路召回融合 | BM25（原始 query 关键词）+ 向量（增强 query）→ RRF(k=60) | 兼顾精确匹配与语义 |
| 图文联合向量检索 | 图描述拼入 query 后统一编码检索 | 图文语义联合相似度 |
| 重排模型 | bge-reranker-v2-m3 对 Top-20 精排 | 优先图文语义最匹配片段 |
| 提示工程 | CROSSMODAL_PROMPT 明确“结合图纸描述分析” | LLM 获得视觉推理依据 |
