## 四、运行步骤（一键与分步）

### 4.1 一键流水线

```powershell
python run_pipeline.py
```

顺序执行：`数据转换 → LoRA 微调 → 微调前后评估 → 报告生成`。

### 4.2 分步执行（推荐，便于观察每步真实输出）

```powershell
# ① 数据格式转换（产出物 1）
python convert_data.py

# ② LoRA 微调（产出物 2）—— 至少 1 个 epoch
python train_lora.py --epochs 2

# ③ 微调前后对比评估（产出物 3）
python evaluate.py

# ④ 产出物生成
python tools/gen_flowcharts.py         # 架构图 / 流程图
python tools/render_terminal_shots.py  # 真实运行截图
python tools/render_ui_shots.py        # 界面截图 / 指标对比图
python tools/make_demo_video.py        # 演示视频（截图 + 字幕）
```

### 4.3 冒烟测试（快速验证链路）

```powershell
python run_pipeline.py --smoke          # 少量步数 + 小评估集
python train_lora.py --max-steps 6      # 仅训练前 6 个优化步
python evaluate.py --limit 12           # 仅评估前 12 题
```

### 4.4 复用已有适配器（跳过训练）

```powershell
python run_pipeline.py --skip-convert --skip-train
```

## 六、生产 GPU 部署（Qwen2-VL-2B + LLaMA-Factory）

本工单同时给出可直接用于生产 GPU 的微调配置：`config/llamafactory_qwen2vl_lora.yaml`。

```bash
# 安装 LLaMA-Factory
git clone https://github.com/hiyouga/LLaMA-Factory.git && cd LLaMA-Factory
pip install -e ".[torch,metrics]"

# 数据格式已由 data_converter 导出为 sharegpt+images（data/llamafactory/）
# 直接启动 LoRA 微调
llamafactory-cli train config/llamafactory_qwen2vl_lora.yaml
```

配置要点（与 CPU 版口径一致）：

| 项 | 取值 |
|---|---|
| 基座 | `Qwen/Qwen2-VL-2B-Instruct` |
| 微调方式 | LoRA，`lora_target=all`（**冻结视觉塔**：`freeze_vision_tower=true`） |
| 图像 | 单块 512，`image_max_pixels` 受控 |
| 学习率 / 调度 | 2e-4 / cosine，warmup 0.05 |
| 批次 | 1 × 梯度累积 8 |
| 精度 | bf16 |

## 七、常见问题（本机实测踩坑记录）

### 7.1 transformers 5.x 在纯 CPU 机器 import 阶段报错

现象：`RuntimeError: Cannot access accelerator device when none is available`，
导致 `AutoProcessor` / `AutoModelForImageTextToText` 无法导入。

原因：transformers 5.x 在导入期调用 `torch.accelerator.current_accelerator()`。

解决：`src/env_patch.py` 在 import transformers 之前拦截该调用并回退到 `torch.device("cpu")`，
所有入口脚本（`convert_data.py` / `train_lora.py` / `evaluate.py`）已自动应用。

### 7.2 下载模型时 xet 通道 401 Unauthorized

解决：设置 `HF_HUB_DISABLE_XET=1`，并使用 `HF_ENDPOINT=https://hf-mirror.com`。

### 7.3 LoRA 目标层误包含视觉塔

现象：自动探测目标模块时把 `vision_model.*` 的线性层也纳入，可训练参数过多、CPU 训练极慢。

解决：`vlm_backend.lora_targets()` 显式过滤含 `vision_model` / `vision_tower` 的模块名，
**只对语言侧**注入 LoRA（r=16 时约 5.77M 可训练参数，占比 2.2%）。

### 7.4 CPU 单步过慢

现象：默认图像切片使单图产生约 900 个图像 token，单步约 11 s。

解决：固定图像最长边 512 且关闭切片（`do_image_splitting=false`），
图像 token 降至约 100，单步降至约 1.2 s（前向+反向含生成前处理实测 ≈ 20 s/步含数据加载）。
