## 5. 接口清单

| 方法/路径 | 说明 |
| --- | --- |
| GET  /api/v6/health | 健康检查（图像库行数 + 全文索引文档数） |
| GET  /api/v6/config | 三种模式 / 两种融合 / 三种重排器 / 四种匹配 / 预设 |
| POST /api/v6/ask | 单轮问答，body.retrieval 携带策略覆盖 |
| POST /api/v6/chat | 多轮对话（沿用工单五指代消解），retrieval_config 透传 |
| GET  /api/v6/history/{session_id} | 会话历史 |
| POST /api/v6/reset/{session_id} | 重置会话 |
| POST /api/v6/feedback | 点赞/点踩/评论 → data/feedback_v6/（自适应重排器学习数据） |

请求示例：

```bash
curl -X POST http://localhost:8006/api/v6/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"报告期内公司来自军用领域的收入分别是多少？",
       "doc_id":"招股说明书1",
       "retrieval":{"mode":"hybrid","fusion":"rrf","reranker":"llm",
                    "vector_weight":0.6,"fulltext_weight":0.4,"match":"and"}}'
```

retrieval 可覆盖字段（均可选，不传走默认 hybrid/rrf/llm）：

| 字段 | 取值 |
| --- | --- |
| mode | vector / fulltext / hybrid |
| fusion | rrf（投票机制）/ weighted（加权平均） |
| reranker | llm（bge-reranker）/ tfidf / adaptive（用户反馈自适应） |
| vector_weight / fulltext_weight | 0~1，自动归一化（weighted 生效） |
| match | and / or / phrase / fuzzy |
| fields | title / content / summary（任意组合） |
| top_k | 返回条数（3~12） |

## 7. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 健康检查 fulltext_docs=0 | Milvus 中 rag_chunks 为空或连接失败；确认 `systemctl status milvus` 后重新灌库重启 |
| 首次 /ask 超过 3 秒 | 冷启动加载 bge-m3 / reranker / 建全文索引；评估与服务启动后先 warmup，稳态 ≤3s |
| LLM 重排器不可用 | 自动降级为保序透传，不阻断问答；TF-IDF / adaptive 重排器零模型依赖可随时切换 |
| 全文 AND 查询无结果 | 切换 match=or 或 fuzzy；多字段索引含未登录词子串扫描兜底 |
| 端口冲突 | v6 固定 8006/8506，与 v3/v4/v5 隔离；可先 `bash scripts/stop_v6.sh` 再启动 |
