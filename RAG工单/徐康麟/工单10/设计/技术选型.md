| 对外 API 形态 | REST + JSON | gRPC、GraphQL | 验收要"测试通过"，REST 用 curl/requests 即可验，无需额外工具链 |

| 指标 | **自产 Prometheus 文本格式**（`/metrics`） | `prometheus_client` 包、statsd | 指标就 10 个，手写 exposition 格式零依赖；口径同时给工单17 复用 |
| 监控栈 | `prom/prometheus:v2.55.1`（**profile 门控，默认不起**） | 常驻 | 默认拉起会平白吃 ~512MB；用 `--profile monitoring` 按需起 |
| 日志 | 业务侧 JSON 结构化日志（工单7 已有）+ Docker `json-file` 驱动轮转 | ELK、Loki | 单机部署，`docker logs` + 卷内 `app.log` 已足够；轮转 `max-size=20m / max-file=5` 防撑爆磁盘 |
| 镜像内模型 | **不装**，全部走宿主机 Ollama | 容器内装 torch + CLIP/qwen | 省 2~3GB；本机 GPU/Ollama 已就绪；换模型不动镜像 |

## 2. 关键取舍详解

### 2.1 为什么不用 Alpine 基础镜像

`faiss-cpu` 与 `numpy` 在 PyPI 上只有 **manylinux（glibc）** wheel。
Alpine 用 musl libc，装这两个包会退回**源码编译**（faiss 需要 cmake + 长编译时间 + 大内存），
直接踩中本机资源纪律红线（§共享约定 §5.5：单进程峰值 ≤2GB）。
`slim` 是 Debian glibc，wheel 直接可用 —— 这是选 `slim` 而不是 `alpine` 的唯一决定性理由。

### 2.2 为什么在 `runtime` 阶段用 `--no-index --find-links`

```dockerfile
RUN pip install --no-index --find-links=/wheels -r /tmp/requirements.txt
```

* `--no-index` = **绝不联网**：即使镜像源临时抽风，构建也不会挂在网络等待上；
* 保证 builder 与 runtime 装的是**同一批 wheel**（可复现构建）；
* 网络只在 builder 阶段碰一次，失败点单一、好定位。

### 2.3 为什么健康检查要点 `/healthz` 而不是 `/health`

基座冷启动实测 **27.3 秒**（全文索引构建占 20.1 s）。
若容器 `HEALTHCHECK` 直接打 `/health`（内部要加载索引），启动期必然连续失败：
`--retries 3 × --interval 30s` 也未必够，容易被编排判定为不健康 → 反复重启。
因此把"存活"与"就绪"拆开：容器探 `/healthz`（亚毫秒返回），
"能否接流量"交给 `/readyz`（索引不可用返回 503）供网关/编排使用。

### 2.4 为什么业务阈值与部署阈值分两套前缀

| 前缀 | 归属 | 例子 |
| --- | --- | --- |
| `RAG_*` | **业务层**（`app/core/config.py`，工单7 定义） | `RAG_RETRIEVAL__TOP_K`、`RAG_ANSWER__MIN_VECTOR_SIMILARITY` |
| `DEPLOY_*` | **部署层**（`service/config.py`，本工单定义） | `DEPLOY_API_PORT`、`DEPLOY_SESSION_TTL_S`、`DEPLOY_MAX_CONCURRENCY` |

好处：① 职责清晰，业务调参不必懂部署；② 两个模块互不覆盖对方的键；
③ `app/core/config.py` 会对未识别的 `RAG_*` 写 WARNING（工单7 已有机制），
部署层同样对被误写的 `DEPLOY_*` 做 `unknown_env` 列表输出，避免"改了环境变量却不生效"的排查黑洞。

### 2.5 为什么 `rag-ui` 复用同一镜像

见 `设计/容器化方案.md` §4。核心是**杜绝版本漂移**，而非省一次构建。

## 4. 被否决的方案（避免后人重走）

| 方案 | 否决理由 |
| --- | --- |
| 容器内集成 Ollama 一起跑 | 镜像 +4GB，且 GPU 直通在 Windows Docker Desktop 上不可用 |
| 用 `streamlit` 做 UI | 本机未装 streamlit；工单7 已有零依赖的标准库 UI，装了纯属增加体积 |
| 用 sqlite 存会话（单文件） | 多进程/多容器并发写同一 sqlite 文件易锁；文件-per-会话 + Redis 更稳 |
| compose 里写顶层 `version:` | Compose V2 已废弃，会打印 obsolete **警告** —— 直接违反"无异常日志"验收项 |
| 索引读写挂载 | 运行期不需要写索引；只读挂载额外获得"防误写"保护 |
| 把 `qa_runtime.sqlite3` 留在索引目录 | 索引只读 → `EROFS` 写失败（**本工单真实踩到**，见 `部署/过程问题记录.md` 问题7） |
