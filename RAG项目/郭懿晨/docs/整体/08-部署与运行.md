# 08 · 部署与运行（v2）

> **定位**：从零跑通本项目（后端服务 + 前端 + v2 重排）。环境为 Windows 单机（专高六教学环境）。

## 一、环境依赖

| 依赖 | 版本/位置 | 用途 |
|---|---|---|
| Python | 3.10+（本项目开发环境 3.12） | 运行环境 |
| 依赖包 | `requirements.txt`（精确锁定） | 后端 |
| BGE-M3 | `D:\八维学习\bge-m3`（`BGE_M3_MODEL_PATH`） | 嵌入（dense+sparse） |
| **bge-reranker-v2-m3（v2）** | `D:\八维学习\bge-reranker-v2-m3`（`RERANKER_MODEL_PATH`） | 精排 |
| Ollama | `http://localhost:11434`，模型 `deepseek-r1:7b` | 问答生成 |
| MinerU | `D:\an\envs\mineru`（pip 安装 mineru==3.4.5） | PDF 解析（可选，无则回退 pypdf） |
| VLM | `qwen-vl-plus`（阿里云 DashScope 兼容接口） | 表格/图片视觉后处理 |

**已验证版本组合**（requirements.txt）：`transformers==5.7.0` + `FlagEmbedding==1.4.2` + `sentence-transformers==5.7.0` + `mineru==3.4.5`。

> ⚠️ **MinerU × transformers 5.x 兼容**：MinerU 3.4.x 的 PP-DocLayoutV2 依赖 transformers 5.x 的 `hgnet_v2` backbone（4.x 不提供，会导致 layout 检测全空并静默回退 pypdf）。重新安装 mineru/初始化环境后运行一次：`python scripts/patch_mineru_tf5.py`（幂等补丁）。

## 三、启动步骤

### 步骤 1：准备环境

```bash
# 安装依赖（建议虚拟环境）
pip install -r requirements.txt

# MinerU 环境初始化后运行兼容补丁
python scripts/patch_mineru_tf5.py

# 确认 Ollama 已启动且有模型
ollama list          # 应包含 deepseek-r1:7b

# 确认模型目录存在：D:\八维学习\bge-m3、D:\八维学习\bge-reranker-v2-m3
```

### 步骤 2：配置 `.env`

复制 `.env.example` 为 `.env`，确认模型路径正确（尤其 `BGE_M3_MODEL_PATH`、`RERANKER_MODEL_PATH`）。

### 步骤 3：启动服务

```bash
cd D:\Claude Code代码存放处\全新项目
python backend/app/main.py
# 或
uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

### 步骤 4：访问

- **前端 SPA**：`http://127.0.0.1:8000/`
- **Swagger**：`http://127.0.0.1:8000/docs`
- **健康检查**：`http://127.0.0.1:8000/health`

## 六、运行验证

启动后：

## 七、常见问题

| 现象 | 原因/处理 |
|---|---|
| `/api/chat` 报错或兜底 | Ollama 未启动 / 模型不存在 → `ollama serve`，`ollama pull deepseek-r1:7b` |
| chat 500「bge-reranker 模型路径不存在」 | `RERANKER_MODEL_PATH` 配错 / 模型未下载 → 修正路径或下载 v2-m3 |
| 构建失败「模型路径不存在」 | `BGE_M3_MODEL_PATH` 配错 → 检查 `.env` |
| 解析全空/静默回退 pypdf | MinerU × transformers 版本不匹配 → `python scripts/patch_mineru_tf5.py` |
| Qdrant 打开超时/锁冲突 | `data/qdrant/` 单进程锁：uvicorn 与独立脚本/评测不能同时开 |
| `_del msvcrt` 退出报错 | QdrantClient 析构（Windows 无害） |
