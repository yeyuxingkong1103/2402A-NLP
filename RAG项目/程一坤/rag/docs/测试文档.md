## 2. 测试目标

1. 验证用户、角色、知识库、会话和记忆功能。
2. 验证 PDF、OCR、表格和多模态解析质量。
3. 验证分块、Embedding、Milvus 入库和动态更新。
4. 验证问题改写、多路召回、混合检索和 BGE-Reranker 精排。
5. 验证 Prompt、模型调用、后处理、引用和流式输出。
6. 使用 RAGAS 评测检索质量和生成质量。
7. 使用 Postman/APIpost 验证接口，使用 PyUnit 验证代码，使用 JMeter 验证性能。
8. 验证多用户、多角色隔离和法律领域的法源、时效、法域与风险规则。

## 7. 模块测试

### 7.0 测试组织方式（硬性约定）

- **一个模块一个测试脚本**：`tests/test_<模块名>.py`，例如 `tests/test_package_module.py`。
- 不为每个代码文件单独建测试文件；同一模块下的多个文件共用一个脚本。
- 只写有效测试：覆盖"错了会真出问题"的行为，例如数据被篡改、路径逃逸、引用断裂、失败产生半成品。
- 不写无效测试：不写"断言某库能被 import""断言 getter 返回刚赋的值"这类零信息量用例。
- **禁止测试文件之间互相 import**；共享夹具统一放在 `tests/conftest.py`。
- 统一执行入口：`cd backend && python -m pytest tests -q`，要求 **0 error 且全部通过**。
- **真联网用例标记**：依赖真实外部服务（SiliconFlow Embedding、Milvus、MySQL、Redis）的用例打 `@pytest.mark.real_api`（如 `tests/test_retrieval_factory_smoke.py`）。默认全量命令仍运行这些用例；需要稳定快速回归时用 `pytest tests -q -m "not real_api"` 跳过。**上线前或改动检索链路后必须跑全量（含 real_api）**。real_api 用例允许"失败即重试一次"，重试后仍失败必须报错并打印重试证据。

### 7.1 文档解析

- Python 离线导入命令能够扫描 `data/labor_law_raw/` 中的 `.html` 和 `.htm` 文件。
- 每个已映射 HTML 都经过 `parse_document()`、文本清洗和 `chunk_document()`。
- 单个文件解析失败或缺少已验证 URL 映射时，记录结构化错误并继续处理其他文件。
- 成功数据包包含 `documents.jsonl`、`document_versions.jsonl`、`document_chunks.jsonl` 和 `crawl_records.jsonl`。
- 成功数据包能够由 `PackageData.read_records()` 重新读取，且至少包含一个 chunk。
- 原始文件内容 SHA-256、稳定 `document_id` 和 `version_id` 可用于识别文档版本。
- 法律文档能够识别文书类型、法规名称、发布机关和日期字段。
- 法条能够保留章节路径、条号、款号、项号（款号与项号见《开发路线图》任务 1.2）。
- **首期不纳入案例材料**，因此"判决书识别案号、法院、裁判日期、裁判要旨"不在本期测试范围，列为后续扩展。

### 7.1.1 真实 HTML 离线导入验证

```bash
cd backend
```

### 7.2 文档分块

- 固定长度分块满足长度上下限。
- 句子分块不会截断关键句。
- 段落和标题分块保留标题路径。
- 语义分块能够在主题切换处切分。
- 父子块能够通过子块召回父块上下文。
- 分块结果保存页码、来源、版本和内容哈希。

### 7.3 检索和排序

- 问题向量化维度与 Milvus 集合一致。
- BM25 关键词召回能够命中编号和专有名词。
- 向量召回能够命中同义表达。
- 多路结果能够合并和去重。
- 权限过滤在模型调用前生效。
- 余弦相似度阈值正确执行。
- BGE-Reranker 按分数降序排序。
- 最终上下文不超过 token 和片段数量限制。
- 根据法域、文书类型和适用时间过滤结果。
- 失效法规不会在当前有效版本查询中被优先召回。
- 条文号、案号和法院查询支持精确匹配。

### 7.4 记忆和生成

- Redis 只返回当前用户和当前会话的短期记忆。
- 长期记忆写入前会进行摘要和去重。
- 用户删除记忆后，检索不到该记忆。
- Prompt 模板正确注入角色、知识和记忆。
- 用户输入和文档内容不能覆盖系统规则。
- 正则后处理只做允许的格式修正。
- 引用 ID 不存在时被拦截。
- 流式 token 可以正确拼接为完整回答。
- 法律引用包含法规名称、条文号或案号、来源和适用时间。
- 回答区分法规原文、司法解释、案例材料和模型归纳。
- 事实不完整时能够输出待补充事实，而不是直接下最终结论。

- 只允许 `@qq.com` 和 `@foxmail.com` 注册；
- QQ SMTP 验证码过期、重复使用和频率限制行为正确；
- 密码不出现在日志和错误响应中；
- 官方站点白名单之外的 URL 被拒绝；
- 采集任务遵守 `robots.txt` 和访问频率限制；
- 内容哈希可以识别重复页面和新版本；
- 未审核文档不会参与检索；
- 审核拒绝的文档不会发布；
- 审核通过且索引成功后文档才可检索；
- 新版本索引失败时旧生效版本仍可用。

## 10. RAGAS 评测

### 10.1 检索指标

- `Context Precision`：召回上下文的精确性；
- `Context Recall`：相关上下文的召回率；
- `Recall@5`；
- `MRR@10`；
- `nDCG@10`。

### 10.2 生成指标

- `Faithfulness`：回答是否被上下文支持；
- `Answer Relevancy`：回答是否回应问题；
- `Context Entity Recall`：关键实体是否召回；
- `Citation Correctness`：引用是否正确；
- `Refusal Accuracy`：无答案问题是否正确拒答；
- 角色一致性：回答是否符合人物性格和风格；
- `Legal Source Validity`：引用的法律文档在指定时间点是否有效；
- `Legal Applicability`：法域、文书类型和事实条件是否匹配；
- `Legal Citation Completeness`：法规名称、条文号、案号和来源是否完整；
- `Fact Issue Completeness`：事实要素和争议焦点是否覆盖。

### 10.3 评测对照组

至少比较：

1. 仅向量检索；
2. 仅 BM25；
3. BM25 + 向量混合检索；
4. 混合检索 + BGE-Reranker；
5. 不同分块策略；
6. 不同 BGE-M3 模型或微调版本；
7. 不同 Prompt 模板；
8. 不同余弦相似度阈值。

### 10.4 初始质量门槛

| 指标 | MVP 目标 |
| --- | --- |
| `Recall@5` | 不低于 85% |
| `MRR@10` | 不低于 0.70 |
| `Faithfulness` | 不低于 0.85 |
| `Answer Relevancy` | 不低于 0.80 |
| 引用正确率 | 不低于 90% |
| 法律来源有效率 | 不低于 95% |
| 法律引用完整率 | 不低于 90% |
| 无答案拒答准确率 | 不低于 90% |

法律领域必须同时进行律师或法律专业人员人工抽样审核，自动评测结果不能作为唯一上线依据。法规版本冲突、法域不匹配和重大法律风险问题属于阻断性问题。

## 11. 性能和压力测试

### 11.1 JMeter 场景

- 20、50、100 并发用户逐级压测；
- 混合短问题、长问题和多轮问题；
- 在线问答与文档索引同时运行；
- Redis 命中和未命中两种场景；
- 本地模型和在线 API 两种场景；
- Nginx 单实例和多实例负载均衡场景；
- 模型延迟增加、Milvus 延迟增加和 Redis 重启场景。

### 11.2 性能指标

| 指标 | 目标 |
| --- | --- |
| 问答首 token `p95` | 不超过 3 秒 |
| 完整回答 `p95` | 不超过 10 秒 |
| 检索阶段 `p95` | 不超过 2 秒 |
| 健康检查 `p95` | 不超过 200 ms |
| 错误率 | 不超过 1% |
| QPS（20 并发下） | 不低于 5；部署实测后按实际值修正并更新本文档 |

报告必须包含 QPS、并发数、`p50`、`p95`、`p99`、错误率、CPU、内存、GPU、Milvus 延迟、Redis 命中率和模型 token 数。

## 12. 安全测试

### 12.1 权限安全

- 未登录访问；
- 过期 Token；
- 普通用户调用管理员接口；
- 修改角色 ID、知识库 ID、会话 ID；
- 跨用户读取 Redis 记忆；

- 越权检索专业知识库；
- 删除不属于自己的文档和角色。

### 12.2 RAG 安全

- 文档中加入“忽略系统指令”；
- 用户要求泄露系统 Prompt；
- 检索内容要求模型输出密钥；
- 用户诱导模型访问其他用户记忆；
- 伪造引用 ID；
- 低相似度内容强行回答；
- 通过角色扮演规避法律安全规则。
- 通过角色扮演要求系统伪造证据、隐瞒事实或规避法律责任；
- 诱导系统把过期法规当作当前有效依据；
- 诱导系统把单个案例泛化为必然适用规则；
- 诱导系统输出“保证胜诉”或“确定违法”等绝对结论。

### 12.3 文件安全

- 伪造扩展名；
- 错误 MIME 类型；
- 损坏 PDF；
- 超大文件；
- 路径穿越；
- 恶意 HTML；
- 压缩炸弹；
- 带宏或脚本的文档。

## 13. 可靠性和部署测试

### 13.1 依赖故障

| 故障 | 预期 |
| --- | --- |
| MySQL 不可用 | 就绪检查失败，业务接口返回明确错误 |
| Redis 不可用 | 短期记忆降级或拒绝请求，不泄露旧用户记忆 |
| Milvus 不可用 | 不生成无依据回答，返回可重试提示 |
| 模型超时 | 释放连接，返回稳定错误码 |
| Worker 崩溃 | 任务可重试，不产生半成品有效索引 |
| Nginx 节点故障 | 其他节点继续服务 |

### 13.2 部署验证

- Ubuntu 安装脚本执行成功；
- CentOS 安装步骤可执行；
- Anaconda 环境创建成功；
- `requirements.txt` 安装成功；
- MySQL、Redis 和 Milvus 可连接；
- 代码通过 Git 或压缩包部署成功；
- `scripts/deploy.sh` 启动成功；
- `shutdown.sh` 停止成功；
- 服务重启后数据和索引仍可用；
- 健康检查和日志输出正常。
