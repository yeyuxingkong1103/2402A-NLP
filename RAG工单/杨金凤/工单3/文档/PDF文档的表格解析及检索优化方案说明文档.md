## 2. 新增需求分析

### 2.1 新增 PDF

工单新增《招股说明书2.pdf》（武汉力源信息技术股份有限公司），与原有《招股说明书1.pdf》（武汉兴图新科电子股份有限公司）并列。

**技术挑战：**

- 向量库需同时容纳两份文档的内容
- 检索时需区分公司，避免数据混用
- 问题涉及力源时从 PDF2 召回，涉及兴图时从 PDF1 召回

### 2.2 表格数据检索（核心优化）

工单 03 的核心难点：**前 4 个力源问题（发行股数、募集资金项目、关联方）的答案都在表格中。**

**传统解析的问题**：`pdfplumber.extract_text()` 会把表格解析成错乱的文本流，字段名与数值分离，检索必然失败。

**优化方案**：使用 `pdfplumber.extract_tables()` 提取表格，转为 Markdown 格式**追加到文本中**，保证表格作为结构完整的原子单元被分块和检索。

**示例（力源发行股数表）：**

原始文本提取（错乱）：

```text
发行前 发行后 股数 比例 股数 比例 6,670万 100% 8,340万 100%
```

Markdown 化后（结构清晰）：

```text
| 项目 | 发行前 | 发行后 |
|---|---|---|
| 发行股数 | - | 1,670万股 |
| 占发行后总股本比例 | - | 25.04% |
| 发行后总股本 | 6,670万股 | 8,340万股 |
```

## 3. 优化方案实施

### 3.1 PDF 表格解析优化

新增脚本 `parse_pdf_tables.py`：

```python
# 核心逻辑
with pdfplumber.open(pdf_path) as pdf:
    for page in pdf.pages:
        page_text = page.extract_text() or ""
        tables = page.extract_tables()  # 提取表格
        for t in tables:
            md = table_to_markdown(t)    # 转 Markdown
            # 表格用特殊标记包裹，便于分块识别
            block += f"\n### 表格 {idx} ###\n{md}\n### 表格 {idx} 结束 ###\n"
```

**效果：**

- PDF1 提取 954 个表格
- PDF2 提取 482 个表格
- 表格内容以 Markdown 结构完整保留

### 3.2 分块优化

分块参数调整：

- `chunk_size`：500 → 800（保留完整表格）
- `chunk_overlap`：50 → 100
- 分隔符优先级：`### 表格` 最高（保证表格不被切断）

**效果**：向量库从 1214 块扩至约 2000+ 块，表格内容完整保留。

### 3.3 检索优化

**Reranker 精排（沿用工单 02）：**

- 向量检索 + BM25 召回 20 个候选
- bge-reranker-base 精排取 top 6
- 保证表格数据在最终上下文中

**Prompt 新增规则：**

| 规则 | 说明 |
| --- | --- |
| 规则 1 | 根据公司名判断使用哪份 PDF，不混用 |
| 规则 7 | 表格数据按行列对照提取，不跨行错位 |
| 规则 8 | 严格保留单位（万元、万股、%） |

### 3.4 多语言优化

英文问题处理流程改进：

1. **问题预处理**：规则替换英文公司名 → 中文公司名（避免 LLM 误译）
2. **直接检索**：用替换后的混合问题检索（不再整句翻译）
3. **生成英文答案**：prompt 指定用英文回答
4. **答案后处理**：强制替换公司名为标准英文全称

### 3.5 稳定性（沿用工单 02）

- 输入校验、超长截断、非法字符检测
- LLM 生成重试 2 次
- OOM 自动恢复
- 单路检索失败隔离
