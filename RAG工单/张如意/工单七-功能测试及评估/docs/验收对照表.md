### 验收项 3：要有 10 个问题的检索结果和评估结果，要体现检索结果存在的问题分析

这一条拆成三个子项：

#### 3.1 检索结果

| 要求 | 实现 | 证据文件 |
|---|---|---|
| 每题给出检索到的片段 | `run_rag_test.py` 的 `run_case()` 记录 `retrieved` 列表：文档名 / 页码 / 分数 / 片段摘要 | `results/rag_test_results.json` |
| 每题给出生成的答案 | 同上，记录 `answer` 字段 | `results/rag_test_results.md` |
| 每题给出耗时 | 记录 `latency` 与分阶段 `stage_ms` | 同上 |

#### 3.2 评估结果

| 要求 | 实现 | 证据文件 |
|---|---|---|
| 使用评估框架 | `rag_core.evaluate`（RAGAS 方法论自实现，支持切换官方 ragas 包） | `src/run_evaluation.py` |
| 给出可量化指标 | faithfulness / answer_relevancy / context_precision / context_recall / answer_correctness + hit_rate / mrr / recall_at_k + 延迟分位数 | `results/evaluation.json` |
| 有判读标准 | `PASS_RULES` 定义每个指标的通过阈值，`judge()` 逐题判定 | `docs/评估方法说明.md` |

#### 3.3 问题分析

| 要求 | 实现 | 证据文件 |
|---|---|---|
| 自动发现问题 | `analyze_problems.py` 自动统计：乱码文件名、数字不被上下文支撑的题、召回文档数不足的题、召回错误文档的题、表格页未入库的题、同名章节串扰的题 | `results/problem_analysis.md` |
| 归类并给出根因 | 六类问题体系（P1~P6），每类含现象/根因/证据/改进方向 | `docs/问题分析与改进建议.md` |
| 给出改进优先级 | 按「影响面 × 实现成本」排序的改进建议表 | 同上，第四节 |
