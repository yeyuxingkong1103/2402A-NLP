## 6. 数据集说明

### 6.1 总体情况

知识库共 **13364 个切片**，三个角色均衡在 4000 条以上，来自五个开源项目与一份 WHO 报告。
原始数据经 `scripts/prepare_dataset.py`、`scripts/fetch_statutes.py`、
`scripts/fetch_finance_extra.py` 清洗为统一 JSONL 格式
（`embed_text` 作检索目标、`display_text` 喂给大模型）。

> **本表的数字是「构建 + 去重」之后的。** 全量重建会得到 13432 条——
> 源数据里有 68 条记录只差标点写法、归一化后文本完全相同，入库即成为重复切片，
> 需再跑一次 `scripts.dedup_kb --apply` 才是 13364 条。

| 角色 | 切片数 | 源项目 | 数据构成 |
|---|---|---|---|
| lawyer | 4555 | LaWGPT + lawtext/laws | 4068 条现行法条 + 483 条刑法罪名条目 + 2 条法律问答 + 2 篇裁判文书 |
| psychologist | 4675 | MentalGLM + WHO | 3407 条认知歪曲识别 + 1249 条自杀风险识别 + 22 条世界精神卫生报告 |
| financial_advisor | 4134 | DISC-FinLLM + Fin-Eva | 四类金融问答 + 286 篇金融材料 + 1281 条金融知识 + 2250 条金融问答 |
| **合计** | **13364** | — | — |

> 切片数比记录数多，是因为超出 1500 字的长记录会走**语义分块**再切
> （见 `app/core/chunk_service.py`）。知识库 99.9% 的记录是法条与问答对，
> 本身就是原子语义单元，不参与分块。

### 6.2 lawyer —— 法律（4555 切片）

| 文件 | 记录数 | 内容 | doc_type |
|---|---|---|---|
| `legal_statutes.jsonl` | 4068 | **现行法条全文**，按「条」切分，来自国家法律法规数据库 | statute |
| `legal_articles.jsonl` | 483 | 刑法罪名条目：罪名 + 法条依据（条文序号）+ 所属章节 + 子类 | article |
| `legal_qa.jsonl` | 2 | 法律问答，含法条正文引用 | qa |
| `legal_cases.jsonl` | 2 | 裁判文书全文（长文，入库时走语义分块） | case |

**法条数据集构成**（`legal_statutes.jsonl`，共 4068 条 / 21 部法规）

由 `scripts/fetch_statutes.py` 从 `lawtext/laws`（国家法律法规数据库 flk.npc.gov.cn 的
转换文本，公有领域）提取。筛选规则：

1. 只取**有效 / 尚未生效**状态，已废止与已修改的历史版本一律剔除，避免引用失效条文；
2. 按咨询频率排序，**整部纳入**直到累计达到目标条数——不拦腰截断某部法律，
   否则用户问到后半部会检索不到；
3. 同名法规保留施行日期最新的一版；
4. 滤除「本法自公布之日起施行」等无独立检索价值的条款。

| 法域 | 法规 | 条数 |
|---|---|---|
| 民事 | 民法典 | 1254 |
| 刑事 | 刑法 / 刑事诉讼法 | 448 + 307 |
| 民事程序 | 民事诉讼法 / 民事诉讼证据规定 | 304 + 100 |
| 商事 | 公司法 | 263 |
| 劳动 | 劳动法 / 劳动合同法 / 劳动争议调解仲裁法 / 劳动争议解释（一）/ 社会保险法 | 106+97+53+54+97 |
| 行政 | 行政处罚法 / 行政诉讼法 / 治安管理处罚法 / 道路交通安全法 | 85+102+142+123 |
| 消费者 | 消费者权益保护法 | 62 |
| 宪法 | 宪法（2018 年修正文本） | 142 |
| 司法解释 | 民法典婚姻家庭编 / 继承编 / 担保制度 / 合同编通则解释 | 91+45+71+69 |

条目示例（`display_text`）：

```
【现行法条】《中华人民共和国刑法》第一百三十三条（第二章 危害公共安全罪）
违反交通运输管理法规，因而发生重大事故，致人重伤、死亡或者使公私财产遭受重大损失的，
处三年以下有期徒刑或者拘役；交通运输肇事后逃逸或者有其他特别恶劣情节的，处三年以上
七年以下有期徒刑；因逃逸致人死亡的，处七年以上有期徒刑。
```

> 条文序号带「之一」的增补条款（如《刑法》第一百三十三条之一的危险驾驶罪）会单独成条，
> 共 53 条，便于按罪名精确检索。

### 6.5 金融数据补充：Fin-Eva

`data/financial_advisor/finance_extra_knowledge.jsonl`（1281 条）与
`finance_exam_qa.jsonl`（2250 条）来自 **Fin-Eva**——蚂蚁集团与上海财经大学
联合发布的金融领域数据集，许可 **CC BY 4.0**（使用时需保留署名）。

原始数据是四选一单选题，**直接当知识库价值不高**，因此分两种方式提取：

| 原始形态 | 处理方式 | 产出 |
|---|---|---|
| 带 `context`（保险条款原文、产品分析、事件解读） | 抽成独立知识文档，跨文件按内容去重 | 1281 条 |
| 无 `context`（理财知识、金融术语、从业资格题） | 「问题 + 正确选项原文」转成问答对 | 2250 条 |

**踩过的坑**：该数据集是**评测集**，`answer` 列大部分被 withheld
（保险条款解读 317 行里 246 行答案为空），因此问答只能从有答案的行提取；
上财部分的 `test` 集（3340 行）整个删掉了 answer 列，只有 `val`/`dev` 可用。

刻意排除的目录：`内容生成`（营销文案，非知识）、`金融认知`（情绪/槽位识别，
是 NLP 标注任务）、`执业医师`/`执业药师`（与金融无关）。

### 6.6 外部文档接入：WHO 世界精神卫生报告

`data/psychologist/who_mental_health.jsonl`（22 条）来自世界卫生组织
《世界精神卫生报告：向所有人享有精神卫生服务转型》概述中文版（2022，28 页）。

它演示了**完整的 PDF 接入链路**，也是知识库里唯一含图表内容的语料：

| 环节 | 处理 |
|---|---|
| 去水印 | 该文档无水印，报告显示 0 处 |
| **解析（主路径）** | 先由 PyMuPDF 擦水印并另存干净 PDF，再交给 MinerU（basic 档）解析为整篇 Markdown |
| **解析（兜底）** | MinerU 不可用或解析失败时，退回三件套：PyMuPDF 取文本层 + PaddleOCR 补图表文字 + pdfplumber 提表格 |
| 剥内嵌图 | MinerU 把图以 base64 内嵌进 Markdown，剥掉后正文 15174 字 |
| 语义分块 | 整篇 Markdown 单条记录超长，按话题转折切分 |

**为什么图表内容能读到**：该报告第 22 页是一张"转型前 vs 转型后"对照图，
文本层只有 54 字（一句图题），图内 58 行文字对纯文本提取完全不可见；
MinerU 的版面分析与 OCR 把它们一并解析出来（旧管线靠 PaddleOCR 补 110 行 / 5 页，
全文 14830 字；现主路径 15174 字，兜底三件套补 125 行 / 6 页、14925 字）。
这些内容可被检索——实测三问均命中该页且排第一：

| 提问 | 命中 | 精排分 |
|---|---|---|
| 精神卫生转型之前和之后有哪些变化？ | P22 图表 | 5.17 |
| 实现精神卫生转型有哪几条路线？ | P25 图表 | 5.13 |
| 转型前对精神卫生的重视程度如何？ | P22 图表 | 3.70 |

> 入库耗时：主路径约 38 秒（28 页，MinerU basic 档跑 GPU）；MinerU 不可用时退回
> 三件套兜底，同一份文档实测约 283 秒（改造前只有自研三件套时为 254 秒）——
> 兜底能读出图内文字，只是慢一个数量级。

### 6.7 数据集的已知局限（如实说明）

**法律数据集**

已具备**法条正文全文**（4068 条），律师角色可以逐字引用条文原文作答，例如
「酒驾撞人要判多久」会命中《刑法》第一百三十三条原文、「没签劳动合同能否要二倍工资」
会命中《劳动合同法》第八十二条原文。仍存在的局限：

- **覆盖范围有限**：只纳入 21 部法规，而数据源中现行有效法规共 1517 部。
  未纳入的包括知识产权三法、保险法、破产法、票据法、仲裁法，以及大部分行政法规与部门规章。
  扩围只需在 `scripts/fetch_statutes.py` 的 `PRIORITY` 列表后追加法规名并提高 `TARGET`。
- **没有判例库**：仅有 2 篇裁判文书样例，无法检索类案或指导性案例。
  回答「实践中通常怎么判」这类问题时，角色只能依据条文本身说明，
  不能给出裁判倾向——业务规则中已要求区分「法律如何规定」与「实践如何处理」。
- **未纳入地方性法规与部门规章**，涉及地方性规定的问题需另行补充语料。
- **法条不随修订自动更新**：数据源按发布日期快照，法规修订后需重新拉取并走
  `POST /api/update/dataset/lawyer` 增量更新。

**金融数据集**

- 内容偏**市场分析材料与咨询类问答**，语言风格接近研报与投顾话术；
- **缺少结构化产品数据**：如基金净值、费率表、产品要素说明书、历史行情时间序列；
- 因此金融角色擅长解释概念、梳理配置思路与提示风险，但**难以回答精确的产品对比与计算类问题**
  （如「某基金近三年年化多少」），此类问题应识别为资料不足并引导用户补充背景。
- 数据时效性受源项目发布时间限制，角色规则中已要求「涉及具体数据时须注明来源与时间」，
  实际回答中如引用过时数据，需要运维侧通过增量更新接口替换语料。

**心理数据集**

- 数据来自公开心理问答语料，**不是临床诊断标准**，仅覆盖认知歪曲识别与自杀风险识别两类任务；
- 因此角色规则中明确禁止精神科诊断与药物建议，高危情形固定输出危机干预热线，
  定位是「心理支持」而非「诊疗」。
