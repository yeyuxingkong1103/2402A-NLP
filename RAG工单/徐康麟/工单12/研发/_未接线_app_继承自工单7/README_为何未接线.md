## 1 为什么移出

本目录原为 `工单12\研发\app\`，是**从工单7 基座复制**而来（工单7 ← 工单6 ← 工单5 ← 工单4 一路继承），
是面向**工单7 那种"分块 + FAISS + CLIP 图像"索引**的完整 RAG 应用（30+ 模块：可答性闸门、多轮对话、
对话缓存、检索策略、CLIP 图像检索……）。

而**工单12 走的是自研 LightRAG 链路**，索引格式完全不同：

| 项 | app 期望（工单7 格式） | 工单12 实际（lightrag 自研） |
| --- | --- | --- |
| 索引目录 | `研发/data/index/bge-m3_1024/` | `研发/data/index/`（扁平） |
| 必需文件 | `chunks_indexed.jsonl`、`faiss.index`、`ids.json`、`bm25.pkl`、`vectors.npy` | `vectors.npy`、`bm25.pkl`、`ids.json`（**缺前两个**） |
| 结果 | 服务启动即抛错 | — |

实测报错原文：

```
app.core.errors.IndexMissingError: [RAG-3100/index] 索引块文件缺失：
  E:\gao6gongdan\工单12\研发\data\index\bge-m3_1024\chunks_indexed.jsonl
```

## 2 为什么不改造它

`app/` 的 30+ 模块**全部围绕工单7 的索引格式设计**（检索器、可答性闸门、缓存键、CLIP 图像通道……）。
让它们去读 lightrag 的扁平索引，等于重写半个检索栈，改造面远大于收益；
而工单12 的交付目标（知识图谱 + 双层检索 + 16 题对比）**已全部达成且不依赖 app**：

- `研发/lightrag/`（12 个模块）+ `研发/scripts/10~32`（8 个脚本）
- 测试 **27 passed**
- 16 题对比可一键复现
