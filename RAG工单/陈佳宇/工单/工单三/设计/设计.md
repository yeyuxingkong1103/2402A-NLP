# 工单3 - 设计文档
## 1. 需求分析
### 1.1 业务背景
本项目为RAG检索增强生成实训工单，目标实现对包含表格的招股说明书PDF文档进行问答检索。用户输入自然语言问题，系统在PDF文档内检索相关原文片段并返回，重点支持股权信息、财务数据类表格内容查询。

### 1.2 功能需求
1. PDF文档解析：读取PDF招股说明书，提取正文与表格文本内容。
2. 文本预处理：对读取的全文进行滑动窗口分块，保留上下文关联性。
3. 向量处理：使用向量嵌入模型将文本块转为向量，存入Milvus向量数据库。
4. 向量检索：接收用户问题，将问题向量化，在向量库中检索相似度最高的文本片段。
5. Web交互页面：提供网页输入框，用户提交问题，展示检索结果与检索耗时。

### 1.3 非功能需求
1. 检索响应时间：单次检索耗时控制在0.1秒以内。
2. 运行环境：支持WSL Ubuntu环境稳定运行。
3. 可扩展性：代码模块化，预留接入大模型生成答案、混合检索的扩展接口。
4. 稳定性：可正常解析PDF内表格文字，能够正确检索到表格内数字信息。

## 2. 总体架构设计
系统分为四层架构，从底层文档处理到上层Web交互：
1. **文档解析层**：采用PyMuPDF读取PDF页面文本，提取页面内正文与表格文字。
2. **文本分块层**：滑动窗口文本切分，`chunk_size=512`，`chunk_overlap=50`，避免表格上下文被截断。
3. **向量存储与检索层**：Sentence-Transformers向量模型生成文本向量；Milvus向量数据库存储向量与原文，提供相似度检索。
4. **Web应用层**：Flask搭建后端服务，提供网页与API接口；前端静态页面负责接收用户提问，展示检索返回结果。

## 3. 数据模型设计
Milvus向量集合名称：`rag_waterwork3`
| 字段名 | 字段类型 | 说明 |
| ---- | ---- | ---- |
| text | VARCHAR | 分块后的PDF原文文本，保存文档片段内容 |
| vector | FLOAT_VECTOR | 向量，维度384，由all-MiniLM-L6-v2模型生成 |

> 主键id：Milvus自动生成auto_id，无需手动维护。

## 4. 接口设计
### 接口1：首页页面
- 请求方式：GET
- 路径：`/`
- 功能：返回Web问答页面，提供输入框和提问按钮

### 接口2：问答检索接口
- 请求方式：POST
- 路径：`/ask`
- 请求体：`{"q": "用户的问题"}`
- 返回：`{"ans": "检索耗时 + 原文片段结果"}`

## 5. 页面UI设计
页面布局：
1. 标题：工单3｜招股说明书RAG问答系统
2. 输入框：用于输入自然语言问题
3. 提问按钮：点击触发检索请求
4. 结果展示区：展示检索耗时、PDF原文片段，纯文本展示

## 6. 技术选型
| 模块 | 技术选型 | 作用 |
| ---- | ---- | ---- |
| PDF解析 | PyMuPDF | 读取PDF文本，提取表格文字 |
| 向量模型 | all-MiniLM-L6-v2 | 轻量文本向量化模型，384维向量 |
| 向量数据库 | Milvus | 向量存储、相似度检索 |
| Web后端 | Flask | 提供Web服务与API接口 |
| 前端 | HTML+CSS+JS | 网页交互页面 |
| 开发语言 | Python3.12 | 项目开发语言 |

## 7. 总体业务流程
1. 程序启动：读取PDF文档 → 提取全部文本 → 文本分块 → 生成向量 → 存入Milvus向量库。
2. 用户操作：浏览器打开网页，输入问题，点击提问。
3. 后端处理：接收问题，问题向量化，调用Milvus做相似度检索，获取Top3相关文本块。
4. 返回结果：拼接检索耗时与原文片段，返回前端网页展示。
