# 前端行为测试

用 [jsdom](https://github.com/jsdom/jsdom) 加载**真实的** `app/static/index.html`，
再用可控的 SSE 流仿真后端，驱动页面跑完整交互。不需要浏览器，也不需要启动服务。

## 运行

```bash
cd tests/web
npm install     # 只装 jsdom，约 10MB，不下载浏览器内核
npm test
```

退出码 0 表示全部通过。

## 为什么单独有这么一套

后端有 pytest 兜底，但对话区的**流式状态**全在前端，而且是最容易改坏的一块：
生成中途切角色、切会话、删会话、点停止，几条路径互相纠缠，光看代码很容易漏。

`test_background_generation.cjs` 覆盖的场景：

| 场景 | 断言要点 |
|---|---|
| 生成中切角色 | 后台那条流继续跑；输入区解锁可继续提问 |
| 切回仍在生成的会话 | 能看到已生成内容；该会话下发送禁用、停止可用、带「生成中」角标 |
| 两个角色并发提问 | 两路互不干扰，各写各的会话 |
| 先后结束 | 答案落在**发起时**那个会话，不会串到切换后的会话 |
| 中途点停止 | 已生成部分保留并落盘，输入区恢复 |
| 删除正在生成的会话 | localStorage 不残留孤儿数据 |

## 写法约定

- **只断言可观测输出**：DOM 文本 + `localStorage`。页面里的 `const state` 是脚本作用域
  本来就取不到，这样写也更贴近真实用户视角。
- **`fetch` 桩要仿真 AbortSignal**：真实浏览器里 `abort()` 会让响应体读取抛 `AbortError`，
  假流不会。漏了这一步，「点停止」的路径根本没被走到，测试会假通过。
- 每次 `/chat/stream` 请求后 **立刻抓住流句柄**（`const s = pending`），否则会被下一次请求覆盖。
