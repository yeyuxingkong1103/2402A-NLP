# RAG2 在线阶段 · 部署文档

本文档介绍如何把 RAG2 在线问答服务部署到本地环境。

## 1. 系统架构

```
浏览器（零依赖网页客户端）
        │  HTTP / SSE
        ▼
 FastAPI 服务（rag2.server）
   ├─ RAGChat 编排器（online_chat.py）
   │    ├─ 混合检索  HybridRetriever（Milvus + BM25 + bge 重排）
   │    ├─ 生成       LLMClient（Ollama OpenAI 兼容端点）
   │    └─ 短期记忆  RedisMemory（Redis，TTL 自动过期）
   ├─ 角色表        roles.yaml（农业专家 / 技术支持 / 通用助手 / 客服）
   └─ 评估          RagasEvaluator（RAGAS，接本地 Ollama + bge-m3）
        │
        ▼
 ┌───────────┬────────────┬─────────────┐
 │  Redis    │   Milvus   │   Ollama    │
 │ 127.0.0.1 │ localhost  │ localhost   │
 │ :6379     │ :19530     │ :11434      │
 └───────────┴────────────┴─────────────┘
```

## 2. 前置依赖

### 2.1 Python 环境

使用 conda 环境 `rags_`（解释器 `D:\an\envs\rags_\python.exe`）。需已安装：

| 包 | 用途 |
| --- | --- |
| fastapi / uvicorn | Web 服务 + SSE 流式 |
| redis | Redis 短期记忆 |
| httpx / python-multipart | 服务探测 / 表单上传 |
| openai | LLM 客户端（连 Ollama） |
| yaml | 读取 config.yaml / roles.yaml |
| pymilvus | 混合检索（稠密 + Milvus 原生 BM25 稀疏向量） |
| ragas / sentence-transformers | RAGAS 评估 / 向量化（可选，评估时用） |

一键检查：

```bash
D:/an/envs/rags_/python.exe -c "import fastapi,uvicorn,redis,httpx,yaml,openai,pymilvus; print('依赖 OK')"
```

### 2.2 外部服务

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| Redis | `127.0.0.1:6379` | 无密码；用于短期记忆、登录令牌、会话 |
| Milvus | `http://localhost:19530` | 集合 `agriculture_knowledge` 已入库 |
| Ollama | `http://localhost:11434` | 生成模型 `Qwen3.5:4B` |

模型权重（需存在）：

```
D:\modelscope\bge-m3                  # 向量化（1024 维）
D:\modelscope\bge-reranker-v2-m3      # 交叉编码器重排
```

## 4. 启动步骤

1. **启动 Redis**：确认 `127.0.0.1:6379` 可连接。
2. **启动 Milvus**：确认 `http://localhost:19530` 可连接，且集合 `agriculture_knowledge` 已入库。
3. **启动 Ollama**：确认 `http://localhost:11434` 可连接，已拉取 `Qwen3.5:4B`。
4. **启动服务**（任选其一）：

   ```bash
   # Windows cmd
   deploy\start.bat

   # WSL / Git Bash
   bash deploy/start.sh

   # 或直接
   D:/an/envs/rags_/python.exe run.py
   ```

5. 浏览器打开 **http://127.0.0.1:8000**。

## 5. 配置说明

配置文件 `config.yaml`，所有配置项都可用 `RAG2_*` 环境变量覆盖（详见 `rag2/config.py` 的 `_ENV_MAP`）。

| 配置路径 | 默认值 | 说明 |
| --- | --- | --- |
| `app.host` / `app.port` | `127.0.0.1` / `8000` | 服务地址 |
| `app.log_dir` / `app.log_level` | `logs` / `INFO` | 日志目录与级别 |
| `llm.base_url` | `http://localhost:11434/v1` | LLM OpenAI 兼容端点 |
| `llm.model` | `Qwen3.5:4B` | 生成模型 |
| `llm.reasoning_effort` | `none` | 关闭 Qwen 思考链（避免输出被截断） |
| `milvus.uri` | `http://localhost:19530` | Milvus 地址 |
| `milvus.collection` | `agriculture_knowledge` | 检索集合 |
| `milvus.embed_model` | `D:/modelscope/bge-m3` | 向量化模型 |
| `milvus.rerank_model` | `D:/modelscope/bge-reranker-v2-m3` | 重排模型 |
| `redis.host` / `redis.port` | `127.0.0.1` / `6379` | Redis 地址 |
| `redis.prefix` | `rag2:` | Redis key 前缀 |
| `redis.history_ttl` | `86400` | 会话/消息短期记忆过期（秒） |
| `redis.token_ttl` | `43200` | 登录令牌有效期（秒） |
| `retrieval.top_k` | `6` | 召回条数 |
| `retrieval.mode` | `hybrid` | 检索模式 dense / bm25 / hybrid |
| `retrieval.rerank` | `true` | 是否 bge 重排 |
| `memory.short_term_turns` | `5` | 拼进提示词的最近轮数 |
| `admin.usernames` | `[admin]` | 管理员用户名列表（登录即管理员，可在线改配置） |
| `roles_path` | `roles.yaml` | 角色配置文件 |

## 6. 日志系统

统一日志由 `rag2/logging_config.py` 提供：所有模块的 logger 均为 `rag2.*` 命名空间，
启动时 `setup_logging()` 配置 root `rag2` logger —— 控制台输出 + `logs/rag2.log` 滚动落盘
（单文件 5MB，保留 5 个备份）。

```python
from rag2 import setup_logging, get_logger
setup_logging(level="INFO", log_dir="logs")
logger = get_logger("my_module")
```

## 7. 常见问题

**Q1：`/api/health` 里 Redis/Milvus 显示 `ok: false`？**
确认对应服务已启动，地址与 `config.yaml` 一致。

**Q2：提问后返回「模型没有返回内容」？**
检查 Ollama 是否已拉取 `Qwen3.5:4B`；确认 `llm.base_url` 正确。若换用其它模型，可把 `llm.reasoning_effort` 设为空以匹配非思考模型。

**Q3：首次提问很慢？**
首次会加载 bge-m3（向量化）与 bge-reranker-v2-m3（重排）模型，之后会快很多；如不需要重排，可在 `config.yaml` 把 `retrieval.rerank` 改为 `false`。

**Q4：如何清空所有短期记忆？**
Redis 中本项目数据以 `rag2:` 为前缀，可执行：

```bash
redis-cli --scan --pattern 'rag2:*' | xargs redis-cli del
```

**Q5：多用户数据会互相串吗？**
不会。会话列表、消息、令牌均按 `user:<用户名>` / `sess:<id>` / `auth:<token>` 隔离，且 `/api/sessions/{id}` 校验会话归属。

## 8. 管理员配置后台

管理员登录后（用户名在 `admin.usernames` 列表中，默认 `admin`），侧边栏会出现「**⚙ 管理后台**」按钮，
可在网页端直接修改基础配置与角色，**保存即热生效**（无需重启），并自动写回 `config.yaml` / `roles.yaml`（重启后仍保留）。

**可在线修改的基础配置：**

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| 服务地址 | `app.host / port` | 监听地址与端口；保存后点「重启服务」自动重启生效 |
| 对话模型 | `llm.base_url / api_key / model / temperature / max_tokens` | LLM 端点与生成参数，改动后重建客户端 |
| 检索参数 | `retrieval.top_k / mode / rerank / rerank_top_k` | 检索模式与重排开关 |
| 记忆与过期 | `memory.short_term_turns`、`redis.history_ttl / token_ttl` | 短期记忆轮数与 TTL |
| 管理员 | `admin.usernames` | 管理员用户名列表（逗号分隔） |

**角色管理**：新增 / 编辑 / 删除角色（含 `role_id`、名称、`system_prompt`、描述、头像、推荐问题），
写回 `roles.yaml`，主界面角色列表即时同步。

**改端口**：在后台改 `app.port`（1~65535）→ 保存 → 点「**重启服务**」。服务会以新端口自动重启（约 2 秒中断），
浏览器需访问新地址。自动重启仅在用 `python run.py` 启动时可用；若用 `uvicorn rag2.server:app` 启动，保存后请手动重启。

> 提示：
> - `milvus.uri`、`redis.host`、`redis.prefix` 等需重启且不在网页后台范围内，请直接改 `config.yaml` 后重启。
> - 后台保存会**重新生成** `config.yaml` / `roles.yaml`，原文件内的行内注释会丢失（仅保留头注释），字段值不变。
> - 注意不要把管理员自己从 `admin.usernames` 中移除，否则将失去后台访问权限。
