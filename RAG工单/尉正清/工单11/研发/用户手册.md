## 一、五步跑通

```bash
# 0) 装环境（只需一次）
bash 部署/install.sh

# 1) 激活环境 + 配置大模型（生成问答对要用）
conda activate rag_gd
export DEEPSEEK_BASE_URL=https://api.deepseek.com
export DEEPSEEK_API_KEY=sk-xxxxxxxx
export HF_ENDPOINT=https://hf-mirror.com      # 国内必须，否则下载数据集卡死

# 2) 一条命令跑完整条流水线（首次约 1 小时）
bash 部署/start.sh
tail -f 部署/logs/pipeline.log                # 看进度
```

跑完看两个文件：

| 文件 | 内容 |
|---|---|
| `测试/评估报告.md` | 微调前后指标对比 + 逐 query 明细 + 验收结论 |
| `优化/过程问题记录.md` | 实现步骤与踩过的坑 |

想中途停：`bash 部署/stop.sh`。中断后重跑会**复用已算好的向量缓存**，不会从头再来。

## 二、分步跑（想调参或只跑其中一步）

```bash
cd 研发

python build_dataset.py                    # ① 生成数据集（约 20 分钟，含难负例挖掘）
python evaluate.py --model base            # ② 微调前基线（约 18 分钟）
python gen_qa.py --n 5000                  # ③ 生成问答对（约 10 分钟，要 API）
python finetune.py --use-gen --batch 24 --epochs 2 --freeze-layers 6 \
       --keep-last --patience 1000        # ④ 微调（约 100 秒）
python evaluate.py --model finetuned       # ⑤ 微调后评估（约 18 分钟）
cd ../测试 && python compare.py            # ⑥ 生成报告
```

**时间都花在哪**：给 57,638 篇语料编码。训练本身只要 80 秒。
所以调参时改 `finetune.py` 的参数最划算，改语料相关的设置才要等十几分钟。

### 常用参数

```bash
python finetune.py --help
```

| 想干什么 | 怎么加 |
|---|---|
| 扩充训练数据（推荐） | `--use-gen` —— 并入 `gen_qa.py` 生成的问答对 |
| 不用 dev loss 回滚 | `--keep-last` —— 只用 batch 内负例时**必须加**，原因见下 |
| 控制可训练参数量 | `--freeze-layers N` —— **最关键的一个参数**，默认 6；传 0 就是全参数微调（实测会低于基线） |
| 调学习率 | `--lr 1e-5` |
| 省显存 | `--batch 8`（默认 24；开 `--use-hard` 时要降到 16） |
| 换输出目录 | `--output output/我的实验` |

## 三、用微调好的模型

模型在 `研发/output/bge-base-en-v1.5-fiqa/`，是一个标准的 sentence-transformers
模型目录，可以像普通 bge 一样直接加载：

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("研发/output/bge-base-en-v1.5-fiqa")
model.max_seq_length = 512

# ⚠️ 查询侧要加指令前缀，文档侧不加 —— 训练和评估都是这个口径，
#    不加的话效果对不上（见 研发/config.py 的 QUERY_INSTRUCTION）
Q = "Represent this sentence for searching relevant passages: "
q = model.encode(Q + "How do I analyse moving averages?", normalize_embeddings=True)
d = model.encode(["Some passage text ..."], normalize_embeddings=True)

score = q @ d.T          # 已归一化，点积即余弦相似度
```

## 四、常见问题

### 「指标纹丝不动，换了模型也没变化」

多半是向量缓存没失效。缓存键里带了**模型路径 + 权重文件修改时间**，
正常重训后会自动失效。如果你是**原地覆盖**了权重且文件时间没变，
清掉 `研发/cache/emb_*.npy` 再跑。

### 「下载数据集卡住不动」

`HF_ENDPOINT` 没生效。它是在 **import `datasets` 时**被读走的，
必须在启动 Python 之前 export，写到脚本里面再 import 是来不及的。

### 「大模型返回空字符串」

`deepseek-flash` 是推理模型，`max_tokens` 给小了会被 reasoning token 吃光。
本项目 `gen_qa.py` 已经做了翻倍重试（最多三次）；自己写调用时
`max_tokens` 给 4096 起步。

### 「训练时 OOM / 显存不够」

MNR 一个 batch 要跑两次前向（anchor / positive）且都留激活做反向，
显存约为普通微调的两倍。降 `--batch`，或把 `config.TRAIN_MAX_LEN` 调小。

### 「dev loss 一路上涨，是不是过拟合了？」

**在只用 batch 内负例的配置下不是。** 这时模型把向量空间摊开会让 batch 内
那些「别的问题的正确答案」更难分开，dev loss 因此单调上涨，与检索质量脱钩。
这种情况要加 `--keep-last`，不要让它回滚到第 25 步。
详见 `优化/过程问题记录.md` 问题 10。

### 「训完了指标反而比基线低」

大概率是**可训练参数太多**。训练样本只有约 5.6k 条，全参数微调会把预训练
学到的通用语义带偏。加 `--freeze-layers 6`（本工单的默认值）再试。
详见 `优化/过程问题记录.md` 问题 9。
