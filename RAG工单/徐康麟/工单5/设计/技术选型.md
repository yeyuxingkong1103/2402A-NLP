## 2. 四个最关键的选型展开

### 2.1 Query 改写：为什么坚持「规则 + 模板」

| 维度 | 规则 + 模板（选定） | 小模型改写（放弃） |
| --- | --- | --- |
| 延迟 | 纯本地字符串操作（目标 ≤5 ms，**待实测**） | 每轮一次 LLM 调用（预热后仍在百毫秒级；**冷启动首字实测 3430.8 ms，直接违约**，来源 `设计/环境事实.md`） |
| 确定性 | 同输入 → 同输出（不变量 I5） | 温度/上下文波动 → 判分不可复现 |
| 可测性 | `strategy` 枚举 + `rewritten` 逐字比对，**离线**可测（不需要 Ollama） | 只能人看或 LLM 自评 |
| 可解释性 | `resolved_refs` 逐条给出「哪个词换成了什么」 | 只给一句自然语言，出错无法定位 |
| 覆盖度 | 本工单 5 个用例（指代 / 省略式 / 槽位继承）**全部可覆盖** | 可能覆盖更多，但引入新的失败模式（改写跑偏、丢字段、加事实） |
| 依赖 | 零新增 | 依赖 Ollama 可用（多一个失败点） |

**结论**：速度优先 + 最低可运行 + 确定性判分的组合下，规则是**唯一**能同时满足三项的方案。
若未来要引入模型兜底，必须**先**在 `设计/Query改写流程.md` 登记触发条件并把 `multi_turn_enrich` 从预留变为启用，**不得**悄悄改行为。

### 2.2 对话历史：3 轮 + 状态化（而不是「3 轮里翻找」）

* **裁的是记录，不裁状态**：`turns` 只保留 3 轮（工单备注要求），但 `focus_entity` / `last_slot` / `entity_stack` 长期保留。
* **为什么 3 轮够用**：指代与省略式只依赖「当前话题 + 上次问的字段」两个量，它们在状态里而不是在历史里。
  5 轮用例中 Q5 执行时 `turns` 只剩 Q3/Q4/Q5，但 Q1 建立的实体仍在 `entity_stack`（见 `设计/Query改写流程.md` §6.7 快照表）。
* **代价**：`entity_stack` 上限 8，超出丢栈底；被丢的实体不能再被「栈回退」找回——登记为已知限制。

### 2.3 Web 界面：Gradio 首选 + 标准库兜底（**因为本机确实没有 Gradio**）

| 路径 | 文件 | 端口 | 依赖 | 角色 |
| --- | --- | --- | --- | --- |
| 首选 | `部署/界面/gradio_app.py` | 7860 | `gradio`（**本机未安装**） | 满足工单「如 Gradio」的原始要求；缺依赖时**打印安装指引并退出码 3**（不静默降级、不伪装成功） |
| 兜底（必可用） | `部署/界面/web_app.py` | 8123 | **零第三方依赖**（`http.server` + 内嵌 HTML/JS） | 交付与验收的**实际可用界面**：多轮气泡、引用展示、`session_id` 保持、用户反馈按钮、`GET /health` |
| API | `部署/脚本/serve_api.py` | 8600 | `fastapi` + `uvicorn`（已装） | 评测与集成入口（`POST /api/chat`） |

**纪律**：三条路径**共用**同一个 `MultiTurnEngine`（禁止各写一套业务逻辑）；界面差异化只允许在传输与渲染层。
截图留痕以**兜底界面**为准（它是本机唯一保证可跑的界面）。

### 2.4 缓存：LRU + 落盘，且**不给改写结果加缓存**

* 复用 `QAEngine` 的**问题级内存 LRU + 答案级落盘**（`研发/data/index/qa_runtime.sqlite3`），`use_cache` 由 `MultiTurnEngine.ask` 透传。
* **缓存键是「改写后的独立问句」**（`QAEngine._cache_key(resolved_question, language, top_k)`）：多轮 Q3 与单轮「武汉兴图新科电子股份有限公司的法定代表人是谁？」命中**同一条**缓存 → 多轮与单轮的收益可叠加。
* **副作用与要求**：缓存键不含 `session_id`，因此改写结果必须**稳定**（规则实现天然满足 I5 确定性）；若将来引入模型改写，缓存会因改写抖动而失效——这也是 2.1 选型的又一个理由。
* **不给改写加缓存**：改写耗时低于「构造缓存键 + 查表 + 淘汰」的开销；且改写依赖会话状态，键会包含状态快照，命中率低、复杂度高。
* **延迟测量纪律**：缓存命中与未命中**分别统计**，不得用命中样本充当全量性能（`设计/验收标准.md` A4）。

## 3. 拒绝项汇总（一句话版）

| 被拒绝的方案 | 一句话原因 |
| --- | --- |
| LangChain / LlamaIndex 框架 | 工单4 已确定自实现轻量管线（无框架依赖更可控、更少失败面） |
| Milvus / Elasticsearch / Redis / Chroma | 均需额外服务或依赖，违反「零服务依赖 + 速度优先」 |
| 云端大模型（生成或改写） | 联网、密钥、成本、延迟不可控，破坏离线可复现 |
| 小模型改写 / 训练式改写 | 增加延迟与不确定性，且 5 个用例规则已全覆盖 |
| Streamlit | 本机未安装（与 Gradio 同因），无补充价值 |
| 直接 `pip install` | 落点是只读的 `工单1\.venv\Lib\site-packages`（红线） |
| 多进程 / 多 worker 跑多轮 | 状态在进程内，多 worker 会丢会话（`设计/多轮对话架构.md` §10） |
| LLM 自评判分 | 不可复现、会掩盖回归；判分一律确定性（`测试/common/golden.py`） |
