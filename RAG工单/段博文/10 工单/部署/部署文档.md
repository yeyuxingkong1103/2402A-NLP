# RAG 金融问答系统 Docker 部署文档

> 工单编号：人工智能NLP-RAG-金融问答系统部署

---

## 一、项目概述

将 RAG 金融问答系统以 Docker 容器形式部署在服务器中，支持金融场景下的对话功能。

**技术栈**：
- Web 框架：FastAPI + Uvicorn
- 向量数据库：Milvus v2.4.0（standalone）
- 元数据存储：etcd v3.5.5
- 对象存储：MinIO
- 向量模型：bge-m3
- 重排模型：bge-reranker-large
- LLM：DeepSeek API

## 四、快速部署

### 4.1 准备模型文件

将 bge-m3 和 bge-reranker-large 模型放到宿主机目录，例如 `/data/models/`：

```
/data/models/
├── bge-m3/
│   ├── config.json
│   ├── pytorch_model.bin
│   └── ...
└── bge-reranker-large/
    ├── config.json
    ├── pytorch_model.bin
    └── ...
```

### 4.2 配置环境变量

```bash
cd 部署/
cp docker/.env.example docker/.env
# 编辑 .env，填入 LLM_API_KEY
vim docker/.env
```

### 4.3 启动服务

```bash
cd 部署/
docker-compose up -d --build
```

### 4.4 查看服务状态

```bash
docker-compose ps
docker-compose logs -f rag-app
```

### 4.5 验证服务

```bash
# 健康检查
curl http://localhost:8000/api/health

# 检索测试
curl "http://localhost:8000/api/search?query=平安银行董事长&top_k=3"

# 问答测试
curl -X POST http://localhost:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"query": "平安银行2019年的董事长是谁？", "top_k": 3}'
```

## 五、数据持久化

### 5.1 Docker 卷说明

| 卷名 | 挂载路径 | 用途 |
|------|----------|------|
| `milvus-data` | `/var/lib/milvus` | Milvus 向量数据 |
| `etcd-data` | `/etcd` | Milvus 元数据 |
| `minio-data` | `/minio_data` | Milvus 对象存储 |
| `rag-data` | `/app/data` | 上传的 PDF 与索引数据 |
| `rag-models` | `/models` | 模型权重 |
| `rag-logs` | `/app/logs` | 应用日志 |

### 5.2 数据备份

```bash
# 备份所有卷
docker run --rm -v rag-data:/data -v $(pwd):/backup alpine tar czf /backup/rag-data.tar.gz -C /data .

# 备份 Milvus 数据
docker run --rm -v milvus-data:/data -v $(pwd):/backup alpine tar czf /backup/milvus-data.tar.gz -C /data .
```

### 5.3 数据恢复

```bash
docker run --rm -v rag-data:/data -v $(pwd):/backup alpine tar xzf /backup/rag-data.tar.gz -C /data
```

## 六、容器管理

### 6.1 启动与停止

```bash
# 启动
docker-compose up -d

# 停止
docker-compose down

# 重启单个服务
docker-compose restart rag-app

# 重建（代码修改后）
docker-compose up -d --build rag-app
```

### 6.2 查看日志

```bash
# 查看所有服务日志
docker-compose logs

# 实时查看应用日志
docker-compose logs -f rag-app

# 查看最近 100 行
docker-compose logs --tail=100 rag-app
```

### 6.3 进入容器

```bash
# 进入应用容器
docker exec -it rag-app bash

# 进入 Milvus 容器
docker exec -it rag-milvus bash
```

### 6.4 清理

```bash
# 停止并删除容器（保留数据卷）
docker-compose down

# 停止并删除容器和数据卷（⚠️ 数据会丢失）
docker-compose down -v
```

## 七、网络配置

### 7.1 端口映射

| 服务 | 容器端口 | 主机端口 | 说明 |
|------|----------|----------|------|
| rag-app | 8000 | 8000 | Web API + 前端 |
| milvus | 19530 | 19530 | Milvus gRPC |
| milvus | 9091 | 9091 | Milvus HTTP |
| minio | 9000 | 9000 | MinIO API |
| minio | 9001 | 9001 | MinIO 控制台 |

### 7.2 与其他服务通信

容器加入 `rag-net` 网络后，可通过容器名直接访问其他服务：

```python
# 在应用容器内访问 Milvus
MILVUS_URI = "http://milvus:19530"

# 访问 RTMP 服务器（假设在同一网络）
RTMP_URL = "rtmp://rtmp-server:1935/live"
```

如需与外部服务通信，可将外部服务加入 `rag-net` 网络：

```bash
docker network connect rag-net <external-container>
```

## 八、性能优化

### 8.1 资源限制

在 `docker-compose.yml` 中添加资源限制：

```yaml
rag-app:
  deploy:
    resources:
      limits:
        cpus: '4'
        memory: 8G
      reservations:
        cpus: '2'
        memory: 4G
```

### 8.2 GPU 支持

```yaml
rag-app:
  deploy:
    resources:
      reservations:
        devices:
          - driver: nvidia
            count: 1
            capabilities: [gpu]
  environment:
    - EMBED_DEVICE=cuda
    - RERANK_DEVICE=cuda
```

## 九、常见问题

| 问题 | 解决方案 |
|------|----------|
| Milvus 启动失败 | 检查 etcd 和 minio 是否正常启动；检查磁盘空间 |
| 模型加载失败 | 确认 `rag-models` 卷已挂载模型文件；或删除卷让容器自动下载 |
| API 无响应 | 检查端口 8000 是否被占用；查看应用日志 |
| 中文乱码 | 确认容器内 `LANG=C.UTF-8` 环境变量已设置 |
| 内存不足 | 增加宿主机内存；或降低 `TOP_K_RECALL` 参数 |
