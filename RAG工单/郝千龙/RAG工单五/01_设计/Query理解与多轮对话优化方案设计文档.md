# Query理解与多轮对话优化方案设计文档

工单编号：人工智能NLP-RAG-Query理解优化任务

## 一、设计目标

在无 GPU、无外网大模型的离线环境下，基于 TF-IDF + BM25 检索链路，实现对多轮对话中用户 Query 的深度理解，覆盖：

1. **术语归一与同义词扩展**：将用户口语/简称映射到招股书标准术语（如“军用”↔“国防”）。
2. **指代消解**：识别“他 / 这个公司 / 该公司 / 其”等指代词，替换为当前话题实体。
3. **省略补全**：对“那 XX 呢？”这类省略主语或意图的问句，继承上一轮意图并补全新实体。
4. **对话状态管理**：维护实体栈与最近意图，支撑多轮上下文。
5. **多轮对话 UI**：基于 Streamlit 的多轮问答界面，展示原始问句、改写后查询、答案与证据页码。

验收指标：整组多轮准确率 ≥ 90%，单轮响应 ≤ 3 秒。

## 二、总体架构

```
用户输入
  │
  ▼
DialogueManager（对话状态：entity_stack / last_intent）
  │
  ▼
QueryUnderstanding
  ├─ 术语归一（军用→国防 等）
  ├─ 指代消解（他/这个公司→最近话题实体）
  └─ 省略补全（那XX呢→继承上轮意图）
  │
  ▼ 改写后查询
Retriever（TF-IDF + BM25，主体公司加分）
  │
  ▼ Top-K 证据
QAEngine
  ├─ 槽位抽取（法定代表人/注册资本/英文名，主语约束）
  ├─ “分别”题数字最全句选择（核心词+口径约束）
  └─ 组织结构图几何重建答案
  │
  ▼
Streamlit UI（多轮对话展示）
```

## 三、Query 理解核心设计

### 3.1 术语归一

招股书中同一概念存在多种表述，用户提问与原文术语不一致会导致检索漏召回。

| 用户术语 | 归一术语 | 说明 |
|---------|---------|------|
| 军用 | 国防 | 兴图招股书正文统一用“军用领域”，但部分上下文用“国防”；双向扩展 |
| 军方/军品 | 军用/国防 | 答案抽取时同义词扩展，避免敏感度分析表误命中 |

实现位置：`query_understanding.py` 的 `normalize_terms`，在检索前将查询中的“军用”替换为“国防”以匹配原文高频词；在 `qa_engine.py` 答案抽取时对“国防↔军用↔军品↔军方”做双向扩展。

### 3.2 指代消解

触发词集合：`{他, 她, 它, 这个公司, 该公司, 其, 这家公司}`。

消解策略：
1. 若当前问句含指代触发词，取 `entity_stack` 栈顶（最近话题实体）替换。
2. 实体栈上限 3 轮，新实体入栈时淘汰最旧。
3. 实体来源：上一轮问句中出现的公司全称（通过公司名正则匹配）。

样例：
- 轮1：“武汉兴图新科电子股份有限公司来自军用领域的收入…” → 实体入栈 `[兴图]`
- 轮2：“他参与的哪个工程荣获了国家科技进步一等奖？” → 消解为“武汉兴图新科电子股份有限公司参与的…”

### 3.3 省略补全

触发模式：问句以“那 / 那么”开头，且不含明确意图词（如“法定代表人”“注册资本”）。

补全逻辑：
1. 剥离“那/那么”前缀，提取新实体（公司名）。
2. 若剩余文本含意图词，直接用该意图。
3. 若剩余文本无意图（如“那武汉力源信息技术股份有限公司呢？”），继承 `last_intent`。
4. 拼接为“新实体 + 上一轮意图”。

样例：
- 轮3：“这个公司的法定代表人是谁？” → 意图 = 法定代表人
- 轮4：“那武汉力源信息技术股份有限公司呢？” → 补全为“武汉力源信息技术股份有限公司的法定代表人是谁”

### 3.4 对话状态管理

`DialogueState` 数据结构：
- `entity_stack: List[str]`：最近话题实体，最新在前，上限 3。
- `last_intent: str`：上一轮意图关键词（法定代表人/注册资本/收入/英文名等）。
- `history: List[Tuple[str, str]]`：完整问答历史，用于 UI 展示。

每轮更新规则：
1. 从改写后查询中提取公司实体，压入 `entity_stack`（去重）。
2. 从问句中提取意图词，更新 `last_intent`。

## 四、检索与答案抽取优化

### 4.1 主体公司加分

`retriever.py`：当查询含明确公司名时，对 chunk 头部“主体：”标签匹配的块加 0.5 分，避免中介机构/子公司同名槽位压制目标公司块。匹配前先剥离“那/那么”前缀。

### 4.2 槽位主语约束

`qa_engine.py` `_slot_answer`：
- `extract_company_from_question` 先剥离“那/那么”再匹配公司名。
- `_subject_ok`：匹配位置前最近公司须为目标公司；或目标公司字号（去城市前缀+去“股份有限公司”后缀，取前 6 字）出现在附近 300 字内——解决前身公司名（如“武汉力源信息技术有限公司”）问题。
- 兜底：Top-10 证据未命中时，扫描全部 `issuer==目标公司` 的 chunks。

### 4.3 “分别”题答案选择

对含“分别”的数字题，不再全局取数字最多的句子（会选中敏感度分析大表），改为：
1. 计算 `best_score`（Top1 句子得分）。
2. `core_cands`：得分 ≥ `best_score - 0.3` 且含领域核心词（排除“来自/期内/报告”等通用词）。
3. 收入类问题额外约束：须含“收入/销售额/营收”且含“领域”。
4. 优先选含“分别为/分别是”的候选，再取数字最全者。

### 4.4 组织结构图几何重建

`pdf_parser.py` `_detect_orgchart`：
1. 用 `page.get_text("dict")` 拼接全部 span 文本（解决竖排页 `get_text()` 截断问题）。
2. 同一 x 桶内按 y 间隔（>40）分段，重建竖排文字单元（解决“行政人事部”与“武汉销售处”同 x 桶拼接问题）。
3. 检测水平母线（y≈543，跨度>200），只保留母线上方的竖线（销售部→母线），排除母线下方竖线（销售处→母线）。
4. 有竖线触达母线的销售部即为所有销售处的父部门。
5. 生成结构化文本块：销售处最多的销售部、下设销售处清单、全部销售处。

## 五、多轮对话 UI 方案

基于 Streamlit 实现（`app.py`）：
- 左侧：对话历史（用户问题 + 系统答案 + 改写后查询 + 证据页码）。
- 右侧：当前轮输入框。
- 每轮展示：原始问题、改写后查询（体现指代消解/省略补全）、答案、Top1 证据页码。
- 会话状态通过 `st.session_state` 维护 `DialogueManager`，支持连续多轮。
