## 2. 领域与语料

- 语料：工单7 已解析的 **9 份 A 股年报**（平安银行/中国平安/招商银行/邮储银行/中信证券/中国人寿/中国太保/招商证券/国泰君安），共 **8847 个分块**（text 7325 / table 1417 / image 105），页码基准 1-based physical。
- 领域特征（正是原文说的「语义鸿沟」）：
  - 大量专业指标（不良贷款率、拨备覆盖率、拨贷比、核心一级资本充足率、已赚保费…），通用模型对同族指标（净利润 vs 归母净利润 vs 扣非净利润）区分度不足；
  - 高频数值事实，查询与证据段之间存在**词汇鸿沟**（问「营业收入是多少」而正文是表格数字）；
  - 同一指标在 9 家公司重复出现，**实体（公司）+ 年度**才是区分性信息 —— 这决定了难负例的构造方式。

## 3. 关键需求决策（含风险）

| 决策 | 理由 | 风险与缓解 |
| --- | --- | --- |
| 底座选 `bge-small-zh-v1.5`（本地权重） | 23.95M 参数、512 维、4 层，CPU 可训；无需联网下载 | 底座弱，绝对指标有限 → 如实记录，并用 bge-m3 作参照口径说明 |
| **自实现训练循环**（不用 sentence-transformers Trainer） | 本机**无 accelerate/peft/datasets**，`Trainer` 会直接 ImportError | 手写 `nn.Module` + `AdamW` + 余弦调度，损失函数自己实现（原文已点名公式） |
| 训练走 **CPU**，6 线程 | 原文环境与 `_共享约定.md` 要求，避免与并行工单抢 RTX 2060 6GB | 时间预算 1080s 硬约束，到点停并保留检查点 |
| 数据集**不使用工单7 的 17 道测试问题** | 那 17 题是唯一的「真实评测集」，一旦进入训练即为泄漏 | 训练锚点全部来自语料弱监督；17 题仅用于最终评估 |
| 页级留出（12% 页面） | 保证 dev/test 的正例分块在训练中**正例与负例都未出现过** | 负例候选池显式剔除留出页分块 |
| 检索池抽样 2500 块 | 全量 8847 块 × 2 个模型编码超时间预算 | 抽样池**包含全部金标准分块**，仅压缩干扰项数量；口径写入结论 |

## 4. 明确的非目标

- 不引入 LoRA/PEFT（原文提到 LoRA 但环境不允许装包；本任务参数少，全参微调的最后两层即等价效果）。
- 不做重排（rerank）、不做生成侧（RAG 生成是工单7 的范畴）。
- 不重训 bge-m3（1024 维，CPU 上不可行），bge-m3 仅作为工单7 生产模型的参照口径。
