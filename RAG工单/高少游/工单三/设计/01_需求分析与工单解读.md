## 2. 答案在 PDF 中的定位分析（本工单的技术出发点）

对 14 道题的答案逐一定位后，可归纳出**两类**：

### 2.1 表格型问题（10 道，占 71%）——必须靠表格解析

| id | 问题要点 | 答案位置与形态 |
|---|---|---|
| 1 | 发行股数、占发行后总股本比例 | 招股2 第24页「本次发行概况」表 |
| 2 | 募集资金拟投资项目 | 招股2 第22页「募集资金投资项目」表（多行罗列） |
| 3 | 存在控制关系的关联方、持股比例、关系 | 招股2 第157页「关联方及关联关系」表 |
| 4 | 不存在控制关系的关联方企业 | 招股2 第157页同表（多行罗列） |
| 260 | 军用领域收入（分年度） | 招股1 第343页「军用领域收入构成」表 |
| 33 | 军用领域收入占主营业务收入比重 | 招股1 第343页同表（另一列） |
| 543 | 注册资本 | 招股1 第22页「发行人基本情况」表 |
| 531 | 法定代表人 | 招股1 第22页同表 |
| 207 | 用于补充流动资金的募集资金金额 | 招股1 第30页「募集资金运用」表 |

**共性**：答案 = "**表头字段 → 取值**"的绑定关系。若表格被拍平成文本，字段与取值分离，检索必然失败。

### 2.2 正文型问题（4 道）

| id | 问题要点 | 答案位置与形态 |
|---|---|---|
| 95 | 参与制定的技术标准 | 正文段落（"全军第一个视频指挥系统技术标准"） |
| 34 | 电子信息行业上游涉及企业 | 正文段落（枚举型） |
| 793 | 电子信息行业下游主要行业 | 正文段落（枚举型） |
| 795 | 荣获国家科技进步一等奖的工程 | 正文段落 |

**共性**：答案在连续文本中，靠句子级抽取即可，但也需**对比词消歧**（如问"上游"不要召回"下游"）。

## 3. 核心难点

| 难点 | 说明 | 后果 |
|---|---|---|
| D1 行列关系丢失 | 表格拍平为文本行后，表头与数据行分离 | "表头命中、数值在别处"，答案拼不出 |
| D2 合并单元格错位 | 多级表头 / 跨行合并单元格在纯文本中丢失归属 | "某年—某项目—某数值"三元关系无法还原 |
| D3 交错列布局 | 力源信息招股书的表格被 PDF 线条切成"表头列 / 数据列"交替网格 | 表头与取值整体错位 |
| D4 跨页表格断裂 | 长表格跨页后表头不再重复 | 后半段成为"无表头孤儿行" |
| D5 多文档串味 | 两份招股书都有"发行股数/募集资金/关联方"同构表 | 问力源却召回兴图新科 |
| D6 数值密集表抢占 | 现金流量表等数值极多但与问题无关 | 无关表格排在前面，答案被污染 |
| D7 答案冗长 | 直接拼整张表 | 可读性差，违反"交互友好" |

## 4. 需求 → 方案映射

| 需求 | 对应设计 | 对应模块 |
|---|---|---|
| 新增招股2解析 | 多文档知识库 + source 溯源 | `config.PDF_PATHS` / `knowledge_base.py` |
| 表格定位（备注1） | 版面级表格检测 + 合并单元格还原 + 双表示 | `table_parser.py` / `chunking.py` |
| 准确率 ≥ 90% | 表格感知重排 + 表格专用答案路径 | `reranker.py` / `answer_builder.py` |
| 响应 ≤ 3 s | 抽取式答案（不调用 LLM 生成） | `answer_builder.py` |
| 多文档消歧（D5） | 公司名 → 源文件 文档级路由 | `query_understanding.py` / `retriever.py` |
| 交互友好 | Streamlit 四视图界面 | `app.py` |
| 多语言 | 中英文分词 + 中英混合检索 | `retriever.tokenize` |
| 稳定性/容错 | 多级 try/except + 降级 + 兜底答案 | 全链路 |
| 代码注释含工单编号 | 所有模块 docstring 首行注明 | `src/*.py` `scripts/*.py` |
