## 二、系统总体架构

系统采用**分层架构**，自下而上为：数据层 → 索引层 → 检索层 → 重排层 → 多轮理解层 → 应用层。
其中**检索层**为本工单核心，三种策略共用同一套索引，可运行期热切换。

```
┌──────────────────────────────────────────────────────────────────────┐
│  应用层     Streamlit 检索配置界面 │ 命令行演示 run_demo │ 评测 evaluate_retrieval │
├──────────────────────────────────────────────────────────────────────┤
│  多轮理解层  会话记忆 Conversation │ Query 改写（指代/省略）│ Query 理解（关键词/实体/类型/路由）│
├──────────────────────────────────────────────────────────────────────┤
│  重排层      多信号线性融合 │ TF-IDF 重排 │ LLM 重排 │ 反馈自适应重排 │
├──────────────────────────────────────────────────────────────────────┤
│  检索层      ① 向量检索（召回+重排）  ② 全文检索（倒排索引）  ③ 混合检索（权重+融合）│
│  （核心）            └──────────── 统一入口 HybridRetriever ────────────┘        │
├──────────────────────────────────────────────────────────────────────┤
│  索引层      多嵌入模型向量库          多字段倒排索引           结构感知切片       │
│              bge-m3/bge-large/nomic   BM25(title/body/abstract)  文本/表格/图形语义 │
├──────────────────────────────────────────────────────────────────────┤
│  数据层      招股说明书1（武汉兴图新科）        招股说明书2（武汉力源信息）        │
└──────────────────────────────────────────────────────────────────────┘
```

架构图见 `设计/assets/01_系统总体架构.png`。

## 三、检索策略设计（核心）

三种策略由 `RetrievalConfig.strategy` 选择，统一入口为 `HybridRetriever`。

### 3.1 向量检索（召回 + 重排）

**召回**：`VectorRetriever` 用选定的嵌入模型把 Query 与文档块编码为稠密向量
（已 L2 归一化），以**余弦相似度**（等价于点积）做 Top-K 召回。
多查询扩展（同义词 / 实体）批量编码后按块取最大相似度聚合。

**重排**：召回候选交由所选重排器重新排序（见第四章）。

**多嵌入模型**：`config.EMBEDDING_MODELS` 登记 slug → (Ollama 模型名, 维度, 说明)，
同一份切片可并行向量化多个模型，落盘为 `emb_<slug>.npy`，运行期切换 slug 即切换模型。

### 3.2 全文检索（倒排索引）

`InvertedIndex` 自建**含位置信息**的倒排链，支持：

| 能力 | 说明 |
|---|---|
| BM25 打分 | 多字段加权（title / body / abstract），可调字段权重 |
| 布尔查询 | `AND` / `OR` / `NOT`（兼容中文「与 / 或 / 非」） |
| 短语匹配 | 双引号 `"…"`，词元位置连续校验 |
| 模糊匹配 | 编辑距离（Levenshtein ≤ 阈值）近似词扩展 |
| 模式自动判定 | `auto`：含布尔词→布尔；含引号→短语；否则 BM25，无结果兜底模糊 |

### 3.3 混合检索（向量 + 全文）

两通道**同时执行**，再按融合算法合并，权重可调（自动归一化）：

| 融合算法 | 原理 | 适用 |
|---|---|---|
| 加权平均 `weighted` | 两通道分数极值归一化后按权重求和 | 分数可比、需平滑 |
| 倒数排名融合 `rrf` | `Σ wᵢ / (k + rankᵢ)`，只用排名、对分数量纲不敏感 | 稳健默认 |
| 投票 `voting` | 各通道 Top-M 各投一票（按权重计票） | 强调共识 |

### 3.4 文档级路由（实体消歧）

两份招股说明书存在同构字段（法定代表人 / 注册资本 / 关联方…），
`HybridRetriever._doc_filter` 依据查询中的公司别名匹配到源文档后，
**只在对应文档的块集合内检索**，避免「问力源却召回兴图」的跨文档串味。

路由优先级为：**当前轮 Query 理解得到的 `doc_hint` > 主查询别名 > 扩展查询别名**。
历史话题实体（多轮上下文）只作兜底，不得覆盖当前轮显式指定的公司——否则多轮里
「先问兴图、再问力源」时，上一轮的话题公司会把当前轮路由劫持到错误文档。

## 四、重排算法设计（4 种，≥3 种）

统一接口：`rerank(query, candidates, kb, analysis, feedback, top_k)`。

| # | 重排器 | 核心信号 | 特点 |
|---|---|---|---|
| 1 | **LinearFusionReranker** | 向量分 + BM25 分 + 关键词/同义词/实体覆盖 + 数值命中 + 序列 + 短语 + 表格/图形 + 话题 + 反馈 | 多信号融合，效果最稳（默认） |
| 2 | **TfidfReranker** | 语料 IDF × 候选 TF，余弦相似度 | 无监督、可解释 |
| 3 | **LLMReranker** | 本地大模型（deepseek-r1:1.5b）listwise 打分 | 语义理解强，但延迟不可控（实测均值 4.23s、离群 67.4s，超 3s） |
| 4 | **AdaptiveFeedbackReranker** | 👍 加分 / 👎 减分，块级在线学习 | 随用户反馈持续优化 |

线性融合的关键信号（`config.W_*` 可调）包括：查询核心短语（连续 n-gram）匹配、
数值命中、序列标记、表格/图形块加成、话题实体覆盖与反馈加权。

> 重排选型结论：默认 **linear**（准确率 100%、0.019s）；**LLM 重排不作为默认**，
> 因本地小模型延迟超标，需配合候选截断 + 超时回退使用。

## 五、检索策略配置对象

`RetrievalConfig`（`retrieval_config.py`）把所有可调项收敛为一个可序列化对象：

```python
strategy        # vector | fulltext | hybrid
embedding_model # bge-m3 | bge-large | nomic-embed | m3e-base
fulltext_mode   # auto | bm25 | boolean | phrase | fuzzy
reranker        # none | tfidf | llm | adaptive | linear
fusion          # weighted | rrf | voting
vector_weight / fulltext_weight   # 混合权重（自动归一化）
recall_k / top_k / answer_top_k / rrf_k
fields          # title / body / abstract
use_synonyms / use_llm_rewrite
```

**三入口配置**：界面下拉（`app.py`）→ 命令行参数（`evaluate_retrieval.py`）→ 环境变量（`.env`），
三者最终都落到 `RetrievalConfig`，保证「同一套索引、三种策略、可消融对比」。

## 六、知识库与索引构建

`build_kb.py` 流程：

1. **PDF 解析**（`pdf_parser.py`）：正文 + 表格（`kind=table`）；
2. **图形语义**（`figure_semantics.py`）：矢量组织结构图 → 「X 由 N 个 Y 构成：…」可检索文本（`kind=figure`）；
3. **结构感知切片**（`chunking.py`）：按结构切分并派生 title / abstract 多字段；
4. **多模型向量化**（`embedding.py`）：对选定 slugs 批量编码 → `emb_<slug>.npy`；
5. **倒排索引**（`knowledge_base.build_inverted_index`）：多字段建索引 → `inverted_index.pkl`；
6. **落盘**：`chunks.jsonl` + `meta.json`。

## 七、Query 理解与多轮

| 模块 | 职责 |
|---|---|
| `conversation.py` | 会话记忆（Turn 列表、话题公司、话题实体、历史文本） |
| `query_rewriting.py` | 四类改写：省略补全 / 指代消解 / 追问补全 / 独立问句 |

## 八、答案合成（抽取式、零幻觉）

`answer_builder.py` 按答案类型分流抽取，输出答案句 + 证据（源文件 / 页码 / 片段 / 得分）：

结构枚举型、多字段型、关系型、字段型、金额字段型、时长型、数值序列型（含表格行兜底）、
指标值型、奖项型、名单型、通用型。

## 九、界面与交互

`app.py`（Streamlit）左侧提供**检索策略配置面板**：

- 检索策略：向量 / 全文 / 混合
- 嵌入模型：bge-m3 / bge-large / nomic-embed
- 全文模式：自动 / BM25 / 布尔 / 短语 / 模糊
- 重排算法：linear / tfidf / llm / adaptive / none
- 融合算法：加权平均 / RRF / 投票
- 权重调整：向量权重 / 全文权重

每条回答展示：多轮改写、命中文档、答案类型、响应耗时、检索策略详情、证据片段，
并提供 👍/👎 反馈（驱动自适应重排）。

## 十、多语言支持

`i18n.py`：界面双语（中/英）；英文提问经术语映射转为中文检索式检索中文库；
英文模式下可开启「答案自动翻译」。

## 十一、关键设计取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 向量库 | Ollama HTTP + numpy（不引入 faiss/torch） | 依赖轻、易复现、便于离线部署 |
| 答案 | 抽取式（非生成式） | 零幻觉、可溯源，满足招股书问答的严谨性 |
| 融合默认 | RRF | 只用排名，避免两通道分数量纲不一致 |
| 重排默认 | linear（非 LLM） | LLM 本地延迟不可控（实测超 3s），linear 精度最高且 0.019s |
| 深度 | `answer_top_k` > `top_k` | 展示取 top_k，抽取用更深的池，兼顾体验与命中率 |
| 消歧 | 文档级路由 | 同构字段跨文档串味是招股书问答的主要错误源 |
