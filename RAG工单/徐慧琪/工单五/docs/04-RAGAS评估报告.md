## 三、5 轮验收序列（多轮题）

- 参考答案（`reference`）取自需求文档《需求开发.docx》的标准答案，
  **不是**从系统输出倒推的；
- 答案与 contexts 复用 `python run_acceptance.py` 的产物（`data/eval/acceptance_result.json`）——多轮题的 contexts 只有在**带对话状态**的那一次运行里才是对的，单独重跑等于换了输入；
- 因此本组数字评的是「多轮链路真实产出的回答」，与 `docs/06-验收序列逐轮报告.md` 逐轮可对照。

| 指标 | 均值 | 说明 |
| --- | --- | --- |
| faithfulness | 0.7 | 回答是否忠实于检索上下文（1=无编造） |
| answer_relevancy | 0.515 | 回答与问题的相关性 |
| context_recall | 1.0 | 检索上下文对标准答案（reference）的覆盖度 |
| context_precision | 0.83 | 检索上下文中相关内容的占比 |

### 3.2 怎么读这组数字

- **`context_recall` 5 轮全部 1.0**：这是本工单最关键的一格——Q2/Q3/Q4 的
  原问题含代词或省略，**不做改写就不可能检索到覆盖标准答案的片段**。
  5/5 说明改写后的独立问题确实检索到了正确答案所在的位置；
- **`answer_relevancy` 对简短与列点式答案天然偏低**（该指标由「答案反向生成
  问题」计算，短答案反向生成的问题必然泛化），Q1 的长数字列表得 0.0 属口径特性，
  与 `docs/04` 历史上记录的同一现象一致，不代表答非所问；
- **`faithfulness` 低分要归因，不能一律当成编造**：本组「答案逐字来自上下文」
  一列就是为此设的——若该列为 ✅ 却得 0 分，那是**裁判误判**而非幻觉。

  **本次实测**：Q2（0.333） 的 `faithfulness` 低于 0.5，但该轮答案在检索片段中**逐字可查**（脚本自动核对，见上表），
  故判定为**裁判压分**，不是编造。该轮答案与上下文的一致性以
  `docs/06-验收序列逐轮报告.md` 的逐字对照为准。

  **附带证据（裁判不稳定性是实测的，不是推测）**：同一份 Q2 答案在两次裁判运行间实测得 **0.0** 与 **0.333** 两个分数，
  而该答案两次都逐字来自检索片段。因此本表的绝对值只能横向读（同一组内比较），不能当成精确刻度。

> 结论：多轮组的 `context_recall = 1.0` 与逐轮事实全命中（见 docs/06）
> 互为佐证；`faithfulness` 的绝对数值受本机 3b 裁判稳定性限制，
> 不宜作为「有没有编造」的唯一判据。
