### ⚠️ 关于「网络」的一处判断更正（重要）

本仓库**最初**沿用工单6 遗留笔记，写下「沙箱封禁外网出口、pip 会挂死」，据此把 Gradio / pandas /
pdfplumber / RAGAS 列为「技术栈偏离」。**该结论是错的**，已按用户提示重新逐层探测：

| 探测项 | 实测 |
| --- | --- |
| DNS / TCP 443 | ✅ 正常 |
| **Python TLS + HTTP GET**（OpenSSL 3.5.6 + certifi） | ✅ baidu / pypi.org / 清华源 / 阿里源 / hf-mirror / github **全部 200** |
| `pip index versions gradio` | ✅ 秒回（300+ 版本） |
| HF 镜像下载 718 MB 权重 | ✅ 实测 1.22 MB/s |
| `curl.exe` / `Invoke-WebRequest` | ❌ `schannel: SEC_E_NO_CREDENTIALS`（**Windows 系统 TLS 凭证不可用**，与封网无关） |

**结论：网络可用；真正受限的是 `pip install` 的落点** ——
`pip install --target` 在本机沙箱下抛 `PermissionError`（pip 自己的临时解包目录被拒，改 TMP/TEMP 也绕不过）。
因此本工单提供 **`工具/不依赖pip装包.py`**：直接下 wheel → `zipfile` 解包到 `研发/第三方库`，
带依赖约束求解与 `_lock.json` 版本凭证。安装依赖：

```powershell
& $env:GD7_PY 工具\不依赖pip装包.py gradio pandas pdfplumber --with-deps
& $env:GD7_PY 测试\下载中文CLIP权重.py            # 718 MB 中文 CLIP 权重（HF 镜像优先）
```

**两处踩坑（已写进代码注释）**：
1. `研发/第三方库` 必须放在 `PYTHONPATH` 的**最后** —— 它含 numpy 2.x，而 venv 的 faiss 是针对旧 numpy
   编译的 C 扩展，放前面会让 `import faiss` 抛 `_ARRAY_API not found`，向量检索整条链路失败；
2. 第三方库里的 **numpy 2.4.6 已移除**，统一用 venv 的 1.26.4（pandas 3.0.6 与之兼容）。

**图像链路并不需要 cv2/onnxruntime**（旧结论同样有误）：`extract_images.py` 实测只依赖
`PIL + pymupdf + numpy` → 已真实产出 **175 个图像块 / 102 图表 / 19 框图 / 196 条 CLIP 嵌入**。

## 七、已知限制（如实列出，未粉饰）

1. **图像内容检索已补齐，但覆盖面受语料本身限制**：中文 CLIP 链路已实跑（图像块 105 个，覆盖 9 份年报），
   但各年报的图表/框图数量差异极大（中国太保 37 个、招商银行仅 2 个），
   而 `pymupdf` 对 3D 饼图无法做角度定量反算（`charts.jsonl` 里这类图会标注 `uncalibrated`），
   因此图像证据的**可用性随文档而异**。
2. **表格跨页/断裂**：年报数值大量在表格里，pymupdf 的 `find_tables()` 在无框线表上会漏识；
   实测「招商银行 2019 年报」识别到 288 张表，而「中国平安 2019 年报」只有 22 张（大量退化表），
   这类差异会直接影响数值题的召回。
3. **生成层回退**：小模型 `qwen2.5:3b` 的候选答案若未包含草稿中的关键**原子**（数字/字符串），
   会被原子保全护栏拒绝并回退到规则拼接 —— 回退答案数字正确但可读性差（可能直接是表格片段）。
   本工单已修掉「假原子」导致的大面积误拒（候选被拒 10 题 → 0 题），并新增「候选数字是否都有证据出处」
   的第二放行路径，但**回退本身仍是设计上的保守行为**（宁可退回模板，也不放行可能编造的数字）。
4. **跨语料泄漏的残余场景**：问句不提公司名、或同时提多家公司时，语料路由**不冒险过滤**（返回 None，全语料检索），
   此时仍可能引到别家公司的块（如「对比平安银行与招商银行」这类跨文档题，实测 TC-Q09 引用落到中国平安 p41）。
5. **响应时间波动**：Ollama 在 CPU 上单实例串行推理，与其它任务共享 CPU 时跨轮波动明显；
   冷启动不预热时首问约 7.5 s（**必违约**），所以 `warmup(with_generate=True)` 是达标前提。
6. **PyPI 直连较慢**：`files.pythonhosted.org` 实测仅 2.06 MB/s，清华镜像直链 4.95 MB/s（快 2.4 倍），
   故补装依赖走镜像；大文件（如 700 MB 级权重）建议留足时间。
7. **`corpus_key` 兼容性**：既有语料（招股说明书1/2）的 chunk_id 口径**完全未变**；
   只有检测到跨文件名前缀冲突时才启用哈希前缀（本语料仅「招商证券/中国太保」两份受影响）。

## 八、常见问题

**Q：为什么评估用自研脚本而不是 RAGAS？**
A：本机无 `ragas`，且任务书明确「最低需求：自定义简单指标（如答案是否包含关键信息、检索片段是否命中）」。
自研判分把口径写在 `设计/评估指标定义.md` 里，可解释、可复现、不引入新依赖。

**Q：为什么判分用「关键词覆盖率」而不是语义相似度？**
A：年报问答的正确答案核心是**数值与专名**，语义相似度对「数字差一位」不敏感。
关键词覆盖率对数值严格，但会低估「意思对、措辞不同」的答案 ——
该失真风险已在 `设计/评估指标定义.md` 里显式说明，并同时报告**严格**与**宽松（含部分正确）**两档准确率。

**Q：为什么 `answer_keywords` 可以当「相关片段」的代理标注？**
A：无人工标注的语料上，这是唯一可自动化的口径；且本工单的 103 个关键词已用 pymupdf **逐页核对**
（通过率 100%），能确证「语料里确实存在」，因而适合做召回上限的判据（见 `关键词核对结果.json`）。

**Q：运行报 `IndexMissingError`？**
A：索引没建或不完整。先跑 §五 步骤 1，确认 `研发/data/index/index_manifest.json` 的 `chunk_total = 8847`（含图像块 105）。

**Q：能换回招股说明书语料吗？**
A：能。把 PDF 放回 `研发/data/raw/`，设好 `RAG_DATA__*` 后重建索引即可 ——
既有语料的 chunk_id 口径未变，工单4/5/6 的既有资产仍可复用。
