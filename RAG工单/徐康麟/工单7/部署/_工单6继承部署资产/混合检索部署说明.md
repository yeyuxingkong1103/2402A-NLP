## 四、检索策略怎么切换

三种模式：`vector`（向量检索）/ `fulltext`（全文检索）/ `hybrid`（混合检索，默认）。
预设共 5 个：`vector`、`fulltext`、`hybrid`、`hybrid_rrf`、`hybrid_voting`。

**四条可用途径**（按上手难度排序）：

| # | 途径 | 小节 | 适合 |
| --- | --- | --- | --- |
| 1 | Web 界面（下拉框 + 权重滑块） | §4.1 | 人工体验、录屏演示 |
| 2 | HTTP API `POST /api/chat` | §4.2 | 脚本化、接其它前端 |
| 3 | 命令行 `研发/app/main.py --strategy …` | §4.3 | 单次验证、批处理问句文件 |
| 4 | 直接调策略层 `search_by_strategy()` | §4.4 | 只跑检索不生成、自定义评测 |

### 4.1 界面操作（最直观）

1. 打开 <http://127.0.0.1:8123/>
2. 右侧「检索策略」面板 → **「模式」** 下拉框：向量检索 / 全文检索 / 混合检索
3. 混合模式下可继续调：
   * **「融合算法」**：加权平均 / RRF / 投票机制
   * **「权重」滑块**：拖「向量」一侧，全自动跟随（向量 + 全文 = 1.00）
4. 「嵌入模型」下拉框可切 `bge-m3` / `m3e-base`（见第五节）
5. 其余可调项：重排模型、Top-K、向量召回 K、全文召回 K、归一化分数阈值、
   向量相似度下限、全文检索字段（多选）、布尔运算符（OR/AND）、启用模糊匹配
6. 点 **「套用预设」** 按钮可一键回到所选模式的预设值

不点「发送」也会实时显示一行策略摘要，例如：

```
混合检索｜融合=weighted_average｜向量 0.50 / 全文 0.50｜bge-m3｜重排=rule
```

### 4.2 HTTP API（可脚本化）

`POST /api/chat` 请求体中的 `strategy` 对象即策略配置；**不传 `strategy` 就是工单4/5 的基线行为**。

**PowerShell 示例（直接整段复制执行）**

```powershell

$bytes = [System.Text.Encoding]::UTF8.GetBytes($json)
$r = Invoke-RestMethod -Uri 'http://127.0.0.1:8123/api/chat' -Method Post -ContentType 'application/json; charset=utf-8' -Body $bytes -TimeoutSec 120
$r.answer

# ② 全文检索

# ③ 混合检索（加权平均 0.5/0.5，默认预设）
```

> 转成字节后再传，PS 5.1 与 PS 7 都正确。

**curl.exe 示例**（Windows 10/11 自带 `C:\Windows\system32\curl.exe`，实测 8.10.1）

```powershell
cd E:\gao6gongdan\工单6

$json = '{"question":"报告期内，武汉兴图新科电子股份有限公司来自军用领域的收入分别是多少？","session_id":"curl-fulltext","strategy":{"mode":"fulltext","top_k":5}}'
$json | Out-File -FilePath "$env:TEMP\_q6.json" -Encoding utf8 -NoNewline
curl.exe -s -X POST "http://127.0.0.1:8123/api/chat" -H "Content-Type: application/json" --data-binary "@$env:TEMP\_q6.json"
Remove-Item "$env:TEMP\_q6.json"
```

> 这里用 `--data-binary "@文件"` 而不是 `-d "{...}"`：`-d` 传中文在 Windows 命令行下会乱码。

**策略对象全部可传字段**（含默认值）：

| 字段 | 默认 | 可选值 / 约束 |
| --- | --- | --- |
| `mode` | `hybrid` | `vector` / `fulltext` / `hybrid` |
| `embedding_model` | `bge-m3` | `bge-m3` / `m3e-base` / `bge-large` / `nomic-embed` / `all-minilm` |
| `vector_k` | `20` | ≥ 1 |
| `vector_min_similarity` | `0.0` | **必须在 [0,1]**（余弦相似度上限为 1） |
| `fulltext_k` | `20` | ≥ 1 |
| `fulltext_fields` | `["content"]` | 非空；元素 ∈ `content` / `title` / `keywords` / `summary` |
| `fulltext_op` | `OR` | 仅 `OR` / `AND`（大小写不敏感） |
| `enable_fuzzy` | `true` | `true` / `false`（查询串写 `词~` 才真正触发） |
| `fusion` | `weighted_average` | `weighted_average` / `rrf` / `voting` |
| `vector_weight` | `0.5` | ≥ 0，且不能与 `fulltext_weight` 同时为 0 |
| `fulltext_weight` | `0.5` | 同上 |
| `rrf_k` | `60` | 整数 |
| `rerank_model` | `rule` | `none` / `rule` / `tfidf` / `cross_encoder` |
| `top_k` | `5` | ≥ 1 |
| `score_threshold` | `0.0` | 必须在 [0,1] |
| `use_image_channel` | `true` | `true` / `false` |

参数不合法时接口**不静默改用默认策略**，而是直接 400：

```powershell
$json = '{"question":"测试","session_id":"bad","strategy":{"mode":"nope"}}'
$bytes = [System.Text.Encoding]::UTF8.GetBytes($json)
$r = Invoke-WebRequest -Uri 'http://127.0.0.1:8123/api/chat' -Method Post -ContentType 'application/json; charset=utf-8' -Body $bytes -SkipHttpErrorCheck
"HTTP $($r.StatusCode)"; $r.Content
```

> `-SkipHttpErrorCheck` 是 PowerShell 7 的参数（本机实测 PS 7.6.6）；
> 在 Windows PowerShell 5.1 下请改用 `curl.exe`（写法见下）或直接看服务窗口的日志。

实测输出：

```
HTTP 400
{"ok": false, "error": {"code": "E_PARAM_STRATEGY_INVALID", "message": "检索策略参数不合法：未知检索模式：'nope'（可选：vector, fulltext, hybrid）"}}
```

> 注意：`strategy` 是**放在请求体里**告诉服务用哪条链路的；
> 成功响应里那个同名的 `strategy` 顶层字段是**诊断字段**，取值可能是字符串 `"none"`，
> 不要拿它判断实际用了哪种模式——判断依据是你在请求里传了什么，以及回答里的引用块。

### 5.4 纪律：切换模型时索引必须匹配（不同模型的向量不可混用）

**索引目录名就是「模型身份」**：`{模型 id}_{维度}`，例如 `bge-m3_1024`、`m3e-base_768`。
策略层在 `bundle_for_model()` 里按「模型 → 索引目录」取向量索引：

* slug 与当前 bundle 一致 → 直接复用（零开销）；
* 否则加载 `{index_dir}/{slug}/` 的向量索引；
* **该模型的索引不存在 → 抛 `IndexMissingError`，绝不跨模型混用**
  （不会拿 bge-m3 的索引去跑 m3e 的查询向量）。

实测（对未建索引的 `bge-large` 提问）：

```
HTTP 503
{"ok": false, "error": {"code": "E_INDEX_MISSING", "message": "多轮问答失败：IndexMissingError: [RAG-3100/index] 嵌入模型 bge-large（bge-large:latest）的向量索引不存在：E:\gao6gongdan\工单6\研发\data\index\bge-large_1024"}}
```

**维度不同，向量绝不可混用**：1024 维的 bge-m3 向量与 768 维的 m3e 向量维度都对不上，
FAISS 索引本身就无法互查；即使维度凑巧相同，不同模型的语义空间也不同，相似度不可比。

## 七、常见问题排查

### 7.1 端口被占用：`OSError: [WinError 10048] 通常每个套接字地址只允许使用一次`

**症状**：启动 `web_app.py` 时抛 `WinError 10048`，服务起不来。

**原因**：8123 已被别的进程（上一次没关掉的服务、或其它程序）占用。

**解决**：先查出占用者，再换端口或结束进程。

```powershell
# 查占用 8123 的进程
Get-NetTCPConnection -LocalPort 8123 -State Listen -ErrorAction SilentlyContinue |
    Select-Object LocalAddress, LocalPort, OwningProcess
Get-Process -Id (Get-NetTCPConnection -LocalPort 8123 -State Listen).OwningProcess

# 方案 A：换一个空闲端口启动
pwsh -NoProfile -File run_py.ps1 部署/界面/web_app.py --host 127.0.0.1 --port 8124

# 方案 B：确认是自己上次开的服务后，结束它
Stop-Process -Id (Get-NetTCPConnection -LocalPort 8123 -State Listen).OwningProcess -Force
```

### 7.2 Ollama 未启动

**症状**：`/health` 里 `engine.checks.llm.ok = false`，或提问时嵌入/生成报连接被拒；
命令行可能报 `URLError: [WinError 10061] 由于目标计算机积极拒绝`。

**原因**：本地 Ollama 服务没起来（或不在 11434 端口）。

**解决**：

```powershell
# 先探测
Invoke-RestMethod -Uri 'http://127.0.0.1:11434/api/tags' -TimeoutSec 10 | Select-Object -ExpandProperty models | Select-Object name

# 启动 Ollama（Ollama Desktop 安装后自带 CLI）
ollama list
ollama serve

# 确认嵌入与生成模型都在
ollama list | Select-String 'bge-m3|m3e-base|qwen2.5:3b'
```

Ollama 恢复后重启 Web 服务（引擎是进程内单例，不会自动重连）。

### 7.3 索引缺失：`E_INDEX_MISSING`

**症状**：`POST /api/chat` 返回 503，`code = "E_INDEX_MISSING"`，
消息形如「嵌入模型 xxx 的向量索引不存在：…\研发\data\index\xxx_维度」。

**原因**：在界面上切了一个**还没建索引**的嵌入模型（如 `bge-large` / `nomic-embed` / `all-minilm`）。
策略层按纪律**拒绝跨模型混用**，所以直接报错而不是拿别的索引硬跑。

**解决**：要么切回已建索引的模型，要么先建索引。

```powershell
pwsh -NoProfile -File run_py.ps1 研发/scripts/build_index_multi.py --list
pwsh -NoProfile -File run_py.ps1 研发/scripts/build_index_multi.py --model bge-large
pwsh -NoProfile -File run_py.ps1 研发/scripts/build_index_multi.py --model bge-large --verify-only
```

### 7.4 检索策略参数不合法（HTTP 400 `E_PARAM_STRATEGY_INVALID`）

**症状**：`POST /api/chat` 返回 400，`error.code = "E_PARAM_STRATEGY_INVALID"`。

**原因**：`strategy` 里有非法值。接口的设计纪律是**不静默改用默认策略**，直接报错。
实测会触发的例子：

| 传值 | 实测报错消息 |
| --- | --- |
| `"mode": "nope"` | 未知检索模式：'nope'（可选：vector, fulltext, hybrid） |
| `"vector_min_similarity": 1.5` | vector_min_similarity 必须落在 [0,1]（余弦相似度上限为 1；当前 1.5） |

**解决**：按报错消息改正；或用 `GET /api/strategies` 取 `defaults` / `presets` 作为模板。

```powershell
# 取默认配置与 5 个预设，直接抄字段名与合法值
$s = Invoke-RestMethod -Uri 'http://127.0.0.1:8123/api/strategies' -TimeoutSec 20
$s.defaults | ConvertTo-Json -Depth 3
$s.presets.PSObject.Properties.Name
```

### 7.5 界面能打开，但 `/health` 返回 503

**症状**：浏览器里 <http://127.0.0.1:8123/> 正常显示，但 `/health` 是 503 且
`status = "degraded"`；提问返回 503 + 中文指引。

**原因**：这是**设计行为**——服务照常启动，引擎不可用时如实降级，绝不返回假答案。
常见根因：Ollama 没起来、索引目录缺失、端口占用导致预热失败。
启动窗口里会打印一行 `[警告] 引擎未就绪：…` 与具体原因。

**解决**：看启动窗口的警告原因，再按下面顺序定位。

```powershell

$r = Invoke-WebRequest -Uri 'http://127.0.0.1:8123/health' -SkipHttpErrorCheck
"HTTP $($r.StatusCode)"
$r.Content

# 逐项体检
Test-Path 'E:\gao6gongdan\工单6\研发\data\index\bge-m3_1024\vectors.npy'
Invoke-RestMethod -Uri 'http://127.0.0.1:11434/api/tags' -TimeoutSec 10 | Select-Object -ExpandProperty models | Measure-Object
```

修好后重启服务（引擎是进程内单例，不会热重连）。

### 7.6 `.pytest_cache` 权限错误

**症状**：跑 `pytest` 时出现 `PermissionError: [WinError 5] 拒绝访问`，
路径指向 `研发/tests/.pytest_cache` 或仓库根 `.pytest_cache`。

**原因**：上一次 pytest 进程残留 / 缓存目录被占用或只读。

**解决**：

### 7.7 中文乱码

**症状**：控制台里中文输出成 `δ��װ` 一类乱码，或 HTTP 返回的中文变成问号。

**原因**：控制台编码不是 UTF-8，或 HTTP 请求体没按 UTF-8 编码。

**解决**：

```powershell
# ① 让 run_py.ps1 统一设置 UTF-8（它内部已设 PYTHONUTF8/PYTHONIOENCODING）
pwsh -NoProfile -File run_py.ps1 -c "print('中文测试：混合检索')"

# ② 控制台切 UTF-8
chcp 65001
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8

# ③ HTTP 请求体必须转成 UTF-8 字节再传（不要直接 -Body '中文 JSON'）
$json = '{"question":"武汉力源信息技术股份有限公司本次发行股数是多少？","session_id":"enc"}'
$bytes = [System.Text.Encoding]::UTF8.GetBytes($json)
Invoke-RestMethod -Uri 'http://127.0.0.1:8123/api/chat' -Method Post -ContentType 'application/json; charset=utf-8' -Body $bytes -TimeoutSec 120
```

### 7.8 第一次点「全文检索」特别慢（约 4 秒）

**症状**：全文通道第一次查询耗时约 4100 ms，之后同进程内降到约 6~14 ms。

**原因**：多字段倒排索引的**首次构建**（实测 4158.09 ms，2676 块）。
服务正常启动时会预热，所以走界面/接口不会遇到；
只有像第 4.3 节那样直接调 `search_by_strategy` 的独立脚本才会碰上。

**解决**：脚本里先调一次预热，或直接接受首次开销。

```powershell
pwsh -NoProfile -Command @'

$env:PYTHONPATH = 'E:\gao6gongdan\工单6\研发'
$env:PYTHONUTF8 = '1'
```

`{'chunks': 2676, 'fields': {'content': 23607, 'title': 970, 'keywords': 14471, 'summary': 17366}, 'ms': 4200.81}`

（两次实跑里倒排索引构建分别为 4241.01 ms 与 4200.81 ms；不取 `['fulltext_index']`
时还会返回 `models` / `models_ms` / `elapsed_ms`，实测 `elapsed_ms: 6121.05`。）

### 7.9 报告页 404 / 403
