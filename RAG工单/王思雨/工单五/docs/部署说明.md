## 3. 启动 Redis

本机为 **Windows 原生 Redis 5.0.14**（服务名 `Redis`），通常开机自启。验证：

```bash
redis-cli ping        # 期望 PONG
```

若未启动：

```bash
cmd //c "net start Redis"          # 需要管理员权限
# 或用可执行文件： "C:/Program Files/Redis/redis-server.exe" "C:/Program Files/Redis/redis.windows-service.conf"
```

> **⚠️ 必须知道的坑**：本机 Redis 是 5.0.14，**不支持 RESP3（`HELLO` 命令）**。
> `redis-py 8.x` 默认会发 `HELLO 3`，直连会报 `unknown command 'HELLO'`。
> 本项目已在 `.env` 固定 `REDIS_PROTOCOL=2`（客户端会退回 RESP2），**不要删掉这一项**。

## 6. 入库（构建知识库）

确认两份招股说明书已在 `data/raw/`（工单验收使用预置的这两份）：

```bash
ls data/raw/
# 招股说明书1.pdf   （武汉兴图新科电子股份有限公司，548 页）
# 招股说明书2.pdf   （武汉力源信息技术股份有限公司，350 页）

python scripts/ingest.py
```

流程与耗时（本机实测）：

| 阶段 | 耗时 | 说明 |
| --- | --- | --- |
| 解析两份 PDF | ~0s | 命中 MinerU 缓存 `data/parsed/`；无缓存时会实跑 MinerU（548 页约数分钟） |
| 图像内容提取 | ~150s | 77 张图；其中组织结构图/流程图做层级还原。结果缓存到 `data/image_texts.json`，**重建时自动复用** |
| 语义分块 | ~20s | chunk_size=512 / overlap=80，产出约 4000 个分块 |
| 写入 Milvus | ~85s | 3989 条向量 |
| 建 BM25 索引 | ~3s | 落盘 `data/bm25.pkl` |
| **合计** | **~145s** | |

> **⚠️ 入库期间不要并行跑别的吃显存的任务**（例如同时开着后端服务再跑评测）。
> 实测教训：两个进程同时占 8G 显存时，入库从 **86 秒** 拖到 **13 分钟以上**，且 GPU 显示 100% 占用看不出问题。
> 结论：**重任务必须串行**。

只想快速重建纯文本索引（跳过图像）：`python scripts/ingest.py --no-images`

## 9. 验收：跑工单五的 5 个多轮问题

在**同一个会话**内按顺序提问（Q2/Q3 依赖 Q1 引入的实体，Q4 是实体切换）：

```bash
python - <<'PY'
import json, urllib.request
SID = "acceptance"
QS = [
 "报告期内，武汉兴图新科电子股份有限公司来自军用领域的收入分别是多少？",
 "他参与的哪个工程荣获了国家科技进步一等奖？",
 "这个公司的法定代表人是谁？",
 "那武汉力源信息技术股份有限公司呢？",
 "武汉力源信息技术股份有限公司组织结构图中，哪个销售部的销售处最多？有哪些销售处？",
]
for q in QS:
    req = urllib.request.Request("http://127.0.0.1:8000/chat",
        data=json.dumps({"session_id": SID, "question": q}).encode(),
        headers={"Content-Type": "application/json"})
    r = json.loads(urllib.request.urlopen(req).read())
    print("Q:", q); print("  改写:", r["rewritten_query"]); print("  A:", r["answer"])
    print("  引用:", [(x["doc"], x["page"]) for x in r["references"]][:3], "耗时", r["latency_ms"], "ms")
PY
```

> Git Bash 下 `curl` 传中文会乱码，且会**伪装成检索失败**（返回"未找到"）。故上面统一用 Python 的 `urllib`。

英文提问同样支持：

```
What are the military-related revenues of Wuhan Xingtu Xinke Electronics Co., Ltd. during the reporting period?
Who is the legal representative of this company?
What about Wuhan P&S Information Technology Co., Ltd.?
```

## 11. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `unknown command 'HELLO'` | Redis 5 不支持 RESP3 | 确认 `.env` 的 `REDIS_PROTOCOL=2` |
| `OSError: [WinError 127] ... torch\lib\shm.dll` | 先 import paddleocr 再 import torch | 本项目已固定"先 torch 后 paddle"（`backend/ocr_image.py`），勿调导入顺序 |
| MinerU 报 fasttext 打不开模型 | 中文用户名 | 配好 `MINERU_LANGFIX_DIR` |
| PaddleOCR 报 `Cannot open file ... pdmodel` | 中文用户名 | 把模型复制到 `C:/paddleocr_models/` |
| Milvus 连不上 | 容器没起 | `docker start rag-etcd rag-minio rag-milvus` |
| 刚入库却检索不到 | Milvus 默认 `Bounded` 一致性 | 本项目检索固定用 `Strong`，改造时勿删 |
| 大模型返回空内容 | 推理型模型未关思考 | 配 `LLM_REASONING_EFFORT=none`；对 `flash`/`reason` 模型名已自动处理 |
| 第一条问题特别慢 | 未预热 | 保持 `WARMUP_ON_START=1` |
| 评测指标全是 `null` | 余额不足（402）或判官参数错误 | 先看 `results/` 里已落盘的问答结果，再查日志 |
| 入库/评测异常慢 | 有别的进程在占显存 | 确认只有一个重任务在跑 |
