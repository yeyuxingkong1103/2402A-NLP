> 相关实现：`src/multi_turn_chat.py`（执行与记录）、`src/ablation_multiturn.py`（开/关对比）、`src/wo05_common.py`（判定标准）

## 一、对话主体状态机（整体设计）

多轮对话的本质是维护一个「**当前主体（公司）+ 当前问点（属性）**」的状态，每轮根据问题决定：继承、替换，还是两者都变。

```
轮次   用户问题（原文）                       主体              问点                动作
──────────────────────────────────────────────────────────────────────────────────────────
 1     报告期内，武汉兴图新科…收入分别是多少？  兴图新科(显式)     军用领域收入         建立主体
 2     他参与的哪个工程荣获国家科技进步一等奖？ 兴图新科(指代)     获奖工程             继承主体，换问点
 3     这个公司的法定代表人是谁？               兴图新科(指代)     法定代表人           继承主体，换问点
 4     那武汉力源信息技术股份有限公司呢？       力源信息(显式)     法定代表人(省略)     替换主体，继承问点
 5     武汉力源…组织结构图中，哪个销售部的…？   力源信息(显式)     组织结构/销售处      继承主体，换问点
──────────────────────────────────────────────────────────────────────────────────────────
        第 1~3 轮 → 《招股说明书1》              第 4~5 轮 → 《招股说明书2》（跨文档）
```

**四种能力与轮次对应**：

| 轮次 | Query 理解能力 | 触发机制（代码事实） |
|------|----------------|----------------------|
| 1 | 无（基准轮） | `has_anaphora=False`，零改写；长度 34 ≥ 25 → 走问题分解 |
| 2 | **指代消解**（人称代词） | `has_anaphora=True`（命中「他」）→ 规则不匹配 → LLM 慢通道 |
| 3 | **指代消解 + 话题继承** | `has_anaphora=True`（命中「这个公司」）→ LLM 慢通道 |
| 4 | **省略句补全 + 主体切换** | `has_anaphora=True`（「那…呢」句式）→ **规则快速通道直接命中** |
| 5 | **主体延续 + 跨文档检索** | `has_anaphora=False`（自包含问题）→ 零改写；长度 40 ≥ 25 → 走问题分解 |

> 说明：第 1、5 轮不含指代词，天然不需要消解——**消解的成本只花在真正需要的轮次上**，这是 3 秒约束下的重要设计前提。

## 三、逐轮剖析

### 第 1 轮：建立对话主体

- **问题**：报告期内，武汉兴图新科电子股份有限公司来自军用领域的收入分别是多少？
- **考察能力**：自包含问题的基准轮（对照组），检验检索与生成的基本功。
- **系统如何识别**：
  - `has_anaphora=False`（无指代词、无「那…呢」句式）→ **不做指代消解，零开销**；
  - 意图识别：规则表命中「分别是 / 是多少」→ **数值查询**；
  - 实体抽取：得到 `武汉兴图新科电子股份有限公司`；
  - 长度 34 ≥ 25 → 触发问题分解（LLM 通道，最多 4 个子问题），若拆出多个子问题则多路检索后合并。
- **检索式如何改写**：**不改写**（检索式 = 原问题）。
- **为什么这样改写**：问题已自包含，任何改写都有引入偏差的风险；改写器的原则是「无事则不改」。
- **检索要点**：应命中《招股说明书1》中「军用领域收入」相关段落/表格；答案需覆盖报告期各期数据（判定口径要求 ≥ 2 个年份），防止只答一年。

### 第 2 轮：人称代词「他」→ 上一轮主体

- **问题**：他参与的哪个工程荣获了国家科技进步一等奖？
- **考察能力**：**指代消解**（跨句消解到上一轮主体）。
- **系统如何识别**：
  - `has_anaphora=True`：命中指代词表「他」；
  - 规则快速通道：句式不是「那 X 呢？」，**不匹配** → 转 LLM 慢通道；
  - LLM 拿到近 4 轮历史（Q/A 截断），把「他」替换为历史中的公司全称。
- **检索式如何改写**：`他参与的哪个工程荣获了国家科技进步一等奖？`
  → `武汉兴图新科电子股份有限公司参与的哪个工程荣获了国家科技进步一等奖？`
- **为什么这样改写**：原问题的信息缺口只在主语。补上公司全称后，检索式从「无主语句子」变成「可锚定的实体 + 事件」；否则「他」会作为噪声词进入 BM25，向量侧也完全无法定位公司。
- **消融证据**：关闭 Query 理解时，该轮 `extract_entities` 返回 **0 个实体**——检索式里没有任何公司名，属于「检索失败」的典型场景。
- **检索要点**：命中《招股说明书1》「国家科技进步一等奖」相关段落。

### 第 3 轮：指示代词「这个公司」+ 话题继承

- **问题**：这个公司的法定代表人是谁？
- **考察能力**：**指代消解 + 话题继承**——主体仍是兴图新科，问点切换为「法定代表人」。
- **系统如何识别**：
  - `has_anaphora=True`：命中指代词表「这个公司」；
  - 规则通道不匹配（非「那 X 呢」句式）→ LLM 慢通道；
  - 改写后重新做意图识别：命中「法定代表人 / 是谁」→ **实体属性**。
- **检索式如何改写**：`这个公司的法定代表人是谁？`
  → `武汉兴图新科电子股份有限公司的法定代表人是谁？`
- **为什么这样改写**：注意一个细节——天真的实体抽取会把「**这个公司**」本身当成实体（正则匹配到「…公司」后缀），若不消解就检索，会浪费召回机会。改写后实体变成真实公司全称，问点「法定代表人」也完整保留（**话题继承而非话题覆盖**）。
- **检索要点**：命中《招股说明书1》「法定代表人」字段所在页（发行人的基本信息章节）。

### 第 4 轮：省略句补全 + 主体切换（最难一轮）

- **问题**：那武汉力源信息技术股份有限公司呢？
- **考察能力**：**省略句补全 + 主体切换**——两个变化同时发生：
  1. 主体从兴图新科切到力源信息（跨文档！）；
  2. 谓语被省略（「呢？」），必须从上一轮问题（「…的法定代表人是谁？」）继承问点。
- **系统如何识别**：
  - `has_anaphora=True`：命中省略句式前缀「那」；
  - **规则快速通道命中**：`re.match(r"^(?:那|那么|然后|还有)\s*(.+?)(?:呢|呢？|\?|？)?$")` 抽出新实体，再从上一轮问题中把旧实体替换为 `{ENTITY}` 占位符得到模板，最后用新实体填充。
- **检索式如何改写**：

  ```
  上一轮问题（第 3 轮）：这个公司的法定代表人是谁？
  抽旧实体             ：这个公司
  模板化               ：{ENTITY}的法定代表人是谁？
  填新实体             ：武汉力源信息技术股份有限公司的法定代表人是谁？
  ```

- **为什么这样改写**：
  - 若只把「那 X 呢」换成「X」，检索式是「武汉力源信息技术股份有限公司」——没有问点，检索结果会是一堆公司概况，答非所问；
  - 若沿用上一轮完整问题（「兴图新科的法定代表人是谁？」）→ 主体错误，跨文档跑偏到《招股说明书1》；
  - 正确做法是**「主体换新、谓词沿用」**，得到自包含问题。规则模板替换精确地实现了这一点，且**不调用 LLM**（断言验证 LLM 调用增量 = 0），延迟从秒级降到微秒级。
- **检索要点**：检索式含「武汉力源信息技术股份有限公司」→ 命中《招股说明书2》（**跨文档检索**），并覆盖「法定代表人」。
- **消融证据**：关闭 Query 理解时检索式仍是「那武汉力源信息技术股份有限公司呢？」，实体虽在，但问点缺失，无法保证检索到「法定代表人」相关内容。

### 第 5 轮：主体延续 + 跨文档检索（组织结构图）

- **问题**：武汉力源信息技术股份有限公司组织结构图中，哪个销售部的销售处最多？有哪些销售处？
- **考察能力**：**主体延续 + 跨文档检索**，且问题是**图表类**——需要工单04 的图像语义块（组织结构图）参与检索。
- **系统如何识别**：
  - `has_anaphora=False`：自包含问题，**不做指代消解**（零改写、零 LLM 成本）；
  - 意图识别：命中「有哪些」→ **列表查询**；
  - 长度 40 ≥ 25 → 触发问题分解（LLM 通道），可能拆成「哪个销售部的销售处最多？」与「有哪些销售处？」两个子问题 → 多路检索后合并（保证「最多」与「清单」两部分信息都召回）。
- **检索式如何改写**：**不改写**。
- **为什么这样改写**：问题已经完整（主体 + 属性 + 范围都在），改写只会增加风险。本轮的关键不在改写，而在**跨文档 + 跨模态**：知识库必须同时索引《招股说明书1》与《招股说明书2》，且图像块（组织结构图）的语义描述要入库，否则问题无解。
- **检索要点**：命中《招股说明书2》组织结构图对应的 **image 类型块**（内容为多模态模型生成的结构描述），答案需给出销售处最多的销售部及其销售处清单。

## 四、跨文档设计说明

| 设计点 | 做法 | 原因 |
|--------|------|------|
| 文档命名 | `招股说明书1` / `招股说明书2` 作为 `doc` 元数据 | 引用来源可读，前端直接展示《文档》页码 |
| 索引范围 | `build_index.py` 一次索引两份 PDF 到同一 collection | 第 4/5 轮需要跨文档检索；分库会让实体切换后检索不到 |
| 主体切换的落地 | 检索式中显式包含公司全称（由消解产生） | 向量/BM25 都以「公司全称」为最强锚点，天然完成文档路由 |
| 串味防护 | 答案生成要求先定位再作答、标注页码；评测统计片段文档分布 | 便于发现「问力源却召回兴图」的问题（`results/multiturn_ablation.md` 的「片段来源分布」列） |
| 评估 | 每轮指定 `expected_doc`（`wo05_common.TURN_SPECS`） | 把「跨文档是否正确」变成可自动判定的指标 |

## 五、一句话总结每轮的设计取舍

1. **第 1 轮**：不改写——自包含问题不动它；
2. **第 2 轮**：LLM 改写——人称代词无法穷举，用模型换准确率；
3. **第 3 轮**：LLM 改写——代词「这个公司」需消解，且要保住「法定代表人」这个新问点；
4. **第 4 轮**：规则改写——最难的省略句恰好落在最高频的句式上，用模板替换换延迟与成本；
5. **第 5 轮**：不改写——把成本花在跨文档与图像块的召回上。
