# 演示样本（录屏用）

工单18 演示视频用的一小撮文件。**不是真实语料，是特意挑的。**

## 为什么要单独挑一份

主验证语料是 IMDR 那 1700 份专利。它有两个问题，放视频里演示不方便：

| 问题 | 说明 |
|---|---|
| **敏感信息跑出来是 0 条** | 专利是公开文献，著录项里只有公司名和发明人，没有手机号/邮箱/身份证 |
| **跑一次要 1 分钟** | 录屏时干等一分钟很难看 |

所以挑 6 个文件凑成一份，**一次运行就能同时产出三类列表**，而且一两秒跑完。

## 每个文件演示什么

| 文件 | 大小 | 用来演示 | 依据 |
|---|---|---|---|
| `CN100408987C.pdf` | 0.45MB | **扫描型** → 路由 `ocr` | 高清扫描件（4376×6665 位图），**一个字符都抽不出来** |
| `CN2926129Y.pdf` | 0.44MB | **扫描型** → 路由 `ocr` | 拍下来的专利首页，无文字层 |
| `CN106926565B.pdf` | 0.75MB | 对照：**文字型** → 路由 `text` | 数字排版 + 一张带标注的附图（附图页会被误判成扫描页，见优化说明问题 1） |
| `CN110775870A.pdf` | 0.38MB | **版本冲突**（一对） | 发明专利，苏州千律工业设备，2019.11.08 |
| `CN211226175U.pdf` | 0.38MB | **版本冲突**（一对） | 同申请人、同申请日的实用新型 —— 中国特有的「双申请」 |
| `平安银行2019年年度报告.txt` | 0.86MB | **敏感信息** | 年报里的投资者关系邮箱 `PAB_db@pingan.com.cn` |

`CN100408987C` 和 `CN106926565B` 这两个值得在视频里对比着讲：
前者渲染出来**比电子版还干净**，却一个字符都抽不出来；
后者有清晰的文字层。**「扫描型」的含义是「没有文字层、必须 OCR」，不是「画质差」。**

## 跑出来应该是什么样

```bash
cd 研发/document_quality_assessment
D:/Anaconda/envs/rag_gd/python.exe scripts/assess.py ../../测试/演示样本 -o ../../测试/results/demo
```

```
文件总数 6 份，3MB，解析失败 0 份
格式分布  .pdf 5   .txt 1
PDF 分流  scanned 2   text 3   （扫描型占 40%）
待确认版本冲突  1 对（另有 2 份正文过短未参与比较）
敏感信息命中  3 条
主路由    text ← 3 份   ocr ← 2 份   chunk_aggressive ← 1 份
```

三路主路由（`text` / `ocr` / `chunk_aggressive`）正好演示工作流的 Switch 分流。

## 注意

- **「扫描型占 40%」是挑出来的，不是语料的真实比例。**
  真实语料 IMDR 1700 份是 **36.6%**，见 `测试/验证报告.md` 第二节。
  被问到要如实说，别拿这个数当语料特征。
- 文件都是**从原语料复制的副本**，改坏了不影响原数据。
  重新生成：从 `D:\BW\RAG 工单\14-17附件\original_problems\documents\` 复制那 5 个 PDF，
  从 `D:\BW\RAG 工单\附件\ccf_competition\txt\` 复制平安年报
  （原名是乱码 `2020-02-14__...`，这里改成了可读名）。
- 端点要质检它们，得先把整个目录 `docker cp` 进容器（端点在容器内执行），
  见 `录屏说明/工单18-录屏说明.md` 第二节。
