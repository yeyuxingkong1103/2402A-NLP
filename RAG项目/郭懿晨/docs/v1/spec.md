# RAG PDF 问答系统 v1 MVP 设计

## 目标

第一版目标是做一个本地可运行的 RAG 问答系统，用于读取混合型 PDF，并提供高质量、可溯源的检索问答能力。

核心优先级为：

1. 准确优先
2. 答案可追溯到 PDF 页码
3. 本地快速交付 MVP 基线版
4. 前端可展示真实构建流程

## 范围

### 包含

- PDF 上传/导入
- 真实构建流水线：清洗 → 分块 → 向量化 → 入库
- 向量库查看
- 检索问答
- 前端展示任务进度条和当前步骤
- 答案返回引用来源与页码
- 默认全库检索，不做类别过滤

### 不包含

- 多用户权限系统
- 云端部署
- reranker 精排
- 复杂评测平台
- 类别过滤检索

## 架构

系统分为离线构建链路和在线问答链路两部分。

### 离线构建链路

- PDF 文件放入系统后，创建构建任务
- 后端异步执行 MinerU 解析、清洗、分块、向量化和入库
- 分块阶段保留 MinerU 标签作为类别字段
- 处理结果写入本地 Qdrant

### 在线问答链路

- 前端提交问题
- 后端执行 dense + sparse 检索，并使用 RRF 融合排序
- 将 Top-K 证据片段送入 Ollama 生成答案
- 答案必须返回引用来源、页码和片段
- 无依据时返回兜底信息，不编造答案

## 模块设计

### 1. PDF 上传/导入

职责：接收用户上传的 PDF，保存到本地目录，并创建构建任务。

接口预留：

- `POST /api/files/upload`

### 2. 构建任务

职责：记录和驱动真实流程状态。

流程：

- 清洗
- 分块
- 向量化
- 入库

状态建议：

- `pending`
- `running`
- `completed`
- `failed`

接口预留：

- `POST /api/tasks/{task_id}/start`
- `GET /api/tasks/{task_id}`

### 3. 向量库查看

职责：展示已经入库的数据、文档和类别。

类别来源：

- 直接继承 MinerU 分块阶段生成的标签

接口预留：

- `GET /api/documents`
- `GET /api/vector-store`
- `GET /api/categories`

### 4. 检索问答

职责：对用户提问进行检索、拼装上下文并生成答案。

默认行为：

- 全库检索
- 不按类别过滤
- 返回答案与引用来源

接口预留：

- `POST /api/chat`

## 数据流

### 入库流

1. 用户上传 PDF
2. 系统保存 PDF 到本地
3. 创建构建任务
4. MinerU 解析 PDF
5. 执行清洗
6. 执行分块
7. 生成 dense 与 sparse 表示
8. 写入本地 Qdrant
9. 更新任务为完成

### 问答流

1. 用户输入问题
2. 后端生成查询向量
3. Qdrant 执行检索
4. RRF 融合排序
5. 选取 Top-K 证据片段
6. 构造带引用约束的 prompt
7. Ollama 生成答案
8. 返回答案与引用

## 错误处理

- 上传失败：返回文件错误原因
- 解析失败：任务标记失败，并记录失败步骤
- 缺少页码：chunk 不允许入库
- 向量库不可用：构建流程失败并提示修复配置
- 模型不可用：问答接口返回服务不可用
- 检索为空：返回“知识库中未找到相关依据”

## 测试与验收

### 验收标准

- PDF 上传后可以启动构建任务
- 构建流程能跑通清洗 → 分块 → 向量化 → 入库
- 分块结果保留页码和 MinerU 标签
- 向量库能展示已入库文档及类别
- 问答返回答案 + 引用来源
- 无依据时能正确兜底
- 前端能展示构建进度条和当前步骤

### 测试策略

- 单元测试：任务状态流转、元数据完整性、检索兜底
- 集成测试：PDF 上传 → 构建 → 入库 → 问答完整链路
- 回归测试：至少使用一份真实 PDF 样本

## 未来优化方向

- 引入 reranker 提升检索质量
- 增加更细的任务日志和重试能力
- 增加类别过滤检索
- 扩展评测集与指标对比
