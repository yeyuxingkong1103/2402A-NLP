## 2 五阶段 + 子阶段埋点

```
① 查询处理与增强
     └ 查询改写 / 实体标注 / 关键词抽取
② 检索
     └ 查询嵌入 / 向量检索 / BM25 检索 / RRF 融合+重排 / 证据页补全
③ 上下文组装与提示工程
     └ 上下文拼接 / 提示词构造 / 长度截断
④ LLM 生成
     └ 生成后端调用（含首字延迟）
⑤ 后处理与响应格式化
     └ 引用标注 / 护栏复核 / 响应组装
```

每个阶段记 `enter/exit` 单调时间戳，落 `优化/评估结果/*.jsonl`（逐题）与 `*_汇总.json`（统计）。

## 3 优化点清单（对应 `部署/配置/优化开关.json`）

| 开关 | 默认 | 作用 | 依据 |
| --- | --- | --- | --- |
| `warmup_enabled` | true | 启动时预热索引/分词/嵌入/生成，避免首题抖动 | 预热实测见汇总「预热」段 |
| `embed_backend_cache` + `embed_probe_ttl_s` | true / 300s | 嵌入后端探测结论缓存，基线每次调用都 HTTP 探测 `/api/tags` | 探测 TTL 标定 |
| `parallel_channels` + `parallel_workers` | true / 2 | 检索通道路径并行（**上限 2，遵守资源纪律**） | 并发压测 |
| `rerank_prune` + `rerank_budget` | true / 40 | RRF 融合后送特征重排的候选上限，基线 60 | 实测 40 与 60 的 Top-5 一致 |
| `cache_enabled` | true | 答案/检索/生成三级缓存 | 生产链路有效；**对比实验关掉读取** |
| `context_io_cache` | true | 上下文读盘缓存 | — |
| `adaptive_top_k` | true | 按 `answer_shape` 收敛检索广度（枚举/对比 multi=5，单值/是否 single=3） | 不牺牲召回的多点题保持 5 |
| `async_log` + `async_log_queue` | true / 4096 | 日志异步化，避免写盘阻塞主链路 | — |
| `generate_budget` | true / 512 | 生成 token 上限与上下文字符预算 | **不无证据压缩**（保持 512，避免护栏失败） |
| `ollama_timeout_s` | 20.0 | 生成后端超时 | — |

> **红线**：任何优化必须能通过 `--perf-profile baseline` 一键回退；且必须成对给出「优化前后」同口径数据。

## 4 预期与实测的差距（如实记录）

本机为 **CPU 推理**（无 GPU 可用给生成模型；RTX 2060 6GB 空闲但未接 vLLM），
生成阶段（④）是端到端耗时的主要构成，因此 3S 验收线在 CPU 环境下**难以达成**。
处理方式：**如实标注「未达标 + 根因」**，并给出在同等硬件下的实际分位数与改善幅度；
不通过缩减生成质量（如强行砍 `max_tokens`）来伪造达标。

## 5 一键复现命令

```powershell
# 优化前（基线）
pwsh -NoProfile -File run_py.ps1 研发/scripts/分段计时剖析.py --profile baseline --out 优化/评估结果/优化前.jsonl --summary 优化/评估结果/优化前_汇总.json

# 优化后
pwsh -NoProfile -File run_py.ps1 研发/scripts/分段计时剖析.py --profile optimized --out 优化/评估结果/优化后.jsonl --summary 优化/评估结果/优化后_汇总.json
```

> 误认成自身参数（与 `-OutVariable`、`-Summary` 歧义）并直接报错，**参数传递会静默失败**。
> 稳妥做法是直接用解释器调用：
> ```powershell
> $py='E:\gao6gongdan\工单1\.venv\Scripts\python.exe'

> ```
