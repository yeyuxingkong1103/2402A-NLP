# 部署文档（工单10 · 金融问答系统）—— 给新人的完整操作手册

> 工单编号：人工智能NLP-RAG 项目-金融问答系统部署
> 目标读者：第一次接触本项目、需要把服务跑起来并**自己验证四项验收**的同学。
> 每一步都给出**命令**、**预期输出**、**不达标时先看哪里**。

## 1. 你要部署的是什么

工单7 已完成的金融问答 RAG 系统（解析 A 股年报 → 分块 → bge-m3 嵌入 → FAISS + BM25 → RRF 融合 → 重排 → 生成/抽取合成 → 拒答护栏），
本工单把它**容器化**，交付两个对外入口：

| 入口 | 端口 | 形态 |
| --- | --- | --- |
| `rag-api` | **8200** | FastAPI：`POST /api/v1/ask`、`GET /health`、`GET /metrics` |
| `rag-ui` | **8201** | 工单7 的中文 Web 问答界面 |

外加 `redis`（会话跨容器共享）与可选 `prometheus`（指标）。

## 3. 实现步骤（从零到跑通，逐步可验证）

### 步骤 1：准备环境文件

```powershell
Copy-Item 部署\配置\.env.example 部署\配置\.env
notepad 部署\配置\.env      # 至少确认 HOST_INDEX_DIR 与 REDIS_PASSWORD
```
**预期**：文件存在且 `HOST_INDEX_DIR=../../工单7索引`（相对路径基准是 `部署/docker/`，见过程问题记录 问题6）。

### 步骤 2：校验编排配置（**不需要 Docker daemon**）

```powershell
docker compose --env-file 部署/配置/.env.example -f 部署/docker/docker-compose.yml --profile monitoring config --format json >
    部署\日志\compose配置校验-json.log
```
**预期**：退出码 0，JSON 里能看到
`services.rag-api.ports[0].published = "8200"`、`services.rag-ui.ports[0].published = "8201"`、
`build.context = E:\gao6gongdan\工单10`、`volumes` 里同时有 `type: volume` 与 `type: bind`。
**失败**：先把这一步弄绿再往下走 —— 配置错的话后面所有报错都是它的次生现象。

### 步骤 3：构建镜像

```powershell
pwsh -NoProfile -File 部署\脚本\build.ps1 -Tag rag-finqa:1.0.0
```
**预期**：日志落 `部署/日志/构建-<时间戳>.log`，末尾出现
```
[OK] 构建成功，耗时 <秒> 秒
<n>            # docker images 行
<字节数>        # docker image inspect .Size
```
**失败排查**：
* `permission denied ... npipe` → 第 8 节；
* `apt-get`/`pip` 超时 → 确认 Dockerfile 里的清华镜像 `ARG` 生效（问题3）；
* `libgomp.so.1: cannot open shared object file` → Dockerfile 的 `libgomp1` 被误删（faiss 运行时依赖）。

### 步骤 4：启动服务

```powershell
pwsh -NoProfile -File 部署\脚本\up.ps1            # 只起核心三件套
pwsh -NoProfile -File 部署\脚本\up.ps1 -WithMonitoring   # 额外起 prometheus
```
脚本按顺序做四件事：① `compose config -q` 预校验 → ② `up -d` → ③ 轮询 `docker inspect .State.Health.Status` → ④ 端口探活。

**预期输出**（节选）：
```
[1/4] 校验 compose 配置（docker compose config -q）
[OK] compose 配置校验通过
[2/4] 启动容器
[3/4] 等待 rag-api 健康（最长 300 秒）
  HH:mm:ss rag-api health = starting
  HH:mm:ss rag-api health = healthy          ← 冷启动约 30~60 秒（索引 8847 块 + 预热）
[4/4] 端口探活
  [OK]   rag-api http://127.0.0.1:8200/health → HTTP 200（<N> 字节）
  [OK]   rag-ui  http://127.0.0.1:8201/health → HTTP 200（<N> 字节）
```
**为什么 `starting` 会持续一会儿**：基座实测冷启动 **27.3 秒**（全文索引构建 20.1 s + 实体标注 2.1 s + 索引载入），
所以 `start_period` 给了 90~150 秒。**不要**因为健康检查还在 starting 就重启容器。

### 步骤 5：一键健康检查（把四项验收的证据一次收齐）

```powershell
pwsh -NoProfile -File 部署\脚本\health.ps1
```
六项检查：① 容器状态 ② 三档探针 ③ 真实问答回归 ④ 卷持久化（含卷内文件列举）⑤ 会话共享 ⑥ 网络连通（Ollama / Redis / RTMP / 服务名 DNS）。
**预期**：末尾 `汇总：PASS=<n>  FAIL=0`（RTMP 一项在本机未运行时**如实报告不可达**，不代表部署失败）。
日志：`部署/日志/健康检查-<时间戳>.log`。

### 步骤 6：真实提问（看答案）

```powershell
$body = @{ question = "平安银行2019年年度报告中，报告期末的资产总额是多少？"; session_id = "demo-1" } | ConvertTo-Json -Compress
$r = Invoke-WebRequest http://127.0.0.1:8200/api/v1/ask -Method POST -Body $body `
        -ContentType 'application/json; charset=utf-8' -UseBasicParsing
$r.Content | ConvertFrom-Json | Select-Object answer, refused, cited_pages, generation_method, session_turns
```
**预期**：`refused=false`、`answer` 里含年报里的真实数字、`cited_pages` 非空。
多轮追问：保持同一个 `session_id` 再问一次，看 `session_turns` 变成 2。

### 步骤 7：浏览器看界面

打开 `http://127.0.0.1:8201/` —— 工单7 的中文问答界面；`http://127.0.0.1:8200/docs` 是 API 交互文档。

### 步骤 8：跑测试

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'
pwsh -NoProfile -File run_py.ps1 -m pytest 测试/测试脚本 -v -p no:cacheprovider *> 部署\日志\pytest-本地等价验证.log
Get-Content 部署\日志\pytest-本地等价验证.log -Tail 40
```
**预期**：全绿（`RAG_TEST_DOCKER=1` 的用例在无 daemon 时会 SKIPPED，属预期）。
证据落 `测试/测试数据/`。

## 4. 单容器 `docker run`（验收标准 2.1 明确点名的姿势）

```powershell
docker build -f 部署/docker/Dockerfile -t rag-finqa:1.0.0 .

docker run -d --name rag-api `
  -p 8200:8200 `
  -e RAG_LLM__OLLAMA_BASE_URL=http://host.docker.internal:11434 `
  --add-host host.docker.internal:host-gateway `
  -v rag-finqa-index:/app/data/index:ro `
  -v rag-finqa-log:/app/logs `
  -v rag-finqa-session:/app/sessions `
  -v rag-finqa-runtime:/app/data/runtime `
  --memory 2g --cpus 2 --restart unless-stopped `
  rag-finqa:1.0.0

# 指定端口验证 + 健康状态
Invoke-WebRequest http://127.0.0.1:8200/health -UseBasicParsing | Select-Object StatusCode
docker inspect --format '{{.State.Health.Status}}' rag-api      # 期望 healthy
docker logs rag-api 2>&1 | Select-String -Pattern 'ERROR|Traceback'   # 期望 0 命中（验收项②"无异常日志"）
```
> ⚠️ 单独 `docker run` 时**必须**挂 `rag-finqa-runtime`，否则运行期 sqlite 会退回到只读索引卷（问题7）。

## 7. 回滚

**场景 A：新镜像有问题，回到上一个可用标签**
```powershell
docker compose --env-file 部署/配置/.env -f 部署/docker/docker-compose.yml down
# 把 .env 里 IMAGE_TAG 改成上一个可用标签（例如 rag-finqa:0.9.0）
docker compose --env-file 部署/配置/.env -f 部署/docker/docker-compose.yml up -d
```
**因为 `down` 不删卷，会话/日志/运行期数据全部保留**，用户无感（这是 `down.ps1` 默认保留卷的设计目的）。

**场景 B：改了环境变量导致起不来**
```powershell
Copy-Item 部署\配置\.env.example 部署\配置\.env -Force     # 回到已知可用配置
pwsh -NoProfile -File 部署\脚本\up.ps1
```

**场景 C：索引卷被写坏**
```powershell
docker volume rm rag-finqa-index        # 索引是可重建的构建产物
# 重新灌入：用一次性容器把宿主机索引拷进卷
docker run --rm -v rag-finqa-index:/dst -v E:\gao6gongdan\工单7\研发\data\index:/src:ro alpine `
    sh -c "cp -a /src/. /dst/"
```

## 8. 本机 Docker 不可用时的替代路径（**本工单实际交付形态**）

若 `docker ps` 报 `permission denied ... npipe:////./pipe/dockerDesktopLinuxEngine`：

```powershell
pwsh -NoProfile -File 部署\脚本\本地等价验证.ps1     # 起 API:8200 + UI:8201（同一份源码、同一组端口、同构卷）
pwsh -NoProfile -File 部署\脚本\health.ps1           # 同样的六项检查（容器相关项会如实 FAIL）
pwsh -NoProfile -File 部署\脚本\本地停止.ps1         # 收尾（务必执行，别留常驻进程）
```

等价性对照表：

| 容器里的东西 | 本机等价物 | 是否同构 |
| --- | --- | --- |
| `研发/service/api.py`（镜像 COPY 进去） | 同一份文件直接跑 | ✅ 完全同一份 |
| `-p 8200:8200` | `uvicorn --host 0.0.0.0 --port 8200` | ✅ 同一端口 |
| `-v rag-session:/app/sessions` | `部署/卷/sessions` 目录 | ✅ 同一目录语义 |
| `-v <索引>:/app/data/index:ro` | `部署/卷/index`（工单7 索引的目录联接） | ✅ 只读引用 |
| `host.docker.internal:11434` | `127.0.0.1:11434` | ⚠️ 地址不同、**同一台 Ollama** |
| `redis:6379`（服务名） | `127.0.0.1:6379`（db 15 隔离） | ⚠️ 地址不同、**同一个 Redis** |
| `docker compose logs` | `部署/卷/logs/app.log` + `部署/日志/` | ✅ 同一份 JSON 日志 |
| `docker inspect .State.Health.Status` | `GET /healthz` | ⚠️ 探针同源（HEALTHCHECK 也是打它） |

**如实声明的限制**（详见 `设计/验收标准.md` §五）：镜像构建/`docker run`/卷的 Docker 侧命令**未取得实测证据**，
交付里对这一部分标注为"配置级验证 + 等价运行验证"，不谎称已在容器里跑过。

## 9. 常见故障速查

| 症状 | 根因 | 处置 |
| --- | --- | --- |
| 容器退出码 **78** | entrypoint 写探针失败（日志/会话/上传卷不可写） | 检查绑定挂载宿主目录权限；改用具名卷 |
| `/health` 里 `volume_index.ok=false` | 索引卷没挂上或路径错 | 确认 `HOST_INDEX_DIR` 与 compose 的挂载点 |
| `/health` 里 `engine.checks.llm.ok=false` | 容器连不到 Ollama | 确认用 `host.docker.internal` 且 `extra_hosts` 生效 |
| `/readyz` 返回 503 | 索引未就绪 | 等冷启动完成，或查 `checks.engine` 具体哪项 false |
| 问答答案变短、`generation_method=rule_composer` | Ollama 掉了，走了抽取合成降级 | 恢复 Ollama；这是**有意的降级**不是 bug |
| `session_backend=file` | Redis 不可达/未启用 | 看 `/health` → `checks.session_store.degraded_reason` |
| 端 oral 8200 无响应但容器在跑 | 服务只听 `127.0.0.1` | 确认 `DEPLOY_API_HOST=0.0.0.0` |
| compose 报路径不存在 | 相对路径基准搞错（基准是 `部署/docker/`） | 见过程问题记录 问题6 |
