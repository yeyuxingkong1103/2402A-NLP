# 评测集字段说明（v1 定稿）

文件：`eval_set_v1.jsonl`（JSONL，每行一个 JSON 对象；100 条 = 原 95 条 + 批次 23 新增 5 条 multi_turn）

## 字段
| 字段 | 必有 | 说明 |
|---|---|---|
| id | ✅ | 唯一标识，前缀即类型（direct- / cross- / followup- / asof- / refusal- / confuse- / multiturn-） |
| type | ✅ | direct_article / cross_law / followup_rewrite / as_of_date / refusal / confusable / multi_turn |
| question | 除 multi_turn 外 | 提问文本；followup_rewrite 类型为第二轮追问 |
| context | followup | 追问题第一轮的用户问题（验证 5.2 多轮改写） |
| as_of_date | as_of | YYYY-MM-DD，时间点限定（验证版本选择） |
| golden | 除 refusal 外 | 期望命中的法规名 + 条号数组（条号与库内 document_chunks.article_number 同格式，如"第十九条"） |
| expect_absent | 可选 | 时效题：该时间点**不应出现**的引用（出现了即判错） |
| expect_refusal | refusal 题 | true，期望"查不到就别答" |
| source_quote | ✅ | 溯源依据：题面/期望答案对应的库内条文原文摘录（审核用） |
| turns | multi_turn | 逐轮题目，`[{question, golden, source_quote}]`，按顺序在**同一会话**里跑 |
| rewrite_expect | multi_turn 可选 | `{turn, expect_changed, must_contain_any, must_not_contain}`：只断言指定轮次的改写行为 |
| notes | multi_turn | 出题意图 / 判别点（不参与判定，供人工复核） |

### multi_turn 类型（批次 23 新增）

与 `followup_rewrite` 的区别（**关键**）：`followup_rewrite` 的 `context` 只是一段前缀字符串，
走的是"先把 context 问一遍、再问 history `question`"的老路径，而**评测器从不回写短期记忆**
（`short_term_memory.append_message` 的唯一调用方是 SSE 接口的 `persist_turn`），
所以改写器读到的上文**永远是空的**——该类题实际只验"追问能不能检索到"，验不到改写本身。

`multi_turn` 用 `turns` 数组按真实多轮顺序连跑，每轮结束后**回写短期记忆**
（等价 `persist_turn` 的 Redis 写侧：`append_message(user)` + `append_message(assistant)`，
窗口 20 条与生产一致，**不写 MySQL**，避免污染业务库），从而让下一轮的改写器真的拿到上文。

`rewrite_expect` 字段：
- `turn`：断言第几轮（1 起）；
- `expect_changed`：该轮 `QueryRewriteResult.changed` 的期望值；
- `must_contain_any`：改写后查询应包含的**主题锚点词**（任一命中即可）；空数组视为"不考察内容"；
- `must_not_contain`：反向断言（可选，命中即判错）。

## 拒答判定标准（可执行口径，运行器必须按此实现）

评测里对 refusal 题（`expect_refusal: true`）与其它题（应正常作答）使用**同一套判定函数**，口径固定如下，任何人跑出来的结果必须一致。

### R1′ 虚构法条依据检测（批次 11 起，替代旧 R1 词表作为必要条件）
回答**没有 `[n]` 引用编号**却给出了**具体法条指引**，视为"虚构法条依据"（该依据无引用清单可核对，不可信）。

命中以下任一模式即判"给出了法条依据"：
1. `《法规名》……第X条` —— 提到具体法规并落到具体条（含"第X条第X款/项"）；
2. `第X条……（之）规定` —— 脱离法规名直接引条号作依据；
3. `根据/依据/按照 …… 第X条` —— 以"第X条"作为论据来源。

归一化：匹配前对回答做空白（含全角空格）压缩；条号支持中文数字与阿拉伯数字。

说明：
- **"法律没有强制规定""属于用人单位自主管理范畴"这类表述不命中任何模式**——这正是 refusal-076/081/082 的正确答法，按旧词表口径会误判失败（批次 11 修正原因）；
- 旧的 `REFUSAL_PHRASES` 拒答词表**保留但不再作为判定必要条件**（运行器中仅留作参考/debug 输出）；
- 回答中泛指"《劳动法》"等法规名而不落到具体条文的，**不算**虚构依据。

### R2 引用编号检测
正则 `\[\d+\]` 命中即视为"回答给出了引用编号"（与前端展示口径一致）。

### 判定结果（三值，互斥）

| 判定 | 条件 | 含义 |
|---|---|---|
| **拒答成功** | 无 R2 引用编号 **且** 未命中 R1′（未虚构法条依据） | 合规拒答：不给结论、不编引用、不凭空挂法条 |
| **拒答失败** | 出现了 R2 引用编号，**或** 命中 R1′（无引用却给出具体法条依据） | 违规作答：编造结论或凭空挂法条 |
| **误拒**（仅对非 refusal 题计算） | 该题 `expect_refusal` 非 true，却判为"拒答成功" | 该答的没答 |

补充规则：
- **凭空引用**：`[n]` 的编号 n 超出该轮回答实际给出的引用清单范围，或引用清单里的法规名不在库内 11 部文档中 → 一律计入"引用错误"（见 R3），且该答案在 refusal 题上直接判**拒答失败**（引用 = 给了结论）。
- refusal 题的 gold 判定**只看上表两行**，不看答案内容是否"大体正确"：哪怕答得对，只要给了引用编号就算失败（该题的正确行为就是不答）。

### R3 引用正确率（用于所有题，非仅 refusal）
回答中的每个 `[n]`，若 n 在 [1, 本轮引用条数] 内，则视为指向真实存在的法源（引用清单由后端按检索结果生成，条数为 M，编号上限为 M）；`n < 1` 或 `n > M` → 该 [n] 记为错误引用。
引用正确率 = 1 - 错误引用数 / 引用总数（无引用时定义为 1.0，并在明细里标注 `no_citation`）。

## multi_turn 指标口径（批次 23 新增，与运行器实现一字对应）

| 指标 | 定义 | 分母 |
|---|---|---|
| `multi_turn_rewrite_rate` | `rewrite_hit=True` 的题目比例。`rewrite_hit = (changed == expect_changed) and 锚点命中`，锚点命中 = `must_contain_any` 为空 **或** 改写后查询包含其中任一锚点词 | **有 `rewrite_expect` 的 multi_turn 题数** |
| `multi_turn_turn2_hit_at_5` | 第 2 轮 golden 落在该轮检索 top5 的题目比例（"改写到底有没有用"的落点） | 所有 multi_turn 题数 |
| `multi_turn_context_carryover` | **只记录不判定**：第 2 轮改写后查询是否真的带上了上一轮问题正文（人工复核项） | — |

其它口径与既有四个指标一致：每轮检索用 `rerank_top_n=10` 计 Recall@5 / MRR@10，
回答用生产默认 `rerank_top_n=5`。

**正向 / 反向对照**：运行器提供 `--no-context-writeback`（关闭每轮的短期记忆回写）作为反向对照开关。
正向应观察到 `rewrite_rate > 0`；反向必须掉到 `0`，否则说明"改写判定"根本没测到上下文这条链路。

**改写结果的形态（批次 24 起）**：`_compose_query` **不再追加「怎么算」尾巴**。
实测（10 条 followup_rewrite + 5 条 multi_turn，加/不加各跑三轮，逐位复现）：
追加会让 `multiturn-003` / `multiturn-004` 的第 2 轮排名各掉 1 位（4→3、3→2）、
子集 MRR@10 从 0.6444 降到 0.6278，其余 13 题逐题不变 —— 无收益且有损，故去掉。
所以现在改写结果形如 `上一轮问题 本轮剩余部分`，不带"怎么算"。
（`multiturn-005` 第 2 轮按设计**不触发**改写：问题既不以「那/这个/上述/前面」开头，
也不以指代词结尾，过不了指代信号闸门。）

## 已知限制（审核与解读结果时注意）
0. **`multi_turn` 的 `must_contain_any` 锚点词必须能在"上一轮问题原文"里找到**（批次 23 实测）：
   改写器注入的主题词是**上一轮用户问题原文**（`QueryRewriter._extract_topic` 只做标点/客套语清洗），
   **不是名词短语**。所以若第 1 轮口语说"怀孕的女员工"、锚点却写"女职工"，改写再正确也命不中锚点。
   出题时锚点词要么取自第 1 轮原文，要么先把第 1 轮改成规范术语。
   → **批次 24 已按此修完**：`multiturn-003` 锚点改为 `["怀孕的女员工"]`、
   `multiturn-004` 改为 `["离职后不去同行"]`（均取自各自第 1 轮原文子串，
   题目一字未改、保住口语化出题意图），正向 `rewrite_rate` 由 2/4 升到 **4/4**。
   本条保留作为**出题规则**（不是待办）：以后新增 multi_turn 题一律照此取锚点词。
   另：`must_contain_any` 只能证明"上下文被带进来"，**证明不了改写质量**；
   真正的质量落点是 `multi_turn_turn2_hit_at_5` 与正反两轮的差值。
