## 2. 总体架构

```
两份招股书 PDF
   │  ① PyMuPDF 正文 + pdfplumber 表格回退（页眉清洗/标题栈/来源文档标注）
   ▼
结构化 Block（text/table，doc_name + heading_path + page_no）
   │  ② 标题感知分块（按句打包、块间重叠、整表独立成块、Small-to-Big）
   ▼
多字段 Chunk：title / body / table / company / summary
   │
   ├──③ 稠密索引：多模型嵌入（bge/m3e，离线TF-IDF降级）→ L2归一矩阵（余弦=点积）
   │
   └──③ 倒排索引：五字段各自 BM25 倒排（布尔/短语/模糊）
                    │
用户 Query（中/英）  │
   ├─ 向量召回 Top-30 ─┐
   ├─ 全文召回 Top-30 ─┤
   │                  ▼
   │        ④ 融合（加权平均 / 投票Borda / RRF）→ 候选池
   │                  ▼
   │        ⑤ 重排（LLM / TF-IDF / 用户反馈自适应）→ Top-K
   │                  ▼
   │        ⑥ 答案抽取（句子级覆盖度 + 确定性槽位；可选LLM生成）
   │                  ▼
   └──────── Streamlit：答案/证据/耗时 + 采纳/不采纳反馈
                        │ 写入 feedback.jsonl
                        ▼
              自适应重排读取反馈 → 反馈闭环
```

## 3. 向量检索模块（召回 + 重排）

### 3.1 多嵌入模型

| 后端键 | 模型 | 说明 |
| --- | --- | --- |
| `bge`（默认） | BAAI/bge-base-zh-v1.5（768 维） | 中英双语；查询侧加指令“为这个句子生成表示以用于检索相关文章：” |
| `bge-large` / `bge-m3` | 本地缓存可选 | 同接口切换，建库 `--backend` 指定 |
| `m3e` | moka-ai/m3e-base（768 维） | 中文嵌入，查询不加指令 |
| `tfidf` | sklearn 字符 2~4-gram TF-IDF（3 万维） | 本地无模型缓存时**自动离线降级**，禁止联网下载 |

加载策略：先查 HF 本地缓存目录，存在才以 `local_files_only=True` 离线加载；任何加载异常一律降级 TF-IDF，保证服务可用。

### 3.2 稠密召回

文档向量 L2 归一后存为 numpy 矩阵，查询向量与矩阵点积即余弦相似度，`argpartition` 取 Top-30（全库约数千块，毫秒级）。

### 3.3 三种重排器

1. **LLM 重排器 `LLMReranker`**：本地离线加载 `BAAI/bge-reranker-large` Cross-Encoder，对 (query, chunk) 深度交互逐对打分。CPU 3 秒预算约束下仅取融合候选前 **12** 个、每候选截断 **64 字**（实测推理 ≈0.7s）；本地无模型时降级为“融合底座+IDF覆盖度+长短语+类型吻合”词法精排。
2. **TF-IDF 重排器 `TfidfReranker`**：全库 jieba 词级 TF-IDF（sublinear）拟合，候选子矩阵余弦相似度 + IDF 加权查询覆盖度 + 长短语有序命中（封顶 0.45）+ 答案类型吻合（数字/人名/枚举）+ 融合底座归一 0.2 权重。
3. **用户反馈自适应重排器 `FeedbackAdaptiveReranker`**：TF-IDF 词法底座之上叠加三类反馈信号：
   - 历史**采纳块词项画像**：采纳文本高频内容词命中加分（系数 0.6，封顶 1.2 倍）；
   - **相似问题采纳/不采纳**：当前问题与历史问题 TF-IDF 余弦 ≥0.45 时，其采纳块 +0.8、不采纳块 −0.8；
   - 任意历史“不采纳”块全局弱降权 −0.25。
   - 每次检索前自动 `refresh()` 重读 `feedback.jsonl`，反馈当次生效。

## 4. 全文检索模块

### 4.1 BM25 倒排

单字段 BM25Okapi：`score(q,d)=Σ IDF(t)·f(t,d)(k1+1)/(f(t,d)+k1(1−b+b·|d|/avgdl))`，`k1=1.5,b=0.75`；倒排表 `term→[(doc,tf)]` postings 实现，评分只遍历命中文档。

### 4.2 多字段加权

每个 Chunk 标注五字段（`chunker.py`）：

| 字段 | 内容 | 权重 w_f |
| --- | --- | --- |
| title 标题 | 章节标题路径（第X节 > 一、…） | **3.0** |
| company 公司实体 | 块内公司全称/文档主体公司（两份招股书分别统计发行人，跨文档消歧） | **2.5** |
| table 表格 | Markdown 表格文本（数字事实密度高） | **2.0** |
| summary 摘要 | 标题+首句（≤80 字） | **1.5** |
| body 正文 | 贪心打包正文 | **1.0** |

多字段总分：`score_full(d)=Σ_f w_f · BM25_f(q,d)`，字段权重在 `config.py` 与界面均可调。

### 4.3 布尔 / 短语 / 模糊

- **布尔**：解析 `AND/OR/NOT` 与中文 `且/与/或/非/不含`；AND 取 posting 交集、NOT 取差集，缺省 OR；
- **短语**：查询相邻内容词在文档词 id 序列中有序相邻，每命中一对 +0.35；
- **模糊**：未登录查询词与词表算字符 bigram Dice 相似度，≥0.75 视为模糊命中并按 0.6×相似度折扣计分（容错错别字/英文形态）。

## 5. 混合检索与三种融合公式

设向量路榜单 `D=[(d,s_d)]`、全文路榜单 `S=[(d,s_s)]`，双路权重 `w_vec,w_full`（归一后和为 1）。

| 融合方式 | 公式 | 特点 |
| --- | --- | --- |
| **加权平均 weighted_avg** | `fuse(d)=w_vec·minmax(s_d)+w_full·minmax(s_s)` | 唯一可直接体现“权重调整”的分数级融合；分数量纲先 min-max 归一 |
| **投票融合 vote（Borda）** | `fuse(d)=Σ_list(N_list−rank_list(d)+1)` | 两张榜单各投一张选票，按名次计分；纯排名、抗分数漂移 |
| **RRF 倒数排名融合** | `fuse(d)=w_vec/(k+rank_d(d))+w_full/(k+rank_s(d))`，`k=60` | 工业界标配，仅一个常数，稳健性最好（最终选定） |

未上榜通道贡献 0；融合后按分降序取候选池（LLM 重排 12 个，其余 30 个）。

## 6. 反馈闭环

```
界面证据“采纳/不采纳” → FeedbackStore 追加 feedback.jsonl
   （query, chunk_id, action, ts, simulated, source）
        │ 自适应重排每次检索前重读
        ▼
采纳词项画像 + 相似历史问题采纳/不采纳 + 负反馈降权 → 重排序变化
```
真实用户反馈 `simulated=false/source=web`；评测脚本生成的反馈强制 `simulated=true/source=simulate`，文件与报告中均明确标注“模拟”。

## 7. 评测方法与指标口径

### 7.1 问题集与 gold 标注

内置 **20 题**（`evaluate.py`）：兴图新科 10 题（数字枚举/实体/列表/人名/表格数字）、力源信息 8 题（法人/成立日期/股本/主营/行业位置/应用领域/客户/募投项目）、英文跨语言 2 题。每题给出：

- `gold`：答案判分关键事实（取自招股书原文）；
- `anchors`：gold 相关 chunk 定位锚点（子串/正则，建库后在“块文本+父段落”去空白匹配，解析为 `gold_chunk_ids`），即**每题 gold 相关 chunk 人工标注**。

### 7.2 指标定义（每题，宏平均）

- **检索准确率（P@1）**：Top-1 证据块是否属于 gold 相关块集合（1/0），宏平均 → 验收“准确率≥90%”；同时报告**答案正确率**（抽取答案包含 gold 关键事实，多事实题要求命中 n−1 个）与 Top3 命中率。
- **召回率 Recall@k（k=5/10）**：
  `Recall@k = |Top-k 结果 ∩ gold 相关块集合| / |gold 相关块集合|`，
  全部题目宏平均 → 验收“召回率≥95%”（主口径 **Recall@10**）。
- **MRR**：首个 gold 块名次倒数平均，辅助观察重排效果。
- **耗时**：检索+答案抽取端到端秒表；报告平均/最大耗时与 **≤3 秒占比**。

### 7.3 策略矩阵

2 个单通道基线（向量/全文 ×2 种重排取代表）+ 3 融合 × 3 重排 = 9 个混合策略，共 **13 种策略**同题同库对比；另对“混合+RRF+自适应重排”做**模拟反馈一轮前/后**对比。输出：

- `03_测试/评测结果.csv`：每题 × 每策略明细（命中、答案、Recall@5/10、MRR、耗时）；
- `03_测试/策略对比表.csv`：13 策略 + 反馈前后 2 行汇总。

## 8. 3 秒延迟预算（纯 CPU）

| 阶段 | 预算 | 实测 |
| --- | --- | --- |
| 查询嵌入（bge，1 条） | ≤0.15s | ≈0.05s |
| 稠密 Top-30 + 五字段 BM25 Top-30 | ≤0.10s | ≈0.02s |
| 融合 + 候选截取 | ≤0.01s | <0.01s |
| LLM 重排（12 候选×64 字） | ≤1.5s | ≈0.7s |
| 答案抽取 | ≤0.1s | <0.05s |
| **合计** | **≤3s** | **典型 0.8~1.3s** |

索引加载/模型加载为服务启动期单例常驻，建库离线完成，均不计入单次响应。
