# LightRAG 优化方案

> 工单编号: 人工智能 NLP-RAG 项目-LightRAG 优化
> 参考: https://github.com/HKUDS/LightRAG

## 一、LightRAG vs 传统 RAG

| 维度 | 传统 RAG | LightRAG |
|------|----------|----------|
| 索引结构 | 扁平向量 | 图 + 向量双索引 |
| 检索层次 | 单层向量 | **双层: 局部+全局** |
| 实体关系 | 忽略 | **图结构建模** |
| 更新机制 | 全量重建 | **增量更新** |
| 复杂推理 | 需 LLM 脑补 | 图谱路径直接支持 |
| 维护成本 | 随数据指数增长 | 增量更新, 线性增长 |

## 二、LightRAG 核心架构

### 2.1 索引构建流程
```
文档 → 切块 → 实体/关系抽取 → 去重合并 → 知识图谱 + 向量索引
                                          ↓
                                    增量更新 (图差异分析)
```

### 2.2 查询响应流程 (双层检索)
```
问题 → 关键词分类
  │
  ├─ 局部关键词 (具体实体: "控股股东", "注册资本")
  │   → 向量库检索具体文本块
  │   → 图谱邻居扩展
  │
  └─ 全局关键词 (概念/主题: "行业增长", "技术标准")
      → 图谱高层遍历 (社区发现)
      → 路径推理 + 关联摘要
```

### 2.3 增量更新
```
新数据 → 提取新实体/关系 → 对比现有图谱 → 增量合并
  - 已有实体: 更新属性
  - 新实体: 添加节点
  - 新关系: 添加边
  - 无需重建整个索引!
```
