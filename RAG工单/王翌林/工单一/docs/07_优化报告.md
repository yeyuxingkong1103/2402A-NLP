## 二、核心优化详解

### 2.1 BM25 + RRF 混合检索（高 ROI）

**改动前**：仅向量检索（COSINE），关键词精确匹配能力弱

**改动后**：
```python
# src/retriever.py —— 两路召回 + RRF 融合
# 向量路：top_k=50 候选
# BM25 路：top_k=50 候选（jieba 中文分词 + 停用词过滤）
# RRF 融合：Σ 1/(k + rank_i), k=60
# 去重键：chunk_id（稳定主键，避免 content md5 误合并）
```

**效果**：
- 关键词精确匹配问题（如"注册资本"、"法定代表人"）召回更准
- RRF 融合天然平衡向量语义和 BM25 关键词
- 去重用 chunk_id 而非 content md5（避免不同文档相同段落被误合并）

### 2.2 bge-reranker-v2-m3 重排序（高 ROI）

**改动前**：仅向量相似度排序，top-5 精度依赖向量召回质量

**改动后**：
```python
# src/retriever.py —— reranker 默认开启
from FlagEmbedding import FlagReranker
reranker = FlagReranker("/home/dabaie/models/bge-reranker-v2-m3", use_fp16=True)
# 对融合后 top-30 做 rerank → 取最终 top-5
```

**效果**：
- reranker 做 cross-encoder 精排，比向量 cosine 精度显著更高
- bge-reranker-v2-m3 支持多语言，中文金融领域适配良好
- 默认开启，首次加载约 2-3s，后续推理 ~200ms/query

### 2.3 Milvus HNSW 参数调优

| 参数 | 优化前 | 优化后 | 说明 |
|------|--------|--------|------|
| M | 16 | **32** | 每个节点 16→32 连接，图更密集 |
| efConstruction | 256 | **512** | 建图搜索空间更大，图质量更高 |
| ef (search) | nprobe=16 | **ef=64** | 搜索时访问更多节点 |
| metric_type | COSINE | COSINE | 保持不变（与 bge-m3 归一化完美匹配） |

**trade-off**：插入/索引时间↑，搜索时间略↑，但召回率↑

### 2.4 分块策略调优

| 参数 | 优化前 | 优化后 | 说明 |
|------|--------|--------|------|
| chunk_size | 800 | **600** | 更细粒度，检索命中更精准 |
| chunk_overlap | 150 | **120** | 匹配 size，节省 token |
| 表格 chunk | 无 | **400 + 表格分隔符** | 表格内容用更小 size 保持完整性 |
| 分隔符 | 5 种 | **12 种** | 加引号、顿号、冒号、书名号等 |

**新增**：表格内容检测 `_is_table_like()` — 多行数字行 + 竖线 + 等宽空格 → 自动切 table chunk

### 2.5 diskcache 检索缓存

**改动**：retriever.py 内置 diskcache 装饰器，缓存 query→results，TTL=1h

**效果**：重复查询 0ms（向量检索 + BM25 + rerank 全部跳过）

## 六、已知限制

| 限制 | 说明 | 影响范围 |
|------|------|---------|
| **Reranker 首次加载慢** | bge-reranker-v2-m3 2.2GB 模型首次加载 ~2-3s | 首条查询 |
| **BM25 索引需 Milvus 数据** | 从 Milvus scan 拉全量 chunks 构建 BM25 | 冷启动 |
| **RRF score 语义** | 融合后 score 混合 rerank_score(0-10) / rrf_score(0-0.1) / distance(0-2) | 前端需统一归一化 |
| **diskcache 持久化** | 默认 TTL=1h，重启后端后缓存仍在（磁盘持久） | 磁盘占用 |

## 七、后续优化方向

1. **Milvus 分区过滤**：按 doc_id 分区，支持多文档隔离检索
2. **Dense-sparse 联合索引**：用 Milvus 原生 BM25 + 向量，避免 Python 侧构建 BM25
3. **Query Decomposition**：复杂问题拆分子问题，多跳检索
4. **Long-context Rerank**：reranker 支持 8k+ tokens 的长上下文精排
5. **GraphRAG**：基于 chunk 引用关系构建知识图谱
