## 1. 项目背景与目标

### 1.1 背景

工单1 已交付基线 RAG 问答系统：PDF 解析（PyMuPDF）→ 分块（2967 块）→ 向量化（bge-small-zh-v1.5，512 维）→ numpy 向量库 + 自实现 BM25 混合检索 → LLM 生成（原设计对接 vLLM `127.0.0.1:8000`，本机不具备）→ 引用 → SQLite → 日志 → Streamlit 界面 → 10 个固定问题评估。【工单1产物：`工单1/data/index/vectors.npy` 6076544 B = 2967×512×4；`chunks.jsonl` 2967 行】

基线在**答案准确率**与**首字延迟**两项上不达标，其余项（引用、拒答、英文）达标：

| 基线指标 | 实测值 | 工单目标 | 结论 |
| --- | --- | --- | --- |
| 10 个工单问题答案准确率 | **0.50（5/10）**【工单1产物】 | ≥ 90% | ❌ 不达标 |
| 首字响应 平均 | 11518.33 ms【工单1产物】 | ≤ 3000 ms | ❌ 不达标 |
| 首字响应 P95 / 最大 | 57312.92 ms【工单1产物】 | ≤ 3000 ms | ❌ 严重不达标 |
| 端到端 平均 | 14186.86 ms【工单1产物】 | —（工单未定，仅观测） | — |
| 引用正确率 | 1.0（10/10 条引用有效）【工单1产物】 | 引用页码真实 | ✅ 已达标，需保持 |
| “不清楚”回复正确率 | 1.0【工单1产物】 | 不知道时回复“不清楚” | ✅ 已达标，需保持 |
| 英文 5 题准确率 / 首字 | 1.0 / 6.2 ms【环境事实】 | 支持中英文 | ⚠️ 达标但口径需复核（见 1.3） |
| 向量检索 top-5 命中证据 | **1/10**【环境事实】 | — | ❌ 根因所在 |

### 1.2 工单目标（原文 5 节 7 条）【工单要求】

1. 检索准确率：10 个工单问题回答准确率 ≥ 90%。
2. 响应速度：首字返回 ≤ 3 秒。
3. 优化对比：输出优化前后准确率、检索命中率、响应时间对比。
4. 中英文支持：支持中文和英文提问，答案优先中文，可英文。
5. 稳定性：长时间运行、异常输入、PDF 解析失败时均有容错。
6. 可解释性：答案必须带引用，引用页码真实可查。
7. 日志完整：函数输入输出、检索片段、模型输出全记录。

### 1.3 一个必须先讲清的口径问题（英文指标）

工单1 的「英文 5 题：准确率 1.0、首字平均 6.2 ms、端到端平均 129.9 ms」【工单1产物：`eval_records.json.summaries.rag_en`】。

【推断】首字 6.2 ms 不可能是任何 LLM 生成的量级（本机实测 qwen2.5:3b 首字 0.20 s【环境事实】），该组数据来自**抽取式/模板英文路径**（工单1 `app/core/english_answer.py` + `language.py` 的规则化英文答案），而不是"英文问题 → 跨语言检索 → LLM 英文生成"的完整链路。

**因此本工单不接受直接沿用该组数值作为"中英文支持达标"的证据**：T7 必须用优化后链路重新采集英文指标（≥5 题，中英各 5 题以上），并如实标注生成模式（`llm` / `extractive` / `fallback`）。本条要求写入 `设计/验收标准.md` 第 4 条与第 6 条。
