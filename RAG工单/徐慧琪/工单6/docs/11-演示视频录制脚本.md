# 演示视频录制脚本（工单06）

**工单编号**：人工智能NLP-RAG-混合检索任务
**对应硬性要求5**：① 一个完整演示视频（系统功能与操作流程）；
② 一个讲解视频（**语义检索、全文检索分别用的检索技术**，Reranker 精排的作用，
并展示检索精度提升的测试问题及答案）。

> 录制前：`python build_index.py` 已跑完；`streamlit run app.py` 已启动；
> 点过侧栏「预热模型」。两个视频都建议 1080p、窗口宽屏（Streamlit 用 wide 布局）。

## 视频一 · 系统功能与操作流程（建议 5~7 分钟）

| 段落 | 时长 | 画面操作 | 口播要点 |
| --- | --- | --- | --- |
| 1. 开场 | 30s | 首页全景 | 工单编号、语料（两份招股书 350+548 页）、本版核心：三种检索策略 |
| 2. 本机模型扫描 | 40s | 终端跑 `python scan_local_models.py`；打开 `docs/01` | 「硬性要求0：**先扫描、后编码**，全程零下载」；四类模型角色（嵌入/Reranker/LLM/多模态）本机全满足 |
| 3. 建库 | 40s | 终端 `python build_index.py`（若时间紧则展示已有日志） | 复用上游解析产物；图像 VLM 描述增强（162 条）；三套索引：Qdrant 8010 点 / 自研倒排 23MB / BM25 |
| 4. 单轮问答 | 60s | 💬 问答页：问 id1「本次发行股数…」 | 答案逐字含数字；展开看**引用来源**（PDF/页码/block_type/表格ID）与**精排报告**（候选数、耗时、名次变化） |
| 5. 多轮追问 | 40s | 🧠 多轮页：Q1 完整问题 → 「**这个公司**的法定代表人是谁？」→「**那武汉力源呢**？」 | 指代消解把追问补全成独立问题；指代不明时会反问而不是瞎答 |
| 6. ★ 检索策略页 | 90s | 🔀 页：依次演示策略切换、拖动权重、换融合算法、换 Reranker 模型 | 「**本工单核心**：三种策略可配置可应用」；每次改动后立即提问，观测条显示召回通路/候选数/三段耗时/名次变化 |
| 7. ★ 三策略并排 | 60s | 点「三种策略并排对比」 | 同一问题三列结果：向量（语义）、全文（关键词精确）、混合（两者融合后精排） |
| 8. 全文语法 | 40s | 粘贴 `(武汉博润 OR 上海博润) AND 关联方`、`注册资木~`、`title:组织结构图` | 布尔/短语/模糊/多字段四种能力现场演示 |
| 9. 图像与组织结构题 | 40s | 问 id6（IC 市场图）、id5（组织结构图） | 图像块命中原图直接渲染；组织图给节点路径 |
| 10. 反馈与自适应 | 30s | 点 👎→ 切「用户反馈自适应重排器」→ 重问 | 反馈落库并影响排序（对比基线之一） |
| 11. 收尾 | 30s | 打开 `docs/04` 汇总表 | 三策略指标一屏；指向验收对照表 |

## 视频二 · 检索技术与精度提升（建议 6~8 分钟）

| 段落 | 时长 | 画面操作 | 口播要点 |
| --- | --- | --- | --- |
| 1. 问题背景 | 30s | 打开 `docs/02` §1 | 为什么要三种策略：招股书问题=语义问法 + 精确事实混合出现 |
| 2. **语义（向量）检索用什么技术** | 90s | 终端跑 `python -m src.retriever "钱花在哪了"` 或用界面向量策略问「募集资金投向哪些项目」 | **bge-m3 稠密向量**（1024 维、中英双语）把问句与文本块映射到同一向量空间，**余弦相似度**在 Qdrant 里做近邻检索；讲清"问法不同也能命中" |
| 3. **全文检索用什么技术** | 120s | 终端 `python -m src.fulltext '"军用领域" AND 收入'`；界面全文策略演示 | **自研位置倒排索引**：词→文档位置表；BM25（k1=1.5,b=0.75）多字段打分（标题 2.5/正文 1.0/摘要 1.2）；演示布尔求交、短语位置校验（`"存在控制关系的关联方"`）、编辑距离 1 的模糊匹配、数字口径归一（`5,520` ↔ `5,520.00`） |
| 4. **Reranker 精排的作用** | 120s | 界面打开「🎯 精排报告」的**名次变化**表；再切 `无精排/向量` 与 `混合+Reranker` 对比同一问 | Cross-Encoder 把 (问题, 候选块)**拼在一起**打分（vs 双塔的各自编码后算余弦），判别力更强：把"含答案的块"顶到前面，把"只含问题措辞"的块压下去；现场展示 before→after 名次变化与新增的 Top-5 命中 |
| 5. **精度提升的实测数据** | 90s | 打开 `docs/04-检索精确度报告.md`、`docs/05-优化前后对比分析.md` | 三策略指标对照：信息召回率、Hit Rate@5、MRR、NDCG@5、答案准确率；对比臂（工单01 仿真 vs 06 系统）提升幅度 |
| 6. **逐题演示** | 90s | 抽 3 题现场问：精确数字题（id1）、表格列举题（id4）、图像题（id6） | 每题念出答案，并指出**引用来源**（页码/类型/ID）——"答案可追溯" |
| 7. 收尾 | 30s | 打开 `docs/09-工单验收对照表.md` | 逐条对照硬性要求 0~8 的达成情况与证据文件 |

## 录制注意事项

1. **终端中文乱码**：Windows 终端默认 GBK，中文可能显示为方块。录屏前执行
   `chcp 65001` 切换 UTF-8，或改在 PowerShell + `$OutputEncoding` 设置；也可直接展示已落盘的报告文件（UTF-8 正常）。
2. **首题延迟**：务必先预热，否则第一题会花 30 秒加载模型，视频里很难看。
3. **数据可复现**：视频里引用的所有数字都能用 `evaluate_retrieval.py` / `evaluate_compare.py` /
   `evaluate_ragas.py` / `benchmark_load.py` 重跑得到；报告里标注了运行时间与机器。
4. **诚实展示降级**：如果现场出现「⚠️ 降级」（显存被占用），不要剪掉 —— 这正是容错机制的演示点（`docs/07`）。
