## 2. 启动与前置检查

### 2.1 启动

```powershell
conda activate gao6gongdan
cd E:\gao6gongdan\工单1
streamlit run app/ui/streamlit_app.py
```

终端会打印本地访问地址，浏览器打开该地址（Streamlit 默认 `http://localhost:8501`）即可。

### 2.2 三项前置检查

打开界面后，先确认以下三件事，否则后面每一步都会失败：

| # | 检查项 | 怎么确认 | 不通过怎么办 |
| --- | --- | --- | --- |
| 1 | **问答引擎就绪** | 侧边栏**没有**红色“问答引擎尚未就绪”提示；底部输入框可以输入 | 点击侧边栏最下方的 **🔄 重新初始化问答引擎**；仍不就绪说明 `app/core/qa_engine.py` 尚未落地 |

## 3. 选择或上传 PDF

系统**默认加载** `data/raw/招股说明书1.pdf`，正常情况下你不需要做任何操作。相关控件都在侧边栏的 **📁 文档** 小节。

### 3.1 使用默认文档（推荐）

侧边栏 `选择 PDF 文档` 下拉默认选中《招股说明书1.pdf》，下方 `当前文档` 会显示：

```text
当前文档
文件：招股说明书1.pdf
路径：E:\gao6gongdan\工单1\data\raw\招股说明书1.pdf
大小：13.65 MB
文档 ID：（引擎默认）
```

### 3.2 切换到其它文档

在 `选择 PDF 文档` 下拉中选择目标文件即可。**下拉里的候选项来自 `data/raw/` 目录**，所以想切换就得先把 PDF 放进该目录（或用 3.3 的上传功能）。切换后界面会重新绑定文档。

### 3.3 上传新 PDF

1. 在 `📁 文档` 小节点击 **`上传 PDF（可选）`**；
2. 选择本地 PDF 文件（仅接受 `.pdf`）；
3. 该文件会被**保存到 `data/raw/` 目录**，并自动切换为当前文档；
4. 之后需要为它建立索引才能提问（见 [DEMO_CHECKLIST.md](DEMO_CHECKLIST.md) 阶段 B）。

> **注意**：上传只是把文件放进 `data/raw/` 并切换当前文档，**解析与建索引仍是独立步骤**。548 页量级的文档建索引耗时较长，请等脚本跑完再提问。

### 3.4 指定 `文档 ID`（高级，通常不用）

若引擎要求特定的 `doc_id`，可在 `文档 ID（选填）` 输入框中填写，再点击 **`应用文档 ID`**。留空时使用 PDF 文件名（不含扩展名）作为 `doc_id`。

### 3.5 下拉里没有《招股说明书1.pdf》

说明文件不在 `data/raw/`。此时界面上会出现黄色警告：

```text
未找到 PDF 文件。请上传，或把《招股说明书1.pdf》放到：E:\gao6gongdan\工单1\data\raw
```

按 [README.md](README.md) 第 5.5 节把 PDF 放进去，然后刷新页面（或点击 `🔄 重新初始化问答引擎`）。

## 4. 提问

### 4.1 基本操作

1. 在页面**底部的输入框**输入问题，输入框提示语是“请输入关于招股说明书的问题，例如：武汉兴图新科电子股份有限公司注册资本是多少？”；
2. 按 **Enter** 提交（该输入框靠回车提交，没有单独的“发送”按钮）；
3. 提交后先显示“_正在检索文档并生成回答…_”，随后答案**逐字出现**（流式输出），无需等待整段生成完毕。

### 4.1.1 一键提问（推荐演示时使用）

侧边栏有一个 **`🎯 演示问题（一键提问）`** 折叠面板，展开后是工单固定的 **10 个问题**各一个按钮。点击任一按钮即自动提问，**免去手打或复制粘贴**。

- 按钮上显示问题前 30 个字，鼠标悬停可看到完整问题；
- 引擎未就绪时这些按钮是禁用（灰色）状态。

> 演示建议：**优先用一键按钮**保证提问文字与工单完全一致；需要展示“手打提问”时再用底部输入框。

### 4.2 提问技巧（让答案更准）

| 技巧 | 示例 | 原因 |
| --- | --- | --- |
| **带上关键实体** | “武汉兴图新科电子股份有限公司来自军用领域的收入分别是多少？” | 招股书里同类表述很多，带上主体能显著提高召回精度 |
| **带领域关键词** | 收入、占比、注册资本、法定代表人、募集资金、补充流动资金、上游、下游、供应商、客户、技术标准、科技进步奖 | 这些词在系统中被**加权**，命中后排序更靠前（见 [TECH_DOC.md](TECH_DOC.md) 第 6.2 节） |
| **一次问一件事** | 把“注册资本和法定代表人分别是什么？”拆成两问 | 复杂问题虽会被分解，但分开问答案更聚焦 |
| **追问用代词** | 先问“……军用领域的收入”，再问“那占比呢？” | 系统会结合最近 5 轮对话改写当前问题 |

### 4.3 关于“不清楚”

如果问题超出 PDF 范围、或检索不到相关内容，系统会统一回复 **“不清楚”**。这是**设计行为，不是故障**——系统宁可说不知道，也不编造答案。验证方法见第 11 节。

## 5. 查看引用与原文

每条回答下方都带**引用来源**，这是核对答案是否可信的关键入口。

### 5.1 引用区长什么样

```text
📚 引用来源（3 条）
  ▸ [页码: 129]　第二节 主营业务　相关度 0.812
  ▸ [页码: 130]　第二节 主营业务　相关度 0.764
  ▸ [页码: 135]　第三节 行业情况　相关度 0.701
```

每条引用的标题由三部分组成：**页码标记**、**所属章节**（未标注时显示“未标注章节”）、**相关度分数**。

### 5.2 操作步骤

1. 点击任意一条引用（折叠面板），展开后可以看到：
   - `片段 ID：c000123` —— 该片段在 `chunks` 表中的主键；
   - **原文片段** —— 引用摘要，带边框展示；
   - 若该片段还有更完整的正文，会出现一个 **`查看完整片段原文`** 复选框，**勾选后展开完整原文**；
2. 把页码抄下来，打开 PDF 阅读器跳到该页，肉眼比对数字与措辞；
3. 若回答是兜底结果（没有引用），界面会显示蓝色提示：

   ```text
   本次为“不清楚”兜底回复：文档中没有检索到可支撑该问题的内容。
   ```

### 5.3 核对要点

| 核对什么 | 说明 |
| --- | --- |
| 页码是否真实 | 引用页码必须落在 1~548 之间，且该页内容确实与答案相关 |
| 数字是否一致 | 收入、占比、注册资本等数字必须与引用页原文**完全一致**（注意单位：万元/元） |
| 是否答非所引 | 答案里出现的内容，应当能在引用片段中找到依据 |
| 相关度是否合理 | 相关度明显偏低（例如 < 0.1）却给出了肯定答案，需要警惕 |

> 若发现引用页码与内容不符，请记录问题原文、回答、引用页码与 `片段 ID`，并附上 `logs/rag_trace.jsonl` 中对应时间段的记录，提交给开发者。

## 6. 多轮对话

系统保留**最近 5 轮**对话作为上下文，用于理解代词和省略。

### 6.1 推荐演示脚本

| 轮次 | 你输入 | 期望发生的事情 |
| --- | --- | --- |
| 第 1 轮 | 武汉兴图新科电子股份有限公司参与制定了哪个技术标准？ | 正常回答 + 引用 |
| 第 2 轮 | 那这个标准是什么级别的？ | 系统把“这个标准”改写为具体标准名称后检索，答案延续上一轮主题 |
| 第 3 轮 | 该公司注册资本是多少？ | 换话题，正常回答 |
| 第 4 轮 | 法定代表人呢？ | 系统理解为“该公司的法定代表人”，继承上一轮主体 |

### 6.2 说明

- 上下文只影响**检索与理解**，不影响“答案必须有引用”这一约束；
- 超出 5 轮之前的对话不再参与改写，长对话中请适当重复关键实体；
- 切换文档或新建对话后，上下文重新开始。

## 7. 点赞与点踩

### 7.1 操作

每条回答下方有一排反馈控件：

```text
[👍 有帮助]  [👎 没帮助]      [补充评论（选填）………………]  [提交评论]
```

操作步骤：

1. 答案正确、引用可信 → 点击 **`👍 有帮助`**；
2. 答案错误、引用不相关、或该答“不清楚”却硬答 → 点击 **`👎 没帮助`**；
3. 点击后按钮位置会变成状态文字 **`👍 已赞`** 或 **`👎 已踩`**，表示已记录；
4. （可选）在 **`补充评论（选填）`** 输入框写评论，输入框提示语是“例如：答案与原文不符 / 缺少页码 / 检索不到内容”，写完点击 **`提交评论`**；
5. 提交成功会提示 **“评论已提交，感谢反馈！”**。

界面的校验提示：

| 情况 | 界面提示 |
| --- | --- |
| 还没点赞就提交评论 | 请先点击 👍 或 👎，再提交评论。 |
| 评论内容为空 | 评论内容为空，请输入后再提交。 |
| 提交成功 | 评论已提交，感谢反馈！ |

### 7.2 反馈记录到哪里

反馈写入 SQLite 的 `feedback` 表（会话 ID、消息 ID、评分 `up`/`down`、评论、问题原文、时间戳）。可按下面的命令查看统计：

```powershell
python -c "from app.storage.sqlite_manager import get_sqlite_manager as g; print(g().feedback_stats())"
```

预期输出形如：

```text
{'up': ..., 'down': ...}
```

## 8. 清空对话

相关控件都在侧边栏的 **💬 对话** 小节。

### 8.1 清空当前对话

1. 点击 **`🗑 清空当前对话`**；
2. 当前会话的全部消息被删除，页面上的问答历史清空，上下文重置。

- 效果：当前 `conversation_id` 下的 `messages` 记录被清空，`conversations.message_count` 归零；
- 不影响：已构建的索引、其它会话、`feedback` 与 `eval_results` 记录。

### 8.2 新建对话

点击 **`➕ 新建对话`**：开启一个全新会话（新的 `conversation_id`），历史互不干扰。

> 演示时的区别：想保留上一题供对比用 **新建对话**；想让画面回到干净状态用 **清空当前对话**。

### 8.3 切换历史会话

在 **`切换历史对话`** 下拉框中选择历史会话即可切换，侧边栏底部显示 `当前会话：xxxxxxxx`（会话 ID 前 8 位）。

> **已知限制**：会话回放能力取决于引擎实现。若历史会话是在本次打开界面之前创建的，界面会提示“该会话在问答引擎中已有 N 条历史消息。引擎接口未提供消息回放能力，此处仅显示本次打开界面后产生的问答。”——这不是故障，是引擎接口范围的说明。

```text
│ 首字响应      │ │ 总耗时    │ │ 检索片段  │ │ 命中页码  │
│  1234 ms     │ │  3.45 s  │ │   5 个   │ │   3 页   │
│  1.23 s      │ │          │ │          │ │          │
└──────────────┘ └──────────┘ └──────────┘ └──────────┘
✅ 首字响应 1234 毫秒（1.23 秒），满足 3.0 秒预算。
命中页码：第 129 页、第 130 页、第 135 页
共检索到 5 个相关片段，其中 3 条作为引用来源。
```

（上例中的数字仅为**格式示意**，实际数值以运行时显示为准。）

### 9.2 四项指标的含义

| 指标卡 | 含义 | 验收线 |
| --- | --- | --- |
| **首字响应** | 从提交提问到界面出现**第一个字**的耗时（同时以 ms 和 s 显示） | **< 3000 ms（即 3 秒）** |
| **总耗时** | 整段回答生成完毕的总时间 | 无硬性要求 |
| **检索片段** | 交给 LLM 的检索片段数量（默认最多 5 个） | — |
| **命中页码** | 检索命中的页码数量 | 应与引用条数大致吻合 |

### 9.3 预算提示怎么读

- **达标**：显示一行灰色小字 `✅ 首字响应 xxxx 毫秒（x.xx 秒），满足 3.0 秒预算。`
- **超标**：显示**红色错误框** `⏱ 首字响应 xxxx 毫秒（x.xx 秒），已超出 3.0 秒预算！`

若指标卡显示 **`未记录`**，说明引擎没有上报该字段（界面会在能自行计时的情况下兜底测量）。

### 9.4 演示时的重要提醒

**冷启动的第一条问题通常明显偏慢**（推理服务首次请求包含模型加载与显存预热）。演示标准流程是：

1. 先随便问一个热身问题（或直接问第 1 题并说明这是热身）；
2. 从第 2 条问题开始正式记录首字响应时间。

### 9.5 想看更细的耗时分布

首字时间只反映“用户体感”，想知道**哪一步慢**（解析、向量化、向量检索、BM25、重排、生成），看追踪日志：

```powershell
Get-Content logs\rag_trace.jsonl -Tail 40
```

每条记录形如：

```json
{"ts":"2026-01-01T10:00:00.000+08:00","event":"exit","module":"app.core.retriever","function":"Retriever.search","elapsed_ms":123.456,"result":{...}}
```

## 12. 常见问题

### Q1：界面打开是空白 / 报错

先在终端看有没有 Python 堆栈。常见原因：依赖没装全（`pip install -r 部署/环境配置/requirements.txt`）、索引不存在、端口被占用（换 `--server.port 8502`）。详见 [README.md](README.md) 第 9 节。

### Q2：提问后一直转圈不出字

大概率是 LLM 服务不可达。检查 `RAG_LLM__BASE_URL` 指向的地址（默认 `http://127.0.0.1:8000/v1`）是否有服务；服务不通时系统会降级为抽取式回答，若降级也拿不到内容就返回“不清楚”。

### Q3：答案看起来对，但引用页码对不上

请记录并反馈（问题、回答、引用页码、`chunk_id`）。引用校验是验收项之一，评估脚本会统计**引用正确率**。

### Q4：同一个问题问两次，答案不完全一样

`temperature` 默认为 `0.1`（偏确定性），但仍可能有措辞差异。**事实性内容（数字、名称）必须一致**；若数字都变了，属于严重问题，请记录。

### Q5：能问英文问题吗

需求说明书按**中文问答**口径实现（工单原件另提到多语言支持，范围待确认，见 [TECH_DOC.md](TECH_DOC.md) 第 17 节）。中文提问是验收路径。

### Q6：怎么把当前对话记录导出

对话与消息都写在 `data/index/rag.sqlite3` 的 `conversations` / `messages` 表中，可用任意 SQLite 客户端查询导出。例如查看总行数：

```powershell
python -c "from app.storage.sqlite_manager import get_sqlite_manager as g; print(g().stats())"
```

### Q7：演示完整流程是什么

打开 [DEMO_CHECKLIST.md](DEMO_CHECKLIST.md)，从阶段 A 到阶段 L 逐项勾选即可。

## 13. 语音输入与英文提问

> 两项追加需求的操作说明；原理与限制见 [`VOICE_AND_ENGLISH.md`](VOICE_AND_ENGLISH.md)。

### 13.1 用语音提问

1. 在提问框上方展开 **🎤 语音输入** 面板；
2. 点击录音控件开始说话（Streamlit < 1.40 时为「上传音频文件」按钮），
   说完再次点击结束；
3. 系统自动转写并显示 **识别结果（语种）**，随后自动作为问题提交；
4. 若显示红色提示，说明语音服务未就绪或音频无法解码，按提示处理后重试；
   期间仍可正常使用文字提问。

> 语音提问的响应时间包含转写耗时，不计入“首字 < 3 秒”指标
> （该指标衡量检索与生成链路）。

### 13.2 用英文提问

直接用英文输入即可，系统会自动识别语言并用**英文作答**：

```
What is the registered capital of the company?
→ The registered capital of Wuhan Xingtu Xinke Electronics Co., Ltd.
  is RMB 55.20 million (5,520.00 ten-thousand yuan).
```

要点：

- 引用格式为 `[Page: N]`（中文回答是 `[页码: N]`）；
- 侧边栏「🎯 演示问题」面板可切换 **中文 / English** 两组演示问题；
- 英文问与语料无关的问题时，会回复 `I don't know`（同样不编造）；
- 金额单位由代码换算，`5,520 万元` 会正确显示为 `RMB 55.20 million`。

### 13.3 强制指定回答语言（可选）

```bash
export RAG_LANGUAGE__DEFAULT_ANSWER_LANGUAGE=zh   # 英文提问也用中文回答
export RAG_LANGUAGE__DEFAULT_ANSWER_LANGUAGE=en   # 中文提问也用英文回答
export RAG_LANGUAGE__DEFAULT_ANSWER_LANGUAGE=auto # 默认：跟随提问语言
```
