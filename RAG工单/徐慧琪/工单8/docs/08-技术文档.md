## 二、完整构建流程

从零到跑通问答（每步都给出预期输出）：

```bash
# 0) 环境确认（可选）
python scan_local_models.py                    # → docs/01 的本机模型清单
python -c "from src import bootstrap, llm; print(llm.health())"
#   → {'ok': True, 'model': 'qwen2.5:3b', ...}；Ollama 未启动时 ok=False

# 1) 解析 PDF + 分块 + 建索引（语料已解压到 data/corpus/）
python build_index.py
#   → [retriever] BM25 索引就绪：7757 篇 ...
#   → [fulltext] 倒排索引就绪：7757 篇 / 词表 ... / 索引已持久化 data/index/fulltext.pkl

# 2) 构建知识图谱（第 1 层：词典+正则，秒级）
python build_kg.py --layer1
#   → [layer1] 完成：7757 块（有实体 1846）→ 实体 560、关系 873，耗时 0.4s
#   → 节点 560 边 873 覆盖文档 9；关系类型：HAS_METRIC 440 / REPORTED_IN 361 /
#     BELONGS_TO 63 / IN_INDUSTRY 9

# 3)（可选）第 2 层 LLM 抽取 —— 耗时长，务必带 --resume 断点续抽
python build_kg.py --all --resume
#   → 每块即时写入 data/kg/llm_extract_ckpt.jsonl，中断后可继续

# 4) 查看图谱统计 / 生成图谱报告
python build_kg.py --stats
python build_kg.py --report                    # → docs/03-知识图谱构建.md

# 5) 自检
python -c "from src.runtime_ext import health_check; import json; print(json.dumps(health_check(), ensure_ascii=False))"

# 6) 批量评测 14 题（约 1 分钟）
python graph_qa_cli.py --all                   # → data/eval/graph_qa_results.json

# 7) 与工单07 对比
python src/compare_with_wo07.py                # → docs/05、docs/06、data/eval/compare_wo07.json

# 8) 启动界面
streamlit run app.py                           # 浏览器打开 http://localhost:8501
```

## 三、配置项（`src/config.py`，工单08 新增）

| 配置 | 默认值 | 说明与调优建议 |
| --- | --- | --- |
| `KG_DIR` | `data/kg` | 图谱产物目录 |
| `KG_PICKLE` / `KG_GRAPHML` | `kg.pkl` / `kg.graphml` | 快速加载 / 可交换格式 |
| `KG_ENTITIES_JSONL` / `KG_RELATIONS_JSONL` | — | 逐行产物，便于增量与抽查 |
| `KG_LLM_CKPT` / `KG_LLM_RESULTS` | — | 断点续抽的检查点与结果 |
| `KG_LLM_MIN_ENTITIES` | `3` | 第 1 层实体命中数达到该值才送 LLM 抽取：**调大 = 更快但召回更窄** |
| `KG_LLM_MAX_BLOCKS` | `3000` | LLM 抽取块数上限（控制总耗时；本机约 500 块/小时） |
| `KG_SUBGRAPH_MAX_NODES` | `60` | 子图节点与事实条数上限（防上下文爆炸）；**调大提升召回但增加 LLM 输入与耗时** |
| `KG_SUBGRAPH_HOPS` | `2` | k-hop 半径；1 = 只取直接邻居，3 = 更全但更慢 |
| `KG_LLM_TIMEOUT_S` / `KG_LLM_RETRY` | `60.0` / `2` | 单块抽取超时与重试 |
| `KG_FUSION_WEIGHTS` | `graph 0.35 / vector 0.40 / fulltext 0.25` | 三路融合权重；**提高 graph 权重会让答案更依赖图谱事实** |
| `KG_FUSION_METHOD` | `weighted` | 可选 `rrf` |
| `PROMPTS_DIR` | `prompts/` | 外置 Prompt 目录（问答与抽取） |
| `WORKORDER_ID` | 本工单编号 | 报告等产物的自标识 |

> 与本机环境相关的既有配置（模型路径、Qdrant 模式等）见 `src/config.py` 与 `docs/01`。

## 五、二次开发指引

### 5.1 换成自己的 PDF 语料

1. 把 PDF 放进 `data/corpus/`（或改 `config` 中的语料目录）；
2. 若换公司/行业：更新 `src/kg_dict.py` 的 `COMPANY_TABLE`（名称、别名、股票代码、行业）
   与 `INDUSTRIES`；否则公司实体识别不到，`Company` 相关三元组全部落空；
3. 重新执行 `python build_index.py` 与 `python build_kg.py --layer1`；
4. 评测问题集换成自己的 `data/eval/ground_truth.json`（字段：`id/question/key_facts/qtype/origin`）。

> 问答页另提供**上传 PDF** 的入口（`src/upload_index.py` + `graph_qa.ask_uploaded`）：
> 上传的文档走**会话级内存索引**（向量 + BM25 混合 → Reranker 精排），
> **不写入** Qdrant / 倒排 / 图谱 —— 一份临时文档混进全局库会污染后续所有问答的取数来源。
> 若要让新语料进入**知识图谱**通道，仍需按上面的步骤重建（见 `docs/09` 用户手册第 2 节）。

### 5.2 改 Prompt

- 问答/研报：`prompts/graph_qa.yaml`（`system_zh` / `system_en` / 研报结构）；
- 抽取：`prompts/kg_extract.yaml`；
- 改完直接生效（每次读取，无需改代码）；抽取 Prompt 的类型清单由本体的 `ENTITY_TYPES`
  自动渲染（`kg_prompt._render_type_block`），改本体即可同步。

### 5.3 新增实体/关系类型

1. 在 `src/kg_schema.ENTITY_TYPES`（或 `RELATION_TYPES`）中登记，并在 `RELATION_TYPES`
   里声明合法的 head/tail 类型；
2. 在 `ENTITY_COLORS` 中给新实体类型配色（可视化用）；
3. 若是规则可抽的类型：在 `src/kg_extract.extract_block` 中增加规则分支；
   若是 LLM 抽取：只需改本体，Prompt 的类型清单会自动包含；
4. 补测试（参照 `tests/test_kg_org_extract.py` 的写法：先写规格测试再实现）；
5. `python build_kg.py --layer1`（秒级）重建验证。

### 5.4 调性能

- 目标：单题 ≤3 秒。实测均值 2.44s，最慢题 6.06s（LLM 生成占大头）。
- 手段：`KG_SUBGRAPH_MAX_NODES` 调小（减少 LLM 输入）、`use_cache=True`（同题缓存）、
  `graph_qa.warmup()`（启动预热模型）、`KG_LLM_MAX_BLOCKS` 控制离线抽取规模。
