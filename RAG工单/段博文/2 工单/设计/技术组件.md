# 技术组件说明

> 工单编号：人工智能NLP-RAG-基于PDF文档的问答系统优化

## 一、组件总览

| 层次 | 组件 | 技术选型 | 版本 | 作用 |
|---|---|---|---|---|
| 前端 | Web 聊天界面 | 原生 HTML/CSS/JS | - | 问答对话、知识库管理、来源展示 |
| 服务层 | API 服务 | FastAPI + Uvicorn | 0.115+ | RESTful 接口、静态页托管、SSE 流式输出 |
| 文档解析 | PDF 解析器 | PyMuPDF (fitz) | 1.24+ | 按页提取文本、清洗去噪 |
| 文本切分 | 递归分块器 | 自研（分隔符递归） | - | chunk=400 / overlap=50，共 1621 块 |
| 向量化 | 嵌入模型 | BGE-M3（本地权重） | 1024维 | 中文语义向量，CPU 推理 |
| 向量库 | Milvus | Milvus 2.x (Docker) | rag_pdf_qa_v2 | AUTOINDEX 索引 + COSINE 度量 |
| 关键词检索 | BM25 | rank_bm25 + jieba | - | 中文分词、内存索引、启动时从 Milvus 全量构建 |
| 融合 | RRF 融合 | 自研 | k=60 | 向量/BM25 两路结果倒数排名融合去重 |
| 精排 | 重排模型 | bge-reranker-large（本地） | - | CrossEncoder 对候选打相关性分 |
| 生成 | 大模型 | DeepSeek API | deepseek-chat | 基于引用生成答案，max_tokens=768，T=0.1 |
| 缓存 | LRU 结果缓存 | cachetools | 256条 | 重复查询约 3ms 返回，入库自动失效 |
| 日志 | 运行日志 | logging | - | 按天滚动 rag_pdf_qa_v2.log |

## 二、关键数据流

```text
入库：PDF → PyMuPDF 解析 → 清洗 → 切分(400/50) → bge-m3 向量化
      → Milvus 写入(批25) → 重建 BM25 → 清空缓存

问答：提问 → 查缓存(命中≈3ms 直接返回)
      → 向量召回Top6 ∥ BM25召回Top6 → RRF 融合
      → bge-reranker 精排 Top3 → 阈值 0.25 过滤
      → DeepSeek 生成(768 tokens) → 写缓存 → 返回
```
