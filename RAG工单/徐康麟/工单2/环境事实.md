| 模型 | 用途 | 实测表现 |
| --- | --- | --- |
| `bge-m3:latest` | **多语言嵌入，1024 维** | 2 条 query 编码 6.44 s（首次含加载），余弦 0.689 |
| `bge-large:latest` | 中文嵌入，1024 维 | 2 条 query 1.36 s |
| `qwen2.5:3b` | **主力生成模型** | **首字 0.20 s / 总耗时 0.95 s**，答案准确且自带 `[页码: 129]` 引用 |

**结论：本机可以完整跑通「LLM 生成 + 引用」的 RAG 链路，并能满足「首字 ≤ 3 秒」**。

### 3.1 统一 LLM 访问层（必须实现）

在 `研发/app/core/generator.py`（或独立 `llm_client.py`）实现**可插拔后端**，按优先级：

### 4.1 独立复核结论：**靶心是「排序」与「生成采纳」，不是「召回」**

> 结论先行（已按 tester 第四次复核更正）：**0 题因证据未被召回而失败**。
> 基线流水线把证据拉进了最终上下文 **10/10**，但：
> - **纯向量排序 top-5 仅 2/10**（证据落在 12~71 名）→ 检索层要改的是**排序**；
> - **95/957 证据已在上下文（第 3 / 第 8）却被答成别的页**，
>   **33/531/793 证据就是上下文第 1 名却答案形态不合口径** → 生成层要改的是**采纳与答案组织**。
> - **最强证据**：同一索引、同一次检索、同一把 `check_answer` 尺子下，
>   基线**抽取式路径在 10 题上接近全对**（两次独立复算 1078/1078 与 1076/1082），
>   而 **LLM 路径只有 50%**（见 §4.1.2(b)）。
>
> 所以优化优先级是：**生成端（第一）→ 排序（第二）→ 解析/分块（第三，用自身指标证明）**。
> **不要**再把问题描述成"检索找不到证据"。

   tokenize("5,520.00 万元") -> ['5', '520', '00', '万元']
   tokenize("15,000.00万元") -> ['15', '000', '00', '万元']
   tokenize("82.10%")       -> ['82', '10']
   ```
   即 `PUNCT_PATTERN = [^\w\u4e00-\u9fff]+` 把**逗号与小数点都替换成空格**，金额被拆成碎片。

**➡ 结论：不是"索引里查不到"，而是"查询侧没给数字"。这是一条可直接转化为优化措施的线索。**
可行的修复方向（任选或组合）：①保留**数字/金额的完整词元**（不要在逗号与小数点处切分）；
②对数字型意图的问题做**查询扩展**，注入金额模式或相关数值线索；
③把 `万/亿/元/%` 从 STOPWORDS 移出或特殊处理。

### 4.2 判分口径（必须沿用，不可放宽）

工单1 `app/core/evaluator.py::check_answer` 是**确定性判分**（不依赖 LLM 裁判），顺序：

1. 去标点后参考答案是答案子串（或反之）
2. **参考答案的全部金额都出现在答案里**（按元折算，容忍 `5,520` 与 `5,520.00 万元`、`1.5 亿元` 与 `15,000 万元`）
3. 关键实体（引号内名称）有交集
4. **参考答案的全部百分比**都出现在答案里
5. 字符二元组 Jaccard ≥ 阈值，**且必须不缺任何数字**（含百分比）

工单2 的 `evaluator.py` 必须**复制并沿用**该判分逻辑（在 `工单2/测试/测试数据/golden_qa.jsonl` 上），
保证「优化前 50% → 优化后 ≥90%」是同一把尺子量出来的。**调低判分标准使准确率虚高 = 造假，禁止。**

#### 4.2.1 已实测固定的判分用例（designer 在 T1 中用真实 `check_answer` 跑出，T3 直接落成用例）

**判错（Negative，必须 `is_correct == False`）**：

| 编号 | 形态 | 说明 |
| --- | --- | --- |
| N-1 | 多值漏答 | 参考答案 4 个比重，回答只给其中 1 个（即基线 Q33 的形态） |
| N-2 | 单位错 | 金额单位错误或量级不符 |
| N-3 | 答非所问 | 回答与参考答案无实质交集 |
| N-4 | 只给合计 | 参考答案为分项，回答只给合计值 |

**判对（Positive，必须 `is_correct == True`）**：

| 编号 | 形态 | 说明 |
| --- | --- | --- |
| P-1 | 金额等价（跨单位） | `1.5 亿元` 与 `15,000 万元` 互认 |
| P-2 | 金额等价（小数位） | `5,520` 与 `5,520.00 万元` 互认 |
| P-3 | 完整句 | 参考答案为答案子串（忽略标点） |

#### 4.2.2 口径固有容忍（**不得**当作"判分被放宽"的证据）

实测：「法定代表人是程家的**明**」（故意插入错别字）仍被判 **True**——
原因是二元组 Jaccard 达 `0.70 ≥ 0.62` 的阈值，且未缺任何数字，落入第 5 条模糊判据。

这属于工单1 判分口径的**固有容忍度**，不是工单2 引入的放宽：

- ❌ T3 **不得**把它写成「判分被放宽」的用例；
- ❌ T3/T5 **不得**修改 `FUZZY_THRESHOLD`（默认 0.62）来"修复"它——改阈值会同时改变基线判定，
  使「优化前 50%」不再可比，等同篡改评估口径；
- ✅ 正确做法：在 `test_evaluator_v2.py` 中把它固化为**边界用例**，断言其判 True，
  并在测试注释与本报告中如实说明这是口径固有容忍度。
