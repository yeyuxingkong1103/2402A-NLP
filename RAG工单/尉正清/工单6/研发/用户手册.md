# 用户手册

**工单编号**：人工智能NLP-RAG-混合检索任务

本手册面向使用者，介绍如何上传 PDF、如何提问、如何查看结果。

---

## 一、启动系统

在 Linux 服务器上执行：

```bash
bash 部署/start.sh          # 启动，默认端口 7860
```

浏览器打开 `http://<服务器IP>:7860` 即可看到界面。停止服务执行 `bash 部署/stop.sh`。

> Windows 本机调试可直接运行：`python 研发/app.py`

---

## 二、上传 PDF 文档

1. 点击界面左上角的 **「上传 PDF（必填） / Upload PDF」** 区域，**可一次选择多个 PDF**（工单3 支持同时挂载《招股说明书1》《招股说明书2》）
2. 保持 **「使用缓存 / Use cache」** 勾选（推荐）：
   - 首次解析该文档：约 80 秒（解析 548 页 + 向量编码）
   - 之后再次使用：约 10 秒（直接读缓存）
3. 点击 **「初始化知识库 / Build knowledge base」**
4. 观察下方 **「状态 / Status」** 栏，出现下面这行即表示成功：

   ```
   初始化完成：招股说明书1.pdf | 548 页文字、477 个表格，共 1759 个块
   ```

> 若提示「初始化失败」，请检查文件是否为有效 PDF、以及 `BGE_M3_PATH` 指向的向量模型是否存在。

## 三、多文档问答（工单3）

系统支持同时挂载多份招股说明书，提问时**按问题里的公司名自动路由**：

| 问题里出现的公司 | 检索的文档 |
|---|---|
| 武汉兴图新科电子股份有限公司 | 招股说明书1 |
| 武汉力源信息技术股份有限公司 | 招股说明书2 |

无需手动切换。若问题没提到任何已挂载的公司名，系统会在所有文档里检索后合并。

## 四、图表类问题（工单4）

系统能回答**只看图才能答的问题**，例如：

- 「组织结构图中，销售部有几个部门构成，其中大客户销售部有几个销售处构成？」
- 「从 2008 年中国 IC 市场应用结构与增长图中可以看出，增长率最快的是哪个行业？负增长的是哪个行业？」

原理是建库时把 PDF 里的图表交给多模态模型转成文字描述，与正文一起入库。
**代价是首次初始化变慢**（图表约 18 秒/页，两份招股书合计约 25 分钟），
之后走缓存不受影响。

如果换用不支持图像输入的模型，图表页会被跳过并在日志中记录，其它功能不受影响。

## 五、多轮对话（工单5）

系统支持**连续追问**，可以用代词或不完整的问句：

```
你：报告期内，武汉兴图新科电子股份有限公司来自军用领域的收入分别是多少？
你：他参与的哪个工程荣获了国家科技进步一等奖？          ← 「他」自动指上一轮的公司
你：这个公司的法定代表人是谁？                          ← 「这个公司」同上
你：那武汉力源信息技术股份有限公司呢？                   ← 自动补成「…的法定代表人是谁？」
你：武汉力源信息技术股份有限公司组织结构图中，哪个销售部的销售处最多？
```

界面上方有**对话历史**区，会保留整段对话。每次提问时下方「元信息」栏会写明
这一轮**有没有改写、怎么改的**：

```
多轮改写：这个公司的法定代表人是谁？ → 武汉兴图新科电子股份有限公司的法定代表人是谁？
        （指代消解（「这个公司」→「武汉兴图新科电子股份有限公司」））
```

点 **「清空对话 / Clear」** 可以重置上下文，之后的问题将作为新话题处理。

> 想让系统知道「他」指的是谁，前提是**先问过一个带公司名的问题** ——
> 上下文里没有主体可用时，改写会退化为原样。

## 六、选择检索策略（工单6）

界面上可以切换三种检索策略、调整权重、更换重排算法：

| 控件 | 说明 |
|---|---|
| **检索策略** | 向量检索 / 全文检索 / 混合检索 |
| **向量权重 alpha** | 仅混合检索生效；alpha 是向量那一路的权重，全文取 1-alpha |
| **重排算法** | 不重排 / TF-IDF / 反馈自适应 / LLM |

**怎么选**：

- **混合检索（默认，推荐）** —— 实测准确率与召回率都是 100%
- **向量检索** —— 问句与原文用词不一致时更稳（看语义）
- **全文检索** —— 找精确术语、编号、人名时最快（0.9 毫秒）；但**单独用**实测
  准确率只有 81%、召回率 90%，不建议作为唯一策略
- **重排** —— 默认不重排。术语密集的问题可以试 TF-IDF 重排；
  点过 👍/👎 之后可以试反馈自适应重排

**全文检索的查询语法**（在问题框里直接写）：

```
军用 AND 收入      布尔：两个词都要有
-民用              布尔：排除含「民用」的
"军用领域"          短语：整串匹配
注册资~1           模糊：容错一个字的差异
```

## 七、提问

### 方式一：文字输入

在 **「请输入问题 / Ask a question」** 输入框中输入问题，按回车或点击 **「提问 / Ask」**。

支持**中文和英文**提问，系统会自动识别语种并用同一种语言作答。

### 方式二：语音输入

点击 **「语音输入 / Voice input」** 区域开始录音，说完后停止，识别结果会自动填入问题框，再点「提问」。

支持中英文自动识别。

### 方式三：使用工单预置问题

界面中部有 **「选择工单测试问题 / Pick a work-order test question」** 下拉框，选中任意一条即可自动填入问题框。这是工单指定的 10 个验收问题。

### 选择回答模式

界面右侧 **「回答模式 / Mode」** 有两个选项：

| 模式 | 说明 |
|---|---|
| **RAG（BGE-M3 检索）** | 先从文档检索相关内容再作答，答案会注明依据页码（默认） |
| **纯 LLM（不检索）** | 直接问大模型，不查文档。用于对比实验 |

## 八、查看结果

提问后界面下方会显示三块内容：

| 区域 | 内容 |
|---|---|
| **回答 / Answer** | 生成的答案，RAG 模式下会注明依据页码，如「根据第 343 页」 |
| **检索到的上下文 / Retrieved context** | 实际送去给大模型的文档片段，格式为 `[第N页-类型] 正文`。类型为 `text`（正文）或 `table`（表格） |
| **元信息 / Metadata** | 本次提问的耗时、识别出的意图、语种、消歧词、子问题数量 |

**元信息示例**：

```
耗时 2.05s | 意图：数据查询 | 语言：zh | 消歧：报告期、公司 | 子问题：0 个
```

其中「耗时」即工单要求的响应时间，应不超过 3 秒。

## 九、反馈

对回答满意就点 **「👍 回答正确 / Good」**，不满意就点 **「👎 回答有误 / Bad」**。
反馈会追加记录到 `研发/feedback.jsonl`，可用于后续分析。

## 十、知识库管理

界面中部的 **「知识库管理 / Knowledge base」** 一行用于管理已建立的文档索引：

| 操作 | 说明 |
|---|---|
| 下拉框 | 列出 `研发/kb_cache/` 下所有已建立的知识库 |
| **加载 / Load** | 直接加载选中的知识库，无需重新上传 PDF 和解析（约 10 秒） |
| **删除 / Delete** | 删除选中的知识库缓存 |

**典型用法**：换一份 PDF 之前先删除旧缓存；或直接点「加载」切换到之前建好的知识库。

## 十一、常见问题

**Q：初始化很慢，正常吗？**
首次解析 548 页 PDF 并做向量编码约需 80 秒，属正常。之后勾选「使用缓存」会降到约 10 秒。

**Q：提问返回「[大模型调用失败]」？**
说明 DeepSeek 接口调用失败。请检查 `DEEPSEEK_API_KEY` 是否配置、网络是否可达 `api.deepseek.com`。

**Q：语音输入提示「未安装 faster-whisper」？**
执行 `pip install faster-whisper`。首次使用会自动下载识别模型，需要联网。

**Q：回答内容和文档对不上？**
先点「显示检索上下文」查看实际检索到的片段。若检索结果本身不对，可在「知识库管理」里删除缓存后重新初始化。

**Q：响应时间超过 3 秒？**
通常是网络波动或大模型负载高。可关闭「Query 理解」（本项目已改为规则实现，关闭与否对结果影响很小），或检查 GPU 是否正常启用。
