# RAG 性能瓶颈识别与优化方案

> 工单编号: 人工智能 NLP-RAG 项目-RAG 性能瓶颈识别与优化
> 目标: 检索返回时间 < **3 秒**

## 一、RAG 典型 5 阶段 (每个都可能是瓶颈)

```
用户 Query
  │
  ├─ ① Query 处理与增强 (query rewrite, hyDE, 子问题拆分)  ── 瓶颈 A
  │
  ├─ ② 检索阶段 (向量/关键词/图谱, Top-K)                  ── 瓶颈 B ⭐ 最常见
  │
  ├─ ③ 上下文组装 + Prompt 工程 (chunk 拼接, 去重, 压缩)    ── 瓶颈 C
  │
  ├─ ④ LLM 生成 (API 调用, 本地推理)                       ── 瓶颈 D ⭐ 最重
  │
  └─ ⑤ 后处理 (格式化, 引用, 校验)                         ── 瓶颈 E
```

## 三、6 大常见瓶颈 + 对应优化

### 瓶颈 B: 向量检索慢 (最常见)
- **原因**: 向量库未索引 / 全量扫描 / HNSW 参数不当
- **优化**: ✅ FAISS IVF-PQ / HNSW / 预量化 / 缓存

### 瓶颈 D: LLM 生成慢 (最重)
- **原因**: 大模型 / API 延迟 / 长上下文
- **优化**: ✅ 小模型 / 本地推理 / 流式生成 / 上下文剪枝 / 缓存

### 瓶颈 A: Query 增强慢
- **原因**: 多轮 LLM 调用做 rewrite
- **优化**: ✅ 规则 rewrite / 跳过 / 缓存

### 瓶颈 C: 上下文组装慢
- **原因**: 拼接超长 / 去重复杂 / rerank 重
- **优化**: ✅ Top-K 剪枝 / 预拼接模板 / 去重哈希

### 瓶颈 E: 后处理慢
- **原因**: 复杂引用校验 / 格式化
- **优化**: ✅ 规则后处理 / 异步

### 瓶颈 X: 全流程串行
- **原因**: 阶段间串行依赖
- **优化**: ✅ 并行处理 (asyncio / 多线程)

## 四、优化前后预期对比

| 指标 | 优化前 (基线) | 优化后 (目标) | 提升 |
|------|--------------|--------------|------|
| **端到端延迟** | ~5-8s | **< 3s** | ↑ 60% |
| Query 处理 | ~0.8s | ~0.1s | ↑ 87% |
| 检索 | ~1.5s | ~0.3s | ↑ 80% |
| 上下文组装 | ~0.5s | ~0.1s | ↑ 80% |
| LLM 生成 | ~3.0s | ~1.8s | ↑ 40% |
| 后处理 | ~0.3s | ~0.05s | ↑ 83% |
