## 3. 核心模块技术梳理 deepdoc_analyse.md

1. 任务触发链路
用户 Web 上传 PDF，选择解析类型 paper /table/one /knowledge_graph；前端 http 请求提交任务；参数封装投递进入**Redis Stream 消息队列**。
Task‑Executor 持续消费该队列，调用`do_handle_task()`主函数处理任务。
2. do_handle_task () 核心逻辑

- 根据传入 paper_type 选择对应 parser 解析器；
- 调用 layout_recognizer 布局识别，区分文本块、图片、表格、标题；
- 如果是图片扫描 PDF，调用 paddleocr_parser 做整页 OCR 识别；
- figure_parser 提取图纸图表信息；
- postprocess 做识别结果清洗、乱码修正；
- 执行文本分块策略，不同 paper_type 分块参数不同；
- 调用 Embedding 模型做向量化；
- 向量写入向量数据库，完成知识库构建。

3. PDF 解析器区分

- pdf_parser：只处理原生可复制文本 PDF，扫描图片 PDF 会提取不到内容；
- paddleocr_parser：扫描图片 PDF，每页图片 OCR 识别文字，工业图纸 PDF 必须选用；
- figure_parser：专门抽取图表、示意图、部件标号。

## 4. 脚本说明

1. **pdf_ocr_fix.py**
本地预处理脚本：对图片型 PDF 做前置 OCR 识别，输出带可编辑文本的 PDF，作为输入给到 RAGFlow，缓解低分辨率图纸 OCR 识别错误。
2. **test_ragflow_api.py**
调用 RAGFlow 开放 API，批量导入 6 条测试问题，自动记录返回回答，对比标准答案，输出测试报告 json。

## deepdoc_analyse.md 路径：`工单14/研发/deepdoc_analyse.md`
```markdown
# DeepDoc模块技术梳理
## 1.RAGFlow整体任务调度流程
1. 用户在Web页面上传PDF文件，选择解析方案（paper / table / one / knowledge_graph / resume等）。
2. Web API Server接收请求，组装解析参数：paper_id、paper_type、文件二进制流、切片参数。
3. 将解析任务推送至 **Redis Stream消息队列**。
4. Task Executor任务执行进程持续消费Redis Stream队列，调用核心处理函数`do_handle_task()`。
5. do_handle_task完成解析、布局识别、OCR、图表抽取、分块、向量化、入库；任务状态回写数据库。

## 2.do_handle_task()关键逻辑
1. 参数接收：paper_id、paper_type、文件路径、切片配置。
2. 根据paper_type路由到对应parser解析器：
    - paper：科技论文、专利文档解析链路；
    - table：侧重表格抽取；
    - one：通用普通文档；
    - knowledge_graph：图谱抽取模式。
3. LayoutRecognizer布局分析：页面分块，识别标题、段落、图片、表格、公式区域。
4. 判断文档类型：原生文本PDF直接pdf_parser；图片扫描PDF进入paddleocr_parser OCR流水线。
5. figure_parser图表解析：提取图纸、示意图，提取图内标号、部件信息。
6. postprocess后处理：OCR纠错、乱码字符清洗、合并被切割的句子。
7. 分块策略：不同paper_type使用不同chunk_size、overlap；paper模式会尽量保证图文上下文不被拆分。
8. 文本向量化，调用Embedding模型。
9. 向量、文本块写入向量数据库，标记任务完成。

##3.deepdoc parser目录解析器清单
|文件|功能|
|---|---|
|pdf_parser.py|原生文本PDF解析，直接提取pdf内置文本，**不能处理扫描图片PDF**|
|paddleocr_parser.py|基于PaddleOCR的图片/PDF扫描件解析；逐页图片OCR识别文字，工业图纸PDF核心解析器|
|figure_parser.py|图表、示意图、技术图纸解析，提取图号、部件编号|
|docx_parser / excel_parser / ppt_parser|Office系列文档解析|
|mineru_parser|第三方MinerU解析引擎适配器|
|txt_parser / md_parser|纯文本、markdown解析|

##4.工业图片PDF踩坑点
1. 如果使用默认pdf_parser处理扫描图片PDF，提取文本为空，图纸信息全部丢失。
2. OCR识别图纸小字标号容易乱码，需要开启图片放大预处理，后处理字符纠错。
3. 布局识别错误会导致图纸图片和对应的说明文本分到不同切片，问答时图文割裂，回答图纸部件问题错误。
4. chunk过小，单条图文信息被切割；chunk过大引入大量无关噪声文本。
