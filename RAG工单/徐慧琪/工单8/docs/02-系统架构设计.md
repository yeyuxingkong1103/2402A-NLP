> 工单编号：人工智能NLP-RAG-基于GraphRAG实现金融问答

# 系统架构设计

本工程在工单07（混合检索 RAG）之上叠加**知识图谱**能力，形成 Graph RAG：
图谱负责**关系与结构**（可确定地取数），向量/全文负责**叙述性内容**（语义召回），
二者融合后交给本地 LLM 生成答案。

---

## 一、Graph RAG 总体流程

```
                    ┌──────────────── 离线：知识图谱构建 ────────────────┐
 ccf_competition    │                                                    │
   .zip 语料  ──►  PDF解析  ──►  实体关系抽取  ──►  图谱构建  ──►  data/kg/
                 (PyMuPDF/表格/   第1层 词典+正则     NetworkX       kg.pkl
                  组织图/MinerU)  第2层 LLM（可选）    + 消歧归一      kg.graphml
                    │                                    │            *.jsonl
                    └──► 分块 → 嵌入 → Qdrant / BM25 倒排索引（复用 07）

                    ┌──────────────── 在线：问答链路 ────────────────┐
 用户提问 ──► 实体识别与链接 ──► 子图检索 ──► 图+向量融合 ──► Reranker ──► LLM 生成
              (词典最长匹配      (四模式：      (三通道按页去重   精排        (带防幻觉
               + 图谱别名兜底)    khop/metric_   拼装上下文)     (复用07)     约束+降级)
                                   compare/
                                   org_tree/path)
                    └──► 输出三部分：答案 / 检索结果(文本块+页码) / 图谱结构
```

## 三、技术选型与理由

| 组件 | 选型 | 理由 |
| --- | --- | --- |
| Graph RAG 框架 | **自研编排**（借鉴 Microsoft GraphRAG 的社区摘要思想） | 工单允许自研。LangChain `GraphCypherQAChain` 只对接 Neo4j/Cypher，NetworkX 后端仍需自写适配器，反而增加胶水代码；自研可最大化复用 01~07，且与工单07 **逐题严格可比** |
| 图数据库 | **NetworkX + 自研持久化**（GraphML + pickle + JSONL） | 已装、零下载（符合工单「禁止下载」硬约束）；支持增量构建与多文档融合；429 行的 `kg_store.py` 已覆盖本项目全部查询需求 |
| 实体/关系抽取 | **分层**：第 1 层词典+正则（确定性、零幻觉）+ 第 2 层本地 LLM（限量、带 evidence 校验） | 本机**无 UIE/Spacy 等专用 NER 权重**（见 `docs/01`）。词典+正则可作**可信骨架**，LLM 只在不确信的关系上补充 |
| 嵌入模型 | bge-m3（1024 维） | 复用 01~07，本机已有 |
| Reranker | bge-reranker-v2-m3 | 复用 06，本机已有 |
| 向量库 | Qdrant（本地嵌入式） | 复用 01~07；嵌入式模式**同目录单实例**，冲突时给出明确处置建议 |
| 全文检索 | 自研倒排索引 + BM25 | 复用 01~07 |
| LLM | Ollama `qwen2.5:3b` | 本机已有；负责答案生成、研报生成、可选的关系抽取 |
| PDF 解析 | PyMuPDF（文本+表格）+ 组织图解析 | 复用 01~04；MinerU 不可用时自动回退 |
| 界面 | Streamlit | 复用 07，新增图谱/实体关系页签 |
| 评估 | 自研关键事实覆盖率（`fact_recall`） + 复用工单07 金标准 | 与 07 同源问题集、同口径，逐题严格对齐 |

## 四、数据流

### 4.1 离线构建链路

```
ccf_competition.zip（已解压至 data/corpus/）
   │
   ├─► PDF 解析 ──► 分块 ──► 嵌入 ──► Qdrant          （复用 07，产物 data/qdrant/、data/chunks/）
   │                    └──► BM25 倒排索引             （产物 data/index/）
   │
   └─► 图谱链路（本工单）
        第1层：kg_extract.extract_block（全量 7757 块，0.4 秒）
             指标三元组 / 公司-行业 / 组织隶属
        第2层：kg_select → kg_extract_llm（LLM，断点续抽，可选、限量）
             kg_prompt 三道闸门校验 → 只保留带 evidence 且类型合法的关系
        归一：kg_dedup（别名 + 规则）
        入库：kg_store.save（原子写：*.tmp → os.replace）
        产物：data/kg/kg.pkl、kg.graphml、kg_entities.jsonl、kg_relations.jsonl、kg_stats.json
```

### 4.2 在线问答链路（`graph_qa.ask`，实测均值 2.44s）

```
问题
 ├─► 实体识别与链接（graph_retriever.link_entities：词典最长匹配 + 图谱别名兜底 + LRU 缓存）
 ├─► 模式判定（detect_mode）：metric_compare > org_tree > path > khop
 ├─► 子图检索（四模式）→ SubgraphResult{facts, nodes, edges, source_pages}
 ├─► 文本检索（复用 07：向量 + 全文 → RRF 融合 → Reranker 精排）
 ├─► 三路融合（graph_fusion：按页去重、分区组装上下文）
 └─► LLM 生成（防幻觉约束；LLM 不可用时退化为抽取式答案并标 degraded）
```

计时埋点（`QaResult.timings`）：`link` / `subgraph` / `retrieve` / `generate` / `total`，
界面「状态」页与评测结果均据此展示。

## 五、与工单07 的复用边界

| 边界 | 内容 |
| --- | --- |
| **零改动复用** | PDF 解析、分块、嵌入、Qdrant、BM25、Reranker、Query 理解、多轮对话、LLM 调用封装 |
| **适配层** | `graph_fusion.py` 把图谱事实与 07 的召回结果按页合并；`graph_qa.py` 组织完整链路并对 07 的检索结果做精排 |
| **新增** | 全部 `kg_*.py` / `graph_*.py`、`speech.py`、`runtime_ext.py`、`compare_with_wo07.py`、`graph_qa_cli.py`、`app.py` 的图谱与实体关系页签 |

**为什么强调这条边界**：Q1~Q10 与工单07 同源同金标准，且底层检索零改动，
因此两份结果的差异**可以归因到图谱本身**，而不是检索器换了实现（见 `docs/06`）。
