## 一、实现步骤

### 步骤 1：创建 Dockerfile

**目标**：构建 RAG 金融问答系统的 Docker 镜像。

**关键决策**：
- 基础镜像选择 `python:3.10-slim`，体积小、兼容性好
- 安装系统依赖（gcc、libfreetype6 等）以支持 PyMuPDF、jieba、OCR
- 设置 `PYTHONUNBUFFERED=1` 确保日志实时输出
- 添加 `HEALTHCHECK` 用于容器健康检查

**命令**：
```bash
docker build -t rag-finance:latest .
```

---

### 步骤 2：创建 docker-compose.yml

**目标**：编排 Milvus、etcd、MinIO、RAG 应用四个服务。

**关键决策**：
- Milvus standalone 模式，依赖 etcd 和 minio
- 使用 Docker 卷持久化所有数据（向量、元数据、对象存储、应用数据、模型、日志）
- 统一网络 `rag-net`，容器间通过服务名通信
- 应用容器通过 `depends_on` 等待 Milvus 启动
- 入口脚本 `entrypoint.sh` 主动等待 Milvus 就绪

**命令**：
```bash
docker-compose up -d --build
```

---

### 步骤 3：编写 entrypoint.sh

**目标**：容器启动时执行初始化逻辑。

**功能**：
1. 等待 Milvus 服务就绪（最多 30 次重试，每次间隔 5 秒）
2. 检查模型文件是否挂载
3. 创建日志目录
4. 打印配置信息
5. 启动 FastAPI 服务

---

### 步骤 4：配置环境变量

**目标**：通过 `.env` 文件管理敏感配置。

**配置项**：
- `LLM_API_KEY`：DeepSeek API 密钥
- `LLM_BASE_URL`：DeepSeek API 地址
- `MILVUS_URI`：Milvus 连接地址
- `EMBED_MODEL_PATH`：向量模型路径
- `RERANK_MODEL`：重排模型路径

---

### 步骤 5：部署与测试

**命令**：
```bash
# 构建并启动
docker-compose up -d --build

# 查看日志
docker-compose logs -f rag-app

# 健康检查
curl http://localhost:8000/api/health

curl -X POST http://localhost:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"query": "平安银行2019年的董事长是谁？"}'
```

## 二、遇到的问题及解决方案

### 问题 1：Milvus 启动慢，应用连接超时

**现象**：`rag-app` 容器启动时 Milvus 尚未就绪，连接报错。

**原因**：Milvus 需要等 etcd 和 minio 都就绪后才能启动，而 `depends_on` 只保证启动顺序，不保证就绪。

**解决方案**：在 `entrypoint.sh` 中添加 Milvus 就绪检测循环，最多重试 30 次，每次间隔 5 秒。

```python
from pymilvus import MilvusClient
for i in range(30):
    try:
        client = MilvusClient(uri="http://milvus:19530")
        break
    except Exception:
        time.sleep(5)
```

---

### 问题 2：模型文件过大，镜像构建慢

**现象**：将模型文件打包进镜像会导致镜像体积超过 10GB，构建和推送极慢。

**解决方案**：使用 Docker 卷挂载模型文件，不打包进镜像。在 `docker-compose.yml` 中挂载 `rag-models` 卷到 `/models`。

```yaml
volumes:
  - rag-models:/models
```

首次运行时可将模型文件复制到卷中：
```bash
docker run --rm -v rag-models:/models -v /host/models:/host alpine cp -r /host/bge-m3 /host/bge-reranker-large /models/
```

---

### 问题 3：中文乱码

**现象**：容器内 jieba 分词、日志输出出现乱码。

**原因**：容器默认 locale 不是 UTF-8。

**解决方案**：在 Dockerfile 中设置环境变量：

```dockerfile
ENV LANG=C.UTF-8 \
    LC_ALL=C.UTF-8
```

---

### 问题 4：容器间网络不通

**现象**：应用容器无法连接 Milvus 容器。

**原因**：服务未加入同一网络，或使用了 `localhost` 而非服务名。

**解决方案**：
1. 所有服务加入 `rag-net` 网络
2. 应用通过服务名 `milvus` 访问，而非 `localhost`

```yaml
environment:
  - MILVUS_URI=http://milvus:19530
```

---

### 问题 5：数据丢失

**现象**：容器重启后 PDF 数据和向量索引丢失。

**原因**：未使用 Docker 卷，数据存储在容器可写层。

**解决方案**：使用 Docker 卷持久化所有关键数据：

```yaml
volumes:
  - rag-data:/app/data        # PDF 数据
  - rag-models:/models        # 模型
  - rag-logs:/app/logs        # 日志
  - milvus-data:/var/lib/milvus  # 向量索引
```

---

### 问题 6：端口冲突

**现象**：宿主机 8000 端口被占用，容器启动失败。

**解决方案**：修改 `docker-compose.yml` 中的端口映射：

```yaml
ports:
  - "8001:8000"   # 主机 8001 映射到容器 8000
```
