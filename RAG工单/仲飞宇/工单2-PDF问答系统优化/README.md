## 代码在哪

**本项目（工单01→02→03）是同一份代码，代码在隔壁的 `../工单3/` 目录。**

工单03 是工单02 的**超集**：工单02 的检索剖面与全部数字在 `../工单3/` 的代码里
**原样可复现**（工单03 只加了第二份文档的支持，没有改动书1 的检索链路，
实测书1 的 10 道题规则命中仍是 10/10、页级指标还略有提升）。

复现工单02 的对比表：

```bash
cd ../工单3
PY=~/rag-data/venv/bin/python

# 只灌书1（工单02 的语料）
$PY scripts/ingest.py

# 三剖面横向对比 —— 优化方案第四章的数字来源
$PY scripts/eval.py --compare all

# 另外两项专项实验
$PY scripts/chunker_ablation.py     # 分块层对照（离线，不需要向量库）
$PY scripts/sweep.py                # 检索参数扫描（两阶段）
```

## 三点口径提醒（验收前必读）

1. **响应时间口径 = TTFT**，判据看「TTFT ≤ 3s 的题数」而不是 P95 —— n=10 时 P95 就是最大值，
   单个离群点就能拉爆。
2. **评估不吃响应缓存**：缓存实现在 `api/`，而评测器直接调 `core/`，所以 TTFT 数字是真的。
3. **页级精确率偏低是正常现象**：招股书同一事实会在十几页重复披露，而 `evidence_page`
   只登记 1–2 页权威出处。判断检索质量看**规则命中**与 **CKC**（上下文关键词覆盖率）。
