# 金融问答系统 · 性能测试报告

> **工单编号：人工智能 NLP-RAG-金融问答系统部署**
> 测试对象：以 Docker 容器部署后的金融问答服务（`finqa-app`）
> 测试方式：全部在**真实运行的容器**内执行，指标由程序测量并落盘（`output/latency_bench.json`、`output/functional_tests.json`）

## 二、测试项与口径

| 编号 | 测试项 | 口径 | 工具 |
|---|---|---|---|
| P1 | 单轮问答响应时间 | 冷启动（每题前清空查询编码缓存） | `tools/bench_latency.py` |
| P2 | 单轮问答响应时间 | 热缓存（连续重复同一问法，下界） | `tools/bench_latency.py` |
| P3 | 连续会话稳定性 | 连续 50 轮问答的时延与错误率 | `tools/run_functional_tests.py` TC-09 |
| P4 | 容器启动性能 | `docker restart` → 健康检查 `healthy` | 现场测量 |
| P5 | 资源占用 | 空闲稳态下 CPU / 内存 / 网络 / 块 IO | `docker stats --no-stream` |
| P6 | 知识库冷加载 | 首次问答前的知识库加载耗时 | 冒烟测试日志 |

> **为什么区分冷/热两种口径**：系统对「查询向量编码」做了缓存（同一问法二次命中）。
> 若只测热缓存会得到偏乐观的数字，因此额外给出**冷启动**（清空缓存）作为最坏情况口径。

## 三、P1/P2 单轮问答响应时间

命令：`docker exec finqa-app python tools/bench_latency.py`（10 题评测集）

**结果（真实测量）**

| 口径 | 样本 n | 平均 | P50 | P95 | 最大 |
|---|---|---|---|---|---|
| 冷启动（清缓存） | 10 | **0.311 s** | 0.300 s | 0.405 s | 0.405 s |
| 热缓存 | 10 | **0.278 s** | 0.282 s | 0.348 s | 0.348 s |

落盘文件：`output/latency_bench.json`

```json
{
  "workorder": "人工智能 NLP-RAG-金融问答系统部署",
  "n": 10,
  "rows": [
    { "strategy": "hybrid",
      "cold": { "n": 10, "avg": 0.311, "p50": 0.3, "p95": 0.405, "max": 0.405 },
      "warm": { "n": 10, "avg": 0.278, "p50": 0.282, "p95": 0.348, "max": 0.348 } }
  ]
}
```

**分析**

- 最坏情况（冷启动）P95 = **0.405 s**，远低于验收口径「≤ 3 s」，余量约 **7.4 倍**。
- 热/冷差异仅 **0.033 s（约 11%）**，说明时延瓶颈在检索与重排，而非查询编码。
- 首轮答案前的**知识库加载**是一次性开销（见 P6），不随问答轮次重复。

## 五、P4 容器启动性能

|---|---|
| `docker restart finqa-app` → 健康检查 `healthy` | **9.3 s** |

**分析**：容器 9.3 s 内即达到 `healthy`；`HEALTHCHECK` 采用 `interval=30s / start-period=90s / retries=5`，

## 六、P5 资源占用（空闲稳态）

命令：`docker stats --no-stream finqa-app`

| 指标 | 值 |
|---|---|
| CPU 使用率 | **0.60 %** |
| 内存使用 | **80.14 MiB / 7.681 GiB（1.02 %）** |
| 网络 IO | 2.97 MB / 262 kB |
| 块设备 IO | 61.4 kB / 9.37 MB |
| 进程数（PIDs） | 21 |

**分析**：空闲态内存占用约 **80 MB**，CPU 近乎为 0。原因在于：

1. 嵌入推理（Ollama）与向量库检索均**不在容器内常驻模型**，容器只承载 Web 服务与检索逻辑；
2. 向量以 `.npy` 内存映射方式加载，避免常驻大对象；
3. 基础镜像 `python:3.10-slim` 无多余系统组件，进程数少。

## 七、P6 知识库冷加载

| 阶段 | 耗时 | 来源 |
|---|---|---|
| 知识库加载（chunks + 倒排索引 + 向量映射） | **8.10 s** | `output/deploy_logs/smoke.log` |
| 冒烟测试 10 题总耗时 | 11.72 s | `output/deploy_logs/smoke.log` |

**分析**：知识库 8086 块 / 10.9 MB `chunks.jsonl` / 16.1 MB `inverted_index.pkl`，
首次加载 8.10 s 后常驻内存，后续问答不再重复加载。若需进一步压缩，可预热镜像内缓存（见《优化报告》）。

## 九、性能结论

1. **响应时间**：冷启动最坏 P95 = 0.405 s，热缓存 0.278 s，稳定满足「≤ 3 s」验收口径。
2. **稳定性**：连续 50 轮问答时延平稳（平均 0.16 s，最大 0.24 s），无劣化、无异常。
3. **启动性能**：容器 9.3 s 内达到 healthy，健康检查配置合理。
4. **资源效率**：空闲内存仅约 80 MB、CPU 0.60%，适合在服务器上与 RTMP 等对端服务**共部署**。
5. **瓶颈定位**：时延主要来自检索 + 重排阶段（冷/热差异仅 11%），后续优化方向为候选集剪枝与索引预热（详见《优化报告》）。
