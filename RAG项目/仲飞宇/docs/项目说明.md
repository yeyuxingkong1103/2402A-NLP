## 一、项目简介

这是一个**可运行、可部署的 RAG（检索增强生成）多角色对话系统**。核心目标：让大模型能够**扮演特定角色**（心理咨询师、律师等），并**基于自有知识库**回答问题，而不是凭大模型的"记忆"凭空回答。

内置 **2 个演示角色**：**心理咨询师**、**律师**。每个角色有自己的人设提示词和**独立的知识库**（按 `role_id` 隔离召回，互不串库），知识库语料来自公开数据集——律师侧是《民法典》《刑法》《劳动法》系列等 14 部法律全文，心理咨询师侧是 CPsyCoun 中文心理咨询对话集 + 《精神卫生法》，来源与许可见 [数据来源](数据来源.md)。

以内置的「律师」为例：你可以问它"试用期最长可以约定多久"，它会先从知识库里检索到《劳动合同法》的相关条文，再组织成专业、有依据的回答。

一句话概括本项目做的事：

> 文档 → 入库（离线） → 提问时检索相关段落 → 让大模型基于这些段落"照着答" → 返回答案。

## 二、为什么需要 RAG（背景）

大模型（LLM）有三个天然短板：

1. **知识有截止日期** —— 训练数据是某个时间点之前的，不知道之后的新知识；
2. **会"幻觉"** —— 不懂的东西也一本正经地编；
3. **不懂私有/专业领域知识** —— 比如某家医院的内部指南、某部法律的细则。

RAG（Retrieval-Augmented Generation，检索增强生成）的思路很简单：**回答问题前，先到知识库里"翻资料"，把翻到的相关段落和问题一起交给大模型**。这样：

- 回答有依据、可溯源（每个答案都附带了检索到的知识片段）；
- 知识可以随时更新（往知识库里加文档即可，不用重新训练模型）；
- 领域专业知识也能被准确利用。

## 三、功能特性

| 能力 | 说明 |
|---|---|
| 多角色 | **2 个内置角色**（心理咨询师、律师），可自定义人设（提示词 + 独立知识库） |
| 混合检索 | 稠密向量检索（语义）+ BM25（关键词），两路召回再融合 |
| 重排序 | 可选 BGE-reranker 交叉编码精排，让最相关的排最前 |
| 多轮对话 | 短期记忆按「会话 + 角色」隔离，支持上下文追问（内存 → 可切 Redis） |
| 流式输出 | `/chat/stream` 提供 SSE 流式（打字机效果） |
| 文档解析 | PDF / Markdown / txt / **图片与扫描件（OCR）** |
| 分块策略 | 固定 / 句子 / 段落 / 标题 / 语义 共 5 种，可带重叠 |
| 召回增强 | Query 改写扩写（可选）、chunk 摘要（可选）、入库去重与低质量过滤 |
| 知识库动态更新 | 入库脚本支持重复入库（按来源先删后插，幂等） |
| 可替换后端 | 向量库 / 关系库 / 短期记忆 均可在 `.env` 里切换，代码不动 |
| 可观测 | `/health` 分档报组件状态与降级原因；统一日志（多 worker 按端口分文件） |
| 可部署 | 一键启动脚本、Nginx 负载均衡、Jmeter 压测、三环境配置分层 |

## 四、技术架构

### 4.1 技术栈

| 层 | 组件 | 本项目采用 |
|---|---|---|
| Web 框架 | FastAPI + uvicorn | 同步接口 + SSE 流式 |
| 大模型 | OpenAI 兼容接口 | 本地 Ollama `qwen3:0.6b` |
| 向量化 | Embedding 模型 | Ollama `bge-m3`（1024 维） |
| 重排序 | 交叉编码 | `BAAI/bge-reranker-v2-m3`（本地服务，可选） |
| 向量库 | Milvus | Milvus Lite（本地文件，免部署）／独立 Milvus 服务 |
| 关键词检索 | BM25 | `rank_bm25` + `jieba` 分词 |
| 关系库 | 用户/角色/文档登记 | SQLite（默认）／MySQL |
| 短期记忆 | 多轮上下文 | 进程内内存（默认）／Redis |
| 文档解析 | PDF/图片/文本 | PyMuPDF + pdfplumber + RapidOCR（扫描件） |
| 前端 | 单文件页面 | `app/static/index.html`（HTML+CSS+原生 JS，无框架无构建） |

> 「默认 / 可替换」两列对应 MVP 与生产：**切换只改 `.env`，代码一行不动**。
> 三个存储后端的抽象见 `app/core/store/`，切换方式见 [设计文档.md](设计文档.md) §5。

### 4.2 整体结构

```
浏览器 / Postman
   │  HTTP（JSON 或 SSE 流式）
   ▼
FastAPI 应用（app/main.py，启动时组装 RAGPipeline）
   │
   ├── 在线链路（对话）──► 需要 Ollama（LLM+embedding）、可选 rerank 服务
   └── 离线链路（入库）──► 需要 Ollama（embedding）、Milvus Lite
```

外部依赖（本地开发时都在本机；生产可换成服务化组件）：

| 组件 | 作用 | 地址 | 必需 |
|---|---|---|---|
| Ollama | 大模型 + 向量化 | `http://localhost:11434/v1` | 是（或用在线 API 替代） |
| Milvus Lite | 向量库（本地文件） | `./data/milvus.db` | 是 |
| rerank 服务 | 交叉编码精排 | `http://127.0.0.1:8001/v1` | 否（`RERANKER=bge` 时才需要） |
| MySQL | 关系库 | `mysql://…` | 否（默认用 SQLite） |
| Redis | 短期记忆 | `redis://127.0.0.1:6379/0` | 否（默认用进程内内存） |

> `bash scripts/start_all.sh`（Windows 双击 `start.bat`）会自动探测这些依赖、能拉起的自动拉起，
> 最后校验 `/health`；MySQL 因需要管理员权限**不自动拉起**，脚本会提示你手动启动。

## 五、数据流程

### 5.1 离线链路：把文档变成可检索的知识

```
文档（PDF / 图片 / md / txt）
  → ① 解析   parser.py       （PyMuPDF / pdfplumber；扫描件与图片走 RapidOCR）
  → ② 清洗   cleaner.py      （去水印、去页眉页脚、空白归一）
  → ③ 分块   chunker.py      （默认按段落，约 500 字 + 50 字重叠）
  → ④ 增强   enhance.py      （低质量过滤 / 去重；可选 LLM 摘要）
  → ⑤ 向量化 embedding.py    （Ollama bge-m3 → 1024 维向量）
  → ⑥ 入库   milvus_store.py （写入 role_knowledge 集合，按角色隔离）
  → ⑦ 登记   sql_store.py    （记录文档元信息）
  → ⑧ 失效   hybrid_retriever.invalidate()  （让本进程的 BM25 索引看见新文档）
```

对应命令：

```bash
# 先拉取语料（公开数据集，约 29MB，支持断点续传）
python scripts/fetch_datasets.py
# 单个角色的知识
python scripts/ingest.py --dir data/corpus/lawyer --role lawyer
# 一次灌入全部演示数据（2 个角色 + 语料 + 示例用户，幂等）
python scripts/seed.py
```

### 5.2 在线链路：一次提问的完整旅程

```
用户问题："试用期最长可以约定多久？"
  ① 取角色        角色人设（内置预设自动登记）
  ② 检索          混合召回：稠密(Milvus 向量) + 关键词(BM25) → RRF 融合
  ③ 重排          精排（score_fusion 融合分 / bge-reranker 交叉编码）
  ④ 拼提示词      人设 + 知识片段 + 多轮历史 + 当前问题（按字符预算裁剪）
  ⑤ 生成          LLM（Ollama qwen3）基于知识作答
  ⑥ 后处理        去推理段噪声、正则清洗、去幻觉引用
  ⑦ 返回 + 记忆   返回给用户，并写回短期记忆支撑多轮
```

对应接口：`POST /chat`（非流式）、`POST /chat/stream`（SSE 流式）。

## 七、快速开始

### 7.1 环境要求

- Python 3.10 ~ 3.14（本项目开发环境实测 **3.14.4**；OCR 依赖 onnxruntime / opencv-python 在 3.14 上均有预编译轮子）
- [Ollama](https://ollama.com/)（本地大模型运行环境）
- 至少拉取两个模型：

```bash
ollama pull qwen3:0.6b    # 大模型
ollama pull bge-m3        # 向量化
```

### 7.2 安装依赖

```bash
cd rag-roleplay
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env       # 按需修改配置
```

### 7.3 入库（离线链路）

```bash
# 先拉取语料（公开数据集，约 29MB，支持断点续传）
python scripts/fetch_datasets.py
# 入库单个角色的语料
python scripts/ingest.py --dir data/corpus/lawyer --role lawyer
# 或一次灌入全部演示数据（2 个角色 + 语料 + 示例用户，幂等可重复执行）
python scripts/seed.py
```

### 7.4 启动服务

推荐用一键启动：它会**自检 Ollama / MySQL / Redis / Milvus，能自动拉起的自动拉起**，
最后校验 `/health`。

```bash
bash scripts/start_all.sh              # 常规启动
bash scripts/start_all.sh --no-start   # 只自检不起服务
bash scripts/start_all.sh --strict     # 有组件不可用即退出非 0（交付演示用）

curl http://localhost:8000/health      # 健康检查，正常时 status=ok
```

**Windows 上双击 `start.bat` 即可**（等价于进 WSL 跑 `start_all.sh`，成功后自动开浏览器）。
也可以只起一个 uvicorn：`bash scripts/run.sh`。

> 若 `.env` 里 `RERANKER=bge`，需先启动本地重排服务：`bash scripts/run_rerank.sh`
> （首次要先 `bash scripts/download_rerank_model.sh` 下模型，约 2.2GB）。

### 7.5 对话测试

```bash
# 非流式
curl -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"question":"试用期最长可以约定多久？","role_id":"lawyer"}'

# 流式（SSE）
curl -N -X POST http://localhost:8000/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"question":"精神障碍的诊断应当由谁作出？","role_id":"psychologist"}'
```

停止服务：`bash scripts/shutdown.sh`

## 八、配置说明（.env 关键项）

| 变量 | 说明 |
|---|---|
| `LLM_PROVIDER` | `ollama` / `openai_compat` / `dummy` |

| `LLM_MODEL` | 默认 `qwen3:0.6b` |

| `RERANK_POOL` | 精排粗排池宽度，默认 `20`（仅 `RERANKER=bge` 生效） |
| `RERANK_BASE_URL` | bge 重排服务地址，默认 `http://127.0.0.1:8001/v1` |
| `RERANK_MODEL` | 默认 `BAAI/bge-reranker-v2-m3` |
| `MILVUS_DB_URI` | `.db` 路径 = Milvus Lite |
| `SQL_URL` | SQLite 或 MySQL 连接串 |
| `MEMORY_BACKEND` | `memory`（默认）/ `redis` |

| `MIN_CHUNK_CHARS` | 入库低质量过滤：低于此字符数的 chunk 丢弃（默认 10） |

| 摘要生成 | 全局开关 `SUMMARY_ENABLED`（默认 `false`）；上传接口 `summary=true` / `ingest.py --summary` 可对单次入库覆盖 |

## 十、常见问题与扩展方向

**常见问题**

- 健康检查 `llm` 或 `embedding` 显示 unavailable → 确认 Ollama 已启动、模型已 `ollama pull`。
- 检索报错 `collection released` → 代码已内置 `load_collection()` 兜底，若仍出现请重启服务。
- 想离线冒烟（不依赖 Ollama/Milvus）→ `.env` 里 `LLM_PROVIDER=dummy`、`EMBED_PROVIDER=dummy`。

**扩展方向**

下面这些多数**已经落地**（括号里是实现位置），剩下的属于后续版本：

- 内置角色（`core/prompt/role_presets.py`）目前是心理咨询师与律师两个，继续加角色只需加一条预设 + 一个语料目录
- 向量库切 Milvus 服务器、关系库切 MySQL、记忆切 Redis —— 已支持，只改 `.env`
- 重排序接入 BGE-rerank 交叉编码 —— 已支持（`RERANKER=bge` + `scripts/run_rerank.sh`）
- 接入在线 API（硅基流动 / DeepSeek / 千问 / 豆包）—— 已支持（`LLM_PROVIDER=openai_compat`）
- 评测与压测：RAGAS 风格评测（`eval/`）、Jmeter 压测与 Nginx 负载均衡（`deploy/`）
- 部署：Ubuntu / 云服务器流程与部署后自证清单（`deploy/README.md`）

仍属后续版本的：多用户登录与鉴权、知识库自动增量更新、把 BM25 迁进 Milvus 稀疏向量。
