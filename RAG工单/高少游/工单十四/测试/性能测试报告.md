# 性能测试报告

**工单编号：人工智能NLP-RAG-修复低质量工业PDF的解析与信息丢失工单**
**测试对象：工业专利（图片型 PDF）多模态检索问答系统**
**测试日期：2026-10-09**

---

## 1. 测试目标

工单的性能验收标准为：

1. **响应时间**：从用户提问到返回答案的时间不超过 3 秒；
2. **资源消耗**：系统应合理利用计算资源，在高并发环境下稳定运行。

本报告给出单问响应时间的冷启动与热缓存两档实测数据，以及资源占用的分析。

---

## 2. 测试方法

基准脚本 `tools/bench_latency.py` 对 6 道测试题逐题计时，分两档测量：

- **冷启动（cold）**：每题作答前清空嵌入编码缓存，测量「首次遇到该问法」的最坏情况；
- **热缓存（warm）**：先跑一遍预热缓存，再测第二遍，测量重复问法命中缓存的下界。

两档均覆盖 `vector / fulltext / hybrid` 三种检索策略，重排器为 `linear`。

复现命令：

```bash
python tools/bench_latency.py --strategies vector,fulltext,hybrid
```

---

## 3. 响应时间结果

### 3.1 冷启动（最坏情况）

| 策略 | 平均(s) | P50(s) | P95(s) | 最大(s) | 是否 ≤3s |
|---|---|---|---|---|---|
| vector | 2.29 | 2.27 | 2.38 | 2.38 | 是 |
| fulltext | 2.37 | 2.39 | 2.41 | 2.41 | 是 |
| hybrid | 2.38 | 2.38 | 2.45 | 2.45 | 是 |

### 3.2 热缓存（重复问法）

| 策略 | 平均(s) | P50(s) | P95(s) | 最大(s) |
|---|---|---|---|---|
| vector | 0.022 | 0.021 | 0.031 | 0.031 |
| fulltext | 0.018 | 0.020 | 0.027 | 0.027 |
| hybrid | 0.020 | 0.019 | 0.025 | 0.025 |

冷启动与热缓存的差距（约 2.3s → 0.02s）主要来自 Ollama 本地嵌入调用的固定开销。缓存命中后不再发起嵌入调用，延迟降至毫秒级。

---

## 4. 延迟构成分析

单问端到端耗时由以下环节组成（冷启动）：

| 环节 | 说明 | 占比 |
|---|---|---|
| Query 改写 + 理解 | 分词、关键词/实体提取、题型识别 | 极小（本地 CPU） |
| **嵌入调用** | 查询 + 6 选项合并为单次 Ollama 调用 | 主导（约 2.3s） |
| 检索（向量 + 全文） | 17 块规模，余弦 + BM25 | 毫秒级 |
| 重排 | 多信号线性融合 | 毫秒级 |
| 答案合成 | 选项打分 + 证据溯源 | 毫秒级 |

结论：**嵌入调用是唯一的耗时瓶颈**，其余环节均为毫秒级。这决定了优化的主攻方向（见第 6 节与优化报告）。

---

## 5. 资源消耗

| 资源 | 占用 | 说明 |
|---|---|---|
| 内存 | 约 1–2 GB（含 Streamlit + 嵌入模型 + 索引） | 知识库仅 17 块，向量矩阵 17×1024，占用极小 |
| 磁盘 | 索引 < 1 MB（chunks.jsonl + emb + 倒排）；OCR 缓存与页面位图约数十 MB | 二次构建零 OCR 开销 |
| CPU | 检索 / 重排 / 作答为轻量计算 | 无 GPU 依赖 |
| 外部服务 | Ollama 本地服务 | 无外部网络依赖，可离线运行 |

### 5.1 高并发稳定性

系统面向单文档（本工单仅 1 份专利）的小规模知识库，单进程即可支撑。针对高并发的设计考量：

- **编码缓存**：相同查询与选项文本命中缓存，重复请求不重复嵌入，天然抵御重复问法的并发压力；
- **向量检索为纯矩阵运算**：17×1024 规模下余弦计算为微秒级，不构成瓶颈；
- **无状态问答引擎**：`QAEngine.ask()` 只读索引，会话状态存于 `Conversation`，便于横向扩展；
- **瓶颈隔离**：唯一的外部依赖是 Ollama 嵌入服务，如需更高并发可对 Ollama 做多实例负载均衡。

在本工单的数据规模（17 块、6 题）下，系统在单机上稳定运行，未出现超时或内存增长。

## 6. 优化前后对比

| 指标 | 优化前 | 优化后 | 改善 |
|---|---|---|---|
| 单问冷启动延迟 | 4.46s | 2.34s | 下降 47.5% |
| 是否满足 ≤3s | 否 | 是 | 达标 |
| 热缓存延迟 | — | 0.02s | 毫秒级 |
| 单问嵌入调用次数 | 2 次（查询、选项分开） | 1 次（合并批量） | 减半 |

优化措施详见 [`优化报告.md`](../优化/优化报告.md)。

---

## 7. 性能验收结论

- 三种检索策略的冷启动平均响应时间均约 2.3–2.4s，P95 均不超过 2.45s，**全部满足 ≤ 3s**；
- 热缓存下响应时间降至 0.02s 量级；
- 资源占用低，无 GPU 依赖，无外部网络依赖，可在单机稳定运行；
- 性能验收标准达成。

原始数据见 `output/latency_bench.json`。
