## 1. M1 严格准确率（Accuracy）与 M1b 宽松准确率

| 项 | 内容 |
| --- | --- |
| **定义** | 在 17 道功能用例上，**严格判对题数 ÷ 有效题数**。 |
| **公式** | `严格准确率 = 严格判对题数 / 有效题数`；`有效题数 = 总数 - 异常题数`。<br>`is_correct(coverage, refused, threshold=KEYWORD_THRESHOLD=0.6)`：**未拒答** 且 `coverage ≥ 0.6` ⇒ 判对。 |
| **题数口径（必写）** | **总题数 = 17**（题库行数）；**无异常题时 `有效题数 = 总题数 = 17`**，此时 `准确率 = 判对题数 ÷ 总题数`（与本工单口径一致）。**一旦出现异常题**（`error` 非空），分母按 `有效题数` 计，并在同一句话里给出「总数 17 / 异常 N / 有效 17−N」，**不得**只报百分比。 |
| **补充档（不算进严格准确率）** | `partial_correct(...)`：未拒答且未达严格判对，但满足 ① `coverage ∈ [PARTIAL_THRESHOLD=0.3, 0.6)` **或** ② 数值原子覆盖率 `atomic_coverage ≥ ATOMIC_THRESHOLD=0.6`（英文作答 / 单位换算的兜底）。<br>`宽松准确率(严格+部分) = (严格判对 + 部分正确) / 有效题数`。 |
| **数据来源字段** | 题库 → `answer_keywords`；逐题 → `judge.keyword_coverage` / `judge.is_correct` / `judge.partial_correct` / `judge.atomic_coverage`；汇总 → `准确率.严格判对题数` / `准确率.严格准确率` / `准确率.部分正确题数` / `准确率.部分正确题号` / `准确率.宽松准确率(严格+部分)` / `准确率.平均关键词覆盖率` / `准确率.判对题号` / `准确率.未判对题号`。 |
| **达标阈值** | **严格准确率 ≥ 90%**；17 题下 `17 × 0.9 = 15.3` ⇒ **≥ 16/17**（15/17 = 88.2% **不达标**）。宽松准确率只作参考，**报告中不得用宽松数替代严格数**（两者必须并列，且标明哪一个用于判定）。 |
| **失真风险** | ①「覆盖率 ≥ 0.6」是**代理判据**，不是人工判卷：答案含关键词但**语义答错**（数字张冠李戴到别家公司）仍可能判对 ⇒ 必须叠加 M5 一起看。②**拒答被计为判错**，闸门误拒会直接压低准确率（须在归因里区分「真不会」与「误拒」）。③分析论述题（Q03/Q04/Q17）关键词是「要点清单」，**不衡量论述质量**。④**分母纪律**：异常题不计入有效题数，报告必须写清「X/有效题数（总数 17，异常 N）」。⑤阈值 0.6（答案命中题库关键词的比例）与闸门的 `min_keyword_coverage=0.45`（问句实词在证据中的覆盖率）**不是同一个东西**，**禁止混用**。 |
| **报告写法** | 「`严格判对 X/有效题数 Y`（总数 17，异常 N）= `Z%`」，并列出 `未判对题号` 与逐题归因。 |

## 2. M2 关键词覆盖率（Keyword Coverage）

| 项 | 内容 |
| --- | --- |
| **定义** | 系统答案命中的 `answer_keywords` 个数 ÷ 该题 `answer_keywords` 总数。 |
| **公式** | `判分.py::keyword_coverage(answer, keywords) → (命中数, 总数, 覆盖率, 命中列表, 缺失列表)`；`覆盖率 = 命中数 / 总数`（关键词为空时返回 `(0, 0, 0.0, [], [])`，不抛异常）。 |
| **归一化口径（唯一实现 `判分.py::normalize`）** | ①**全角转半角**（含全角空格 `\u3000`）；②**去所有空白**（空格/制表/换行/`\u00a0`）；③**去标点、符号、控制符**（Unicode 类别 `P`/`S`/`Z`/`C` 全剔除，**唯独保留小数点 `.`**）；④**小写化**。<br>⇒ `1,379.58 亿元` → `1379.58亿元`；`不良贷款率 1.65％` → `不良贷款率1.65`。 |
| **数字边界（防假阳性）** | 以数字开头/结尾的关键词，匹配位置相邻字符**不得**是数字或小数点：`11.65` **不**命中 `1.65`；`18.25` **不**命中 `18.2`；`1165` **不**命中 `165`。 |
| **数据来源字段** | 题库 `answer_keywords`（每题 4~7 个，合计 **103**）；答案 `answer`；逐题 `judge.keyword_hit_count` / `judge.keyword_total` / `judge.keyword_coverage` / `judge.keyword_hit` / `judge.keyword_miss`；汇总 `准确率.平均关键词覆盖率`。 |
| **达标阈值** | 单题 **≥ 0.6** 记「覆盖达标」（严格判对的必要条件）；**未达标题号清单**必须在报告里给出。 |
| **失真风险** | ①**同义改写漏判**：答案用同义表述（「增速创新高」vs 关键词「营收、净利润增速创转型以来新高」）会被判未命中 ⇒ **虚低**；题库关键词已用 `测试\核对关键词.py` 逐页核对**存在性**（103/103），但**存在性 ≠ 答案会原样复述**。②**单位/量纲**：`1,379.58` 与 `1379.58` 归一化后同串；但 `2.79` 与 `2.79%` 可能互相误命中 ⇒ 依赖关键词自带单位（`1.20元`、`8.51%`、`610.36亿元`）避免。③**短数字关键词**占比高的数值题天然更容易达标，报告须**按题型分组**呈现（`按题型分组`）。④**表格块回退答案**数字齐全 ⇒ 覆盖率可能满分而可读性差：覆盖率**不等于**答案质量。⑤**纯标点关键词**归一化后为空 ⇒ 一律计为缺失（保守，不让空洞关键词白送分）。 |

## 3. M3 recall@5 与 recall@10

| 项 | 内容 |
| --- | --- |
| **定义** | 检索层**召回能力**：对每个 `answer_keywords` 关键词，检查**检索返回前 K 条片段（chunk）的合并正文**是否命中该关键词。 |
| **公式** | `判分.py::retrieval_recall_at_k(hits_text, keywords, k) → (命中数, 总数, recall@k, 命中列表, 缺失列表)`；合并正文 = `normalize("\n".join(texts[:k]))`，逐关键词做归一化 + 数字边界匹配。汇总 `检索召回.平均recall@5` / `平均recall@10`（题级宏平均）。 |
| **K 取值** | `配置.py::RECALL_KS = (5, 10)`；**两者取自同一次检索**：评估统一 `TOP_K = 10` 取回 10 条，再分别取前 5 / 前 10 条算 union。生成层只把 `PROMPT_TOP_K = 3` 条注入提示词（`prompt_top_k`），**不影响** recall 口径。 |
| **数据来源字段** | 逐题 `judge.recall_at_5` / `judge.recall_at_10` / `judge.recall_at_5_hit` / `judge.recall_at_10_hit` / `judge.recall_at_5_miss` / `judge.recall_at_10_miss`；片段正文 `hits[].text_head`（完整正文见 `Answer.evidence`）；汇总 `检索召回.*`。 |
| **达标阈值** | **≥ 95%**（沿用召回口径）；未达标必须给**可达性说明**：用 M9 区分「索引里根本没有」与「索引有但没召回」，并对结构性不可达（证据原文跨块分割、任何单块都不含整段）**穷举证明后单独说明**，**不得**删题或改 K。 |
| **失真风险** | ①**union 口径会偏高**：把 K 段文字拼起来再找关键词，等价于「各段各贡献一点」，与工单基线的 `hit_complete`（单块含完整证据）**是两个口径** ⇒ 报告必须写明「union 口径」。②**关键词短**（`1.65` / `2.79`）易被无关上下文命中（数字边界已削弱但不能消除）。③**返回条数不足 K** 时分子天然变小 ⇒ 须记录实际条数（`hit_count` / `extra_hits` / `extra_hit_ids`；top-K 之后引擎追加的**页上下文补充块**不参与排名，`rank_monotonic_topk` 只对前 `TOP_K` 条校验）。④**缓存命中**会导致检索结果异常 ⇒ 本框架恒 `USE_CACHE=False`。⑤**跨文档题**（Q04/Q09）关键词分散在多份语料，单次检索必然覆盖不全 ⇒ **单独分组**。 |

## 4. M4 页命中率（Page Hit Rate）

| 项 | 内容 |
| --- | --- |
| **定义** | 该题的**命中页**（检索返回片段的页）是否落在题库 `expected_pages_hint` 给出的页码区间内。 |
| **公式** | `判分.py::page_hit(hits, expected_pages_hint, source_filter) → {"hit", "ranges", "matched", "scanned", "reason"}`；汇总 `页命中.命中率 = 命中题数 / 有效题数`。 |
| **区间解析** | `parse_page_ranges()` 支持 `"a-b"`、单页 `"a"`、分号并列 `"a-b;c-d"`（兼容 `~`/`—`/`,`/「至」等写法）。跨文档题（**文件数 == 区间数 > 1**）按**下标配对**：第 i 个 `source_file` ↔ 第 i 个区间；不给 `source_filter` 时任一命中页落在任一区间即算命中。 |
| **数据来源字段** | 题库 `expected_pages_hint` / `source_file`；逐题 `judge.page_hit.ranges` / `.matched` / `.scanned` / `.reason`；汇总 `页命中.命中题数` / `命中率` / `未命中题号`；核对真值见 `测试\测试数据\关键词核对结果.json` 的 `页码` / `命中明细[].文件`。 |
| **达标阈值** | **辅助指标**（不单独判达标）：报告须报 `页命中.命中率` 与 `未命中题号`，并说明与「关键词覆盖率」的差异。 |
| **失真风险** | ①**区间天然宽松**：区间由「关键词命中页的最小值~最大值」生成，**区间内的非证据页也算命中** ⇒ 系统性偏高，**严禁当召回率或准确率使用**。②**多语料题的 hint 与 `source_file` 顺序强耦合**：顺序错位会把命中判成未命中（配对规则的副作用）。③`expected_pages_hint` 只覆盖关键词命中页，**不覆盖 `reference_answer` 里的全部论述页** ⇒ 引用到论述页可能被判未命中。④拒答题无命中页 ⇒ `reason="no_hits"`，必须显式声明分母处理（本框架按「未命中」计入，报告须注明）。⑤`reason` 取值（`no_valid_range` / `no_hits` / `out_of_range`）应当一并报告，避免把「hint 写坏」误读成「检索失败」。 |

## 5. M5 跨语料泄漏（Cross-Corpus Leak）

| 项 | 内容 |
| --- | --- |
| **定义** | 问句点名的公司（语料）与**实际检索命中 / 答案引用**的语料不一致。 |
| **公式** | 三档并列：①`cross_corpus_leak(hits, expected_files, top_n=LEAK_TOP_N=3)` → `judge.cross_corpus_leak`（**top-3 口径**，主口径）；②`top_n=TOP_K=10` → `judge.cross_corpus_leak_top10`（复核口径）；③`citation_leak(citations, expected_files)` → `judge.citation_leak`（**引用级**）。<br>期望语料来自题库 `source_file`（`;` 分隔，`split_source_files()` 解析），比较用 `_basename()` 归一（去目录、大小写不敏感）。 |
| **数据来源字段** | 逐题 `judge.cross_corpus_leak.{leak, foreign, expected, checked}` / `judge.cross_corpus_leak_top10.*` / `judge.citation_leak.{leak, foreign}`；汇总 `跨语料泄漏.题数/题号/top10题数/top10题号/引用级泄漏题数/引用级泄漏题号`；`hits[].file_name` / `company`；`corpus_keys` 见 `研发\data\index\index_manifest.json`。 |
| **达标阈值** | **单语料题（15 题）：目标 0**（实测曾出现「平安银行2019年营业收入」引用**招商银行 p53** 的泄漏，已通过文件名派生别名 + 语料路由修复）。**跨文档题（Q04 点名 6 家、Q09 点名 2 家）：不适用**——问句本就点名多家，改为单独报告「覆盖完整性」（点名的每家公司是否都有命中片段），**不得**把它们算进泄漏率分子/分母。 |
| **失真风险** | ①**问句不提公司名时不设防**（如「2019年营业收入是多少？」）⇒ 路由拿不到主体，**不冒险过滤**；这类题**单列**在报告里。②**同时提多家公司不设防** ⇒ 同上。③**别名未命中**（口语简称、英文写法、错字）⇒ 退化为不过滤，泄漏可能复现，**这正是本指标存在的意义**。④**同名易混**（「招商银行」vs「招商证券」）：别名表过粗会**误过滤成空结果** ⇒ 表现为召回骤降而非泄漏，须同时看 M3/M9。⑤**页码不能判语料**：9 份语料页码空间重叠（多份都有 p5）⇒ 必须用 `file_name` / `corpus`，**禁止**用页码判语料。⑥**英文题 Q13** 走中文检索式路径，语料路由同样可能失效 ⇒ 单独看。 |

## 6. M6 响应时间与 SLA（Retrieval / Generation / First-token / End-to-end）

| 项 | 内容 |
| --- | --- |
| **定义** | 逐题记录分段耗时与端到端耗时，在题目集合上做分布统计。 |
| **分段口径** | ①**检索** = `latency_ms.retrieve`（问句理解 + 检索 + 融合 + 重排）；②**生成** = `latency_ms.generate`（LLM 润色 / 规则拼接）；③**首字** = `latency_ms.first_token`；④**端到端（SLA 主口径）** = `total_ms` = `Answer.latency_ms.total`（**服务端自计时**）。 |
| **统计量（必报）** | `响应时间ms` 给出：`样本数` / `平均` / `中位` / `P50` / `P90` / `P95` / `最大` / `最小`，以及分段 `检索_平均`/`检索_P90`/`生成_平均`/`生成_P90`/`首字_平均`/`首字_P90`/`首字_最大`。**禁止只报平均值。** |
| **SLA** | `SLA.阈值ms = SLA_MS = 3000`；`SLA.达标题数` / `SLA.达标率` / `SLA.超时题号` / `SLA.首字达标率`。**超时题号必须点名，样本不得删除。** |
| **数据来源字段** | 逐题 `latency_ms.{retrieve,generate,first_token,total}` / `total_ms` / `sla_ok`；汇总 `响应时间ms.*` / `SLA.*`；`运行元信息.warmup_ms`（预热耗时单列）。 |
| **达标阈值** | 端到端 **≤ 3000 ms**（逐题）。实测参考：**预热后单题约 0.6~1.7 s**；**冷启动首字可达 3.4 s**（`qwen2.5:3b` 冷启动首字实测 3430.8 ms）。 |
| **失真风险** | ①**冷启动不预热** ⇒ 首题必超线。评估流程已内置 `QAEngine.warmup(with_generate=True)`，`warmup_ms` 单独记录、**不计入**逐题统计。②**缓存命中** ⇒ 延迟被量成毫秒级，性能虚高 ⇒ 本框架恒 `USE_CACHE=False`（每题都按「用户第一次问」计）。③**并发** ⇒ 会显著抬升耗时（工单3 实测并发 4 路可达 10.8 s）⇒ 必须**独占 Ollama、串行跑**。④**口径缺失**：本框架**没有**独立客户端 wall 计时，端到端是**服务端** `total_ms`；与「客户端请求发出→返回」相比会**略低**（不含 HTTP/序列化开销）⇒ 报告必须写明这一点，**不得**声称是客户端 wall。⑤**只报均值**会掩盖长尾 ⇒ 必报 P90/P95/最大。⑥**首字口径歧义**：非流式后端下首字与生成完成可能接近 ⇒ 报告须写明所用口径，**不得**把服务端首字当「用户可见时间」。 |

## 7. M7 拒答率（Refusal Rate）

| 项 | 内容 |
| --- | --- |
| **定义** | `refused == true` 的题占比（系统判定证据不足，答案为固定「不清楚」文案）。 |
| **公式** | `判分.py` 侧：`is_correct()` 对 `refused=True` 一律返回 `False`；`运行评估.py` 汇总：`拒答率 = 拒答题数 / 有效题数`，并给出 `拒答题号` 与 `按原因`（原因取自 `refusal_reason`）。 |
| **数据来源字段** | 逐题 `refused` / `refusal_reason` / `refusal_detail` / `gate.{answerable,reason,coverage}` / `post_composition_refused` / `fallback_coverage`；汇总 `拒答.{拒答题数,拒答率,拒答题号,按原因}`。 |
| **闸门阈值（记录在案）** | `研发\app\core\config.py`：`min_score=0.35`（**向量余弦**阈值，工单7 依据 `测试\测试数据\阈值标定.json` 标定：正样本最小 0.6626 / 负样本最大 0.6113）、`min_keyword_coverage=0.45`、`min_vector_similarity_en=0.45`。`answerability.py` 的 `thresholds` 直接取这三个值。 |
| **达标阈值** | **17 道功能用例预期全部可答 ⇒ 目标拒答率 0**（任何拒答都要归因到具体 `refusal_reason`）；**异常输入用例则期望 100% 拒答**（见 `设计\测试用例设计.md` TC-A 组）。两类分母**不得混算**。 |
| **失真风险** | ①**闸门误拒**会**直接压低 M1**：问句实词覆盖率算不上去（改写后问句与语料措辞差异大）即拒答；分析论述题、跨文档题、英文题最易中招。②**拒答 ≠ 答错**：报告要分开统计「拒答」「答错」「答对」，三者和为有效题数。③**拒答文案不含任何关键词** ⇒ 覆盖率必然 0，与「答了但全错」在覆盖率上不可区分，只能靠 `refused` 区分。④**两类拒答来源要分开报**：`可答性闸门拒答`（闸门直接拒）与 `生成层兜底拒答`（生成落到 `sentence_select` 后复核 `fallback_coverage < 0.5` 再拒），归因结论完全不同。⑤**阈值不得为提分而放宽**：任何阈值变更都必须以 `阈值标定.json` 的正/负样本分布为依据并留下记录。 |

## 8. M8 无引用率（No-Citation Rate）与 M9 索引可达性

### 8.1 M8 无引用率

| 项 | 内容 |
| --- | --- |
| **定义** | **非拒答**且 `cited_pages` 为空的题占比（答案没有可回溯的引用页）。 |
| **公式** | `无引用率 = \|{i : refused_i = false ∧ cited_pages_i = []}\| / \|{i : refused_i = false}\|`。 |
| **数据来源字段** | 逐题 `cited_pages` / `citations`（含 `corpus` / `page` / `quote` / `modality`）。 |
| **⚠️ 落地状态** | **汇总 JSON 目前没有直接给「无引用率」字段** ⇒ 必须从 `评估结果.jsonl` 的 `cited_pages` **重算**（或在下一版 `build_summary` 补该字段，并回写本文件）。**不得**凭印象填数。 |
| **达标阈值** | **目标 0**（每道非拒答题都应有引用页）；可另报 `平均引用条数` 作辅助。 |
| **失真风险** | ①**引用页只表示「引用位置」，不表示「该页确实是答案证据」** ⇒ 无引用率低**不代表**可回溯性好，须与 M4、M5 一起看。②**页码口径**：一律 **1-based 物理页码**（与 `manifest.page_basis="1-based-physical"` 一致）；与 PDF 印刷页码混用会系统性错位（题库 Q01 即注明「PDF第5页，正文页码4」）。③**回退答案**可能带引用但可读性差 ⇒ 引用存在性 ≠ 答案质量。④拒答题不计入分母（须在报告显式声明）。 |

### 8.2 M9 索引可达性（新框架新增，**解释 recall 的第一入口**）

| 项 | 内容 |
| --- | --- |
| **定义** | 对每个 `answer_keywords` 关键词做**全库检索**（不经排序、不看 top-K），判断该关键词在索引中是否存在；并进一步区分「索引里有但没进 top-10」。 |
| **公式** | `运行评估.py::build_index_reach()` 逐关键词产出 `{"in_index", "found", "found_count_capped", "in_expected_pages"}`；`_index_reach_stats()` 汇总：`索引内可达率 = 索引内可达 / 关键词总数`，并给出 `索引内不可达明细` 与 `索引可达但top10未召回明细`。 |
| **数据来源字段** | 逐题 `index_reach` / `index_reach_summary`；汇总 `索引可达性.*`（`关键词总数` / `索引内可达` / `索引内可达率` / `索引内不可达` / `索引内可达且落在期望页` / `索引内不可达明细` / `索引可达但top10未召回明细` / `索引可达但top10未召回关键词数`）。 |
| **达标阈值** | **归因项，不单独判定达标**；但它决定 M3 的结论怎么写：<br>① 若关键词 `索引内不可达` ⇒ 问题在**解析/分块/索引**（内容根本没进库）；<br>② 若 `索引内可达` 但没进 top-10 ⇒ 问题在**检索排序/召回**；<br>③ 两者都正常而答案仍缺 ⇒ 问题在**生成侧**（含原子护栏回退）。 |
| **失真风险** | ①**关键词粒度**：可达性按关键词做子串检索，可能与分词粒度不一致（词表外/超长短语易被误判不可达）⇒ 判读时结合 `关键词核对结果.json`（这些关键词确实存在于 PDF 中）。②**它不衡量排序质量**：可达率高 ≠ 召回率高。③**诊断本身有开销**（逐关键词全库扫描），属离线诊断，**不得**计入 SLA。④`found_count_capped` 表示命中条数被截断记录，不代表全量命中数。 |

## 9. 核心口径声明：`answer_keywords` 作为「无标注语料下相关片段的代理标注」

本工单语料是**9 份原始年报 PDF**，**没有任何人工相关度标注**（无 qrels、无段落级标注）。因此：

| 项 | 说明 |
| --- | --- |
| **我们用什么代替标注** | 用每题的 `answer_keywords`（**合计 103 个**，由 `reference_answer` 提炼并经 `测试\核对关键词.py` 用 pymupdf **逐页核对确实存在于对应 PDF**，通过率 **100%**）作为「**相关片段应当包含的原子**」的**代理标注（proxy labels）**。 |
| **为什么可行** | 关键词含人名、机构名、数值、要点词组，能机械比对；数值题关键词即核心答案，代理质量高。 |
| **⚠️ 局限（必须写进报告）** | ①**代理 ≠ 真值**：命中关键词**不等于**语义正确；未命中**不等于**语义错误（同义改写漏判）。②**覆盖不完整**：关键词是 `reference_answer` 的**提炼**，不可能穷尽所有正确表述与所有证据页 ⇒ recall 与页命中的**分母偏窄**。③**不衡量答案质量**：不评价论述完整性、逻辑、可读性；对分析论述题（Q03/Q04/Q17）尤其不适用。④**存在性是题级/语料级**：核对脚本确认「该关键词出现在该 PDF 的某些页」，**不代表**「它出现在被检索命中的那一段」。⑤**不可比性**：本工单指标**不得**与工单4/5/6（招股说明书语料 + golden 三段页口径）的数字直接横向比较——语料、题数、判据来源均不同。⑥**改进方向**（若需要更强结论）：抽样人工判卷（满分题与临界题各抽若干）+ 报告「人工判分与自动判分的一致率」。 |

## 11. 达标判定与未达标处理（**禁止造假的替代行为**）

| 情形 | 允许的处置 | **禁止** |
| --- | --- | --- |
| 严格准确率 < 90% | 如实报告未判对题号 + 归因（检索未命中 / 生成漏项 / 闸门误拒 / 跨语料污染 / 索引缺内容），修链路后复测 | 放宽 0.6 阈值、删题、改用例关键词迁就系统、用「宽松准确率」替代严格数 |
| recall@K < 95% | 用 M9 区分「索引里没有」与「没排上来」，逐关键词给证据；给出可达题上的指标 | 直接删掉不可达题、静默改 K |
| 延迟超 3000 ms | 复测口径（预热 / 独占 / 缓存），确认 `warmup_ms` 与冷启动轮未被计入，给前后对比 | 用缓存命中样本充当全量、只报平均值、删超线样本 |
| 跨语料泄漏 | 点名泄漏题 + 证据（问句、错语料文件与页码、top-3/top-10/引用级三档），补别名或路由规则后复测 | 把泄漏题从分母里悄悄剔除（跨文档题除外，且须显式声明口径） |
| 拒答率偏高 | 区分 `可答性闸门拒答` 与 `生成层兜底拒答`，给出 `refusal_reason` 分布与题号 | 调低闸门阈值换准确率（阈值变更须有 `阈值标定.json` 依据） |
| 原子护栏误拒 | 报告中被拒候选原文、缺失原子、草稿原子表（JSONL 已含），据此定位是护栏过严还是草稿原子表本身有问题 | 关掉护栏、或只改判据不改逻辑 |
| 图像/其它能力确实不可用 | 在报告与 README 登记为**已知限制**（图像块 = 0 的成因与影响） | 静默省略、含糊表述 |
| 英文题（Q13）未过 | 如实登记（英文为降级路径；`language_degraded`、`atomic_coverage` 一并给出），保留题目 | 删掉英文题或改判据 |
| 评估框架自身异常 | 先修框架（`异常题数 > 0` 时**退出码仍可能是 0**，必须看日志与汇总） | 拿有异常题的汇总结果当有效结论 |
