# 部署文档

**工单编号：人工智能NLP-RAG-修复低质量工业PDF的解析与信息丢失工单**
**项目：工业专利（图片型 PDF）多模态检索问答系统**

---

## 1. 部署形态说明

本系统的部署分两部分：

1. **RAGFlow（任务一）**：以 Docker 方式部署官方项目 `https://github.com/infiniflow/ragflow`，用于理解 deepdoc 解析流水线与对照组测试；
2. **本工单研发系统（任务二）**：一套可独立运行的 Python 工程，复现并修复低质量工业 PDF 的解析缺陷，完成 6 道选择题的 100% 作答。

本文档重点描述第 2 部分的本地部署；第 1 部分的 RAGFlow 容器化部署见第 5 节。

## 3. 安装步骤

### 3.1 获取代码与数据

代码位于交付目录 `交付/工单代码/工单十四/研发/`，数据位于 `data/`。将代码复制到本地工作目录后：

```bash
cd 研发

# source .venv/bin/activate     # Linux
pip install -r requirements.txt
```

### 3.2 配置环境变量

项目根目录的 `.env` 集中管理可调参数（均有默认值，可不配置直接运行）：

```ini
# OCR 专用环境的 Python 解释器路径（关键：需指向含 paddleocr 的环境）
PADDLE_PYTHON=H:\an\envs\paddleocr\python.exe

# OCR 参数
OCR_DPI=300
OCR_MIN_SCORE=0.50
OCR_LINE_TOL=28
OCR_USE_CACHE=1

# Ollama 服务
OLLAMA_BASE_URL=http://localhost:11434
LLM_MODEL=deepseek-r1:1.5b
EMBEDDING_MODEL_SLUG=bge-m3

# 检索默认策略
RETRIEVAL_STRATEGY=hybrid
RERANKER=linear
FUSION=rrf
```

### 3.3 验证 Ollama 与 OCR 环境

```bash
ollama list                                   # 确认 bge-m3 已就绪
"%PADDLE_PYTHON%" -c "import paddleocr; print('ok')"   # 确认 OCR 环境可用
```

## 4. 运行流程

### 4.1 构建知识库

```bash
python build_kb.py                 # 复用已落盘切片，重建向量与倒排索引
python build_kb.py --rebuild       # 强制重新解析 PDF（含 OCR / 附图语义）
python build_kb.py --force-ocr     # 忽略 OCR 缓存重新识别
```

首次运行若 OCR 缓存缺失，会自动渲染页面并调用 PaddleOCR 识别（8 页约数十秒）。二次构建命中缓存，仅重建向量与倒排索引（约 8s）。

构建完成后的索引规模（实测）：

```
块数: 17
模型维度: {'bge-m3': 1024}
倒排词表: 721
类型分布: {'figure': 2, 'text': 15}
```

### 4.2 命令行问答演示

```bash
python run_demo.py
```

逐题输出问题、选项、各选项得分、作答、标准答案、命中文档、响应耗时与证据片段。

### 4.3 选择题评测

```bash
python evaluate_mcq.py                                 # 默认 hybrid + linear
python evaluate_mcq.py --strategies vector,fulltext,hybrid   # 三种策略对比
```

输出 `output/eval_result.json`、`output/eval_report.md`、`output/strategy_compare.json`。

### 4.4 性能基准

```bash
python tools/bench_latency.py --strategies vector,fulltext,hybrid
```

输出 `output/latency_bench.json`（冷启动 / 热缓存两档）。

### 4.5 启动 Web 界面

```bash
streamlit run app.py
streamlit run app.py -- --demo        # 自动回放 6 题（用于截图 / 录屏）
```

浏览器访问 `http://localhost:8501`。左侧为知识库信息与检索策略配置面板，右侧为多模态问答对话区；`?expand=1` 可默认展开全部证据溯源面板。

### 4.6 生成图表与演示视频

```bash
python tools/gen_flowcharts.py                                   # 架构图 / 流程图（PNG + SVG）
python tools/capture_shots.py                                    # 浏览器界面截图
python tools/make_demo_video.py --shots "output/shots,output/figures" \
    --out "output/演示视频.mp4" --seconds 4 --fps 12             # 合成演示视频
```

## 5. RAGFlow 部署（任务一）

RAGFlow 官方提供 Docker Compose 一键部署：

```bash
git clone https://github.com/infiniflow/ragflow.git
cd ragflow/docker
docker compose -f docker-compose.yml up -d
docker logs -f ragflow-server
```

系统架构含两个核心组件：

- **API Server**（`api/ragflow_server.py`）：提供外部接口与平台功能，负责文件上传、知识库管理、解析任务入队；
- **Task Executor**（`rag/svr/task_executor.py`）：从 Redis Stream 消费任务，执行解析、分块、向量化与索引。

解析触发流程：文件上传后点击「解析」按钮 → API Server 按 `parser_id` 选择分块器并生成任务 → 任务写入 Redis Stream 消息队列 → Task Executor 消费并处理。

deepdoc 解析方案的技术细节见 [`任务一-RAGFlow技术实现方案总结.md`](../研发/任务一-RAGFlow技术实现方案总结.md)。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `未找到 PaddleOCR 环境 Python` | `.env` 中 `PADDLE_PYTHON` 路径不对 | 改为含 `paddleocr` 的解释器绝对路径 |
| OCR 结果为空或乱码多 | 渲染 DPI 过低 / 置信度阈值过低 | 提高 `OCR_DPI`，或提高 `OCR_MIN_SCORE` |
| 首次问答超过 3s | Ollama 嵌入模型冷加载 | 已内置 `warmup()` 预热；或先跑一次预热 |
| `向量库缺少模型 xxx` | 未构建该模型向量 | 运行 `build_kb.py --models xxx` |
| 界面证据面板收起 | Streamlit 重渲染 | 使用 `?expand=1` 参数默认展开 |
| `知识库未构建` | 未运行 build_kb | 先执行 `python build_kb.py` |
