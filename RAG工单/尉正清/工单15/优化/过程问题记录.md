记录实施过程中踩到的坑。每条都写了**现象 → 真因 → 怎么绕过去**。

## 一、建库/上传

### 1. `embedding_model` 必须写 tenant_llm 表里的**全名**

**现象**：
- 写 `bge-m3` → `Field: <embedding_model> - Message: <Embedding model identifier must follow <model_name>@<provider> format>`
- 写 `bge-m3@OpenAI-API-Compatible` → `Unsupported model: <bge-m3@OpenAI-API-Compatible>`
- 写 `bge-m3___OpenAI-API@OpenAI-API-Compatible` → ✅

**真因**：`add_llm` 给 `OpenAI-API-Compatible` 工厂注册的模型会自动加
`___OpenAI-API` 后缀存进 `tenant_llm.llm_name`，建库校验拿的是这个全名。

**为什么工单14 没遇到**：工单14 的库早就存在，`create_dataset` 走的是
「复用已有」分支，这条路径从没被执行过。

### 2. `POST /api/v1/datasets` 重名**不报错**，会静默改名

**现象**：每次跑 bootstrap 都打印「建库 wo15test（naive）」，结果库里出现了
`wo15test`、`wo15test(1)`、`wo15test(2)` 三个同名库。

**真因**：RAGFlow 遇到重名不拒绝，自动加 `(1)`、`(2)` 后缀再建一个。
原 `create_dataset` 是「先 POST，失败再按名查」，而 POST 永远不会失败，
复用分支形同虚设。

**处置**：改成**先按名查、查到就复用、查不到才建**。

### 3. 上传文件不能带 `Content-Type: application/json`

**现象**：`{'code': 101, 'message': 'No file part!'}`

**真因**：清理工单14 代码时把 `upload()` 的头统一成了 `self._h()`，
而它带 `Content-Type: application/json`，会把 requests 自己生成的
`multipart/form-data; boundary=...` 顶掉。上传只需要带 `Authorization`。

### 4. 建对话助手前必须等解析出分片

**现象**：`{'code': 102, 'message': "The chat doesn't exist"}`

**真因**：带 `dataset_ids` 建助手时会校验
`The dataset doesn't own parsed file`（`api/apps/sdk/chat.py:161`），
而刚触发的解析还没跑完，`chunk_num` 还是 0。

**处置**：bootstrap 里加上轮询等 `progress >= 1.0`。

## 二、改 RAGFlow 代码

### 5. `figure_parser.py` 原本没有 `import logging`

**现象**：新加的 `_mark_figures()` 里写 `logging.info(...)`，解析跑完
**没有任何日志**，标记也没生效。

**真因**：该文件没有导入 `logging`，`logging.info` 抛 `NameError`；
而调用它的 `vision_figure_parser_pdf_wrapper` 外面套着
`except Exception as e: callback(0.8, f"Visual model error: {e}...")`，
**异常被吞掉**，只表现为「图块没被增强」，很难发现。

**教训**：给这类「外面套了宽 except」的模块加代码，改完先跑一次
`ruff check --select F821`（或任何静态检查），别等解析跑完 3 分钟才发现。

### 6. 挂了文件 ≠ 生效 —— 已加载的模块不会重载

**现象**：改好 `figure_parser.py`（bind mount，文件内容立刻是新的），
重新触发解析，产出还是旧格式的标记。

**真因**：`docker compose up -d ragflow-cpu` 在**配置没变时不会重建容器**，
task executor 进程still 跑着上次启动时 import 的旧模块。

**处置**：改 Python 代码后一律 `docker compose up -d --force-recreate ragflow-cpu`。
（改 `.json`/`.env` 这类数据文件则可以只重启；改 `.env` 的**新增变量**同样
需要重建容器才会进环境变量。）

### 7. `reparse.py --force` 有时不会真的重新解析

**现象**：删了 chunk、触发了 parse，15 秒就"完成"，读到的是**上一轮**的
`progress_msg`，chunk 内容没变。

**真因**：RAGFlow 对「解析配置没变」的文档有 digest 去重
（`task_service.py:467-511`）；另外容器刚重建时 API 还没起来，请求会拿到 502。

**处置**：`reparse.py --force` 之后如果发现 `progress_msg` 还是旧的，
手动删一次 chunk 再触发（见 `测试/reparse.py` 的 `--force`）：
先 `DELETE .../documents/{id}/chunks`，再 `POST .../chunks`。
**并且要等 `curl http://localhost/v1/system/version` 返回 200 再操作**。

### 8. `docker compose up -d`（不带服务名）会去拉全部服务的镜像

**现象**：`Error ... quay.io/minio/minio ... 401 UNAUTHORIZED`，
容器没起来。

**真因**：`docker-compose-base.yml` 里声明了 minio / opensearch / infinity /
oceanbase / seekdb 等服务（本项目用不到），不带服务名时 compose 会尝试准备
整个项目。

**处置**：`docker compose up -d ragflow-cpu`（工单14 一直是这么用的）。

## 三、模型与提示词

### 9. RAGFlow 默认只给模型 **512** 个 max_tokens

**现象**：开了思维链以后，一半题目返回**空字符串**，HTTP 200 不报错。

**真因**：助手配置 `dialog.llm_setting` 里存的是
`{"temperature": 0.1, "top_p": 0.3, "max_tokens": 512}`，
RAGFlow 把它整个透传给模型。deepseek 的思维链与正文**共用**这个额度，
512 个 token 被思考过程吃光，正文就是空的。

**处置**：在 LLM 调度层给 `max_tokens` 设下限（外部可配 `RAGFLOW_MAX_TOKENS`，
默认 8192，取「助手设置」与「下限」的较大者）。注意 `setdefault` 拦不住 ——
`gen_conf` 里已经有这个键了，必须显式取 max。

### 10. 图纸块会**跨页合并**，图号和页码都可能不准

**现象**：明明在第 11 页的图3，标记出来是「图2｜第10页」。

**真因**：`_extract_table_figure` 会把相邻页的图分到一组，`cropout()`
只按组里**第一页**记位置戳；图注也是把组内所有图注拼在一起
（实测第 11 页那块的图注是 `图3 图 2 1` 这种糊在一起的）。
另外多模态模型自己写的描述里会把「图 3」读成「图 2」。

**处置**：
- 图号**只从 OCR 出来的图注里取**（不要从整段描述里取，会被模型的误读带偏）；
- 图注里的图号**全部列出**（`图3/图2`），只取第一个会漏掉真正要的那张；
- 页码**每一页都写出来**（`第10页｜第11页`），这样问「第11页」能命中。

### 11. 「检索变好」≠「答对」—— 加分要配闸门

**现象**：加完图纸标记后准确率从 5/6 掉到 3/6。

**真因**：加分只按「标记里出现图3」匹配，结果把**图例说明页**（正文里列了
「图1/图2/图3 各是什么」的清单）也加了分，它挤进第 2 名；真正用来答题的
正文段（落料架10/紧固机构11/保护管12/链条13）被挤到第 4 名。

**处置**：问题里给了页码时，页码当**闸门** —— 标记里不含该页的块一律不加分。

### 12. 从上一份工单抄来的提示词会带偏

**现象**：工单15 的助手提示词是从工单14 直接拷的，第 3 条讲的是
「气流」「配气带孔盘」「壳体」—— 那是**上一份专利**的零件名。

**处置**：改成与具体文档无关的通用表述（「物料真正穿过或与之发生作用的零件」），
并且在 4 道图文题上做过离线 A/B 才定稿。**别跨工单直接复用提示词规则。**

## 四、其它

### 13. 加分是加在**阈值之前**的

`boost_scores()` 插在 `search.py` 里「算完融合分」和「阈值过滤」之间，
所以调大 `figure_boost` 时要注意别把 `top_n` 撑满、把正文块全挤出去。
调参时配合 `diag_retrieval.py` 看召回列表，别只看最终准确率。
