# 工单06 混合检索 技术文档

**工单编号：人工智能NLP-RAG-混合检索任务**

本系统在基于招股说明书的问答系统中提供三种可配置、可切换的检索策略：
向量检索（召回+重排）、全文检索、混合检索（同时执行前两者）。本文档说明
各策略使用的核心技术、打分公式与工程取舍，对应演示视频中「语义检索、
全文检索分别用的什么检索技术」的讲解内容。

## 1. 语义检索（向量检索：召回 + 重排）

### 1.1 嵌入模型

使用 `sentence-transformers` 加载中英文嵌入模型，注册表见
`rag_core/embed.py::MODEL_REGISTRY`：

| 模型 | 维度 | 说明 |
| --- | --- | --- |
| `bge-large-zh-v1.5` | 1024 | 主用模型，中文金融/招股书语料表现最优 |
| `bge-m3` | 1024 | 多语言长文本，支持稠密+稀疏+多向量 |
| `m3e-base` | 768 | 轻量中文模型，用于对比实验 |

要点：
1. **查询前缀**：BGE 系列官方要求在检索 query 前加指令前缀
   「为这个句子生成表示以用于检索相关文章：」，文档侧不加；
   不加前缀会明显掉点（`embed.encode(is_query=True)` 自动处理）。
2. **归一化**：输出向量做 L2 归一化（`normalize_embeddings=True`），
   于是余弦相似度退化为点积，省去逐对求模的除法。
3. **多模型切换**：`embed.set_model(name)` 运行时切换；不同维度模型
   写入不同向量集合（如 `prospectus` 与 `prospectus_m3e`），
   查询向量与库内向量必须同模型，否则相似度无意义。

### 1.2 相似度计算

```
余弦相似度：  cos(q, d) = (q · d) / (|q| · |d|)

L2 归一化后 |q| = |d| = 1，因此：

              cos(q, d) = q · d = Σ_i q_i · d_i
```

分数区间 [-1, 1]，越大越相似；招股书场景常见命中区间约 0.5~0.8。

### 1.3 近邻索引（HNSW）

向量库由 ChromaDB 持久化，集合元数据 `hnsw:space = cosine`。HNSW
（Hierarchical Navigable Small World）用多层可导航小世界图做近似最近邻：

```
  Layer 2   A ──────────────── F            （稀疏，长跳，快速逼近）
              \              /
  Layer 1   A ── C ── D ── F ── H           （中等密度）
               \  |   |   /
  Layer 0   A─B─C─D─E─F─G─H─I─J             （全量数据，短跳精查）

  检索：从顶层入口点贪心下降，每层选距 query 最近的邻居作为下一层入口，
        底层做 ef 宽度的候选扩展，返回 Top-k。
```

复杂度从暴力检索的 O(N·d) 降为近似 O(log N · d)。本工程文档规模
（数千块）下两种方式延迟均 <100ms；HNSW 为后续扩容预留了性能空间。

### 1.4 召回 + 重排的两段式设计

```
  全库 N 块 ──HNSW 召回──> Top-20（recall_k） ──重排器──> Top-5（top_k）
             追求高召回（不漏）              追求高精度（排序准）
```

对应参数：`config.TOP_K_RECALL = 20`、`config.TOP_K_RERANK = 5`。

### 1.5 结构感知分块（工单02 继承）

招股书按章节结构切块，并把章节路径注入块首：

```
【第五节 业务与技术 > 一、主营业务 > （三）军用领域收入】
报告期内，公司来自军用领域的收入分别为 6,464.51 万元、……
```

好处：① 向量语义更聚焦；② 关键词（军用领域/主营业务）在块内显式出现，
BM25 与重排器均可命中；③ 片段自带来源路径，答案可溯源。

## 2. 全文检索（倒排索引 + Okapi BM25）

### 2.1 倒排索引结构

`rag_core/bm25.py::BM25Retriever` 自研倒排索引，不依赖 Elasticsearch：

```
  正排： doc_0 → "报告期内，公司来自军用领域的收入分别为…"
         doc_1 → "第五节 业务与技术…"

  倒排： 军用   → {doc_0: 1.6, doc_7: 1.6, doc_9: 3.2, …}   # 加权词频
         收入   → {doc_0: 2.0, doc_2: 1.0, …}
         视频   → {doc_3: 1.0, …}
         …

  辅助： doc_len[i]（加权文档长度）、avgdl（平均长度）、N（文档总数）
```

查询时只遍历 query 词条对应的倒排列表（而非全部文档），这是「快速定位」
的关键。中文分词优先 jieba；环境缺失时降级为「单字 + 二元组」切分，
保证任何环境都能跑通。

### 2.2 Okapi BM25 打分公式

```
score(q, d) = Σ_{t ∈ q} IDF(t) · ─────────────────────────────
                                   f(t,d) · (k1 + 1)
                  ─────────────────────────────────────────────
                   f(t,d) + k1 · (1 - b + b · |d| / avgdl)

IDF(t) = ln( 1 + (N - n_t + 0.5) / (n_t + 0.5) )
```

- `f(t,d)`：词条 t 在文档 d 中的（加权）词频；
- `|d|`：文档长度，`avgdl`：平均文档长度；
- `k1 = 1.5`：词频饱和系数——词频涨到一定程度后收益递减，防止堆词作弊；
- `b = 0.75`：长度归一化强度——长文档天然含词多，需要打折。

### 2.3 多字段加权（工单要求：标题/正文/摘要）

本工程对每个块的两个字段分别统计词频并加权求和：

```
  f(t, d) = 1.0 × tf_text(t, d) + 1.6 × tf_section(t, d)
                     正文权重                章节路径（标题）权重
```

章节路径（如「第五节 业务与技术 > 一、主营业务」）是人工归纳的高信息密度
字段，权重 1.6 让标题里的关键词更"值钱"。索引统计中会输出两字段的覆盖块数、
总词数、去重词数与平均长度（见 `results/index_stats.json` 的 `multi_field`）。
核心库默认字典 `{"text": 1.0, "section": 1.6, "title": 2.0}` 还预留了
`title` 字段，供其他语料（如年报标题）使用。

### 2.4 三种查询能力

**① 布尔查询**（`search(query, boolean="AND"|"OR"|"NOT")`）

```
  AND： hit = D(t1) ∩ D(t2) ∩ …      词条倒排列表求交（精确、宁缺毋滥）
  OR ： hit = D(t1) ∪ D(t2) ∪ …      求并（扩大召回）
  NOT： hit = D(t1) − D(t2) − …      首词列表减去其余词条（排除干扰项）

  D(t) 表示包含词条 t 的文档集合
```

**② 短语匹配**（`phrase_search`）：对原文做精确子串扫描，命中次数作为分数。
专有名词、技术标准名（如「视频指挥系统技术标准」）、精确数字
（如「5,520」「42.35%」）用它可以绕开分词误差。

**③ 模糊匹配**（`fuzzy_search`）：

```
  通配符： pattern = "军用*"  →  正则 ^军用.*$ 展开倒排词条
  编辑距离： |len(t) - len(p)| ≤ max_dist 且 Levenshtein(t, p) ≤ max_dist

  Levenshtein 用滚动数组 DP：dp[i][j] = min(
        dp[i-1][j] + 1,            # 删除
        dp[i][j-1] + 1,            # 插入
        dp[i-1][j-1] + (a_i ≠ b_j) # 替换
  )
```

用于容忍错别字/形近字（如「收入」误打为「收人」）。

## 3. 混合检索（双通道 + 三种融合算法）

两路检索各取 Top-20 后，按所选融合算法合并。**关键点**：向量分数
（余弦，约 0~1）与 BM25 分数（无上界）量纲不同，融合前必须处理。

```
  ┌────────────┐  余弦分 0.62, 0.58, …      ┌─────────────────┐
  │ 向量通道    │ ─────────────────────────> │ 归一化 Min-Max   │ ──┐
  └────────────┘                            └─────────────────┘   │
                                                                  ├─> 融合排序
  ┌────────────┐  BM25 分 23.7, 19.2, …     ┌─────────────────┐   │
  │ 全文通道    │ ─────────────────────────> │ 归一化 / 仅取排名 │ ──┘
  └────────────┘                            └─────────────────┘
```

### 3.1 weighted 加权平均（量纲敏感，先归一化）

```
  norm_score(d) = (score(d) - min) / (max - min)        # 各自通道内 Min-Max

  final(d) = α · norm_vec(d) + (1 - α) · norm_bm25(d)

  α=0  → 纯全文； α=1 → 纯向量； 默认 α = 0.6（向量略占优）
```

同一 chunk 同时出现在两路时分数相加，`source` 标记为 `hybrid`。
适用：两路质量相当、希望用单一旋钮连续调节偏好。

### 3.2 rrf 倒数排名融合（工业界标配）

```
  final(d) = Σ_{r ∈ R(d)} 1 / (k + rank_r(d))          k = 60

  R(d)：d 在哪些通道出现；rank_r(d)：在通道 r 中的名次（从 1 起）
  （Cormack, Clarke & Buettcher, SIGIR 2009）
```

只使用名次、不使用原始分数，天然免疫量纲差异；对单通道高分但排名靠后的
情况不敏感，稳健性最好。本工程默认融合算法（`PRESETS["wo06_hybrid"]`）。

### 3.3 vote 投票机制

```
  votes(d) = |{通道 r : d ∈ Top-k_r}| ∈ {1, 2}
  final(d) = votes(d) + norm_vec(d) + norm_bm25(d)   （票数为主排序键）
```

两路都命中的片段得 2 票、优先展示，强调「共识结果」。适用：高风险问答，
宁可牺牲一点召回也要保证排序头部可靠。

### 3.4 三算法对比

| 算法 | 依据 | 量纲敏感 | 稳健性 | 可调性 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| weighted | 归一化分数 | 敏感（依赖归一化） | 中 | 强（α 连续可调） | 两路质量稳定、需调权重 |
| rrf | 名次 | 不敏感 | 高 | 弱（仅 k） | 默认/异构检索器融合 |
| vote | 命中票数 | 不敏感 | 高 | 弱 | 强调共识、结果头部可靠 |

> 实测入口：`src/hybrid_search.py`（同问题三算法排序差异 + α 从 0 到 1 扫描）。

## 4. 重排算法（3 种 + 级联）

召回阶段看的是「快而全」，重排阶段看的是「准」。工单要求至少 3 种重排算法，
本工程实现 4 种（含级联）。

```
              Top-20 候选
                  │
      ┌───────────┼───────────────┬────────────────┐
      │           │               │                │
  TF-IDF      LLM 列表级      自适应反馈        级联（推荐）
  词权重精排   逐片段打分      在线学习权重     TF-IDF 粗排 Top-10
  ~1ms        网络延迟        无网络依赖              ↓
                                              LLM 精排 Top-5
```

### 4.1 LLM 重排（`LLMReranker`）

把 query 与候选片段列表整体交给 LLM，要求输出 0~10 的相关性分数 JSON：

```
  rerank_score(d) = LLM_score(d) / 10            # 归一到 [0,1]
  final(d)        = 0.8 · rerank_score(d) + 0.2 · base_score(d)
```

- 优点：能理解「多期数据」「口径」「单位」等细粒度要求，精度上限最高；
- 缺点：网络延迟大、有调用成本；网络异常自动回退原顺序，不影响主流程。

### 4.2 TF-IDF 重排（`TFIDFReranker`）

轻量词权重模型，零成本、无网络依赖，作为默认档与级联第一级：

```
  基础分： score(d) = sqrt( Σ_{t∈q} (qtf_t/|q|) · (tf_t/|d|) · IDF(t)² )

  数字加权： score *= 1 + (number_boost - 1) · 命中数字数 / 问题数字数
  实体加权： score *= 1 + (entity_boost - 1) · 命中实体数 / 问题实体数

  number_boost = 2.0，entity_boost = 1.8
```

针对招股书问答的两个技巧：金额/比例/年份等**数字命中**显著加分；
公司名、专有名词等**实体命中**加分。

### 4.3 自适应重排（`AdaptiveReranker`，基于用户反馈）

用户点赞/点踩被沉淀为词条级反馈权重，实现「越用越准」：

```
  写入： term_feedback[t] += +1（点赞）/ -1（点踩），t ∈ query ∪ 片段
        type_feedback[type] += +1 / -1

  打分： prior(d)   = Σ_{t ∈ query} term_feedback[t] + type_feedback[type_d]
        adapted(d) = 1 / (1 + exp(-prior / 5))          # sigmoid 压缩到 (0,1)
        final(d)   = 0.7 · base_norm(d) + 0.3 · adapted(d)
```

sigmoid 压缩防止少量极端反馈主导排序；词条级反馈可在相似问法间迁移。
演示入口：`src/adaptive_feedback_demo.py`（同一 query 反馈前后排序对比）。

### 4.4 级联重排（`CascadeReranker`）

```
  Top-20 ──TF-IDF 粗排──> Top-10 ──LLM 精排──> Top-5
           （毫秒级）              （仅 10 条，控制延迟）
```

先用便宜的重排器把候选压到 10 条，再让 LLM 只处理这 10 条，
兼顾精度与工单「响应时间 ≤3 秒」的性能约束。工单06 预设
`PRESETS["wo06_hybrid"]` 即采用 hybrid(rrf) + cascade。

## 6. 常见问题

**Q1：相似度分数为什么只有 0.5~0.7？**
BGE 中文模型的相似度分布偏窄，0.6 已属高度相关；比较时应看相对排名而非绝对阈值。

**Q2：BM25 检索不到同义改写怎么办？**
BM25 只认词面。同义改写交给向量通道，混合检索的融合结果即可覆盖两类需求。

**Q3：未安装 jieba 会怎样？**
分词降级为单字+二元组，召回仍可用但布尔 AND/NOT 精度下降。
建议 `pip install jieba` 后重建 BM25 索引。

**Q4：LLM 重排超时/无 API Key？**
`LLMReranker` 捕获异常并回退为原顺序（打印 warn），主流程不中断；
生产环境建议用级联重排控制 LLM 调用量，或改用 TF-IDF 重排。
