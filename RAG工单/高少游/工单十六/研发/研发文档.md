## 一、研发目标与范围

针对 **RAGFlow 集成的 VLM 在工业专业问题上表现不佳**（对「淬火」「公差配合」等工业术语、
复杂图纸理解不足）的问题，本工单完成「微调数据准备 → 训练调试 → 效果评估」全流程：

```
IMDR QA 对 + RAGFlow 图文块
        │
        ▼
① 数据格式转换  → image / question / answer JSONL（+ LLaMA-Factory sharegpt 导出）
        │
        ▼
② LoRA 微调      → 冻结视觉塔，仅语言侧线性层注入 LoRA（CPU 真实跑通 ≥1 epoch）
        │
        ▼
③ 专业评估       → 专业术语准确性 + 图纸推理正确性 + BLEU/ROUGE，微调前后对比 + 失败分析
```

对应工单三项产出物：

| # | 工单产出物 | 本工程实现 |
|---|---|---|
| 1 | 数据格式转换脚本 | `src/data_converter.py`、`convert_data.py` |
| 2 | 可成功运行的微调配置文件和启动命令 | `config/*.yaml`、`src/lora_trainer.py`、`train_lora.py` |
| 3 | 含专业评估指标的评估脚本 + 对比评估报告 | `src/industrial_metrics.py`、`src/evaluator.py`、`src/report_builder.py`、`evaluate.py` |

## 三、数据准备与格式转换实现（产出物 1）

### 3.1 两类数据源

**A. IMDR QA 对**（`data/raw/questions.jsonl`，10096 题 / 1700 篇专利 PDF）

原始字段：`question`、`document`、`options[A-D]`、`answer`（正确选项字母）、`group`。
按 `group` 分三类，与工单两个评估维度对齐：

| group | 题型 | 承载页来源 | 对应评估维度 |
|---|---|---|---|
| 1 | 文本术语类 | 用**正确选项文本**在 PDF 中检索定位承载页 | 专业术语准确性 |
| 2 | 图纸位置类 | 题干显式「第 N 页」 | 图纸推理正确性 |
| 3 | 图纸原理类 | 题干显式「第 N 页」 | 图纸推理正确性 |

**B. RAGFlow 解析出的图文块**（`vector_db/ragflow_chunks.jsonl`）

字段与 RAGFlow 图文块对齐：`content_with_weight`、`img_id`、`page_num_int`、`position_int`、`top_int`。
若无现成解析结果，则由 `ragflow_chunks.synthesize_chunks()` 从 PDF 合成同构块，
再转为「看图概述该页技术内容」的图文对，仅加入训练集。

### 3.2 转换逻辑（`src/data_converter.py`）

```
select_documents()        按文档分层抽样（train 96 篇 / eval 32 篇，同文档不跨集，避免泄漏）
        │
make_samples()            逐文档逐题：
        ├── group 2/3  → parse_page_ref() 解析「第N页」
        ├── group 1    → locate_answer_page() 用答案文本检索承载页
        ├── _render_if_needed() 渲染该页为 PNG（pymupdf 2x 栅格化，幂等缓存）
        └── 组装 image / question / answer（question 内含 A-D 选项与作答格式约束）
        │
        ▼
write_jsonl()             data/train.jsonl、data/eval.jsonl
write_llamafactory()      data/llamafactory/{train,eval}.json（sharegpt + images）
```

### 3.3 输出格式

每条样本（`data/train.jsonl`）：

```json
{
  "id": "CN100342976C-g2-1",
  "source": "imdr",
  "image": "data/images/CN100342976C_p7.png",
  "question": "请阅读提供的专利文件页面，回答问题并选出唯一正确选项。\n回答格式：先给出选项字母，再给出该选项的完整内容。\n\n问题：在文件中第7页的图片中，部件4相对于部件5在图片中的位置关系是？\n选项：\nA. ...\nB. ...\nC. ...\nD. ...",
  "answer": "A. 部件4位于部件5的左侧",
  "gold_letter": "A",
  "group": 2,
  "doc": "CN100342976C.pdf",
  "page": 7
}
```

LLaMA-Factory 导出（`data/llamafactory/train.json`）：

```json
{"messages": [{"role": "user", "content": "<image>请阅读..."},
              {"role": "assistant", "content": "A. ..."}],
 "images": ["data/images/CN100342976C_p7.png"]}
```

## 四、LoRA 微调实现（产出物 2）

### 4.1 关键配置（`src/config.py`）

| 项 | 取值 | 说明 |
|---|---|---|
| LoRA rank / alpha / dropout | 16 / 32 / 0.05 | 语言侧注意力与 MLP 投影层 |
| 目标模块 | q/k/v/o/gate/up/down_proj | 自动探测并**排除 vision_model**（冻结视觉塔） |
| 图像预处理 | 单块 512、关闭切片 | 控制图像 token，CPU 可训练 |
| 学习率 / 调度 | 2e-4 / cosine + warmup 0.05 | 小模型 LoRA 常用区间 |
| 批次 | batch=1 × grad_accum=8 | 等效 batch 8 |
| 序列长度 | 1024 | |
| 损失 | 仅 assistant 段（prompt 段 label=-100） | |

### 4.2 训练实现（`src/lora_trainer.py`）

- **Tokenizer/模板**：复用基座 processor 的 `apply_chat_template`，训练与评估共用
  `vlm_backend.build_inputs`，保证 prompt 与标签口径一致；
- **仅 assistant 段计损失**：先编码 prompt 得到长度，再把 labels 前段置 `-100`；
- **梯度累积**：`loss /= grad_accum` 后 `backward()`，每 8 步 `clip_grad_norm_` + `opt.step()`；
- **学习率**：`lr_at(step)` 实现 warmup + cosine，逐步写回 param_group；
- **日志**：每 `LOGGING_STEPS=5` 步记录 `loss / lr / elapsed`，落盘 `output/train_log.json`（含 loss 曲线）。

### 4.3 启动命令

```powershell
python train_lora.py --epochs 2          # 完整训练（2 epoch）
python train_lora.py --max-steps 6       # 冒烟测试
```

生产 GPU（LLaMA-Factory）：

```bash
llamafactory-cli train config/llamafactory_qwen2vl_lora.yaml
```

## 五、专业评估实现（产出物 3）

### 5.1 指标设计（`src/industrial_metrics.py`）

工单要求「不仅计算 BLEU/ROUGE，更要设计工业准确性评估」，实现如下：

| 维度 | 指标 | 定义 |
|---|---|---|
| **专业术语准确性** | 选项判定准确率 | 从生成文本解析选项字母，与标准答案比对 |
| | 术语 F1 / 召回 | 以标准答案为术语集合（领域词表命中 + jieba 名词短语），衡量预测术语覆盖 |
| **图纸推理正确性** | 选项判定准确率 | 位置/原理题（group 2/3）选项判定是否正确 |
| 通用文本 | BLEU（zh）/ ROUGE-L / 精确匹配 | |

### 5.2 评估流程（`src/evaluator.py`）

```
load_eval_samples()        载入分层评估集（文本术语类 / 图纸位置类 / 图纸原理类）
        │
run_model(base)            基线模型逐题生成 → 逐题打分
run_model(PeftModel)       挂载 LoRA 适配器逐题生成 → 逐题打分
        │
_dimension_scores()        按「专业术语准确性 / 图纸推理正确性 / 总体」拆解
failure_analysis()         微调后仍错 / 由错变对（修复）/ 由对变错（退化）+ 归因
        │
        ▼
eval_result.json           含总体/分维度/分组指标 + 逐题记录 + 失败案例
```

### 5.3 报告生成（`src/report_builder.py`）

把 `train_log.json` 与 `eval_result.json` 转成 `eval_report.md`（**数据驱动，非人工填写**）：
训练概况 → 总体指标对比 → 分维度拆解 → 分题型细分 → 失败案例分析 → 下一步建议。

## 六、关键工程问题与解决

| # | 问题 | 根因 | 解决 |
|---|---|---|---|
| 1 | transformers 5.x 纯 CPU import 报错 | 导入期调用 `torch.accelerator.current_accelerator()` | `src/env_patch.py` 拦截并回退 CPU，入口脚本自动应用 |
| 2 | 模型下载 xet 通道 401 | xet 传输鉴权失败 | `HF_HUB_DISABLE_XET=1` + `hf-mirror.com` |
| 3 | LoRA 误含视觉塔线性层 | 自动探测未过滤 | `lora_targets()` 排除 `vision_model` / `vision_tower` |
| 4 | CPU 单步过慢（≈11 s） | 默认图像切片产生约 900 图像 token | 单块 512 + 关闭切片，token 降至约 100 |
| 5 | 文本类问题无页码引用 | IMDR 仅图纸题给「第 N 页」 | 用正确选项文本在 PDF 中检索承载页 |
| 6 | 同文档跨训练/评估泄漏 | 随机切分样本 | 按**文档**切分（train 96 / eval 32） |
