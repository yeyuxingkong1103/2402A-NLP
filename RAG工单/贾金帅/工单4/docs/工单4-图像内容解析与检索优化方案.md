## 零、一句话结论

把 PDF 里的**图**从「一堆不可检索的位图 + 被打散的文字碎片」变成「结构化描述 + 跨模态向量」之后，
**两道新增图像题的关键事实覆盖率从 62.5% 提升到 100%（1/2 → 2/2 全中）**；
其中 id=5 问的「谁挂在谁下面」这类**归属关系**（正文与图内散字里都不存在，只存在于连接线的几何拓扑中）
从 **0.000 提升到 1.000**。

代价与修复也如实写在第四、六节：新增的 68 个图像块会给排序引入噪音，
16 题的整体 MRR 一度从 0.783 掉到 0.768（-2.0%）；
定位到是「证照照片」这类低信息图抢占了排名后，加了一个**只作用于排序、不动依据分**的
小幅惩罚，MRR 回到 0.809 —— 反而比不解析的基线还高 3.3%，而关键事实的收益一分未丢。

更贴近生产的一段证据在**带闸门口径**（线上真实配置，依据分 ≥ 0.75 才进上下文）：
不解析时 16 题只有 13 题全中、关键事实覆盖 0.891，**有两道题的关键事实因为依据分不够而根本进不了上下文**
（id=6 漏 `14.0%/IC卡/2.0%`、id=531 漏 `程家明`）；打开图像解析后是 **0.969 / 15 题全中**，两道题双双救回。

## 二、答案在 PDF 中的定位（工单备注要求）

> 页码口径：统一使用 **PDF 物理页序（1-based）**。力源 PDF 的书眉上印的是「3-21」这类原书章节页码，与物理页序不同，引用时以物理页序为准。

| id | 问题 | 答案所在位置 | 图的形态 | 关键事实 |
|---|---|---|---|---|
| **5** | 组织结构图中，销售部有几个部门构成？其中大客户销售部有几个销售处构成？ | **力源 p39**「（二）发行人内部组织结构图 / 1、公司组织结构图」 | 29 个位图节点框 + 37 条矢量连接线，聚类成 1 个图区域 | 销售部 = **4** 个部门：电话及网络销售部、渠道销售部、大客户销售部、国际贸易部；大客户销售部 = **6** 个销售处：珠海、深圳、北京、武汉、广州、成都 |
| **6** | 2008 年中国 IC 市场应用结构与增长图中，增长率最快的是哪个行业？负增长的是哪个行业？ | **力源 p72** 与 **力源 p310**《2008 年中国 IC 市场应用结构与增长（亿元）》 | 柱状图 + 折线（增长率）复合图 | 增长最快 **汽车 14.0%**；负增长 **IC 卡 −2.0%**；其余：工控 10.5%、计算机 7.9%、其他 6.1%、消费 5.1%、网络通信 2.6% |

### 为什么必须做图像解析（这是工单4 的直接动因）

**id=5：答案的两种成分，一种能"捡漏"、一种绝对捡不到。**

- 「销售部下面有哪 4 个部门」这种**名词清单**，在 PDF 文字层里是存在的 —— 但被**逐字打散**：
  pypdf 抽出来是「电」「话及」「网」「络销」「售部」，且竖排节点名的列序与阅读序不一致。
  更要命的是这些散字**留在正文里**（不做图像解析时），拼一拼能凑出大部分部门名 ——
  这就是为什么对照组（图像不解析）在名词清单上的覆盖率也有 0.625。
- 「6 个销售处**挂在『大客户销售部』下面**」这种**归属关系**，正文一个字都没写：
  p40 只说销售部下设 4 个部门，p113 只说设了 6 个销售处，**没有任何一句话把两者连起来**。
  关系只存在于 p39 那 37 条连接线的几何位置里。对照组在这项上的得分是 **0.000**。

**id=6：连"捡漏"都没有。**

正文只写「工业控制领域…增长率达 10.5%，在所有应用行业中位列第二，仅次于汽车电子」——
由它最多反推出"汽车电子第一"，**推不出谁在负增长**，更拿不到 14.0% / −2.0% 这两个数。
所有行业的增长率数值都只存在于 p72/p310 那张柱状图的柱顶与折线标注里。

## 三、技术方案

### 3.1 总览：四个新增模块 + 一处检索接线

```
PDF 页面
   │
   ├─(1) image_detector.py   图区域检测 ── 位图 bbox ∪ 矢量 bbox → union-find 聚类
   │         │                           过滤页眉/页码/页边、排除表格线框
   │         ├─→ 裁剪 PNG（220 dpi）→ data/images/<doc>/p<页>_f<序>.png
   │         ├─→ 图题识别（紧贴图区上下 26pt 的正文行）
   │         └─→ 本页要从正文剔除的行（图内散字 + 图题）
   │
   ├─(2) diagram_topology.py 几何拓扑 ── 方框-连接线图的父子关系（**p39 的唯一权威来源**）
   │
   ├─(3) image_semantics.py  多模态大模型 ── qwen-vl-plus 输出 6 节结构化描述
   │         └─→ 第二遍校验（struct 路 / data 路）
   │
   ├─(4) clip_encoder.py     Chinese-CLIP ── 图向量 → 以文搜图通道
   │
   └─(5) retriever.py        融合：依据分 + 文档共识 + 文档消歧 + CLIP 先验 − 低信息图惩罚
```

### 3.2 图区域检测（`src/image_detector.py`）

**难点：PDF 里的「图」从来不是一张干净的图。**

力源 p39 那张组织结构图，在 PDF 内部是 **29 个位图对象**（每个节点框一张）+ **37 条矢量线段**。
单独抠出任何一个图元，得到的只是一块灰底矩形；而 29 个节点框彼此之间隔着 30~40pt 的空隙，
按"连通性"聚类根本连不起来。做法：

1. **候选图元 = 位图 bbox ∪ 矢量 bbox**。矢量里同时包含**退化矩形**（连接线在 PDF 里是
   `(153,301,423,301)` 这样的零高横线、`(288,99,288,138)` 这样的零宽竖线）。
2. **union-find 聚类**，判据是扩张后的矩形相交，`gap = 30pt`（两边各扩 15pt）。
3. **过滤**：`min_w = 90pt`、`min_h = 55pt`、面积占比 ≤ 0.75；
   并整块裁掉页眉（上 70pt）／页码（下 62pt）／页边（左右 30pt）——这三个区域里的分隔线
   很容易被误检成"图"。
4. **排除表格**：表格的线框也会出现在 `get_drawings()` 里。判据不能用"面积比"
   （表格边框如 321×0.4pt，面积不小，但与图 bbox 的重叠面积恒为 0），
   改用**「细长」判据 `min(w, h) ≤ 2.0pt` → 判中点是否落在表格框内**。

踩过的三个坑（都会让整张图**碎掉或消失**，值得记下来）：

| 坑 | 症状 | 根因 | 修法 |
|---|---|---|---|
| 按 xref 去重 | p39 一个图都没检出来 | 29 个节点框只对应 8 个 xref，去重后剩 8 块孤立矩形，跨不过 39pt 的空隙 | **不按 xref 去重** |
| 丢掉退化矩形 | 同上 | `_clip_to_content` 把零宽/零高的线段当"退化矩形"丢弃，而它们正是节点间唯一的"桥" | 整条线落在正文区内时**保留原始坐标** |
| 只单边扩张 | p38 股权结构图被切成两张 | 单纯按 `gap` 扩张某一边，等效间距只有 `gap/2` | 两边**同时**扩张 `gap/2` |

**结果：68 个图区域（力源 39 / 兴图 29），其中 41 个检出了图题。**
图元构成：纯位图 44 / 位图+矢量混合 23 / 纯矢量 1。

**裁剪 DPI = 220**。实测 150 dpi 太糊（细连接线看不清）；**300 dpi 反而更差**——
图被模型内部缩放后连接线更糊，p39 把「销售部」数成 3 个部门。220 是实测的甜点。

### 3.3 图题识别与正文剔除

- **图题**：紧贴图区域上下 26pt 内的正文行，且与图区域水平重叠 ≥ 较窄一方的 30%。
- 两个必须排除的干扰：
  - **章节标题**（p110 的 `(3)渠道销售`、p113 的 `(4)大客户销售`）——它们紧贴图区、格式也像图题。
    用 `_HEADING_RE`（`(一)`／`第X节`／`1.2.3`／`一、`）排除。
  - **段落散文**——用 `_PROSE_END_RE`（以 `。；;` 收尾的长句）排除。
- **图题逐行保存、不拼接**：p39 的图题有两行（标题 + 资料来源），拼起来会让行匹配失效。
- **正文剔除**用**「字符多重集包含」**而不是行字符串匹配：
  图内竖排节点名被文字层逐字打散，且两个解析器的空格口径不同
  （`2008年中国 IC 市场…` vs `2008 年 中国IC 市场…`），行字符串匹配必然失配。

### 3.4 多模态大模型语义解析（`src/image_semantics.py`，主力路线）

模型 `qwen-vl-plus`（`qwen-vl-max-latest` 在本账号下 HTTP 403 无权限）。
每张图输出**6 节结构化文本**：`图类型 / 图题 / 图内文字 / 结构关系 / 数据 / 可回答的问题`。

提示词里有 5 条硬性要求，都是踩过坑之后加的：
1. **照抄全部，不许用"等"** —— 否则 6 个销售处会变成"珠海、深圳等 6 个销售处"。
2. **层级关系逐层写全** —— 不能只列节点名。
3. **数值逐项列出、含负值** —— 负增长那一项最容易被漏（正文里根本不存在，模型漏了就彻底丢了）。
4. **看不清写「（不清）」不许编造** —— 招股书里的数字编错比不写更糟。
5. 中文回答。

**第二遍校验**（按图类型分路）：
- `struct` 路（组织结构/流程/架构/关系图）再问一次层级归属；
- `data` 路（饼图/柱状/条形/折线/统计图）专门问一次"**有没有负值项**"。

实测：**68/68 全部成功，0 失败**；平均 7.3 s/张、中位 6.4 s、最长 28.8 s、合计 **8.3 分钟**。
其中 19 张走了 data 路校验、15 张走了 struct 路。p72/p310 的 data 路校验**完全正确**
（i.e. 抓到了 `负值项：IC卡：-2.0%`）。

### 3.5 几何拓扑：层级归属的权威来源（`src/diagram_topology.py`，本工单的关键突破）

**多模态大模型在"层级归属"这件事上不稳定。** p39 同一张图、同一个提示词、`temperature=0`，
三次跑出三种层级：
```
2+4  /  6  /  2+1+1+2
```
即「6 个销售处」有时被拆成「电话及网络销售部 2 个 + 渠道销售部 1 个 + 大客户销售部 1 个 + 国际贸易部 2 个」。
**靠采样投票也兜不住**：3 次采样里有 1/4 的概率凑不出多数。

但方框-连接线这类图，父子关系是**几何唯一确定**的：
- **母线型**（宽高比很大的细长矩形，如顶部的"股东大会"横条）：
  从母线向上引竖线找父节点、向下引竖线找子节点；
- **直连型**：父节点底边 → 竖线 → 子节点顶边。

配套的**竖排文字还原**：`_box_text` 用列量化（`col_q = 6.0pt`）+ 排序键 `(-列, 行)`
（中文竖排自上而下、列自右向左），把「电/话/及/网/络/销/售/部」还原成「电话及网络销售部」。

**p39 实测：29 个节点 / 21 条边 / 完全正确。** 输出：
```
销售部 → 电话及网络销售部、渠道销售部、大客户销售部、国际贸易部
大客户销售部 → 珠海销售处、深圳销售处、北京销售处、武汉销售处、广州销售处、成都销售处
各层级子节点数量：… 销售部 4 个；大客户销售部 6 个
```

`render_description()` 里有一条硬规则：**当 `topology.usable` 为真时，层级关系以几何拓扑为权威**，
模型读到的层级降级为「（参考）」。这样渲染出的描述是：
```
结构关系（按 PDF 矢量连接线几何还原，权威）：
   …
（参考）多模态模型读出的层级：
   …   ← 即使这里被拆错，上面的权威段落仍然是对的
```

**已知限制（如实记录）**：68 张图里只有 **1 张**（p39）抽出了可用的拓扑。
其余同类图（p38 股权结构图、p110/p113 业务流程图）要么是**一整张位图**（矢量层是空的），
要么用**斜向线段 / 填充路径**画连接线，几何规则匹配不到。
这类图仍靠多模态描述兜底 —— 它们对应的题目恰好不在验收清单里，但这是真实的能力边界。

### 3.6 CLIP 跨模态通道（`src/clip_encoder.py`，第二条路线）

工单备注写的是「使用多模态模型（**CLIP 或**多模态大模型）实现」——**两条都落地**，
因为它们解决的不是同一件事：

| 路线 | 产物 | 作用 |
|---|---|---|
| 多模态大模型（主力） | 图的**文本描述** | 让**文本检索**能命中图里的内容（id=5/id=6 靠它） |
| CLIP（本模块） | 图的**跨模态向量** | 让**以文搜图**直接成立：问题向量与图向量在同一空间比相似度 |

CLIP 的独立价值在于：当问题措辞与图的文本描述**用词对不上**时
（问「哪个行业的增长是负数」，描述里写的是「IC 卡：−2.0%」——「负数」和「−2.0%」在字面与向量空间都不近），
纯文本检索会漏，跨模态向量仍可能把那张柱状图排上来。

模型：`OFA-Sys/chinese-clip-vit-base-patch16`（中文原生），**CPU 推理**
（本机是 RTX 3050 Laptop 4 GB，且 torch 装的是 CPU 版；离线批处理没必要动显卡）。

检索侧的接线与既有的文档先验**同一套设计**：
- 相似度**按组内最大值归一到 0~1**再乘权重（与 BM25 项一样），避免随语料规模漂移；
- 加**地板值** `RETRIEVAL_CLIP_MIN_SIM = 0.20` —— CLIP 的相似度**恒为正**
  （中文图文对普遍落在 0.1~0.35），不加地板等于给全库 68 张图无条件发先验，会污染表格题与正文题；
- **只加 score、不加 evidence** —— 依据分是绝对量纲、是阈值闸门的唯一判据；
  让"长得像图"进闸门会变成"离题问题也该放行"；
- **映射用图的身份 `(doc_key, 页, 序号)` 而不是索引里写死的行号** ——
  这样"算完 CLIP 向量"不必回头重建索引（行号会随重算向量失效）；
- CLIP 加载失败 / 向量缺失 → **静默降级**，并在 `trace.steps` 里写明原因，检索链路照常工作。

> 本机网络受限，Chinese-CLIP 的 `pytorch_model.bin`（约 590 MB）在本轮交付时**只下到 60 MB**，
> 因此消融实验里的 `T3_image_clip` 臂与 `T2` 数值相同（通道未生效，按设计自动降级，未报错）。
> 补齐方式见第八节复现步骤第 3 步；代码路径与降级逻辑均已完整验证。

### 3.7 检索侧融合与分块

图像块的分块策略（`src/chunker.py` 第三节）：
- 每个图区域 **1 个块**，正文 = 定位头（`【图】图类型（第X页 第Y张图）` + 来源文档 + 图题）+ 结构化描述；
- 描述超长时**按行（节）切**而不是按字符切 —— 从中间截断会让"结构关系"的层级断掉；
- 块上带 `image`（裁剪图相对路径）、`fig_type`、`caption`、`fig_page`、`fig_index`，
  前端据此**直接回显原图**。

融合公式（在工单2/3 的基础上新增最后一项）：
```
依据分 evidence = 余弦 + β · BM25归一                        β = 0.30
融合分 score    = 依据分 + δ·文档共识 + 文档消歧加成
                        + 0.12·CLIP相似度（归一后）
                        − 0.15·[低信息图]                     ← 工单4 新增调优
闸门            依据分 ≥ min_evidence（默认 0.75），只看依据分
```

### 3.8 一处实测代价与它的修法（低信息图排序惩罚）

加上 68 个图像块之后，**整体 MRR 从 0.783 掉到 0.768（-2.0%）**。逐题排查定位到两处：

| 题目 | 掉排名 | 元凶 |
|---|---|---|
| id=531（法定代表人） | 第 1 → 第 3 位 | 兴图 p539 那张**「证照照片」**的图像块 |
| id=543（注册资本） | 第 3 → 第 4 位 | 兴图 p149「2018 年各国军费支出及占 GDP 比重」图像块 |

p539 的图内文字是「二、发行人控股股东、实际控制人声明；本人承诺本招股意向书…」这类**签名页碎片**，
语义价值几乎为零，但它**恰好同时含有公司名与"法定代表人/注册资本"这类高频问题词**，
于是在字面与向量两路都拿到高分。

修法不是丢弃（信息仍在库里、界面仍能看到），而是给这类图一个**排序惩罚**：
`LOW_INFO_FIG_TYPES = ("证照照片",)`、`RETRIEVAL_LOW_INFO_PENALTY = 0.15`，
**只减 score、不动 evidence**（否则会变成"因为图类型不好，离题问题也该放行"这种说不通的逻辑）。
判据用**子串包含**而不是相等 —— 图类型是多模态模型自由生成的文本，
「证照照片」「营业执照照片」这类变体都该归到同一类。

**效果：MRR 0.768 → 0.809（+5.4%），id=531 回到第 1 名（+0.667）、id=543 的损失保持不变
（那张图确实是带数据的柱状图，不该被罚），关键事实收益一分未丢。**

id=543 剩下的 -0.083 如实保留：要修它就得扩大惩罚的图类型范围，
而那会连带惩罚 id=6 真正需要的那张柱状图 —— 得不偿失。

### 3.9 顺带修掉的一处口径缺陷：BM25 归一化的基准

加图像块时还暴露了工单2/3 遗留的一个隐患。**依据分**里的 BM25 项多年来是按
「全库 BM25 最大值」做归一（`b_norm = b_raw / bm25_max`），这个基准**极其不稳**：
图像块的文本是"结构化描述 + 图题 + 图内散字"，天然含有大量高频词，把全库最大值
从 12.31 抬到 19.34，于是**所有块的 evidence 被同比例压小** ——
id=531 的 0.7756 被压到 0.7436，**正好跌破 0.75 的闸门**，直接从检索结果里消失。

修法是把基准换成**稳健分位**而不是极值：

```python
ref_pool = sparse[pool] if pool else sparse
max_bm25 = (float(np.percentile(ref_pool, RETRIEVAL_BM25_REF_PERCENTILE))  # 默认 p95
            if RETRIEVAL_BM25_REF_PERCENTILE < 100.0 else float(sparse.max()))
...
b_norm = min(1.0, b_raw / max_bm25) if max_bm25 > 0 else 0.0   # 稳健基准下要截断到 1.0
```

- 用 **p95** 而不是最大值：少数极端高的块不再能"绑架"全库的归一基准；
- 加 `min(1.0, …)` 截断：p95 之下的基准意味着约有 5% 的块 `b_raw` 会超过基准，
  不截断会算出 >1 的"归一化"分数，反而给它们超额加成。

这一段修完，带闸门口径下 id=531 稳定保留 5 条命中、p72 回到第 1 名，
**16 道题的正确页召回全部命中（no_image 那条链路只有 15/16）**。

## 六、遗留问题与已知代价（如实记录）

1. **68 张图里只有 1 张抽出了几何拓扑。** 其余同类图要么是**一整张位图**（矢量层为空），
   要么用**斜向线段 / 填充路径**画连接线，几何规则匹配不到。
   这类图的层级仍靠多模态描述，而模型在层级归属上**不稳定**（同 prompt、`temperature=0`
   三次跑出三种结果）。→ 已用「（参考）」显式标注降级，但这是真实的能力边界。
2. **id=543 的 -0.083 未修复**。修它需要扩大惩罚的图类型范围，而那会连带惩罚
   id=6 真正需要的柱状图。**主动选择不修**。
3. **CLIP 权重本轮未下全**（`pytorch_model.bin` 约 590 MB，本轮下到 **230 MB**，后台仍在续传），
   因此 `T3` 臂与 `T2` 数值完全相同 —— 这是**如实标注的降级**，不是"CLIP 没用"。
   代码路径（`src/clip_encoder.py` + `retriever.py` 的 3c 步）与失败降级逻辑已验证：
   权重目录缺文件时 `load()` 置 `_failed` 并永久降级，`trace` 里会明确写出「跳过」。
   补下完成后跑 `python scripts/parse_images.py --clip-only` 生成图向量，再重跑
   `python scripts/ablation_image.py`，`T2 → T3` 那一行才会有真值。
4. **id=207 漏 `15,000.00`**：正确答案排在第 5 位之后，top-8 上下文预算装不下。
   提高 top_k 可以救，但会拖慢首字延迟 —— 工单性能要求（≤3 s）优先。
5. **低信息图的惩罚系数 0.15 是实测调出来的**，不是理论值。它对本语料（68 张图、
   15 张证照照片）有效；换成图像构成差异很大的语料需要重新标定。
6. **p39 的几何拓扑对"跨行/跨列斜连线"无效**。当前只覆盖母线型与直连型两类
   （正好覆盖组织结构图的常见画法），复杂图（如带正交折线回绕的）会退化。
7. **工单3 的表格消融在本工程里复跑时多出一处差异，已用单变量复跑证实是 top_k 预算问题、非回归**：
   在本工程以 `top_k=8`（工单4 的线上配置）复跑 `scripts/ablation_table.py`，
   T1 的关键事实是 0.964（13/14），比工单3 里 `top_k=12` 的 1.000 少一条；
   少的正是 **id=207 的 `15,000.00`**，与上面第 4 条同因（加入表格块 + 图像块后正确答案被挤出前 8）。

### 10.1 最有说服力的一组对照（id=6，同一次请求内两条链路）

同一个问题、同一份索引格式、同一个模型，只差「图有没有被解析」：

| | `no_image`（图像不解析） | `image`（多模态解析） |
|---|---|---|
| 关键事实覆盖率 | **0.25**（漏 `14.0%`、`IC卡`、`2.0%`） | **1.000**（全中） |
| 生成的答案 | 汽车电子 **10.5%**；负增长 **3C −1.2%** —— **两个数都错** | 汽车电子 **14.0%**；**IC卡 −2.0%** —— 全对 |
| 召回到的图 | 无 | p72 / p310 的柱状图原图（可直接点开） |

`no_image` 那条链路答错的原因正是第二节分析的：正文只写了「工业控制 10.5%，位列第二，仅次于汽车电子」，
模型**把正文里的 10.5% 当成了第一名**，而负增长那一项正文根本没写，只能凭空编一个 −1.2%。
这组对照同时也说明：**关键事实覆盖率这个指标和"答案对不对"是一致的**，不是纸面数字。

### 10.2 联调中修掉的两个真实缺陷

这两个都是**只有真正把服务跑起来、打一次 HTTP 才会暴露**的问题，之前单纯的脚本评测碰不到：

1. **`_image_url()` 恒返回空串 —— 检索命中了图，界面上却不显示图。**
   索引里 `image` 字段落盘的是 `data\images\xingtu\p99_f1.png`（**反斜杠 + 相对路径**），
   而 `config.IMAGE_DIR` 是**绝对路径**，`Path(rel).relative_to(IMAGE_DIR)` 每次都抛 `ValueError`，
   被 `except` 静默吞掉、返回 `""`。
   修法：先把分隔符统一成 `/`，再按「相对工程根目录」补全，最后对齐 `IMAGE_DIR`，两种写法都能取到图。
   （选择在**读取侧**容错，而不是重建索引 —— 索引里已落盘的 68 条图像块不用动。）
2. **`_fact_hits()` 的问题文本比对没做归一化 —— 明明问的是验收题，"命中清单"却是 null。**
   它对问题用的是 `question.strip()` 精确比对，而同一函数里对关键事实用的却是
   `_norm_fact()`（NFKC + 去空白）。两套口径不一致，全角/空格变体就对不上。
   修法：问题比对也走 `_norm_fact()`，与事实匹配置于同一口径。

> 教训：**脚本级评测全绿 ≠ 功能可用。** 这两处都在「脚本不经过、但界面一定要经过」的路径上 ——
> 前者在 `main.py` 的展示层，后者在演示辅助函数里。交付前跑一遍真实 HTTP 请求是必要的。
