## 一、现状诊断（基于 08 工单的实测结论，不是猜测）

| 编号 | 问题 | 实测证据 | 影响的指标 |
|---|---|---|---|
| P1 | **同名校实体混淆**：问"平安银行"时被中国平安年报片段挤占 | 记忆 [[group-report-subsidiary-name-collision]]：目标公司占比仅 0.12~0.25 | precision |
| P2 | **重排器吃掉融合权重**：链路末端有 cross-encoder 时，调向量/BM25 权重几乎无效 | 4 组权重首条重排分恒等 0.868 | 调参策略 |
| P3 | **加权 RRF 架空弱权通道**：权重直接乘原始分数让两路区间不相交 | 记忆 [[rrf-weights-starve-a-channel]] | precision/recall |
| P4 | **多期聚合类问题召回短板** | 单事实类 0.91~1.00，多期聚合类仅 **0.59** | recall |
| P5 | **RAGAS 三个坑**：四指标混跑打 nan / 402 静默作废 / 噪声底 ±0.05 | 记忆 [[ragas-with-deepseek-gotchas]] | 结论可信度 |
| P6 | **页眉页脚污染 + 中文词间插空格** | 页眉页脚占召回 28.7%；去空格前会得假阴性 | precision / 假阴性 |
| P7 | **08 图谱无社区摘要**，只能做邻域扩展，做不了主题型/全局型问答 | 08 `graph_core.py` 无 community 代码 | recall |

**一句话诊断**：08 已解决"**能不能锁到目标公司**"（图约束，纯度 0.7361→0.8333），
但没解决"**锁进来的是不是最相关的那几条**"（precision）与"**多期/聚合类召回不足**"（recall）。

| 目标 | 值 | 测量 |
|---|---|---|
| `context_precision` | **≥ 0.80** | RAGAS `LLMContextPrecisionWithReference` |
| `context_recall` | **≥ 0.90** | RAGAS `LLMContextRecall` |

## 三、四层优化方案

### 3.1 第①层：prompt 构建实体、关系

**目标**：让抽取出的三元组干净、可回溯，从源头减少脏节点对检索的干扰。

**方案**：闭合本体 + 禁止数值实体 + 强制 evidence + 强制 JSON。全文见 `app/graph_rag.py::EXTRACT_SYS`。

```
你是金融知识图谱抽取器。从给定年报片段中抽取实体与关系，只输出 JSON，不要解释。
实体类型限定：公司/人物/指标/机构/产品；关系类型限定：任职/披露指标/持股/子公司/合作/监管。
禁止把纯数值、百分比、日期当作实体；每个关系必须给出 evidence（原文短句）。
输出格式：{"entities":[{"name":"","type":""}],"relations":[{"head":"","rel":"","tail":"","evidence":""}]}
```

**预期收益**：减少"数值当实体"的脏节点（08 有 55 个兜底类目节点），边可回溯 → 便于定位"哪条边带偏了检索"。

### 3.2 第②层：检索

| 子项 | 方案 | 原理 |
|---|---|---|
| **降 RERANK_N** | 8 → 6 | RAGAS 的 `contexts` 就是喂进模型的这几条，**分母变小 = 精度直接受益** |
| **升 FUSION_K** | 30 → 40 | 先多召回、再精排；精排比粗排准，裁掉低质候选 |
| **重标定融合权重** | 0.7/0.3 → 0.6/0.4 | 数值/表格型问题靠关键词更稳；先通道内归一化再加权，弱权通道不被架空 |
| **加深图扩展** | 1 跳 → 2 跳 | 治 P4 多期聚合召回短板 |
| **过滤公司类扩展词** | 新增 | ⚠ 2 跳会把**同业公司名**注入 BM25 → 直接伤 precision。锚定唯一公司时剔掉 `type=="公司"` 的邻居 |
| **社区摘要通道** | 新增 | GraphRAG global search：命中实体所属社区的摘要作为补充上下文，封顶 2 条 |
| **图约束双侧下推** | 沿用 08 | 向量与 BM25 **都**要下推 code 过滤；只锁一侧则"锁到目标公司"名存实亡 |
| **图约束触发条件** | 修正 | 只从**命中实体**收集 code（不是从扩展邻居），否则 2 跳扩展后 `len(codes)==1` 永不成立 |

**调整顺序（遵守 P2 的教训）**：先动**重排候选数与 `RERANK_N`**，再动融合权重——
末端有 cross-encoder 时权重的作用会被吸收。

### 3.3 第③层：生成

**方案**：结论→证据→来源三段式；句末 `【来源：公司 第X页】`；片段不足答"年报中未提及"；
按问题语言自适应；检索超预算或生成异常一律降级为检索原文（响应有上界）。

### 3.4 第④层：评估

**方案**：只跑工单点名的两项、逐指标串行、nan 记 None、上报有效样本数、before 同题重跑、
复用判官/嵌入单例、比较前量噪声底、卡线不算达标。

## 五、验证方法

| 层 | 验证 | 判据 |
|---|---|---|
| prompt | `POST /graph/text` 贴一段年报 | 无纯数值节点；每条关系带 `evidence` |
| 检索 | 打印 `graph.codes` / `expand` / `contexts` 出处 | 单公司问题 `codes` 唯一；扩展词不含同业公司名；contexts 纯度 100% |
| 生成 | 看答案是否带来源、语言是否跟随提问 | 中问中答/英问英答；无来源即不合格 |
| 评估 | `eval/before.json`、`eval/after.json` + 打印的对比表 | `valid_*` 必须 `3/3` |
| 性能 | `latency_ms` 的 p50/p95/max | p95 ≤ 3000 ms |
| 容错 | E1~E4 停机实测 | 四条全过（见 `docs/03_测试.md` §4） |

## 六、回退与风险

| 风险 | 触发条件 | 回退动作 |
|---|---|---|
| 2 跳扩展引入噪声，precision 反降 | after 的 precision < before | `HOPS=1` 回退到 08 深度 |
| 社区摘要稀释精度 | 去掉摘要后 precision 上升 | `USE_COMM=0` |
| `RERANK_N=6` 导致金标被裁 | recall 下降 | 回调 `RERANK_N`，并检查金标在重排后的名次（既有记忆：便宜预筛会误杀金标） |
| 融合权重改动无效果 | 首条重排分几乎不动 | 说明被重排器吸收（P2），停止在权重上花时间，转去调 `RERANK_N`/`HOPS` |
| 大模型 402 / 网络抖动 | 评估整轮作废 | 如实标注；Key 充值后重跑，**不引用半轮数字** |
| 显存被占用导致时延爆表 | rerank 突然数十秒 | 杀残留进程（`nvidia-smi` + `taskkill`），重任务串行 |
