## 一、命名规范

```
{序号}-{内容简述}.png
```

- 序号两位数字，与下表一致（`01-`、`02-` …）
- 内容简述用中文短词，不含空格（用 `-` 连接）
- 格式统一 PNG，宽度 ≥ 1600 px，确保终端与图谱文字清晰可读
- 截图存放于本目录：`工单08-GraphRAG金融问答/demo/screenshots/`

## 三、截图制作要点

1. **终端截图**：字体 ≥ 16 pt，浅色背景；中文若乱码，
   运行前设 `PYTHONIOENCODING=utf-8`，或在 Windows Terminal 中运行
2. **代码截图**：只截关键函数，不要截整屏代码；
   IDE 用浅色主题并隐藏行号栏以外的面板
3. **图谱截图**：这是本工单的核心视觉证据，
   - 静态图要完整可见，必要时分区域截图；
   - 交互式截图要包含鼠标悬停/点击的效果，体现可交互性
4. **界面截图**：浏览器窗口宽度固定 1440 px，隐藏书签栏
5. **数据截图**：文件内容过长时只截有代表性的片段，并在图上标注重点
6. **标注**：可在截图上加红框/箭头标出关键实体或数字，但不要遮挡内容

## 四、图谱截图特别说明

本工单验收标准第 1 条是「**知识图谱可视化：可视化展示 PDF 中的文档解析出来的
知识图谱数据中的实体、关系**」，因此图谱相关截图（05~08）是最关键的证据：

| 截图 | 要体现什么 |
|---|---|
| 05 静态图 | 实体数量、关系网络、按类型着色 |
| 06 交互式 | 可拖拽、可缩放——证明不是静态图片 |
| 07 节点属性 | 点击后能看到实体的类型、描述、度数、来源 chunk |
| 08 社区检测 | 社区划分与摘要——这是 Graph RAG 全局检索的基础 |

建议 06、07 用**连续的几张截图**展示交互过程（打开 → 拖拽 → 点击节点 → 显示属性）。
