# Query 理解优化说明报告

## 1. 项目目标

工单 05 要求在已有 PDF-RAG 系统基础上提升 Query 理解能力，使系统能够更好处理模糊问题、复合问题、表格问题和图像问题，从而提升检索召回质量和最终问答准确率。

## 2. 技术栈

- 页面框架：Streamlit
- RAG 框架：LangChain
- PDF 解析：MinerU
- 向量数据库：FAISS
- Query 理解模型：通义千问 `qwen-plus`
- Embedding：通义 DashScope `text-embedding-v4`
- 检索对象：文本、表格、图像三类索引

## 3. Query 理解优化

系统在检索前会对用户问题进行分析，输出：

- `type`：问题类型，包括 `text`、`table`、`image`、`mixed`；
- `rewrite`：改写后的检索问题；
- `sub_queries`：多个扩展检索子问题。

如果 LLM 改写失败，系统会回退到关键词分类和原始问题检索，保证流程稳定。

## 4. 检索路由优化

系统根据 Query 类型选择检索通道：

- `text`：主要检索文本索引；
- `table`：优先检索表格索引，再检索文本索引；
- `image`：优先检索图像索引，再检索文本索引；
- `mixed`：同时检索图像、表格和文本索引。

每个 Query 会使用改写问题和多个子查询进行检索，最后去重融合，提升召回覆盖率。

## 5. Prompt 优化

最终回答 Prompt 会包含：

- 原始问题；
- Query 理解结果；
- 检索到的参考资料；
- 回答约束。

模型需要严格依据参考资料回答，表格问题保留数值单位，图像问题优先依据图像上下文。

## 6. 批量评测

批量输出文件为 `query_optimized_answers.json`，每条结果包含：

- 问题 ID；
- 原始问题；
- Query 理解结果；
- 答案；
- 检索依据及依据类型。

## 7. 完成情况

项目已完成 Query 分类、问题改写、子查询扩展、多索引路由、多路召回融合、Query 理解展示、单问题问答、批量问答和答案导出，满足工单 05 的 Query 理解优化要求。
