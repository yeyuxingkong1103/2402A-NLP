# 工单六任务说明：混合检索策略（向量 + 全文 + 混合）

> 工单编号：人工智能NLP-RAG-混合检索任务

## 一、背景

- 工单四已实现图文表三路融合 RAG，工单五已实现多轮对话（指代消解 / 实体追踪 / 用户反馈）
- **工单六（本工单）**：在工单五基础上提供**向量检索（召回+重排）、全文检索、两者同时执行的混合检索**三类检索策略的配置及应用能力，提升 PDF 文档检索精度

## 二、核心目标

1. **向量检索（召回+重排）**：文本/Query 向量化（bge-m3 嵌入）+ 余弦相似度召回 + 重排算法精排
2. **全文检索**：倒排索引 + 布尔查询（AND/OR/NOT）+ 短语匹配 + 模糊匹配 + 多字段（标题/正文/摘要）
3. **混合检索**：向量与全文同时执行（并行），支持通道权重调整，提供加权平均、投票机制（RRF）两类融合算法
4. **至少三种重排器**：基于 LLM 的重排器（bge-reranker-v2-m3 交叉编码）、基于 TF-IDF 的重排器、基于用户反馈的自适应重排器
5. **策略可配置**：API 请求级 / 界面侧栏均可切换模式、融合算法、重排器、权重、匹配方式
6. 沿用工单五多轮对话与反馈能力，反馈数据直接供自适应重排器学习

## 三、验收标准

| 类别 | 指标 | 要求 |
|------|------|------|
| 功能 | 检索策略 | 向量 / 全文 / 混合三种可配置 |
| 功能 | 重排算法 | ≥3 种（LLM / TF-IDF / 用户反馈自适应） |
| 功能 | 融合算法 | 加权平均、投票机制（RRF），权重可调 |
| 功能 | 全文能力 | 布尔查询、短语匹配、模糊匹配、多字段 |
| 功能 | 交互 | 多轮对话 + 用户反馈，界面可配策略 |
| 功能 | 语言 | 中文、英文问答 |
| 性能 | 准确率 | ≥ 90% |
| 性能 | 召回率 | ≥ 95% |
| 性能 | 响应时间 | ≤ 3 秒 |
| 性能 | 稳定性 | 高并发环境下稳定运行 |

> 代码注释均包含工单编号：**人工智能NLP-RAG-混合检索任务**

## 四、技术方案

```
用户提问（可携带 retrieval 策略配置）
   │
   ├── vector   ：bge-m3 嵌入 → Milvus 余弦召回(24) → 重排器精排(top_k)
   ├── fulltext ：jieba 分词 → 三字段倒排索引(AND/OR/短语/模糊) → TF-IDF 评分 → 重排器
   └── hybrid   ：向量/全文 ThreadPoolExecutor 并行召回
                   → RRF 投票 或 加权平均(min-max 归一化, 权重可调)
                   → 可配置重排器（llm / tfidf / adaptive）
   │
   ├── 文本(v6 可配) + 表格(v3) + 图像(v4) 三路并行（沿用工单四）
   ├── 多模态 Prompt → LLM 生成（沿用工单四）
   └── 多轮会话（指代消解/实体追踪，沿用工单五）+ 反馈落盘（adaptive 学习）
```

关键设计：

1. **配置中心** [retrieval_config.py](../src/retrieval/retrieval_config.py)：`RetrievalConfig` dataclass 集中管理全部策略项，非法值自动回退默认，权重自动归一化；提供 4 套预设（vector_only / fulltext_only / hybrid_rrf_llm / hybrid_weighted_adaptive）
2. **全文检索** [fulltext_retriever.py](../src/retrieval/fulltext_retriever.py)：进程单例，启动时从 Milvus `rag_chunks` 全量加载（千级 chunk 内存索引），构建 title/content/summary 三字段倒排索引与 IDF 表；未登录词补子串扫描，模糊匹配用字符 bigram Jaccard
3. **三种重排器** [rerankers.py](../src/retrieval/rerankers.py)：LLM 重排器复用工单四 bge-reranker-v2-m3 单例（加载失败保序透传）；TF-IDF 重排器在候选集上做词法余弦（0.85 词法 + 0.15 通道先验）；自适应重排器融合点赞/点踩历史（0.6 词法 + 0.4 反馈），冷启动退化为 TF-IDF
4. **融合算法** [fusion.py](../src/retrieval/fusion.py)：RRF `1/(k+rank)` 投票（两路共现候选得票更高）；加权平均先 min-max 归一化再加权
5. **统一编排** [hybrid_retriever_v6.py](../src/retrieval/hybrid_retriever_v6.py) / [rag_engine_v6.py](../src/rag_engine_v6.py)：输出与 TextRetrieverV3 同构；文本走 v6 可配置检索，表格/图像通道沿用 v4 保证不回归
6. **不引入额外重服务**：全文索引内存化，不依赖 Elasticsearch；确定性算法不增加 LLM 调用，保障 ≤3s
