## 2. 关键选型论证

### 2.1 为什么图谱抽取以规则为主（而不是 LLM 全量抽取）

| 维度 | 规则/词典/正则 | LLM（qwen2.5:3b）全量 |
| --- | --- | --- |
| 7430 块耗时 | **5.2 s**（单进程 CPU，实测） | 3B 模型约 2~4 s/块（本机 CPU）→ **4~8 小时** |
| 精确率 | 高：实体必须原样出现在文本里 | 中：小模型会改写实体名、造关系、漏抽 |
| 可审计 | 每个实体带 `chunk_id` + 原文 `snippet`，每条关系带 `evidence` 原句 | 需要额外做「回指校验」才能确认 |
| 复现性 | 完全确定（同输入同输出） | 受采样/版本影响，需固定 seed 与 temperature=0 |
| 内存 | < 400 MB | 需常驻模型（qwen2.5:3b 约 2.16 GB） |

**结论**：主链路用规则抽取；LLM 只用于**抽样补抽**（≤400 块）作为可选的图谱增强，
且补抽结果单独标记 `extractor=llm_qwen2.5-3b` 以便对比增量（对应 优化/ 的前后对比）。

### 2.2 为什么不用 Neo4j / networkx

* 本机**未安装** networkx / py2neo，Neo4j 需 Docker（本会话沙箱下 docker CLI 走命名管道不可用）；
* 需求只要求「一跳/两跳邻域扩展」与「可视化」，自实现 BFS + 力导向即可覆盖；
* 零依赖 ⇒ 部署脚本在任何有 Python 的机器上都能跑（`部署/脚本/一键启动.ps1`）。

### 2.3 为什么图谱通道采用「加分 + 名额交错」

见 `需求分析.md` §3.4。一句话：**重排分（4.x）与结构分（0.02~0.06）量纲不同**，
直接相加会让图谱增强在结果上完全看不出来；直接比大小则图谱通道永不进榜。
因此基础命中加小量结构分（同分档微调），图谱独有候选按名额插入 Top-K，
并把「被替换掉的块」完整记录在 `diagnostics.graph_displaced` —— 规则明确、结果可审计。

### 2.4 为什么复用 工单7 的判分模块而不是自己写

验收要求「比对 07 工单的测试结果」。若两次评测使用**不同的判分实现**，
即使题目相同，归一化细节（千分位、全角半角、数字边界 `11.65 ≠ 1.65`）、
recall@k 的合并正文口径、页命中区间解析都可能不同，对比表就失去意义。
因此 `研发/评估/判分口径.py` **只做导入与参数固化**，不复制任何判分逻辑；
若 工单7 目录缺失，`available()` 返回 `False`，评估脚本**直接失败（退出码 3）**而不是给分。
