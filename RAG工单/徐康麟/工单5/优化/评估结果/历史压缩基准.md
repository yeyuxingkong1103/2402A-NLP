# 对话历史压缩基准（工单5 · 人工智能NLP-RAG-Query 理解优化）

## 口径

* `token 近似数 = len(text)`（中文 ≈ 1 字 1 token，见 `history_compress.approx_tokens`）；
* 原始长度 = **全部 N 轮**（question + rewritten_query + answer）字符数之和，即「不压缩会话」要携带的上下文量；
* 压缩后长度 = 摘要 digest + 保留的 K 轮原文（**送进 LLM 的全部内容**）；
* 历史为**合成数据**（2 家公司 × 6 个字段槽位轮换），不含真实用户数据；
* 每档跑 `--repeat 20` 次取 P50 / 最大，避免单次抖动当结论。

## 未完成项 / 边界

* 本基准只测 **`compress_history` 本身**：`MultiTurnEngine` 尚未调用它（接线由 captain 负责），故「长对话端到端延迟下降」**未运行**、不做估算。
* 合成历史的答案长度偏短（约 50 字/轮），真实招股书答案更长；压缩比由「保留 3 轮原文」主导，结论对答案长度不敏感，但绝对字符数会同步放大。
* token 数按字符数近似，未接真实分词器；如需精确 token 请另跑 jieba/模型分词。
