# 工单12 LightRAG金融问答系统 - 设计文档
## 1.项目背景
本项目基于LightRAG框架实现金融招股说明书问答系统，对比传统Naive-RAG（纯向量检索）与LightRAG混合检索（知识图谱+向量检索）的效果差异。
工单12基于工单11成果独立新建文件夹开发，复用工单5的Python虚拟环境，使用工单11训练好的BGE向量模型作为Embedding。

## 2. 总体架构
整体分为四大模块：
1. 文档加载模块：读取PDF招股说明书，文本分块；
2. 知识抽取模块：调用Qwen2-7B大模型，使用自定义中文金融抽取Prompt，提取实体与关系，构建知识图谱；
3. 检索引擎模块：
    - Naive模式：纯向量检索（传统RAG）
    - Hybrid混合模式：LightRAG本地语义检索 + 全局知识图谱检索
4. 评估模块：使用RAGAS指标进行量化评估，指标包含answer_relevancy、faithfulness、context_recall、context_precision。

## 3. 数据模型设计
### 3.1 实体Schema（严格限定）
允许实体类型：公司、部门、人物、募集投资项目、行业、产品、财务指标、关联方、销售处、业务板块
### 3.2 关系Schema（严格限定）
允许关系类型：持股、隶属、投资、属于、参与制定标准、收入来源、业务覆盖、构成
> 禁止抽取超出列表的实体/关系，防止图谱噪声。

## 4. 接口设计
1. 知识库构建接口：rag.insert()，传入PDF二进制流，自动分块、实体抽取、入库
2. 问答接口：rag.query(question, QueryParam(mode="naive"/"hybrid"))
    - naive：普通RAG，仅向量召回
    - hybrid：LightRAG混合图谱检索
3. 批量评测接口：批量输入9条固定测试集，输出两套回答JSON，供给RAGAS评估

## 5. 业务流程
1. 加载两份招股说明书PDF
2. 文档切片 → LLM实体关系抽取 → 构建知识图谱+向量库（lightrag_cache持久化）
3. 遍历测试问题，分别调用两种检索模式，保存问答结果
4. RAGAS计算两套方案评估指标，生成对比报告

## 6. 风险与约束
1. LLM依赖：Ollama提供Qwen2:7b推理服务，WSL与Windows跨主机访问需要配置OLLAMA_HOST=0.0.0.0
2. 抽取质量：依赖自定义Prompt限制实体类型，避免编造不存在信息
3. 持久化：缓存目录lightrag_cache保存图谱与向量，原生支持增量文档插入，无需全量重建
