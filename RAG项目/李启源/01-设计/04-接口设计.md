# 接口设计

## 1. 基本信息

- Base URL：`http://<host>:8000`
- API 前缀：`/api/v1`
- 数据格式：JSON；文件上传使用 `multipart/form-data`
- 字符编码：UTF-8
- 在线文档：`/docs`、`/redoc`
- 指标接口：`/metrics`
- 存活检查：`/health`
- 就绪检查：`/ready`

生产环境建议携带：

```http
X-API-Key: <configured-api-key>
```

也支持：

```http
Authorization: Bearer <configured-api-key>
```

## 2. 问答接口

### 2.1 标准问答

```http
POST /api/v1/chat
Content-Type: application/json
```

请求示例：

```json
{
  "query": "退换货规则是什么？",
  "session_id": "session-id",
  "knowledge_base_id": 1,
  "top_k": 5,
  "enable_memory": true,
  "enable_rerank": true,
  "enable_query_rewrite": true,
  "enable_hybrid_search": true,
  "temperature": 0.7
}
```

响应核心字段：

| 字段 | 说明 |
|---|---|
| `answer` | 最终回答 |
| `query` | 实际处理的问题 |
| `conversation_id` | 对话标识 |
| `session_id` | 服务端会话标识，可为空 |
| `sources` | 来源文本块、来源地址和相关性分数 |
| `metadata` | 改写结果、召回数量、模型、耗时和记忆信息 |
| `warnings` | 降级或依赖不可用时的提示 |

### 2.2 流式问答

```http
POST /api/v1/chat/stream
Content-Type: application/json
Accept: text/event-stream
```

请求体与标准问答一致，服务端以 SSE 返回 `start`、`content`、`metadata`、`done` 或 `error` 事件。

### 2.3 兼容查询

```http
POST /api/v1/query
```

该接口将旧版 Query 请求适配到统一 `ChatService`，返回 `answer`、`query`、`sources`、`model` 和 token 统计。

### 2.4 问答链路健康

```http
GET /api/v1/chat/health
```

返回 Query 改写、检索、重排、Prompt、LLM、后处理和记忆组件状态。

## 3. 知识库与文档接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/knowledge-bases` | 创建知识库 |
| GET | `/api/v1/knowledge-bases` | 分页查询知识库 |
| GET | `/api/v1/knowledge-bases/{kb_id}` | 查询知识库 |
| PATCH | `/api/v1/knowledge-bases/{kb_id}` | 更新知识库 |
| DELETE | `/api/v1/knowledge-bases/{kb_id}` | 删除知识库 |
| GET | `/api/v1/knowledge-bases/{kb_id}/documents` | 查询知识库文档 |
| GET | `/api/v1/documents/{document_id}` | 查询文档详情 |
| DELETE | `/api/v1/documents/{document_id}` | 标记删除文档并删除向量 |
| POST | `/api/v1/documents/upload` | 上传并索引文档 |
| POST | `/api/v1/knowledge-bases/{kb_id}/documents` | 上传到指定知识库 |

上传字段：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---:|---|
| `file` | file | 必填 | 文档文件 |
| `tenant_id` | int | 当前身份 | 租户范围 |
| `role_id` | int | 0 | 角色标识 |
| `parser` | string | `auto` | 解析器 |
| `chunking_strategy` | string | `paragraph` | 分块策略 |
| `chunk_size` | int | 800 | 目标字符数 |
| `force_reindex` | bool | false | 是否强制重建 |

## 4. 会话接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/sessions` | 创建会话 |
| GET | `/api/v1/sessions/{session_id}` | 查询会话详情 |
| GET | `/api/v1/sessions/{session_id}/history` | 查询消息历史 |
| POST | `/api/v1/sessions/{session_id}/clear` | 清空历史但保留会话 |
| POST | `/api/v1/sessions/{session_id}/end` | 结束会话并尝试归档长期记忆 |
| PUT | `/api/v1/sessions/{session_id}/role` | 切换会话角色 |

会话接口依赖 Redis 和 MySQL；依赖未就绪时应返回 `503 Service Unavailable`，而不是误报为业务成功。

## 5. 系统接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 进程存活检查，不初始化外部依赖 |
| GET | `/ready` | 检查 Milvus、LLM 和记忆依赖的就绪情况 |
| GET | `/api/v1/stats` | 查询向量集合名称、向量数量和维度 |
| GET | `/metrics` | Prometheus 指标文本 |
| GET | `/` | 重定向到 Web 页面 |

## 6. 常见状态码

| 状态码 | 场景 |
|---:|---|
| 200 | 查询、问答或更新成功 |
| 201 | 会话、知识库或文档创建成功 |
| 204 | 删除成功 |
| 400 | 参数或角色不合法 |
| 401 | 缺少或无效 API Key |
| 404 | 知识库、文档或会话不存在 |
| 413 | 请求或上传文件超限 |
| 429 | 超出每分钟请求限制 |
| 500 | 应用处理失败 |
| 503 | MySQL、Redis 或向量服务未就绪 |

## 7. curl 示例

```bash
curl http://127.0.0.1:8000/health

curl -X POST http://127.0.0.1:8000/api/v1/chat \
  -H 'Content-Type: application/json' \
  -d '{"query":"退货规则是什么？","knowledge_base_id":1}'

curl -X POST http://127.0.0.1:8000/api/v1/documents/upload \
  -F 'file=@examples/售后政策.txt' \
  -F 'knowledge_base_id=1' \
  -F 'chunking_strategy=paragraph'
```
