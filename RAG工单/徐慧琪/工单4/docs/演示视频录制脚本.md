## 二、录制前检查清单

- [ ] 索引已建好且未被其他进程占用（`data/qdrant` 只有一个进程能持有）；
      录制期间不要跑 `scripts/build_index.py`。
- [ ] API key 与 Ollama 均可用（侧栏「系统状态」应看到 `llm: ok`、`ollama: ok`、
      `clip: ok`、`rerank: ok`）。
- [ ] 界面已于启动时**自动预热**（reranker/CLIP/存储常驻，侧栏「系统状态」下方显示
      「模型已预热…」，日志 `warmup[store]/[rerank]/[clip]/[embed]`），首答不再付约 8 秒
      模型加载；**仅当那里显示「预热失败」时**，才先手动提问一次把加载时延消化掉。
- [ ] **报告版本已核对**：录制前核对 **`docs/reports/检索精确度报告_full_04.md`
      与 `docs/reports/eval_full_04.json`** 的抬头与生成时间（`python scripts/run_eval.py full_04`
      重跑才会刷新），两者必须互相一致、且与本脚本解说的数字一致；
      `docs/reports/检索精确度报告_full_04_rc2.md` 是 RC-2 旧口径（p50 3888.6 ms），
      仅供参考，**不要把与解说数字不一致的版本录进画面**。
- [ ] 报告文件已就位并打开：与解说数字一致的那一份精确度报告、`docs/答案定位报告.md`；
      对比与压测报告若已生成一并打开（未生成则按分镜 9 的话术处理，
      **不要口头编造数字**）。
- [ ] 终端字号调大、浏览器缩放 125%，让引用行与指标块可读。
- [ ] 两段提问话术提前复制到剪贴板（见 §一 分镜 4/5/7）。

## 四、录制注意

1. **不要现场建库**：全量约 15 分钟，用日志文件代替，并说明命令与统计含义。
2. **不要现场跑评估**：16 题真实 LLM 调用耗时数分钟且费用不可控，展示已生成的报告即可。
3. 时延数字一律念**实测值**（热态 p50 1730.3 ms、15/16 题 ≤ 3 s；首题冷启动 41.7 s；并发档见压测报告），不要念「约 3 秒内」这类未经跑出的说法。
4. 若演示机比录制机慢，允许解说「本机实测」，不要把环境差异讲成指标变化。
5. 图像题证据只认这三处：`data/figures/招股说明书2_p39_7fb46462e43d.png`、
   `招股说明书2_p72_00eb1d43b4c6.png`、`招股说明书2_p310_126713956351.png`；
   引用行中的 `figuretext#39#fig4` 等来源ID 与之一一对应。
