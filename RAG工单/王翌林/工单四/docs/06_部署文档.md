# 06_部署文档

> 工单编号：人工智能NLP-RAG-图像内容解析及检索优化（工单四）
> 增量说明：工单四 = 工单三（文本+表格 RAG）+ 图像解析/检索能力；工单三接口与数据完全保留

## 1. 系统架构

```
PDF ──> 图像提取（PyMuPDF L1位图+L2矢量渲染）
        ├─> 多模态解析（Qwen2-VL caption/VQA + PaddleOCR）
        │     └─> 图像向量化（bge-m3 文本通道 + Chinese-CLIP 图像通道）
        │           └─> Milvus rag_images
        └─> 文本 chunk / 表格解析（工单三链路）
              └─> Milvus rag_chunks / rag_tables + MySQL

提问 ──> 图像感知路由（image_first / hybrid / table_only / text_only）
      ──> 三路检索（文本 + 表格 + 图像三子通道）→ RRF 融合 → bge-reranker 重排
      ──> DeepSeek-v4-flash 生成（图文表三源引用）
```

| 服务 | 端口 | 入口 |
|------|------|------|
| FastAPI v4 | 8004 | `src.api_v4:app` |
| Streamlit v4 | 8504 | `app/streamlit_app_v4.py` |
| Milvus 2.6 standalone | 19530 | systemd `milvus.service` |
| MySQL 8 | 3307 | 库 `rag_pdf_qa`（会话/反馈） |

## 3. 一键安装

```bash
bash scripts/install_v4.sh                # 完整安装（幂等，可重复执行）
bash scripts/install_v4.sh --skip-ingest  # 只装环境不入库
```

install_v4.sh 执行阶段：

| 阶段 | 内容 | 幂等策略 |
|------|------|----------|
| STEP 0-1 | GPU 检查、Python 环境（venv 优先，否则自动创建） | 已存在直接复用 |
| STEP 2 | 依赖安装：PyMuPDF、paddlepaddle/paddleocr(3.x)、transformers（含 Chinese-CLIP/BLIP 实现）、sentence-transformers 及工单三全量依赖 | pip 已装自动跳过 |
| STEP 3 | `.env` 检查（缺失则生成模板，需手工填 Key） | 已存在不覆盖 |
| STEP 4 | MySQL 建库 `rag_pdf_qa` + 建表（复用工单二 `src/db.py`） | CREATE IF NOT EXISTS |
| STEP 5 | Milvus 连接检查 | — |
| STEP 6 | 文本/表格入库（复用工单三 `init_milvus_v3.py`、`ingest_text_v3.py`） | rag_chunks>100 且 rag_tables>50 则跳过 |
| STEP 7 | 图像提取（`image_extractor`）→ 多模态解析（`image_parser`，VLM 缺失自动降级）→ 入库 `init_milvus_v4.py --rebuild`（先删后插） | 清单/解析 JSON 存在即跳过对应步骤 |
| STEP 8 | 库存统计（rag_chunks / rag_tables / rag_images 行数） | — |

中文路径处理：脚本内全部路径变量加引号（`$PROJECT_ROOT`、`$ATTACH_DIR/$PDF_NAME.pdf`）；附件目录默认 `/home/dabaie/code/工单/附件`，可用环境变量覆盖：`ATTACH_DIR=/path/to/附件 bash scripts/install_v4.sh`。

## 4. 启动 / 停止

```bash
bash scripts/start_v4.sh   # 启动 FastAPI(8004) + Streamlit(8504)，含健康检查重试（90s）
bash scripts/stop_v4.sh    # 按端口停止两个服务
```

- 日志：`/tmp/api_v4.log`、`/tmp/streamlit_v4.log`
- 健康检查：`curl http://127.0.0.1:8004/api/v4/health`
- Streamlit 首次打开需加载嵌入/重排模型（约 20-40s），由 `st.cache_resource` 缓存

## 5. API v4 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v4/health` | 健康检查（含 rag_images 行数） |
| POST | `/api/v4/ask` | 图文表三路融合问答（body: query/doc_id/use_image） |
| GET | `/api/v4/images/{doc_id}` | 图像解析结果列表 |
| POST | `/api/v4/upload` | 上传 PDF → 后台子进程跑完整图像管线 |
| POST | `/api/v4/evaluate` | 触发内置对比评估 |

工单三端点（`/api/v3/*`，端口 8003）完全保留，可并行运行。

## 7. 常见问题（FAQ）

| 现象 | 原因 | 处置 |
|------|------|------|
| LLM 调用瞬间失败、答案全为兜底话术 | 进程未加载 .env | FastAPI/Streamlit/脚本入口均已显式 `load_dotenv()`；自写脚本需照做 |
| Milvus search 报 collection not loaded | 重启后 collection 卸载 | `python scripts/load_milvus_collections_step5.py`（巡检并自动 load） |
| table_only 问题全空结果 | Milvus 重启后数据丢失（曾发生） | `python scripts/init_milvus_v3.py` 幂等重灌 |
| PaddleOCR 报 NotImplementedError | 3.x PIR/oneDNN | 代码已固定 `enable_mkldnn=False`，勿改 |
| bge-m3 OOM | 显存不足 | 已固定 CPU/batch=8/max_seq=512（RAG_EMBED_* 环境变量可调） |
| 图像 caption 为空 / parse_status=failed | Qwen2-VL 未就绪或 OOM | 自动降级 OCR-only，不阻塞入库；VLM 就绪后重跑 `image_parser` + `init_milvus_v4.py --rebuild` |
| 冷启动首问 >3s | 模型懒加载 | 部署预热：启动后先发一条预热问题，或调用任一接口 |
