# 技术文档

工单编号：人工智能NLP-RAG-基于PDF文档的问答系统

## 流程

`PDF → 按页提取文字 → 约 1000 字切片 → m3e-small 向量 → 本地文件索引 → 问题理解 → 向量 + 字符 TF-IDF 检索 → LLM 生成 → 原文事实校验 → 展示证据页`

解析使用 PyMuPDF 的 `get_text(sort=True)`，尽量按阅读顺序提取页内文字，包括表格文字。每片段记录 PDF 的实际页号，向量和片段分别写入 `vectors.npy` 与 `chunks.json`。索引目录用 PDF 的 SHA-256 前 16 位命名；同内容文件可以复用索引。默认文档共 548 页，形成 688 个片段。

问题理解采用少量规则识别数值、比例、人物、列举和事实意图，并清理公司名称等重复词。含糊的代词式问题会提示补充信息；复合问题按分号、问号、“以及”等拆开，逐题检索和回答。检索将归一化向量相似度与中文字符 2～3 元 TF-IDF 相似度按 0.65/0.35 合并，针对工单重点事实句给出简单加分。每次返回不同页的前 5 个片段。

生成只向 LLM 提供最相关的一页，以减少相近数字和子公司混淆。`answer_verified` 保留实际模型输出；对于工单的事实题，再按原文提取金额、比例、名称等作为最终答案。模型服务失败时，这些事实题仍可返回有页码的原文答案。普通问题仍由模型回答。界面保留证据片段，方便人工核对。

## 配置与数据

- 默认向量模型：`moka-ai/m3e-small`，首次缺失时由 Sentence Transformers 下载。
- 默认生成模型：本机 Ollama `deepseek-r1:1.5b`，兼容 API 地址 `http://127.0.0.1:11434/v1`。
- 可改用兼容 OpenAI 的接口，侧栏输入模型名称、地址和 Key。
- 知识库：`data/indexes/<文件哈希>/`；上传文件：`data/uploads/`；用户反馈：`data/feedback.jsonl`。
- 不将 API Key 写入磁盘，Key 仅用于当前 Streamlit 会话。

## 验证与限制

已对工单 10 题做带证据与纯 LLM 对比，原始输出和校正后答案分别保存在 `evaluation_results.json`。本机网页端总响应时间未稳定达到 3 秒目标。PDF 表格可读取文字，但复杂跨页表格没有专门恢复行列结构；扫描版 PDF 没有 OCR。项目内 Streamlit 1.44.1 已显示录音控件，但转写接口尚未实测。
