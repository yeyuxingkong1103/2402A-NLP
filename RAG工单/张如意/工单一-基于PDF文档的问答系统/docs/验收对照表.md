## 一、功能验收

### 1. PDF 解析：能够准确解析 PDF 文档中的文字、表格数据

| 子项 | 实现 | 验证 |
| --- | --- | --- |
| 文字解析 | `rag_core/pdf_parse.py` 的 `extract_text_blocks()`：PyMuPDF 逐页提取，去页眉页脚/页码，合并被硬换行切断的句子，保留页码 | `python src/build_index.py`，统计中的「页数/块数」即文字解析结果 |
| 表格解析 | `extract_table_blocks()`：pdfplumber 提取表格并转 **Markdown**（保留行列关系），表格块整体成 chunk 不切碎 | `python src/build_index.py --preset wo03_table --with-tables`，索引统计中 `chunk_types.table > 0` |
| 页码溯源 | 每个块携带 `(doc, page, type, section)`，答案引用可回到具体页码 | 问答结果中的「来源：《招股说明书1》第 X 页」 |
| 解析容错 | 单页表格解析失败仅告警不中断；解析结果按文件指纹缓存；PDF 缺失/损坏时脚本给出明确提示与退出码 | `python src/build_index.py --pdf 不存在的.pdf` → 打印错误与修复建议 |

> 说明：表格解析会显著增加建索引时间（pdfplumber 逐页解析数百页 PDF），
> 因此默认预设未开启，验收演示时用上面的命令开启即可。

### 2. 问答准确性：基于 PDF 的内容返回答案；对比基于 PDF 的结果与只使用 LLM 的答案

| 子项 | 实现 | 验证 / 证据 |
| --- | --- | --- |
| 基于 PDF 返回答案 | 流水线：Query 理解 → 向量 + BM25 检索 → RRF 融合 → 重排 → 严格依据上下文生成 | `python src/qa_cli.py -q "武汉兴图新科电子股份有限公司法定代表人是谁？"` |
| 答案可溯源 | 生成 Prompt 要求末尾输出【来源】片段X（第Y页），`generator._extract_citations()` 解析为结构化引用 | 答案尾部与界面「来源」标签 |
| 拒答抗幻觉 | 上下文不足时固定回复「根据提供的文档内容，未能找到该问题的答案。」 | 问一个文档外问题（如「公司食堂几点开饭？」）应拒答 |
| RAG vs 纯 LLM 对比 | `src/compare_rag_vs_llm.py`：同一问题分别跑 `Pipeline.ask()` 与 `generator.generate_llm_only()`，记录答案全文/耗时/引用/关键词命中，输出总览表与逐题详情 | `python src/compare_rag_vs_llm.py` → `results/rag_vs_llm.md`（含「RAG 胜 X / 纯 LLM 胜 Y / 持平 Z」与准确率对比） |
| 对比结论 | 报告中给出结论：RAG 可溯源、数字更准、能拒答；纯 LLM 无来源、易编造、无拒答 | `results/rag_vs_llm.md` 第五小节 |

### 3. 交互友好性：提供清晰、简洁的用户界面

| 子项 | 实现 | 验证 |
| --- | --- | --- |
| 问答界面 | `rag_core/api.py` 内置 HTML 界面（零前端构建）：对话气泡、答案、来源标签、耗时、加载提示 | 启动 `python src/serve.py` 后打开 `http://127.0.0.1:8000/` |
| 问题输入 | 输入框 + 回车发送 + 发送按钮；空输入不发送 | 界面底部输入区 |
| 答案展示 | 答案正文 + 引用来源 + 「耗时 xx ms · 第 N 轮」 | 每次回答下方 |
| 反馈机制 | 每条回答带「有帮助 / 没帮助」按钮，调用 `/api/feedback` 写入自适应重排器 | 点击后显示「感谢您的反馈」 |
| 多轮对话 | 同一页面内自动维护 session 上下文，支持「他/这个公司」追问 | 连续两问验证指代消解 |
| 语音输入 | `src/speech_input.py`；`qa_cli --voice` 可复用 | `python src/speech_input.py --loop --ask` |
| 上传入口 | `POST /api/upload`，可在 `http://127.0.0.1:8000/docs` 图形化操作 | Swagger UI 上传 PDF 返回 `"ok": true` |

### 4. 多语言支持：支持中文和英文的问答

| 子项 | 实现 | 验证 |
| --- | --- | --- |
| 语言自动判别 | `generator._is_english()`：中文字符占比 < 15% 判为英文提问，自动切换中/英文 System Prompt 与拒答话术 | 中文问 → 中文答；英文问 → 英文答 |
| 英文提问示例 | `python src/qa_cli.py -q "What is the registered capital of Wuhan Xingtu Xinke Electronics Co., Ltd.?"` | 返回英文答案与来源 |
| 英文语音 | `--lang en-US`（在线识别）/ Whisper 自动截取语言码 | `python src/speech_input.py --lang en-US --file q.wav` |

## 二、性能验收

### 1. 响应时间：从用户提问到返回答案的时间应不超过 3 秒

| 环节 | 措施 | 证据 |
| --- | --- | --- |
| 检索提速 | 索引常驻内存；向量检索 + BM25 均为本地计算（毫秒级） | `results/rag_vs_llm.json` 中 RAG 侧检索耗时 |
| 生成提速 | 上下文截断 4000 字符、`max_tokens=1500`、温度 0、LLM 磁盘缓存 | `results/evaluation.json` 的 `latency_avg / latency_p95 / latency_max` |
| 重排可控 | 默认预设 `wo01_baseline` 不做重排；需要重排时可切 `--reranker tfidf` 替代级联，避免额外 LLM 调用 | `qa_cli.py --reranker tfidf` |
| 端到端计时 | `qa_cli.py` 每次回答打印毫秒耗时并标注「满足/超出 3 秒预算」；评估脚本汇总平均/P95/最大耗时 | 控制台输出与 `results/evaluation.md` |

> 验收口径：在缓存已预热、网络正常的情况下，问题回答的**平均**端到端耗时应在 3 秒内。
> 首次运行因模型加载与网络冷启动会偏慢，属正常现象；请在演示前先跑一轮预热。

### 2. 资源消耗：合理利用计算资源，确保高并发环境下稳定运行

| 措施 | 说明 |
| --- | --- |
| 模型单例 | 嵌入模型与 LLM 客户端进程内单例，避免重复加载（`embed.get_model()` / `llm.get_client()`） |
| 惰性加载 | Web 服务首次请求才加载索引，加快容器启动（`api.get_pipeline()`） |
| 批处理 | 向量编码批量 64 条、入库批量写入 |
| 缓存 | PDF 解析缓存 + LLM 响应磁盘缓存，重复请求零算力 |
| 指标可观测 | `/api/metrics` 输出请求数、错误数、P50/P95/最大延迟、LLM token 用量与费用估算 |
| 健康检查 | `/api/health` 供负载均衡/容器编排探活 |
| 并发安全 | LLM 缓存写入用临时文件 + 原子替换并加锁；会话按 session 隔离 |
| 可伸缩 | `serve.py --workers N` 多进程；向量库可切 Chroma 持久化服务 |

验证：`python src/serve.py` 后访问 `http://127.0.0.1:8000/api/metrics`。

## 三、任务目标

| 目标 | 要求 | 实现 | 验证 |
| --- | --- | --- | --- |
| 1. 检索质量 | 基于 PDF 返回答案 + 与纯 LLM 对比 | `compare_rag_vs_llm.py` 输出对比表、关键词准确率、逐题胜负与结论 | `results/rag_vs_llm.md` |
| 1. 检索质量 | 响应时间 ≤ 3 秒 | 见「性能验收 1」 | `results/evaluation.md` 的耗时汇总 |
| 2. 问题列表 | 10 个兴图新科问题全部覆盖 | 问题集取自 `rag_core/config.py` 的 `QUESTIONS_XINGTU`（id 260/95/33/34/957/793/795/543/531/207），对比与评估脚本默认跑全量 | `python src/run_evaluation.py` 输出 10 题明细 |
| 3. 系统稳定性 | 高可用、长时间运行 | 服务基于 uvicorn/FastAPI，具备健康检查、指标接口、日志与异常隔离 | `/api/health` 连续探活 |
| 3. 系统稳定性 | 容错：用户输入错误、文档解析失败 | 见「技术文档 8.2 容错与高可用」清单：空/超长输入处理、闲聊引导、拒答、逐题异常隔离、索引自检、依赖降级 | 见下方「容错演示用例」 |

### 容错演示用例（验收时可现场演示）

| 用例 | 输入 | 预期表现 |
| --- | --- | --- |
| 空输入 | 交互模式下直接回车 | 提示「问题为空，请重新输入」，不崩溃 |
| 闲聊 | 「你好」 | 返回引导语，不触发检索 |
| 文档外问题 | 「公司食堂几点开饭？」 | 回复「未能找到该问题的答案」 |
| 超长输入 | 粘贴 500 字以上文本 | 自动截断并提示，正常回答 |
| API Key 缺失 | 不设密钥直接跑问答 | 明确报错并给出设置示例，退出码非 0 |
| 索引缺失 | 删除索引后跑问答 | 提示先执行 `build_index.py` |
| PDF 路径错误 | `--pdf 不存在.pdf` | 提示找不到文件与 `--pdf` 用法 |
| 语音依赖缺失 | 未装 speech_recognition 直接 `--voice` | 打印 `pip install` 安装命令并退回键盘输入 |
