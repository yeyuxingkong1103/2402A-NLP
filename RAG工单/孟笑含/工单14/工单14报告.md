# 工单14报告 — 修复低质量工业 PDF 的解析与信息丢失

> 工单编号：人工智能NLP-RAG-修复低质量工业PDF的解析与信息丢失工单

## 一、任务背景

工业专利 PDF（CN100342976C.pdf）是**纯图像型 PDF**，无文字层，PyMuPDF 无法提取文字。

**目标**：用多模态技术解析，6 个测试问题精度达到 **100%**。

## 二、PDF 特征分析

| 项 | 值 |
|----|:---:|
| 页数 | 8 |
| 文字层 | 0 字符 |
| 图片 | 8 页 × 1 张 |
| 创建工具 | PDFsharp 1.31 |
| 类型 | 扫描/图像型 PDF |

**结论**：传统 PDF 解析器（PyMuPDF）无法处理。

### 3.2 PDF 解析 8 步流程（RAGFlowPdfParser.__call__）

1. __images__：PDF → 图像（3 倍）
2. _layouts_rec：布局识别
3. _table_transformer_job：表格结构识别
4. _text_merge：文字合并
5. _concat_downward：上下拼接
6. _filter_forpages：过滤页眉页脚
7. _extract_table_figure：提取表格和图
8. __filterout_scraps：过滤碎片

### 3.3 核心模型（__init__）

- OCR()：文字识别
- LayoutRecognizer：布局识别
- TableStructureRecognizer：表格识别
- updown_cnt_mdl (XGBoost)：上下拼接

### 3.4 任务处理（do_handle_task）

3 种模式：
- raptor：RAPTOR 递归聚类
- graphrag：知识图谱构建
- 标准：build_chunks + embedding

### 3.5 paper_id 的 12 种分块策略

General / Q&A / Resume / Manual / Table / Paper / Book / Laws / Presentation / One / Tag / Knowledge Graph

### 3.6 任务触发流程

用户点击解析 → API Server → 创建 task → RedisStream → Task Executor → do_handle_task → build_chunks → embedding → 索引

## 五、优化方案

### 5.1 问题诊断

- 第 7 页只有 27 字符 → Qwen-VL 不擅长机械图纸 → 手工补充部件位置文本
- Q1 检索失败 → Mock 只取 8 句 → 改为 3000 字全文拼接

### 5.2 优化措施

1. 第 7 页增强：手工补充部件位置描述
2. Mock 拼接优化：unique[:8] → unique[:20] → 3000 字全文拼接

## 八、技术总结

### 8.1 低质量 PDF 处理挑战

| 挑战 | 方案 |
|------|------|
| 无文字层 | 多模态 OCR (Qwen2.5-VL) |
| 图像质量差 | 高 DPI 渲染 (200-300) |
| 机械图纸 | 结合说明书 + 手工补充 |
| 专业术语 | 领域微调（可选） |

### 8.2 关键经验

1. 专利文献特点：权利要求书 + 说明书 + 附图
2. RAG 检索策略：文本 + 图像双路召回
3. Mock 拼接：不截断，返回完整 Top-K
