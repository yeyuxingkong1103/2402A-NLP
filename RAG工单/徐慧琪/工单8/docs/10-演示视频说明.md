# 演示视频说明

本文给出两个演示视频的分镜脚本与录制建议。

- **视频一：功能演示** —— 启动系统、中文提问、三部分输出与响应时间、英文提问、语音输入、研报生成、评测结果。
- **视频二：图谱可视化 + 实体关系创建思路讲解** —— 彩色图谱交互、子图筛选、节点 provenance，以及「定本体 / 分层抽取 / 三道闸门 / 多文档融合 / provenance」五步讲解。

> 本文所有界面元素（页签名、控件名、按钮文案、提示语）均逐一核对自 `app.py`、`src/speech.py`、`src/graph_viz.py`、`src/ui_helpers.py` 的实际实现，录制时请**照抄第四节的「界面原文速查表」**，避免口误。
>
> 实测数字来自 `data/eval/graph_qa_results.json`、`data/eval/compare_wo07.json`、`data/kg/kg_stats.json`（详见 `docs/05`、`docs/06`）；录制时以屏幕实际显示为准。

### 1.2 需要提前准备的状态

1. **Ollama 已启动**：`ollama serve`（默认地址 `http://127.0.0.1:11434`，见 `src/config.py` 的 `OLLAMA_HOST`）；问答与研报使用的模型是 `qwen2.5:3b`，配置了 30 分钟常驻显存。**建议开录前先手工问一题把模型拉进显存**，否则「生成研报」镜头会出现明显冷启动等待。
2. **图谱已构建**：`data/kg/kg.pkl` 存在。若图谱页显示「图谱不可用：…」并附命令块 `python build_kg.py --layer1`，说明图谱未就绪，需先构建。
   - 第 1 层（词典 + 正则，全量块，**秒级**）即可支撑本视频的全部演示内容；第 2 层（LLM 定向抽取）是**可选的**长尾增强，用 `python build_kg.py --all --resume` 断点续抽 —— **录视频不需要跑第 2 层**。
3. **评测产物已生成**：`data/eval/ground_truth.json`、`data/eval/graph_qa_results.json`、`data/eval/compare_wo07.json` 三个文件齐备。否则评测页只会显示占位提示（「尚无逐题结果。运行：`python graph_qa_cli.py --all`」/「尚无对比结果。运行：`python src/compare_with_wo07.py`」），录不出结果表。
4. **界面预热**：正式开录前完整点一遍六个页签（让图谱页、评测页的数据进入缓存），并先跑一遍问答题，避免第一次提问时模型冷启动。
5. **网络**：图谱页的交互式渲染走 vis.js CDN，语音输入走浏览器 Web Speech API，**两者都需要联网**。若录制环境不通外网，图谱页改用「静态（matplotlib）」渲染，语音输入镜头按第 1.4 节的降级话术录制。

### 1.4 已知边界（讲解时必须如实说明，不要回避）

- **语音输入是降级方案**：本工程零下载，未下载 Whisper 等 ASR 权重，语音识别依赖浏览器 Web Speech API（Chrome / Edge 通常可用，**需联网**；Firefox 不支持；完全离线不可用）。界面在控件下方固定显示一行说明文字，并在不支持时禁用按钮。
- **图谱实际覆盖 6 类实体**：图例列出本体的 10 类实体及其颜色，当前图谱实际出现的是 `Metric` 436、`Department` 69、`Time` 24、`Institution` 19、`Company` 9、`Industry` 3，共 560 个节点。讲解时说「本体定义了 10 类实体，图例按 10 类给出配色，当前语料实际落到 6 类」最准确。
- **评测并非全胜**：14 题里 Q07、Q08 的覆盖率低于 07（落后 2 道），Q10、Q14 的图谱通道为空（`org_tree`/`none` 模式下图谱事实 0 条）。展示评测页时应把结论落在「Graph RAG 的增量集中在关系型、多跳型、结构型问题」，而不是「全面更优」。

### 3.2 五步讲解的备忘卡（照此口播即可）

| 步骤 | 一句话主旨 | 关键数字 / 名词 |
| --- | --- | --- |
| 一、定本体 | 先看语料结构，再定实体与关系；10 类实体、关系类型在 `RELATION_TYPES` 中显式声明合法头尾类型 | 10 类实体；章节：公司治理 / 股东 / 组织结构图 / 主要会计数据 / 业务概要 / 风险管理 |
| 二、分层抽取 | 第 1 层词典 + 正则打底（可信骨架），第 2 层 LLM 抽长尾（可选） | 第 1 层全量块、秒级；第 2 层用章节白名单 / 图谱触发词 / 实体密度三条信号筛块 |
| 三、三道闸门 | 实体类型在内、关系类型与头尾约束在内、evidence 逐字落地 | 三条都要过，任一不过即丢弃 |
| 四、多文档融合 | 别名归一到同一节点、边累加来源、同期间不同值保留并标记冲突 | 实体 ID = `{类型}:{规范名}`；9 份年报；`BELONGS_TO` 累计 63 条 |
| 五、provenance | 每条边带来源文档 + 页码 + 原文片段 | `source_doc` / `page` / `evidence` |

## 五、录制建议

### 5.1 画质与窗口

- 分辨率：**1920×1080**（最低），条件允许用 2560×1440 录屏后导出 1080p，图谱连线更清晰。
- 帧率：30 fps 即可（界面无高频动画，vis.js 的力导向稳定过程反而是可讲的看点）。
- 浏览器：Chrome 或 Edge（图谱 CDN 与语音识别都在这两者上最稳）；按 `F11` 全屏，隐藏书签栏与个人账号信息。
- 页面缩放 100%~110%；图谱页建议先等力导向布局稳定（约 2~3 秒）再开始讲解。
- 录制区域固定为浏览器内容区，终端只在启动镜头出现。

### 5.2 总时长与节奏

| 视频 | 建议时长 | 节奏提示 |
| --- | --- | --- |
| 视频一 功能演示 | 6~7 分钟 | 提问后必须**剪掉等待**（spinner 可保留 2~3 秒再快进）；答案与三部分是核心，占一半以上篇幅 |
| 视频二 图谱可视化 + 建图思路 | 7~8 分钟 | 可视化占前 4 分钟，五步讲解占后 4 分钟；每步讲解不少于 30 秒，重点放在第 2 步（分层抽取）与第 3 步（三道防幻觉闸门），这两步是「为什么可信」的核心 |

### 5.3 旁白要点

1. **先讲「是什么」再讲「怎么做的」**：视频一每个页签先用一句话说明它是什么、解决什么问题，再操作。
2. **数字要落到来源**：提到响应时间、覆盖率、图谱规模时，先说数字再说出处（答案区响应时间行、评测页逐题结果、图谱页规模说明）。
3. **主动说明边界**：语音输入的联网依赖、图谱实际覆盖 6 类实体、评测有 2 道落后题 —— 主动讲比被问出来更有说服力。
4. **强调可回溯**：检索结果区的「文档名 + 页码」、图谱连线的 evidence、研报的数据来源表，这三处是同一条主线，建议在视频一和视频二各点一次。
5. **口播与界面文字一致**：按钮就叫「提问」「生成研报」「添加到内存图谱」「添加关系」，不要临场改叫「搜索」「生成」等。

### 5.4 录制顺序与应急预案

- **先录视频二再录视频一**更省时间：图谱页加载最慢，先录完可保持预热状态。
- 若 `生成研报` 返回较慢：提前把「研报主题」和公司选好并试跑一次，正式录制时重跑；若出现「降级：LLM 撰写失败…」，说明 Ollama 未启动或模型未加载，重启 `ollama serve` 后重录该镜。
- 若语音识别无响应：检查浏览器是否联网、是否授予麦克风权限；必要时改录「提示文字 + 文字输入降级」版本，并如实说明。
- 若图谱页 CDN 不可达：切「静态（matplotlib）」录制，并在旁白中说明这是离线兜底方案。
- 若评测页为空：先运行 `python graph_qa_cli.py --all` 与 `python src/compare_with_wo07.py` 生成 `data/eval` 下的结果文件再录。
