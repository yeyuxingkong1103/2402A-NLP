## 一、判定逻辑类（影响正确性）

### 1. 专利附图页冒充扫描页 —— 298 份误判

**现象**：按工单原文「每页字符数低于阈值就算扫描页」实现后，
1700 份里 **298 份被判成「混合型」**，意味着要多排 298 份 OCR。

**原因**：专利**附图页**整页只有「图1」「图2」几个字，字符数当然低，
但它是数字排版的原生页，不需要 OCR。

```
CN106926565B.pdf
  第 1~5 页   字符 925~1477   图片覆盖 0.01      ← 正文
  第 7~10 页  字符 32         图片覆盖 0.32~0.44 ← 附图页
```

**修法**：每页多记一个物理量 —— **图片覆盖率**（图片面积 ÷ 页面面积），
「扫描页」= 字符数低 **且** 图片铺满（≥0.8）。实测扫描件 ≈1.00、附图页 0.32~0.44。

**效果**：扫描型 622 份一份没少，误判的 298 份全部归位到文字型。

### 2. `get_text("dict")` 取不到图片块，真扫描件被判成文字型

**现象**：改动 1 落地后重跑，扫描型从 622 掉到 **618** —— 有 4 份掉队了。
但它们逐页字符数都是 0，图片覆盖率也报 0.00，于是被判成「文字型」，
送去抽文字只会得到**一篇空白**。

**查证**：渲染成 PNG **肉眼看** —— `CN2926129Y.pdf` 明明白白是拍下来的专利首页。
再看 API：`get_text("dict")` 返回的 blocks 是**空的**，而
`get_images()` 明明报告有 1 张图。

**原因**：这几份的内容流大概用 Form XObject 之类的方式画图，
pymupdf 不在 dict blocks 里报。

**修法**：换 `page.get_image_info()` 取图片 bbox（dict 块降级为兜底）：

```
文件                    dict块   get_image_info
CN2926129Y（扫描件）     0.00    1.00   ← dict 漏了
CN100408987C（扫描件）   0.93    0.93
CN111318330A（文字型）   0.09    0.10
CN106926565B（附图页）   0.10    0.11
```

**教训**：**统计数字看起来正常，不代表没错。** 这一条是渲染出来肉眼看的才发现 ——
「扫描型 618 而不是 622」这种 4 份的差异，光看报表根本不会起疑。

### 3. SimHash 按单字切，准确率只有 38%

**现象**：阈值 5 捞出 19 对「版本冲突」，逐对打开核对，**标题对得上的只有三分之一**。

**原因**：初版按单字切中文（注释里还写着「不引分词器，按字切足够了」）。
单个汉字的熵太低 —— 「的、一、是、在」每份中文文档里都是常客，
两份毫不相干的专利也能有 92% 的二进制位相同。

**修法**：改 **3 字滑窗**（shingle）。比的是「短语」而不是「用字偏好」。
**依然不引分词器**，滑窗就够。

**效果**：距离分布从「平滑衰减、无空档」变成「有明确空档」，
准确率 38% → **94%**。

**边界**：滑窗对**插入噪声**敏感 —— 水印版/无水印版这种「正文里密集插了水印字符」
的副本，滑窗会被打断（实测招股说明书那对距离 17，漏检）。单字切反而能认出来。
这是取舍，写在 `SKILL.md` 的局限里了。

### 4. 空 `when` 的兜底规则变成「永远命中」

**现象**：30 份文档打出 **90 个标签**，其中 30 个是 `Unclassified`。

**原因**：配置里 `Unclassified` 的 `when: {}` 本意是「兜底」，
但代码把空 when 当成「条件永远满足」，于是每份文档都挂上它，标签分布失去意义。

**修法**：把空 `when` 的规则摘出来，只在其他规则都没命中时才用。

### 5. 扫描件全被判成「坏文件」

**现象**：`Empty_or_Broken`（字符数 < 50）本意是抓「解析失败或占位文件」，
但扫描件本来就没文字层，字符数当然是 0 ——
**1700 份扫描专利每一份都被判成坏文件**，而且路由变成「`ocr`、`review`」两个，
工作流不知道该送哪个解析器。

**修法**：规则加 `pdf_kind_not: scanned`。已被判为扫描型的，字符数少是预期内的，
不叫坏。真正要抓的是「有文字层却几乎没抽出字」的文件。

### 6. 金额被截成手机号

**现象**：年报语料 2 条手机号命中，**全是误报**：

```
本年提取数18921754811,6892,734      ← 其实是 1,892,175,481.1 被截出 11 位
应收账款21,19362019822,011          ← 同类
```

**原因**：`(?<!\d)` 数字边界挡不住**逗号千分位** ——
前面是「数」不是数字，后面是逗号也不是数字。

**修法**：加判据 —— 命中的数字串前后紧邻 `,`/`.`/`%` 就判为「长数字的一截」。

**代价**：「手机号后紧跟半角逗号」会漏。权衡值得（见设计说明 3.4）。

### 7. 扫描件的换行符被当成「字符」

**现象**：一份 8 页的纯扫描件（页页空白）被数出 **7 个字符**。

**原因**：`p.get_text("text")` 对空白页返回 `"\n"`，几页拼起来就是一串换行符。
`len(text)` 把换行符算成了内容。

**修法**：先 `text.strip()` 再数字符。改完 622 份扫描件的字符数从「几个」
变成「0」，`Empty_or_Broken` 的判定和长度分布的分位数才准。

## 二、工程与流程类

### 8. Windows 控制台把整个质检打崩

**现象**：跑 IMDR 时控制台报 `UnicodeEncodeError: 'gbk' codec can't encode character`，
**整个质检中断**。

**原因**：知识库里混着下载来的乱码文件名（非 GBK 字节）。Windows 控制台默认 GBK，
`print` 这些路径直接抛异常。

**修法**：`common.utf8_console()` 在入口把 stdout/stderr 重设为 UTF-8
（`errors="replace"`）。Linux 上本来就是 UTF-8，是空操作。

### 9. 报告里两个静默的渲染 bug

发现这两个都是因为「跑了真数据才发现列的数和想的不一样」：

- **PDF 占比永远 100%+**：`write_html` 用 `pt.get('pdf_total', 1)` 当分母，
  但 `summarize()` 压根没返回这个键 → 分母恒为 1。
- **「路由去向」列恒为空**：`d["_tagged"][:0]` 是个空切片，
  推导式永远产出空集合 → 每行都显示 `-`。

**修法**：把报告的 details 结构**显式定义**（`report.py` 顶部的 `COLS` 表头
和 `summarize.build_report()` 里造的行一一对应），
并加了单元测试 `test_报告结构完整` 检查必需字段。

### 10. 「跳过」被当成「查过了」

**现象**：第一次跑完，控制台显示「待确认版本冲突 0 对」——
看起来像查过了没问题，**实际是 622 份扫描件根本没有正文，全被跳过了**。

**修法**：明确统计并输出跳过份数与原因：

```
待确认版本冲突  0 对（另有 622 份正文过短未参与比较）
```

报告 JSON 里也带 `simhash_compared` / `simhash_skipped_thin` 两个字段。
**没有静默截断** —— 这是工单「列表可操作性」精神的一部分。

顺带修了一个统计 bug：`thin` 计数写在 `continue` 之后，导致「完全没正文」
的文档根本没被计进去，数字偏小。

### 11. 多语料共用一个 workdir，分析时混着比

**现象**：`分析.py pairs` 报「参与比较 1100 份」，但 IMDR 单独只有 1078 份
有正文。

**原因**：缓存是按**文件路径**做键的，同一个 `.quality_work/parsed.jsonl` 里
攒了多个语料的记录，两两比较时把两个语料混在一起了。而且按关键字 `附件`
过滤会**同时命中** `附件\` 和 `14-17附件\`（后者路径里也含「附件」）。

**修法**：`分析.py` 加 root 过滤参数，用带分隔符的精确串（`\附件\`）匹配。

### 12. 逐对核对版本冲突，`分析.py` 一开始判错了

**现象**：第一版核对脚本用「首页第一行非空文本」当标题来比对，
判出「标题一致 28/37」。

**原因**：这行的实际内容是 `(19)中华人民共和国国家知识产权局` —— **专利页眉**，
两份不同专利完全一样。更坑的是这行在 2018 年机构改革后从
「中华人民共和国国家知识产权局」缩成「国家知识产权局」，
于是「机关更名」被当成了「文档差异」。

**修法**：改取首页著录项 —— 名称 `(54)`、申请人 `(71)/(73)`、申请日 `(22)`，
判据改成「**同申请人 + 同申请日**」。这也顺带解决了「标题因权利要求类型而不同」
的问题（发明专利能写方法权利要求，实用新型不能）。

### 13. 拆文件：300 行是硬约束

`assess.py` 一度涨到 342 行，超过项目约定（单文件 ≤300 行）。
按职责拆成：

- `assess.py`（200 行）—— 跑：遍历、解析、缓存、断点续跑、CLI
- `summarize.py`（134 行）—— 算：把解析记录汇总成报告
- `print_brief` 移进 `report.py`（223 行）—— 和 JSON/HTML 渲染放一起

拆的边界正好是第三节那条「解析 vs 判定」的分界线，不是硬凑的行数。

## 三、运维类

### 14. 删掉 `ragflow-logs/` 会让容器挂载失效

**现象**：清理密钥时删掉了 `工单14/15/17/研发/ragflow/docker/ragflow-logs/`，
之后 `docker exec docker-ragflow-cpu-1 ...` 报：

```
error while creating mount source path '.../ragflow-logs': mkdir ...: file exists
```

**原因**：这个目录是**运行中容器的 bind mount 源**。删掉之后 Docker 重新挂载时
找不到源目录（挂载表里还留着条目），于是报「file exists」。

**修法**：把目录 `mkdir -p` 回来即可，容器不用重启。

**教训**：**清理日志要「清空内容」而不是「删除目录」**，或者提前确认它是不是挂载源。
`docker inspect` 能看到所有 bind mount 源，删之前值得扫一眼。

### 15. 容器自带 venv 里没有 pymupdf

**现象**：装好补丁、挂载也对了，但端点一调，所有 PDF 都被判成 `unreadable`。

**原因**：`/ragflow/.venv/bin/python`（容器里跑质检用的解释器）**没有 `fitz`**。
`common.pdf_parse()` 走 `except ImportError` 分支返回 `(None, None, None, 0)`，
整个「文字型/扫描型分流」失效。

**修法**：`docker exec docker-ragflow-cpu-1 /ragflow/.venv/bin/pip install pymupdf`。

**注意**：装在容器可写层，**容器重建就丢**，要重跑。写进 `部署/DEPLOYMENT.md` 了。

> 备选方案（没采用）：把 `common.pdf_parse()` 改成 `pdfplumber` 实现。
> 容器里确实有 pdfplumber，但**换抽取器会让字符数口径变化**，
> 配置里的阈值（`min_chars_per_page` 等）是拿 pymupdf 的字符数标定的，
> 换实现要整套重新标定 —— 代价比装个包大。
