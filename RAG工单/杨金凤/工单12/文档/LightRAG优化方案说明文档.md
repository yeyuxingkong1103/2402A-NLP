# LightRAG 优化 —— 优化方案说明文档

- **工单编号**：人工智能NLP-RAG-LightRAG 优化任务
- **项目名称**：LightRAG 优化
- **日期**：2025 年

---

## 1. 任务目标

用 LightRAG 对《招股说明书1.pdf》和《招股说明书2.pdf》构建知识图谱，检索 16 个问题，对比 RAG 与 LightRAG 的检索和 RAGAS 评估结果。

---

## 2. 实施方案

| 步骤 | 内容 |
| --- | --- |
| 1 | 安装 lightrag-hku |
| 2 | 用 Qwen2.5-7B 抽取实体关系，构建 LightRAG 索引 |
| 3 | 用 LightRAG 检索 16 个问题 |
| 4 | 与传统 RAG 对比 |

**索引规模（路径 A：只处理前 2 万字符）：**

- 图谱节点：641
- 图谱边：277
- 实体：345 + 42
- 关系：162

---

## 3. LightRAG 核心机制

- **双层检索**：低层（实体级）+ 高层（主题级）
- **图结构 + 向量库**：实体关系存入 GraphML + JSON 向量库
- **增量更新**：支持新数据快速整合

---

## 5. 失败原因分析

| 原因 | 说明 |
| --- | --- |
| 索引覆盖不足 | 只处理前 2 万字符（占全文不到 10%） |
| 中英文失配 | LightRAG 内部用英文关键词（日志显示 wuhan, xingtu, xinke...），匹配中文内容差 |
| 图谱噪声 | LLM 混入 "Qwen"、"Alibaba Cloud" 等无关实体 |
| 数据规模不够 | 641 节点撑不起 16 题的检索需求 |
| LightRAG 不适配中文金融 | 它是为通用英文场景设计的 |

---

## 6. 结论

LightRAG 在本场景下表现显著差于传统 RAG，主要原因：

1. 索引覆盖不足（可扩大处理范围改善，但耗时数小时）
2. 中英文语义鸿沟（需修改 LightRAG 内部 prompt）
3. 图谱质量不佳（Qwen 抽取有噪声）

**推荐方案**：继续使用工单 08 的 Graph RAG（NetworkX 自建图谱），它在招股书场景下 fidelity 达 1.0。
