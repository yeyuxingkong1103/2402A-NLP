# 工单17 解决API服务并发瓶颈与资源泄漏｜总结文档
##1.任务完成情况
✅ 使用docker‑compose部署完整RAGFlow集群；
✅ 编写两套JMeter压测脚本：场景A(20并发问答)、场景B(混合负载问答+PDF解析)；
✅ 使用py‑spy定位CPU热点函数，memory‑profiler/objgraph分析内存对象；docker stats/nvidia‑smi/redis‑cli做系统与队列监控；
✅ 完成重量级AI组件单例封装，解决每请求重复初始化模型的并发瓶颈；
✅ 修复数据库、向量库连接池泄漏，try‑finally保证连接归还；
✅ 确认PDF解析任务交给Redis队列异步消费，API‑Server不再阻塞解析；
✅ 增加Prometheus埋点，采集接口耗时、请求数、队列、连接池指标；
✅ 优化后压测：场景A 20并发10分钟P95≤3s无失败；场景B混合负载P95≤5s；
✅ 12小时稳定性测试，RSS内存增长≤20%，资源泄漏修复。

##2.学习收获
1. 大模型RAG服务并发两大典型问题：**重量级组件重复实例化瓶颈、各种资源泄漏**。
2. 耗时重任务（文档解析）不可以在HTTP同步接口执行，必须异步消息队列解耦。
3. 数据库/向量库连接泄漏：异常分支极易忘记归还连接，必须try‑finally保证释放。
4. 性能调优流程：压测获取基线 → 工具定位瓶颈 → 修改代码 → 再次压测对比，假设‑验证迭代。
5. 可观测性很关键：CPU采样、内存分析、容器监控、队列监控、指标埋点，不能只看业务现象。

##3.现存不足
1. 实训没有接入Grafana做可视化告警；
2. 没有实现接口限流熔断。

##4.后续拓展方向
1. 增加API网关限流、熔断器，保护后端模型服务；
2. Prometheus对接Grafana面板，配置告警规则；
