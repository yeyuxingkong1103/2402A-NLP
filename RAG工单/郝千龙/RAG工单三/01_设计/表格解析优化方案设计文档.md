- 文档版本：V1.0（2025-02）

### 1.2 14 个问题的答案形态分析

工单问题按"答案在 PDF 中的载体"可分为四类，直接决定表格解析的设计重点：

| 类型 | 题号 | 答案载体 | 表格解析价值 |
| --- | --- | --- | --- |
| A. 纯表格数字/比例 | 1（发行股数 1,670 万股、25.04%） | 力源 P22/P24 发行概况表 | ★★★ 表格键值对 |
| B. 纯表格枚举列表 | 2（5 个募投项目）、3（赵马克/42.35%/控股股东）、4（7 家非控制关联方）、207（补充流动资金 15,000.00 万元） | 力源 P22 募投表、P157 关联方两张表；兴图 P30 募投表 | ★★★ 表格行逐条还原 |
| C. 多级表头财务表 + 正文互证 | 260（军品收入四期金额）、33（四期占比） | 兴图 P4 正文整句 + P185/P343 两级表头表（年度×金额/占比） | ★★☆ 多级表头还原、越界单元格修复 |
| D. 正文事实句 | 95、34、957、793、795、543、531 | 兴图 P22 基本情况卡、P26/27、P152/154 正文 | ★☆☆ 表格页正文保留、键值槽位 |

关键观察（均已在 PDF 中逐字核实）：

1. 力源 P157 一页内紧挨着两张结构相同的三列表（"关联方名称/持股比例/与本公司关系"与"企业名称/与本公司关系"），通用纯文本切块会把两张表与小标题打散，必须**按表独立成块并把最近标题（caption）挂到表上**才能区分 id=3 与 id=4。
2. pdfplumber 默认 `lines` 策略在兴图 P185 财务表上会**漏掉边框外的行表头列（国防领域/民用领域/合计）和最后一列占比（82.10% 等）**（见下表实测），需要基于词坐标（word bbox）做越界单元格修复与多级表头还原。
3. 兴图 P22 基本情况卡被 pdfplumber 切成"值在前、标签在后"的错位列（如 `['5,520.00万元','法定代表人']`），不能用劣质表覆盖正文；方案设表格质量门控，并在文本行级别做"被表格覆盖"去重，错版表自动丢弃、正文保留。
4. 两本招股书存在同名章节（募集资金、注册资本、法定代表人、关联方），**必须先做公司路由**，否则兴图/力源互相串答案。

### 1.3 纯文本基线的缺陷（优化动因）

工单一/二早期链路（PyMuPDF 正文 + 定长窗口块 + 纯向量检索）在本工单问题上的实测问题：

- 表格被按版面顺序拉平为无结构词序列（如力源 P157 的"融冰投资 持有公司股份5%以上的股东 武汉博润 …"），行列归属丢失；
- 定长窗口把两张关联方表切到同一块、或把半张表切到两块，枚举题漏项；
- 多级表头表只剩数字，丢失"2016 年度/金额/占比"语义；
- 无公司路由，"募集资金""注册资本"类高泛词跨公司串扰；
- 无表格行/单元格抽取，答案只能返回整块文本，无法精确作答。

第 04 阶段给出同环境真实跑出的基线 vs 优化后逐题对比数据。

## 3. 表格解析方案（核心）

### 3.1 pdfplumber 表格识别

- 对两本 PDF **每一页**调用 `page.find_tables()`（线框策略），实测速度约 0.05 秒/页，898 页建库期一次性成本约 1 分钟，可接受；在线问答零表格解析开销（索引已持久化）。
- 取表格 bbox 与行带（row bands）、单元格边（cell edges）。
- 不盲目相信 `extract_tables()` 的单元格结果：线框表存在跨行合并、边框外文字等问题，进入 3.2 重建流程。

### 3.2 表格清洗与词坐标网格重建（table_parser）

实测缺陷与修复手段：

| 实测缺陷 | 示例 | 修复算法 |
| --- | --- | --- |
| 空列/空行泛滥 | 力源 P157 抽成 9 列，其中 6 列全空 | 删除全空列、全空行；相邻空白槽位合并 |
| 边框外行表头丢失 | 兴图 P185 漏"国防领域/民用领域/合计" | 取 bbox 左外侧 ≤46pt 内的词，按 y 坐标归入对应行带，补第 0 列 |
| 边框外末列丢失 | 兴图 P185 漏"82.10%/17.90%/100.00%" | 取 bbox 右外侧 ≤46pt 内的词，补末列 |
| 单元格内换行/空格 | "持有公司股份5%以上 的股东" | 合并换行符、归一化空白、去除 CJK 间多余空格 |
| 列错位（无表格线弱表） | 兴图 P22 卡片值/标签颠倒 | 质量门控不通过即丢弃表格，保留 PyMuPDF 正文 |

网格重建步骤：

1. 汇总全部单元格的 x 坐标边，去重得到内部列槽位；bbox 左右各加一个"越界词槽位"；
2. 页内全部词（`extract_words`）按中心 y 归入行带、按中心 x 归入列槽；
3. 同一格内多词按中文无空格、英文有空格拼接，得到规整 R×C 字符矩阵。

### 3.3 表头还原（含多级表头）

- 表头行判定：第 0 行默认为表头；若第 0 行是年度分组（正则 `20\d{2}` 年/期）且第 1 行重复出现"金额/占比"等子表头，则识别为两级表头；
- 稀疏上级表头按列**前向填充**（forward-fill），再与下级表头组合：
  - 兴图 P185 还原结果：`类型 | 2019年1-6月-金额 | 2019年1-6月-占比 | 2018年度-金额 | … | 2016年度-占比`；
- 常见键值/枚举表头词典（关联方名称、企业名称、项目名称、持股比例、与本公司关系、计划总投资、序号、类型、金额、占比）辅助判定；
- 表头去重，空表头补 `列N` 占位。

### 3.4 表格标题（caption）还原

在表格 bbox 正上方 95pt、x 范围与表对齐的区域内聚类文本行，取最近 1~3 行作为表标题，并随表保存。实测挂载效果：

- 力源 P157 表一 → `1、存在控制关系的关联方`；表二 → `2、不存在控制关系的关联方`；
- 力源 P22 表三 → `五、募集资金用途 / 本次募集资金拟投资以下项目：`；
- 兴图 P185 表 → `报告期内，公司主营业务收入按客户列示如下：单位：万元`。

caption 使表格块自带"这张表在回答什么"，是 id=3/id=4 区分与枚举题召回的关键。

### 3.5 表格 Markdown 化

清洗后的矩阵统一序列化为 GitHub 风格 Markdown（首行表头、次行 `|---|`、数据行），竖线与换行做转义；同时保留 Python 侧二维数组与行陈述句三种表示，分别服务于展示、精排与答案抽取。

### 3.6 表格质量门控

同时满足才保留为表格块，否则回退正文：

1. 行数 ≥ 2 且列数 ≥ 2；2. 单元格填充率 ≥ 45%；3. ≥70% 的行至少 2 个非空格；4. 单元格平均长度 < 60 字（排除把段落误判成表）。

### 3.7 表格区正文去重

逐文本行计算其字符在"本页表格单元格语料"中的覆盖率，≥75% 且长度 ≥8 字则判定该行已被表格承载并从正文块剔除；其余正文（包括错版表格承载不了的键值行）原样保留。避免同一事实重复入索引，同时绝不丢信息。

## 4. 表格感知分块（chunker）

| 块类型 | 粒度 | 文本（用于检索） | 父文本（用于展示/作答） |
| --- | --- | --- | --- |
| text | 句子贪心打包，约 450 字、80 字重叠，标题路径+主体公司前缀 | 同左 | 同标题路径+同页父段落 |
| table | 整张表 | `标题路径 + 主体 + caption + Markdown 全表` | Markdown 全表 |
| table_row | 表格每一数据行 | `caption + 行陈述句`，如"存在控制关系的关联方：赵马克，持股比例42.35%，与本公司关系：公司控股股东" | 所属整表 Markdown |

- 行陈述句采用 Small-to-Big：行块小、信号密度高，TF-IDF/BM25 极易命中；命中后父文本给全表上下文，答案可溯源到具体行与页码；
- 宽表（如四期年度财务表）一整行保留全部期数字，天然匹配"分别是多少"类多值题；
- 每个块带 `company`（发行人全称）与 `chunk_type` 元数据。

## 5. 检索与答案定位方案

### 5.1 公司路由（双招股书隔离）

- 查询出现"力源 / Liyuan"→ 仅检索力源块；出现"兴图 / 新科 / Xingtu / Xinke"→ 仅检索兴图块；
- 14 题全部含公司全称，路由硬过滤可靠；未命中公司词（如英文泛问）则全库检索；
- 公司全称在块内高频出现、IDF≈0，查询侧仍对公司名做归一化，避免干扰 BM25 打分。

### 5.2 双路召回 + RRF

- 稠密路：sklearn TF-IDF（`char_wb` 2~4 gram，sublinear，L2 归一，**稀疏矩阵**存储与乘法，5000 块级内存仅数十 MB），对中文专名、数字串（1,670 / 42.35% / 6,464.51）区分度好；
- 稀疏路：jieba 分词 + 英文整词 BM25，postings 倒排表只累加命中文档，毫秒级；
- RRF（k=60）倒数排名融合，再进入精排。
- 嵌入层保留 BGE 接口：启动时探测本地 HF 缓存，有缓存可自动升级语义向量；本环境无缓存且禁止联网，自动降级 TF-IDF（建库日志显式标注）。

### 5.3 表格感知精排

RRF 底座上叠加：① IDF 加权查询词覆盖度；② 关键长短语精确命中（"不存在控制关系""军用领域的收入""补充流动资金"等，滑窗 4~6 字）；③ 答案类型吻合（数字/比例题奖数字格，枚举题奖顿号行）；④ **表格行块加权 +0.15、整表块 +0.08**，让精确行陈述句优先于大段正文；⑤ 证据名次先验。

### 5.4 表格行/单元格答案抽取（qa_engine）

按问题意图分派，全部只在"已检索到的证据"上抽取，不写死答案：

| 意图 | 触发词 | 抽取方式 |
| --- | --- | --- |
| 发行股数/占比 | 发行股数、占发行后总股本 | 键值正则，输出"股数+比例" |
| 募投项目枚举 | 募集资金、投资、项目 | 读 `项目名称/项目` 列，逐行拼"名称（投资额）"，排除合计行 |
| 控制关系关联方 | 存在控制关系、关联方、持股比例 | 读三列表行，输出"名称+持股比例+关系" |
| 非控制关联方枚举 | 不存在控制关系 | 读两列表全部数据行，逐条枚举 |
| 多期金额/占比 | 分别是多少、比重 | 取含数字/百分比最全的表格行或正文整句 |
| 注册资本/法定代表人/补充流动资金 | 对应键名 | 带主体约束的槽位正则，排除历史值与其他公司 |
| 上游/下游、技术标准、重要供应商、科技进步一等奖 | 对应短语 | 句子级覆盖度排序后返回原文整句 |

### 5.5 3 秒延迟预算

索引启动加载不计入单次响应；单次问答：分词+TF-IDF transform < 20ms，双路召回 < 50ms，精排（候选 30）< 30ms，答案抽取 < 20ms，实测单题 0.1~0.4 秒，余量充足。

## 6. 双语、稳定性与可观测

- Streamlit 侧边栏中/英切换，英文示例问题可直接提问（公司英文名 Wuhan Xingtu Xinke / Liyuan 参与路由）；
- 自定义 `PDFParseError`；表格解析异常逐页捕获回退纯文本；空查询、缺索引均有友好提示；
