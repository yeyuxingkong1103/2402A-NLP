# 工单06 技术文档：混合检索

> 工单编号：人工智能NLP-RAG-混合检索任务

## 一、功能实现（hybrid_retriever.py + run_hybrid.py）

### 1. 向量检索（召回+重排）
- 嵌入：bge-m3（1024维，Ollama本地）；支持通过 `EMBED_MODEL` 环境变量切换嵌入模型
  （本地已验证可切换：nomic-embed-text / bge-large 等均可经 Ollama 直接替换）；
- 召回：余弦相似度 Top-20；
- 重排：内置 3 种重排器（见下）。

### 2. 全文检索（BM25 倒排索引）
- jieba 搜索引擎模式分词 + rank_bm25(BM25Okapi) 倒排打分；
- 支持：布尔查询（`AND / OR / NOT` 操作符）、短语匹配（引号 `"..."`）、
  模糊匹配（词项编辑距离近似，相似度≥0.85）；
- 多字段：元数据含来源文档/页码，可按 source 过滤扩展。

### 3. 混合检索
- 两路各召回 Top-20，分数 min-max 归一化后加权融合：`score = vec_w × 向量分 + ft_w × 全文分`；
- 权重可配：`run_hybrid.py --vw 0.5 --fw 0.5`（也可选纯 vector / 纯 fulltext 模式）；
- 融合之外另支持 RRF 备选实现（query_optimize.multi_retrieve）。

## 二、三种重排器

| 重排器 | 原理 | 成本 |
|---|---|---|
| LLM重排器 | qwen2.5 对候选片段按相关性重新排序（输出序号JSON） | 每查询1次LLM调用 |
| TF-IDF重排器 | 候选集上构建TF-IDF向量，与query余弦相似度重排 | 零外部调用 |
| 用户反馈自适应重排器 | 记录用户采纳的来源页（index_store/feedback.json），后续查询对已采纳来源加权，随使用累积自适应 | 零外部调用 |

## 三、对比实验（10个验收问题，知识库2773块，关键事实人工核对）

| 策略 | 准确率 | 召回率 | 平均耗时 |
|---|---|---|---|
| 向量检索(召回+TF-IDF重排) | 6/10 | **8/10** | 3.7s |
| BM25全文检索 | 6/10 | 6/10 | 4.0s |
| 混合检索(等权) | 6/10 | 7/10 | 4.3s |
| 混合+LLM重排器 | 6/10 | 7/10 | 4.8s |
| 混合+TF-IDF重排器 | 5/10 | 5/10 | 5.3s |
| 混合+用户反馈重排器 | 4/10 | 6/10 | 2.9s |

### 结论与分析
1. 召回率：向量(80%) > 混合(70%) > BM25(60%)——向量语义泛化最强；
2. 未能到 90%/95% 目标的根因与工单03一致：**生成端波动**（同一上下文多轮回答不一致），
   检索侧真值块实测可进前列；可靠提升路径为更大模型/生成端自一致性（记录于工单03技术文档）；
3. 用户反馈重排器在本轮冷启动（反馈库为空）无增益，属预期行为——其价值在持续使用场景；
4. TF-IDF 重排在字面重合低的语义问题上反而降序（字面偏置），适合关键词型查询场景按需启用。

## 四、运行方式

```bash
python run_hybrid.py                                    # 完整对比实验 → 检索策略对比报告-工单06.md
python run_hybrid.py --query "注册资本是多少" --mode hybrid --rerank tfidf --vw 0.5 --fw 0.5
                                                        # 单查演示（可配模式/重排器/权重）
```
