## 1. PDF 解析模块 `src/pdf_parser.py`

### 1.1 数据结构

```python
@dataclass
class PageDoc:
    page_no: int              # 页码（1 基）
    text: str                 # 清洗后的正文
    tables: List[str]         # Markdown 表格
    headings: List[str]       # 本页识别到的标题
    content: str              # text + tables 拼接（供基线分块使用）
```

### 1.2 处理流程

```
parse_pdf(path, with_tables=True, clean_boilerplate=True)
  1) fitz.open(path)，逐页 page.get_text("text")
  2) 统计跨页重复行（出现页数 ≥ 阈值且长度 < 60）→ 判定为页眉页脚 → 剔除
  3) 剔除纯页码行（正则 _PAGE_NO_RE：数字 / 罗马数字）
  4) 行合并：行尾非句末标点时与下一行拼接，修复 PDF 断句
  5) 表格：page.find_tables() → 渲染 Markdown（保留行列）
  6) 标题识别：_HEADING_RE 匹配"第X节 / 一、/（一）/ 1.1"等
  7) 单页异常 try/except 跳过，保证整体不中断
```

## 2. 分块模块 `src/chunking.py`

### 2.1 数据结构

```python
@dataclass
class Chunk:
    content: str      # 块文本
    page: int         # 页码
    section: str      # 小节标题
    ctype: str        # text / table
    parent: str       # 父块（小节全文，截断 2000 字符）
    index: int        # 序号
```

### 2.2 分块算法

```
build_chunks(pdf_path, chunk_size=700, chunk_overlap=120)
  for 每页 pg:
      # (1) 表格：原子块
      table_section = "；".join(pg.headings) or "表格"
      table_parent  = "\n\n".join(pg.tables)
      for t in pg.tables:
          append Chunk(f"[表格]\n{t}", ctype="table", parent=table_parent)

      # (2) 正文：先切小节，再递归切片
      for (title, body) in _split_sections(pg.text):
          parent_text = f"{title}\n{body}"
          if len(parent_text) < MIN_CHUNK_SIZE: continue
          for piece in RecursiveTextSplitter(parent_text):
              if len(piece) < 12: continue
              append Chunk(piece, section=title or "正文",
                           ctype="text", parent=parent_text[:2000])
```

**要点**：表格块的 `section` 取本页标题集合，使"概览/基本情况"类问题的章节先验可命中表格块。

## 4. 检索模块 `src/retriever.py`

### 4.1 HybridRetriever

```python
retrieve(analysis, k=6):
    merged = {}
    for q in analysis.retrieval_queries:          # 多路查询
        for (doc, vec_sim, bm25_score) in retrieve_candidates(q):
            merged[doc.page_content] = 取各维度最大值
    scored = reranker.rerank(analysis, merged.values(), top_n=max(k*3, 12))
    # 按父块去重
    seen_parent = set()
    return [首个非重复父块的 scored 元素 ... 至 k 个]
```

```python
retrieve_candidates(query):
    vec = store.similarity_search_with_score(query, k=VECTOR_TOP_K)   # L2 → sim = 1/(1+d)
    bm  = bm25_index.search(query, k=BM25_TOP_K)
    rrf = {doc: Σ 1/(rrf_k + rank + 1)}                               # RRF 融合
    return 按 rrf 排序的 [(doc, vec_sim, bm25_score)]
```

## 5. 重排模块 `src/reranker.py`

```python
rerank(analysis, candidates, top_n=6):
    vec_norm  = min-max 归一化(向量相似度)
    bm_norm   = min-max 归一化(BM25 分)
    for (doc, v, b) in candidates:
        kw  = 关键词覆盖率        # 查询实词在片段中的出现比例
        num = 数值/年份匹配度      # 比例型看 %、金额型看 万元/亿元、年份命中
        ent = 实体匹配度          # 公司名/标准名/工程名等
        s = W_VECTOR*vec_norm + W_BM25*bm_norm + W_KEYWORD*kw
          + W_NUMERIC*num + W_ENTITY*ent
        if doc.ctype == "table" and answer_type in (amount, ratio, number):
            s += 0.03             # 表格块加成
    return 按 s 降序的 top_n 个 ScoredDoc(doc, score, detail)
```

默认权重：`W_VECTOR=0.30, W_BM25=0.20, W_KEYWORD=0.25, W_NUMERIC=0.15, W_ENTITY=0.10`。

## 6. 答案合成模块 `src/answer_builder.py`

### 6.1 候选收集 `_candidate_units`

对每个 `ScoredDoc`，取「块正文 + 父块」两处文本：
- 表格块 / 以 `|` 开头 → 按行拆为候选；
- 普通文本 → `split_sentences()` 按句切分。

过滤规则：去空白后长度 < 6 丢弃；命中 `_HEADING_RE` 且长度 ≤ 45 的标题行丢弃。

### 6.2 打分函数

| 函数 | 作用 |
|---|---|
| `_kw_cov` | 关键词覆盖率 |
| `_num_score` | 按 ratio/amount/number 类型检查百分号、金额单位、数字、年份 |
| `_enum_score` | 列举型：命中"主要包括/包括/涉及/分为/覆盖" + 顿号密度 |
| `_signal_score` | 按答案类型选择上述信号；实体型检查"为/是/：/，/、"后紧跟 2-4 个汉字 |
| `_ent_score` | 实体匹配 |
| `_defn_score` | 关键词后 8 字符窗口内出现取值标记 |
| `_len_score` | 12~200 字符得满分，过短/过长降权 |
| `_summary_prior` | 关键词属公司基本信息字段时，"概览/基本情况"章节得 1.0 |
| `_contrast_penalty` | 对比词对（上游/下游、军用/民用、直接/间接…）只问一侧却出现另一侧 → 惩罚 |
| `_boilerplate_penalty` | 签署页/中介机构套话 → 惩罚 |

### 6.3 综合打分与拼装

```
s = 0.34·kw + 0.16·signal + 0.09·ent + 0.09·defn + 0.05·table
  + 0.04·len + 0.05·片段得分 + 0.18·章节先验 - 0.20·对比词惩罚 - 0.15·套话惩罚
```

选取规则：`s > 0.15` 且同一页最多 2 句，取 Top-N（默认 3），按得分降序拼装：

```
根据招股说明书第X页、第Y页：句1；句2；句3
```

同时返回 `evidences`（证据句 + 得分）与 `citations`（页码集合）。

## 7. 问答引擎 `src/qa_engine.py`

| 方法 | 链路 | 说明 |
|---|---|---|
| `answer_optimized(q)` | 优化检索 + 抽取式 | **本工单最终方案** |
| `answer_baseline(q)` | 基线检索 + LLM 生成 | 复刻 01 工单，用于对比 |
| `answer_baseline_extractive(q)` | 基线检索 + 抽取式 | 消融：隔离检索侧贡献 |
| `answer_optimized_llm(q)` | 优化检索 + LLM 生成 | 消融：隔离生成侧贡献 |
| `answer_llm_only(q)` | 无检索 + LLM | 纯 LLM 对照 |

检索器懒加载：只有用到对应链路时才加载向量库，避免无谓开销。

## 8. 知识库 `src/knowledge_base.py`

- 向量化：`OllamaEmbeddings(model="bge-m3:567m")`，`_BatchedEmbeddings` 按 50 条分批调用 `/api/embed`；
- 索引：`FAISS.from_documents`，持久化 `index.faiss` + `index.pkl`；
- **中文路径桥接**：Windows 版 FAISS 的 C++ 层使用窄字符 API，无法打开含中文路径。
  `save_local/load_local` 检测路径非 ASCII 时，先在临时 ASCII 目录读写，再 `shutil.copyfile` 回目标目录。

## 9. 评估脚本 `scripts/evaluate.py`

- 预热：先跑一次问答，规避 embedding 模型冷启动（避免把 5 s 冷启动计入耗时）；
- 每题分别执行基线链路与优化链路；
- 指标：Top-K 命中、Top-1 命中、MRR、答案命中、耗时；
- 命中判定使用「块正文 + 父块」，与答案合成实际可用上下文一致；
- 输出 JSON 与 Markdown 报告。
