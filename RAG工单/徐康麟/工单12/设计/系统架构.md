## 3. 流程一：LightRAG 索引构建

```
① 解析  研发\data\raw\*.pdf  ──corpus──▶  pages.jsonl（逐页文本）
                                          │
② 切块+分类  ──corpus──▶  chunks.jsonl（3013 块：text 2000 / table 922 / image 91）
                          块长目标 700 字、重叠 120 字、丢弃 < 80 字
                                          │
③ 向量化  ──ollama_client /api/embed──▶  vectors.npy（3013 × 1024）
                                          + ids.json（块 id 有序列表）
                                          │
④ BM25   ──vector_index──▶  bm25.pkl（词表 21271）
                                          │
⑤ 小样抽取（LLM，本工单核心）              │
   graph_extract：按 sample_size=400、seed=20250826 分层抽样 400 块
     ├─ 过滤：content 长度 < min_chunk_chars(150) 的块剔除
     ├─ 加权：table / image 块 +density_bonus（信息密度更高）
     ├─ 提示词注入 entity_schema.schema_prompt_block()（17 实体/16 关系封闭集）
     ├─ 每块 1 次 LLM 调用（batch_chunks=1，串行，避免多模型驻留）
     └─ 逐块 append 到 raw_extractions.jsonl（防中断丢数据）
                                          │
⑥ 存图谱  ──graph_store──▶  实体表 + 关系表（JSON / GraphML）
     ├─ 类型吸附：coerce_type() 把非法类型名映射到封闭集
     ├─ 约束校验：relation_allowed() 按头尾实体类型过滤非法关系
     ├─ 别名归并：normalize_name → resolve_alias → Dice ≥ 0.82
     └─ 关系去重：同 (head, rel, tail) 合并 + 置信度累积
                                          │
⑦ 可视化  ──graph_viz──▶  测试\测试截图\知识图谱可视化.png（≤60 节点 / ≤120 边）
```

**成本口径**：⑤ 是唯一调 LLM 的重活，调用数 = 抽样块数（默认 400），全程串行；**绝不跑全量 3013 块**。

## 4. 流程二：查询响应

```
用户问题
   │
① 问题分析  ──routing──▶  局部关键词（具体实体） + 全局关键词（抽象概念）
   ├─ 实体词典命中（词典来自图谱节点，entity_dict_from_graph=true）→ 局部
   ├─ 抽象后缀/提示词命中（abstract_suffixes 37 条、abstract_char_hints 17 条）→ 全局
   └─ 分不出 → route_fallback="both"（两路都走）
   │
② 两路检索（可开关，便于单独观测）
   ├─ 局部检索：局部关键词 → 向量检索 local_top_k=12，相似度 < 0.15 丢弃
   └─ 全局检索：命中的实体 → 图谱沿关系扩展 graph_hops=1（上限 3）
                → 收集关联块 global_top_k=12，上限 graph_max_relations=60
                分数 = 图分 + 0.35 × 关系置信度
   │
③ 融合  ──double_retrieval──▶  RRF（k=60）合并两路
   权重：local_weight=0.55 / global_weight=0.45   → 取 top_k=8
   │
④ 组上下文  ──qa──▶  取 top_k_in_prompt=6 块，截断至 max_context_chars=5200
   │
⑤ 生成  ──ollama_client /api/generate（qwen2.5:3b, temperature=0.1）──▶ 中文回答 + 引用
```

**RAG 基线对照路径**：跳过 ①③ 的图谱部分，直接 `向量检索 + BM25 检索 → RRF(0.5/0.5) → top_k=8 → 生成`，其余同上。两套后端共用同一 `top_k` 与同一生成参数，保证对比公平（口径见 `设计\检索与评估方案.md`）。

## 6. 接口约定

| 接口 | 约定 |
| --- | --- |
| 配置 | 三级优先级：`DEFAULT_CONFIG` → `部署\配置\lightrag.json` → 环境变量 `LIGHTRAG__<段>__<字段>`（如 `LIGHTRAG__RETRIEVAL__TOP_K=10`） |
| 硬编码红线 | 所有阈值（相似度、字符数、并发数、超时、抽样量）**只允许**出现在配置文件/环境变量 |
| 后端切换 | `--backend rag \| lightrag`；不传则按 `eval.backend_list=["rag","lightrag"]` 全跑 |
| 运行入口 | `cd E:\gao6gongdan\工单12` → `pwsh -NoProfile -File run_py.ps1 研发\scripts\xxx.py --args` |
| 重活包装 | 调 LLM 的脚本必须经 `_共享工具\安全跑.ps1` 包一层，日志落 `_共享工具\运行日志\` |
| 错误兜底 | 解析损坏 PDF / 网络失败 / 模型缺失一律 try-except 并记录，不裸崩；`ollama_client.health()` 给出缺失模型清单 |
