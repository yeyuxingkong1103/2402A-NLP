# 工单14 修复低质量工业PDF的解析与信息丢失｜部署文档
##1.RAGFlow部署方式（Docker Compose）
```bash
git clone https://github.com/infiniflow/ragflow.git
cd ragflow
docker compose up -d
访问 Web 页面：`http://127.0.0.1:8000`
内部依赖组件：

1. API Server：web 接口服务
2. Task‑Executor 任务消费进程
3. Redis：解析任务消息队列（Redis Stream）
4. 向量数据库、MySQL 元数据存储

##2. 实训部署步骤

1. WSL 环境启动 ragflow 容器；确认所有容器状态 Up。
2. 准备测试文档：`CN100342976C.pdf`放入工单 14 研发 /dataset 目录。
3. （可选）运行 pdf_ocr_fix.py 做本地 OCR 预处理，输出增强版 PDF。
4. Web 页面创建知识库，上传 PDF 文件；解析方案选择`Paper`。
5. 触发解析，观察任务执行日志，确认 Task Executor 消费 Redis 任务，调用 paddleocr_parser。
6. 解析完成，在 Web 界面进行问答测试；或者运行`test_ragflow_api.py`批量 API 测试。

##3. 关键配置说明

> 
> 处理扫描工业图纸 PDF 必须：解析类型选 Paper；底层启用 OCR 解析链路。

- 若上传原始扫描 PDF 识别效果差，优先使用本地脚本预处理得到 OCR‑PDF 再上传。

##4. 运维与故障排查

1. 文件解析卡住：查看 Task‑Executor 容器日志；检查 Redis 服务状态。
2. 图纸内容识别为空：确认解析器走 paddleocr_parser，不要使用 pdf_parser。
3. OCR 识别乱码：使用本地 pdf_ocr_fix.py 做图片放大预处理。
4. 问答图纸问题错误：检查分块策略、是否开启 rerank；查看检索召回切片，确认图纸相关文本是否被召回。
