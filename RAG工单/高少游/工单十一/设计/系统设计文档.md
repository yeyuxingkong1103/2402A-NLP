# Embedding 模型微调系统 · 系统设计文档

> **工单编号：人工智能 NLP-RAG-Embedding 模型微调任务**
> 项目：RAG 项目 ｜ 任务：在金融年报语料上微调 Embedding 模型，弥补「语义鸿沟」
> 基座模型：`BAAI/bge-small-zh-v1.5`（512 维）｜ 语料：`ccf_competition` 9 份上市公司年度报告
> 前置工单：01 基于 PDF 的问答 → 02 优化 → 03 表格解析 → 04 图像解析 → 05 Query 理解 → 06 混合检索 → 07 功能测试及评估

---

## 一、设计背景与目标

通用嵌入模型（如 BGE 系列）在大规模网络语料上预训练，为语义理解提供了良好起点；但面对
**金融领域的专业术语、独特实体与特定语义关联**时，其性能会下降——即所谓「语义鸿沟」：

| 现象 | 在本语料中的表现 |
|---|---|
| 误解查询 | 「不良率」与「不良贷款率」、ROE 与「净资产收益率」在通用空间中距离偏远 |
| 遗漏相关文档 | 数值指标（如「拨备覆盖率 389.45」）散落在表格块中，通用模型难以对齐查询 |
| 检索不相关文档 | 9 家公司同口径指标（如「营业收入」）高度相似，容易**跨文档串味** |

本工单的目标：**通过领域微调（Domain Fine-tuning）调整嵌入空间**，使「查询」与其在专业语料中的
「相关段落」映射得更近，并用可复核的检索指标量化「微调前 vs 微调后」的差异。

**验收标准**：微调后的 Embedding 模型检索效果优于微调前，且**有数据指标支撑**。

## 二、工单实现步骤映射

工单要求实现 8 个步骤，本系统的模块映射如下：

| 工单实现步骤 | 承载模块 | 说明 |
|---|---|---|
| 1. 数据集生成 | `src/dataset_builder.py` | 从语料挖掘「指标 × 公司」锚点，生成四类数据 |
| 2. 运行问答对生成 | `src/dataset_builder.py::generate_pairs` | 生成 (问题, 相关段落) 正例对 810 条 |
| 3. 数据集与模型加载 | `src/dataset_loader.py` + `src/embedding_model.py` | JSONL → `InputExample`；加载 BGE 基座 |
| 4. 定义损失函数 | `src/losses.py::build_loss` | MNRL / Triplet / Contrastive / Cosine / Matryoshka |
| 5. 定义训练参数 | `src/train_config.py::TrainConfig` | 超参收敛为 dataclass → `SentenceTransformerTrainingArguments` |
| 6. 创建评估器 | `src/evaluator.py::RetrievalEvaluator` | Recall@K / MRR / NDCG / 实体准确率 / 块级召回 |
| 7. 微调前评估模型 | `src/trainer.py`（`before` 分支） | 基座模型在留出评估集上的指标 |
| 8. 微调后评估模型 | `src/trainer.py`（`after` 分支） | 微调模型同口径指标 + 对比 |

## 四、数据设计

### 4.1 语料与切片

- **语料**：附件提供的官方解析结果 `txt/*.txt`（JSONL，每行一个 row，含 `page/type/inside`），
  复用可避免对 9 份超大 PDF 重复解析，并与工单「数据集生成」的数据口径一致。
- **噪声过滤**：剔除 `页眉/页脚`（版式噪声，无语义）。
- **结构感知切片**（`chunking.py`）：
  - **正文块（text）**：同页连续正文按 `CHUNK_SIZE=500` 聚合、`CHUNK_OVERLAP=80` 重叠；
  - **表格块（table）**：连续 excel 行聚合成一张表（≤12 行），行内以 ` | ` 分隔单元格，
    保留「指标名 + 数值」的对应关系。
- **切片规模**：**7476 块**（正文 + 表格），每块携带
  `chunk_id / doc / company / year / sector / page / type / text`。

### 4.2 四类数据集的生成

以 `METRIC_LEXICON`（20 个金融指标 × 同义表述）为语义锚点，构建 `(股票代码, 指标) → 命中块`
索引，覆盖 **135 个指标单元**，生成四类数据：

| 数据集 | 规模 | 格式 | 生成逻辑 | 对应损失 |
|---|---|---|---|---|
| 正例对 `pairs` | **810** | (query, positive) | 每个指标单元 × 6 类问法模板 | MNRL / Matryoshka |
| 三元组 `triplets` | **1215** | (anchor, positive, negative) | 负例取**同指标、同行业、异公司**段落（硬负例） | TripletLoss |
| 相似度对 `sim_pairs` | **945** | (s1, s2, score) | paraphrase=1.0 / 同指标异公司=0.4 / 无关=0.0 | CosineSim / Contrastive |
| 评估集 `eval` | **330** | question + relevant_ids | 留出问法（exact 270 + colloquial 60） | — |

**正例块优选**（`_rank_positive`）：在同指标命中块中挑「信息量最大」的一块——偏好表格块、
含数值块、指标词与数字邻近（±40 字）的块；**惩罚注释/释义块**（这类块虽多次出现指标词，
但只是定义说明，作正例会误导模型）。

### 4.3 防泄漏与可复核设计

这是本系统数据设计的关键：

1. **模板不相交**：训练查询模板（6 类）与评估查询模板（4 类）**严格不相交**，评估集不会
   因为「背过模板」而虚高。
2. **语料侧标注**：评估集的 `relevant_ids` 由**语料侧**（指标词命中）标注，
   **不取自检索器输出**，避免「用检索结果自证检索结果」。
3. **实体绑定**：评估集每条都绑定目标公司 `code`，据此计算**实体准确率@1**（Top-1 命中块
   是否属于目标公司），专门度量「跨文档串味」。
4. **口语化子集**：60 条口语/同义改写查询（如「营收」「归母净利润」「ROE」），考察泛化。

## 五、模型与训练设计

### 5.1 基座模型选择

| 项 | 值 | 说明 |
|---|---|---|
| 基座模型 | `BAAI/bge-small-zh-v1.5` | BGE 家族中文模型，工单指定 BGE 系列 |
| 向量维度 | 512 | 小模型，**适配 CPU 训练**（工单环境无 GPU） |
| 参数量 | 23,953,920 | 训练/推理成本可控 |
| 训练截断长度 | 128 | 训练用 |
| 评估截断长度 | 256 | 评估用（覆盖更长的表格块） |

> 工单正文以 `bge-base-en-v1.5` 举例说明 BGE 的高性能与低资源适配性。本任务语料为**中文
> 年报**，故选择同家族的中文小模型 `bge-small-zh-v1.5`：既满足「BGE + 低资源」的选型意图，
> 又能在无 GPU 环境下完成真实训练。

### 5.2 损失函数设计

`losses.py` 统一工厂 `build_loss(model, kind)`，覆盖工单列举的全部四类损失：

| 损失 | 数据格式 | 本系统实现要点 |
|---|---|---|
| **MNRL**（MultipleNegativesRankingLoss） | (anchor, positive) | **默认**。批内把其他样本的正例当负例，等价于大量难负例；`scale=20` |
| **TripletLoss** | (anchor, positive, negative) | `margin=0.3`；负例为跨公司硬负例 |
| **ContrastiveLoss** | (text_a, text_b, label) | `margin=0.5` |
| **CosineSimilarityLoss** | (text_a, text_b, score) | 引导余弦相似度与标注分数一致 |
| **MatryoshkaLoss** | (anchor, positive) + 多维度约束 | 包裹 MNRL，分层维度 `[512,256,128,64]`，权重 `1/2^i` |

### 5.3 训练参数设计

`TrainConfig`（dataclass，可序列化）→ `SentenceTransformerTrainingArguments`：

| 参数 | 值 | 说明 |
|---|---|---|
| epochs | 4 | |
| batch_size | 16 | 对比学习：批内负例数 = batch−1 |
| learning_rate | 2e-5 | |
| warmup | 0.1（v5 下以 `warmup_steps` 浮点表达） | 见《实现步骤与问题记录》问题 4 |
| weight_decay | 0.01 | |
| optimizer | adamw_torch | |
| scheduler | cosine | Transformers v5 的 `SchedulerType` 名称 |
| fp16 / bf16 | False | CPU 训练关闭半精度 |
| seed | 42 | 可复现 |
| dataloader_num_workers | 0 | Windows / CPU 下最稳 |

**复现性**：固定随机种子 + 确定性数据生成，保证「同参数同结果」，报告可复核。

## 六、评估设计

### 6.1 评估口径（问题级，越接近 1 越好）

| 指标 | 定义 | 度量目标 |
|---|---|---|
| Recall@K | Top-K 命中至少一个相关块的查询占比（K=1/3/5/10） | 检索**召回**能力 |
| MRR@10 | 首个相关块排名倒数的均值 | **首命中位置** |
| NDCG@10 | 二值相关性的归一化折损累计增益 | **排序质量** |
| 实体准确率@1 | Top-1 命中块属于「目标公司」的比例 | **实体区分/抗串味** |
| 块级召回@10 | \|相关块 ∩ Top-K\| / \|相关块\| 的均值 | **信息覆盖度** |

### 6.2 对比流程

> 流程图见 `设计/流程图/04_评估与对比流程图.png`

同一份留出评估集、同一份语料向量库，**双模型并列评估**：

```
基座模型 ─┐
          ├─→ 编码语料(7476块) + 编码留出查询(330条)
微调模型 ─┘        ↓
              余弦相似度排序 → Top-K 命中
                      ↓
          Recall@K / MRR / NDCG / 实体准确率 / 块级召回
                      ↓
              指标对比 (after − before) → 图表 + 报告 + 验收判定
```

**缓存策略**：语料向量按模型分别缓存为 `.npy`（`emb_base.npy` / `emb_finetuned.npy`），
避免重复编码，使「重跑评估」接近瞬时。

### 6.3 微调前后核心指标（真实运行结果）

| 指标 | 微调前（基座） | 微调后（领域） | 变化 |
|---|---|---|---|
| Recall@1 | 0.3303 | **0.4788** | ↑ +0.1485 |
| Recall@3 | 0.4758 | **0.6515** | ↑ +0.1758 |
| Recall@5 | 0.5424 | **0.7576** | ↑ +0.2152 |
| Recall@10 | 0.6091 | **0.8576** | ↑ +0.2485 |
| MRR@10 | 0.4207 | **0.5904** | ↑ +0.1697 |
| NDCG@10 | 0.4434 | **0.6187** | ↑ +0.1753 |
| 块级召回@10 | 0.0905 | **0.2065** | ↑ +0.1160 |
| 实体准确率@1 | 0.8121 | 0.7848 | ↓ −0.0273 |

> 数据来源：`evaluate.py` 实跑（`output/评估报告.md`）。
> 结论：检索核心指标全面显著提升，满足验收标准；实体准确率@1 轻微下降（exact 子集），
> 已在《优化报告》中通过 **TripletLoss 补充实验**做针对性分析与改进。

## 九、设计取舍与约束

| 取舍 | 决策 | 理由 |
|---|---|---|
| 模型规模 | 选 small（512 维） | 环境无 GPU，small 可在 CPU 上完成真实训练 |
| 语料来源 | 复用官方解析 JSONL | 避免重复解析 9 份超大 PDF，口径一致 |
| 负例构造 | 同指标同行业异公司 | 直击本任务最痛的问题——跨文档串味 |
| 评估独立性 | 语料侧标注相关块 | 避免「用检索结果自证检索结果」 |
| 损失函数 | MNRL 为主 + Triplet 补充 | MNRL 适合检索式嵌入；Triplet 强化实体区分 |
| 兼容性 | `_compat.py` 垫片 + 版本回退导入 | 适配 CPU-only torch 与 ST v6 的模块变更 |
