# 08 — 安全与合规

> 原则：系统只提供**心理陪伴、心理教育、自助技巧和就医建议**，不能诊断、不能开药、不能替代线下医生（需求文档 §0/§9.2/§14）。

---

## 1. 医疗边界（最高优先级）

| 禁止行为 | 实现机制 |
| :--- | :--- |
| 不做医学诊断 | 三角色 system prompt 安全边界第 1 条；`post_process` 正则兜底：将"作为心理医生我可以为你诊断/开药"替换为"我不能进行诊断或开药" |
| 不开药、不推荐药物 | 同上；知识库仅收录科普/自助类资料 |
| 不替代线下就医 | 提示词明确声明；FAQ 与免责声明（`GET /`）告知 |
| 不输出违法/暴力/歧视/色情 | 提示词安全边界第 3 条；敏感词脱敏 |

## 2. 危机干预（crisis_service）

1. **检测**：`detect_crisis()` 对用户输入做危机词匹配——自杀、自尽、自残、自伤、不想活、结束生命、伤害自己、割腕、跳楼、轻生、想死、杀人、报复社会等 30+ 关键词，外加弱风险正则（"活着没意思""撑不下去"等）；
2. **注入**：命中后向 system prompt 追加【危机干预优先指令】：先稳定情绪、明确建议联系热线与陪伴、不做诊断判断（见 docs/05-prompts.md §4）；
3. **兜底**：`post_process(ensure_crisis_notice)` 检查回复中若没有热线（`CRISIS_HOTLINE`/120/110），自动追加转介文案；
4. **转介渠道**：心理援助热线 **12356**、急救 **120**、报警 **110**、当地精神卫生中心急诊（号码可由 `.env` 的 `CRISIS_HOTLINE`/`EMERGENCY_PHONE` 配置）；
5. 危机词表与转介逻辑属**不可弱化资产**，修改需评审（见 CLAUDE.md §0.5）。

## 3. 认证与账号安全

| 措施 | 实现 |
| :--- | :--- |
| 密码存储 | bcrypt（`BCRYPT_ROUNDS=12`），不存明文，自带盐 |
| 鉴权 | JWT HS256（`PyJWT`），access 1440 分钟 + refresh 10080 分钟；签名密钥 `JWT_SECRET_KEY` 生产必须 ≥32 字符随机 |
| 密码校验 | `verify_password` 对非法 hash 返回 False 不抛异常；错误密码计 401 并写审计 |
| 账号禁用 | `users.status=0` 登录被拒（U-05，管理员操作） |
| 权限分级 | `sys_roles` + `user_sys_roles`：普通用户 / 管理员；管理接口经 `get_current_admin` 校验 |
| 修改密码 | 需验证旧密码 |

## 4. 应用层防护

| 风险 | 防护 |
| :--- | :--- |
| SQL 注入 | 全部经 SQLAlchemy ORM 参数化查询，无字符串拼 SQL |
| 越权访问 | 会话/消息接口强制 `user_id` 归属校验（他人会话 403） |
| XSS | 响应为 JSON（API 服务），不渲染 HTML；前端按白名单渲染富文本 |
| 限流 | 聊天接口按用户限流 `RATE_LIMIT_PER_MINUTE`（默认 30/分钟，Redis 计数，EXPIRE 60s）；Redis 不可用放行（可用性优先） |
| 并发覆盖 | 会话写操作使用 Redis 并发锁（`lock:conversation:{id}`，NX EX 30） |
| 上传安全 | 知识库上传仅允许 pdf/txt/md/docx 扩展名；文件落 `data/uploads/` 带时间戳前缀 |
| 参数校验 | Pydantic 长度/格式校验（用户名 3~64、密码 6~128、消息 ≤4000 字符等） |

## 5. 数据保护与隐私

1. **传输**：生产环境必须在 API 前置 HTTPS 反向代理（Nginx/Caddy），终端到服务端全链路加密；
2. **脱敏**：回复后处理对敏感词（毒品、赌博、色情、枪支等）做星号脱敏；
3. **日志红线**：禁止打印密钥、密码、token、完整对话内容；检索日志只记条数/耗时/改写前后 query（不含原文）；
4. **审计**：注册/登录/登出/改密/用户禁用等敏感操作写 `audit_logs`（含 IP）；登录写 `login_logs`（IP、User-Agent）；
5. **隔离**：多用户数据严格按 `user_id` 隔离；会话、短期记忆（Redis Key 含 user_id）、长期记忆（Milvus 按 user_id+persona_id）均不可跨用户访问；
6. **删除**：会话逻辑删除；知识库文档删除同步清理 Milvus 向量与 MySQL 元数据；
7. **密钥管理**：全部敏感配置走 `.env`（不入库不入代码）；`.env.example` 仅含占位符。

## 6. 模型安全与幻觉控制

| 风险 | 措施 |
| :--- | :--- |
| 幻觉 | RAG 限定知识片段 + 提示词"不要编造"；回复返回 `references` 溯源；无命中时注入"不得编造专业结论"提示 |
| 角色越界 | 每角色独立 system prompt + 统一安全边界；`model_params` 按角色固化 temperature |
| 后处理遗漏 | 危机转介、敏感词、诊断正则三重兜底，不依赖大模型自觉 |
| 外部依赖故障 | LLM 失败返回 502 且不中断服务；Redis/Milvus 降级策略见 docs/06-deployment.md |

## 7. 合规声明（需随产品展示）

1. 系统页面/接口文档显著位置展示免责声明（`GET /` 已内置）：不诊断、不开药、不替代就医、不提供急救调度；
2. 危机场景优先转介人工渠道（12356/120/110）；
3. 用户应知晓：对话仅供个人参考，不作为医疗决策依据；症状持续或加重请线下就诊；
4. 对话数据的保存期限、导出与彻底删除策略上线前需按所在辖区隐私法规（如个人信息保护法）补充用户协议。
