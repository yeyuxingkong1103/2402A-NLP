## 一、HTTP API（RAGFlow 集成）

端点挂在 RAGFlow 的 API Server 上，随容器一起跑。

### 1.1 触发质检

```
POST /v1/document/quality-inspection
```

**请求头**

| 头 | 值 |
|---|---|
| `Authorization` | `Bearer <API_KEY>` |
| `Content-Type` | `application/json` |

> 取 API Key：`POST /v1/api/new_token`，或浏览器里 RAGFlow 的「API」页。
> `@login_required` 同时接受登录 JWT 和 API Key（见 `api/apps/__init__.py:128-131`）。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | string | ✅ | **容器内**可见的目录或文件路径。宿主机路径要先挂载进容器 |
| `limit` | int | | 只处理前 N 份，试跑用 |
| `refresh` | bool | | 丢弃解析缓存重新解析（改了抽取类配置才需要） |
| `out` | string | | 报告落盘目录，默认 `/ragflow/quality_report` |

```bash
curl -X POST http://localhost/v1/document/quality-inspection \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"path": "/ragflow/data/docs", "limit": 100}'
```

**响应**：完整的结构化 JSON 报告（结构见第三节）。

**错误**

| 情况 | 响应 |
|---|---|
| `path` 为空 | `{"code": 102, "message": "`path` 不能为空"}` |
| 路径不存在 | `{"code": 102, "message": "路径不存在：…（注意这是容器内的路径…）"}` |
| 质检脚本非 0 退出 | HTTP 500，`message` 里带 stderr 末尾 2000 字 |
| 超时（默认 1800s） | HTTP 500，提示加大 `QUALITY_TIMEOUT` 或加 `--limit` |

### 1.2 取 HTML 简报

```
GET /v1/document/quality-inspection/report?out=<报告目录>
```

返回 `text/html`，浏览器直接打开就能看。**上一次质检的产出**（不重新跑）。

> 为什么分成两个端点：一个 HTTP 响应不能既是 JSON 又是 HTML。
> JSON 给程序（工作流读路由），HTML 给人（扫一眼那几张待办列表）。

### 1.3 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `QUALITY_SKILL_DIR` | `/ragflow/document_quality_assessment` | Skill 在容器里的落点 |
| `QUALITY_PYTHON` | `/ragflow/.venv/bin/python` | 必须用容器自带的 venv |
| `QUALITY_OUT_DIR` | `/ragflow/quality_report` | 默认产出目录 |
| `QUALITY_TIMEOUT` | `1800` | 单次质检超时（秒） |

## 二、命令行接口

Skill 也能完全独立运行（**验收标准要求「该 Skill 能独立运行并返回正确的结构化报告」**）。

```bash
python scripts/assess.py <目录或文件> [选项]
```

| 选项 | 说明 |
|---|---|
| `-c, --config` | 配置文件，默认 Skill 自带的 `assessment_config.yaml` |
| `-o, --out` | 报告输出目录，默认 `quality_report` |
| `--workdir` | 解析缓存目录（断点续跑用），默认取配置 `output.workdir` |
| `--limit N` | 只处理前 N 个文件（试跑） |
| `--refresh` | 丢弃解析缓存重新解析 |
| `--json-only` | 只出 JSON，不出 HTML |
| `--quiet` | 不打印解析进度 |

**退出码**：`0` 成功；`2` 参数/路径错误；`130` 被 Ctrl+C 中断（缓存已落盘，可续跑）。

**产出**：`quality_report.json` + `quality_report.html`。

## 三、JSON 报告结构

```jsonc
{
  "report_version": "1.0",
  "skill": "DocumentQualityAssessmentSkill",

  // ── 概要：一眼看全貌 ──
  "summary": {
    "root": "D:\\...\\documents",
    "total_files": 1700,
    "total_bytes": 725821440,
    "parse_failed": 0,
    "ext": {".pdf": 1700},                    // 格式分布
    "pdf": {"scanned": 622, "text": 1078},     // PDF 分流
    "pdf_scanned_ratio": 0.3659,
    "chars": {"total": 5906520, "mean": 3474.4, "P25": ..., "P50": 4124,
              "P75": ..., "P90": 6835, "P99": ...},
    "exact_dup_groups": 0,                     // MD5 完全重复组数
    "redundant_copies": 0,
    "similar_pairs": 18,                       // 待确认版本冲突对数（null=跳过）
    "simhash_compared": 1078,                  // 实际参与比较的份数
    "simhash_skipped_thin": 622,               // 因正文过短未参与的份数
    "sensitive_hits": 0,
    "uncertain_pdf": 0,
    "unreadable_pdf": 0,
    "by_tag": {"Text_PDF": 1078, "Scan_PDF": 622},
    "by_route": {"text": 1078, "ocr": 622},    // 所有标签的路由（统计用）
    "by_primary_route": {"text": 1078, "ocr": 622},  // 主路由（工作流读这个）
    "elapsed_sec": 51.6,
    "reused_from_cache": 0
  },

  // ── 明细：各列表 ──
  "details": {
    "format": {"total": 1700, "by_ext": {...}, "ratio": {...}},
    "pdf": {
      "counts": {...}, "ratios": {...}, "total": 1700,
      "unreadable": ["<路径>", ...],
      "uncertain": [["<路径>", "mixed", "0.43", "扫描页占比 43% 落在 30%~70% 之间"]]
    },
    "length": {"count": 1078, "failed_count": 622, "percentiles": {...},
               "distribution": [{"range": "0~500", "count": 622, "ratio": 0.366}]},
    "dup": {
      "md5_groups": [["<md5前8位>", 2, "<路径1> ｜ <路径2>"]],       // 完全重复
      "sim_pairs": [["<路径A>", "<路径B>", "95%", 3]],                // 待确认版本冲突
      "note": ""                                                      // 跳过原因（若有）
    },
    "sensitive": {
      "summary": {"total_hits": 0, "by_type": {...}, "top_files": [...]},
      "hits": [["<路径>", "email", "<命中内容>", "<前后40字上下文>"]]
    },
    "tags": {
      "by_tag": {...}, "by_route": {...}, "by_primary": {...},
      "tag_routes": {"Scan_PDF": ["ocr"]},
      "docs": [["<路径>", "Scan_PDF", "ocr"]]      // ← 第三项是主路由
    },
    "errors": [["<路径>", "<错误原因>"]]
  }
}
```

### 工作流只需要读一个字段

```jsonc
details.tags.docs[i][2]     // 主路由："ocr" / "text" / "hybrid" / "table" / "review" / "chunk_aggressive"
```

**主路由 = 每份文档第一条标签的去向**（规则按「最确定 → 最兜底」排序），
一份文档只有一个主路由，工作流按它挑解析器；
其余标签当参数用（比如 `Long_Document` 提示切块要更碎）。

> ⚠️ **不要用 `by_route` 定路由**。它把一份文档的所有标签都算了一遍
> （一份文档可能算几次），是统计值。
> 这个坑有单元测试守着：`test_主路由汇总每份只算一次`。

## 四、工作流接口

工作流 `document_ingestion_workflow`（DSL 见 `研发/workflows/document_ingestion_workflow.json`）。

```
POST /api/v1/agents/webhook/<agent_id>      # RAGFlow 的 Webhook 触发端点
```

**请求体**（字段与 `Begin` 组件的 `inputs` 对应）

| 字段 | 必填 | 说明 |
|---|---|---|
| `route` | ✅ | 主路由，取自报告 `details.tags.docs[i][2]` |
| `path` | | 文档路径，仅用于回显 |
| `tags` | | 标签串，仅用于回显 |

```bash
curl -X POST "http://localhost/api/v1/agents/webhook/$AGENT_ID" \
  -H "Content-Type: application/json" \
  -d '{"route": "ocr", "path": "/data/CN100408987C.pdf", "tags": "Scan_PDF"}'
```

**路由表**

| `route` | 分支 | 下游动作 |
|---|---|---|
| `ocr` | `Message:ToOCR` | 送 OCR 解析器（RAGFlow 的 DeepDOC 自带 OCR） |
| `text` | `Message:ToText` | 走 plain_text 直接抽文字，不 OCR（省时间） |
| `hybrid` | `Message:ToHybrid` | 按页决定解析方式 |
| 其他/为空 | `Message:ToReview`（ELSE 分支） | 不自动入库，转人工 |

**创建方式**（不改 RAGFlow 代码）：

```bash
curl -X POST http://localhost/v1/canvas/set \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"title\":\"document_ingestion_workflow\",
       \"canvas_category\":\"agent_canvas\",
       \"dsl\": $(cat 研发/workflows/document_ingestion_workflow.json | python -c 'import json,sys; print(json.dumps(json.load(sys.stdin)["dsl"]))')}"
```

> `canvas_category` **必须是 `agent_canvas`**。
> 用 `dataflow_canvas` 的话会走 `Pipeline` 执行器，而它
> （`rag/flow/pipeline.py:143-164`）只按下游线性推进，**不支持条件分支**，
> 而且 webhook 明确拒绝 DataFlow（`api/apps/sdk/agents.py:156-157`）。

## 五、Python 库接口

API 端点内部就是调这个函数，也可以直接 import 用：

```python
import sys
sys.path.insert(0, "研发/document_quality_assessment/scripts")
import assess, common

cfg = common.load_config()                      # 读 assessment_config.yaml
rep = assess.assess(
    root="D:/docs",                             # 目录或单个文件
    cfg=cfg,
    workdir=".quality_work",                    # 解析缓存（断点续跑）
    limit=0,                                    # 0 = 全量
    refresh=False,                              # True = 丢弃缓存重解析
    progress=False,                             # 是否打印进度
)
print(rep["summary"]["by_primary_route"])       # {'ocr': 622, 'text': 1078}
```

返回的就是第三节那个 dict。**不落盘**，要落盘用 `assess.write_reports()`。

### 只想拿汇总、不重新解析

解析缓存落盘后，重出报告不需要再读文件：

```python
import summarize, json
records = [json.loads(l) for l in open(".quality_work/parsed.jsonl", encoding="utf-8")]
rep = summarize.build_report("D:/docs", records, cfg)   # 纯内存计算，几秒
```

**这是「调阈值几秒出结果」的实现基础** —— 缓存里存的是**事实**
（字符数、每页字符数、图片覆盖率、SimHash、敏感信息命中），
判定是每次出报告现算的。

## 六、配置文件

见 `研发/document_quality_assessment/assessment_config.yaml`（7 大类，165 行）。
**所有核心判断阈值都在这里，代码里不写死**（验收标准要求）。

改动分两类：

| 类型 | 例子 | 生效方式 |
|---|---|---|
| **判定类** | `pdf_type` 阈值、`length` 区间、`dedup.simhash_distance`、`tags.rules` | 直接重跑，**几秒出结果** |
| **抽取类** | `sensitive` 正则、`dedup.simhash_sample_chars`、`simhash_shingle` | 要加 `--refresh` 重新解析 |

配置里每个阈值旁边都写了**为什么取这个值**（实测依据），改之前值得读一眼。
