## 四、问题分析

### 1. 跨文档问题（ID:4）表现较差

- 问题要求"分析这些银行和保险公司" → 需要多个文档
- 检索只命中 1-2 个文档，未覆盖全部 9 个
- **原因**：单一 Query 的检索能力有限
- **改进**：拆分子问题，分别检索

### 2. 定性问题（ID:2）答案不完整

- "创新商业模式"是开放性问题
- Mock 模式只能拼接原文，不能总结
- **改进**：接入 LLM API 做总结

### 3. 数值问题（ID:5/6/7/8/10）表现最好

- 表格块按行拆分的优化生效
- 精确命中"营业收入 1,379亿"、"净利润 1,494亿"

### 4. 定性 + 数值混合问题（ID:1/3/9）中等

- 命中相关段落，但数字偶有截断

## 五、改进建议

1. **跨文档问题**：拆分子问题分别检索
2. **定性问题**：接入 LLM 做总结
3. **数值问题**：保持现有表格按行拆分策略
4. **长文档**：增加 chunk overlap，避免信息截断

## 六、结论

1. **命中率 100%**：所有问题都命中了正确文档
2. **响应时间 0.23s**：远小于 3s 要求
3. **数值问题表现优秀**：表格按行拆分策略生效
4. **跨文档 / 定性问题**：是当前瓶颈
5. **整体可用**：RAG 系统在年报问答场景下效果良好
