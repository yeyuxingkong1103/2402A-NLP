## 三、过程问题记录（真实遇到并解决）

### 问题 1：`ModuleNotFoundError: No module named 'torch'`

- **现象**：首次运行 `run_pipeline.py` 直接报错，缺少 PyTorch。
- **原因**：环境未预装深度学习依赖。
- **解决**：使用国内镜像安装 CPU 版依赖：

  ```powershell
  python -m pip install "torch>=2.2,<2.7" transformers sentence-transformers datasets accelerate `
    scikit-learn -i https://pypi.tuna.tsinghua.edu.cn/simple
  ```

- **结果**：torch 2.6.0+cpu / transformers 5.19.0 / sentence-transformers 6.1.0 安装成功。

---

### 问题 2：`RuntimeError: Cannot access accelerator device when none is available`

- **现象**：导入 `transformers` 即崩溃，堆栈指向
  `transformers/utils/import_utils.py → torch.accelerator.current_accelerator()`。
- **原因**：本机**无 GPU**，而 `torch.accelerator.current_accelerator()` 在 CPU-only 构建下会抛错；
  新版 transformers 在导入期调用了它。
- **解决**：新增兼容垫片 `src/_compat.py`，在任何 transformers 导入**之前**修补：

  ```python
  acc = getattr(torch, "accelerator", None)
  if acc is not None and hasattr(acc, "current_accelerator"):
      try:
          acc.current_accelerator()          # 正常环境不抛错则无需垫片
      except Exception:
          acc.current_accelerator = lambda *a, **k: None   # CPU-only：返回 None
  ```

  并在 `src/__init__.py` 首行调用 `_compat.apply()`，保证**先于** transformers 生效。
- **结果**：导入正常，CPU 训练/推理全程可用。

---

### 问题 3：`ModuleNotFoundError: Could not import module 'PreTrainedModel'`

- **现象**：`import sentence_transformers` 失败，表层报找不到 `PreTrainedModel`。
- **原因**：**问题 2 的次生现象**——transformers 导入期崩溃，导致 `PreTrainedModel` 未能注册。
- **解决**：同问题 2，垫片生效后即消失（关键在于垫片必须**先于** transformers 执行）。
- **经验**：脚本一律 `import src`（触发垫片）后再导入 transformers 系模块。

---

### 问题 4：`ValueError: warmupcosine is not a valid SchedulerType`

- **现象**：构造训练参数时报错，列出合法值
  `['linear','cosine','cosine_with_restarts','polynomial','constant',…]`。
- **原因**：本机为 **Transformers v5**，学习率调度器枚举名变更，`warmupcosine` 不再合法；
  同时 `warmup_ratio` 在 v5 中被弃用，建议改用 `warmup_steps`（浮点比例）。
- **解决**：`TrainConfig.scheduler` 改为 `cosine`；`to_arguments()` 用
  `warmup_steps=<浮点比例>` 构造，并对旧版本做回退：

  ```python
  try:
      return SentenceTransformerTrainingArguments(warmup_steps=self.warmup_ratio, **base)
  except (TypeError, ValueError):
      return SentenceTransformerTrainingArguments(warmup_ratio=self.warmup_ratio, **base)
  ```

- **结果**：训练参数构造成功，训练正常启动。

---

### 问题 5：`Importing from 'sentence_transformers.losses' is deprecated`

- **现象**：大量 `DeprecationWarning`，且未来版本可能移除旧路径。
- **原因**：sentence-transformers v6 将模块迁至 `sentence_transformers.sentence_transformer.*`。
- **解决**：`losses.py` / `train_config.py` 采用「新路径优先、旧路径回退」的导入：

  ```python
  try:      # ST >= 6
      from sentence_transformers.sentence_transformer.losses import (...)
  except Exception:   # 旧版本
      from sentence_transformers.losses import (...)
  ```

- **结果**：警告消除，跨版本可用。

---

### 问题 6：生成的正例块质量不佳（把「注释/释义」当正例）

- **现象**：抽检 `train_pairs.jsonl` 发现部分 `positive` 是「注：……」「释义：……」类文本，
  虽多次出现指标词，但**不含真实数据**，会误导模型。
- **原因**：早期正例选取仅按「指标词命中次数」，未区分「数据陈述」与「定义说明」。
- **解决**：重写 `_rank_positive` 打分函数——引入
  **指标词与数字邻近性（±40 字）检测**、**表格块加成**、**注释块惩罚**、
  **注释密度惩罚**、长度惩罚：

  ```python
  s = (2.0 if near_num else 0.0) + (1.0 if has_num else 0.0) + table_bonus
  s += min(hits, 3) * 0.4 + length_pen
  if footnote:      s -= 2.0
  s -= min(note_density * 400, 1.5)
  ```

- **结果**：正例块改为「含指标 + 邻近数值」的真实数据块（多为表格块），数据集质量显著提升。

---

### 问题 7：实体准确率@1 轻微下降（0.8121 → 0.7848）

- **现象**：检索核心指标大幅提升，但**实体准确率@1** 在 exact 子集上略降。
- **原因**：MNRL 用批内负例，负例多为随机其他样本，对「同指标异公司」这一最难区分场景
  的针对性不足。
- **解决**：新增补充实验 `tools/run_loss_experiment.py`，用 **TripletLoss** 复跑微调——
  其三元组负例为「同指标、同行业、异公司」的跨文档硬负例，专门强化实体区分。
- **结果**：Triplet 确实把**实体准确率@1 提升到 0.9182**（+0.1061），但**Recall@1 崩塌到 0.0939**
  ——因为正负例主题相同、仅公司不同，模型学会了「只看实体、忽略主题」。
  这证明主实验的 **MNRL 选择是正确的**（召回优先），实体准确率的轻微回退属已知、可控的副作用。
  权衡分析与改进方案详见《优化报告》。

---

### 问题 8：Windows PowerShell 下中文输出乱码 / 日志混入报错行

- **现象**：`python … | Tee-Object` 时日志中混入 PowerShell 的
  `NativeCommandError` 包裹行，且中文可能乱码。
- **解决**：运行前设置 `$env:PYTHONIOENCODING="utf-8"`、`$env:PYTHONUNBUFFERED="1"`；
  日志整理时过滤 PowerShell 包裹行。
- **结果**：日志干净、中文正常，可直接渲染为终端截图。
