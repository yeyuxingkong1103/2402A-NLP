## 0. 架构目标与设计原则

| 原则 | 落地方式 |
| --- | --- |
| 多 PDF 通用 | `data/raw/*.pdf` 自动发现；检索支持 `file_names` **硬过滤**；代码内零文件名常量（§3） |
| 表格一等公民 | 表格整块成块、`type=table`、Markdown 化、表格/数字加权（§6、§8） |
| 页码口径唯一 | 全链路 1-based 物理页，禁止任何换算（§4） |
| 在线快、离线重 | 在线热路径只走 Ollama HTTP；重库一律惰性导入（§5） |
| 可观测 | 每个函数入口/出口/异常都有结构化日志；`trace_id` 串联全链路（§11） |
| 无静默失败 | `except` 必须 log + 传播或显式降级；禁用 `except: pass`（§12） |
| 无编造 | 无依据回「不清楚」；RAGAS 未运行如实标注（§9.4、§17） |
| 只读合规 | 复用 `工单1/2` 一律只读 + `sys.dont_write_bytecode = True`（§11.5） |

| 规则 | 说明 |
| --- | --- |
| 发现 | `config.discover_pdfs(raw_dir)` 用 `Path(raw_dir).glob("*.pdf")`（大小写不敏感兜底：`*.PDF`），按文件名排序后返回 `PdfSource` 列表 |
| 零硬编码 | 代码中**不得**出现 `"招股说明书1.pdf"` / `"招股说明书2.pdf"` 字面量；如需示例，只允许出现在 `测试/测试数据/*`、Markdown 文档或注释中。T8 加静态检查断言：`研发/app/**` 与 `研发/scripts/**` 命中数为 0 |

| 过滤 | `HybridRetriever.retrieve(..., file_names=[...])` 在**候选生成阶段**做硬过滤（向量/BM25 结果先按 `file_name ∈ file_names` 裁剪，再做 RRF）；**禁止**只靠打分抑制（那会漏召回并让「选 2 号却返回 1 号块」通过） |

## 4. 【硬约束 1】页码口径：唯一、1-based、物理页

**三套编号的真实关系（实测；两套数值相同才是混用根源）**：

| 编号体系 | 物理第 129 页 | 物理第 130 页 | 关系 |
| --- | --- | --- | --- |
| ① **1-based 物理页码（唯一采用）** | 129 | 130 | —— |
| ② 0-based 索引 `d[i]` | `d[128]` | `d[129]` | 物理 − 1 |
| ③ 页脚「印刷页码」 | `1-1-128`（PDF1）/ `'128'`（PDF2 形） | `1-1-129` / `'129'` | 末段数字 = 物理 − 1 = **与 ② 同值** |

| 层 | 字段 | 口径 |
| --- | --- | --- |
| `pdf_parser` | `PageText.page`、`TableBlock.page`、`TextBlock.page` | 1-based 物理页 = `i+1`（`i` 为 `doc[i]` 索引） |
| `chunker` | `Chunk.page` / `page_start` / `page_end` | 表格块 `page = page_start`（引用页 = 真实物理页），`page_end` 覆盖续表末页；文本块 `page_start = page_end = page` |
| `citation` | `Citation.page`、`[文件名: 页码]` | 直接用块内真实物理页，**不做任何 ±1 换算** |
| 回查 | `pdf_parser.get_page_text(pdf, page)` | `doc[page - 1]` |
| 评估 | `evidence_pages` 比对、引用范围校验 | 同口径；`1 ≤ page ≤ doc.page_count` |

**三条禁止 + 一条清洗纪律**：
1. 不得用 0-based 索引充当页码；
2. 不得用页码行（页脚/页眉印刷页码）做引用，**也不得用其数值反推页码**；
3. **不得**写「页码行 = 物理 − 1」的通用假设 —— PDF1 是 `1-1-N` 且位于**页脚**，**PDF2 是裸数字且位于页眉块第 2 行**（实测 `p22→'21'`、`p157→'156'`、`p340→'339'`、`p1→'0'`、`p350→'349'`），必须**分别清洗**；
4. **清洗必须「位置 + 值」双判据**：captain 全量校验 **PDF2 350 页中第 2 行 ≠ 物理页 − 1 的页数 = 0**（T2 独立复现 = 0），该判据可靠，但 PDF2 正文存在大量合法数字行（项目序号等）→ **禁止**无脑删除独立成行的数字；仅当「页眉块第 2 行」**且**「值 == 物理页 − 1」同时成立才删。清洗只改文本，**不改 `page` 字段**。

**铁证（T2 取证 + 环境事实 §3.0/§8.8）**：题 33/260 `evidence_pages=[129]`，p129（`d[128]`）`find_tables()=0` 但正文含「82.10%、97.31%、94.84%和94.34%」，同表在 p130（`d[129]`）7×10、p131（`d[130]`）9×10（续表）；题 543/531 `[22]`，p22（`d[21]`）页码行 `1-1-21`；题 34/793 `[152]`，**152 含完整答案正文且 `tables=0`、引用优先**，**表在 153（辅助）**；题 207 依据 PDF1 **490**（**PDF2 物理 340 是银行借款 300 万美元，严禁混用**，见 `设计/需求分析.md` §4.3）。
**实现防线**：`Chunk`/`TableBlock` 生成处断言 `1 <= page <= page_count`，越界抛 `ChunkError`（不静默钳制）。
**回归锚点**：物理 **129/130/131**（正文页无表 → 表头页 → 续表页）+ **152/153**（答案正文页 / 示意表页）。

## 5. 【硬约束 2】在线热路径 vs 离线冷路径

| 维度 | 在线热路径（`qa_engine.ask`） | 离线冷路径（`build_index.py`） |
| --- | --- | --- |
| 允许导入 | 标准库、`numpy`、`jieba`、`pymupdf`（引用回查）、`fastapi`/`uvicorn`（服务）、`requests/httpx`、`openai`（仅当后端为 openai） | 同左 + `torch`、`transformers`、`sentence_transformers`、`faiss`（可选） |
| 禁止导入 | `torch`、`transformers`、`sentence_transformers`（实测 import 2.54 / 3.51 / 5.08 s，captain 复测） | —— |
| 模型来源 | **Ollama HTTP**（`127.0.0.1:11434`）：嵌入 `bge-m3:latest`(1024)、生成 `qwen2.5:3b` | 同左；不可用时惰性导入本地模型 |
| 计时 | 每题记录 `first_token_ms` / `total_ms`（写 `rag_trace.jsonl`） | 记录每阶段耗时与块数（写 `index_manifest.json`） |
| 预热（**硬要求，不可协商**） | **在线入口启动流程必须调用** `QAEngine.warmup()`，其内部依次调用 **`text_utils.warmup_tokenizer()`**（jieba 冷启动 **import 384 ms + 首次 `cut()` 779 ms ≈ 1.16 s**，T3 实测）→ **`embedder.warmup()`**（Ollama `/api/embed`，冷 76~188 ms）→ **`llm_client.probe_backends()`**（0.5 s 无重试）→ `QAEngine` 内可加一次生成预热。调用点：`app/main.py` 的 `startup` 事件、`serve_fallback.py`/`streamlit_app.py` 首次渲染前。**零调用点 = 实现缺陷**（T3 曾出现该情况，经 captain grep 确认后已要求 T5/T6 落地） | 冷路径不适用（离线可慢） |

**预热效果（实测依据）**：BM25 查询 **冷 1020 ms → 热 1.00 ms**；`jieba` 词表与缓存常驻后，首题不再出现 ~1 s 级尖峰 —— 这是「首字 ≤ 3 s 且**每题**达标」的前提。

**惰性导入实现规则**：

```python

# 在线路径禁止 eager import 重库：仅在降级分支内部 import，并记录降级日志
def _embed_local(texts):                      # 只有 Ollama 不可用时才走到这里
    import sentence_transformers              # noqa: 惰性导入（离线冷路径专用）
    logger.log_event("embedder.degrade", backend="sentence_transformers", reason=...)
```

**首字预算（同 `设计/需求分析.md` §6.1）**：热态合计 ≤ 1 440 ms，留 1.5 s 余量；冷启动实测嵌入 76~188 ms、生成首字 47~107 ms【环境事实 §4】，因此**达标前提是预热**。

## 6. 表格解析流水线

### 6.1 【硬约束 4】逐页扫描（表格密集且跨页是常态）

`page.find_tables()` 必须对**每一页**调用，禁止按固定间隔抽样。全量实测【环境事实 §8.8，T2 独立复现一致】：

| 指标 | 招股说明书1.pdf | 招股说明书2.pdf |
| --- | --- | --- |
| 含表页数 | **312 / 548（56.9%）** | **134 / 350（38.3%）** |
| 连续含表段 / 最长段 | 50 段 / **28 连页（399–426）**（T2 复算 60 段 / 28 连页） | 18 段 / **17 连页（47–63）** |
| 相邻两页都含表的「连续对」 | 252 对 | 99 对 |
| 续表页（首行首格空/`None`） | 45 页（T2 复算 40 页） | 79 页 |
| 重复表头页 | 21 页（T2 复算 20 页） | 10 页 |

> ⚠️ 早期「表格稀疏（前 60 页 34 页无表）」的判断**只对前 60 页成立，已作废**，不得据此设计抽样。
> 段数与续表的绝对计数依赖检测实现口径，**不作验收门槛**；验收只锚定确定性锚点页（129/130/131、153）。

**性能**：实测 0.04~0.23 s/页；T0 全量扫描 548 页 63.95 s + 350 页 19.63 s【环境事实 §8.8】；T2 逐页扫描 PDF1 前 140 页 12.17 s（≈87 ms/页）→ 全量约 80 s，可接受。
**可选优化**：仅 `--fast-table` 时跳过「无绘制线且文本极短」页；默认**不启用**（避免漏表）。

### 6.2 归一化规则（确定性，必须有单测）

| 规则 | 输入示例 | 输出 |
| --- | --- | --- |
| R1 单元格空白归一 | `'有限公司成立日\n期'` | `'有限公司成立日期'`？**否** —— 规则定义为：`\n`→1 个空格，再折叠连续空白 → `'有限公司成立日 期'` 仍不美观；最终**采用：先删行尾连字符、再把 `\n` 替换为空格、再折叠空白**，随后对「同一逻辑单元格内的中文字符分段」做**拼接**（无空格）→ `'有限公司成立日期'`。判据：输出不含 `\n`，且 `'注册资本'`/`'法定代表人'` 等关键键可 `in` 命中 |
| R2 `None` 向前填充 | 表头 `['用户类别', None, '2019 年1-6 月', None, ...]` | 先按「相邻 `None` 合并为一列」得到 5 逻辑列；数据行中 `None` 表示**行内合并**，按最近非空**左侧**值填充（如 `['军种', '军种一', ...]` → 后续 `None` 归到 `军种`） |
| R3 全列皆空 | 整列为 `None`/`''` | 删除该列（避免 Markdown 里出现空列） |
| R4 退化表 | **实测退化例**：PDF2 `招股说明书2#p0259#t00`（物理 259，`degenerate=True`、`logical_cols=1`、`md_len=0`，captain + T3 实测）。<br>⚠️ **v1.8 更正**：旧版此处举例「PDF2 p24 发行费用概算」，实测该表 **`degenerate=False`**、`logical_cols=2`、`md_len=122`（占位符 `[ ◆ ]` 已归一化为「**未披露**」）→ **不是退化表**，文档已更正 | 判定依据 = **归一化后**逻辑列数 < 2 或有效数据行 = 0（**不是**原始物理列数：p259 t00 物理 4 列，归一化后仅 1 逻辑列）→ `degenerate=True`，只保留表标题与 1 行注记，`markdown` 为空串，**不进正文 chunk**（`设计/验收标准.md` §3.2 已认定其为设计选择，非缺陷） |
| R5 Markdown 模板 | —— | 首行为表头；第二行为分隔行（每列写 `---`）；数据行逐行转义：单元格内的竖线字符必须先转义再拼接 |
| R6 数字/单位保真 | `'5,520.00 万元'`、`'25.04%'` | **原样保留**（不做千分位去除、不做单位换算），保证 golden 数值可被包含判定命中 |
| **R7 续表继承（跨页常态）** | 物理 131 首表首行 `['', '军种五', '2,727.20', '55.60%', …]`（表头在物理 130） | 本页首表首行**首格为空/`None`** 且上一页含表 → 判为**同一逻辑表的续表**：继承上页表头，行并入同一逻辑表块；`TableBlock.continued_from` = 上页表 `table_id`、`header_inherited=True`。**禁止**把「军种五」当成列首值独立成块（会丢列含义并污染 BM25 词频） |
| **R8 重复表头去重** | PDF1 21 页 / PDF2 10 页的本页首表首行与上一页首行完全相同（示例 PDF1 57→58、165→166；PDF2 204→205、208→211） | 判为表头重复 → **去重保留一份**（并入前表块），`repeated_headers_removed` 计数 +1；否则同一张表产生多份表头块、BM25 词频虚增 |
| **R9 逻辑表块合并元数据** | 物理 130 + 131 | 合并后的逻辑表块记 `page_start=130`、`page_end=131`（均 1-based），`row_pages[i]` 记录每行所属物理页；**对外引用取真实物理页**：默认 `page = page_start`，若能定位到被问数据行则取该行所在页 |

### 6.3 逻辑表块、表标题与 `table_id`

- `table_id = f"{stem}#p{page_start:04d}#t{idx:02d}"`（例：`招股说明书1#p0130#t00`），全局唯一、可回溯到**起点物理页**。
- **逻辑表块**（R7/R8/R9）：把「表头页 + 未被重复表头的续表页」合并为 **1 个 `TableBlock` / 1 个 chunk**：
  - `page_start` / `page_end`（1-based，闭区间）；
  - `continued_from`（续表时才非空，指向上页 `table_id`）；
  - `header_inherited`（`True` 表示表头继承自上页）；
  - `row_pages[i]`（第 i 行所在物理页，便于按数据行定位引用页）；
  - `page = page_start` 为默认引用页；
  - 合并的页若跨越 3 页以上（28 连页段里可能出现长表）仍**整块不拆**；若 `content > max_table_chars`（4 000 字）才按「重复表头 + 行批次」拆，且每块带同一 `table_id` 后缀 `_part{k}`。
- 表标题 = 表格上方最近一行非空文本中，含「表」「情况」「单位：」等提示词者；跨页表沿用 `page_start` 上方标题；取不到则用 `f"{page_start} 页表格{idx+1}"`（不得留空，避免检索无锚点）。

### 6.4 表格块的 `content` 组成（供检索与生成共用）

```
[表标题] 报告期内兴图新科军品业务最终用户情况（单位：万元）
[来源] 招股说明书1.pdf 第 130–131 页（表头页 130）   ← 单页表则写「第 N 页」
[Markdown]
| 用户类别 | 二级单位 | 2019 年1-6 月 金额 | 2019 年1-6 月 占比 | ... |
| --- | --- | --- | --- | ... |
...
[关键数字] 82.10% 97.31% 94.84% 94.34% 2,727.20 55.60% 6,464.51 14,414.16 18,780.67 4,627.14
```

「关键数字」行由 `text_utils.extract_numbers()` 产出，是**数字类问题**（33/260/543/207/1/2）能被 BM25 与嵌入同时击中的关键设计。

## 8. 检索架构

```
question ─┬─▶ query_understanding.rewrite()  ──▶ normalized_query（含主体，供指代消解）
          │
          ├─▶ embedder.embed_query() ──▶ q_vec(1024)
          │        └─▶ vector_store.search(q_vec, k=VECTOR_K) ──▶ [(chunk_id, cos)]
          │
          └─▶ bm25_index.search(normalized_query, k=BM25_K) ──▶ [(chunk_id, bm25)]
                              │
      ┌───────────────────────┴───────────────────────┐
      │ ① file_names 硬过滤（两路各自裁剪，过滤后不足则降 k 补偿并 WARN） │
      │ ② RRF 融合  score = Σ w_i / (k + rank_i)，k=60，w=(1.0, 1.0)   │
      │ ③ 加权：type=table ×1.25；含数字/百分比/金额 ×1.15；关键词命中 ×1.10 │
      │ ④ reranker.rerank()：确定性启发式（关键词覆盖 + 数值匹配 + 表格 + 段落位置）│
      └───────────────────────┬───────────────────────┘
                              ▼
                 top_k（默认 5）RetrievedChunk 列表（含双路分与加权明细，全部落日志）
```

| 设计点 | 规定 |
| --- | --- |
| 融合 | RRF（不依赖分数量纲）：`1/(k+rank)`；k=60 可配 `RAG_RETRIEVAL__RRF_K` |
| 加权位置 | **只在融合后**乘系数（避免破坏单路排序），权重写日志以便复盘 |
| 过滤位置 | **硬过滤最先执行**（§3） |
| 重排 | 默认确定性、零额外延迟；LLM 重排默认**关闭**（会吃首字预算），如需开启必须实测首字仍 ≤ 3 s |
| 表格召回不足 | 若 top-5 中 `type=table` 数为 0 且问题含数字/占比/金额信号，则**追加**一路「表格块专用检索」（仅表块、BM25 数字 boost）并合并 —— 记录为 `retrieval.table_fallback` 事件 |
| **同页相邻表隔离** | 题 3/题 4 的两张表同在物理 157、仅隔一行标题 → 检索层面**不做人为拆分**（拆了会丢上下文），隔离改由 §9.4 的**主体类型闸门**在答案层完成；同时把两表各自成块（`type=table` 一块一表），保证阈值内的 `chunk_id` 可区分 |
| 留痕 | `RetrievalResult.stages` 记录 `vector_ms/bm25_ms/fusion_ms/rerank_ms`、`candidates_count`、两路原始 top 列表摘要 |

## 9. 生成、引用与「不清楚」

### 9.1 后端优先级与探测

```
resolve_backend():
  RAG_LLM__BACKEND = auto（默认）
    ① ollama   : GET / 或 /api/tags 探测（超时 0.5s、不重试）→ POST /api/generate(stream=true)
    ② openai   : 探测 {OPENAI_BASE_URL}/v1/models（超时 0.5s、不重试）→ /v1/chat/completions
    ③ extractive: 进程内兜底（无 HTTP），从 top-1 证据块抽取原句 + 拼引用
  RAG_LLM__BACKEND = ollama|openai|extractive → 强制指定（探测失败即抛错，不静默换后端）
```

探测失败**必须**写 `llm.probe_failed` 日志（含 target、耗时、异常），并降级到下一后端；全部失败 → `extractive` 且 `Answer.backend="extractive"`（界面与报告如实显示模式）。

### 9.2 Prompt 契约（`研发/app/prompts/qa_prompt.txt`）

硬约束（测试要断言）：
1. 只允许依据「检索片段」作答，片段之外的知识一律不得使用；
2. 每个事实性句子必须带 `[文件名: 页码]`；
3. 数值必须**完整抄录**（不得只写其中一个，如基线 33 题只答 `82.10%`）；
4. 片段不支撑答案时**只输出**「不清楚」；
5. 英文提问 → 英文作答 + `[File: Page N]`。

### 9.3 引用校验回路

```
生成文本 ──▶ citation.parse_citations() ──▶ [Citation(file_name, page, chunk_id, quote)]
                                   │
                                   ▼
        citation.validate()：① 1 ≤ page ≤ page_count；② chunk_id 可在 SQLite 查到且 page 一致
                            ③ 引用页文本（或引用块内容）包含 quote 的关键片段
                                   │
       ┌── 有非法引用 → 修一轮（把非法引用剔除 + 追加一句「以下内容依据不足」）→ 仍非法则整题回「不清楚」并记 error 日志
       └── 全部合法 → 输出
```

### 9.4 可答性闸门（`answerability`）

| 信号 | 判定 |
| --- | --- |
| 检索最高分 < 阈值，或关键词覆盖率 < 阈值，或问题期望数值但片段无数值 | `is_answerable = False` → 直接回「不清楚」，`unknown_reason` 写日志与 `answer.unknown_reason` |
| 问题主体与语料主体不符（如问 A 公司却过滤了 B 公司文件） | 同上（防止跨文件串答） |
| **主体类型不符（题 3/题 4 同页互污染，见 §9.4.1）** | `subject_gate.ok = False` → 修一轮剔除夹带主体 → 仍失败则回「不清楚」；`answerability.subject_gate` 事件落 `rag_trace.jsonl` |
| 阈值（**以实现为准，v1.8 回写**） | `RAG_ANSWER__MIN_SCORE = 0.12`（**退化底线**；正样本 min score **0.153** / 负样本 max **0.205** → 区间**重叠**，score 不可作主判据）、`RAG_ANSWER__MIN_KEYWORD_COVERAGE = 0.45`（**主判据**；正样本 min coverage **0.615** / 负样本 max **0.400** → **可分**）。默认值由 T6 标定并写入报告；**阈值只由标定决定，不得为通过验收而放宽**（T11 复核项） |

#### 9.4.1 主体类型闸门（题 3/题 4 同页相邻表的通用解法）

**问题**：题 3（存在控制关系的关联方，自然人赵马克 42.35% 公司控股股东）与题 4（不存在控制关系的关联方**企业**，7 家）的证据**同在物理 157**，两张表仅隔一行标题；上下文合并后极易互相夹带：

| 夹带 | 后果 |
| --- | --- |
| 题 4 答案混入自然人 **赵马克** | 判错（题 4 问的是企业） |
| 题 3 答案混入 7 家企业 | 判错（题 3 应为「自然人 + 持股比例 + 关系」三者齐备） |
| 题 4 因「与赵马克/赵依军相关」误删 **力源贸易 / 普芯达** | 判错（二者是**企业**，属题 4 答案） |

**解法（通用规则，严禁单题特判——红线 ⑥；v1.4/v1.5 修订版 + v1.6 调用顺序冻结）**：

```
每轮固定三步（顺序不得调换，v1.6）：
   ① classify_question(用户本轮原文)      → (field_type, expects_numeric, prefer_table_retrieval)
   ② rewrite_query(本轮原文, history)     → 独立问题（**仅供检索**，不参与任何分类）
   ③ classify_subject_expectation(strip_issuer_names(用户本轮原文)) → expected
   ★ 数值信号与主体类型一律取自「本轮原文」；改写结果只进检索
     （防多轮下可答性漂移：同一题在不同轮次必须得到相同的 expects_numeric）

闸门内部 ──▶ ①剥离发行人全称（config.discover_issuer_names() 动态提取 → 「该公司」，**纯替换可逆**）
                  ② 顺序固定：person 优先（谁/姓名/自然人/法定代表人/控股股东/实际控制人）
                              → 否则按**问句意图**判 organization（哪些企业/企业有哪些/…）
                              → 否则 "any"
                                        │
证据表 ──▶ ③列语义推导双桶（allowed / other）
             · "企业名称/公司名称" 列 → organization（整列）
             · "姓名/股东名称/姓名" 列 → person（整列）
             · "关联方名称" 列 → 单值且无组织后缀 → person；否则逐值按组织后缀判定
                                        │
答案文本 ──▶ ④**表列取值反查**（不做 NER、不从答案抽专名）：
             found  = allowed 取值出现在答案中的项
             leaked = other   取值出现在答案中的项
                                        │
             ⑤判定：organization → ok = found 非空 且 leaked 为空
                    person       → ok = found 非空 且 leaked 为空 且 check_person_triple 通过
                                        │
             ⑥ ok=False → 修一轮剔除夹带 → 仍失败 → 回「不清楚」+ 日志
                ok=True 且 counted=True → 闸门真正生效并通过（可作验收证据）
```

| 设计点 | 规定 |
| --- | --- |
| 检索层 | **不拆分**同页相邻表（拆开丢上下文）；两表各自成块，`chunk_id` 可区分 |
| 答案层 | 由主体类型闸门做隔离；`citation.validate(..., subject_gate=…)` 联动，未通过不计入有效引用 |
| **fail-open（★ 防误伤可答题）** | `expected=="any"` / 无主体表 / `allowed` 为空 / 闸门关闭 → **一律放行**（`ok=True`、`counted=False`、不判「不清楚」），且**不得作为「闸门通过」的验收证据**。理由：题 34/793 的证据是**正文段落**（物理 152，`tables=0`；同节 153 的表头「领域/行业进入难度/市场竞争程度/主要竞争企业」不含任何主体列）→ allowed 必为空；若不放行，会把基线做对的题误杀为「不清楚」 |
| **分类实测（14 题，T2 v1.4）** | 剥离发行人后 **any = 10 / person = 2（题 3、题 531）/ organization = 2（题 4、题 34）**；修正前（含「公司」即 organization）实测 **organization = 14**（过度触发缺陷） |
| 开关 | `RAG_ANSWER__ENABLE_SUBJECT_GATE`（默认 `true`）；关闭时 `reason="disabled"`、`counted=False`，**不得**作为通过证据 |
| 接口 | 见 `设计/接口设计.md` §3.19（`classify_subject_expectation` / `column_kind` / `allowed_set_from_tables` / `SubjectGateResult` / `subject_gate` / `check_person_triple`）、§2.4（`Answer.subject_gate`）、§3.1（`discover_issuer_names`） |
| 验收 | `设计/验收标准.md` §2.1 **N-5**（三条夹带判错）+ **N-6**（题 34/793 不得被闸门判为不可答）+ 验收 3 分类/主体断言 |
| **已知待修（T12，v1.8 记录）** | 权威产物 `answer_eval_t6.json` 实测：**题 4 被闸门误拒答**（`unknown_reason=subject_gate:org_leaked`，`unknown_ids=[4]`），而限定模式下同题可答出 5 家 → engineer 正在 **t12** 修复。**拿到根因前不预设修法**；修完后由 architect 按根因补充「闸门误拒答」负例（拟新增 **N-9**，扩展 N-6 覆盖面）。此条为**待办**，既不得据此判缺陷，也不得据此判通过 |
| 实测锚点 | PDF2 物理 157 `tables=2`（列语义：表1「关联方名称/持股比例/与本公司关系」→ person 桶 = 赵马克；表2「企业名称/与本公司关系」→ organization 桶 = 7 家）；物理 21 为题 3 辅助源（2,117.70 万股 / 42.35% / 控股股东及实际控制人）。**注意**：分桶必须按**列语义**，仅按值后缀会把 上海博润/武汉博润/联众聚源/普芯达 误判为自然人（T2 原型实测，已修） |

## 11. 日志与可观测架构

### 11.1 三个落盘文件（正本在 `部署/日志/`）

| 文件 | 内容 | 行格式 |
| --- | --- | --- |
| `app.log` | INFO 及以上全部事件 | JSON Lines |
| `error.log` | ERROR/CRITICAL（含 `traceback`） | JSON Lines |
| `rag_trace.jsonl` | 链路事件：`retrieval.*`、`generation.*`、`llm_io`、`citation.*`、`answerability.*`、`eval.question` | JSON Lines |

### 11.2 事件模型

```
func.enter ──▶ （业务事件若干） ──▶ func.exit
                                  └─▶ func.error（异常路径，带 traceback）
```

- 公共字段：`ts, level, event, func, module, run_id, trace_id, span_id, stage, pid, thread`
- 入口：`inputs`（**摘要**，非全文：长文本取前 N 字 + 长度 + sha1 前 8 位）
- 出口：`outputs`（条数/维度/首字耗时/判定结果等）+ `elapsed_ms`
- 异常：`error.type`、`error.message`、`error.traceback`（完整栈）
- **禁止**只写「开始/结束」：`func.enter` 必须含具体输入摘要，`func.exit` 必须含具体输出摘要（T8/T11 用它判定）

### 11.3 trace 串联

`trace_id` 在 HTTP 请求或 `QAEngine.ask` 入口生成（`uuid4().hex[:16]`），向下贯穿 `query_understanding → retriever → generator → llm_client → citation → conversation`；`retrieval_traces` 表与之同 id，做到「一条日志串起一次问答」。

### 11.4 写入安全

- 单进程内 `threading.Lock` 保护文件追加；每行一次 `write` + `flush`（行原子，满足 NFR-8）
- 日志目录不存在则创建；创建失败 → 抛 `LogSetupError`（不静默）
- API Key 等敏感值统一 `mask_secret()`（只留前 4 后 4）

### 11.5 只读复用 `工单1/2` 的合规做法（红线保护）

```python
sys.dont_write_bytecode = True        # 关键：防止在 工单1 下生成 __pycache__
sys.path.insert(0, r"E:\gao6gongdan\工单1\研发")   # 只读引用
from app.core.evaluator import Evaluator            # 判分口径复用（只读）
```
并在测试中断言：运行前后 `工单1`/`工单2` 的文件清单与 mtime 未变化。

## 12. 错误处理与降级

| 异常（`errors.py`） | 触发点 | 处理 | HTTP | 用户看到 |
| --- | --- | --- | --- | --- |
| `ConfigError` | 配置缺失/非法 | 启动即失败（fail fast） | 500 | 服务未起 |
| `PdfParseError` | PDF 打不开/损坏 | log + 跳过该文件（其他文件继续），`files_failed` 记录 | 500 | 「文件解析失败：X」 |
| `TableParseError` | 单表归一化异常 | log + 该表降级为纯文本块（显式降级） | —— | —— |
| `IndexMissingError` | 索引不存在 | log + 明确提示重建命令 | 503 | 「索引未就绪，请先建索引」 |
| `IndexDimensionError` | 维度不符 | log + 传播（禁止静默） | 500 | —— |
| `RetrievalError` | 检索异常 | log + 空结果 + 走「不清楚」路径 | 200 | 「不清楚」 |
| `LLMProbeError` / `LLMTimeoutError` | 后端不可用/超时 | log + 降级下一后端 → 最终 `extractive` | 200 | 正常答案（模式=extractive） |
| `LLMResponseError` | 返回体无文本 | log + 重试 1 次 → 仍失败降级 `extractive` | 200 | 正常答案 |
| `CitationError` | 引用非法 | 修一轮 → 仍非法回「不清楚」 | 200 | 「不清楚」 |
| `StorageError` | SQLite 异常 | log + 传播（写失败不允许静默） | 500 | 错误提示 |
| `EvalError` | 评估脚本异常 | log + 非零退出码 | —— | 报告标注失败 |

三类故障（解析失败 / 检索为空 / 模型异常）**必须**各有对标用例（`测试/在线/test_fault_tolerance.py`），且均产生 `error.log` 记录。

## 13. 并发与资源

| 项 | 设计 |
| --- | --- |
| FastAPI | 问答端点用 `def`（同步）跑在 Starlette 线程池，避免阻塞事件循环；`QAEngine` 内部对索引只读、对 SQLite 每线程独立连接（`check_same_thread=False` + `Lock`） |
| SQLite | `journal_mode=WAL`、`synchronous=NORMAL`；写操作用 `Lock` 串行化 |
| 索引常驻 | 向量矩阵与 BM25 结构在进程内加载一次（`numpy.load(mmap_mode="r")` 可选），请求间复用 |
| Ollama | 无并发流式调用上限，默认向量化批量 ≤ 16 条/次；HTTP 连接复用 `requests.Session` |
| 内存 | 898 页文本 + 向量（约 2~4 万块 × 1024 float32 ≈ 80~160 MB）→ 峰值 < 8 GB（NFR-9） |
| 日志 | 线程锁 + 行原子；不引入异步队列（保持简单可审计） |

## 17. 架构决策记录（ADR）

| 编号 | 决策 | 备选与否决理由 |
| --- | --- | --- |
| ADR-1 | 表格解析用 `pymupdf.page.find_tables()` | `pdfplumber` 缺失且断网；自研线框检测成本高、无必要 |
| ADR-2 | 向量检索用 `numpy` 精确检索（`faiss` 可选加速） | `chromadb` 缺失；数据量小，精确检索误差为 0、可复现 |
| ADR-3 | BM25 自实现（jieba 分词） | `rank_bm25` 缺失；自实现便于表格/数字场景调参 |
| ADR-4 | 自实现 loguru 风格 JSON logger | `import loguru` 实测失败（缺 `win32_setctime`）；JSONL 更利于测试断言（§10） |
| ADR-5 | 在线路径只走 Ollama HTTP，重库惰性导入 | 导入实测 torch 2.54 s / transformers 3.51 s / sentence_transformers 5.08 s，直接突破 3 s 预算 |
| ADR-6 | 保留 `streamlit_app.py` 为真 Streamlit 应用 + 提供 `serve_fallback.py` | 算力云可跑 Streamlit；本机无 streamlit 也必须能演示；两者共用 `app/core` 保证一套逻辑 |
| ADR-7 | RAGAS 不运行，改用确定性指标 | 依赖缺失且断网；伪造数值属红线 |
| ADR-8 | 表格整块成块、不拆 | 拆表会割裂「表头↔数值」对应关系，正是基线 33/260 类数值题失败的原因 |
| ADR-9 | `file_names` 用硬过滤而非打分抑制 | 打分抑制无法保证「选 2 号不返回 1 号块」的可证伪性（T5 必测项） |
| ADR-10 | 判分口径只读复用 `工单1\...\evaluator.py`（`dont_write_bytecode`） | 换尺子会破坏与基线的可比性；需工程隔离防止写入只读目录 |
| ADR-11 | 跨页续表**合并为逻辑表块**并继承表头 | 若按页独立成块，续表会丢列含义（「军种五」被当列首值）、重复表头会虚增 BM25 词频；而跨页是常态（PDF1 45 页续表 / 21 页重复表头，PDF2 79 / 10） |
| ADR-12 | 引用页取 `page_start`（真实物理页），不引入「页码区间」引用格式 | 引用格式 `[文件名: 页码]` 已冻结且必须可回溯到单页；区间仅写入 `content` 的 `[来源]` 行与 `page_start/page_end` 元数据，避免引用解析歧义 |
| ADR-13 | 题 3/题 4 同页相邻表的隔离放在**答案层**（主体类型闸门），不放检索层 | 检索层硬拆同页表会丢上下文并损害召回；答案层的「措辞定类型 + 表头语义定允许集合」是通用规则，可同时满足红线 ⑥（禁单题特判）与 N-5 三条判错 |
| ADR-14 | 题 207 的评测锚点取 **479（同页共现）+ 490（金额原文）**，PDF2 340 永久禁用 | 479 是唯一同页共现页（可证伪）；340 语义为银行借款，混入即编造（红线 ⑨） |
| ADR-15 | 主体类型闸门采用「**发行人剥离 + person 优先 + 列语义双桶 + 表列取值反查 + fail-open**」 | T2 原型实测：不剥离发行人 → 14/14 被判 organization（过度触发）；organization 先判 → 题 3/531 的「谁」永远到不了 person；无 fail-open → 题 34/793 因证据页无主体表被判不可答（误杀基线做对的题）；按值后缀分桶 → 4/7 企业被误判自然人。五项缺一即失效 |
| ADR-16 | fail-open 用 `counted` 显式区分「闸门真正生效」与「不适用放行」 | 避免用「闸门关闭/不适用」冒充「闸门通过」，同时保证可答题不被误拒（与「误拒答 = 0」红线一致） |

## 附：本架构的「不可变项」清单（变更即需 architect 修订 + 全员通知）

1. 页码口径 = 1-based 物理页（§4），含三条禁止（0-based / 页脚引用 / 页脚通用化假设）；

7. `[文件名: 页码]` 引用格式（取真实物理页）与「不清楚」兜底（§9.2~§9.4）；
8. 三套日志文件与 `func.enter/exit/error` 事件（§11）；

11. **在线入口必须调用预热**：`QAEngine.warmup()` → `text_utils.warmup_tokenizer()` + `embedder.warmup()` + `llm_client.probe_backends()`（§5；jieba 冷 1.16 s、BM25 冷 1020 ms → 热 1.00 ms；零调用点即缺陷）；
