## 0. 范围声明（做什么 / 不做什么）

**做**（工单明确列出）：

1. 针对《招股说明书1.pdf》的问答系统
2. Query 理解：意图识别、消歧、分解与抽象
3. 检索与生成：PDF 文字 + 表格解析、语义分块、向量检索 + BM25、重排、LLM 生成
4. 用户体验：FastAPI + Vue 界面，问题输入（**文字 + 语音**）、答案展示、点赞/点踩反馈
5. 知识库管理：PDF 解析提取、解析内容存储与管理
6. 中英文问答
7. 目标：RAG 与纯 LLM 对比、响应 ≤3s、容错、资源合理

**不做**（工单未提及，一律不实现）：登录注册、用户权限、多租户、聊天历史持久化、多文档协同管理、模型微调、前端工程化（npm/vite）、移动端适配、监控告警平台。

## 3. 数据流

### 3.1 离线索引流（一次性，`scripts/build_index.py`）

```
招股说明书1.pdf (548p)
   ↓ ① 解析
   ├─ 主：MinerU pipeline  → content_list.json（text 块 + table_body(HTML) 块）
   └─ 降级：pymupdf 抽文本 + pdfplumber 抽表(477 张) → 统一为同构块
   ↓ ② 结构化（统一 schema）
   {type: text|table, page_no, content, caption}
   ↓ ③ 语义分块（SemanticChunker）
   句子切分 → bge-m3 逐句向量 → 相邻句余弦相似度 → 低于分位阈值处断开
   → 合并到 [min_chars, max_chars]，表格块整块不分
   ↓ ④ 向量化：bge-m3 dense(1024, L2 归一化)
   ↓ ⑤ 写入 Milvus collection `pdf_chunks`（HNSW / COSINE）
   ↓ ⑥ BM25 语料（jieba 分词后的 token 列表）pickle 落盘 data/index/bm25.pkl
   ↓ ⑦ Redis 写入索引指纹（doc_id → 分块数/时间），供健康检查
```

### 3.2 在线问答流（`POST /api/chat/stream`）

```
用户问题
   ↓ ① 缓存查询（Redis，精确 key = md5(规范问题)）
   │   命中 → 直接返回（目标 <100ms，绕过全部下游）
   ↓ ② Query 理解（DeepSeek 轻量 rewrite，单次 max_tokens≈200）
   │   输出 JSON：{intent, rewritten, sub_questions[], need_rewrite}
   │   ⚡ 简单事实型问题（含公司名/年份/数字、长度短）走启发式跳过 LLM
   │   ⚡ 与①并行：先用原始 query 触发第一轮召回，rewrite 回来若有差异再补一轮
   ↓ ③ 混合召回（并行）
   │   ├─ Dense：bge-m3(query) → Milvus HNSW top_k=20
   │   └─ Sparse：jieba 分词 → rank_bm25 top_k=20
   ↓ ④ 融合：RRF（Reciprocal Rank Fusion, k=60）→ 取 top N=24
   ↓ ⑤ 重排：bge-reranker-v2-m3 打分 → 阈值过滤 → 取 top 5 进上下文
   ↓ ⑥ 上下文组装：带页码/类型标记，控制总长
   ↓ ⑦ 生成：DeepSeek，SSE 流式吐字（前端首字可见）
   ↓ ⑧ 落缓存 + 返回引用片段（页码、类型、得分）
```

## 6. Milvus Collection Schema

Collection：`pdf_chunks`

| 字段 | 类型 | 说明 |
|---|---|---|
| `pk` | INT64, primary, auto_id | 主键 |
| `vector` | FLOAT_VECTOR, dim=**1024** | bge-m3 稠密向量，L2 归一化（配合 COSINE） |
| `doc_id` | VARCHAR(64) | 文档标识（文件内容 md5 前 16 位） |
| `doc_name` | VARCHAR(256) | 原文件名 |
| `chunk_index` | INT64 | 分块序号 |
| `page_no` | INT64 | 起始页码（1-based，用于引用定位） |
| `page_end` | INT64 | 结束页码 |
| `chunk_type` | VARCHAR(16) | `text` / `table` |
| `title` | VARCHAR(512) | 所属章节标题（若可提取） |
| `content` | VARCHAR(8192) | 分块正文（表格为 HTML 转纯文本后的内容） |

索引：`HNSW`（M=16, efConstruction=200），度量 `COSINE`；标量 `doc_id` / `chunk_type` 建 INVERTED 索引用于过滤。

> **不用 Milvus 内置稀疏向量/BM25**：工单指定 `rank_bm25`，故稀疏检索在进程内做，BM25 语料 pickle 落盘，进程启动时加载。这样检索逻辑与工单一致，也便于离线调参。

**降级**：`MILVUS_URI` 配置项同时支持 `http://localhost:19530`（Docker）与 `./data/milvus/lite.db`（milvus-lite），`pymilvus.MilvusClient(uri)` 一条代码路径覆盖两种部署。

## 7. 性能预算：3 秒怎么花

单次问答（非缓存命中）预算拆解，目标 **P95 ≤ 3s**：

| 环节 | 预算 | 手段 |
|---|---|---|
| ① 缓存查询 | 20 ms | Redis 精确缓存 + 高频问题预热 |
| ② Query 理解 | 0 或 1000 ms | **简单事实型问题启发式跳过**（工单 10 问均属此类）；复杂问题才调 DeepSeek，`max_tokens=200`，且与③并行 |
| ③ 混合召回 | 250 ms | Dense(bge-m3 GPU ~60ms) 与 BM25(~10ms) 并行；Milvus HNSW |
| ④ RRF 融合 | <10 ms | 纯内存 |
| ⑤ 重排 | 350 ms | 候选取 24，bge-reranker-v2-m3 GPU，FP16 |
| ⑥ 生成 | TTFT ≤ 800 ms | SSE 流式；`max_tokens` 按问题类型限幅；**首字即视为「返回答案」** |
| **合计（首字）** | **≈ 1.4 s** | |
| 合计（完整答案） | 2.5–4 s | 流式下用户感知延迟=首字延迟，完整答案时长单独统计并如实报告 |

**如实说明**：若把「生成完整答案」计入 3 秒，DeepSeek 长回答（300+ 字）通常需 3–6s，无法保证。因此系统按「首字响应 ≤3s」交付，并在测试报告中**同时给出首字延迟与完整答案延迟两组真实数字**，不做粉饰。优化手段见《优化记录》。

## 8. 风险与降级方案

| # | 风险 | 触发表现 | 降级/容错策略 | 影响 |
|---|---|---|---|---|
| 1 | MinerU 中文路径崩溃（fasttext） | `DetectError: Failed to load FastText model` | 注入 `PYTHONPATH=C:\mineru_models\langfix`（sitecustomize 打补丁）；仍失败 → 自动降级 pymupdf+pdfplumber 并在响应中标注 `parser=fast` | 表格结构精度下降，功能不中断 |
| 2 | MinerU 解析超时/显存不足 | 进程超时或 OOM | 页级切片重试；单页失败跳过并记入 `failed_pages`，不阻塞整篇 | 少量页缺失 |
| 3 | MinerU 表格内容读错字段 | 表格全丢 | 已知坑：表格在 `content_list.json` 的 **`table_body`(HTML)** 字段而非 `text`，解析时显式取 `table_body` 并转纯文本 | 避免丢 502 张表 |
| 4 | Milvus 连接失败 | 19530 拒绝 | ① 自动尝 `MILVUS_URI` → ② 回退 milvus-lite 本地文件 → ③ 回退 NumPy 内存暴力检索（候选集小，<10 万块可行） | 功能不中断，性能下降 |
| 5 | DeepSeek 超时/限流/欠费 | 429 / timeout | 重试 2 次（指数退避）→ 仍失败则**返回检索原文摘要 + 明示"生成服务暂不可用"**，不返回空白也不编造 | 答案质量降级但可读 |
| 6 | Redis 不可用 | 连接拒绝 | 全部缓存读写 try/except 吞掉，退化为无缓存模式；反馈写本地 `data/feedback.jsonl` | 仅性能与反馈持久性下降 |
| 7 | BM25 语料文件缺失 | 文件不存在 | 启动时若发现缺失且 Milvus 有数据 → 从 Milvus 标量字段回捞 `content` 现场重建 | 启动稍慢 |
| 8 | 用户输入错误/空/超长/注入 | 空串、10 万字、prompt 注入 | 长度截断至 512 字；空问题返回 400；提示词中上下文用分隔符包裹并声明"仅依据资料作答"；HTML 转义防 XSS | 不崩、不越权 |
| 9 | 模型加载失败/GPU 不可用 | CUDA OOM | `EMBED_DEVICE` 配置可切 `cpu`；reranker 失败时跳过重排直接用 RRF 结果 | 精度下降 |
| 10 | PDF 损坏/加密/无文本层 | 打不开或空文本 | 校验页数与字符数；无文本层 → 提示启用 OCR（paddleocr）；加密 → 明确报错 | 明确提示，不静默失败 |
| 11 | 高并发 | 请求堆积 | uvicorn 异步 + 模型调用放线程池；bge-m3/reranker 加 `asyncio.Lock` 防止并发抢占显存；SSE 连接数上限 | 稳定不崩，排队延迟上升 |

## 10. 代码规模约束

工单要求「每个 .py ≤300 行，总自定义 Python 尽量 ≤300 行」。前者严格执行；后者与「完整可运行系统 + 逐行中文注释」存在客观冲突，处理原则：

- 优先保证核心链路（解析→分块→检索→重排→生成）完整可跑；
- 压缩非核心（CLI 参数、日志、工具函数），能复用标准库就不自己写；
- 实测总行数在《测试报告》中如实给出，不隐瞒超标。
