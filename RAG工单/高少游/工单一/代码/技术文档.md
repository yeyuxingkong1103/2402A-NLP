# RAG 基于 PDF 文档的问答系统 · 技术文档

> 工单编号：人工智能 NLP-RAG-基于 PDF 文档的问答系统
> 运行环境：Python 3.10 / langchain2 环境 ｜ 模型：本地 Ollama（无外部 API）

---

## 1. 系统概述

本项目实现一个基于 PDF 文档的检索增强生成（Retrieval-Augmented Generation, RAG）问答系统。以《招股说明书1.pdf》为唯一知识源，用户用自然语言提问，系统通过「查询理解 → 混合检索 → 检索增强生成」链路，严格依据文档内容回答问题并给出来源页码，同时提供「纯 LLM」对比基线用于衡量 RAG 的增益。

核心能力与需求对应：

| 需求 | 实现 |
|---|---|
| 基于 PDF 内容精准回答 | 文本/表格解析 + 切片 + 向量/词法混合检索 + 强约束提示词 |
| 查询理解 | 意图识别、消歧、子问题分解，提升召回与回答质量 |
| RAG 与纯 LLM 对比 | `scripts/evaluate.py` 双链路评估，RAGAS 指标 + 人工命中 |
| 响应时间 < 3s | `LLM_MAX_TOKENS` 控制生成长度、HNSW 向量检索、缓存知识库 |
| 评估框架 | RAGAS（faithfulness / answer_relevancy / context_precision / context_recall / answer_correctness） |
| 用户友好界面 | Streamlit（文字 + 语音 + 反馈） |

## 3. 关键技术设计

### 3.1 PDF 解析（`pdf_parser.py`）
- 采用 **PyMuPDF** 逐页抽取文本，`with_tables=True` 时额外用 `pymupdf.FindTables` 提取表格并转成「键:值」结构化文本，保留原页号。
- 每页产出 `PageDoc(content, page_no)`，供下游切片。

### 3.2 切片与向量化（`knowledge_base.py`）
- **切片**：`RecursiveCharacterTextSplitter(chunk_size=500, overlap=80)`，分隔符适配中文（`。；，\n`）。
- **向量化**：本地 `bge-m3:567m`，通过 `_BatchedEmbeddings` 分批（每批 50 条）调用，**规避本地 Ollama 在超大批量时 tokenizer 服务连接被拒的问题**。
- **索引**：FAISS（HNSW 近似最近邻），单目录持久化，加载/保存稳定。

### 3.3 查询理解（`query_understanding.py`）
解决自然语言提问的三种歧义问题：
- **意图识别**：判断是否为需检索文档才能回答的问题；
- **指代消歧**：把「该公司/它」等指代还原为实体名；
- **子问题分解**：对复合问题拆分为若干可独立检索的子问题。
设计上保证 `retrieval_queries` **始终以消歧后主问题为首位**，子问题作为补充召回，避免检索被拆分后丢失主线语义。

### 3.4 混合检索与融合（`retriever.py`）
- **向量检索**：语义相似（对同义改写友好）；
- **BM25 词法检索**：jieba 分词 + rank-bm25，对专有名词、数字、公司名精确命中友好；
- **RRF 融合**：`RRF score = Σ 1/(k + rank)`，融合两路排序，兼顾精度与召回。

### 3.5 检索增强生成（`qa_engine.py`）
- RAG 提示词强约束「**仅依据参考文档回答、给出数值原样、标注来源页码、不得编造；参考文档确实不含信息时才明确说明无法回答**」，显著降低幻觉；
- 纯 LLM 提示词独立生成基线答案，用于 RAGAS 对比。

### 3.6 语音提问（`app.py`）
- 可选依赖 `openai-whisper`：上传音频 → 本地转文字 → 自动填入问题框；
- whisper 未安装时自动降级为纯文字输入，不影响系统使用。

## 4. 评估方案（RAGAS）

`scripts/evaluate.py` 对 10 道题分别用 RAG 与纯 LLM 回答，再用 RAGAS 评分：

| 指标 | 适用链路 | 含义 |
|---|---|---|
| `faithfulness` | RAG | 回答是否忠实于检索上下文 |
| `answer_relevancy` | RAG | 回答与问题的相关性 |
| `context_precision` | RAG | 检索返回的相关片段占比 |
| `context_recall` | RAG | 参考答案所需信息被召回的比例 |
| `answer_correctness` | RAG + LLM | 回答与参考标准答案的一致性（两链路可对比） |

要点：
- 裁判模型与检索/生成同为本地 `deepseek-r1:1.5b`，完全离线下运行；
- `RunConfig(timeout=300, max_retries=6, max_workers=1)` 序列化并延长超时，确保本地小模型评分稳定；
- 除 RAGAS 外，`build_report.py` 加入**人工关键词命中检查**，对每题的参考答案核心数据（数字、专有名词）做二值判定，用作 RAGAS 的可信度交叉验证。

## 6. 配置说明

见 `.env.example`，可复制为 `.env` 覆盖默认值（模型、检索 Top-K、切片大小、嵌入批次等）。关键参数：

| 变量 | 默认 | 说明 |
|---|---|---|
| `LLM_MODEL` | `deepseek-r1:1.5b` | 生成模型 |
| `EMBEDDING_MODEL` | `bge-m3:567m` | 向量模型 |
| `TOP_K` | `8` | RAG 检索返回片段数 |
| `CHUNK_SIZE` | `500` | 切片大小 |
| `LLM_MAX_TOKENS` | `768` | 生成长度上限（影响耗时） |
