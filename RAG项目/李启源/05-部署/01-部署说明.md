# Linux 部署说明

## 1. 支持范围

- 操作系统：Ubuntu 20.04 / 22.04 / 24.04，x86_64；
- Python：Conda 环境内 Python 3.11；
- CPU 模式：适合外部 Embedding/LLM 服务或功能验证；
- CUDA 模式：适合本地 Embedding、Reranker 或 LLM 推理；
- 数据依赖：Milvus、Redis、MySQL 可通过 Docker 或独立服务部署。

> CUDA 模式要求宿主机已经正确安装 NVIDIA 驱动，`nvidia-smi` 可以正常执行。应用安装脚本安装的是 CUDA 版 PyTorch 运行包，不负责修改宿主机显卡驱动。

## 2. 文件说明

| 文件 | 用途 |
|---|---|
| `check_env.sh` | 检查 Linux、CPU、内存、磁盘、Conda、Docker、GPU 和配置文件 |
| `install.sh` | 安装 Miniconda（如缺失）、创建环境并安装核心代码依赖 |
| `run.sh` | 校验配置并在后台启动 `02-研发/核心代码/` 中的 API |
| `shutdown.sh` | 根据核心代码目录中的 PID 文件优雅结束 API |

脚本与说明直接放在 `05-部署/` 下，并自动定位同一交付包内的 `02-研发/核心代码/`。完整复制 `RAG项目/` 后即可使用。

## 3. 部署步骤

### 3.1 赋予执行权限

```bash
cd /opt/rag-project
chmod +x RAG项目/05-部署/*.sh
```

### 3.2 检查服务器环境

```bash
bash RAG项目/05-部署/check_env.sh
```

### 3.3 安装 Conda 与 Python 依赖

CPU / 外部模型服务模式：

```bash
bash RAG项目/05-部署/install.sh --mode cpu
```

NVIDIA GPU 模式：

```bash
nvidia-smi
bash RAG项目/05-部署/install.sh --mode cuda
```

可指定环境名称：

```bash
bash RAG项目/05-部署/install.sh --mode cuda --env-name rag-prod
```

默认 Conda 环境名为 `rag-kf`。

## 4. 配置 `.env`

安装脚本只在 `.env` 不存在时从 `.env.example` 创建，不覆盖已有配置。至少核对：

```dotenv
APP_ENV=production
API_HOST=127.0.0.1
API_PORT=8000

REQUIRE_API_KEY=true
API_KEY=替换为足够长的随机密钥

EMBEDDING_PROVIDER=http
EMBEDDING_BASE_URL=http://127.0.0.1:11434
EMBEDDING_MODEL=bge-m3
EMBEDDING_DIM=1024

VECTOR_STORE_PROVIDER=milvus
MILVUS_URI=http://127.0.0.1:19530
MILVUS_COLLECTION=kf_chunks

DATABASE_URL=mysql+pymysql://rag_user:密码@127.0.0.1:3306/rag_system?charset=utf8mb4
REDIS_URL=redis://127.0.0.1:6379/0

LLM_PROVIDER=openai
LLM_BASE_URL=https://你的OpenAI兼容网关/v1
LLM_API_KEY=替换为真实密钥
LLM_MODEL=替换为可用模型
```

注意：

- `.env` 不应提交到 Git；
- 不要使用示例密码或默认 API Key；
- `EMBEDDING_DIM` 必须与 Embedding 输出维度以及 Milvus 集合一致；
- 对外服务时由 Nginx 终止 TLS，Uvicorn 建议仅监听 `127.0.0.1`；
- 使用 API Key 身份映射时可配置 `API_KEY_IDENTITIES` 实现多租户隔离。

## 5. 准备基础服务

启动 API 前需保证按实际功能启用依赖：

| 服务 | 默认地址 | 是否可降级 |
|---|---|---|
| Milvus | `127.0.0.1:19530` | 真实向量检索不可缺少 |
| Redis | `127.0.0.1:6379` | 缺失时短期记忆和会话接口不可用 |
| MySQL | `127.0.0.1:3306` | 缺失时知识库管理、文档元数据和会话接口不可用 |
| Embedding | 按 `.env` | Mock 模式可用于开发，生产需真实服务 |
| LLM | 按 `.env` | Mock 模式可用于开发，生产需真实服务 |

MySQL 首次部署后执行仓库 `sql/` 中与当前版本对应的 Schema。Milvus 集合由应用索引/记忆模块按配置初始化；已有集合的向量维度必须匹配。

## 6. 启动服务

生产模式：

```bash
bash RAG项目/05-部署/run.sh --mode production
```

开发验证模式：

```bash
bash RAG项目/05-部署/run.sh --mode development
```

指定 Conda 环境和 Worker 数量：

```bash
bash RAG项目/05-部署/run.sh \
  --mode production \
  --env-name rag-prod \
  --workers 4
```

运行文件：

- 日志：`logs/rag-api.log`
- PID：`data/pids/rag-api.pid`

验证：

```bash
curl http://127.0.0.1:8000/health
curl -H 'X-API-Key: <key>' http://127.0.0.1:8000/ready
curl -H 'X-API-Key: <key>' http://127.0.0.1:8000/metrics
```

## 7. 停止服务

```bash
bash RAG项目/05-部署/shutdown.sh
```

脚本先发送 `SIGTERM` 并等待进程退出，超时后才发送 `SIGKILL`。它只处理 `data/pids/rag-api.pid` 中登记的项目进程，不使用全局 `pkill`。

## 8. Nginx 建议

仓库已有 `deploy/nginx/rag_loadbalancer.conf` 可作参考。生产配置至少应包含：

- HTTPS 和安全响应头；
- SSE 路径关闭代理缓冲；
- 上传大小与应用 `MAX_REQUEST_SIZE_MB` 对齐；
- 合理的连接、读取和上游超时；
- 网关级限流，避免多 Worker 各自限流导致总配额放大。

## 9. 常见故障

| 现象 | 排查方向 |
|---|---|
| 启动后立即退出 | 查看 `logs/rag-api.log`，生产环境常见原因是未配置 API Key |
| `/ready` 为 degraded | 检查 Milvus 地址、LLM 密钥和记忆依赖 |
| 会话接口返回 503 | 检查 Redis、MySQL 和 `DATABASE_URL` |
| 上传后无法检索 | 核对 `EMBEDDING_DIM`、Milvus 集合维度和知识库过滤字段 |
| GPU 未生效 | 运行 `nvidia-smi`，再在 Conda 环境执行 `python -c 'import torch; print(torch.cuda.is_available())'` |
| SSE 断流或整段返回 | 检查 Nginx `proxy_buffering off` 和读取超时 |

## 10. 上线检查清单

- [ ] `.env` 中无示例密钥和默认密码；
- [ ] `APP_ENV=production`，鉴权已开启；
- [ ] MySQL、Redis、Milvus 数据目录已持久化并备份；
- [ ] `/health`、`/ready`、`/metrics` 已接入监控；
- [ ] Nginx 已配置 HTTPS、SSE 和请求大小限制；
- [ ] 用真实 Embedding 维度完成一次建库与问答验证；
- [ ] 日志不输出 API Key、用户隐私或完整敏感请求体；
- [ ] 已准备停止、回滚和索引恢复方案。
