# 工单14 修复低质量工业PDF的解析与信息丢失｜总结文档
##1.任务完成情况
✅ 梳理RAGFlow整体架构，掌握API Server + Task‑Executor + Redis Stream任务队列机制。
✅ 深入梳理DeepDoc解析模块各个parser，理解`do_handle_task()`完整任务处理逻辑，输出deepdoc_analyse.md。
✅ 区分原生文本PDF解析器pdf_parser和扫描件OCR解析器paddleocr_parser的适用场景。
✅ 针对工业图片专利PDF CN100342976C.pdf，定位图文丢失、图文割裂根因。
✅ 实现本地PDF OCR预处理脚本pdf_ocr_fix.py；实现RAGFlow API批量测试脚本test_ragflow_api.py。
✅ 通过解析器切换、OCR预处理、分块调优、开启rerank，完成6道测试用例全部正确。

##2.学习收获
1. 工业PDF分为原生可复制文本PDF与图片扫描PDF；扫描PDF不能使用普通文本提取，必须OCR识别。
2. RAGFlow任务分发机制：前端请求投递Redis Stream消息队列，Task‑Executor异步消费执行解析任务。
3. DeepDoc各个parser分工；paper模式专门适配专利、科技文档，内置图文绑定切片逻辑。
4. 工业文档故障点：OCR识别质量、图文切片割裂是RAG问答错误高频来源；不是仅仅调大向量检索top‑k就能解决。
5. 调优思路分层：解析层 > 分块切片层 > 检索rerank层；解析层问题上层检索调优无法弥补。

##3.现存不足
1. OCR对于极低分辨率图纸仍然会出现少量标号识别错误；需要专业图纸词典。
2. 当前方案依赖OCR转文字；没有使用原生多模态大模型直接读取图片图纸。

##4.后续拓展方向
1. 接入多模态大模型，实现图文混合多模态RAG，绕过OCR识别图纸；
2. 训练工业图纸OCR自定义词典，优化部件编号、特殊符号识别；
3. 对IMDR数据集上万条文档实现批量预处理流水线。
