# RAG 评估结果（工单07 · 需求硬性要求4）

> **工单编号**：人工智能NLP-RAG-功能测试及评估  
> **评估口径**：复用上游 06 `evaluate_retrieval.py` 的指标实现（`score_hits`/`corpus_stats`/`answer_accuracy`/`ndcg_at_k`）  
> **k = 5**　**策略**：hybrid, vector, fulltext

## 一、指标定义（本报告口径）

| 指标 | 定义 |
| --- | --- |
| Precision@5 | top-5 中相关块占比。相关 = 该块正文含本题任一 `evidence_facts` |
| Recall@5 | top-5 相关块数 ÷ **全语料**相关块数（严格 IR 口径，分母大，天然偏低） |
| Hit Rate@5 | top-5 是否至少含 1 个相关块（0/1，再按题平均） |
| MRR | 第一个相关块名次的倒数（1/rank） |
| NDCG@5 | 以相关/不相关为增益的二值 nDCG |
| 事实覆盖@k | top-k 上下文并集覆盖本题关键事实的比例（**信息召回率**，业务口径） |
| Answer Accuracy | 生成答案对 `key_facts` 的逐字覆盖率 |

> 说明：`Recall@k` 的低值主要来自**分母**——同一事实在年报里会以正文、多处表格、
> 附注等形式重复出现，形成几十个相关块；该指标用于**横向比较策略**，不宜单独解读。
> 业务上更应看**事实覆盖@k**与**答案准确率**。
