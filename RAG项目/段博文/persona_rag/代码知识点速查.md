## 3. 老师最可能问的 10 个知识点（按"能讲出为什么"排序）

1. **RRF 只用名次不用分数** —— `retriever.py:195-199`：两路分数不可比（余弦 vs BM25），加权求和需归一化且脆弱，RRF 天然规避；c=60 是经验值。
2. **向量归一化 + COSINE 的配套** —— `db_milvus.py:72`：归一化后余弦等价内积、分数落 [-1,1] 才可能设阈值。
3. **阈值过滤的权衡** —— `retriever.py:212-218`：宁缺毋滥 vs 有问必答；注意取不到分数时默认 1.0 的兜底。
4. **BM25 必须配 jieba 预分词** —— `retriever.py:52-66,123`：默认空格切词会让中文 BM25 完全失效，且建索引与查询必须同一分词器。
5. **PDF 两级策略：先文字层再 OCR** —— `doc_parser.py:440-443`：OCR 慢几十倍，不能一上来就 OCR；判断点放在 `extract_text` 以保持单一职责。
6. **入库幂等去重** —— `db_milvus.py:180,191`：`(source, chunk_index)` 做键，重复入库不产生重复向量。
7. **BM25 全量重建 + 空语料 pop** —— `retriever.py:97-128`：没有增量接口，入库后必须全量重拉；空语料留旧索引会检索到已删文档。
8. **Session 在 finally 关闭 + pool_pre_ping** —— `db_mysql.py:43,120-121`：连接池借还必须成对，pre_ping 解决"MySQL server has gone away"。
9. **流式回答"流结束才写 Redis"** —— `main.py:488-491,536-537`：半截回答会污染下一轮上下文；流内异常改不了状态码，只能当正文吐出。
10. **lifespan 启动顺序不可换** —— `main.py:91-139`：建表 → 向量模型 → Milvus 集合 → 重排 → BM25 → 预置角色，顺序错则后续加载失败。

## 4. 容易被问空的点（先说清，别踩）

1. **`pool_recycle` 本项目根本没配**（全项目无命中）——只配了 `echo / pool_pre_ping / pool_size`，靠 pre_ping 探活。
2. **知识库三个集合的 schema 不是手写的**：由 langchain-milvus 按向量维度自动创建（`db_milvus.py:103-109`）；手写 schema 只出现在 `kb_update.py:265-270`（全量重建）和 `db_milvus.py:367-373`（长期记忆）。
3. **`doc_parser.py` 的扩展解析器已启用 4 个**（图抽取 / 表格整合 / Excel / PPT，依赖 openpyxl 与 python-pptx 已装）；**只有 VLM 两条仍是注释**（`278-325`，需要 vlm_api_key 与可用的视觉模型服务）——回答"VLM 预留扩展点、其余已启用"。
4. **阈值过滤当前实际不生效**：`retriever.py:167` 的 docstring 说结果 metadata 里会有重排模型的 `score`，但当前安装的 langchain 版本**不写这个字段**，所以 `retriever.py:214` 永远取默认值 1.0、`SCORE_THRESHOLD=0.3` 从未触发过。这是"文档写了、实测不生效"的典型，能主动说出是加分项。
5. **README 与代码的三处不一致**：
   - README 把 `post_processor.py` 描述为"检索结果后处理（去重、压缩）"，实际是**模型输出的清洗与引用抽取**；
   - README 数据流写"向量检索 top_k*3 候选"，实际是固定 `TOP_K_RECALL=10`；
   - README 目录清单里没有 `check_milvus.py`。
