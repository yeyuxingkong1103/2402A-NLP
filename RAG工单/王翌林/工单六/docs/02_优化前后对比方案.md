## 1. 实验目标

在同一问题集、同一索引数据、同一 LLM 参数下，对比"工单一基线系统"与"工单二优化系统"的 6 项指标，量化每层优化的净收益，验证是否达成验收目标：

- 检索准确率 ≥ 90%
- 响应时间 ≤ 3 秒
- 中英文问答均可用
- 系统稳定容错

## 2. 实验设计

### 2.1 实验分组

| 组别 | 配置 | 说明 |
|------|------|------|
| **A 组（基线）** | 工单一原链路：向量+BM25+RRF+reranker+精确缓存 | 保持复制时原样，不改动 |
| **B 组（优化）** | 工单二链路：A + 查询改写/多路召回/父子块/表格召回/翻译路由/语义缓存/容错 | 逐项消融开关可配置 |

### 2.2 变量控制（公平性保障）

| 控制项 | 设定 |
|--------|------|
| 问题集 | 完全相同的 10 条核心问题（见 §3） |
| 索引数据 | 同一份招股说明书1.pdf 解析产物；B 组重建索引前，A 组先完成全部测量 |
| LLM | 同一 DeepSeek-v4-flash，temperature=0.3，max_tokens=2048 |
| top_k | 统一 top_k=5 |
| 运行环境 | 同一 conda 环境 rag_pdf_qa、同一 WSL 实例、无其他重负载任务 |
| 缓存干扰 | 每题首轮测量前清空检索缓存与语义缓存；延迟统计取 3 次运行的中位数 |
| 判定标准 | 同一参考答案关键词表 + 同一 LLM-as-Judge prompt |

### 2.3 执行流程

```
Step 1  启动 A 组系统（工单一原样，端口 8001）
Step 2  逐条发送 10 题 × 3 轮（共 30 次请求），记录答案/引用/耗时
Step 3  计算 A 组 6 项指标 → data/optimized/eval_baseline.json
Step 4  B 组优化逐项落地（每项消融开关，单独回归）
Step 5  B 组重建索引后，同口径跑 10 题 × 3 轮
Step 6  计算 B 组指标 → data/optimized/eval_optimized.json
Step 7  生成对比表与结论 → docs/02 对比分析定稿（Step 9 完成后）
```

## 4. 评估指标定义（6 项）

### 4.1 指标体系

| 指标 | 定义 | 计算方法 | 工具 |
|------|------|---------|------|
| **准确率 Accuracy** | 答案包含参考答案关键锚点的题目占比 | 逐题关键词命中判定（大小写/全半角归一），10 题命中数/10 | 自建脚本 eval |
| **响应时间 Latency** | 从发请求到收到完整答案的耗时 | 每题 3 轮取中位数，报 P50/P95（10 题 × 3 轮 = 30 样本） | requests 计时 |
| **忠实度 Faithfulness** | 答案是否完全由上下文支持（无幻觉） | LLM-as-Judge 1~5 分：5=全部可溯源，1=凭空编造；10 题均分 | RAGAS 或自建 Judge prompt |
| **答案相关性 Answer Relevancy** | 答案与问题的相关程度 | LLM-as-Judge 1~5 分：5=直接回答问题，1=答非所问；10 题均分 | RAGAS 或自建 Judge prompt |
| **上下文精度 Context Precision** | 检索到的 top_k 块中相关块是否排在前面 | Judge 逐块标注相关/不相关 → 相关块平均排名（1-相关块占比罚分），即 precision@k | 自建 Judge |
| **上下文召回 Context Recall** | 答案所需信息是否全部包含在上下文中 | Judge 判断"给定上下文能否推出参考答案"，可推出=1；10 题均分 | RAGAS |

### 4.2 判定实现说明

```python
# 工单编号：人工智能NLP-RAG-基于PDF文档的问答系统优化
# 评估判定核心逻辑示意（正式脚本见 scripts/evaluate_optimized.py，Step 2 交付）

def hit(answer: str, anchors: list[str]) -> bool:
    """准确率判定：答案文本归一化后包含任一关键锚点即命中（人工智能NLP-RAG-基于PDF文档的问答系统优化）"""
    a = answer.lower().replace("，", ",").replace(" ", "")
    return any(x.lower() in a for x in anchors)
```

- **Judge prompt 原则**：仅给定（question, context, answer/reference）三元组，要求输出 JSON `{"score": x, "reason": "..."}`，temperature=0，保证可复现；
- **RAGAS 优先**：requirements 已含 ragas，faithfulness / answer_relevancy / context_recall 直接复用 RAGAS 实现；judge LLM 同样走 DeepSeek 环境变量配置。

### 4.3 指标合格线（验收映射）

| 指标 | 基线 A | 优化 B 目标 | 验收要求 |
|------|--------|------------|---------|
| 准确率 | 实测 | ≥ 90% | ✅ 硬指标 |
| P95 响应时间 | 实测 | ≤ 3s | ✅ 硬指标 |
| 忠实度 | 实测 | ≥ 4.0/5 且 ≥ 基线 | 软指标 |
| 答案相关性 | 实测 | ≥ 4.0/5 且 ≥ 基线 | 软指标 |
| 上下文精度 | 实测 | ≥ 基线 +10% | 软指标 |
| 上下文召回 | 实测 | ≥ 基线 +15% | 软指标 |
| 英文题命中（Q8~Q10） | 实测 | ≥ 2/3 | ✅ 多语言硬指标 |
| 稳定性（20 连发零失败） | — | 100% 成功 | ✅ 硬指标 |
