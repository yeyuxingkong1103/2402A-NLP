## 一、构建

```bat
cd /d D:\桌面\徐子睿工单二
docker build -t finqa-graphrag:1.0 .
```

- 构建结果：**成功**（`docker_build.log`，日志尾部 `View build details: docker-desktop://...`）；
- 依赖层：`pip` 走清华镜像（`PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple`），
  仅运行期依赖（pymupdf / jieba / numpy / fastapi / uvicorn / python-multipart / requests），**不含 mineru、不含 torch** → 镜像小、构建快（二次构建 < 20s，pip 层走缓存）。
- 已验证 `docker images`：`finqa-graphrag:1.0  506MB`。

## 二、启动

```bat
docker run -d --name finqa-graphrag -p 8100:8100 ^
  --add-host host.docker.internal:host-gateway ^
  -v "D:\桌面\徐子睿工单二\data:/data" ^
  finqa-graphrag:1.0
```

| 关键设计 | 说明 |
|---|---|
| `-v <工程>\data:/data` + `ENV DATA_DIR=/data` | 索引（6240 块）、BM25、图谱 `graph.json`、年报原文全部**离线产物挂载**，镜像保持轻量 |
| `--add-host host.docker.internal:host-gateway` | 容器内访问宿主机 Ollama（`OLLAMA_BASE=http://host.docker.internal:11434`，模型 bge-m3 / qwen2:7b） |
| `HEALTHCHECK` | 每 30s 探 `/api/health`；`docker ps` 显示 `Up (healthy)` |

启动日志（`docker logs finqa-graphrag`）：


容器状态：`finqa-graphrag  Up (healthy)` ✅

## 四、验证中发现并修复的问题

| 问题 | 现象 | 修复 |
|---|---|---|
| 图谱路径未跟随 `DATA_DIR` | 容器内 `POST /api/graph/query` 报 `FileNotFoundError: /app/data/graph/graph.json` | `app/graph_rag.py` / `app/graph_viz.py` 的图谱路径由 `PROJECT_ROOT/data` 改为 **`config.DATA_DIR/graph`** → 容器内正确读 `/data/graph/graph.json` |

> 首次构建后 `/api/graph/query` 500，定位到上述硬编码路径；修复后**重新构建镜像**（506MB）并**重新起容器**，6/6 通过。

## 六、备注

- 生成/嵌入走**外部 Ollama**（宿主机），这是本机显存与模型复用的现实选择；若要“全容器化”，可另起 `ollama` 服务并把 `OLLAMA_BASE` 指向它（`docker-compose.yml` 已预留注释）。
- 解析（MinerU）与建库（`build_kb_txt.py`）、建图（`graph_build.py`）属**离线步骤**，不打包进运行镜像。
