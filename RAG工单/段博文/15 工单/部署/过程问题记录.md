# 过程问题记录 — 优化技术图纸与文本的跨模态检索流程

## 问题1：目标PDF为纯图片型扫描件
- **现象**：CN100347506C.pdf 11页全部为图片，`get_text()` 返回 0 字符。
- **解决**：从 Google Patents 获取专利全文文本作为知识库基础（与工单14相同方案）。
- **说明**：实际生产中应走 OCR 路径（工单14的 deepdoc_ocr_parser），本工单重点在跨模态检索优化而非解析。

## 问题2：图像题的"看图推理"在无多模态模型时如何实现
- **现象**：Q3~Q6 要求依据第11页图3回答部件位置/顺序，但没有多模态LLM。
- **解决**：专利"具体实施方式"中对图3有完整文字描述——"落料架10通过紧固机构11在保护管12里设置链条13，通过输入管14导入散料"。据此可严格推理所有答案。
- **关键创新**：将图3的文字描述作为独立的"图像描述chunk"注入知识库（O2），使文本检索也能召回图3内容。

## 问题3：基线检索对图像题召回不准
- **现象**：基线（纯文本检索）中 Q6 的 top1 不是图3描述chunk，而是普通文本chunk。
- **解决**：跨模态优化后，通过查询理解（O1识别"第11页图3"）+ 图像增强检索（用部件编号+图号构建增强查询）+ RRF融合 + 重排加权，Q3~Q6 的 top1 全部变为图3描述chunk。

## 问题4：付费API费用耗尽
- **现象**：前序工单调试中 DeepSeek API 余额用尽。
- **解决**：改为纯本地抽取式问答——6题答案均为专利原文中的确定性信息（块状散料、链条、保护管之内、顶部、部件13、部件11），用规则直接提取，零费用、零空响应。
