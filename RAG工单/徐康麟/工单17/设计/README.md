## 一句话结论（详见 `优化/瓶颈排查与修复报告.md`）

> 本服务的并发瓶颈**不在**文档解析器或模型加载（本仓库根本没有「每请求新建解析器」这种写法 ——
> 已核实并如实记录），而在**四处真实位置**：
> ① 入口无任何限流（`service/config.py:119` 的 `max_concurrency` 定义了却零引用）；
> ② 每次嵌入调用都重新探测 Ollama 后端（`app/core/embedder.py:299`）；
> ③ 所有外部 HTTP 用 `urllib.request.urlopen`，**每请求新建 TCP**（`llm_client.py:92/239/278`、`embedder.py:84`）；
> ④ 每请求 4 次 sqlite `commit()` 串行在同一把锁上（`sqlite_manager.py:155/176/190/200`）。
> 泄漏点则是：`qa_engine._memory_cache` 无锁无 TTL、`answer_cache` 表无上限、会话卷无清理、
> 以及 `keep_alive="30m"` 导致的 Ollama 显存不释放。
