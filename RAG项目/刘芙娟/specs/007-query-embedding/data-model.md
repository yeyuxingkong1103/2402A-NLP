# Phase 1 Data Model: 提问落盘与问题向量化（S8）

**Feature**: `007-query-embedding` | **Date**: 2026-09-27

本特性有**唯一的持久化产物**：`data/questions/{yyyymmdd}.jsonl`。一行一条记录，自包含（FR-034）—— 仅凭一行即可还原"哪个问题、什么时候问的、向量是多少、用什么口径算的"。

---

## 1. 文件布局

```text
data/
├── questions/
│   ├── 20260927.jsonl          # 一天一个文件，追加写
│   └── 20260928.jsonl
├── embeddings/                 # ← S5 的产物，本特性只读（用于核对口径，不读内容）
├── index_manifest.json         # ← 指纹门禁的比对基准（只读）
└── ...
```

**文件名用本地日期**（`yyyymmdd`），不是 UTC。理由：运维按"今天的问题"去找文件时，用的是本地时间；若按 UTC 切分，晚上 8 点之后的问题会落到"明天"的文件里，每次找都要换算一次。

---

## 2. 记录（`AskRecord`）— 一行一条

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `answer_id` | string (UUID) | ✅ | 与 SSE `status`/`done` 帧的 `answer_id` **同值**，是关联服务端日志的钥匙 |
| `question` | string | ✅ | 去除首尾空白后的问题原文（与 `validate.py` 返回的规范化结果同源） |
| `asked_at` | string (ISO 8601 带时区) | ✅ | 如 `2026-09-27T20:31:38+08:00`。格式与 `index_manifest.json` 的 `built_at` 一致 |
| `embedding` | object | ✅ | 见 §3 |
| `vector` | array[1024] \| null | ✅ | 1024 个 float；`null` 表示向量化失败 |
| `status` | enum | ✅ | `ok` / `failed`（见 §4） |
| `error` | string \| null | ❌ | 仅 `status == "failed"` 时出现，记录失败原因（**已脱敏**，不含堆栈/路径） |

**字段顺序固定**（`answer_id` → `question` → `asked_at` → `embedding` → `vector` → `status` → `error`）：行内 `grep` 时字段顺序稳定，人眼扫一行就能拿到前几项，不必读到底。

### 为什么 `status` 与 `vector` 分开而非用 `vector: null` 一个信号

二者是**两件事**：
- `vector == null` 说"没有向量"；
- `status` 说"为什么没有"（还没算 / 算失败了）。

只留一个字段的话，"向量化失败"与"还没向量化"会混成同一个状态，而它们的处置完全不同（前者要查原因，后者只需重跑）。

## 3. `embedding` 对象 — 编码指纹

**逐字段复制** `backend/embed/model.py` 的 `fingerprint()` 返回值（10 个字段）。**不是重新算的**，是编码这个向量时实际用的那份。

| 字段 | 实测值（本期） | 作用 |
|---|---|---|
| `model_dir` | `E:\资料\BAAI--bge-m3` | 权重来源 |
| `config_sha256` | `26159e7a…49fa` | 配置变更检测 |
| `weight_file` | `pytorch_model.bin` | — |
| `weight_bytes` | `2271145830` | 权重要换没换，看这个最直接 |
| `max_length` | `4096` | 截断长度 |
| `pooling` | `cls` | 池化方式 |
| `normalization` | `l2` | 归一化方式 |
| `dtype` | `float32` | 数值类型 |
| `dim` | `1024` | 维度 |
| `rule_version` | `embed-v1+bge-m3` | 口径版本 |

**为什么每行都要带这一份**（而不是在文件头记一次）：

文件是按天切的，同一份文件里理论上可能混有**不同口径算出的向量**（比如上午用旧权重、下午换了新权重重启）。**一行一份指纹，意味着每一行自己就能被判定"这个向量是不是过期口径"** —— 而文件头记一次的话，这种混合状态根本表达不出来。

代价是每行多约 400 字节（相对 21 KB 的向量是 2%），换的是**每一行都可独立判定**。

## 4. 状态机

```text
        提交（通过校验）
              │
              ▼
        ┌──────────┐    编码成功     ┌────────┐
        │ 已落盘   │ ─────────────▶ │  ok    │   vector 非空
        │ (待编码) │                └────────┘
        └──────────┘                     ▲
              │  编码失败                 │
              ▼                          │
        ┌──────────┐                     │
        │ failed   │  vector = null ─────┘
        └──────────┘
```

**关键点**：**落盘与编码是同一个原子动作**（FR-033 要求二者同行）。因此不存在"已落盘但还没编码"的中间态被持久化 —— 要么一行完整（`ok`），要么一行完整（`failed`）。

这意味着**失败的行也占一行**，而不是"没写"。这是刻意的：`status == "failed"` 的行是**可重跑的工作队列**（FR-013 的幂等批量处理只处理 `failed` 与未出现的 `answer_id`）。

**被校验拒绝的输入（空、超长）不产生任何行**（FR-005）—— 它们在 `validate.py` 就被挡下，从未走到这里。

## 5. 编码与转义约定

| 项 | 取值 | 理由 |
|---|---|---|
| 编码 | UTF-8 | 中文 |
| `ensure_ascii` | `False` | 与 `backend/api/events.py` 同一约定 —— `grep` 得到的是中文而不是 `\uXXXX` |
| 分隔符 | `separators=(",", ":")` | 去掉空格，单行体积小约 5% |
| 行尾 | `\n`（显式 `newline="\n"`） | 不让平台默认值悄悄改写 |
| 换行 | JSON 转义为 `\n` 两字符 | 一行一条的前提 |

**已验证：float32 → JSON 文本 → float32 逐位无损**（4096 个随机样本全部相同）。这是 SC-010 成立的前提，不是假设。

---

## 6. 并发写的前提（**是个前提，不是保证**）

当前 `backend/serve.py` 以**单进程、单事件循环**运行，且写入路径中**没有 `await`**，因此两个请求的写入不可能交错。

**这个保证依赖两个条件，任一被打破就失效：**

1. 不用 `uvicorn --workers N`；
2. 写入路径中不引入 `await`（例如"异步落盘"）。

两条都成立时，整行一次 `write()` 是安全的。若将来要打破，需要改用文件锁（Windows 上 `msvcrt.locking`）。

**这段前提 MUST 出现在 `backend/query/store.py` 的模块注释里** —— 否则后来者会把它当成"本来就是并发安全的"，而在加 worker 的那天得到一个只在并发下出现、且破坏的是数据文件本身的问题。

## 7. 实体关系

```text
AskRecord (1) ──── embedding (1) : 编码指纹，复制自 Encoder.fingerprint()
     │
     ├─── vector (0..1) : 1024 维 float32，L2 范数 = 1
     │
     └─── answer_id ──── 关联到 SSE status/done 帧 ──── 关联到服务端日志
```

**`answer_id` 是唯一的关联键**，它同时出现在：留存记录、SSE 首帧、SSE 终帧、服务端日志。四处的值 MUST 相同 —— 这是 SC-004（可定位）在两条链路（问答 / 留存）之间的落点。
