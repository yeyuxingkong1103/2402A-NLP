# 03 · 数据管线设计

> **环节**：从 PDF 到可检索的知识库。五步：**解析 → 清洗 → 分块 → 向量化 → 入库**（v1 已定型，v2 未改动构建侧）。
> 代码入口：`backend/app/pipeline.py`（BuildPipeline），各步实现见 `backend/app/`。

## 一、管线流程

```
PDF ─(MinerU 3.4.5 pipeline / pypdf 兜底)→ 内容块 MinerUBlock[](page/label/text/source_span)
   ─(VLM 后处理 qwen-vl-plus)→ 表格/图片块 Markdown 回填
   ─(clean_text)→ 清洗后文本
   ─(build_chunks)→ Chunk[]（max_chars=800 截断）
   ─(BGE-M3)→ dense(1024) + sparse
   ─(QdrantVectorStore.upsert_chunks)→ data/qdrant/ rag_documents
```

## 二、各步关键决策

| 步 | 关键决策 | 实现 |
|---|---|---|
| **解析** | MinerU 3.4.5 pipeline（`doc_analyze_streaming`，本地模型）；**需 transformers 5.x + `scripts/patch_mineru_tf5.py` 兼容补丁**（PP-DocLayoutV2 的 hgnet_v2 backbone，否则 layout 全空静默回退 pypdf）；失败/空结果自动回退 pypdf 段落提取 | `mineru.py`、`patch_mineru_tf5.py` |
| **VLM 后处理** | 仅处理非纯文本块（table/figure/image/formula 等）；渲染页面 PNG → `qwen-vl-plus`（DashScope 兼容接口）转 Markdown → 按 source_span 回填 | `mineru_vlm.py`、`vision.py` |
| **清洗** | 去空行/首尾空白（`clean_text`），不丢元数据 | `chunking.py` |
| **分块** | 按 MinerU 块为单位；`max_chars=800` 超长截断；保留 `document_id/page/category/source_span`；`page<1` 拒绝入库 | `chunking.py` |
| **向量化** | BGE-M3 本地模型；FlagEmbedding 1.4.2（完整模型目录）优先，否则 sentence-transformers 兜底；dense 1024 维 | `embeddings.py` |
| **入库** | Qdrant embedded；named vectors `dense`(1024, Cosine) + `sparse`；payload=Chunk 全字段；Point id=chunk_id(UUID) | `vector_store.py` |

## 三、数据形态（每步产物）

| 步 | 产物 | 说明 |
|---|---|---|
| 上传 | `data/{uuid}-{清洗后文件名}.pdf` | 非 PDF 拒绝；非法字符（`\/:*?"<>|`）替换为 `_` |
| 解析 | `MinerUBlock[]` | page(1-based) / label(类别) / text / source_span(`page=N:block=M` 或 `page=N:fallback=M`) |
| 清洗 | 清洗后文本 | 去空行、去首尾空白 |
| 分块 | `Chunk[]`（state.json `chunks` 段） | 当前库实测 **198 chunk**（覆盖 p1–p15，类别：正文），多文档/多任务记录并存 |
| 向量化 | dense 1024 + sparse(indices/values) | FlagEmbedding 用 `lexical_weights`；ST 兜底用字符计数哈希 |
| 入库 | Qdrant `rag_documents` collection | 198 点，dense+sparse 双向量 + payload |

## 四、质量保障

- **page 级评测**（recall@k / MRR / refusal_accuracy）——单文档库用 `expected_page`（标准页）判定，比文档级有区分度
- **诚实覆盖**：构建失败不产生半成品——任务与文档标记 failed + error_message 保留（NFR5）
- **失败可诊断**：每个步骤异常都会落到任务 `error_message`，前端可展示
- **评测集红线**：`eval/sets/README.md` 要求评测问题必须来自真实 PDF 内容或真实用户查询，不编造数据
