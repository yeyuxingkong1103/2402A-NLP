## 3. 队列消费验证（场景 B 验收取证）

工单要求场景 B 中「文档解析任务正常进入队列并被消费」。使用
`tools/verify_queue.py` 连续上传多个文档并轮询任务状态，验证入队 → 消费 → 入库全链路。

### 3.1 验证结果（真实运行 · `output/loadtest/queue_verify.json`）

| 指标 | 实测值 | 说明 |
|------|--------|------|
| 提交任务数 | **12** | 连续上传 12 份样例 PDF |
| 提交总耗时 | **0.326s** | API 仅入队，立即返回（不阻塞） |
| 入队后队列深度峰值 | **10** | 证明任务真实进入队列 |
| 完成 / 失败 / 残留 | **12 / 0 / 0** | 全部被消费为 `done` |
| 消费总耗时 | 68.55s | 2 worker × `parse_sem=2` 并发消费 |
| 单文档解析耗时 | 均值 11.03s（7.66s ~ 16.46s） | 受 `parse_max_pages=40` 限制 |
| 累计入库知识块 | **1182** | 解析产物已入库，可被检索 |

**消费时间线（节选）**：`t=1.0s` 待完成 12 → `t=11.4s` 完成 1 → `t=35.9s` 完成 6
→ `t=68.5s` 完成 **12**（队列清空）。

**服务端交叉验证**（`GET /health` 的 executor 统计）：
`workers=2, done=12, failed=0, queue={backend:memory, depth:0, enqueued:12, dequeued:12}`
——`enqueued == dequeued == done == 12`，入队与消费完全配平，**队列验收通过**。

## 6. 测试结论

1. 10 项功能用例全部通过，接口契约与 RAGFlow / OpenAI 对齐；
2. 队列链路（入队 → 异步消费 → 知识入库 → 可检索）真实跑通；
3. 验收标准对照见 §5，核心性能与稳定性指标全部达标（详见性能测试报告）；
4. 已知限制：沙箱无 Docker/Redis 与 GPU 直通，相关等价观测手段已在报告中说明。
