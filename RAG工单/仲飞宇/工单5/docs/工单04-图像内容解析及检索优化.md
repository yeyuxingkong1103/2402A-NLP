# 工单04 · PDF 文档的图像内容解析及检索优化

> 工单编号：**人工智能NLP-RAG-图像内容解析及检索优化**
> 在工单01→03 的问答系统上，用**多模态模型**解析 PDF 里的图表与组织结构图，
> 使 16 道题（既有 14 题 + 新增 2 题）可被检索回答。

---

## 一、工单要求与本次难点

工单要求加入图像内容解析，实现下列 16 题的检索回复（准确率 ≥90%、响应 ≤3s），
并在备注里点名：**「PDF 中的图像语义解析使用多模态模型（CLIP 或多模态大模型）实现」**。

新增的两道题，答案**都在图上**：

| 题 | 问什么 | 答案在哪 | 形态 |
|---|---|---|---|
| id=5 | 组织结构图中，销售部有几个部门、大客户销售部有几个销售处 | 书2 **页 38** | **矢量图**：方框用 drawing 画，标签在文本层 |
| id=6 | IC 图表中增长率最快/负增长的是哪个行业 | 书2 **页 71** | **位图**：638×479 + 525×473 两张 jpeg 并排 |

难点有三，每一处都能静默出错：

1. **噪声淹没信号**：书2 的 `get_image_info()` 返回 **5920 个图像实例**，其中
   **98.2% 是噪声**（1 像素细条、每页重复 15 次的水印、小 logo）。不过滤，
   VLM 的调用会全部浪费在分隔条上。
2. **矢量图和"表格框线"长得一样**：`get_drawings()` 在书1 有 319 页、书2 有 138 页
   图元数 ≥15 —— 因为**招股书满页都是表格，表格框线也是 drawing**。
   按"图元多"判，判出来的是表格。
3. **答案是图里的一行字**：id=6 问的"负增长的是哪个行业"，正文里**根本没有**
   （正文只写了"工业控制 7%、增长率 10.5%、位列第二，仅次于汽车电子"，
   连"最快"都是从这句推出来的）；id=5 的"6 个销售处"在文本层里是一串
   没有层级的 run-on。

## 二、三个关键设计判断

### 2.1 VLM 只在**入库期**用，问答期零改动

验收要求"提问到回答 ≤3 秒"。3B 视觉模型读一张图要 **2 秒左右**（实测），
如果放在查询期，这个指标必挂。所以图在**入库时**就被转写成文字进了知识库，
问答期走的还是原来的纯文本链路（bge-m3 双路召回 + qwen3 生成），**一行都没改**。

### 2.2 为什么用多模态大模型而不是 CLIP

工单备注允许"CLIP 或多模态大模型"。选后者的理由：

- CLIP 给的是**图文相似度**，不是文字。要让它派上用场，得给 Milvus 加一路
  CLIP 向量（schema 建表即定死，必须重建库），并在查询侧再挂一个 CLIP 文本编码器。
- 而且它**回答不了**"销售部有几个部门"这种计数题 —— CLIP 没有计数能力。
- 多模态大模型把图**读成文字**，直接复用现有链路，代价只在入库那一次。

### 2.3 转写结果可人工覆写 —— 这是 VLM 会读错的必然要求

实测页 71 的柱状图，qwen2.5vl:3b 把七个类别的数值**全读对了**，却把最上面那条
`-2.0%` 的归属记成了"计算机"（实际是 **IC卡**），还把饼图里 `汽车/IC卡` 的数值
对调了。而 id=6 问的恰恰是"负增长的是哪个行业"。

所以缓存里存两个字段：`vlm_text`（模型原始输出）与 `reviewed_text`（人工修正），
`effective_text` 取后者优先。**不直接改 vlm_text 是有意的**：验收时要能说清
哪些是模型读的、哪些是人工校正的，否则等于把人工结果冒充成模型能力。

## 三、实现

### 3.1 图区定位（`app/core/figure_locator.py`）

**位图：四道过滤 + 一次合并**

| 规则 | 阈值 | 杀掉什么 |
|---|---|---|
| R1 最短边 | <32px | `1x394 / 1x914 / 1x1304` 的 1 像素细条 |
| R2 同页同 xref | 出现 ≥3 次 | 页眉水印 `143x127`（**每页重复 15 次**） |
| R3 同 xref 跨页 | 出现 ≥3 页 | 同上，及其变体（预扫描一次建全局计数） |
| R4 版面面积占比 | <2.4% | 小 logo / 图标 |
| R5 版面面积占比 | **>60%** | 整页扫描件（签字页、封面、附录） |

**R5 要在合并之后再判一次**：书2 的签字页是 8 条位图拼成的，单条只占 11%，
合起来才是整页 92% —— 只看单条会漏掉它们（实测书1 因此从 29 个图区降到 16 个）。

合并规则（"**宁合不拆**"）：并排面板（y 重叠 >60% 且水平间隙 <30pt）或
上下堆叠（x 重叠 >60% 且垂直间隙 <20pt）即并成一块。页 71 的饼图 + 柱状图
因此合成一个图区（`src_bboxes` 长度 = 2，留痕可查）。
**拆开的代价是致命的**：只转写饼图就丢掉了柱状图，而"负增长的是哪个行业"只在柱状图上。

**矢量图：双判据，在 898 页上验证零误判**

```
① 本页没有行数 ≥8 的表格          ← 排除书2 页 207–218 的旋转财报页
② 块级 bbox 满足「宽≤22 且 26≤高≤120 且含≥2 汉字且不含数字」的块 ≥5 个
```

命中：书2 页 37、38；书1 页 59 —— 全是真组织结构图/流程图。

- **必须用块级 bbox，不能用 span 级**：竖排标签在 span 级被逐字拆开
  （实测页 38 在 span 级命中 **0**、块级命中 **17**）。
- **必须加条件①**：书2 页 207–218 是旋转 90° 的合并股东权益变动表，
  其文本块天然"窄而高"，没有①会把 8 页财报全判成组织结构图。
- **高度上限 ≤120 也必需**：组织结构图的标签是**一个词**（h=31.5~84），
  旋转页的"标签"是**整行**（h=690~764）。

**题注锚定**：取图区上方 ≤40pt 内最像题注的文本块；找不到且图在页顶（<15% 页高）时，
回退到**上一页**末尾 —— 实测组织结构图的题注「1、公司组织结构图」印在页 37、
图体在页 38，是一张跨页的图。

### 3.2 多模态转写（`app/core/vision.py`）

`OllamaClient` 原本是**纯文本客户端**（模型名写死、`messages` 类型装不下图片），
本工单做了四处向后兼容的改造：`_payload()` 支持 `model`/`keep_alive`/`extra_options`、
`chat()` 支持 `images`（挂到最后一条 user 消息 —— 这是 Ollama 原生协议的位置，
挂到别的 role 上会被**静默忽略**）、超时外置到配置、新增 `unload()`。

**显存时序**（8GB 卡的硬约束，实测 qwen3:8b 常驻 5.58GB + 3B VLM 约 3.2GB 装不下）：

```
parse(CPU) → unload(聊天模型) → 逐图转写(VLM) → unload(VLM) → chunk/dedup(CPU) → embed(bge-m3) → insert
```

转写与嵌入天然错峰（转写在 embed 之前全部结束）。若不主动赶走聊天模型，
Ollama 会**被动**淘汰一个 —— 那意味着下一个提问要付一次数秒冷启动。

**提示词按图的类型分两套**，`temperature=0`、`num_predict=800`：

- `chart`：逐项输出「类别：数值」，**要求标出正负号**、禁止用行业常识补全。
- `diagram`：按层级缩进输出每个方框的文字，并把**文本层标签一并塞进 prompt 当锚**
  —— 页 38 的 17 个标签在文本层里与原文逐字一致，拿它当锚能让模型不去"猜字"。

### 3.3 转写缓存（`app/core/image_cache.py`）

**内容寻址**：key = `sha256(PNG 字节 + 模型名 + 提示词版本)[:16]`。于是：

- 改 dpi / 换模型 / 改提示词 → key 变 → 自动重跑；没变的继续命中。
- 缓存里同时存一份 `{key}.png` —— 本机没装 poppler，这是**唯一能亲眼核对图**的途径
  （`scripts/transcribe_images.py --dump-png 71 /tmp/x.png`）。

**实测缓存收益**：全量重建时书2 的 33 张图 **33 次缓存命中、0 次 VLM 调用、0.6 秒**
（首次转写用了 71 秒）。开发期改提示词、核对、重跑都不必重付这笔钱。

### 3.4 入库与检索

- 新增一个 **`figure` 阶段**夹在 `parse` 与 `chunk` 之间（转写是网络 I/O，
  而 parse 跑在 `to_thread` 里；转写结果必须回填到 `Figure.text` 上）。
- `chunk_type` 新增取值 **`image`**（与 `vectorstore.py` 建表注释里预留的
  `text / table / image` 一致，`VARCHAR(16)` 无枚举约束，**不需要改 schema**）。
- 图块与表格同属**原子块**（`chunker.is_atomic_chunk`）：
  - `build_context` **不切窗口** —— 图块转写常超 600 字，而"负增长"那一行排在末尾，
    切窗口正好切掉它（与工单01 的 id=793 是同一类失败）；
  - 邻块扩展里**不受互补性过滤**（图块与"引子句"常无共同查询词）。
- **只给图块的片段头加「（图）」**：text/table 的拼装字节一个都不动 ——
  否则前 14 题的 prompt 会逐字节改变，既打掉 Ollama 的前缀 KV cache，
  又可能把已交付的 14/14 搅了。

## 五、口径声明（看数字前必须知道的三件事）

### 5.1 id=5 的判据在 15:xx 之前是错的，已修正

第一轮评测这道题判"未命中"，`rule_detail` 显示只命中 10 个关键词里的 1 个。
但**模型的答案是「销售部由4个部门构成，大客户销售部有6个销售处构成」** ——
问题问的就是"**有几个**"，它答了 4 和 6，**完全正确**。

错的是我最初把 `rule_keywords` 写成了要求**枚举全部名字**
（渠道销售部/电话及网络销售部/…/珠海/深圳/…）。那是**判据写错了**，
不是系统答错了。现在改成直接校验问题真正问的那两个数：`["4个部门", "6个销售处"]`。

> 这正是「规则化命中」这一轨的用法：它必须**贴着问题的问法**来写。
> 写成"更严格的额外要求"，得到的是**假阴性**。

### 5.2 id=5 的 CKC 是 0.0%，这不是故障

CKC 问的是"`rule_keywords` 在召回上下文里覆盖了多少"。id=5 的关键词是
「4个部门 / 6个销售处」这两个**计数短语** —— 它们在**图块里**是枚举（部门名/处名列表），
**没有**"4 个部门"这样的字面表述。所以 CKC=0 而模型答对，是**判据与指标的错配**，
不是检索没召回。判断 id=5 的检索质量要看 `citations`（引用页含 38）与答案本身。

### 5.3 书1 有 7 张图转写失败，不影响验收

`qwen2.5vl:3b` 对**复杂 3D 插图**有硬缺陷：实测页 1-1-223（openVone 视音频中间件
示意图，一张 3D 建筑渲染图）会让模型**坍缩成重复的 `@` 字符**，Ollama 中断并返回
`500 {"error":"prediction aborted, token repeat limit reached"}`。

穷举验证过，以下手段**都无效**：改提示词、降到 80dpi、换 JPEG 编码、
提高温度（0.7/1.0）、加大上下文（8192/16384）、提高 repeat_penalty（1.3）、
换编码格式。是模型能力边界。

影响面：书1 16 张里失败 7 张，**书2 33 张全部成功** —— 而两道新题都在书2。
失败的图块**保留题注与图内文字**（不静默消失），失败数记在
`st.stats["figure"]["failures"]` 与缓存记录的 `note` 里。

## 六、顺带修掉的缺陷

| 缺陷 | 后果 | 修法 |
|---|---|---|
| VLM 调用无重试 | 瞬时 500 会让整张图的语义**永久缺失**（缓存里存了失败记录，重跑还被当成命中） | 3 次重试 + 指数退避；且**失败记录不算缓存命中** |
| Ollama 的"重复死循环"闸 | 某些图直接 500，无任何提示 | 加 `repeat_penalty`/`repeat_last_n`，并把 500 的报文如实记进缓存 `note` |
| `n_empty_pages` 判据 | 只有图的页会被算成"空页"（统计失真） | 把 `figures` 纳入判据 |

## 七、已知限度与推迟项

1. **书1 的 7 张复杂插图转写不了**（见 5.3）。要补的话得换 7B 级 VLM
   （再下约 6GB，且不保证能解），或对这些页改用 OCR + 版面分析。
2. **id=6 的关键词是大小写敏感的**："IC卡" 能命中，"ic卡"/"IC 卡"不能。
   实测模型稳定输出"IC卡"，故保留；若换模型需重新核对。
3. **题注不一定准**：页 38 的题注取到了图里的方框名（真题注在上一页），
   图块靠 `section_path` 兜底（`… > 四、发行人组织结构 > 1、公司组织结构图`）。
4. **49 个图区里有约 3 个是业务流程图/产品照片**，转写出来的文本对检索
   帮助有限（不致命，图块占比 46/1848 = 2.5%）。
5. **没有为书2 的 8 页旋转横向表做图像解析**（它们的文字层完整，不需要）。
6. **演示视频**需人工录制（见 `docs/工单04-演示截图清单.md`）。

## 八、复现命令

```bash
PY=~/rag-data/venv/bin/python

# 0. 环境自检（29 项，含工单04 的图区定位与转写缓存探针）
$PY scripts/preflight.py

# 1. 多模态模型（一次性）
ollama pull qwen2.5vl:3b

# 2. 起向量库
docker compose -f docker-compose.milvus.yml up -d

# 3. 图像转写作业台（不碰 Milvus，可反复跑）
$PY scripts/transcribe_images.py --scan          # 只解析 + 查缓存
$PY scripts/transcribe_images.py --run           # 真跑 VLM（缓存命中会跳过）
$PY scripts/transcribe_images.py --list          # 一览：页/类型/题注/是否已核对
$PY scripts/transcribe_images.py --dump-png 71 /tmp/x.png   # 导出图肉眼核对
$PY scripts/transcribe_images.py --review 71     # 编辑 reviewed_text（人工覆写）

# 4. 入库（图像解析随流水线自动发生）
$PY scripts/ingest_all.py --rebuild --yes
$PY scripts/ingest_all.py --status               # 每份文档的块数与 image 数

# 5. 16 题评测 —— 本文第四章的数字来源
$PY scripts/eval.py --profile optimized

# 6. 测试
$PY -m pytest tests/ -v                          # 58 passed
```
