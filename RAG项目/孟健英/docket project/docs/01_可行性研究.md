# 1. 可行性研究报告

## 1.1 项目背景

对标 Character.ai，构建一个基于 RAG（检索增强生成）架构的医疗智能助手"医小助"。
系统支持西医医生 / 中医 / 心理医生三种角色一键切换，具备多轮对话、指南级知识增强回答、
急症安全拦截、短期/长期记忆，并对每条回答给出可溯源的指南引用。

## 1.2 业务可行性

| 维度 | 分析 | 结论 |
|------|------|------|
| 目标用户 | 高血压等慢性病患者、健康咨询者 | ✅ 需求明确 |
| 核心价值 | 就医前获取基于权威指南的健康科普，降低信息差 | ✅ 有实际意义 |
| 边界约束 | 不做确定性诊断、不开处方，页面全程免责声明 | ✅ 风险可控 |
| 商业模式 | 课程设计/学习演示项目，非商业运营 | ✅ 无需考虑 |

## 1.3 技术可行性

| 技术组件 | 选型 | 部署方式 | 成熟度 |
|---------|------|---------|--------|
| 向量库 | Milvus 2.4（standalone） | Docker 容器 | ⭐⭐⭐⭐⭐ 生产级 |
| 向量化模型 | BGE-m3（1024 维） | **本地部署**（项目外 models 目录） | ⭐⭐⭐⭐⭐ 中文 SOTA |
| 重排模型 | bge-reranker-v2-m3 | **本地部署**（项目内 models/） | ⭐⭐⭐⭐⭐ 效果好 |
| 大模型 | DeepSeek-chat | 在线 API（OpenAI 兼容） | ⭐⭐⭐⭐⭐ 合规低成本 |
| RAG 框架 | LangChain + 原生编排 | pip 依赖 | ⭐⭐⭐⭐⭐ 社区活跃 |
| 短期记忆 | Redis 7（List + TTL） | Docker 容器 | ⭐⭐⭐⭐⭐ 稳定 |
| 长期记忆 | Milvus（user_memory 集合） | 与知识库同实例 | ⭐⭐⭐⭐ 可行 |
| 用户/角色 | roles.json 配置化 | 本地文件 | ⭐⭐⭐⭐ 免部署、易扩展 |
| 关键词检索 | BM25（rank_bm25 + jieba） | 进程内索引 | ⭐⭐⭐⭐⭐ 轻量 |
| PDF 解析 | PyMuPDF（页眉页脚/水印/表格） | pip 依赖 | ⭐⭐⭐⭐⭐ 轻量 |
| 图片 OCR | PaddleOCR（可选演示） | 按需安装 | ⭐⭐⭐⭐ |
| 评测 | RAGAS 0.2 + pytest 8 | pip 依赖 | ⭐⭐⭐⭐ RAG 标准 |
| 界面 | Streamlit | WSL Ubuntu / Python 3.10 | ⭐⭐⭐⭐ 快速演示 |

结论：**技术栈全部成熟，两个大模型本地加载、DeepSeek 仅承担生成，无硬阻塞**。

## 1.4 数据可行性

系统实际入库的权威资料（`data/guidelines/`）：

| 数据源 | 发布机构 | 类型 | 用途 |
|--------|---------|------|------|
| 《国家基层高血压防治管理指南（2025 版）》 | 国家卫健委 | PDF（约 1.3MB） | 西医问答主知识库 |
| 《成人高血压食养指南（2023 年版）》 | 国家卫健委 | PDF（约 1.9MB） | 饮食/食养知识补充 |

- PDF 经自研解析管线（页眉页脚剥离、水印过滤、表格转 Markdown）后按页切块（55 字/块、8 字重叠），
  BGE-m3 向量化入库，当前知识库约 2400+ 个片段。
- 角色人设来源于 `data/roles.json`（3 个角色，含 system_prompt、禁用术语、检索偏向）。
- 支持追加 PDF/TXT 增量入库（`scripts/04_update_kb.py`），数据可持续扩充。

## 1.5 合规与风险

| 风险 | 应对措施 |
|------|---------|
| 医疗误导 | 急症关键词拦截 + 药物白名单校验 + 角色禁用术语过滤 + 全程免责声明，不做确定性诊断 |
| 越角色作答（西医讲中医） | 角色 banned_terms 后置过滤 + system prompt 自检约束 |
| 模型幻觉乱引药名 | 只把重排分 ≥ 阈值的片段给 LLM；回答中药名与知识库原文做白名单比对 |
| 数据隐私 | Redis 短期记忆 TTL 30 分钟自动过期；不收集真实身份信息 |
| API 成本/超时 | DeepSeek 单次超时 30s、max_retries=0；无命中走短提示兜底，控费控时 |
| 服务依赖故障 | Redis/Milvus/reranker 任一不可用时自动降级，主流程不中断 |

## 1.6 结论

**业务边界清晰、技术选型成熟、数据权威可扩、风险有护栏兜底，项目完全可行，建议立项开发。**
