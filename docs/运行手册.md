### 1.3 Milvus 与 Redis（WSL 内）

本项目依赖 WSL 中已部署的 Milvus standalone 容器与 Redis 服务：

```powershell

wsl -e bash -lc "docker start milvus-standalone"

# 启动 Redis
wsl -e bash -lc "sudo service redis-server start"
```

| 服务 | 地址 | 凭据 |
| --- | --- | --- |
| Milvus | `http://127.0.0.1:19530` | 无 |
| Redis | `127.0.0.1:6379` | 密码 `123456`，db 0 |

> 本机另有一条 `netsh portproxy 0.0.0.0:19530 -> 172.29.33.179:19530` 的端口转发（用户原项目遗留），Milvus 端口依赖 WSL 容器处于运行状态。

验证连通：

```powershell

wsl -e bash -lc "redis-cli -a 123456 ping"
```

## 3. 知识库入库

```powershell
$py = 'D:\an\envs\rags_\python.exe'
$env:PYTHONIOENCODING='utf-8'

& $py tools\ingest_cli.py --all --recreate     # 重建并入库全部启用角色 + 公共库（14 篇 → 78 块，约 56s）
& $py tools\ingest_cli.py --roles scientist    # 只入库某个角色
& $py tools\ingest_cli.py --file data\kb\lawyer\01_contract_basics.md --role lawyer
& $py tools\ingest_cli.py --report             # 只看知识库现状
& $py tools\kb_health.py                        # 知识库健康检查（源文件 -> 分块 -> 入库 是否对得上）
& $py tools\ingest_cli.py --delete-scope lawyer # 删除某角色的知识块
& $py tools\ingest_cli.py --reset              # 重建集合（清空全部）
```

入库完成后 `kb:version` 会自增，检索缓存与 BM25 内存索引自动失效重建。

知识库目录约定：

```text

├─ shared/            # 公共知识，所有角色可见（2 篇）
├─ financial_planner/ # 金融理财师（4 篇）
├─ scientist/         # 科学家（4 篇）
└─ lawyer/            # 律师（4 篇）
```

## 6. API 示例

### 6.1 登录并保存令牌（PowerShell）

```powershell
$base = 'http://127.0.0.1:8020'
$login = Invoke-RestMethod -Method Post -Uri "$base/api/auth/login" `
    -ContentType 'application/json' `
    -Body '{"username":"alice","password":"alice123"}'
$token = $login.token
$h = @{ Authorization = "Bearer $token" }
```

### 6.2 查看健康状态与可用角色

```powershell
Invoke-RestMethod -Uri "$base/api/health"
Invoke-RestMethod -Uri "$base/api/roles" -Headers $h | ConvertTo-Json -Depth 5
```

### 6.3 流式问答（SSE）

```powershell
$body = @{ role_id = 'lawyer'; question = '试用期最长可以约定多久？' } | ConvertTo-Json
Invoke-WebRequest -Method Post -Uri "$base/api/chat" -Headers $h `
    -ContentType 'application/json' -Body $body
```

SSE 事件类型：`meta`（会话 / 角色 / 召回统计）→ `delta`（增量文本）→ `citations`（引用片段）→ `done`。

### 6.4 检索调试与四路对比

```powershell
$q = @{ role_id = 'lawyer'; query = '试用期最长多久'; mode = 'hybrid'; top_k = 6 } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "$base/api/retrieval/search" -Headers $h `
    -ContentType 'application/json' -Body $q | ConvertTo-Json -Depth 6

$c = @{ role_id = 'lawyer'; query = '试用期最长多久' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "$base/api/retrieval/compare" -Headers $h `
    -ContentType 'application/json' -Body $c | ConvertTo-Json -Depth 6
```

### 6.5 会话与记忆

```powershell
Invoke-RestMethod -Uri "$base/api/sessions" -Headers $h | ConvertTo-Json -Depth 5
Invoke-RestMethod -Uri "$base/api/sessions/<session_id>" -Headers $h
Invoke-RestMethod -Uri "$base/api/memory" -Headers $h | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri "$base/api/memory/clear" -Headers $h `
    -ContentType 'application/json' -Body '{"scope":"all"}'
```

### 6.6 知识库与任务（管理员）

```powershell
Invoke-RestMethod -Uri "$base/api/kb/status" -Headers $h | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri "$base/api/kb/ingest" -Headers $h `
    -ContentType 'application/json' -Body '{"roles":["lawyer"],"recreate":false}'
Invoke-RestMethod -Uri "$base/api/jobs" -Headers $h | ConvertTo-Json -Depth 5
```

## 8. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `check_env.py` 报 Milvus `[FAIL]` | WSL 容器未启动 | `wsl -e bash -lc "docker start milvus-standalone"` |
| Milvus 连接被拒绝 / 超时 | 端口转发对端不可达 | 确认容器运行；确认 `netsh portproxy` 指向的 WSL IP 未变（WSL 重启后 IP 可能变化） |
| Redis `[FAIL]` | 服务未启动或密码不符 | `wsl -e bash -lc "sudo service redis-server start"`；确认 `redis.password=123456` |
| `unsupported ID type` | 长期记忆集合为空时走原生 `hybrid_search` | 已修：空集合跳过原生混合检索（`_memory_has_rows()` 30s 探针）；若自定义代码绕开该判断需自行判空 |
| `LocalProtocolError: Too much data for declared Content-Length` | 某个 204 / 304 响应带了 body。h11 对这两个状态码强制按 `Content-Length: 0` 分帧，多发的字节会直接报错断连 | 已修：`/favicon.ico` 原用 `JSONResponse(status_code=204, content=None)`，而 `JSONResponse` 会把 `None` 渲染成 `b"null"`（4 字节）；现改为 `Response(status_code=204)`。自定义路由返回 204 / 304 时请务必使用无 body 的 `Response` |
| `mat1 and mat2 must have the same dtype` / `cannot import name 'AutoModel'` | 预热线程与请求线程并发加载模型 | 已修：`_lock` 双检锁，发布前不赋值 `self.model`；如自行扩展模型类需保持同一模式 |
| `CUDA out of memory` | 显存不足 | 确认 `dtype: float16`；降低 `models.embedder.batch_size`；关闭并行大请求；必要时 `ROLE_RAG_DEVICE=cpu`（很慢） |
| 端口 8020 被占用 | 已有实例在跑 | `.\start.ps1 -Port 8030`，或结束占用进程：`Get-NetTCPConnection -LocalPort 8020 \| Select OwningProcess` |
| 控制台中文乱码 | 控制台代码页非 UTF-8 | 先 `$env:PYTHONIOENCODING='utf-8'; [Console]::OutputEncoding=[Text.Encoding]::UTF8` |
| 退出时打印 `multiprocess resource_tracker` 的 `_thread.RLock` 报错 | 已知无害噪声（`rags_` 环境 + multiprocess 后台线程） | 忽略；测试仍 `exit 0` |
| 首个提问很慢 | 模型懒加载 / 预热未完成 | 等待预热完成（约 25.9s）或保持 `app.warmup=true` |
| 回答「知识库中没有相关内容」 | 该角色知识未入库或问题超出范围 | 跑 `ingest_cli.py --report` 确认块数；必要时 `--all --recreate` |
| 登录后接口 403 | 角色未授权给该用户 | 换用有权限的账号，或修改 `security.users_seed` 后重建用户（见下） |

用户种子仅在 Redis 无 `users` 键时写入，修改 `users_seed` 后需先清理：

```powershell
wsl -e bash -lc "redis-cli -a 123456 DEL rolerag:users"
```

## 9. 日志与数据清理

- 日志：`logs/app.log`（全量）、`logs/error.log`（错误）；也可查 `GET /api/logs`
- 检索缓存：`wsl -e bash -lc "redis-cli -a 123456 --scan --pattern 'rolerag:cache:*' | xargs redis-cli -a 123456 DEL"`
- 全部业务键（谨慎）：`wsl -e bash -lc "redis-cli -a 123456 --scan --pattern 'rolerag:*' | xargs redis-cli -a 123456 DEL"`
- 知识库：`ingest_cli.py --reset` 或 `POST /api/kb/reset`
