# 金融问答系统 · 研发文档

> **工单编号：人工智能 NLP-RAG-金融问答系统部署**
> 任务：将已开发的金融问答系统（RAG）以 Docker 容器的形式部署在服务器中，并运行成功
> 前置工单：01 基于 PDF 的问答 → 02 优化 → 03 表格解析 → 04 图像解析 → 05 Query 理解 → 06 混合检索 → 07 功能测试及评估

---

## 一、研发目标与范围

本工单**不新增问答算法**，研发工作聚焦于**容器化交付工程**：

1. 把前序工单已跑通的 RAG 金融问答系统（多嵌入模型向量召回 + 倒排索引全文检索 + 混合融合 + 重排 + 多轮理解）
   打包为可交付镜像 `finqa:1.0`；
2. 通过 `docker run` / `docker compose` 在 **8501** 端口提供服务；
3. 满足容器管理三类验收：**启动与运行**、**数据管理**、**网络配置**；
4. 全链路代码注释统一带工单编号 `人工智能 NLP-RAG-金融问答系统部署`。

## 四、核心模块说明（`src/`）

### 4.1 配置与类型

| 模块 | 关键定义 | 职责 |
|---|---|---|
| `config.py` | 常量 | 路径、模型、检索与多轮参数、`TARGET_ACCURACY` 等默认配置 |
| `retrieval_config.py` | `RetrievalConfig` | 检索策略（`vector`/`fulltext`/`hybrid`）、融合方式、召回数、重排池等运行时配置 |
| `retrieval_types.py` | `Retrieved` | 召回结果的统一数据结构（chunk_id / score / source / page / kind） |
| `i18n.py` | — | 中英文提示与拒答文案 |

### 4.2 数据与索引层

| 模块 | 关键定义 | 职责 |
|---|---|---|
| `pdf_parser.py` | `PageData` | PDF 解析（文本 / 表格 / 图像页），输出按页结构化数据 |
| `chunking.py` | `Chunk` | 分块（含页号、来源、类型标注） |
| `knowledge_base.py` | `KnowledgeBase` | 知识库加载与查询：`chunks.jsonl` + 倒排索引 + 向量矩阵统一入口 |
| `inverted_index.py` | `InvertedIndex` / `_BoolParser` / `Node` | 倒排索引与 **BM25** 打分，支持 `AND/OR/NOT` 布尔表达式解析 |
| `embedding.py` | `Embedder` | 调用 Ollama 生成查询向量，含**查询编码缓存** |
| `figure_semantics.py` | `FigureSemantics` | 图形语义（图表/图像页的语义化处理） |

### 4.3 检索层

| 模块 | 关键定义 | 职责 |
|---|---|---|
| `vector_retriever.py` | `VectorRetriever` | 向量通道召回（余弦相似度） |
| `fulltext_retriever.py` | `FulltextRetriever` | 全文通道召回（倒排索引 + BM25，支持 `auto`/`bm25` 模式） |
| `hybrid_retriever.py` | `HybridRetriever` | **混合检索**：双通道召回 → RRF 融合 → 文档过滤 → 输出融合候选 |

### 4.4 重排与理解层

| 模块 | 关键定义 | 职责 |
|---|---|---|
| `rerankers.py` | `LinearFusionReranker` / `TfidfReranker` / `LLMReranker` / `AdaptiveFeedbackReranker` / `NoneReranker` | 多种重排器（默认 `linear`） |
| `query_understanding.py` | `QueryUnderstanding` / `QueryAnalysis` | 查询理解：实体识别、答案类型判定（amount/ratio/list…）、文档过滤依据 |
| `query_rewriting.py` | `QueryRewriter` / `RewriteResult` | 多轮改写：**指代消解**、**省略补全**、多语言归一 |

### 4.5 会话与答案层

| 模块 | 关键定义 | 职责 |
|---|---|---|
| `conversation.py` | `Conversation` / `Turn` | 多轮会话状态管理（历史轮次、实体记忆、重置） |
| `answer_builder.py` | `AnswerBuilder` / `Answer` | **抽取式答案合成**：按答案类型抽取关键句/数值，附证据溯源 |
| `qa_engine.py` | `QAEngine` / `QAResult` | **问答总编排**：改写 → 理解 → 检索 → 重排 → 合成，输出统一结果 |
| `feedback.py` | `FeedbackStore` | 用户反馈存储（供自适应重排） |

## 五、一次问答的调用链

```
app.py (Streamlit)
  └─ QAEngine.answer(question, conversation)
        ├─ QueryRewriter.rewrite()          # 多轮改写（指代消解 / 省略补全）
        ├─ QueryUnderstanding.analyze()     # 实体 / 答案类型 / 文档过滤
        ├─ HybridRetriever.retrieve()       # 向量 + BM25 双通道 → RRF 融合 → doc_filter
        ├─ Reranker.rerank()                # linear 重排（rerank_pool 剪枝）
        └─ AnswerBuilder.build()            # 抽取式答案 + 证据溯源
  └─ 返回 QAResult { answer, answer_type, doc, evidence[], latency }
```

对应真实验证产物：`output/multiturn_demo.json`（5 轮完整回放，含证据块）、
`output/smoke_test.json`（10 题端到端）、`output/functional_tests.json`（10 项功能用例）。

## 六、容器化研发要点

### 6.1 镜像分层（`Dockerfile`）

| 层 | 内容 | 说明 |
|---|---|---|
| 基础层 | `python:3.10-slim` | 无多余系统组件，减小体积 |
| 环境层 | `ENV`（UTF-8 / 时区 / pip 镜像 / Ollama 地址 / 端口） | 统一运行环境 |
| 依赖层 | `pip install -r requirements.docker.txt` | 依赖单独成层，改代码不重装依赖 |
| 应用层 | `COPY src/ app.py build_kb.py run_demo.py evaluate_ccf.py tools/ deploy/ data/ vector_db/ .env` | 内置知识库与索引，开箱即用 |
| 安全层 | `useradd appuser` + `chown` + `USER appuser` | 非 root 运行 |
| 健康层 | `HEALTHCHECK`（Python `urllib` 访问 `/_stcore/health`） | 不依赖 curl |

> **注意**：Dockerfile **不含任何 `apt-get`**——构建期 apt 源不可达是本工单的关键问题（见《实现步骤与问题记录》问题 6），
> 因此依赖全部走 pip，并以 `requirements.docker.txt` 精简。

### 6.2 数据持久化

| 命名卷 | 挂载点 | 承载数据 |
|---|---|---|
| `finqa_kb_vol` | `/app/vector_db` | 知识库索引（chunks / 向量矩阵 / 倒排索引） |
| `finqa_data_vol` | `/app/data` | 年报 PDF 与题集 |
| `finqa_out_vol` | `/app/output` | 运行产物、评测结果、共享数据 |

### 6.3 网络

- 自定义 bridge 网络 `finqa-net`，服务容器 IP `172.18.0.2`；
- `extra_hosts: host.docker.internal:host-gateway` 使容器可访问宿主 Ollama；
- 对端服务 `finqa-rtmp`（自建最小 RTMP 服务器）同网部署，验证「与其他服务正常通信」。

## 七、构建 / 运行 / 测试

```bash
# 构建
docker build -t finqa:1.0 .
# 启动
docker network create finqa-net 2>/dev/null || true
docker run -d --name finqa-app --network finqa-net -p 8501:8501 \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  -e EMBEDDING_MODEL_SLUG=bge-m3 -e TZ=Asia/Shanghai \
  --add-host host.docker.internal:host-gateway \
  -v finqa_kb_vol:/app/vector_db -v finqa_data_vol:/app/data -v finqa_out_vol:/app/output \
  --restart unless-stopped finqa:1.0

# 测试
docker exec finqa-app python deploy/smoke_test.py            # 端到端问答（10 题）
docker exec finqa-app python tools/run_functional_tests.py   # 功能/容错/稳定性（10 项）
docker exec finqa-app python tools/bench_latency.py          # 响应时间基准
bash deploy/verify.sh                                        # 容器管理验收（Linux）
powershell -File deploy/verify.ps1                           # 容器管理验收（Windows）
```

## 九、代码规范

1. **工单编号注释**：所有源码文件首部注释均含 `工单编号: 人工智能 NLP-RAG-金融问答系统部署`，
   镜像 `LABEL workorder` 与落盘结果 `workorder` 字段同步标注。
2. **配置外置**：运行参数通过 `.env` / 环境变量注入，代码内 `config.py` 提供默认值；
   `python-dotenv` 默认**不覆盖**已有环境变量，保证容器 `-e` 配置优先生效。
3. **结果落盘**：所有评测/验收脚本将结果以 UTF-8 JSON 落盘到 `output/`，便于复核与产物归档。
4. **脚本可复现**：`deploy/` 下脚本均为幂等或可重复执行，验收检查项逐条输出 `PASS/FAIL`。
