## 二、功能验收

### 2.1 问答准确性（≥ 90%）

| 要求 | 实现 | 验证方式 | 证据 |
|------|------|----------|------|
| 准确率 ≥ 90% | 关键词命中式判定（最小必要证据口径）：非拒答 + 关键信息点齐全 + 年份数量达标 | `python run_evaluation.py` | `results/evaluation.json` 字段 `keyword_accuracy.accuracy`（运行后生成） |

## 三、性能验收

### 3.1 响应时间不超过 3 秒

| 要求 | 实现 | 验证方式 | 证据 |
|------|------|----------|------|
| 单轮 ≤ 3 秒 | ① 指代消解**规则快速通道**（第 4 轮零 LLM 调用）；② LLM 磁盘缓存；③ `--fast` 用 TF-IDF 重排替代 LLM 重排；④ 闲聊/操作类短路不检索；⑤ 分解前的代价判断（短问题不调 LLM） | `python multi_turn_chat.py --fast` 查看每轮耗时与「3 秒约束」标记 | `results/multi_turn_conversation.md` 耗时汇总 + 逐轮「阶段耗时明细」 |
| 可定位瓶颈 | `trace["timings"]` 记录 query_understanding / vector_recall / fulltext_recall / fusion / rerank / generate | 查看 JSON/表格中的 timings | `results/multi_turn_conversation.json` |
| 服务侧延迟观测 | `rag_core.api` 的 `/api/metrics` 输出 avg / P50 / P95 / max 延迟 | `curl http://127.0.0.1:8000/api/metrics` | 接口返回 |
| 达标率统计 | `latency_summary()` 输出「3 秒达标率」 | 脚本汇总区 | `results/multi_turn_conversation.*`、`results/evaluation.md` |

> 说明：默认预设 `wo05_multiturn` 使用 `cascade` 级联重排（含一次 LLM 精排），属于**精度优先**配置；
> 演示/验收若以硬性 3 秒为唯一目标，请用 `--fast`（`reranker=tfidf`）。两种配置的耗时都会落盘，便于对照。

### 3.2 资源消耗

| 维度 | 现状与优化手段 | 验证方式 |
|------|----------------|----------|
| LLM 调用次数 | 规则通道命中时不调用；`llm` 模块磁盘缓存重复问题；短问题不触发分解 | 脚本结束打印「LLM 调用 N 次（缓存命中 M 次）」；`llm.get_usage()` 亦写入各结果 JSON 的 `LLM用量` |
| Token 与费用 | `llm.get_usage()` 统计输入/输出 token 与预估费用（DeepSeek 参考价） | 同上；服务侧 `/api/metrics` 的 `llm_usage` |
| 显存/内存 | 嵌入模型本地加载一次（`embed` 模块单例）；向量库 Chroma 持久化、缺失时降级 NumPy 本地库 | 观察进程内存与 `data/index/` 体积 |
| 磁盘 | 索引与缓存分别落在 `data/index`、`data/cache`；PDF 解析结果缓存避免重复解析 | `results/index_stats.json` 的块数/向量数 |

## 四、稳定性验收（高可用性、容错机制）

| 风险场景 | 系统行为 | 验证方式 | 代码位置 |
|----------|----------|----------|----------|
| LLM 指代消解超时/失败/无 Key | 捕获异常 → 使用原问题继续问答 | 断网或删除 Key 后跑脚本，观察 `[warn]` 与流程继续 | `rag_core.query_understand.resolve_coreference` |
| LLM 问题分解失败 | 回退规则分解（按连词/问号切分） | 无 Key 时跑 `query_understanding.py --offline` 的「规则分解」用例 | `rag_core.query_understand.decompose` |
| LLM 重排失败 | 回退原检索顺序，不影响出答案 | 断网跑 `multi_turn_chat.py` | `rag_core.rerank.LLMReranker` |
| 单轮问答异常 | 记录 `error` 后继续下一轮，对话历史保留 | 人为构造异常问题观察脚本不中断 | `src/wo05_common.py::run_script` |
| 评估指标不可用 | 单项指标标记「不可用」，其余照常汇总 | 无嵌入模型时跑 `run_evaluation.py` | `src/run_evaluation.py::safe_metrics` |
| 索引未建立 | 启动前检查并给出中文提示（退出码 2） | 未建索引直接跑任一脚本 | `src/wo05_common.py::index_ready` |
| 附件缺失 | 明确列出缺失路径后退出（退出码 2） | 临时改名 PDF 后跑 `build_index.py` | `src/wo05_common.py::check_data_files` |
| 服务健康监控 | `/api/health` 健康检查 + `/api/metrics` 指标，可接容器探针 | `curl /api/health` | `rag_core/api.py` |
| 并发会话隔离 | 界面按 `session_id` 隔离历史；服务端 `_SESSIONS` 按会话隔离 | 两个浏览器窗口分别追问 | `rag_core/api.py`、`src/chat_ui.py` |
