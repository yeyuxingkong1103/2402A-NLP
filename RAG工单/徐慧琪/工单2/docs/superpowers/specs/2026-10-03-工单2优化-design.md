## 2. 现状分析（优化前系统 = 工单1）

工单1管线：`PyMuPDF 文本抽取 → 字符级分块(900字/重叠120) → bge-m3 向量化 → Qdrant(本地模式) → 向量+BM25+RRF → bge-reranker-v2-m3 精排 → qwen2.5:3b 生成（带引用）`

| 层面 | 现状 | 局限 |
| --- | --- | --- |
| PDF 解析 | PyMuPDF 纯文本流 + 启发式标题识别 | 无版面分析；表格被拉平成文本行；公式/图片丢失；标题层级误判 |
| 分块 | 固定 900 字符窗口 + 重叠 | 切断标题与正文、拆散表格、无父子结构、歧义块无法还原上下文 |
| 检索 | 向量 + BM25 + RRF + 精排 | 无查询改写（仅轻量消歧）、无上下文压缩、无多子问题分解检索 |
| 生成 | qwen2.5:3b，引用校验+修复 | 上下文组织可再优化；部分题超时 |

资源约束（实测）：
- 本机**无 Docker**（无 `docker` 可执行文件）→ Qdrant 无法以 Docker 方式部署
- `sentence_transformers`/`FlagEmbedding` 直接导入在 Windows 上段错误 → 必须走工单1已验证的 `bootstrap`（离线环境变量 + pandas/sklearn 预热 + 16MB 大栈线程）
- bge-m3（`D:\model\bge-m3`）、bge-reranker-v2-m3（`D:\model\reranker`）、Ollama `qwen2.5:3b/0.5b`、`bge-m3:latest` 均在本机可用
- MinerU 权重已在 ModelScope 缓存（`MinerU2.5-Pro-2605-1.2B` + `PDF-Extract-Kit-1.0`），但 Python 包未装 → 需安装 `mineru`（pip 包，不触发模型下载）

## 3. 总体方案（三选一，推荐 A）

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 在工单2独立成项目，全面重做解析+分块+检索（推荐）** | 新目录完整实现优化版；工单1原样保留作为「优化前」对照系统 | 对比真实（优化前=实际交付物）；互不污染；工单2可独立验收 | 需重跑 548 页解析（一次性 ~20 分钟） |
| B. 在工单1代码上原地改造，用 git 分支/开关切优化前后 | 改动小、复用多 | 对比时同一份代码切换 | 工单1交付物被破坏，无法交付「优化前」原样系统；两套逻辑纠缠 |
| C. 只做检索层优化，解析分块不动 | 最省时间 | 无法覆盖工单明确要求的「解析/分块」两个层面 | 不符合需求 |

**推荐 A**：工单要求「从 PDF 解析、分块、检索三个层面优化」且需「优化前后对比」，
保留工单1为基线、工单2为优化版是最贴合验收的形态。

## 4. 详细设计

### 4.1 PDF 解析优化（MinerU 主 + PaddleOCR-VL 兜底）

- **MinerU**（新装 `mineru==2.7.6`，权重走本机 ModelScope 缓存，强制本地）：
  - 输出 Markdown + `content_list.json`（含 `type`/`page_idx`/`bbox`/表格结构）
  - 表格 → 结构化 Markdown 表格；公式 → LaTeX；图片保留 caption
  - 通过环境变量 + `mineru.json` 将模型源指到本地缓存目录，**不联网**
  - 解析失败/模型装载失败时自动回退到工单1式 PyMuPDF 解析（容错要求）
- **PaddleOCR-VL 兜底**：扫描质量检测（页面文本 < 阈值、乱码率高、纯图页）
  → 对问题页调用独立 venv：`D:\model\Paddle-OCR\venv\Scripts\python.exe`（子进程，不污染主环境）
- **元数据**：每个块保留 `page_idx / heading_path / source / block_type(text|table|formula|image)`

### 4.2 分块优化（弃用 RecursiveCharacterTextSplitter）

- **标题层级切分**：按 Markdown `#`~`######` 维护标题栈，得到 `heading_path`（如 `["第四节 风险因素","三、技术风险"]`）
- **表格/公式独立成块**：表格整块不拆（超长截断保留表头），公式带上下文独立成块
- **父子块（Parent-Child）**：
  - 子块 300–450 字：向量化 + BM25 的检索单位，命中精度高
  - 父块 1200–1800 字：同标题路径下的完整小节，作为 LLM 上下文
  - payload 存 `parent_id / parent_text / parent_page_idx`，检索命中子块后按去重后的父块送 LLM
- **元数据入 Qdrant payload**：支持按 `block_type`/`source` 过滤

### 4.3 检索优化

1. **混合检索**：Qdrant 稠密向量 + BM25（jieba 分词 + 领域保护词），RRF 融合（k=60）
2. **重排**：bge-reranker-v2-m3 cross-encoder 精排（本机已有；子块粒度重排，返回父块上下文）
3. **查询改写**（三层，按延迟预算逐级启用）：
   - 规则层（零额外延迟）：意图识别（数值/事实/列表/比较）、疑问词剥离、领域同义扩展（"军用领域收入"→+ "主营业务收入 占比"）
   - 分解层：多子问题检测（"分别"、"和"、"以及"）→ 逐子问题检索后合并 RRF
   - LLM 层（可选，qwen2.5:0.5b）：仅当规则层置信度低时启用，控制 ≤0.4s
4. **上下文压缩**：相邻块去重合并、按精排分裁剪、总长度上限（默认 ≤3000 字）

### 4.4 生成与性能（≤3 秒硬指标）

- **预热**：进程启动即加载 embedding/reranker、`ollama` 模型 keep_alive 常驻（避免首题冷启动）
- **并行**：稠密检索与 BM25 并行；查询改写与检索重叠执行
- **生成控制**：qwen2.5:3b、`num_predict` 上限、答案简洁化提示词（关键事实优先，少客套）
- **缓存**：Query→答案 LRU 缓存 + embedding 缓存；重复问题直接命中
- **流式输出**：界面流式显示；计时口径在报告中明确（首 token / 完整答案）
- **降级策略**：LLM 超时 → 返回抽取式答案（检索片段直接作答），保证 ≤3s 稳定性

### 4.5 评估与对比（三层）

| 层级 | 内容 | 产物 |
| --- | --- | --- |
| 客观指标 | 10 题 × {优化前(工单1), 优化后(工单2), 纯LLM}：关键事实命中率、响应时间、Hit Rate@k（k=5，检索结果含答案所在页即命中）、MRR、NDCG@5 | `data/eval/compare_results.json` |
| LLM 裁判 | qwen2.5:3b 按标准答案打分（复用工单1判定器，同一标准保证可比） | 同上 |
| RAGAS | faithfulness / answer_relevancy / context_precision / context_recall（Ollama 本地裁判） | `data/eval/ragas_results.json` |

- 基准数据复用：`工单1/data/eval/ground_truth.json`（10 题标准答案+关键事实）、工单1 的 `eval_results.json` 作为「优化前」参考实测值
- 「优化前」系统由 `src/baseline.py` 通过 `sys.path` 引入工单1代码（只读，不修改工单1任何文件），调用其索引（`工单1/data/qdrant` collection `zhaogu_shuoming_shu`）跑同一批题，保证同机同时段可比
- MRR/NDCG 的相关性判定：以 ground_truth 的 `key_facts` 是否出现在检索片段所在页（`page_idx`）为相关性标签

```
工单2/

├── build_index.py          # MinerU解析→分块→向量化→Qdrant入库
├── app.py                  # Streamlit 中英双语（问答/对比/知识库）
├── evaluate_compare.py     # 10题三方对比（准确率/时间/HitRate/MRR/NDCG）
├── evaluate_ragas.py       # RAGAS 评估
├── data/{parsed,chunks,qdrant,eval}/
└── docs/
```

## 6. 关键决策与取舍理由

| 决策 | 选择 | 理由 / 替代方案被否原因 |
| --- | --- | --- |
| Qdrant 部署 | **qdrant-client 本地持久化模式**（`QdrantClient(path=...)`），代码保留 server 模式开关 | 本机无 Docker；本地模式与 server 同 API、同数据结构，换环境只改一个配置项。文档中如实说明 |
| Embedding | bge-m3（`D:\model\bge-m3`） | 工单要求优先 BGE；中英双语；1024 维；本机完整 sentence-transformers 目录 |
| LLM | Ollama qwen2.5:3b（生成）/ 0.5b（轻量改写） | 已 pull 且离线可用；3b 已在工单1实测平均 2.3s 满足指标 |
| 解析器 | MinerU 2.7.6（+ 兜底回退 PyMuPDF） | 工单明确要求；权重已在本地缓存；pip 装包不违反"禁下载模型"约束 |
| 界面 | Streamlit（沿用） | 已装 1.61.1；工单1界面可平滑升级；中英双语用轻量 i18n 字典 |
| 评估 | RAGAS 0.2.15（本地 Ollama 作 judge）+ 自建客观指标 | 已装；用本地模型避免外部 API 与费用；规则指标保证可复现 |
| 对比基线 | 直接调用工单1代码与索引 | 保证"优化前"是真实交付物而非复刻；同机同时段可比 |
| 分块 | 标题层级 + 父子块 | 工单明确禁用 RecursiveCharacterTextSplitter 一刀切 |
| 性能 | 预热 + 并行 + 缓存 + 流式 + 抽取式降级 | 3 秒是硬指标，需要多层保险 |

## 7. 风险与对策

| 风险 | 概率 | 对策 |
| --- | --- | --- |
| MinerU 装包/模型装载失败 | 中 | 自动回退 PyMuPDF 增强解析；解析产物分层缓存，不阻塞下游 |
| MinerU 548 页解析耗时过长 | 中 | 后台一次性跑，支持断点续跑（逐页缓存）；GPU 加速 |
| 窗口段错误（sentence_transformers） | 已知 | 移植 bootstrap（预热 + 大栈线程），所有入口走 `run_with_large_stack` |
| 3 秒指标个别题超标 | 中 | 流式计时口径 + 缓存 + 降级；报告中如实给出分布（P50/P90/≤3s占比） |
| RAGAS 依赖外部 LLM/embedding | 高 | 全部指向本机 Ollama + 本地 bge-m3，离线可跑 |
| 准确率 90% 未达标 | 低 | 10 题逐题分析（95/34/957/795 为重点），针对性优化并在报告中披露逐题结果 |

## 8. 实施顺序

1. **骨架**：bootstrap/config/embedder/vector_store/llm 移植与适配（含 mineru 安装验证）
2. **解析**：pdf_parser（MinerU）+ 质量检测 + OCR 兜底 + 回退链路；跑通 548 页
3. **分块**：chunker（标题层级/表格独立/父子块）+ 元数据
4. **入库**：build_index.py（向量化 + payload + 双 collection 支持）
5. **检索**：retriever + reranker + query_rewrite + context 压缩
6. **编排**：rag.py（计时/降级/缓存）+ 预热
7. **界面**：app.py 中英双语（问答/引用页码/对比页/知识库）
8. **评估**：evaluate_compare.py + evaluate_ragas.py；跑出对比数据
9. **文档**：优化方案 / 对比分析 / RAGAS 报告 / 技术文档 / 用户手册 / README
10. **验收**：10 题端到端复跑，确认 ≥90% 与 ≤3s；整理演示脚本
