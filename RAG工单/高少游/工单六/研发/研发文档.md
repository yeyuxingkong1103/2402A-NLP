# 研发文档 · 检索策略实现说明（向量 / 全文 / 混合）

> 工单编号：**人工智能 NLP-RAG-混合检索任务**
> 版本：V1.1　|　日期：2026-10-08
> 目标：在基于招股说明书的问答系统中，优化检索策略，提供向量检索（召回+重排）、
> 全文检索以及两者同时执行的混合检索的**配置及应用**功能，提升 PDF 文档检索精度。

## 1. 需求拆解

| 工单子需求 | 交付形态 | 落地模块 |
|---|---|---|
| 向量检索（召回+重排） | 多嵌入模型召回 + ≥3 种重排算法 | `embedding.py` / `vector_retriever.py` / `rerankers.py` |

## 2. 向量检索（召回 + 重排）

### 2.1 多嵌入模型（`embedding.py`）

`config.EMBEDDING_MODELS` 把「slug → (Ollama 模型名, 维度, 说明)」登记为注册表：

| slug | Ollama 模型 | 维度 | 说明 |
|---|---|---|---|
| `bge-m3` | bge-m3:567m | 1024 | 多语言，默认 |
| `bge-large` | bge-large:latest | 1024 | 中文语义 |
| `nomic-embed` | nomic-embed-text:latest | 768 | 英文语义 |
| `m3e-base` | m3e-base | 768 | 可选，需先 `ollama pull` |

每个模型独立持久化 `vector_db/emb_<slug>.npy`，检索时按当前策略加载对应矩阵。
`Embedder.encode_many_cached()` 把一次 ask 的多路查询（原查询 + 同义词 + 实体）
**合并为单次 HTTP 调用**并缓存，显著降低 Ollama 固定开销（~2s/次）。

### 2.2 召回（`vector_retriever.py`）

- 文档向量在构建期已 L2 归一化 → 余弦相似度等价于内积，`numpy` 矩阵乘法一次算完；
- 多路查询分别召回后按块取**最大相似度**聚合，再取 Top-`recall_k`；
- 支持文档级路由（`allow` 集合）限制在目标文档内召回。

### 2.3 重排（`rerankers.py`，共 4 种）

| 重排器 | 名称 | 打分信号 | 备注 |
|---|---|---|---|
| `LinearFusionReranker` | linear | 向量分、BM25 分、关键词/同义词/实体覆盖、数值命中、序列标记、**查询核心短语**、表格/图形加成、话题、反馈 | 默认，效果最优（100%） |
| `TfidfReranker` | tfidf | 语料 IDF × 候选 TF 的余弦相似度 | 无监督、可解释（98%） |
| `LLMReranker` | llm | 本地大模型 listwise 排序 | 语义强，但实测均值 4.23s、离群 67.4s，超 3s |
| `AdaptiveFeedbackReranker` | adaptive | 👍/👎 块级偏好在线学习 | 随使用自适应（92%） |

> 统一接口：`rerank(query, candidates, kb, analysis, feedback, top_k)`。
> `none` 为消融基线（不重排），其分数经单调校准到 [0.5,1.0] 以通过相关性门限。

## 3. 全文检索（`inverted_index.py` / `fulltext_retriever.py`）

自建**含位置信息**的倒排索引（不依赖 Elasticsearch，轻量可复现）：

| 能力 | 实现要点 |
|---|---|
| BM25 打分 | `k1=1.5, b=0.75`，多字段加权（title / body / abstract） |
| 布尔查询 | 解析 `AND/OR/NOT`（兼容「与/或/非」），集合交并差 |
| 短语匹配 | 双引号短语 → 词元位置连续校验 |
| 模糊匹配 | Levenshtein 编辑距离扩展近似词 |
| 模式判定 | `auto`：布尔词→布尔；引号→短语；否则 BM25，无结果兜底模糊 |

倒排索引持久化 `vector_db/inverted_index.pkl`（词表 20629）。

## 4. 混合检索（`hybrid_retriever.py`）

```
                 ┌── 向量通道（多嵌入模型 → 余弦召回）──┐
Query ─ 改写/理解 ─┤                                        ├─ 融合 → 重排 → 答案合成
                 └── 全文通道（倒排索引 → BM25）──────────┘
```

| 融合算法 | 公式 / 机制 | 特点 |
|---|---|---|
| `weighted` 加权平均 | `wv·norm(v) + wf·norm(b)` | 分数可比、平滑（实测 94%） |
| `rrf` 倒数排名融合 | `Σ wᵢ/(k + rankᵢ)`，`k=60` | 只用排名、稳健（默认，100%） |
| `voting` 投票 | 各通道 Top-M 按权重计票 | 强调共识（100%） |

权重 `vector_weight / fulltext_weight` 自动归一化；`RetrievalConfig.fusion` 运行期可切。

## 5. 检索策略配置（`retrieval_config.py`）

`RetrievalConfig` 是「策略的配置与应用」的单一事实来源，三入口均可配：

| 入口 | 场景 |
|---|---|
| 界面下拉（`app.py`） | 交互式演示 / 人工调参 |
| 命令行参数（`evaluate_retrieval.py --strategies/--rerankers/--fusions/--models`） | 批量消融评测 |
| 环境变量（`.env`） | 部署默认值 |

## 6. 与检索配套的关键优化

| 优化 | 文件 | 说明 |
|---|---|---|
| 文档级路由 | `hybrid_retriever._doc_filter` | 依据公司别名只在目标文档内检索，避免跨文档串味 |
| 查询核心短语重排信号 | `rerankers.py` `W_PHRASE` | 「各期净利润 / 累计研发投入」等连续短语整体命中加成 |
| 答案候选池加深 | `qa_engine.py` `answer_top_k` | 展示取 top_k，抽取用更深候选池，命中率显著提升 |
| 分数校准 | `rerankers.py` | `none/tfidf` 分数单调校准，修复「选不重排即无答案」 |
| 序列/指标抽取增强 | `answer_builder.py` | 口径污染降权（归母/扣非）、表格行序列兜底、精确值优先 |
