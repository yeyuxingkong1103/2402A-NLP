# 用户手册（工单 03）

**工单编号：人工智能NLP-RAG-PDF文档的表格解析及检索优化**

本系统面向《招股说明书1.pdf》（武汉兴图新科电子股份有限公司）与
《招股说明书2.pdf》（武汉力源信息技术股份有限公司）两份文档，提供中文/英文问答，
回答会标注**来源文档 + 页码**；若答案出自表格，还会给出**表名与命中的行号**。

---

## 1. 启动系统

### 1.1 前置检查

| 项目 | 要求 | 检查命令 |
| --- | --- | --- |
| Ollama 服务 | 已启动，且有 `qwen2.5:3b` | `ollama list` |
| 向量库 | 已建库（`data/qdrant` 存在） | 若首次使用见 1.2 |

### 1.2 首次使用：建库

```bash
python build_index.py
```

耗时参考（本机 RTX 4060 Laptop，实测）：**约 6 分钟**，其中
MinerU 解析招股2 约 4 分钟（招股1 复用已有解析产物）、表格 OCR 兜底约 4 分钟
（首次；结果会缓存，之后重建几乎不耗时）、向量化约 1 分钟。

> 只想知道界面长什么样、不等建库？可先跑 `python build_index.py --no-ocr`，
> 跳过表格 OCR 兜底（只影响个位数张低质量表）。

### 1.3 启动界面

```bash
streamlit run app.py
```

浏览器自动打开 `http://localhost:8501`。

## 2. 界面功能

左侧边栏可切换 **中文 / English**（界面文案与示例问题随之切换，回答语言由问题语言决定）。

### 2.1 💬 问答

1. 在输入框提问（或用下方"示例问题"按钮一键填入）；
2. 点「提问」；
3. 查看结果：
   - **回答**：直接给结论；
   - **📄 引用来源**：形如
     `招股说明书2 第2页｜表格：本次发行概况（第 2、8 行）`
     —— 明确告诉你答案来自哪份文档、哪一页、哪张表的哪几行；
   - **🧭 文档路由**：系统识别出问题问的是哪家公司，从而只在对应文档内检索；
   - **⏱ 耗时明细**：查询理解 / 混合检索 / 重排 / 上下文 / 生成 / 总计；
   - **检索到的片段**（折叠）：展开可看送进模型的原文，表格片段会以 Markdown 表格呈现。

侧栏可调参数：

| 参数 | 说明 | 建议 |
| --- | --- | --- |
| 启用重排 | 用 bge-reranker-v2-m3 精排候选 | 保持开启（准确率明显更高） |
| 返回片段数 | 送进 LLM 的片段数 | 默认 4；表格题多时可加到 5~6 |
| 预热模型 | 提前加载 embedding/reranker/LLM | 首次提问前点一次，首题不再多等几秒 |

### 2.2 ⚖️ 优化前后对比

选择一个必测问题，点「开始对比」，三列并排展示：

- **工单03（表格优化）**：本系统；
- **工单01/02（无表格优化）**：上游系统（只索引招股1、表格整块处理）；
- **纯 LLM（无检索）**：不检索直接问模型，用来验证 RAG 的增益。

> 涉及武汉力源的题目（id 1~4），"无表格优化"一列会答不出——因为它没有招股2 的索引。
> 这正是本工单"多文档 + 表格结构化"的价值所在。

### 2.3 📊 表格检索

浏览已结构化入库的表格：

- 顶部三个指标：文档数 / 表格总数 / 低质量表数；
- 选择文档 → 选择表格（按页序列出）；
- 查看该表的：来源、页码、**表型**（`header` 列式表 / `kv` 字段-值表）、行数、质量分、`table_id`、
  表头或字段清单、表格内容（前 60 行）。

用途：验证表格解析是否正确（例如「本次发行概况」应显示为 `kv` 表，
字段里能看到"发行股数""发行后总股本"）。

### 2.4 📚 知识库

查看系统状态（向量库模式与集合名、embedding/reranker/LLM 模型信息），
并可点击「重建知识库」在后台重新建库。

## 3. 提问技巧

| 场景 | 建议问法 |
| --- | --- |
| 表格类 | 直接问表里的字段名，如"本次发行股数是多少" |
| 需要计算 | 可以直接问比例，如"发行股数占发行后总股本的比例是多少"（系统允许用表中数字做一步除法） |
| 多文档 | **带上公司名**，如"武汉力源……""兴图新科……"，系统会自动路由到对应文档 |
| 报告期数据 | 说清指标名，如"报告期内来自军用领域的收入分别是多少" |

**关于"无法确定"**：当检索到的片段确实不含相关信息时，系统会回答
"根据已有资料无法确定。"，而不是编造。这是有意设计。

## 4. 常见问题

**Q1：回答里的数字和我翻书看到的不一致？**
系统有数字校验：答案中的数字必须能在检索到的上下文中逐字找到（或由其中两个数一步算出），
否则会重试一次；仍不一致则改为抽取式回答（直接给原文）。
若你发现确实是错的，多半是 MinerU 对该表识别有误——可在「📊 表格检索」里找到该表，
看"质量分"是否偏低。

**Q2：系统答不出招股2 的问题？**
检查建库是否包含招股2：

```bash
python build_index.py --source 招股说明书2.pdf
```

或查看「📊 表格检索」页的文档下拉框里是否有该文档。

**Q3：响应超过 3 秒？**
首次提问包含模型冷启动。点侧栏「预热模型」后，后续问题通常在 1 秒左右。
若持续偏慢，可把「返回片段数」调小，或关闭重排。

**Q4：重建索引后界面还报"向量库为空"？**
Qdrant 本地模式同一时刻只允许一个进程占用。先关闭其他正在运行的
`build_index.py` / `app.py`，再重建。

**Q5：想换文档问答？**
把新 PDF 放进项目根目录，加入 `src/config.py` 的 `SOURCE_PDFS`，
并在 `DOC_ALIASES` 里补上公司名别名，然后 `python build_index.py --rebuild`。

**Q6：表格 OCR 兜底很慢？**
首次建库会对低质量表格所在页调用 PaddleOCR-VL（实测 9 页约 236 秒）。
结果缓存在 `data/tables/<文档>_ocr_pages.json`，之后重建不再重复识别。
不需要时加 `--no-ocr` 跳过。
