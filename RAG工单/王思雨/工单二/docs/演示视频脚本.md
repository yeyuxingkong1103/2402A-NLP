## 第 2 幕　加载 / 解析 `招股说明书1.pdf`（2:30–4:30）

**画面**：终端

**操作与旁白**

```bash
python -c "from src.pdf_parser import parse_pdf; from src import config as C; b,p = parse_pdf(C.PDF_PATH); print(p, len(b))"
```

旁白要点：

- 「知识库是 548 页的《招股说明书1.pdf》。」
- 「主解析器用 MinerU 做版面还原与表格识别，产物缓存到 `data/parsed/`，第二次运行直接用缓存，不重复跑。」
- 「MinerU 的表格在 `table_body` 字段里，是 HTML；只读 `text` 字段会丢掉全部 502 张表格，所以我们把表格按行还原成 `单元格 | 单元格` 的文本。」
- 「表格本身往往只有裸数字，比如『国防领域 | 4,627.14 | 94.34%』，既没有『军用领域』也没有『收入』，检索命中不了，所以我们把最近的章节标题和表题拼在表格前面。」
- 「如果 MinerU 失败——比如中文路径导致 fasttext 加载不了——会自动降级到 PyMuPDF 加 pdfplumber；如果连文本层都没有（扫描件），再降级到 PaddleOCR。」

**加分演示（可选，体现容错）**：临时把 PDF 改名，提问，界面返回「知识库文件不存在：招股说明书1.pdf」而不是堆栈。

## 录制注意事项

1. **耗时数字必须与实测一致**，不要口播未跑出来的数字。录制前先跑一遍 `python -m src.evaluate` 拿到真实数据。
2. 首次提问会触发模型懒加载（bge-m3 与重排模型各约 10 秒），**这一条不要算进 3 秒验收**，先随便问一次预热再正式录。
3. 三个容易穿帮的点：索引没建（会提示「知识库尚未构建」）、后端没起（前端报「请求失败」）、Milvus 没起（会提示「系统繁忙」）。
4. 视频文件名建议：`工单二-基于PDF文档的问答系统优化-演示.mp4`。
