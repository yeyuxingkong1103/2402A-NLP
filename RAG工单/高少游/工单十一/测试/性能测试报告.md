# Embedding 模型微调系统 · 性能测试报告

> **工单编号：人工智能 NLP-RAG-Embedding 模型微调任务**
> 被测系统：金融年报领域 Embedding 微调系统（基座 `BAAI/bge-small-zh-v1.5`）
> 测试脚本：`tools/bench_latency.py` ｜ 数据源：`output/latency_bench.json`
> 测试日期：2026-10-08 ｜ **全部数据为真实运行测量值**

---

## 一、测试目的

量化微调系统在**无 GPU 的 CPU 环境**下的关键性能，为部署与容量规划提供依据：

1. **模型加载时间**：基座 / 微调模型冷启动耗时；
2. **语料编码吞吐**：建立/重建向量库的耗时（blocks/s）；
3. **查询编码延迟**：单条查询向量化的 mean / p50 / p95；
4. **端到端检索延迟**：查询编码 + 7476×512 相似度 + Top-10；
5. **训练吞吐**：微调训练的 samples/s、steps/s。

---

## 二、测试环境

| 项 | 值 |
|---|---|
| 操作系统 | Windows 11 |
| CPU | 16 逻辑核（无 CUDA GPU） |
| Python | 3.10 |
| PyTorch | 2.6.0+cpu |
| sentence-transformers | 6.1.0 |
| 模型维度 | 512（bge-small-zh-v1.5） |
| 语料规模 | **7476 块**（向量库 7476×512，float32 ≈ 14.6 MB） |
| 评估截断长度 | 256 |

---

## 三、测试方法

`tools/bench_latency.py` 逐项测量并落盘：

- **语料编码吞吐**：抽样前 512 块，batch_size=64，测 `blocks/s`，再外推全量 7476 块；
- **查询编码延迟**：取评估集前 30 条查询，逐条编码计时，统计 mean / p50 / p95；
- **端到端检索延迟**：查询编码 + 与缓存语料矩阵做内积 + `argsort` 取 Top-10；
- **训练吞吐**：由 `finetune_result.json` 复算（810 样本 × 4 epoch ÷ 训练秒数）。

---

## 四、测试结果

### 4.1 模型加载时间

| 模型 | 加载耗时 |
|---|---|
| 基座 `bge-small-zh-v1.5` | 8.43 s |
| 微调模型（本地目录） | **0.15 s** |

> 基座首次加载含 HF 缓存校验开销；微调模型为本地目录、体积小，加载极快。

### 4.2 语料编码吞吐（向量库构建）

| 模型 | 吞吐 | 全量 7476 块预计耗时 |
|---|---|---|
| 基座 | 42.7 blocks/s | ≈ 175 s |
| 微调 | 42.3 blocks/s | ≈ 177 s |

> 两模型吞吐基本一致（同架构同维度）。**全量建库约 3 分钟**，
> 系统对语料向量做 `.npy` 缓存，**重跑评估接近瞬时**，避免重复建库。

### 4.3 查询编码延迟（单条）

| 模型 | mean | p50 | p95 |
|---|---|---|---|
| 基座 | 9.94 ms | 9.99 ms | 10.97 ms |
| 微调 | **9.89 ms** | 9.56 ms | 11.81 ms |

> 单条查询向量化稳定在 **10 ms 量级**，满足交互式检索需求。

### 4.4 端到端检索延迟（Top-10）

| 模型 | mean | p95 |
|---|---|---|
| 基座 | 11.38 ms | 13.75 ms |
| 微调 | **10.15 ms** | 11.74 ms |

> 端到端（含查询编码）**约 10~14 ms**；微调后略快（p95 11.74 ms）。
> 主要开销为查询编码（~10 ms），7476 向量的内积+排序仅约 1 ms。

### 4.5 训练吞吐

| 项 | 值 |
|---|---|
| 训练样本 | 810 |
| epochs / batch_size | 4 / 16 |
| 训练步数 | 204 |
| 训练耗时 | **475.67 s**（≈ 7 分 56 秒） |
| 训练吞吐 | **6.81 samples/s** |
| 全流程耗时（建库+数据集+训练+评估） | 668.74 s（≈ 11 分 9 秒） |

## 五、性能汇总

| 指标 | 数值 | 评价 |
|---|---|---|
| 单条查询编码延迟 | ≈ 10 ms | 优（交互式） |
| 端到端检索延迟 p95 | ≤ 13.75 ms | 优 |
| 全量建库耗时 | ≈ 3 min（一次性，可缓存） | 可接受 |
| 微调训练耗时 | ≈ 8 min（CPU） | 可接受（无 GPU） |
| 训练吞吐 | 6.81 samples/s | 受限于 CPU |

---

## 六、性能瓶颈与优化建议

| 编号 | 瓶颈 | 说明 | 建议 |
|---|---|---|---|
| P1 | 训练速度 | CPU 仅 6.81 samples/s，4 epoch 需 8 分钟 | 生产环境启用 GPU（预计提速 20~50×）；或减小 batch 累积步数 |
| P2 | 建库耗时 | 全量 7476 块需 3 分钟 | 已实现 `.npy` 向量缓存，增量更新即可 |
| P3 | 相似度检索 | 当前为**暴力内积**（7476×512） | 语料增长到 10 万+ 时建议接入 FAISS / HNSW 近似检索 |
| P4 | 查询编码 | 单条 ~10 ms，逐条编码未批处理 | 高并发下可做微批（batch=8/16）提升吞吐 |
| P5 | 模型加载 | 基座首次 8.43 s | 服务化时保持常驻进程，避免重复冷启动 |

---

## 七、结论

1. 系统在**无 GPU 的 CPU 环境**下，单条查询端到端检索延迟 **10~14 ms**，可满足交互式问答的实时性要求；
2. 向量库一次性构建约 3 分钟，且**有缓存**，生产可增量维护；
3. 微调训练约 8 分钟（CPU），是主要耗时环节，**建议生产环境使用 GPU**；
4. 检索侧性能瓶颈为「暴力相似度检索」，**语料规模化后需引入 ANN 索引**。
