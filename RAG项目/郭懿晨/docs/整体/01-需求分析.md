# 01 · 需求分析（v2）

> **定位**：从「教学 + 工程」双角度明确本项目要解决什么。基于 GB/T 44653-2024（SF6 循环再利用导则）构建本地 RAG PDF 问答系统，v1 建立 MVP 基线，v2 优化检索质量（粗排 + 精排）。

## 一、项目背景

### 1. 行业场景与真实痛点

SF6（六氟化硫）是 GIS 组合电器、断路器、互感器等电力设备广泛使用的绝缘与灭弧介质，也是强温室气体（全球增温潜势约为 CO₂ 的上万倍量级），因此其现场回收、净化、回充、检测等作业必须严格遵循导则，以减少泄漏排放。GB/T 44653-2024《六氟化硫气体现场循环再利用导则》正是面向该场景的国家标准，覆盖气体回收分类与处理方式、回收与净化装置功能要求、检测方法与数值指标、回充技术要求、安全使用与人员防护等条款。

对电力/工业领域一线运维人员而言，「查标、用标」的真实痛点是：

- **标准长、条款杂、跨页分布**：正文、表格与数值指标混杂，现场需快速定位「某作业环节对应哪些条款」，逐页翻找成本高、易漏读。
- **引用必须可溯源**：工程引用讲究「依据到条、到页、到原文」，不允许凭印象作答，更不能让模型自由发挥——系统必须做到「答有所据、无依据宁可不答」。
- **数据不能随意上云/出网**：作业文档与内部资料常有网络隔离与保密要求，问答能力必须在本地离线完成，不依赖在线大模型 API。

### 2. 为什么用本地 RAG

采用「本地 RAG（检索增强生成）」：离线将标准 PDF 解析、清洗、分块并向量化入库；问答时先从知识库检索相关条款原文作为证据，再让本地 LLM 仅基于证据作答，从而同时满足「本地离线」与「可溯源、可拒答」。

### 3. 技术演进动机（v1 → v2）

演进由实测驱动，分两期：

- **v1（MVP 基线）**：先打通「解析 → 清洗 → 分块 → 向量化 → 入库 → 复合检索（dense+sparse+RRF）→ 问答 → 页码引用」完整闭环并跑出评测基线，证明链路真实可运行、回答可回溯；同时趟平 MinerU/transformers 兼容、Qdrant embedded 单进程等工程坑。
- **v2（检索质量优化）**：基线评测暴露出真正的短板不在「能否作答」，而在**检索质量**——召回后直接截断取 top_k，低质候选会挤占引用名额；且系统对域外问题（变压器油、发电机等不在本知识库标准范围内的问题）不设任何防线、直接作答，实测全部误答。因此 v2 在召回后新增「粗排（复用 BGE-M3 dense 余弦，零新增模型）+ 精排（本地 bge-reranker-v2-m3 交叉编码）」与相关性阈值过滤，将无关候选挡在引用之外、对域外问题正确拒答，并以 recall@k / MRR / 拒答率 / 检索延迟四类指标对每次改动跑 v1/v2 可复现的 A/B 对比，用分数而非感觉迭代。

## 二、业务目标

1. **知识库**：面向电力/工业领域工程师「查标、用标」场景，把标准 PDF（正文 + 表格 + 数值指标）变成可检索、可问答、可追溯来源的本地知识库。
2. **构建服务**：把「解析 → 清洗 → 分块 → 向量化 → 入库」暴露成服务——上传 PDF、启动构建任务、查看任务进度、浏览向量库。
3. **检索质量（v2 核心）**：在 RRF 召回后新增「粗排 + 精排」两阶段重排，让最终引用更相关、域外问题正确拒答，按 recall/MRR/拒答率/延迟可迭代对比。
4. **教学落点**：专高六学生理解「RAG 全流程 + 复合检索 + 重排优化 + 前后端服务」；每个环节分数说话（评测回归）。

## 四、非功能需求（NFR）

| # | 需求 | 说明 |
|---|---|---|
| NFR1 | 可复现 | 本地单机运行：本地 PDF、本地模型路径、Qdrant embedded、Ollama |

| NFR7 | 可迁移 | Qdrant embedded 的 collection/named vectors/payload 贴近服务端用法 |
| NFR8 | 可测试 | 配置/模型/存储/上传/分块/问答/路由/重排均有 pytest 覆盖 |

## 五、范围边界

- **范围内**：单机本地 RAG PDF 问答系统；PDF 上传；MinerU 解析；VLM 后处理（qwen-vl-plus，DashScope）；清洗；分块；BGE-M3 向量化；Qdrant embedded 入库；dense+sparse 复合检索（RRF）；**粗排（BGE-M3 dense 余弦）+ 精排（bge-reranker-v2-m3）两阶段重排（v2）**；Ollama 问答生成；引用返回；域外拒答兜底；任务状态轮询；文档与向量库浏览；静态前端操作台。
- **范围外（后置）**：多用户权限；云端部署；SSE 实时推送；SQLite 任务历史；多文档批量并发；任务队列治理；完整评测平台与指标看板；模型微调；父子/递归分块；Qdrant→Milvus 迁移；**MinerU 空结果兜底修复（另开一轮）**。

## 六、验收标准（AC）

> **约定**：每条需求以 Given/When/Then 场景表述，任一场景满足即该条验收通过；判定证据来自 07-测试与验收.md（实测）与 `docs/v2/checklist.md`（SC-001~005）。AC 编号与第三、四节 FR/NFR 一一对应。

### 1. 功能需求验收（FR1–FR18）

**FR1 · 文档上传**
- **FR1-1 合法上传**：Given 用户通过上传接口提交一个合法 PDF，When 系统保存文件，Then 创建 document 记录与构建任务并返回 `task_id`。
- **FR1-2 非法文件**：Given 用户提交非 PDF 文件，When 系统校验类型，Then 返回 400「只允许上传 PDF 文件」，且不产生 document/task 记录。

**FR2 · 文档解析**
- **FR2-1 主路径**：Given 合法 PDF 已进入构建，When MinerU 解析执行，Then 产出带 `page`/`category`/`text` 的内容块列表。
- **FR2-2 失败回退**：Given MinerU 抛出异常，When 构建执行，Then 自动回退 `pypdf` 提取；两步均失败则任务标记 `failed` + 错误信息。
  > 注：MinerU 正常返回但结果为空的情形仍列为范围外待修复（见五、范围边界），暂不计入本验收。

**FR3 · 复杂元素后处理**
- **FR3-1 启用路径**：Given `.env` 中 `VLM_ENABLED=true` 且文档含表格/图片等复杂块，When 构建到后处理步骤，Then 调用 `qwen-vl-plus` 对视觉块回填理解结果。
- **FR3-2 关闭路径**：Given `VLM_ENABLED=false`（代码默认），When 构建执行，Then 跳过 VLM，不影响解析→入库主链路。

**FR4 · 数据清洗**
- **FR4-1 保留可追溯文本**：Given 内容块含空行/页眉页脚等噪声，When 数据清洗执行，Then 去除噪声且保留可溯源文本，证据内容不丢失。

**FR5 · 分块**
- **FR5-1 元数据完整**：Given 清洗后内容块，When 分块执行，Then 每个 chunk 携带 `document_id/page/category/text/source_span`。
- **FR5-2 页码校验**：Given chunk 的 `page < 1`，When 写库前校验，Then 拒绝入库。

**FR6 · 向量化**
- **FR6-1 双向量**：Given 任一 chunk，When BGE-M3 向量化，Then 产出 dense(1024) 与 sparse 向量，结构/维度正确。

**FR7 · 向量库存储**
- **FR7-1 结构化入库**：Given 向量化后的 chunk，When 写入 Qdrant embedded，Then 以 named vectors（dense+sparse）存储、payload 保留元数据，可检索、可浏览。

**FR8 · 复合检索**
- **FR8-1 RRF 融合**：Given 用户提交问题，When 检索执行，Then 并行召回 dense 与 sparse 并经 FusionQuery(RRF) 融合，返回带分数候选。

**FR9 · 问答生成**
- **FR9-1 基于证据**：Given 检索到可用证据，When 生成回答，Then 本地 Ollama（`deepseek-r1:7b`）仅依据引用证据生成并返回 `answer`。

**FR10 · 引用校验**
- **FR10-1 引用回传**：Given 一次问答完成，When 返回结果，Then 附带引用（文档名/页码/类别/原文片段）；命中兜底时 `fallback=true` 且 citations 为空。

**FR11 · 构建过程展示**
- **FR11-1 轮询展示**：Given 前端打开任务视图且构建进行中，When 状态刷新，Then 以轮询方式展示步骤/进度/错误（不使用 SSE）。

**FR12 · 向量库内容展示**
- **FR12-1 列表与筛选**：Given 前端打开文档/向量库视图，When 加载数据，Then 展示文档列表、向量库记录并支持按类别筛选。

**FR13 · 任务状态持久化**
- **FR13-1 状态一致**：Given 构建/删除等状态变化，When 写入 `data/state.json`，Then 重启后文档/任务/chunk 状态保持一致。

**FR14 · 前端操作台**
- **FR14-1 五视图闭环**：Given 启动前端，When 访问操作台，Then 上传/任务/文档/向量库/问答 5 视图可用，可完成课堂演示闭环。

**FR15 · 粗排**
- **FR15-1 主路径**：Given RRF 召回得到候选集 `retrieval_candidate_k`，When 执行粗排，Then 以 BGE-M3 dense 余弦打分并保留 `coarse_top_k` 进入精排。
- **FR15-2 dense 缺失回退**：Given 候选缺失稠密向量（内存兜底路径），When 粗排执行，Then 回退 `rrf_score` 打分，不报错。

**FR16 · 精排**
- **FR16-1 主路径**：Given 粗排结果 `coarse_top_k`，When 执行精排，Then 本地 `bge-reranker-v2-m3` 交叉编码打分（0~1）并保留 `final_top_k` 作为引用。
- **FR16-2 本地离线**：Given 精排执行，When 打分，Then 全程本地加载模型，不调用 Ollama/外部 API。

**FR17 · 重排可配置**
- **FR17-1 配置生效**：Given 修改 `AppSettings` 中任一候选规模/各层 top_k/阈值/粗排打分方式/模型路径/批大小，When 链路执行，Then 按新配置运行，无需改业务代码。
- **FR17-2 开关退化**：Given `rerank_enabled=false`，When 检索，Then 行为与 v1 完全一致（search limit=`final_top_k` + RRF 分数过滤）。

**FR18 · 检索重排评测**
- **FR18-1 双档产出**：Given 评测集与真实检索库就绪，When 运行 `python scripts/run_sf6_eval.py --variant both`，Then 产出 v1/v2 两档 recall@k/MRR/拒答率/检索延迟并落盘 `eval/results/`。
- **FR18-2 对比报告**：Given v1 基线已存档，When 执行对比，Then 产出 v1 相对 v2 的 delta 报告（如 `v1_vs_v2_comparison.json`）。

### 2. 非功能需求验收（NFR1–NFR8）

**NFR1 · 可复现**
- **NFR1-1 本地全链路**：Given 全新本地单机环境与配置，When 按 08-部署与运行.md 启动，Then 解析/向量化/检索/问答全链路本地跑通，不依赖在线大模型 API（VLM 为可选项）。

**NFR2 · 可追溯**
- **NFR2-1 逐条溯源**：Given 任一次问答，When 检查其引用，Then 每条 chunk/引用可回溯到来源文档、页码、类别、原文片段。

**NFR3 · 无依据不编造**
- **NFR3-1 兜底响应**：Given 空问题、检索为空或引用不可用，When 问答接口被调用，Then 返回固定兜底文案「知识库中未找到相关依据。」，`fallback=true` 且 citations 为空。
- **NFR3-2 域外拒答（v2 重点）**：Given 问题超出本知识库范围（如变压器油、发电机），When 检索重排执行，Then 无关候选被相关性阈值过滤并返回拒答兜底，不编造（对照 07 实测拒答率 0.92）。

**NFR4 · 诚实进度**
- **NFR4-1 步骤级进度**：Given 构建任务进行中，When 前端轮询状态，Then 仅展示真实步骤级进度/错误，不虚构页级解析进度。

**NFR5 · 原子性**
- **NFR5-1 失败不示成功**：Given 构建任一步骤失败，When 任务结束，Then 任务与文档标记 `failed` + 错误信息，绝不展示为成功。

**NFR6 · 轻量化**
- **NFR6-1 无重型依赖**：Given 交付包与运行依赖，When 审查架构，Then 不含账号体系、消息队列、分布式组件与关系型数据库。

**NFR7 · 可迁移**
- **NFR7-1 贴近服务端用法**：Given 未来接入 Qdrant 服务端，When 复用写入/检索代码，Then collection/named vectors（dense+sparse）/payload 结构与服务端一致，迁移成本低。

**NFR8 · 可测试**
- **NFR8-1 pytest 全绿**：Given 代码就绪，When 在项目根运行 `pytest backend/tests -v`，Then 全部用例通过（含 v2 新增 `test_rerank.py` / `test_rerank_real.py`）。

### 3. v2 指标门槛（对照 07-测试与验收 实测）

| 指标 | 门槛 | 实测（2026-09-02，43 题） |
|---|---:|---:|
