# 截图规范

**工单编号**：人工智能NLP-RAG-基于PDF文档的问答系统优化
**目录用途**：存放演示视频、验收文档与答辩材料中引用的界面/结果截图。

---

## 一、命名规范

```
<环节编号>-<内容简称>-<补充说明>.png
```

| 环节编号 | 对应内容 |
|---|---|
| 01 | 系统总体 / 项目结构 |
| 02 | 分块策略对比实验 |
| 03 | 检索重排配置对比实验 |
| 04 | Prompt 对比实验 |
| 05 | 优化前后答案对比（重点） |
| 06 | Web 问答界面 |
| 07 | 性能与稳定性 |

示例：

```
05-before-after-id260.png          优化前/后对比：军用领域收入（id 260）
05-before-after-id33.png           优化前/后对比：收入占比（id 33）
05-before-after-id207.png          优化前/后对比：补充流动资金（id 207）
06-web-compare-mode.png            Web 端对比模式整屏
06-web-single-optimized.png        Web 端「仅优化后」模式
07-metrics-api.png                 /api/metrics 运行时指标
```

同一内容的多版本用 `-v2` 后缀区分；**不要**用 `截图1.png`、`新建图片.png` 这类命名。

## 二、画面要求

| 项 | 要求 |
|---|---|
| 分辨率 | ≥ 1920×1080（与录屏一致），保留原始像素，不缩放 |
| 格式 | PNG（界面/表格），JPG 仅用于照片类素材 |
| 主题 | 终端深色主题、编辑器浅色主题，全片统一，不混用 |
| 字号 | 终端 ≥ 16pt，保证 1080p 下缩略图可读 |
| 语言 | 界面与终端全部为中文（英文提问的多语言截图除外），不得出现乱码 |
| 窗口 | 只截取目标窗口，不含桌面图标、聊天软件、无关标签页 |
| 隐私 | 不得出现 API Key、个人路径中的用户名以外的隐私信息；截图前用 `set DEEPSEEK_API_KEY=***` 之类方式遮蔽 |

## 三、必备截图清单

1. **代码规范**：`src/common.py` 文件头（可见工单编号注释）1 张；
2. **分块对比**：`results/chunking_comparison.md` 主表整屏 1 张；
3. **重排对比**：`results/retrieval_comparison.md` 主表整屏 1 张；
4. **Prompt 对比**：`results/prompt_comparison.md` 主表 + 一例典型差异案例 2 张；
5. **答案对比（重点）**：`results/before_after.md` 第三节中
   id 260 / 33 / 207 三题的并排答案各 1 张，共 3 张；
6. **Web 界面**：对比模式整屏 1 张 + 单模式 1 张 + 英文提问 1 张；
7. **性能与稳定性**：`/api/health` 与 `/api/metrics` 各 1 张，
   `docs/优化方案.md` 3.6/3.7 两张表各 1 张；
8. **演示视频**：视频封面帧 1 张（命名为 `00-cover.png`）。

## 四、标注规范

- 关键数字（准确率、耗时、漏答要点）用**红色细边框**圈出，
  同一张图内标注不超过 3 处，边框线宽 2px、圆角 4px；
- 箭头使用直线 + 实心三角，颜色统一为 `#E11D48`；
- 对比类截图左右两栏之间可加一条 2px 灰色竖线分隔；
- 标注后另存为 `-marked` 版本，例如 `05-before-after-id260-marked.png`，
  **保留未标注原图**以便二次加工。

## 五、存档与引用

- 所有截图放在本目录，不要散落到 `results/` 或 `docs/`；
- 文档引用使用相对路径，例如：
  `![优化前后对比](demo/screenshots/05-before-after-id260.png)`；
- 答辩 PPT 中引用同一批文件，避免出现「文档与 PPT 数字不一致」。
