### 1.2 端到端数据流（工单第 6 节优化链路的落地形态）

```text
招股说明书1.pdf (14.3MB / 548页 / 文字版)
   │  ① pdf_parser：PyMuPDF 取正文+页码；page.find_tables() 取表格→Markdown；
   │     跨页表格合并；结构化字段 page/section/type/content/bbox
   ▼
研发/data/processed/招股说明书1.parsed.json  +  .tables.jsonl
   │  ② chunker：标题层级切段 → 段落滑窗 400~600/overlap 80；
   │     表格整表成块不拆；每块打 page/section/type/keywords 元数据
   ▼
研发/data/processed/chunks.jsonl  （同时写 SQLite chunks 表）
   │  ③ embedder：Ollama /api/embed 调 bge-m3:latest → 1024 维向量
   │     （降级：sentence-transformers 本地 bge-small-zh-v1.5 → 512 维）
   ▼
研发/data/index/<embed-model>-<dim>/  ：vectors.npy + vectors_meta.jsonl + bm25_index.pkl
   │  ④ 在线：query_understanding（语言识别/意图/页码过滤/多轮改写/同义扩展）
   ▼
⑤ 混合检索：向量 top-k  +  BM25 top-k（jieba 分词，自实现）
   │   融合（加权线性）→ 表格块加权 / 数字·百分比·金额块加权 / 领域关键词加权
   │   → 释义页(前30页)降权 / 半句碎片降权 / 页码过滤
   ▼
⑥ 重排：top 20 → 重排（bge-reranker-base；不可用时规则化重排并记日志）→ top 5
   │
   ▼
⑦ 生成：llm_client 选后端（ollama ＞ openai兼容(vLLM/SGLang) ＞ extractive）
   │   流式逐块 → 首字计时；prompt 只依据片段、无答案回「不清楚」、按提问语言作答
   ▼
⑧ 引用：citation 从命中的 chunk 生成 [页码: X]（英文 [Page: X]）+ 页码真实性校验
   │
   ▼
⑨ 落库与可观测：SQLite（会话/消息/检索追踪/反馈/评估）
   日志：部署/日志/app.log、error.log、rag_trace.jsonl（含检索片段与模型 prompt/输出）
```

> 与基线（工单1）的关键差别：③ 由 512 维本地嵌入改为 **1024 维多语言嵌入**；④⑤⑥ 由"多查询变体 + 样板降权"扩展为**查询改写/扩展 + 相对化加权 + 显式重排**；⑦ 由不可用的 `127.0.0.1:8000` 改为**本机 Ollama**（实测首字 0.20 s）【环境事实 3】。

## 2. 部署形态与后端可插拔关系（工单要求：本机 Ollama ↔ 算力云 vLLM/SGLang）

### 2.1 LLM 后端分层

| 层 | 内容 | 本机（当前实测环境） | 算力云（4090） |
| --- | --- | --- | --- |
| 统一访问层 | `app/core/llm_client.py`：`LLMClient.chat_stream(messages) -> Iterator[LLMChunk]`、`probe() -> BackendInfo` | 同一份代码 | 同一份代码 |
| 后端 1（首选） | `ollama`：`POST http://127.0.0.1:11434/api/generate`（`stream=true`） | ✅ 在线，`qwen2.5:3b` 首字 **0.20 s** / 总 **0.95 s**【环境事实 3】 | 可选保留（小模型） |
| 后端 2 | `openai`：`POST {base_url}/v1/chat/completions`，兼容 **vLLM / SGLang** | ❌ 本机无 `127.0.0.1:8000` 服务（**基线曾因此把首字拖到 57 s**）【设计取证 A.5】 | ✅ 主用：`vllm serve Qwen2.5-7B-Instruct-AWQ` 或 `python -m sglang.launch_server` |
| 后端 3（兜底） | `extractive`：无任何 LLM 服务时的抽取式回答 | ✅ 可在断网/无服务时保证系统不崩 | 备用 |
| 选择方式 | 环境变量 `RAG_LLM__BACKEND`（`auto`/`ollama`/`openai`/`extractive`）+ `RAG_LLM__BASE_URL` + `RAG_LLM__MODEL` | `auto` → 探测顺序 ollama → openai → extractive | `RAG_LLM__BACKEND=openai`、`RAG_LLM__BASE_URL=http://127.0.0.1:8000/v1` |
| 探测纪律 | 探测**超时 ≤0.5 s、不重试**，结果进程内缓存 | 硬性要求：探测发生在生成之前，重试会把首字拖到秒级【环境事实 3.1】 | 同左 |

**可插拔的工程含义**：`generator.py` 只依赖 `LLMClient` 抽象，不出现任何 Ollama/vLLM 专有字段；Ollama 的 `/api/generate` 与 OpenAI 的 SSE 增量都由 `llm_client.py` 归一化为同一事件流 `(event, payload)`：`first_token` / `delta` / `done` / `error`。切换后端**不改业务代码**，仅改环境变量。

### 2.2 嵌入后端分层

| 层 | 内容 | 主路径 | 降级路径 |
| --- | --- | --- | --- |
| 访问层 | `app/core/embedder.py`：`Embedder.encode(texts) -> np.ndarray`、`encode_one(text)`、`dimension`、`name`、`health()` | — | — |
| 后端 | `OllamaEmbedder`（`POST /api/embed`，`bge-m3:latest`，**1024 维，多语言**） | ✅ 首选 | — |
| 后端 | `SentenceTransformerEmbedder`（本地 `bge-small-zh-v1.5`，**512 维**） | — | ✅ Ollama 不可用时自动降级【环境事实 3.2】 |
| 索引隔离 | 索引目录含模型名与维度：`研发/data/index/bge-m3-1024/`、`研发/data/index/bge-small-zh-512/` | **不同维度绝不可混用** | 同左 |
| 版本校验 | `vectors_meta.jsonl` 记录 `embedder` / `dimension` / 块数 / 构建时间；加载时不一致则拒绝加载并提示重建 | 防"维度漂移导致静默错检" | 同左 |

## 4. 组件职责表

### 4.1 解析层

| 组件 | 职责 | 关键接口 | 输入 → 输出 | 降级/异常 |
| --- | --- | --- | --- | --- |
| `core/pdf_parser.py` | 正文/页码/表格提取；跨页表格合并；清洗页眉页脚与断行 | `PDFParser.parse(pdf_path, doc_id, max_pages, extract_tables) -> ParsedDocument`、`save(doc) -> dict[str, Path]`、`load_parsed(path)` | PDF → `ParsedDocument`（pages+tables） | 文件不存在 → `FileNotFoundError`（上层转友好提示）；表格识别失败 → 记录日志后跳过该页表格，正文仍成功【工单1产物同源】 |
| 表格策略 | `pymupdf.page.find_tables()` → Markdown 表；`bbox` 用于跨页合并 | `ParsedTable{table_id, page, section, markdown, rows, bbox?}` | 页 → Markdown 表 | `pdfplumber` 不可用；若存在则作为备选解析器，**默认关闭**【环境事实 2.2】 |
| OCR | 扫描件兜底（本语料为文字版，跳过） | `parser_capabilities() -> {"pymupdf": bool, "pdfplumber": bool}` | — | 本机无 OCR 依赖；日志显式记录「文字版，跳过 OCR」【工单要求 6.1】 |

### 4.2 分块层

| 组件 | 职责 | 关键接口 | 输出 | 说明 |
| --- | --- | --- | --- | --- |
| `core/chunker.py` | 标题层级切段 → 段落滑窗 400~600/overlap 80；表格整表成块；打关键词标签 | `Chunker.split(document) -> list[Chunk]`、`save(chunks, dir, name) -> Path` | `chunks.jsonl` + SQLite `chunks` 表 | 基线为 700/100【工单1产物】；本工单按工单要求改 400~600/80【工单要求 6.2】 |
| 元数据 | `chunk_id/page/section/type/keywords` | `Chunk`（pydantic） | — | 表格块额外 `table_id` |
| 关键词标签 | 收入/占比/注册资本/法定代表人/募资/上下游/供应商/客户/技术标准/科技进步奖 等 | `Chunker._tag_keywords(text) -> list[str]` | `Chunk.keywords` | 标签仅作**加权候选信号**，不直接决定排序（见 §7 ADR-5） |

### 4.3 索引与检索层

| 组件 | 职责 | 关键接口 | 输出 | 降级/异常 |
| --- | --- | --- | --- | --- |
| `core/embedder.py` | 文本→向量；维度/模型名自描述 | `encode(texts) -> np.ndarray`、`encode_one(text)`、`dimension`、`name`、`health()` | 1024 维（主）/512 维（降级） | Ollama 不可达 → 自动降级 ST 模型；两者都不可用 → 拒绝构建索引并报错（**不静默**） |
| `core/vector_store.py` | 向量持久化与精确检索 | `add(chunks, vectors) -> int`、`search(vector, top_k) -> list[(chunk_id, score)]`、`save()/load()/reset()/count()` | `vectors.npy` + `vectors_meta.jsonl` | 后端 `numpy`（默认）/`chroma`（本机不可用→不使用）【环境事实 2.2】 |
| `core/bm25_index.py` | 自实现 BM25（jieba 分词，k1=1.5/b=0.75） | `build(chunks)`、`search(query, top_k)`、`save()/load()` | `bm25_index.pkl` | 索引文件缺失 → 按 SQLite 内容重建并告警 |
| `core/retriever.py` | 混合召回 + 相对化加权 + 释义降权 + 页码过滤 + 融合 | `retrieve(query, analysis, top_k, page_filter) -> list[RetrievedChunk]`、`retrieve_multi(queries, ...)`、`is_confident(results)`、`is_answerable(q, results)` | `RetrievedChunk{chunk, score, vector_score, bm25_score, rerank_score, source}` | 向量/BM25 均无命中 → 返回 `[]` 并记录日志；置信度不足 → 交生成层回「不清楚」 |
| `core/reranker.py` | top20 → top5 重排 | `Reranker.rerank(query, candidates, top_n) -> list[RetrievedChunk]`、`health()` | 重排后的候选 | `bge-reranker-base` 不可用（本机断网无法下载）→ **规则化重排**（关键词覆盖/数字命中/块类型/位置先验加权），并记录 `mode=rule`（**绝不假装跑过模型**） |

### 4.4 生成与引用层

| 组件 | 职责 | 关键接口 | 输出 | 降级/异常 |
| --- | --- | --- | --- | --- |
| `core/llm_client.py` | 三后端统一访问 + 快速探测 + 流式计时 | `chat_stream(messages, **kw) -> Iterator[(event, payload)]`、`probe() -> dict`、`backend_name` | `first_token`/`delta`/`done`/`error` 事件 | 探测失败快速返回（≤0.5 s、不重试）；请求异常 → `error` 事件 + 日志堆栈 |
| `core/generator.py` | 组织 prompt、流式生成、抽取式兜底、统一 Answer 组装 | `stream(question, contexts, history) -> Iterator[(event, payload)]`、`generate(...) -> Answer` | `Answer{answer, citations, is_unknown, first_token_ms, total_ms, mode, language, ...}` | 无 LLM → `mode="extractive"`；LLM 异常 → 回「服务暂时不可用，请稍后再试」并落 `error.log` |
| `app/prompts/qa_prompt.txt` | 三条硬约束（仅依据片段/无答案回不清楚/带 `[页码: X]`/按语言作答） | — | — | 提示词缺失 → 使用内置默认并告警 |

## 5. 时序说明

### 5.1 离线索引构建（`研发/scripts/build_index.py`）

```text
CLI → config.ensure_directories()
 → PDFParser.parse(pdf)                       [记录 pages/tables/chars/elapsed]
 → PDFParser.save()                            → parsed.json / pages.txt / tables.jsonl
 → Chunker.split(doc) → Chunker.save()          → chunks.jsonl
 → SQLiteManager.upsert_document()/insert_chunks()
 → Embedder.encode(all chunk contents)          → 1024 维（bge-m3，分批调用 /api/embed）
 → VectorStore.add() → save()  →  index/<model>-<dim>/vectors.npy + vectors_meta.jsonl
 → BM25Index.build() → save()   →  index/<model>-<dim>/bm25_index.pkl
 → 打印索引规模（块数/维度/耗时）并写 app.log
```

【待验证】索引构建的具体耗时由 T2 实测填入 `研发/scripts/build_index.py` 输出与 `部署/配置/README.md`。

### 5.2 在线单轮问答（`QAEngine.stream`）——含首字计时点

```text
t0  用户点击提问（UI 记 start = perf_counter()）
t1  QAEngine.stream(question, conversation_id)
t2  QueryUnderstanding.analyze()：语言识别 / 意图 / 页码过滤 / 多轮改写（LLM 或规则）+ 同义扩展
t3  Retriever.retrieve_multi(variants)：
      ├ Embedder.encode_one(query)   ← 走 Ollama /api/embed（网络往返）
      ├ VectorStore.search(top_k=20)
      ├ BM25Index.search(top_k=20)
      ├ 融合 + 相对化加权（表格/数字/关键词）+ 释义页降权 + 片段降权 + 页码过滤
      └ 取融合 top 20
t4  Reranker.rerank(top20 → top5)
t5  置信度判定：is_confident(top cosine ≥ 阈值) 且 is_answerable(实义词覆盖)
       └ 不通过 → 立即产出「不清楚」（不再调用 LLM，首字极小）
t6  LLMClient.chat_stream(prompt + 5 个片段)
       └ 首个 delta 到达 → **t_first = perf_counter() - start**（首字延迟定义）
t7  流式增量推给 UI（逐块渲染）
t8  生成结束 → Generator 组装 Answer（含 citations、pages、mode）
t9  Citation.validate() 校验页码真实性 → SQLite 落库 → rag_trace.jsonl 记检索片段 + prompt + 输出
```

**首字延迟定义（全链路一致）**：从收到用户提问到**第一个 token 字符送达界面**的墙钟时间，含查询理解、嵌入、检索、重排、首 token 生成；不含前端渲染与人工输入时间【工单要求 5.2】。所有测试（`test_api_v2.py`）与对比脚本（`compare_optimization.py`）必须用同一口径。

### 5.3 多轮对话

```text
用户：法定代表人是谁？        → 检索/生成/落库（messages: user, assistant）
用户：那注册资本呢？          → Conversation.history_pairs() 最近 5 轮
                              → QueryUnderstanding.rewrite_with_history()：
                                  LLM 改写（有 LLM）→ 独立问题；
                                  规则改写（无 LLM）→ 主题槽位替换 + 指代消解
                              → 用改写后的问题检索（原始问题原文入日志与 traces）
                              → 答案落库，UI 显示轮次
```

【环境事实 4.2/5.3】提示：改写必须避免"把上一轮主题带进新问题"导致串题，因此保留 `is_answerable()` 实义词覆盖校验作为第二道闸门。

### 5.4 降级时序（三类故障，工单 6.7）

| 故障 | 触发点 | 时序行为 | 用户可见文案 |
| --- | --- | --- | --- |
| PDF 解析失败 | `build_index.py` / `pdf_parser.parse` | 立即抛出并捕获，写 `error.log`（含堆栈），不进入嵌入阶段 | 界面：`PDF 解析失败，请检查文件是否损坏：<原因>` |
| 检索为空/置信度不足 | `retriever` → `qa_engine` | 跳过重排与 LLM，直接产出兜底 Answer（`is_unknown=True`，记 `unknown_reason`） | `不清楚` |
| 模型异常/超时 | `llm_client` | 触发快速失败（探测 ≤0.5 s）→ 若为生成期异常，先尝试抽取式；仍失败则统一文案 | `服务暂时不可用，请稍后再试` |
| 无 LLM 服务（整机离线） | `llm_client.probe()` | 探测失败 → `mode="extractive"`，系统仍可用 | 正常答案（标注为抽取式，仅内部可见） |

## 7. 关键设计决策（ADR）

| ID | 决策 | 备选方案 | 依据 |
| --- | --- | --- | --- |
| ADR-1 | 生成走**本机 Ollama `qwen2.5:3b`** | ①继续等 `127.0.0.1:8000` 的 vLLM（本机不存在）②纯抽取式为主 | `qwen2.5:3b` 实测首字 0.20 s / 总 0.95 s，满足 ≤3 s；`deepseek-r1:7b` 首字 18.68 s 超预算，禁止用于在线路径【环境事实 3】 |
| ADR-2 | 嵌入用 **bge-m3（1024 维，多语言）**，保留 bge-small 512 维降级 | 仅 512 维 | 多语言要求（工单 6.6）+ 1024 维语义分辨力更强；实测 bge-m3 首调 2 条 query 6.44 s（含加载），余弦 0.689【环境事实 3】 |
| ADR-3 | 索引**按嵌入模型分目录** | 单目录覆盖 | 维度不可混用；避免换模型后静默错检【环境事实 3.2】 |
| ADR-4 | 核心优化落在**检索排序**（相对化加权 + 重排），而非只调提示词 | 只改 prompt | 基线向量 top-5 命中 1/10，而证据原文 10/10 都在索引里【环境事实 4.1】+【设计取证 A.4】 |
| ADR-5 | 加权必须**相对化**（按命中密度/位置/类型归一），不做无差别关键词加乘 | 基线式 `boost *= weight` 乘积加权 | 全库 64.7% 的块含 ≥6 位数字、24.3% 含 `%`、322 块带 `客户` 标签；无差别加乘等于整体抬升【设计取证 A.3】 |
| ADR-6 | 重排**必须存在**但允许规则化实现；模型不可用时如实标注 `mode=rule` | 假装跑 `bge-reranker-base` | 本机断网、无法获取重排模型权重（工单要求"可选"）；诚实性优先【环境事实 2.2】+【工单要求 6.3】 |
| ADR-7 | 判分沿用**工单1 确定性 `check_answer`**，不改阈值不剥离引用标签 | 自定义更宽松判分 | 「优化前 50% → 优化后 ≥90%」必须同一把尺子；放宽即造假【环境事实 4.2】 |
| ADR-8 | 日志**自实现** JSON logger（保留 loguru 风格 API） | 等 loguru | `loguru` 本机不可用且无法安装；三文件 schema 与字段保持不变，云端可无缝切换到 loguru【环境事实 2.2/6.5】 |
| ADR-9 | UI 双实现：真 Streamlit（云端）+ 标准库 `serve_fallback.py`（本机） | 只写 Streamlit（本机无法演示） | `streamlit` 本机不可用；两者共用 `app/core` 同一份业务逻辑【环境事实 2.2】 |
| ADR-10 | 引用"真实性"口径改为「页码 ∈ [1, 548] 且可回查真实 chunk」 | 以 `evidence_pages` 为真值 | `evidence_pages` 存在错标（Q531/Q543 等）【环境事实 5.1】+【设计取证 A.4】 |

## 8. 性能预算与容量

### 8.1 首字延迟预算分解（3 s）

| 阶段 | 预算（设计目标） | 当前依据 |
| --- | --- | --- |
| 查询理解（规则路径） | ≤ 50 ms | 【待验证】规则实现为主；LLM 改写仅在多轮且服务可用时启用，超时 0.5 s |
| 查询嵌入（1 条 query，bge-m3 热态） | ≤ 500 ms | 冷启动实测 6.44 s / 2 条（含模型加载）【环境事实 3】→ 必须 **warmup**，把冷启动移出首问 |
| 向量 + BM25 召回（2967 块） | ≤ 300 ms | numpy 精确检索 O(n·d)；【待验证】 |
| 相对化加权 + 释义降权 + 排序 | ≤ 50 ms | 【待验证】 |
| 重排 top20→top5 | ≤ 500 ms（规则化）/ ≤1500 ms（模型） | 【待验证】；规则化路径为保底 |
| LLM 首 token（qwen2.5:3b，≤5 片段） | ≤ 1500 ms | 实测首字 0.20 s（单测条件）【环境事实 3】 |
| 合计（含余量） | **≤ 3000 ms** | 【待验证】由 T4/T7 实测逐题确认 |

> 注意：基线 P95 57 s 全部来自 LLM 侧（`127.0.0.1:8000` 不存在 + 探测重试）【设计取证 A.5】。本架构把"LLM 可用性探测"前置到 `warmup()`（应用启动时），使在线路径不再承担冷启动与探测失败代价。

### 8.2 容量

| 维度 | 当前值 | 依据 |
| --- | --- | --- |
| 语料规模 | 548 页、2967 块（text 2464 / table 503） | 【设计取证 A.2/A.3】 |
| 向量规模 | 2967 × **1024** × 4 B ≈ 12.2 MB（优化后）；基线 2967×512×4 B = 6.08 MB | 【工单1产物】+【推断】 |

## 10. 架构级风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| bge-m3 首次加载慢（6.44 s / 2 条 query） | 首问首字超预算 | 启动 `warmup()` 预热嵌入与 LLM；UI 显示"预热中"；【待验证】预热耗时记录到日志 |
| Ollama 单实例串行 | 10 并发延迟劣化 | 如实记录 P50/P95；不宣称并发达标；必要时串行队列 + 明确提示 |
| 规则化重排效果弱于模型 | 命中率提升不足 | 用 T3 的 `test_reranker.py` 做定量对比（重排前 vs 后 top-5 命中数）；若不足，回退到"扩大召回 + 相对化加权"组合【待验证】 |
| 相对化权重参数过拟合 10 题 | 泛化性差 | 参数只作**保守默认**，并在 `优化方案设计.md` §3 说明每项权重的物理含义与调参边界；对比报告需给出逐题明细而非只给汇总 |
| `evidence_pages` 错标引发的引用误判 | 验收争议 | 引用口径与数据缺陷如实披露（R-01），并在 `验收标准.md` 第 3 条固定判定方法 |
