## 1. 为什么要做表格解析

招股说明书中的关键事实（发行股数、募集资金投向、关联方持股比例、分年度收入及占比、
注册资本、法定代表人……）**大量以表格形式呈现**。沿用 01/02 工单"把表格当普通文本行"
的做法，会产生三类致命问题：

| 问题 | 现象 | 后果 |
|---|---|---|
| 行列关系丢失 | 单元格被按阅读顺序拍平成一行 | 表头命中、数值却在另一行，答案拼不出 |
| 合并单元格错位 | 多级表头 / 跨行合并单元格丢失归属 | "某年—某项目—某数值"三元关系断裂 |
| 跨页表格断裂 | 跨页后表头不再重复 | 后半段成为"无表头孤儿行" |

---

## 2. 解析流程（六步）

```
PDF 页面
  │
  ├─① 版面级表格检测  page.find_tables() → 单元格网格 + bbox
  │
  ├─② 单元格规整     换行/全角空格归一化，空值占位符统一
  │
  ├─③ 合并单元格还原  _fill_merged()：左邻优先、上邻兜底
  │
  ├─④ 交错列折叠      _collapse_interleaved()：还原"表头列/数据列"交替布局
  │
  ├─⑤ 表头规整        _merge_header()：多级表头合并为单行
  │
  ├─⑥ 表题识别        _caption_above()：取 bbox 上方最近文本块作表题
  │
  ▼
TableBlock { page, rows, header, caption, bbox, source }
  │
  ├─► markdown  属性：Markdown 表（保留行列结构，供人读）
  └─► kv_lines  属性：["表头：取值；表头：取值", ...]（供机器精准召回）
```

## 3. 关键算法说明

### 3.1 合并单元格还原 `_fill_merged`

PyMuPDF 对跨行/跨列合并的单元格返回 `None`。若直接丢弃，"归属关系"就丢了。
本模块按阅读顺序做**前向填充**，并加了一个约束避免误填真实空值：

```python
for c in range(n_cols):
    for r in range(1, len(grid)):
        if not grid[r][c] and grid[r - 1][c]:
            # 仅当本行左侧也为空（典型的合并延续）时才向上填充
            if c == 0 or not grid[r][c - 1]:
                grid[r][c] = grid[r - 1][c]
```

### 3.2 交错列折叠 `_collapse_interleaved`（力源信息表格特征）

部分表格被 PDF 线条切成"表头列 / 数据列"交替的网格：

```
|      | 关联方名称 |      | 持股比例 |      | 与本公司关系 |
| 赵马克 |          | 42.35% |         | 公司控股股东 |      |
```

表头落在奇数列、数据落在偶数列，若不还原，表头与取值整体错位（键值对退化为"列1/列3/列5"），
检索时"表头关键词"永远命中不到。

**还原判据**：若相邻两列在**每一行**中"至多只有一个非空"，则判定为交错列，合并为一列
（保留非空值），重复执行直到不再变化，可处理多层嵌套。

```python
for _ in range(4):
    ...
    mergeable = all(not (r[a].strip() and r[a+1].strip()) for r in grid for a in range(0, n_cols, 2))
    if not mergeable: return cur
    cur = [[grid[r][a] if grid[r][a].strip() else grid[r][a+1] for a in range(0, n_cols, 2)] ...]
```

### 3.3 处理顺序（关键坑）

```
错误顺序：填充 → 折叠 → 删空列     ✗ 空分隔列导致表头与数据错位
正确顺序：填充 → 删空列 → 折叠 → 删空列   ✓
```

**必须先删掉 PDF 线条造成的空分隔列**，才能得到规整的交错列网格，再折叠才正确。
这是本工单调试中定位到的关键修复点。

### 3.4 表题识别 `_caption_above`

取表格 bbox **上方、垂直间距 ≤30pt、水平有重叠**的最近文本块作为表题。
表题（如"本次发行概况""关联方及关联关系""募集资金投资项目"）是**表格级消歧**最可靠的信号
（见 `answer_builder._block_section_score`）。

### 3.5 质量过滤 `_quality_ok`

行数 < 2 或列数 < 2，或有效文本单元格过少 → 判定为误检表格，直接丢弃，避免噪声入库。

## 4. 双表示输出（表格 → 两种检索块）

同一张表生成**两类原子块**，互补使用：

| 块类型 | 内容 | 优势 | 适用问题 |
|---|---|---|---|
| `table` | `[表格]` + Markdown 表 | 保留行列结构，人可读、可结构化展示 | 罗列型（募投项目、关联方企业） |
| `table_kv` | `[表格行] 表头：取值` | 把"表头—数值"强绑定 | 数值/比例/字段型（发行股数、注册资本） |

示例（招股2 第22页募投项目表）：

```
[表格行] 序号：1；项目名称：仓储及物流中心；计划总投资(万元)：3,393.40
[表格行] 序号：2；项目名称：研发中心；计划总投资(万元)：1,526.38
```

> 若没有键值对块，问"仓储及物流中心的投资额是多少"时，检索命中"表头行"却拿不到数值。

---

## 5. 跨页表格处理

- `pdf_parser.parse_pdf` 中维护 `last_caption`：某页表格无表题时**继承上一页最近表题**；
- `chunking._table_parent`：**同表题**的多页表格共享同一个父块（父块 = 同表题全部表格内容），
  使跨页数据可整体召回、整体拼装。
