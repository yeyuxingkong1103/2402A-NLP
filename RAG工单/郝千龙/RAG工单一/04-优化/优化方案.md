## 二、优化方向

### 2.1 检索链路优化

#### 2.1.1 切分策略优化（C2）
- **现状**：固定 512 字符 + 64 overlap
- **优化**：
  - 表格单独切分，保留表头上下文
  - 按章节标题切分（招股说明书有"业务与技术""募集资金运用"等章节）
  - 引入语义切分（基于句法/章节）
- **预期收益**：召回率 +5~10%

#### 2.1.2 Embedding 微调（C3）
- **方法**：使用 InfoNCE 对比学习在招股说明书问答对上微调 bge-small-zh
- **数据**：工单 10 题做种子，扩展到 200~500 条标注问答
- **预期收益**：faithfulness +3~5%
- **成本**：单卡 4h

#### 2.1.3 Rerank 重排（新增 C3.5）
- **方法**：Milvus 召回 Top-20 → bge-reranker 重排取 Top-5
- **预期收益**：context_precision +8%
- **延迟代价**：+50~100ms（仍 < 3s）

#### 2.1.4 多路召回
- 路径1：向量召回（语义）
- 路径2：BM25 召回（关键词，如公司名、年份）
- 路径3：表格结构化检索（SQL-like）
- 融合：RRF（Reciprocal Rank Fusion）
- **预期收益**：召回率 +5~8%

### 2.2 缓存优化
- **现状**：仅缓存最终答案
- **优化**：
  - 缓存 Query 向量（命中率 30%）
  - 缓存 Top-K 命中集合（命中率 50%）
  - 引入语义相似度缓存（Query embedding 相似度 > 0.95 复用）
- **预期收益**：缓存命中率 +20%，重复 Q 延迟 < 30ms

### 2.3 LLM 推理优化
- **现状**：调用 OpenAI 兼容接口，temp=0.3
- **优化**：
  - 启用流式响应（streaming），首 token < 800ms
  - 量化：vLLM + AWQ INT4，吞吐 ×2
  - KV Cache 复用：prefix caching，把系统 prompt 共享
  - 批量请求：连续批处理（continuous batching）
- **预期收益**：单次延迟 -30%，并发 QPS ×2~3

### 2.4 向量库优化
- **索引切换**：IVF_FLAT → HNSW，查询延迟 -50%
- **分区**：按 doc_id 分区，多文档场景提升隔离性
- **GPU 索引**：CUDA 加速距离计算，<10ms
- **预期收益**：检索延迟从 ~80ms → ~20ms

### 2.5 服务并发优化
- FastAPI worker 数 = GPU 数 × 2
- 同步 LLM 调用改异步（`async/await`）
- 请求队列 + 限流（令牌桶 100 QPS）
- 健康检查 + 自动重启（supervisor）

### 2.6 长尾问题优化
- 表格数字类问题（如"军品收入"）→ 表格字段结构化抽取 + SQL 检索
- 多义/消歧问题 → 引入意图分类器
- 跨章节问题 → 多跳检索 + 答案合成

## 三、优化优先级与排期

| 优先级 | 优化项 | 预期收益 | 实施复杂度 |

- 端到端 P50/P95/P99 延迟
- 缓存命中率
- Top-K 召回率
- RAGAS：faithfulness / answer_relevancy / context_precision / context_recall
- GPU 利用率 / 内存占用

## 五、回归验证方法

每项优化上线前需执行：

1. 跑 `03-测试/test_unit.py` 确保单测全过
2. 跑 `03-测试/run_workorder_eval.py`，对比工单 10 题延迟与答案质量
3. 跑 `03-测试/test_api.py::test_latency_under_3s` 确保不超 SLA
4. 截图归档：每轮优化生成新截图到 `screenshots_opt_v{n}/`

## 六、风险与回滚

| 风险 | 触发条件 | 回滚策略 |
| :--- | :--- | :--- |
| Embedding 微调掉点 | RAGAS 下降 > 3% | 切回 base 模型 |
| HNSW 内存暴涨 | >2× 内存 | 退回 IVF_FLAT |
| 流式响应前端断流 | 兼容性问题 | 退回非流式 |
| Rerank 超时 | 检索 > 200ms | 关闭重排，直接用 Top-5 |

---

> 技术备注：
> - **RAG**：优化贯穿 RAG 全链路：切分→Embedding→检索→重排→生成→缓存。
> - **Transformer**：LLM 量化与 KV Cache 复用均依赖 Transformer 注意力机制特性。
> - **Fine-tuning**：本方案中的 Embedding 微调属于表示学习领域的 fine-tuning，对领域术语检索效果显著。
